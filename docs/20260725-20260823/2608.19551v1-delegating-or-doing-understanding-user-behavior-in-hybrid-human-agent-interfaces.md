## 摘要
大语言模型（LLMs）越来越多地嵌入到应用程序中，使用户能够通过直接操作或将操作委托给会话代理来完成任务。然而，关于用户在两种方式同时可用时如何平衡这些方式，目前知之甚少。我们通过模型上下文协议（MCP）将LLM代理集成到基于Web的内容管理系统中，使用户能够通过图形界面、会话代理或两者结合来执行CRUD任务。我们进行了一项受试者间研究（N=73），比较了三种交互模式：仅传统、人工智能优先和混合。在十六个场景中，我们分析了任务完成时间、交互日志和委托行为。AI辅助交互显著减少了点击次数、页面导航和滚动，表明交互工作量更低。令人惊讶的是，这些减少并未转化为更快的任务完成速度，因为各条件下的任务持续时间没有显著差异。我们还发现CRUD操作类型与委托之间没有显著关系，这表明用户并未系统地避免委托风险较高的操作。相反，委托行为在参与者之间的差异远大于任务之间的差异，个体差异约占助手使用方差的近一半（ICC = .50）。我们的研究结果表明，人类-智能体界面的主要好处可能是减少交互工作量，而非提高速度，并且委托行为更多反映用户是谁，而非任务需求是什么。

## Abstract
Large Language Models (LLMs) are increasingly embedded into applications, allowing users to complete tasks either through direct manipulation or by delegating actions to conversational agents. However, little is known about how users balance these modalities when both are available. We present a web-based content management system augmented with an LLM agent through the Model Context Protocol (MCP), enabling users to perform CRUD tasks through a graphical interface, a conversational agent, or both. We conducted a between-subjects study (N=73) comparing three interaction modes: Traditional-Only, AI-First, and Hybrid. Across sixteen scenarios, we analyzed task completion time, interaction logs, and delegation behavior. AI-assisted interaction significantly reduced clicks, page navigations, and scrolling indicating lower interaction effort. Surprisingly, these reductions did not translate into faster task completion, as task duration did not differ significantly across conditions. We also found no significant relationship between CRUD operation type and delegation, suggesting that users did not systematically avoid delegating higher-risk actions. Instead, delegation varied far more between participants than between tasks, with individual differences accounting for roughly half the variance in assistant use (ICC = .50). Our findings suggest that the primary benefit of human--agent interfaces may be reducing interaction effort rather than improving speed, and that delegation reflects who the user is more than what the task demands.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：大语言模型（LLM）正在从被动查询工具演变为能够主动执行任务的智能代理。以 ChatGPT、Claude、Gemini 为代表的应用已吸引数亿用户，其使用模式从"探索和操作"转向"对话和委派"。同时，Model Context Protocol（MCP）作为Anthropic推出的开放标准，允许LLM客户端发现并调用外部系统功能，使得代理能够真正"代表用户行动"，而非仅仅生成内容。
- **核心矛盾**：当同一应用程序同时提供图形界面（GUI）和会话代理两种执行路径时，用户如何在"自己动手做"和"委托给代理"之间做出选择？不同交互模态如何影响用户的探索性任务执行（Exploratory Task Execution, ETE）行为？现有研究对此知之甚少。
- **研究意义**：这一问题对 HCI 和人机交互（HAI）领域具有直接意义——理解用户在双界面场景下的行为模式，可以为 LLM 增强应用的设计提供实证依据，帮助设计者在用户自主性与代理自主性之间找到恰当的平衡。

  - **AI-First**：被明确指示尽可能依赖 AI 聊天助手，但仍允许必要时直接操作系统。
- **任务场景**：共 16 个任务，每个对应一种 CRUD 操作（创建、读取、更新、删除），涵盖更新个人资料、按语言查看帖子、创建/删除/编辑帖子、查看角色权限、创建角色、查看/更新/删除用户、按国籍搜索计数用户、创建带角色分配的新用户、验证新用户详情等场景。所有参与者按相同顺序执行这些任务。

- **统计分析**：使用线性混合模型（log 变换时长）、负二项广义线性模型（UI事件计数）、泊松广义混合模型（聊天交互次数）以及 ICC（组内相关系数）分析个体差异贡献。

- **实验规模**：主要实验为三项条件对比（N=73），每个参与者完成 16 个连续任务，共计超过 1100 个任务样本点。这是一次中等规模但行为学层面足够支撑统计推断的实验。

- **关于充分性的评估**：

## 6. 论文的主要结论与发现

- **AI 辅助显著降低直接操作量**：交互模式对 UI 事件（点击、页面导航、滚动）均有显著影响。AI-First 条件下点击和页面导航最少，Traditional 条件最多，Hybrid 介于两者之间。
  - 点击数：AI-First（μ=5.71）< Hybrid（μ=8.05）< Traditional（μ=9.99），各组间差异均显著。
  - 页面导航：AI-First（μ=1.56）< Hybrid（μ=1.91）< Traditional（μ=2.14），AI-First 与传统差异显著，Hybrid 与传统差异不显著。
  - 滚动：Hybrid（μ=7.87）< AI-First（μ=8.44）< Traditional（μ=10.50），仅 Hybrid 与传统间差异显著。
- **效率未提升**：任务完成时间在三组间无显著差异（F(2, 64.6)=0.26, p=.772）。尽管 AI-First 描述性均值最低（46.60 秒），但未达到统计显著水平。这说明"减少交互努力"不等于"加快完成速度"。
- **委派行为与任务风险无关**：CRUD 操作类型对聊天交互次数无显著影响（χ²(3)=6.60, p=.086）。最危险的 DELETE 操作（μ=0.386）在描述性统计上甚至比 UPDATE（μ=0.250）得到了更多的聊天交互，与"风险校准委派"的预期相反。
- **个体差异主导委派行为**：参与者层面的随机截距解释了聊天交互中约一半的方差（ICC = .50），加入条件作为协变量后这一数值几乎不变。委派行为更多反映"用户是谁"而非"任务是什么"。
- **指令的有限效力**：即使 AI-First 条件下明确指示参与者优先依赖助手，聊天交互仍然稀疏且极不均匀，总体委派水平仅比 Hybrid 稍有提升。然而，即使对话量不高，AI-First 仍然产生了最少的点击和导航——因为每次成功的工具调用将多步定位-导航-操作序列压缩为一次对话轮次。
- **核心结论**：混合人机界面的主要价值在于降低交互成本（effort），而非提高速度；用户是否选择委派更取决于个体倾向（可能是"倾向性信任"），而非任务特征。设计者应将交互努力作为评估指标，而不是仅看任务完成时间。

## 7. 优点

- **架构可推广性强**：基于 MCP 将现有 REST API 包装为代理可调用工具的思路具有高度的通用性，论文明确指出无需修改底层系统即可使既有 Web 服务"代理就绪"。这为工业界采用提供了低成本路径。
- **行为日志而非自我报告**：所有测量基于系统自动记录的真实操作痕迹（点击、导航、滚动、聊天轮次），避免了自我报告数据中常见的记忆偏差和社会期望偏差。这正是探索性搜索文献中方法论传统的延续。
- **Hybrid 条件的独特设计**：多数既有研究只比较"纯图形"与"纯对话"界面，Hybrid 条件允许用户在两种方式之间自由切换，首次从行为层面量化了"委派 vs. 自己动手"的实际边界，这是本研究最具方法论价值的贡献。
- **重定向增强的精细设计**：自动导航到操作结果页面，既保证了反馈可见性，又由于计数中包含系统产生的导航而朝"不利于研究假设"的方向偏移——意味着真实的用户主动导航减少幅度比数据呈现的更大，分析上的保守性增强了结论可信度。
- **对反直觉结果进行了坦诚的讨论**：并未简单地把"任务时间无差异"当作负面结果，而是上升到评估指标的设计启示；对"CRUD 与委派无关"的发现，提出了统计粗粒度、使用方式（更仔细而非更少）和倾向性信任等合理解释。

## 8. 不足与局限

- **样本同质性**：全部为英语母语的本科生，属于年轻且数字素养较高的群体。既有研究表明会话界面最受益的人群恰恰是低领域或低计算机素养用户，这类用户在本研究中完全缺失。
- **委派测量过于粗粒度**：仅统计会话轮次数量，无法区分"谨慎、深思熟虑的使用"和"随意使用"，可能掩盖用户在风险感知上的真实行为差异。论文自认 CRUD 相关结论应视为"不确定"而非"否定风险校准委派"。
- **缺乏自我报告数据**：未采集满意度、偏好或信任量表，因此无法将行为观测与主观体验关联，也无法验证"倾向性信任"这一解释机制——论文明确将其定位为"解释而非结论"。
- **条件分配不完美**：分配发生在注册而非完成时，且流失不均导致各组人数不均衡，无法完全排除选择效应。
- **任务顺序单一**：所有参与者按同一顺序完成 16 个任务，练习效应和疲劳效应与任务位置混淆，无法检验顺序影响。
- **重定向可能混淆导航计数**：每次工具调用成功后系统自动导航，此事件被计为一次页面导航。虽然这使结果偏向保守，但确实意味着"导航数"并非纯粹的用户主动行为指标。
- **单一模型限制**：仅使用 Gemini 3.1 Flash-Lite，模型的能力、延迟和错误行为很可能影响委派决策，结论不应被解读为与模型无关。
- **应用域单一**：仅测试了 CMS 域中的 CRUD 任务，任务本身的语义简单且明确，无法外推到决策支持、创意生成等更复杂的代理场景；提出的设计建议（如不为委派设置默认值、优化单次交接、在代理路径上设置保障）也尚未经过实证检验。
