## 摘要
真实用户研究对于理解人们如何与被测试或已部署的系统进行交互非常重要。然而，在实践中，它们通常成本高昂、耗时且难以扩展。为解决这些挑战，我们引入了PersonaEval，一个基于用户画像的用户模拟框架，可在多种交互设置中近似真实用户行为。PersonaEval将来自现有用户画像数据集的模拟用户连接到特定任务的应用界面，并收集交互轨迹和结果。PersonaEval提供了一种即插即用的评估工作流，其中被评估的应用可以轻松更换。在本次演示中，我们在三种交互式应用形式上展示了PersonaEval：调查问卷、聊天机器人和网页应用。这些例子共同表明，PersonaEval可以在不同交互设置中支持可重复、可并行和可扩展的评估，同时产生面向用户的反馈和特定任务的行为。

## Abstract
Real user studies are important for understanding how people interact with systems under test or already deployed. In practice, however, they are often costly, time-consuming, and difficult to scale. To address these challenges, we introduce PersonaEval, a persona-based user simulation framework that approximates real-user behavior across diverse interactive settings. PersonaEval connects simulated users drawn from existing persona datasets to task-specific application interfaces and collects the interaction trajectories and outcomes. PersonaEval provides a plug-and-play evaluation workflow in which the application being evaluated can be easily changed. In this demo, we present PersonaEval on three forms of interactive applications: surveys, chatbots, and web applications. Together, these examples show that PersonaEval can support repeatable, parallelizable, and scalable evaluation across different interaction settings, while producing user-oriented feedback and task-specific behavior.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心架构

PersonaEval采用模块化设计，由三大核心组件构成：

1. **Persona API（用户画像接口）**——模拟用户侧
   - 将一个人物画像模型包装为"模拟用户"；
   - 接收分配的人物画像（persona）和任务指令，通过任务所需的接口生成下一步用户行为；
   - 行为形式取决于应用类型：可以是问卷回答、聊天消息或浏览器操作。

2. **Task API（任务接口）**——应用侧
   - 封装测试特定应用所需的环境；
   - 定义任务指令、托管或连接被测应用、管理交互协议、提供评估表单；
   - 允许每个任务定义自己的环境和评估标准，同时共享相同的模拟工作流。

3. **对话终止与评估机制**
   - 模拟用户通过结构化 JSON 输出每一步行为（temperature=0.7）；
   - 在交互结束后，同一人物画像条件化的实例以人物身份完成交互后评估表单；
   - 评估反映的是分配用户自身的视角，而非外部裁判的视角。

### 2.2 模拟用户的设计（关键技术细节）

- **系统提示词设计**：将应用上下文、应用描述和渲染后的人物画像文本块组合成系统提示词，并配以"目标-上下文"模板，要求模拟用户：
  - （i）推断一个现实目标及对其重要的约束/偏好；
  - （ii）逐步揭示需求，而非一次性全部暴露；
  - （iii）对应用响应做出反应——确认、反驳或要求澄清；
  - （iv）保持消息简短（1–3句话）。
- **人物画像来源**：来自四个公开数据集的336个精选画像（Nemotron-Personas-USA、PersonaHub、PRIMEX、OASIS），每个画像都是结构化记录（人口统计信息、多个侧面叙事、自由文本背景、明确属性列表），加载器将其渲染为单一连贯的文本块。

### 2.3 人物画像选择流程

- 对每个应用，将应用描述嵌入后，按与应用描述的相似度对画像排序，保留最相近的**50个画像**；
- 这近似于招募背景与应用匹配的真实用户，无需人工筛选即可为每个应用构建50人测试集。

### 2.4 三种任务适配器

| 任务类型 | 交互协议 | 评估方式 |
|---------|---------|---------|
| **问卷（Survey）** | 单次问卷提交；用户阅读产品简报/任务背景，完成结构化问卷 | 基于完成的问卷本身（答案、理由、置信度）+ 验证检查 |
| **聊天机器人（Chatbot）** | 多轮对话；用户形成基于人物的现实目标，逐步揭示需求，可追问/反驳 | 交互后表单：约束满足、偏好匹配、澄清质量、总体评分、评分理由 |
| **网页（Web）** | 基于浏览器的交互；用户陈述具体闭环任务，浏览网站、比较商品、加入购物车、沙盒结算 | 任务完成与否、所选商品、易用性、信息质量、总体评分、理由 |

### 2.5 算法流程（文字描述）

1. **输入**：应用描述、人物画像文本、任务类型；
2. **画像选择**：通过嵌入相似度从人物语料库中选取50个最相关的画像；
3. **初始化**：将画像文本+应用描述+目标上下文模板组装为系统提示词，实例化LLM为模拟用户；
4. **交互循环**：
   - 模拟用户生成下一步行为（JSON格式）；
   - 应用返回响应（聊天消息/网页状态变化/问卷确认）；
   - 重复直到用户设定`done=true`或达到最大轮次（聊天机器人上限8轮）；
5. **后交互评估**：模拟用户以人物身份填写结构化评估表单；
6. **输出**：统一格式的交互轨迹、行为结果、评估报告；
7. **聚合分析**：跨画像聚合评分，按人物群体聚类分析差异。

### 8.1 实验覆盖方面的局限

- **应用覆盖有限**：仅涵盖问卷、聊天机器人和网页三类应用，尚未扩展到游戏、VR/AR、移动应用、语音助手等更广泛的交互范式；
- **人物画像多样性有限**：虽然语料库包含336个画像，但主实验仅使用Nemotron子集，且仅选取50个与应用最相关的画像，可能遗漏边缘用户群体；
- **模型覆盖有限**：仅使用Claude Haiku 4.5作为模拟用户模型，未测试不同LLM（如GPT系列、Llama系列、Gemini）对模拟质量的影响；
- **语言覆盖有限**：所有应用和画像均为英语，未涉及多语言场景。

### 8.2 偏差风险

- **模拟真实性未校准**：论文主动承认"未来工作应校准模拟与人类数据的对比"，当前缺乏对LLM模拟用户与真实用户行为一致性的定量验证；
- **已知的LLM模拟偏差**：此前研究（如Cui et al. 2024）已发现LLM模拟人类实验对象时存在"效应量膨胀"和"敏感话题保真度低"的问题，PersonaEval未对此进行讨论或缓解；
- **满意度分布偏差**：从结果看，人物画像评分的整体分布偏向中等偏低（多数均分在0.5-0.65区间），这可能反映了LLM模拟用户的系统性批评倾向，而非真实用户的实际分布；
- **评估者偏差**：人物一致性评估依赖人类评审，但论文未报告评审者间一致性，也未说明评审者的背景和评估标准。

### 8.3 方法与理论局限

- **缺乏理论框架支持**：论文以系统演示和实证观察为主，未提出关于"为什么人物画像模拟有效"或"何时失效"的理论解释；
- **聚类方法的主观性**：作者承认人物群体是"软主题组"而非清晰分离的类别（silhouette分数仅0.09-0.21），据此解释群体间差异时需要谨慎；
- **缺乏与真实用户研究的定量对标**：未提供"模拟用户可以替代X%的真实用户研究"这类定量结论，限制了实际应用中的可信度；
- **未见代码或公开平台链接**：论文声称"代码和演示视频已上传"，但在提供的文本中未包含具体仓库地址，影响可复现性验证。
