## 摘要
创意人工智能正从单步资产生成迈向长周期多模态制作。尽管近期的生成模型能够合成高质量的图像、视频、音频片段、UI元素、故事板、幻灯片及其他创意资产，但现实世界的创意工作需要的不仅仅是孤立的提示-输出交互。它涉及参考资料、草稿、备选方案、编辑、失败尝试、版本关系、工具操作、评估信号和人类反馈，这些共同构成了一个不断演化的项目状态。现有的基于提示、基于聊天和基于节点的生成系统仅部分支持这一状态，因为它们常常丢弃中间上下文、依赖线性对话，或需要手动指定的工作流。近期的商业系统表明其正转向代理辅助的创意生产，但其封闭的架构使得难以研究代理如何表示上下文、选择工具、修改工件、从失败中恢复以及随时间保持一致性。为了解决这一差距，我们提出了JarvisHub，一个用于长周期多模态创作的原生画布创意代理框架。JarvisHub将可编辑的画布视为用户工作区、代理的外部记忆、行动空间和共享项目状态，将多模态工件、依赖关系、版本和反馈表示为类型化的画布节点和链接。通过画布状态、协议桥接和代理运行时三层架构，JarvisHub使代理能够在可检查和可编辑的创意状态中行动。这一设计将创意代理从孤立的工具使用推向持续的、可由人类引导的创意自动化，代理可以逐步规划、生成、修订和组织多模态项目，同时用户能够在整个过程中进行检查、指导和干预。

## Abstract
Creative AI is moving from single-step asset generation toward long-horizon multimodal production. Although recent generative models can synthesize high-quality images, videos, audio clips, UI elements, storyboards, slides, and other creative assets, real-world creative work requires more than isolated prompt-output interactions. It involves references, drafts, alternatives, edits, failed attempts, version relations, tool actions, evaluation signals, and human feedback, which together form an evolving project state. Existing prompt-based, chat-based, and node-based generation systems only partially support this state, as they often discard intermediate context, rely on linear conversations, or require manually specified workflows. Recent commercial systems indicate a shift toward agent-assisted creative production, but their closed architectures make it difficult to study how agents represent context, choose tools, revise artifacts, recover from failures, and maintain consistency over time. To address this gap, we introduce JarvisHub, a canvas-native creative agent harness for long-horizon multimodal creation. JarvisHub treats an editable canvas as the user workspace, the agent's external memory, action space, and shared project state, representing multimodal artifacts, dependencies, versions, and feedback as typed canvas nodes and links. Through a three-layer architecture of canvas state, protocol bridge, and agent runtime, JarvisHub enables agents to act within an inspectable and editable creative state. This design moves creative agents beyond isolated tool use toward sustained, human-steerable creative automation, where agents can progressively plan, generate, revise, and organize multimodal projects while users remain able to inspect, guide, and intervene throughout the process.

## 2. 方法论：JarvisHub 的设计

### 核心思想

JarvisHub 将**可编辑画布**（Canvas）同时视为用户工作区、代理的外部记忆、行动空间和共享项目状态。多模态工件、依赖关系、版本和反馈都被表示为类型化的画布节点与链接，代理通过“观察→决策→执行→写回”的循环持续操作画布。

### 三层架构

1. **画布状态层（Canvas State Layer）**：存储多模态工件的节点内容、属性、布局、版本和依赖链接。
2. **协议桥（Protocol Bridge）**：在代理与画布之间执行受控交互，负责能力清单、执行授权、操作格式校验、权限管理和日志记录。
3. **代理运行时（Agent Runtime）**：负责规划、调用工具、同步状态并记录轨迹，整合画布工具、媒体生成、原生执行、恢复机制和 MCP 扩展。

### 关键技术细节

**画布状态的形式化定义**：

```
Ct = (Gt, Xt, Mt, Ut, Lt),  Gt = (Vt, Et)
```

- Gt 为带类型的工件图，Et 表示有向类型化关系（引用、版本谱系、生成依赖、分组、工作流延续等），Xt 存储可编辑内容，Mt 存储来源与执行元数据，Ut 记录用户选择与反馈，Lt 存储空间布局。
- 每个节点可表示为 vi = (id_i, k_i, p_i, x_i, y_i, m_i, s_i)，涵盖稳定标识符、节点类型、位置、可编辑输入、生成输出、来源信息和运行状态。
- 该表示提供三个关键特性：**可寻址性**（引用特定候选而非模糊描述）、**可复用性**（中间产物可作后续输入）、**依赖可检查性**（可追溯影响结果的素材与版本）。

**协议约束的动作空间**：

```
At = A(Ωt, Γt, Ct, qt)， at ∈ At
```

- 代理的每个动作都必须同时满足：扎根于观察到的画布、由能力清单 Γt 暴露、被执行授权 Ωt 允许、通过协议桥提交。
- 状态转移算子：Ct+1 = F(Ct, at, ot, ft, rt)，其中 ot 为工具观测，ft 为反馈信号，rt 为修复或后续决策。

**工具族**（五大类）：

- 画布工具（更新项目状态，如创建、连接、分组、分支）
- 生成工具（图像、视频、音频等媒体生成）
- 原生工具（浏览器、文件、代码、搜索等外部执行）
- 恢复工具（结构化反馈、验证、检查点、局部修复）
- MCP 工具（在统一契约下扩展外部服务）

**高层工作流支持**：技能（Skills，封装可复用的创意程序）、记忆（Memory，跨轮次保留用户偏好与先验决策）、子代理（Sub-agents，并行探索独立子任务）。

**轨迹形式化**：

```
τ = {(qt, Ct, Γt, Ωt, at, ot, ft, rt, Ct+1)}Tt=1
```

轨迹完整记录每一轮的请求、状态、授权、动作、观测、反馈、修复决策和更新后状态，使创意过程可审查、可恢复、可作为训练数据。

## 6. 主要结论与发现

1. **画布作为共享工作空间**对长周期创意代理至关重要。它不仅提供可视化界面，更充当外部记忆和行动空间，使用户与代理共享同一可编辑状态。
2. **协议约束的画布交互**使得创意过程可审查、可恢复。代理的每次画布修改都会被记录，替代了隐藏在提示词和工具调用中的不透明过程。
3. **JarvisHub 支持更可检查、可复用的代理用创意工作流**。在叙事媒体、Web 开发和演示文稿三类任务中，画布成功保留了跨步骤的上下文，支持了风格一致性和版本管理。
4. **轨迹记录为未来研究提供了基础**。结构化轨迹数据可用于构建项目状态基准、制定过程级评估协议（如上下文保持、工具适用性、依赖正确性、反馈遵循、修复成功率），以及训练未来的创意代理。
5. **过程级分析比最终工件更能刻画代理行为**——一个视觉上良好的结果可能来自脆弱的过程，而一个不完美的结果也可能包含有用的中间产物。

## 7. 优点与亮点

- **概念创新**：将"画布"从用户界面提升为代理的外部记忆与共享项目状态，是对"长周期创意代理需要什么运行时"这一问题的清晰回答。
- **架构设计清晰**：三层架构（画布状态、协议桥、代理运行时）职责分明；状态、动作和轨迹都有严格的形式化定义（公式 1-5），理论严谨性较高。
- **受控行动空间**：能力清单 Γt 和授权 Ωt 的双重约束避免了代理随意修改项目状态，兼顾灵活性与安全性。
- **反馈机制显式化**：将用户/模型/子代理的反馈作为状态转移的显式输入，使修正和恢复成为可追踪的一等公民。
- **轨迹记录完整**：τ 的每一轮都包含 10 个要素，为可解释性、可恢复性和后续研究数据建设奠定了结构基础。
- **开放性与可复现性**：提供项目页面和 GitHub 开源仓库，利于社区复现与扩展。
- **工具族设计**：通过 MCP 扩展机制兼顾开放性和统一契约，不局限于特定生成模型。

## 8. 不足与局限

- **实验缺乏量化验证**：仅有三个定性案例，无 benchmark、无消融、无用户研究、无统计显著性分析，无法客观衡量框架在不同条件下的增益幅度。
- **无对比实验**：未能证明 JarvisHub 相对于现有基于聊天或基于节点的系统在过程可检查性、效率或输出质量上确有可量化的优势。

- **语义正确性缺乏保证**：协议桥确保画布操作在格式和权限上合法，但不验证代理创意决策本身的语义合理性。
