## 摘要
生成式用户界面（GenUI）有望根据用户的任务和需求提供个性化界面。然而，用户需求往往是隐性的：系统难以推断，用户也难以清晰表达，因此用户很难获得理想的界面。我们提出偏好引出式用户界面（Elicitive UIs），这是一种将偏好引出方法作为界面本身的一部分来生成的 GenUI 设计方法。偏好引出式用户界面会根据用户、任务和界面调整这些方法，以引出用户偏好。为指导其设计，我们归纳出一个由六个维度构成的设计空间，描述界面引出用户偏好的方式。通过两项使用设计探针开展的用户研究，我们发现，偏好引出式用户界面能够促使用户形成此前尚未明确的偏好；用户对偏好引出方式的反应在不同用户之间的差异大于不同任务之间的差异。用户对于希望如何被询问逐渐形成了更稳定的偏好，这表明偏好引出过程本身也具有个性化的潜力。

## Abstract
Generative user interfaces (GenUI) promise personalized interfaces to a user's tasks and needs. However, user needs are often implicit---difficult for systems to infer and users to articulate, making it hard for users to arrive at their ideal interface. We propose Elicitive User Interfaces, a design approach to GenUI that generates elicitation techniques as part of the interface itself. Elicitive UIs adapt these techniques to the user, task, and interface to draw out user preferences. To guide the design of Elicitive UIs, we synthesize a six-axis design space that shapes how an interface elicits user preferences. Across two user studies with a design probe, we found that while Elicitive UIs surfaced preferences users had not already formed, and that responses to elicitation varied more across users than across tasks. Users developed more consistent preferences for how they wanted to be elicited, suggesting an opportunity to personalize elicitation itself.

## 1. 核心问题与研究动机

- **核心问题**：生成式用户界面（GenUI）可以按任务生成界面，但用户未必事先知道自己想要什么，也未必知道界面哪些部分可以修改。系统仅靠初始提示词，难以获得这些隐含需求。
- **研究洞察**：界面不仅呈现设计结果，也影响用户能否发现、形成并表达偏好。一个看起来已经完成的界面，可能让用户以为布局和功能都已定型；即使用户想修改，也可能担心文字指令误改其他部分。
- **整体含义**：生成式界面需要设计的不只是“生成什么”，还包括**如何在生成和使用过程中询问用户、展示可选方案，并让用户安全地修改局部决策**。

## 2. 方法论与技术实现

### 核心思想：偏好引出式用户界面

论文提出 **Elicitive User Interfaces（EUIs）**：把偏好探询机制直接生成为界面的一部分，并根据用户、任务及当前界面，决定询问什么、如何询问、何时询问。

作者归纳出六个描述探询方式的设计维度：

| 维度 | 设计问题 |
|---|---|
| 完成度（Fidelity） | 提问时展示完整界面，还是仍可修改的低保真草图？ |
| 显著性（Saliency） | 提示应当隐蔽、环境式呈现，还是主动吸引注意？ |
| 数量（Amount） | 一次呈现多少问题、备选方案或待定区域？ |
| 频率（Frequency） | 提示出现一次、持续保留，还是随界面变化再次出现？ |
| 主动程度（Assertiveness） | 只标示可修改处、提出建议，还是要求回答后再继续？ |
| 位置（Placement） | 将提问关联到具体数值、组件、区域，还是整个界面？ |

### Ditto 设计探针的流程

作者实现了可生成工作界面的原型 **Ditto**，支持澄清问题、文本计划、低保真草图、候选方案、问号标记、空白槽位、可编辑面板等 **12 种探询技术**。其流程大致为：

1. **确定任务约束**：考虑界面是否会被反复使用、错误假设的后果、用户间需求差异，以及用户能否在看到界面前说清需求。
2. **先生成界面，再识别待确认决策**：找出生成过程中作出的排序、偏好假设、信息省略等决策；排除用户已经明确指定或有清晰惯例的决策。
3. **确定探询形式并渲染**：沿相关设计维度决定提问的位置和方式，检查是否符合任务约束，再把探询附着到界面元素。探询文案由模型生成，视觉形式和回应控件由原型预设。
4. **处理用户回应**：用户回答后，相应决策不再视为待定，提示消失；后续修改引入新决策时可以出现新提示。

实现上，Ditto 使用 Python 服务端、React 客户端和沙箱化界面；论文报告使用 **Claude Sonnet 5** 生成及修改界面，使用 **Claude Haiku 4.5** 识别候选决策并定位设计维度。论文没有提出需要训练的新模型或数学优化公式。

## 3. 实验设计、场景与对比

论文采用的是**设计空间构建与用户研究**，而非标准数据集上的模型 benchmark。

- **形成性研究（10 人）**：参与者评价预先用 Claude Artifacts 生成的界面，场景为学习信用评分、撰写申请信、规划受预算及饮食限制的聚会。研究记录他们想保留或修改什么，以及是否能说出替代方案。
- **用户研究 1（12 人、36 个任务会话）**：每人使用 Ditto 完成学习、规划、写作三类任务中的各一个，具体题目由参与者选择。前两次会话由系统选择探询技术；第三次允许参与者自行选择。研究记录探询展示与操作，并收集访谈、评分和问卷。
- **用户研究 2（3 人、共 19 次会话）**：邀请研究 1 的参与者在约三至四天内处理自己的真实任务。前三次会话不使用个人探询档案；之后根据交互与反馈建立、更新档案，以观察偏好是否稳定及参与者如何理解档案。

**对比基线与 benchmark**：论文没有使用公开标准数据集，也**没有直接设置“无探询 GenUI”或“固定探询方式 GenUI”的受控对照组**。其比较主要是不同探询维度、技术、用户、任务，以及个人历史与汇总历史对后续反馈的预测差异；因此不能将结果解读为 EUIs 相对于传统 GenUI 的严格性能提升。

## 5. 实验规模与充分性

- 研究规模包括：形成性研究 **10 人**；用户研究 1 **12 人、36 次会话**；用户研究 2 **3 人、19 次会话**。研究 1 共展示 **330 个探询标记**，其中 **139 个最终得到用户操作（42%）**。
- **充分之处**：既有早期问题发现，也有多任务使用和短期重复使用；结合行为日志、评分与访谈，能够考察“用户有没有操作”之外的体验。
- **证据边界**：样本量较小，重复使用阶段仅 3 人；研究 1 中 12 人有 8 人接受过设计或前端相关教育。论文未报告标准意义上的消融实验，缺乏随机化受控基线。用户与任务差异的方差分析虽方向一致，相关检验**未达到常规显著性水平**，应视为探索性发现，而非确定的总体规律。

## 6. 主要结论与发现

- **探询有助于形成偏好**：在获得评分的偏好中，**63%** 被参与者报告为看到探询标记后才产生的想法，而非原本已有的需求。
- **未点击不等于无价值**：参与者有时利用备选方案确认当前界面已经合适，或借提示思考其他可能性；因此，单凭点击率衡量探询价值并不充分。
- **呈现方式影响体验**：更显著的标记更常被操作；低保真草图让界面显得更可修改；贴近组件的提示有助于明确修改范围。但更多提问并不稳定地带来更高参与度，问题是否相关更重要。
- **个体差异值得关注**：研究 1 中，用户身份解释的观测差异大于任务类别；重复使用研究还显示，参与者对“希望如何被询问”形成了一定程度的持续偏好。相比逐个选择提示，他们更愿意用可调节的个人档案设定默认探询方式，再按任务微调。

## 7. 亮点

- **将“如何询问用户”提升为独立设计对象**，而不是把偏好收集局限于对话框或生成后的文字修改。
- **六维设计空间具有可操作性**：能够描述从低保真草图到局部提示的不同技术，也为后续扩展提供共同语言。
- **兼顾偏好形成与修改安全感**：通过展示备选方案、标明局部修改范围，回应了用户“不知道还能改什么”和“担心改错范围”两类障碍。
- **关注隐性反馈**：指出保留现状、忽略提示或仅借提示思考，也可能包含有意义的用户判断。

## 8. 不足与局限

- **缺乏受控基线**：无法分离“加入探询”与“自适应选择探询技术”各自带来的收益，也无法证明最终界面优于普通 GenUI。
- **未验证下游任务效果**：主要测量偏好表达、操作和主观感受；尚未证明改后的界面能提高任务效率、可用性、决策质量或长期满意度。
- **决定“问什么”的能力仍是瓶颈**：六维空间主要指导“怎么问”，值得询问哪些决策则很大程度上依赖模型和启发式规则；系统仍可能问琐碎问题、漏掉关键需求。
- **推广性有限**：参与者人数少、背景不均衡，长期研究时间短；不同任务及用户群体中的效果仍需验证。用户与任务差异的统计证据也需要更大样本支持。
- **个性化信号不易解释**：用户不操作某提示，可能意味着不感兴趣、认可现状、没注意到或暂时不想修改；直接把操作记录当作稳定偏好，存在误判风险。
