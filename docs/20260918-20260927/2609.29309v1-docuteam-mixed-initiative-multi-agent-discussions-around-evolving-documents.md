## 摘要
在开放式问题求解中，协作者常通过讨论发现问题、质疑不同观点，并随着共同成果的演进不断完善它。尽管 AI 智能体日益被用作讨论伙伴，现有多智能体系统仍要求用户主动发起并精心组织讨论，给用户带来较大负担。我们提出 DocuTeam，一个混合主动式多智能体讨论系统，用户和智能体均可发起并引导对话。智能体监测文档变化，随着工作进展主动发起讨论或调整讨论方向；用户则可以灵活地塑造对话，或采纳智能体的想法。在一项被试内研究（N=20）中，与基线系统相比，使用 DocuTeam 的参与者产出的成果在新颖性、相关性和具体性方面获得了显著更高的评价，且认知负荷并未增加。参与者并非仅将智能体用于一次性获取创意，而是参与了一个迭代完善的循环：文档变化引发智能体回应，进而促使用户重新审视并进一步发展自己的工作。

## Abstract
In open-ended problem solving, collaborators often rely on discussion to surface concerns, challenge perspectives, and refine shared work as it evolves. While AI agents are increasingly used as discussion partners, existing multi-agent systems place a heavy burden on users to initiate and carefully orchestrate the discussions. We present DocuTeam, a mixed-initiative multi-agent discussion system in which both users and agents can initiate and steer conversations. Agents monitor document changes to proactively start and redirect discussions as the work evolves, while users can flexibly shape the conversation or adopt agent ideas. In a within-subjects study (N=20), participants using DocuTeam produced outcomes rated significantly more novel, relevant, and specific than with a baseline without any increase in cognitive load. Rather than using agents for one-off idea sourcing, participants engaged in an iterative refinement loop in which document changes prompted agent reactions, which led users to revisit and further develop their work.

## 1. 核心问题与整体含义

- **研究问题**：在写作、规划等开放式任务中，如何让多个 AI 智能体像团队成员一样，随着共享文档的变化主动发现问题、展开讨论，同时不迫使用户持续发起和编排对话？
- **研究动机**：已有多智能体讨论系统通常依赖用户提出问题、指定讨论对象并推动后续轮次；已有文档内主动式助手则多提供单个智能体的反馈，缺少持续的智能体间讨论。两类系统都未充分支持“边修改文档、边与智能体团队讨论”的协作方式。
- **整体含义**：论文将文档从被处理的对象提升为**人和智能体双向协调的媒介**：用户的修改为讨论提供信号，智能体的讨论又促使用户重新审视、完善文档。

## 2. 方法论：DocuTeam 如何工作

- **设计依据**：研究者先组织了 15 人的在线设计工作坊，提炼出四项需求：支持不同讨论目的；让用户低成本掌握讨论焦点与进展；允许直接或间接引导讨论；便于选择性地将讨论成果写回文档。
- **文档内交互**：DocuTeam 作为浏览器扩展运行于 Notion。讨论绑定到具体文档块，以气泡显示参与智能体、话题摘要和未读状态；侧栏提供完整对话及结构化摘要。用户可将某条发言或摘要项拖入文档，由系统按上下文和行文风格调整。
- **混合主动式讨论**：
  - 用户可以将智能体拖到目标文档块，选择**创意、讨论、评价**三种模式之一，并可补充问题。
  - 系统监测文档编辑，以 **2 秒防抖**合并修改并过滤琐碎编辑；随后结合修改内容及邻近文档块判断讨论需求。相关智能体分别为三种模式给出 0—1 分；若某模式的平均分超过经预试确定的 **0.75** 阈值，系统便主动开启讨论。
  - 用户可以发言、增减参与智能体；当讨论取决于用户尚未说明的偏好或取舍时，智能体也可以请求澄清。
- **讨论引擎流程**：首先从文档范围、任务背景、模式及用户输入中提取讨论焦点；随后由后台主持智能体反复决定由谁发言、是否询问用户、或是否结束讨论。发言智能体依据角色设定、对话历史和长期记忆，以提出议题、主张、支持、反驳或提问等方式推进交流。每轮后系统更新记忆与界面摘要。三种模式分别侧重扩展选项、厘清权衡、评价现有内容。
- **实现模型**：论文报告使用 OpenAI API，其中 `gpt-5-mini` 生成智能体发言，`gpt-4o-mini` 承担其他大模型组件；附录给出了主要提示词。

## 3. 实验设计与对比基线

- **场景与任务**：正式研究使用两个开放式活动策划任务——学术工作坊规划、跨院系运动会规划。参与者依据已有的未完成草案、限制条件及利益相关者需求，在文档中完善方案。论文**没有使用公开数据集或标准化 benchmark**。
- **被试与流程**：20 名参与者完成被试内研究，每人分别使用 DocuTeam 和基线系统完成一个任务，共得到 **40 份最终方案**。条件顺序和任务进行了平衡安排；每个任务的实际策划时间为 30 分钟。另有两名具备相关活动策划经验的外部评价者，在不知道实验条件的情况下评价最终方案。
- **对比方法**：基线同样提供多智能体讨论，并使用**相同的讨论引擎和摘要流程**，但主要采用独立侧栏中的用户发起式对话：不提供智能体主动发起讨论，也不提供与具体文档块绑定的原位交互。它比单智能体基线更能检验整套交互设计的价值，但不能分离各项功能的独立贡献。

## 6. 主要结论与发现

- **成果质量**：与基线相比，DocuTeam 方案的新颖性（3.20 对 2.68，*p*=0.047）、相关性（3.30 对 2.78，*p*=0.048）和具体性（3.25 对 2.28，*p*=0.001）显著更高；**可行性无显著差异**（*p*=0.623）。
- **协作过程**：用户用于引导讨论的消息平均从 **5.0 降至 2.7**；文档增删改词数从 **322.95 升至 448.70**；采纳进文档的讨论消息数从 **9.0 升至 12.3**。访谈显示，用户更常围绕已写内容展开讨论，而非只通过聊天获取一次性创意。
- **工作负荷与感受**：总体 NASA-TLX 评分差异**不显著**（*p*=0.169），不能据此断言两者负荷完全相同。参与者一方面减少了编排对话的工作，另一方面也需要处理更多并发的智能体信息；其结果信心和满意度同样未见显著提升。
- **核心机制性解释**：论文认为“修改文档—触发讨论—重新审视并修订”的循环，有助于把不同观点落实为更具体、更贴合约束的方案；这一解释同时得到日志与访谈支持，但并非经过独立机制实验验证。

## 7. 优点

- **交互设计有明确问题导向**：不是简单增加智能体数量，而是处理主动性、用户控制权和讨论可理解性之间的权衡。
- **讨论紧贴实际工作**：具体文档块的锚定和选择性写回，减少了聊天内容与工作成果之间的转换成本。
- **比较基线较强**：双方使用相同讨论引擎，使比较更聚焦于整套交互方式。
- **证据类型互补**：将成果盲评、行为日志、负荷问卷和访谈结合，既观察产出，也分析协作过程。

## 8. 不足与局限

- **泛化范围有限**：样本量为 20，参与者具有大模型使用经验；两项任务均为限时活动策划，尚不清楚结论能否推广到长期写作、研究或视觉设计工作。
- **功能效应难以拆分**：基线与 DocuTeam 同时在主动讨论、文档定位和原位操作等方面不同，缺少消融实验。
- **负荷与打扰风险仍在**：部分用户感到信息量大、初期学习成本高；“负荷差异不显著”不等于已证明系统不会增加负荷。论文也发现，多数参与者很少阅读预设的文字摘要，说明讨论进展的呈现方式仍待改进。
- **质量与评估边界**：可行性没有改善，评价者认为两种条件下的计划都可能因时间限制而不够完整。论文也未独立评估对话的自然度、事实可靠性或长期实用性。
- **潜在偏差与部署问题**：智能体视角取决于角色配置和模型生成，可能遗漏重要立场或产生貌似充分、实则重复的争论；对文档持续监测还涉及实际部署中的隐私、调用成本和触发频率控制，本文未作系统评估。
