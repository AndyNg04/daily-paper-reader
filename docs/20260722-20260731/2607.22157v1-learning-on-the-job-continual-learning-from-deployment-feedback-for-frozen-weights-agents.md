## 摘要
AI智能体在每一轮运行中都会遇到学习机会，却几乎全部丢弃：底层模型在部署时被冻结，因此一个今天解决了棘手请求的智能体，明天该请求重现时又从零开始。然而，常规运行本身就会产生反馈，形式包括结果判定和事后修正。我们证明，当冻结模型配有一个外部记忆，将每一轮经验蒸馏为可检索的自然语言规则时，这些反馈就是持续学习的充分信号。在τ-bench的银行领域，与在完整策略语料上进行检索的静态RAG对照组相比，利用单比特结果判定学习可将单次尝试成功率提升至基线的1.6倍，利用修正学习则可提升至2.6倍，并解决了基线从未解决的84个任务中的22个。该结果适用于整个部署谱系，在Mistral Large上测得——这是一种有数据主权要求的组织可自行托管的开放权重模型——并在前沿模型Claude Sonnet 5上得到复现。积累的记忆还可以迁移：每个模型读取对方构建的存储库后，都能超越自身无记忆的基线。我们公开了相关工具链、协议和数据。

## Abstract
AI agents encounter learning opportunities in every episode they run, and discard nearly all of them: the underlying models are frozen at deployment, so an agent that resolves a difficult request today starts from zero when it recurs tomorrow. Yet ordinary operation already produces feedback, in the form of outcome verdicts and after-the-fact corrections. We show that this feedback is a sufficient signal for continual learning when the frozen model is paired with an external memory that distils each episode into retrievable natural-language rules. On the banking domain of $τ$-bench, against a static-RAG control retrieving over the complete policy corpus, learning from the one-bit outcome verdict lifts single-trial success to 1.6$\times$ the baseline, and learning from corrections to 2.6$\times$, converting 22 of the 84 tasks the baseline never solves. The result spans the deployment spectrum, measured on Mistral Large, an open-weights model that organisations with data sovereignty requirements can self-host, and replicated on a frontier model, Claude Sonnet 5. The accumulated memory also transfers: each model, reading the store built by the other, rises above its own no-memory baseline. The harness, protocol, and data are released.

# 论文详细总结

## 1. 核心问题与整体含义

- **核心问题**：AI 智能体在部署后其底层模型权重被冻结，每次运行中产生的学习机会几乎全部被丢弃。一个今天能解决某类难题的智能体，明天遇到同样的问题时依然从零开始。
- **现状瓶颈**：
  - 经典持续学习依赖权重更新，但训练基础设施、灾难性遗忘风险、每轮更新后的重新评估与安全审查成本极高，许多组织难以承担。
  - 行业普遍使用的 RAG 只能提供静态知识，无法从部署经验中积累新知识。
- **关键观察**：实际部署中天然存在监督反馈——客户是否接受方案、人工是否修改了 AI 草稿、合规检查是否通过等，但这些反馈没有被用于学习。
- **论文主张**：将冻结模型与一个外部记忆库配对，利用部署中已有的反馈信号，以“蒸馏为自然语言规则 + 检索复用”的方式实现无需梯度更新的持续学习。

## 2. 方法论

- **核心思想**：冻结模型权重不变，通过外部的可演化自然语言记忆库承担学习角色；每个回合结束后，将经验蒸馏为紧凑的 WHEN–THEN 规则存入记忆库，后续相关场景中检索并复用。
- **记忆系统 Spark**：
  - 记忆单元为 *insight*：包含标题、内容、检索查询（以未来 agent 可能提出的问题形式编写），可选标签。
  - Agent 接口提供四个工具：`memory_search`（检索）、`memory_create`（新建）、`memory_enrich`（增补）、`memory_feedback`（反馈有用性），形成“读-贡献-反馈”循环。
  - 知识生命周期：入库时经安全过滤、质量门、去重折叠；后台运行修剪、冲突消解、抽象合成等策展操作，全程无人工参与。
- **两种反馈信号**：
  - *结果判定（outcome verdict）*：一个比特，最终数据库状态是否与 ground truth 匹配，是部署中最弱的反馈。
  - *修正（correction）*：任务失败后，一次性提供验证过的标准动作序列，对应“已解决的工单/专家评审/政策裁定”。
- **三种实验条件**：
  - **baseline**：基准 agent + 静态 RAG（BM25 检索完整政策语料），无记忆。
  - **experience**：只从单比特结果判定学习；失败时只允许写入“避免类”规则，不得臆造正确动作。
  - **instruction**：失败时额外获得修正；可以写入验证过的正确规则。
- **记忆集成机制**：
  - 读路径：完全由 agent 自主发起 `memory_search`，系统不主动注入；首轮消息附带提醒，鼓励在关键行动前复查记忆。
  - 写路径：所有写入发生在回合结束后的专用反思回合，回合中禁止中途写入，防止不成熟错误污染记忆。
  - 写入约束：每条一个 WHEN–THEN 规则；关键决策值必须逐字保留并由校验器强制；不得弱化或冲突已验证规则；仅允许一种受控合并（双胞胎情境的分支规则）。
- **指标设计**：
  - `pass^k`：沿用 benchmark 原定义，但指明在记忆条件下试验间存在耦合，上升一致性是研究对象而非协议违规。
  - 增加**每试次成功率曲线**（per-trial success curve）反映获取过程。
  - 增加**保持率（hold rate）**：任务在试次 t 通过后，t+1 再次通过的概率，作为知识保留的操作化度量。

## 3. 实验设计

- **数据集 / 场景**：τ-bench 的银行领域（含 τ-Knowledge 扩展），97 个任务，每个任务是多轮客服对话，由 LLM 扮演隐藏角色与目标的模拟客户。任务成功判定为程序化、完全确定性（除 1 个任务）。政策库约 700 篇相互关联的文档，agent 需通过 BM25 检索自行发现规则和工具。
- **Benchmark 特性**：任务核心依赖模型不具备的外部专有知识；公开前沿结果单次成功率仅约 25%，即使 gold 配置（关键文档直接放入系统提示）也仅约 40%，适合检验记忆带来的增量。
- **模型**：
  - 两个 agent 模型：Mistral Large（2512 版，开放权重，可自托管）和 Claude Sonnet 5（前沿模型，中等推理强度）。
  - 客户模拟器：GPT-5.2，与 benchmark 公开榜单配置一致。
- **对比方法**：
  - 无记忆 baseline（静态 RAG 对照，检索完整政策语料）。
  - experience 模式（仅结果判定）。
  - instruction 模式（结果判定 + 修正）。
  - 跨模型迁移：冻结另一模型 instruction 运行积累的存储库，消费者只读，与自身无记忆 baseline 对比。
- **实验协议**：每个条件对全部 97 任务各跑 4 次试验（共 388 场对话/条件）；记忆条件从空记忆开始并跨试验保留；任务调度按“试次优先”（trial-major）；每个条件使用独立的全新记忆库。

## 4. 资源与算力

- **论文未明确说明**使用的 GPU 型号、数量或训练/推理时长。
- 仅可推断：使用了 Mistral Large 2512、Claude Sonnet 5、GPT-5.2 三个模型 API/自托管推理；所有实验属于推理型评估（无权重训练），总对话数约 388 × 6 个条件 ≈ 2300+ 场，具体硬件资源不可知。

## 5. 实验数量与充分性

- **实验规模**：
  - Mistral Large：3 个条件（baseline / experience / instruction），每个 97×4 = 388 对话。
  - Claude Sonnet 5：2 个条件（baseline / instruction），同样规模；experience 因成本考虑省略。
  - 跨模型迁移：2 个方向（Sonnet 存储 → Mistral 读取；Mistral 存储 → Sonnet 读取），各 4×97 对话。
  - 另有 per-task 结果网格、分层分析（floor/competent）、保持率与对比区间等诊断。
- **充分性评估**：
  - **优点**：覆盖开放式权重模型与前沿模型，能检验方法对不同能力水平的普适性；三个条件对比设计干净，以静态 RAG 为强基线，排除“仅靠检索增强”的解释；迁移实验直接验证可移植性。
  - **不足**：所有条件均为单次运行，没有重复运行以估计 run-to-run 变异；experience 模式只在一个模型上测试；仅覆盖单一领域（银行），外部效度受限。
- **公平性**：对比在相同任务集、相同试次协议下进行；基线本身已能检索完整政策语料，因此任何提升都归因于记忆而非单纯的附加检索；配对对比按任务进行，使用 cluster bootstrap 处理任务内相关性，统计上较严谨。

## 6. 主要结论与发现

- **反馈信号足以驱动持续学习**：
  - Mistral Large：pass^1 从 baseline 的 0.064 提升至 experience 的 0.103（1.6×）和 instruction 的 0.170（2.6×）；解决基线从未解决的 84 个任务中的 22 个（experience 仅 5 个）。
  - Claude Sonnet 5：instruction 将 pass^1 从 0.248 提至 0.397，提升在绝对值和相对值上均更大，说明外部记忆不仅补偿弱模型。
- **学习曲线特征**：冷试次上三种条件几乎相同（空记忆无贡献）；baseline 保持水平，记忆条件随试验上升；效应完全由试次间记忆状态驱动。
- **保持率差异**：experience 保持率为 0.88，instruction 为 0.65；Claude 上 instruction 为 0.83，高于 baseline 的重新抽取持久性 0.70。保持率与转化率之间存在 trade-off。
- **跨模型迁移有效**：
  - Mistral 读 Sonnet 构建的存储：pass^1 从 0.064 升至 0.289（+0.224）。
  - Sonnet 读 Mistral 构建的存储：pass^1 从 0.248 升至 0.314（+0.066）。
  - 两方向在可迁移任务上的转化率均约 31%，说明方向差异主要源于可迁移知识量不同，而非迁移效率不同。
  - 强模型也能从弱模型积累的规则中获益（不同模型解决不同任务集合）。
- **pass^k 的解释性发现**：在内存条件下，pass^4 上三个条件收敛（均 0.031），这是指标结构性导致的：被转化任务若首试失败后保持成功（如 0111），其 pass^4 贡献为 0；因此高 k 无法体现学习优势。论文因此以 per-trial 曲线 + 保持率作为主要度量，pass^k 仅作基准兼容报告。

## 7. 优点

- **问题设计务实**：直接利用部署中天然存在的反馈（结果判定/修正），不要求额外人工标注，贴近企业真实场景。
- **方法轻量且不侵入**：冻结权重 + 外部记忆，无需训练基础设施，规避灾难性遗忘，也无需每次更新的安全重审。
- **严格的写入契约**：经验模式下失败只写“避免类”规则，防止臆造；关键值逐字校验；已验证规则不可随意改写，保证记忆精度。
- **实验对照严密**：以覆盖完整语料的静态 RAG 为基线，所有提升都归因于记忆动态；冷试次对齐、分层分析（floor/competent）增强了因果论证。
- **统计严谨**：任务级 cluster bootstrap、配对对比、保留率与重抽持久性的区分，避免将随机再抽误认为知识保留。
- **跨模型迁移作为一级实验对象**：不仅报告效果，还量化可迁移任务数、转化率，且区分“知识量”与“迁移效率”。
- **开源与可复现**：发布 harness、协议、数据，配合固定随机种子的分析代码。

## 8. 不足与局限

- **领域与模型覆盖有限**：只在一个领域（τ-bench 银行）、两个模型上验证；experience 模式仅在 Mistral Large 上运行，Claude 上的体验学习效果未测。
- **单次运行无方差估计**：所有条件单 run，区间只反映任务抽样，不含 run-to-run 变异；跨任务耦合虽被作者论证为弱，但缺乏直接重复实验验证。
- **反馈可靠性假设过强**：实验中反馈由确定性评估器提供，完全可靠；真实部署反馈常延迟、缺失或噪声化，论文将噪声容忍度划为未来工作。
- **不测泛化能力**：记忆只覆盖“当前任务复现”场景，不评估对未见任务类型的泛化；作者以先前编码域研究作为广度的补充证据，但本实验未直接验证。
- **pass^k 指标在记忆条件下存在误导**：虽然论文通过结构性解释揭示了问题，但沿用该指标仍有被误读的风险。
- **存储维护依赖自治策展**：实际运行中安全过滤、去重、冲突消解等环节若出现错误可能累积，论文未讨论策展失败对长期记忆质量的影响。
