## 摘要
编码代理（例如 Cursor）通过优化任务完成来提高开发者的生产力，但将用户从编写代码转变为提示和审查可能损害他们的理解，从而阻碍监督、学习和沟通。为了探究这一点，我们让 54 名学生使用两种 AI 系统之一创建网站：一种编辑用户代码的代理；或一种聊天机器人，用户在其中独自编写代码或改编通用代码片段。我们通过理解性问题和一个用户在没有代理的情况下扩展代码的任务来测试理解，结果显示：（1）虽然代理有助于初始任务完成，但它们损害了用户的代码理解，因此未能让用户准备好扩展代码；（2）低努力度的代理交互类型，如复制粘贴提示和自动接受的编辑，与较低的理解相关；（3）尽管自我报告的理解较弱，用户仍然更喜欢编码代理，因为它们快速且易于使用。虽然用户保持在编码工作流程的循环中，但不应该忘记理解。为了实现这一目标，我们将分析提炼为编码代理开发者的未来研究方向：劝阻低努力度的提示、创建可读代码和促进积极投入。

## Abstract
Coding agents (e.g., Cursor) improve developer productivity by optimizing task completion, but shifting users from writing code to prompting and reviewing may harm their understanding, impeding oversight, learning, and communication. To probe this, we have 54 students create a website with one of two AI systems: an agent that edits user code; or a chatbot where users write code alone or adapt generic code snippets. We test understanding via comprehension questions and a task where users extend their code without agents, showing: (1) While agents aid initial task completion, they harm users' code comprehension and thus do not prepare users to extend their code; (2) Low-effort agent interaction types, like copy+paste prompts and auto-accepted edits, are linked with lower comprehension; and (3) Despite self-reported weaker understanding, users still prefer coding agents because they are quick and easy to use. While users stay in the loop for coding workflows, understanding should not be forgotten. Towards this goal, we distill our analyses into future research directions for coding agent developers: dissuading low-effort prompting, creating readable code, and promoting active engagement.

- **核心问题**：编码代理（Coding Agents，如 Cursor）在提升开发者生产力的同时，是否会损害开发者对代码的理解？
- **研究背景**：编码代理将开发者的角色从"编写代码"转变为"提示与审查"（prompting and reviewing），这一转变可能带来认知层面的代价——理解力下降，进而影响用户的**监督能力**（能否发现AI错误）、**学习过程**（能否通过写代码获得技能）和**沟通能力**（能否与他人讨论代码）。
- **深层含义**：论文呼应人机交互中"自动化悖论"的经典议题——工具越强大，使用者的技能越可能退化。在AI编程场景中，这种退化尤其隐蔽，因为用户"留在回路中"（stay in the loop），却可能只是机械地执行提示与接受，并未真正理解代码。作者认为，**理解不应成为追求效率的牺牲品**。

## 6. 论文的主要结论与发现

1. **代理提升初始任务完成效率，但损害代码理解**：使用编码代理的参与者虽然更顺利地完成了网站搭建，但在理解性测试中得分更低，且在无代理的扩展任务中表现不佳——即代理并未帮助用户准备好独立演进代码。
2. **低努力交互模式与低理解显著相关**：诸如"直接复制粘贴 AI 生成的提示"、"不加审查地自动接受 AI 编辑"等交互行为，与更差的代码理解呈正相关。这暗示**交互的认知投入程度**是理解力变化的关键中介。
3. **用户仍偏好编码代理**：尽管用户自我报告理解较弱，他们依然倾向于选择代理，原因是**快和易用**——效率优先的偏好压过了对理解的担忧。
4. **核心呼吁**：用户虽然"在回路中"，但理解不应被遗忘。论文为编码代理开发者提炼了三个改进方向：**劝阻低努力提示（dissuade low-effort prompting）、生成可读代码（create readable code）、促进主动参与（promote active engagement）**。

## 7. 优点

- **问题重要且时效性强**：直击 AI 编程工具大规模普及下的核心隐患——技能退化与盲目信任。
- **研究设计巧妙**："扩展任务"设计能有效区分"完成任务的能力"与"真正理解代码的能力"，避免以任务完成度替代理解力的常见测量偏差。
- **多维度证据链**：同时收集客观表现、行为日志和主观感受，能揭示"用户感知—实际理解—行为模式"之间的复杂关系。
- **行为层面归因**：不只停留在"代理 vs 聊天机器人"的二元对比，还深入分析了交互模式（如复制粘贴、自动接受）与理解力的关联，提供了更细粒度的解释。
- **提出可落地的设计建议**：结论能直接转化为编码代理的功能改进方向，对工业界有现实指导意义。

## 8. 不足与局限

- **样本范围有限**：54 名学生参与者，样本量偏小，且学生群体不能完全代表专业开发者的行为模式（专业开发者可能更擅长审查 AI 代码）。
- **单任务设计**：仅使用网站构建任务，任务类型单一，未覆盖算法实现、维护、调试等其他编程场景，结论的普适性存疑。
- **短期测量**：只在任务结束后立即测量，未追踪长期影响——理解力下降是否持续、是否可通过适应工具而缓解，均未回答。
- **工具代表性**：只对比了代理和聊天机器人两类系统，但实际工具谱系更丰富（如代码补全、代码审查助手等），结论难以直接推广。
- **无法完全排除混杂因素**：两类条件下的用户交互界面和体验差异较大，可能影响参与者的投入程度、学习动机等，进而间接影响理解力，论文未完全控制这些变量。
- **测量理解的工具本身存在局限**：理解题和扩展任务能否完整反映真实开发中的"代码理解"，尚值得商榷。
- **潜在偏向风险**：研究者提出的设计建议（如劝阻低努力提示）可能增加用户认知负担，与代理追求效率的核心卖点存在张力，论文对此权衡讨论不够充分。
