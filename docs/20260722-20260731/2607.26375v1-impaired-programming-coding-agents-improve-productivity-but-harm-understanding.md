## 摘要
编码智能体（例如Cursor）通过优化任务完成来提升开发者的生产力，但将用户从编写代码转变为提示和审查，可能会损害他们的理解，从而妨碍监督、学习和沟通。为了探究这一点，我们让54名学生使用两个AI系统之一创建网站：一个能编辑用户代码的智能体；或一个聊天机器人，用户在其中单独编写代码或改编通用代码片段。我们通过理解类问题以及一个用户在没有智能体的情况下扩展代码的任务来测试理解力，结果表明：（1）虽然智能体有助于初始任务完成，但它们损害了用户的代码理解，因此不能帮助用户扩展其代码；（2）低努力智能体交互类型，如复制粘贴提示和自动接受的编辑，与较低的理解力相关；（3）尽管用户自我报告理解力较弱，他们仍然更喜欢编码智能体，因为它们快速且易于使用。虽然用户保持在编码工作流程的循环中，但不应忽视理解。为此，我们将分析提炼为编码智能体开发者的未来研究方向：劝阻低努力提示、创建可读代码，并促进主动参与。

## Abstract
Coding agents (e.g., Cursor) improve developer productivity by optimizing task completion, but shifting users from writing code to prompting and reviewing may harm their understanding, impeding oversight, learning, and communication. To probe this, we have 54 students create a website with one of two AI systems: an agent that edits user code; or a chatbot where users write code alone or adapt generic code snippets. We test understanding via comprehension questions and a task where users extend their code without agents, showing: (1) While agents aid initial task completion, they harm users' code comprehension and thus do not prepare users to extend their code; (2) Low-effort agent interaction types, like copy+paste prompts and auto-accepted edits, are linked with lower comprehension; and (3) Despite self-reported weaker understanding, users still prefer coding agents because they are quick and easy to use. While users stay in the loop for coding workflows, understanding should not be forgotten. Towards this goal, we distill our analyses into future research directions for coding agent developers: dissuading low-effort prompting, creating readable code, and promoting active engagement.

## 1. 核心问题与整体含义（研究动机与背景）
- **研究现象**：以 Cursor 为代表的编码智能体（coding agents）正被大量开发者采用，其设计目标是最大化“任务完成”效率（如自动编辑代码、预测下一步动作），从而显著提升生产力。
- **核心矛盾**：这类工具将用户角色从“代码编写者”转变为“提示管理者”与“代码审查者”，可能削弱用户对代码的深度理解（包括系统架构、逻辑细节等），进而带来三重风险：
  - **监督困难**：不理解代码难以有效审查与纠错；
  - **学习受阻**：新手难以通过实践积累编程能力；
  - **沟通障碍**：无法与他人有效讨论、维护或交接代码。
- **整体含义**：论文试图在“AI提升效率”这一普遍共识之外，揭示其“认知代价”，并提出：**效率不应以牺牲理解为代价**，用户判断力、长期能力和协作可靠性都需要被重新重视。

## 2. 方法论
- **核心思想**：通过受控用户实验，比较两种不同类型的 AI 辅助编程系统对用户理解力的影响：
  - **智能体系统（Agent）**：能直接“读取并修改用户代码”，用户主要做提示与审查；
  - **聊天机器人系统（Chatbot）**：用户自行编写代码，或只能“复制粘贴、改编通用代码片段”，AI 不直接接触用户真实代码。
- **技术细节**：
  - 54 名参与者在上述两种系统中任选其一，任务是**创建并完成一个网站**；
  - 测试包含两个维度：
    1. **理解力测试**：基于理解类问题（comprehension questions）考察用户对代码的认知程度；
    2. **扩展性测试**：在不借助智能体的前提下，要求用户扩展自己先前编写的代码，考察真实应用能力。
- **分析维度**：将用户与智能体的交互行为进行分类（如复制粘贴提示、自动接受编辑等），并统计各类行为与理解力之间的相关性。

- **Benchmark**：自定义理解力测试题和“扩展代码任务”作为评估标准。
- **对比方法**：智能体 vs. 聊天机器人（两种代表性 AI 开发工具范式）。
- **被试**：54 名学生，包含多元背景但不限制编程水平。

  - **优点**：实验设计在受控条件下比较两种工具生态，任务真实、测量维度双重（测试+实践），能够直接回答“理解是否受损”这一核心问题；

## 6. 主要结论与发现
1. **效率与理解不可兼得**：智能体确实有助于初始任务完成（初始生产力更高），但因理解被削弱，用户**无法有效扩展原有代码**，其长期能力不升反降。
2. **交互模式影响认知投入**：低努力交互（例如复制粘贴提示、自动接受 AI 编辑）与较低的理解力显著相关；即“动手越少，懂得越少”。
3. **用户自评与行为背离**：尽管用户**自报理解能力较弱**，但依然更偏好编码智能体，主要原因是“快速、易用”。这种偏好可能导致用户低估或忽视潜在的认知退化。
4. **未来研究方向**（为编码智能体开发者）：
   - 劝阻低效/低努力的提示行为；
   - 生成可读性更强的代码；
   - 设计促进用户主动参与和思考的交互机制。

## 7. 优点（亮点）
- **研究问题时机精准**：直接切中当前 AI 编程工具热需，回应了“人类是否在失去编程能力”这一广泛关切。
- **实验设计具备生态效度**：使用真实的网站开发任务，而非抽象的代码测试，提高了结论的现实意义。
- **多维度检验理解力**：既用理解性问题考察显性认知，又用“在无智能体条件下扩展代码”的任务考察程序性能力，后者更接近真实工程场景。
- **交互行为分析与可操作建议相结合**：以数据识别出“低努力交互”这一具体风险因素，并提出具体改进方向，对开发者有直接指导意义。

## 8. 不足与局限
- **实验结果的可重复性与外部效度**：54 名学生样本量较小，且以学生为主，未必代表在职开发者；
- **概念测量的边界**：“理解”是一个多层面概念，本测试可能过于聚焦任务可得的结果，未涵盖深层代码心智模型或跨项目迁移能力；
- **自我报告与现实行为的偏差**被识别但在统计模型中未能完全控制；
- **未考虑长期学习效应**：一次性实验无法反映数周/数月内理解力的变化趋势；
- **工具与任务范围有限**：仅对比两种系统类型、仅采用单一网页构建任务，结论对移动端、系统编程或大规模团队开发等场景的适用性还有待验证。
