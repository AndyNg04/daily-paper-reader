## 摘要
个人AI助手日益被部署为面向任务、工具增强的代理，在统一服务环境中运行以支持日常用户活动。在现实场景中，此类助手必须对持久用户状态进行推理，尊重用户特定的配置和权限，并在跨多个服务的长时间跨度、约束感知交互中保持持续性。然而，现有基准测试常常将服务上下文碎片化或抽象掉用户状态，限制了它们在现实服务环境中评估用户中心个人助手行为的能力。我们引入了PAUSE，一个用于在状态化、服务集成环境中评估个人AI助手的用户中心基准。PAUSE通过要求代理协调异构用户自有资源上的操作，同时保持与环境状态、多轮交互中的授权约束的一致性，捕捉了真实世界助手部署的核心挑战。该基准通过逼真的用户模拟纳入显式用户-代理交互，使评估超越静态工具执行。为了支持原则性和可复现的评估，PAUSE采用了一个与任务特征一致的多机制评估框架。开放式服务管理任务使用语义和轨迹级行为度量进行评估，而约束密集型任务则允许确定性的、基于状态的验证。基准结果显示，即使是最先进的专有模型，在需要状态化推理和配置感知的场景中，任务完成率也未能达到70%，揭示了一致且可解释的失败模式。最后，我们提出了一个用户中心的合成流程，能够可扩展地生成连贯的服务环境、用户配置和可靠标注的任务，支持基准的可扩展性和未来研究。

## Abstract
Personal AI assistants are increasingly deployed as task-oriented, tool-augmented agents that operate within unified service environments to support everyday user activities. In realistic settings, such assistants must reason over persistent user state, respect user-specific configurations and permissions, and sustain long-horizon, constraint-aware interactions across multiple services. Existing benchmarks, however, often fragment service contexts or abstract away user state, limiting their ability to evaluate user-centric personal assistant behavior in realistic service settings. We introduce PAUSE, a user-centric benchmark for evaluating personal AI assistants in stateful, service-integrated environments. PAUSE captures core challenges of real-world assistant deployment by requiring agents to coordinate actions across heterogeneous user-owned resources while maintaining consistency with environment state, authorization constraints over multi-turn interactions. The benchmark incorporates explicit user-agent interaction via realistic user simulation, enabling evaluation beyond static tool execution. To support principled and reproducible evaluation, PAUSE adopts a multi-regime evaluation framework aligned with task characteristics. Open-ended service management tasks are assessed using semantic and trajectory-level behavioral metrics, while constraint-intensive tasks admit deterministic, state-based verification. Benchmark results show that even state-of-the-art proprietary models fail to reach 70% task completion on scenarios requiring stateful reasoning and configuration awareness, revealing consistent and interpretable failure patterns. Finally, we present a user-centric synthesis pipeline that enables scalable generation of coherent service environments, user configurations, and reliably annotated tasks, supporting benchmark extensibility and future research.

## 2. 方法论

### 2.1 核心思想
- **用户中心**：所有任务都基于持久、用户自有资源和权限构建，覆盖健康数据追踪、账户检查、日程安排、购物、计划管理等多种日常活动。资源访问由用户显式控制，助手不能假设拥有完全访问权。
- **整体性系统配置**：所有服务共享一个持久、统一的系统配置（权限、资源可用性、钱包状态、订阅状态等），单个任务往往涉及多个服务及权限、状态的联动变化。

### 2.2 环境建模
- 状态形式化：隐环境状态 s_t = (D_u, I_u, C_u)，分别表示用户数据、用户画像/账户信息、系统与用户配置。助手通过部分观察 o_t = Ω(s_t, h_t) 获取信息。
- 双控制环境：扩展了 τ²-Bench 的双控制设置，用户可控制系统关键状态和配置（如钱包充值、权限授予），交互序列为用户指令 → 助手工具调用 → 观察 → 助手回复 → 用户操作 → 下一轮。
- 环境特征：多粒度时间数据（需时间推理）、57 个工具（50 个助手工具 + 7 个用户工具）构成的大工具空间、需要从工具响应中推断的隐含系统配置、以及对原始数据/外部服务资源的门控访问。

### 2.3 用户中心任务生成管线（三阶段）
- **第一阶段——用户中心任务生成**：初始配置 s_t0 = I(D, D_k)，其中 D 为模板采样的基础结构化用户数据，D_k 为模板 k 决定的任务注入数据（活动记录、可穿戴设备数据）。每个模板定义为 T_k = {E_k, P_task_k, P_rollout_k, O_k, D_k}。LLM 联合生成用户任务指令 q 和一组可验证的目标条件 τ。
- **第二阶段——引导式轨迹回滚**：在回滚提示 P_rollout_k 引导下，多个 SOTA LLM 与系统和用户代理进行真实执行交互，采集多条候选轨迹。用 Gemini-3-Flash 等作为用户代理进行角色扮演。
- **第三阶段——目标对齐验证**：LLM 评审委员会对候选轨迹进行筛选，生成摘要并挑选最优轨迹；无满意轨迹时触发带反馈的优化重生成。最终将选定的轨迹与目标集 τ 对齐，无法满足全部目标的任务被移除。

### 2.4 多机制评估框架
- **数据与日志追踪任务（开放式，无唯一解）**：采用 LLM-as-judge 目标评估，以可验证目标集 τ 为核心打分信号，目标完成率 TC = (1/m)·Σ I(τ_j)。同时补充轨迹级重叠指标（Precision / Recall / F1），基于工具调用的多集匹配计算：P = Σ min(c_M, c_ˆM) / Σ c_ˆM，R = Σ min(c_M, c_ˆM) / Σ c_M。
- **购物任务（约束密集型，具有显式状态）**：采用确定性状态验证，分解为多个可验证目标（目标产品识别 PID、数量与尺寸 Qty_Size、优惠券 Voucher、预算 Balance），按目标满足度聚合评分，不依赖参考轨迹。

### 2.5 消融设计
- 通过在评估回滚中加入参考轨迹生成时的策略引导提示 P_rollout_k（显式说明系统配置语义），检验系统配置感知对代理推理的影响。

## 6. 主要结论与发现

- **总体性能**：即使最强专有模型在需要状态推理和配置感知的任务上，任务完成率也未达到 70%，且失败模式具有一致性和可解释性。
- **数据与日志追踪任务**：
  - 简单任务上顶级专有模型接近饱和（GPT-5 达 95.26%，Gemini-3-Pro 92.06%，GPT-5-Mini 92.07%），但困难任务显著下降（Gemini-3-Flash 59.12%、Gemini-3-Pro 48.39%），揭示配置推理是当前模型的普遍短板。
  - 困难任务显著增加对话轮次和工具调用次数，且用户工具调用仅出现在困难任务中，验证了用户中介操作的不可回避性。
- **购物任务**：专有模型总体领先，但 Qty_Size、Voucher、Balance 等状态化环节表现明显低于 PID，说明多约束优化与状态转换管理仍是难点。DeepSeek-V3.2-Thinking 在购物任务上表现出接近专有模型的竞争力，可能因为购物任务对时间推理要求较低。
- **错误模式分层**：强模型（Gemini-3-Flash）主要败在系统配置推理；中等模型（DeepSeek-V3.2-Thinking）额外存在数据计算/时间推理问题（长上下文中时间信息丢失导致工具入参错误）；弱模型（GPT-4.1）在基础数据一致性和资源导航上也表现不佳。
- **策略引导消融**：显式配置策略可显著降低系统配置错误（Gemini-3-Flash 提升最大），但无法弥合全部模型间差距，说明更深的推理与接地问题无法仅靠提示解决。
- **LLM-as-judge 可靠性**：强评估器（Gemini-3-Pro 87.2/85.1，GPT-5 84.6/83.4）与人类判断高度一致；弱评估器（GPT-5-mini）一致率较低，倾向于仅基于被评估轨迹本身而非参考摘要判断。

## 7. 优点

- **基准定位新颖**：填补了从“工作流中心/工具隔离”到“统一、用户中心服务环境”评估的空白，更贴近真实部署场景。
- **环境设计富有挑战性**：隐含配置、门控工具、多粒度时间数据、用户中介的状态转换，综合构成对助手推理能力的多维度考验。
- **多机制评估框架**：按任务性质匹配评估方式（开放式用 LLM-as-judge+轨迹重叠、约束型用确定性状态验证），兼顾灵活性与严谨性；跨指标一致性验证增强了评估可信度。
- **可扩展的合成管线**：三阶段（生成→回滚→验证）管线可规模化产出连贯环境、用户配置与可靠标注任务，支持基准扩展、数据蒸馏和后续训练。
- **可解释的误差分析**：结构化错误分类（DCE/TBE/RNE/SCE/OTHER）+案例研究，揭示了模型失败模式的层级差异。
- **支持开源开放**：代码已在 GitHub 发布（https://github.com/hyc481/PAUSE），遵循 CC BY 4.0 许可。

## 8. 不足与局限

- **抽样稳健性指标缺失**：未系统报告 pass^k / pass@k 等多次运行指标（论文自我承认），单次运行可能引入随机性偏差。
- **验证严谨性有提升空间**：开放式任务缺乏对所有关键变量的显式状态验证；论文指出人类验证轨迹与目标型 LLM 评估大体一致，但协议本身未强制执行这一更强约束。
- **模型覆盖有限**：开源模型仅覆盖 DeepSeek-V3.2 系列，未包含 Llama、Qwen、Mistral 等其他主流开源模型，可能影响结论的普适性。
- **领域单一**：基准实例化于个人健康管理领域，尽管环境设计有通用性，但对跨领域（如金融、教育、出行等）的泛化尚未验证。
- **评估器偏差风险**：LLM-as-judge 依赖评估器能力（GPT-5-mini 一致性明显较低）；默认评估器与部分被测模型同族（Gemini），存在潜在评估偏差。
- **算力信息缺失**：未报告任何计算资源消耗，不利于复现成本估量和同类工作横向比较。
- **生成管线依赖 LLM 质量**：任务生成、回滚、筛选都依赖强 LLM（GPT-5、Gemini 等），若底层模型存在系统性缺陷，可能传入基准本身。
