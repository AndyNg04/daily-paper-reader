## 摘要
个人AI助手正越来越多地被部署为面向任务的、工具增强的智能体，在统一的服务环境中运行，以支持用户的日常活动。在现实场景中，此类助手必须对持久化的用户状态进行推理，尊重用户特定的配置和权限，并在多个服务间维持长时程、约束感知的交互。然而，现有基准测试往往将服务上下文碎片化或抽象掉用户状态，限制了其在现实服务环境中评估以用户为中心的个人助手行为的能力。我们提出了PAUSE，一个用于在状态化、服务集成环境中评估个人AI助手的以用户为中心的基准。PAUSE通过要求智能体在异构用户自有资源间协调行动，同时保持与环境状态的一致性以及多轮交互中的授权约束，捕捉了现实世界助手部署的核心挑战。该基准通过逼真的用户模拟纳入显式的用户-智能体交互，使评估超越静态工具执行。为支持有原则且可复现的评估，PAUSE采用了与任务特性对齐的多机制评估框架。开放式服务管理任务使用语义和轨迹级行为指标进行评估，而约束密集型任务则可采用确定性的、基于状态的验证。基准测试结果表明，即使是最先进的专有模型，在需要状态化推理和配置感知的场景下，任务完成率也未能达到70%，这揭示了一致且可解释的失败模式。最后，我们提出了一个以用户为中心的合成流水线，能够可扩展地生成连贯的服务环境、用户配置以及可靠标注的任务，支持基准的可扩展性和未来研究。

## Abstract
Personal AI assistants are increasingly deployed as task-oriented, tool-augmented agents that operate within unified service environments to support everyday user activities. In realistic settings, such assistants must reason over persistent user state, respect user-specific configurations and permissions, and sustain long-horizon, constraint-aware interactions across multiple services. Existing benchmarks, however, often fragment service contexts or abstract away user state, limiting their ability to evaluate user-centric personal assistant behavior in realistic service settings. We introduce PAUSE, a user-centric benchmark for evaluating personal AI assistants in stateful, service-integrated environments. PAUSE captures core challenges of real-world assistant deployment by requiring agents to coordinate actions across heterogeneous user-owned resources while maintaining consistency with environment state, authorization constraints over multi-turn interactions. The benchmark incorporates explicit user-agent interaction via realistic user simulation, enabling evaluation beyond static tool execution. To support principled and reproducible evaluation, PAUSE adopts a multi-regime evaluation framework aligned with task characteristics. Open-ended service management tasks are assessed using semantic and trajectory-level behavioral metrics, while constraint-intensive tasks admit deterministic, state-based verification. Benchmark results show that even state-of-the-art proprietary models fail to reach 70% task completion on scenarios requiring stateful reasoning and configuration awareness, revealing consistent and interpretable failure patterns. Finally, we present a user-centric synthesis pipeline that enables scalable generation of coherent service environments, user configurations, and reliably annotated tasks, supporting benchmark extensibility and future research.

  - 或聚焦于窄领域、API调用准确率，忽略持久用户状态、配置权限等真实场景；
  - 或采用MCP式大规模工具编排，将问题简化为“工作流执行”，抽象掉了统一的、以用户为中心的服务环境。
- **核心问题**：现实中的个人助手必须对持久化用户状态、隐藏的系统配置、权限门控资源、多服务间的状态依赖进行推理，并需要与用户显式交互以解决约束冲突。现有基准无法全面评估这些能力。
- **研究意义**：提出PAUSE基准，弥补“有状态、以用户为中心、统一服务环境”这一维度的评测空白，为真实场景下的个人AI助手能力评估提供基础。

  2. **受引导的轨迹回放**：用策略引导提示 \(P^{rollout}_k\) 约束模型行为，让若干LLM在真实执行环境中与模拟用户多轮交互，收集候选轨迹。

## 3. 实验设计
- **数据集与场景**：PAUSE实例化在“个人健康管理”领域，模拟集成了可穿戴设备（Fitbit、小米等）、第三方健康服务、医疗预约、购物等服务的统一平台。
- **基准规模**：通过合成流水线生成300多条候选任务，最终筛选出180条任务：
  - 63条数据与日志追踪（简单）任务；
  - 57条数据与日志追踪（困难）任务；
  - 60条购物任务（长上下文多约束优化）。
- **对比模型**：
  - 专有模型：GPT-5、GPT-5-Mini、GPT-4.1、GPT-4.1-Mini、Gemini-3-Pro、Gemini-2.5-Pro、Gemini-3-Flash；
  - 开源模型：DeepSeek-V3.2（含/不含思考模式）。
  - 使用Gemini-3-Flash作为默认评估者，并做LLM与人类评估一致性检验，评估者还包括GPT-5、Gemini-3-Pro等。

## 6. 主要结论与发现
- 在最先进的专有模型（GPT-5、Gemini-3系列）在**数据与日志追踪（简单）**任务上可接近饱和（如GPT-5达到95.26% TC），但在**困难任务**上大幅下降（最好模型Gemini-3-Flash仅59.12% TC），整体均未达到70%的任务完成率。
- 购物任务中，各个模型在“产品识别”上表现较好，但**在数量/尺寸选择、优惠券使用、预算管理**等状态约束环节明显薄弱，说明即使强模型也难以可靠地处理多步购买流程中的状态转换。
- 错误分析显示：
  - 强模型主要失败在**系统配置推理**（如未识别外部数据源未连接、未发现权限/订阅约束）；
  - 弱模型则更多出现**数据计算错误、资源导航错误**等基础问题。
- 消融实验表明：显式提供配置策略提示可显著降低强模型的系统配置错误（尤其对Gemini-3-Flash），但对弱模型效果有限，说明仅靠提示无法弥补深层推理和基础能力缺陷。
- LLM-as-judge与人类评估一致性较高（强评估模型约85%左右），但在困难任务上评估器能力不足时（如GPT-5-mini）一致性下降，提示评估器选择很重要。

## 7. 优点
- **环境设计真实且具有挑战性**：统一有状态环境、隐式配置、门控工具、用户权限控制，能区分不同能力层级的模型。
- **多机制混合评测**：既有LLM语义判别，又有轨迹行为重叠，还有确定性状态验证，兼顾开放性与鲁棒性，比单一评测范式更具可信度。
- **可扩展的合成流水线**：能够自动生成连贯环境、用户配置、任务与参考轨迹，并设有目标对齐筛选，保证任务可行性。
- **错误分析细致**：对代表性模型分类错误模式，提供具名案例分析，帮助诊断模型失败根因。
- **评估结果可复现**：提供代码仓库，并明确许可协议（CC BY 4.0）。

## 8. 不足与局限
- **未报告pass^k/pass@k**：缺乏多次尝试通过率的统计，对随机性影响的评估不充分。
