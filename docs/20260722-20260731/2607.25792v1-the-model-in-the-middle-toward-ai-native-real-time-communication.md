## 摘要
全双工全模态模型正在将人机交互从基于回合的交流转变为连续的、多模态的对话，其中说话、倾听和推理同时进行。我们并不将模型视为人类端点的替代品，而是提出一种新的视角：模型是位于以人为中心的反馈环路内部的有状态计算中间盒，其中网络传输、模型服务和用户播放共同塑造交互的演化。这一视角打破了围绕局部目标设计的传统阶段边界。与其孤立地优化这些阶段，一个AI原生的实时堆栈应允许每个阶段的状态塑造其他阶段的行为。我们探索了三种跨阶段协调机会：网络感知的推理调度、执行感知的传输优先级排序，以及同时考虑网络和模型可变性的播放控制。我们正在构建Conflux来探索这些想法，初步结果表明，在网络退化的情况下，响应延迟和播放截止时间遵从性取得了显著改善。更广泛地说，我们呼吁建立一个AI原生的实时通信堆栈，以解决跨越通信、计算和播放的联合控制问题。

## Abstract
Full-duplex omni models are transforming human--AI interaction from turn-based exchanges into continuous multimodal conversations in which speaking, listening, and reasoning unfold concurrently. Rather than viewing the model as a replacement for a human endpoint, we argue for a new perspective: the model is a stateful computational middlebox inside a human-centered feedback loop, with network transport, model serving, and user playback jointly shaping how the interaction evolves. This perspective breaks the traditional boundaries among stages designed around local objectives. Rather than optimizing them in isolation, an AI-native real-time stack should allow the state of each stage to shape the actions of the others. We explore three cross-stage coordination opportunities: network-aware inference scheduling, execution-aware transport prioritization, and playback control that accounts for both network and model variability. We are building Conflux to explore these ideas, and preliminary results show substantial improvements in response latency and playback deadline adherence under network degradation. More broadly, we call for an AI-native real-time communication stack that resolve the joint control problem spanning communication, computation, and playback.

### 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型正从基于回合的问答模式，向实时、全双工、多模态交互演进（如 Gemini Live、GPT-Live、Qwen-3.5-Omni-Realtime 等）。用户可以在对话中随时打断、指向新视觉证据、连续调整意图，说话、倾听与推理同时进行。
- **核心问题**：传统实时通信（RTC）和 LLM 服务都基于“发送者—接收者”抽象，各阶段（网络传输、模型推理、用户播放）围绕各自局部目标孤立优化。但在全双工交互中，网络延迟决定模型输入何时可用，模型服务决定输出何时进入下行链路，播放必须同时吸收网络和模型带来的抖动——三者构成一个紧密耦合的闭环系统，孤立优化已无法满足需求。
- **论文核心主张**：将全双工模型重新定位为**人类反馈回路中的有状态计算中间盒**（stateful computational middlebox），而非人类端点的替代品。在此基础上，呼吁构建一个 **AI 原生的实时通信栈**，通过块（chunk）级别的跨阶段协调，联合求解涵盖通信、计算与播放的控制问题。

### 2. 方法论：核心思想、关键技术细节

**核心思想：Chunk 作为跨阶段协调的统一基板。**
- 每个上行 chunk 代表一个有界交互窗口（如 500ms），包含多模态对齐数据（音频、视频帧、文本、控制事件）。chunk 在传输、推理、播放各阶段流转时，可携带并累积跨阶段信号（如剩余延迟预算），同时保持稳定的身份标识。
- 各阶段无需理解 chunk 的语义含义，只需通过执行级属性（execution-level properties）进行协调。

**关键技术细节——三个跨阶段协调机会：**

1. **网络感知的推理调度（Network-aware inference scheduling）**
   - 传统调度器基于服务端本地信号（排队时间、请求年龄、GPU 效率）做准入和批处理决策。
   - 论文提出：chunk 到达模型时已累积了不同的网络延迟，剩余延迟预算不同。调度器应为每个 chunk 计算优先级，综合交互状态（如是否 barge-in、轮次转换）、最近 QoE 和网络状况，决定是立即执行、等待批处理、还是丢弃过时输入。
   - 核心公式（Box 1）：优先级函数 𝑃(𝑠,𝑐) = PriorityFunc(𝐼(𝑠,𝑐) + 𝑄(𝑠) + 𝑁(𝑠))，其中 𝐼 为交互状态、𝑄 为 QoE、𝑁 为网络质量；当候选批次中所有 chunk 的优先级总和超过阈值 𝜃 时立即准入，否则等待批处理。

2. **执行感知的传输优先级（Execution-aware transport prioritization）**
   - 全双工交互中的各模态天然具有不同的传输需求（表 2）：控制事件高紧急、高可靠、不可替换；音频高紧急、中可靠、不可替换但可自适应；视频低/中紧急、低可靠、可替换、可自适应；文本中紧急、高可靠、不可替换。
   - 模型应显式暴露一个“模型中心传输规范”（model-centric transport specification），声明各模态的最低保真度、可调操作范围、延迟敏感度、可靠性需求和跨模态对齐约束。传输层据此在不理解语义的前提下实施优先级调度。

3. **联合网络与模型变化的播放控制（Playback control）**
   - 每次模型响应开始时，接收端需建立新的播放时间线。初始播放缓冲 𝑏₀ 的设定是关键权衡：越小则首响应时间（TTFR）越低，但后续 chunk 迟到风险越大（Deadline Miss 升高）。
   - 论文提出基于拥塞控制思想的播放缓冲自适应策略：
     - 当端到端延迟 𝐿_𝑡 超过高阈值 𝜙_high 时，缓冲以乘性因子 𝛾 快速增大；
     - 当 𝐿_𝑡 低于低阈值 𝜙_low 时，缓冲以加性步长 𝛿 缓慢减小；
     - 中间区域为滞回区间，避免抖动引起的振荡。

**系统架构 CONFLUX：**
- 发送端跨层传输、服务端网络感知推理、接收端播放调度三者形成端到端控制闭环。
- 信号类型包括：模型规范（模态要求、推理背压）、网络信号（RTT、带宽、抖动）、播放信号（TTFR、Deadline Miss）。

### 6. 主要结论与发现

- **跨阶段协调能带来显著 QoE 增益**：
  - **TTFR**：CONFLUX 在各网络条件下保持在 1.39–1.88s，优于基线的 1.77–5.41s。在 L1 下改善 21.3%，在 L4（最差网络）下改善达 74.4%。
  - **Deadline Miss**：CONFLUX 在所有网络条件下将每 chunk 平均延迟控制在 10ms 以内；基线则从 L1 的 46ms 恶化到 L4 的 94ms。
- **网络条件会影响模型生成的内容本身**：以 barge-in 为例，网络劣化导致用户打断指令延迟到达模型，模型继续输出过时回复。barge-in 延迟从良好网络的 542.7ms 恶化到受限网络的 5040.9ms——这是传统实时通信中不存在的现象。
- **Chunk 级抽象是可行的协调基板**：通过执行级属性而非语义理解，即可实现跨阶段的有效协调。

### 7. 优点

- **视角创新**：将模型定位为“有状态计算中间盒”而非端点，打破了传统 RTC 和 LLM serving 的发送者—接收者抽象，清晰揭示了全双工 AI 交互中通信、计算、播放三方耦合的本质问题。
- **协调方式的实用性**：强调通过执行级属性（chunk 的延迟预算、模态传输特性）而非在线语义分析实现跨阶段协同，避免了语义理解的高成本（如 CLIP 方案增加 27.13% 推理成本），更具工程可操作性。
- **抽象简洁有力**：chunk 作为统一基板贯穿传输、推理、播放三个阶段，概念清晰、便于实现。
- **模块化系统设计**：CONFLUX 采用模型规范、网络信号、播放信号三方驱动的端到端控制回路，各模块可独立演进和替换。

- **坦诚的实验分析**：承认 TTFR 在 L4 下低于 L3 的非直觉结果，说明策略在不同网络机制下响应不一致，为后续工作留下明确开放问题。
