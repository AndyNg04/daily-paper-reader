## 摘要
创意AI正从单步资产生成转向长周期多模态生产。尽管最近的生成模型能够合成高质量的图像、视频、音频片段、UI元素、故事板、幻灯片及其他创意资产，但现实世界的创意工作需要的远不止孤立的提示-输出交互。它涉及参考资料、草稿、备选方案、编辑、失败尝试、版本关系、工具动作、评估信号以及人类反馈，这些共同构成了一个不断演变的项目状态。现有的基于提示、基于聊天和基于节点的生成系统仅部分支持这种状态，因为它们常常丢弃中间上下文、依赖线性对话或需要手动指定工作流。近期的商业系统表明正在转向智能体辅助的创意生产，但其封闭架构使得研究智能体如何表示上下文、选择工具、修改工件、从失败中恢复以及随时间保持一致性变得困难。为弥补这一空白，我们引入了JarvisHub，一个面向长周期多模态创作、以画布为原生的创意智能体框架。JarvisHub将可编辑画布视为用户工作区、智能体的外部记忆、动作空间和共享项目状态，将多模态工件、依赖关系、版本和反馈表示为类型化的画布节点和链接。通过画布状态、协议桥接和智能体运行时三层架构，JarvisHub使智能体能够在可检查和可编辑的创意状态中运作。这种设计将创意智能体从孤立的工具使用推向持续、可由人类引导的创意自动化，使智能体能够逐步规划、生成、修订和组织多模态项目，同时用户在整个过程中能够检查、指导和干预。

## Abstract
Creative AI is moving from single-step asset generation toward long-horizon multimodal production. Although recent generative models can synthesize high-quality images, videos, audio clips, UI elements, storyboards, slides, and other creative assets, real-world creative work requires more than isolated prompt-output interactions. It involves references, drafts, alternatives, edits, failed attempts, version relations, tool actions, evaluation signals, and human feedback, which together form an evolving project state. Existing prompt-based, chat-based, and node-based generation systems only partially support this state, as they often discard intermediate context, rely on linear conversations, or require manually specified workflows. Recent commercial systems indicate a shift toward agent-assisted creative production, but their closed architectures make it difficult to study how agents represent context, choose tools, revise artifacts, recover from failures, and maintain consistency over time. To address this gap, we introduce JarvisHub, a canvas-native creative agent harness for long-horizon multimodal creation. JarvisHub treats an editable canvas as the user workspace, the agent's external memory, action space, and shared project state, representing multimodal artifacts, dependencies, versions, and feedback as typed canvas nodes and links. Through a three-layer architecture of canvas state, protocol bridge, and agent runtime, JarvisHub enables agents to act within an inspectable and editable creative state. This design moves creative agents beyond isolated tool use toward sustained, human-steerable creative automation, where agents can progressively plan, generate, revise, and organize multimodal projects while users remain able to inspect, guide, and intervene throughout the process.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- **"画布即一切"**：可编辑画布不仅是用户的可视化界面，同时是：
  - 智能体的**外部记忆**（存储所有中间产物）；
  - 智能体的**动作空间**（通过修改画布来执行创作）；
  - **共享项目状态**（用户和智能体共同读写同一份状态）。
- 提示词、参考图、候选结果、编辑记录、版本关系、用户反馈等全部表示为**类型化的画布节点（nodes）和链接（links）**。

### 2.2 三层架构

| 层级 | 职责 |
|------|------|
| **画布状态层（Canvas State）** | 存储多模态工件、属性、布局、版本和依赖链接，以类型化图结构组织 |
| **协议桥接层（Protocol Bridge）** | 校验智能体对画布的读写操作——权限控制、操作格式验证、变更日志记录 |
| **智能体运行时（Agent Runtime）** | 规划动作、调用工具、同步状态、记录轨迹；集成技能库、记忆和子智能体 |

### 2.3 形式化定义

- **画布状态**（公式1）：$C_t = (G_t, X_t, M_t, U_t, L_t)$，其中 $G_t=(V_t, E_t)$ 为类型化工件图，$X_t$ 存储节点内容，$M_t$ 存储来源/执行元数据，$U_t$ 记录用户选择/编辑/反馈，$L_t$ 存储空间布局。
- **节点表示**（公式2）：$v_i = (id_i, k_i, p_i, x_i, y_i, m_i, s_i)$，包含稳定ID、节点类型、位置、输入配置、输出句柄、来源信息和运行状态。
- **状态转移**（公式3）：$C_{t+1} = F(C_t, a_t, o_t, f_t, r_t)$，其中 $a_t$ 为智能体动作，$o_t$ 为工具观察结果，$f_t$ 为反馈信号，$r_t$ 为修复/后续决策。
- **动作空间**（公式4）：$A_t = A(\Omega_t, \Gamma_t, C_t, q_t)$，即当前回合**相关且被许可**的动作集合。$\Gamma_t$ 是能力清单（capability manifest），$\Omega_t$ 是执行授权（execution grant）。
- **轨迹记录**（公式5）：$\tau = \{(q_t, C_t, \Gamma_t, \Omega_t, a_t, o_t, f_t, r_t, C_{t+1})\}_{t=1}^T$，每个回合的完整上下文和决策过程都被记录。

### 2.4 关键设计机制
- **协议桥接的目的**：确保画布更新是**显式、有效、可恢复**的（auditable而非隐蔽在语言生成中）。
- **五大工具家族**：画布工具、生成工具、原生执行工具（浏览器/文件/代码等）、恢复工具（验证/检查点/局部修复）、MCP工具（外部服务扩展）。
- **高层支持机制**：
  - **技能（Skills）**：可复用的创意流程模板（故事板、版式生成、设计转网页等）；
  - **记忆（Memory）**：跨回合保持用户偏好和先前决策；
  - **子智能体（Subagents）**：用于可并行的独立子任务（如多镜头并行探索）。

## 6. 主要结论与发现

1. **画布可以作为智能体的有效工作空间**：将画布作为共享项目状态，智能体能读取、更新、维护跨步骤的创意上下文，实现可检查的长期创作。
2. **协议桥接使画布操作显式且可追溯**：通过能力清单和执行授权约束智能体行为，使每次画布变更都能被记录和审计，而不是隐藏在对话/工具调用中。
3. **轨迹记录是研究创意Agent的关键数据源**：完整轨迹（含用户查询、画布状态、动作、观察、反馈、修复决策和下一个状态）能暴露**过程级失败**，例如忽略参考材料、丢失已接受的选项、覆盖有效变体、局部问题却全局重新生成等。
4. **开放性带来研究基础设施价值**：JarvisHub可支撑未来**项目级基准测试**、**过程级评估协议**（最终工件质量 + 上下文保持、依赖正确性、反馈遵循度）和**训练数据飞轮**（轨迹数据用于训练创意Agent的规划、工具选择、状态追踪和局部修复能力）。
5. **三个任务案例均展示了画布对跨步骤一致性（跨镜头、跨页面、跨幻灯片）的支撑作用**。

## 7. 优点

- **问题定义清晰且重要**：精准捕捉了现有创意AI系统的核心痛点——缺乏对"项目状态"的维护，并给出了严格的数学形式化定义（画布状态、节点表示、状态转移、轨迹）。
- **架构设计有层次感**：画布状态 / 协议桥 / 运行时三层分离，职责明确；协议桥层的设计（校验、授权、日志）实际回应了AI安全与可控性问题，使智能体操作可审计。
- **"画布即外部记忆+动作空间"的提法具有普适性**：不局限于图像/视频/网页等特定领域，而是统一的类型化图结构，可扩展性强。
- **五个工具家族 + 技能/记忆/子智能体的设计务实**：既可编排复杂工作流，又不把逻辑硬编码进框架。
- **针对过程而非只针对结果**：强调轨迹记录和分析，识别出"最终工件好≠过程正确"这一重要洞察，为未来的创意Agent评估提供了方向。
- **完全开放**：提供项目页面和GitHub仓库（LYL1015/JarvisHub），便于复现和社区扩展。
