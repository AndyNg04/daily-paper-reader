## 摘要
理解开发者如何与AI编码助手互动，需要的不仅仅是孤立的聊天日志或git历史；它需要重建完整的背景：哪个提示导致了哪次编辑，开发者尝试并放弃了什么，以及他们的策略如何随时间演变。我们提出RECAP（回放与检查捕获的AI编程），一个开源平台，它（1）被动地记录AI聊天会话和VS Code内部的细粒度代码编辑，不干扰开发者的工作流程，（2）将它们合并到一个统一的时间线中，用于交互式会话回放，以及（3）提供一个可扩展的分析层，包括行为分类和AI依赖度测量的示例模块。在一个大学软件工程课程中部署，RECAP从41名学生跨越多周的项目中捕获了2,034条提示和8,239次代码编辑。我们展示了该平台如何通过链接数据和回放能力，实现对开发者-AI交互模式的分析，这是任何单一数据源都无法支持的。

## Abstract
Understanding how developers interact with AI coding assistants requires more than chat logs or git histories in isolation; it requires reconstructing the full context: which prompt led to which edit, what the developer tried and discarded, and how their strategy evolved over time. We present RECAP (Replay and Examine Captured AI Programming), an open-source platform that (1) passively records AI chat sessions and fine-grained code edits inside VS Code without disrupting the developer's workflow, (2) merges them into a unified timeline for interactive session replay, and (3) exposes an extensible analysis layer, with example modules for behavioral classification and AI reliance measurement. Deployed in a university software engineering course, RECAP captured 2,034 prompts and 8,239 code edits from 41 students across a multi-week project. We demonstrate how the platform's linked data and replay capabilities enable analyses of developer-AI interaction patterns that no single data source could support.

## 1. 研究动机与核心问题
- AI编程助手（如GitHub Copilot、Cursor）已融入日常开发，但理解“开发者如何使用这些工具”需要**重建完整的交互上下文**：哪个提示触发了哪次编辑，开发者看到了什么并接受或放弃了哪些建议，策略如何随项目演变。
- 现有方法面临两大挑战：
  - **链接断裂**：聊天日志与git历史分离，无法追踪提示到编辑的因果链。
  - **长时程缺失**：开发会话跨越数小时甚至数天，远超实验室研究的时间尺度，而现有工具要么仅针对短时任务，要么缺乏对多文件、代理式（agentic）工作流的细粒度记录。
- RECAP旨在通过**被动、完整地记录聊天与代码编辑，构建统一时间线**，为研究人员、教育者和工具开发者提供自然、可回放的观测平台。

## 2. 方法论
RECAP由三个层面组成：**数据采集扩展（VS Code插件）**、**会话回放查看器（Web应用）**以及**可扩展分析层**。

- **数据采集——Copilot Interaction Archiver**
  - **聊天会话捕获**：监控VS Code的工作区存储，当Copilot会话文件创建或修改时，读取完整对话（含用户提示、AI回复、工具调用、代码引用及TEG——文本编辑组），以10秒防抖上传。
  - **代码编辑捕获（Shadow Git）**：在后台维护一个隐藏的git仓库（`.archiver_shadow`），每次文件保存、创建、删除或重命名都会触发提交；未保存的编辑器内更改也以“DIRTY SNAPSHOT”提交捕获（5秒防抖，最大间隔30秒），提供比开发者手动git提交更细粒度的历史。
  - **隐私保护**：用户ID在客户端SHA-256哈希后上传，后端强制路径前缀，扩展仅使用短期预签名URL，不持有云凭证。

- **回放与分析——Session Replay Viewer**
  - **统一时间线**：将影子git提交与聊天事件按时间顺序合并，形成可交互的时间轴。
  - **界面布局**：四面板设计——文件树（展示当前提交的工作区状态，含变更指示器与AI归属标记）、中心差异视图（GitHub风格unified diff，带AI归属标识）、聊天面板（合并所有会话）、时间轴条（彩色事件标记：绿色人工、黄色Copilot、橙色疑似外部来源、蓝色聊天提示、紫色代理动作）。
  - **编辑归属**：通过模糊行级匹配，将聊天回复中的TEG与5分钟窗口内的影子diff关联，按完整匹配、部分匹配、未匹配分类；对未匹配的提交，使用启发式规则（新增内容超过阈值或键入速度>100 WPM）标记可疑外部来源。

- **可扩展分析模块**（示例）
  - **行为分类**：基于LLM，利用17类行为代码对每条提示分类（6个类别：计划、编码、解释、评估、设置、对话），覆盖Ma等人（2026）的类别并补充了Setup与Converse。
  - **AI依赖度测量**：按工作会话（30分钟无活动间隔）分割时间线，计算人均AI编辑比例，可追踪随时间的变化。
  - **提示嵌入与聚类**：多语言句子嵌入→t-SNE降维→KMeans聚类，交互式可视化支持按聚类、学生、模型、时段等着色。
  - 平台还记录了粘贴事件、Copilot调试日志（代理意图、补全事件）、工具调用（终端命令与退出码）等，便于扩展新分析。

- **部署场景**：2026年春季，美国一所R1大学的应用机器学习课程中，41名学生使用GitHub Copilot完成一个为期两周的Zulip项目扩展任务。
- **数据规模**：共采集2,034条提示（29名学生产生聊天数据），8,239次影子git提交（全部41名学生），形成406个工作会话。
- **分析示例**：
  - **行为概况**：提示分类结果显示，“解释”类占比44%（其中“解释错误”占29%），“编码”仅14%，说明学生更多用AI理解而非生成。

## 6. 主要结论与发现
- RECAP能够**在长时间、真实项目中连续捕获代理式AI编程交互**，证明统一时间线对重建上下文的有效性。
- 通过链接的提示-编辑数据，可观察到：
  - 学生更多利用AI进行错误解释与代码理解，而非直接生成代码。
  - 项目过程中AI编辑的比例逐渐下降，提示依赖度可能随任务深入而调整。
  - 回放功能可揭示常规日志无法发现的交互模式（如错误粘贴循环、跨AI工具协调、代理生成在不同复杂度任务中的收敛差异）。
- 平台为未来行为研究提供了可扩展的基础设施。

## 7. 优点
- **端到端集成**：从非侵入式捕获、云存储到交互式回放与分析，构成完整研究流水线。
- **细粒度链接**：通过TEG匹配实现提示→代码编辑的直接因果关联，这是与以往仅分析Chat日志或git历史的本质区别。
- **高时间分辨率**：影子git的“每次保存+脏快照”机制，捕捉到开发过程中的暂存修改与丢弃版本。
- **交互式回放**：可视化时间轴和差异对比，便于研究者直观理解开发者决策过程。
- **隐私设计**：客户端哈希、无云凭证、路径前缀控制，保障数据安全与合规。
- **可扩展性**：分析模块可插拔，且提供粘贴、日志等多条数据流接口。

## 8. 不足与局限
- **平台依赖性强**：目前仅支持VS Code与GitHub Copilot，无法捕获其他IDE（如Cursor、JetBrains）或别的AI助手（如Claude Code、ChatGPT网页版）的交互，导致部分学生多工具使用时的数据缺失。
- **行为分类可靠性**：依赖商业LLM的分类方法，可能引入成本波动和结果不一致，未报告分类性能指标。
- **外部来源启发式误差**：检测“外部AI”打字过快的规则可能导致误判（人工快速键入大段代码可能被标记为外部来源）。
- **泛化性不足**：案例研究仅在一门课程中开展，学生群体和专业开发者行为模式可能存在差异，未进行多站点或纵向验证。
- **实验严谨性**：缺少与现有工具（如Blackbox、DevGPT、Editrail）的横向对比，以及分析模块准确性的定量评测。
