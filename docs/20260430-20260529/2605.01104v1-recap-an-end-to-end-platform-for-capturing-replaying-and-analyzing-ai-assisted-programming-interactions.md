## 摘要
理解开发者如何与AI编程助手互动不仅需要孤立的聊天记录或git历史；它需要重建完整的上下文：哪条提示导致了哪次编辑，开发者尝试并放弃了什么，以及他们的策略如何随时间演变。我们提出了RECAP（回放与分析捕获的AI编程），一个开源平台，该平台（1）在VS Code内部被动记录AI聊天会话和细粒度代码编辑，而不中断开发者的工作流，（2）将它们合并到一个统一的时间线中，用于交互式会话回放，以及（3）暴露一个可扩展的分析层，带有行为分类和AI依赖度测量的示例模块。在一个大学软件工程课程中部署后，RECAP从41名学生跨多周项目中捕获了2,034条提示和8,239次代码编辑。我们展示了该平台的关联数据和回放能力如何使得分析开发者与AI的交互模式成为可能，而这些模式是任何单一数据源都无法支持的。

## Abstract
Understanding how developers interact with AI coding assistants requires more than chat logs or git histories in isolation; it requires reconstructing the full context: which prompt led to which edit, what the developer tried and discarded, and how their strategy evolved over time. We present RECAP (Replay and Examine Captured AI Programming), an open-source platform that (1) passively records AI chat sessions and fine-grained code edits inside VS Code without disrupting the developer's workflow, (2) merges them into a unified timeline for interactive session replay, and (3) exposes an extensible analysis layer, with example modules for behavioral classification and AI reliance measurement. Deployed in a university software engineering course, RECAP captured 2,034 prompts and 8,239 code edits from 41 students across a multi-week project. We demonstrate how the platform's linked data and replay capabilities enable analyses of developer-AI interaction patterns that no single data source could support.

- **核心目标**：提供一个端到端的开源平台，能够在不干扰开发者工作流的前提下，被动记录AI对话与代码编辑，并将其融合为可交互回放、可扩展分析的统一时间线，从而支持更自然、更全面的开发者- AI 交互研究。

## 2. 论文提出的方法论：核心思想、关键技术细节

RECAP 由**数据采集扩展（Copilot Interaction Archiver）**和**回放与分析平台（Session Replay Viewer）**两部分构成，并内置可扩展的分析模块。

#### 2.1 数据采集：VS Code 扩展
- **聊天会话捕获**：监听 VS Code 工作区存储的 Copilot 对话 JSON 文件，每有新建或修改即读取完整会话（包含用户提示、AI 回复、工具调用、文本编辑组 TEG 等），并上传至云存储。
- **影子 Git 仓库**：在本地创建隐藏仓库 `.archiver_shadow/`，对工作区中的每一次**文件保存、创建、删除、重命名**都自动提交，甚至每 **5 秒（最长 30 秒间隔）** 捕获一次未保存的编辑器内修改（Dirty Snapshot 提交）。从而获得远细于开发者正常 git 提交的编辑历史。
- **隐私保护**：用户标识在客户端进行 SHA‑256 哈希后再上传；后端强制将上传路径与用户哈希绑定；扩展本身不持有云凭证，通过预签名 URL 上传。
- **附属捕获**：同时记录剪贴板粘贴、大段插入（用于外源推测），以及 Copilot 的调试日志（代理意图、完成事件等）。

#### 2.2 回放与编辑归属：Session Replay Viewer
- **统一时间线**：将所有影子 git 提交与聊天事件（按时间戳）合并为一条时间线。
- **编辑归属（关键链接）**：对于每个 git 提交，通过将 AI 回复中的**文本编辑组（TEG）** 与后续 5 分钟内的影子 git diff 进行**模糊行级比较**，判定代码的来源：
  - **完全匹配** / **部分匹配**（通常因格式化差异或开发者微调）。
  - **未匹配**：再通过外源启发式（新增内容超过阈值或隐含输入速度 >100 WPM）标识可能的外部来源。
- **界面设计**：四面板布局——文件树（显示变更及 AI 归属徽章）、中心 diff 视图（支持 AI 来源标记）、聊天面板（按时间合并的对话）、底部颜色编码的时间线（人为编辑、Copilot 编辑、外源、聊天提示、代理动作）。支持文件过滤、聊天搜索、时间比例/事件间距两种视图模式。
- **多学生概览**：为课堂部署提供所有学生时间线的堆叠视图及归一化密度图，可按 AI 编辑份额排序并快速定位异常个体。

#### 2.3 可扩展分析模块（示例）
- **行为分类**：使用 LLM 将每条提示归入 6 大类别（计划、编码、解释、评估、环境设置、对话）共 17 个细粒度行为码。
- **AI 依赖度量**：将会话按 30 分钟静默划分工作会话，统计每会话的 AI 编辑份额，并可跟踪其随时间变化。
- **提示嵌入与聚类**：用句子转换器编码提示，投影到二维并聚类，交互式可视化可用于探索学生、时间、类别等维度的模式。
- **扩展性**：架构已支持接入更多遥测源（如窗口焦点、光标跟踪），研究者可编写新分析而不更改采集层。

## 6. 论文的主要结论与发现

- RECAP 成功实现了 **AI 聊天会话与细粒度编辑的自动链接和统一回放**，填补了已有工具在长期、多文件、智能体编程场景下的记录空白。
- 课堂部署显示：
  - 学生使用 AI 时**“解释/调试”行为远多于“代码生成”**（解释类 44% vs. 代码生成 14%），暗示理解性对话的主导地位。
  - **AI 编辑份额随项目进行而下降**，说明学生对 AI 的直接代码依赖可能在后期减弱。
  - 回放所揭示的定性模式（如反复粘贴同一错误、先用 ChatGPT 设计策略再让 Copilot 实施）是单独的聊天日志或 git 历史无法观察到的，为未来研究提供了假设来源。
- 平台的开源和可扩展性为研究人员和教师研究“人-AI 协作编程”提供了可复现的基础工具。

## 7. 优点

- **端到端闭环**：在一个平台内完成采集、链接、回放与分析，减少多工具组合的麻烦。
- **无损被动采集**：不改变开发者 IDE 环境或工作流，自然提高生态效度。
- **细粒度编辑历史**：通过影子 git 和 Dirty Snapshot 捕获几乎每一次变更，远细于普通 git。
- **智能链接**：利用 AI 回复中的 TEG 与代码 diff 进行模糊匹配，自动化提示到编辑的归属，这是核心创新。
- **交互式回放**：四面板视图和时间线让研究者可以“重走”开发者的交互过程，便于发现策略性模式。
- **可扩展架构**：分析层设计为插件式，已提供行为分类、依赖度衡量等示例，方便二次开发。
- **注重隐私**：客户端哈希、无永久凭证、路径绑定等措施降低隐私风险。
- **开源与实践验证**：代码公开，并在真实教学场景中稳定运行。
