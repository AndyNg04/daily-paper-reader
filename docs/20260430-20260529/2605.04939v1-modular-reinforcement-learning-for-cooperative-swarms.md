## 摘要
协作机器人群体是一组共享共同目标但计算能力有限的机器人。每个机器人只能与少数同伴交互，且不知道这种交互如何影响集体效用。分布式多智能体强化学习的最新进展表明，即使每个机器人独立学习，它们也能学会如何以与共同目标一致的方式与其他机器人有效交互。然而，这要求每个机器人表示可能组合数量庞大的交互状态，挑战了机器人的记忆能力。本文提出了一种替代方法，用于群体中多机器人强化学习的空间交互状态表示。采用模块化（分解）表示，状态的每个特征由单独的学习过程处理，然后将结果聚合。我们在模拟机器人群体执行觅食任务的大量实验中证明了该方法的有效性。

## Abstract
A cooperative robot swarm is a collective of computationally-limited robots that share a common goal. Each robot can only interact with a small subset of its peers, without knowing how this affects the collective utility. Recent advances in distributed multi-agent reinforcement learning have demonstrated that it is possible for robots to learn how to interact effectively with others, in a manner that is aligned with the common goal, despite each robot learning independently of others. However, this requires each robot to represent a potentially combinatorial number of interaction states, challenging the memory capabilities of the robots. This paper proposes an alternative approach for representing spatial interaction states for multi-robot reinforcement learning in swarms. A modular (decomposed) representation is used, where each feature of the state is handled by a separate learning procedure, and the results aggregated. We demonstrate the efficacy of the approach in numerous experiments with simulated robot swarms carrying out foraging.

- **背景**：协作机器人群体（swarm）由大量计算和存储资源极度受限的机器人组成（如 e-puck2 RAM 仅 192 KB，Elisa-3 仅 8 KB）。它们只能通过局部感知与少数同伴交互，无法获取全局信息。
- **挑战**：在多智能体强化学习（MARL）中，要学习有效的避碰或协作策略，机器人需表示空间交互状态（如周围各方向是否有邻居）。直接枚举所有传感器组合会导致状态空间指数爆炸（例如 8 个布尔传感器产生 \(2^8=256\) 个状态，加入方位信息后可达 \(9^8\approx4300\) 万状态），严重超出群机器人的内存能力。
- **整体含义**：如何在保持学习性能的同时，大幅降低状态表示的存储需求，使分布式强化学习能在真实硬件资源下运行，是本文要解决的核心问题。

## 2. 方法

### 2.1 核心思想：模块化状态表示
将完整的空间状态按传感器（方向特征）分解为多个独立的学习过程，每个过程只负责自己对应方向的状态。最终通过固定的融合机制（“Council”）将各模块的动作偏好聚合成机器人的实际动作。

### 2.2 关键技术细节

- **单个学习器**：
  - 每个传感器方向对应一个学习器。学习器仅根据本传感器是否检测到碰撞半径内的邻居（二元状态：碰撞/无碰撞）来做决策。
  - 动作空间是整个机器人的可行方向（如 8 个离散方向），而非局限于该传感器方向本身，从而允许建议“向其他方向移动”。
  - 每个学习器采用连续时间 UCB-1 多臂老虎机算法选择动作。所有学习器在发生碰撞时同步触发，共享后续奖励（无细粒度信用分配）。

- **融合过程（Council）**：
  - 收集每个学习器推荐的方向角 \(d_i\)。
  - 对每个推荐方向，在其自身及相邻方向（基于高斯分布）累积偏好分数。
  - 将所有偏好归一化为离散动作的概率分布，最终按此概率采样一个动作由机器人执行。
  - 同一奖励信号传递给所有学习器进行更新。

- **奖励函数**：
  - 主要使用差分奖励 \(\Delta^i_k\)（式 4），将单个机器人的碰撞开销与生产率增益相结合，使个体最大化与群体目标对齐。
  - 也可使用简化自私奖励 \(\Omega = P^i_k - C^i_k\)（式 3）。

- **总状态数量**：对于 \(k\) 个传感器（每个传感器 \(m\) 种状态），完整表示需 \(m^k\) 个状态，模块化表示只需 \(k \times m\) 个状态，显著降低内存占用。

- **仿真平台**：ARGoS3 多机器人模拟器，模拟 Krembot 机器人（圆柱形，直径 6.5 cm，8 个均匀分布的距离传感器）。
- **任务场景**：三类 1.5 m² 的觅食环境：
  - Arena 1：基站位于中心；
  - Arena 2：基站位于角落（难度更高）；
  - Arena 3：两个基站位于对角附近（碰撞密度较低）。
- **机器人数量**：4 到 36 个（以 4 为步长）。
- **对比基准**：
  - Random：随机选择动作。
  - Dynamic Window：固定的避碰算法（有状态）。
  - R-Learner：基于 myopic R-learning 的全状态 RL（256 个状态），作为“理论上界”但成本高。
  - Continuous-Time Q-Learning：全状态 Q-learning 的连续时间变体（同样 256 状态）。
- **评估方式**：先进行 12 小时模拟训练，然后停止学习，进行 20 分钟评估，记录收集到的物品数量。每种配置用 20 个随机种子重复。

## 6. 主要结论

- **性能相当**：模块化表示在多数场景下与全状态学习算法（R-Learner）和固定高级算法（Dynamic Window）达到相近的觅食效率，尤其在中低密度下表现稳健。
- **鲁棒性**：模块化方法对奖励函数变化不敏感——改用非对齐的自私奖励 \(\Omega\) 仍能保持性能，而全状态 R-learning 则显著下降。
- **动作空间优势**：使用可组合的向量动作空间比使用不可组合的宏动作算法能够获得更好的学习效果，这支持了模块化融合的可行性。
- **内存效率**：通过分解，状态数从指数级降至线性，可在真实群机器人（内存低至几十 KB）上运行。

## 7. 方法优点

- **大幅降低内存**：状态表示复杂度由指数降为线性，适应资源受限的硬件。
- **无需中央协调**：每个模块独立学习，分布式运行，不增加通信负担。
- **模块间兼容**：通过“Council”机制实现动作融合，避免了传统分解方法中难以合并宏动作的局限。
- **鲁棒性强**：对不同奖励函数的适应性好，有利于实际应用中的奖励设计简化。
- **通用性**：框架可扩展至其他空间感知任务，不限于觅食。

## 8. 不足与局限

- **高密度性能下滑**：在机器人数量极多（如 36）且单基站时，模块化方法的性能略低于全状态 R-learning，可能因为分解丢失了全局上下文信息。
- **融合策略固定**：Council 采用固定高斯加权与概率采样，未进行学习，可能无法适应所有协同模式。
- **状态特征简单**：实验仅使用二元距离信息，未充分利用传感器能提供的丰富数据（如邻居朝向），而这在实际中可能有助于提升性能。
- **无实物验证**：全部实验在仿真环境中完成，未在真实机器人上测试，实物部署中的感知噪声、通信延迟等影响未知。
- **任务单一**：仅测试了觅食场景，尚未推广到其他群机器人任务。
