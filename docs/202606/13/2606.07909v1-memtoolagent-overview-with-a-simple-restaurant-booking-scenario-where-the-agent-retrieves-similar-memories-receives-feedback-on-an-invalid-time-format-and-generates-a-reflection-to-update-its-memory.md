## 摘要
现代大语言模型（LLM）代理可以使用外部工具帮助用户解决复杂任务。然而，对于需要从长期历史事件或先前的代理-环境交互中学习的问题，LLM代理需要使用记忆机制来存储和检索经验。虽然对话代理存在复杂的记忆系统，但很少有研究实证检验如何通过过去的用户-代理对话来改进代理的工具使用能力。我们提出MemToolAgent，这是一种通过记忆管理改进工具使用的框架。我们的方法包含一个记忆提取模块，将过去的经验处理成结构化记忆条目，以及一个检索模块，动态选择存储的记忆条目的子集。这使得无需LLM微调即可实现更个性化和准确的响应，与用户偏好和反馈保持一致。总之，本工作有三个主要贡献：（1）统一的记忆条目格式，无需LLM微调即可改进通用和个性化工具使用；（2）基于反思的记忆提取，利用环境和用户反馈将错误执行提炼为批评以存储；（3）基于记忆相似性分布选择使用多少过去经验的检索模块。在WorkBench、NESTFUL和PEToolBench基准上，MemToolAgent相比强基线分别实现了29%、80%和17%的相对改进。

## Abstract
Modern large language model (LLM) agents can use external tools to help users solve complex tasks. However, for problems that require learning from long-term historical events or from previous agent-environment interactions, LLM agents are required to use memory mechanisms to store and retrieve experiences. While sophisticated memory systems exist for dialogue agents, few studies have empirically examined how to improve agents' tool-using capabilities through past user-agent conversations. We propose MemToolAgent, a framework that improves tool use through memory management. Our approach contains a memory extraction module that processes past experiences into structured memory entries, and a retrieval module that dynamically selects a subset of the stored memory entries. This enables more personalized and accurate responses aligned with user preferences and feedback without requiring LLM fine-tuning. In summary, this work has three main contributions: (1) a unified memory entry format that improves both general-purpose and personalized tool use without LLM fine-tuning, (2) a reflection-based memory extraction that uses environment and user feedback to distill wrong executions into critiques to store, and (3) a retrieval module that chooses how many past experiences to use based on the memory similarity distribution. MemToolAgent achieves 29%, 80%, and 17% relative improvements compared to strong baselines on the WorkBench, NESTFUL, and PEToolBench benchmarks, respectively.

# MemToolAgent 论文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）代理在执行复杂任务时需要使用外部工具，但现有代理缺乏从历史交互中学习的能力，导致重复出现相似的参数错误、工具调用顺序错误或个性化不足。固定上下文窗口限制了长期连贯性，而单纯的扩展推理并不足以解决工具使用的常见错误模式。
- **研究动机**：需将记忆机制引入工具使用代理，使其能够存储和检索过去的成功/失败经验，从而无需微调LLM即可提升通用工具使用（如遵循正确参数顺序）和个性化工具使用（如根据用户偏好选择工具）。
- **整体含义**：提出MemToolAgent框架，通过结构化记忆条目（包含查询、动作、二元反馈和反思）以及动态检索机制，实现从用户-代理交互中学习，显著提升多个基准上的性能。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将过去经验以统一格式存储为记忆条目，查询时基于语义相似度动态选取相关条目作为上下文示例（即上下文学习），并在每次执行后根据环境反馈和用户反馈生成反思（critique）存入记忆，从而不断优化未来行为。
- **关键技术细节**：
  - **记忆条目格式**：每个条目 m = (q, a, f, r)：
    - q：用户查询
    - a：工具调用序列
    - f ∈ {0,1}：二元用户反馈（1表示成功，0表示失败）
    - r：当 f=0 时的反思/批评（失败时由记忆提取模块生成）
  - **动态 Top-n 检索**（Dynamic "n" Retrieval）：
    1. 计算查询与所有记忆条目的余弦相似度；
    2. 降序排列相似度值；
    3. 基于滑动窗口计算一阶导数估计（类似寻找“膝盖点”）；
    4. 利用 SciPy 的 `find_peaks` 找到导数估计中的峰值，对应的位置即为动态 n 值（即选取的记忆条目数量）。
    参数：半径 R（平滑参数）、显著性（prominence）、峰值序号（peak number）。
  - **记忆提取模块**：一个专门的 LLM 模块，输入当前查询、工具集合、代理动作序列、环境反馈、用户反馈以及检索到的相似记忆，输出反思/批评。对于失败案例，生成简洁的批评以帮助未来避免类似错误；对于个性化场景，则提取用户偏好（如“用户偏好使用 API_X 下的工具”）。
- **算法流程**（文字说明）：
  1. 对当前查询，执行动态 Top-n 检索，从记忆库中选出相关条目；
  2. 将这些条目作为少量示例注入到代理的系统提示中；
  3. 代理结合示例执行当前任务；
  4. 执行后，根据环境反馈和用户反馈，由记忆提取模块生成反思（若失败）或记录成功；
  5. 将新的经验（q, a, f, r）存储到记忆库中。

## 3. 实验设计：数据集、Benchmark、对比方法

- **基准（Benchmark）**：
  - **WorkBench**：通用工具使用，包含5个数据库、27个工具，任务涉及分析、日历、CRM、邮件、多域等，评价指标为任务准确率（outcome accuracy）。
  - **NESTFUL**：通用工具使用，侧重嵌套工具调用序列，基于 MathQA 和 StarCoder2-Instruct 生成，评价指标包括工具 F1、参数 F1、部分序列匹配、完整序列匹配、胜率。
  - **PEToolBench**：个性化工具编排，每个查询附带80-100条历史指令及二元评分，评价指标为工具准确率和参数准确率。
- **对比方法**：
  - 通用任务：No Memory（无记忆）、Extended Thinking（扩展思考）、ReAct Agent。
  - 个性化任务：A-MEM、Mem0（两种主流记忆架构）。
- **实验设置**：
  - 使用 Large Language Model：WorkBench/NESTFUL 用 Claude 3.7 Sonnet，PEToolBench 用 Claude 3.5 Sonnet。
  - 嵌入模型：Qwen3-Embedding-8B。
  - 动态检索超参数：R=10，prominence=1e-5，峰值序号根据任务调整（PEToolBench用第二峰值，其他用第一峰值）。

## 6. 主要结论与发现

- MemToolAgent 在 **WorkBench** 上整体准确率从 No Memory 的57.56%提升至85.06%（相对提升29%）；**NESTFUL** 完整序列匹配从15.6%提升至30.4%，胜率从51.2%提升至70.2%（相对提升80%）；**PEToolBench** 工具准确率从0.700（A-MEM/Mem0）提升至0.820（相对改善17%）。
- 动态 Top-n 检索优于固定 Top-k，能根据查询自适应选择最优记忆条目数。
- 记忆提取模块（即反思/批评）比直接使用原始错误轨迹更有效，显著提升性能。
- 硬偏好引导（Hard Preference Guiding）可作为记忆提取的低成本替代方案（在 PEToolBench 上有效）。
- 冷启动问题可通过合成查询缓解，但多域任务仍具挑战。
- MemToolAgent 虽然增加了输入 token 数，但输出 token 少于扩展思考和 ReAct 基线，降低了延迟和成本。

## 7. 优点

- **无需微调**：完全通过上下文学习利用记忆，适用于任何 LLM，具有强迁移性。
- **统一记忆格式**：覆盖通用和个性化两类工具使用，扩展性好。
- **动态检索机制**：基于相似度分布自动确定条目数量，避免固定 k 的过少或过多问题，且对噪声相似度曲线鲁棒。
- **反思生成模块**：将复杂失败轨迹提炼为简洁批评，减轻代理认知负担，提升从错误中学习的能力。
- **支持用户反馈**：利用二元反馈信号（可扩展为文本或评分），实现环境与用户双重引导。
- **消融实验全面**：验证了检索策略、记忆提取、记忆类型等各模块的贡献，结论可信。

## 8. 不足与局限

- **冷启动问题**：首次使用时记忆为空，需依赖合成查询或人工标注，多域场景下合成查询效果有限。
- **工具数量限制**：实验基准工具数少于40，实际应用可能数百甚至上千，记忆覆盖率会下降，冷启动更严重。
- **单轮对话限制**：所有基准均为单轮任务，不支持多轮对话中动态更新记忆（每次用户输入后需重新检索），文中未验证多轮场景。
- **二元反馈粗糙**：用户反馈仅为成功/失败，缺乏细粒度错误类型，可能误导参数正确但工具错误的案例（如PEToolBench参数准确率未提升）。
- **单次运行无方差**：未报告多次运行的平均值和标准差，统计可靠性待加强。
- **计算成本**：记忆提取模块需要额外 LLM 调用，增加推理开销（虽比扩展思考少，但比无记忆高）。
- **超参数调优**：动态检索的 R、prominence、峰值序号等需手动调优，不同任务最优值不同（如第二峰值 vs 第一峰值），泛化性需进一步验证。
