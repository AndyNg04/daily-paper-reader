## 摘要
语言智能体越来越多地部署在不断积累的多模态信息之上，然而现有基准假设为人际交互形式，视觉内容稀疏且内容直白，既不能评估对真实多模态文件交互的推理，也不能评估对隐藏用户信息的解读。为此，我们提出M$^3$Exam，一个基于真实用户-智能体交互、以查询为中心的多模态对话记忆基准，具有跨模态基础理解和隐含信息推理的多维度评估。对多模态大语言模型和记忆系统的基准测试揭示了跨模态基础理解、跨会话推理以及积累多模态上下文的效率成本方面持续存在的差距。我们进一步提出M$^3$Proctor，一种多模态记忆方法，它检测查询模态偏差，并仅按需消耗原始视觉源，在将索引构建时间和检索令牌减少70%以上的同时，将准确率提升13%。

## Abstract
Language agents are increasingly deployed over accumulating multimodal information, yet existing benchmarks assume a human-human form with sparse visuals and straightforward content, evaluating neither reasoning over authentic multimodal file interaction nor the interpretation of concealed user information. We therefore introduce M$^3$Exam, a query-centric multimodal conversational memory benchmark built on realistic user-agent interaction, with multi-dimensional evaluation spanning cross-modal grounding and implicit information inference. Benchmarking MLLMs and memory systems reveals persistent gaps in cross-modal grounding, cross session reasoning, and the efficiency cost of accumulating multimodal context. We further propose M$^3$Proctor, a multimodal memory method that detects query modality bias and consumes raw visual sources only on demand, improving accuracy by 13% while cutting index-construction time and retrieved tokens by over 70%.

### 2. 方法论：核心思想与关键技术

#### 2.1 M³Exam 基准的构建

M³Exam 的核心思想是通过模拟真实场景中用户与智能体的多会话对话，构建一个具有挑战性的记忆基准。其构建流程分为三个阶段：

1.  **时间线构建 (Timeline Construction)**：
    - **输入**：由“人物角色 (Persona)”、“核心事件 (Core Event)”和“多模态文件池 (Multimodal File Pool)”三元组驱动。
    - **过程**：利用文本LLM生成一个按时间排列的核心事件线，每个事件包含描述、用户查询、时间戳和图像搜索关键词。同时，生成与核心事件无关的干扰事件，增加检索噪声。
    - **质量控制**：通过LLM自检和人工抽查，确保人物角色一致性、事件无矛盾。

2.  **多轮对话合成 (Multi-Turn Conversation Synthesis)**：
    - **输入**：经过验证的时间线。
    - **过程**：使用一个事件滑动窗口，逐轮生成对话。每轮对话由“用户模拟器”根据当前事件和之前对话的摘要生成查询，并由“助手”回答。一轮对话后，其摘要会追加到运行中的记忆“`S_k`”中，用于指导下一轮对话。
    - **质量控制**：通过分块和跨块两阶段检查，修复角色偏离和矛盾，最后经过专家审查。

3.  **问题库合成 (Question Bank Synthesis)**：
    - **过程**：从最终对话数据中，针对覆盖多轮会话的上下文窗口，由LLM自动生成8种类型的问题。
    - **问题类型**：
        - **记忆 (Memorizing)**：单会话检索(SS)，文件管理(FM)，事实判断(FJ)。
        - **推理 (Reasoning)**：多会话分析(MS)，多模态推理(MR)，时间推理(TR)。
        - **解读 (Interpreting)**：隐式推断(II)，主题推理(TH)。
    - **质量控制**：确保每个问题都能从其所引用的上下文中得到答案。

#### 2.2 M³Proctor 多模态记忆方法

M³Proctor 的核心思想是**按需检索**，通过识别查询的模态偏见，避免无差别地加载所有视觉信息，从而实现效率与准确性的平衡。

1.  **多模态索引构建 (Multimodal Index Construction)**：
    - 将所有原始多模态数据（图像、图表、PDF）投影为可搜索的**文本代理 (Textual Surrogates)**，如图像的标题（Caption）、图表的转录（Transcription）、文档的摘要（Digest）。
    - 每个文本块都附带一个**模态标签 (Modality Tag)**，标记其原始来源（图像、文档、图表）。
    - 为每个会话创建一个**会话摘要块**，作为迷你时间线，保留跨会话信号。

2.  **模态感知推理 (Modality-Aware Inference)**：
    - **偏见检测与重排序 (Bias Detection & Re-ranking)**：
        - 使用一个轻量级LLM调用，判断查询是否需要对特定模态（如图像`I`、文档`P`、图表`C`）进行推理，得到查询的模态偏见向量 `b(q)`。
        - 基于此偏见向量，对Dense Retrieval检索到的候选块进行重排序。评分公式为：`s(q, c) = cos(q, c) + Σ λ_m * b_m(q) * ⊮_m(c)`，其中 `λ_m` 是针对不同模态的奖励权重。这会优先将与查询模态相匹配的证据排在前面。
    - **成本感知的模态级联 (Cost-aware Modality Cascading)**：
        - **第一阶段**：仅使用文本代理（即之前构建的标题、转录、摘要）来回答问题 `â_1`。
        - **决定是否级联**：通过置信度测试 `Φ(â_1, q)`，若文本答案不可靠（`u(â_1)=1`）或模态偏见未被满足（`β(q)=1`），则进入第二阶段。
        - **第二阶段**：根据融合了证据分数、偏见信号和词汇线索的综合评估 `e_m(q)`，决定是否加载特定模态的原始数据（如图表或PDF的原始像素）。实现了“按需”消费原始视觉源（仅有26.4%的查询需要级联）。

### 6. 主要结论与发现

1.  **M³Exam是极具挑战性的基准**：最强的前沿MLLM（GLM-5.1）总体得分为0.549，表明任务远未被解决。
2.  **瓶颈在于跨模态和隐式意图问题**：所有系统在处理单会话任务时表现良好，但在**多模态推理（MR）、隐式推断（II）和主题推理（TH）** 上表现急剧下降。这说明挑战在于证据管理而非骨干网络能力上限。
3.  **M³Proctor显著推进了智能体记忆前沿**：在基于7B骨干网络的系统中，M³Proctor以0.484的总体得分领先，在MR、II和FM类型上取得了最佳成绩。其表现甚至超过了几个获得了金标证据的前沿MLLMs。
4.  **多模态信息提升作用显著**：仅在需要时提供原始多模态证据能显著提升复杂任务性能（MR +0.300, FM +0.116），证实M³Exam的问题与视觉证据紧密耦合。
5.  **M³Proctor实现了效率与准确性的平衡**：其级联策略仅在26.4%的查询中触发，从而在达到高准确率的同时，将平均令牌消耗和索引构建时间降至文本级系统的水平（远超其他多模态系统）。它证明了按需提供模态信息是实现多模态准确性的关键，而非无差别注入视觉信息。

### 8. 不足与局限

1.  **基准任务形式的局限性**：论文自身承认，当前基准主要关注**单轮问答**，即给定一个累积的对话历史和当前查询，模型进行回答。而真实世界中的交互往往包含多轮对话、意图演化以及需要迭代更新的记忆。这也是所有现有记忆基准的共同不足。
2.  **隐式推理能力的局限性**：虽然M³Proctor在隐式推理任务上领先于其他方法，但其在该类任务上的绝对性能（LLM-J得分约65%）仍然有较大提升空间。论文指出，更好地建模隐式用户状态和进行深层上下文解读是未来工作的重要方向。
3.  **数据集全合成风险**：整个基准（对话、问题、答案）由LLM合成。尽管进行了严格的质量控制，但合成数据可能存在偏差、重复模式或与真实用户行为不完全一致的风险。虽然论文声称进行了人工检查，但合成数据的固有偏差是无法完全消除的。
4.  **无法根除的LLM裁判偏差**：尽管验证了LLM-J裁判的鲁棒性，但任何LLM作为裁判都可能存在对特定答案风格或知识领域的偏好，无法完全替代人工评估，尤其在评判复杂的隐式推理答案时。
5.  **未讨论模型偏见**：论文未讨论所使用的LLM（作为用户模拟器、助手或裁判）可能带来的文化、社会或职业偏见，这些偏见可能渗透到合成数据和评估结果中。
