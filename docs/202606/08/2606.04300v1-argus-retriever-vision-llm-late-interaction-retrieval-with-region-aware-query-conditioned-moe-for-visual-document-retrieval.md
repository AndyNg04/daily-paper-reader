## 摘要
晚期交互视觉-语言检索器将每个文档页面表示为多个视觉标记嵌入，并使用MaxSim对查询进行评分。在ColPali、ColQwen、ColNomic和Nemotron ColEmbed等系统中，文档嵌入是在未见查询的情况下生成的，因此同一页面对于表格查找、图表问题和布局敏感的证据请求具有相同的表示。我们引入了\textbf{Argus}，这是一个基于Qwen3.5-VL构建的查询条件晚期交互检索器家族。Argus添加了一个区域感知的混合专家模块：查询编码器同时生成检索嵌入和一个紧凑的上下文向量，文档页面被池化为空间区域，并且在MaxSim之前，一个查询感知路由器为每个区域选择潜在专家。输出仍然是多向量索引，与ColPali风格的检索兼容，但文档表示现在依赖于查询（即$\mathbf{D}(q)$）。所有Argus模型使用1024维的检索头，而最新的最先进系统使用2560维和4096维的头，并且仅使用约9%的可用公共监督进行训练，而不是全部数据。9B模型在ViDoRe V1上达到\textbf{92.67} NDCG@5，在V1+V2组合排行榜上达到\textbf{86.0} NDCG@5，这是开放晚期交互模型在组合排行榜上报告的最高值。在ViDoRe V3上，Argus-9B以Qwen3.6-27B代理检索流程封装，进一步将其在公共任务上的NDCG@10从60.28提升至\textbf{64.80}，表明同一检索器既可用作强大的独立系统，也可用作迭代LLM代理的搜索原语。

## Abstract
Late-interaction vision-language retrievers represent each document page as many visual token embeddings and score queries with MaxSim. In systems such as ColPali, ColQwen, ColNomic, and Nemotron ColEmbed, the document embeddings are produced without seeing the query, so the same page is represented identically for a table lookup, a chart question, and a layout-sensitive evidence request. We introduce \textbf{Argus}, a family of query-conditioned late-interaction retrievers built on Qwen3.5-VL. Argus adds a region-aware Mixture-of-Experts module: the query encoder produces both retrieval embeddings and a compact context vector, the document page is pooled into spatial regions, and a query-aware router selects latent experts per region before MaxSim. The output remains a multi-vector index compatible with ColPali-style retrieval, but the document representation is now dependent on the query (i.e., $\mathbf{D}(q)$). All Argus models use a 1024-dimensional retrieval head, compared with the 2560-dimensional and 4096-dimensional heads of recent state-of-the-art systems, and are trained on roughly 9\% of the available public supervision rather than the full pool. The 9B model reaches \textbf{92.67} NDCG@5 on ViDoRe V1 and \textbf{86.0} NDCG@5 on the combined V1+V2 leaderboard, the highest reported value for an open late-interaction model on the combined leaderboard. Wrapped in a Qwen3.6-27B agentic retrieval pipeline on ViDoRe V3, Argus-9B further improves its NDCG@10 from 60.28 to \textbf{64.80} over public tasks, showing that the same retriever serves both as a strong standalone system and as a search primitive for iterative LLM agents.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有晚期交互视觉文档检索器（如 ColPali、ColQwen、Nemotron ColEmbed）在编码文档时完全不考虑查询，导致同一页面对不同查询（如表格查找、图表问题、布局敏感证据）产生完全相同的固定表示，缺乏对查询意图的自适应性。
- **背景**：检索增强生成（RAG）中的第一步是高效检索外部知识，但企业/科学文档常以 PDF、扫描件等形式存在，答案可能位于表格、图表、公式中。纯文本提取或仅用单向量检索难以捕获细粒度证据。晚期交互（MaxSim）虽然保留了细粒度匹配，但文档端仍是查询无关的。
- **动机**：使文档表示能够随查询动态变化，同时保持多向量索引的兼容性和晚期交互的高效性，以提升视觉文档检索的精度，尤其是面对域外、多语言等复杂场景。

## 2. 方法论
- **核心思想**：在 Qwen3.5-VL 骨干网络上引入 **查询条件化的区域感知 Mixture-of-Experts (MoE) 模块**，使文档的多向量表示 $\mathbf{D}(q)$ 依赖查询 $q$，但仍通过 MaxSim 与查询令牌匹配，保持 ColPali 风格的索引兼容性。
- **关键技术细节**：
  - **查询分支**：用共享骨干编码文本查询，得到查询令牌嵌入 $Q$，并池化得到单一查询上下文向量 $z_q$（L2 归一化后用于路由）。
  - **文档分支**：
    - 在骨干的两个深度提取隐藏状态：**路由中间层** $L-5$（用于区域级决策）和**最终层** $L$（用于检索特征）。
    - 将视觉特征重塑为 2D 网格，按区域大小 $r=4$ 平均池化为 $N$ 个区域令牌，同时保留区域坐标 $c$。
  - **查询感知路由器**：每个区域输入为 $u_r = R_r + W_{\text{coord}}c_r + W_{\text{query}}z_q$（加法连接保持维度）。经过两层 MLP 和 top-k 稀疏 softmax（$K=4$ 潜在专家，top-2）得到专家权重 $g_r$。
  - **潜在专家库与共享专家**：4 个小型位置 FFN 提供一个候选网格 $E_k$；一个共享专家始终激活；专家权重 $g_r$ 从区域广播到所属图像块并进行加权求和 $S_{ij}$。
  - **门控残差融合**：$F = G_{\text{final}} + \sigma(\alpha) S_{\text{shared}} + \sigma(\beta) S$，两个门控标量可学习，初始化为 0.5 保持接近基线。
  - **投影**：最终 $F$ 写回图像令牌位置，通过 1024 维检索头投影为 $D(q)$，L2 归一化后与 $Q$ 进行 MaxSim 评分。
- **训练目标**：联合损失 $L = L_{\text{NCE}} + \lambda_{\text{bal}} L_{\text{bal}}$，其中 $L_{\text{NCE}}$ 为对比 InfoNCE 损失（使用批内负样本），$L_{\text{bal}}$ 为负载均衡损失。
- **算法流程**：两阶段训练：
  1. **路由器预热**：冻结 LoRA 和融合门，仅训练路由器和专家，使用路由交叉熵 + 负载均衡损失，无检索信号。
  2. **联合训练**：解冻 LoRA，加入检索对比损失，路由器噪声关闭。

## 6. 主要结论与发现
- **主结果**：Argus-9B 在 ViDoRe V1+V2 组合排行榜上达到 **86.0 NDCG@5**，超过之前最高 Nemotron-colembed-8b-v2（84.7）和 Ops-Colqwen3-4B（84.6），创开放晚期交互模型新高。
- **域外增益显著**：在 V2（域外）上，Argus-9B 比第二名高 **4.3 点**（69.2 vs 64.9），表明查询条件化在分布偏移时最有效。
- **小维度高效率**：所有 Argus 模型使用 1024 维检索头，远小于其他模型（2560/4096），但精度更高；存储每页 4.2 MB，比 Nemotron-8b-v2（18.9 MB）低 4.5 倍。
- **少训练数据**：仅用 9.3% 可用监督数据，仍达 SOTA，训练高效。
- **代理增强**：包入 Qwen3.6-27B 代理后，V3 平均 NDCG@10 从 60.28 提升至 **64.80**，说明可同时作为独立检索器和搜索原语。
- **多语言表现**：在 MIRACL-Vision 上获最高宏观平均（0.7552），在 Yoruba 长尾语言上尤其突出（0.8099 vs 0.5252）。
- **路由器行为**：同一页面在不同查询下，区域专家分配显著变化（可视化显示 24/63 区域改变首选专家），且所有专家均被使用（有效熵约 3.88）。

## 7. 优点
- **创新性**：首次将查询条件化引入视觉文档晚期交互检索，使文档表示动态适配查询，同时保持索引兼容。
- **高效部署**：文档编码一次离线缓存，查询时仅需查询编码 + 区域路由 + 融合投影 + MaxSim，与查询无关的文档特征可重复利用。
- **窄头高精度**：1024 维比主流 2560/4096 存储更低、查询更快，但精度更高。
- **数据效率高**：仅用 9% 公开数据，节省训练成本，利于可重复性。
- **消融完整**：证明了每个设计组件（查询条件、区域位置、共享专家、专家数、路由深度）的必要性。
- **兼容性与扩展性**：输出多向量索引与 ColPali 生态兼容，可直接用于现有索引和评分工具。
- **代理友好**：通过 Agent 包装能进一步提升检索质量，保留后续推理能力。

## 8. 不足与局限
- **继承晚期交互弱点**：仍需要存储所有文档页面的多向量嵌入，且在线查询时需对候选集做路由融合，存储和延迟仍高于单向量索引（但相比同类模型已更优）。
- **索引策略改变**：由于文档表示依赖查询，无法像 ColPali 那样一次索引 $\mathbf{D}$ 固定，必须采用先检索后重排的两阶段流程（先用静态索引粗排，再路由重排）。
- **V3 覆盖不完整**：ViDoRe V3 的私有域（Nuclear、Telecom）未被 MTEB 维护者开放，代理结果仅针对公共域，可能不反映全貌。
- **代理实验局限性**：仅使用单一 Qwen3.6-27B 代理和固定搜索预算（100 候选、200 步），结果可能随不同骨干或预算而变化。
- **路由器可解释性差**：潜在专家并无显式的语义标签（如“表格”“图表”），专业领域知识隐式地在训练中形成，难以解释单个路由决策。
- **训练细节透明度**：虽然提供了数据来源和启发式均衡，但未详细说明如何从各源中筛选 9.3% 子集，可能影响复现。
