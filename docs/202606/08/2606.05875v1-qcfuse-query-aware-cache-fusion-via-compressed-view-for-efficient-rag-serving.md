## 摘要
检索增强生成（RAG）通过将生成过程锚定于外部证据来提高大语言模型（LLM）的答案质量，但处理检索到的上下文使得预填充阶段成为主要的服务成本。RAG缓存融合通过重用检索到的块的预计算键值（KV）缓存，并选择性重新计算当前提示下的令牌来降低此成本。然而，现有的选择器在质量和效率之间面临困境：快速的查询无关或最终层查询到上下文选择器可能会遗漏与请求相关的证据，而全视图查询感知选择器需要在重新计算之前查看广泛的上下文和层，因此会阻碍逐层缓存融合流水线。我们提出了QCFuse，一种用于RAG缓存融合的压缩视图查询感知选择器。QCFuse使用块锚点查询探测来将用户查询状态条件化于紧凑的每块锚点，并使用关键层分析来在不检查所有层的情况下识别重新计算令牌。我们在SGLang中实现了QCFuse，并在六个数据集上对四个开放权重的LLM进行了评估。QCFuse达到了完全预填充级别的质量。在匹配质量下，QCFuse相比完全预填充实现了平均1.7倍的预填充时间加速，相比最强的保质量基线ProphetKV实现了1.5倍加速。

## Abstract
Retrieval-augmented generation (RAG) improves large language model (LLM) answer quality by grounding generation in external evidence, but processing retrieved contexts makes the prefill stage a dominant serving cost. RAG cache fusion reduces this cost by reusing precomputed key-value (KV) caches for retrieved chunks and selectively recomputing tokens under the current prompt. Existing selectors, however, face a dilemma between quality and efficiency: fast query-agnostic or final-layer query-to-context selectors can miss request-relevant evidence, whereas full-view query-aware selectors require broad context and layer visibility before recomputation and therefore stall the layer-wise cache-fusion pipeline. We present QCFuse, a compressed-view query-aware selector for RAG cache fusion. QCFuse uses chunk-anchor query probing to condition user-query states on compact per-chunk anchors and critical-layer profiling to identify recomputation tokens without all-layer inspection. We implement QCFuse in SGLang and evaluate it on four open-weight LLMs across six datasets. QCFuse reaches full-prefill-level quality. At matched quality, QCFuse achieves an average prefill-time speedup of 1.7x over full prefill and 1.5x over ProphetKV, the strongest quality-preserving baseline.

# QCFuse: 论文详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：检索增强生成（RAG）中，处理检索到的外部上下文使得预填充阶段（prefill）成为主要的服务成本。KV缓存融合通过复用先前数据的KV缓存来降低预填充开销，但现有选择器在“质量”与“效率”之间存在两难困境。
- **具体矛盾**：
  - 查询无关选择器（如CacheBlend、EPIC）速度快，但可能遗漏请求相关证据；
  - 最终层查询感知选择器（如FusionRAG）轻量，但多跳任务中可能错过关键上下文；
  - 全视图查询感知选择器（如ProphetKV）质量高，但需要加载完整的上下文和所有层的KV缓存，导致流水线阻塞，选择阶段耗时显著（例如占端到端时间的34%）。
- **研究目标**：如何在不牺牲速度的前提下，利用查询感知的令牌选择来保持生成质量。

## 2. 方法论

### 2.1 核心思想
通过**压缩视图**保留查询感知选择能力，同时避免全上下文、全层扫描。具体通过两种压缩策略实现：
- **块锚点查询探测（Chunk-Anchor Query Probing）**：压缩令牌视图，在每个可重用语料块中选择代表性锚点，用锚点KV缓存代替完整上下文对查询进行条件化。
- **关键层剖析（Critical-Layer Profiling）**：压缩层视图，通过离线剖析确定最能定位查询相关上下文令牌的若干关键层（默认Top-3），在线选择时仅检查这些层。

### 2.2 关键技术细节

#### 2.2.1 离线准备阶段
- **块KV缓存预计算**：为每个可重用语料块独立计算其位置无关缓存（PIC）。
- **锚点选择**：使用KVzip规则（自监督重建探测）从每个块中选择排名最高的10%令牌作为锚点。
- **关键层剖析**：基于SQuAD、NewsQA、Natural Questions等带有答案跨度标注的数据集，计算每个单层的证据定位Recall@10%，选取排名最高的k层（k=3）。

#### 2.2.2 在线服务阶段
1. **锚点条件化查询探测**：加载锚点KV缓存（仅原上下文10%的令牌），拼接后作为前缀，让用户查询进行前向传递，得到锚点条件化的查询状态。
2. **关键层令牌评分**：仅使用关键层的PIC上下文键，计算用户查询到上下文的注意力分数，对原始上下文位置进行重要性排序。
3. **选择性重计算**：选取Top-K（按重计算比ρ）令牌进行重计算，其余复用PIC缓存。

#### 2.2.3 流水线集成
- 选择阶段与重计算阶段分离：选择阶段位于预融合路径，仅加载锚点缓存和关键层键；重计算阶段通过Triton优化内核，实现稀疏重计算与层间KV加载重叠。

### 2.3 公式要点（文字描述）
- 全视图重要性分数：\( I(t) = \sum_{l=1}^L \text{Attn}_l(Q_U^l(C), K_C^{PIC,l})_t \)
- 压缩视图重要性分数：仅使用关键层集合L★，且查询状态Q_U^l(CA)基于锚点上下文CA而非完整上下文C。
- 选择集合：P = TopK(I(t), ⌊ρN⌋)，ρ为重计算比，N为上下文令牌数。

## 6. 主要结论与发现

- QCFuse在**匹配质量**（达到全预填充级别）下，相比全预填充实现平均**1.7倍预填充时间加速**，相比ProphetKV实现**1.5倍加速**。

## 7. 优点

- **方法创新**：首次提出“压缩视图”概念，将全视图查询感知选择器压缩为锚点+关键层两种独立压缩维度，有效解决流水线阻塞问题。
- **系统实现**：在SGLang中完整实现，并集成Triton优化的稀疏重计算内核，确保实用性和可复现性。
- **离线-在线分离**：锚点选择和关键层剖析完全离线完成，在线服务仅需轻量计算，不会引入额外延迟。
- **广泛的实验验证**：在4种模型架构、6个数据集、多个重计算比、带宽和吞吐量场景下验证，结果充分且一致。
- **公平比较**：保持了所有基线方法处于相同实现框架和硬件环境，有效隔离了系统优化对选择策略的影响。

## 8. 不足与局限

- **模型范围有限**：只评估了7B~14B的开源模型，未验证70B+规模或MoE架构，也未涉及闭源LLM。
