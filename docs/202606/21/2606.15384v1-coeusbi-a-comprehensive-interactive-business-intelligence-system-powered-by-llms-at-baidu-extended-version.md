## 摘要
大语言模型的出现催生了交互式商业智能（BI）系统的兴起。尽管商业BI产品日益采用语义层与自然语言界面相结合的方式，但它们主要依赖手动配置来定义指标和维度。实际部署面临严峻挑战：（a）频繁的JOIN操作降低了SQL生成的准确性；（b）宽模式加剧了模式链接的难度；（c）方言特定查询的生成以及多轮对话的准确支持导致计算成本高且准确性有限。我们提出CoeusBI，一个工业级交互式BI系统，通过一种新颖的双智能体架构与分层模式链接模块来解决这些障碍：（1）离线视图生成智能体，利用错误反馈自动将复杂的JOIN查询转换为简单的单视图查询，从而消除了手动语义建模的需要；（2）分层模式链接模块，利用视图上的向量检索高效处理异常宽的模式；（3）动态路由智能体，评估对话上下文以路由查询，动态调用合成新的中间表示或针对性地修改现有表示，然后通过一个与方言无关的确定性SQL编译器编译统一表示。在公共数据集和生产数据集上的大量实验表明，与现有方法相比，CoeusBI在查询准确性、令牌效率和用户满意度方面取得了显著提升。CoeusBI作为独立服务部署在百度的数据平台上，并在多个业务线广泛使用，每天支持数千用户，证明了其强大的实用性和可扩展性。

## Abstract
The advent of Large Language Models has catalyzed the emergence of interactive Business Intelligence (BI) systems. Although commercial BI products increasingly adopt semantic layers paired with natural language interfaces, they predominantly rely on manual configurations to define metrics and dimensions. Real-world deployments face critical challenges: (a) frequent JOIN operations degrade the accuracy of SQL generation; (b) wide schemas exacerbate the challenge of schema linking; and (c) the generation of dialect-specific queries and the accurate support for multi-round dialogues incur high computational costs and yield limited accuracy. We introduce CoeusBI, an industrial-scale interactive BI system that addresses these barriers through a novel Dual-Agent Architecture paired with a Hierarchical Schema Linking module: (1) an offline View Generation Agent that utilizes error-feedback to autonomously convert complex JOIN queries into simple single-view queries, which eliminates the need for manual semantic modeling; (2) a Hierarchical Schema Linking module that leverages vector retrieval over views to handle exceptionally wide schemas efficiently; and (3) a dynamic Routing Agent that evaluates dialogue contexts to route queries, dynamically invoking either the synthesis of new intermediate representations or targeted modifications of existing ones, before compiling the unified representation via a deterministic SQL compiler that is agnostic to dialects. Extensive experiments on both public datasets and production datasets demonstrate that CoeusBI achieves significant improvements in query accuracy, token efficiency, and user satisfaction relative to existing methods. CoeusBI is deployed as a standalone service on the data platform of Baidu and is widely used across multiple business lines supporting thousands of users daily, thereby evidencing strong practicality and scalability.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **背景**：大语言模型的快速发展推动了交互式商业智能（BI）系统的兴起。商业产品（如 Snowflake Cortex Analyst、Databricks Genie、Google BigQuery）广泛采用语义层与自然语言界面，但这些系统**高度依赖手动配置**（如 YAML、LookML）来定义指标和维度，人力成本高且难以适应 schema 演化。
- **核心挑战**：在实际生产环境中（以百度为例），现有系统面临三大难题：
  - **C1：频繁 JOIN 操作**——90.8% 的黄金 SQL 包含 JOIN，生成多表 JOIN 的 SQL 难度显著增大，精度受限。
  - **C2：宽 schema 下的模式链接**——工业数据集列数极多（如 BD-Baijiahao 视图平均 219 列），基于 prompt 的方法迅速耗尽 token 预算。
  - **C3：多轮对话处理与方言特定查询**——多轮对话中 query 重写和 LLM 直接生成 SQL 导致幻觉风险，且支持多种 SQL 方言成本高。
- **目标**：构建一个无须手动语义建模、能处理宽 schema、支持多轮对话且方言无关的工业级交互式 BI 系统。

## 2. 论文提出的方法论：核心思想、关键技术细节
### 2.1 整体架构：离线准备 + 在线查询处理的双智能体架构
- **离线准备阶段**：
  - **视图生成智能体（View Generation Agent）**：自动将复杂 JOIN 查询转换为单视图查询，消除手动语义建模。
    - 描述生成器：利用数据库 schema 和领域知识（文档、业务术语、专家反馈）生成语义描述，捕获表的主要用途、典型查询模式和外键关系。
    - 视图生成器：将描述作为数据库级规范，调用 LLM 生成 SQLite 或 ClickHouse 等方言的视图。生成过程是**需求驱动**而非结构驱动，避免视图组合爆炸；通过批处理错误反馈机制持续优化视图，无需每次错误都重建。
- **在线查询处理阶段**：
  - **路由智能体（Routing Agent）**：评估用户 NL 查询是否为单轮（SRD）或多轮（MRD），动态选择处理路径。
    - SRD 路径：完整执行层次化模式链接 + NL2IR 合成新中间表示。
    - MRD 路径：仅执行 View2Column 轻量级模式链接，通过 JSON Patch 修改上一步的金标准 IR。
  - **层次化模式链接模块（Hierarchical Schema Linking）**：分两阶段处理宽 schema。
    - Stage 1: Word2View（单视图选择）：利用三种向量检索模式（C2C、V2C、ALL2C）构建按业务线的向量数据库，结合 Query2Column 和 Query2Query 检索，配合紧凑模型（Ernie-Tiny v2）离线微调以加速预测。
    - Stage 2: View2Column（列修剪）：对选定视图构建自有的 Query2Column 向量数据库，返回 Top-K 近邻列，并将其作为 schema 上下文。
  - **确定性 SQL 编译器（Deterministic SQL Compiler）**：将 IR 编译为可执行 SQL，完全消除 LLM 幻觉风险。编译器是方言无关的，通过虚拟列机制将复杂逻辑下沉到视图层，保持 IR 的简洁性。
- **IR 设计**：采用结构化 JSON 中间表示（包括 dimensions、measures、filters、aggregator、comparison、viz_type 等），覆盖常见 BI 查询模式，并支持时间对比、比例分析等高级语义。

### 2.2 关键技术细节
- **视图生成**：使用 prompt 模板引导 LLM 生成描述，并指定视图依赖（如 JOIN 路径）；支持多方言（只需在 prompt 中指明 dialect）。
- **模式链接**：三种向量模式——C2C（列名直接映射）、V2C（列值到列）、ALL2C（领域知识到列）。系统并发执行两种检索，哪个先返回就预占哪个以降低延迟。
- **多轮支持**：路由智能体判断为 MRD 后，仅编辑上一轮 IR（如添加 comparison 字段），无需完整 schema 链接。当编译失败时自动回退到 SRD 路径。
- **Schema 演化**：采用增量更新策略，只插入新 embedding 或打墓碑标记，避免全量重建。

## 7. 优点：方法或实验设计上的亮点

## 8. 不足与局限
- **IR 表达力受限**：当前 IR 不支持复杂嵌套子查询、高级窗口函数（递归排名、移动平均）、非标准分组等。论文承认这是刻意设计，但仍有 4.7% 的查询无法自动处理，需专家介入。
- **对视图质量高度依赖**：若视图生成或错误反馈积累不充分，可能导致模式链接失败或 MRD 处理错误。
- **路由智能体误分类风险**：虽然准确率 98%+，但误分类可能导致硬失败或静默语义错误（后者需用户界面辅助验证）。
- **领域知识依赖**：描述生成需要领域知识（文档、业务术语），若缺失可能影响视图质量，且依赖专家积累的反馈数据。
- **实验覆盖有限**：
  - 公开数据集仅使用 BIRD-dev，未测试其他主流 NL2SQL 数据集（如 Spider 2.0、WikiSQL）。
  - 生产数据集仅来自百度业务（视频、搜索、广告），泛化到其他企业或行业有待验证。
  - 未系统评估不同 LLM backbone 下的极端表现（如高延迟、低资源环境）。
- **可复现性限制**：由于数据隐私，部分生产数据集仅部分脱敏公开；视图生成和模型微调的详细超参数（如学习率衰减、优化器）未完全公开。
- **资源开销**：虽然 token 高效，但 SFT 仍需要 16 卡 A800，且在线推理依赖 LLM（如 DeepSeek-V3），对小团队可能门槛较高。
