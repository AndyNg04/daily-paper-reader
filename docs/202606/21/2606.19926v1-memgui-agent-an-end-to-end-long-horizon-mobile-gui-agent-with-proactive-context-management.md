## 摘要
基于多模态大语言模型的移动图形用户界面代理在短周期任务上取得了显著进展，但在需要跨多个步骤和应用程序转换保留中间事实的长周期任务上仍然不可靠。我们将此限制归因于ReAct风格的提示，它被动地累积每个步骤的记录，导致提示膨胀和关键跨应用事实的稀释。为了解决这个问题，我们引入了MemGUI-Agent，一种具有主动上下文管理的端到端长周期移动GUI代理。MemGUI-Agent基于上下文即动作（ConAct），该机制将上下文管理作为由选择UI动作的同一策略发出的第一类动作。与被动追加历史记录不同，ConAct维护三个结构化的上下文字段：折叠的动作历史、折叠的UI状态和最近的步骤记录，在保持关键UI事实的同时保持上下文紧凑。为了使主动上下文管理在不同模型规模上可学习，我们构建了MemGUI-3K，一个包含2956条轨迹的数据集，带有完整的ConAct注释，用于监督训练和离线分析。在MemGUI-3K上训练一个8B模型产生了MemGUI-8B-SFT，一个在MemGUI-Bench上实现了最佳开放数据8B性能并泛化到分布外MobileWorld基准的8B MemGUI-Agent。代码、数据和训练好的模型将在https://memgui-agent.github.io/上发布。

## Abstract
MLLM-based mobile GUI agents have made substantial progress on short-horizon tasks, yet remain unreliable on long-horizon tasks that require retaining intermediate facts across many steps and app transitions. We attribute this limitation to ReAct-style prompting, which passively accumulates per-step records, leading to prompt explosion and dilution of critical cross-app facts. To address this, we introduce MemGUI-Agent, an end-to-end long-horizon mobile GUI agent with proactive context management. MemGUI-Agent is built on Context-as-Action (ConAct), which casts context management as first-class actions emitted by the same policy that selects UI actions. Instead of passively appending history, ConAct maintains three structured context fields: folded action history, folded UI state, and recent step record, preserving critical UI facts while keeping context compact. To make proactive context management learnable across model scales, we construct MemGUI-3K, a 2,956-trajectory dataset with full ConAct annotations for supervised training and offline analysis. Training an 8B model on MemGUI-3K produces MemGUI-8B-SFT, an 8B MemGUI-Agent that achieves the best open-data 8B performance on MemGUI-Bench and generalizes to the out-of-distribution MobileWorld benchmark. Code, data, and trained models will be released at https://memgui-agent.github.io/.

# MemGUI-Agent: 一种具有主动上下文管理的端到端长周期移动GUI代理 — 详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：基于多模态大语言模型的移动GUI代理在短周期任务（如单应用单步骤）上已经取得较好效果，但在长周期任务中（需要多个步骤、跨应用切换、保留中间事实）表现不可靠。例如，最强8B端到端模型GUI-Owl-1.5-8B在AndroidWorld（平均8.4步）上达到71.6%，但在MobileWorld（平均27.8步）上降至38.2%，在MemGUI-Bench（平均36.2步）上仅11.7%。
- **根本原因**：现有方法（如ReAct风格）被动地累积每步记录，导致提示膨胀（prompt explosion）且关键跨应用事实（如价格、编号、复制文本）被稀释、遗忘或丢失（information loss）。被动策略（追加、截断、丢弃）无法根据任务需求进行上下文管理。
- **研究目标**：提出**主动上下文管理**，让端到端策略同时决定UI动作和上下文管理动作，使长周期交互保持紧凑且关键事实持久化。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想：Context-as-Action (ConAct)

- **统一策略**：将上下文管理（折叠、内存写、自描述）视为与UI动作**同等地位的第一类动作**，由同一策略模型输出。
- **避免被动追加**：不再被动地追加历史记录，而是维护三个结构化上下文字段：
  - **Folded Action History (Ht)**：压缩的轨迹摘要。
  - **Folded UI State (Mt)**：持久化UI关键事实（如价格、电话号码、复制内容）。
  - **Recent Step Record (Lt)**：最近一步交互的完整细节（用于折叠和内存写）。

### 2.2 关键技术细节

- **每步输出5部分**（按顺序）：
  1. `<thinking>`：推理（思考下一步）。
  2. `<folding>`：折叠指令（JSON，指定范围区间和摘要）。
  3. `<tool_call>`：工具调用（UI动作或内存动作）。
  4. `<ui_observation>`：详细的屏幕描述（包含精确文本、数字、价格等）。
  5. `<action_intent>`：下一步动作意图（计划）。
- **动作空间**：A = A_ui ∪ A_mem，其中A_mem = {memory_add, memory_update, memory_delete}。
- **历史折叠**：从第2步开始，每步必须输出<folding>。可分为**步骤级蒸馏**（仅压缩当前步）或**跨度级抽象**（合并多步子任务为一个摘要），使上下文增长从线性变为次线性。
- **UI内存动作**：每个内存项是结构化三元组(id, description, content)，存储完整内容而非引用或损失性摘要。
- **自描述步骤输出**：通过<ui_observation>和<action_intent>使每步可被后续上下文动作重用。

### 2.3 算法流程（文字说明）

1. 当前步输入：截图It和结构化状态St = (G, Ht, Mt, Lt)。
2. 策略模型πθ输出五部分yt = (τt, φt, at, ot, ιt)。
3. 并行更新：
   - 折叠指令φt更新Ht+1。
   - 工具调用at执行UI动作（改变屏幕）或内存动作（更新Mt+1）。
   - 自描述字段ot和ιt与动作结果rt组成Lt+1。
4. 下一状态St+1 = (G, Ht+1, Mt+1, Lt+1)进入下一步。

### 2.4 数据集MemGUI-3K

- **构建目的**：使主动上下文管理可学习（零-shot仅在235B Thinking模型上有效）。
- **来源**：从MemGUI-Bench 128个种子任务扩展（实体替换、内存操作增强、任务简化）至7,303任务池，最终5,293任务被部署。
- **教师模型**：Qwen3-VL-235B-Thinking，使用完整5部分ConAct协议。
- **过滤**：轨迹级（成功轨迹，过滤异常）、步级（合理步标签，移除冗余错误步）。

- **数据集全面**：MemGUI-3K包含长轨迹、多应用、多种上下文操作注释，支持监督训练和离线分析。

## 8. 不足与局限

- **环境范围有限**：仅针对Android风格移动GUI环境，未扩展到iOS、桌面或Web界面。
