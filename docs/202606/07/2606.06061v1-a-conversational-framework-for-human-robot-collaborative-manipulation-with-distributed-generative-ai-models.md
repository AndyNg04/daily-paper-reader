## 摘要
本文提出了一种用于人机协作操作的分布式对话框架，该框架将本地语言模型和视觉语言模型（VLM）与基于机器人操作系统2（ROS 2）的执行栈集成在一起。语言理解、视觉定位、协调和运动执行作为独立的ROS 2节点运行，支持在分布式硬件上灵活部署，同时保持响应式控制循环。系统从自由形式的用户命令中生成结构化的动作请求，用于抓取、放置和移交。它使用VLM返回图像空间中的目标，并通过深度和校准将其转换为机器人框架中的公制坐标。一个网络仪表盘展示中间意图和定位覆盖层（像素、深度和机器人框架），并在执行任何运动之前要求操作员明确确认。在Franka FR3平台上进行的实验评估了在不断增加的工作台场景模糊性下的端到端任务可靠性和延迟，并比较了同一流程中不同的LLM/VLM配置。代码和完整文档可在[github.com/cogrob-tuni/franka-llm](https://github.com/cogrob-tuni/franka-llm)获取。

## Abstract
This paper presents a distributed conversational framework for human-robot collaborative manipulation that integrates local language and vision-language models (VLMs) with a Robot Operating System 2 (ROS 2)-based execution stack. Language understanding, visual grounding, orchestration, and motion execution run as separate ROS 2 nodes, enabling flexible deployment across distributed hardware while maintaining a responsive control loop. From free-form user commands, the system generates structured action requests for pick, place, and handover. It uses a VLM to return image-space targets, which are converted into metric robot-frame goals using depth and calibration. A web dashboard exposes intermediate intent and grounding overlays (pixel, depth, and robot-frame) and requires explicit operator confirmation before any motion is executed. Experiments on a Franka FR3 platform evaluate end-to-end task reliability and latency under increasing working table scene ambiguity and compare alternative LLM/VLM configurations in the same pipeline. Code and full documentation are available at [github.com/cogrob-tuni/franka-llm](https://github.com/cogrob-tuni/franka-llm).

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：人机协作操作中，用户以自然语言下达指令时存在指令不完整、场景描述模糊、物体在机器人视角下外观相似等问题，导致现有系统难以准确理解意图并安全执行。此外，大语言模型（LLM）和视觉语言模型（VLM）虽能简化交互，但其会“幻觉”（hallucination），直接输出可能引发错误物理动作，带来安全隐患。
- **整体目标**：提出一个**分布式、可检查、带明确确认步骤的对话框架**，将语言理解、视觉定位、协调和运动执行解耦为独立的ROS 2节点，灵活部署在不同硬件上（如边缘设备和工作站GPU），通过操作员确认门控保证安全，并提升在场景模糊性增加时的可靠性。

## 2. 方法论

### 核心思想
- 采用**多智能体ROS 2管道**，将流水线分为四个独立节点：
  - **语言理解节点**（ministral-3:8b LLM）：解析用户自由文本输入，分类为`pick`、`place`、`handover`、`go home`等结构化动作请求。
  - **视觉定位节点**（Qwen2.5-VL 32B VLM）：接收RGB图像，返回目标物体中心的像素坐标（或归一化值）。
  - **协调节点（coordinator）**：整合语言和视觉结果，计算机器人坐标系中的目标位置，并管理用户确认循环。
  - **运动执行节点**：利用MoveIt2生成并执行轨迹。

### 关键技术细节
- **自由命令→结构化动作**：LLM仅负责提取动作类型和参数（如物体ID、方位关系），不直接控制机器人。对`place`命令，支持“左/右/上/下于参考物体”的方向关系，默认偏移8cm。
- **视觉定位与坐标转换**：
  - VLM输出像素坐标`(u_c, v_c)`，从对齐深度图中取5×5邻域的中值深度`z`。
  - 使用针孔模型将像素点转换为相机光框架坐标：
    ```
    x_c = (u_c - p_x) * z / f_x
    y_c = (v_c - p_y) * z / f_y
    z_c = z
    ```
  - 通过离线ArUco标定得到旋转`R_a←c`和平移`t_a←c`，再经轴重映射和固定偏移`d`得到机器人基座框架坐标。
- **安全机制**：所有运动前通过web仪表盘展示意图、像素/深度/机器人框架覆盖层，并等待操作员明确确认。这一步骤是主要安全屏障。
