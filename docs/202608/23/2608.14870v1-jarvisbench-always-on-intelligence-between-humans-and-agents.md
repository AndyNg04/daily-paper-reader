## 摘要
长时程智能体可以持续执行任务，但人类的注意力仍然是间歇且稀缺的。这产生了一个双向协调问题：当后台工作继续进行时，用户可能需要立即访问智能体；而智能体在用户停止监控执行后，可能遇到需要用户判断的重大决策。我们提出一个常时在线的注意力协调层——Jarvis（以《钢铁侠》中的虚构AI助手命名）——来调解这一界面，并在一个或多个工作智能体之间分配人类注意力。我们引入JarvisBench来评估这种协调的两个方向：中介能否准确且及时地回答用户关于正在进行的工作的提问，以及它能否识别智能体何时需要用户判断、在正确的时机征求该判断，并将其路由回以改善任务结果。JarvisBench包含45个智能体任务实例：20个单智能体任务和25个工作流，组织成10个多智能体项目。这些任务覆盖19个领域，从2000多个公开候选中挑选并改编而来。关键在于，用户注意力的需求在执行过程中自然产生，而非源于初始提示中的明显遗漏。JarvisBench设计为可与任意智能体运行时集成，无需修改其底层执行循环。我们的参考实现还提供了全双工语音界面，使用户能够自然地联系Jarvis，同时及时的注意力协调支持后台工作的智能体。通过将智能体执行与注意力协调分离，JarvisBench在智能体能力持续提升时提供了一个稳定的评估目标。

## Abstract
Long-horizon agents can execute continuously, but human attention remains intermittent and scarce. This creates a bidirectional coordination problem: users may need immediate access to an agent while work continues in the background, whereas agents may encounter consequential decisions that require user judgment after the user has stopped monitoring execution. We posit an always-on attention-coordination layer---\textit{Jarvis}\footnote{Named after the fictional AI assistant in \textit{Iron Man}.}---that mediates this interface and allocates human attention across one or more working agents. We introduce \textit{JarvisBench} to evaluate both directions of this coordination: whether an intermediary can accurately and promptly answer user-initiated questions about ongoing work, and whether it can recognize when an agent requires user judgment, solicit that judgment at the right moment, and route it back to improve task outcomes. JarvisBench contains 45 agentic task instances: 20 single-agent tasks and 25 workstreams organized into 10 multi-agent projects. The tasks span 19 domains and were selected and adapted from more than 2,000 public candidates. Crucially, the need for user attention arises naturally during execution rather than from an obvious omission in the initial prompt. JarvisBench is designed to integrate with arbitrary agent runtimes without modifying their underlying execution loops. Our reference implementation further provides a full-duplex speech interface, allowing users to reach Jarvis naturally while timely attention coordination supports agents working in the background. By separating agent execution from attention coordination, JarvisBench provides a stable evaluation target as agent capabilities continue to improve.

## 1. 论文的核心问题与整体含义（研究动机和背景）

### 核心问题
- **注意力错配（Attention Mismatch）**：现代长时程智能体（long-horizon agents）可以持续自主执行任务，但人类的注意力仍然是**间歇性（intermittent）且稀缺的**。这导致一个双向协调困境：
  - **用户→智能体方向**：当智能体后台工作时，用户想提问或提供指导，往往被迫打断智能体的执行，频繁中断会降低效率，并将临时对话混入智能体的工作上下文。
  - **智能体→用户方向**：当智能体遇到需要人类判断的重大决策时，无法保证用户正在观看。智能体往往只能猜测并继续，等用户回来时，该决策可能已经影响后续工作。

### 现有方法的不足
- 现有智能体主要训练和评估目标是**任务完成率**，而非在间歇性可用的用户面前决定**何时应将用户纳入执行过程**。
- 已有研究（Qian et al., 2025; Zhang et al., 2026; He et al., 2025）表明：**主动性（proactivity）是一个独立能力**，当前智能体在这方面的校准很差。
- 现有智能体主动性研究仅覆盖**智能体→用户**的单向方向，未解决用户需要持续可用界面来提问或引导的问题。
- 工业界已有向此方向移动的尝试（如 Codex、Qoder 的更新），但**没有任何现有基准评估这一双向注意力协调问题**。

### 论文主张
论文提出一个**常时在线的注意力协调层（always-on attention-coordination layer）**——Jarvis，作为用户与工作智能体之间的中介界面，并推出 **JarvisBench** 来系统评估这一双向协调能力。核心观点是：**将智能体执行（agent execution）与注意力协调（attention coordination）分离**，为智能体能力持续提升时提供稳定的评估靶点。

## 2. 论文提出的方法论

### 核心思想：Jarvis 注意力协调层

JarvisBench 分离了三个角色：
- **用户（User）**：拥有意图、偏好、权威、私有上下文和验收判断权。评估中用带冻结任务特定用户画像的 LLM 模拟。
- **工作智能体（Working Agents）**：执行任务的智能体，使用其自有运行时（如 OpenClaw harness）和工具。
- **Jarvis（中介）**：连接两边——对用户保持常时可用，观察有界任务事件（bounded task events），并将用户指导传回相关智能体。**Jarvis 不解决任务本身、不使用工作智能体的工具、不替代其规划。**

### 关键技术设计

- **可移植集成**：Jarvis 通过**有界任务事件**和**窄指导接口**附加在智能体运行时之外，不修改 worker 的执行循环，使同一协调协议可跨不同运行时运行。这一"旁车（sidecar）"设计是公平性和可推广性的关键。
- **干预机制**：当需要干预时，Jarvis 在**动作边界（action boundary）** 暂停 worker、取消待执行动作、注入**有范围限定的软指导（scoped soft guidance）**，然后继续执行，不丢弃已完成的工作。
- **任务拓扑**：包含两种执行拓扑——
  - **单智能体任务（20个）**：每个任务跟随一个 worker 的完整轨迹，测试 Jarvis 能否在用户所有的决策点及时介入。
  - **多智能体项目（10个，共25个工作流）**：耦合工作流贡献同一共享成果，测试 Jarvis 能否识别跨工作流共享的项目级决策需求。注意：JarvisBench 指定任务、交互边界和评估目标，但不规定多智能体编排架构。
- **关键原则**：注意力需求在任务执行中**自然涌现**，而非通过在初始提示中人为扣留必要约束来制造。

### 评估指标

**任务结果得分（Task Outcome Score）**：每个任务定义冻结的加权检查点集合：
- Si = 100 × Σj wij·cij，其中 cij∈[0,1] 是检查点 j 的完成度，Σwij=1
- 检查点覆盖：客观执行、用户决策对齐、交付质量、安全性
- 基础设施或提供方故障标记为无效（invalid）而非给零分

**Agent-Collaboration 轨道指标**：
- 报告 worker-only 均分 S̄base、带 Jarvis 均分 S̄Jarvis、平均注意请求数 N̄req
- **注意力效率（Attention Efficiency）** = (S̄Jarvis − S̄base) / (100·N̄req)，表示每个请求的用户回合带来的平均增益（占满分比例），可正可负

**User-Interaction 轨道指标**：
- 通过**因果重放（causal replay）** 协议评估，读方式运行，不必为每个 Jarvis LLM 重跑 worker
- 每个轨迹在两个时间点（≈25% 和 ≈75% 执行进度）进行交互：用户先问固定的通用问题（General），再由 GPT-5.6-Luna 基于 Jarvis 的前一个回答生成一个追问（Follow-up）
- 每次回答由评估器独立打分 0/1/2：2=直接有效且重要声明有状态支撑；1=核心正确但不完整/模糊/略偏题；0=重要事实或依据错误、矛盾、非答案、或泄露未来/私有信息
- 若一条轨迹的任何回答含 future leak 或 privacy leak，该轨迹四个回答全部归零

## 3. 实验设计

### 数据集与基准构成

- **构建流程**：审计 69 个现有智能体基准，对 12 个进行任务级审查，产生 **2,038 个候选任务**目录作为搜索空间。
- **筛选标准**（四条）：
  1. 初始请求须含足够信息使智能体开始并取得有意义进展；
  2. 重大决策只能在智能体检查任务状态或产出中间成果后才具体化；
  3. 缺失的决策属于用户所有（偏好、授权、当前观察、预期用途、验收判断等），而非智能体应自行检索的事实；
  4. 一次简洁的用户干预能实质性地改善结果。
- **排除标准**：排除仅遗漏初始提示中明显字段的任务、需全程密集交互的任务、依赖不稳定服务或评估器措辞的任务。单有难度不够——只有失败可归因于缺失的人类判断的任务才被纳入。
- **最终构成**：JarvisBench 包含 **45 个任务实例**（20 个单智能体任务 + 10 个多智能体项目中的 25 个工作流），覆盖 **19 个领域**（如编程、调度、沟通、内容创作、数据分析、安全、医疗、旅行、法律审查、金融、采购等）。单智能体任务含 7 种注意需求形式（潜在上下文揭示、授权边界、异常升级、成果审查、专家引导、风险决策、轨迹修复）。

**优点**：
- 实验设计对称：既变 worker 又变 Jarvis LLM，可以分离开两者对结果的贡献；

- 上游候选任务全部来自公共基准，可能携带这些基准的固有偏差。

## 6. 论文的主要结论与发现

### 发现 1：外部 Jarvis 层能一致改善不同 worker 代理的效果
- 固定 GPT-5.6-Sol 为 Jarvis LLM 时，**每一个完成评估的 worker 配置均获得提升**：
  - 单智能体任务：增益 +4.9 至 +24.7 分
  - 多智能体任务：增益 +12.5 至 +28.2 分
- 增益幅度跨模型家族有很大差异（GPT-5.6-Sol 作为 worker 仅 +4.9，而 DeepSeek V4-Pro 单智能体达 +24.7），表明**Jarvis 不是被动的消息路由器**，它必须理解进行中的工作、识别何时人类判断重要、将其转化为有效干预。

### 发现 2：GPT-5.6-Sol 是最强默认 Jarvis LLM
- 固定 Claude Opus 4.8 为 worker 时，GPT-5.6-Sol 作为 Jarvis 产生**最大的任务增益和最高的最终分数**（单智能体 +24.1 达 83.1；多智能体 +28.2 达 80.8）。
- 但**注意力效率给出更细化的图景**：DeepSeek V4-Pro 在多智能体任务上效率最高（Eff.=0.41），因其仅用 0.30 次请求/任务的更少请求就获得增益。

### 发现 3：GPT-5.6-Sol 提供最佳用户交互体验
- GPT-5.6-Sol Overall 分数最高（96.3）。
- 延迟受部署方式和语音服务策略影响显著：
  - 本地模型（Qwen235B 1.6s、GPT-OSS-120B 1.3s）比 API 模型（GPT-5.6-Sol 1.8s）更低
  - 由于延迟与 API 条件、TTS 服务策略混杂，论文声明这些测量仅作为当前实现的参考。

### 总体结论
- 注意力协调**既有效又具有技术挑战性**；
- 不存在一个普遍最优的干预策略——最优操作点取决于如何权衡任务质量、响应时间和人类注意力；
- 通过将 Jarvis 从 worker 循环中分离，JarvisBench 允许未来对智能体运行时、干预策略、交互模型和语音界面在同一协议下进行比较。

## 7. 优点（方法/实验设计的亮点）

1. **问题定义新颖且切中痛点**：首次将"人类注意力"作为跨智能体的协调对象进行评估，填补了双向注意力协调基准的空白（区别于多智能体系统研究和智能体主动性研究两条线）。
2. **执行与协调分离的架构设计**：Jarvis 作为外部 sidecar，不修改 worker 执行循环、不使用其工具，保证了评估的公平性和跨运行时可移植性，为后续代理能力提升预留了稳定的评估靶点。
3. **任务构建原则强调自然涌现性**：注意力需求源于任务展开过程中的自然决策点，而非人为扣留初始约束——这显著提高了生态效度，避免"提示词补洞"式的假任务。
4. **严格的选择与验证流程**：2,038 个候选 → 四重筛选标准 → 静态检查/运行时预检/手动轨迹审查/参考结果验证，保证了任务质量。
5. **双轨评估覆盖双向问题**：Agent-Collaboration 轨道关注"注意请求是否有效"，User-Interaction 轨道关注"用户请求时 Jarvis 是否有用"，两条轨道共享任务集但独立度量。
6. **因果重放协议设计了严格的防泄漏机制**：Follow-up 生成器和评估器只能访问因果状态，未来事件/私有信息/评估器信息均不可见；任何未来或隐私泄漏导致整条轨迹归零，惩罚机制严格。
7. **注意力效率指标精巧**：将增益归一化为每请求用户回合的贡献，暴露了"高增益但高打扰"与"低增益但低打扰"之间的真实权衡。
8. **实验矩阵对称**：同时变化 worker 与变化 Jarvis LLM，能区分出协调层增益来自 worker 端还是 Jarvis 端。
9. **多智能体任务为耦合项目而非并列任务**：保证了项目级决策的真实性。
10. **提供完整全双工语音参考实现**：包含 VAD 端点检测、流式 ASR/LLM/TTS 流水线、barge-in（语音打断）处理细节，使基准可直接对接实际交互场景。

## 8. 不足与局限

1. **实验规模相对有限**：45 个任务（20 单 + 10 多智能体项目）规模不算大；多智能体项目的"项目数量"为 10，每个项目的评分粒度较粗。
2. **关键结果缺失**：GPT-5.6-Sol 作为 worker 时多智能体结果缺失，削弱了跨模型推算能力；论文未说明原因。
3. **未报告方差与置信区间**：平均分数的波动范围、单次运行稳定性未报告，无法判断增益的统计显著性。
4. **评估链依赖单一 LLM**：Follow-up 生成器与响应打分器均为 GPT-5.6-Luna，存在系统性偏向该模型偏好的风险；虽设定了严格的错误标签和规则，但缺乏与人类评分一致性的验证（inter-annotator agreement 未报告）。
5. **干预策略单一**：仅在"轻量策略"上评估（允许有用干预、劝阻不必要请求），未扫描干预频率/强度对任务质量与注意力消耗的 Pareto 前沿；这限制了关于"最优注意力预算"的结论，但论文坦诚指出了这一点。
6. **模拟用户的局限**：用户角色由 LLM 模拟（具有冻结的用户画像），模拟用户的判断质量、一致性和真实性未与真实人类行为验证。

## 8. 不足与局限（续）

7. **延迟测量混杂**：语音响应的端到端延迟同时受 API 调用条件、TTS 服务策略、模型部署方式和 VAD 端点检测参数的影响，论文明确承认这些测量只是当前实现的参考值，无法据此比较不同 Jarvis 大脑的固有速度。用户交互轨道中本地模型（Qwen235B、GPT-OSS-120B）延迟低于 API 模型，这一现象与技术能力的相关性存疑，更可能是网络往返与服务水平决定的。
8. **上游任务来源的偏差**：全部 2,038 个候选任务均取自公共基准，因此 JarvisBench 继承了这些基准的固有偏差——例如任务语言以英文为主、领域偏向编程/知识工作/办公场景、任务规模偏短（多数在数十分钟内完成），缺乏对超长时程（数天至数周）真实项目任务的覆盖，也缺乏对体力型/线下型任务的考量。
9. **多智能体编排未标准化**：JarvisBench 有意不规定多智能体架构，这保证了灵活性，但也意味着不同 worker 在多智能体项目中的工作流拆分方式可能不同（如谁负责哪个子任务、如何共享中间产物），使得跨 worker 的多智能体增益对比可能混入了编排架构差异，而非纯粹由 Jarvis 协调能力造成的差异。
10. **单次运行、缺乏重测**：所有实验报告均为单次运行结果，未见多次重复实验的标准差、置信区间或最好/最差案例分析；考虑到单智能体任务每个拓扑下仅 20 个任务，个别长尾任务（如提供方故障、工具不稳定）可能大幅扰动均分，增益的稳健性值得进一步验证。
11. **人类注意力的建模仍然简化**：评估中"用户不可用"是二值化建模（available/unavailable），而真实人类的注意力是连续的、可预测的（如会议中、休息时）且可被主动提醒的；Jarvis 是否应具备"预测用户何时最可能响应"的能力，尚未在基准中体现。

## 9. 总体评价与领域启示

### 核心贡献的定位

JarvisBench 的贡献不在于提出一个新的"更聪明的智能体"，而在于**为"智能体执行"与"人类注意力"之间建立了一个可度量的接口层**。这一抽象使得三个原本纠缠的问题得以解耦：

- **任务做得对不对**（worker 能力）
- **何时该问人**（协调策略）
- **问了之后能不能说清楚**（交互质量）

论文通过双轨设计分别对应后两者，并用"attention efficiency"这一指标将两者的成本-收益关系统一起来。这种"旁车（sidecar）"式的架构立场——不侵入 worker、不替代 worker 的规划器、只做有界事件观察与窄接口注入——在方法论上是克制的，也正是这种克制保证了其评估结论的干净性。

### 对后续研究的启示

1. **干预策略的可搜索性**：论文承认只评估了一个操作点，但其框架天然支持对干预阈值、请求频率上限、请求优先级排序等进行系统搜索，从而绘制"任务质量 × 注意力消耗"的 Pareto 前沿。这是最直接且最有价值的后续工作。
2. **代理能力提升后的再校准**：既然 worker 能力在快速进步，未来"何时需要问人"的边界会动态移动（更强的 worker 需要更少的干预），JarvisBench 提供一个稳定的协议来跟踪这一移动——这正是论文强调"评估靶点稳定"的深意。
3. **真实人类用户验证**：当前用户由带冻结画像的 LLM 模拟，未来需要小规模真人研究来验证模拟用户的判断是否与真实用户在"是否该问、问什么、答案是否有效"上一致，尤其是 Follow-up 问题的人类自然性。
4. **多模态与语音交互的扩展**：论文提供了语音参考实现，但基准本身仍以文本为核心。真实场景中用户可能通过语音提问、手势或共享屏幕与 Jarvis 互动，注意力协调的模态宽度有待扩展。
5. **注意力的预测性建模**：真实人类注意力有节律（如每日工作节奏），将用户的"预响应性"建模为可预测信号，可进一步提升协调质量——这一维度当前基准尚未触及。

### 总体判断

这是一篇**问题定义价值高于方法创新价值**的工作。它的最强之处在于敏锐地识别了长时程智能体落地中的关键瓶颈——不是能力不足，而是**人类注意力成为稀缺资源时，智能体缺乏与之协调的机制**；并用一套设计严谨、克制、可复现的评估体系将这一瓶颈显性化。实验设计和评估协议的细节质量（因果重放、防泄漏、无效标记、注意力效率）达到较高水准。局限主要来自规模与统计稳健性（45 个任务、单次运行、单一评估器），以及模拟用户对真实人类行为的简化。总体而言，JarvisBench 为"人机注意力协调"这一新兴评估维度奠定了坚实的基准基础和清晰的研究议程，具有较高的引用与扩展价值。
