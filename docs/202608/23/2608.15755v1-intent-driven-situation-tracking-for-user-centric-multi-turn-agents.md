## 摘要
用户中心多轮代理必须根据不断变化的用户意图、积累的基于工具的事实、缺失信息和执行约束，对不断演变的任务情境采取行动。现有的上下文管理方法改善了过去交互历史的利用，但很少维护一个将基于事实的信息与任务状态判断分开的显式情境状态。因此，代理通常需要从对话轨迹中隐式推断细粒度属性、任务依赖和约束满足情况。我们提出了意图驱动情境状态（IDSS），这是一种无需训练的框架，在对话旁边维护一个显式的情境状态。IDSS将工具返回结果解析为具有来源感知的实体和属性，跟踪用户意图、所需变量、约束和执行状态，并将新事实传播到任务约束以更新行动的可执行性。这使得代理能够避免不可行的行动，推进依赖目标，并在不反复搜索原始历史的情况下重用相关信息。在八个LLM上的三个交互式基准测试中的实验表明，IDSS提高了任务完成度、偏好引导和交互效率，在涉及多实体协调、不断演变的用户约束和约束感知重规划的任务上效果显著。消融和错误分析表明，这些改进来自于事实持久化、以意图为中心的状态跟踪和约束建模之间的相互作用。这些结果表明，显式情境跟踪为可靠的用户中心多轮代理提供了一种有效的替代以历史为中心的上下文管理的方法。

## Abstract
User-centric multi-turn agents must act on an evolving task situation shaped by changing user intents, accumulated tool-grounded facts, missing information, and execution constraints. Existing context-management methods improve the use of past interaction history, but rarely maintain an explicit situation state that separates grounded facts from task-state judgments. As a result, agents often need to infer fine-grained attributes, task dependencies, and constraint satisfaction implicitly from dialogue traces. We propose Intent-Driven Situation States (IDSS), a training-free framework that maintains an explicit situation state alongside the dialogue. IDSS parses tool returns into provenance-aware entities and attributes, tracks user intents, required variables, constraints, and execution status, and propagates new facts to task constraints to update action executability. This allows agents to avoid infeasible actions, advance dependent goals, and reuse relevant information without repeatedly searching raw history. Experiments on three interactive benchmarks across eight LLMs show that IDSS improves task completion, preference elicitation, and interaction efficiency, with clear gains on tasks involving multi-entity coordination, evolving user constraints, and constraint-aware replanning. Ablations and error analyses show that these improvements come from the interaction between fact persistence, intent-centered state tracking, and constraint modeling. These results suggest that explicit situation tracking offers an effective alternative to history-centric context management for reliable user-centric multi-turn agents.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：基于大型语言模型（LLM）的智能体正广泛应用于客服、旅行规划、生活服务等用户中心场景。这类智能体不再执行孤立的指令，而是参与持续的多轮交互，需要理解不断演变的用户目标、调用外部工具、遵循规则，并在询问、检索、执行或结束之间作出决策。
- **核心挑战**：用户中心多轮任务对状态维护提出了极高的要求。用户可能在一次对话中引入多个目标，这些目标之间可能存在依赖或冲突；偏好往往逐步透露而非一次性给出；工具返回结果可能推翻先前假设的事实，新观察到的事实也可能使先前的行动路径变得不可行。
- **现有方法的不足**：现有上下文管理方法（外部记忆、压缩、摘要等）虽然改善了历史信息的使用效率，但智能体仍需从检索到的记忆、摘要或压缩轨迹中隐式推断当前任务状态，极少将**基于工具的事实**与**任务状态判断**（活动意图、缺失变量、约束条件、执行状态）显式分离，导致事实遗漏、意图漂移、过早执行和约束违反等系统性问题。
- **研究含义**：本文主张，可靠的用户中心多轮智能体应维护显式的、面向决策的情境状态，而非仅依赖对过去交互历史的访问和检索。

### 2. 方法论：核心思想、关键技术细节与流程

#### 2.1 核心思想：Intent-Driven Situation States（IDSS）

- 一种**免训练**框架，在对话历史之外维护一个显式的情境状态（Situation State），将多轮交互组织为围绕不断演变的用户意图展开的结构化状态。
- 形式化定义：IDSS 用情境增强策略替代纯历史策略：
  - 原策略：at = π(Ht, A)
  - 新策略：at = π(Dt, Hcomp_t, A)
  - 其中 Dt = (Ft, St)，Ft 为事实层（Fact Layer），St 为状态层（State Layer），Hcomp_t 为压缩后的残余对话历史。
- 事实层与状态层的分离是该框架的核心创新，使智能体能够基于显式表示而非原始历史进行决策。

#### 2.2 事实层（Fact Layer）

- 采用确定性解析器将工具返回转换为结构化实体：Ft = {ei = (type_i, id_i, attrs_i, src_i)}，其中 type 为实体类型，id 为实体标识符，attrs 为属性集，src 为来源（溯源）。
- 更新方式：解析器将工具返回转换为操作序列（ADD、UPDATE、DELETE、MERGE），增量合并到事实库：Ft = Ft−1 ⊕ Δt。
- **冲突解决**：当同一属性收到冲突值时，按来源可信度裁决——工具观察到的属性优先于智能体推断的属性，同类型来源中较新的观察覆盖较旧值。
- **压缩**：提取后的工具返回在历史中被替换为事实层的简短引用，保持提示词紧凑同时保留可访问的完整事实。

#### 2.3 状态层（State Layer）

- 围绕用户意图组织，记录三类信息：St = (It, Vt, Ct)。
  - **意图追踪（Intents）**：识别用户消息中的显式/隐式目标，记录为意图并赋予四种状态之一：ACTIVE、PENDING、COMPLETED、BLOCKED。意图之间可建立依赖关系，依赖完成后意图可激活，约束违反时意图被阻塞。
  - **变量追踪（Variables）**：记录当前或待处理意图所需的信息槽位，标注来源类型（askable / retrievable / derivable）和已知/未知状态。
  - **约束建模（Constraints）**：记录动作必须满足的条件（用户偏好、工具前置条件、规则），状态标记为 satisfied / unsatisfied / violated。约束被违反时关联意图被标记为 BLOCKED。
- **完成判定**：当所有用户引入的意图均为 COMPLETED 或 BLOCKED，且没有可执行意图所需的未知变量时，任务完成。
- 实现机制：智能体在每轮回复前生成 `<state>` 块，系统解析后移除并重新注入下一轮提示词，**不产生额外 LLM 调用**。

#### 2.4 跨层约束传播（Cross-Layer Constraint Propagation）

- 当事实层更新实体属性时，系统通过确定性属性比较重新评估约束。
- 约束缺乏足够依据时保持 unsatisfied，而非错误标记为 violated。
- 约束被违反时，系统阻塞关联意图并记录事实依据和约束链条，帮助智能体理解为什么路径不可行，并推导替代方案（例如：basic_economy 舱位违反改签约束 → 阻塞修改意图 → 激活取消并重新预订的意图）。

### 6. 主要结论与发现

- **IDSS 在整体性能上显著优于所有基线**，在三个基准上普遍优于最强基线 U-Fold。
- **τ-bench**：Airline 上相对 U-Fold 提升 1.5 Avg@4 和 2.0 pass 4；Retail 提升较小但正向。ReSum 和 IterResearch 往往劣于 ReAct，说明摘要/检索式上下文管理可能丢失客户服务任务所需的精确标识符、状态和时效字段。
- **VitaBench**：在需要多实体协调、跨服务组合和状态继承的 OTA 和 Cross-domain 任务上优势最明显（相对 U-Fold 分别提升 1.7 和 2.1 分）。
- **UserBench**：Score 和 CER 全面领先，相对 U-Fold 分别提升约 4.6% 和 4.0%；偏好引导（PE）提升较小且因模型而异。
- **消融结论**：事实层对 τ-bench 最重要（Avg@4 下降 2.2，pass 4 下降 3.5）；状态层对 UserBench 最关键（Score 下降 8.4%）；VitaBench 需要两者的协同贡献；约束建模提供小而一致的增益。
- **错误分析**：事实遗漏从 14% 降至 8%，缺失信息错误从 8% 降至 5%；约束违反变化不大（5%–8%），说明部分规则违反源于模型对规则本身理解不充分，而非仅缺状态。
- **效率**：IDSS 实现了最高的平均性能（50.5%）和最少的交互轮次（7.8），零额外 LLM 调用。

### 7. 优点

- **免训练设计**：无需微调或专用监督信号，可直接应用于任意 LLM，跨领域泛化能力强。
- **显式状态与事实-判断分离**：将工具事实与任务状态判断分离，是相对于 DST、外部记忆、上下文压缩等方法的核心创新。
- **零额外调用开销**：事实层采用确定性解析，状态层在动作生成过程中维护，不产生额外的 LLM 调用。
- **跨层约束传播**：新事实自动触发约束评估，支持非线性意图依赖和阻塞-替换逻辑，使智能体"知道为什么不可行"。
- **提示词紧凑**：事实层替换工具返回、历史压缩后注入，同时保持事实完整可访问。
- **实验覆盖面广**：3 个基准 × 8 个 LLM × 6 种方法，跨不同模型族和规模验证了方法的普适性。
- **详细的错误归因和案例分析**：提供了消融、错误分类、效率分析和完整案例走查，论证链条完整。

### 8. 不足与局限

- **应用范围限制**：IDSS 依赖工具返回能被确定性解析为结构化文本字段；对于多模态观察、非结构化自由文本或更丰富的工具环境，框架需要扩展。
- **真实用户验证缺失**：实验使用模拟用户（GPT-4.1 作为用户模拟器），真实用户自然表达、纠正和偏好表达的不确定性未被充分覆盖。
- **消融实验覆盖不足**：仅在 GPT-4.1 上进行了消融，未验证组件贡献在不同模型上的稳定性。
- **试验次数较少**：τ-bench 和 VitaBench 每组仅 4 次独立试验，统计显著性未报告。
- **约束更新依赖确定性规则**：跨层传播虽然免训练，但约束的字段匹配和比较可能需要针对不同任务领域设计专用解析逻辑，通用性受限。
- **约束违反改善有限**：错误分析显示 IDSS 对状态维护类错误改善显著，但对约束违反类错误仅有小幅变化，说明模型对规则本身的理解缺陷仍需其他手段弥补。
- **伦理与部署风险**：论文虽讨论了伦理考虑，但明确承认 IDSS 不能消除工具输出错误、模型幻觉或高敏感场景部署风险，需要附加安全措施。
