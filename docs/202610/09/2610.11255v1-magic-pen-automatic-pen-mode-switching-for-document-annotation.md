## 摘要
传统数字笔界面通过菜单按钮切换笔模式，用户需要在往返交互上花费时间和认知资源，还可能因点击较小的模式选择按钮而出现模式错误。本文提出 Magic Pen，这是一种利用机器学习自动切换数字笔模式、无需显式更改模式的技术。Magic Pen 由一个 LSTM 模型驱动，该模型基于两项研究中从 27 名参与者收集的笔迹数据进行训练，并通过迁移学习迭代调整，以适应特定用户的批注方式。该技术还结合了轻弹手势或屏幕点击等错误缓解方法，以纠正模式错误或快速删除笔迹。我们首先对 18 名参与者开展了对比研究，随后进行了迭代改进，并对 8 名参与者开展了部署研究。与传统的基于菜单的方法相比，参与者更倾向于使用 Magic Pen；迁移学习则提升了模型预测的可靠性和稳定性。

## Abstract
Traditional digital pen interfaces use menu buttons to change the pen mode, which results in time and cognitive load spent on round-trip interactions and mode errors from tapping small mode selection buttons. This work presents the Magic Pen, a technique which uses machine learning to automatically switch between digital pen modes without requiring explicit mode changes. Magic Pen is driven by an LSTM model trained on pen data collected from 27 participants across two studies and uses transfer learning to iteratively tune the model towards how a specific user annotates. Error mitigation techniques using a flick gesture or on-screen tap are incorporated to correct mode errors or remove a stroke quickly. We evaluated Magic Pen in a comparative study with 18 participants, followed by iterative improvements and a deployment study with 8 participants. Magic Pen was preferred compared to a conventional menu-based approach, and transfer learning allowed for greater model predictability and stability.

## 1. 核心问题与研究背景

- **核心问题：数字笔的“模式切换”会打断批注流程。**  
  在传统文档批注软件中，用户需要反复前往工具栏，切换手写、荧光高亮、下划线等模式。这不仅增加笔尖往返移动和认知负担，还可能因忘记切换或误点按钮产生模式错误。
- **研究动机：让系统从自然笔迹中推断用户意图。**  
  不同批注模式在运动轨迹、压力和相对文本的位置上存在规律，例如高亮通常覆盖文字，下划线通常位于文字底部。作者希望利用这些隐式信号，在用户绘制过程中自动选择工具，而非要求用户额外按键或学习特定切换手势。
- **关键挑战：准确率并不等于良好的交互体验。**
  - 短笔画、字母中的点和横线可能难以分类。
  - 批注风格、设备姿态和文档布局因人而异。
  - 自动切换一旦出错，可能降低用户的控制感和信任。
- **整体含义：**  
  本文不仅研究笔迹分类，还探索了一个完整的自适应交互方案：**实时意图推断、稳定化策略、快速纠错、个性化学习以及手动模式回退**。其价值主要在于人机交互系统设计，而非提出新的神经网络架构。

## 2. 方法论与关键技术

### 2.1 核心思想与输入特征

系统最终识别三种模式：

- **Draw：**手写文字、符号和自由绘制。
- **Highlight：**荧光高亮。
- **Underline：**下划线。

最初还考虑删除线，但由于其与高亮容易混淆，后续研究将其移除。

系统通过浏览器 Pointer Events API 记录笔输入，多数采样间隔约为 **10–15 ms**，将连续 **10 个采样点**组成一个笔画窗口。最终使用六类特征：

| 特征 | 含义 |
|---|---|
| ΔX、ΔY | 相邻采样点的位置变化 |
| 笔压力 | 归一化到 0–1 的压力 |
| 压力变化 | 相邻采样点的压力差 |
| 是否覆盖文本 | 笔尖是否位于文本对象上方 |
| 距离文本底部的位置 | 到最近文本边界框底部的距离，以文本高度归一化 |

这些特征同时描述**笔的运动行为**与**文档上下文**。虽然研究采集了倾斜等信息，但它们未进入最终特征集。

### 2.2 两种模式分类方法

- **机器学习方法：**
  - 使用单层 LSTM，包含 **10 个隐藏单元**，后接两组全连接层。
  - 使用类别权重缓解训练数据不平衡。
  - 采用批归一化、Gaussian Noise 和 Dropout 控制过拟合；后两者参数分别为 **0.1、0.15**。
  - 批大小为 **64**，最多训练 **500 个 epoch**。
  - 使用 EarlyStopping，耐心参数为 **20**。
  - 作者通过逐步加入特征、搜索隐藏单元数及超参数选择配置，但未完整报告所有搜索结果。

- **规则方法：**
  - 根据笔迹相对文本的位置，人工构建决策树。
  - 同样使用笔画窗口进行分类，便于与 LSTM 保持一致的处理流程。
  - 优点是逻辑更容易理解；不足是难以利用压力和运动动态，且高度依赖文本位置。

### 2.3 实时模式选择与稳定化

初版处理流程为：

1. 收集笔输入并构建窗口。
2. 若笔画结束时不足 10 个采样点、但至少有 2 个点，则线性插值补齐。
3. 对窗口进行分类。
4. 只有最近 **3 次连续分类一致**，才更新显示模式。

后续加入三项改进：

- **快速连续笔画启发式：**若新笔画与上一笔画间隔小于 **500 ms**，直接继承上一笔画模式，帮助处理字母中的点、短横线等。
- **置信度启发式：**若窗口分类置信度低于 **75%**，以此前笔画模式替代该窗口预测，再进入模式选择流程。
- **带迟滞的模式选择：**候选模式的连续分类次数必须比当前模式对应次数多 **25%**，才允许切换，以减少同一笔画内反复变换模式。

这些机制以部分响应灵活性换取稳定性；例如，快速连续但意图不同的笔画也可能错误继承模式。

### 2.4 错误缓解设计

- **初版：橡皮端轻弹手势。**
  - 在空白区域向上或向下轻弹，循环改变最近笔画的模式。
  - 但与正常擦除共享橡皮端，容易误删已有笔画；用户还需要记住模式循环顺序。
- **改进版：点击快速删除。**
  - 最近笔画完成后显示半透明橙色提示。
  - 提示持续 **5 秒**，或直到下一笔画开始。
  - 用户可点击屏幕删除最近笔画，再重新绘制。

因此，轻弹纠正模式与点击删除主要属于**不同迭代版本**，不宜简单理解为最终系统同时依赖两种纠错方式。

### 2.5 个性化迁移学习

这里的“迁移学习”主要是**在同一分类任务上进行用户级微调**：

- 以多用户数据训练的模型作为起点，使用个人笔迹继续训练，学习率设为 **0.0001**。
- 离线实验使用目标用户 **20% 数据微调、80% 数据评估**。
- 在线系统至少积累 **500 个窗口，约 10–20 个笔画**后才触发训练。
- 训练发生在会话结束时，或切换到手动模式 **10 秒后**，避免干扰自动分类。
- 新模型只有在用户验证集上准确率 **超过 80%**时才被保留。
- 工具栏用颜色反馈模型质量：灰色表示不可用，橙色表示 80%–90%，绿色表示超过 90%。

训练标签的收集依赖一个重要假设：**用户若认为模式错误，会在下一笔画前删除它；未及时删除的笔画可以作为训练样本。**

  - 7 人最喜欢菜单；

- 菜单显著更可预测；规则方法报告的努力程度显著低于 LSTM。

### 6.2 自动切换改变了批注组织方式

相邻笔画模式发生变化的比例为：

- LSTM：**29.3%**
- 规则：**22.2%**
- 菜单：**10.6%**

这表明自动模式更容易支持交替批注，而菜单更容易促使用户按工具分组操作。不过，这不能直接证明自动方法更快或批注质量更高。

### 6.3 个性化微调具有潜力，但在线收益并不单调

- 27 人离线实验中，微调后准确率平均提高约 **3.44 个百分点**。
- 最大提升约 **13.88 个百分点**，但有 1 人小幅下降。
- 部署期间，验证准确率在 **80%–100%**之间波动；最终会话相较第一次迁移学习会话，平均验证准确率反而下降约 **5 个百分点**。
- 作者认为每次使用不同的近期验证数据，使跨会话比较难以解释。这意味着部署结果**不能证明模型客观准确率持续提高**。

### 6.4 用户满意度与准确率之外的因素有关

- 部署研究中，主观准确性、可预测性和效率总体改善，自动模式使用增加，后期笔画删除减少。
- 使用意愿评分为 **M=3.88，SD=1.0**。
- 挫折感与偏好相关，报告 **R=0.78，p=0.02**；但样本仅 8 人，且部分量表反向处理，不应作强因果解释。
- 核心发现是：**预测稳定性、错误恢复成本和用户能否理解系统行为，同样决定交互接受度。**

## 7. 优点与亮点

- **问题明确、应用价值直接：**针对高频文档批注中的工具栏往返操作，而非孤立地优化识别准确率。
- **结合笔迹与文档上下文：**用少量特征和小型 LSTM 支持自动模式推断，具有浏览器部署可行性。
- **关注实时过程：**分类在绘制过程中进行，而不是仅在笔画结束后改变外观。
- **重视失败处理：**通过真实用户反馈，将易误触的模式纠正手势改为更清晰的快速删除机制。
- **支持自动与手动共存：**允许用户回退，并利用手动模式提供个性化训练数据。
- **评价不限于准确率：**揭示规则系统虽不够准确，却可能因可理解性而更受欢迎。
- **具备端侧实现：**最终架构避免服务器分类往返，并为非研究应用中的本地隐私保护提供基础；研究期间仍上传了相关日志和脱敏材料。

## 8. 不足与局限

### 8.1 数据与泛化范围有限

- 初始数据仅来自 9 名右利手参与者，部署研究也全部为右利手。
- 参与者年龄、背景和数字笔经验覆盖有限。
- 最终仅支持三种模式，尚未覆盖删除线、选择、复杂编辑等操作。
- 对密集行距、无文本层 PDF 或扫描件较敏感，因为核心特征依赖文本对象的位置。

### 8.2 评估指标存在风险

- 初始随机交叉验证未清楚说明是否按用户划分；若同一用户出现在训练和测试中，结果不能代表新用户泛化能力。
- 窗口级准确率无法完整体现笔画内模式抖动、用户看到的错误或真实修正成本。
- 删除笔画不一定代表模式错误，也可能是内容修改或重画。
- 变化的近期验证集和 **80% 模型接纳门槛**使部署准确率难以作为长期性能趋势指标。

### 8.3 在线学习可能强化错误

- “未在下一笔前删除即视为正确”的假设可能引入错误伪标签，形成反馈循环。
- 训练批次若主要包含一种模式，可能造成类别偏斜或遗忘其他模式；本文没有充分检验这类风险。
- 完全依赖自动模式的用户可能无法提供足够的可靠手动标签，个性化效果因此受限。

### 8.4 缺少组件级与长期验证

- 没有独立消融快速继承、置信度阈值、迟滞机制和迁移学习。
- 缺少固定长期测试集、更多设备和文档布局测试。
- 缺少明确的耗时、认知负荷和长期生产力测量。
- 用户体验改善可能同时来自模型适配、任务熟悉和用户主动改变笔迹，不能完全归因于模型学习。

### 综合评价

Magic Pen 展示了**自动模式推断结合个性化适配与低成本纠错**的可行性，其最重要的贡献是说明：交互系统的成功取决于准确率、可预测性、控制感和错误恢复的共同作用。现有证据支持其作为值得继续发展的交互原型，但尚不足以证明它在广泛真实场景中稳定、显著地优于传统工具栏。
