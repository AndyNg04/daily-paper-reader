## 摘要
训练大语言模型（LLM）智能体与用户进行多轮交互颇具挑战，因为学习信号不仅取决于智能体，还取决于用户模拟器和环境；三者共同塑造智能体的经验。模拟用户可能具有随机性或行为不一致，而环境则可能包含不可靠的工具、不完整的状态覆盖以及错误的验证器。以往研究主要通过奖励塑形或更密集的监督来应对由此产生的不稳定性，同时将这些组件视为固定不变。为此，我们提出 EAU，一种用于环境—智能体—用户协同演化的元智能体框架。在训练过程中，EAU 会监控交互轨迹、工具调用记录、奖励和训练统计信息，诊断失败及缺乏有效信息的交互，并针对用户模拟器、环境、奖励设计和强化学习（RL）配置提出有针对性的修改。经验证的改动会被热切换至正在进行的训练流程中，使训练设置能够随策略共同演化。这些调整还会保留并延续至后续训练，使其能够基于此前发现的改进继续推进，而非从固定设置重新开始。我们通过用户与环境动态的可编辑符号表示实现这一过程，同时智能体仍采用经 RL 优化的神经网络大语言模型。在三个交互式智能体基准和两种骨干模型上的实验表明，EAU 的表现始终优于以往的 RL 方法：相较于最强基线，其总体得分提升了 14.7%—15.0%，并使 ColBench 上的任务成功完成率最高提升 36.7%。这表明，使训练系统与策略协同演化，能够显著提升多轮 RL 的效果。

## Abstract
Training LLM agents to interact with users over multiple turns is challenging because the learning signal depends not only on the agent, but also on the user simulator and environment, which jointly shape the agent's experience. Simulated users can be stochastic or inconsistent, while environments may contain unreliable tools, incomplete state coverage, and incorrect verifiers. Prior work mainly addresses the resulting instability through reward shaping or denser supervision, while treating these components as fixed. We instead introduce EAU, a meta-agent framework for environment--agent--user co-evolution. During training, EAU monitors trajectories, tool traces, rewards, and training statistics; diagnoses failures and uninformative interactions; and proposes targeted modifications to the user simulator, environment, reward design, and RL configuration. Validated changes are hot-swapped into the ongoing run, allowing the training setup to evolve together with the policy. These adaptations also persist across runs, so later training can build on previously discovered improvements rather than restarting from a fixed setup. We enable this process through an editable symbolic representation of user and environment dynamics, while the agent remains a neural LLM optimized with RL. Across three interactive-agent benchmarks and two backbone models, EAU consistently outperforms prior RL methods, improving the overall score over the strongest baseline by 14.7--15.0% and increasing successful task completion on ColBench by up to 36.7%, showing that co-evolving the training system with the policy can substantially improve multi-turn RL.

## 1. 核心问题与研究动机

### 1.1 论文要解决什么问题？

面向用户的智能体通常不能直接获得完整任务说明，而需要通过多轮对话澄清需求、获取隐藏信息，并调用工具完成任务。因此，其强化学习训练质量不仅取决于策略模型，也取决于**用户模拟器和环境是否能够生成可靠、有信息量的交互经验**。

论文指出，固定训练系统存在三类问题：

- **用户模拟器不可靠**：可能编造信息、提前泄露答案、偏离指定人设，或在相似情境下表现不一致。
- **环境实现存在缺陷**：工具、状态覆盖、任务可达性和验证器可能有问题，导致奖励失真。
- **训练经验逐渐失去针对性**：随着策略能力提升，固定模拟器与环境仍可能持续产生重复、简单或无法暴露当前弱点的交互。

以往方法主要通过奖励塑形、辅助监督等方式改善下游学习信号，但如果交互过程本身出错，仅修改奖励并不能恢复原本应有的任务体验。

### 1.2 整体思想与研究意义

EAU 将优化对象从“智能体策略”扩展为“**产生训练经验的整个系统**”：

> 由元智能体持续诊断训练问题，并联合修改用户模拟器、环境、奖励和训练配置，使训练系统与策略共同适应。

这里的“协同演化”是**非对称、由元智能体协调的共同适应**，并不意味着环境、用户与智能体都是通过梯度训练的独立模型：智能体通过 RL 更新，用户和环境主要通过代码与规则修改更新。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 总体架构

EAU 使用编码智能体担任元智能体，读取：

- 多轮对话与任务轨迹；
- 工具调用及返回结果；
- 奖励与任务成功率；
- 熵、对数似然等训练统计；
- 训练源码和配置文件。

元智能体据此判断问题来自策略、用户模拟器、环境实现还是优化配置，并执行针对性干预。

### 2.2 用户侧：可编辑符号用户与 LLM 用户混合

论文引入**符号用户模拟器**，以显式规则将交互状态映射为用户回复，例如：

- 哪些事实可以回答；
- 每次最多披露多少事实；
- 什么条件下主动补充信息；
- 遇到用户本来不知道的信息时，应明确表示不知道，而不是编造。

符号用户可控、确定，但自然性和表达多样性有限；LLM 用户更灵活，却可能不一致。因此，论文采用概率混合：

- 以概率 **ε** 使用符号用户；
- 以概率 **1−ε** 使用 LLM 用户。

框架允许修改混合比例、规则、温度与人设提示，但**接口支持不代表实验中实际使用**。例如，附录分析的 ColBench 运行中，混合比例始终固定为 0.5，并未验证动态调整比例的收益。

### 2.3 环境侧：调整奖励、交互约束与实现

环境演化主要不是学习新的世界模型，而是：

- 在成功奖励过于稀疏时，增加中间进展奖励；
- 修改诱发错误行为的奖励规则；
- 调整最大交互步数、最低提问要求等约束；
- 修复训练代码或接口缺陷。

例如，元智能体发现 ColBench 的提问计数器遗漏“同一轮既提问又回答”的情况，导致部分交互陷入死锁，并进行了代码修复。

### 2.4 智能体侧：RL 更新与训练动态干预

默认训练算法为 **PPO + 学习型价值网络 + GAE**。

关键设计是：

- 价值估计仅作用于智能体的动作 token；
- GAE 沿动作序列计算，而不是将环境观察、用户回复等所有 token 一并纳入；
- 目的是避免交互中的观察文本稀释动作的信用分配。

元智能体不必重写底层算法，而可以调整熵系数、KL 系数等参数。论文另通过实验说明，该框架也可以与 UserRL、InfoPO 配合。

### 2.5 运行内与跨运行干预

EAU 支持两个时间尺度：

- **运行内干预**：将规则、奖励或训练配置热更新到当前训练过程中。
- **跨运行干预**：在严重故障或不可在线修复时重启，并将已有经验用于后续运行。

经验以文件系统中的文档保存，供元智能体后续查询和更新。

其流程可以概括为：

1. 执行 RL 训练并收集轨迹和统计。
2. 元智能体定期检查，识别异常或低信息量交互。
3. 参考历史经验，提出代码、规则或参数修改。
4. 通过有限的接口与完整性检查。
5. 热更新，或在必要时回滚、恢复检查点、重启。
6. 记录观察结果，指导后续干预。

需要注意，所谓“验证”主要是**约束写入范围、检查接口和准入条件**，并不能保证修改具有正确的行为效果。

## 6. 主要结论与发现

### 6.1 主结果整体较强

- **Qwen3-4B 总体得分**：由 InfoPO 的 **0.545** 提升至 **0.627**，相对提升约 **15.0%**。
- **Qwen2.5-7B 总体得分**：表 1 为 **0.544 → 0.615**。
- **ColBench / Qwen3-4B**：
  - Pass：**0.553 → 0.685**，相对提升约 **23.9%**；
  - Succ.：**0.439 → 0.600**，相对提升约 **36.7%**，即绝对增加 **16.1 个百分点**。
- **τ²-bench**：平均得分由 PPO 的 **18.5 → 21.5**，相对提升约 **16.2%**。

“最高 36.7%”对应特定模型、基准和指标，并非所有任务的统一提升。

### 6.2 改善不是均匀发生的

- τ²-bench 中，EAU 在航空和电信表现最好，零售仍由 InfoPO 领先。
- UserGym 的跨环境迁移有正面证据，但 Tele. 上未超过 InfoPO。
- 纯符号用户比纯 LLM 用户更差，混合用户仅有小幅均值提升，说明**确定性并不能替代交互多样性**。
- 单纯引入通用元智能体收益不稳定，EAU 的结构化接口与专用流程更重要。

### 6.3 局部指标可能误导干预

附录中的发现尤其值得注意：

- 增加事实披露可能直接泄露参考解；
- 更主动的用户回复可提高流程成功率，却降低智能体提问率；
- 提高 token 熵不一定提高实际行为多样性；
- 缩短交互预算可能显著损害成功率。

这些现象表明，元智能体需要结合轨迹理解，而不能只依据奖励或单项统计决策。

### 6.4 数值报告存在不一致

提供文本中有几处需要核对：

- Qwen2.5-7B 的 **0.544 → 0.615** 实际相对增幅约为 **13.1%**，不是正文声称的 **14.7%**。
- UserGym 均值在主表、正文和消融表之间存在不一致，例如 Qwen2.5-7B 的 **0.632** 与 **0.620**。

因此，论文摘要中的“14.7%—15.0%”不宜未经核验直接视为完全一致的统计结论。

## 7. 优点与亮点

- **问题定位有价值**：把学习不稳定的原因追溯到经验生成过程，而不只归咎于奖励或策略优化。
- **系统级适应能力强**：统一纳入用户规则、环境约束、奖励、训练参数和代码修复。
- **支持在线干预与经验积累**：不必所有修改都重新训练，失败经验也能用于后续运行。
- **符号与神经方法互补**：符号用户提供可控性，LLM 用户保留自然交互与多样性。
- **评估隔离明确**：避免利用最终测试反馈指导训练系统搜索。
- **负面结果披露较充分**：记录有害修改、控制接口失效及归因撤回，使方法边界更清楚。
- **兼容性得到初步验证**：不仅适用于默认 PPO，也能与其他 RL 方法和编码元智能体结合。

---

## 8. 不足与局限

### 8.1 方法贡献难以精确拆解

EAU 同时进行了代码修复、模拟器调整、奖励塑形和超参数搜索。最终提升中，各部分分别贡献多少尚不清楚。

尤其是修复原有实现缺陷也能带来明显收益，因此仍需要“**所有方法共享修复后的环境，再比较适应机制**”等更严格实验。

### 8.2 完整性检查不等于语义正确

接口检查主要限制参数范围和更新条件，不能保证：

- 不泄露隐藏任务信息；
- 不诱发奖励投机；
- 不降低真实交互质量；
- 不产生延迟性的负面影响。

附录也展示了控制变量名称与实际行为不一致、验证窗口过短等问题。

### 8.3 泛化与真实用户证据有限

- 只有两个 Qwen 骨干，缺少更广泛模型家族与规模测试。
- ColBench 仅使用后端编程子集。
- 没有真实用户实验，也没有长期部署研究。
- 模拟环境成绩不能直接推出真实用户满意度、信任、安全性或协作效率提升。

### 8.4 可复现性与成本不透明

依赖闭源编码元智能体和外部模型服务，而元智能体干预路径本身具有随机性。即使配置相同，也可能得到不同修改序列；缺少全流程独立重复与成本统计，限制了稳定性和性价比判断。

### 8.5 部分框架能力尚未充分验证

动态混合比例、部分用户人设、奖励接口等并非在所有基准上可用或被实际使用。应区分：

- 框架允许什么；
- 实现支持什么；
- 实验真正执行了什么；
- 哪些操作已被证明有效。

**总体而言，EAU 提供了一个有说服力的系统级研究方向：训练体验本身也应随策略持续优化。但现有证据更能支持“该框架在所测设置中改善了最终性能”，尚不足以证明其普遍具备更高计算效率、稳定的自主改进能力或真实用户收益。**

（完）
