## 摘要
目前，基于大语言模型（LLM）的智能体安全性依赖于对齐训练和安全分类器，但二者都无法排除复杂的间接提示注入（IPI）得逞并造成重大危害的可能。因此，近期研究构建了具备信息流保障的智能体，并依靠结构化工具接口与环境交互。计算机使用智能体（CUA）通过视觉方式操作计算机屏幕，而屏幕并未提供可信的第一方界面与不可信且可能由攻击者编写的内容之间的边界。操作本身也同样存在歧义：一次点击可能落在应用程序工具栏上，也可能落在由攻击者控制的按钮上。将用户视为信任源，并要求其确认每一项敏感决策，会造成确认疲劳，从而增加漏掉有害操作的风险。我们提出 SA-CUA，这是一种双 LLM 框架，通过从辅助功能树中推导保守的确定性规则，在特权 LLM 的屏幕截图中揭示可信区域，从而为 CUA 建立可靠的信任边界，并将可信与不可信内容分隔开来。人机交互仅在任务开始时用于正确指定任务。任务执行过程中，稳健的背书通道通过可信渠道验证信息，使数值能够从不可信域传递到可信域。这使智能体能够自主处理涉及不可信信息的任务。SA-CUA 在将攻击成功率保持为零的同时，维持了远高于 CaMeL-CUA 的实用性。

## Abstract
The safety of LLM-based agents currently rests on alignment training and safety classifiers, neither of which can rule out that a sophisticated indirect prompt injection (IPI) goes through and causes significant harm. Recent work therefore builds agents with information-flow guarantees that rely on structured tool interfaces to interact with the environment. Computer Use Agents (CUAs) act visually on the computer screen, which does not provide a boundary between trusted first-party interfaces and untrusted, potentially attacker-authored content. Actions are equally ambiguous: a click may land on an application toolbar or a button controlled by an attacker. Treating the user as the source of trust and confirming each sensitive decision produces confirmation fatigue, with the risk of missing harmful actions. We introduce SA-CUA, a dual-LLM framework that generates a reliable trust boundary for CUAs by deriving conservative deterministic rules from the accessibility tree for unmasking trusted regions from the privileged LLM's screenshot, keeping trusted and untrusted content separated. Human interaction is only required for proper task specification in the beginning. During the task a robust endorsement channel allows values to pass from the untrusted to the trusted domain by verifying information via trusted channels. This allows the agent to autonomously handle tasks involving untrusted information. SA-CUA maintains much higher utility than CaMeL-CUA while keeping the attack success rate at zero.

## 1. 核心问题与研究背景

### 1.1 论文要解决什么问题？

论文研究的是：**计算机使用智能体（Computer Use Agents，CUAs）如何在接触攻击者可控制的屏幕内容时，仍安全、自主地完成任务，而不依赖用户反复确认。**

CUA 通过截图理解环境，并使用鼠标、键盘操作浏览器和桌面应用。这种通用交互方式存在三个安全难点：

- **视觉内容混合**：可信的应用控件与不可信的帖子、邮件、文档等同时出现在截图中。
- **操作语义不明确**：同样一次点击，可能是在操作可信工具栏，也可能是在触发攻击者提供的链接。
- **任务通常依赖外部信息**：安装软件、回复邮件、添加协作者等任务，需要读取网页或消息中的名称、地址、命令，不能简单屏蔽所有外部内容。

攻击者可以在这些内容中嵌入**间接提示注入（IPI）**，诱导智能体泄露文件、删除数据、修改权限或使用错误收件人。

### 1.2 为什么现有方案不够？

- **对齐训练与安全分类器**只能降低攻击概率，不能排除复杂注入。
- **传统双模型隔离**让有权限的模型不读取不可信内容，但会严重限制依赖外部数据的任务。
- **限制返回类型或通信容量**不等于确保内容正确。例如，恶意邮箱和真实邮箱都符合邮箱类型。
- **逐次人工确认**增加用户负担，并可能引发“确认疲劳”。

论文的整体思路是：**把安全防线从模型“识别恶意指令的能力”，转移到系统对“可见内容、数据流与操作权限”的控制上。**

## 2. 方法论：SA-CUA

### 2.1 核心架构：双模型隔离

SA-CUA 包含两个运行时模型角色：

| 组件 | 能看到什么 | 可以做什么 |
|---|---|---|
| 特权模型 P-LLM | 用户任务、可信上下文、遮罩后的截图 | 规划任务并调用操作工具 |
| 隔离模型 Q-LLM | 完整截图，包括不可信内容 | 提取指定类型的数据，不能操作计算机 |

Q-LLM 提取的数据首先以**隐藏值的变量引用**返回，例如模型只知道“这是一个 URL 变量”，看不到具体 URL。

- 未核验变量不能直接进入 P-LLM 的明文上下文。
- 读取或用于有实际后果的操作之前，必须经过背书。
- 可以直接将未背书数据报告给用户；论文不把最终回答视为具有实际后果的操作。

此外，规则生成模型 RP-LLM 负责生成界面可信区域规则，通常不参与每一步操作决策。

### 2.2 可信区域标注：默认遮罩，仅揭示可信内容

论文将“不可信用户生成内容”定义为：**网站运营者之外的主体能够影响其显示值的区域**。因此，时间戳、计数等也可能是不可信的，即使它们不能承载完整指令。

其关键设计是：

> 不去穷举并遮住所有不可信内容，而是先遮住全部内容，再明确放行可信区域。

这使规则遗漏通常表现为“看不到某个控件”，而不是“漏出攻击内容”。

#### 规则生成与运行流程

1. **采集无障碍树**
   - 使用 Linux AT-SPI 获取角色、层级、标识符、链接目标、位置和窗口堆叠信息。
   - 同时覆盖网页与原生桌面应用，而非仅依赖浏览器 DOM。

2. **清洗页面文字**
   - 将名称、正文替换为长度占位符，保留角色、ID、class 等结构。
   - RP-LLM 根据站点类别和结构提出可信区域规则，避免直接受页面文字诱导。

3. **检查规则覆盖范围**
   - 删除过宽或无效规则。
   - 最后读取原始文字进行审计；这一阶段只能撤销规则，不能新增信任。

4. **运行时确定性应用**
   - 根据当前域名、URL 模板或应用选择规则。
   - 在实时无障碍树上匹配，并揭示相应截图区域。
   - 缺失节点、几何不匹配等情况默认继续遮罩；无法构建遮罩时重试后停止，不退回完整截图。

系统还对受信任文件、已知同意横幅，以及符合封闭语法的价格、日期等低容量字段设置了特殊放行机制。

### 2.3 操作门控：不仅检查参数，还检查目标位置

系统把点击、输入、拖动等视为具有实际后果的操作：

- 点击目标必须位于可信、已揭示区域。
- 键盘输入需要检查当前焦点是否可信。
- 拖动检查起点与终点。
- 不可信 URL 的获取受到域名白名单限制。
- 滚动、等待等低风险操作可以执行。

因此，**模型即使猜出遮罩区域中的按钮坐标，也不能绕过策略点击它。**

### 2.4 稳健背书：先独立确定预期，再比较候选值

论文最重要的数据流机制是 **robust endorsement，稳健背书**。

其流程可以概括为：

1. 仅从可信信息推导正确值、允许值集合或约束。
2. 推导过程不接触待验证候选值。
3. 使用规范化后的确定性比较，而不是让模型阅读候选值后判断其“是否可信”。
4. 匹配成功后，才将变量提升为可信并展示给 P-LLM。

主要可信依据包括：

- 用户任务中明确写出的值；
- 不接触候选值的模型参数知识；
- 可信联系人目录；
- 受维护的软件仓库、官方文件或版本列表；
- 白名单来源上的独立查询结果；
- 从可信上下文预先生成的有限候选集合。

**这里核验的不是“它像不像一个邮箱”，而是“它是否是这项任务允许使用的邮箱”。**不过，对于任务有意开放选择的部分字段，系统也允许仅按形状或约束背书。

### 2.5 命令与任务说明的特殊处理

- **Shell 命令**：
  - 拆解为程序、子命令、参数、重定向等结构；
  - 检查其能力范围是否符合任务；
  - 对 URL、文件路径、包名等参数逐项背书；
  - 拒绝无法建模的循环、命令替换和未知程序；
  - 执行的是系统重建后的命令，而非页面原文。

- **任务说明分类器**：
  - 在执行前判断任务是否足够具体，以支持独立背书。
  - “安装能在终端输出彩色文字的 Python 包”可以接受。
  - “照屏幕上的说明操作”不能建立独立核验依据，需要用户补充。

## 3. 实验设计与 Benchmark

### 3.1 数据集与任务场景

| 测试集 | 任务数 | 场景与目的 |
|---|---:|---|
| WASP† | 42 | GitLab、Reddit；完成正常任务不必读取注入内容 |
| RTC† | 65 | Reddit、OwnCloud、RocketChat；恶意步骤与正常步骤交织 |
| RTC-value | 78 | Reddit、Thunderbird、GitLab；替换任务需要的值 |
| OSWorld 小子集 | 36 | 无攻击桌面任务，评估正常效用 |
| UCM-B | 99 | 十类无攻击网站任务，评估正常效用 |

共涉及 **185 个对抗任务和 135 个正常任务**。其中 WASP†、RTC† 是作者调整后的版本，不应直接视为原始 benchmark 全量结果。

**RTC-value 是新增的重要测试集**，覆盖：

- 推荐恶意代码仓库或下载地址；
- 仿冒邮件发件人、收件人；
- 假发票与附件；
- 仿冒协作者账号；
- 恶意软件包索引。

其特点是：**攻击值与正确值类型相同，能够通过普通类型检查。**

### 3.2 对比方法与模型

- **CUA**：无额外架构防御的截图操作智能体。
- **CaMeL-CUA**：预先生成计划，通过隔离模型读取环境。
- **SA-CUA**：本文完整框架。
- **UCM**：主要用于可信区域标注对比，未在本文环境中完整复现其端到端智能体。

规划模型使用：

- Qwen3.8-27B；
- GPT-5.6-Luna。

SA-CUA 和 CaMeL-CUA 的隔离模型均为 Qwen3.8-27B；智能体主实验中的规则生成模型统一为 GPT-5.6-Luna。

### 3.3 评估指标与环境

- **ASR@k**：某任务在 \(k\) 次运行中只要攻击成功一次，就计为攻击成功。
- **CR**：正常任务完成率，按运行平均。
- **FR**：既未完成正常任务、也未实现攻击目标的比例。

ASR@k 与 CR、FR 的统计口径不同，**不能简单相加为 100%**。对抗主实验中，Qwen 使用 3 个种子，GPT 使用 1 个种子。

实验在 Ubuntu 虚拟机、自托管网站和模拟邮件服务中进行，任务与攻击结果主要根据文件、数据库、邮件发件箱等环境状态确定性评分。

## 4. 资源与算力

### 4.1 明确披露的资源

每个任务运行环境包括：

- Ubuntu 22.04；
- QEMU/KVM 虚拟机，运行于 Docker 内；
- 4 个 CPU 核心；
- 4 GB 内存；
- 32 GB 磁盘；
- 1920 × 1080 屏幕。

主要预算为：

- 最多 50 个界面操作步骤；
- SA-CUA 最多 70 个规划模型回合；
- 每次操作后等待约 2 秒采集观察。

### 4.2 未明确披露的信息

论文**没有明确报告**：

- GPU 型号、数量及总 GPU 小时；
- 本地模型的完整推理硬件配置；
- 全部实验实际运行时长；
- 总 API 费用。

该研究以推理时系统架构为主，**没有报告新模型训练或微调实验及训练时长**。虚拟机的 CPU、内存配置也不能代表模型推理所需的全部算力。

### 4.3 Token 开销

以 GPT-5.6-Luna 的成功任务计算：

- SA-CUA 的 P-LLM Token 开销约为普通 CUA 的 **7.5 倍**；
- 按论文的缓存计价方式约为 **4.2 倍**；
- 约 73% 来自固定系统提示与工具定义；
- 另有隔离模型和规则生成开销。

这些数字是成功任务上的统计，**不是包含所有失败、重试与离线成本的完整部署账单**。

## 5. 实验数量、充分性与公平性

### 5.1 实验规模

主要结果涵盖：

- **3 个框架 × 2 个规划模型 × 5 个测试集**，约 30 个主实验条件；
- 160 张人工标注截图上的可信区域实验；
- 规则迁移实验；
- 去除背书、操作门控的联合消融；
- 去除文字审计的规则消融；
- 按平台、任务描述详细程度拆分的结果；
- 规则生成成本与执行 Token 成本分析；
- 10 个困难任务上的两个 Claude 模型补充测试。

标注集包含：

- 18 个网页域名、13 类原生应用；
- 20,744 个界面元素，其中 8,515 个不可信。

### 5.2 充分性与客观性评价

**较充分之处：**

- 同时评估安全性、任务完成率与计算成本。
- 涵盖网页、邮件、共享文档、聊天和桌面应用。
- 同时包含指令劫持与同类型值替换。
- 实验间重置环境，并采用确定性状态评分。
- 在同一环境中重跑主要基线，减少跨论文比较误差。

**需要保留的判断：**

- OSWorld 仅使用 36/369 个任务，通用桌面能力覆盖有限。
- GPT 主实验仅一个种子，未报告置信区间或显著性检验。
- UCM 缺少统一环境下的完整端到端对比。
- 联合消融同时移除多个组件，无法精确区分各自贡献。
- 背书工具和应用适配器围绕评测任务构建，对未知任务的迁移能力仍需验证。
- 被分类器拒绝的泛化任务，在实验中会自动换成更具体的 loose 版本。因此部分结果包含了**任务说明被改善后的收益**。

总体上，实验对验证机制有效性较有说服力，但还不足以证明开放环境下的普遍安全与通用可用性。

## 6. 主要结论与发现

### 6.1 已测试攻击中未出现成功攻击，效用高于 CaMeL-CUA

下表为正常任务完成率 CR：

| 规划模型 | 方法 | WASP† | RTC† | RTC-value |
|---|---|---:|---:|---:|
| Qwen3.8-27B | CUA | 81.7% | 95.4% | 53.4% |
|  | CaMeL-CUA | 61.1% | 18.5% | 18.8% |
|  | **SA-CUA** | **88.9%** | **86.2%** | **50.9%** |
| GPT-5.6-Luna | CUA | 97.6% | 98.5% | 60.3% |
|  | CaMeL-CUA | 73.8% | 27.7% | 29.5% |
|  | **SA-CUA** | **100.0%** | **81.5%** | **69.2%** |

- SA-CUA 和 CaMeL-CUA 在三个对抗套件中均为 **0 ASR**。
- 普通 CUA 在 RTC†、RTC-value 上的 ASR 约为 **38.5%—46.2%**。
- SA-CUA 的主要收益是：在同样未观察到成功攻击的情况下，比 CaMeL-CUA 完成更多任务。

### 6.2 正常任务效用仍有明显损失

| 测试集 | 普通 CUA：Qwen / GPT | SA-CUA：Qwen / GPT |
|---|---:|---:|
| OSWorld 小子集 | 58.3% / 58.3% | 30.6% / 38.9% |
| UCM-B | 90.9% / 91.9% | 50.5% / 49.5% |

因此，“效用较高”主要是**相对其他强隔离框架**而言，不意味着接近无防护智能体的通用能力。

### 6.3 默认拒绝提高了标注安全性，但过度遮罩严重

- SA-CUA 在标注集上的自由文本漏遮率为 **0%**。
- UCM 在网页上的对应漏遮率为 **44.1% / 36.7%**。
- 代价是 SA-CUA 的可信元素误遮率较高：网页约 **76.9% / 56.3%**，显著高于 UCM。

### 6.4 类型限制不是完整防线

移除背书与门控后，RTC†、RTC-value 分别出现 **1.5%、3.8%** 的攻击成功率，说明仅靠遮罩与类型约束仍会留下数据流攻击路径。

## 7. 优点与亮点

- **安全边界清晰**：把“谁能读取什么、哪些值能用于操作”落实到系统机制。
- **默认拒绝设计合理**：将规则覆盖不足的主要代价从安全泄漏转为功能下降。
- **稳健背书具有针对性**：候选值不能参与生成自身的验证标准，降低“恶意内容说服验证者”的风险。
- **覆盖网页与原生应用**：AT-SPI 比纯 DOM 方案更适合混合桌面任务。
- **强调语义层面的值替换**：仿冒邮箱、仓库和账号比明显的“忽略先前指令”更贴近真实风险。
- **报告负面结果较充分**：明确展示正常效用下降、高误遮率、长任务失败和额外成本。
- **减少执行期确认负担**：将人工投入前置到可信源配置和任务说明，而非每一步审批。

## 8. 不足与局限

### 8.1 “零攻击成功率”不是无条件安全证明

需要区分：

- **实验证据**：在本文样本与种子中未观察到成功攻击。
- **架构性质**：如果标注正确、背书来源可信、策略实现无漏洞，可以限制不可信信息影响高权限操作。
- **现实部署保证**：仍取决于上述条件是否持续成立。

规则由 LLM 提出，有限截图上的零泄漏并不证明所有动态页面都不会泄漏。文字审计只能删除规则，也不意味着它一定能够识别并删除所有错误规则。

### 8.2 信任来源仍可能存在偏差

- 模型参数知识可能过时或错误。
- 白名单网站也可能包含攻击者可提交的信息。
- 论文将 GitHub 等开放平台用于部分权威核验，不能据此假定搜索结果天然可信。
- 软件包存在于可信仓库，不等于它一定符合用户意图。

因此，**验证过程独立于攻击候选值，不等于可信来源必然正确，也不等于任务授权检查完整。**

### 8.3 低容量信息仍可能影响决策

论文指出单比特也能改变控制分支，但同时允许部分价格、日期、版本号等按容量或形状放行。

这些字段虽然难以承载自然语言指令，仍可能通过错误价格、版本或数量影响任务结果。此类放行应理解为**特定威胁模型下的策略选择**，而不是普遍的数据正确性保证。

### 8.4 不保证机密性与一般正确性

- 论文明确不提供完整的机密性保障，例如智能体仍可能在公开帖子中披露敏感信息。
- 最终报告允许携带未背书内容；若下游系统将报告再次作为指令执行，风险会被转移。
- 可信上下文中的模型本身仍可能规划错误，架构并不能解决所有误操作。

### 8.5 开放任务与长流程能力不足

- 若任务只能依赖卖家描述、未知账号等不可独立核验的信息，系统可能只能拒绝。
- Thunderbird 长任务完成率较低，Qwen 约 **8%**、GPT 约 **36%**。
- 高遮罩率增加查找控件、核验与重试的复杂度。
- 未知应用、页面结构变化和新的命令语法需要额外规则或适配支持。

### 8.6 成本与威胁覆盖有限

- 执行 Token 开销较高，规则生成也需要额外调用。
- 未充分评估可信站点被攻陷、恶意第一方界面、多渠道协同或自适应攻击者。
- 辅助功能树到像素的映射、动态更新与策略执行仍是需要持续验证的工程边界。

**总体评价**：SA-CUA 的贡献在于展示了一条可行路线——通过“默认遮罩、双模型隔离、独立背书和操作门控”，在受限威胁模型下提升智能体的安全自主性。它显著改善了强隔离系统的可用性，但距离低成本、开放环境、完整安全保障的通用个人智能体仍有明显距离。
