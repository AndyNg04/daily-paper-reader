## Abstract 

CTR, MRR, and behavioral NDCG assume the user sees ranked results and acts on them. In an agentic assistant, a generation layer consumes retrieval output first, and that assumption breaks in three ways. The agent reads the results before the user does (who). The user’s action can come several turns or sessions after re-trieval (when). Outcomes blend retrieved content with the model’s own knowledge (what caused it). We call this the attribution gap. We propose Layered Agentic Retrieval Assessment (LARA), which measures retrieval quality, engagement and outcome, and product success as three independent layers joined by a four-field lineage schema that requires no new modeling. We examine the motiva-tion on Adobe Express, where one retrieval infrastructure serves a gallery search surface and an agentic assistant at roughly one-eighth its session volume for the same user population. Chat users reformulate more than gallery users (44.4% vs. 33.1%) because chat reformulation refines generated output. LARA restores attribution for the retrieval.

a subagent whose output is consumed by a generation layer before the user sees anything. Each assumption fails, and each failure is a structural shift rather than a tuning problem. 

Shift 1: the agent reads the results first (who). In gallery search, a user types “birthday invitation,” scans 40 templates, and clicks one; the click grades retrieval. In an assistant, the user asks for a birthday invitation, the search subagent retrieves templates, and the agent picks one and builds the design. The user never sees the other 39. There may be no click at all, and whatever the user does see has already been filtered and reordered by the agent. 

Shift 2: action and retrieval come apart in time (when). In a conversation, the same asset can be retrieved in turn 1 and again in turn 3, then exported in turn 5 or in a different session. Without an identifier that links the action to a specific retrieval event, timing cannot say which retrieval earned it. 

Shift 3: retrieval and generation blend (what caused it). Abad outcome cannot be split between retrieval failure and gener-ation failure, and a good outcome can hide a retrieval failure the model quietly compensated for. Without per-component instrumentation, teams rely on session-level proxies such as retry, abandonment, and task completion. Retry alone fails in both directions. It fires on generation failures unrelated to retrieval, and stays silent when the model covers for a retrieval failure. We call this the attribution gap. Prior work frames agentic retrieval [12], reintroduces fine-grained feedback into gen-erative search [2], and documents technical debt in production ML [10] and drift in agentic systems [8], but leaves retrieval attribution in production unresolved. We make three contributions. (1) A who/when/why account of how agentic assistants break behavioral retrieval attribution, mapped to the metric failures each shift causes (§2.1). (2) LARA, three independent measurement layers joined by a four-field lineage schema that restores attribution without new modeling (§2.2–2.5). (3) Production evidence from Adobe Express, where one retrieval in-frastructure serves a gallery search surface and an agentic assistant for the same user population (August 2026), including a reformula-tion rate that runs opposite to the naive expectation and a retrieval rate of 0.31% on assistant prompts (§3–4). LARA evaluates retrieval once a retrieval event fires; whether retrieval should fire at all is a planner-routing question we name Layer 0 and leave to future work.

## 2.2 Three layers 

LARA measures each pipeline stage at the earliest point where its failure becomes observable.

Figure 1: LARA’s three layers. Layer 1 is computable from server-side logs alone. Layers 2 and 3 require the lineage schema from §2.4. The schema (right) connects all three lay-ers across event types and turns. Layer 1: Retrieval quality. Did the search subagent return the right assets, in the right order? Metrics are null rate, precision@1, precision@K, and NDCG@K, computed from server-side logs against offline relevance labels (human or LLM-as-judge [13]) at the mo-ment retrieval fires, independent of anything the user or agent does next. CTR becomes a secondary directional signal. Layer 1 is the only layer that can detect a silent retrieval failure the model compensated for. 

Layer 2: Engagement and outcome. Did anyone use what re-trieval returned, and did anything signal that retrieval was wrong? Layer 2 keeps positive evidence and failure evidence separate and reports both by retrieval role, a tag written at retrieval time that records what retrieval was for: direct retrieval, retrieve-then-inspect, retrieve-then-act, reference input for generation, an embedded step in a larger task, or context-dependent. 

Genuine Positive Rate (GPR) is the share of retrievals followed by user-initiated use of a returned asset after the response is shown, ei-ther a follow-up prompt that continues with it or a direct interaction such as selecting, editing, or exporting it. 

Agent Consumption Rate (ACR) is the share of retrievals where the agent uses a returned asset inside the same request, before the user has a result to act on (e.g., finding a logo and removing its background because the user asked for both in one prompt). This is positive evidence that the result entered the workflow, and it is counted, not discarded. It is tracked separately from GPR because it carries different evidentiary weight: the agent using an asset is the agent’s judgment, while a user’s follow-up action is independent confirmation. A retrieval can register in both GPR and ACR if the user later acts on the same asset the agent already consumed. 

Observed Retrieval Failure Rate (ORF) is the share of retrievals followed by at least one of three retrieval-specific signals, Search Correction (the user says the retrieved object or route was wrong), Search Reformulation (the user tries again to retrieve for the same unresolved need), or Agentic Rejection (the workflow expected to consume a returned asset but used something else). A Downstream Correction, which fixes an edit, answer, or generation while keeping the retrieved asset, is not a retrieval failure. The Observed Non-Failure Rate (ONFR = 1 − ORF) is reported alongside GPR and ACR and never read as satisfaction. 

Unobserved Outcome Rate (UOR) is the share of retrievals with no evidence of use by the user or the agent and no failure signal. It is reported as its own category, not as abandonment or as success. 

Layer 3: Product success. Did the user accomplish the goal? In creative tools the clearest signals are export, share, and download, because the goal is a work artifact. Task completion is defined per retrieval role rather than globally, and goal fulfillment requires LLM-as-judge [13] or human annotation. Layer 3 becomes a retrieval signal, not only a product-health signal, when source_retrieval_id links the success event to the retrieval that supplied the asset. 

## 2.3 Reading the layers together 

Reading Layer 1 against Layer 2 locates the failing stage (Table 2). The last row is the most dangerous. Without Layer 1 it is invisible; with Layer 1 it is detectable when retrieval fires, before complaints accumulate. 

## 2.4 Lineage schema 

In current production logs, retrieval events and action events share no field that connects them. Four fields close the gap. retrieval_id is a unique identifier on every retrieval event. returned_asset_ids is the full ranked list at fire time, before the generation layer filters or reorders it; alone it enables Layer 1 and is the highest-value single change. consumed_asset_id is the asset on every action event, whether a user action or an agent tool call. source_retrieval_id is the retrieval_id that supplied that asset, on the same action event; for an asset already placed in the document, it is inherited from the placement event. All four are logging additions, not predictive models; no new modeling is required. Because source_retrieval_id names a retrieval rather than a ses-sion, it resolves cross-turn recurrence (Shift 2) and survives session boundaries, so exports landing in a new session stay attributable. Joined, the four fields recover the retrieval rank of the asset ac-tually used, independent of display order, letting RAG evaluation frameworks such as RAGAs [3] and ARES [9] use direct attribution instead of timing heuristics. The retrieval role tag is written on the retrieval event alongside them.

## 3 Production Evidence from Adobe Express 

Adobe Express serves a gallery search surface and an agentic AI assistant, with chat and in-editor entry points, from the same re-trieval infrastructure to the same user population. We analyzed production sessions from August 2026. Table 3 reports the behav-ioral proxies teams compute today. None of LARA’s lineage fields is implemented yet, so every engagement figure is timing-based. Table 3 demonstrates the problem LARA addresses, whether the same metric means the same thing across interaction modes. §3.4 shows what LARA itself can measure today. 

## 3.1 Shift 1: the agent reads first 

Assistant-wide CTR is near zero because 99.7% of interactions never invoke retrieval, leaving no applicable denominator. Retrieval fired on 0.31% of in-scope assistant prompts. Where retrieval fires, it works. The null rate is 1.51% and users click about 1.05 times per returned grid. The direct test is ACR, which requires con-sumed_asset_id and is not yet computed. Externally, click-free consumption reached 68.0% of U.S. search queries and rises when an AI-generated answer is shown [4]. 

## 3.2 Shift 2: action is delayed 

Assistant sessions average 2.04 prompts (chat: 2.65), so retrievals are routinely followed by further turns in which the same as-set can reappear. More directly, exports initiated from chat land in a different session_guid once the user leaves the chat surface. Session-level attribution counts these users as abandoning, which inflates chat abandonment (59.5%) and deflates engagement. Carry-ing source_retrieval_id on the export event removes this error. 

## 3.3 Shift 3: retrieval and generation blend (the reformulation reversal) 

A naive reading predicts that assistant users reformulate less than gallery users, since they do not inspect result lists. Chat users re-formulate more: 44.4% versus 33.1%. The two numbers measure different behavior. Gallery reformulation means “these results were not relevant; I will try another query.” Chat reformulation mostly means “I see the generated output and want to change it” (“make it bluer,” “try a bolder font”), because most chat prompts never trigger retrieval. This is Shift 3 in production data: one behavioral signal mixes retrieval failure with generation refinement, and the aggre-gate cannot be read as either. LARA splits it into Search Reformula-tion, counted only on retrieval turns, and Downstream Correction, counted everywhere else. At the model level, the blending itself is well documented. Models often favor parametric knowledge over retrieved context when the two conflict [7].

## 4 Unexpected Finding: Retrieval Nearly Vanishes 

Gallery search is retrieval by definition; the assistant invoked re-trieval on 0.31% of prompts. Roughly 82% of assistant activity is generative editing with no gallery-search analog. LARA’s layers apply once retrieval fires, covering only a small slice of interaction volume. The larger risk may be missed retrieval: the planner routes a prompt such as “find me a birthday invitation template” to gener-ative editing, no retrieval event fires, and Layer 1 has nothing to score. Confirming this requires ground-truth intent. Table 3’s 10.7% chat retrieval-intent figure is directional until reconciled against the 0.31% fired-retrieval figure; if it reflects intent rather than fired retrieval, the gap between the two is itself a first estimate of missed retrieval. We name this Layer 0, planner routing, and treat it as an exten-sion of LARA rather than a fourth layer. This boundary is inten-tional. LARA addresses attribution once retrieval fires; the four-field schema is a concrete fix for that problem. Planner routing needs ground-truth intent labels this deployment does not have. Naming it here keeps the two problems separate without claiming either framework solves both. Two measures follow. Mis-routing rate is the share of retrieval calls whose prompt falls outside retrieval scope; these calls should be excluded from Layer 1. Missed-retrieval rate is the share of prompts with retrieval intent that never triggered retrieval; it needs ground-truth intent compared against routing decisions, and no published standard provides one. Multi-intent prompts make rout-ing harder still: in a 273-prompt sample, roughly 5–7% contained two or more distinct retrieval intents. Instrumenting Layer 0 means logging the planner’s intent class and routing decision on every prompt, not only on prompts that reach retrieval. Today the plan-ner’s generated query is captured only on the retrieval path, and raw prompt text on about 65% of prompt-send events. 

## 5 Discussion and Conclusion 

Lessons for practitioners. Three lessons from Express apply beyond creative tools. First, do not report assistant-wide CTR or reformula-tion as retrieval metrics; restrict retrieval metrics to turns where retrieval fired, and split reformulation into Search Reformulation and Downstream Correction. Second, log the full ranked list at fire time before adding anything else; it is the only field that unblocks Layer 1. Third, define user-initiated use once and publish the def-inition. Express chat meaningful-action rate moved from 7.6% to 40.5% depending on which actions qualified. Limitations. All evidence comes from one deployment, and the 0.31% retrieval rate and the reformulation reversal may be specific to creative assistants dominated by generative editing. None of the lineage fields is implemented, so all Layer 2 figures are timing-based inferences; retrieval role is inferred post hoc rather than tagged at retrieval time; and chat abandonment is overstated by exports that land in separate sessions. LARA begins at the retrieval component; how the agent interprets intent, generates queries, or decomposes multi-part requests upstream needs separate instru-mentation. Production telemetry is not inherently trustworthy [10]; schema and value-range validation has not been run on this dataset; synthetic traffic was excluded manually; and latency and tokens per successful task are not instrumented per stage. In sum, agentic assistants remove the three conditions behav-ioral retrieval metrics depend on, who sees the results, when the user acts, and what caused the outcome. LARA restores attribu-tion with three independent layers and four logging fields, without new modeling. Adobe Express shows why this is needed. The same reformulation metric measures search failure on one surface and generation refinement on the other. It also shows where the next problem lies. When retrieval fires on 0.31% of assistant prompts, the open question is not whether retrieval ranked well but whether it was called at all.
