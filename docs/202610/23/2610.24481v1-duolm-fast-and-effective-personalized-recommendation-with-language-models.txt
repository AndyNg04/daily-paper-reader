Abstract 

Language models can make personalized rec-ommendations from rich item content, user history, and feedback. However, evaluating many candidates with full-text inputs incurs substantial online computation and limits serv-ing throughput. We introduce DuoLM, a framework for fast and effective personalized recommendation that integrates a compact rec-ommendation model with an efficient serving runtime. An encoder LLM learns compact item representations for offline reuse, while a personalized ranker LLM combines them with user history and feedback for recommenda-tion. We train both models end to end with recommendation supervision and teacher dis-tillation. The runtime further accelerates in-ference through virtual token IDs for embed-ding access, shared history computation, and CUDA Graph replay. Benchmark results show that our framework achieves recommendation quality comparable to that of the expert teacher model. On a single H100, it delivers approx-imately 26,400 candidate scores per second, about 60 × the throughput of the teacher served with vLLM and automatic prefix caching. 

1 Introduction

From personalized shopping to content discov-ery, language models use item content, user his-tories, and feedback to assess which items best match individual preferences (Chen et al., 2024; Ning et al., 2024; Bao et al., 2023). Each rec-ommendation request typically involves multiple candidates, while the system must sustain a con-tinuous stream of requests within a given com-putational budget. The practical value of lan-guage models for recommendation therefore de-

pends on both recommendation quality and serv-ing efficiency. Despite advances in language-model-based per-sonalized recommendation, efficient online serv-ing remains challenging. We identify two primary challenges. 

First, it remains difficult to substantially re-duce online computation without compromising recommendation quality. Traditional ID-based two-tower recommenders score items efficiently, but models trained solely on interactions do not di-rectly incorporate textual semantics or pretrained world knowledge. This reliance on interaction data limits generalization to long-tail and cold-start items (Hou et al., 2022; Li et al., 2023; Kim et al., 2024). Full-text cross-encoders use item de-scriptions together with user history and feedback, but the resulting candidate representations depend on the user context and cannot be directly reused across users. Compressing item text can reduce online computation (Ge et al., 2024; Cheng et al., 2024; Louis et al., 2025), yet may discard details that matter to particular users. The challenge is to obtain compact, reusable item representations that still support high-quality personalized judgments. 

Second, a reduction in model computation does not automatically translate into faster end-to-end request processing. Inference engines such as vLLM (Kwon et al., 2023) improve latency and throughput via batching and prefix caching, but re-dundant work can remain in how a recommenda-tion service prepares and submits its workload. A single recommendation request typically evaluates multiple candidates against the same user history. If candidates are submitted separately, the service may repeatedly construct and transmit the same history inputs and incur separate scheduling over-head for each candidate. Prefix caching can reuse history KV states (Juravsky et al., 2024), but does not per se eliminate these repeated operations. As model execution becomes faster, these overheads 1arXiv:2610.24481v1 [cs.IR] 17 Oct 2026 can limit end-to-end recommendation throughput. To address these challenges, we introduce DuoLM, a framework that integrates representa-tion learning and efficient inference for personal-ized recommendation (Figure 1). The core idea is to learn reusable item representations and per-sonalization together, enabling offline item en-coding. Runtime optimizations translate the re-sulting computational savings into faster serv-ing. 

On the model side, an encoder LLM compresses each item’s text into a single hidden-state vector, which replaces its text tokens in a personalized ranker LLM. The ranker receives a candidate vec-tor with individual history-item vectors and their associated textual feedback. Each candidate at-tends to these history entries to produce personal-ized score. We co-train the encoder and ranker end to end with recommendation labels and distillation from a frozen full-text teacher (Hinton et al., 2015). Cross-entropy encourages selection of the observed target, while KL divergence encourages the compact model to match the teacher’s prefer-ence distribution over the same candidates. After training, we precompute item representations of-fline and run only the ranker online. 

On the runtime side , we introduce a series of coordinated optimizations tailored to this model architecture. First, virtual token IDs (VIDs) ref-erence a GPU-resident table of precomputed item embeddings shared by history and candidate items. The runtime resolves these IDs into continuous in-put embeddings for the ranker. Requests therefore carry item IDs and user feedback instead of full item vectors. In our rating benchmark, VIDs re-duce average request payloads by over 90% com-pared with full-vector transmission. We build a novel multi-item scoring (MIS) 

path on SGLang (Zheng et al., 2024) to score multiple candidates in one request. The run-time constructs and prefills the user history once, then shares its prefix KV cache across candidate branches. A tree-structured attention mask allows each candidate to attend only to the shared history and its own branch, preserving independent scor-ing. We further adapt the MIS scoring path to seg-mented prefill CUDA Graphs . These graphs capture GPU operations and their dependencies. The runtime replays the captured graphs to reduce CPU scheduling and kernel launch overhead. Experiments on Amazon Books and Video Games show: (i) Our model outperforms the ex-pert teacher model on Books recommendation (NDCG@10: 0.5586 vs. 0.5440), with compa-rable performance on Video Games (0.5298 vs. 0.5313) and Books rating prediction. (ii) On a sin-gle H100, recommendation throughput reaches up to 60 .1× and 109 .9× that of the teacher served by vLLM and SGLang, respectively. Our contri-butions can be summarized as follows: 1. We introduce DuoLM, a framework that learns compact, reusable, efficient representations for personalized recommendation. 2. We develop an efficient serving runtime that reuses item representations across users and his-tory computation across candidates. 3. We demonstrate substantial throughput gains with recommendation quality comparable to that of the expert teacher model, and share practical lessons from model and runtime ablations. 

2 Method 

Overview. For request q, we score Kq candidate items using an ordered history of nq interactions: 

Hq = (( i1, r 1), . . . , (inq , r nq )) ,Cq = ( c1, . . . , c Kq ).

Each history entry (it, r t) records an item and the user’s feedback on it. As shown in Figure 1, an en-coder LLM A maps item text to user-independent representations. A continuous input interface con-verts each representation into one input embed-ding for a causal ranker LLM B, which scores candidates using the ordered history of item em-beddings and their associated feedback text (Sec-tion 2.1). The encoder, interface, and ranker are jointly trained with recommendation labels and distillation of candidate distributions from a sep-arately trained, frozen full-text teacher T (Sec-tion 2.2). After training, we precompute item embeddings and run only B online. Our run-time reuses these embeddings across requests and shares history KV states across candidates within each request (Section 2.3).

A linear head maps the final-layer hidden state at the last token of the scoring suffix to a scalar score tq,j . We train T with cross-entropy to identify the observed target within each candidate group. After training, we freeze T and cache its raw scores for the exact histories and ordered can-didate groups used in student training.

4.3 Representation and Training Analysis 

This section analyze how item readout, feedback placement, distillation, and self-alignment affect quality. Readout and loss ablations here share a separately trained default model. 

RQ4: How should content be read out from the Encoder for effective use by the Ranker? 

We compare direct EOS readout with two ded-icated learnable readout mechanisms on Books. All three readouts produce one vector per item and use the same scale-calibrated interface and joint training objective. LastToken uses the En-coder’s final-layer hidden state at EOS. MEM1 ap-pends one learnable memory position after EOS and uses its final-layer hidden state as the item vector, following PISCO (Louis et al., 2025) and CLaRa (He et al., 2025). Perceiver1 aggregates the Encoder’s output states with one learnable query, following Perceiver (Jaegle et al., 2021) and Flamingo (Alayrac et al., 2022). LastToken achieves the highest scores across all four ranking metrics (Table 3). It also introduces no additional readout parameters and records the shortest total update time: 7.39 hours for 7,424 training updates, compared with 7.54 for MEM1 and 8.96 for Perceiver1. We therefore adopt Last-Token as the default readout.

FIE achieves slightly lower rating NLL (0.9236 vs. 0.9249), while FIR achieves higher Books recommendation NDCG@10 (0.5586 vs. 0.5538), as shown in Ta-ble 4. Given their comparable quality, we adopt FIR to reuse item representations independently of user feedback. 5 Related Work 

Language models for personalized recommen-dation. In traditional recommendation pipelines, two-tower models encode users and items sepa-rately for efficient retrieval (Yi et al., 2019). For models that rely on ID embeddings, sparse or miss-ing interaction data limit representation learning for long-tail and cold-start items (Li et al., 2023). Language-based approaches use pretrained mod-els to encode item content and model user pref-erences (Hou et al., 2022; Li et al., 2023), in-cluding hierarchical item and user modeling in HLLM (Chen et al., 2024). Whereas HLLM scores candidates by user–item representation sim-ilarity, DuoLM lets each candidate attend directly to individual history items and their associated feedback. 

Personalization and compact representations. 

Prior work personalizes language models through history representations (Ning et al., 2024; Liu et al., 2025), and decoding adjustments (Song et al., 2026). Continuous context compression replaces long text with compact representations consumed by downstream LLM (Ge et al., 2024; Cheng et al., 2024; Louis et al., 2025; He et al., 2025). 

Efficient language model inference. KV-cache management and shared-prefix execution reduce redundant storage and computation (Kwon et al., 2023; Zheng et al., 2024; Juravsky et al., 2024). Optimized attention kernels reduce memory traf-fic (Dao et al., 2022), and runtimes support CUDA Graph capture and replay (Ye et al., 2025). 

6 Conclusion 

We presented DuoLM, a framework that jointly trains two LLMs for reusable item representations and personalized recommendation, paired with an efficient serving runtime. DuoLM achieves recom-mendation quality comparable to the teacher. For Books recommendation on a single H100, it de-livers up to 60 .1× the throughput of the teacher served by vLLM. 

Limitations 

Our evaluation focuses on Amazon Books and Video Games with 0.6B language-model back-bones. Results on these datasets may not general-ize to other domains, larger models, or recommen-dation settings with rapidly changing user prefer-ences. Recommendation quality is evaluated on fixed candidate sets containing randomly sampled unobserved items, which may be easier to distin-guish than candidates produced by a strong re-trieval system. Compressing each item into a single vector may discard details relevant to particular users. Offline representations also require regeneration when item content or encoder parameters change. Our throughput measurements cover online serv-ing and exclude training and offline encoding costs. Finally, the serving results are measured on an H100 under controlled request loads. A.2 Model and Baseline Implementations Model configuration. Encoder A is initial-ized from Qwen3-Embedding-0.6B. The full-text teacher and ranker B use Qwen3-0.6B-Base for recommendation and Qwen3-0.6B for rating pre-diction. B is initialized from the public base weights. Both A and B have 28 layers and a hid-den dimension of 1,024. Recommendation uses LastToken and a scalar scoring head; rating prediction uses Resam-pler/RMS and a five-star output head. For the RMS reference in rating prediction, we use the mean of the per-token RMS values. The main con-figuration uses FIR, m = 1 , and the short input-suffix template. Appendix B.3 compares the long-and short input-suffix templates. Item content is capped at 512 tokens for recom-mendation and 256 tokens for rating prediction, measured with B’s tokenizer; A additionally re-ceives the template prefix and EOS. The rating FIE and FIR configurations in Table 4 use matched to-tal update budgets and ranker input budgets, while the allocation of history vectors varies by recipe. 

Statistical and content baselines. For rating prediction, Global prior uses the training rating distribution; Item prior uses item rating counts; and History prior uses rating counts from the cur-rent user’s visible history. The latter two are smoothed toward the global distribution. Content 12 kNN weights historical ratings by the similarity of frozen content vectors and follows the same smoothing approach. Smoothing and kNN param-eters are selected by development NLL averaged equally across K and then fixed. For recommendation, Popularity counts the dis-tinct users who interacted with each item in the union of training histories and targets. History sim-ilarity compares each candidate with the equally weighted mean of the user’s history content vec-tors. 

ContentSASRec/publicA. This content-based SASRec uses frozen Qwen3-Embedding-0.6B item vectors and trains a projection from 1,024 to 256 dimensions, rating and position embeddings, and a two-layer, four-head sequential Transformer. It scores candidates by the dot product of normal-ized user and candidate representations. 

HLLM and HLLM-rating. For recommenda-tion, HLLM uses two Qwen3 models of approx-imately 0.6B parameters to encode item content and user history, respectively. It ranks candidates by the cosine similarity between user and candi-date representations, with the item sequence as the history input. Our adaptation for five-star predic-tion, HLLM-rating, adds star-rating embeddings to history item representations and feeds interac-tion features between the user and target represen-tations into a classification network. The HLLM and HLLM-rating baselines are initialized from public weights and trained on their respective task data. HLLM-rating uses cross-entropy loss on true star ratings. 

Full-text language models. Raw Qwen3-0.6B directly reads the user history, feedback, and tar-get item text to predict a five-star rating. The full-text teacher is trained as described in Section 2.2. It uses Qwen3’s causal Transformer to jointly pro-cess the history, feedback, and original candidate text, then outputs candidate scores or probabilities over the five rating levels through an output head, without generating recommendation text.

E.3 Multi-Item Scoring 

We implement multi-item scoring (MIS) on top of SGLang (Zheng et al., 2024) to score multiple candidates in a single forward pass. Each request packs a shared history prefix followed by candi-date segments separated by transport delimiters. An item-aware causal attention mask allows each candidate to attend to the shared prefix and its own segment while blocking cross-candidate attention. The prefix KV states are computed once per re-quest and shared across candidates. To execute these packed requests, we pass the prefix length and candidate-boundary metadata to FlashInfer’s prefill kernels. We assign token positions within each candidate as if it followed the shared prefix directly, indepen-dent of the other candidates. For our recommenda-tion model, the scalar head reads the final candi-date hidden state immediately before each trailing delimiter. We exclude the endpoint of the shared history prefix and return one score per candidate in the original order.
