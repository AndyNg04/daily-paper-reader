## 摘要
个人智能系统正承担越来越复杂的日常任务，但反复提问、不必要的确认和不受欢迎的主动联系，可能会让本来能力出众的助手变成互动负担。要减轻这种负担，智能体需要记住用户希望获得何种协助。然而，现有记忆基准主要关注事实回忆和个性化回答，很少检验智能体如何学习并依据交互偏好采取行动。我们提出 MemPABench，这是一个用于对个人智能体记忆进行在线策略评估的交互环境。MemPABench 设置了长时程任务，要求智能体判断何时需要澄清、确认或自主行动。四位有现实依据的模拟用户在工作和个人场景中各自拥有 14 项偏好。在四个月内，这些用户通过 99 场会话提供反馈，并且每位用户的偏好都发生了五次由事件触发的变化，以此测试记忆更新能力。我们评估偏好选择、实际行为表现，以及对情境和偏好变化的敏感度。我们在四种 LLM 主干模型上评测了四种记忆系统，发现当前记忆机制在偏好选择方面带来的提升有限。基于检索的系统（即 Mem0、MemOS 和简单 RAG）表现不优于无记忆系统；基于文件的记忆虽能提高准确率，却会将偏好应用于不相关的情境。分析表明，当前记忆机制难以检索交互偏好，也难以适应偏好变化。即使能够获取正确的偏好，改变智能体默认的互动习惯仍然很有挑战。环境和数据集可在 https://mempabench.com 获取。

## Abstract
Personal intelligence systems are taking on increasingly complex everyday tasks, yet repeated questions, unnecessary confirmations, and unwanted outreach can turn capable assistance into interaction burden. Reducing this burden requires agents to remember how users want to be assisted. However, existing memory benchmarks focus on factual recall and personalized answers and rarely test how agents learn and act on interaction preferences. We introduce MemPABench, an interactive environment for on-policy evaluation of memory in personal agents. MemPABench poses long-horizon tasks requiring agents to decide when to clarify, confirm, or act autonomously. Four grounded simulated users hold 14 preferences across work and personal contexts. Their feedback spans 99 sessions over four months, with five event-driven changes per user testing memory updates. We evaluate preference selection, delivered behavior, and sensitivity to context and preference change. Evaluating four memory systems across four LLM backbones, we find that current memory brings limited gains in preference selection. Retrieval-based systems (i.e. Mem0, MemOS, simple RAG) do not outperform No Memory, while File-based memory improves accuracy but applies preferences beyond relevant contexts. Our analysis shows that current memory struggles to retrieve interaction preferences and adapt to preference changes. Even with the correct preference available, overriding the agent's default interaction habits remains challenging. The environment and dataset are available at https://mempabench.com.

## 1. 核心问题与研究背景

### 1.1 研究关注什么？

论文研究的不是智能体能否记住用户的姓名、日程或喜欢的商品，而是：

> **个人智能体能否从长期互动中学会“用户希望如何被协助”，并在正确的情境和时间落实这些偏好？**

作者将其称为**交互偏好（interaction preferences）**，例如：

- 回答应该简洁还是详细；
- 是否需要解释依据、报告执行进度；
- 遇到信息缺失时，直接推断、一次问完，还是逐项询问；
- 执行动作前是否需要确认；
- 是否可以主动联系用户、顺带处理相邻任务。

### 1.2 为什么重要？

- **任务成功不等于交互体验良好**：助手即使完成任务，也可能因重复提问、过度确认、解释过多或主动打扰而增加用户负担。
- **偏好依赖情境**：同一用户可能允许助手自主处理工作事务，却要求发送私人消息前必须确认。
- **偏好随时间变化**：一次不良后果可能使用户收紧授权边界，旧偏好不能永久有效。
- **偏好通常隐含在反馈中**：用户往往通过纠正、拒绝或接受表达偏好，而不是直接提供结构化配置。

现有记忆评测主要关注事实召回、内容偏好和个性化回答。本文的意义是把评测目标扩展到：**长期记忆能否真正降低交互负担，而不只是改善答案内容。**

## 2. 方法论：MemPABench 的核心设计

### 2.1 将偏好建模为动态状态

论文将目标偏好表示为由**用户、情境、属性和时间**共同决定的状态：

- 每名用户有工作、个人生活两种情境；
- 每种情境包含14个交互属性；
- 因此每名用户有28个“情境—属性”偏好单元；
- 除预设变化事件外，偏好保持稳定；每次事件只改变一个单元。

这避免了把“用户喜欢简短回答”当成不分场合、永久生效的全局规则。

### 2.2 将失败拆解为三个阶段

| 阶段 | 关键问题 | 典型失败 |
|---|---|---|
| 偏好获取 | 能否从用户反馈中形成记忆？ | 只记住任务内容，忽略用户纠正 |
| 偏好选择 | 能否取出当前情境下仍有效的偏好？ | 检索不到、混淆情境、使用旧规则 |
| 行为落实 | 实际回复与操作能否遵循偏好？ | 选择“简洁”，却仍输出大量解释 |

整体流程为：

1. 模拟用户根据世界状态、个人经历和当前偏好提出请求。
2. 智能体根据当前消息访问记忆。
3. 智能体选择一个交互设置，并生成回复及工具操作。
4. 交互包装器执行相应的呈现、投递或动作控制。
5. 用户针对实际发生的行为反馈。
6. 工具操作更新世界，互动记录写入记忆，进入后续会话。

### 2.3 14项交互属性

| 维度 | 属性 |
|---|---|
| 表达风格 | 语气与正式程度、详略程度、情感参与、指导程度 |
| 信息披露 | 理由可见性、不确定性表达、过程可见性 |
| 主动性与自主权 | 自主程度、主动联系、任务扩展、方案广度、能力边界处理 |
| 信息流 | 信息询问方式、多话题管理 |

这些属性被离散化为可观察的设置。例如，自主程度分为事前逐项确认、部分自主和完全自主。14项属性中，10项为二分类、4项为三分类，因此均匀随机选择的平均准确率为**45.2%**。

### 2.4 人物与环境构建

- 从《生活大爆炸》和美国版《办公室》前3季剧本中构建4名模拟用户。
- 提取人物如何接受帮助、如何回应他人表达方式的证据，再进行人工核查。
- **优先依据人物对他人的反应，而非其自身说话风格**：一个喜欢长篇讲话的人，不一定喜欢听长篇解释。
- 替换姓名、机构和地点，减少模型利用知名角色先验猜测偏好的可能。
- 为每名用户建立持续4个月、包含工作与生活事件的可执行世界。

### 2.5 在线策略评测与受控变化

- 大多数历史由**被测智能体自己的行动及用户反应**生成，而不是统一提供预制对话。
- 每名用户的5次偏好变化事件使用固定脚本回放，保证不同记忆条件接收相同的变化证据。
- 因此，这是一种**实时累积互动与固定变化事件结合**的评测，并非所有历史都完全在线生成。

### 2.6 IX Wrapper：分开观察“选了什么”和“做了什么”

智能体在决策点调用交互工具，明确选择设置。包装器再通过以下机制执行：

- **直接透传**：保留模型原文，如语气、详略程度；
- **选择性呈现**：显示或隐藏理由、置信度、过程信息；
- **投递控制**：分批释放话题、问题或主动消息；
- **执行控制**：暂停动作，等待批准或补充信息。

包装器**不知道正确偏好**，不会替智能体纠错。不过，它也不能完全控制模型正文：模型即使选择隐藏理由，仍可能把理由写进普通回复。

### 3.2 评测协议与指标

探针从保存的世界和记忆检查点启动，但**不携带此前原始对话**，历史只能通过记忆访问。每个探针运行在隔离分支，运行后的修改被丢弃。

| 指标 | 测量内容 |
|---|---|
| **PSA：偏好选择准确率** | 最终选择是否与当前正确设置一致 |
| **CS：情境敏感性** | 工作与生活偏好不同的属性，两个情境是否都选对 |
| **PET：偏好演化跟踪** | 变化单元在变化前和最终检查时是否都选对 |
| **BRS：行为落实评分** | 独立LLM裁判根据公开回复及实际动作给出1—5分 |
| **PRS：感知落实评分** | 模拟用户从自身视角给出1—5分 |

**注意**：CS和PET要求两个端点同时正确，比单点准确率更严格；PET也不直接测量变化后需要多久才能适应。

- **Oracle**：直接提供当前正确偏好及定义，观察已知偏好后的选择与落实能力。

### 5.2 充分性评价

**较充分的方面：**

- 同时覆盖多种骨干与记忆架构；
- 不只比较总体准确率，还检查情境、变化、实际行为和用户感知；
- 用No Memory与Oracle帮助区分记忆失败和行为落实失败；
- 提供聚类bootstrap置信区间，以及人工核验和独立模型复评。

**仍不充分的方面：**

- 只有4名合成用户，长会话不能替代用户群体多样性；
- 3次重复主要发生在探针阶段，不能充分反映整条历史生成的随机性；
- 缺少查询改写、混合检索、重排序、结构化偏好记忆等关键消融；
- “存储了却没检索到”的直接存储诊断主要来自少量案例。

### 5.3 是否公平？

- **控制较好**：各系统使用相同用户设定、会话安排、工具、包装器和探针协议；检索系统共享嵌入模型及检索预算。
- **并非严格等资源比较**：
  - File整体注入记忆，检索系统最多注入4,000 tokens；
  - MemOS与其他系统使用不同的记忆侧模型；
  - 各系统自己的行为会形成不同历史，后续证据量也可能不同。

因此，结果适合说明**这些具体集成配置下的端到端表现**，不能直接推出某类记忆架构在所有配置下都优于另一类。

## 6. 主要结论与发现

### 6.1 只有File memory明显提升偏好选择

以下为跨骨干汇总结果：

| 条件 | PSA | CS | PET |
|---|---:|---:|---:|
| No Memory | 49.6% | 21.8% | 11.2% |
| Simple RAG | 49.9% | 20.8% | 15.0% |
| Mem0 | 50.0% | 22.2% | 14.2% |
| MemOS | 50.0% | 19.9% | 10.8% |
| **File memory** | **59.2%** | **14.4%** | **25.4%** |

- File的PSA比No Memory高**9.6个百分点**，95%置信区间为 **[+3.9，+15.6]**。
- 三种检索方法与No Memory的PSA差异置信区间均包含零，未显示明确提升。

### 6.2 检索更容易找到任务内容，而不是交互规则

在被检查的有效探针输入中：

- 三种检索系统合计334个样本，只有**7个**包含适用交互偏好；
- File的111个样本中有**60个，约54%**包含适用偏好。

检索通常找到“之前与谁处理过什么事”，却遗漏同一事件中的“以后发送前先问我”等反馈。案例进一步表明：**偏好可以已被存储，却仍无法在决策时被取出。**

### 6.3 File记得更多，但容易用错情境

- File的PET从11.2%提高到25.4%，变化跟踪有所改善。
- CS点估计从21.8%下降到14.4%，但差异置信区间包含零，不能据此断言CS显著下降。
- 更直接的证据是：**26.9%的CS配对实例出现跨情境迁移**，明显高于No Memory的6.0%。

典型问题是把私人场景中的“逐项处理”归纳为全局规则，随后错误应用于工作任务。

### 6.4 File也改善实际行为与模拟用户感受

跨骨干结果中：

- File的BRS约为**3.46—3.57**；
- File的PRS约为**3.59—3.62**；
- 均高于检索条件和No Memory对应的评分。

BRS与PRS的Spearman相关系数为0.83，但二者都主要由同一个模型生成，应结合独立复评理解。

### 6.5 行为偏好比措辞偏好更难

- 信息流维度的PSA仅约**34%—44%**，最困难；
- 表达风格约为57%—69%，相对容易；
- 在无记忆条件下，涉及动作的偏好选择准确率为40.3%，低于该组随机水平44.4%。

这表明，**改变怎么说，比改变何时询问、确认或行动更容易。**

### 6.6 给出正确偏好，也不保证落实

Oracle几乎解决了偏好选择问题，但以下设置仍较难执行：

- 隐藏理由；
- 简洁回答；
- 逐项询问；
- 一次结构化问全；
- 只展示一个推荐方案。

这些设置中，已正确选择的探针只有约**60%**达到BRS≥4，其他25种已覆盖设置约为95%。

核心原因是模型仍倾向于**解释过多、罗列替代方案，或少问问题、直接填补假设**。

## 7. 论文优点

- **问题有实际价值**：将交互负担与任务完成分开，贴近长期个人助手的真实需求。
- **评测结构有诊断性**：清晰区分偏好获取、选择和落实，避免把所有失败都归因于“记忆不好”。
- **同时建模情境与时间**：不仅要求记住规则，还要求知道规则在哪里适用、何时已失效。
- **可执行世界增强可信度**：依据真实执行日志判断是否发送、修改或等待批准，而非只听模型自述。
- **探针隔离设计合理**：防止测试过程继续教授偏好，减少探针之间污染。
- **结果解释比较深入**：不仅给出排名，还检查检索输入、记忆内容和行为偏离案例。
- **验证措施较丰富**：包括匿名化、人工反馈核验、泄漏审计、独立裁判和置信区间。

## 8. 不足与局限

### 8.1 用户与偏好模型的外部有效性有限

- 只有4名电视剧人物衍生用户，无法代表真实用户群体。
- 部分偏好依赖薄弱证据或人工指定：112个单元中，仅53个经高置信核验直接保留。
- 模拟器按目标偏好生成反馈，验证的是其与设定的一致性，而不是真实人的偏好形成规律。
- 工作/生活二分较粗，未覆盖对象、风险、紧急程度等更细粒度情境。
- 离散设置便于评分，却难描述真实用户的连续、模糊或相互冲突的偏好。

### 8.2 长期学习环境仍较理想化

- 每次累积会话都被要求提供可识别的接受或纠正信号，现实用户可能沉默、退出或反馈含糊。
- 固定变化事件提高可比性，但不是由当前被测智能体自然导致。
- 每个变化单元只变化一次，且PET比较变化前与最终状态，无法刻画即时适应速度、反复变化和遗忘过程。

### 8.3 检索结论受实现限制

- 主要使用当前消息作为查询，没有验证面向“交互属性＋情境”的主动查询策略。
- 没有系统比较不同嵌入、Top-k、预算或结构化索引。
- 因而更准确的结论是：**常见内容相似度检索配置难以支持交互偏好调用**，而不是检索式记忆原则上无效。

### 8.4 包装器与评分可能引入偏差

- IX工具显式暴露待测属性，并替智能体执行部分控制，区别于完全自然的自主交互。
- 某些评分规则较机械，例如固定位置的情感句、置信度标记、正式连接词。
- 系统提示词中的通用要求，如“调用工具前说明意图”“存在歧义时澄清”，可能与部分用户设置冲突，混入指令冲突处理能力。
- 直接询问用户偏好被统一判为最低分，适合测试“不要再问”，但不代表现实中所有偏好确认都不合理。

### 8.5 还没有完整衡量产品价值

- PRS是模拟用户评分，不是真实用户满意度。
- 未直接测量打扰次数、确认成本、时间节省、长期留存等体验结果。
- 未全面报告隐私、授权安全与任务成功的联合权衡。
- 没有给出等成本比较或提出并验证新的记忆解决方案，贡献主要在于**基准与问题诊断**。

**总体评价：**本文有力地说明，个人智能体的个性化不是“存下用户信息”就能完成的。可靠系统需要同时解决**从反馈提取规则、在决策时检索规则、保留情境与时效边界，以及让实际行为遵循规则**四个环节；不过，其发现仍需在更多真实用户和更丰富检索配置中验证。
