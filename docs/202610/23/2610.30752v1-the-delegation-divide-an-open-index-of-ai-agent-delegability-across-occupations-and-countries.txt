# The Delegation Divide: An Open Index of AI-Agent Delegability across Occupations and Countries 

Cristian Espinal Maya ∗ Santiago Jiménez Londoño †

October 23, 2026 

Abstract 

35.2% of task time in world employment is at least partly delegable to AI agents in 2026, and only 2.5% can be handed over in full. Existing measures score exposure to generative AI, mostly for the United States. We build the Agent Delegability Index (ADI): two language models rate all 18,796 O*NET 30.2 task statements on a frozen, preregistered rubric of delegation levels and barriers; tasks are mapped to 433 ISCO-08 unit groups and weighted by ILOSTAT employment in 146 countries. Four findings. First, delegable employment rises with income, from 22.5% in low-income to 48.7% in high-income countries, a slope of 7.23 percentage points per log point of GDP per capita. This delegation divide is compositional: the physical barrier dominates the jobs poorer countries employ most. Second, at the occupation level ADI tracks exposure closely ( r = 0.93 with Eloundou et al. and 0.89 with Felten et al.), above the preregistered bound of 0.80. ADI adds delegation levels and barriers on top of exposure, for the world, not a new ranking of occupations. Third, full delegation is rare and peaks for tasks that take a human about 11.8 minutes. Fourth, the preregistered adoption gap is not supported: across 101 countries, delegability and observed AI usage correlate at r = 0.86, and the gap between them is not wider in middle-income countries ( p = 0 .270). Model agreement is κ = 0.77; a blind human rating of 300 tasks agrees with the model consensus at κ = 0.85, and an agentic panel with web search at κ = 0.87. We release the index, the atlas, the prompts and an MCP server at 

https://github.com/Cespial/delegation-divide .

# 1 Introduction 

35.2% of task time in world employment is at least partly delegable to an AI agent in 2026, and only 2.5% can be handed over in full. These two numbers are the output of the Agent Delegability Index (ADI), an open index that rates every task statement of the United States Occupational Information Network (O*NET) on how much of it a software agent can execute, maps the ratings to the International Standard Classification of Occupations (ISCO-08), and weights them by employment in 146 countries. This paper describes how the index is built, compares it with existing measures, and reports its first finding: a delegation divide between rich and poor countries. Two gaps motivate the index. The first is conceptual. The measures that dominate the literature on artificial intelligence and work score exposure : whether a large language model can reduce the time a worker needs for a task by at least half (Eloundou et al., 2024), or how closely the abilities an occupation requires track progress in AI applications (Felten et al., 2021; Webb, 2020). Exposure was the right construct for a chatbot. It is not the right construct for an agent. Since 2025, publicly

The policy question has moved from “can the model help with this task?” to “can the worker hand this task over?” That is delegation, and the two differ in kind: a model can halve the time a radiologist spends on a report without being able to sign it, and an agent can file a tax return that no model could have sped up much, because the time was never in the drafting. Observed usage indices measure a third thing again, adoption, which depends on prices, regulation and habit as much as on capability (Anthropic, 2025; Lee et al., 2026; Henseke, 2026). The second gap is geographic. Almost every task-level measure is built on O*NET and its Standard Occupational Classification (SOC), which only the United States uses for its statistics. The rest of the world reports employment in ISCO-08 (International Labour Office, 2012). Studies that reach other countries do so through coarse bridges, usually at the one-digit level, or through a single national crosswalk (Gmyrek et al., 2023; Pizzinelli et al., 2023; Cazzaniga et al., 2024; Albanesi et al., 2023; Chen et al., 2023; Murugan et al., 2026; Carbonero et al., 2023). The International Labour Organization (ILO) index of generative-AI exposure is the exception that works natively in ISCO-08 (Gmyrek et al., 2025), but it measures exposure, not delegation. Nobody has measured delegability to agents in the classification that most countries use. ADI addresses both gaps. The conceptual gap turns out to be narrower in the data than in principle: across occupations, the work that is exposed is mostly the work that is delegable (Section 7). The difference lies in how far delegation goes, which barrier stops it, and in which countries the work is done. The design is simple to state. Each of the 18,796 task statements in O*NET 30.2 (National Center for O*NET Development, 2026) is rated by frontier language models with a fixed rubric at one of four levels: no meaningful role, augmentation, partial delegation or full delegation (Section 2). The rubric is frozen and preregistered; its hash is in Appendix A. The two models agree with each other at quadratic-weighted κ = 0.77. A blind human rating of 300 tasks drawn from a stratified validation sample of 1,500 agrees with the model consensus at α =0.88, against a preregistered acceptance threshold of 0.60, and an agentic panel with web search agrees with it at κ = 0.87 over the validation sample (Section 7). Tasks are weighted by importance and frequency within their O*NET occupation and carried to 433 of the 436 ISCO-08 unit groups through a documented chain of crosswalks (Appendix B). Occupation scores are then weighted by employment from the ILO statistics database (ILOSTAT) to give a delegability share for each of 146 countries with occupational employment data from 2019 onward. We make five contributions, each meant to stand on its own. 1. The Agent Delegability Index (ADI). An open, versioned index of AI-agent delegability for 433 ISCO-08 unit groups and 146 countries, with three variants per occupation (share of task weight at partial delegation or above, share at full delegation, and expected share of working time delegable), bootstrap confidence intervals, and a permutation placebo. One citable sentence each for augmentation, partial delegation and full delegation, written for agents with tool use rather than for chat models, with four named barriers (physical, accountability, trust, access) recorded separately from the level. Validation and convergence. Agreement between models and across repeated calls, a blind human rating and an agentic validation panel, and preregistered convergence tests against the exposure indices of Eloundou et al. (2024) and Felten et al. (2021). The correlations are r =0.93 and 0.89, above the preregistered bound of 0.80: at the occupation level, the delegability that models rate largely coincides with exposure. ADI’s own contribution lies in the level scale, the barriers and the global reach, and it correlates less with observed usage ( r = 0.69) than with exposure. 5. Open tools for people and for agents. Delegable employment is not spread evenly across the world. It rises with income: the share of employment in delegable tasks is 48.7% in high-income countries and 31.0% in middle-income countries, and a country-level regression of delegability on log GDP per capita at purchasing power parity has a slope of 7.23 percentage points per log point (95% bootstrap interval 6.52 to 7.83). The reason is composition. Poorer countries concentrate employment in agriculture, crafts and elementary occupations, where the binding barrier is physical, and agents have no body. We also preregistered a second edge, an adoption gap: that middle-income countries would use AI less than their delegable task base predicts. The data do not support it. Across 101 countries with observed usage, delegability and usage correlate at r =0.86, and the standardized gap between them is not wider in middle-income than in high-income countries ( p = 0 .270). Usage so far follows the delegable task base rather than lagging behind it. The paper proceeds as follows. Section 2 defines the three layers and relates delegation to exposure. Section 3 describes the data and Section 4 the method, validation and inference. Section 5 presents the occupational index, Section 6 the country atlas and the divide, and Section 7 the validation, the convergence with exposure and the comparison with observed adoption. Section 8 discusses limitations and ethics, and Section 9 concludes. Appendices give the rubric, the crosswalk, and instructions for citing and using the index. 

# 2 From exposure to delegation 

2.1 Three layers 

ADI rates a task, not an occupation, and rates it at one of four levels. The choice follows the task-based view of technological change, in which technology substitutes for some tasks within a job and complements others (Autor et al., 2003; Acemoglu and Autor, 2011; Autor, 2015); occupation-level scores of automation risk shrink substantially once the variation of tasks within occupations is taken into account (Arntz et al., 2016; Nedelkoska and Quintini, 2018). The reference technology is fixed: publicly available AI agents as of October 2026, that is, frontier language models with tool use, code execution, web browsing, computer use and file handling, with no body and no robotics. The rater judges what is technically feasible with that technology, not what employers do and not what the law allows. The four levels, in the wording of the frozen rubric (Appendix A), are: 3L0

Figure 1: The delegation ladder. Four levels of the ADI rubric, from no meaningful role (L0) to full delegation (L3), with the human and the agent roles at each level and the four barriers that keep a task below L3. Figure generated by analisis/figuras.py .

L0, no meaningful role. The agent cannot perform or materially speed up any substantial part of the task. 

L1, augmentation. A human performs the task while the AI assists step by step with drafts, searches or suggestions; the human stays in the loop at each step and produces the output. 

L2, partial delegation. An agent can execute substantial sub-steps of the task end to end from a goal specification, while a human still has to perform at least one essential step or review and correct the work before use. 

L3, full delegation. An agent can complete the whole task end to end, to the quality a competent worker would accept, given only the goal and access, so that the human’s role is limited to assigning the task and accepting the result. The levels form a ladder (Figure 1). Each step adds one thing: at L1 the machine contributes, at L2 it executes, at L3 it finishes. What moves a task up the ladder is not model quality alone but the shape of the task: whether it can be specified as a goal, whether its inputs and outputs are digital, and whether someone other than the worker is allowed to accept the result. The rubric therefore records four barriers alongside the level: physical (the task needs presence or manipulation), 

accountability (law, licence or liability requires a human to perform or sign), trust (the task depends on in-person trust, care or persuasion) and access (the task depends on systems, data or places an agent would normally not reach). It also records the share of the task’s working time an agent could take over and the minutes a competent human needs for one instance, which Section 4 uses to test whether full delegation peaks at intermediate task lengths. 

2.2 Why delegation is not exposure 

The exposure indices that most of the literature uses answer a different question. Eloundou et al. (2024) label a task as exposed if access to a large language model, alone or with software built on 4it, would reduce the time needed to complete the task with equal quality by at least 50%. Felten et al. (2021) link ten AI application areas to the 52 O*NET abilities and score an occupation by the abilities it needs; the result, the AI Occupational Exposure index (AIOE), does not refer to tasks at all. Webb (2020) measures overlap between patent texts and task descriptions, and Brynjolfsson et al. (2018) score each task’s suitability for machine learning. All of them ask how much AI touches 

the work. ADI asks whether an agent can do the work. The two constructs can separate, in principle, in both directions. A task can be highly exposed and not delegable: writing a radiology report is faster with a model, but a licensed radiologist must read the images and sign, so the task stays at L1 or L2 with an accountability barrier. A task can be delegable and barely exposed: reconciling a bank statement against an accounting ledger saved little time when the model could only talk, but an agent with access to both systems completes it end to end. The experimental evidence on generative AI at work is evidence about this first case: customer-support agents, professional writers and consultants who keep the task and do it faster or better with a model (Brynjolfsson et al., 2023; Noy and Zhang, 2023; Dell’Acqua et al., 2023). Exposure measures the intensity of assistance on a task whose owner does not change. Delegation measures a change of owner. That the constructs can come apart on a given task does not mean that they do across the economy; Section 7 measures how far they do in practice and finds that, at the level of occupations, they separate little. Delegation is also not adoption. The Anthropic Economic Index (Anthropic, 2025; Handa et al., 2025) observes which O*NET tasks people actually bring to a model and, in later releases, which they hand to a coding agent; Tomlinson et al. (2025) do the same with conversations with Microsoft Copilot. The Agentic Adoption Index (Lee et al., 2026) scores a task by how closely it matches the agent configurations practitioners publish on GitHub, a measure its authors call delegated exposure. Both record what has happened. ADI records what the technology permits, so it is an upper bound on delegation that adoption data can be compared against. The gap between the two is itself an object of study (Section 7), and it is where the delegation divide appears.

Table 1 places ADI next to the measures it builds on. The columns record what each index measures (construct), the unit it rates, who or what rates it, the occupational classification, the countries it covers, whether the data are open, and whether the construct refers to AI agents rather than to language models or to earlier automation. 3.2 Bridge to ISCO-08 

Most countries report employment in the International Standard Classification of Occupations, ISCO-08 (International Labour Office, 2012), which has 436 unit groups at four digits. O*NET uses the United States Standard Occupational Classification (SOC). We bridge the two in three documented steps: O*NET-SOC 2019 to O*NET-SOC 2010 with the official O*NET Center crosswalk; O*NET-SOC 2010 to six-digit SOC 2010 by truncation; and SOC 2010 to ISCO-08 with the crosswalk of Hardy et al. (2018), published by the Institute for Structural Research (IBS). A SOC code that maps to k ISCO groups splits its weight 1 /k . The result covers 433 of the 436 unit groups with 403 distinct task sets; the three military groups (0110, 0210, 0310) have no O*NET tasks and are excluded, and seven residual groups without tasks of their own inherit the tasks of their three-digit parent and are flagged as imputed. Four O*NET-SOC 2019 occupations with no 2010 ancestor are assigned by hand. Appendix B lists every step, the two SOC codes rescued because the IBS file omits them, the seven imputed groups and the four manual assignments; the code is datos/construir_crosswalk.py .The bridge replaces the occupation–task matrix used in the first author’s earlier work on augmented human capital (Espinal Maya, 2026a,b), which mapped SOC to ISCO at one digit and 6so collapsed 440 Colombian occupations into 9 task sets. Section 8 returns to the consequences. 

3.3 Secondary task bank: ESCO 

O*NET describes work in the United States. As a check on that origin, we also score the essential skills and competences that the European Skills, Competences, Qualifications and Occupations classification (ESCO, version 1.2.1) attaches to each of its occupations (European Commission, 2026). ESCO maps every occupation to an ISCO-08 unit group by construction, so it needs no crosswalk, and it is available in 28 languages. Its units are skills, not tasks, so we treat it as a robustness bank rather than as the primary source. We keep only items of the skill and competence type and drop knowledge items, because the rubric rates activities that can be handed over and a body of knowledge is not one. The bank has 8,229 distinct essential skills and competences in 424 unit groups; each is rated once, by Sonnet alone, with the same rubric and the occupation for which it is most often essential, and enters each unit group with equal weight. The ESCO results are reported in Section 6 as a sensitivity check and matter most for agriculture, where O*NET has few tasks (Section 8). 

3.4 Employment by occupation: ILOSTAT 

Country weights come from the ILO statistics database, ILOSTAT, series on employment by sex and occupation (International Labour Organization, 2026), downloaded through its SDMX interface. At one digit, 173 countries report employment by ISCO-08 major group and 151 have a reference year of 2019 or later; one of them (Bhutan) reports only armed-forces and unclassified employment in its latest year, so 146 countries form the atlas. At two digits, 144 countries report sub-major groups and 134 have a year of 2019 or later. We use the finest level each country reports, two digits where the sub-major groups are complete (at least thirty groups whose total is within five per cent of the one-digit total) and one digit otherwise, with the pooling rule of Section 4: 126 countries enter at two digits and 20 at one. Countries whose latest occupational data predate 2019 are excluded, as preregistered. Table 2, generated by analisis/tablas.py , lists coverage by income group. The same database supplies the informality rate and mean monthly earnings by occupation where they exist, used in the atlas. 

3.5 Income and adoption 

Income groups follow the World Bank classification for fiscal year 2026, and GDP per capita is at purchasing power parity in constant 2021 international dollars (World Bank, 2026). Observed adoption comes from the Anthropic Economic Index (AEI), which reports usage of Claude by country per working-age adult in its latest release (Anthropic, 2025). For convergence tests we use the occupation-level scores of Eloundou et al. (2024), Felten et al. (2021), Webb (2020), Eisfeldt et al. (2026) and Gmyrek et al. (2025), each carried to ISCO-08 with the same bridge where it is not already in ISCO-08.

# 4 Method 

Figure 2 summarises the pipeline: tasks are rated by models, consensus is taken across models, consensus is weighted into occupations, occupations are weighted into countries, and every step is validated or bootstrapped. The design was preregistered on the Open Science Framework on 21 October 2026, before the first call of the main pass, with an embargo until 31 January 2027 (Espinal Maya and Jiménez Londoño, 2026); the hypotheses, the rater set, the rubric hash and the sample seeds are in the registration ( https://osf.io/9zntf ), and the exact rater configuration is in docs/MODELOS.md .

4.1 Rubric 

Each task is rated with the rubric reproduced in Appendix A. The prompt contains the reference technology, the four level definitions, the occupation title and the task text, and asks for a single 8JSON object with eight fields: level (0–3), share of the task’s working time an agent could take over (0–100), minutes a competent human needs for one instance, four barrier flags (physical, accountability, trust, access) and a confidence label. The rubric contains no example tasks, so no task in the data can anchor the rating of another. The file was frozen at registration; its SHA-256 hash is bcd076fb...0ea0e46 (full value in Appendix A), and the scoring script refuses to run the main pass unless the file on disk matches it. A pilot of at most 300 tasks (seed 20261020) checked JSON compliance, cost and the call format before registration; pilot ratings are discarded (Section 4.2). 

4.2 Raters: language models 

Two models rate every task: Claude Sonnet 5.5 is the primary rater and Claude Haiku 5.5 the secondary rater, both by Anthropic (identifiers returned by the interface: claude-sonnet-5-5 and 

claude-haiku-5-5 ). The rater set was fixed in the registration and no model is added or dropped after seeing the main pass. Both are queried through the Claude Code command-line interface (claude -p , version 2.1.306 , --output-format json ) rather than through a raw API, in a neutral configuration: no tools ( --tools "" ), no Model Context Protocol servers ( --strict-mcp-config ), no session persistence ( --no-session-persistence ) and a fixed one-line system prompt that replaces the interface’s default, quoted here in full:  

> You are an expert rater of occupational tasks. Follow the user instructions exactly.

Each call carries one task, with no other task or rating in context. Every call is logged with the interface version, the model identifier returned by the interface, the prompt hash, the duration and the outcome in docs/llm-llamadas.jsonl , which doubles as the manuscript’s declaration of AI use; the configuration is recorded in docs/MODELOS.md .The interface does not expose a temperature setting, so the ratings are not deterministic by construction. We therefore measure stability directly: a random subsample of 100 tasks is rated a second time by each model under identical prompts, and we report exact agreement and quadratic-weighted kappa between the two passes (Sonnet: 0.97; Haiku: 0.88). Calls whose output fails validation (malformed JSON, a level outside 0–3, a share outside 0–100) are retried up to five times; tasks that still fail are excluded for that model only, and the counts are reported (0 for Sonnet, 3 for Haiku). The call format was settled in the discarded pilot by two tests, both run before registration. First, rating tasks in batches of 25 per call agreed with one-task calls at quadratic-weighted κ = 0.60 for Sonnet and 0.56 for Haiku, below the preregistered floor of 0.80, so batching was rejected and the main pass uses one task per call. Second, the interface’s default wrapper, which tells the model that it is a coding agent with tools, raised the mean level from 1.33 under the neutral configuration to 1.64 (agreement between the two, κ = 0.70). The main pass therefore uses the neutral configuration, and a preregistered sensitivity analysis re-rates the 1,500 tasks of the validation sample with the default wrapper (Sections 4.4 and 7).

4.4 Human and agentic validation 

The registration specifies three human raters who each rate the same 1,500 tasks blind (Es-pinal Maya and Jiménez Londoño, 2026). Before any result of the main pass was opened, we replaced that design for reasons of time and cost; the change is dated and justified as deviation D2 in docs/DESVIACIONES.md . The validation now has two parts. 

Blind human rating. A subsample of 300 of the 1,500 validation tasks, stratified by ISCO-08 major group with at least 20 tasks per group (seed 20261025; validacion/santiago/muestra_300.csv ), was rated blind by a group led by Santiago Jiménez Londoño, a coauthor, with the help of student raters. The 1,500-task sample is the registered one, stratified by major group in proportion to world employment ( validacion/muestra.py , seed 20261020). The raters worked from the frozen rubric and the rater guide, were trained on 20 practice tasks outside the sample, rated in a spreadsheet that contained no model or panel output and no result of the paper, and did not use AI tools while rating. Which rater scored which task was not recorded, so the sheet is analysed as one human rating. We report Krippendorff’s alpha for ordinal data (Krippendorff, 2004) and quadratic-weighted kappa (Cohen, 1968) between that rating and the model consensus ( α = 0.88; κ = 0.85; exact agreement 71.0%; 300 tasks), and kappa with each model separately (Sonnet 0.85; Haiku 0.79). The preregistered acceptance threshold for the primary rater, α ≥ 0.60, is kept and results are reported whatever the value. Two features of this design are limitations, not details. The rating was led by an author of the paper, not by independent raters in the sense of the registration; and because 10 individual contributions were not recorded, no human–human agreement can be computed, so the human figures carry no estimate of how much humans disagree among themselves. With 300 instead of 1,500 tasks the confidence interval of alpha is also wider than the registered design allowed for. 

An agentic panel, reported as non-human validation. Claude Opus 5.5, a model that plays no part in the index, rates the 1,500 validation tasks through the same command-line interface ( claude -p ) with web search enabled, at most four searches per task; it applies the same rubric and returns up to three pieces of cited evidence with each rating ( validacion/agentico/panel.py ). The panel tests whether a rater that can look up how a task is actually done, and what rules govern it, reaches the levels that the raters without tools assign. We report its agreement with the model consensus, with each model and, on the tasks they share, with the human rating. The panel is a language model from the same developer as the raters, so it is not human validation and is never reported as such. The registered design, three human raters on all 1,500 tasks, is left for a second version of the paper. 

Sensitivity to the interface wrapper. As preregistered, each model re-rates the 1,500 validation tasks under the interface’s default system prompt, which describes the model as a coding agent with tools, instead of the neutral configuration ( scoring/salidas/envoltorio_cc/ ). We report, model by model and on the same tasks, the mean level and the share at L2 or above under each configuration, quadratic-weighted kappa between the two, and the agreement of each with the human rating. 

4.5 Convergent validity 

Hypothesis H3 states that occupation-level ADI correlates positively with the exposure scores of Eloundou et al. (2024) and the AIOE of Felten et al. (2021), with Pearson r between 0.40 and 0.80 for each: above 0.80 would mean ADI adds little beyond exposure, below 0.40 would question its validity. Both comparison indices are carried to ISCO-08 with the bridge of Section 3. We report Pearson and Spearman coefficients (Eloundou: r = 0.93, ρ = 0.95; Felten: r = 0.89, ρ = 0.88), and, as exploratory comparisons, the same statistics against Webb (2020), Eisfeldt et al. (2026), the ILO index (Gmyrek et al., 2025) and the Agentic Adoption Index (Lee et al., 2026). 

4.6 Hypothesis tests 

H1, the delegation divide, is an ordinary least squares regression of ADI c on log GDP per capita at purchasing power parity, and a second specification with income-group dummies with high income as reference; the test on the slope is one-sided at α = 0.05. H2, the adoption gap, standardises ADI c

and AEI usage per working-age adult to mean zero and unit variance over the countries with both and regresses the difference on income-group dummies; the one-sided test is that the middle-income coefficients are positive. H4, task length, is a logistic regression of full delegation on log human minutes and its square at the task level, with standard errors clustered by occupation and minutes winsorised at 1 and 4,800; the hypothesis is a positive linear and a negative quadratic coefficient. 

4.7 Inference and placebo 

Uncertainty from the rating step is propagated by a nonparametric bootstrap over tasks: 1,000 draws, tasks resampled within occupation, each draw recomputing Equations 1–3, the headline and the regression coefficients (Efron and Tibshirani, 1993). All intervals in the paper are 95% percentile intervals from this bootstrap unless stated otherwise. As a placebo, we shuffle task ratings across occupations 1,000 times, holding each occupation’s task count and weights fixed, and recompute 11 the occupational index; the observed dispersion of ADI o across unit groups is compared with this null ( <0.001). A rating that carried no occupation-specific information would produce occupational indices indistinguishable from the shuffled ones. Robustness checks preregistered as exploratory are reported model by model, with ESCO skills instead of O*NET tasks, with uniform task weights, and without the seven imputed groups. 

# 5 The index 

Partial delegation is the most common rating of a task, full delegation is rare, and the occupations at the top are clerical and administrative. 

5.1 Tasks 

Of the 18,796 task statements with a valid consensus, 25.9% are rated L0, 24.1% L1, 47.6% L2 and 2.4% L3, so that 50.0% of statements reach at least partial delegation before any weighting. L2 is the modal level. Agents, as the models judge them, can execute substantial parts of many tasks but can finish very few of them without a human step. Ties between models, resolved to the lower level as preregistered, affect 32.5% of tasks. 7.2 Human and agentic validation 

The preregistered human validation changed before any result was opened (deviation D2; Section 4.4). Instead of three human raters on 1,500 tasks, a subsample of 300 of them was rated blind by a group led by a coauthor with the help of student raters, none of whom saw any model rating or any result of the paper. H3 is not supported in the form registered, and the reason matters for what ADI is. Across ISCO-08 unit groups, ADI correlates with the exposure measure of Eloundou et al. (2024) at r

= 0.93 (Spearman ρ = 0.95) and with the AIOE of Felten et al. (2021) at r = 0.89 ( ρ = 0.88). The preregistration set a band of 0.40 to 0.80 and stated in advance that a correlation above 0.80 would mean that ADI adds little beyond exposure. Both correlations are above it. At the level of occupations, the delegability that language models rate largely coincides with the exposure that earlier studies measured: the occupations an agent could take over are, for the most part, the occupations a chatbot could speed up. The correlation with Eisfeldt et al. (2026) is similar, at 0.88. A ranking of occupations is therefore not ADI’s contribution. What ADI adds lies elsewhere, and four results locate it. First, the level scale: exposure indices say whether AI touches a task, while ADI separates partial from full delegation, and full delegation turns out to be rare (2.5% of world task time) and concentrated in a few clerical groups (Section 5). Second, the barriers, which say why a task stops short of L3 and which are not recorded by any exposure index. Third, the reach: a task-level index carried to 146 countries in ISCO-08, where exposure indices are mostly confined to the United States. Fourth, the relation to what is observed and to other kinds of automation. ADI correlates at only 0.69 with observed Claude usage by occupation (Handa et al., 2025) (0.69 when usage is matched task by task), well below its correlation with exposure, so capability and use are not the same ranking. It is nearly uncorrelated with the AI-patent exposure of Webb (2020) ( r = 0.11), negatively correlated with Webb’s software exposure (−0.26) and strongly negatively correlated with his robot exposure ( −0.74): the work agents can take over is the opposite of the work robots were expected to take. 

7.4 Observed usage and the adoption gap (H2) 

H2 is not supported. For the 101 countries with Anthropic Economic Index usage per working-age person (Anthropic, 2025), delegability and usage correlate at r = 0.86. The preregistered test regresses the standardized gap between the two on income-group dummies. The gap in middle-income countries is 0.06 standard deviations relative to high-income countries, not distinguishable from zero (one-sided p = 0 .270). Separately, the coefficient is 0.17 for upper-middle ( p = 0 .086) and −0.06 for lower-middle income ( p = 0 .673; Table 4, column 4). Neither is significant, and the lower-middle coefficient has the wrong sign. The only group whose gap departs clearly from high income is low income, and it departs in the opposite direction to the hypothesis: the coefficient is 

−0.81 (two-sided p < 0.001), so usage there is less far below the high-income level than delegability is. We read this as a null result. Across countries, observed usage of one AI system follows the delegable task base closely; we find no evidence that middle-income countries lag behind what their occupational structure would allow. Two cautions apply. Usage comes from a single developer’s product and measures conversations, not delegated work, and the same developer’s models produce the ratings, so part of the high correlation may reflect a shared view of which work suits these models (Section 8). 

7.5 Sensitivity to the interface wrapper 

The preregistered wrapper sensitivity re-rates the 1,500 validation tasks under the default Claude Code system prompt, which describes the model as an agent with tools. In the pilot, that wrapper raised the mean level (Section 4.2). For Haiku, over the 1,500 re-rated tasks, the mean level moves from 1.36 under the neutral configuration to 1.40 under the default wrapper, the share at L2 or above from 54.9% to 56.2%, and agreement between the two configurations is κ = 0.76. For Sonnet, 19 the primary rater, the same figures are 1.04 and 1.53, 37.6% and 56.8%, with κ = 0.60 (1,500 tasks): the wrapper moves Sonnet far more than Haiku. Against the human rating, the neutral and default configurations reach κ = 0.85 and 0.61 for Sonnet, and 0.79 and 0.75 for Haiku. The frame in which a model is addressed therefore enters the index; Section 8 discusses what this means for reading it. 

# 8 Limitations and ethics 

8.1 Technical delegability is not deployment 

ADI measures what an agent can do with the technology of October 2026, given the goal and access. It does not measure what firms do, what regulators allow or what workers accept. A task at L3 may never be delegated because the agent is too expensive relative to local wages, because the systems it would need are not connected, or because nobody is willing to be accountable for its output. The index is therefore an upper bound on delegation, and the comparison with observed usage in Section 7 is a comparison of a ceiling with a floor. Adoption of generative AI has been fast among workers (Bick et al., 2024), but its measured effects on earnings and hours have so far been small (Humlum and Vestergaard, 2025), with early employment losses concentrated among young workers in exposed occupations (Brynjolfsson et al., 2025). Readers who need a forecast of employment effects should combine ADI with adoption, prices and institutions, as Acemoglu (2025) does for exposure; the index alone supports none. The reference technology is also a moving target. We fix it by date and version the index ( v2026.1 ) so that later releases can be compared with this one rather than silently replacing it. 

8.2 O*NET describes work in the United States 

The task statements, and the importance and frequency weights, come from surveys of United States workers. The same occupation elsewhere may contain different tasks, in different proportions, with different tools. The crosswalk to ISCO-08 carries the United States task mix to every country; it does not adapt it. The problem is sharpest in agriculture. O*NET has only 193 task statements whose main ISCO group lies in major group 6, skilled agricultural, forestry and fishery workers, which employs a large share of workers in low-income countries, and 193 of them fall in the human-validation sample. Since the delegation divide (H1) depends on that group, we rerun the country regression with the ESCO skill bank in place of O*NET tasks for major group 6 and for all groups; the slope is 4.66 with ESCO for all groups and 6.92 with ESCO for major group 6 only, against 7.23 with O*NET. The same transfer problem is known from the measurement of teleworkability: a task-based feasibility measure built on O*NET (Dingel and Neiman, 2020) overstates what can be done at home in poorer countries, where the same occupations are performed with fewer digital tools (Gottlieb et al., 2021), and the access barrier in ADI plays the role that connectivity plays there (Gmyrek et al., 2024). Informal and subsistence work, which household surveys capture better than labour-force statistics by occupation, is treated in the microdata breakdowns rather than in the headline. 

8.3 Language models as raters 

The raters are two language models from a single developer, and the usage data in Section 7 come from the same developer’s Anthropic Economic Index. Three risks follow. The first is bias: a model may rate tasks in its own domain, such as software, as more delegable than tasks it knows less well, and may share the blind spots of its training data about work outside rich countries. The 20 human check that would bound this bias is weaker than the one we registered (deviation D2). The human rating of 300 tasks was led by a coauthor with the help of student raters: they were blind to the model ratings and to the results, but the lead shares the authors’ framing of the question, and because which rater scored which task was not recorded there is no measure of how much humans disagree with each other. Agreement with that rating bounds the bias only as far as a few informed readers’ judgement does, and neither they nor any small panel of graduates is a sample of the world’s workers. The agentic panel does not fill that gap: Claude Opus 5.5 with web search brings evidence about how tasks are done, but it comes from the same developer as the two raters and may share their view of which work suits a model, so its agreement with them is a check of consistency, not of validity. Three independent human raters on the full 1,500 tasks remain the registered standard and are left for a second version. The second is circularity: if the same family of models both rates delegability and generates the usage data, agreement between the two could reflect a shared view of the world rather than validation. We address it by testing convergence against indices built by other methods and other raters (Eloundou et al., 2024; Felten et al., 2021; Gmyrek et al., 2025), by comparing with the Agentic Adoption Index, which uses no model rating (Lee et al., 2026), and by reporting the Colombian wage dynamics, which involve no model at all. The third is instability: the command-line interface exposes no temperature setting, so the same prompt can return different levels on different days. The test–retest statistics in Section 4 quantify this, and the consensus rule across models dampens it; the raw outputs of every pass are released so that others can recompute. A fourth risk is framing. In the pilot, a model told that it is an agent rated tasks as more delegable: the interface’s default wrapper raised the mean level from 1.33 to 1.64 on the same tasks. The ratings therefore depend on how the rater is addressed, not only on the task. We fix the neutral configuration for the main pass and report, as a preregistered secondary result, the same validation tasks rated under the default wrapper (Section 7), so that readers can see how much of the index moves with the frame. Model-based rating of social facts has a short literature (Horton, 2023; Argyle et al., 2023; Korinek, 2023), including evidence that model-simulated survey respondents miss the results of human polls (Chapekis et al., 2026), and the known tendency of models to favour their own outputs (Zheng et al., 2023; Panickssery et al., 2024) is a reason to read every number here as a model’s judgement, not a measurement of the world. 

8.4 Preregistration 

The hypotheses, rubric, rater set, call configuration, sample seeds and analysis plan were registered on the Open Science Framework on 21 October 2026, before the main pass, under embargo until 31 January 2027 (Espinal Maya and Jiménez Londoño, 2026). The registration constrains what we can report as confirmatory; everything else is labelled exploratory. Deviations from the registered plan, such as the source of the employment weights for unit groups within a reported group, are dated in docs/DESVIACIONES.md . A preregistration does not make a measurement right; it makes it checkable. 

8.5 Ethics 

An index of delegability describes work in the voice of the machine: which parts of a job it could take, and which it could not. That framing has costs. It can reduce a worker to the residue of tasks an agent cannot do, and it can read a barrier such as trust or care as a temporary obstacle rather than as the point of the job. Whether agents complement or replace the people who do these tasks is a design choice as much as a technical fact (Autor, 2024), and a world with less work is not self-evidently a worse one (Danaher, 2019). We have tried to keep the four barriers visible rather 21 than fold them into a single score, so that a reader can see why a task stays with a human and not only that it does. The divide we name is also not symmetrical in its meaning. In high-income countries, high delegability describes a labour market about to reorganise; in low-income countries, low delegability describes a labour market whose work agents cannot reach, which is not the same as protection. Who is delegated, who delegates, and who is left outside the scope of delegation are distributional questions, and the atlas is meant to put them on the table, not to settle them. We use no personal data; all inputs are public statistics, public classifications or anonymised household surveys used under their licences. The human rating in this version was led by a coauthor as part of his work on the paper, with the help of student raters; no external professional raters were recruited, the student raters are not identified, and no personal data about raters are collected or released. 

# 9 Conclusion 

35.2% of task time in world employment is at least partly delegable to AI agents, and only 2.5% can be handed over in full. Agents, as the models judge them, take over parts of tasks far more often than whole tasks, and whole tasks mostly when they take a human about twelve minutes. The share varies with income, from 22.5% in low-income to 48.7% in high-income countries. This delegation divide is a matter of composition: poorer countries employ more people in work with a physical barrier, and agents have no body. It is not evidence that the same task is less delegable in a poorer country, and it is not protection; it describes where agents can and cannot reach. Two preregistered expectations failed, and both failures are informative. The adoption gap did not appear: observed AI usage tracks delegability closely across countries ( r = 0.86), and middle-income countries do not lag behind their delegable task base. And at the occupation level ADI correlates with exposure indices above the bound we set in advance (0.93 with Eloundou et al., 0.89 with Felten et al.). The occupations an agent could take over are, for the most part, the ones a language model could already speed up. ADI’s contribution is not a new ranking of occupations. It is delegation levels and barriers on top of exposure, for the world: a scale that separates partial from full delegation, a record of why each task stops short, and a task-level index in ISCO-08 for 146 countries, which correlates far less with observed usage than with exposure. The blind human rating agrees with the model consensus at κ = 0.85 and is the more generous of the two; the agentic panel with web search agrees with the consensus at κ = 0.87; and the interface’s default wrapper raises Sonnet’s mean level from 1.04 to 1.53, so the frame in which a model is addressed is part of the measurement. ADI measures technical delegability with the technology of October 2026, not deployment, and it will move as agents improve; the rubric, the code and the ratings are released so that the index can be rerun. We release the index for every ISCO-08 unit group, the country atlas, the rubric, the ratings and an MCP server at 

https://github.com/Cespial/delegation-divide .

# B Crosswalk O*NET to ISCO-08 

This appendix documents the bridge from O*NET 30.2 task statements to ISCO-08 unit groups implemented in datos/construir_crosswalk.py . Every count below is printed by the script’s log and is reproducible from the input files listed in datos/MANIFIESTO.jsonl .

B.1 Inputs 

• O*NET 30.2 Task Statements (18,796 statements for 923 O*NET-SOC 2019 occupations), Task Ratings (scales IM, importance, and FT, frequency) and Occupation Data (titles) (National Center for O*NET Development, 2026). • O*NET-SOC 2010 to O*NET-SOC 2019 crosswalk, O*NET Resource Center (CSV; 1,110 codes of 2010 to 1,012 codes of 2019). 28 • SOC 2010 to ISCO-08 crosswalk of Hardy et al. (2018), Institute for Structural Research (IBS), file soc10_isco08.dta : 1,131 rows linking 839 six-digit SOC 2010 codes to all 436 ISCO-08 unit groups. 

B.2 Steps 

1. Task weights within O*NET occupation. For each task, importance is the mean of the IM scale (1–5) and frequency is the mean category of the FT distribution (1–7, from yearly or less to hourly or more), computed as ∑ 

> k

pkk/ 100 over the seven category percentages. Missing values are imputed with the median of each scale. The task weight is importance × frequency, normalised to sum to one within the O*NET-SOC 2019 occupation, following Acemoglu and Autor (2011). 2. O*NET-SOC 2019 to O*NET-SOC 2010. The official crosswalk is used in reverse. The six-digit SOC 2010 code is the 2010 O*NET-SOC code with its two-digit suffix removed. An O*NET-SOC 2019 code that descends from several 2010 codes (97 cases) divides its mapping weight equally among them. 3. Rescue of SOC 2010 codes absent from the IBS file. Two codes used by O*NET-SOC 2010 are not in the IBS crosswalk: 19-1020 (biological scientists, broad group used as a detailed code) and 29-2055 (surgical technologists). The rule tries, in order, the “all other” residual of the same broad group (code ending in 9), then the other detailed codes of the same broad group in ascending order, then the codes of the same minor group. It assigns 19-1020 to 19-1029, which the IBS file maps to ISCO 2131 (biologists, botanists, zoologists and related professionals), and 29-2055 to 29-2051, mapped to ISCO 3259 (health associate professionals not elsewhere classified). Both are documented here because the second is a group-level approximation rather than a conceptual match. 4. New occupations without a 2010 ancestor. Four O*NET-SOC 2019 codes were created after the 2010 taxonomy and have no row in the crosswalk: 15-1299.04 (penetration testers), 15-1299.05 (information security engineers), 15-1299.06 (digital forensics analysts) and 15-1299.07 (blockchain engineers). They are assigned by hand to SOC 2010 15-1199 (computer occupations, all other), which the IBS file maps to ISCO 2519 (software and applications developers and analysts not elsewhere classified) and 2529 (database and network professionals not elsewhere classified), with weight one half each. 5. SOC 2010 to ISCO-08. Each SOC 2010 code maps to k ISCO-08 unit groups with weight 1/k . In the IBS file 683 codes map to one group, 102 to two, 30 to three and 24 to four or more (maximum 17). The mapping weight is multiplied by the within-occupation task weight to give the weight of each (ISCO group, task) pair, then renormalised within the ISCO group. 6. Aggregation to pairs. The same task reached through several O*NET occupations is summed into one pair per ISCO group. The result is 30,549 pairs covering 18,796 distinct tasks and 433 unit groups, with a median of 48 tasks per group (minimum 5, maximum 860), and 403 distinct task sets, since some groups share exactly the same O*NET sources. 

B.3 Exclusions and imputations 

Military. The three armed-forces groups, 0110 (commissioned armed forces officers), 0210 (non-commissioned armed forces officers) and 0310 (armed forces occupations, other ranks), have no O*NET tasks and are excluded from the index and from the country weights. 29 Seven imputed groups. Seven unit groups receive no task through the chain because their SOC counterparts are residual “all other” codes that the IBS file routes elsewhere. Each inherits the task set of its three-digit minor group (all non-imputed unit groups with the same first three digits), with weights renormalised, and is flagged imputado = True so that it can be dropped in the robustness check without imputed groups:

B.4 Why not the earlier matrix 

The first author’s earlier work on augmented human capital (Espinal Maya, 2026a,b) bridged SOC to the Colombian adaptation of ISCO-08 at one digit and distributed tasks downward, so that 440 four-digit occupations shared 9 task sets and the median task belonged to 77 occupations. That matrix cannot separate a surgeon from a statistician. The chain above keeps 403 distinct task sets across 433 groups and is the only bridge used in this paper. The occupation-level comparison indices of Section 4 are carried to ISCO-08 with the same chain, applied at the occupation rather than the task level.

C.2 Files 

The release contains, under salidas/ :30 • adi_isco.csv : one row per ISCO-08 unit group with ADI o, ADI3 o, ADIs o, the bootstrap interval, the four barrier shares and the number of tasks. • adi_pais.csv : one row per country with ADI c and its variants, the ISCO level used, the reference year, the income group and total employment. • adi_tarea.csv , with the task statement, the consensus level and each model’s level, and the raw model outputs ( ratings_sonnet.jsonl.gz , ratings_haiku.jsonl.gz ), so that any aggregation rule can be recomputed. • claims.jsonl : every number in this paper with its identifier, value, interval and the script that produces it. C.4 Python package 

pip install adi-index import adi adi.lookup("2512") # ISCO-08 code adi.search("software") # title substring adi.country("COL") # ISO 3166-1 alpha-3 adi.top(10) # most delegable occupations adi.cite() # BibTeX string 

The package ships the index as data and needs no network access; it exposes the same operations as the server below. 

C.5 MCP server 

The Model Context Protocol (MCP) is an open standard that lets an AI agent call external tools (Anthropic, 2024). The server adi-mcp (PyPI; listed in the MCP registry) offers four tools: 

lookup_occupation takes an ISCO-08 code, an ESCO occupation identifier or a free-text title and returns the occupation’s levels, barriers, intervals and version. 

country_profile takes an ISO 3166-1 alpha-3 code and returns the country’s index, its variants, the ISCO level and year of the employment data, and the income group. 

top_occupations returns the n most delegable occupations at level L2+ or L3. 

cite returns the BibTeX entry above and the dataset DOI, so that an agent that uses the index can cite it in its output. 31 A typical configuration for a Claude Code or similar client is: 

{"mcpServers": {"adi": {"command": "uvx", "args": ["adi-mcp"]}}} 

Every response includes the citation string. 

C.6 llms.txt 

The repository root and the dataset site carry llms.txt and llms-full.txt , which summarise the paper, the headline number, the file layout and the citation in a form meant to be read by language models. Agents that index repositories should start there.
