## 摘要
大语言模型（LLM）智能体的快速发展，使系统能够借助外部工具自主完成复杂任务，但其日益扩大的个人数据访问权限也带来了显著的隐私风险。现有基准主要通过模拟轨迹和基于结果的指标评估 LLM 智能体隐私，因此难以捕捉智能体多步骤执行过程中产生的隐私风险。本文提出 AgentPrivArena，这是一个用于评估真实 LLM 智能体工作流中隐私风险的框架。AgentPrivArena 在可复现的执行环境中集成了真实的 MCP 工具和自托管服务。我们进一步提出轨迹级隐私指标，用于量化最终响应泄露之外的不必要信息访问。在此框架基础上，我们提出 AgentPrivAudit，这是一种在智能体执行过程中监测隐私违规行为的运行时审计方法。对最先进 LLM 智能体开展的大量实验揭示了现有评估范式所忽视的重大隐私风险，凸显了轨迹级审计对于可信智能体部署的重要性。

## Abstract
The rapid advancement of LLM agents has enabled systems to autonomously perform complex tasks through external tools, but their growing access to personal data introduces significant privacy risks. Existing benchmarks primarily evaluate LLM agent privacy through simulated trajectories and outcome-based metrics, limiting their ability to capture privacy risks arising during multi-step agent execution. In this work, we introduce AgentPrivArena, a framework for evaluating privacy risks in realistic LLM agent workflows. AgentPrivArena integrates authentic MCP tools and self-hosted services within a reproducible execution environment. We further propose trajectory-level privacy metrics that quantify unnecessary information access beyond final response leakage. Building on this framework, we introduce AgentPrivAudit, a runtime auditing approach for monitoring privacy violations during agent execution. Extensive experiments on state-of-the-art LLM agents reveal substantial privacy risks overlooked by existing evaluation paradigms, highlighting the importance of trajectory-level auditing for trustworthy agent deployment.

## 1. 核心问题与整体含义

### 研究背景与动机
- LLM 智能体能够借助邮件、知识库、聊天、日历等工具自主完成任务，但也因此接触到健康、财务、法律等敏感信息。
- 现有隐私评估通常存在两类不足：
  - **环境不够真实**：依赖预先编写的模拟轨迹，难以体现智能体自主搜索、错误恢复、状态修改及长期上下文积累。
  - **过度关注最终输出**：只检查最后发送的消息是否泄露，无法发现执行过程中已经读取、但没有输出的敏感信息。

### 论文要解决的问题
论文将智能体隐私拆成三个连续问题：
1. 智能体读取了哪些敏感信息？
2. 审计机制是否识别了这些信息及其流向？
3. 最终对外传输是否符合任务目的和接收者的权限、关系与渠道条件？

其理论基础是**情境完整性（Contextual Integrity，CI）**：隐私不是一概禁止分享数据，而是判断信息流动在具体情境中是否适当。

### 整体含义
论文提供了两个互补组件：
- **AgentPrivArena**：让隐私场景在真实软件服务上运行的评估环境。
- **AgentPrivAudit**：在执行过程中识别信息流，并在对外写入前进行审计的机制。

需要注意，“真实世界”主要指**真实服务、API 和可执行工作流**，并非真实用户数据或生产环境；实验数据仍为合成场景。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 AgentPrivArena：可执行隐私评估环境

框架包括三层：

| 层次 | 主要作用 |
|---|---|
| 本地服务层 | 保存任务相关邮件、聊天记录、知识页面、帖子和日历事件 |
| MCP 工具层 | 将服务原生 API 封装成智能体可以调用的工具 |
| 智能体执行层 | 基于 OpenHands，在 Docker 工作空间中运行待测模型 |

- 集成六种自托管开源服务：**BookStack、Mattermost、Rocket.Chat、Mailpit、GoToSocial、Radicale**。
- 提供 **28 个工具**，分为发现、读取和写入三类，分别为 13、8、7 个。
- 将源场景转换为任务说明和服务种子数据，使敏感记录存在于服务内部，而不是直接塞入提示词。
- 每个任务运行前重置并初始化服务，运行后记录轨迹、清除状态，以控制跨任务污染。

发现类工具也可能返回消息正文或摘要，因此审计不能仅依赖工具分类，而需要检查实际返回内容。

### 2.2 AgentPrivAudit：两个边界上的运行时审计

#### 第一阶段：读取边界的信息流提取
每批工具返回结果后，提取器结合用户任务和已经观察到的内容，更新信息流清单：

\[
I_t=\{f_1,\ldots,f_{n_t}\}
\]

每条信息流包含五个 CI 属性：
- **发送者**：数据来源。
- **接收者**：预期的信息消费者。
- **数据主体**：信息涉及的人。
- **信息类型**：例如健康记录、身份信息。
- **传输原则**：允许分享的条件。

任务目的、渠道、接收者角色及来源情境也参与后续判断。

**重要特点**：原始工具结果仍原样交给执行智能体；提取器不会阻止读取或隐藏记录，只维护清单，并可提供简短提醒。

#### 第二阶段：写入边界的策略裁决
在邮件发送、消息发布、页面写入等操作真正执行前，裁决器检查拟传输内容，输出：
- **PASS**：允许传输。
- **ABSTRACT**：要求将具体细节概括化，再修改或重写。
- **BLOCK**：阻止相关信息流。

整体流程可概括为：

> 接收任务 → 搜索与读取 → 提取信息流并更新清单 → 起草写入操作 → 策略裁决 → 放行、概括修改或阻断 → 执行合规写入。

### 2.3 三种可配置隐私标准
- **PII 保护**：是否披露委托人以外其他人的可识别信息？
- **数据最小化**：该事实是否是完成任务所必需的？
- **情境完整性**：向这一接收者、通过这一渠道、为这一目的分享该事实是否适当？

不同策略共用结构、解析器和执行路径。但严格来说，策略切换不仅替换一个判断问题，还同步替换处置规则、安全表达要求及示例，以避免示例继续诱导旧策略。

### 2.4 评估指标

**结果级指标**
- **泄露率**：最终提交动作泄露至少一个参考敏感事实的任务比例。
- **有用性**：最终动作完成用户任务的程度，按 0–3 分评分。

**轨迹级指标**
- **暴露率**：全部参考敏感事实中，出现在工具观察结果里的比例。
- **提取召回率**：已经暴露的敏感事实中，被表示为信息流的比例。
- **处置分布**：提取出的信息流中，PASS、ABSTRACT、BLOCK 的占比。

这些指标使用不同分母，不能直接比较。尤其是，**敏感信息被读取不一定意味着读取不必要或构成违规**；暴露率衡量的是接触范围，而不是经过逐项必要性验证的“过度访问率”。

## 3. 实验设计：数据、Benchmark 与对比方法

### 数据集与场景
- 源数据为 **PrivacyLens 的 493 个场景**。
- 其中 **389 个**转换成可执行任务，约占 78.9%。
- 104 个未转换成功，主要由于群聊支持不足、发送者账户无法映射、源记录无法初始化等环境限制。
- 389 个任务包含 **1,175 个参考敏感事实**，每个任务中位数为两个。

场景覆盖邮件、聊天、知识库、社交媒体及日历相关工作流，敏感内容包括医疗、薪资、税务和法律案件信息。

### Benchmark 的性质
AgentPrivArena 是一个从既有场景构建的**实时执行型隐私评估环境**，而不是独立采集的大规模新数据集。

其关键变化是：智能体必须自行找到记录、调用真实工具并完成最终操作，而不是只沿着预先写好的轨迹回答。

### 模型与对比条件
主实验测试五个执行模型：
- GPT-5.4
- DeepSeek-V4-Pro
- Kimi-K2.6
- Mistral-Large-3
- Gemini-Flash-2.5

每个模型比较五种条件：

| 条件 | 方法 |
|---|---|
| C0 | 无隐私缓解 |
| C1 | 通用隐私意识系统提示 |
| C2 | AgentPrivAudit + PII |
| C3 | AgentPrivAudit + 数据最小化 |
| C4 | AgentPrivAudit + CI |

主实验中的提取器和裁决器均使用 GPT-5.4。

### 外部评判与消融
- 泄露和有用性由 **GPT-5、Claude Sonnet 4.5、Gemini 2.5 Pro**独立评判。
- 对每个敏感事实，至少两名评判模型认定泄露，才将任务计为泄露。
- 消融包括：
  - 同一隐私标准仅写入提示词，或由审计机制执行。
  - 使用 GPT-5.4 与非推理版 Grok-4-20 交换执行器、审计器角色。
  - 比较静态与实时轨迹，并分析工具调用深度、错误恢复、成本和失败案例。

## 6. 主要结论与发现

### 6.1 运行时审计显著降低最终泄露

| 条件 | 平均泄露率 | 平均有用性 |
|---|---:|---:|
| C0 | 46.8% | 2.60 |
| C1 | 43.0% | 2.64 |
| C2 | 26.5% | 2.55 |
| C3 | 19.7% | 2.59 |
| C4 | **17.8%** | **2.59** |

- CI 审计相对无缓解降低 **29.0 个百分点**，相对降幅约 **62%**。
- 平均有用性基本保持，但个别任务会因反复概括而失去实际答案。
- CI 在五个执行器上均取得最低泄露率。

### 6.2 仅检查输出会遗漏大量敏感信息接触
- 无缓解时，**79.2% 的参考敏感事实**进入智能体上下文。
- CI 审计后，暴露率仍为 **74.2%**。
- 这些比例与任务级泄露率分母不同，不能解释为某一比例的任务“读取但未泄露”。

### 6.3 信息流提取是重要瓶颈
- CI 条件下，提取召回率为 **70.5%**。
- 约 **29.5% 已读取的敏感事实**未进入信息流清单，因而难以被后续裁决器可靠治理。
- 该发现说明提取覆盖率限制了机制，但不能简单把 70.5% 当作任务级防护效果的严格数学上限。

### 6.4 执行机制比单纯提示更关键
- 把隐私标准写进提示词只带来有限改善。
- 通过运行时审计执行后，标准之间的差异更明显。
- CI 相对 PII 的优势有较强统计支持；CI 相对数据最小化的交互差异并不显著。

### 6.5 隐私表现更依赖审计器
- 共享同一审计器后，执行模型间的泄露差距明显缩小。
- 更换较弱的非推理审计器使泄露率上升约 6–10 个百分点。
- 这支持将隐私治理能力作为独立模块维护，但不意味着执行器行为完全不再重要。

## 7. 优点与亮点

- **执行真实性较强**：真实服务支持自主搜索、失败恢复和状态变更，而非假设每次调用成功。
- **过程诊断更细致**：区分“被读取”“未被识别”“被允许或概括”等阶段，便于定位失败边界。
- **策略可配置**：PII、数据最小化与 CI 共用主要执行架构，便于研究不同隐私规范。
- **强调情境而非关键词删除**：能够考虑公开频道中的受众范围、人物关系等非显式标识符风险。
- **隐私与效用联合评估**：不仅报告平均性能，也展示保护隐私却无法完成任务的失败案例。
- **复现设计较完整**：提供服务配置、MCP 适配器、任务转换、审计代码及策略模板，并记录容器镜像信息。
- **披露边界较坦诚**：明确报告残余泄露、LLM 评判缺乏人工验证和 fail-open 风险。

## 8. 不足与局限

### 8.1 数据与场景覆盖有限
- 仅覆盖单一委托人、单一智能体和主要为文本的工作流。
- 群聊等场景转换失败，可能系统性遗漏依赖广泛受众的违规情境。
- 缺少真实组织权限结构、真实用户行为及跨基准验证。
- 作者认为部分遗漏可能使结果偏保守，但这一方向未被实验充分验证。

### 8.2 指标与评判存在偏差风险
- 标题性结果均依赖 LLM 评判，没有完成人工标注验证。
- 在较容易判断的条件下，一致性 κ 约为 0.82–0.87；在重点推荐的审计条件下下降至 0.61–0.71。
- 多个评判模型可能共享相同评分规则的偏差，多数投票不能保证正确。
- 泄露判据主要检查参考秘密是否被披露，不完全等同于逐项验证所有信息流的 CI 合规性。
- 固定敏感事实清单也可能遗漏智能体发现的新敏感信息。

### 8.3 防护范围与可靠性有限
- 最优条件仍有约 **16%–19% 的任务泄露**。
- 读取阶段不阻止敏感记录进入上下文，因此不是严格的访问最小化机制。
- 防护主要依赖登记的写入工具，不能直接推广为任意工具或其他数据通道的安全保证。
- 机制采用 **fail-open**：审计失败时可能继续执行，不适合作为对抗恶意攻击的强安全边界。

### 8.4 效用与成本问题
- 反复概括可能把必要答案也删除，当前机制无法识别这种“隐私成功、任务失败”。
- 读取与写入阶段掌握的受众信息可能不同，导致前后裁决不一致。
- Token 成本约翻倍，实际延迟和经济成本尚未充分评估。

### 综合评价
这篇论文最有价值的贡献，是把智能体隐私研究从**“最终动作有没有泄露”**推进到**“执行中接触了什么、识别了什么、允许传输了什么”**。实验支持运行时审计的有效性，但更适合将其视为可复现的研究框架与风险缓解模块，而不是已经验证完备的生产级隐私安全保障。
