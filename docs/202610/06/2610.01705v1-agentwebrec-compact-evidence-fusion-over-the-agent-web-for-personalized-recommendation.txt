## Abstract 

LLM-based personal agents are emerging as persistent carriers of user semantics and intermediaries between users and recommenda-tion platforms, maintaining richer user knowledge locally. As agents interact with one another, the conventional User–Platform relation evolves into a User–Agent Web–Platform information pathway, en-abling distributed user-side information to complement item-side information. This new pathway, however, defies conventional rec-ommendation: evidence is scattered across mutually opaque agents and reachable only through bounded queries, only a small portion of it is relevant to the current recommendation decision, and the responses returned by different agents are semantically heteroge-neous. We therefore recast recommendation over the Agent Web as a task-time evidence acquisition and fusion problem under a finite evidence budget by deciding what to ask and what to keep, rather than learning from aggregated data. We propose AgentWebRec, a user-agent-oriented framework that progressively acquires and fuses distributed evidence for each user-item decision while keep-ing underlying agent memories local. It grounds each decision in platform-provided item semantics and task-relevant evidence from the target user agent’s private memory, and conditionally queries neighboring user agents for complementary preference patterns when local evidence is insufficient. Experiments on four InstructRec datasets show that AgentWebRec consistently outperforms base-line recommenders, and ablations verify that the evidence layers contribute complementary gains.

## 1 Introduction 

Recommendation systems have long served as a core infrastruc-ture by which individual users discover relevant information on the Web, proactively surfacing items aligned with personal prefer-ences instead of requiring users to search an ever-growing space themselves. Classical recommendation methods predominantly op-erate on direct user–platform interactions, from which they learn user and item representations to model user preferences [11, 12, 16, 17]. Although this platform-centric setting has enabled substantial progress in recommendation, interaction signals remain ambiguous. Because observed behaviors reveal only the users’ actions but not the underlying intentions, aggregating such heterogeneous signals into user representations could emphasize recurring patterns while obscuring transient or evolving preferences. Consequently, similar behavioral histories would correspond to different individual pref-erences, while the same user exhibits distinct needs under different contexts [20, 44]. With the development of LLMs in recent years, LLM-based personal agents are beginning to change this interaction model. Consumer-oriented agent products, such as Alibaba’s Qwen and Amazon’s Alexa+, combine historical user information and cur-rent context to infer intentions and preferences [2, 7]. On this basis, an agent act on the user’s behalf to interact with the plat-form by formulating searching for specific items, examining ranked results and comparing candidates. In contrast to conventional user-platform interactions, where user actions are observed as isolated stateless events, an agent maintains the evolving states across re-quests. Meanwhile, memory-oriented agent systems show that an LLM agent can organize and retrieve long-term user-specific infor-mation [25, 26, 36]. A user agent plays two roles in this new interac-tion model. As a persistent carrier of user semantics, it accumulates the user’s preferences, feedback, and context across sessions and arXiv:2610.01705v1 [cs.IR] 1 Oct 2026 KDD ’27, August 01–05, 2027, San Jose, United States Haoran Qiang, Guannan Liu *, Liang Zhang, and Junjie Wu

services, maintaining a local user profile richer than what any sin-gle platform observes. As an intermediary, it stands between the user and platforms, interpreting the user’s intentions and acquiring information on the user’s behalf. However, richer local knowledge does not guarantee sufficient task-time evidence: when prior experi-ence offers little analogous signal for the candidate item, an isolated agent lacks the reusable preference patterns needed to ground its decision, and must look beyond its own memory. Emerging agent-native communities provide a basis for con-necting distributed information. Within this setting, when private memory lacks available information for a recommendation task, a user agent can discover and collaborate with agents that provide relevant information [13, 24]. In a macro view, task-oriented collab-orations between user agents constitute the edges of the Agent Web [5, 39]. Crucially, such collaboration only exposes task-level capabil-ities and responses with the internal states unseen: protocols such as A2A make agents discoverable while leaving their internal memo-ries and reasoning states opaque [1]. Agent-native communities are not limited to interactions among user agents: recommendation plat-forms also participate in the Agent Web through functional agents that expose item-side information [1, 5]. As shown in Figure 1, the conventional User–Platform relation is thereby transformed into a User–Agent Web–Platform paradigm, where the user agent in-terprets preferences from local semantic memory and integrates task-relevant evidence acquired across the Agent Web .Existing recommendation research does not directly address this configuration. LLM-based recommendation methods use LLMs to improve the representation of user intentions, item semantics, in-teraction sequences, and recommendation instructions [9, 14, 18, 38, 44]. Agent-based approaches further introduce planning, tool use, user simulation, reflection, feedback loops, and multi-agent coordination into recommendation [4, 15, 34, 35, 42, 43]. These stud-ies demonstrate the potential of agent reasoning and memory, but generally organize agents within a platform-controlled workflow or allow the platform to construct and update reusable agent states. Meanwhile, research on the Internet of Agents and the Agentic Web studies general-purpose agent discovery, communication, and collaboration [5, 39], but does not specify how independently main-tained user-side information should be combined with platform-side information for a specific recommendation decision. This gap changes the central problem from aggregating more user information to eliciting the information required by the cur-rent decision. We therefore ask: How can a user agent construct task-specific queries that acquire and fuse useful information from distributed and opaque sources for a current recommendation task? 

This question presents three challenges. First, the relevant infor-mation is distributed across participants whose internal states are mutually inaccessible. A requester must express what information is needed without inspecting the underlying evidence in advance. Second, richer information is not necessarily more useful. A user agent maintains extensive long-term information, but only a small fraction may be relevant to the current decision context. Uncon-strained acquisition can introduce irrelevant information and dilute the target user’s actual preference. Third, the returned responses are heterogeneous. Platform knowledge, agent local information, and external agent feedback describe different aspects of the task and may differ substantially in semantic perspective. Directly con-catenating them does not guarantee that they support the decision. To investigate this problem, we propose AgentWebRec, a user agent oriented recommendation framework that formulates recom-mendation as task-time information acquisition and fusion over the Agent Web. AgentWebRec treats task-specific queries as the interface between distributed information sources and the current decision. Instead of transferring complete memories or reconstruct-ing a global user profile, each participant interprets the information query locally and returns a compact response. The target user agent then organizes the acquired information around the current user-item context, allowing user-side information to complement the platform representation and external experience to provide addi-tional support when appropriate. We evaluate AgentWebRec on four domains from the Instruc-tRec benchmark and compare it with conventional recommendation methods. AgentWebRec achieves consistently strong performance across the evaluated datasets. More analyses further demonstrate that target-agent information and external-agent experience pro-vide complementary benefits, while task-oriented information ac-quisition avoids indiscriminately introducing all available agent information. Together, the contributions are summarized as follows: 

• We introduce recommendation over an Agent Web composed of user agents, which mediates interactions between users and the platform while agent memories remain distributed and local. 

• We propose AgentWebRec, which selectively acquires dis-tributed information and progressively fuses it into task-specific evidence without centralizing agent memories. 

• Experiments on four InstructRec datasets demonstrate the effectiveness of AgentWebRec against baselines for person-alized recommendation.

## 3 Methodology 3.1 Overview of AgentWebRec 

To address the two coupled problems formulated above, we propose AgentWebRec to selectively acquire distributed information and progressively fuse it into compact evidence for each recommen-dation task. AgentWebRec instantiates 𝐹𝑢𝑠𝑒 (·) as a progressive process that interleaves task-time information acquisition with evidence fusion over the Agent Web. As shown in the Figure 2(a), the target user agent performs the recommendation task by interacting with the platform agent, its own local memory, and its neighboring user agents. The query-response data flow enables interaction among agents whose internal states are mutually inaccessible. A query and a response are gen-erated autonomously by an agent according to its current internal state without knowing the external states from other collaborators. As a result, no centralized orchestrator is required to maintain a global view of the participating agents in the Agent Web .Within this decentralized interaction interface, the three agent actions in Figure 2(b) progressively identify information relevant to the current decision. The platform query 𝑞 𝑃 𝑡 elicits enhanced item semantics 𝑑 𝐸 𝑖 as R𝑃 𝑡 , which establishes a preference-relevant semantic anchor for the candidate item. This anchor determines the scope of local retrieval, allowing the target user to select relevant interactions from its own memory as R𝑈 𝑡 . The retrieved information is projected into a task-specific preference state 𝑃 𝑡 and an initial decision 𝐷 𝑡 . When the semantic evidence from target user agent is insufficient, the unresolved decision is transformed into a collab-oration query 𝑞 𝐶 𝑡 , which elicits generalizable preference patterns evidence from neighboring agents as R𝐶 𝑡 . These patterns comple-ment the limited coverage of the target user’s private experience and strengthen the reliability of the resulting decision. Information acquisition is therefore controlled by the evolving task state, which respects to the relation R𝑡 = R𝑃 𝑡 ∪ R 𝑈 𝑡 ∪ R 𝐶 𝑡 , where R𝐶 𝑡 = ∅ when collaboration is not activated. Together, AgentWebRec constructs compact, task-oriented evidence without exposing agent-internal states, using query-response interactions to elicit decision-relevant information and progressive state updates to reconcile the hetero-geneous semantics of different sources.

## 4 Experiments 

We conduct experiments to evaluate whether distributed user agents can autonomously infer task-specific preferences from decentral-ized user evidence and construct effective recommendation signals. The experiments are organized to answer the following four re-search questions: 

RQ1 (Overall Performance): How does AgentWebRec per-form compared with conventional centralized recommendations and existing LLM/agent-based recommendation methods? 

RQ2 (Agent Actions Contribution): How do the key agent actions in AgentWebRec contribute to recommendation effective-ness? 

RQ3 (Parameter Sensitivity): How do key task-time parame-ters affect the recommendation performance of AgentWebRec? 

RQ4 (Collaboration Structure): How does the construction of user agent edges in the Agent Web affect recommendation perfor-mance? 

## 4.1 Experimental Setup 

4.1.1 Datasets. We evaluate AgentWebRec on four domains from the InstructRec benchmark [44]: Books, Goodreads, MovieTV, and Yelp. Each dataset provides timestamped user-item interactions, user persona descriptions, item profiles, and review texts. Table 1 summarizes the statistics of the four datasets. Following common experimental settings in agent-based recom-mendation [6, 21, 43], we order each user’s interactions temporally, use the earlier records as warm-up history and the last interac-tion as the test target. For evaluation, we randomly sample 1,000 users and rank each target item against nine sampled negatives. User agents operate continuously as autonomous participants in the Agent Web without activation by the users’ instruction. We therefore provide no instruction and require the target user agent to infer the user’s relevant preference. We report Hit Rate ( H@K )and NDCG ( N@K ) for 𝐾 ∈ { 1, 3, 5}. To reduce randomness, we report the average results of three repeating tests. By default, Agen-tWebRec enhances each candidate with five semantic neighbors, retrieves up to five private-memory interactions for the target and each collaborator, and activates at most three collaborators over item-co-occurrence edges under a confidence threshold of 0.7. ## 4.2 Main Results (RQ1) 

We compare AgentWebRec with centralized representation-based recommendation methods to assess whether it can exceed platform-centric recommendation under the User–Agent Web–Platform set-ting. Table 2 reports the main comparison results. As seen, Agen-tWebRec achieves the best results across all reported metrics on the four datasets. Its advantages are particularly clear on H@1 and NDCG for Books, Goodreads, and MovieTV, indicating that the acquired information helps the target agent distinguish the ground-truth item at the highest ranking positions. The consistent gains in H@3, H@5, and NDCG further show that the improvement is not limited to a single top-ranked prediction. LightGCN and SASRec primarily learn from structural regular-ities in user-item interactions, so their support becomes limited in the sparse datasets whose preference inference is mainly from the semantic textual content. LLMRank and AFL rely on LLMs to reason over the semantic content of user-item histories. How-ever, irrelevant information can obscure useful evidence without task-specific filtering while the absence of interactions among user agents prevent them from capturing generalized collaborative pat-terns. AgentCF and AgentCF++ user collaborative memory propaga-tion to capture generalizable patterns across user agents. However, they encode user preference and collaborative information into persist profiles, mixing information from different sources before decision. AgentWebRec instead tightly couples its acquisition and fusion actions, with each action guided by the state produced by the preceding one. This progressive design integrates task-relevant information from heterogeneous sources into reliable evidence, in-troducing collaborative patterns only when needed without diluting the target user’s personalized information. MemRec is generally the strongest baseline, as it curates and synthesizes target-user information with collaborative signals into a compact reasoning context. However, its reliance on an explicit user instruction weak-ens its ability. AgentWebRec instead uses the enhanced candidate semantics to retrieve relevant interactions from the target user’s private memory and projects them with the user persona into a task-specific preference state, thereby identifying the user’s current preference without a predefined instruction. The performance can be understood from two dimensions: in-teraction availability and semantic understanding. LightGCN ben-efits from dense interactions on Goodreads but weakens when sparse overlap limits structural support. AgentCF and AgentCF++ do not consistently benefit from richer histories. Goodreads con-tains longer and more diverse reading histories, where additional interactions span multiple preference facets and therefore provide less concentrated support for a particular recommendation task. AgentWebRec remains robust by acquiring a well-calibrated infor-mation set: sufficient semantic evidence under sparse local support and collaborative patterns only when necessary.

## 4.4 Sensitivity Analysis (RQ3) 

4.4.1 Confidence Threshold 𝜃 𝜅 and Collaboration Budget 𝐾 𝐶 . As shown in Fig. 3, both parameters indicate that collaboration is effective only within a controlled scope. A moderate 𝜃 𝜅 introduces external evidence for uncertain tasks while preserving reliable local decisions; a restrictive gate may miss useful cross-user signals, whereas a permissive gate admits weakly aligned patterns. The collaboration budget 𝐾 𝐶 similarly exhibits saturation: expanding the collaborator set improves preference-pattern coverage until the main relevant signals are captured, after which additional agents become largely redundant or noisy. Thus, fragmented local histories may benefit from broader collaboration, while informative histories require fewer collaborators. 

4.4.2 Platform-Local Item-Support Budget 𝐾 𝐼 . The third panel of Fig. 3 varies the semantic neighbors 𝐾 𝐼 − 1, with the candidate included in the total budget 𝐾 𝐼 . Performance follows an inverted-U pattern: undersized support sets yield unstable enhancement, moderate neighborhoods produce the most reliable rankings, and excessive expansion degrades performance. With too few neigh-bors, incomplete or idiosyncratic candidate descriptions dominate, and the support is insufficient to reveal recurring task-relevant at-tributes. A moderate set establishes enough semantic agreement to calibrate the candidate, whereas broader neighborhoods introduce less aligned semantics that dilute its distinctive characteristics and cause semantic drift. 

4.4.3 Target-User Memory Budget 𝐾 𝑀 . Across datasets, 𝐾 𝑀 shows a similar preference for concentrated evidence. Too few records leave R𝑈 𝑡 insufficient to ground 𝑃 𝑡 beyond the user persona, while a moderate budget supplies enough aligned interactions to stabi-lize the task-specific preference state. Excessive retrieval instead introduces weakly related or contextually mismatched behaviors, diluting relevant signals and increasing the reasoning load. Oc-casional gains on individual metrics under small budgets do not persist across broader ranking measures, indicating that robust personalization depends on evidence relevance and concentration rather than memory volume. ## 4.5 Effect of Agent Web Topology (RQ4) 

To investigate how the Agent Web topology G = (A , E) affects task-time collaboration, we compare different strategies for constructing the user-agent edges in E. The persona-similarity construction builds edges according to semantic similarity between persona em-beddings, while the random construction preserves the out-degree of the item co-occurrence construction but randomly rewires its edges. This comparison examines whether task-time collaboration benefits from a scope induced by agent-level similarity. Table 4 shows that structured user-agent edge constructions con-sistently outperform random rewiring. Item co-occurrence achieves the strongest overall performance, suggesting that shared interac-tion histories provide a reliable signal for identifying collaborative user agents with homophilic interests. This verifies the role of the user-agent edges in E in determining the task-time collaboration scope: since not all collaborative evidence is useful for the target decision, preserving homophilic connectivity in the Agent Web helps acquire more relevant preference-pattern responses. The persona-similarity construction also remains competitive, indicating that semantic user descriptions capture another useful form of agent-level proximity. However, its gains are less uniform than those of item co-occurrence, suggesting that high-level per-sona similarity may miss fine-grained preference evidence tied to the candidate item space. By contrast, the consistent degradation under degree-preserving random rewiring demonstrates that ir-relevant agent links inject distracting evidence into collaboration, confirming that similarity-based connectivity is essential for pre-serving useful preference signals. Overall, these results show that different task-relevant similarity signals can be used to instantiate the user-agent edges in E, but effective collaboration requires the Agent Web topology to encode task-relevant user proximity. 

## 5 Related Work 5.1 Platform-Centric Recommendation 

Traditional recommenders follow a platform-centric pipeline that learns reusable user and item representations from centrally col-lected interactions. Matrix factorization, pairwise ranking, and neu-ral collaborative filtering model global preference patterns [12, 30], while sequential methods capture temporal dynamics and contex-tual dependencies [16, 32]. Their effectiveness relies on aggregat-ing behavioral histories and optimizing a platform-wide ranking objective. Even when recent interests or high-order relations are modeled, the underlying evidence is still aggregated and interpreted centrally. Evidence processing and preference estimation therefore remain controlled by the platform, which differs from the Agent Web settings. 

## 5.2 LLM and Agent-Based Recommendation 

LLM-based recommendation introduces language representations and semantic reasoning into recommendation. Existing methods formulate recommendation as instruction following, textual se-quence modeling, or semantic item generation [9, 18, 29, 44], and incorporate collaborative semantics or augment sparse interaction graphs [37, 45]. Surveys further summarize the potential of LLMs for generative and general-purpose recommendation [19, 38]. injecting documents, collaborative signals, or graph contexts into LLM reasoning [8, 28, 47]. In most cases, however, retrieval remains a platform-side operation rather than an evidence-acquisition deci-sion made by a user-owned agent. LLM-powered agents extend this paradigm with planning, tool use, memory, reflection, and environmental interaction [26, 33, 40]. Recommendation agents can invoke tools, plan zero-shot proce-dures, coordinate specialized modules, and support interactive rec-ommendation [15, 34, 35]; other approaches simulate users or re-fine recommendations through agentic feedback loops [4, 42, 43]. Memory-oriented studies further address long histories, reusable personas, lifelong preference modeling, and collaborative mem-ory [6, 27, 31, 46]. Despite improving adaptability, these methods often wrap platform workflows or summarize histories into persis-tent contexts for a downstream LLM. AgentWebRec instead treats recommendation as task-oriented evidence reasoning, grounding each decision in relevant agent-owned evidence across the Agent Web. 

## 6 Conclusion 

This paper investigates personalized recommendation in the emerg-ing Agent Web , where LLM-based personal agents maintain person-alized context beyond individual platforms and collectively provide distributed user-side knowledge. Realizing this opportunity requires reasoning over opaque memories through bounded query-response interactions and aligning heterogeneous evidence with each deci-sion. We formulate the problem as task-time evidence acquisition and progressive fusion, and propose AgentWebRec, a framework that constructs compact decision evidence while keeping agent memories local. AgentWebRec enhances candidate semantics with platform knowledge, grounds them in the target agent’s relevant private experience, and, when local semantic evidence is insuf-ficient, supplements the decision with generalizable preference patterns distilled from related user agents. Experiments on four In-structRec datasets demonstrate strong and consistent performance against baselines. Overall, our work establishes task-oriented evi-dence acquisition and progressive fusion as a principled foundation for personalized recommendation in the Agent Web .

Prompt 1 AbstractLLM: Item semantic enhancement 

You are an item-analysis agent in a recommendation system. 

## Candidate item 

Description: {{candidate_description}} 

Attributes: {{candidate_attributes}} 

## Related items (by semantic + attribute similarity) 

{{related_items_block}} 

## Task 

Enhance the semantic description of the candidate item by focusing on the COMMON patterns shared across the candidate and its related items. Specifically: 

• Identify recurring semantic themes and attribute patterns among related items. 

• Extract the shared characteristics that define this group of items. 

• Use these shared patterns to refine and strengthen the description of the candidate item. 

• If a text contains a [TRUNCATED: ...] marker, use both remaining content and attributes to infer key semantics. Do NOT introduce unrelated details or emphasize differences. Focus on pattern abstraction and semantic consolidation. Return only the enhanced description as plain text. 

In this template, {{candidate_description}} and 

{{candidate_attributes}} denote the raw item description 𝑑 𝑖 .Together, these two fields provide the content of the candidate item record. {{related_items_block}} contains the descriptions the related item memory records 𝑚 𝑃 𝑗 for 𝑗 ∈ J 𝑃 𝑡 (𝑖 ). AbstractLLM extracts their recurring semantic and attribute patterns and returns the enhanced item semantics 𝑑 𝐸 𝑖 .

Prompt 3 MatchLLM: Listwise local matching 

You are a recommendation decision agent. You must output ONLY valid JSON. 

## Candidate item list 

{{structured_candidate_item_list}} 

## Candidate Item IDs (authoritative) 

{{candidate_item_id_list}} 

Total candidates: {{num_candidates}} 

## User preference summary 

{{target_user_preference_summary}} 

## Task 

Score every candidate item against the user preference. 

• Use each item’s ‘Item ID’ as the unique key. 

• score: float in [0, 1] 

• confidence: float in [0, 1] 

• rationale: one concise sentence 

• If uncertain, still provide a conservative score; never skip. 

## Hard constraints (must follow) 

• Output EXACTLY one decision for each candidate Item ID above. 

• Do NOT omit any candidate Item ID. 

• Do NOT add extra Item IDs.

{"decisions": [ {"item_id": <int>, "score": <float>, "confidence": <float>, "rationale": "<text>"}]}

You are the central agent that revises item-list ranking after one-hop collaboration. You must output ONLY valid JSON. 

## Candidate item list 

{{structured_candidate_item_list}} 

## Original list decisions 

{{list_decisions_json}}

{{candidate_item_id_list}} 

Total required decisions: {{num_candidates}} 

## Neighbor responses (with persona) 

{{neighbor_responses_with_personas_json}} 

## Task 

Notice the recurring and mutually consistent signals from the neighbor responses and use neighbor responses and personas to revise the list decisions. 

• Keep item_id unchanged. 

• score/confidence in [0, 1]. 

• rationale should mention key evidence briefly. 

• Treat item IDs in ‘Original list decisions’ as authoritative.

{"decisions": [ {"item_id": <int>, "score": <float>, "confidence": <float>, "rationale": "<text>"}]} 

RefineLLM takes the candidate list and local decisions produced by MatchLLM, together with the collaborator evidence returned by PatternLLM.
