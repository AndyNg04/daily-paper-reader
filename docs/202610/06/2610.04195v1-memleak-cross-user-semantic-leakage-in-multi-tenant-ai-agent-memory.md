## 摘要
在企业级多租户部署中，个人 AI 智能体共享一个用于长期记忆的向量存储。共享的嵌入空间为跨用户记忆泄漏提供了入口：通过常规的余弦相似度检索，某位用户的查询可能检索到属于另一位用户、语义相近的记忆，而无需利用任何漏洞。我们将此现象形式化为跨用户可访问性失效，并通过六项实验及后续消融实验，在稀疏检索（TF-IDF）和贴近生产环境的检索（MiniLM-L6-v2）两种设置下对其进行评估。在汇集同团队数据的检索设置下，非对抗性的偶发泄漏率达到 70%–100%；精心构造的对抗性记忆在 top-k 排名中的命中率达到 90%–100%，超过较弱的基于关键词的攻击基线。在贴近生产环境的稠密检索中（配置 B），其检索得分提升为 +0.416 至 +0.511。端到端响应污染在生产检索流程下达到 5.00/5，在 Claude Sonnet 4.5 下达到 4.67/5；受污染的响应往往被评为与干净响应同样有帮助，甚至更有帮助，这一差异也经人工评估得到验证。在三种架构层面的缓解措施中，只有检索后的严格所有权校验能够在两种生成模型下始终恢复干净基线（1.00/5），其测得的延迟开销约为每次查询 1.4 ms。

## Abstract
Personal AI agents in enterprise multi-tenant deployments share a common vector store for long-term memory. Shared embedding spaces create a surface for cross-user memory leakage: a user's query can retrieve semantically adjacent memories belonging to another user through ordinary cosine-similarity retrieval, without any exploit. We formalize this as cross-user admissibility failure and evaluate it across six experiments, plus follow-up ablations, under both sparse (TF-IDF) and production-faithful (MiniLM-L6-v2) retrieval. Non-adversarial, incidental leakage reaches 70--100\% under pooled {same-team} retrieval; adversarially crafted memories achieve 90--100\% top-$k$ placement, exceeding weaker keyword-based attacker baselines, with score lifts of $+0.416$ to $+0.511$ under production-faithful dense retrieval (Config B); and end-to-end response contamination reaches 5.00/5 under a production retrieval path and 4.67/5 with Claude Sonnet~4.5, with contaminated responses often scoring as helpful or more helpful than clean ones, a gap validated against human judgment. Among three architectural mitigations, only hard post-retrieval ownership gating consistently restores the clean baseline (1.00/5) across {two generation models, at a measured latency overhead of roughly 1.4~ms per query.

## 1. 核心问题与整体含义

### 研究背景与动机
- 企业个人 AI 智能体通常使用长期记忆保存用户偏好、项目背景和历史决策。为方便统一维护，多名用户的记忆可能存储在**同一个向量索引**中，通过用户、团队或项目元数据划定检索范围。
- 当所有权只是软元数据，或检索范围因协作需求扩大到团队、部门时，查询可能召回其他用户的私人记忆。例如，经理提出薪酬管理问题，可能检索到同事的薪资谈判、外部录用意向或股权信息。
- 既有记忆安全研究主要关注单用户内部的问题，如不适当记忆影响当前任务、越狱和工具调用偏移；本文关注的是**不同用户之间的信息边界**。

### 核心研究问题
- **语义相关的记忆，是否一定有资格进入当前用户的上下文？**
- 论文将“他人的记忆因语义相似而被正常检索召回”称为**跨用户语义共振**，并将其形式化为**跨用户准入失效**。
- 这种泄漏可以在没有恶意提示、代码修改或模型攻击的情况下发生；攻击者也可以利用同一机制，通过编写贴近目标业务的记忆，提高自身内容被召回的概率。

### 整体含义与适用边界
- 核心观点是：**语义相关性不能替代访问授权，回答有帮助也不代表隐私安全。**
- 论文并未证明共享向量库必然不安全，更未证明可以绕过正确实施的用户隔离。它主要研究**过滤不足、范围过宽或有意共享记忆池**的部署。
- 严格用户分区在本文实验中有效消除了跨用户召回，是明确的安全基线。

## 2. 方法论：核心思想、技术细节与流程

### 系统模型与泄漏定义
- 每名用户拥有一组记忆，记忆和查询被编码为向量。
- 系统计算查询与候选记忆之间的余弦相似度，取排名最高的 **top-k** 记忆，并注入大模型上下文。
- 本文将泄漏事件定义为：**某条记忆进入当前查询的 top-k，但它的所有者不是当前用户。**
- 准入指标同时要求：
  1. 记忆属于当前用户；
  2. 记忆适合当前查询。

这一形式化采用严格的个人所有权边界，因此与合法跨用户协作场景之间存在一定张力：现实系统还需要表达共享许可、角色权限和用途限制。

### 两类威胁
- **被动、偶发泄漏**：用户正常提问，其他用户的普通专业笔记因为词汇或业务背景相近而被召回。
- **主动利用**：攻击者编写“语义桥接”记忆，使其主题和叙述方式贴近目标用户的业务需求。
  - 核心攻击条件只假设攻击者知道目标的领域和角色。
  - 不要求知道目标的精确查询，也不要求了解嵌入模型内部机制。
  - 另设精确查询关键词和逐字复制查询的基线，用于界定知识优势。

### 主要指标
- **泄漏率 LR／XLR**：至少召回一条跨用户记忆的查询比例。
- **平均跨用户排名 MCR**：每个查询中排名最高的跨用户记忆的平均位置。
- **攻击记忆命中率**：攻击者记忆进入 top-k 的查询比例。
- **得分提升**：构造记忆相对于普通记忆的平均相似度增量。
- **回答污染、帮助程度**：分别使用 1–5 分量表评价信息披露程度和回答效用；污染 1 分表示未披露跨用户私人信息，5 分表示明确、详细披露。
- **共振指数 RI**：结合用户记忆质心相似度、Jaccard 重叠和泄漏率的启发式指标，权重分别为 0.35、0.25、0.40。该指标未经外部校准，不是核心结论的依据。
- 对小样本比例报告 **95% Wilson 置信区间**。

### 评估与防护流程
1. 构造不同用户的记忆与查询。
2. 在共享索引或用户隔离索引中进行相似度检索。
3. 测量跨用户召回、排名及攻击命中。
4. 将记忆注入生成模型，评价回答污染与帮助程度。
5. 在不同位置加入防护：
   - **M1：元数据过滤／用户分区**；
   - **M2：所有权感知嵌入代理**，包括用户身份前缀与用户向量偏移；
   - **M3：检索后门控**，包括硬性所有权校验与相似度阈值式“可疑内容”过滤。

其中 M3 的硬门控直接删除所有者不匹配的候选，不依赖模型理解或相似度判断。

## 6. 主要结论与发现

### 共享检索存在明显的偶发泄漏
- 同团队共享检索：
  - TF-IDF：**100%**；
  - MiniLM：**70%**，95% 区间约为 **40%–89%**。
- 用户分区检索在这批样本中为 **0% 观察泄漏**，但这不等于对所有部署证明零风险。
- MiniLM 下，同部门和跨部门条件均为 90%，跨公司为 10%。
- 70% 与 90% 的置信区间明显重叠，不能据此确定细粒度风险排序；组织距离和全局质心相似度不足以作为可靠的精细风险代理。

### 主动构造显著提高召回
- 语义桥接记忆在三类攻击场景中达到 **90%–100% top-k 命中率**。
- MiniLM 下平均得分提升为 **+0.416 至 +0.511**。
- 薪酬场景的命中率依次为：
  **普通记忆 10% → 领域关键词 40% → 查询关键词 80% → 语义桥接 90% → 逐字复制 100%**。
- 结果支持：仅掌握目标业务领域和角色，也可能获得较高攻击收益。

### 泄漏可能产生“有帮助但不安全”的回答
- 所有干净条件的污染基线均为 1.00／5。
- 检索后生成条件：
  - Gemini：污染 **5.00／5**，帮助程度 **5.00／5**；
  - Claude：污染 **4.67／5**，帮助程度 **2.67／5**。
- 静态注入的污染分别为 2.67 和 4.67。
- 因而回答质量监控不能替代隐私监控；但“污染同时提高帮助程度”并非所有模型和路径都成立。

### 硬授权边界最可靠
- 严格用户过滤在正确限定范围时同样有效；查询措辞不能绕过分区。
- 当检索范围明确包含攻击者时，范围过滤不再保证个人隐私边界。
- 身份前缀只部分降低泄漏；向量偏移反而恶化结果。
- 可疑度门控仍允许 30%–40% 的攻击命中。
- 硬所有权门控使攻击命中降至 0%，并在两种模型、两条记忆路径中把污染恢复至 **1.00／5**。

### 未展示可靠的隐蔽通信信道
- 8 位顺序传输中，前两位误码率为 0%，第 3–4 位为 50%，第 5–8 位为 100%。
- 单条恶意记忆可以高概率召回，不代表可以稳定传输多位信息；本文没有证明可控吞吐量的隐蔽信道。

## 7. 优点

- **问题定位明确**：将个人智能体记忆安全从单用户扩展到跨用户授权边界。
- **区分相关性与授权**：避免把检索准确率或回答帮助程度误当作安全保证。
- **评估链条完整**：从召回、主动利用到回答污染，再到防护与延迟成本。
- **基线较全面**：包含严格分区、不同攻击知识水平及逐字复制上界。
- **考虑模型与路径差异**：两种生成模型、静态／实际检索路径提供了更细致的比较。
- **透明报告不确定性与失败**：承认小样本限制，公开无效向量偏移及隐蔽信道失败结果。
- **防护易理解、可验证**：硬门控是确定性的工程措施，不依赖模型自行判断权限。

## 8. 不足与局限

### 实验覆盖与统计限制
- 手工合成数据规模小，真实性、代表性和语言多样性未经验证。
- 缺少真实企业环境、大规模用户和长期运行测试。
- 嵌入模型规模测试只覆盖同团队场景，不能推出所有大模型都不会降低泄漏。
- 没有系统考察不同 top-k、索引规模、候选过采样比例和记忆更新策略。

### 评分与结论偏差
- 生成模型同时作为评分模型，存在自评偏差。
- 人工试验样本很少且由作者标注，独立性有限。
- 作者根据一个明显低估披露的案例，将污染评分称为“保守下界”；**这一解释不能视为经过统计证明的下界**。

### 应用边界
- 硬所有权门控适合私人记忆，但会删除合法共享信息，不能直接解决协作系统的全部权限需求。
- 更一般的生产防护应校验“当前用户是否被授权在当前任务中使用这条记忆”，而不仅是所有者是否相同。
- 过滤 top-k 后可能留下过少或质量不足的候选；文中采用过采样缓解，但没有完整评价召回率和补取成本。
- 元数据过滤在正确实施时本身有效，因此不能把结果概括为“所有元数据过滤都不可靠”；关键问题是授权范围与使用权限不匹配。
- 多数效果实验并非真实数据库服务，单一配置下的 1.4 ms 增量不能外推到高并发、分布式或超大索引。

### 总体评价
- 本文有力展示了一个重要的系统安全失效机制，但属于**小规模、受控的概念验证**。
- 最可靠的工程结论是：**共享记忆系统应在记忆进入生成上下文前实施确定性的授权校验，而不能指望语义相似度、身份前缀或模型判断承担权限隔离责任。**
