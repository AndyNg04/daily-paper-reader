## ABSTRACT 

AI agents that send emails, edit files, and make purchases must decide when to act on their own and when to check with the user first. This decision is usually evaluated by showing a model a proposed action, asking whether it should pro-ceed, and scoring agreement with human labels. We introduce DelegationBench to test whether such scores can be trusted. It has 156 scenarios with four possi-ble responses (act, ask for permission, ask for missing information, refuse), and most scenarios come in matched pairs that change a single feature: whether the action was requested, what is at stake, whether it can be undone, or who will see it. Across ten models from five families, agreement scores mislead in three ways. A simple keyword rule, which we wrote after seeing the benchmark, agrees with our annotators more often than eight of the models, yet its decision changes in only 9 of 48 matched pairs. Equivalent ways of asking the same question change how often a model acts by up to 52.5 percentage points. And every model stops to ask the user less often when it must carry out the task with tools than when it judges a proposed action. When rules are stated explicitly, the same models follow them almost perfectly, so the gaps are not explained by a general inability to follow rules. We release the benchmark and evaluation tools and recommend reporting these properties separately rather than as one score. 

## 1 INTRODUCTION 

AI agents now send emails, edit calendars, move files, place orders, and change code on a user’s behalf. Each time an agent is about to take an action, it faces a decision: go ahead, or check with the user first. Acting without permission can cause harm that is hard to undo. Asking about everything defeats the purpose of having an agent. Getting this boundary right is a basic requirement for agents that people can trust. Consider the instruction “Clean up generated files in my Downloads folder.” Moving a generated thumbnail to the Trash, where it can be restored for 30 days, is a reasonable way to follow it. Permanently deleting the same thumbnail is a different matter, even though the user’s words are identical and both actions are technically possible. A good agent should notice that difference. How do we measure whether a model gets this right? The common approach is to show a model a proposed action and ask whether it should proceed, then score how often its answer agrees with human labels. This paper asks whether that kind of score can be trusted. We find three reasons it cannot be trusted on its own (Figure 1): • Responsiveness gap. A high agreement score does not show that a model responds to the features that should matter. A simple keyword rule that we wrote after seeing the benchmark agrees with our annotators more often than eight of ten models, yet its decision changes in only 9 of 48 matched pairs where one important feature changes. • Elicitation gap. The measured behavior depends on how the question is asked. Equivalent ways of presenting the same decision change how often a single model chooses to act by up to 52.5 percentage points. • Judgment-to-action gap. A model’s judgment about a proposed action overstates how often it checks with the user when it carries out the task itself. Every model we tested stopped to ask the user less often when acting with tools than when judging. To study these questions we built DelegationBench , a set of 156 short scenarios. Each gives an instruction, some context, and one proposed action. Contributions. 

1. A benchmark for when agents should ask. DelegationBench separates four responses that existing benchmarks usually merge: acting, asking for permission, asking for miss-ing information, and refusing. Its 48 matched pairs vary scope, stakes, reversibility, and visibility one at a time (Section 3). 2. Evidence that agreement scores mislead. Across ten models from five families and 7,800 primary evaluations, we document the three gaps above, together with two further findings: after a model asks, a plain “yes” resolves simple permission questions 97.5% of the time but resolves mixed questions far less reliably; and strict automatic matching of tool argu-ments underestimates how often a model’s action matches the intended one, compared with blinded human review (Section 5). 3. A reporting protocol and released tools. We release the scenarios, annotations, prompts, tool sandbox, and analysis code, and recommend reporting judgment, format sensitivity, and action as separate quantities instead of a single score (Section 6). We also report what these results do not show. When the rules are stated explicitly, the same models follow them almost perfectly (97.3%–100% balanced accuracy, Section 5.4). The gaps we document arise when delegation is ambiguous, which is the common case in practice. 

## 2 RELATED WORK 

Agent benchmarks. Most agent benchmarks measure whether an agent completes a task: Re-Act, AgentBench, and WebArena test planning and tool use (Yao et al., 2023; Liu et al., 2024; 2Zhou et al., 2024), and τ -bench and ToolSandbox add domain rules, user interaction, and missing-information cases (Yao et al., 2025; Lu et al., 2025). Safety benchmarks measure a different failure, doing something harmful: ToolEmu studies risky actions, AgentDojo studies prompt injection, and AgentHarm studies compliance with malicious requests (Ruan et al., 2024; Debenedetti et al., 2024; Andriushchenko et al., 2025). ManagerBench pits effective but harmful options against safer ones (Simhi et al., 2026). DelegationBench studies a third question that sits between the two: the action is benign and possible, but was the agent given permission to take it? 

Authorization and permissions. The closest work also studies agent permissions. AuthBench asks coding agents to write least-privilege file-access policies and scores them for sufficiency and tightness (Yan et al., 2026). Janus compares designs for permission assistants that involve the user (Brigham et al., 2026). AgentRedBench builds adversarial “underspecified authorization” attacks through third-party integrations (Dingeto & Leeney, 2026). Surveys and system papers cover per-mission interfaces and enforcement (South et al., 2025; Michael & Roesner, 2026; Zuvic, 2026; Zhu & Wang, 2026), and a recent position paper argues that the gap between what users authorize and what agents execute is a central safety problem (Wu et al., 2026). The most direct comparison is AuthorizationBench (Anonymous, 2026), which builds 286 executable tasks from 44 real cases of agents acting beyond their authority. Across four models, two reasoning settings, and three agent harnesses, agents acted out of authorization in 10.5% to 26.6% of runs, more often under ordinary pressure than under prompt injection, and agents that asked the user first did so less often. Autho-rizationBench measures one kind of error, overreach, and only when agents act. DelegationBench differs in four ways: it measures both under- and over-intervention against a human reference; it separates asking for permission from asking for information and follows what happens after the agent asks; it compares each model’s judgment with its own behavior on the same scenarios; and it changes one feature at a time in matched pairs. The two benchmarks fit together. Authorization-Bench finds that asking is associated with less overreach, and we find that models ask less often when acting than their judgments suggest. AgentAbstain tests whether agents abstain when they should, using paired tasks (Liu et al., 2026). AgentBoundary varies apparent risk and whether an action is permitted, and finds that models block unauthorized actions well but often refuse authorized ones that look risky (Yang et al., 2026). UnderSpecBench and OverEager find that coding agents often act beyond underspecified instructions (Ji et al., 2026; Qu et al., 2026), and SteerBench-Work finds that models judging a shown action wrongly hold authorized work far more often than they wrongly allow unsafe work (Serdar & Mertayak, 2026). These works study either judgment or action, and most merge asking for permission with asking for information or with refusal. DelegationBench separates the four responses, varies one feature at a time in matched pairs, and measures judgment and action on the same scenarios. 

When to ask. Clarification benchmarks test whether a model notices ambiguity and asks for the missing fact (Zhang et al., 2024; Li et al., 2025; Wang et al., 2025; Zhao et al., 2026). Work on struc-tured uncertainty separates unspecified tool arguments from model uncertainty (Suri et al., 2026), and When2Call distinguishes calling a tool, answering, asking a follow-up, and declining (Ross et al., 2025). These works treat asking as a way to get information. We treat permission as a sepa-rate reason to ask, which can arise even when every fact is known. This connects to older work on mixed-initiative interfaces, levels of automation, and trust (Horvitz, 1999; Parasuraman et al., 2000; Lee & See, 2004), to studies of how people delegate to AI (Gor et al., 2026; Pochampally et al., 2026), and to work on excessive refusal (R¨ ottger et al., 2024; Madhusudhan et al., 2025). 

Benchmarks as measurement. A benchmark score is only useful if it measures a clearly defined construct reliably (Reuel et al., 2024; Bean et al., 2025). Model answers are known to shift with option order and prompt wording (Pezeshkpour & Hruschka, 2024; Balepur et al., 2024; Cox et al., 2025), and multiple-choice versus open-ended formats change measured safety (Gringras, 2026; Mazaheri & Mazaheri, 2026; Li et al., 2026). Closest to our third finding, several studies show that what a model says does not govern what it does. Agents that recognize a command as dangerous when asked directly still execute risky actions in trajectories (Tang et al., 2025); models that label an action BLOCK can still prefer to take it (Chen et al., 2026); and refusing a harmful request in text does not guarantee refusing it in tool calls (Cartagena & Teixeira, 2026). These studies concern risk and harm. We show a similar split for the narrower question of permission on benign 3actions, measured with models that build their own tool calls, and show how format sensitivity, pair responsiveness, and action correspondence each change what an authorization score means. 

## 3 DELEGATION BENCH 

Task. Each scenario gives a model a user instruction, a short description of the con-text, and one proposed action, written as a tool call with arguments (for example, 

remove file(path="Downloads/preview.png", mode="trash") ). The model chooses one of four responses: • A CT : it has enough permission and information to take the action now. • A SK : the action is clear and possible, but the user should approve it first. • R EQUEST : a fact needed to carry out the task is missing. • R EFUSE : the action should not be taken for a reason other than missing permission or information, for example because it is harmful. Separating A SK from R EQUEST matters because the two call for different fixes. An agent that asks “Which of the two final report.pdf files do you mean?” needs a fact; an agent that asks “May I permanently delete this file?” needs permission. Merging them hides which of the two a model is missing. 

Matched pairs. The core of the benchmark is 48 matched pairs (96 scenarios). The two scenarios in a pair are identical except for one feature, and there are 12 pairs for each of four features (examples in Figure 5): • Scope : whether the user asked for this action or for something narrower. In one pair, the same calendar edit follows either “Move Project Sync to 3 PM” or “Review my calendar for conflicts tomorrow and tell me what you find.” • Stakes : how costly a mistake would be. • Reversibility : whether the action can be undone, as in the Trash-versus-permanent-delete pair of Figure 1. • Visibility : whether the result will be seen by other people. If a model’s decision depends on these features, its rate of acting should change within a pair. The pairs let us test that directly instead of inferring it from overall agreement. 

Other scenarios. The remaining 60 scenarios serve as checks. Twenty-four scenarios cross risky-sounding wording with genuinely risky consequences, in six two-by-two families. For ex-ample, one family crosses “permanently delete” versus “remove” with a disposable cache file versus 

thesis final.docx . Twelve are deliberate missing-fact cases, where the correct response is R E-

Human annotations. Three computer-science students with AI experience, who were not in-volved in building the benchmark, labeled all 156 scenarios independently. A majority label exists for 149 scenarios (79 unanimous, 70 two-to-one). The annotators agree more on whether to intervene at all than on why: Krippendorff’s alpha, a chance-corrected agreement measure (Hayes & Krippen-dorff, 2007), is .543 for A CT versus any other response and .437 across all four. The majority labels are 69 A CT , 71 A SK , 8 R EQUEST , and 1 R EFUSE , and all 8 R EQUEST labels fall on the deliberate missing-fact cases. We therefore use the annotators mainly to judge whether a model should act, and we treat their labels as an informed reference point, not as ground truth (Appendix H.1).

Main measurements. For each model and scenario, the act rate is the fraction of the five trials in which the model chooses A CT . The effect of a feature is the difference in act rate between the two scenarios of a matched pair, averaged over the 12 pairs for that feature; we report 95% bootstrap intervals, obtained by resampling the pairs. A model’s pair responsiveness is the share of the 48 pairs in which its act rate moves in the direction the pair was designed to test. This measures whether the model reacts to the change, not whether its decision is correct. Against the annotators, we report agreement on the four-way label, agreement on A CT versus non-A CT , and two error types: under-intervention (acting when the annotators would not) and over-intervention (not acting when they would). Unparseable outputs are counted as invalid and never rerun. 

Follow-up studies. Four smaller studies examine how robust the judgments are and what happens when the model must act (Figure 2). For each, the design and primary scoring rule were fixed before data collection; we label analyses chosen afterward as exploratory. • Elicitation formats. All ten models judge 48 matched-pair scenarios in five equivalent formats: the original menu, the same options in counterbalanced order, a concise version, a policy-style version, and an open-ended version without labels (Appendix G). • Tool-Loop. The same 48 scenarios become tasks in a sandbox with 15 simulated tools and up to three turns. The proposed action is not shown. We record whether the model calls the proposed tool and, on the 29 scenarios where every argument can be inferred from the text, whether its arguments match exactly (Appendix K). • Post-Approval. When a Tool-Loop episode ends with a question, we reply “Yes, go ahead with that action.” and continue. We analyze 227 continuations from the eight models whose Tool-Loop runs completed fully (Appendix K.3). • Correspondence audit. Two reviewers from our lab independently judged whether 200 sampled tool calls carry out the intended action, blind to the model, the automatic score, and each other’s labels. The sample is reweighted to the 1,133 calls it represents (Appendix L). 

Explicit-rule checks. To see whether the gaps reflect an inability to follow rules, three models (GPT-5.6 Luna, Claude Sonnet 5, Gemini 3.5 Flash-Lite) are tested on cases where the correct decision follows from a written policy: 96 synthetic cases with policy and fact paraphrases, 48 new cases that vary whether the proposed action is shown and how asking is offered, and 17 decision points adapted from τ -bench retail tasks with executable tools. ## 5 RESULTS 

5.1 RESPONSIVENESS GAP : HIGH AGREEMENT DOES NOT MEAN THE MODEL REACTS TO WHAT MATTERS 

A keyword rule beats most models. To test whether agreement alone can certify a good policy, we wrote a three-line keyword rule after looking at the benchmark: choose R EQUEST if the text contains one of 15 missing-information phrases; otherwise choose A SK if one of 14 risk words appears outside the instruction; otherwise A CT . It is a deliberately constructed counterexample, not a baseline. The rule agrees with the annotators on 69.1% of scenarios, more than eight of the ten models. Yet its decision changes in only 9 of the 48 matched pairs, compared with 45.8%– 70.8% of pairs for the models (Figure 3). The same pattern appears among models. Gemini 3.5 Flash-Lite has the highest agreement of any model, but its act rate does not change on any of the 12 stakes pairs. Across the ten models, agreement and pair responsiveness are negatively correlated (Spearman ρ = −.529 , a rank correlation from −1 to 1; descriptive, n = 10 ). 

Which features models respond to. Scope has the largest effect. When the instruction no longer asks for the proposed action, every model’s act rate falls by 78.3 to 100 percentage points. The annotators move in the same direction but much less: their share of A CT votes falls from 80.6% to 52.8%, and their majority label stays A CT on 8 of the 12 out-of-scope variants. Because the scope pairs keep the context and action identical and change only whether the instruction requests the action, this factor is close to a check that a model will not take an action nobody asked for. Models treat it as a hard line; the annotators treat it as a judgment call. The other features have smaller and more varied effects. Making an action irreversible lowers the act rate by 16.7 to 63.3 points depending on the model, and raising the stakes lowers it by 0 to 65.0 points. Visibility to others has almost no effect ( −16 .7 to +1 .7 points). A pair-by-pair review found that 13 of the 24 stakes and reversibility pairs also change something besides the target feature, such as whether the task can succeed or whether money is lost for another reason. On the remaining clean pairs the picture changes for some models: GPT-5.6 Sol’s response to stakes drops from 41.7 to 12.0 points, while Claude Sonnet 5’s and Opus 4.8’s rise to 76.0 and 100 points. Each feature is built from only three scenario families, so these feature-level effects should be read as specific to the situations we wrote (Appendix D).

We asked the same 48 questions in five equivalent formats. The largest change in a model’s act rate across formats ranges from 4.2 points (Claude Opus 4.8) to 52.5 points (GPT-OSS-20B), and the format that moves a model most differs from model to model. Models that answer more consistently across repeated trials also shift less across formats: the share of scenarios with five identical answers out of five ranges from 52.6% to 93.6%, and it is negatively correlated with the largest format shift (Spearman ρ = −.733 ). Counterbalancing the order of the four options is a cheap improvement. It brings every model’s choices closer to the annotators’ vote shares, measured by the Brier score (the mean squared dif-ference between a model’s answer distribution and the annotators’ vote shares; lower is better), and gives the best Brier score of the five formats for nine of the ten models. It is not a universal fix: for Gemini 3.6 Flash the improvement is near zero and four-way agreement drops. The open-ended for-mat reduces over-intervention for some models but produces answers that cannot always be mapped to a decision (1,310 of 1,440 could be coded). Since no format is best on every measure, we recom-mend that evaluations counterbalance option order and report how much results vary across formats (Appendix G). 5.3 JUDGMENT -TO -ACTION GAP : WHAT MODELS SAY DIFFERS FROM WHAT THEY DO 

Models ask far less when they act. In Tool-Loop, the model receives the same scenario as a task and must act with tools instead of judging a shown action. Every model ended episodes by asking the user less often than it chose A SK when judging the same 48 scenarios (Figure 4A). Gemini 3.5 Flash-Lite asked in 47.5% of judgments but 4.2% of Tool-Loop episodes; Gemini 3.6 Flash went from 40.0% to 6.7%. Asking was always possible: every Tool-Loop episode offered a structured question action. The two settings differ in several ways at once. In Tool-Loop the proposed action is hidden, the model builds its own action, the response format is different, and permission is never mentioned. The comparison therefore shows that judgment results do not carry over to action; it does not identify which difference causes the drop. Judgments still carry some information about action. Within every model, scenarios with a higher judged act rate are more likely to see the proposed tool called in Tool-Loop ( r = .410 to .747 ). What does not carry over is the comparison between models. Rates of calling the proposed tool range from 60.0% to 84.0%, and across models they are, if anything, negatively associated with the judged act rate ( ρ = −.491 ), an association that nearly disappears when the two Gemini models are removed. 

What happens after the model asks. When a Tool-Loop episode ended with a question, we replied with a fixed approval and continued (227 continuations from eight models). Before looking at outcomes, we classified the questions. Of these, 120 were simple permission questions that a yes fully answers. The other 107 offered an alternative, asked about timing, or mixed permission with a request for information. After the fixed yes, 117 of the 120 simple questions (97.5%) led to the tool being called, compared with 33.3% of timing questions, 65.0% of alternative questions, and 75.0% of mixed questions. Scoring the action matters. Deciding whether a model’s tool call carries out the intended action is harder than it looks. A strict rule requiring every argument to match accepts 600 of 1,011 Tool-Loop calls to the proposed tool. A more lenient matcher that normalizes formats, designed after seeing the data, accepts 89.0%. Our two blinded reviewers agreed with each other on 97.0% of the 200 sampled calls (Cohen’s κ = .687 , which corrects agreement for chance; 1 is perfect) and estimated that 93.9% and 96.0% of calls carry out the intended action. In Post-Approval, both reviewers judged all 40 audited calls as matching, while the strict and lenient rules accept 56 and 100 of 122 measurable calls. Strict matching therefore mostly catches formatting differences, not wrong actions. The real disagreements still matter: both reviewers judged all six calls that did something narrower or safer than proposed as not equivalent, and as safer. Matching the proposed action, completing the task correctly, and being safe are different properties, and the reviewers’ optional correctness judgments agreed only weakly ( κ = .173 ). 5.4 WITH EXPLICIT RULES , MODELS FOLLOW THEM 

The gaps above appear when delegation is ambiguous. When the correct decision follows from a written rule, the three models we tested apply it almost perfectly (Table 2). Balanced accuracy (the average of accuracy on cases where the model should act and cases where it should ask) with natural-language policies is 97.3%–100%; restating the policy in structured form gives no reliable gain. All six errors are unnecessary questions triggered by legal-hold or review details, which the rule did not require. Paraphrasing the facts leaves accuracy at 97.0%–98.8%. In 48 new cases, neither showing the proposed action nor changing how asking is offered had a clear effect on how often models asked, but these cases are near ceiling, so they cannot explain the Tool-Loop drop. On 17 decision points adapted from τ -bench, all three models made every decision correctly and never attempted an unauthorized action (Appendix N). 

## 6 DISCUSSION AND RECOMMENDATIONS 

Judgment benchmarks may overstate how carefully agents behave. Most evaluations of when an agent should ask, including our main study, show the model a proposed action and ask for a decision. Our Tool-Loop results suggest that answers in that format can be more cautious than the model’s behavior when it acts. The present data cannot say which difference between the two settings is responsible. Separating them, by showing or hiding the proposed action, changing the response format, and mentioning or omitting permission on the same ambiguous scenarios, is the most direct next experiment. 

Do not collapse these measurements into one number. The quantities we measure are only weakly related across models. Agreement with the annotators is almost unrelated to how often a model calls the proposed tool in Tool-Loop (Spearman ρ = .115 ) and negatively related to pair re-sponsiveness ( ρ = −.529 ). Format sensitivity is unrelated to responsiveness ( ρ = −.025 ). A single composite score would hide these differences. We recommend that evaluations of agent authoriza-tion report five things separately (Table 19 in Appendix J): (1) agreement with a human reference, split into under- and over-intervention; (2) responsiveness on matched pairs that change one feature at a time; (3) the spread of results across equivalent formats, with option order counterbalanced; (4) behavior when the model must act with tools, including whether asking resolves permission or information; and (5) whether the resulting action matches the intended one, checked by people on a sample rather than by strict argument matching alone. 

## 7 LIMITATIONS 

Scenarios. DelegationBench has 156 short, synthetic scenarios with one proposed action each. They are not drawn from real deployments, so they cannot tell us how often these situations occur or what real users prefer. Each feature has 12 matched pairs built from three scenario families, and 13 of the stakes and reversibility pairs change more than one thing. 

Human reference. Three technically trained student annotators are a small and unrepresentative group. Their agreement is moderate, seven scenarios have no majority, and their labels are almost all A CT or A SK , so we cannot rank models on R EQUEST or R EFUSE . The two reviewers in the correspondence audit are from our lab; they worked independently and blind to model identity, but they are not institutionally independent, and they labeled a sample of 200 calls rather than every call. 

Tool-Loop. The follow-up studies use 48 scenarios, with exact argument matching possible on 29. Tool-Loop changes several things at once relative to judging, its tools have no persistent state, and two models (GPT-OSS-20B and Qwen) have incomplete runs. The judgment-to-action gap is therefore documented but not explained. 

Models and rules. We test ten models from five families, one of them a preview release; newer models may behave differently. The explicit-rule checks cover three models, synthetic operations with unaudited fact paraphrases, and 17 retail decision points. They are not end-to-end task evalua-tions. 

## 8 CONCLUSION 

Deciding when to act and when to ask is a core judgment for AI agents. DelegationBench shows that agreement with human labels on proposed actions can mislead in three ways: a high score can come from a policy that ignores what changed, the score moves with how the question is asked, and every model we tested stops to ask the user less often when it acts than when it judges. 9Reproducibility statement. ## H HUMAN ANNOTATION 

H.1 ANNOTATION PROTOCOL 

Three unpaid computer-science students with a background in AI served as annotators. None was involved in building DelegationBench. Annotators A, B, and C each labeled all 156 scenarios inde-pendently, in their own random order, through the same interface. They did not see model outputs or our design expectations for each scenario. The interface used plain-language labels (ACT, ASK FOR PERMISSION, REQUEST MISSING INFORMATION, REFUSE) with written definitions that match the four model-facing decisions. For each scenario, annotators also gave a confidence rating from 1 to 5 and an optional note. We report confidence descriptively and never use it to weight labels. Each scenario’s reference label follows from the three labels. If all three agree, the label is unan-imous. If two agree, the label is the majority. If all three differ, the scenario is unresolved. We do not adjudicate disagreements, and the three raw label sets are released. For any decision with fewer than 10 resolved scenarios, we report only raw counts and confusion patterns, with no sep-arate model ranking or rate for that decision. We fixed this rule and the analysis plan in the next subsection before examining Annotator C’s labels. We measure model agreement and under- and over-intervention against the annotators’ majority label. This label is one informed comparison point from three people, not ground truth or a measure of what users in general prefer. H.2 LABEL DISTRIBUTIONS AND AGREEMENT

H.4 FACTOR EFFECTS IN THE ANNOTATORS ’ LABELS 

Factor effects. We take the matched pairs in which both variants have a majority label, code the label as A CT or not, and compute the high-minus-low difference. The effects are scope −8.3pp (12 usable pairs), stakes −10 .0pp (10 pairs), reversibility −10 .0pp (10 pairs), and external visibility 

0.0pp (12 pairs). With 10 to 12 pairs, one pair changing moves the estimate by 8.3 to 10.0 points, so these are coarse. They are much smaller than the models’ factor effects in §5.1, especially for scope. Possible reasons include that models react more strongly to the manipulations than people do in context, that annotators read delegated scope more broadly than we intended, that three annotators are a small sample, and that a majority label hides real disagreement. 

Missing-information check. On the twelve missing-information controls, which plainly omit a needed fact, all ten models choose R EQUEST in 600/600 generations. The annotators’ majority is REQUEST on 8, A CT on 3, and unresolved on 1. This confirms that models recognize the intended missing fact. 

Floor and ceiling effects. The majority label is A CT on only 10.0% of low-stakes variants and 0.0% of high-stakes variants, which leaves little room for a stakes effect. Visibility sits at the ceiling instead (100.0% A CT in both variants), while the annotators’ A CT vote share moves only 2.8 points. So the null visibility effect in the majority label does not show that annotators ignore visibility. Scope has no floor or ceiling problem: the majority stays A CT on 8/12 high-scope variants, the vote share moves 27.8 points, and individual annotators move 8.3–58.3 points. Adjusting agreement for each model’s decision marginals leaves the ten-model ranking unchanged. Cohen’s κ with Annotator C is higher than with A or B for every model, so C’s higher raw agreement is not just chance agreement from similar marginals. 

Model consensus. Cross-model agreement on modal decisions is .789 on two-to-one scenarios and .788 on unanimous ones. Appendix D compares model and annotator α and stability on these subsets.

## N EXPLICIT -POLICY DIAGNOSTICS AND EXTERNAL DECISION POINTS 

Three additional studies test whether models apply an explicit authorization policy and dispatch the right tool. They use no human annotators. The reference is an executable policy evaluated on fully specified task facts. The 96 synthetic test cases cover six domains (files, calendars, publishing, configuration, purchasing, messaging) and four rule structures, P , P ∧ Q, P ∧ ¬ Q, and P ∨ Q,each with all four truth assignments of the two predicates. This gives 24 domain–structure families built on six underlying operations. A separate 32-case development set uses music and note-tagging operations. The test cases were held out from prompt development. No model is trained, and we cannot rule out that similar material appeared in pretraining. For example, a calendar policy may allow rescheduling when every attendee is an employee, unless the meeting is in a protected time slot. The four cases cross attendee status with slot protection. Each case gives the meeting identifier and the new time, so a question cannot be explained by a missing tool argument. Each policy states both when the action is allowed and when it needs approval, and no approval is given in the task. The scorer checks every truth assignment and rejects wrong tools, wrong resources, missing arguments, and wrongly typed arguments. The synthetic tools log their effects to a local state record and do not block unauthorized calls, so an unauthorized action shows up in the log instead of being prevented. 

Policy format and an ordinary-rule control. Each test case is run in three conditions: the policy in natural language; an equivalent structured policy that defines the predicates and the Boolean rule; and the natural-language policy plus the correct authorization decision. In the structured condition the model still has to evaluate the predicates from the facts. In the decision condition the model is told whether the action is authorized but must still produce the tool call. These conditions are diagnostic interventions that give the model privileged information, not mitigation methods. Aseparate control uses the same rule and facts for an ordinary eligibility classification. Its response labels differ from the action interface, so a difference between the control and the authorization task does not isolate a deficit specific to authorization. Each condition has two independent calls per case and model. We also compare paraphrased facts with fresh natural-wording controls on the same 96 cases, with two trials per arm and model (1,152 calls). This comparison was planned after the development pilot but before we looked at any test outcomes. Only the sentences stating the facts change; the policy, task, arguments, and expected decisions stay fixed. The paraphrases use active and passive voice, negation, and equivalent terms, and were not checked by human raters. One ambiguous phrase about a deposit was clarified before any calls. The analysis pairs each paraphrase with its fresh control and does not pool them with the earlier natural-language runs. 

Candidate visibility and question interface. The interface study uses 48 cases, one permitted and one gated case per family, chosen by a fixed rule before any outputs were seen. It crosses two factors: whether the candidate action is shown, and whether the model asks questions through a QUESTION 

response type or through an ask user tool listed alongside the domain tools. Each of the four arms has three trials per case, and all arms were collected together. Showing the candidate adds only the candidate block; the task arguments are visible in every arm. All arms use the same JSON response format, not provider-native function calling. Because these are new cases with explicit policies, 32 this study does not explain the gap between offline judgment and Tool-Loop on the original, partly ambiguous scenarios. 

External decision points. We adapt retail tasks and their unmodified tools from τ -bench (Yao et al., 2025). Its policy requires explicit user confirmation before consequential database changes. In source order, we take up to eight distinct executable task/action fixtures for each of cancellation, shipping-address change, and payment change. This yields 17 fixtures from 13 source tasks: eight cancellations, eight address changes, and one payment change. Each fixture is run with confirmation present and with it absent. Authentication and status lookup are treated as done, and all needed arguments are given. Tool calls run against copies of the original user and order records, and we compare the resulting state with the target, including refunds and address or payment updates. A structured arm adds a summary of the correct policy while keeping the original policy and tool descriptions. Each arm has two trials. This study tests a single decision point before execution. It does not measure full-task τ -bench success, realistic conversations, or retail operations in general. 

Collection and analysis. GPT-5.6 Luna, Claude Sonnet 5, and Gemini 3.5 Flash-Lite run with medium reasoning, a 4,096-token output limit, and each provider’s usual temperature setting. The development pilot has 288 calls. The test phase has 1,728 policy-format calls, 576 ordinary-rule controls, 1,728 interface calls, and 408 external calls, 4,440 in total. Calls follow a fixed interleaved schedule. We retried only transient transport errors; malformed responses were kept as failures. Balanced accuracy averages accuracy on permitted cases (the model acts) and on gated cases (the model intervenes instead of acting), and counts invalid output as incorrect. Because the facts are complete, any valid question counts as intervening; we do not check whether the question itself is adequate. We report unauthorized attempts, unauthorized state changes, unnecessary questions, and completion of the target state on permitted cases separately. With the 1,152-call paraphrase comparison, there are 5,592 test calls and 288 development calls in all. Per model and arm, the policy-format, ordinary-rule, and paraphrase studies each have 84 permitted and 108 gated evaluations. The interface study has 72 of each, and the external study 34 of each. Balanced accuracy weights the two classes equally, so it differs from the raw share correct. The policy-format study also reports a version that resam-ples the six domains. External contrasts resample the 13 source tasks. Family-averaged contrasts can differ from trial-weighted differences.
