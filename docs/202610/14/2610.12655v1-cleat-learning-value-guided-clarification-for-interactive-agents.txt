LLM agents can execute increasingly complex tasks, but effective assistance also requires aligning their actions with goals and constraints that users may leave unstated. We study this problem as interactive intent alignment through clarification. Yet clarification is useful only when the agent can turn the answer into better decisions. As training changes how the agent handles incomplete information and uses additional answers, the same clarification can become more or less useful. We introduce CLEAT (CL arification through valu E-guided Agent co-Training), a framework that co-trains a clarification-value controller and the task policy from shared interaction outcomes. We formulate residual query value to measure the task utility gained by asking rather than proceeding under the current policy, and estimate it through paired rollouts from the same interaction history. These paired returns train the controller to predict clarification value and the task policy to select useful questions and act on the answers. The controller guides subsequent rollout collection, while outcomes from the updated agent provide new value labels that allow clarification guidance to adapt as the agent learns. With Qwen3-4B, CLEAT achieves the highest mean score in all ten evaluation settings across four benchmarks. Gains over the strongest baseline reach 13.2 and 6.5 percentage points on UserGym Travel and IN3 underspecification judgment accuracy, respectively. Ablations show that co-training improves the task policy even when the controller is removed at inference, while adapting clarification guidance to the evolving policy yields further gains. 

# 1 Introduction 

Large language model (LLM) agents have made rapid progress in planning and tool use, enabling them to carry out increasingly complex tasks (Zhou et al., 2024; Yang et al., 2024; Li et al., 2026). However, stronger execution alone does not ensure that an agent’s actions reflect what the user actually wants. In practice, users may leave important constraints unstated, rely on mistaken assumptions, or struggle to articulate their preferences (Qian et al., 2024; Vijayvargiya et al., 2026), creating a gap between their explicit requests and intended goals. Effective assistance therefore requires agents to help close this gap through interaction, rather than expect users to specify everything upfront. We study this problem as interactive intent alignment ,where agents align their task decisions with the user’s intended goals and constraints through interaction. Clarification can support this alignment by resolving uncertainty about the user’s goals and constraints. 1

Yet clarification can reveal more about the user without improving the agent’s decisions, while still requiring the user’s time and attention. For example, suppose an agent must choose between two flights operated by the same airline but arriving at different times. Asking about airline preference may reveal more about the user, but it does not help distinguish between the two options. By contrast, asking about an unstated arrival deadline can determine which flight meets the user’s needs (Figure 1). The challenge is therefore to recognize when clarification can improve the task outcome and what information the agent needs to obtain.

Prior work guides clarification through information-based signals (Deng et al., 2026; Kong et al., 2026), value-of-information estimates (Rao & Daumé III, 2018; Dong et al., 2026), and rewards from subsequent interaction out-comes (Zhang et al., 2025; Wu et al., 2025). Despite this progress, identifying which clarifications help the agent remains challenging, particularly while its policy is being trained. First, a clarification can appear useful without ac-tually improving the task outcome. A question may reveal additional information or be followed by a successful out-come, yet the same agent might have achieved an equally good result by proceeding on its own. Second, clarification value can change even at a fixed interaction history. Train-ing can improve how the agent uses an answer and how it proceeds on its own by different amounts. The incremental value of the same clarification can therefore change as the policy learns, requiring renewed value supervision. To address these challenges, we introduce CLEAT, which couples clarification-value learning with task-policy learning through paired interaction outcomes. For each evaluated clarification target, paired rollouts compare asking with native continuation under the current policy from the same interaction history. Native continuation retains the agent’s own ability to ask, so the utility difference measures the added benefit of the targeted clarification. We call this difference the residual query value (RQV). The same outcomes provide controller value targets and policy advantages; for each target, the mean query advantage equals its RQV label. During training, controller predictions prioritize which comparisons to collect, while sampling-corrected policy updates use observed task returns. Fresh outcomes renew value supervision as the agent learns. At inference, the trained agent acts on clarification answers, while the controller guides when and what to ask using predicted RQV. We evaluate CLEAT on four benchmarks spanning personalized decision making, user-in-the-loop tool use, and requests with missing information or false premises. With Qwen3-4B as the backbone, CLEAT achieves the highest mean score in all ten evaluation settings. Gains over the strongest baseline reach 13.2 and 6.5 percentage points on UserGym Travel and IN3 underspecification judgment accuracy, respectively. Ablations show that the trained policy improves over the original backbone even without controller-based action selection at inference. Updating the controller during policy training also yields higher mean scores than freezing it in all six ablation settings. Our contributions are summarized as follows. • We construct paired policy-relative supervision from matched ask-versus-proceed outcomes, provid-ing controller value targets and task-policy advantages relative to the agent’s native continuation. • We develop value-guided co-training , in which predicted values guide rollout collection, observed returns drive sampling-corrected policy updates, and fresh outcomes renew value supervision as the agent learns. • We demonstrate gains beyond inference-time guidance , with ablations showing that co-training improves the task policy itself and that updating clarification values provides benefits beyond fixed guidance. 

# 2 Preliminaries 

## 2.1 Interactive Intent Alignment 

We consider interactive tasks in which the user’s initial request may not fully or accurately express the goals and constraints that determine success. For example, a travel assistant may need to establish whether the 2user prioritizes price or ticket flexibility, while a service agent may need to identify which reservation the user wants to change. Clarification can help resolve these gaps, but its purpose is to inform task decisions rather than serve as an objective in itself. Formally, let G denote the user’s latent goal and h the interaction history, which provides only partial information about G. The task policy πθ selects actions based on h and may ask for clarification when permitted by the environment, with replies added to h. We evaluate the resulting episode τ by its task utility U(τ, G), including any benchmark-specified interaction costs. To compare asking with proceeding, we consider their continuations from h, each comprising the remainder of an episode generated under πθ .During training, we assume access to an environment that can sample multiple continuations from the same 

h and G, with the policy held fixed within each comparison. 

## 2.2 Group-Relative Policy Optimization 

To train the task policy from these sampled outcomes, we build on Group Relative Policy Optimization (GRPO) (Shao et al., 2024). GRPO estimates advantages by normalizing returns within a group, without a learned critic. In our setting, consider n continuations sampled under the matched conditions above, yielding completed episodes τ1, . . . , τn with utilities Ui = U(τi, G). # 3 CLEAT 

CLEAT co-trains a task policy and a clarification-value controller from paired rollouts. At each training history, we compare asking about selected targets with letting the current policy continue on its own. The observed returns provide value labels for the controller and advantages for updating the task policy. The updated controller guides target selection in the next round, and new rollouts under the updated policy provide fresh value labels (Figure 2). 

## 3.1 Problem Setup and Residual Query Value 

At an interaction history h, we compare letting the task policy proceed ( PASS ) with first asking for additional information ( QUERY (z)). Here z identifies what information to request, such as a travel date or budget. Choosing PASS delegates the remaining interaction to the task policy, which retains its own ability to ask questions. A fixed target constructor supplies the finite candidate set Z(h). A history is clarification-eligible when another user exchange is permitted and this set is nonempty. For QUERY (z), a fixed question realizer turns the target into a question, and the question–answer exchange is appended to h before task execution resumes. This separates the decision of what to ask from question wording. For a fixed task policy π, let Vπ (h) denote the expected utility of choosing PASS and Qπ (h, z) that of choosing QUERY (z). Information gain, IG (h, z) = I(G; Yz | h), measures what an answer Yz reveals about the user’s goal. An informative answer need not improve the agent’s decisions, so IG and RQV can rank clarification targets differently. This reflects the classical distinction between information gain and decision value (Howard, 1966). RQV also depends on how the policy uses the answer. Ignoring it may leave utility unchanged, while misusing it can hurt even without interaction costs. Classical value of information evaluates an optimal decision maker; RQV evaluates the policy being trained. Training can improve answer use and native continuation by different amounts, changing RQV even for a fixed history and target. We therefore renew value supervision as the policy learns (Appendix A.1).

## 3.5 Online Co-Training and Inference 

Online co-training. We repeat collection and update both components to track how clarification value changes as the task policy learns. First, we bootstrap f0 on paired rollouts under π0, drawing targets from ¯pπ0 without value guidance. At step t, we hold both components fixed during collection. ft guides target selection, and πt generates the continuations. We then use the same batch to fit ft+1 to the paired value labels and update πt to πt+1 using the sampling-corrected policy update. Sharing the batch requires only one rollout phase for the two updates. It also introduces a one-update lag because ft+1 learns from outcomes under πt and then guides πt+1. After the final policy update, we hold 

πT fixed and collect fresh paired rollouts to refresh the controller with labels generated under the final task policy. Algorithm 1 summarizes the procedure, and Appendix A.5 discusses the supervision lag.

# 4 Experiments 

## 4.1 Experimental Setup 

Benchmarks. We evaluate on four benchmarks spanning ten settings. UserGym (Qian et al., 2025) com-prises Travel, Turtle, Intention, and Telepathy, with Intention and Telepathy held out from training. τ2-Bench (Barres et al., 2026) evaluates user–agent coordination and tool use in the Airline, Retail, and Telecom domains. IN3 (Qian et al., 2024) evaluates whether an agent recognizes underspecified instructions and recovers missing task requirements. AskBench (Zhao et al., 2026) distinguishes requests with missing information in AskMind from requests with false premises in AskOverconfidence. 

Baselines. We compare four groups of baselines. Prompting-based methods use fixed model weights and guide behavior through prompting or agent scaffolds, including Vanilla (Yang et al., 2025), ReAct (Yao et al., 2023), Reflexion (Shinn et al., 2023), Proactive CoT (Deng et al., 2023), and PRIME (Wang & Jiang, 2026). 

Threshold-based methods include CLAM (Kuhn et al., 2023), INTENT-SIM (Zhang & Choi, 2025), and VoI-Gate, which score ambiguity, intent uncertainty, and expected clarification utility, respectively. We tune their decision thresholds on validation data. VoI-Gate is our threshold-based adaptation of value-of-information reasoning (Dong et al., 2026). Information-based training methods include IG-Reward (Deng et al., 2026), InfoPO (Kong et al., 2026), and IGPO (Wang et al., 2026), which use information-derived signals either alone or alongside task-return supervision. Supervised and outcome-based training methods include SFT, which learns from demonstrations, and GRPO (Shao et al., 2024), which constructs group-relative advantages from task returns. 

Evaluation and metrics. All main comparisons use Qwen3-4B as the backbone. We use the official evaluation harnesses with our configured turn budgets and report main results as mean and standard deviation over 3 seeds. Table 1 reports UserGym Pass-1 scores; domain-level task pass rates on τ2-Bench; underspecification judgment accuracy (Judg.Acc) on IN3; and answer accuracy (Acc) on AskBench. All 7columns are percentages except UserGym Intention, whose per-detail credits accumulate within an episode. Benchmark-specific settings, baseline implementations, and metric definitions are detailed in Appendix C. 

## 4.2 RQ1: Overall Performance 

CLEAT achieves the highest mean score in all ten settings in Table 1, including gains of 13.24 points on Travel and 6.48 points in IN3 judgment accuracy over the strongest baselines. Baseline strengths vary across settings. SFT leads the baselines on Travel and IN3, while InfoPO leads on AskBench and GRPO on Turtle and Telepathy. CLEAT improves across these different interaction demands using the same paired-outcome learning procedure. The gains on Intention and Telepathy further support transfer to held-out environments without additional training of either the policy or controller. On AskBench and IN3, CLEAT also achieves higher mean scores than ACT (Chen et al., 2025) and CollabLLM (Wu et al., 2025), which learn from interaction outcomes, across all six reported metrics (Table 8). We next examine how renewing value supervision and guiding collection contribute to these gains, and how much the trained policy retains without controller guidance at inference. 

## 4.3 RQ2: Where the Gain Comes From

This motivates renewing value supervision as the policy learns. We test its practical benefit by freezing the controller after bootstrap while continuing task-policy training. Freezing lowers mean scores by 1.27–6.70 points across all six settings (Figure 3, bottom). Both variants retain controller-guided collection, so this comparison assesses the benefit of updating the controller within the training loop. The results support renewing supervision over reusing guidance fitted to the initial backbone. Removing value guidance during collection reduces mean scores by 1.97–8.33 points (Figure 3, bottom). This variant retains paired comparisons, task-return advantages, sampling correction, and controller updates, with five con-tinuations per eligible history. These gains support value-guided allocation for joint policy and controller learning under a fixed rollout budget. To test the guidance signal, we replace predicted RQV with an IG proxy in the same proposal rule. RQV guidance achieves higher mean scores than both unguided collection and IG guidance in all six settings (Figure 3, top). Relative to unguided collection, IG guidance improves four settings but reduces Airline and Telecom by 3.34 and 2.00 points. With the proposal rule and task-return objective retained, this comparison tests which training outcomes the guid-ance signal favors. Under a shared turn budget, informa-tive questions may leave fewer turns for execution; this is one possible explanation for the degradation on these two settings. RQV instead prioritizes the estimated benefit rel-ative to native continuation while keeping policy updates grounded in observed returns. The resulting gains also persist in the trained policy. Replacing the controller with policy-based semantic action selection at inference reduces mean scores by 0.44–6.14 points, but the policy still exceeds the strongest baseline on Travel (59.49% vs. 50.48%). In five of six settings, the mean drop from removing collection guidance exceeds that from removing controller-based selection at inference. This pattern highlights the controller’s role in shaping training experience alongside 8its deployment role. Comparisons using the same constructor and realizer also support gains beyond the menu interface (Appendix D.1).

# 5 Related Work 

Clarification and adaptive decisions. Research on clarification addresses how to resolve ambiguous information needs (Aliannejadi et al., 2020; Min et al., 2020) in settings such as question answering (Kuhn et al., 2023; Zhang & Choi, 2025), code generation (Mu et al., 2024), and planning (Zhang et al., 2024). 9Interactive agent benchmarks extend this focus to implicit user intentions and tool use (Qian et al., 2024; Chen et al., 2026), incomplete instructions (Ji et al., 2026), and communication failures (Bao et al., 2026; Zhang et al., 2026). These settings require agents to recognize missing information and decide when to seek it. Value-of-information methods offer a decision-theoretic view of this problem by weighing the expected benefit of obtaining information against the cost of the interaction (Rao & Daumé III, 2018; Dong et al., 2026; Howard, 1966). 

Learning from interaction outcomes. Another line of work evaluates questions through the interactions they produce. Future-turn simulation (Zhang et al., 2025) generates preference labels from anticipated dialogue, and CollabLLM (Wu et al., 2025) incorporates subsequent turns into its rewards. STaR-GATE (An-dukuri et al., 2024) uses gains in personalized-response likelihood to select questions. For dialogue-action learning, ACT (Chen et al., 2025) constructs and refreshes preference pairs through on-policy simulations. Related ideas appear in retrieval, where RICE-PO (Li et al., 2026) assigns credit using local counterfactual outcomes. 

Information-based rewards and guided collection. A complementary approach measures how feedback changes an agent’s beliefs or subsequent decisions. IGPO rewards answer-likelihood gains (Wang et al., 2026), while clarification-specific rewards track user-goal belief updates (Deng et al., 2026). InfoPO (Kong et al., 2026) combines next-action likelihood changes under observed versus masked feedback with outcome advantages. Beyond reward design, experience prioritization (Schaul et al., 2016) addresses how to allocate training effort across collected experiences. CLEAT connects these strands by using predicted clarification value to guide collection and paired task outcomes to train both the value model and the policy. Appendix E discusses additional evaluation settings and broader adaptive-agent mechanisms. 

# 6 Conclusion, Limitations and Future Work 

We presented CLEAT for interactive intent alignment through value-guided clarification. Paired interaction outcomes supervise both a clarification-value controller and the task policy, while renewed supervision tracks the policy’s changing capabilities. Across four benchmarks, CLEAT improves task performance and clarification quality with Qwen3-4B. The fixed target constructor and question realizer restrict the controller’s available clarification choices. Training also relies on repeated continuations from the same history and user goal, an assumption that is difficult to satisfy in live interactions. Our evaluation uses simulated users, so effectiveness with real users and evolving goals remains to be established. Future work could jointly learn target construction and question realization, and develop value supervision that requires fewer paired rollouts.

15 A Additional Theory and Method Details 

CLEAT learns clarification value relative to the task policy and uses that value to guide the experiences from which the policy learns. This appendix develops the reasoning behind this design. We first explain what the value comparison should measure and how paired continuations provide its supervision. We then derive the rollout allocation rule and the sampling correction needed to learn from these selectively collected outcomes. Finally, we connect the two learning processes through co-training as the task policy evolves. 

## A.1 Defining Policy-Relative Clarification Value 

To learn useful clarification, we need to distinguish the utility achieved after an exchange from the utility added by that exchange. A successful outcome alone cannot make this distinction because the agent may already have been able to succeed by proceeding on its own. We therefore compare a targeted clarification with native continuation from the same interaction history under the same task policy. We identify a clarification by its information target z, such as a travel date or a budget, rather than by its surface wording. At history h, a fixed constructor supplies candidate targets, and a fixed realizer turns a selected target into a question. The comparison is between QUERY (z), which obtains the corresponding user response before task execution resumes, and PASS , which delegates the continuation to the task policy, including its native ability to ask. Let Qπ (h, z) and Vπ (h) denote the expected task utilities of these two continuations under policy π. Their difference defines residual query value, 

gπ (h, z) = Qπ (h, z) − Vπ (h).This reference makes clarification value specific to both the information requested and the policy that will act on the answer. Both branches use the same task utility, including any benchmark-specified interaction costs. 

Information and decision value can rank questions differently. To see why this comparison differs from information gain, consider a zero-cost, single-decision task with latent goal G = ( X, W), where 

X ∼ Bernoulli (1/2 ) and W ∼ Unif {1, . . . , K} are independent, with K > 2. The agent receives reward one for predicting X correctly and zero otherwise. Revealing W provides information gain log K but leaves the best achievable expected reward at 1/2, whereas revealing X provides only log 2 information gain but raises that reward to one. The more informative question therefore need not provide greater task value, even when both answers are reliable and free to obtain. Even when the answer is task-relevant, however, its benefit still depends on the policy receiving it. Keeping the same task and question, consider two policies that both predict zero without clarification. After observing X, one follows the answer and achieves reward one, whereas the other ignores it and retains expected reward 1/2. Their residual query values are therefore 1/2 and zero, respectively, despite receiving exactly the same information. This difference motivates evaluating clarification through the outcomes of the current task policy rather than through the information revealed alone. 

Relation to classical value of information. Unlike classical value of information, which evaluates the benefit to an optimal decision maker, RQV measures the benefit under the policy that actually continues the task. Because training can improve the QUERY and PASS continuations by different amounts, the value of the same clarification can change even when the information it reveals remains fixed. We therefore estimate this policy-relative value from paired outcomes generated by the policy being trained. 

## A.2 Estimating RQV from Paired Continuations 

To turn this policy-relative comparison into a learning signal, we collect paired continuations that share the same history, latent user goal, and task policy. Holding these quantities fixed isolates the initial clarification decision from differences in the task or the agent. For each selected target, the QUERY branch obtains a user response before execution resumes, while the PASS branch delegates directly to the task policy. Both then continue without further controller intervention, including any questions the policy asks on its own. 16 Specifically, at a history h, the constructor supplies a finite candidate set Z(h). When another user exchange is permitted and Z(h) is nonempty, the semantic action set is 

A(h) = {PASS } ∪ { QUERY (z) : z ∈ Z (h)}.Otherwise, it reduces to {PASS }.

Target construction and realization. The candidate constructor is fixed across training and inference. It uses predefined information fields from the task interface where available; otherwise, a frozen model constructs a small target set from the current history. Target construction does not use hidden annotations, rollout outcomes, task rewards, or RQV labels. We hold the realized candidate set fixed within each comparison, so every branch starts from the same decision menu. Let G ∼ p(G | h) denote the latent user goal, which is held by the environment rather than supplied to the policy or controller. Executing QUERY (z) invokes a fixed realizer that produces a benchmark-native question, followed by a user response y ∼ pU (· | G, h, z). The exchange is appended to the history before task execution resumes. Its tokens are environment-side and masked from the task-policy loss, so the learnable decisions are which target to select and how to act on the answer. Keeping the constructor and realizer fixed separates these two sources of improvement from changes in candidate generation or question wording.

## A.5 Online Co-Training and Inference 

Co-training follows from the policy-relative definition of RQV. As the task policy learns, it can improve both its use of an answer and its native continuation, changing the comparison that the controller should predict. For a fixed history h and target z, subtracting Equation 2 across consecutive policy versions gives 

gπt+1 (h, z) − gπt (h, z) = Qπt+1 (h, z) − Qπt (h, z)

− Vπt+1 (h) − Vπt (h).Improved use of an answer can increase its residual value, whereas improved native execution can make the same exchange redundant. What matters is the relative change in the two branches, which motivates renewing the controller’s supervision as the policy evolves rather than treating the values learned at bootstrap as fixed. 

One collection phase, two updates. We implement this feedback loop through a shared rollout batch. First, we bootstrap f0 on paired outcomes under π0, drawing targets from the policy-based reference without value guidance. At step t, we hold πt and ft fixed during collection, so the controller guides target selection while all continuations follow the same task policy. The batch then provides paired RQV labels for fitting 

ft+1 and sampling-corrected task-return gradients for updating πt to πt+1. The controller learns the value of intervention, while the policy learns both target selection and subsequent task execution from observed returns. Controller fitting uses only the current batch, keeping its labels tied to one collecting policy. The next round uses both updated components, so the controller shapes exploration and the policy’s resulting behavior supplies fresh value supervision. 

One-update lag and final refresh. Because both updates use outcomes generated before the policy step, 

ft+1 is fitted to gπt and then guides collection under πt+1. This introduces a one-update lag between value supervision and the policy being guided. The next batch renews supervision under πt+1, tying the targets to successive policy versions while retaining only one collection phase per training step. After the final policy update, we hold πT fixed and collect fresh paired outcomes solely to refresh the controller, without another policy update. Its regression targets are therefore generated by the same policy used at inference. Algorithm 1 summarizes bootstrap, joint updates, and final refresh, using the group allocation in Appendix A.3. 

From exploration to intervention. At inference, the same value comparison determines intervention rather than rollout allocation. While active, the refreshed controller follows Equation 7, selecting the highest-valued query only when its predicted RQV is positive and otherwise choosing PASS . Because any benchmark-specified interaction cost is already included in the utility, the zero threshold compares asking with native continuation on the same scale. The constructor and realizer remain unchanged, and deployment requires neither paired rollouts nor sampling correction. Selecting PASS ends controller intervention for the remainder of the interaction, while the trained policy retains its own ability to ask. The w/o controller variant retains the trained policy, constructor, and realizer, but selects menu actions using πA instead of controller scores.

## C.1 Benchmarks and Evaluation Metrics 

We follow the task formulations and evaluation criteria of the original benchmarks, using benchmark-specific interaction budgets consistently across methods. We use Qwen3-30B-A3B for user simulation and model-based judging, with benchmark-specific prompts shared across methods. Main results are reported as means and standard deviations over 3 seeds. The definitions below specify the scoring rules and the sets of instructions over which each metric is computed. They complement the task overview in Section 4.1. 

UserGym (Qian et al., 2025). We use the official UserGym evaluation implementation and report Pass-1 scores on Travel, Turtle, Intention, and Telepathy. Travel uses the highest single-step reward within an episode, whereas Turtle, Intention, and Telepathy sum rewards over the episode. Scores are averaged over tasks and scaled by 100. The underlying reward differs across environments. Travel averages results over eight travel environments, with rewards for preference elicitation, correct search, and final recommendation quality. Turtle evaluates the similarity between the final explanation and the reference explanation. Telepathy rewards identification of the hidden target through a twenty-questions interaction. Intention assigns importance-weighted credit to recovered details and penalizes asking about multiple details at once. Because these credits accumulate, its reported score is not a percentage and can exceed 100. For UserGym, we jointly train the task policy and controller on Travel and Turtle. Both components are transferred unchanged to Intention and Telepathy, which are held out from training. 

τ2-Bench (Barres et al., 2026). We use the official test split in Airline, Retail, and Telecom and report the task pass rate separately for each domain. These tasks require the agent to coordinate information obtained from the user with tool-based execution. Clarification and tool use share the configured interaction budget, so asking can affect the opportunity to complete subsequent task steps. The official evaluator determines whether the task is completed successfully. 

IN3 (Qian et al., 2024). We report three complementary metrics. Judg.Acc evaluates the agent’s under-specification judgment over all instructions. Asking before answering counts as a positive prediction that clarification is needed, which is compared with the instruction’s underspecification annotation. Instruction recovery (Recover) measures the importance-weighted fraction of missing details resolved before the final answer, evaluated on instructions annotated as underspecified. Vague ask rate is the fraction of those underspecified instructions on which the agent asks before answering. It therefore measures recall of clarifi-cation need, while Judg.Acc also accounts for decisions on fully specified instructions. Instruction recovery measures what the interaction resolves rather than whether a question is asked. 

AskBench (Zhao et al., 2026). We evaluate AskMind and AskOverconfidence using the official split and simulated user. Acc is the fraction of tasks answered correctly. Clarification coverage (Cov) is the fraction of tasks in which every required point is resolved before the final answer. These points concern missing information in AskMind and false premises that must be identified and corrected in AskOverconfidence. Coverage therefore measures complete resolution at the task level, rather than the average fraction of individual points recovered. Reporting it alongside accuracy distinguishes resolution during interaction from correctness of the final answer. 

## C.2 Baselines 

We describe the baseline implementations used in Table 1, grouped by how they guide interaction or train the task policy. 26 Prompting-based. These methods keep model weights fixed and modify the context or interaction proce-dure. Vanilla (Yang et al., 2025) uses each benchmark’s default agent prompt and serves as the backbone reference without task-specific training. ReAct (Yao et al., 2023) interleaves reasoning with environment actions, including clarification where supported by the benchmark. Reflexion (Shinn et al., 2023) uses verbal feedback from previous attempts to guide subsequent attempts through an updated memory. Proactive CoT (Deng et al., 2023) explicitly prompts the model to assess whether the request is sufficiently specified before deciding to ask or answer. PRIME (Wang & Jiang, 2026) maintains and retrieves structured memories of successful strategies, failure patterns, and user preferences, adapting interaction behavior through memory evolution rather than parameter updates. 

Threshold-based. Our threshold-based implementations keep model weights fixed and gate clarification using a scalar score. We sweep the threshold τ on validation data separately for each method and benchmark. 

CLAM (Kuhn et al., 2023) gates clarification by estimated request ambiguity. INTENT-SIM (Zhang & Choi, 2025) uses uncertainty over the user’s intent. Following the value-of-information perspective of Dong et al. (2026), our VoI-Gate adaptation compares the agent’s predicted task-success probabilities for asking first and acting directly. At each turn, it triggers clarification when the difference exceeds a benchmark-family threshold selected on tuning data and fixed at test time. 

Information-based training. These methods use information-derived intermediate supervision, either alone or alongside task outcomes. IG-Reward (Deng et al., 2026) rewards the belief update toward the ground-truth user goal induced by a clarification exchange. InfoPO (Kong et al., 2026) compares the likelihood of the same next action under observed and masked feedback, then combines this information signal with outcome-based advantages. IGPO (Wang et al., 2026) uses increases in the likelihood of the ground-truth answer as turn-level rewards and combines them with outcome rewards. These baselines provide information-based credit assignment. CLEAT instead uses predicted query value to allocate rollouts, while constructing policy advantages from observed task utilities relative to a PASS reference. 

Supervised and outcome-based training. SFT optimizes demonstration likelihood, providing a supervised reference for learning clarification behavior. For GRPO , we follow the group-relative policy optimization framework (Shao et al., 2024). 

Shared settings. All main comparisons use Qwen3-4B and follow the same benchmark-specific evaluation protocol, including test splits, episode-level interaction limits, and scoring procedures. Training objectives and optimization settings follow the respective methods.

## D.8 Qualitative Examples of Policy Behavior 

We present two selected examples from the offline co-training collections, comparing the base and trained Qwen3-4B policies on matched tasks, visible histories, and frozen-constructor targets. Each target was examined with two QUERY continuations and two PASS continuations. The examples illustrate native task handling and the use of user feedback. Task and trajectory descriptions are condensed for presentation. 

Case 1 (IN3) – Native handling of an unspecified detail Task. Write a Python script to parse a CSV file and calculate the average. 

Trajectory comparison. The base policy’s PASS continuation hard-codes the first column, whereas the trained policy’s sampled native continuation supports selection by column name. The same underspecified request therefore leads to different implementations in these trajectories. 

Interpretation. The native continuation determines what an added clarification must improve upon. Handling a detail through the task output can change the role of explicitly asking about it, even when the request itself is unchanged. 

Case 2 (UserGym Travel) – Using an indirect answer Task. Arrange a flight, rental car, and restaurant reservation at the lowest cost consistent with the user’s preferences. 

User feedback. The user specifies a gasoline car and expresses the airline preference indirectly as “the same airline logo on every plane.” 

Trajectory comparison. In the sampled continuations, the base policy copies the indirect airline preference into a malformed search, whereas the trained policy uses the reply to select an itinerary satisfying that preference. 

Interpretation. Obtaining a preference and using it correctly are distinct steps. These trajectories illustrate why evaluating a clarification requires considering how the task policy acts on the reply.

# E Additional Related Work 

Agent capabilities and adaptive computation. Progress in large language models (Ye et al., 2025; Zhang et al., 2025; Xiong et al., 2026a,b) has broadened the capabilities of agents that plan, use tools, and interact with external environments (Zhang et al., 2026; Shi et al., 2026a,b; Huang et al., 2026). Related adaptation mecha-nisms include joint routing–prompt refinement in EvolveRouter (Huang et al., 2026), context-conditioned evidence use in RAG (Li et al., 2026a), and utility-based computation gating in DIAL (Li et al., 2026b). These mechanisms adapt how an agent processes a task. CLEAT focuses on acquiring information from the user according to its incremental value for the evolving task policy. 

Counterfactual comparisons and confidence calibration. CAGE-CAL (Huang et al., 2026) calibrates multi-agent confidence by comparing post-communication agent graphs with matched no-communication graphs, accounting for dependencies induced by agent communication. CLEAT uses paired continuations to estimate the task utility added by user clarification under the current policy. 

Evaluation under imperfect communication. Benchmarks complement clarification methods by construct-ing tasks with missing, ambiguous, or faulty information. IN3, ClarQ-LLM, and MediQ support asking for additional information before committing to an answer (Qian et al., 2024; Gan et al., 2024; Li et al., 2024); CLAMBER examines identifying and clarifying ambiguous information needs (Zhang et al., 2024). Interactive information seeking and user-centric agent settings further connect user exchanges to subsequent actions and task outcomes (Chen et al., 2024; Qian et al., 2025; Sun et al., 2026). Perturbation-based gen-eration extends evaluation to systematically constructed misaligned or underspecified tasks (Zhang et al., 2026). Related work on reasoning and planning (Xiong et al., 2026, 2025), learning to ask under unclear instructions (Wang et al., 2025), and rollout interventions (Zhang et al., 2026) highlights the broader need to 33 connect uncertainty with effective task behavior. This motivates evaluating both whether an agent obtains useful information and whether it successfully acts on that information. 

Specialized clarification and user assistance. SpeakRL studies the integration of reasoning, speaking, and acting (Acikgoz et al., 2026), while ClarEval evaluates clarification by code agents under ambiguous instructions (Li et al., 2026). HiL-Bench examines whether agents recognize when external human assistance is needed (Trinh et al., 2026). These settings broaden the scope of interaction beyond answering an ambiguous question, encompassing task execution and decisions to seek help. Our evaluation measures task performance and clarification quality with simulated users. Robustness to real user behavior and evolving goals remains an important direction beyond the present study.
