ABSTRACT 

Conversational task disambiguation over tabular data uses dialogue to resolve missing information about a user’s intended task before producing a solution over tables or databases. Existing evaluation and training lack a leakage-aware foun-dation. Task success mixes the agent’s disambiguation and solution-generation capabilities and can also reflect oracle leakage , that is, information that a user simulator reveals beyond what a real user would. Existing datasets also lack a shared representation of ambiguities and access boundaries. We introduce the notion of an ambiguous verifiable task , which formalizes ambiguities and resolu-tions, decomposing the agent into an asking policy and a solution policy, and the environment into an oracle and verifier. This framework provides baselines and metrics for evaluating task disambiguation separately from solution generation, formal definitions of oracle leakage, judge-free leakage diagnostics, and a train-ing objective for the asking policy. We instantiate the framework in text-to-SQL with AmbiTab , a benchmark suite that unifies six ambiguous datasets under a com-mon representation specifying what the agent, oracle, and verifier may access. We evaluate clarification strategies and oracle leakage, and train an asking policy with reinforcement learning. The trained asker improves our disambiguation metrics on all six datasets and task success on five, and our leakage diagnostics measure how training affects oracle leakage. 

1 INTRODUCTION 

1.1 CONTEXT AND PROBLEM STATEMENT 

Language models are increasingly used to solve tasks over tables and relational databases (Tian et al., 2026; Wu et al., 2025; Li et al., 2026). When the solution is an executable query, execution provides a trusted verifier. Reinforcement Learning (RL) using such rewards (Pourreza et al., 2025; Ma et al., 2025; Lei et al., 2025b) has improved single-turn systems on text-to-SQL benchmarks such as BIRD (Li et al., 2023) and Spider 2.0 (Lei et al., 2025a). These benchmarks assume that the task specification determines the intended solution. Real task specifications often do not: for example “list the top earners” leaves open both how many earners to return and what counts as earn-ings (Figure 1(c)). We study conversational task disambiguation over tabular data : an agent asks clarifying questions to resolve missing information about the intended task before producing a solu-tion over tables or databases. We focus empirically on text-to-SQL, where clarification identifies the user’s intended interpretation and the solution policy generates a corresponding query. Conversa-tional benchmarks such as SParC and CoSQL (Yu et al., 2019b;a) established the value of evaluating complete interactions, and interactive benchmarks such as BIRD-Interact (Huo et al., 2026) show that this type of ambiguous task remains difficult even for capable models. Evaluating and training conversational task disambiguation requires a leakage-aware foundation, which current practice lacks, for three reasons. First, success rate, the natural metric, depends on

Second, at scale the user is replaced by an oracle, often a language model, and an agent selected or trained against it may exploit its errors, as it might exploit a misspecified reward (Skalse et al., 2022; Pan et al., 2022), for example by eliciting details of the reference solution that no real user would supply. We call this oracle leakage ; prior work separates, constrains, or audits user simulators against it (Jain et al., 2025; Huo et al., 2026; Sullutrone et al., 2026), and diagnosing it with a language model judge adds another untrusted component. Both problems carry over to training: a success-based reward can attribute gains to the asker that actually arise from the solver’s capabilities or from oracle leakage. Third, existing datasets lack a shared representation of ambiguities, resolutions, and what the agent, the oracle, and the verifier may access. We address these difficulties with a formalism that makes explicit what is trusted and what the agent, the oracle, and the verifier may each access. We use it to address the following questions: 

Q1. How can task disambiguation be evaluated separately from solution generation? 

Q2. How can oracle leakage be formally defined and diagnosed without relying on an untrusted language model judge? 

Q3. How can an asking policy be trained within the same formalism, and how does training affect task success rate, asking behavior, and leakage? 1.2 CONTRIBUTIONS 

We introduce the notion of an Ambiguous Verifiable Task (AVT) (Definition 1), a general representa-tion of underspecified tasks with verifiable solutions. An AVT consists of a public task specification, a probability space of hidden interpretations, a finite set of ambiguities and their resolutions, and a verifier (Figure 1c); nothing in the definition is specific to tables or SQL. We study conversational task disambiguation through an ask-then-solve protocol for AVTs and instantiate it in text-to-SQL over relational databases. In this setup, the agent consists of an asking policy (or asker ) that asks the oracle questions and a solution policy (or solver ) that submits a solution. The environment consists of an oracle , whose matcher credits the ambiguities each question addresses and whose responder 

returns information about their resolutions, and a trusted verifier that scores the solution. Because only the asker interacts with the oracle, we can vary the asker while holding the solver fixed. We address questions Q1 -Q3 through three main contributions: 21. Theory. We develop a leakage-aware formalism for AVTs and instantiate it in an agent-environment interaction protocol (Section 2). For Q1 , it separates asking from solving through no-disambiguation and full-disambiguation baselines and asking precision and recall. Splitting the oracle into a matcher and a responder, as some user simulators already do (Huo et al., 2026; Sullutrone et al., 2026; Zhang et al., 2026; Trinh et al., 2026), separates two leakage channels: crediting ambiguities that a question does not address, and revealing more than the credited resolutions. For Q2 , we use our framework to give mathematical formulas quantifying the two types of leakage. The formalism also introduces judge-free, computable diagnostics and proves how they witness or approximate leakage under explicit assumptions. 2. AmbiTab Benchmark Suite. We introduce AmbiTab for conversational task disambiguation over tabular data, comprising more than 8,000 task records across six ambiguous text-to-SQL datasets (Section 3). AmbiTab-Bird and AmbiTab-EW-Bird derive from BIRD (Li et al., 2023); AmbiTab-BIRD-Interact and AmbiTab-Ambrosia adapt BIRD-Interact (Huo et al., 2026) and Ambrosia (Saparina & Lapata, 2024); and AmbiTab-AmbiQT and AmbiTab-TACO adapt Am-biQT (Bhaskar et al., 2023) and TACO (Deng et al., 2026). All six share a record that separates the public specification, the resolutions available to the oracle, and the private reference used by the verifier (Figure 1b), supporting the metrics for Q1 and, with the reference-response and sampling procedures in Appendix A.4, the diagnostics for Q2 . AmbiTab-Bird and AmbiTab-EW-Bird also include training splits relevant to Q3 .3. Experiments. We address Q1 by comparing no-disambiguation, evaluated-asker, and full-disambiguation conditions and reporting both success and asking metrics (Section 4.2). Re-porting all three success rates together with macro precision and recall distinguishes the benefit of clarification from gaps in question quality. For Q2 , we apply the diagnostics to deterministic and LLM oracles and test them on a responder that reads the reference SQL (Section 4.3). For 

Q3 , we train the asking policy with a multi-turn GRPO variant with DAPO-style asymmetric clipping and zero-advantage group filtering (Shao et al., 2024; Yu et al., 2025) on AmbiTab-Bird, evaluate its coverage and task success with a fixed solution policy across datasets, and compare training oracles and reward objectives (Section 4.4). 1.3 RELATED WORK 

Conversational task disambiguation. Ambiguous text-to-SQL benchmarks represent alternative readings (Bhaskar et al., 2023; Saparina & Lapata, 2024; Deng et al., 2026). BIRD-Interact and ABISS evaluate clarification with simulated users (Huo et al., 2026; Sullutrone et al., 2026), whereas DySQL-Bench studies follow-up requests in database exploration (Sun et al., 2026a). Information-gain methods select questions that distinguish interpretations (Kobalczyk et al., 2025; Qiu et al., 2025); IN3, AskBench, and π-Bench assess coverage of missing information (Qian et al., 2024; Zhao et al., 2026; Zhang et al., 2026). We focus on eliciting the missing information that resolves the current task’s intended interpretation. Our task representation makes task ambiguities, resolu-tions, and oracle access explicit, with text-to-SQL as the evaluated instantiation over tabular data. See Appendix F for broader comparisons of benchmarks, clarification methods, and reward formu-lations. 

Oracle reliability. Prior work restricts solution access or audits simulated responses (Jain et al., 2025; Huo et al., 2026; Sullutrone et al., 2026), but simulator fidelity and policy overfitting remain concerns (Seshadri et al., 2026; Yu et al., 2026). We define leakage relative to a perfect oracle and derive judge-free diagnostics for undeserved question credit and excess response information. 

Learning to disambiguate. RL for SQL generation and table reasoning directly rewards solu-tion correctness (Pourreza et al., 2025; Ma et al., 2025; Lei et al., 2025b). ACT and SGP learn clarification policies (Chen et al., 2025; Berant et al., 2026), while IntentRL learns to enumerate interpretations and SQL queries in one response (Saparina & Lapata, 2026). InfoPO combines in-formation gain with outcome rewards (Kong et al., 2026); HiL-Bench combines blocker coverage with per-question bonuses and penalties (Trinh et al., 2026). Our question-F1 reward balances am-biguity coverage and question efficiency without additional shaping coefficients. Training improves downstream accuracy through better disambiguation. 32 THEORY 

Agent, environment, and oracle leakage. We model the interactions between an agent A and an environment E as a stochastic process from which we sample trajectories τ ∼ (A; E). Both A and 

E are conditional distributions: A models the probability distribution of the next action given the observable history, and E that of the next state given the history and the action taken by A. The sets of states and actions depend on the setup. We are interested in situations where the environment is determined by two kinds of distributions: (1) Trusted distributions, such as a programmatic verifier V , which could even be deterministic. (2) Untrusted distributions, such as an oracle O implemented by a language model, intended to approximate a perfect oracle O⋆, which could be defined to be, e.g., the behavior of a user base. The agent is usually evaluated using its success rate J(A; E) := Eτ ∼(A;E)[V (τ )] . However, maxi-mizing J(A; E) can lead the agent to exploit deviations of O from O⋆, e.g., by eliciting information from O that O⋆ would not provide. We refer to any such deviation as oracle leakage .

Ambiguous verifiable tasks. We represent task specifications, ambiguities, clarification ques-tions, responses, and solutions as text; we write Text for this set. Task disambiguation elicits information about the intended interpretation of a specification. In our text-to-SQL instantiation, this interpretation determines what the user intends to compute over the database, and the solution is a corresponding SQL query (Figure 1c). 

Definition 1. An ambiguous verifiable task is a tuple (x, Θ, Amb , ρ, V ) consisting of • A specification x ∈ Text ;• A probability space Θ of interpretations of x;• A finite set Amb ⊆ Text of ambiguities ;• A resolution map ρ : Θ × Amb → Text ;• A verifier V : Θ × Text → { 0, 1}.Proofs, technical assumptions, a table of notation, and other details are in Appendix A.

53 AMBI TAB BENCHMARK SUITE 

We introduce AmbiTab, a suite of six ambiguous text-to-SQL datasets for evaluating conversational task disambiguation over tabular data. Each dataset consists of task records with explicit ambiguity annotations, fixed resolutions, and verification assets. 

Task record. Abstractly, a task record implements a fixed interpretation of an ambiguous verifiable task (x, Θ, Amb , ρ, V ), so it can be seen as a sample of an AVT. More precisely, given an interpre-tation θ ∈ Θ, its corresponding task record is the tuple (x, Amb , ρ θ , V θ ), where ρθ (α) = ρ(θ, α ) is the resolution map for an ambiguity α evaluated on the fixed interpretation, and Vθ (s) = V (θ, s ) is the verifier evaluated on the fixed interpretation. In practice, this is implemented as follows (see Figure 1(b) for an illustration): • Task specification and context. The user request, and optionally the database schema, the column meanings, external knowledge, and other context. • Ambiguities and resolutions. A list pairing each ambiguity with its resolution as text. Op-tionally, it might include the ambiguity type, a SQL snippet for grounding the responder, etc. • Verification assets. Usually, an executable database and a reference query. Optionally, test cases, statements that prepare and restore the database, a policy for comparing result sets, etc. 

Dataset construction and details. We adapt BIRD (Li et al., 2023), BIRD-Interact (Huo et al., 2026), Ambrosia (Saparina & Lapata, 2024), AmbiQT (Bhaskar et al., 2023), and TACO (Deng et al., 2026) (Appendix B.1). All datasets use SQLite except for AmbiTab-BIRD-Interact, which uses PostgreSQL. Training configuration. To improve both precision and recall ( Q3 ), we train the asker on AmbiTab-Bird with the deterministic oracle, using a multi-turn GRPO variant with DAPO-style asymmetric clipping and zero-advantage group filtering (Shao et al., 2024; Yu et al., 2025). Our main policy uses a question-F1 reward , the harmonic mean of asking precision and recall within each episode. Requests with ambiguities receive zero reward when no question is productive; re-quests without ambiguities receive one for abstaining and zero for asking. The reward encourages efficient ambiguity coverage without requiring solver output; Appendix D gives the formal definition and training details.

Ablations. We compare the policy trained with question-F1 reward with two variants trained on final SQL correctness ( outcome reward ), using either the deterministic oracle or Qwen3-14B. Both achieve lower mean precision, recall, and SR under the same evaluation protocol (Figure 5a shows the Qwen3-14B variant). Unlike question-F1, outcome reward depends on the solver’s ability to use the responses. A separate outcome-reward run on AmbiTab-BIRD-Interact failed to sustain clarification improvements before crashing (Appendix D.4).

5 CONCLUSIONS 

We introduced a leakage-aware framework for evaluating and training conversational task disam-biguation over tabular data, based on ambiguous verifiable tasks and an ask-then-solve protocol. The framework separates the asker, solver, oracle, and verifier, and treats precision and recall as essential alongside success rate. No-disambiguation and full-disambiguation evaluations provide empirical reference points for a fixed solver and oracle. Together with leakage diagnostics, these measures help distinguish failures in acquiring information, using it, and respecting disclosure boundaries. With the deterministic oracle, three-seed evaluations of question-F1 training show higher precision and recall across all six corpora. Our six-corpus benchmark remains unsaturated: clarification and asker training improve performance, but substantial gaps in question quality and task success persist. Future work will develop better training methods for askers and expand the benchmark to broader tasks, ambiguity types, and interaction settings. 9AI USE STATEMENT

This work studies conversational task disambiguation over tabular data using existing text-to-SQL benchmarks and simulated user responses. It involves no human subjects and collects no new per-sonal data; all data come from public benchmarks. Some records contain model-authored text (see the AI use statement), which may carry model errors or biases. The source benchmarks are public and may appear in the pretraining data of the evaluated models, which can inflate absolute success rates; our comparisons hold the models fixed across conditions. Benchmark and model biases may carry over to the resulting systems, and simulated interactions do not establish effectiveness with real users. Macro precision and recall. The offline scorer maps each recorded oracle routing action to a reg-istered ambiguity. An exact labeled term takes precedence; otherwise it matches annotated terms against the question, response, and recorded routing rationale. Only critical and knowledge ambi-guities count. Recall is the fraction of distinct registered terms credited over the episode, and pre-cision is the fraction of questions receiving a previously unseen credit. We macro-average defined episode scores, omitting precision when no question was asked and recall when no ambiguity was registered. Thus the eligible populations differ: pooled AmbiTab-Bird has 615 ambiguity-bearing records out of 664, and AmbiTab-BIRD-Interact has 593 out of 600. The scorer also omits recall and F1 for fallback-stop episodes; this removes one AmbiTab-AmbiQT episode in each of two of the 90 oracle-comparison runs, and all other inference recall denominators equal the ambiguity-bearing populations. When shown, F1 is the mean of episode-level harmonic means, not the harmonic mean of macro precision and recall. These are credited-coverage measures: oracle wording can affect them, including by volunteering a resolution that the question did not name.

D TRAINING THE ASKING POLICY : IMPLEMENTATION AND ADDITIONAL RESULTS

F ADDITIONAL RELATED WORK 

Ambiguous and interactive tabular tasks. AmbiQT, Ambrosia, and TACO represent alterna-tive text-to-SQL interpretations (Bhaskar et al., 2023; Saparina & Lapata, 2024; Deng et al., 2026); SParC and CoSQL establish conversational evaluation (Yu et al., 2019b;a). DialSQL and PIIA ask multiple-choice clarification questions (Gur et al., 2018; Li et al., 2020), while MISP models in-teractive parsing as an agent in a user environment (Yao et al., 2019). MMSQL, PRACTIQ, and CLARITY provide fixed clarification dialogues (Guo et al., 2025; Dong et al., 2025; Sarwar et al., 2026). BIRD-Interact and ABISS combine clarification with simulated users and executable SQL checks (Huo et al., 2026; Sullutrone et al., 2026); ODUTQA-MDC studies dialogue-based clarifi-cation for open-domain tabular QA (Wang et al., 2026). DySQL-Bench focuses on evolving user requests and follow-up database exploration (Sun et al., 2026a). Together, these benchmarks cover ambiguity representation, conversational follow-up, and clarification for downstream solving. Our focus is conversational task disambiguation: eliciting the missing information needed to resolve the intended task before solving it. Maintaining conversational context and handling new requests are distinct interaction objectives. Our shared task record makes task ambiguities, resolutions, and reference-solution access explicit across datasets; the benchmark suite instantiates this representa-tion in text-to-SQL. 

Task formalization and clarification evaluation. Hidden goals and verifiable outcomes appear in τ -bench and τ 2-bench (Yao et al., 2025; Barres et al., 2026); CoVe constructs interactive tasks from hidden constraints with deterministic verification (Chen et al., 2026). Active Task Disam-biguation distinguishes consistent from acceptable solutions and selects questions by information gain under a truthful oracle (Kobalczyk et al., 2025); related approaches study when to clarify under a distribution of interpretations (Zhang & Choi, 2025), information-gain selection with annotated oracle responses (Qiu et al., 2025), and value-of-information scoring for tool parameters (Suri et al., 2026). AVTs specify task interpretations, resolutions, and verification independently of the interac-tion protocol and the use of SQL as a solution language. AmbigQA and ASQA evaluate answers or rewrites (Min et al., 2020; Stelmakh et al., 2022), while GATE and STaR-GATE assess elicitation through downstream outcomes (Li et al., 2025; Andukuri et al., 2024). IN3, AskBench, and π-Bench score questions against annotated missing information (Qian et al., 2024; Zhao et al., 2026; Zhang et al., 2026); ClariQ evaluates clarification retrieval (Aliannejadi et al., 2021). HiL-Bench 34 hides blockers in BIRD and SWE-bench Pro tasks, evaluates blocked, full-information, and ask conditions, and trains with question precision and recall (Trinh et al., 2026). Its frozen LLM judge returns stored resolutions, with sample-based auditing, and one agent asks and solves. Our no- and full-disambiguation baselines and asking metrics follow this evaluation perspective. Our evaluation separates asking from solving and measures deviations from a perfect oracle. 

Oracle reliability and leakage. AutoEval-ToD separates simulation from solution information; BIRD-Interact and ABISS constrain or audit responses (Jain et al., 2025; Huo et al., 2026; Sullutrone et al., 2026). Hack-verifiable environments detect reward hacking separately from success (Roth et al., 2026). Simulator research studies policy-value gaps (Dann et al., 2026) and exploitation of simulator error during optimization (Muratore et al., 2018). LLM user simulations can misestimate human-user performance (Seshadri et al., 2026), and policies can overfit to frozen simulators (Yu et al., 2026). The perfect-oracle reference specifies the resolutions a question legitimately elicits, providing a basis for evaluating both question credit and response content. Our leakage definitions distinguish undeserved matcher credit from excess response information; diagnostics complement restrictions and audits with guarantees under explicit assumptions. 

Learning clarification policies. Execution rewards support SQL and table-reasoning RL (Pour-reza et al., 2025; Ma et al., 2025; Lei et al., 2025b), with group-relative optimization providing training methods (Shao et al., 2024; Yu et al., 2025). Multi-turn methods address credit assign-ment and rollout stability (Zhou et al., 2025; Xue et al., 2026). ACT trains through conversations with an LLM oracle (Chen et al., 2025); SGP learns cost-conditioned clarification, answering, and enumeration through self-play using an LLM oracle (Berant et al., 2026). AskBench combines cor-rectness and checkpoint coverage (Zhao et al., 2026), UserVille penalizes question effort (Sun et al., 2026b), and InfoPO adds turn-level information gain to outcome rewards (Kong et al., 2026). Inten-tRL instead trains interpretation and solution enumeration in one output (Saparina & Lapata, 2026). HiL-Bench combines terminal blocker coverage with a reward of +0 .3 for productive questions and a penalty of 0.1 for irrelevant or repeated questions (Trinh et al., 2026). Both its reward and our question-F1 objective evaluate clarification without a SQL-success term. Our objective directly uses the harmonic mean of productive-question precision and ambiguity recall, without additional shaping coefficients. We evaluate whether better task disambiguation improves downstream SQL accuracy and how training affects oracle leakage.
