ABSTRACT 

LLM-agent workflows routinely transform rich observations into plans, sum-maries, memories, handoffs, and other reusable state. This creates a privacy boundary that task relevance alone does not capture: an observation may be needed as evidence for a task without its full semantics being authorized to per-sist. We call this mismatch the purpose-to-state semantic gap . The key distinction is that evidence authority is not release authority . We introduce Purpose IR ,a bounded typed intermediate representation that compiles natural-language user purpose into an executable semantic boundary for reusable agent state. A Purpose program is an acyclic semantic dataflow graph in which evidence leaves spec-ify task-required semantics, typed dependencies constrain authorized derivations, and declared sinks determine which values or actions may cross the reusable-state boundary. A deterministic compiler constructs and validates the authoritative pro-gram, while a typed runtime reconstructs reusable state only from validated sink outputs. Under explicit execution contracts, this design yields release confine-ment and purpose noninterference , characterizing what factual semantics may be released and which observation differences must become irrelevant to reusable state. Across 1,200 cases spanning LangGraph, CrewAI, and MobileRun, Pur-pose IR achieves 99.6% Privacy , 83.3% Task , and 83.3% Privacy-Compliant Success (PCS) , outperforming the strongest high-privacy baseline by 27.5 PCS points . On 493 PrivacyLens trajectories, it achieves the highest Safe Action Rate 

at 77.3% , 10.4 points above the next-best method, extending the same bound-ary from reusable state to downstream actions. These results show that privacy-preserving agent state requires more than filtering sensitive or task-irrelevant con-tent: it requires an explicit, executable representation of what the user’s purpose authorizes to survive. . 

1 INTRODUCTION 

LLM agents increasingly operate through multi-step workflows that combine language-model rea-soning with tool use, environment observations, coordination, and persistent state (Yao et al., 2023; Schick et al., 2023; Wu et al., 2024; Park et al., 2023; Packer et al., 2023). During execution, these workflows routinely transform rich observations into plans, summaries, memories, handoffs, and other intermediate artifacts that are reused by later steps or later agents. This reuse is operationally useful, but it creates a distinct privacy boundary: information that is legitimately observed for com-putation can persist far beyond the semantic result the user actually requested. Consider a user who asks, “Do I have a meeting reminder?” A workflow may inspect a notifica-tion containing a sender name, meeting time, office location, phone number, and full message body. These fields can all help determine whether the notification is a meeting reminder, yet the requested result is only a Boolean predicate. purpose-to-state semantic gap : the semantics retained in reusable workflow state can exceed the semantics required by the user’s purpose. The key distinction is that the information an agent is authorized to inspect as evidence can be strictly richer than the information it is authorized to retain as reusable state. Task relevance therefore governs what may be useful as evidence, not what may persist as state. The purpose-to-state semantic gap exposes three fundamental challenges. (P1) Semantic specifica-tion. A user’s task specifies the desired outcome but not the boundary between semantics needed as evidence and those authorized to persist. (P2) Purpose compilation. Natural-language purpose is not directly executable and must be compiled into a representation that makes evidence, deriva-tion, and release authority explicit. (P3) Semantic preservation. The compiled boundary must remain authoritative as information flows through heterogeneous workflow representations, prevent-ing richer observation semantics from re-entering reusable state. Existing span-based privacy tools, contextual-privacy models, runtime policies, and information-flow controls address important parts of these challenges, such as detecting sensitive content, judging contextual relevance, or restricting propagation (Microsoft, 2026; Ngong et al., 2025; Bagdasarian et al., 2024; Costa et al., 2025; Wang et al., 2026; Siddiqui et al., 2025; Kolluri et al., 2026). Existing studies also reveal leakage in reason-ing traces, inter-agent communication, memories, and actions (Green et al., 2025; El Yagoubi et al., 2026; Shao et al., 2024). What remains missing is a common, task-derived semantic boundary that specifies what result semantics may survive into reusable state and makes that boundary executable across workflows. We introduce Purpose IR to provide this boundary. The core idea is simple: evidence may be richer than the result, but reusable state should not be. Purpose IR compiles a natural-language task into a bounded typed semantic dataflow program: evidence leaves specify what task semantics may be acquired, typed dependencies constrain how results may be derived, and declared sinks determine what values or actions may cross the reusable-state boundary. A task-only semantic frontend proposes candidate semantics, while a deterministic compiler constructs the authoritative program; workflow adapters ground its evidence requirements, and a typed runtime reconstructs reusable state only from validated sink outputs. Purpose IR therefore governs which semantics may survive, rather than how the agent performs the task. 2Preprint 

This structure yields two formal properties that characterize the reusable-state boundary indepen-dently of any particular workflow representation. First, release confinement requires every factual semantic value in reusable state to be justified by the authorized ancestry of an explicit sink. Second, 

purpose noninterference requires observations that induce the same typed results at all sink-relevant Purpose leaves to produce equivalent reusable factual state under deterministic Purpose execution. Together, these properties capture both what information may be released and which observation differences must become irrelevant once the authorized result has been computed. We evaluate Purpose IR in two complementary settings. The main evaluation contains 1,200 English workflow cases balanced equally across LangGraph, CrewAI, and MobileRun. Purpose IR achieves 

99.6% Privacy , 83.3% Task Success Rate , and 83.3% Privacy-Compliant Success (PCS) ; the strongest high-privacy baseline reaches 55.8% PCS. We further evaluate external transfer on 493 PrivacyLens trajectories (Shao et al., 2024), where Purpose IR achieves the highest Safe Action Rate at 77.3% , 10.4 points above the next-best method. In summary, this paper makes three contributions aligned with the three challenges above: 

(1) A semantic formulation of reusable-state privacy. We identify the purpose-to-state semantic gap and distinguish task-relevant evidence from the smaller result semantics authorized to persist. 

(2) Purpose compilation into an executable semantic representation. We introduce Purpose IR , a bounded typed dataflow IR that separates task-only semantic interpretation from determinis-tic authority construction and makes evidence, dependencies, and release/action sinks explicit. (3) Semantic preservation with formal and cross-workflow evidence. We formalize the compiled reusable-state boundary through release confinement and purpose noninterference , and evaluate it across three workflow frameworks and on PrivacyLens. 

2 RELATED WORK 

Privacy leakage in agent workflows. Recent work shows that privacy leakage in LLM agents is not confined to final outputs. Green et al. (2025) demonstrate that reasoning traces of personal agents can contain sensitive user data, while AgentLeak instruments inter-agent messages, shared memory, tool arguments, and related channels, showing that output-only auditing can miss substantial inter-nal leakage (El Yagoubi et al., 2026). Multi-agent contextual-privacy work studies how upstream privacy errors propagate through workflow topology (Li et al., 2025), and CIPL models privacy leakage across heterogeneous agent pipelines as a channel-inversion problem (Huang et al., 2026). Together, these studies establish intermediate workflow artifacts and internal communication as im-portant privacy surfaces. Purpose IR focuses on the semantics retained when legitimately accessed observations are transformed into reusable workflow state, and on how those retained semantics can be bounded by the user’s task. 

Task-aware privacy and agent enforcement. Several lines of work incorporate task context into privacy protection or enforce explicit constraints over agent execution. AirGapAgent minimizes the private source information exposed to a conversational agent (Bagdasarian et al., 2024), while contextual-privacy approaches evaluate disclosure in terms of relevance and necessity for the user’s goal (Ngong et al., 2025). Fides and related work apply deterministic information-flow controls to agent planning and LLM calls (Costa et al., 2025; Siddiqui et al., 2025; Kolluri et al., 2026); AgentSpec provides a DSL for runtime safety constraints (Wang et al., 2026); and agent firewalls, MNC, and CXI introduce structured or typed boundaries for agent communication and execution (Abdelnabi et al., 2025; Xu et al., 2026; Santos-Grueiro, 2026). AgentSecBench further separates data flow from authority and formalizes policy-enforced projections under intent-to-execution non-interference (Alpay & Alpay, 2026). Purpose IR contributes a task-derived semantic representation for this setting: natural-language purpose is compiled into typed evidence requirements, authorized derivations, and release sinks that govern the observation-to-state boundary.

3 METHOD 

Purpose IR makes the observation-to-state boundary executable. Given a user task T and workflow observation O, the system compiles the task into a Purpose program, grounds the program in typed evidence, executes its semantic dataflow, and reconstructs only authorized outputs: 

P = Compile( T ), B = Bind( P, O ), C = Interpret( P, B ), Aout = Release( P, C ).

The central separation is that O supplies evidence for the computation, whereas P defines the se-mantic authority under which results may enter reusable state. Figure 2 gives an overview of this compiler–runtime design. 3.1 PURPOSE IR: T YPED SEMANTIC DATAFLOW 

A compiled Purpose program is a typed acyclic graph 

P = ( V, E, S ),

where V is a finite set of typed Purpose nodes, E is the authorized dependency relation, and S is the set of release or action sinks. Each node declares an operator, an output schema, and typed predecessor references; leaf nodes additionally declare a semantic target and evidence cardinality. Optional activation guards are bounded predicates over predecessor values. The graph captures 

semantic dependencies , not agent control flow: tool selection, navigation, retry, and planning remain outside the IR. Purpose nodes have three roles, summarized in Table 1: evidence-binding leaves, typed derived nodes, and release/action sinks. Only leaves may bind workflow evidence; derived and sink nodes operate only on typed predecessor results. This role separation creates the central dataflow invariant. For every derived or sink node v,

RawAccess( v) = ∅, Inputs( v) ⊆ { Cu : u ∈ Pred( v)}.

For example, the task “Send the meeting link and meeting time to my assistant” compiles to the following Purpose program:             

> R1 =GET_VALUE(meeting_link, one) R2 =GET_VALUE(meeting_time, one) R3 =COMPOSE(record, meeting_link=ref(R1), meeting_time=ref(R2)) R4 =ACTION(send_message, destination="assistant", content=ref(R3)) sinks =[R4]

The program exposes exactly the semantics authorized by the task—the meeting link and time, their bounded composition, and a destination-scoped action— without prescribing how the upstream agent discovers those values. The graph representation becomes important when authorized results require multiple semantic values to be composed, conditionally propagated, or bound to structured actions. Purpose IR therefore represents the semantic computation from task-required evidence to authorized release, rather than merely selecting a flat set of fields. 3.2 COMPILING NATURAL -L ANGUAGE PURPOSE 

Compilation separates semantic interpretation from executable release authority. A Qwen3.5-0.8B frontend reads only the user task T and proposes candidate operations, semantic targets, multiplicity, and decomposition: 

T Mθ

The frontend proposal bQ carries no execution or release authority. The deterministic Purpose Compiler resolves it into the canonical graph P by assigning semantic targets, operator contracts, schemas, cardinalities, dependencies, and sinks, and validating the result. It also separates task-level semantic targets, such as meeting link or meeting time , from generic observation carriers such as “text”, “notification”, or “message body”, which cannot become release targets. Valida-tion rejects malformed structure, including duplicate identifiers, unknown references, cycles, invalid guards or schemas, unsupported cardinalities, malformed action arguments, and derived references to raw observations. Once constructed, P is the sole authority consumed by the runtime; frontend proposals cannot directly expand evidence access or release. The compiler provides executable authority rather than a guarantee that the resulting program per-fectly captures the user’s intended semantics. The formal properties below are therefore conditional on the compiled program P and the stated binding, operator, and reconstruction contracts; task-to-program semantic accuracy is evaluated empirically. Appendix D and Appendix B specify the binding and operator contracts. 3.4 PURPOSE -C ONSTRAINED RELEASE 

Typed completions are computation state, not automatically reusable state. The release layer val-idates the declared sinks and reconstructs a fresh host-framework artifact from valid sink outputs only: 

Aout = Reconstruct ( {Cs : s ∈ S, C s valid }) .

Source prose, evidence records, provenance, frontend candidates, compiler diagnostics, and non-sink completions do not become reusable merely because they participated in the computation. Release is therefore a graph-level operation: factual content can enter reusable state only through validated sink outputs, and a typed dependency carries an authorized value without granting author-ity over unrelated fields from the same source observation. Dependency reachability and release authority are consequently distinct. Returning to the meeting-reminder example, sender, time, location, phone number, and message body may all support the evidence-binding process for deciding whether a reminder exists, yet the reusable output can still be exactly the Boolean requested by the task. The richer carrier supports the computation without becoming part of the released result. The Purpose language, interpreter, and release rule are shared across LangGraph, CrewAI, and Mo-bileRun; workflow-specific code is confined to evidence adapters and native reconstruction. Ap-pendix E and Appendix F provide the implementation and formal details. 3.5 FORMAL PROPERTIES 

The graph discipline above yields two properties that characterize the semantic boundary enforced by Purpose IR. The properties concern factual semantics released into reusable state. Structured action sinks obey the same typed dependency and sink-validation discipline for their emitted ar-guments, while environment-level side effects are outside the scope of FactSem and of the two propositions below. We call an execution valid when leaf bindings respect their declared semantic targets and cardinalities, node evaluation respects the corresponding operator and schema contracts, and reconstruction emits factual content only from validated sink outputs. 

Proposition 1 (Release confinement) . Let P = ( V, E, S ) be a valid Purpose IR program and con-sider a valid execution. For every factual semantic value x visible in the released artifact Aout , there 

6Preprint exists a sink s ∈ S such that x is contained in the semantic output of s and its factual provenance is confined to semantics authorized by the Purpose ancestors of s:

x ∈ FactSem( Aout ) = ⇒ ∃ s ∈ S : x ∈ Sem( Cs) ∧ Prov( x) ⊆ Auth(Anc( s)) .

Release confinement states that graph reachability cannot create authority. A value may flow to a sink only through typed dependencies already admitted by the Purpose program; neighboring fields in the original observation do not become releasable merely because they appeared in the same evidence carrier or supported the same computation. For the second property, let LS ⊆ V denote the leaf ancestors of declared sinks. We call two observations purpose-equivalent for P when they induce the same typed completion at every sink-relevant leaf: 

O1 ≡P O2 ⇐⇒ ∀ℓ ∈ LS , C ℓ(O1) = Cℓ(O2).

Proposition 2 (Purpose noninterference) . For deterministic valid executions of P , if O1 ≡P O2,then the two observations induce the same reusable factual semantic state: 

O1 ≡P O2 =⇒ FactSem( Aout (O1)) = FactSem( Aout (O2)) .

The proof follows the DAG structure: equal sink-relevant leaf completions imply equal derived completions by induction over topological order, hence equal sink outputs; deterministic sink-only reconstruction then yields equal factual semantic state. Intuitively, once two observations agree on everything the compiled purpose is authorized to use for its sinks, all remaining differences in the raw observations become irrelevant to reusable factual state. 4 EXPERIMENTS 

4.1 EVALUATION DESIGN 

Main workflow-state benchmark. We evaluate on 1,200 English workflow cases spanning Lang-Graph, CrewAI, and MobileRun, with 400 cases per workflow. The three subsets share a com-mon semantic task space while preserving their native workflow-state representations. Cases cover semantic-boundary conditions such as ambiguous evidence, negation, mixed private content, dupli-cate records, and semantic minimality. For each case, all methods receive the same user task and the same fixed workflow input. We evaluate the downstream reusable artifact with a unified deterministic evaluator. Privacy mea-sures whether the artifact excludes semantically unauthorized content, while Task Success Rate 

measures whether task-required result semantics remain available downstream. Our primary metric is their per-case conjunction, Privacy-Compliant Success (PCS) ,

PCS( i) = Privacy( i) ∧ TaskSuccess( i).

External transfer. We additionally evaluate on 493 PrivacyLens privacy-sensitive action trajec-tories (Shao et al., 2024). Unlike the main benchmark, this setting evaluates downstream actions rather than reusable workflow state. We follow the action-level protocol with a fixed local Mistral-7B-Instruct-v0.2 judge, while Purpose IR uses the same task-only Qwen3.5-0.8B semantic frontend as in the main evaluation. We report Privacy Pass , Helpfulness ≥ 2, and their per-trajectory conjunction, Safe Action Rate ,

SafeAction( i) = PrivacyPass( i) ∧ [Helpfulness( i) ≥ 2] .

A PURPOSE IR S PECIFICATION 

This appendix specifies the bounded typed dataflow language used by Purpose IR and the static constraints enforced before execution. A.1 LANGUAGE BOUNDARY 

Purpose IR is a semantic dataflow language for user purpose, not a full agent execution language. It represents task-required evidence semantics, typed dependencies among authorized intermediate results, and declared release or action sinks. Tool selection, navigation strategy, retry policy, loops, recursion, and unrestricted user-defined computation remain outside the IR. A Purpose program is 

P = ( V, E, S ),

12 Preprint 

where V is a finite set of typed nodes, E is an acyclic dependency relation, and S is the set of declared sinks. The operator vocabulary is partitioned by role: 

Oleaf = {EXISTS , COUNT , GET VALUE , DIAGNOSE },

Oderived = {COMPOSE }, Osink = {ACTION }.

A completed leaf or derived node may also be declared directly as a release sink when the task result itself is the reusable output. A.2 CANONICAL NODE CONTRACT 

Each node has a stable identifier, operator, output schema, and optional dependency metadata. Leaf nodes additionally declare a semantic target and evidence cardinality. Derived and sink nodes refer-ence predecessor results explicitly. Table 4 summarizes the core fields. A representative compositional program is: 

R1 = GET_VALUE(error_code, cardinality=one) R2 = GET_VALUE(device_model, cardinality=one) R3 = COMPOSE(record, error_code=ref(R1), device_model=ref(R2)) R4 = ACTION(send_message, destination="administrator", content=ref(R3)) sinks = [R4] 

The graph makes internal and external values explicit. R1–R3 can complete without becoming reusable state; R4 is the declared sink. A.3 SEMANTIC TARGETS AND CARDINALITY 

Semantic targets belong to a bounded registered namespace with auditable binding paths. Ex-amples include meeting reminder , meeting link , tracking number , error code ,

device model , app version , and delivery status . Generic carriers such as text ,

clipboard , notification , screen , or message body are not semantic targets. Leaf nodes additionally declare bounded evidence cardinality. The implementation supports single-value and bounded multi-value requirements, including one , many , at most k , and 

all matching . Cardinality is checked during binding and materialization rather than inferred from field order at runtime. A.4 DEPENDENCY , COMPOSITION , AND SINK SEMANTICS 

Dependencies are first-class typed references. A node may consume only declared predecessor out-puts, and the compiler rejects unknown references and cycles. Derived COMPOSE nodes construct schema-bounded records or templates from predecessor values; they do not receive an observation handle. Structured ACTION nodes similarly consume declared literals and typed predecessor results and define the downstream destination and arguments. This separation yields the leaf-access invariant 

v ∈ Vderived ∪ Vsink =⇒ RawAccess( v) = ∅.

A dependency therefore transports an already-authorized typed value; it does not expand the seman-tic authority of the consumer.

C SEMANTIC FRONTEND AND PURPOSE COMPILER 

The compiler separates neural semantic proposal from deterministic authority construction. C.1 TASK -ONLY SEMANTIC FRONTEND 

The Qwen3.5-0.8B frontend reads only the natural-language task. It does not observe native work-flow state, raw observations, artifact fields, privacy labels, or benchmark annotations. F FORMAL PROPERTIES 

This section states the execution contracts and proof obligations behind Propositions 1 and 2. These contracts define valid execution for the shared Purpose IR semantics. F.1 EXECUTION CONTRACTS 

Let P = ( V, E, S ) = Compile( T ) be a valid acyclic Purpose program and O a workflow observa-tion. A valid execution satisfies the following contracts. 1. Binding contract. For every leaf ℓ, each value in Bℓ = Bind( ℓ, O ) denotes the semantic target declared by ℓ, satisfies its assertion constraints, and preserves record identity when required by the operator. 2. Operator and codec contract. For every node v, JvK produces only values admitted by the node’s declared output type, cardinality, and schema. Derived and sink nodes read only typed predecessor outputs and declared literals. 3. Reconstruction contract. Reconstruct emits factual semantic content only from validated sink outputs; source observations, bound evidence, provenance, compiler diagnostics, and non-sink completions are not copied into factual reusable state. 4. Determinism (for Proposition 2). Given the same typed predecessor completions, guards, operator semantics, and sink outputs, graph execution and factual reconstruction are deter-ministic. Together, these contracts define the executions to which the two propositions apply. F.2 PROOF OF RELEASE CONFINEMENT 

For each non-leaf node v, the language invariant requires 

RawAccess( v) = ∅, Inputs( v) ⊆ { Cu : u ∈ Pred( v)}.

Consider any x ∈ FactSem( Aout ). By the reconstruction contract, x must be emitted from a vali-dated sink output Cs for some s ∈ S. Each factual component of Cs is either a contract literal or is obtained through a typed predecessor reference. Following predecessor references backward in the finite acyclic graph reaches only leaf completions and declared literals. By the binding contract, each leaf completion denotes its declared semantic target; by the operator and codec contract, de-rived nodes cannot introduce factual inputs outside their declared predecessor semantics. Therefore every factual provenance path for x is contained in semantics authorized by Anc( s). This establishes Proposition 1. The result is a confinement property of the language and release discipline: dependency edges trans-port already admitted values, but do not grant authority over other semantics co-located in the same observation carrier. F.3 PROOF OF PURPOSE NONINTERFERENCE 

Let LS be the leaf ancestors of the declared sinks and suppose O1 ≡P O2. By definition, 

∀ℓ ∈ LS , Cℓ(O1) = Cℓ(O2).

We proceed by induction over a topological ordering of the sink-relevant subgraph. The base case holds for all leaves in LS . For an internal node v, all predecessor completions are equal under the induction hypothesis. Because activation guards and operator interpretation are deterministic functions of those typed predecessors, Cv (O1) = Cv (O2). The argument therefore reaches every declared sink, giving 

∀s ∈ S, Cs(O1) = Cs(O2).
