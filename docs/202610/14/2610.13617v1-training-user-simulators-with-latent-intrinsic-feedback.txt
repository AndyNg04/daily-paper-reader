# Training User Simulators with Latent Intrinsic Feedback 

Tarek Naous *1,2 , Craig Boutilier 1, Wei Xu 2 and Ofer Meshi 1 

> 1Google Research, 2Georgia Institute of Technology

User simulators are gaining attention as environments to train LLM assistants that can better cope with the nuances of multi-turn conversations with real users. Prior work on user simulation has emphasized generating realistic user utterances, leaving unexplored their potential as a source of direct feedback on the assistant’s responses. Such evaluation signals may not be explicitly communicated in language, but can instead reside in the latent reasoning of users. In this work, we introduce user simulators with intrinsic feedback , namely, models equipped with latent evaluation states : internal thoughts, reactions, and scalar ratings that evaluate the assistant from a first-person user perspective at each conversation turn. We train LLM-based simulators using interaction logs between real users and assistants and demonstrate that intrinsic feedback improves simulation realism and critiquing behaviors versus prompted simulator baselines, while also providing turn-level evaluations that existing fine-tuned simulators lack. Further, evaluations generated by our trained simulators correlate better with human judgments than those of prompted simulators of the same size. Lastly, our experiments reveal that simulators with intrinsic feedback provide effective reward signals for multi-turn RL training, matching setups that rely on external judge LLMs for rewards while cutting RL compute by more than half. 

1. Introduction 

AI agents are transforming the way people interact with digital platforms. Instead of doing tasks directly, users now spend ever-increasing time engaging in conversations with LLMs to get work done, unlocking new levels of productivity. According to Pew (Pew Research Center, 2026), the use of AI chatbots by U.S. adults has been on the rise, with about half reporting daily usage as of June 2026, and 38% using AI to complete tasks at work. Despite this wide adoption, recent work has highlighted shortcomings in how LLM assistants handle multi-turn conversations, such as making incorrect assumptions about unspecified details in earlier turns (Laban et al., 2026) or losing track of the user’s goals (Tack et al., 2026). In fact, analyses of user-assistant interactions by Baumann et al. (2026) show that users push back against AI assistants’ outputs 44% of the time through corrections and interruptions. To cope with such challenges, training user simulators that replicate the nuanced behavior of human users is gaining increased attention (Naous et al., 2026; Zhou et al., 2026a). Importantly, a key use of user simulators is to provide a realistic environment for multi-turn RL training of assistant LLMs (Abdulhai et al., 2025; Wan et al., 2026). Such RL training requires inferring the value created for the simulated user (e.g., degree of satisfaction) to provide a reward signal for the assistant. Yet, current simulators are trained primarily as utterance generators, requiring external judge models to estimate this signal from interactions (Suh et al., 2026). This is limiting, first, because external judges may poorly correlate with the subjective first-person user assessment (Dou et al., 2025; Meshi et al., 2026); and second, additional LLM-as-judge calls during training increase computational overhead significantly. A natural question thus emerges: can we build user simulators that provide direct evaluations of how well an assistant is serving them? 

To address this question, we propose user simulators with intrinsic feedback , which not only model what users say but also how they evaluate the assistant. A user’s evaluation of an assistant’s

For example, a user may recognize that a response is incomplete, but continue the conversation by reformulating or refining their request instead of pointing out the assistant’s failure (Yuan et al., 2025). Our objective is to train a user simulator that possesses two main capabilities. First, it should generate realistic user turns that align with the language distribution and behavior of real users. Second, the simulator must also produce per-turn evaluations of the assistant’s output from a user perspective that match real human evalu-ations. This is a key aspect that has been over-looked in past approaches to simulator training, which focused only on user utterance genera-tion, and where latent states were restricted to only thoughts that keep the simulator aligned with its goals. In contrast, we leverage latent states as an evaluative mechanism and propose simulators with latent evaluation states (LESs) .

• Rating: A score of 1 (bad) to 5 (perfect) that reflects the satisfaction rate of the user with the assistant’s output at the current turn.

3.2. Training Details Training Data. We use the WildChat-1M open-source dataset (Zhao et al., 2024), which contains one million interaction logs between users and ChatGPT. First, we select the non-toxic subset of 529,428 conversations filtered via the OpenAI Moderation API, and then restrict to English-language data, yielding 284,168 conversations. We further clean the data by performing deduplication, running a 10-gram counter on first-turn user prompts to discard samples containing repeated 10-grams. This removes many noisy, recurring prompt templates in the data that do not reflect real user interactions, resulting in 135,901 unique conversations. Lastly, we perform “decontamination” of the WildBench dataset (Lin et al., 2025), which was constructed using a subset of 2,004 WildChat conversations. We removed those samples since we later use WildBench in some of our evaluations. 

Latent Evaluation State Generation. For each conversation in the WildChat data, we generate LESs using Gemini3.1-Pro (Google DeepMind, 2026). LESs are generated starting from the second user turn, after the first assistant response has been generated, and for each subsequent turn. We provide Gemini with the conversation history up to the last user utterance, and instruct it to generate the LES as a JSON with the five sub-state components described above (see the prompt used, including full instructions and few-shot examples, in Appendix E). In total, we generate 238,636 LESs for conversations of two or more turns. 14.15% of LESs (33,776 turns) contain a Critique reaction from users while only 1.26% (3,001 turns) are labeled as Praise , with the remaining 84.59% Neutral .Additional statistics are provided in Appendix A. 

User Intent Generation. Following Naous et al. (2026), we also experiment with conditioning on a high-level user intent, reflecting their general conversational goal. This intent is conditioned on before the first user turn, making the trained simulator more steerable towards a desired task. For each of the 135,901 conversations in our training dataset, we generate a high-level intent by prompting Gemini3.1-Pro (see prompt in Appendix E). 

Data Splitting. We evaluate the feedback behavior of our LES simulators with a held-out test set from WildChat. To ensure sufficiently many evaluation samples contain critiques, we first sepa-rate conversations into those with at least one turn where the user critiqued the assistant (20,148 conversations), and those that do not. We then randomly sample 2,000 conversations from each set, creating a held-out set of 4,000 conversations that reflect a mix of user reactions: 5,888 turns have a neutral user reaction, 3,464 turns where the user critiques the assistant, and 132 where the user

4. Evaluating the Feedback Behavior of User Simulators 

4.1. Evaluation Setup 

To evaluate the alignment of simulator feedback with that of real users, we use the held-out test set of 4,000 conversations with mixed user reactions(Sec. 3.2). For each user turn where a ground-truth LES is present (9,484 turns), we condition the simulator on the conversation history up to that turn and generate a response. We compare the simulator-generated responses to ground-truth user responses w.r.t. both feedback and realism. 

Metrics for Feedback Behavior. To assess whether a simulator critiques the assistant at times similar to real users, we run a Gemini3.1-Pro judge on simulator-generated responses to classify reactions as “critiquing” or not (see the judge’s prompt in Appendix E). We consider turns with either 

Neutral or Praise reaction types in ground-truth data to be non-critiquing (the latter is very infrequent in the data). We then compute a binary F1 score (Critique/Non-Critique) to measure how closely a simulator’s critiquing behavior matches that of real users. We also measure how well simulator ratings (1-5 scale) correlate with ground-truth data using Spearman rank correlation.

4.2. Main Results 

Table 1 summarizes results comparing our trained simulators to the baselines, all using intent conditioning, on the held-out WildChat test set. We make the following observations: 

Latent evaluation states improve feedback behavior. The Gemma3 simulators trained with LESs perform much better than prompted Gemma3 baselines of the same model size, achieving higher F1 scores and rating correlations. The rating correlation of our largest Gemma3-27B-LES simulator is close to that of the prompted Gemini3.1-Pro, a model of a larger size. 1 Rating correlations also show consistent improvements with model scaling going from 4b to 27b. Interestingly, the Gemma3 simulators trained via SFT without latent states achieve slightly higher F1 scores than those trained with LESs. This difference is mainly due to a drop in recall when simulators are trained with latent thoughts, which can cause them to be more careful when initiating a critique (see precision and recall results in Appendix C). However, we note that SFT simulators are pure utterance generators and do not provide latent information such as ratings. Indeed, in Sec. 5, we show that this latent information is hihgly valuable for training assistants, making SFT simulators less practically useful than LES simulators. 

Latent evaluation states improves simulation realism. Across all model sizes, simulators trained with LESs achieve better realism scores than the prompted simulator baselines, with greater statistical alignment with ground truth user turns and lower PPL values. Improvements are also observed over the SFT baseline simulators in most cases, showing how LESs can also help improve realism in trained simulators.

4.4. Correlation with real human ratings 

The rating correlations computed on held-out test data above use an LLM judge’s estimates of user ratings in WildChat conversations. To better evaluate how ratings produced by simulators correlate with actual human judgments, we apply the same analysis to the SimulatorArena dataset (Dou et al., 2025). SimulatorArena consists of 909 conversations between humans and LLM assistants, focused on math tutoring and document creation tasks, where these users provide a conversation-level rating of the LLM’s performance. At the end of each assistant turn, we condition the simulators on the past conversation history and generate turn-level rating evaluations. We average the per-turn simulator ratings and compute the correlation between this average and the ground-truth human rating. Results in Table 4 show that ratings generated by our LES simulators are better correlated with human judgments than those of prompted baselines, a finding that holds across all model sizes. 

5. Training LLM Assistants with Simulators via Multi-Turn RL 

One critical use of user simulators is offline training of LLM assistants to improve their performance prior to exposing them to real users. This requires not only that simulators reflect realistic user behavior, but that they also provide reasonable signals upon which to assess performance. We hypothesize that LES-based simulators, due to their explicit, per-turn, first-person assessment of assistant responses, can offer value for such training. To test this hypothesis, we train an LLM assistant via multi-turn RL using different simulator choices (prompted simulator vs. our LES simulator) and reward sources (intrinsic simulator reward vs. external judge reward) to serve as the RL environment. We then compare the performance of the assistant after RL training in each setup. 

5.1. Multi-turn RL Experimental Setup Dataset. We use WildChat-4.8M for RL training, an expanded version of the WildChat-1M dataset used above. We apply the same filtering and deduplication procedure to remove overlapping conversations. From the resulting dataset, we randomly sample 100k conversations. For each conversation, we use Gemini3.1-Pro to generate a user intent, which serves as the initial user input for multi-turn rollouts between the simulator and assistant during RL training.

RL Training. We use Qwen2.5-1.5B-Instruct as the LLM assistant and further train it using RL with the Gemma3-4B-LES , Gemma3-4B-IT , and Gemma3-4B-SFT user simulators as the en-vironment. For each data sample, we condition on the user intent as a system prompt and the first ground-truth user turn, then generate multi-turn rollouts capturing interactions between the LLM assistant and the simulator. We use turn-level rewards during training and explore two ways of obtaining the reward: (1) using an external judge model (Qwen2.5-14B-Instruct) that assesses the assistant’s current output given the history so far, and (2) obtaining the reward intrinsically from the simulators without reliance on an external judge (generated as part of the intrinsic latent state for Gemma3-4B-LES, and by the Gemma3-4B-IT model in addition to the user response). In both setups, we train the assistant to maximize the average rating across conversation turns as its reward, using multi-turn GRPO (Shao et al., 2024). See Appendix D for implementation details. 

Evaluating the LLM Assistants. We adopt the procedure of Suh et al. (2026) to evaluate our trained LLM assistants, using WildBenchV2 (Lin et al., 2025), which contains 1024 multi-turn user task instructions with a task-specific checklist for each sample (comprising 10–12 fine-grained objective requirements) that can be used for evaluation. We condition the RL-trained LLM assistants on each instruction to generate a response. We then use a Gemini3.1-Pro judge to evaluate the response of the assistant, using the task-specific checklist to determine which requirements are satisfied. We report the checklist satisfaction rate across all samples.

Table 5 shows the checklist satisfaction rates on WildBenchV2. We report the average and standard deviation across three sampling runs for each model. We also compare to the LLM-assistant initial checkpoint before RL training. We make the following observations: 

LES simulators yield competitive assistants. All of the RL-trained models across all setups improve greatly over the performance of the initial checkpoint. Notably, models RL-trained with our Gemma3-4B-LES simulator achieve a higher mean checklist satisfaction rate than those trained with

Gemma3-4B-IT and Gemma3-4B-SFT. This suggests that the improved realism of trained simulators is important for training assistants that perform well on real-world user queries. These findings are consistent with those of Suh et al. (2026), whose approach is equivalent to our simulator-plus-external-judge baselines. 

Intrinsic rewards from simulators can exceed external judges. The assistants trained with intrinsic rewards from the simulators perform on par with or slightly better than those trained with rewards computed by an external judge. We observe this for both our trained LES simulator as well as the prompted baseline, although the differences are not large. The best overall performance is achieved by the assistant trained with intrinsic rewards from Gemma3-4B-LES. 

Training with intrinsic rewards is more computationally efficient. While the RL-training with intrinsic rewards offers some performance gains, these are relatively small when compared to an external judge (at least on the current datasets). However, just as importantly, RL training with intrinsic simulator rewards offers a significant advantage w.r.t. computational efficiency (since only one LLM inference run per turn is needed). Specifically, training an assistant using intrinsic rewards from a Gemma3-4B simulator requires an estimated 2 .45 × 10 19 total FLOPs, compared to 5 .48 × 10 19 total FLOPs when using rewards from the Qwen2.5-14B-Instruct judge (2.24 × more computation), which causes RL training to run much more slowly. We also note that a sufficiently large judge LLM is needed to efficiently perform RL training, as initial experiments with a smaller judge (Qwen2.5-3B-Instruct) led to minimal improvements (see results in Appendix C.3). 

6. Related Work 

User Simulation. As LLMs have shown performance gaps in multi-turn settings compared to their single-turn evaluations (Chang et al., 2025), developing realistic user simulators is becoming a key research focus for the evaluation and training of LLM assistants that perform better in live settings (Ni et al., 2026; Zhou et al., 2026a,b). Early work on user simulators focused on rule-based (Ie et al., 2019; Li et al., 2016) or neural-based systems (Shi et al., 2019; Tseng et al., 2021) for task-oriented dialogue in specific domains. More recently, pre-trained LLMs have opened up new directions for the generative simulation of users. A typical approach has been to prompt LLMs to role-play a user given a conversational history (Chopra et al., 2026; Li et al., 2024; Mehri et al., 2026b; Qin et al., 2025; Zhong et al., 2025; Zhu et al., 2025, 2026). While prompting-based approaches offer good controllability of the simulator’s behaviors, prompted simulators have been shown to lack realism and drift from real user behavior (Dou et al., 2025; Ivey et al., 2026; Mehri et al., 2026a), sparking interest in training methods for LLM-based user simulators (Meshi et al., 2026). 

Trained User Simulators. A standard training approach for user simulators has been to fine-tune a pre-trained LLM on flipped user-LLM interaction logs to generate user turns while conditioning on a user’s conversational intent to steer the simulator (Naous et al., 2026; Wang et al., 2025). Simulators trained this way often replicate human behavior better than prompted baselines (Wang et al., 2026), but are less controllable (i.e., more difficult to adapt to new user profiles or assistants). Several studies address this issue by training simulators with latent states in the form of reasoning traces that guide the simulator’s output (Wu et al., 2026b; Zhang et al., 2026), improving consistency of personality and goal adherence (Wei et al., 2026; Wu et al., 2026a), and adapting better to unseen assistant policies (Tennenholtz et al., 2026). Prior work has focused on training simulators that more closely match the language and behavior distributions of real users. We complement this research direction by introducing LESs into trained simulators, going beyond training only user utterance generation to produce per-turn evaluations of LLM assistants from a first-person perspective. Our experiments demonstrate that simulators trained with LESs offer better feedback behavior than prompted baselines 

> 10 Training User Simulators with Latent Intrinsic Feedback

while also achieving greater realism. 

Multi-Turn RL Training of Assistants with Simulators. Recent research has explored the training of LLM assistants using multi-turn RL with a simulator (Qian et al., 2025; Sun et al., 2025; Wu et al., 2025; Yu et al., 2026; Zhou et al., 2025). Most recently, Suh et al. (2026) perform multi-turn GRPO by simulating multiple assistant-simulator conversations and using an external LLM judge to determine a conversation-level reward for each trajectory. They find that training using fine-tuned rather than prompt-based simulators produces better-performing assistants. Abdulhai et al. (2025) use an external LLM judge to provide per-turn reward scores that attempt to reduce deceptive behavior by the assistant, while Wan et al. (2026) explore per-turn rewards that personalize the assistant’s output to different users. Our work can be distinguished from most past work by its use of explicit rewards obtained directly from the simulator via its latent evaluation states, rather than an external judge. Our results show that this provides a somewhat better RL training signal and, just as importantly, improves computational efficiency by eliminating the need for calls to external judges. 

7. Conclusion 

We introduced user simulators with intrinsic feedback via latent evaluation states , which go beyond user turn generation to evaluate LLM assistants in interactive settings. We showed that training with LESs produces simulators with better feedback alignment and greater realism than baseline approaches. Furthermore, we showed that LES simulators offer significant value when RL-training LLM assistants, driving high performance with lower computational cost. Such simulators are a critical component of future dynamic agent evaluation techniques and multi-turn training recipes for LLM assistants as we move away from traditional single-turn static setups.

D. Implementation Details 

Training User Simulators. Full parameter fine-tuning was performed on 8 H100 GPUs which required ∼88 GPU hours to train the Gemma3-12B model and ∼208 GPU hours for the Gemma3-27B model. 

RL Training of Assistant LLMs. We train the LLM assistant using GRPO (Shao et al., 2024) via the TRL library (von Werra et al., 2020) that we extended to support multi-turn rollout training. We use vLLM (Kwon et al., 2023) as the inference engine when generating rollouts. We perform multi-turn rollouts up to 2 additional turns from the initial ground-truth user turn, resulting in 3-turn conversational rollouts. Training was performed on 8 GPUs, where 7 were reserved for training the LLM assistant, and 1 was used a server for the simulator. For each sample, we generate 8 candidate rollouts to compute advantages in GRPO. We use a total effective training batch size of 56 rollout trajectories to update the policy and perform full-parameter finetuning using a learning rate of 5e −6.We also apply KL regularization using the KL3 estimator with a coefficient of 0.001. The maximum sequence length for generation was set to 1,024 tokens. We show the mean reward per step for all RL training setups (intrinsic vs. judge rewards for both Gemma3-4B-IT and Gemma3-4B-LES simulators) in Figure 3 which show an increase in the reward given to the trained assistant.
