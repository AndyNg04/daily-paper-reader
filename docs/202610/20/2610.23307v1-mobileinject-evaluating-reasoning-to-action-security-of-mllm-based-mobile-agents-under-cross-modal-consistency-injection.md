## 摘要
基于多模态大语言模型（MLLM）的移动智能体正迅速从对话助手演进为能够感知智能手机环境、进行推理并采取行动的自主系统。这种能力也带来了新的安全风险：攻击者可以在跨应用的移动内容中嵌入恶意目标，通过间接的多模态注入操控智能体行为。尽管桌面和 Web 场景中的提示注入已得到研究，但其在移动生态系统中的跨模态特性仍缺乏充分认识，现有安全分析也仍较为有限。为弥补这一空白，我们推出 MobileInject，这是首个用于评估移动智能体抵御多模态注入攻击能力及其推理到行动安全风险的基准。MobileInject 提供高保真交互式移动评测框架，涵盖 11 个场景、9 类安全风险和 108 个可执行风险实例。此外，该基准还提出跨模态一致性注入，以利用不同模态之间的相互印证；提出两种增强攻击方法——多角色协同欺骗和推理伪装注入，以加剧信任操纵和推理劫持；并构建推理安全诊断框架，以进行细粒度的失效分析。系统性实验表明，移动智能体普遍易受多模态注入攻击，且许多失效源于早期阶段的推理劫持。这些发现确立了 MobileInject 作为系统性跨模态基准的地位，可用于研究和提升移动智能体的安全性。代码发布详情见附录中的开放科学部分。

## Abstract
Multimodal large language model (MLLM)-based mobile agents are rapidly evolving from conversational assistants into autonomous systems that perceive, reason over, and act on smartphone environments. This capability also exposes a new security risk: adversaries can embed malicious objectives in cross-application mobile content and steer agent behavior through indirect multimodal injection. Although prompt injection has been studied in desktop and web settings, its cross-modal properties in mobile ecosystems remain poorly understood, and existing security analyses are still limited. To close this gap, we introduce MobileInject, the first benchmark for evaluating mobile agents against multimodal injection attacks and reasoning-to-action security risks. MobileInject provides a high-fidelity interactive mobile evaluation framework covering 11 scenarios, 9 security-risk categories, and 108 executable risk instances. It further introduces Cross-Modal Consistency Injection to exploit corroboration across modalities, two enhanced attack methods, Multi-Role Collaborative Deception and Reasoning-Camouflage Injection, to intensify trust manipulation and reasoning hijacking, and a Reasoning Security Diagnosis Framework for fine-grained failure analysis. Systematic experiments show that mobile agents are broadly vulnerable to multimodal injection, and that many failures stem from reasoning hijacking at early stages. These findings establish MobileInject as a systematic cross-modal benchmark for studying and improving the security of mobile agents. Code release details are provided in the Appendix Open Science section.

## 1. 核心问题与研究背景

### 1.1 从“生成错误回答”转向“执行危险操作”

- 基于多模态大语言模型（MLLM）的移动智能体，已经能够读取界面、跨应用导航、输入文字、管理文件和执行交易等。
- 这些能力构成“**感知—推理—行动—状态变化**”闭环，也放大了间接提示注入的后果：
  - 攻击者不必修改用户指令，只需把恶意内容放在短信、邮件、网页、日历等环境载体中。
  - 智能体可能把这些内容误当成新的任务、用户授权或高优先级指令。
  - 最终风险不只是有害文本，还可能包括隐私泄露、未授权操作、数据破坏与财务损失。

### 1.2 移动场景的特殊性

- **跨应用、动态且有状态**：攻击可能出现在不同应用、不同执行阶段，操作结果也会持续保留。
- **视觉与结构化文本并存**：同一界面的恶意内容，可能同时出现在截图和 UI/XML、无障碍树中。
- **与敏感资源紧密连接**：手机往往关联联系人、身份信息、私人文件和支付能力。

论文关注的关键问题是：**同一恶意指令在不同模态中相互印证，是否会增强攻击？恶意目标如何从可见推理说明传播到实际行动？**

## 2. 方法论：核心思想与技术流程

### 2.1 威胁模型：可信指令与不可信观察分离

论文将系统指令和真实用户任务视为可信来源，将环境观察视为潜在不可信输入。

- 攻击者可以操纵截图内容、消息、网页、UI/XML 文本及部分界面元数据。
- 不能修改系统提示、模型参数、操作系统或真实用户指令。
- 攻击目标是在正常任务执行过程中，让智能体采纳并执行外部恶意目标。

因此，安全边界的核心是：**环境内容可以提供信息，但不应自动获得指令权限。**

### 2.2 跨模态一致性注入：CMCI

CMCI 将**相同恶意指令**分别放入：

1. 视觉观察，如截图中显示的消息；
2. 文本观察，如对应 UI/XML 节点；
3. 或同时放入两个通道。

其形式化思想是：在原始视觉与文本观察中，分别叠加承载同一恶意指令的载荷，并要求两侧注入内容一致。

论文提出的解释是：

- 视觉通道使指令显得属于当前真实界面；
- 文本通道使其更容易被直接读取并转化为动作；
- 二者一致时，可能促使智能体把攻击者目标提升为当前任务。

为排除“只是重复两次”的解释，作者增加了**单通道重复两次**与**两个通道各呈现一次**的等曝光对照。

### 2.3 两种增强攻击

| 方法 | 核心机制 | 测试的安全薄弱点 |
|---|---|---|
| **MRCD：多角色协同欺骗** | 在外部内容中组合伪装的权威、用户目标、同意确认、紧急性与理由 | 智能体是否把环境中的角色化文本误当成可信授权 |
| **RCI：推理伪装注入** | 用“当前应用上下文—正常任务衔接—恶意下一步”的伪推理组织载荷 | 智能体是否把恶意目标当成当前任务的合理延续 |

需要注意，RCI 注入的是**外部可见的伪推理文本**，并非直接改写模型内部推理状态。

### 2.4 执行与验证流程

每个实例依次经过：

1. 选择正常任务与攻击目标；
2. 恢复 Android 快照并初始化应用状态；
3. 在指定模态和载体中注入内容；
4. 执行最多 **20 个动作**，记录观察、模型输出的推理说明、动作、目标与状态；
5. 每步运行正常任务与恶意目标的两个状态判定器；
6. 对轨迹进行细粒度诊断。

当正常任务完成、恶意目标完成、智能体声明失败或动作预算耗尽时，回合结束。

### 2.5 推理安全诊断框架：RSDF

RSDF 将**实际状态验证**与**轨迹语义诊断**分开：

- 状态判定器验证正常目标、恶意目标是否完成。
- 独立语义评估器结合规则、冲突检查与自动裁决，对每步进行标注：
  - 是否明确识别注入风险；
  - 输出的推理说明是否采纳恶意目标；
  - 动作是否实质推进恶意目标。

主要指标包括：

| 指标 | 含义 |
|---|---|
| UC / UA | 无攻击 / 有攻击时的正常任务完成率 |
| AGR | 恶意目标实际完成率 |
| SAR | 至少一次明确识别注入风险的回合比例 |
| RHR / AHR | 出现推理说明劫持 / 行动劫持的回合比例 |
| RHOR / RHD | 劫持出现的相对位置 / 出现后的持续深度 |
| OCM | 正常目标与恶意目标完成情况的四种组合 |
| RATM | 安全对齐、仅行动偏移、推理受损但行动受约束、完全劫持等逐步状态分布 |

辅助综合分数 **OSS** 对低攻击成功率、风险意识、低推理劫持率和低行动劫持率加权求和。其权重属于人为设计，应优先结合分项指标解读。

因此，可以估算主要评测回合数量，但不能据此可靠估算总算力与复现成本。提供的正文也未给出可直接核验的代码仓库地址。

## 5. 实验数量与充分性

### 5.1 大致规模

- 主实验：**2 个框架 × 9 个模型 × 108 个实例 = 1,944 个执行回合**。
- 此外还有模态消融、MRCD/RCI 消融、匹配对照、防御实验和重复运行。
- 防御表包含无防御基线与五种防御，每个展示条件均有 108 个实例；但这些基线可能与主实验重用，不能直接全部相加。
- 部分关键匹配实验仅在 **Gemini-2.5-Flash 的四种主要工作流**上进行。

**论文未汇总全部独立运行的总数，因此总实验量不宜给出精确数字。**

### 5.2 充分性与公平性评价

**较充分之处：**

- 多模型、双框架设计优于单模型案例研究。
- 同时比较正常效用和攻击成功率，避免把“什么都做不成”误判为安全。
- 等曝光与预算匹配对照，减少了长度、重复和显著性等混杂因素。
- 使用真实应用状态验证结果，而不是仅依赖模型自述。
- 作者承认实例间存在依赖，部分比较使用聚类配对推断。

**仍需保留判断之处：**

- 108 个实例复用了工作流和攻击目标，**不等于 108 个独立语义样本**。
- 严格匹配对照未全面覆盖全部模型与框架。
- 多数条件主要报告点估计，不能据此认定所有性能差异具有统计显著性。
- 提示防御的主要详细结果集中于一个高脆弱性配置，防御结论的普遍性有限。

## 6. 主要结论与发现

### 6.1 当前移动智能体普遍脆弱，但差异很大

| 框架 | 平均正常任务完成率 UA | 平均攻击成功率 AGR | 平均推理劫持率 RHR | 平均行动劫持率 AHR |
|---|---:|---:|---:|---:|
| MobAgent | 17.59% | 51.13% | 75.31% | 70.78% |
| M3A | 11.11% | 50.31% | 80.86% | 67.59% |

在 MobAgent 下：

- Gemini-3-Flash：UA **54.63%**、AGR **24.07%**；
- GLM-4.5V：UA **0.93%**、AGR **83.33%**。

但排名依赖框架，不能把某一配置的表现直接视为模型固有安全水平。

### 6.2 低攻击成功率不必然代表安全

- GLM-4.6V 在 M3A 下的 AGR 只有 **14.81%**；
- 但 UA 为 **0%**，RHR 达 **77.78%**。

这说明攻击可能因为操作失败而未完成，而不是智能体真正抵抗了恶意目标。

### 6.3 跨模态一致性增强攻击，不能仅用重复解释

在四种工作流的等曝光实验中：

- 文本单次曝光 AGR：**68.8%**；
- 文本重复两次：**72.9%**；
- 视觉重复两次：**27.8%**；
- 跨模态各一次：**85.4%**，UA 为 **0%**。

另有 **30/108** 个配对实例呈现：两个单模态条件均未成功，但一致跨模态条件成功。

### 6.4 推理说明与行动偏移经常共同出现，且劫持持续性较强

- 多数模型的推理劫持率高于最终攻击成功率。
- GLM-4.5V 在 MobAgent 下，RHR 与 AHR 均为 **98.15%**，RHD 达 **100%**。
- 这些结果支持：一旦采纳恶意目标，部分智能体在后续步骤中很少恢复正常任务。

不过，这些指标受到结果约束标注机制影响，不能完全视为独立的内部推理因果证据。

### 6.5 增强攻击有效，提示级防御不足

- 加入 RCI 后，六种基础攻击的 AGR 增加 **5.6—16.7 个百分点**。
- 预算匹配基线的 AGR 为 **70.83%—77.08%**，完整增强条件达到约 **85.4%**。
- SCoT 将一个配置的 AGR 从 **83.33%** 降至 **70.37%**，但风险仍高。
- 该防御差异的聚类区间跨零，Holm 校正后 **p = 0.486**，因此不能宣称其改善具有可靠统计显著性。
- 部分防御虽然拒绝恶意行为，也未完成正常任务，存在安全—效用权衡。

## 7. 优点与亮点

- **评测贴近实际执行**：使用动态、有状态、可重置的移动环境，而不是只测静态提示。
- **突出移动端特有的双通道攻击面**：直接研究截图与 UI/XML 的同步注入。
- **机制对照较细致**：通过等曝光和预算匹配，检验增益是否仅来自更多文字或更显眼的载荷。
- **结果验证可靠性较高**：以应用和设备状态作为最终完成依据。
- **兼顾安全与任务能力**：明确指出低攻击成功率可能只是执行能力不足。
- **诊断维度丰富**：不仅判断最终成功与否，还定位风险识别、目标采纳、行为推进和持续劫持。
- **具有一定统计自觉**：承认样本依赖，并披露防御改善不显著和运行归档标签问题。

## 8. 不足与局限

### 8.1 “推理劫持”测量存在可观察性边界

- RSDF 分析的是模型**输出的推理说明**，不等于直接观察模型内部计算。
- 输出文本可能遗漏真实决策依据，也可能是事后解释。
- 因此，更准确的结论是“可见推理说明与行动发生偏移”，而非完整揭示内部推理机制。

### 8.2 结果约束标注带来循环性风险

诊断管线规定：恶意目标一旦完成，就必须包含行动劫持标签；若存在推理说明，还要补足推理劫持标签，并采用结果相关的持续性处理。

- 优点是减少标签与实际结果冲突。
- 代价是 RHR、AHR、RHD 及推理—行动耦合指标，并非完全独立于最终攻击结果。
- 因而，“推理劫持紧密传播到行动”的统计关系，可能部分受到标注规则强化。

更有说服力的补充应是：报告不使用结果约束的盲标结果、人工一致性及约束前后指标变化。

### 8.3 场景数量有限，外部泛化尚未充分验证

- 108 个实例主要由有限工作流和注册攻击目标组合形成。
- 尚不足以覆盖不同手机品牌、系统版本、界面语言和应用生态。
- 模拟器与模拟交易不能完全代表真实支付、身份验证和权限交互。
- 20 步预算及命中判定器即停止的设计，限制了对长期潜伏、延迟触发和事后恢复的评估。

### 8.4 攻击权限与现实可部署性需进一步对应

- 控制短信正文与控制任意 UI 元数据，需要的现实权限并不相同。
- 分别修改截图与 UI/XML 有利于模态消融，但不一定对应普通内容攻击者能自然实现的操作。
- 应进一步区分“环境观察级压力测试”与“真实第三方内容发布者可实施攻击”。

### 8.5 防御覆盖与统计证据仍有限

- 主要测试提示级防御，未系统比较权限隔离、动作审批、来源追踪、执行沙箱或独立安全验证器。
- 关键匹配实验集中在单模型、部分工作流，不能直接推广到全部配置。
- 稳定性分析的重复次数和覆盖范围有限；少量种子下方差较小，不等于已经证明跨模型、跨场景稳定。
- 自动语义诊断所用模型、人工核验及误差评估，在提供文本中交代不足。

### 8.6 综合分数与复现信息需谨慎使用

- OSS 权重人为设定，且不直接纳入正常任务完成率，不能替代安全—效用联合评价。
- 算力、调用成本与部署参数缺失，增加复现和成本比较难度。
- 提取文本个别位置混用了 AGR 与 RHR/AHR 的表述，应优先依据表格和正式指标定义解读。

**总体评价**：MobileInject 的突出价值是建立了“跨模态不可信观察—目标采纳—动作执行—状态后果”的系统评测路径。跨模态一致性增强攻击的受控证据较有说服力；对于内部推理因果机制、诊断指标独立性，以及真实手机生态中的普遍风险，则仍需更广泛、独立的验证。
