## 摘要
浏览器智能体通过读取任意网页内容并采取相应操作，实现复杂工作流的自动化；然而，这种灵活性也使其容易遭受提示注入攻击和非预期的数据外泄。近期研究指出，由大语言模型驱动的浏览器智能体会削弱同源策略（Same-Origin Policy，SOP）等传统 Web 安全边界：智能体以用户权限跨源操作，且缺乏内置隔离机制。我们认为，恢复 SOP 对保护用户安全而言既非充分条件（同源的公共数据接收端仍可能泄露私密数据），也非必要条件（合法任务需要经过授权的跨源数据流）。我们提出 SPIDES，通过根据信息流标签控制浏览器的基本操作（如输入、点击和导航）来实施信息流控制；这些标签由 HTML 元素级的机密性与完整性标注传播而来。系统会在智能体上下文中屏蔽不可信和机密内容，并通过策略阻止未经授权的信息流，从而针对提示注入和数据外泄提供安全保障，且该保障不依赖于驱动智能体的模型。为在统一威胁模型下评估 SPIDES 和基线防御方法，我们构建了 MicroNet：一个由 28 个相互链接网站组成的封闭生态系统，提供元素级真实标签以及成对的良性／对抗性任务。SPIDES 通过设计实现了 0% 的攻击成功率，同时保持较高的任务完成率和自主性。我们的研究结果表明，信息流控制是一种将 Web 安全扩展至浏览器智能体的有效技术；相较于当前最先进的基线方法，它在自主性和实用性方面表现更优。源代码和数据已公开发布于 https://github.com/microsoft/SPIDES。

## Abstract
Browser agents automate complex workflows by reading and acting on arbitrary page content, but this flexibility exposes them to prompt injection attacks and unintended data exfiltration. Recent work argues that LLM-driven browser agents erode traditional web security boundaries such as the Same-Origin Policy (SOP) by acting across origins with the user's authority and no built-in isolation. We argue that restoring SOP is neither sufficient (a same-origin public sink can leak private data) nor necessary (legitimate tasks require authorized cross-origin flows) for protecting the security of users. We propose SPIDES, which instead enforces information-flow control by gating primitive browser actions such as typing, clicking and navigating on labels propagated from element-level HTML confidentiality and integrity annotations. Untrusted and confidential content is masked from the agent's context, while policies block unauthorized flows, providing security guarantees against both prompt injection and data exfiltration that hold independently of the model driving the agent. To evaluate SPIDES and baseline defenses under a common threat model, we build MicroNet, a closed ecosystem of 28 interlinked websites with element-level ground-truth labels and paired benign/adversarial tasks. SPIDES achieves 0% attack success rate by design while retaining high task completion rate and autonomy. Our findings demonstrate that information-flow control is an effective technique to extend web security to browser agents, gaining on autonomy and utility against state-of-the-art baselines. The source code and data are openly accessible at https://github.com/microsoft/SPIDES.

# SPIDES：面向浏览器智能体的信息流控制——论文总结

## 1. 核心问题与研究背景

### 1.1 浏览器智能体带来的安全问题

浏览器智能体能够使用用户的登录会话，在多个网站之间读取、复制信息并执行操作，但这也使网页中的恶意内容有机会影响其决策。论文关注两类风险：

- **完整性攻击**：不可信网页内容诱导智能体执行未经授权的操作，例如购买商品、修改账户或转账。
- **机密性攻击**：诱导智能体把邮件、账户信息等私密数据发送给未经授权的接收方。

问题的本质是：**智能体同时接触不同信任等级的数据，却拥有统一的用户操作权限，容易把“不可信数据”误当成“操作依据”。**

### 1.2 为什么仅恢复同源策略不够

论文认为，同源策略（SOP）不应成为浏览器智能体的主要安全边界：

- **并不充分**：同一网站可能同时包含私信、公开个人资料和恶意用户评论，同源流动仍可能造成泄密或越权操作。
- **也非必要**：合法任务经常需要跨站流动，例如从购物网站收集商品信息，再整理到笔记网站。

因此，安全判断应关注“数据是否可信、允许谁读取、是否影响了高风险操作”，而不只是“是否跨源”。

### 1.3 整体意义

SPIDES 将防护重点从“让模型识别并拒绝恶意指令”，转向**在模型之外确定性地约束信息流和工具执行**。其安全性不依赖模型抵抗提示注入的能力，但依赖正确标签、可信执行框架及明确的网页行为假设。

## 2. 方法论：元素级标签、上下文隔离与动作检查

### 2.1 核心思想

SPIDES 结合信息流控制（IFC）与双模型隔离模式：

1. 网站运营者对 DOM 元素添加完整性、机密性标签。
2. 系统把标签传播到智能体读取的网页快照。
3. 默认用符号变量隐藏会降低上下文安全等级的内容。
4. 在执行输入、点击、导航等动作前，检查信息流是否符合策略。
5. 违反策略的操作需要用户批准；任意代码执行工具默认阻止。

### 2.2 标签体系与传播

每项数据具有标签 \((I,R)\)：

- **完整性 \(I\)**：`Trusted` 或 `Untrusted`，表示内容是否可信。
- **读者集合 \(R\)**：允许读取该数据的用户与网站源。
  - `Public` 表示所有源均可读取。
  - 非公开数据可以只允许用户和指定网站读取。

标签通过 HTML 属性提供，并允许子元素继承祖先标签。对于用户未列为可信的网站，系统忽略其自报标签，统一视为“不可信、公开”。

智能体上下文也维护标签，初始为“可信、公开”。一旦读取更受限制的数据：

- 读取不可信内容后，上下文变为不可信；
- 读取机密内容后，上下文读者集合缩小为原集合与数据读者集合的交集。

**上下文限制只会收紧，不会自动恢复。** 生成的工具调用和参数也继承上下文标签，以保守覆盖潜在的信息影响。

### 2.3 内容隐藏与双模型处理

会进一步限制当前上下文的内容，被替换为 `[var_id]` 等不透明变量。系统提供两种处理方式：

- **`quarantined_llm`**：隔离模型读取变量原值，但没有工具执行权限；结果保存为新的带标签变量，而非直接暴露给主模型。
- **`inspect_variable`**：主模型显式查看变量，其上下文同步受到该变量标签约束。

这样既能处理不可信或机密文本，又不必让主模型过早接触这些内容；确实需要依据内容作决策时，则显式承担后续动作限制。

实现上，作者修改 Playwright 的快照生成过程，保留不同 DOM 来源的标签，避免多个元素合并成一个 ARIA 节点时，把恶意评论错误地标为可信。

### 2.4 两项核心安全策略

- **可信动作策略 \(P_T\)**：
  - 具有用户账户权限的潜在重要操作，不能受到不可信上下文或参数影响。
- **许可流策略 \(P_F\)**：
  - 目标网站必须同时属于上下文和参数数据的授权读者集合。

对于仅发送数据、但不被视为重要操作的工具，采用：

\[
P_T \lor P_F
\]

即：操作没有受到不可信数据影响，或数据发送给了授权目标，满足其一即可执行。

这里采用的是**稳健解密（robust declassification）**：允许未受攻击者影响的可信决策把数据发送到原读者集合之外。因此，论文的机密性保证**不是“任何私密数据都绝不越出读者集合”**，而是“越界披露不能受到不可信信息影响，除非用户批准”。

### 2.5 浏览器工具如何执行策略

| 工具类别 | 策略 |
|---|---|
| 只读观察，如快照、已有网络记录 | 始终允许，但返回内容仍需标记和隐藏 |
| 面向可信源的点击、导航、提交等潜在重要动作 | 要求 \(P_T\) |
| 面向不可信源的上述动作 | 要求 \(P_T \lor P_F\) |
| 填表、选择选项、不提交的输入 | 要求 \(P_T \lor P_F\) |
| 任意代码执行 | 始终阻止 |

系统假定用户只在可信源拥有账户，因此保守地把面向可信源的重要动作视为可能使用用户权限，而不精确追踪登录状态。

## 3. 实验设计与 Benchmark

- **28 个互联网站源、470 个网页**；
- 其中 **16 个可信源**，包含所有用户持有账户的网站；

**良性任务共 56 个：**

- 同源任务 34 个、跨源任务 22 个；
- 数据无关任务 41 个、数据依赖任务 15 个。
- 数据依赖指的是：具体动作或参数的选择，需要根据执行时读到的数据决定。

**攻击场景共 56 个：**

- 完整性攻击与机密性攻击各 28 个；
- 同源攻击 26 个、跨源攻击 30 个；
- 指令注入 50 个、数据注入 6 个；
- 攻击来源覆盖恶意网站、可信网站上的用户内容、第三方 iframe。

### 3.2 对比方法与模型

比较五种配置：

1. **Vanilla**：不添加信息流防御。
2. **SPIDES**。
3. **SOPGuard**：主要检查跨源数据流，必要时请求批准。
4. **UCM**：隐藏不可信内容，隔离模型只返回受限类型的明文结果。
5. **UCM+**：作者扩展的基线，允许返回被隐藏的自由文本，但不支持主动查看变量。

使用五个模型：

主模型和隔离模型采用同一模型；各配置共用浏览器、执行框架和基准，每项评测重复五次。论文未实验比较相关工作中的 ceLLMate。

### 3.3 评价指标与攻击设置

主要指标包括：

- **TCR**：任务完成率；
- **ASR**：攻击成功率；
- **TCR@k**：最多允许 \(k\) 次人工批准时的完成率；
- Token、调用次数及估算费用。

论文采用最坏情形的“拜占庭攻击者”模型：模型接触不可信输入后，攻击者可以控制其输出，而执行框架继续检查动作。

但实际实现有重要区别：

- **指令注入**：可将模型输出替换成固定恶意工具调用序列。
- **数据注入，以及难以预先枚举的隔离模型查询**：没有全面替换模型响应，而是使用攻击载荷和模型实际响应。

因此，**威胁模型比实际实验中所有场景都实现的攻击控制能力更强**，两者应区分理解。

## 6. 主要结论与发现

### 6.1 安全性

- SPIDES 在五个模型上均取得 **0% ASR**。
- **UCM+ 也在该攻击集上达到 0% ASR**，因此零攻击成功率并非 SPIDES 独有。
- SOPGuard 的 ASR 为 **53.2%–73.2%**，说明仅限制跨源流动无法覆盖同源和完整性攻击。
- UCM 总体 ASR 为 **4.6%–6.8%**，但在数据注入场景中达到 **43.3%–63.3%**，暴露了将隔离模型结果直接作为明文决策依据的风险。

### 6.2 效用与自主性

- SPIDES 良性任务完成率为 **67.1%–86.1%**，在每个模型上均高于 UCM 和 UCM+。
- 部分模型上，隐藏敏感附件减少了模型安全过滤造成的拒绝，使其完成率反而高于 Vanilla。
- 在统一安全保证、较低人工批准预算下，SPIDES 总体表现更优；论文报告，最多允许八次批准时，其完成任务数在各模型上均超过 SOPGuard 和 UCM。
- 默认配置下，SPIDES 每个成功任务平均需要 **1.84 次批准**，高于 SOPGuard 的 **0.22 次**；但 SOPGuard 的攻击成功率也明显更高，不能只按审批次数比较优劣。

### 6.3 结论的适用范围

结果支持：**细粒度信息流约束能够在受控环境中兼顾安全与任务能力。**

但“0% ASR”应理解为：在论文的标签、工具语义、可信组件和审批假设下，评测攻击均被阻止；不等于对任意真实网站和攻击的无条件保证。

## 7. 主要优点

- **安全边界更贴近真实需求**：区分可信与不可信内容、公开与私密数据，而不是简单阻止跨站操作。
- **不依赖模型自律**：恶意工具调用仍必须通过外部策略检查。
- **允许受控查看隐藏内容**：比完全不允许主模型接触数据更适合数据依赖任务。
- **实现考虑细致**：处理 DOM 到 ARIA 快照时的标签合并问题，避免底层表示转换破坏安全性。
- **兼顾安全、效用、自主性和费用**：没有仅凭低 ASR 宣称成功。
- **提供可复现基准与代码**：MicroNet 同时覆盖多种攻击源、流向和攻击目标。

## 8. 不足与局限

### 8.1 强依赖标签与可信源配置

- 网站运营者需要持续维护元素级标签，动态内容和第三方组件会增加成本。
- 可信源未标注元素默认“可信、公开”，漏标可能直接造成保护缺失。
- 误把恶意网站加入可信列表，可能使其恶意标签被信任；反之，漏掉用户实际拥有账户的网站，也可能导致错误分类。
- 论文认为标注成本类似无障碍信息，但未以真实网站部署研究验证这一判断。

### 8.2 接收方粒度仍偏粗

- 读者集合以网站源为单位，不能完整区分同一网站内不同用户、群组和公开受众。
- 因此，仍可能允许某些同源泄露。
- 论文的“私密恢复邮箱写入公开简介”案例，主要依靠阻止最后的保存动作保护，而非机密性策略本身识别了公开受众。

### 8.3 工具语义与网站行为假设较强

- 系统把未提交的输入和选项选择视为仅发送数据，假设它们不会直接触发重要操作。
- 现实网页可能存在自动保存、即时提交或事件驱动操作，需要重新验证这些分类。
- 主要检查工具调用的直接目标，后续脚本和后端流动依赖网站自身安全机制，而非由 SPIDES 全程追踪。
- XSS、供应链入侵等破坏 DOM 完整性的攻击不在其保护范围。

### 8.4 真实部署与评测外推有限

- 只验证基于可访问性快照的文本浏览器智能体，未覆盖视觉智能体、截图中文字、文件上传等更广泛能力。
- 使用作者自建的合成网站与标签，可能存在基准适配偏差，缺少真实网站上的独立验证。
- 缺乏真实用户审批实验，未衡量审批疲劳、误批准和实际交互时间。
- 上下文标签持续收紧可能造成后续审批增加；隔离调用也提高推理费用。
- 未提供完整组件消融、标签错误鲁棒性测试及更大规模的数据注入评估。

**总体评价：SPIDES 的主要贡献，是把已有的信息流控制思想落实到通用浏览器工具和元素级网页内容上，提出了清晰、可执行的安全框架。其受控实验结果有说服力，但实际效果仍受标签可靠性、网站行为假设和人工审批质量制约。**
