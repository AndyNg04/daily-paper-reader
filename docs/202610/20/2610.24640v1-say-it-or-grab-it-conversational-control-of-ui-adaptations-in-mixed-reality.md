## 摘要
混合现实界面必须根据用户不断变化的任务和环境持续调整，但适配策略通常预先固定，或由系统预设，或由用户配置。自然语言提供了一种在任务进行中表达需求变化的方式，但用户能否借此描述界面行为，以及相较于直接操控有何优势，尚不明确。我们首先考察了用户如何用语言表达适配需求（N=19）。随后，我们构建了 ConverseMR：该系统将口头请求转化为适配目标与约束，并在用户情境变化时持续满足这些目标与约束。在一项被试内研究中（N=24），对话式控制与直接控制展现出互补优势：直接操控更精确，ConverseMR则在触及范围和表达广度方面更具优势，而两者结合获得了最高评价。口头指令很少是最终指令；用户体验到结果后，往往会进一步完善或替换指令。这体现了一种我们称为“用户主导适配”的模式：用户表达适配需求，由系统确定解决方案。

## Abstract
Mixed reality interfaces must continuously adapt to a user's changing task and environment, yet adaptation policies are fixed in advance, either preset by the system or configured by the user. Natural language offers a way to state changing needs mid-task, but whether users can express interface behavior this way, and what it gains over direct manipulation, is unknown. We first elicited how users verbalize adaptation needs (N=19). We then built ConverseMR, which translates a spoken request into adaptation objectives and constraints and satisfies them continuously as the user's context changes. In a within-subjects study (N=24), conversational and direct control proved complementary: direct manipulation for precision, ConverseMR for reach and expressive breadth, with their combination rated highest. Spoken commands were rarely final and users frequently refined and replaced them upon experiencing the result, characteristic of, what we call, user-led adaptation, where users communicate adaption needs and the system identifies a solution.

# 论文总结：混合现实中界面适配的对话式控制

## 1. 核心问题与研究背景

### 1.1 论文研究什么？

论文研究：**用户能否通过自然语言，在任务进行中指定和修改混合现实（MR）界面的持续适配行为？这种方式与直接操控相比有什么优势，二者如何配合？**

这里的“适配”不仅是把窗口移动到某个位置，还包括持续生效的行为规则，例如：

- 让操作面板跟随身体或头部移动；
- 将说明界面固定在某个物体上方；
- 保持界面可见、可触达，并避免遮挡现实任务；
- 在特定条件下显示、隐藏或移动界面。

### 1.2 为什么需要研究？

MR 界面没有固定屏幕，用户的位置、任务与环境持续变化，因此界面必须不断调整。既有方案主要存在两类问题：

- **系统自动适配**：设计者预设目标，由系统推断需求，但容易误判用户意图，损害可预测性与控制感。
- **用户手动配置**：通过拖拽和菜单设置行为，虽然直接、明确，却需要占用双手、注意力和时间。

论文探索二者之间的第三条路径：**用户决定“界面应该如何表现”，系统负责计算并持续执行具体方案。**作者将其称为“用户主导适配”（user-led adaptation）。

## 2. 方法论：核心思想与技术流程

### 2.1 总体思路

论文采用“**需求探索 → 系统构建 → 对照用户研究**”的研究路线，构建了对话式适配系统 **ConverseMR**。

其关键区别在于：自然语言不是只触发一次移动操作，而是被转化为**持续有效、可以迭代修订的适配策略**。

### 2.2 形成性研究与设计要求

作者先开展了 **19 人形成性研究**，在三种移动条件下收集了 **57 条需求描述**，归纳出十类主题，如空间参照、界面召回、锚定、可见性、人体工学与条件触发。

由此提出五项设计要求：

1. **组合指令**：一条话语可以同时包含多个目标、参照、行为和约束。
2. **情境化指代解析**：理解界面、身体部位、环境物体，以及“它”“刚才那个”等表达。
3. **持续与条件行为**：将指令视为长期规则，并根据姿态、移动或任务状态触发执行。
4. **处理不完整表达**：适当补全参数，仅在解释不确定且可能产生不良后果时追问。
5. **修订与透明反馈**：支持追加、替换、撤销，并说明系统实际理解和应用了什么。

### 2.3 ConverseMR 的四阶段流程

#### 第一阶段：语音输入

- 用户通过**双捏合手势**显式激活系统，避免持续监听造成误触发。
- 使用 **Meta Voice SDK** 将语音转成文本。
- 系统不专门改进语音识别模型，而是在后续阶段利用上下文恢复识别错误。

#### 第二阶段：意图提取

使用 **GPT-5.2，经 OpenAI Responses API 调用**，结合以下信息解析指令：

- 语音转写文本；
- 当前界面和环境物体的位置、边界等场景信息；
- 用户位置；
- 最近指令、对话历史及当前适配状态。

模型通过少样本提示与严格结构化输出，生成固定模式的 **JSON 中间表示**，包含：

- 目标界面；
- 适配目标与空间约束；
- 锚定对象、空间关系、距离和移动参数；
- 条件触发规则；
- 与旧策略合并或替换的方式；
- 解释置信度；
- 执行、澄清或撤销等控制信息。

**LLM 负责把语言翻译为结构化策略，具体空间执行由后端适配引擎完成。**

#### 第三阶段：意图验证

- 模型报告的解释置信度**高于 80%**时，直接应用策略，并提供文字和语音反馈。
- 置信度较低或存在多种解释时，先提出澄清问题。
- 不属于支持范围的请求不执行，并反馈原因。
- 用户可在观察结果后撤销或修改。

需要注意：这里使用的是 **LLM 自报置信度**，论文未充分证明其经过概率校准。

#### 第四阶段：持续执行与迭代修订

- 使用 **AUIT** 工具包，把结构化意图映射为带权目标、约束和参数，通过多目标优化持续调整界面。
- 每收到一条新指令，将旧指令对应权重乘以 **0.95**，逐步降低旧请求的影响，使近期需求获得更高优先级。
- 避免遮挡用户视野、保持界面朝向用户的目标始终启用。
- 用户体验结果后，可继续细化、替换或撤销策略，形成闭环。

论文没有提出新的模型训练算法；其主要技术贡献是**语言解释、策略管理与持续优化执行的系统整合**。

## 3. 实验设计、场景与对比基准

### 3.1 使用了什么数据与 benchmark？

论文**没有使用公开机器学习数据集或标准化 benchmark**，而是通过自建 MR 实验任务采集用户行为与评价。

数据包括：

- 形成性研究的 57 条需求描述；
- 主研究中的问卷、访谈、观察记录；
- 语音转写、结构化意图、执行与撤销日志；
- 主研究分析涉及的 **988 条语音指令**。

因此，其评估基准是**受控用户研究中的适配体验与行为表现**，而非模型排行榜成绩。

### 3.2 主研究设计

- **参与者**：24 人，21–31 岁。
- **设计**：被试内设计，每人体验三种方法。
- **试次数**：每种方法 6 次，共每人 18 次，合计 **432 个正式试次**。
- **时长**：每人约 90 分钟。
- **移动条件**：静止、半静止、持续移动，每种条件在每个方法区组内重复两次。

### 3.3 三种对比方法

| 方法 | 支持的操作 |
|---|---|
| **DM：直接操控** | 手部拖拽；通过菜单选择头部、躯干、手部或世界锚定，以及近、中、远距离 |
| **ConverseMR** | 仅通过自然语言控制适配，不提供拖拽 |
| **Combined：组合方式** | 同时提供对话、菜单与拖拽 |

DM 与 ConverseMR 的顺序进行了平衡；**Combined 始终最后进行**。

### 3.4 实验任务

实验采用主任务与两个次任务相结合的多任务场景：

- **钥匙任务**：查找指定钥匙并投递，说明界面需要视觉与手动交互。
- **视觉任务**：观察旋转形状，口头报告指定颜色的面数，不需要手动操作。
- **控制任务**：应对来电、音乐等模拟事件，需要短暂手动交互。

通过改变箱子布局和任务要求，诱发不同的移动、可见性和可触达需求。场景中的对象与界面附有标签，方便语言指代。

### 3.5 评价与统计方法

- 八项 7 点量表：需求满足、易用性、舒适度、控制感、可预测性、速度、纠错负担、适配支持范围。
- 总体使用意愿与简单/复杂调整偏好。
- 指令频率、主题、澄清、细化、替换和撤销行为。
- 使用 **Friedman 检验**及 **Holm 校正的 Wilcoxon 配对检验**。
- 结合访谈主题分析解释定量结果。

- 不同澄清阈值；
- 不使用权重衰减。

### 5.2 是否充分、客观、公平？

**对探索性交互研究而言，证据较丰富；对证明普遍性能优势而言，仍不充分。**

有利之处：

- 被试内设计可减少个体差异。
- 覆盖多种移动程度与界面交互需求。
- 结合问卷、访谈和真实行为日志。
- 使用适合序数数据的统计检验，并进行多重比较校正。
- 作者明确披露部分设计限制。

- **顺序混杂**：Combined 总是最后进行，较高评分可能部分来自练习和熟悉效应。

## 6. 主要结论与发现

### 6.1 组合方式整体评价最高，但语音并未全面优于直接操控

- Combined 相比 ConverseMR，在八项体验指标上均显著更好。
- Combined 相比 DM，在八项中的六项显著更好。
- DM 与 ConverseMR 在七项指标上没有显著差异。
- ConverseMR 的**纠错负担更高**：中位数 4.5，DM 为 3.0，差异显著。

总体使用意愿中位数：

| 方法 | 使用意愿 |
|---|---:|
| Combined | 7.0 |
| DM | 5.0 |
| ConverseMR | 4.5 |

**无显著差异不等于证明两者等效。**

### 6.2 两种交互方式具有明确互补性

- **23/24 人**认为 DM 更适合简单、细微调整。
- **21/24 人**认为 ConverseMR 更适合复杂、大范围适配。
- **18/24 人**指出距离较远时更倾向使用语音。

直接操控的优势是精确、确定、选项可见；对话控制的优势是远距离召回、批量表达、减少手部占用和更广的行为表达。

### 6.3 语音主要替代菜单，而不是手部拖拽

在 Combined 条件下：

- 平均每人约 9.79 次语音指令、3.21 次菜单操作。
- **13/24 人完全未使用菜单**。
- 语音中的细调类指令占比从独立语音条件的 35% 降至组合条件的 20%。

这些结果支持“**用语言配置行为，用手完成精细定位**”的分工，但由于拖拽未完整记录，不能精确计算两者的总使用比例。

### 6.4 适配是持续修订过程，而非一次性命令

在 781 条达到具体解决方案的指令中，后续行为为：

- **32.4%**：替换先前属性；
- **31.2%**：继续细化同一界面；
- **27.7%**：转向其他界面；
- **8.7%**：重复同一指令。

这说明用户常在看到结果后才明确自己的需求。**细化和替换既可能是正常探索，也可能是纠错，不能全部解释为失败。**

### 6.5 上下文有助于恢复语音识别错误

附录报告：

- 完全正确转写：49.1%；
- 部分保留原意：37.4%；
- 完全错误：13.5%；
- 无需澄清的高置信度指令中，提取目标与参考目标一致的比例为 96.0%。

最后一个数字仅对应**特定子集的目标提取准确率**，不是全系统端到端成功率。

- **研究对象有价值**：关注动态、持续的界面行为，而非仅生成静态布局。

## 8. 不足与局限

### 8.1 实验覆盖与外部有效性有限

- 样本较小，以年轻校园人群为主，且 LLM 熟悉度较高。
- 单次约 90 分钟，不能代表长期使用。
- 场地紧凑、对象稀疏且有标签，真实环境中的模糊指代与多候选参照更困难。
- 未充分覆盖户外、噪声、多用户、公共场合和真实高风险任务。

### 8.2 因果归因与评价仍不完整

- Combined 的固定顺序削弱了“组合方式本身更优”的因果解释。
- 菜单与语音能力范围不完全一致。
- 缺少完整拖拽日志，无法可靠比较总操作成本。
- 核心证据侧重体验，未充分建立对任务效率、准确率或现实任务安全性的提升。
- 主研究质性分析主要由一名研究者编码，存在解释偏差风险。

### 8.3 系统与部署限制

- 4.45 秒中位响应延迟对细微调整明显偏慢。
- LLM 自报置信度不能直接视为可靠的不确定性估计。
- 0.95 权重衰减规则较启发式，缺少参数敏感性分析。
- 语言指令到正确 JSON，并不保证最终空间行为符合用户预期。
- 外部 API 部署涉及联网依赖、成本及语音和场景信息隐私，论文未系统评估。

### 8.4 数据报告存在需要澄清之处

- 适配次数中位数在结果部分为 **18.0**，讨论部分为 **18.5**。
- 正文与附录的指令总数、澄清比例和替换比例采用不同统计口径，但对应关系不够清楚。
- 主题分析表只覆盖部分已应用指令，其与全部 988 条指令之间的筛选流程未充分说明。
- 以替换或撤销频率支持执行稳定性仍不充分：用户不撤销不代表执行一定正确。

**总体而言，论文较有说服力地展示了对话控制与直接操控的互补价值，以及“用户表达需求—系统持续求解—用户再修订”的交互模式；但尚不足以证明语音能独立取代直接操控，或在真实部署中普遍提升效率与可靠性。**
