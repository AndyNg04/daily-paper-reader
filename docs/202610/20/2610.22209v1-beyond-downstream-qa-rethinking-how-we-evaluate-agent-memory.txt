Abstract 

Agent memory benchmarks evaluate whether an agent’s re-sponses reflect correct knowledge, measuring downstream question-answering accuracy as a proxy for memory quality. We show this evaluation paradigm is incomplete: it conflates memory correctness with retrieval and generation quality, pro-ducing both false positives where correct responses mask bro-ken memory and false negatives where incorrect responses blame correct memory for retrieval failures. We introduce FEB-30, a benchmark of 30 fact-evolution trajectories span-ning 6 diagnostic categories and 3 difficulty levels, constructed via paradigm inversion: documents are generated from known fact trajectories, yielding deterministic ground truth without human annotation. Each trajectory defines how a fact should evolve across multi-author artifacts (documents, emails, con-versations), enabling direct inspection of the memory store after each ingestion step. Applying FEB-30 to a representative memory system, we demonstrate that intrinsic and extrinsic evaluation diverge by an average of 16 percentage points, with 44% of trajectories exceeding meaningful divergence thresh-olds. Diagnostic decomposition reveals that the system cor-rectly classifies memory operations (create, update, reinforce, supersede) only 20% of the time, a failure entirely invisible to extrinsic evaluation, and that failure modes differ system-atically by category and difficulty. We release the benchmark, document generation pipeline, and scoring framework to sup-port reproducible evaluation of agent memory systems. 1

## 1 Introduction 

Large language model (LLM) agents operating over ex-tended time horizons require persistent external memory to accumulate knowledge beyond the ephemeral context win-dow (Sumers et al. 2024; Jiang et al. 2026). As these systems grow more complex, with over a dozen distinct architectures published since 2023 (Latimer et al. 2026; Packer et al. 2024; Rasmussen et al. 2025; Chhikara et al. 2025; Zhu et al. 2026), the question of how to evaluate them becomes pressing. A survey of current benchmarks reveals a systematic lim-itation: every existing evaluation measures memory quality 

extrinsically , by posing questions to the agent and grading its responses (Maharana et al. 2024; Wu et al. 2026; Hu, Wang, and McAuley 2026; Uddin et al. 2026; Liu and Yadav 2026;

When the system fails, one cannot identify which component is respon-sible; when it succeeds, one cannot confirm the memory is actually correct (Toma and Matei 2026). We identify two concrete failure modes that extrinsic eval-uation cannot detect: 

• False positives (LLM compensation): A strong gener-ation model can produce correct responses despite in-correct or incomplete memory state, by reasoning over partial retrieval results at inference time. Extrinsic evalu-ation scores this as success. 

• False negatives (retrieval bottleneck): A memory sys-tem may correctly store and update facts, yet fail to re-trieve them for a specific query due to embedding mis-match or retrieval cutoff. Extrinsic evaluation blames the memory system for a retrieval failure. We propose intrinsic evaluation , direct comparison of the memory store contents against known ground truth at each stage of knowledge evolution, as a complementary evaluation paradigm. The relationship mirrors unit versus end-to-end testing in software engineering: intrinsic evaluation checks the memory component’s internal state directly, while ex-trinsic evaluation only observes end-to-end behavior, so a passing end-to-end test can mask a broken component just as a correct component can fail end-to-end due to an integration bottleneck. A parallel from NLP history motivates the same shift: in the 2010s, word embeddings were evaluated only through downstream task performance until intrinsic evalu-ation (analogy tasks, similarity correlations) enabled faster progress by isolating representation quality (Baroni, Dinu, and Kruszewski 2014; Schnabel et al. 2015). Our contribu-tions are: 1. FEB-30 , a benchmark of 30 fact-evolution trajectories with deterministic ground truth, spanning 6 diagnostic categories that isolate distinct failure modes invisible to extrinsic evaluation. The benchmark comprises: 

• Fact-evolution trajectories with atomic claim ground truth at each state. 

• A paradigm-inversion document generation pipeline using multi-model rotation and 3-judge verification. arXiv:2610.22209v1 [cs.CL] 15 Oct 2026 • A scoring framework measuring both intrinsic (claim coverage, update detection, false update rate) and ex-trinsic (QA accuracy) metrics. 2. Intrinsic evaluation methodology for agent memory: direct inspection of memory state against known ground truth at each stage of knowledge evolution, enabling di-agnostic decomposition of failures by pipeline stage. 3. Empirical evidence that intrinsic and extrinsic evaluation 

diverge by 16 percentage points on average , with 44% of trajectories exceeding meaningful divergence and fail-ure modes differing systematically by category. 

## 2 Related Work 

Agent Memory Benchmarks. MemoryAgentBench (Hu, Wang, and McAuley 2026) defines four memory com-petencies (retention, temporal reasoning, knowledge up-dates, and information integration) evaluated through QA interactions. Memora (Uddin et al. 2026) introduces the FAMA metric that penalizes reliance on invalidated mem-ories, decomposing performance into freshness-aware com-ponents. LongMemEval-V2 (Wu et al. 2026) tests long-term memory along five temporal reasoning capabilities. AMA-Bench (Zhao et al. 2026) evaluates long-horizon memory for agentic applications. STATE-Bench (Liu and Yadav 2026) measures whether agents improve at tasks through accu-mulated experience. MEME (Jung et al. 2026) introduces controlled state trajectories with multi-entity evolution, the closest methodology to ours, though still evaluated through the response layer. All these benchmarks share a common structure: pose queries to the agent, grade responses against expected an-swers. None directly inspects the memory store. 

Memory Architecture Surveys. Recent surveys (Jiang et al. 2026; Du 2026; Luo et al. 2026; Hu et al. 2025; Huang et al. 2026) catalog memory architectures and operations. Du et al. (Du et al. 2025) define six core memory opera-tions (consolidation, updating, indexing, forgetting, retrieval, condensation), decisions that should be evaluated at the op-eration level, not only through downstream responses. The Anatomy of Agentic Memory survey (Jiang et al. 2026) iden-tifies benchmark saturation as a key concern, yet proposes more extrinsic benchmarks as the solution. 

Conflict Detection Benchmarks. ConflictBank (Su et al. 2024) benchmarks LLM behavior under knowledge conflicts but evaluates at query time, not at the memory consolidation stage. MAGIC (Lee, Lee, and Kim 2025) tests multi-hop conflict detection in retrieval-augmented generation. These address a related but distinct problem: they test whether a model can reason about conflicts in retrieved context, not whether a memory system correctly detects and resolves con-flicts during ingestion.

Intrinsic vs. Extrinsic Evaluation. We present the first benchmark and empirical results that validate this argument. 

## 3 Benchmark Design: FEB-30 

FEB-30 (Fact Evolution Benchmark, 30 trajectories) is orga-nized along diagnostic categories and difficulty levels (Sec-tion 3.4). The name is a deliberate analogy: February 30 is a date that does not exist, the calendar approaches it asymptoti-cally (February 28, sometimes 29) but never reaches 30. Sim-ilarly, recent benchmarks and surveys have moved progres-sively closer to intrinsic evaluation, introducing memory-specific tasks (Hu, Wang, and McAuley 2026), decomposing scores into memory-aware components (Uddin et al. 2026), and defining controlled state trajectories (Jung et al. 2026), yet remain on the extrinsic side of the threshold, never di-rectly inspecting the memory store, as illustrated by (Toma and Matei 2026). FEB-30 crosses it. 

3.1 Diagnostic Categories 

Each category targets a specific gap in extrinsic-only evalu-ation (Table 1): 

C1 (LLM Compensation) constructs scenarios where memory state is incorrect (e.g., outdated fact not updated, contradictions unresolved) but a strong LLM still produces correct answers by reasoning over retrieved fragments, so a system that never updates its facts scores well extrinsically. C2 (Retrieval Bottleneck) constructs scenarios where facts are correctly stored but queries are phrased to produce low embedding similarity (vocabulary mismatch, different abstraction level). The memory is correct, only retrieval fails. 

C3 (Classification Accuracy) tests whether the system correctly classifies each observation as a create, update, re-inforce, or conflict operation, decisions extrinsic evaluation cannot observe directly. 

C4 (Synthesis Quality) tests whether multiple observa-tions from different artifacts merge into correct, well-formed facts, with ground truth specifying which should form a sin-gle fact versus separate facts. 

C5 (Temporal Correctness) tests whether the memory state correctly reflects temporal evolution: linear progression (A →B→C), retraction, and gradual drift across artifacts. 

C6 (Multi-Author Attribution) tests whether source identity affects consolidation correctly: corroboration from different authors should raise confidence differently than rep-etition from one, and disagreement should trigger conflict detection. 

3.2 Difficulty Levels 

At L1 (Table 2), target claims appear almost verbatim in gen-erated documents with minimal surrounding noise. At L2, claims are embedded within realistic document context and require extraction from longer passages. At L3, claims must be inferred from combinations of statements, and documents contain substantial unrelated content that could mislead ex-traction systems. 

3.3 Trajectory Schema 

Each trajectory is defined as a JSON structure specifying: 

• A unique trajectory ID, category, difficulty, and domain assignment. 

• A type indicating the evolution pattern (linear-evolution, contradiction, scope-expansion, retraction, stable, or gradual-drift). 

• A sequence of states , each containing a set of atomic 

claims representing the expected memory contents after processing documents up to that state. 

• Per-state docClaims , the subset of claims that the docu-ment for that state should contain (new information only, not cumulative repetition). 

• An expected action per state transition (create, update, reinforce, conflict, or supersede). 

• Author role and document type metadata for multi-author trajectories. Claims are required to be atomic (one assertable proposi-tion per claim) and self-contained (understandable without reference to other claims). This ensures scoring is unambigu-ous: each claim either is or is not entailed by the system’s fact store. The key design choice is docClaims vs. claims : docu-ments contain only new information per state. The system must retain prior knowledge across document ingestions, testing actual memory persistence, not single-document ex-traction. 

3.4 Distribution 

FEB-30 contains 30 trajectories across 6 categories, dis-tributed across difficulty levels (10 at L1, 10 at L2, 10 at L3). Trajectories span 6 technical domains (infrastructure, secu-rity, financial operations, machine learning, data engineering, and containers) to avoid domain-specific bias. These trajec-tories instantiate the benchmark in a technical and business-operations setting, but the methodology is domain-agnostic as the same paradigm-inversion construction can produce tra-jectories for any domain in which facts evolve across multi-author artifacts, by substituting the domain’s own topics and observation categories. The total corpus comprises 147 gen-erated documents: 127 trajectory state documents and 20 noise documents (4 per C2 trajectory to test retrieval under distraction). 

## 4 Document Generation Pipeline 

We adopt paradigm inversion (Roig 2025): rather than anno-tating ground truth on real documents (expensive and subjec-tive), we generate documents from known fact trajectories, making the trajectory itself the ground truth. Algorithm 1 formalizes the pipeline. 

4.1 Multi-Model Rotation 

Documents are generated using 6 models across 5 providers, rotated per state index within each trajectory to simulate dif-ferent human authors with different writing styles. No single model generates more than 30% of total documents. Fol-lowing evidence that multi-source synthetic data mitigates distribution collapse (Schaffelder and Gatt 2026) and re-duces single-generator bias (van Elburg, van der Putten, and Marx 2025), this additionally simulates the natural stylistic variation of multi-author corpora. The generation models are all different from the system’s extraction model (which uses a different LLM family), avoid-ing the stylistic bias that inflates scores when the same model generates and extracts (van Elburg, van der Putten, and Marx 2025). 

4.2 Style-Grounded Generation 

Documents follow a realism gradient across difficulty levels: 1. Style-grounded (L1/L2): An LLM generates a new doc-ument for the trajectory claims but mimics the tone, vo-cabulary, and structure of a real reference document. 2. Hybrid injection (L3): Claims are inserted into actual human-written documents from unrelated domains, pro-ducing text that is approximately 90% authentic. 4.3 Verification Pipeline 

The verification criterion (Algorithm 1, line 6) requires unan-imous agreement from 3 independent judge models (different from the generators), following the multi-judge grounding methodology of (Uddin et al. 2026) and (Roig 2025). Each judge assesses: (1) all target claims are inferable from the document, (2) no extra factual information beyond the tra-jectory is introduced, and (3) the document reads naturally. Additionally, documents underwent human review, with 11% requiring content corrections (forward leakage, narra-tive contradictions, cross-document inconsistencies, numeric mismatches) and 28% requiring scaffolding removal (code fences, LLM preamble such as “generated email about...” or “injected claims into...”) that does not affect extraction.

## 6 Experiments 

6.1 System Under Test 

To demonstrate the benchmark’s diagnostic utility, we eval-uate a representative agent memory system (Figure 1). The system follows the dominant architectural pattern shared by virtually all contemporary memory systems, Hindsight (La-timer et al. 2026), Mem0 (Chhikara et al. 2025), Ariadne-Mem (Zhu et al. 2026), and commercial agent memory ser-vices alike: (1) extract structured observations from artifacts (documents, emails, meeting transcripts), (2) embed them, (3) retrieve related existing facts via vector search, (4) clas-sify the relationship via LLM (create, update, reinforce, con-flict, or skip), and (5) synthesize into evolving facts with history. This extract-embed-classify-synthesize pipeline rep-resents the current state of the art; despite surface differences in implementation details (confidence stepping in Hindsight, entropy-aware gating in AriadneMem, Add/Update/No-op in Mem0), the core information flow is shared. The specific system is not the contribution; any system implementing this pattern could be substituted. Our goal is to demonstrate what the benchmark reveals about this class of systems, not to evaluate a particular implementation. We adopt a two-layer terminology: observations are static, atomic factual statements extracted from a single artifact (typed into categories such as decisions, commitments, or milestones), while facts are the evolving, synthesized knowl-edge units that the system maintains over time. Observa-tions are immutable once extracted; facts are the persistent memory that gets created, reinforced, updated, or superseded as new observations arrive. Not all observations aggregate into facts: some are too granular or transient (e.g., a one-time action item), and evaluating observations in isolation would only measure extraction completeness and atomicity, not whether the system forms and maintains correct knowl-edge. Other systems use different terms for similar concepts (Hindsight calls atomic extractions “facts” and synthesized summaries “observations”; Mem0 uses “memories” for both layers without distinction), but the underlying two-layer pat-tern, extraction followed by aggregation, is shared. Intrinsic evaluation targets the fact layer, as this is the knowledge state that determines system behavior. Each fact maintains a numeric confidence score (0–1), strengthened by +0.1 per reinforcing observation and ad-justable by the LLM on create, update, or supersede deci-sions. A temporal guard prevents stale observations from overwriting newer knowledge: if an observation is older than the matched fact’s last update, update and supersede deci-sions are automatically downgraded to reinforce. Facts track a full chronological history (statement, confidence, change type, and trigger observation at each step), enabling intrinsic evaluation to inspect the complete evolution path. The sys-tem additionally tracks the number of distinct contributing authors per fact, counting unique contributors across support-ing observations, which enables C6 (multi-author) evalua-tion. Retrieval uses hybrid search combining BM25 (Robert-son and Zaragoza 2009) keyword matching (weight 0.3) with k-NN vector similarity (weight 0.7) over 1024-dimensional embeddings. All LLM classification and synthesis calls use temperature 0 for deterministic outputs; remaining variance across runs comes from the embedding retrieval layer. 6.2 Results 

Finding 1: Intrinsic-Extrinsic Divergence. Across all 30 trajectories (Table 3), the mean absolute divergence between intrinsic and extrinsic evaluation is 0.168 ± 0.025 (over 16 percentage points), with 44% of trajectories exceeding the 

τ = 0 .15 threshold ( N =11 runs). Using a stricter pass/fail criterion ( ≥0.5 vs. <0.5), in 21 ±4% of trajectories one eval-uation method passes while the other fails, meaning a practi-tioner relying on extrinsic evaluation alone would reach the wrong conclusion about system correctness in roughly 1 out of 5 cases (Cohen’s κ = 0 .118 , barely above chance), con-firming the two evaluation methods carry largely independent signal. A Pearson correlation between intrinsic and extrin-sic scores across all 330 paired evaluations is r = 0 .423 

(p < 10 −15 ), so r2 ≈ 0.18 : only 18% of the variance in one score is explained by the other, 82% independent. The signed mean divergence is +0 .118 ± 0.029 , indicating in-trinsic scores are systematically higher than extrinsic: the system’s memory is on average better than what QA evalua-tion reveals. Finding 2: Difficulty and Divergence. DivRate decreases with difficulty (L1: 55%, L2: 50%, L3: 26%). At L1, intrinsic substantially exceeds extrinsic ( 68 .0 ± 3.2 vs. 50 .9 ± 4.2), meaning the system stores correct knowledge that retrieval fails to surface for QA. At L3, both scores converge near 47%, but diverge on individual trajectories in opposite di-rections (some false positives, some false negatives). MAD varies across levels (.178, .224, .103), indicating disagree-ment persists at all difficulty levels. Classification accuracy degrades sharply with difficulty ( 33 .8 → 16 .5 → 10 .1%), confirming that the system’s ability to correctly label actions deteriorates as signal becomes more subtle. 

Finding 3: Category-Specific Failure Modes. Diagnostic decomposition reveals distinct failure patterns. The overall false update rate is 22 .2 ± 1.2%: the system modifies facts when it should only reinforce. Update detection recall is 

73 .6±2.6%. Classification accuracy (whether the system cor-rectly labels the action as create/reinforce/update/supersede) is only 20 .1 ± 2.7%, with C2 (4.5%) and C5 (0.4%) near zero. Confidence MAE is 0.106 ± 0.002 across all trajecto-ries. C6 (Multi-Author) shows the lowest intrinsic accuracy (41.5%), identifying multi-author source attribution as the system’s weakest dimension. These insights are invisible to extrinsic evaluation, which reports a near-uniform 42–55% across most categories (per-category/difficulty breakdowns in Appendix F). 

Finding 4: Actionable Diagnostics. The intrinsic metrics directly identify which pipeline stage to improve: (1) classifi-cation accuracy is 20.1% overall, meaning the system rarely assigns the correct action label even when its fact state ends up partially correct; (2) multi-author source attribution (C6: 41.5%) does not adequately leverage author identity; (3) false updates (22.2%) indicate overly aggressive modification on reinforcement signals. None of these are recoverable from extrinsic scores.

Across all four configurations, intrinsic accuracy remains in a narrow

The configuration used for the main results in this paper adds retrieval relevance filtering, concurrent fact-update han-dling, and improved large-document extraction; the simpler-system ablation lacks these refinements, which accounts for its modestly lower intrinsic accuracy. All configurations im-plement the same extract-embed-classify-synthesize pattern (Figure 1). The divergence therefore persists across all four, with full statistics in Appendix H. 

6.3 Diagnostic Decomposition 

A key advantage of intrinsic evaluation is diagnostic decom-position : when a system fails, we can identify which pipeline stage is responsible: 

• Extraction failures: Claims present in artifacts but not captured by the system’s observation layer. 

• Synthesis failures: Claims extracted but incorrectly merged, duplicated, or lost during fact aggregation. 

• Update failures: State transitions missed or false updates applied. 

• Conflict failures: Contradictions not detected or resolved incorrectly. Table 4 reveals three co-occurring failure patterns that in-tensify with difficulty. First, the claim miss rate rises from 58% at L1 to 88% at L3, indicating that subtle or embedded claims are increasingly lost during extraction. Second, fact count inflates from 9.1 to 20.7, showing the system fragments knowledge into many small, partially redundant facts rather than synthesizing them into coherent evolving beliefs. Third, classification accuracy degrades from 37% to 10%, mean-ing the system rarely identifies the correct action (create vs. update vs. reinforce) at higher difficulty. These three signals are mutually reinforcing: poor classification leads to creating new facts instead of updating existing ones (inflating count), which in turn fragments claims across facts (increasing miss rate on claim-level matching). None of these diagnostics are available from the extrinsic QA score, which remains flat at 

∼50% regardless of the underlying failure pattern. 

## 7 Discussion and Limitations 

Complementary, Not Replacement. Intrinsic evaluation does not replace extrinsic evaluation, it complements it. Ex-trinsic captures end-to-end utility as intrinsic enables diag-nosis. A system scoring high on both is genuinely effective; high extrinsic but low intrinsic signals fragility (dependent on LLM compensation); high intrinsic but low extrinsic in-dicates a retrieval or generation bottleneck. 

Synthetic Document Validity. Generated documents may not capture all properties of real multi-author text. We miti-gate this through style grounding, multi-model rotation, and hybrid injection at L3. Future work should validate transfer via rank correlation with human-annotated real document sequences. 

Scope and Limitations. FEB-30 targets factual evolution across multi-author artifacts. It does not evaluate episodic memory, procedural memory, or single-turn conversational recall, capabilities addressed by existing benchmarks. The benchmark contains 30 trajectories, sufficient for diagnostic evaluation but not for fine-grained statistical comparisons. Scoring relies on embedding similarity thresholds and LLM judges, introducing potential measurement noise. 

## 8 Conclusion 

We introduced FEB-30, the first benchmark designed for in-trinsic evaluation of agent memory systems. By constructing trajectories where the expected memory state is known at ev-ery step, we demonstrated that intrinsic and extrinsic evalua-tion diverge by an average of 16 percentage points, with 44% of trajectories showing meaningful disagreement, revealing false positives and false negatives invisible to response-based benchmarks. Diagnostic decomposition showed the system correctly classifies memory operations only 20% of the time (degrading from 34% at L1 to 10% at L3), a dimension ex-trinsic evaluation cannot measure. We argue that intrinsic evaluation should become standard practice alongside extrinsic benchmarks, analogous to how intrinsic evaluation of embeddings complemented down-stream task evaluation in NLP. We release FEB-30, the gen-eration pipeline, and the scoring framework for reproducible evaluation of agent memory. The intrinsic–extrinsic divergence holds across all four: posi-tive signed divergence, near-chance pass/fail agreement, and MAD and DivRate in a narrow range, indicating the finding is not an artifact of a single system implementation, corpus version, or backbone model. Beyond these aggregate statistics, the paper’s category-level findings are also preserved under the upgraded back-bone. Comparing per-category metrics between the main configuration and the upgraded backbone, the category rank-ings are highly stable: Spearman rank correlation across the six categories is ρ = 0 .94 for MAD, ρ = 0 .89 for intrin-sic accuracy, and ρ = 0 .94 for classification accuracy. The named extremes the paper relies on are unchanged: C1 (LLM Compensation) has the highest MAD and the highest classi-fication accuracy, C6 (Multi-Author) has the lowest intrinsic accuracy, and C5 (Temporal) has the lowest classification ac-curacy, in both configurations. The only differences are adja-cent swaps among already-close values, never a reordering of these extremes, indicating the diagnostic category structure is not an artifact of a particular backbone model.
