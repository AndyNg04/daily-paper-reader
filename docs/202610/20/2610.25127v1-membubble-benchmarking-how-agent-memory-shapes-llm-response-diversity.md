## 摘要
记忆是基于大语言模型的智能体的核心组件，使其能够从过往交互中提取并利用用户偏好，从而生成个性化响应。然而，记忆的使用可能会降低响应多样性，进而缩窄用户可获取的信息范围。现有评估大多依赖合成交互，且涵盖的记忆系统有限，因此尚未在真实场景中充分评估记忆对响应多样性的影响。我们提出 MemBubble，这是一个包含 1000 个实例的基准，基于从真实用户与助手对话中提取的偏好构建。为衡量记忆使响应分布集中的程度，我们构建了测试查询：这些查询所处的场景不同于用户偏好对应的场景，同时通过共享偏好类别保持主题相关性。在多种大语言模型和记忆机制下，与直接提供完整交互历史相比，熵平均降低了 34.7%，凸显了记忆处理在多样性损失中的重要作用。我们还探究了简单的用户侧干预以及信息可获取性的变化，但发现这些方法并不能有效缩小多样性差距。研究结果表明，在设计和使用智能体记忆系统时，除了提升个性化能力，还应考虑如何保留多样性并保障用户获取信息的能力。

## Abstract
Memory serves as the core component of LLM-based agents, enabling personalized responses via extracting and using user preferences from past interactions. However, its use may reduce response diversity, thereby narrowing the range of information available to users. Existing evaluations rely largely on synthetic interactions and cover few memory systems, leaving the effects of memory on response diversity insufficiently evaluated in real-world scenarios. We introduce MemBubble, a benchmark of 1000 instances built on preferences extracted from real user-assistant conversations. To measure the extent to which memory concentrates response distributions, we construct test queries in scenarios distinct from user preferences while preserving topical relevance through shared preference categories. Across multiple LLMs and memory mechanisms, entropy decreases by 34.7% on average compared with directly providing the full interaction history, highlighting the important role of memory processing in diversity loss. We also explore simple user-side interventions and changes in information availability but find that these do not effectively close the diversity gap. Our findings highlight the need to consider preserving diversity and user access to information alongside improvements in personalization when designing and using agent memory systems.

## 1. 核心问题与整体含义：个性化记忆是否会收窄回答范围？

- **研究背景**：大语言模型智能体通过持久记忆保存用户偏好，并在后续对话中检索、利用这些信息，以提供个性化服务。但记忆也可能让模型反复围绕用户已经喜欢的对象作答，使用户更难接触其他合理选项。
- **核心问题**：对于存在多种合理答案、且不明确要求个性化的开放问题，记忆系统是否会使回答分布更加集中？这种变化来自历史信息本身，还是来自记忆的提取、组织与检索过程？
- **现有研究不足**：
  - 主要使用合成用户历史，难以代表真实用户表达偏好的方式。
  - 常将偏好直接放入上下文，或只使用简单检索，缺少对实际记忆架构的系统评估。
- **整体意义**：论文把智能体记忆的评价目标从“是否记得准确、是否符合偏好”，扩展到“是否保留探索空间与信息广度”。其关注的是潜在的“信息茧房”风险，**并非主张个性化本身有害，也未直接证明记忆会导致现实中的偏见强化或社会极化**。

## 2. 方法论：真实偏好、跨场景问题与功能性多样性评估

### 2.1 核心思想：同类别、不同场景

论文构建 **MemBubble** 基准，刻意选择以下评估位置：

- 问题与用户历史偏好属于相同类别，使记忆有机会影响回答。
- 问题所处场景与原偏好场景不同，避免把合理的偏好匹配简单判为多样性损失。
- 问题只要求一个选项，但允许多个合理答案，便于重复采样并比较分布。

例如，用户曾表示某位音乐家深刻影响其音乐品味，测试问题则要求“推荐一位代表某国参加文化外交活动的音乐家”。历史偏好可以成为答案，但不应是唯一自然选择。

### 2.2 基准构建流程

1. **筛选真实对话**
   - 从 LMSYS-Chat-1M 和 WildChat 出发，保留包含 10–100 条消息的对话。
   - 去重，剔除模板化内容、信息被占位符遮蔽的样本，以及容易混淆用户真实偏好的角色扮演、越狱、改写或翻译等任务。

2. **提取和验证偏好**
   - 用 LLM 提取偏好，并附上用户原话证据。
   - 使用不同模型家族的验证器检查事实是否忠实、是否把一次性要求过度概括为稳定偏好。
   - 再由两个不同提供商的模型独立判断偏好是否稳定、适合评估，并提取“偏好类别”和“原始场景”；仅保留双方均通过的样本。

3. **生成跨场景查询**
   - 查询生成器只看到类别与原场景，**看不到具体偏好对象**，降低答案泄漏风险。
   - 生成英文、非个人化、只要求一个选项的开放问题。
   - 检查问题是否泄漏偏好，以及偏好对象是否仍是该问题的合理答案。

4. **进行多样性预筛选**
   - 对每个候选问题无记忆采样 5 次，并计算功能类别熵。
   - 仅保留熵超过 **1.4 bits** 的问题，确保存在观察多样性下降的空间。

5. **构建多会话历史**
   - 将偏好对话与同语言的随机背景对话混合。
   - 初始抽取 50 段背景对话，随机删除至背景总量不超过 30,000 tokens。
   - 偏好对话完整保留，所有会话随机排序。

### 2.3 记忆与生成过程

论文将记忆系统抽象为：

- 根据交互历史构建外部记忆；
- 根据当前问题检索相关记忆；
- 将问题与检索结果一起交给回答模型。

因此，比较“完整历史”和“记忆检索”条件，可以观察**信息经过选择、压缩和重新呈现之后**，回答分布如何变化。

### 2.4 多样性指标

论文不统计表面措辞差异，而是将回答划分为**功能等价类**：若两个回答的核心选项相同，用户看过一个后再看另一个，几乎没有新增任务价值，则归为同类。

- **Adapted distinct-k**：重复生成的 \(k\) 个回答中，有多少个不同的功能类别。
- **类别熵（Class Entropy）**：根据各类别出现比例计算 Shannon 熵，衡量回答是否集中于少数选项。
  - 类别更多、分布更均匀，熵更高。
  - 全部回答属于同一类时，类别数为 1，熵为 0。

所有回答由 LLM 一次性分组。人工验证中，人—人平均调整兰德指数（ARI）为 **0.843**，模型—人分别为 **0.762、0.791**，说明自动评估与人工判断具有较好但不完全的一致性。

## 3. 实验设计：数据、基准与对比方法

### 3.1 数据与任务

- **原始数据集**：LMSYS-Chat-1M、WildChat，原始规模各约 100 万段真实对话。
- **最终基准**：
  - 1,000 个“多会话历史—测试问题”实例，来自 985 段不同源对话。
  - WildChat 贡献 758 例，LMSYS-Chat-1M 贡献 242 例。
  - 源对话覆盖 35 种语言，英语占 52.5%，中文占 13.3%；**测试问题统一为英文**。
  - 问题覆盖 14 个主题，主要包括 STEM、艺术文学、社会、游戏、体育、音乐等。
  - 构建后的历史平均包含约 37.7 段会话。

### 3.2 记忆条件

| 条件 | 核心方式 |
|---|---|
| No mem. | 仅提供当前问题，不提供历史 |
| Full history | 直接提供完整交互历史 |
| NaiveRAG | 按相关性检索原始会话，不进行 LLM 记忆提炼 |
| MemoryBank | 使用对话记录、事件摘要和用户画像 |
| A-Mem | 使用相互链接、可更新的记忆笔记 |
| mem0 | 提取事实，并进行新增、更新、删除等管理 |
| MemoryOS | 使用短期、中期、长期分层记忆 |

其中，NaiveRAG 与四种记忆架构共同构成五种记忆机制。

### 3.3 回答模型与统一设置

按论文列示，实验使用六个回答模型：

- GPT-6-Sol、GPT-5.6-Luna；
- Claude Haiku 4.5、Gemini 3.7 Flash；
- GLM-5.3-flash、Llama3.3-70B。

主实验每个问题、每种条件独立生成 **10 次**，温度为 **1.0**，最大输出长度为 **512 tokens**。

为控制变量：

- 四种持久记忆架构统一使用 DeepSeek-V4-Flash 构建记忆，并在不同回答模型之间复用。
- 所有检索统一使用 text-embedding-3-small。
- 各方法的检索条数按其默认设置配置，而非统一检索量。

### 3.4 扩展实验

- 采样温度：0.1–2.0。
- 推理强度：从 none 到 max。
- 历史长度：背景对话初始数量为 0、5、10、20、50、100。
- 检索深度：top-k 为 1、3、5、10、20。
- 回答采样量：每题生成 5、10、20 次。

## 6. 主要结论与发现

### 6.1 记忆机制普遍使回答分布集中

- 相比 **No mem.**：
  - 功能类别数平均下降 **25.0%**；
  - 类别熵平均下降 **34.1%**。
- 相比 **Full history**：
  - 功能类别数平均下降 **25.7%**；
  - 类别熵平均下降 **34.7%**。

**34.7% 指的是重复采样所得功能类别熵的相对下降，并不代表答案质量、知识量或正确率下降了同样比例。**

- 五种记忆机制下，平均约 **34%** 的实例在十次生成中只有一种核心答案；无记忆与完整历史条件分别约为 **6%** 和 **9.5%**。
- 完整历史并不总使多样性下降，部分模型反而提高。这说明不能将问题简单归结为“历史信息越多，多样性越低”。

### 6.2 不同系统和模型存在差异

相对无记忆条件，各机制的平均熵变化为：

| 记忆机制 | 平均类别熵变化 |
|---|---:|
| NaiveRAG | −22.75% |
| MemoryBank | −39.58% |
| A-Mem | −39.88% |
| mem0 | −46.66% |
| MemoryOS | −21.77% |

- mem0 的平均降幅最大，MemoryOS 最小。
- GPT-6-Sol 平均降幅较大；Gemini 3.7 Flash 较小，但其无记忆多样性本来就较低，存在基线差异。
- 多样性降幅较大的配置，通常也有更高的偏好命中率，但这属于相关性观察。

### 6.3 简单干预未能消除差距

- **问题改写**能提高测得的多样性，但仍不能追平相同策略下的参照条件；且不同改写问题的混合分布与同一问题重复采样并不完全可比。
- **多样性系统提示**单独使用效果有限。
- **提高温度**通常有帮助，但超过 1.0 后，记忆条件下收益有限。
- **增加推理强度**未带来明显改善，多样性反而总体略降。
- **增加背景历史或检索条数**可在部分配置下缓解下降，但趋势不单调，也未消除差距。
- 将每题采样量提高至 20，主要结论仍成立。

## 7. 优点与亮点

- **问题具有实践价值**：指出记忆能力增强可能伴随探索能力下降，补充了只看偏好遵循与检索准确率的评价框架。
- **设计兼顾相关性与非必要个性化**：“同类别、不同场景”避免问题与偏好完全无关，也降低把正常个性化误判为风险的可能。
- **真实对话来源**：相比完全合成的用户画像，更接近用户实际表达偏好的形式。
- **构建过程有多层质量控制**：包括原话证据、跨模型核验、双模型筛选、答案隔离生成及人工抽查。
- **功能性指标更切合任务价值**：不会把同一推荐对象的不同措辞误认为多样答案。
- **完整历史基线有解释力**：表明历史本身与经记忆系统处理后的历史，可能产生不同效果。
- **没有夸大简单补救手段**：明确报告改写、升温和增加检索量只能有限缓解，而非解决问题。

## 8. 不足与局限

### 8.1 基准存在选择偏差

- 高熵预筛选刻意选择无记忆时较多样的问题，有利于检测下降，但不代表真实用户请求的整体分布。
- 预筛选依赖特定模型，可能偏向该模型容易产生多样答案的任务。
- 任务集中于“从某类别中选一个对象”，对复杂规划、长文创作、代码生成和多轮决策的适用性有限。

### 8.2 “场景不同”不等于“偏好不应使用”

- 稳定偏好可能合理地跨场景迁移，不能仅凭跨场景就认定个性化不恰当。
- 论文未直接测量用户意图、满意度或是否愿意探索新选项，因此**多样性下降不必然意味着用户效用下降**。

### 8.3 真实对话不等于真实长期用户历史

- 背景会话来自随机拼接，而非同一用户的自然长期记录。
- 固定历史无法反映偏好变化、记忆反复更新，以及持续交互中的反馈循环。
- 源对话虽覆盖多语言，但查询统一为英文，尚不能视为完整的多语言评估。

### 8.4 自动评价和辅助指标有误差

- 功能等价分组具有主观性，模型—人工一致性尚未达到人工之间的水平。
- DeepSeek-V4-Flash 同时参与偏好提取、记忆写入和最终分组评估，可能引入相关偏差。
- 偏好命中率使用名词子串匹配，可能误判、漏判，不能直接等同于真正遵循偏好。
- 每题仅采样 10 次，熵只是有限样本下的估计；20 次采样实验增强了稳健性，但仍不是完整输出分布。

### 8.5 尚未解释机制，也未建立质量—多样性权衡

- 未充分拆解偏好提取、摘要压缩、检索选择和上下文强调分别贡献多少损失。
- 未系统联合评估正确性、推荐适切性、个性化收益与多样性，因而不能据此认定某种记忆系统整体更优。
- 尚无经过验证的有效缓解方法，也未直接验证长期信息茧房或社会影响。
- 论文称公开数据不存在隐私问题，但**公开可获取不等于没有隐私风险**；从真实对话提取长期偏好仍涉及用户画像与敏感信息处理。

## 总体评价

MemBubble 的主要贡献是提出一个基于真实对话、强调功能性差异的评估框架，并提供较广泛证据：**在所测开放任务中，记忆系统不仅保留用户偏好，也可能使模型过度围绕偏好生成答案。**其结论支持将多样性与信息接触广度纳入记忆系统评价，但仍需结合用户意图、任务质量、动态交互和更严格的机制实验，判断何时应坚持个性化、何时应主动扩展选项。
