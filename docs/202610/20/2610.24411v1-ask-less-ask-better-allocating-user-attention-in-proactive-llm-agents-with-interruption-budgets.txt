## Ask Less, Ask Better: Allocating User Attention in Proactive LLM Agents with Interruption Budgets 

Xuanming Zhang 1*, Amir H. Rezaeian 2, Miguel Ballesteros 2, Weiyi Sun 2, Werner Geyer 2

Lydia B. Chilton 1, Zhou Yu 1, Yassine Benajiba 2, Dan Roth 2

1Columbia University, 2Oracle AI 

xz2995@columbia.edu, {amir.rezaeian,dan.roth}@oracle.com 

Abstract 

LLM agents can ask clarifying questions to complete tasks, but answering each question demands users’ time and effort. Existing evalu-ations typically measure this burden by count-ing questions, treating necessary and avoidable questions equally. We propose an evaluation protocol that distinguishes how often agents ask from how well they ask. An interruption budget limits the number of questions, while a user-attention cost charges extra for questions that are hard to read or not worth asking, as rated by a human-validated LLM judge. Beyond ques-tion counts, this cost captures perceived effort: on conversation pairs with the same number of questions, human annotators agreed with the cost on which conversation required more ef-fort 75% of the time. Across eight LLMs and four customer-service domains, limiting agents to one to three questions reduces user-attention cost by 36–73% while keeping 86–94% of the task reward they earn with unlimited questions. At the same budget, reviewing each question against the memory of users’ earlier answers cuts attention cost by another 13% with little reward loss and yields more valuable questions. Models also differ sharply in how well they ask: at the same user-attention cost, the most effi-cient models gain more than twice as much re-ward from their questions as the others. These results show that asking less and asking bet-ter are distinct goals, and that evaluations of proactive agents should measure both.

2 Related Work 

Evaluating user interaction. Interruption man-agement treats human attention as scarce, with tim-ing and context shaping disruption (Simon, 1973; Horvitz, 1999; McFarlane and Latorella, 2002; Horvitz and Apacible, 2003; Mark et al., 2008); interactive systems reduce user effort by reusing context or adding user review (Zhang et al., 2024; Long et al., 2025). Agent benchmarks with simu-lated users evaluate tool use, hidden intents, and specification gathering (Yao et al., 2024; Barres et al., 2025; Zhang et al., 2026a; Wang et al., 2026), and some bound interaction through turn limits (Zhao et al., 2026) or query budgets (Hamblin et al., 2026). π-Bench distinguishes turn count from user burden but does not compare burden across tran-scripts (Zhang et al., 2026a). Our protocol com-bines interruption budgets, a cost beyond count, equal-count and equal-cost comparisons, and hu-man burden judgments (Table 1). 

Deciding when to ask. Prior work studies when and what to ask (Rao and Daumé III, 2018; Alian-nejadi et al., 2019; Kuhn et al., 2022; Toles et al., 2025), using uncertainty, learned help-seeking, turn-limited planning, information sufficiency, or training for clarification (Ren et al., 2023; Feng et al., 2024; Suri et al., 2026; Hu et al., 2024; Li et al., 2024; Chen et al., 2025a; Berant et al., 2025; Wu et al., 2025). Value of information (VoI) weighs a question’s expected benefit against its communi-cation cost (Dong et al., 2026), and anytime reason-ing studies quality under compute budgets (Zhang et al., 2026b). We instead evaluate how agents allocate a task-level budget of user attention. 

3 Problem Formulation 

We use interruption budgets to study whether agents can ask fewer, more valuable questions while preserving task reward. A budget controls how often an agent asks, and user-attention cost measures how demanding and justified each request is. Table 2 lists what the LLM judge scores. 

Setting. A user begins a session with a request. The proactive agent uses tools and decides when to ask for further input. Task-relevant information may already be in the conversation, be retrievable through tools, or be held only by the user, such as an unstated preference. At each step t, the agent’s policy π chooses whether to ask the user, call a tool, or respond, given prior messages and tool results. We denote the complete session by τ and score its outcome with task reward R(τ ) ∈ [0 , 1] .

Interruption budget. An interruption, or ques-tion, is a discretionary request for user input after the initial request: a clarification, a confirmation, or a request to respond to a suggestion. Exchanges re-quired by the environment’s policy, such as authen-tication or mandatory confirmations, are exempt; a message that adds any discretionary request is charged. A classifier shared across all methods la-bels each proposed request (91.0% agreement with human labels, versus 90.0% between annotators; Appendix E.2). Let Q(τ ) be the discretionary re-quest messages delivered in τ , and each q ∈ Q(τ )

counts once. A budget N imposes |Q(τ )| ≤ N .The cap may go unspent. Once it is reached, further discretionary requests are refused and the agent pro-ceeds without them (Appendix D). Appendix E.4 reports the savings when we also charge for ex-changes required by the environment’s policy. 

User-attention cost beyond count. A simple question count treats all requests alike, so we add two surcharges, scored by a human-validated LLM judge using domain-specific rubrics (Appen-dices E.1 and I).

4 Memory-Guided Review Agent 

An interruption budget limits how often an agent asks, but not which questions it spends the bud-get on. We propose the memory-guided review 

(MGR) agent (Budgeted + MGR in our tables), which uses self-review and persistent memory to choose which questions to ask. MGR builds on agent memory (Packer et al., 2023; Park et al., 2023; Xu et al., 2025) and self-feedback (Madaan et al., 2023; Shinn et al., 2023), but applies self-review to proposed questions rather than task out-puts. We expect memory to matter most when an earlier answer or tool finding is no longer in the recent context, so review without memory can-not see it. Persistent memory. Memory M = ( P, s, I ) per-sists across review calls within a session. User records P store the initial request and every user re-ply verbatim; the model can append to them but not rewrite them. A revisable summary s records task constraints, relevant tool findings, and progress, and evidence links I point to the user turn or tool result that supports each entry. Each review reads 

M and selected recent evidence, then returns its question decision together with updated (s, I ), so review and memory maintenance share one call. Keeping user records separate from tool findings is intended to stop the agent from treating retrieved facts as user preferences: finding a larger size in stock does not establish that the user wants to ex-change for it (Figure 2). The agent can then avoid repeated questions while still asking about unre-solved preferences, and Section 6.3 measures how often it obtains them. Ablations that remove user records (Budgeted + Review + Summary) or all persistent memory (Budgeted + Review) test these components (Section 6.3). Self-review and mem-ory maintenance add an average of 1.8 model calls and about 15k tokens per session (Appendix F.2). 

5 Experimental Setup 

Our experiments address four questions: whether user-attention cost tracks human burden beyond question count (RQ1, §6.1), how budgets trade task reward for user attention (RQ2, §6.2), whether memory-guided review improves how an agent spends its budget (RQ3, §6.3), and how these ef-fects vary across models and tasks (RQ4, §6.4). 

5.1 Datasets Customer service. Our main testbed combines customer support and shopping assistance. For τ -bench, we use the retail and airline domains of Yao et al. (2024) and the telecom domain of Barres et al. (2025), with the official τ 2-bench harness, tools, and reward criteria. Because user requests often leave context and preferences implicit (Malaviya et al., 2025), we change the simulated user’s in-structions: it starts from a high-level goal and gives further details only when asked. As a robustness check, we also evaluate agents under the bench-mark’s original user instructions, where budgets still cut user-attention cost and earn higher utility than unrestricted asking (Appendix H.4). For Ambiguous WebShop , we adapt synthetic shopping goals (Yao et al., 2022) by withholding preferences (Dong et al., 2026). Each initial request becomes “Find me {query}.” , using the product’s short query; attributes, options, and price limits are given privately to the simulated shopper. For example, “Find me milks & creams.” omits dietary requirements, package size, and a price cap. The shopper reveals only requested requirements, po-tentially several per message. Purchases are scored against the unchanged complete goal using Web-Shop’s programmatic reward. 

Interactive research. Ambiguous BrowseComp-Plus provides a separate out-of-domain test. We adapt BrowseComp-Plus (Chen et al., 2025b) by withholding identifying constraints from the initial query. The simulated user holds these constraints and supplies them when asked, but does not know the answer to the research question itself, which the agent must still find by searching. We report its five-model results separately from the four-domain main evaluation (Appendix H.1). 

Data splits. We split each task population into about 20% development tasks for prompt and self-review design and 80% test tasks for reported eval-uation. Table 6 lists the size of each dataset and split, and the test splits total 382 customer-service and 559 research tasks. 

5.2 Baselines and Ablations Unrestricted allows uncapped asking; Frugal prompt instructs the model to ask sparingly and concisely. VoI gate adapts Dong et al. (2026), comparing a question’s estimated information gain about user needs with an asking-cost threshold. 

Budgeted enforces an interruption budget N with-out self-review or added persistent memory. The budget is stated in the prompt for each domain. 

Budgeted + MGR adds memory-guided review at the same N (Section 4). Two ablations remove its components: Budgeted + Review reviews ques-tions without persistent memory, and Budgeted + Review + Summary keeps the task summary and evidence links but drops verbatim user records. No-ask sets N = 0 without separately optimizing the backbone for this setting. See more baseline details in Appendix C. For customer service, where agents ask 2.84 questions per session without a budget (Appendix H.1), we test N = 1 –3. For interac-tive research, where the user holds 2–20 hidden clues per query and reveals one per question (Ap-pendix B.2), we test N = 1 –8 given the compute limits.

6.2 RQ2: Small Budgets Cut Attention Cost and Spend It More Efficiently 

Budgets of one, two, and three questions cut user-attention cost by 73%, 52%, and 36% relative to Unrestricted while lowering reward by only 7.1, 4.0, and 2.8 points, keeping 86–94% of total reward (Figure 3). However, total reward flatters budgets: No-ask already earns much of it, and budgets keep only 49%, 71%, and 80% of the reward that asking adds (Table 20). 

Questions beyond the budget earn little. We measure asking efficiency as yield , the reward gained over No-ask per unit of user-attention cost, shown by the slopes in Figure 3. 6.3 RQ3: Memory Helps Agents Ask Better, Not Only Less 

Under the same budget, the MGR agent asks fewer questions and drops mostly those not worth ask-ing; without persistent memory, review lowers both reward and judged value at equal cost. 

MGR asks less without losing reward at equal cost. At the same N as Budgeted, MGR lowers user-attention cost by 12.7% with minimal reward loss, mostly by asking less often (10.9% fewer requests) rather than by bundling questions (Ap-pendix E.4). The loss reflects asking less, not ask-ing worse: against a Budgeted policy that spends the same expected attention, reward does not differ detectably ( +0 .2 [−0.4, +0 .8]). 

MGR drops the questions not worth asking. 

Judged question value rises by 2.3 points at the same budget and stays 1.8 points higher ([1.3, 2.3]) when the two policies ask equally often on average (Appendix F.1), so the gain reflects which questions are asked, not how many. MGR removes 20% of questions scored 4 or below but only 5% of those scored 8 or above (Table 16). The gain holds under the human-validated judge; a judge from another model family, which agrees less with annotators, finds a smaller gain (Appendix E.3). Memory is what makes review selective. With-out memory, review (Budgeted + Review) lowers reward ( −0.7) and judged value ( −0.9) relative to Budgeted at equal cost (Table 5) and removes low-and high-value questions alike (Table 16). With memory, review costs 6.2% less and gains 2.9 value points at the same N . Keeping the task summary but dropping the verbatim user records (Budgeted + Review + Summary) recovers only part of this gain. Averaged over the four domains, self-review needs to know what the user has already said. 

Question value must be read alongside recall. 

Value scores only delivered questions, so it cannot see questions an agent should have asked. On Web-Shop, where each goal withholds 7.1 requirements on average, we also measure elicitation recall, the share of withheld requirements the shopper dis-closes (Appendix F.4). Even Unrestricted obtains only 31.1%, so missed requirements, not excess questions, are the larger problem there. Recall also exposes a failure that value misses: MGR’s recall is 2.9 points below Budgeted’s at matched count, because its review rule mistakes options listed on product pages for known preferences. Requiring a grounded reason for each block restores recall to within 1.4 points of Budgeted and raises reward by 5.2 points on three models. It did not transfer to Retail in development, so we apply it to WebShop only, apart from the main results (Appendix F.3). Evaluations that report question value should there-fore report recall alongside it. 

6.4 RQ4: Asking Efficiency Varies Across Models, Tasks, and Users 

The protocol separates models by how efficiently they ask, a skill that neither question frequency nor base task ability reveals, and the value of budgets and question review depends on the task and the simulated user. 

Some models ask far more efficiently than oth-ers. GPT-6-Astra and Grok-4.6 gain 7.3–7.8 re-ward points per unit of attention cost under unre-stricted asking, more than twice any other model (at most 3.3), and a three-question budget raises both significantly, to 8.9–9.2 (Figure 3; Table 22). Frequency does not predict efficiency: on Telecom under Unrestricted, GPT-4.1 asks 5.7 questions for a 5.5-point gain over No-ask, whereas GPT-6-Astra asks 1.6 for a 31.9-point gain (Figure 8). Nor does base ability: Grok-4.3 earns the second-highest reward without asking but ranks sixth in efficiency. 

The best budget follows asking efficiency. At 

λ = 0 .03 , the three most efficient askers (GPT-6-Astra, Grok-4.6, and GPT-OSS-120B) do best with two or three questions, and the other five with one (Table 24), and per-model budgets add 0.9 utility points over the best common budget. The better a model asks, the more questions it should be allowed. 

Review saves attention for most models; reward gains are model-specific. MGR reduces cost for seven of eight models and raises judged value for six, but its reward gains at equal cost are supported only for Grok-4.6 and Llama-3.3 (Figure 4). 

Tasks and simulated users change the value of asking. On interactive research (five models; 

N = 1 –8), budgets save only 15.6% of cost at a 3.1-point reward loss, and MGR a further 5.4% at a further 0.9-point loss. Unlike in customer ser-vice, neither improves utility over Unrestricted at 

λ = 0 .03 (Table 21). In a two-model, three-domain study, MGR with GPT-6-Astra at N = 1 raises re-ward by 11.7 points when simulated users disclose only what is asked but lowers it by 2.5 points under the benchmarks’ original instructions, while bud-gets save cost under both (Appendix H.4). Because neither regime is known to be more realistic, eval-uations should vary how forthcoming simulated users are. 

7 Conclusion 

We proposed an evaluation protocol that separates how often proactive agents ask, capped by an inter-ruption budget, from how well they ask, measured by user-attention cost. At equal question counts, an-notators judged the higher-cost conversation more tiring in 75% of non-tie answers. Budgets of one to three questions cut attention cost by 36–73% while keeping 86–94% of reward, though only 49–80% of the gain from asking. At the same budget, memory-guided review cuts attention cost by a further 13% with little reward loss and asks more valuable ques-tions; without memory, review hurts. Models also differ sharply in how well they ask: at equal cost, the most efficient gain over twice as much reward from their questions as the others. Asking less and asking better are thus distinct: evaluations should report reward and attention cost together, compare agents at equal count or cost, pair question value with recall, and vary how forthcoming simulated users are. 8 Limitations 

Extending to live collaboration. Our controlled customer-service and interactive-research tasks pro-vide a starting point for studying budgeted inter-action with real users, naturally underspecified re-quests, and additional languages and modalities. The current evaluation uses English interactions with simulated users; disclosure instructions affect the tradeoff (Appendix H.4). Future evaluations can test how budgets transfer to users with differ-ent knowledge and communication styles. 

Measuring experienced burden. The conversa-tion study supports evaluation beyond count and motivates larger, counterbalanced studies in which users interact with different agents and report effort, fatigue, and willingness to continue. Such studies would extend the current two-annotator judgments on selected conversation pairs to experienced bur-den. Independent participants and broader pair sampling would strengthen this evidence. 

Learning adaptive budgets. The observed curves guide choices among tested question lim-its. A natural extension is to learn budgets from task demands and elicited user preferences. This also invites limits on individual questions within bundled messages and broader comparisons with optimized no-question and VoI policies.

Human annotation. Six professional annotators from an in-house pool took part, two in each of three tasks, with no annotator in more than one: val-idating the judge’s readability and question-value scores, validating the request classifier’s labels, and rating pairs of conversations for burden. Annotators were informed of the purpose of the study. The material consists of simulated conversations and contains no personal data. 

Data and models. We use publicly released benchmarks ( τ -bench, τ 2-bench, WebShop, and BrowseComp-Plus) under their licenses, and com-mercial and open-weight language models. Task conversations use simulated users.

Action generation, review, and memory updates share the served backbone, route, and reasoning set-ting. Reasoning models use medium effort. Memory M = ( P, s, I ) contains verbatim user records, a revisable summary, and observation links. Review receives memory, selected evidence, and remaining budget; it approves, substitutes, or blocks requests. Tool actions and final answers by-pass review. Budgeted + Review + Summary re-moves user records; Budgeted + Review removes all persistent memory. D Request Classification and Budget Accounting 

GPT-5.6-Terra classifies requests from the policy and conversation. Required-only authentication/-confirmations bypass review and incur no charged cost; any discretionary component makes a mixed message discretionary. Substitutions are reclassi-fied from final text. BrowseComp charges every ASK. A 100-case human audit finds 91.0% mean classifier–human agreement, compared with 90.0% human–human agreement (Appendix E.2). This au-dit examines application of the request rules; read-ability/value judge validation is a separate study. 

Enforcement. The main-text protocol states N in the agent’s prompt for every domain and caps deliv-ered messages identically across budgeted methods. On τ , the budget notice accompanies the bench-mark’s native instructions; self-review also receives the remaining budget. At exhaustion, proposed re-quests are suppressed; a system notice instructs proceeding with available information, allowing two retries. Continued requests receive a fixed re-fusal in context, at most twice per turn, without reaching the simulator. Persistent asking produces 

“I’m unable to make further progress with the infor-mation currently available” instead. No-ask uses 

N = 0 . WebShop refuses excess ASK actions; No-ask has no ASK. The initial τ budget notice states the question limit, distinguishes optional requests from required policy exchanges, and instructs the agent to spend questions where the answer changes its actions. Its full text is reproduced in Appendix I. The exhaustion notice begins “You have no re-maining allowance for optional questions to the user in this conversation” and directs the agent to proceed with available information, policy defaults, and judgment. The fixed context reply is “I’m sorry, I don’t have time to answer more questions. Please proceed with the information I’ve already given you, using reasonable defaults and your best judgment.” 

Message content. A message contains about two atomic questions (Table 14) and, in WebShop, asks for about two withheld requirements. Compound requests obtain 1.7 items per session at N = 1 

versus 2.1 unrestricted. Reading-effort cost penal-izes demanding requests; the cap counts messages. Unrestricted requests are 76% clarifications, 5% confirmations, and 19% suggestions; at N = 1 ,94% are clarifications, chiefly removing later re-quests.

E.3 A Judge from Another Model Family 

Grok-4.6 re-scores 1,989 fixed-hash sampled ques-tions, up to 21 per model/domain/policy (Unre-stricted, Budgeted, Budgeted + MGR), using the same prompts. Rank correlations are 0.69 for value and 0.85 for effort (Table 12). Both judges esti-mate −1.6 effort points for Budgeted + MGR ver-sus Budgeted, but value gains are +3 .5 under the paper’s judge and an uncertain +0 .7 under Grok. Relative own-vendor value advantages are an un-certain +0 .8 for the first judge and +3 .4 for the second. We also re-scored the 80 held-out human-annotated pairs per rubric of Table 10 ( τ -bench and WebShop) with Grok-4.6, using identical inputs, prompts, and tie rule. By a rule fixed in advance, a substitute judge counts as less human-aligned if the 95% interval of the agreement difference (paper’s judge minus substitute) lies above zero. On these pairs it does on both rubrics: +13 .1 [+5 .3, +21 .5]for question value and +18 .8 [+11 .0, +27 .6] for readability. The paper’s judge agrees with annota-tors about as often as annotators agree with each other (question value: 90.0% vs. 87.5%), while Grok agrees less (76.9%). Of Grok’s 37 disagree-ments among the 160 judge–annotator comparisons on question value, 35 are tie-versus-side and two are reversals. The gap is concentrated on τ -bench (+22 .5 [+10 .3, +36 .6]), which is also where the judges disagree about the MGR agent’s value gain on the 1,989-question sample ( +4 .6 vs. +1 .4). On WebShop, where no agreement difference is de-tectable ( +3 .8 [−5.0, +13 .1]), neither judge finds a gain. This comparison favors the paper’s judge in two ways: the rubrics were developed with it on devel-opment pairs, and the held-out pairs were stratified by its score gaps. The result therefore shows that a judge used without calibration is less reliable, not that one model family is better. We report value under the calibrated judge and recommend check-ing any substitute judge against the released human pairs before use.

F.2 Persistent Memory and Self-Review Memory ablations. The MGR agent (Budgeted + MGR) in Tables 3 and 5 uses persistent user records, a revisable task summary, and question self-review with the remaining budget. User records are appended when replies arrive; the sum-mary and evidence links are updated within self-review. Budgeted + Review + Summary removes user records but retains the summary and evidence links. Budgeted + Review retains question self-review and the same evidence window, but car-ries no memory between reviews. Budgeted re-moves both memory and self-review. Compared with Budgeted + Review, Budgeted + MGR saves 6.2% in user-attention cost and adds 2.9 question-value points. Removing user records alone has a smaller effect, supporting the contribution of per-sistent memory. 

Computational overhead. Our overhead mea-surement estimates that self-review and memory maintenance add an average of 1.8 model calls, approximately 15k tokens, and 8 seconds of model-call latency per session, excluding base-agent com-putation. 

Wider evidence window without memory. Athree-GPT-model τ follow-up ( N = 1 –3, one trial, 1,998 sessions) expands the evidence window of Budgeted + Review from 6,000 to 9,072 tokens, the nominal combined evidence/memory allowance. It gains 2.5 value points but still costs 4.8% more and scores 3.3 value points below Budgeted + MGR (Table 17). Its equal-cost reward deficit is uncertain overall ( −0.7), but supported on Telecom ( −4.4)and Astra ( −3.4). Design. We pair complete user-facing trial-0 con-versations for the same task and backbone (GPT-6-Astra or GPT-5.4; four domains). Analysis and findings. Alignment averages the two annotators’ shares of non-tie answers choosing the higher-cost side. We use 10,000 paired boot-strap draws, resampling conversation pairs with both annotators’ labels together; the pre-specified criterion is a 95% interval above 50%. Agreement and Cohen’s κ include ties; alignment rates appear in Table 4. Question-burden alignment is 90.8% [84.9, 95.8] at different counts and 71.7% [59.1, 82.9] at equal counts; count gives the same ranking in the former. Overall-burden alignment is 62.5% [52.5, 72.5] and 75.0% [64.5, 84.9], respectively. Question agreement is 99/120 ( κ = 0 .70 ), over-all agreement 95/120 ( κ = 0 .60 ). On equal-count pairs, the longer conversation is chosen in 49.5% of question-burden and 37.5% of overall answers; because pairs were restricted to a length ratio of at most 1.5, this comparison has limited range, and the main text instead reports the word count of the agent’s questions. These are transcript impressions, not fatigue or time during live interaction. This study does not separately examine the classifier’s exemptions, which Appendix E.2 validates. 

Component analysis. To identify which terms carry the equal-count alignment, we scored each equal-count pair by one component at a time, using the same final labels, alignment measure, and boot-strap, and a reading rule fixed before alignment was computed: a score is supported if its 95% in-terval lies above 50%. Because counts are equal, count plus effort reduces to effort and count plus value to value. Value alone is supported (71.1% question burden, 73.6% overall) and matches the full cost (full minus value +0 .6 [−1.4, +2 .9] for question burden and +1 .4 [0.0, +3 .4] overall); ef-fort alone (62.7%, 57.3%) and the word count of the agent’s discretionary questions (49.6%, 56.7%) are not (Table 4). The full cost exceeds effort alone on overall burden by 17.7 points [ +5 .2, +30 .9]. Pairs were selected for a full-cost gap of at least 0.5 units, which favors the full cost and whichever component drives its gaps. Within-pair effort gaps are small (median 0.10 cost units versus 0.70 for value), so the study has limited power to detect a contribution from reading effort.
