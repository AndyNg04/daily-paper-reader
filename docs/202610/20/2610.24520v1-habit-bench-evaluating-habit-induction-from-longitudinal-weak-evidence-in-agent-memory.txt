Abstract In long-term interactions with large language model (LLM) agents, users reveal habits through their choices and actions. These habits capture implicit user information that agents must infer across conversations. However, individual observations may provide only partial evidence about a habit or when it applies. Retaining past interactions alone does not ensure that agents can infer habits and apply them appropriately. We introduce HABIT-Bench to evaluate how well agent memory systems infer habits from weak evidence and apply them to later requests. We construct synthetic user histories from task-oriented dialogue data and controlled habit graphs. The histories span hundreds of sessions across food, finance, software, and travel. Four-choice tasks assess agents’ ability to infer user habits and apply them appropriately. They include temporary exceptions, changes in habits, and suggestions that users have not accepted. Sampled tasks undergo independent human review. We evaluate eight memory methods with Qwen3-235B-A22B and GLM-5.3-Flash. The best-performing memory method achieves 33.61% macro accuracy across the four domains. Performance remains limited even when annotated evidence is supplied directly. These results expose a persistent gap between access to past interactions and the ability to infer and appropriately use user habits. 

## 1. Introduction 

Long-term interaction requires large language model (LLM) agents to learn from experience, not merely retain explicit facts and preferences [Shinn et al., 2023, Xu et al., 2026]. Associative and latent memories offer complementary mechanisms for organizing and retaining experience [Gutiérrez et al., 2024, Wang et al., 2024, 2025]. Useful personalization depends on inferring user characteristics and preferences from interaction history [Nam et al., 2026, Zhong et al., 2024, Zollo et al., 2025] and deciding when these regularities should guide a response. Context and subsequent changes can alter whether an otherwise useful default applies [Jiang et al., 2025, Wood and Rünger, 2016]. Existing benchmarks address complementary parts of this problem. LoCoMo and LongMemEval assess recall and reasoning over extended histories [Maharana et al., 2024, Wu et al., 2024], while MemoryAgentBench adds incremental learning and selective forgetting [Hu et al., 2026a]. Pref Eval examines implicit preference inference and following, while PersonaMem tracks evolving user profiles [Jiang et al., 2025, Zhao et al., 2025]. PERMA and DynamicMem study evolving preferences and habits [Liu et al., 2026, Xie et al., 2026]. BenchPreS and OP-Bench examine when personalization should be withheld [Hu et al., 2026b, Yoon et al., 2026], while MemoryArena and Mem2ActBench connect memory to subsequent action [He et al., 2026, Shen et al., 2026]. We define habit memory as the ability to infer behavioral defaults from incomplete evidence across sessions and apply them according to their scope, exceptions, temporal validity, and user endorsement. A relevant past interaction need not establish a valid default. A repeated choice may apply only in one context, and an assistant’s suggestion does not become a user preference merely because it appears in the history. The target is the support that memory provides for a justified decision, rather than a particular memory representation [Rabinowitz et al., 2018, Siththaranjan et al., 2024]. HABIT-Bench constructs synthetic histories using task-oriented dialogue seeds and controlled habit graphs. It contains 114 users, 37,152 sessions, and 3,328 probes across food, finance, software, and travel. The domains cover complementary evidence structures. Food combines repeated choices with contextual contrasts, and Travel tests behavioral-rule recovery and its application to new requests. Finance and Software emphasize reconstructing user-confirmed workflows and tracking their changes across sessions. Candidate actions differ in their use of habits, including applying an outdated choice, extending a default beyond its scope, or treating an unaccepted suggestion as an established decision. Memory methods process each user’s history chronologically and supply context to a shared base model. We evaluate eight memory methods alongside retrieval baselines and a compressed-history control. The best memory-method macro accuracy is 33.06% with Qwen3-235B-A22B [Yang et al., 2025] and 33.61% with GLM-5.3-Flash [Zeng et al., 2026]. These results are close to the best retrieval baselines, while GLM’s compressed-history control reaches 41.98%. Oracle Evidence improves access to relevant observations but still leaves substantial decision errors. The results identify both the reconstruction of habits and their appropriate use as important targets for memory system evaluation. Our contributions are as follows. 

Capability definition. We formulate habit memory as the joint problem of inferring behavioral defaults and determining when the evidence supports their use. 

Benchmark construction. We introduce a four-domain benchmark with chronological histories,

Evaluation and diagnostics. We compare memory systems under a shared answer protocol and provide diagnostic controls for evidence access and downstream decision making. The experiments show that elaborate memory pipelines do not consistently outperform simple retrieval on these tasks. 

## 2. Related Work 

Long-term memory evaluation. LoCoMo evaluates long-conversation question answering, summa-rization, and multimodal generation [Maharana et al., 2024], while LongMemEval tests extraction, multi-session and temporal reasoning, updates, and abstention [Wu et al., 2024]. MemoryAgentBench examines retrieval, learning, long-range understanding, and selective forgetting under incremental input [Hu et al., 2026a], and MemOps diagnoses memory operations and their composition [Hao et al., 2026]. 

Implicit and evolving user modeling. PERMA studies preference formation and refinement [Liu et al., 2026], while DynamicMem evaluates evolving attributes, habits, and preferences across applications [Xie et al., 2026]. HorizonBench constructs graph-controlled preference trajectories with traceable provenance [Li et al., 2026]. RefMem-Bench tests behavioral pattern induction, temporal dynamics, and implicit boundaries from fragmented multimodal evidence [Lin et al., 2026]. HABIT-Bench focuses on whether longitudinal evidence supports a behavioral default and its subsequent application. 

Selective personalization. BenchPreS tests preference application under social and institutional constraints in third-party communication [Yoon et al., 2026]. OP-Bench examines irrelevant memory use, repetition, and sycophancy [Hu et al., 2026b]. HABIT-Bench couples selectivity with weak-evidence induction, testing scope, exceptions, temporal validity, and user endorsement. 

Memory-grounded agent behavior. MemoryArena evaluates experience reuse across interdependent sessions [He et al., 2026], and Mem2ActBench tests memory-dependent tool selection and parameter grounding [Shen et al., 2026]. PersonaTrail studies personalized web navigation [Yang et al., 2026], while PersonalAlign’s AndroidIntent evaluates intent resolution and proactive GUI assistance [Lyu et al., 2026]. IBA-Bench connects implicit user modeling to task execution under enduring traits and transient states [Song et al., 2026]. HABIT-Bench uses non-interactive action selection with a shared answer LLM to compare the context produced by different memory systems. Table 1 compares these evaluation targets.

We check that the choices cover the request, the evidence supports the intended decision, and the context is consistent. The resulting lifelines are source-grounded synthetic histories, not longitudinal records of the source participants.

3.4. Human Validation 

Human validation tests whether the intended decision is recoverable from the annotated evidence, independently of a memory system’s ability to find that evidence in a long history. Two human reviewers, A and B, independently inspect the request, four alternatives, and a chronological evidence packet without seeing the gold answer or system predictions. They select the uniquely supported action and assess eight criteria covering answerability, evidence sufficiency, scope, boundaries and exceptions, choice balance, naturalness, source grounding, and privacy. An item without a uniquely defensible answer receives no choice rather than a forced guess. A third human reviewer, C, adjudicates disagreements in either the answer or quality judgments before the merged record is frozen and compared with the gold labels. Appendix B details the protocol, sampling, and domain-specific results. Independent review covers 200 Food, 340 Finance, 311 Software, and 618 Travel probes. A/B answer agreement over jointly valid choices is 99.50%, 100.00%, 99.68%, and 92.84%, respectively, with domain-specific denominators and Cohen’s 𝜅 reported in Appendix Table 6. The quality rubric is stricter than agreement with gold: four Finance items initially receive Modify because their alternatives omit an additional output-placement requirement, although the evidence supports the intended habit. These local issues were corrected before final evaluation, while the audit retains the original modification flags. The remaining 336 Finance items and all 311 Software items pass adjudication. All 79 content-revised Travel items pass targeted gold-blind validation, and all 200 reviewed Food items pass naturalness checks after naturalization. High independent agreement and the rubric’s ability to detect narrow construction defects support the quality of the reviewed evidence and decision labels. These checks assess decision recoverability given the evidence, not human retrieval from full histories. 

## 4. Experiments 

4.1. Experimental Setup Systems and models. We organize the comparison by the role of memory in each system: controls, retrieval baselines, memory methods, and multi-store memory methods. The No Memory and Full Memory controls omit the interaction history or provide a compressed history, respectively. The retrieval baselines select sessions directly from the history and comprise Recency-5, Recency-10, BM25 RAG, Dense RAG, and Temporal Hybrid RAG. The memory methods construct and maintain their own

memory representations: A-MEM [Xu et al., 2026], Mem0 [Chhikara et al., 2025], MemOS [Li et al., 2025], MemRL [Zhang et al., 2026], LightMem [Fang et al., 2026], and SeCom [Pan et al., 2025]. Letta [Packer et al., 2023] and MIRIX [Wang and Chen, 2025] are shown separately as multi-store memory methods, reflecting their coordination of distinct memory stores. The other six are grouped for presentation rather than treated as a single architecture. References to the eight memory methods include both groups. Qwen3-235B-A22B [Yang et al., 2025] and GLM-5.3-Flash [Zeng et al., 2026] are the two primary language models. Within each setting, all methods use the same model to select an answer and to perform memory operations that require an LLM. Dense retrieval components use a fixed BGE-M3 encoder [Chen et al., 2025]. Together with additional controls, oracle diagnostics, and experiments with smaller Qwen3 models, the evaluation covers 308 configurations across methods, models, and domains. 

Inference protocol. Methods maintain a separate memory for each user and process sessions in chronological order, using only the history available at each probe’s visibility cutoff. We set the decoding temperature to zero. The two primary model settings use the same prompt for selecting an action and require outputs to follow a fixed JSON schema. In the GLM experiments, the Qwen3-8B tokenizer is used only to measure token budgets, not to generate memories or answers. Context construction and token budgets vary by method. We report accuracy over all probes within each domain and macro accuracy as the unweighted mean of the four domain accuracies. Appendix E reports supplementary accuracy averaged across users and, where available, bootstrap confidence intervals obtained by resampling users. It also provides the model configurations, decision prompts, token budgets, and rules for truncation, retries, and answer parsing. 

Baselines and oracle controls. Retrieval baselines use the request alone, without the answer alternatives, to select complete sessions from the visible history. No Memory omits the interaction history, while Full Memory supplies a compacted history that fits within its context budget. Oracle Evidence supplies the private annotated evidence, whereas Oracle Habit State supplies the private habit state and required action. Both oracle conditions use information unavailable to the evaluated methods and serve only as diagnostic controls. 

4.2. Main Results 

Table 3 evaluates whether current memory systems can infer habits from longitudinal weak evidence and apply them to subsequent decisions. Three findings emerge across the two primary model settings. 

Habit induction and action selection remain challenging. Across the eight memory methods, four-domain macro accuracy ranges from 27.01% to 33.06% with Qwen3-235B-A22B and from 30.42% to 33.61% with GLM-5.3-Flash. Even the best configurations achieve only approximately one-third accuracy, despite using the primary model for both memory operations and action selection. The task requires selecting one of four actions and is scored by exact match, without an LLM judge. The model need not formulate a free-form response, but must still distinguish actions supported by the user’s history from plausible yet unsupported alternatives. Habit-conditioned decision making remains a demanding evaluation target across the tested memory designs and model settings. 

The benefit of memory depends on the domain. Under Qwen3-235B-A22B, the best memory-method results improve over No Memory by 20.32 percentage points on Food and 13.07 points on Travel. In Finance, all eight methods fall below the 23.54% No Memory point estimate. In Software, the largest gain is 1.03 percentage points. The domain contrast also appears with GLM: the best memory-method accuracies are 28.29% on Finance and 25.44% on Software, compared with 54.62% on Travel. 4.3. Diagnostic Controls and Evidence Analysis 

Annotated evidence leaves substantial decision difficulty. Under Qwen3-235B-A22B, Oracle Evidence achieves 39.26–58.25% accuracy across domains, while Oracle Habit State achieves 98.41–99.26% (Table 4). The same qualitative separation appears with Qwen3-8B. Supplying the annotated evidence therefore does not by itself resolve the task. Oracle Habit State additionally exposes the private active state and required action, demonstrating that the answerer can map this privileged information to the correct alternative. The comparison diagnoses remaining difficulty after evidence selection, while combining differences in reconstruction requirements and supplied information. Evidence access and decision correctness remain distinct. For the six source-attributed Qwen3-32B methods, Hit@5 ranges from 37.77% to 41.44%, and annotated-evidence recall from 11.17% to 13.89% (Appendix E.5 Table 13). Hit@5 indicates whether any of the first five attributed sessions is annotated as positive evidence. Evidence recall measures the fraction of the annotated set covered by these sessions. The joint accuracy of the answer and the evidence (Joint A+E) is 12.92-16.20%, requiring a correct answer and at least one evidence hit. Clean Grounded@5 is 5.49-8.20% on its eligible subset and additionally requires that none of the attributed sessions be labeled nonbinding. This stricter condition describes the composition of the attributed context. It does not directly measure whether the answerer improperly follows a retrieved suggestion. These diagnostics distinguish evi-dence access, answer correctness, and the exclusion of nonbinding observations, without interpreting an evidence hit as complete reasoning support or differences between eligible subsets as an error decomposition. This distinction matters when the decisive information is distributed across sessions. Retrieving a user’s later selection may be insufficient if an earlier session defines the alternatives, just as retrieving an established default may be insufficient without a subsequent exception or replacement. An evidence hit can therefore identify a relevant observation without establishing which action is justified at the probe’s target time. The diagnostic goal is to assess whether the retrieved context supports the complete decision, including the conditions under which the remembered behavior applies. The capability slices in Appendix D provide a complementary analysis. Method rankings vary across temporal resolution, provenance, reference reconstruction, induction, and exception handling. Strong relative performance on one requirement does not imply the same ordering on another. Overall accuracy should thus be read alongside these diagnostics, which identify distinct demands on memory without attributing every error to retrieval or to habit induction alone.

## 5. Conclusion 

HABIT-Bench evaluates whether agents can infer behavioral defaults from longitudinal weak evidence and use them to make context-appropriate decisions. Its four domains require agents to integrate distributed observations while tracking applicability, exceptions, temporal validity, and user endorse-ment. Across the evaluated configurations, memory benefits vary substantially by domain, and richer memory pipelines do not consistently outperform retrieval or budget-feasible history compression. Oracle controls show that supplying annotated evidence still leaves substantial decision difficulty, while evidence-attribution diagnostics distinguish partial retrieval from grounded action selection. These findings motivate memory representations that preserve the relationships between a default, its supporting observations, and its conditions of validity. HABIT-Bench provides a controlled setting for studying how such representations support context-appropriate decisions.

## Appendix A. Domain-specific Construction and Validation 

The four domains share chronological user histories and a deterministic four-choice interface, while differing in their source tasks, evidence structures, and habit composition. The following sections describe the construction and validation of the evaluated datasets. 

A.1. Food Templates and source compatibility. The Food pipeline starts with 20 habit templates for private preparation, finishing, and serving choices. Each template specifies its applicability condition, default action, a competing action, boundary condition/action, and exception condition/action. Illustrative axes include the placement of herbs, chili, and briny accents, as well as recipe finishing styles. Tem-plates that are effectively generic safety rules are filtered out. Trigger patterns constrain assignment to compatible recipe seeds, so that an oven-related habit is not inserted into an unrelated cooking task. The dialogue and recipe seeds come from CookDial [Jiang et al., 2023]. User continuity, habit assignments, and probe labels are constructed within HABIT-Bench rather than inherited from CookDial. 

Evidence scheduling. Each user receives seven habits. A stable habit has ten signal sessions: one candidate shortlist, one distant ordinal resolution, three ratified reuses, two boundary observations, one one-case exception, one nonresolving rehearsal, and one rejected assistant suggestion. Key signals are distributed across early, middle, and late history. The boundary observations deliberately include a weak positive and an adjacent near-boundary negative: the contrast is locally available even though the overall habit evidence is longitudinal. This is not a claim that every supporting observation is far from every other observation. Sixty ordinary sessions are added to the 70 signal sessions, giving 130 sessions per user and 3,900 sessions in total. 

Naturalization and probes. Naturalization rewrites planned sessions into cooking conversations while preserving recipe facts and habit evidence. Validation checks turn limits, protected recipe numbers, evidence-index alignment, preference leakage in ordinary sessions, mechanical phrasing, and benchmark-related terms. Each of the 210 user-level habits yields direct-use, boundary, and exception probes. Query surfaces reduce direct overlap with reuse evidence, and all four alternatives are adapted to the current scenario so that the gold action is not the only physically applicable option. The final dataset contains 630 probes. 

Exception scope and validation. Exceptions authorize a local departure from the default rather than a durable replacement. The decision target distinguishes applying the default, respecting its boundary, and following the exception in its applicable context. Naturalization and human validation are part of the construction pipeline, with review criteria and results reported in Appendix B. 

A.2. Finance Source transformation and persona consistency. The Finance source from MultiDoGO [Peskov et al., 2019] contains 8,832 conversations and 157,229 utterances. Conversations are reconstructed by identifier and turn order, then assigned a primary task intent. They supply task types, slot categories, interaction patterns, and style exemplars, while original identities and sensitive financial fields are replaced in the synthetic lifelines. The resulting 17,405 source-linked sessions use 7,049 primary source conversations, with no primary seed used more than three times. Source-linked and evidence-annotated sessions are overlapping categories.

Habit state and evidence topology. There are eight candidate habits. Each user activates six and leaves two absent; two active habits undergo replacement. A.5. Cross-domain Interpretation 

The common four-choice interface does not make the evidence mechanisms identical. Food includes both split decisions and repeated reuse, with local contrast for boundaries. Finance and Software pre-dominantly test cross-session decision reconstruction and policy-state maintenance. Travel emphasizes behavioral-rule recovery and compositional application. The benchmark therefore evaluates integra-tion of incomplete longitudinal evidence, not exclusively statistical inference from unratified behavior. Likewise, deterministic action labels do not establish a probabilistic habit-calibration task. These distinctions should constrain both the capability claims and the interpretation of domain-averaged accuracy.

Input truncation. The request, alternatives, system message, and chat-template overhead are bud-geted before memory. The remaining allocation reserves eight additional tokens. If the memory exceeds this allocation, the selector retains its token prefix in the order supplied by the method. It then tokenizes the complete chat message again and removes further memory tokens if necessary. The request and alternatives are never truncated. An input that exceeds the ceiling even without memory is rejected. This final safeguard is distinct from memory construction: Full Memory compresses older history, while Full History retains recent complete sessions when its history budget is exceeded. 

Retries and parsing. Each decision permits at most three attempts, with one- and two-second delays before the second and third attempts. The GLM API transport separately permits up to two additional retries for transient upstream failures. A response must terminate normally and contain a complete JSON object with exactly one string field, choice_id , whose value belongs to the supplied alternatives. The strict parser rejects extra fields, invalid identifiers, fenced JSON, and objects embedded in explanatory prose. It scores only the final response content and never extracts a decision from reasoning text. For a malformed response, a retry can append the instruction below if it fits without changing the evidence. Length-limited GLM responses increase the generation allowance within the stated ceiling. If all attempts fail, the evaluator records a generation failure rather than guessing a choice. Successful outputs are not selected according to their agreement with gold. 

> Format-only retry instruction

Return ONLY one JSON object with the single key "choice_id", whose value is one of ["<id 1>", "<id 2>", "<id 3>", "<id 4>"]. Do not return user/session records, memory updates, or rationale. 

Memory output constraints. MIRIX uses structured output for memory construction. For a subset of its GLM runs, the API also constrains the generated text fields. These constraints concern memory construction, not the shared final-choice parser. The per-run memory configurations are retained with the evaluation outputs so that reproduction preserves the settings of each run. 

Smaller Qwen models. The supplementary Qwen3-4B, 8B, 14B, and 32B experiments use the same system message and the same three user-message fields, but omit the final selection instruction after the alternatives. Thinking is disabled for these smaller Qwen models. Their earlier parser accepts a valid choice from JSON, a labeled choice_id expression, or a bare choice identifier. Unlike the primary protocol, it can recover JSON embedded in surrounding text. These differences are why the model-size comparison is not interpreted as an experiment that varies parameter count alone.
