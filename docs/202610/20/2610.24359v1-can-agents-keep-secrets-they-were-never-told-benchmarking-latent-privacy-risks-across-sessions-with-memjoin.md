## 摘要
为支持持续交互和个性化协助，智能体会使用长期记忆，在多个会话间保留并整合用户信息。复用此类记忆时，智能体可能会在完成一项与敏感关系无关的普通任务时，将该关系陈述出来。在写入记忆时，受保护的关系以及能够揭示该关系的线索组合可能仍然是隐蔽的，因为此时后续记录和任务尚不可知。本文介绍 MemJoin，这是一项隐私基准测试，包含 288 个合成分析案例：完整历史记录能够推导出一项敏感关系，但任何单个会话都不足以推导出该关系。我们使用相同的答案生成模型评估了六种记忆系统，并设置了完整历史记录和无历史记录两种对照。每种系统都按照会话顺序写入并更新记忆，随后为一项普通任务检索上下文，而目标标注信息仅由评估方掌握。我们分别检查目标属性值是否出现在存储记录和检索上下文中，以及最终答案是否陈述了完整且与特定人员关联的关系。在另一个针对预先指定子集开展的配对测试中，移除共享标识符和其他连接线索后，即使所有被检查的目标属性值仍然可见，完整关系的输出也可能发生变化。这些发现表明，仅检查属性是否可见，不足以评估不同会话的记录组合后会揭示什么。

## Abstract
To support sustained interactions and personalized assistance, agents use long-term memory to retain and combine user information across sessions. Reusing such memories can lead an agent to state a sensitive relation while completing an ordinary task that does not require it. The relation to protect and the combination of clues that reveal it may remain hidden at memory write time, when later records and tasks are still unknown. In this paper, we introduce MemJoin, a privacy benchmark of 288 synthetic analysis cases in which the complete history entails a sensitive relation, but every individual session is insufficient. We evaluate six memory systems with the same answer-generating model, alongside full-history and no-history controls. Each system writes and updates memories in session order and later retrieves context for an ordinary task, while target annotations remain with the evaluator. We separately check which target attribute values appear in stored records and retrieved context, and whether the final answer states the complete, person-linked relation. In a separate paired test on a prespecified subset, removing shared identifiers and other connecting clues can change complete-relation output while all checked target attribute values remain visible. These findings show why checking attribute visibility alone is insufficient to evaluate what records from different sessions reveal together.

## 1. 核心问题与整体含义

### 1.1 研究背景与动机
- 长期记忆使智能体能够跨会话保存用户信息，支持持续交互与个性化服务，但也会让原本分散、单独看并不敏感的信息被重新组合。
- 例如，不同会话分别提供“用户预约代码”“代码对应的诊疗项目”“机构与日期”，完整历史便可能揭示“该用户将在某日到某机构接受某项诊疗”。
- 即使后续任务只是准备物品清单，智能体也可能主动说出这一**任务并不需要的敏感关系**。

论文将这一风险称为 **跨会话推断（cross-session inference）**。这里的“从未被告知的秘密”并不是无证据猜测，而是指：**完整历史支持该关系，但任何单次会话都没有完整提供它。**

### 1.2 为什么既有隐私检查不足
- **写入时难以识别**：后续线索与任务尚未出现，无法提前确定哪些记录组合后会变得敏感。
- **风险可能在多个阶段形成**：记忆写入、更新整合、检索拼接，都可能促成关联。
- **只检查敏感词或属性不足**：服务名称、地点、日期同时出现，不等于已经将它们与具体个人绑定；反过来，普通标识符也可能成为揭露关系的关键。
- **只检查最终答案不足以解释机制**：没有泄露，可能是系统保护得好，也可能只是相关信息根本没有被保存或检索出来。

**整体意义**：隐私保护的对象不应只有单条记录与敏感字段，还应包括**多条记忆能够共同推导出的个人关系**。

## 2. 方法论：核心思想、技术细节与评估流程

### 2.1 从敏感关系反向构造案例
论文提出 **MemJoin** 基准，从一个固定目标关系出发构造历史：

> 用户主体 → 敏感服务或属性 → 地点 → 日期

随后将事实及连接线索拆散到多个会话中，要求：
1. 完整历史能够支持目标关系；
2. 任意单个会话不足以支持目标关系；
3. 破坏关键连接后，关系不再成立；
4. 后续普通任务不需要披露该完整关系；
5. 目标与权限标注仅供评估者使用，不提供给普通智能体。

### 2.2 三种证据配置
每种配置各有 96 个案例：

| 配置 | 会话数 | 设计意图 |
|---|---:|---|
| 写入物化（Writer materialization） | 4 | 测试记忆写入、合并互补事实时形成关系的风险 |
| 更新整合（Update consolidation） | 5 | 测试更新操作将早期与后续记录联系起来的风险 |
| 检索连接（Retrieval join） | 4 | 测试多个相互引用的记录进入同一上下文后形成关系的风险 |

需要注意，这些配置描述的是**证据如何分布**，并不能直接证明模型实际在哪个内部阶段完成了推断。

### 2.3 案例质量检查
- **确定性检查**：验证字段一致性、来源、重复内容，以及运行输入与评估标注隔离。
- **隐私规范审查**：三个标注模型检查场景家族的分享边界，存在分歧时人工裁决。
- **语义验证**：
  - 三个验证模型都必须认为每个单独会话不足以建立目标绑定；
  - 至少两个模型必须从完整历史恢复目标关系；
  - 破坏关键引用后，三个模型都不能恢复完整关系。

### 2.4 分阶段评估流程
每次试验：
1. 从空记忆库开始；
2. 按时间顺序输入会话；
3. 由框架自身写入、更新与检索；
4. 固定回答模型根据普通任务生成答案；
5. 分别检查存储内容、输入上下文与最终输出。

设置四种主要输入条件：
- **Task only**：只有任务，无历史；
- **Full history**：直接提供完整原始历史；
- **Retrieved memory**：提供框架检索出的记忆，最多 5 条；
- **All memory**：跳过检索筛选，提供该次试验导出的全部记忆。

另外使用 **Itemized history**，将原始消息转换为分条记录，以控制“呈现形式变化”的影响。

### 2.5 关键指标
#### 信息可见性
- **Avail.**：上下文中是否同时具备服务或属性、地点、日期的词面覆盖。
- 分别检查存储与实际提供给回答模型的上下文，以区分写入丢失和检索遗漏。
- 该指标**不检查主体绑定，也不等价于语义可推导性**。

#### 披露等级与比例
- **A0**：没有目标成分；
- **A1**：出现目标成分，但没有与用户绑定；
- **A2**：用户与敏感服务或属性绑定；
- **A3**：在 A2 基础上，增加地点或日期之一；
- **A4**：用户、服务或属性、地点、日期构成完整关系。

进一步报告：
- **A4 rate**：所有回答中达到 A4 的比例；
- **Conditional A4**：仅在通过可见性检查的输入中，计算 A4 比例；
- **DR**：每个案例运行三次，至少两次达到 A4，才计为披露案例。

#### 任务效用
- **TCR**：三次回答中至少两次完成任务的案例比例；
- **Helpfulness**：0—3 分帮助度；
- **Refusal**：拒绝或未提供实质内容的回答比例。

三个评审模型先对语义字段投票，再推导披露等级，避免仅靠关键词判断。

## 3. 实验设计：数据、场景与对比方法

### 3.1 数据与 Benchmark
MemJoin 包含 **288 个合成英文案例**：
- 12 类信息，每类 24 个案例；
- 每类包含两种场景：
  - 对合法接收者的过度披露；
  - 向不适当接收者或为不兼容目的披露；
- 共 24 个场景家族，每个家族 12 个案例；
- 三种证据配置各 96 个案例。

覆盖身份与账户、联系方式、设备标识、生物特征、资产、家庭与信仰、活动位置、就业、医疗、教育、金融、法律与移民等信息。

这些类别由作者参考 NIST SP 800-122 的示例自行分组，**不是 NIST 官方分类体系**。案例不使用真实个人记录，部分文本通过受约束的模型改写降低模板痕迹。

### 3.2 对比的记忆系统
共评估六种框架：
- A-Mem
- LangMem
- Mem0
- MemGPT
- MemoryBank
- SimpleMem

统一配置：
- 回答模型：**Qwen3.5-9B，非思考模式**；
- 各框架的模型配置统一使用该模型；
- 向量模型：**BGE-M3**；
- 常规检索最多返回 5 条记录；
- 每个条件运行三次。

### 3.3 隐私干预实验
干预在记忆构建和检索结果冻结后单独施加，不是顺序叠加：

| 干预 | 操作 |
|---|---|
| M1 隐私指令 | 强调数据最小化，警告跨记录组合风险 |
| M2 数值与实体清洗 | 替换名称、地点、机构、日期和标识符等 |
| M3 跨记录连接线索移除 | 将共享名称或标识符改为局部、不共享的标签 |
| M4 检索预算限制 | 只保留排名第一的记忆条目 |
| 输出过滤 | 由 critic 删除答案中超出权限的片段，必要时拒绝 |

其中，M2—M4 主要在目标值可见性均为 100% 的 A-Mem 与 MemGPT 上测试，以减少原有信息缺失的干扰；M1 和输出过滤覆盖全部六种框架。

## 5. 实验数量与充分性、公平性

### 5.1 大致实验规模
- **主要实验**：六框架 × 两种记忆视图，加上两个参考输入，共 **14 个条件**。
  - 每个条件 288 个案例、每例三次；
  - 合计 **12,096 条原始回答**。
- **输入干预与呈现控制**：共 **16 个条件**，计划覆盖 **13,824 条回答**；少量标注失败使部分配对分析剩余 287 个完整案例。
- **输出过滤**：覆盖六种检索记忆输入与两个参考输入，共 **8 个条件、6,912 条编辑后回答**。
- 另有证据配置、场景家族、可见性保持子集、隐私与完成度联合分布等分析，以及部分案例的会话组合和逐次写入诊断。

这些条件复用同一批案例，**不等于多个独立数据集**。

### 5.2 实验设计的充分性
- 对“是否存在跨会话关系披露”“信息在哪个环节丢失”“连接线索是否影响输出”等问题，实验比较系统。
- 但全部结果仍建立在一个合成基准、一个主要回答模型及较短历史上，尚不足以估计真实部署中的泄露发生率。

### 5.3 公平性与统计处理
**较好的控制：**
- 固定回答模型、向量模型、案例与检索条数；
- 每次重置记忆，按时间顺序写入；
- 检索记忆与全部记忆共享同次试验的存储；
- 隐藏框架身份进行评审；
- 使用案例级 bootstrap、配对 McNemar 检验及 Holm 多重比较校正；
- 明确排除缺失标注，而不是将其当作“不泄露”。

**仍需谨慎：**
- 相同检索条数不等于相同 token 预算，不同框架的条目长度和信息密度不同。
- 温度为 0 时，三次试验不是三个独立用户样本，直接历史条件还可能高度重复。
- 部分分析是在观察基线结果后规划的，属于探索性研究与后续固定方案的结合，而非整项研究预注册。
- 多个评审模型可能存在相关偏差，投票不能替代独立人工验证。

## 6. 主要结论与发现

### 6.1 六种框架均出现完整关系披露

| 系统／输入 | 输入可见性 Avail. | 案例披露率 DR | 任务完成率 TCR |
|---|---:|---:|---:|
| A-Mem | 100.0% | 13.9% | 20.1% |
| LangMem | 60.2% | 5.9% | 13.5% |
| Mem0 | 64.8% | 9.4% | 14.6% |
| MemGPT | 100.0% | 11.1% | 18.1% |
| MemoryBank | 98.4% | 8.7% | 14.6% |
| SimpleMem | 81.5% | 9.4% | 14.2% |
| 完整历史 | 100.0% | 22.9% | 18.1% |
| 仅任务 | 0.0% | 0.0% | 12.8% |

六框架数据为常规检索条件。

- 所有记忆框架都存在风险，但披露率低于完整历史。
- 无历史消除了本实验中的目标披露，却导致帮助度下降、拒绝率升至 53.1%。

### 6.2 低披露率不一定代表更好的隐私保护
- LangMem 的 DR 最低，但其目标值可见性也最低。
- 在目标值确实到达回答模型的输入中，六框架的条件 A4 比例为 **10.8%—14.4%**。
- 因此，部分低披露表现来自信息丢失，而非准确识别“哪些信息不该分享”。

### 6.3 记忆重写会改变被披露的案例
- 六框架累计有 168 个“框架—案例”披露结果，其中 56 个在完整历史对照中未达到案例披露阈值，约占三分之一。
- 这里不是 168 个不同用户或不同案例，而是跨框架累计计数。
- 说明完整历史不是覆盖所有风险的上界，评估需要实际运行记忆流水线。

### 6.4 连接线索具有独立于目标值可见性的影响
在 **207 个移除线索后仍保持全部目标值可见的配对案例**中：

| 输入 | 移除前 DR | 移除后 DR | 变化 |
|---|---:|---:|---:|
| A-Mem | 16.4% | 7.7% | −8.7 个百分点 |
| MemGPT | 15.0% | 1.9% | −13.0 个百分点 |
| 分条完整历史 | 25.6% | 8.7% | −16.9 个百分点 |

这提供了论文最关键的实验证据：**即使属性值仍在，共享标识符等连接线索也会显著影响完整关系输出。**

### 6.5 防护效果取决于删掉的是“值”还是“连接”
- **M2 实体清洗、M4 Top-1 检索**：使所测案例的 DR 降为零，但损害任务完成。
- **M3 连接线索移除**：
  - A-Mem：DR 约从 13.9% 降至 5.6%，TCR 从 20.2% 变为 19.2%；
  - MemGPT：DR 从 11.1% 降至 1.4%，TCR 从 18.1% 变为 20.6%。
  - 不过拒绝率上升，帮助度也略降，不能视为完全无代价。
- **M1 隐私指令**：效果不稳定；部分框架披露减少伴随着更多拒绝。
- **输出过滤**：五种框架案例 DR 为零，MemGPT 为 0.3%，但依赖额外权限标注，应视为偏乐观结果。

### 6.6 输出过滤后的 TCR 上升需要谨慎解读
- 288 个案例中，有 84 个完成标准同时要求“不添加无关个人细节”。
- 输出过滤的整体 TCR 增益完全来自这些案例。
- 在其余 204 个主要按所需内容评估的案例中，六框架平均 TCR 反而从 13.6% 降至 12.0%。

因此，不能把过滤后的 TCR 上升直接解释为任务能力增强，也不能从“披露回答完成率较低”推导出披露对完成度的因果影响。

## 7. 优点与亮点

- **问题定义明确**：将“历史蕴含但单会话不蕴含”的关系披露，与直接复制已有敏感信息区分开。
- **评估覆盖记忆全流程**：不只看答案，还区分存储保留、检索提供与最终表达。
- **可见性与关系绑定分离**：避免把关键词同时出现误认为完整泄露。
- **配对干预有较强解释力**：在保持目标值可见的子集中移除连接线索，比仅做框架间比较更能支持核心论点。
- **兼顾隐私与效用**：同时报告完成度、帮助度与拒绝率，避免奖励“什么都不回答”的系统。
- **研究边界披露较充分**：附录说明词面指标缺陷、缺失标注、探索性分析，以及输出过滤的额外信息优势。

## 8. 不足与局限

### 8.1 外部有效性有限
- 全部为合成英文数据，历史仅 4—5 个短会话，每次由一条用户消息与确认回复组成。
- 未覆盖真实长期交互中的噪声、矛盾、模糊指代、多用户、多语言、多模态与动态授权。
- 单案例只固定一个目标关系，不能代表真实系统中大量潜在关系的组合空间。

### 8.2 模型与系统覆盖有限
- 主要回答模型只有 Qwen3.5-9B 非思考模式，尚不清楚结论如何迁移到更强模型、不同规模模型或推理模式。
- 六框架统一模型有利于控制变量，但未必反映各框架最佳部署配置。
- 引用中仍存在 `VERSION`、`COMMIT` 占位信息，给精确复现带来不确定性。

### 8.3 指标存在盲区
- Avail. 是词面覆盖检查：同义改写可能漏判，不相关记录中的词也可能被合并计入。
- 不同框架的 Conditional A4 基于不同输入子集，不能直接作为公平的安全排名。
- A4 要求服务、地点、日期全部出现；只有敏感服务与用户绑定的 A2，也可能造成严重实际伤害。
- 三次至少两次的案例阈值会淡化偶发泄露，而真实隐私损害可能一次即成立。
- 不覆盖接收者结合外部知识才能恢复的隐含泄露与侧信道泄露。

### 8.4 评审与任务效用存在偏差风险
- 构造验证和答案评分都较依赖 LLM，缺乏充分的独立人工一致性评估。
- 隐私规范部分由作者设定，未必覆盖不同文化、组织和真实用户偏好。
- 所有主要条件的 TCR 都偏低，约为 13%—20%，限制了对高能力真实助手中隐私—效用权衡的判断。
- 某些完成标准包含隐私要求，因此 TCR 并非完全独立于隐私表现。

### 8.5 防护尚未解决端到端部署问题
- M3 主要在冻结后的检索上下文上改写，没有验证持续写入、更新与后续任务中的长期效果。
- 移除共享标识符可能破坏合法关联；即使 TCR 变化小，拒绝率和帮助度仍可能受损。
- 输出过滤需要普通回答模型没有的任务权限元数据，并与一个评审模型共享模型来源，存在信息优势与评审偏差风险。
- 论文没有提出形式化隐私保证，也没有解决如何自动、准确判断当前任务需要哪些连接。

**总体评价**：MemJoin 的主要贡献是提出一种更贴近长期记忆特征的隐私评估视角，并以配对实验说明“连接方式”不能被“属性是否出现”替代。它有力揭示了问题，但尚不是具有普遍保证的防护方案；下一步关键是实现**任务条件化、选择性的记忆关联控制**，并在真实长期交互中验证。
