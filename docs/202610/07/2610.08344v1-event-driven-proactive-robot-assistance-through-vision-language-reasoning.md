## 摘要
在协作操作中，辅助行为通常由用户指令触发，因此高层推理往往由请求驱动。然而，在流畅的人类团队协作中，协作者常根据某项动作产生的结果推断下一步有助于推进任务的行动，而非等待指令。受此启发，我们研究了一种事件驱动的主动辅助方法：在推理阶段，无需用户提供任务说明，而由人机交互的结果触发辅助推理。为此，我们提出一种事件驱动框架，利用事件监测器跟踪工作空间状态变化，并在事件完成后提取稳定的前后状态快照，以表征由此产生的状态转变。随后，冻结的预训练视觉语言模型（VLM）利用其语义先验推断任务情境、判断是否适合提供辅助，并在需要时根据观察到的状态转变生成一系列辅助动作。为确保输出可执行且可验证，我们将动作限制为一组动作原语，并通过整数 ID 引用物体。我们在三项不同的真实世界桌面协作任务中评估了同一框架，且未进行针对特定任务的训练或微调。该事件驱动框架取得了与提供用户指令的变体相当的性能。

## Abstract
Assistance in collaborative manipulation is often initiated by user instructions, making high-level reasoning request-driven. In fluent human teamwork, however, partners often infer the next helpful step from the observed outcome of an action rather than waiting for instructions. Motivated by this, we investigate an event-driven formulation of proactive assistance, where human--object interaction outcomes initiate assistive reasoning without user-provided task specifications at inference time. To this end, we propose an event-driven framework that monitors workspace state changes with an event monitor and, upon event completion, extracts stabilized pre/post snapshots that characterize the resulting state transition. A frozen pretrained Vision-Language Model (VLM) then uses its semantic priors to infer the task context, decide whether assistance is appropriate, and, when needed, generate a sequence of assistive actions from the observed transition. To make outputs executable and verifiable, we restrict actions to a set of action primitives and reference objects via integer IDs.We evaluate the same framework across three distinct real world tabletop collaboration tasks without task-specific training or fine-tuning. The event-driven framework achieves performance comparable to variants given user instructions.

## 1. 核心问题与整体含义

### 研究背景与动机
- 现有协作机器人通常采用**请求驱动**模式：用户先给出明确指令、模糊请求或控制线索，机器人再启动高层推理与行动规划。
- 这种模式即使具备较强的意图推断能力，仍需要人类主动发起交互，难以实现流畅、低负担的协作。
- 人类伙伴则经常根据他人刚完成的动作及其结果，推断下一步需求，而不必等待逐步指示。

### 核心研究问题
**机器人能否仅根据人—物交互造成的工作空间变化，在没有用户任务说明的情况下，自主决定何时介入、帮助什么，以及如何执行？**

论文提出“事件驱动的主动辅助”：
- 将人类交互引起的、持续存在的工作空间变化视为事件。
- 在事件完成后，以稳定的交互前后图像触发视觉语言模型（VLM）推理。
- 从状态变化中推断任务情境，选择执行辅助动作或等待。

### 整体意义
本文的主要价值不是训练一个新的机器人基础模型，而是提出一套**将物理交互结果转换为推理触发条件与语义证据的系统框架**。

需要注意：“无需用户任务说明”不等于“没有任何先验”。系统仍使用固定协作提示词、预定义动作接口，以及预训练 VLM 的语义知识。

## 2. 方法论：核心思想与关键技术

### 2.1 总体流程

系统形成如下闭环：

**监测工作空间 → 确认交互完成 → 提取稳定前后快照 → 识别物体并编号 → VLM 推断辅助目标 → 校验与几何落地 → 执行 → 验证结果 → 更新基准状态。**

其中：
- VLM 负责语义理解与符号规划。
- 机器人控制系统负责事件检测、物体几何信息、运动规划和执行验证。
- 不进行任务专用训练或微调。

### 2.2 事件检测与稳定状态提取

事件监测器采用三个状态：
1. **交互前**：保存稳定的桌面高度图和 RGB 图像。
2. **交互中**：检测持续的工作空间变化。
3. **交互后**：确认场景已经稳定，才启动推理。

检测使用两类变化指标：
- **瞬时变化比例**：比较相邻观测，判断是否正在发生动作。
- **累计变化比例**：比较当前观测与交互前基准，判断是否产生持续状态变化。

关键设置包括：
- 瞬时与累计变化阈值均为 `0.010`，分别要求连续 2 次与 3 次满足条件。
- 静止阈值为 `0.008`，要求持续静止约 `0.7 秒`。
- 监测桌面上方 `6–80 mm` 的高度范围。
- 事件完成还需满足变化区域重叠度、深度有效性、高度一致性和侵入区域比例等条件，例如连续 3 次检查的 IoU 不低于 `0.60`。

**作用**：避免在手部遮挡、物体移动途中或短暂扰动时启动规划，以减少证据不完整和计划过时的问题。

### 2.3 物体解析与整数 ID 接口

- 使用 **FastSAM** 获取物体实例，再结合 RGB–D 信息进行几何细化。
- 为每个物体分配整数 ID，保存其：
  - 边界框与实例掩码；
  - 顶面中心；
  - 尺寸和主方向等几何信息。
- 前后图像分别标记为 PRE、POST，**仅在交互后图像上叠加物体 ID**，确保模型引用的是当前可执行场景中的对象。

这一设计将“语义目标选择”与“精确空间坐标计算”分离，降低直接生成机器人坐标的风险。

### 2.4 VLM 规划与保守介入原则

固定系统提示要求模型：
- 依据前后变化预测人类下一步需求；
- 仅在目标明确且场景支持执行时行动；
- 如果有多个合理选择，或没有适用物体，则等待；
- 不得编造物体 ID。

动作被限制为：
- `pick`：抓取指定 ID 的物体；
- `place`：相对于参考物体放置；
- `wait`：不行动并说明原因。

放置关系限定为左、右、上、下或放在其上，输出采用结构化 JSON。

### 2.5 推理早停与人工问答

论文通过监测生成推理中的目标 ID，实现早停：
- 从包含“移动、放置、抓取”等操作表述的语句中提取候选 ID。
- 忽略疑问、假设性表达和元层面描述。
- 若同一 ID **连续出现 3 次**，认为目标已收敛，停止继续生成。
- 再调用一次模型，固定目标 ID，只补全放置位置等计划字段。

若推理正常结束但候选目标仍不稳定：
- 向人类提供候选 ID 和 `wait` 选项，进行简短问答（QA）。
- 若仅出现一个候选 ID，且最终计划选择该对象，可直接接受。

**重要限制**：早停固定目标后，最终补全阶段不再允许选择 `wait`。因此，重复出现同一目标只是“生成稳定性”信号，并不保证目标正确。

### 2.6 几何落地、执行与验证

- 抓取位置采用物体顶面中心，夹爪保持固定向下姿态。
- 放置位置由参考物体中心、沿指定方向的物体尺寸、模型给出的偏移比例及安全余量共同计算。
- 左右等方向以摄像机视角定义；“放在其上”单独处理高度。
- 通过相机到机器人基座的标定变换获得执行坐标，使用 **MoveIt** 规划运动。
- 执行前检查动作类型、ID 是否存在，以及是否出现“未抓取就放置”等非法序列。
- 执行后验证计划中的空间关系；失败时最多允许再执行一次。

这些检查提高了可执行性，但不能完整验证模型推断的目标是否真正符合人的意图。

## 3. 实验设计与 Benchmark

### 3.1 数据与场景

论文没有采用标准公开数据集，而是构建了真实桌面协作评测：

| 任务 | 事件数 | 场景与目标 |
|---|---:|---|
| T1：算式补全 | 60 | 人类补入算式中的一个数字块，机器人选择正确结果块完成单数字四则运算 |
| T2：桌面分类 | 30 | 人类放置三个物品，建立水果/蔬菜与垫子的对应关系，机器人分类剩余物品 |
| T3：工具引入 | 30 | 人类放入削皮器，机器人选择唯一适用的土豆并移到砧板 |

- 主 benchmark 共 **120 个事件**。
- 各事件改变物体布局，T1 还改变候选数字块组成。
- T1 有一半场景在算式中也出现与答案相同的数字，用于测试对象引用是否准确。
- 主评测均设计为存在**唯一正确的辅助动作**。

### 3.2 评价指标

结果分为：
- **自主成功**：无需人工问答，完成正确辅助。
- **有效 QA**：正确选项被保留，并通过人工选择得到正确计划。
- **失败**。

论文的核心指标为：

**Appropriate（适当响应率）＝自主成功率＋有效 QA 比例。**

因此，95% 的 Appropriate **不能解读为 95% 的完全自主成功率**。此外，论文报告了延迟，但所给文本没有明确其是否覆盖事件检测、人工响应和完整机械执行全过程。

### 3.3 对比方法

为控制变量，各方法使用相同 VLM、动作接口和基本执行系统，主要改变提示信息：

- **本文方法**：不提供任务专用用户指令。
- **显式请求**：提供明确任务规则，如计算算式并移动答案。
- **隐式请求**：提供宽泛协作目标，如帮助人类整理桌面。
- 上述三类设置均比较保留和移除交互前图像的情况。

这些是**统一框架中的请求式变体**，并非对引用论文原始完整系统的直接复现比较。

- **取消事件触发**：每隔 1 秒或 2 秒固定调用模型。
- **取消交互前图像**：仅使用当前状态。
- **取消推理早停**。
- **早停阈值敏感性**：比较 `k=0、2、3、4`。
- 文中提到在另一模型 **Qwen3.8-27B** 上观察到一致趋势，但没有提供完整结果表。

另有 **150 个边界事件**：

## 6. 主要结论与发现

### 6.1 无任务指令也能取得较高适当响应率

| 方法 | 自主成功 | 有效 QA | Appropriate |
|---|---:|---:|---:|
| 本文方法 | 87.5% | 7.5% | **95.0%** |
| 显式请求 | 79.2% | 16.7% | 95.8% |
| 隐式请求 | 82.5% | 8.3% | 90.8% |

- 本文方法在 120 个事件中对应 **105 次自主成功、9 次有效 QA、6 次失败**。
- 与显式、隐式请求的失败率差异均未达到统计显著。
- 分任务 Appropriate 为：T1 **100%**、T2 **80%**、T3 **100%**，说明分类场景的空间放置仍是明显短板。

### 6.2 三项核心组件均有贡献
- 取消事件触发：
  - 2 秒周期：Appropriate 降至 **27.5%**；
  - 1 秒周期：降至 **31.7%**。
- 移除交互前图像：
  - 降至 **84.2%**；
  - 失败从 6 次增至 19 次，配对检验 `p=0.010`。
- 取消早停：
  - 降至 **75.8%**；
  - 三类任务延迟均增加。
- `k=3` 在测试阈值中表现最好，失败率 **5%**，中位延迟约 **8.93 秒**。

### 6.3 请求信息并非总是有益
- 请求措辞会显著影响表现，例如“同类物品”与“相同物品”的语言歧义可能引发不必要的等待。
- 在必须拒绝行动的边界场景：
  - 本文方法正确率为 **76.7%**；
  - 显式请求为 **50.0%**；
  - 隐式请求为 **60.0%**。
- 这说明请求信息可能增加行动倾向，但不一定提高适当性。本文方法相对更保守，不过仍有 **23.3%** 的必须等待场景出现错误抓取。

## 7. 优点与亮点

- **触发机制具有明确价值**：不仅研究“如何规划”，还研究“何时启动推理”。
- **前后状态信息紧凑有效**：无需连续视频推理，也能提供任务变化线索。
- **跨任务复用**：同一冻结 VLM 与统一接口覆盖三种不同推理类型，无任务专用微调。
- **语义与几何解耦**：整数 ID 和动作原语提高输出的可解析性、可检查性与可执行性。
- **具有执行闭环**：结合输入稳定性检查、计划合法性检查和执行后验证。
- **关注拒绝行动能力**：边界测试避免仅用“存在正确动作”的场景评价主动辅助。
- **如实展示人工介入与失败**：没有将所有正确结果包装为完全自主成功。

## 8. 不足与局限

### 实验覆盖与泛化
- 场景局限于桌面、少量候选物体、固定抓取姿态及简单放置关系。
- 未验证复杂遮挡、动态照明、多用户、连续并发操作、长任务链和开放环境。
- 三任务有效不等于已证明广泛的开放世界泛化能力。
- 对没有明显持续几何变化的意图线索，如注视、犹豫和口头表达，当前事件机制未必适用。

### 意图推断与偏差风险
- 模型依赖常识和物体功能先验，可能将“通常如此”误当成“用户此刻确实想如此”。
- 实验强调唯一可推断目标，可能高估真实人机协作中的意图可识别性。
- 缺少个体偏好、用户授权及“正确但不受欢迎的帮助”评价。

### 早停与安全性
- 同一 ID 重复出现不等于正确性或置信度得到验证。
- 早停后取消 `wait`，可能将错误候选锁定为必须执行的目标。
- 几何与结构检查只能验证动作是否可执行，不能保证其符合用户意图。
- 论文没有提供完整的人机协作安全评估，例如接触风险、紧急停止和风险分级。

### 系统与应用限制
- 约 9 秒量级的推理延迟和四卡服务器依赖，可能限制自然协作节奏与部署成本。
- 空间推理仍会失败，例如选对物体却放到垫子外或已有物体上。
- 依赖事件结束后再行动，更准确地说是**基于上一动作结果预测下一步**，而非在人类动作完成前进行实时预判。
- 缺少用户满意度、工作负荷、实际任务效率以及公开可复现 benchmark 的充分说明。

**总体评价**：论文为“由物理事件而非用户请求启动机器人辅助”提供了有说服力的真实系统验证。其最扎实的贡献是稳定事件接口、前后状态证据与受约束执行的组合；现有证据支持受控桌面场景中的可行性，但尚不足以证明普遍可靠、完全自主或安全的开放环境协作能力。
