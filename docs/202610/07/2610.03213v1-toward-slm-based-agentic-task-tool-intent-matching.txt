# Toward SLM-based agentic task-tool intent matching 

Chiara Troiani Arash Salarian Majed El Helou Benjamin Ryder Jean Diaconu Hervé Muyal Marcelo Yannuzzi 

Cisco Systems, Switzerland 

{chtroian, asalaria, melhelou, beryder, jdiaconu, hmuyal, mayannuz}@cisco.com 

## Abstract 

Tool-equipped AI agents use tool calls to access data and act on external systems. Horizontal growth of agentic systems increases the number of these interactions, and further motivates the need for automated, per-call oversight that can operate at low latency and/or on-prem. Conventional authorization schemes can determine whether an agent is allowed to invoke a tool, but cannot assess the agent’s underly-ing cognition, specifically, whether the tool selection represents a logical, relevant step toward satisfying the intent of the task or not. Consequently, an allowed call may still deviate from the task’s intent: a rogue agent might deviate the calls or nudge other agents to make a combination of calls that would not align with the intent of the task. Therefore, every call needs to be verified. In this study we investigate the applicability of Small Language Models (SLMs) to this purpose: an SLM functions as a task-tool relevance classifier that evaluates every selected tool independently against the assigned task and returns a relevance signal for downstream enforcement. Equipped with a novel dataset with multi-tool tasks whose required tools span distinct Model Context Protocol (MCP) servers, we used prompt-optimization, supervised fine-tuning, and reinforcement learning through GRPO to optimize and specialize SLMs. 

## 1 Introduction 

Agents within a multi-agent system (MAS) rely on tool usage as the main method to interact with the environment. As these systems scale out, a trajectory highlighted by recent discourse on the Internet of Agents [1, 2] and its next evolution into the Internet of Cognition [3, 4], the research into fending off threats and ensuring the security of these systems is also advancing rapidly. Our work extends Task Based Access Control (TBAC) to intent-based TBAC: broadly, TBAC dynamically activates, tracks, suspends, consumes, and revokes permissions as the authorization steps of a task progress [5]. In other words, a permission is available only when required by the current stage of an active task, and only for its authorized lifetime and usage. However, the original TBAC does not determine whether a tool semantically matches a user’s or an agent’s natural language intent. Furthermore, classical TBAC assumes that the tasks, workflow steps, dependencies, and permissions have been explicitly modeled. In agentic systems, however, due to the enormous flexibility of natural language, explicit modeling of these components ahead of time becomes impossible. In order to assess semantic relevance of a tool to a given task a system needs to inspect both the subject query as well as the tool descriptions. Cloud-based, frontier LLMs with reasoning capability are effective for analyzing these calls (see the results section). However, in many organizations, concerns over privacy, cost, latency or organizational policies limit the practical applications of these models. The hypothesis for our study is that optimizing an SLM for this purpose is sufficient to achieve high accuracy while satisfying the operational constraints.

## 2 Method 

2.1 Methodology Foundation 

Let S denote the set of MCP servers parsed and prepared for our problem’s underlying data. For 

s ∈ S , let Ts be its entire tool catalog, with t ∈ T s denoting one tool (the tool’s name and its metadata). We represented tool candidates as server-tool pairs c = ( s, t ), keeping identically named tools on different servers distinct. We created tasks that should require their intended sets of tools for execution. For a task q, let G(q) be its annotated grounding set of candidate tools, 

R(q) = {s ∈ S : ∃ t ∈ T s, (s, t ) ∈ G(q)} the represented servers, and Nq = |G(q)| the number of tools paired with q that are relevant to its execution. We set the task-tool relevance matching label 

y(q, c ) = 1 if c ∈ G(q) and y(q, c ) = 0 otherwise. Our generated data thus satisfy: 

Nq = |G(q)| = |R(q)|, Nq ∈ { 2, 3}.

Hence, each task originally has two or three grounding tools, exactly one from each represented server, and is cross-MCP with |R(q)| ≥ 2. In contrast, the prior work within ASTRA drew all grounding tools from one unique server s [6, 7], which makes for lower-complexity tasks. We retained its data samples and pairwise targets, as well as similar data processed and derived from TOUCAN [8], while additionally extending with our novel tasks that have tools spanning across multiple servers. We simulate intent-breaking matches with y(q, c ) = 0 by associating q to candidate tools c / ∈ G(q),while preserving the total number of distinct tool servers Nq . We assigned y(q, c ) labels separately for each candidate c of a task q to enable fine-grained data curation, and a group identifier links all the different candidates from the same multi-tool task. 

Classification objective. Given our labeled task-candidate pairs D = {(qi, c i, y i)}, we formulate task-tool relevance as a binary classification problem. The classifier receives the task q and the candidate tool’s name and description and produces a structured output from which a boolean prediction ˆy(q, c ) ∈ { 0, 1} is parsed. A false positive allows an irrelevant tool, whereas a false negative rejects a tool required by the task; broken outputs are logged as parsing failures. 

Operational objective. Due to the needs of the downstream security task, we set the often used 95 %goal [9, 10] for the accuracy and F1 score. 

2.2 Dataset Setup 

We used a server catalog for data generation containing 352 tools from 12 distinct MCP servers. We divided it into two server-disjoint pools: 194 tools from 8 servers and 158 tools from 4 servers, to serve as non-overlapping validation or test sets. Grounding and alternative tools always remain within their assigned pool, with no task q causing any overlap. For each target size N ∈ { 2, 3}, the first stage uses every tool in the pool equally often as an anchor. Given an anchor, it samples N − 1 distinct servers uniformly at random without replacement from the other servers in the pool, then samples one tool uniformly at random from each chosen server. At the sampling front, anchor coverage is exact; eligible server combinations are equally likely, as are tools within a chosen server. We note that after sampling the realized frequencies can change during generation and curation, and probabilities across all tools differ because server catalogs have different sizes |T s|. The sampled tool sets are then processed with a similar pipeline as ASTRA’s [6], using GPT-5.2 to produce natural-language tasks q matching with the selected tools’ names and descriptions, without exposing the tool-side input schema to avoid over-fitting. The second stage leads to three types of N -tool candidate sets for sampled tasks. A correct set equals 

G(q). A wrong set replaces grounding tools with different tools from the same server. A null set draws candidates from a server outside R(q) but within the same pool, such that its servers and the grounding servers do not overlap. We enforced the wrong and null logic in our cross-server setting, notably by masking all G(q) servers from the sampling pool of null samples. Ultimately, both wrong 

and null are mapped to an irrelevant task-tool label y(q, c ) = 0 . The generation and sampling stages do not mix tool types in a given set, however, curation may introduce heterogeneous candidate sets for a given task, which is why we preserved candidate-level labels. Each candidate set is represented as N task-tool rows for relevance curation. For consistency, we performed a similar curation process as the one proposed by ASTRA [6]. We retained a row only when all recorded curators for that row agreed, and kept only groups containing all expected N rows. Out of our 9289 curated rows, 7811 

formed 3155 complete groups, and 1478 rows in 996 incomplete groups were removed. 22.3 Optimization Approach 

We applied the same sequential optimization strategy to two models of Gemma 3 family (1B and 4B): Base → GEPA → SFT → GRPO .

GEPA [11] produced the prompt used for SFT, and GRPO [12] was initialized from the selected SFT checkpoint. Prompt and checkpoint selection used validation F1 for the relevant class. The test set was evaluated only after all experimental choices had been fixed and shared no MCP servers, tools, or generated tasks with the training or validation splits. Each example contained a task, a candidate-tool name and description, and a target response of the form {"reasoning": "...", "appropriate": true/false} .

GEPA. To optimize agent’s prompt, we used GEPA [11]. We selected a random, balanced subset of the training and validation data ( 500 and 250 samples, respectively). GPT-5.6 Sol was the optimizer/reflection LLM, with a reflection mini-batch size of 35 . For reporting the test results, however, we used the entire test dataset. 

SFT. Using the optimized prompt, we trained LoRA [13] adapters ( r = 32 , α = 64 ) on 4404 class-balanced, single-tool ASTRA examples and selected the checkpoint on 1136 validation examples. We treated single-tool tasks as a lower-complexity curriculum stage because they expressed direct task-tool relationships without the compositional dependencies of multi-tool tasks. We masked prompt tokens and minimized cross-entropy over the model response. Training used AdamW with a peak learning rate of 1.9 × 10 −4, 10 % warmup, three epochs, an effective batch size of 64 , and a maximum sequence length of 1024 in bf16 . To select the hyper-parameters, we used TPE sampler (Tree-structured Parzen Estimator) in Optuna [14], optimizing for validation set’s F1.

GRPO. Starting from the F1-selected SFT checkpoint, we applied GRPO to a class-balanced mixture of single-tool, same-MCP multi-tool, and cross-MCP multi-tool examples ( 9485 training and 2927 

validation). The deterministic reward combined schema compliance, label correctness, and a penalty for excessive reasoning; false positives and false negatives were penalized equally, and invalid outputs received an additional penalty. We did not use an LLM-based reasoning judge. We updated the LoRA adapters and sampled 16 responses per prompt at temperature 1.1. We optimized the Dr. GRPO [15] objective with sequence-level importance sampling, batch-scaled group-relative advantages, and a KL penalty of β = 10 −3. Training used a learning rate of 10 −5 for three epochs at an effective batch size of 256 in bf16 ; prompts and completions were capped at 1024 and 192 tokens, respectively. 

## 3 Experimental Setup 

We evaluated the Gemma 3 1B and 4B model sizes and sought the smallest evaluated model that can reach this target through progressive specialization. The training data were balanced with respect to the binary relevance label, whereas the validation and test sets retained their curated class distributions. Prompt, hyperparameter, and checkpoint selection used only the validation split, with F1 for the relevant class as the primary selection metric. The held-out test set was evaluated only after all experimental choices had been fixed. Aggregate performance is reported in Table 1. Inference was performed with vLLM using a fixed decoding configuration across all four conditions. We report parse success, end-to-end (E2E) accuracy, accuracy, precision, recall, F1, false-positive rate, and false-negative rate. E2E accuracy was computed over the complete test set, with malformed or unparseable outputs counted as incorrect predictions. All other classification metrics were computed from successfully parsed Boolean predictions, with failed parses reported separately. We obtained 

95 % bias-corrected and accelerated confidence intervals from 10 000 paired bootstrap resamples. A server with a single H100 GPU was used for all three steps of the optimization.

## 5 Conclusion 

While frontier LLMs can meet the 95 % operational target (GPT-5.6 Sol achieved an accuracy of 

98 .58 %), both SLMs initially performed well below this threshold, with E2E accuracies of 60 .94 %and 87 .48 % for Gemma 3 1B and 4B respectively. Sequential specialization, however, substantially improved the performance of both model sizes. After GRPO, Gemma 3 1B reached 89 .60 % E2E accuracy, remaining below the operational target, whereas Gemma 3 4B reached 96 .13 %, slightly surpassing it. Although our evaluation is limited to synthetic, LLM-curated task-tool pairs and two model sizes from a single family, these results support our hypothesis that specialized SLMs can provide a viable operational alternative to frontier models for intent-based TBAC in agentic systems. 4References
