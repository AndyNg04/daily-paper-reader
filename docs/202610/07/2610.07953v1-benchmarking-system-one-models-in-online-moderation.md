## 摘要
在线内容审核系统必须在作出可审计且可转交人工审核的判定时，应用不断变化的平台政策、社区规则和既往判例。我们评估了 System One 模型能否支持这一场景。这类模型接受自然语言上下文，但返回类型化选项、概率或分数。在五项内容审核基准测试中，Jev 的表现可与专用参考系统相媲美，并在若干基于政策和有害内容识别的场景中达到或超过这些系统。随后，我们通过控制信息条件，区分书面规则、检索到的判例，以及对候选答案空间的限制。总体而言，检索到的判例有助于提升 Jev 的表现：在固定答案空间的条件下，Jev 对政策条款的精确选择和有害内容的区分能力均有所提高。Laya 的表现则不够稳定：检索往往会改变其正向预测率或无违规率，却未能提升区分能力。在若干场景中，Jev 的置信度可用于支持选择性审核，但其校准效果并不稳定；Laya 的置信度在错误排序方面用处较小。这些结果表明，SOM 驱动的内容审核前景可期。

## Abstract
Online moderation systems must apply changing platform policies, community rules, and prior decisions while producing decisions that can be audited and routed to human review. We evaluate whether System One Models, which accept natural-language context but return typed choices, probabilities, or scores, can support this setting. Across five moderation benchmarks, Jev is competitive with specialized reference systems, matching or exceeding them in several policy-grounded and harmful-content settings. We then use controlled information conditions to separate written rules, retrieved precedents, and restrictions on the candidate answer space. Jev generally benefits from retrieved precedents, improving exact policy selection and harmful-content discrimination when the answer space is held fixed. Laya is less consistent: retrieval often shifts its positive prediction rate or no-violation rate without improving discrimination. Jev confidence can support selective review in several settings, although it is not consistently calibrated; Laya confidence is less useful for ranking errors. These results show a promising future for SOM-powered content moderation.

## 1. 核心问题与整体含义：从“识别有害内容”到“执行具体政策”

### 研究背景与动机
- 在线内容审核不仅需要判断内容是否有害，还需要回答：**它违反了当前平台或社区的哪一条规则？判定是否可靠？是否应转交人工复核？**
- 传统分类器通常围绕固定标签体系训练，平台政策、社区规范或违规类别发生变化后，往往需要重新标注数据或调整模型。
- 大语言模型可以在推理时读取自然语言规则与案例，但自由文本输出会增加解析、验证和系统集成的难度。

### 核心研究问题
论文评估 **System One Models（SOM，系统一模型）** 是否能兼顾自然语言上下文理解与结构化决策输出，具体围绕四个问题展开：
1. 能否根据书面政策和既往审核案例作出判定？
2. 检索案例究竟提升了判断能力，还是仅改变预测倾向、缩小候选答案空间？
3. 输出概率与置信度能否支持人工复核分流？
4. 政策审核中的表现能否推广到一般有害内容检测？

### 整体含义
- 本文主要是**基准评测与受控实验研究，而非提出新的模型架构或训练算法**。
- 其重要价值是将审核效果拆分为：**判定正确性、具体条款选择、区分能力、概率质量，以及选择性自动处理能力**，避免仅凭准确率或 F1 判断模型是否适合部署。

## 2. 方法论：分离规则、先例与答案空间的作用

### 2.1 模型与输出接口
论文评估 **Jev v1.13** 和 **Laya v0.3**。按照论文定义，SOM 接收自然语言状态与任务描述，直接返回类型化、非自回归输出。

使用三种接口：
- **Choice**：从候选集合中选择答案，同时返回候选概率分布和独立的置信度。
- **Noul**：针对一个二元命题返回概率，不提供独立置信度字段。
- **Score**：根据文字锚点给出序数分数，主要用于探索性毒性类别比较。

**关键区别：Choice 的答案概率和“所选答案正确的置信度”不是同一个量，论文分别评估。**

### 2.2 两类任务
- **政策违规检测**：给定内容及适用规则，输出“不违规”或某条具体违规规则。
  - 二元任务：是否违反任意规则。
  - 精确任务：是否正确选择被标注的规则，或正确选择“不违规”。
  - 每条内容只允许一个最终结果，因此不支持同时输出多条违规规则。
- **有害内容检测**：不提供独立书面政策，直接判断内容是否属于有害、冒犯或不安全类别。

### 2.3 四种信息条件

| 条件 | 书面规则 | 检索先例 | 作用 |
|---|---|---|---|
| Direct | 无 | 无 | 一般有害内容检测的基础条件 |
| NAD | 有 | 无 | 测试仅凭规则的审核能力 |
| RAD | 无 | 有 | 测试仅凭既往案例的判断能力 |
| General | 有 | 有 | 测试规则与案例的联合效果 |

政策选择任务进一步设置三类候选规则：
- **All**：完整适用规则集。
- **Represented**：先例来源语料中出现过的规则。
- **Retrieved**：本次检索到的违规先例涉及的规则。

核心受控比较是：
- **General-all vs. NAD-all**：固定完整答案空间，只增加先例。
- **General-retrieved vs. RAD-semantic**：固定检索候选集合，只增加规则描述。
- 有害内容任务中的 **RAD vs. Direct**：固定接口与二元标签，比较有无先例。

这能够避免把“候选答案变少、任务更容易”误当成“模型更理解政策”。

### 2.4 检索与实验流程
1. 清理重复、矛盾及不适配任务定义的样本。
2. 使用 **qwen3-embedding:4b** 编码内容。
3. 按余弦相似度选取通常为 **5 条**的最近先例。
4. 排除目标自身；PluRule 还排除同一讨论配对，并要求先例来自同一社区。
5. 根据实验条件组织目标、规则、先例和候选答案。
6. 调用相同输出接口，评估判定结果、连续概率与置信度。

跨模型比较时，作者固定共同输入内容和确定性文本压缩；政策实验同时保留 **Jev-full** 与 **Jev-compact**，直接比较 Jev 和 Laya 时使用后者。

### 2.5 指标与统计检验
- **EMA**：完整审核结果的精确匹配准确率。
- **VRR**：违规样本中正确恢复具体规则的比例。
- **NVR**：合规样本中正确判为不违规的比例。
- **Accuracy、F1**：特定决策阈值下的分类效果。
- **AUROC**：不依赖某个固定阈值的区分能力。
- **Brier、ECE**：概率质量与校准。
- **Correctness AUC**：置信度能否把正确决策排在错误决策之前。
- **置信度 ≥ 0.8 的覆盖率与准确率**：选择性自动处理的效果。

主要差异使用配对 bootstrap 的 **95% 置信区间**；PluRule 以完整讨论对为重采样单位。区间未进行多重比较校正。

## 3. 实验设计：五个基准与多类参考系统

### 3.1 数据集及场景

| 基准 | 审核场景 | 主要实验规模与处理 |
|---|---|---|
| **PluRule** | Reddit 社区规则执行 | 六个高支持社区，共 6,371 对、12,742 条评论；另测试官方测试集可恢复的 2,829 对、5,658 条评论 |

| **OLID** | 英文推文冒犯性检测 | 清洗后 14,046 条，使用 offensive / non-offensive 标签 |
| **HateXplain** | 社交媒体冒犯性检测 | 仅保留 offensive / normal，清洗后 14,123 条；不评估 hateful 类 |
| **ModerationBench** | Bluesky 帖子安全审核 | 文本加媒体描述版本，共 3,689 条，其中 Safe 2,584 条、Unsafe 1,105 条 |

ModerationBench 原本是多模态基准。作者用 **InternVL3_5-4B-Instruct** 生成中性媒体描述，再交给文本 SOM；附录还使用 Qwen 和 MiniCPM 描述验证敏感性。

### 3.2 检索来源与数据隔离
- PluRule 六社区主实验使用排除目标讨论对的同语料检索，并补充仅从训练集检索的验证集、测试集实验。
- PluRule 完整测试交集与 HateModerate 使用训练集先例。
- HateModerate 中跨训练、测试重复的 114 条句子不进入检索源。
- OLID、HateXplain、ModerationBench 使用评估语料的 **leave-one-out 检索**：排除目标，但允许其他评估样本的标签作为先例。

### 3.3 对比系统
- **Jev 与 Laya**：在共同输入表示下比较。
- **Detoxify 五个版本**：作为 OLID、HateXplain 的专用外部参考，采用任一类别得分大于 0.5 即判为冒犯的规则。
- **PluRule 已发表系统**：包括 Qwen3-VL 8B、GPT-5.2 的不同上下文与推理设置。
- **始终判为不违规**的基线：PluRule 上 EMA 为 50%。
- ModerationBench 原论文的多模态系统仅作为背景参考，不纳入输入匹配的主要比较。

因此，**与外部系统的结果不能统一理解为严格公平的端到端排名**。

## 6. 主要结论与发现

### 6.1 Jev 的先例增益具有较一致的证据
固定完整规则集合，比较 General-all 与 NAD-all：

| 政策实验 | Jev-compact EMA 变化 | 增益 |
|---|---:|---:|
| PluRule 六社区 | 52.7% → 65.1% | +12.35 个百分点 |
| PluRule 测试交集 | 48.4% → 53.6% | +5.20 个百分点 |
| HateModerate | 29.4% → 51.6% | +22.20 个百分点 |

这些提升不是单纯缩小候选空间带来的。不过，精确政策选择仍远未达到可靠全自动执行的水平。

### 6.2 检索增益依赖模型、数据和接口
- Jev 的 **Noul** 接口在 OLID、HateXplain 上 AUROC 分别由：
  - **0.789 → 0.816**；
  - **0.749 → 0.755**。
- 但 Jev 的 **Choice** 接口在 OLID 上加入先例后，准确率和 F1 都下降，说明不能概括为“检索总能提高性能”。
- ModerationBench 上 Jev 收益更一致：
  - Noul AUROC：**0.902 → 0.940**；
  - 准确率：**84.4% → 87.4%**；
  - F1：**71.8% → 79.6%**。

### 6.3 Laya 经常改变预测倾向，而非改善区分能力
- OLID 的 Noul AUROC：**0.800 → 0.702**。
- HateXplain：**0.604 → 0.515**，接近随机排序。
- HateXplain 的正类预测比例由 **60.8% 增至 97.4%**：虽然 F1 上升，但准确率、区分能力和校准明显恶化。
- ModerationBench 是例外：检索提升 Laya 的 AUROC，但 Noul 的准确率仍下降，进一步显示排序与阈值表现需要分开分析。

### 6.4 高 EMA 未必代表更好的违规识别
- PluRule 测试交集上，Jev-compact RAD 的 EMA 达到 **58.3%**，但 VRR 只有 **26.5%**，NVR 则为 **90.0%**。
- 相比之下，General-all EMA 较低，但 VRR 达到 **43.9%**。

这表明候选集合限制可能通过偏向“不违规”提高总分，同时削弱具体违规识别。

### 6.5 Jev 置信度可用于分流，但不是可靠性保证
- ModerationBench 上，Jev 的置信度 ≥ 0.8 子集：
  - 覆盖 **71.9%** 的模型推断；
  - 准确率达到 **94.3%**，高于总体的 86.7%。
- PluRule 测试交集上，同样阈值覆盖 41.0%，准确率仅 67.6%，说明效果高度依赖场景。
- Laya 的置信度排序较弱，有时高置信度子集也没有更高准确率。

## 7. 优点与亮点

- **信息控制清晰**：将书面规则、检索先例和候选空间限制拆开，是论文最有价值的方法设计。
- **指标解释深入**：同时衡量精确条款选择、二元违规识别、AUROC 与校准，能够揭示表面总分背后的行为差异。
- **跨模型比较较审慎**：采用共同输入表示，避免直接把上下文预算差异误归因于模型能力。
- **统计设计匹配数据结构**：PluRule 按讨论对重采样，主要条件使用配对 bootstrap。
- **附录验证较丰富**：训练集检索、输入压缩、规则簇及媒体描述敏感性分析增强了主要发现的可信度。
- **面向实际审核流程**：关注置信度、自动处理覆盖率和人工复核，而不只关注离线分类分数。

## 8. 不足与局限

### 实验覆盖与泛化
- 仅评估两个 SOM，不能将差异推广为整个模型类别的规律，也不能仅归因于架构。
- 未系统测试多语言、政策更新、跨社区迁移、时间漂移和对抗内容。
- 单选任务排除了 175 条多政策正例，低估了真实审核中多重违规的复杂性。
- HateXplain 排除 hateful 类，因此结论只覆盖其冒犯性子任务，而非完整仇恨言论检测。

### 数据与评测偏差
- 同语料 leave-one-out 检索并非直接使用目标标签，但仍不同于严格时间切分、仅利用历史记录的部署情形。
- 候选规则限制可能使真实规则无法被选择；更高总分可能掩盖规则覆盖不足。
- 先例可能复制历史误判、标注偏差和社区不一致；语义相似也不必然代表政策上相似。
- 缺少系统的群体条件误差与公平性评估。

### 方法解释与外部比较
- 控制实验支持“加入先例改变了表现”，但不足以证明模型真正学会了规则或具备稳定政策推理能力。
- 外部参考的输入、标签映射和阈值并不完全一致，“达到或超过参考系统”应限定到具体指标与条件。
- 未充分分离示例选择、标签分布、示例顺序及文本序列化的影响。

### 部署与可靠性
- 类型化输出方便集成，但**不自动提供充分解释，也不等于已验证的可审计性**。
- 置信度校准不稳定，统一 0.8 阈值不能直接推广到不同任务。
- 未评估实际审核员负担、申诉结果、不同误判成本或在线长期效果。
- 缺少延迟和成本报告，因此尚不能确认其生产环境经济性。

**综合评价：本文对受控评测的贡献比对“全自动审核已可部署”的证明更强。Jev 展现了利用规则与先例辅助审核、支持人工复核分流的潜力，但实际落地仍需要严格的历史数据评估、场景化校准、公平性检查和持续人工监督。**
