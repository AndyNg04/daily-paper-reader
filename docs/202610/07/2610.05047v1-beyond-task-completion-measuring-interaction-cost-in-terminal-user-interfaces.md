## 摘要
大型语言模型（LLM）正越来越多地通过终端用户界面（TUI）使用，但仅衡量任务是否完成，并不能反映界面理解与操作的难易程度。现有的人类评估，以及由 LLM 生成的评分或报告，无法基于经过验证的任务执行情况，对交互投入进行可重复测量。我们提出“以智能体为用户”（Agent-as-a-User）这一评估范式，让 LLM 智能体扮演用户角色。Agent-KLM 将智能体侧的理解成本与操作成本区分开来，并在结构上将其与人类交互关联起来。TUINaut 则通过记录交互轨迹，并借助与执行者无关的判定器验证结果，使这一范式得以实际应用。我们使用 TUINaut-Bench 研究了 15 个真实 TUI 中的 84 项任务，参与者包括 6 名人类用户，并采用了 5 种观察者—评估器配置；此外，还评估了由 3 种领先技术栈生成的 45 个 TUI。相近的总体成功率掩盖了人类与智能体各自完成任务类型上的差异，而理解成本和操作成本的任务排序则呈现相关性，尤其是在操作方面。这一模式在不同配置下均持续存在。生成的 TUI 即使功能正确，仍可能需要改进易用性。上述结果表明，Agent-as-a-User 是一种可重复、以实际执行为依据的任务型易用性测量范式。

## Abstract
Large language models (LLMs) are increasingly used through terminal user interfaces (TUIs), yet task completion alone does not capture how difficult an interface is to understand and operate. Existing human assessments and LLM-generated ratings or reports do not provide repeatable measurements of interaction effort grounded in verified task execution.   We propose Agent-as-a-User, an evaluation paradigm that places an LLM agent in the user role. Agent-KLM separates agent-side interpretation and operation costs and relates them structurally to human interaction. TUINaut operationalizes the paradigm by recording interaction trajectories and verifying outcomes with actor-independent oracles.   Using TUINaut-Bench, we study 84 tasks across 15 real-world TUIs with six human participants and five observation-evaluator configurations, and evaluate 45 TUIs generated by three leading stacks. Similar aggregate success rates mask differences in which tasks humans and agents complete, whereas interpretation and operation costs follow correlated task rankings, especially for operation. This pattern persists across configurations. Generated TUIs can implement correct functionality while still requiring usability improvements. These results position Agent-as-a-User as a repeatable, execution-grounded paradigm for measuring task-based usability.

## 1. 核心问题与整体含义：任务成功不等于界面易用

### 研究背景与动机
- 终端用户界面（TUI）广泛用于文件管理、数据库管理、版本控制和开发运维。它们依赖键盘操作，常包含模式相关快捷键，但可见提示较少。
- 同一任务即使最终完成，也可能经历大量搜索、试错、纠错和结果确认。例如：
  - 缺少滚动提示，迫使用户盲目扫描；
  - 缺少模式切换反馈，导致用户不知道输入是否生效；
  - 隐藏快捷键或保存状态，增加操作探索和结果确认成本。
- 现有评估存在两类不足：
  - **人工可用性研究**能发现问题，但难以低成本、频繁地跨应用与版本重复开展；
  - **LLM 评分或体验报告**主要属于判断性证据，不是来自实际执行、经过结果验证的交互成本测量。

### 核心研究问题
论文研究：**能否让 LLM 智能体充当受控用户，通过实际交互轨迹，为 TUI 提供可重复、与人类交互需求存在关联的任务级成本测量？**

整体含义不是让智能体完全代替人类，而是将其作为一种评估工具，同时衡量：
1. **任务完成情况**：目标是否达成；
2. **理解成本**：确定下一步行动需要多少推理投入；
3. **操作成本**：执行任务需要多少键盘输入。

## 2. 方法论：Agent-as-a-User、Agent-KLM 与 TUINaut

### 2.1 核心思想：智能体作为受控测量工具
- 固定智能体配置，让其仅通过界面观察和键盘输入完成任务。
- 每次任务使用全新上下文，只提供任务描述和行动协议。
- 禁止访问源代码、文件系统、进程状态及任务判定器输出，避免绕过界面直接完成任务。
- 通过实际执行记录成本，而不是要求 LLM 给界面打“易用性分数”。

### 2.2 Agent-KLM：分离理解成本与操作成本
该模型借鉴经典 **Keystroke-Level Model（KLM）**对心理准备与物理操作的区分，但**不预测人类执行时间**，也不将不同成本直接相加。

每条轨迹由多轮“观察—理解—行动”构成：

| 维度 | 智能体测量 | 人类对应测量 |
|---|---|---|
| 理解成本 | 所有轮次的推理 token 总数 | 从初始屏幕到首次提交的交互时间 |
| 操作成本 | 虚拟原子按键事件总数 | 物理原子按键事件总数 |

- **理解成本公式的含义**：累加每一轮产生的推理 token 数。
- **操作成本公式的含义**：将所有行动展开成原子按键后累加。
- 最终报告一个二维成本画像，而非单一总分。
- 人类交互时间与智能体推理 token 单位不同，因此只比较**任务排序相关性**，不比较原始数值大小。

**统一按键计数规则：**
- 使用 US QWERTY 键盘映射；
- 普通按键计为一次事件；
- 修饰键与主键分别计数，例如 `?` 对应 `Shift + /`，计两次；
- 批量输入同样展开，避免把一段文本视为一次操作。

### 2.3 TUINaut：执行、记录与独立验证
评估流程分为三个阶段：

1. **任务初始化**
   - 使用 Docker 固定代码提交、依赖与运行环境；
   - 加载任务数据，并重置到干净初始状态；
   - 通过宿主机 Tmux 会话启动 TUI。

2. **交互执行**
   - 人类直接观看终端，智能体接收屏幕表示；
   - 两者经相同终端输入边界向应用发送按键；
   - 智能体每轮只能选择 `type`、`press`、`submit` 或 `wait`；
   - 记录屏幕、行动、按键时间戳和推理 token，单次运行最多 **100 轮**。

3. **独立结果验证**
   - 提交或退出后，由与执行者无关的预定义判定器检查结果；
   - 检查 shell 状态、文件系统及最终屏幕；
   - 六类断言涵盖命令输出、文件与内容、文本出现/消失以及高亮状态；
   - **所有断言通过才算成功**。

此外，84 项任务中有 **30 项**加入任务指纹，使特定标记进入输入和预期结果，降低通用状态或偶然结果被误判为成功的风险。

### 2.4 三种观察表示
- **Plain**：保留终端字符和布局的纯文本；
- **Semantic**：在文本中加入表示 ANSI 前景色、背景色的标签；
- **Image**：将终端屏幕渲染为 PNG 图像。

## 3. 实验设计：benchmark、场景与对比对象

### 3.1 TUINaut-Bench
- 包含 **15 个真实 TUI、84 项任务、15 个应用级生成提示**。
- 仓库创建时间为 2026 年 1—5 月，旨在降低潜在预训练数据重叠风险。
- 筛选流程：
  - 搜索得到 1,980 个仓库；
  - 超过 50 stars 后剩余 274 个；
  - 两名作者安装并检查，进一步考察 50 个应用；
  - 按可验证性、可复现性、操作可发现性和多样性选出 15 个；
  - 第三名评估者独立检查启动与主要功能。
- 每项任务提供初始化脚本、任务描述、数据 fixture 和结果断言，并在不同时间、机器上人工重复至少五次。

### 3.2 三个研究问题与对比设置

| 研究问题 | 实验内容 | 主要对比 |
|---|---|---|
| RQ1：人机对应关系 | 完成率、两类成本、键盘轨迹 | 6 名人类用户 vs. Plain–Pro 智能体 |
| RQ2：观察表示影响 | 5 种观察—评估器配置 | 纯文本、语义文本、图像及不同评估模型 |
| RQ3：生成 TUI 的可用性 | 原始应用与生成版本执行相同任务 | 3 种生成技术栈 vs. 参考 TUI |

**人类实验：**
- 6 名参与者均有五年以上编程经验，熟悉 Linux 与终端；
- 每人完成全部 84 项任务，主要分析第一次尝试；
- 禁用鼠标，打乱任务顺序，避免同一应用任务连续出现。

**智能体评估配置：**
- Plain–Pro、Plain–Flash；
- Semantic–Pro、Semantic–Flash；
- Image–Vision。
- 每项任务、每种配置重复三次。

**生成应用配置：**
- Claude Code + Claude-Opus-5；
- Codex + GPT-5.6-Sol；
- DeepSeek Harness + DeepSeek-V4-Pro。
- 各自为 15 个参考应用生成一个对应版本，共 **45 个生成 TUI**。
- 生成提示说明功能与开发约束，但不暴露 benchmark 任务或参考界面设计。

### 3.3 指标与统计方法
- 完成情况：成功率；
- 成本：任务内中位数，再跨任务汇总；
- 轨迹：四类按键组成，以及原始按键序列、压缩后的类别序列；
- 相似性：归一化编辑距离与最长公共子序列；
- 排序关系：Spearman 相关系数；
- 多配置一致性：Kendall’s W；
- 不确定性：**10,000 次分层 bootstrap**构造 95% 置信区间。

论文没有在同一数据上系统比较传统 KLM/CogTool、人工问卷或 LLM 主观评分方法；它们主要作为相关研究背景。

- 同时覆盖人机校准、观察表示敏感性及生成应用评估；
- 多次运行、分层置信区间和完整轨迹公开增强结果可信度；
- 固定环境、相同任务与独立判定器，减少评估者主观判断；
- 不只统计文本输入，还分析非文本按键，检验操作相关性是否仅由输入长度驱动。

**仍需保留的判断：**
- 尽管尝试次数较多，独立的人类参与者仍只有 6 名，应用只有 15 个；
- 图像配置同时更换观察模态与模型，**不是纯粹的模态消融**；
- 每种生成栈每个应用只生成一次，未测量代码生成的随机波动；
- 生成实验比较的是完整技术栈，无法分离底层模型、工具和生成预算的贡献；
- 缺少生成 TUI 上的直接人类实验，因此该部分的人类可用性结论依赖参考应用上的校准关系。

---

## 6. 主要结论与发现

### 6.1 相近成功率掩盖任务层面的差异
代表配置 Plain–Pro 下：

| 指标 | 人机任务排序相关性 | 95% 置信区间 |
|---|---:|---|
| 完成率 | 0.348 | [-0.028, 0.568] |
| 理解成本 | 0.622 | [0.204, 0.748] |
| 操作成本 | 0.769 | [0.460, 0.885] |

- 人类总体成功率为 **76.39%**，智能体为 **82.94%**；
- 但完成率相关性的区间包含零，不能据此认定人机任务成功情况稳定对应；
- 两类成本排序相关，尤其是操作成本。

**关键结论：智能体更适合测量任务级交互需求，而非直接复制人类行为。**

### 6.2 操作需求相关，但交互习惯不同
- 智能体可打印按键占 **73.6%**，人类为 **42.6%**；
- 人类导航按键占 **42.4%**，智能体仅 **14.2%**；
- 非文本按键总量仍保持正相关，说明关系并非完全由文本输入长度解释。
- 人机轨迹相似性没有表现出一致的人际相似性劣势，但这**不等于证明二者等价**。
- 智能体重复执行路径比人类路径更规律；人类路径越一致，智能体越容易与其对齐。

### 6.3 更丰富的观察不保证更好评估
- 语义文本平均成本低于纯文本，但配对差异的置信区间均包含零；
- 图像配置成功率为 **68.25%**，低于文本配置约 **83%—84%**，但无法仅归因于图像输入；
- 五种配置的任务排序一致性较高：
  - 完成率 W＝0.761；
  - 理解成本 W＝0.858；
  - 操作成本 W＝0.887。
- 五种配置均复现“完成对应较弱、成本对应较强”的模式。

### 6.4 生成应用能完成任务，但未必更易用
- 生成 TUI 的智能体成功率为 **69.44%—85.71%**；
- 九个生成—评估组合的平均理解成本均高于参考版本；
- 操作成本有三个组合更低、六个更高，没有稳定优势；
- Claude Code 在三种评估配置下均达到或超过参考完成率，且生成版本中的理解成本最低，但两类成本均高于参考。

需要注意：这些平均差异主要是描述性结果；论文未为表4提供差异置信区间，不能将每个小幅差异都解释为统计显著。

## 7. 优点与亮点

- **问题定位清晰**：明确区分“能完成”与“容易完成”，补充传统成功率评估。
- **执行证据扎实**：通过实际轨迹和独立结果检查，避免仅依赖 LLM 主观评分。
- **人机边界尽量统一**：相同终端传输、键盘输入和按键计数规则，增强可比性。
- **成本维度解释性较强**：可区分界面难理解与操作繁琐，不强行压缩成单一分数。
- **开展人类校准**：没有直接假设智能体即人类，而是检验对应关系并报告置信区间。
- **复现基础较好**：固定版本、干净初态、任务指纹、多次执行及公开轨迹。
- **具备开发价值**：可用于版本间可用性回归检测，以及生成界面候选方案比较。

## 8. 不足与局限

### 8.1 理解成本只是代理指标
- 人类交互时间包含理解、输入、等待和纠错，并非纯认知成本；
- 推理 token 受模型、提示、分词器及推理策略影响，不等于人类心理努力；
- 两者相关支持测量价值，但不证明它们测量同一认知构念。
- 跨任务相关也可能部分来自任务本身复杂度，尚未充分分离“任务复杂”与“界面设计不佳”。

### 8.2 成本必须结合成功情况解释
- 成本统计纳入成功与失败运行；
- 提前失败可能带来较低按键数，达到轮数上限则可能带来较高成本；
- 因此，**更低成本不能脱离成功率被解释为更好可用性**。

### 8.3 样本与 benchmark 存在选择偏差
- 参与者全部是熟练终端用户，不代表新手、非技术用户或有无障碍需求的人群；
- 仓库筛选偏向热门、近期、可启动、可验证且可在界面内发现操作的应用；
- 任务由作者手工设计，只覆盖部分主要功能；
- 新仓库筛选降低数据污染风险，但不能保证完全没有预训练重叠。

### 8.4 对照与因果证据有限
- 图像模态与模型能力混杂；
- 人类可以持续观看，智能体只能离散观察，两者感知机制不同；
- 三个设计案例提供了合理解释，但不是严格控制变量的界面干预实验；
- 每个应用每栈只生成一次，无法估计生成结果的稳定性。

### 8.5 应用范围与复现限制
- 当前主要适用于键盘驱动、可确定性验证的任务；
- 尚未覆盖满意度、长期学习、疲劳、信任、审美和无障碍体验；
- 屏幕文本及高亮断言可能与具体呈现方式耦合，需要检查其对替代设计的兼容性；
- 托管模型 API、预算和费用信息不完整，会影响跨时间复现与成本评估。

**总体评价：**论文提出了有价值的执行驱动评估范式，较有说服力地表明智能体交互成本与熟练人类的任务需求存在排序关联。其适合作为人工研究的补充和自动化回归工具，但尚不足以证明智能体可完整替代人类可用性评估。
