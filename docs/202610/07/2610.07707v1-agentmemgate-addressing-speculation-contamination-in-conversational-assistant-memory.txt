## Abstract 

Conversational AI assistants with long-term memory extract facts from user mes-sages into a store consulted in later conversations. A stated plan can enter that store as fact: a user who might move to Seattle may be recorded as already living there. We call this speculation contamination . Final-state memory benchmarks miss this error because they do not probe intermediate state and include few unresolved spec-ulations. We present AgentMemGate, a write-time gate for profile-store memory that classifies extracted statements as speculation, completed event, correction, or other. Speculations remain outside memory, with conditions governing later pro-motion or deletion. We also contribute a dataset of multi-session conversations in which plans are confirmed, abandoned, or left unresolved. On our 147-conversation held-out set, Mem0 and Graphiti assert unresolved plans as current state for 35.2% and 27.3% of pending plans. On the core benchmark, AgentMemGate eliminates all observed contamination relative to the identical ungated pipeline (87.5% to zero for the most exposed extraction style) and raises task accuracy from 65% to 95%. On the harder held-out set, gated contamination is 3.4–5.7% and task accuracy rises by 9–13 percentage points. Our analysis identifies field matching as the main remaining bottleneck: realistic speculations often match no profile field and never reach the gate. We release our datasets, prompts, and evaluation code. 

## 1 Introduction 

Consider a user who tells an assistant: “I’ve been thinking about maybe moving to Seattle, my dad lives there.” Three weeks later, the user asks for a booking “near where I live”. If the memory system wrote current_city = Seattle , the assistant acts on a move that never happened. A plan has displaced a true fact. We call this failure speculation contamination : a speculative statement stored as current fact. Final-state benchmarks do not catch this because they score only after outcomes arrive. Few conversations leave speculations unresolved, and explicit confirmations can repair the store before the final question. Existing systems improve extraction, deduplication, and temporal structure but do not defer writes pending later evidence. On 147 held-out plan-to-outcome conversations, Mem0 [Chhikara et al., 2025] answered 78.9% of final questions correctly yet asserted never-true plans as current state for 35.2% of pending plans. Zep Graphiti [Rasmussen et al., 2025] showed 48.3% final accuracy and 27.3% pending contamination. Final-answer accuracy and pending-window correctness are distinct capabilities. We define, measure, and address the latter. 1

## 2 Related work 

Memory architectures. Long-term assistant memory increasingly manages changing persistent state rather than only retaining history. MemGPT [Packer et al., 2023] uses memory tiers, while Mem0 [Chhikara et al., 2025] and Zep Graphiti [Rasmussen et al., 2025] extract structured memories from conversation. Graphiti’s temporal validity intervals inspire the model for our profile store. Reflective 2and experience-based methods revisit memories after feedback [Tan et al., 2025, Xiong et al., 2025], and Cordon [Chen et al., 2026b] gives agents transactional operations with commit conditions. 

Write-time control. MemRouter [Hu et al., 2026b] learns whether to store a turn, and Consis-tencyGate [Zhang and Li, 2026] admits a fact only when repeated queries agree it is supported. Both filter writes but neither defers a fact for later resolution (Section 1). Longitudinal-risk and memory-poisoning studies likewise place guardrails at write time [Al-Tawaha et al., 2026, Dash et al., 2026]. These methods improve memory organization, revision, and protection but leave open when statements should enter memory. 

Memory evaluation. LongMemEval [Wu et al., 2024] and LoCoMo [Maharana et al., 2024] test recall and reasoning across multi-session conversations; we reuse them in auxiliary evaluations (Sections 4 and 6). Change-focused benchmarks test replacement of outdated or superseded facts [Bae et al., 2022, Jiang et al., 2025, Chao et al., 2026, Patel, 2026, Li et al., 2026b, Hu et al., 2026a, Chen et al., 2026a], while TriggerBench [Zhang et al., 2026] tests execution of intentions when future conditions hold. HaluMem [Chen et al., 2025] traces hallucinations across extraction, updating, and answering. It targets fabricated or conflicting content, whereas we target faithful statements that are not yet true and score them against later outcomes. Temporally structured memories [Sen et al., 2026, Li et al., 2026a] organize when events happened at read time; our gate decides whether they have happened at write time. Existing end-to-end or final-state scoring does not expose intermediate-state errors, so we inspect the store before plan outcomes are known. 

Linguistic factuality and belief revision. Hedge detection and event-factuality research characterize how language marks uncertainty and whether an event occurred [Farkas et al., 2010, Saurí and Pustejovsky, 2009], motivating our distinction between speculation and completed events. Our separation of completed events from corrections also parallels belief-revision theory’s distinction between incorporating a genuine change in the world and correcting a record that was already wrong [Alchourrón et al., 1985, Katsuno and Mendelzon, 1991]. 

## 3 Approach 

This section defines the profile store and the pipeline stages: extraction, field matching, classification, routing, and resolution. Algorithm 1 formalizes the flow. A profile store contains user fields (e.g. home city, grocery store, employer). A field is a slot, and a fact is a proposed value for a slot that can be read later. Our baseline extracts candidate facts, matches them to fields, and writes matches. This is a controlled version of the Mem0 and Graphiti ingestion pattern of comparing candidates with stored content before writing [Chhikara et al., 2025, Rasmussen et al., 2025]. We fix fields in advance to measure write behavior. AgentMemGate classifies each match and either writes or holds it; later evidence promotes or discards held items (Figure 1). 

Formal store definition. An entity e ∈ E is who a fact concerns, and an attribute a ∈ A is its tracked property; together they form a key k = ( e, a ). For example, (user, grocery_store) 

tracks which store the user visits. The profile store P is a partial map from keys K = E × A to values in V . For each key, it stores a current value and historical values with validity intervals [tbegin , t end ).A correction marks an old value’s interval as never valid and reads return the current value. The store makes no cross-field inference: a field changes only through its own commits. Figure 4 in Appendix A.6 illustrates the layout. 

Extraction. At each user turn ut with context Ct, the extractor proposes tuples (e, a, v ) ∈ E ×

A × V ; it does not label statement types or track outcomes. We model the extractor as a model call over the current user message, timestamp, and conversation history. 

Field matching. The field set F ⊆ K is fixed before each evaluation. Match(( e, a, v ), F ) is a model call that returns the matching field k for candidate (e, a ) or none. The model sees the tuple and each frozen field’s name and description, mapping only to the same single-valued semantic slot; the value clarifies the attribute. If no match occurs, nothing is written or staged. Because each conversation has one registered field in our evaluations, the matcher accepts or declines rather than selects among fields. Classification and routing. A separate classifier model call sees the statement’s source span s and up to two preceding turns, returning a distribution q(c | s, C ) over evidence types and then routing by argmax. Speculation describes a possible future change and is held outside the store. A completed event reports a change that happened and commits immediately. A correction replaces a wrong value and marks it as never valid. Other observations also commit immediately. With AgentMemGate off, every matched tuple commits regardless of class. 

Staged items and resolution. A staged item σ = ( k, v, φ ) ∈ H carries two natural-language resolution predicates generated at hold time to avoid later re-extraction. A separate checker model call evaluates each later user turn (example in Appendix A.6): φconfirm (ut) promotes v to P (k), while 

φabandon (ut) discards it. Each item therefore ends up promoted, discarded, or pending and remains invisible to reads while staged. Algorithm 1 gives the procedure. A correct final value can arrive via a promotion or a direct commit of the user’s confirmation. For example, “I bought them yesterday” is a completed event that any system, gated or not, commits. We call these confirmation-commits ; they can lead to correct end states in ungated systems despite contaminated intermediate memory. 

## 4 Experimental setup 

Pipelines. We evaluate four versions of the pipeline: the two extractors of Section 1 crossed with AgentMemGate on/off. The literal extractor records stated values directly, e.g. (user, grocery_store, “Trader Joe’s”) , and the cautious extractor records plans as plans, e.g. 

(user, grocery_plan, “considering Trader Joe’s”) . Their prompts are derived from Zep Graphiti’s and Mem0’s published extraction prompts, adapted to our tuple interface while preserving each product’s extraction policy. All four evaluations share the same profile store, probes, and judge. Since plan-framed attributes in the cautious configuration are more susceptible to failing field match-ing, we introduce a single deterministic retry mechanism: plan-related phrases are RegEx-matched and removed and the remainder is resubmitted to the matcher (e.g. grocery_plan → grocery 

→ grocery_store ). The original speculative statement still reaches the classifier, so it is held rather than committed. An ablation confirms that the retry is not doing the gate’s work (Section 6.3). Extraction, field matching, classification, and resolution checking are each single calls to the pinned LLM below. Routing and the store itself are deterministic. 

Evaluation protocol. We report three measures. Pending-window contamination is the fraction of at-risk plans stored as a field’s current value while the plan is open. At-end contamination is the same fraction at conversation end. Task accuracy is measured by one probe per conversation (“what does the user currently use?”) answered from the final store and scored against ground truth by the fixed judge below. 

Baselines and controls. The ungated baseline is the same pipeline with the gate disabled, in both extraction styles. The prompt-only baseline is the cautious ungated configuration. Product evaluations. We also run black-box Mem0 and Graphiti evaluations for motivation and external context, but they are not causal baselines for our component-level comparison. Although the literal extractor follows Graphiti’s published extraction prompt, end-to-end pipeline behavior may vary because the product adds retrieval, deduplication, and answer-time machinery around extraction. 

Models and scoring. All system components run on a pinned model, gpt-5.5-2026-04-23 , with fixed prompts. Scoring uses one fixed equivalence judge (the same pinned model) that compares a stored or answered value with the labeled value. Judge validation has two layers. A model from a different family re-judged 150 pairs, sampled to over-represent borderline cases, and agreed with the judge on 90.7% of cases. Furthermore, a blind human audit on a sample of 54 pairs agreed with the judge on 87.0% [75.6, 93.6] ( κ = 0 .74 ). All disagreements fell on borderline pairs. In five of the seven, the judge was the stricter of the two, so judge error tends to lower the reported accuracies, not raise them. Proportions carry 95% Wilson confidence intervals (one observation per conversation), and paired differences use a cluster bootstrap. 

Classifier validation. We evaluated the gate classifier on 163 naturally occurring statements from LongMemEval. The reference labels for evidence type are model-annotated with human audit: three model votes under a fixed rubric produce each label, and a model from a different family relabeled all 163 statements, agreeing on 92.0%. A blind human audit of 40 statements sampled from the items where the two model families agreed matched the reference label on 87.5% [73.9, 94.5]. When restricted to the binary commit-versus-hold decision used for routing, agreement was 92.5% [80.1, 97.4]. The 13 statements the model families disputed were audited separately and remain contested. The classifier prompt was fixed before any reference label was produced, but its class taxonomy was developed on the same corpus. We then tested whether the classifier gives higher update scores to statements that should update the profile. Its AUROC is 0.93 [0.89, 0.96], where 1.0 is perfect and 0.5 is chance. Two simpler prompts perform worse on the same test: asking whether the fact is true now scores 0.69, and asking whether it should be stored scores 0.62. Appendix A.5 gives detailed results and the repeated-run analysis.

## 5 Datasets 

In an audit of existing public data, we used an LLM to extract 194 naturally occurring hedge statements from LongMemEval and LoCoMo. Only 16 at-risk plans could be measured through an outcome, so we built our own plan-to-outcome dataset in Table 1. All three splits share the same overall structure: 2–3 dated sessions in which the user states a current value, hedges a switch, and returns later, with each plan labeled by its outcome (came true, abandoned, or still open). The core benchmark split balances the three plan outcomes. The held-out set is a larger set of conversations with the same structure, but with longer free-text extracted values for higher difficulty. This dataset is used only for final evaluation. The controlled-difficulty splits vary one factor at a time: four different levels of plan wording (strongly hedged, weakly hedged, confident plan without a date, scheduled plan with date), plus a completed-change control level, and four different variants of confirmation wording (verbatim, paraphrase, oblique, situational). The completed-change control examples in the held-out set and controlled-difficulty splits are cases where the user reports a change that has already happened instead of speculating a change; this is to measure potential over-holding. An example arc, the classifier prompt, and field-set construction are in Appendix A.6. 

Validation. Validation combined blind model judging with a separate human review. The core benchmark passed an LLM-judge review that checks that conversations read as natural human chat and that each plan statement is motivated by its context, followed by an item-level human review. For the controlled-difficulty splits, blind judges recovered the intended difficulty level (hedge strength or confirmation wording) in 89% of conversations. The held-out split passed the same validation. 

Provenance. All three splits are LLM-generated and reviewed by the authors. Generators are GPT-family, the same vendor family as the evaluated systems, so the held-out split is held-out but not generator-independent. The validation judges are Claude-family, a different model family from both. 

## 6 Results 

6.1 AgentMemGate removes pending-window contamination at little task cost Ungated, the literal extractor stores most pending plans as facts. While a plan is open, 87.5% [73.9, 94.5] of at-risk plans sit in the store as current values, and much of that error survives to conversation end (Table 2). Confirmation-commits repair most abandoned plans only after the user states the outcome, and open plans get no such message and stay wrong. The ungated cautious extractor mostly protects against contamination via plan phrasing: at-risk plan contamination is only 2.5% [0.4, 12.9].

The gate does not trade accuracy for correctness. It moves the literal style from worst to best on the core benchmark (Table 3), which indicates that contamination caused many of the ungated errors. On the held-out set, the gate improves task accuracy for both extractors ( +12.9 and +9.5 points), while the core-benchmark cautious gain (88.3% to 90.0%) is within noise. On the 15 completed-change controls from the held-out set, each gated configuration incorrectly holds one of the changes instead of storing immediately, i.e., 6.7% over-holding rate (Appendix A.2). 

The contrasts hold on the held-out set. We also tested a read-time alternative that commits all speculations but explicitly marks them as plans, and then hides them from reads (Appendix A.1). With appropriate plan confirmation, it matches the gate’s contamination and end-state correctness. Without it, literal came-true correctness falls to 5.0% (Appendix A.1). However, it leaves 85–90% of plan entries unresolved at conversation end. A full rerun on a second model family ( claude-opus-4-8 ) reproduces 15 of 18 directional findings, with exceptions favoring the gate or within noise (Appendix A.3). Overhead is small: on the core benchmark, the gate adds 0.8 model calls per user message under the literal style and 0.4 under the cautious style, excluding the retry’s occasional extra matching call.

Ungated failure concentrates where plans sound most settled. The ungated literal pipeline almost saturates contamination, storing hedges as facts at every level. The ungated cautious style maintains 0 contamination at both hedged levels but contamination levels increase as plan certainty increases (Figure 2). Its protection tracks wording, not evidence, with nothing tracking resolution, so by itself it is particularly sensitive to choice of wording. 

The literal extractor isolates the effect of the gate. In the literal style, 76 of 80 hedges match a field and reach the gate. The gate then stages all 76, i.e., no hedged value is stored as a current fact. In the cautious extractor, only 40 of 80 hedges reach the gate. For 22 missing hedges, the extractor fails to extract the new state, and the other 18 fail field matching. Again, the gate stages all 40 hedges that it receives. Thus, the cautious extractor’s conservative extraction has a real field-matching cost even if raw contamination rate is low. The literal result measures the gate more directly. 

Promotion is less reliable when confirmation is less direct (Figure 3). Implied confirmations are exactly where confirmation-commits also fail, since the implication may not successfully get extracted as a fact. This is where AgentMemGate performance degrades. At the most implicit level of confirmation wording (situational confirmation: e.g. the user mentioned planning to do an activity in the past and now casually references already doing it), the gated literal system answers 13 of 20 task probes correctly, compared with 19 of 20 for the ungated system. The ungated system scores these because it committed the plan as a fact when stated. These came-true conversations happen to reward that premature write. The gated system holds the plan and loses cases where the implied confirmation neither promotes it nor commits on its own. Complete results are in Table 7, Appendix A.4. Promotion rates conditional on staging are similar across the two extraction styles but there is a wide gap in absolute promotion rates. The difference in absolute promotion therefore comes from field coverage. Section 6.3 examines this gap. 

6.3 Hedged plans often match no field, so they never reach the gate 

The main remaining failures occur before classification: many extracted plans do not match a profile field. 

Field matching explains the promotion gap. Across the entire confirmation-wording split (four wording levels with 20 came-true conversations each), the cautious-gated system promotes 19 of 80 plans (23.8%). Conditional on staging, it promotes 19 of 23 (82.6%). The difference occurs because only 23 of the plans match a field and enter staging. The core benchmark shows the same pattern. Without the plan-frame retry (Algorithm 1, Section 4), 9 of 60 hedges reach the gate via the cautious extractor, compared with 55 of 60 for the literal extractor. The retry increases this to 31 of 60 for the cautious extractor. Once a plan is staged, promotion is similar across the two styles. 8The retry widens coverage but is safe only with the gate. Removing the retry from the gated cautious system does not change contamination, task accuracy, or control outcomes. On the controlled-difficulty splits, it reduces staging of plans by 24.0 percentage points [ −30.7, −17.9] and (absolute) promotion of plans by 21.2 points [ −30.0, −12.5]. However, the system still reduces at-end contami-nation by 7.5 points [ −13.8, −2.5] relative to the ungated cautious system on the controlled-difficulty splits and improves held-out task accuracy by 8.2 points [ +2.7, +13.6]. The held-out at-end contami-nation difference ( −4.5 points [ −11.4, +2.3]) is directionally consistent but spans zero. Adding the same retry to the ungated system has the opposite effect. Pending contamination increases by 37.5 points [27.5, 48.7], and task accuracy decreases by 15.1 points [9.5, 20.7], because more plans are extracted and stored as facts. 

Extraction succeeds, but matching often fails. Both extractors emit tuples on every plan turn, yet the cautious extractor produces 89 unmatched tuples on held-out plan turns. Of these, 66 are represented not as explicit plans but as preferences, interests, concerns, or conditions. For example, “might try the black messenger with the wide strap” was extracted as conditional_bag_interest ,which matched no field although the store tracked the user’s main work bag. The fixed RegEx retry misses many such tuples, recovering plans in 22 of 60 core-benchmark conversations but only 11 of 132 held-out conversations. 

A more permissive matcher exposes classifier errors. When the original matcher declines a tuple, we explored using a second LLM call to file it under any field tracking the same quantity. On a planted test suite with 60 probes of confident plans, this raises staging from 11 to 41 of 60 but also increases contamination by 5 points because the classifier commits some confidently worded plans. Thus, matching and classification involve a clear tradeoff. 

## 7 Discussion, limitations, and conclusion 

Memory benchmarks should measure intermediate state, not only final answers. End-state scoring captures recovery but misses contamination while a plan is open, even though an assistant can act on stored state long after it was written. For values reaching the gate, the policy is close to solved; upstream coverage is now the main problem. Open schemas do not remove this risk: they can change “plan never enters memory” into “plan enters as fact”. Why use a separate memory stage instead of a stronger extraction prompt? Prompting is unstable: cautious-extractor protection weakens as plans sound more settled (Figure 2). A combined stage also couples extraction and routing errors, obscuring attribution and tradeoffs. AgentMemGate makes storage explicit and testable; its evidence-type classification outperforms direct truth or storage classification by +0 .24 and +0 .31 AUROC (Appendix A.5). Staging preserves the plan without exposing it in responses, allowing later confirmation to promote it. Five limitations bound generalization. First, the unknown prevalence of at-risk pending plans means our constructed datasets do not establish real-world performance (Section 5). Their realism also needs validation despite blind judging and author review; longitudinal corpora such as REALTALK [Lee et al., 2025] may help. Second, small controlled splits yield wide intervals (Section 6.1), motivating larger and broader datasets. Third, we do not test whether staging harms answers about plans. Fourth, each sample uses one fixed field and accept-or-reject matching, so results do not cover selection within large field sets. Finally, gate costs concentrate at implied confirmations (Section 6.2). Future work should examine confirmation wording, recovery of implied confirmations, and interactive clarification for long-pending plans. Retention limits and user control over staged content remain out of scope but matter for deployment. Systems can mistake plans for facts while final-answer accuracy hides the error. AgentMemGate reduces contamination at low task cost through evidence classification, staging, and promotion while preserving genuine updates. Field matching remains the main bottleneck.

## A Additional results and implementation details 

A.1 Plan-typed commit baseline 

This baseline replaces AgentMemGate routing with a read-time framework (Section 6.1). It stores each speculation immediately, marks the value as a plan, and preserves the validity history. Reads ignore plan-typed values and return the most recent factual value; if none exists, they abstain. The baseline has no staging area, resolution conditions, or checker. A confirmation can therefore resolve a plan only by creating a new commit. We test both extraction styles on confirmation wording split from the controlled-difficulty set. The same judge scores all systems. The gated and ungated systems in Section 6.1 provide the comparison. We report two interpretations. Under the refresh-confirm reading, a confirmation resolves a masked plan when it commits the same value as a fact. Under the strict reading, plans never resolve (only the confirmation statement is committed). With the strict reading, end-state correctness for came-true plans is 45/80 (56.3%) for the cautious style and 4/80 (5.0%) for the literal style. We report strict-reading results only at the aggregate level. 

Most literal-style successes depend on the refresh-confirm rule. Of its 71 came-true successes, 67 are correct only under this rule. The same is true for 13 of 58 cautious-style successes. Thus, the literal baseline matches the gate mainly because equality between the plan and confirmation is treated as resolution. 

Contamination is low, but unresolved plans accumulate. Under both readings, contamination is nearly absent. The ranking and argmax results answer different questions. The 0.93 AUROC in Section 4 measures how well the classifier ranks statements that should update the profile. It uses the total probability assigned to commit classes. Table 8 instead reports the single class with the highest probability. 

Evidence-type classification is better than direct truth questions. A model can be confident that a user said “I might move” without being confident that the move occurred. This makes direct truth and storage questions unreliable in different cases. On the same statements, the evidence-type objective improves AUROC by +0 .24 [0.16, 0.31] and +0 .31 [0.23, 0.39] over the two alternatives. 

The main classifier error is over-commitment. On a test against natural statements, its largest error is to label other statements as completed events (35 of 68). These are not contamination cases. They show a bias toward the class that writes values immediately. 

Repeated runs are stable, except on corrections. The classifier gives the same label in five repeated runs for 88.3% of statements. Its majority label matches the reported run for 95.7%. The probability scores also change little: the per-statement standard deviation averages 0.050, with a median of 0.016. As a result, AUROC remains between 0.933 and 0.950 across runs (mean 0.944). Field-set construction. We fix the store fields before each run. Each held-out conversation has one field. Its attribute name comes from label metadata, not from an answer value. We create the field description from this name alone and attach the probe question that the model sees. We fixed the controlled-difficulty keys deterministically before generation. A validation check rejects any field that contains a label value. The field set is therefore value-free by construction. 

A.7 Product measurement detail 

We ran Mem0 and Zep Graphiti as released, using their own extraction, storage, and retrieval, and configured them to use the same pinned gpt-5.5-2026-04-23 model as our systems. Each of the 147 held-out conversations was ingested session by session. After every session, we asked the product for the user’s current value of the tracked field, and the fixed equivalence judge of Section 4 scored the answer against the ground-truth current value. A plan counts as exposed if any answer before the plan’s outcome asserts it as the user’s current state. Answers worded as plans do not count. Under this reading, Mem0 asserted never-true plans as current for 31 of 88 at-risk plans (35.2%) and Graphiti for 24 of 88 (27.3%). These are whole-product measurements, so differences against our component-level systems cannot be attributed to any single stage. Library versions and configuration are recorded in the released code. 15
