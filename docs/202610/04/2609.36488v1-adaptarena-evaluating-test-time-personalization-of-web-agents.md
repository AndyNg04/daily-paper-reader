## 摘要
大型语言模型（LLM）智能体在复杂网页导航任务中表现出色，但在真实环境中仍较为脆弱，因为用户意图往往未明确说明，且用户偏好各不相同。实际应用中，用户很少提供明确的个人资料，因此智能体需要根据隐式信号推断潜在偏好。尽管这一问题对实际部署至关重要，现有基准测试对其探索仍十分有限。为弥补这一空白，我们推出 AdaptArena，这是一个通过隐式偏好推断评估网页智能体测试时个性化能力的基准。AdaptArena 包含 480 项任务，涵盖单一偏好和双重偏好两种情形。每项评测任务都要求智能体检索并利用最相关的用户历史轨迹，从中推断出隐含的目标偏好。此外，我们提出 AdaptiveAgent，这是一种基于检索的框架，用于对隐式偏好推断进行标准化评估。实验结果显示，性能差距显著：能够获取真实偏好的 oracle 智能体成功率达到 82.92%，而使用我们框架评测的 LLM 智能体成功率最高仅为 15.62%。此外，我们发现，正确推断用户偏好是任务成功的必要条件，但并非充分条件：即使智能体与目标偏好保持一致，后续网页交互中的执行失败仍是一个重要瓶颈。这些发现表明，隐式偏好推断和可靠的动作落地是部署可靠、面向用户的网页智能体所面临的关键挑战。我们已公开代码：https://github.com/McGill-NLP/web-agents-test-time-adaptations

## Abstract
Large language model (LLM) agents have demonstrated strong performance on complex web navigation tasks, yet they remain brittle in real-world settings where user intentions are underspecified and preferences are heterogeneous. In practice, users rarely provide explicit profiles, requiring agents to infer latent preferences from implicit signals. Despite its importance for deployment, this problem setting is largely underexplored in existing benchmarks. To address this gap, we introduce AdaptArena, a benchmark for evaluating test-time personalization of web agents via implicit preference inference. AdaptArena consists of 480 tasks, featuring both single-preference and double-preference scenarios. Each evaluation task must be solved by retrieving and leveraging the most relevant historical user trajectory that implicitly encodes the target preference. In addition, we introduce AdaptiveAgent, a retrieval-based framework for standardized evaluation of implicit preference inference. Experiments reveal a substantial performance gap: while oracle agents with access to ground-truth preferences achieve an 82.92% success rate, the evaluated LLM agents using our framework reach at most 15.62%. Furthermore, we find that correctly inferring user preferences is necessary but not sufficient for task success, as execution failures in downstream web interactions remain a significant bottleneck even when agents align with the target preference. These findings highlight implicit preference inference and robust action grounding as key challenges for deploying reliable, user-facing web agents. We release our code: https://github.com/McGill-NLP/web-agents-test-time-adaptations

## 1. 核心问题与整体含义

### 研究背景与动机
- 现有网页智能体已能完成较复杂的导航、搜索和信息提取任务，但通常假设用户指令足够明确。现实中，用户往往省略默认偏好，例如询问“从这里到目的地需要多久”，却不说明自己的位置和常用交通方式。
- 用户之间的偏好具有明显差异，而且通常不会提供完整、显式的个人档案。因此，智能体需要从历史浏览和操作行为中识别与当前任务有关的隐含偏好。
- 针对每个用户重新训练模型成本较高。论文研究的是**测试时个性化**：保持模型参数不变，通过历史行为证据在推理阶段调整决策，而非进行梯度更新。

### 核心研究问题
论文考察一条完整能力链：

> 历史交互轨迹 → 检索相关证据 → 推断任务相关偏好 → 将偏好转化为网页操作 → 完成任务。

其意义不只是评测“模型是否了解用户”，而是检验**用户偏好能否真正影响并改善端到端任务执行**。论文的主要贡献是提出评测基准 **AdaptArena** 和标准化检索框架 **AdaptiveAgent**，并分析这条能力链中的失败来源。

## 2. 方法论：核心思想与技术流程

### 2.1 两阶段评测范式
为避免长期真人交互带来的成本和不可复现性，论文将偏好历史构建与部署评测分开：

1. **历史轨迹构建**
   - 为用户设定明确的偏好，并将偏好与一般任务指令共同提供给行为生成智能体。
   - 例如：“我喜欢开车。请查询从 CMU 到匹兹堡大学需要多久。”
   - 保存其交互轨迹，使偏好通过网页上的选择和操作隐含表达。

2. **部署评测**
   - 在新任务中删除显式偏好，仅保留不充分明确的任务指令。
   - 智能体必须利用该用户的历史轨迹补全缺失信息，再完成任务。
   - 单偏好任务依赖一个偏好；双偏好任务要求同时满足两个偏好，例如“居住位置＋交通方式”。

### 2.2 AdaptiveAgent 算法流程
框架明确分离“偏好推断”和“任务执行”：

1. **建立用户专属历史索引**
   - 每条历史轨迹表示为按时间排序的截图序列。
   - 使用冻结的 **CLIP ViT-B/32** 编码截图，对向量进行 L2 归一化。
   - 使用 **FAISS 内积索引**进行检索；归一化后，内积对应余弦相似度。

2. **按任务检索两条轨迹**
   - 用 CLIP 文本编码器编码当前任务指令。
   - 找到相似度最高的截图及其所属轨迹，记录截图对应的步骤。
   - 将该轨迹移出候选池，再重复一次，最终获得两条不同轨迹。

3. **重建轨迹前缀**
   - 对每条选中的轨迹，保留从初始状态到命中截图的完整前缀。
   - 这样既提供相关页面，也保留到达该页面之前的部分行为证据。

4. **提取偏好**
   - 将两段截图前缀交给多模态模型 **GPT-5-nano**。
   - 要求只依据可见证据生成简洁的第一人称偏好摘要，避免无依据猜测。

5. **执行当前任务**
   - 将偏好摘要作为辅助上下文加入网页智能体提示词。
   - 智能体据此生成浏览器动作，完成任务。

### 2.3 技术特点与边界
- 全过程不更新模型参数，属于**基于检索和上下文注入的非参数个性化**。
- 截图向量和索引均可缓存，减少重复计算。
- 六种执行模型共享相同检索机制及偏好提取器。因此，实验评测的是**整条固定流水线与不同执行模型的组合**，不能将所有失败直接归因于执行模型自身的偏好推断能力。
- 历史检索和偏好提取使用截图；附录配置显示，下游网页执行主要使用可访问性树等信息，`use_screenshot=False`，不能理解为执行阶段也完全依赖视觉输入。

## 3. 实验设计：场景、基准与对比方法

### 3.1 AdaptArena 基准
基准基于 **WebArena** 的三个受控网页环境，并通过 **BrowserGym** 统一交互：

| 环境 | 典型个性化需求 |
|---|---|
| 电商网站 | 品牌、饮食、产地、排序、过滤、购物车或愿望清单 |
| Reddit 论坛 | 常用论坛、帖子排序方式 |
| OpenStreetMap | 居住位置、交通方式 |

数据规模：
- **10 个用户 persona**，每个包含相同的 **12 类偏好**。
- **120 条历史轨迹**：每个用户每类偏好各一条。
- 历史总计 **1,174 步**，每条平均 **9.78 步**。
- **480 个部署任务**：240 个单偏好任务、240 个双偏好任务。
- 历史轨迹由 **Qwen-3-VL-32B-Thinking** 生成，任务经过人工检查，以保证缺少偏好时存在歧义、补充目标偏好后可以求解。

### 3.2 对比设置
论文比较五种偏好信息条件：

| 设置 | 可获得的信息 | 用途 |
|---|---|---|
| No Profile | 无用户历史或档案 | 无个性化基线 |
| Reconstructed Profile | 根据历史思考与动作重建的文本档案 | 半特权基线 |
| AdaptiveAgent | 检索历史截图并提取偏好 | 主要方法 |
| User-Centric | 完整真实用户档案 | 考察相关偏好的选择与应用 |
| Oracle | 当前任务所需的真实偏好 | 排除偏好获取歧义的理想参照 |

- Reconstructed Profile 使用 GPT-5 重建档案，真实偏好覆盖率平均为 **51.67%**。
- 由于其读取历史思考和动作，可能间接接触由显式偏好诱导的信息，论文将其视为半特权设置，而非完全同条件对比。
- User-Centric 与 Oracle 是理想化参照，不代表现实部署可直接获得的信息。

六种执行模型为：
- Gemini-3-Pro、Gemini-3-Flash；
- GPT-5.4、GPT-5-mini；
- Qwen-3.5-27B、Qwen-3-VL-32B-Thinking。

### 3.3 评测指标
- **任务成功率**：功能性自动评测，使用参考答案或参考程序，通过精确或部分匹配判定。
- **偏好对齐分数**：Gemini-3-Flash 根据执行轨迹判断行为是否符合目标偏好；双偏好任务要求两项均满足。
- **检索召回率**：检查检索结果是否包含目标偏好类别对应的历史轨迹。
- **对齐条件下的成功率**：分析行为已经符合偏好时，执行是否仍然失败。

需要注意，偏好对齐分数衡量的是**最终轨迹的行为一致性**，并非直接验证偏好提取器输出是否正确。

## 6. 主要结论与发现

### 6.1 历史信号有帮助，但距离理想条件很远

| 模型 | 无档案 | 重建档案 | AdaptiveAgent | 完整真实档案 | Oracle |
|---|---:|---:|---:|---:|---:|
| Gemini-3-Pro | 7.71% | 17.71% | **15.62%** | 68.33% | **82.92%** |
| Gemini-3-Flash | 9.17% | 17.71% | 15.00% | 56.04% | 72.29% |
| GPT-5.4 | 8.96% | 14.17% | 12.71% | 51.04% | 71.04% |
| GPT-5-mini | 7.92% | 14.17% | 11.67% | 41.87% | 62.92% |
| Qwen-3.5-27B | 8.96% | 15.00% | 11.04% | 46.46% | 66.87% |
| Qwen-3-VL-32B | 7.29% | 15.42% | 10.42% | 25.21% | 40.83% |

- AdaptiveAgent 对所有模型均优于无档案基线，但也均低于重建档案基线。
- 最佳模型在 AdaptiveAgent 与 Oracle 之间相差 **67.30 个百分点**。
- 完整真实档案仍弱于任务相关真实偏好，说明**拥有更多用户信息不等于能够正确选择和应用信息**。

### 6.2 双偏好任务明显更困难
- Gemini-3-Pro：**22.92% → 8.33%**。
- GPT-5.4：**20.42% → 5.00%**。
- 六种模型下降约 **10.83–15.42 个百分点**。

这说明组合个性化是系统性难点，但下降同时受到检索、偏好提取和执行的影响，不能全部归因于模型的组合推理能力。

### 6.3 检索之后仍有显著信息损失
- 总体 recall@2 为 **71.88%**。
- 单偏好为 **77.50%**，双偏好为 **66.25%**。
- 最终偏好对齐只有 **22.50%–29.79%**，任务成功率仅 **10.42%–15.62%**。

检索通常找得到相关轨迹，但相关证据未必能被正确解释和执行。类别差异也很明显：
- 位置、手机等静态属性较容易识别；
- 排序、过滤等操作性偏好困难；
- 愿望清单与购物车类别的 recall@2 仅 **5%**，体现了纯截图检索对动作差异的敏感性不足。

### 6.4 行为符合偏好，并不保证成功
- 对齐条件下的成功率仅约 **32%–52%**。
- GPT-5-mini 对齐率最高，为 **29.79%**，但任务成功率仅 **11.67%**。
- 常见失败包括动作执行失败、导航循环和不恰当终止。
- Gemini-3-Pro 的对齐后失败中，终止失败占 **44.29%**；GPT-5-mini 的动作失败占 **46.75%**。

因此，偏好理解和可靠交互是两个不同的瓶颈。

### 6.5 收益依赖正确用户历史
将用户历史换成偏好相反的其他用户历史后：
- Gemini-3-Pro：**15.62% → 7.50%**；
- GPT-5-mini：**11.67% → 7.71%**；
- Qwen-3.5-27B：**11.04% → 8.96%**。

结果接近无档案基线，为“收益来自用户特定信号”提供了支持，但不足以排除所有数据集捷径。

## 7. 优点与亮点

- **问题定位具有实际价值**：从显式档案转向隐含行为证据，更接近真实个性化需求。
- **基准定义清晰**：受控 persona、人工检查和单／双偏好设计，使歧义来源可追踪。
- **端到端评测**：不仅考察偏好表达，还验证是否落实到网页行为和最终结果。
- **诊断维度丰富**：检索召回、行为对齐、条件成功率和错误分类帮助区分不同失败环节。
- **框架简单、可复现**：冻结编码器、固定两条轨迹检索、缓存索引，无需额外训练。
- **提供人类可恢复性证据**：独立标注者平均恢复 **85.83%** 的真实偏好，说明历史并非普遍缺乏可理解信号。
- **强调选择性个性化**：完整档案可能引入无关偏好干扰，这一发现对用户记忆系统设计有启发。

## 8. 不足与局限

### 数据与应用范围
- 仅覆盖三个受控网站，不能代表真实开放网页中的动态界面、登录流程和复杂跨站任务。
- 历史由模型在显式 persona 条件下生成，而非来自自然长期用户行为，缺少真实历史中的噪声、稀疏性和矛盾。
- 仅有10个 persona，每类偏好只有一条轨迹，无法充分评测长期学习与证据积累。
- 偏好被视为相对稳定，未覆盖偏好变化、情境依赖以及历史偏好与当前明确指令冲突的情况。

### 方法与归因限制
- CLIP 截图检索更擅长识别页面内容，不一定能区分排序、过滤或保存位置等动作语义。
- 截断前缀可能遗漏后续更明确的证据；固定检索两条轨迹也缺少充分验证。
- 共享 GPT-5-nano 提取器可能形成统一瓶颈，使不同执行模型的能力差异被上游错误掩盖。
- 没有评估主动向用户澄清、表达偏好推断不确定性或拒绝不可靠个性化等策略。

### 偏差与评测风险
- 轨迹生成模型与一个执行模型同属 Qwen 系列，存在潜在风格偏差；该模型成绩最低不能完全排除偏差。
- 自动匹配评测可能受答案格式影响，环境加载失败也可能混入能力评估。
- 行为对齐不等同于真正推断正确：默认操作可能偶然符合偏好，执行失败也可能让正确理解无法显现。
- 表15中“Wishlist vs. Cart”的 **63.3% 对齐率**被正文解释为检索命中后的条件结果，但表中其他对齐值的统计口径不够明确，不宜直接横向比较。
- 双偏好检索是否要求两个目标类别均命中，定义也需要更明确说明。

### 总体评价
**这篇论文最有价值的贡献是提出可诊断的个性化评测问题，而不是证明其检索方法已经足够有效。** 结果有力表明，在当前固定流水线和受控基准下，“找到相关历史”“识别相关偏好”与“可靠完成任务”之间存在显著差距；但这些低成功率仍不能直接推广为所有个性化网页智能体的能力上限。
