## 摘要
记忆是对话智能体的核心组件，使其能够在长时间交互中保持连贯并理解上下文。近期方法通常依赖基于大语言模型的记忆构建：将原始交互改写为结构化记忆单元，随后通过 RAG 流程进行检索。尽管这一范式在受控环境中效果良好，但我们发现，在长时程、高熵对话中，它会逐渐失效：随着上下文长度和信息复杂度增加，记忆构建变得愈发有损且不稳定，并因反复调用大语言模型而产生高昂成本。为解决这些局限，我们提出 Threader，这一记忆系统将重点从记忆构建转向对原始交互进行高效且具备结构感知能力的访问。Threader 不对交互内容进行改写，而是将其作为一等记忆予以保留，通过轻量级增量分段将其组织为主题连贯的片段，并利用多视图表征实现准确检索。在查询阶段，Threader 执行多信号检索，将片段级访问与局部证据匹配相结合，从而兼顾完整性与连贯性。大量实验表明，Threader 能够持续提升答案准确率和证据召回率，同时显著降低记忆构建开销。

## Abstract
Memory is a core component of conversational agents, enabling coherent and context-aware behavior over long interactions. Recent approaches commonly rely on LLM-based memory construction, where raw interactions are rewritten into structured memory units and later retrieved via a RAG pipeline. While effective in controlled settings, we show that this paradigm breaks down in long-horizon, high-entropy conversations: memory construction becomes increasingly lossy and unstable as context length and information complexity grow, and incurs prohibitive cost due to repeated LLM invocation. To address these limitations, we propose Threader, a memory system that shifts the focus from memory construction to efficient, structure-aware access over raw interactions. Instead of rewriting interactions, Threader preserves them as first-class memory, organizes them into topic-coherent segments via lightweight incremental segmentation, and enables accurate retrieval through multi-view representation. At query time, it performs multi-signal retrieval that combines segment-level access with localized evidence matching, ensuring both completeness and coherence. Extensive experiments demonstrate that Threader consistently improves answer accuracy and evidence recall, while significantly reducing the memory construction overhead.

## 2. 方法论：Threader 的核心思想与技术流程

### 2.1 核心思想

- 将原始用户—助手交互作为长期记忆的主要载体。
- 写入时只做轻量组织和索引；查询时进行细粒度匹配，最后交由生成模型综合证据。
- 整体流程为：

  **原始交互 → 增量话题分段 → 多视图与消息索引 → 粗召回 → 精细评分 → 完整片段返回 → 回答生成。**

### 2.2 增量式话题连贯分段

- 系统维护当前片段，将“当前片段 + 新一轮交互”输入 BERT 二分类器：
  - **CONTINUE**：新交互属于当前话题，追加到片段。
  - **SEGMENT**：检测到话题变化，结束当前片段并建立新片段。
- 分段以完整交互轮次为边界，不改写原文，也不切断句子；支持流式处理，不需要重新决定过去的边界。
- 训练监督来自：
  - LongMemEval 的会话边界：提供粗粒度结构信号。
  - GPT-4.1-mini 标注的会话内话题边界：提供细粒度弱监督。
- 两类监督最终均转换为二分类标签，采用交叉熵训练。
- 默认使用 **BERT-base，边界阈值 0.20**；同一模型直接迁移到 PersonaMem。

### 2.3 多视图片段表示

每个片段分别构造并编码三种视图：

- **用户视图**：保留用户陈述的事实、偏好、经历和约束。
- **助手视图**：保留历史建议、解释和回复。
- **完整交互视图**：保留双方对话的整体语境。

三种视图共享编码器，默认相似度权重为 **0.5、0.25、0.25**。这样可以减轻冗长助手回复对简短用户事实的“淹没”。

### 2.4 两阶段、多信号检索

- **第一阶段：高召回候选获取**
  - 根据三视图加权语义相似度检索前 \(K_1\) 个片段。
  - 使用 BM25 检索前 \(K_1\) 个片段。
  - 取两者并集；默认 **\(K_1=40\)**，候选最多 80 个。
- **第二阶段：局部证据精细评分**
  - 计算查询与候选片段内每条用户、助手消息的相似度。
  - 取最高的 **\(K_2=2\)** 个消息分数求平均，突出片段中局部集中的证据。
  - 对分数归一化后，融合消息级语义评分、BM25 和交叉编码器重排序评分。
  - 默认 BM25 融合权重 **β=0.65**；最终混合评分权重 **α=0.3**，重排序信号占其余权重。
- **最终返回的是完整片段，而非孤立消息**，并按时间组织上下文：
  - 消息级评分负责精确定位。
  - 片段级返回负责保留指代、时间关系和对话连贯性。

## 7. 优点与亮点

- **问题定位准确**：区分记忆写入丢失、检索遗漏和生成失败，而非只比较最终准确率。
- **证据可追溯**：保留原文，有利于核对细节、时间和来源。
- **粒度设计合理**：细粒度消息匹配与完整片段返回相结合，兼顾精度与连贯性。
- **角色分离有针对性**：三视图表示适配用户与助手信息分布不对称的特点。
- **工程上轻量可落地**：利用现成编码器和重排序器，无需修改回答模型。
- **评价较全面**：将离线建库与在线检索成本分开，并提供跨模型、跨数据集及多维消融。
- **承认适用边界**：没有将证据保留等同于充分推理，明确讨论与摘要式抽象的互补性。

## 8. 不足与局限

### 8.1 方法与应用限制

- **分段误差会传播**：默认分段器精确边界 F1 为 **0.483**，并非高度准确；错误边界可能切散证据或混入无关内容。
- **保存无损不等于检索无损**：超出嵌入或重排序模型窗口的输入采用默认截断，长片段末尾证据可能未被充分编码。
- **终身规模尚未验证**：原文、多视图向量和消息向量持续增长，需要额外的分层索引、压缩或保留策略。
- **抽象依赖回答模型**：长期偏好归纳和跨片段综合可能需要更强推理模型，增加最终回答成本。
- **增量分段不等于完整在线验证**：真实部署中持续更新索引的成本、多人并发和长期服务性能没有充分评测。

### 8.2 实验覆盖与偏差风险

- 仅两个公开基准，没有真实长期用户部署、百万级记忆库或工具执行轨迹实验。
- PersonaMem 只有 **37 个源对话**，589 个问题并非全部来自独立用户历史。
- LLM 同时参与分段标注和答案裁判；分段参考标准也来自相同标注流程，存在模型偏好和标注误差风险。
- 未系统验证多语言、语音噪声、对抗性历史内容、拒答能力和隐私删除。
- “高熵”“现实复杂性”没有独立量化，基准改善不等于真实环境泛化已经得到证明。

### 8.3 记忆治理与复现限制

- 长期保存原始交互扩大隐私暴露面；访问控制、用户编辑、删除、选择性遗忘仍主要属于未来工作。
- 缺少训练耗时、完整计算账单和稳定性统计，限制成本结论的可迁移性。
- 摘要称代码“将开放”，复现声明称代码“已开放”，表述不一致；仅凭提供文本无法确认仓库实际可用程度。

**总体评价**：Threader 有力说明，在事实型长期对话记忆中，优先保留原始证据并优化访问，可以同时改善准确率和部署效率。但现有结果更支持“证据保留型检索是一条有效且经济的路径”，而不是“摘要或结构化记忆应被全面取代”；原文证据与适度抽象的混合系统仍值得进一步研究。
