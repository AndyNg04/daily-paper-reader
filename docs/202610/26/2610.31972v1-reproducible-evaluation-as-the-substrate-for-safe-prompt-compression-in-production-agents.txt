## Abstract 

Evaluating conversational agents that act on live, mutable enterprise data is hard: replayed sessions drift as backend state changes, and a benchmark built today can silently go stale as the data it describes moves on. We present an offline evaluation harness for a production conversational agent that stays reproducible despite the live data it operates on changing, and that can be regenerated on demand once it goes stale. We then use this harness as the fitness function for GEPA-based prompt optimization under a correctness gate that guards against reward hacking. Applied to a production merchant-facing agent, correctness-gated compression shrinks the agent’s full prompt surface by 3.5–7.6% without regressing held-out task correctness, consistently across three independent subject-model families — and for one, correctness measurably improves. 

## 1 Introduction 

Conversational agents increasingly serve as the interface between users and the software systems that support their work — answering questions grounded in live data [Lewis et al., 2020], and, following the shift toward tool-augmented and agentic LLMs [Yao et al., 2023, Schick et al., 2023, Wang et al., 2024], increasingly taking actions on that data rather than only reporting on it. In practice, teams do not build such an agent by handing an optimizer a blank prompt and a training set. They first fix the product spec and tool contracts — required wording, forbidden wording, which tool answers which question [Schluntz and Zhang, 2024] — so the agent’s behavior stays legible and reviewable. Only once this spec-complete agent exists does the natural question become: is it reliable, and is it efficient? This paper is a blueprint for that starting point: given a production agent whose spec and tools are fixed, how do we make its evaluation trustworthy and its prompt leaner, without re-deriving its behavior from scratch? Reliability is harder to establish here than for static NLP tasks: the ground truth an agent is queried against is not fixed — a sales question has a different correct answer daily, and a write action changes the state the next eval run would read. Naive session replay against a live backend therefore produces incomparable results, and scoring a write tool’s text misses the point — what matters is the state it leaves behind. A benchmark can also go stale after the fact, as the entities it describes move on (a menu reprices, a payout settles), drifting from the system it describes independent of any model change. We treat this as routine: because generation and evaluation share one schema, a stale benchmark can be regenerated on demand from current backend state.

Prior work addresses pieces of this. Static benchmarks like ToolLLM [Qin et al., 2024] assume a frozen corpus; interactive-environment benchmarks like AgentBench [Liu et al., 2024], WebArena [Zhou et al., 2024], and τ -bench [Yao et al., 2024] score end state, but inside simulated environments rather than live, drifting production data. Dynabench [Kiela et al., 2021] and LiveBench [White et al., 2025] refresh benchmarks against saturation and contamination, respectively; our staleness instead comes from the referent data moving, which calls for regeneration rather than continual sourcing. LLM-as-judge scoring [Zheng et al., 2023] handles subjective wording but not reproducibility itself, and prompt optimizers — APE [Zhou et al., 2023], DSPy [Khattab et al., 2024], GEPA [Agrawal et al., 2025] — treat their evaluation signal as given rather than addressing what makes it reproducible or fresh. Our harness matches a reproducibility mechanism to each tool’s data shape: staging the clock for reads immutable once settled, freezing the observed payload for current-state-dependent reads, and seed-then-read-back for tools that write. Archetype-stratified generation covers each skill’s capability surface, and deterministic plus LLM-rubric judges [Zheng et al., 2023] score correctness and policy compliance. Because this harness yields a stable scalar signal, it can also serve as GEPA’s [Agrawal et al., 2025] fitness function. Published GEPA use cases grow a minimal seed prompt via reflection; production agents start spec-complete, so optimization must instead compress without regressing. Shorter prompts directly reduce inference latency and serving cost [Jiang et al., 2023], so token count is worth optimizing even once correctness is already met. We use a lexicographic token-count objective that only breaks exact performance ties, never trading correctness for size, guarded by a hard gate against any rule-violating candidate — a prompt-optimization analogue of reward hacking in reinforcement learning [Skalse et al., 2022]. We validate this on a merchant-facing conversational agent already in production: across three independent subject-model families, compression under our gate reduces the agent’s full prompt surface by 3.5–7.6% without regressing held-out task correctness on a confirmatory held-out set — and for one family, correctness measurably improves — evidence that prompt size and task correctness need not trade off against each other. Our contributions: (1) a sandbox that generates and evaluates benchmark data against live production state, matching each tool’s data-mutability to a reproducibility mechanism and scoring write-tools on end state rather than transcript text; (2) a generation strategy that can be re-run at any point to refresh a benchmark once its underlying production data has moved on; and (3) a token-efficiency method that uses this harness as a correctness-gated fitness function for prompt compression.

## 3 Results 

We apply this harness to a merchant-facing conversational agent in production, optimizing every textual prompt component of the agent — the base system prompt πbase , every skill’s Kj , and the description text of every tool — jointly as one candidate c (§2.4) against the full generated dataset. 

Dataset. Following §2.2–2.3, we generate a train/val split stratified by skill–archetype pair across 10 skills at seed 42: 302 datapoints for training and 99 for validation. A 196-point held-out set Dtest ,disjoint from train and val and also stratified by skill–archetype pair, reports the honest result (§2.4). 

Compression run. We run GEPA independently for three subject-model families — Anthropic (claude-sonnet-4.6 ), Gemini ( gemini-3.7-flash ), and OpenAI ( gpt-5.6-sol ) — each op-timizing the same joint candidate c (system prompt πbase , all ten skill bodies Kj , and shared tool descriptions; 36,336-token seed) at a rollout budget of 800. Fitness follows the f (c) defined in §2.4 (ϵ = 10 −6), with the critical-rule gate checked against every skill’s mandatory rules; candidates are additionally rejected by a no-harm gate that zeroes any candidate whose per-skill mean falls more than 0.02 below the seed’s. The Pareto frontier is hybrid — maintaining non-dominated candidates from two complementary views, per-datapoint performance and aggregate objective scores, rather than either alone — and the module selector is set to all , editing every component within the same reflection step. Seed and winner are each scored on Dtest as the mean of 5 rollouts per datapoint, controlling for sampling noise; Table 1 reports the paired difference with a 10,000-sample bootstrap 95% confidence interval. Only Anthropic’s confidence interval excludes zero: its winner is both 7.6% smaller and a real, statistically distinguishable improvement over its seed. Gemini’s and OpenAI’s intervals include zero — their winners are smaller with no detectable change in quality, not a proven gain. Read together, compression does not cost correctness for any family, and for one it recovers real headroom the seed’s extra tokens did not provide. 

## 4 Conclusion 

We presented an offline evaluation harness that grounds benchmark datapoints in reproducible production state and real tool-call traces, paired with a correctness-gated compression method that treats a compound agent’s entire textual surface as one candidate optimized under a hard gate against reward hacking. Applied to a merchant-facing agent already in production, this let GEPA shrink the agent’s prompt by 3.5–7.6% without regressing held-out correctness on a confirmatory held-out set, across three independent subject-model families (§3) — and for one family, correctness measurably improves — evidence that prompt size and task correctness need not trade off against each other. The gain’s size varies by subject model, so its benefit appears to depend on the model optimized, not solely on the harness. And since our benchmark is a frozen snapshot, we have not yet measured how a compressed candidate’s advantage decays as production drifts, despite the harness being designed to regenerate on demand (§2.3). 4References

## B Reward-Hacking Near-Miss 

During search, one intermediate candidate’s only edit was dropping a frozen store_id_handling 

block from sales_skill_body : 

> -## Store ID --- StoreLevel: pass `store_id` from Current Entity. -- BusinessLevel: **omit** `store_id` for business-wide results. Never -use `business_id` as `store_id`. -## request_json Parameters

This candidate’s own no-harm check correctly zeroed it. But a later candidate in the same lineage inherited the deletion and was not caught the same way — the no-harm gate is computed per-iteration against whichever batch is sampled that round, so a rule a given batch never exercises can slip through. Independently, the text-coverage judge checks for the rule’s text anywhere in the candidate, not per-batch — and here it found the same instruction duplicated earlier in the skill body and passed the candidate without checking that the specific copy it needed was the one just deleted. Only a broader diagnostic pass, checking the sales skill specifically, surfaced the drop (0.90 → 0.00) — after the fact, not as part of the standard selection pipeline. This near-miss is exactly the gap the hard 7critical-rule gate (§2.4) closes going forward: unlike the no-harm gate’s batch-dependent sampling or the text-coverage judge’s static, duplicate-blind text check, the critical-rule gate runs deterministically against every candidate’s actual rule compliance, independent of which batch happened to be sampled or which text happens to appear elsewhere in the skill body.
