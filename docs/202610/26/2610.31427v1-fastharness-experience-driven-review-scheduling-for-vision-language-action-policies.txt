Abstract 

Agentic robot systems combine language-model reasoning with robot policies to monitor execution and recover from failures. However, reviewing every action chunk incurs substantial overhead, even in familiar situations. We intro-duce FastHarness, an experience-driven execu-tion harness that adaptively schedules GPT-6 Astra supervision of a π0.5 policy. A fast path uses stage memory and reviewed outcomes to reduce review frequency as experience accu-mulates, while a complementary recovery path focuses supervision on correcting errors. Once recovery is verified, routine execution resumes, with failure experience retained to guide fu-ture interventions. The policy remains frozen and generates fresh actions from current obser-vations. Across four simulated manipulation tasks, reviewer token use decreases by an aver-age of 57.2% per task from the first evaluated episode to the mean of the final five episodes. Mean episode time decreases from 85.5 to 52.0 minutes over the same interval. On the same tasks, mean success increases from 80% for GPT-as-Policy ( π0.5 + GPT-6 Astra) to 97.19% with FastHarness. These results highlight adap-tive supervision as a practical route to more effi-cient agentic robotics without additional model training. 

1 Introduction 

Agentic robot systems (Zhang et al., 2026; Fu et al., 2026; Lu et al., 2026; Shi et al., 2025) combine learned policies with language-model reasoning to monitor execution and recover from errors. A vision-language-action (VLA) policy (Kim et al., 2024; Black et al., 2024; Lin et al., 2025, 2026c,a; Brohan et al., 2023; Lin et al., 2026b) maps ob-servations and instructions to actions, while a lan-guage model uses execution feedback to assess progress and guide corrections (Huang et al., 2022). GPT-as-Policy follows this approach by pairing 

π0.5 (Physical Intelligence et al., 2025) with GPT-6 Astra (Su et al., 2026). An execution harness coordinates the two models, determining when to request a review and how the resulting feedback affects subsequent actions. Frequent model calls, however, can make exe-cution slow and costly. Reviewing every action chunk repeats this overhead even in task stages that the policy has already completed reliably. Er-rors require a different response: a missed grasp or dropped object may need several rounds of cor-rection before execution can continue. Repeated task execution provides evidence for distinguishing these situations. The challenge is to use that evi-dence to reduce redundant review while retaining the supervision needed for recovery. We introduce FastHarness, an experience-driven harness that uses reviewed outcomes to decide when model supervision is needed (Figure 1). Re-peatedly successful stages can proceed with less frequent review, while remembered failures prompt closer inspection when similar situations recur. The harness updates its memory and review schedule as experience accumulates. The π0.5 policy remains fixed and generates each action chunk from the current observation. FastHarness implements this adaptation through two complementary paths (Figure 2). During rou-tine execution, the fast path uses the current task stage and its reviewed history to set the review fre-quency. When an error is detected, the recovery path guides local repair under continued review. After the reviewer verifies recovery, the harness resumes ordinary scheduling. It retains the failure record to guide future interventions. We evaluate FastHarness on four simulated ma-nipulation tasks, examining both execution effi-ciency and task success. Across repeated runs, re-viewer token use decreases by an average of 57.2% per task, and mean episode time falls from 85.5 to 52.0 minutes. 2 Related Work 

Language-model-guided robot execution. Lan-guage models support robot execution through skill selection, planning, and feedback. SayCan grounds skill selection in robotic affordances (Ahn et al., 2022), while Inner Monologue uses execution feed-back to guide language-based planning (Huang et al., 2022). VLA policies such as π0.5 map vi-sual observations and instructions to robot actions (Physical Intelligence et al., 2025). GPT-as-Policy combines π0.5 with GPT-6 Astra for execution re-view and correction (Su et al., 2026). FastHarness builds on this hybrid execution framework, using accumulated experience to schedule review and coordinate recovery. 

Selective supervision and intervention. Selec-tive supervision concerns when an autonomous sys-tem should request external assistance. Ren et al. (2023) study uncertainty alignment in language-model planners that ask for help. In interactive imitation learning, HG-DAgger incorporates hu-man interventions into policy learning (Kelly et al., 2019), while ThriftyDAgger uses novelty and risk to manage an intervention budget (Hoque et al., 2021). FastHarness addresses this scheduling ques-tion during repeated execution with a fixed pol-icy, using reviewed outcomes from recurring task stages to adjust the frequency of model supervision. 

Experience and failure recovery. Past interac-tions can inform subsequent planning and error cor-rection. Reflexion uses verbal feedback to guide later trials (Shinn et al., 2023), and Voyager accu-mulates reusable skills through open-ended inter-action (Wang et al., 2023). REFLECT summarizes robot experiences to explain failures and support correction (Liu et al., 2023). FastHarness uses re-viewed experience to allocate supervision across routine execution and recovery, retaining failure evidence after ordinary scheduling resumes.

4 FastHarness 

FastHarness augments the GPT-as-Policy execu-tion loop with a scheduler that uses task memory to coordinate π0.5 and GPT-6 Astra (Figure 2). For each new observation, the policy proposes an ac-tion chunk and the scheduler decides whether it requires review. The fast path adjusts this decision using stage-specific experience; the recovery path maintains review while a detected error is corrected. Reviewed outcomes update the memory used for subsequent decisions. 

4.1 Experience-Driven Fast Path Stage recognition and outcome memory. The reviewer assigns stage labels, such as approaching, grasping, and placing, during reviewed execution. FastHarness represents observations using down-sampled RGB views and proprioceptive state, and stores examples under these labels. It matches each new observation to the nearest stored example for each stage; a distant or ambiguous match triggers review. Stage statistics use only explicit success or failure judgments for the immediately preceding or-dinary policy transition, attributed to its pre-action stage. Earlier chunks between reviews receive no individual labels, and corrective or recovery actions are excluded from these counts. 

Experience-driven review scheduling. For each stage, the scheduler computes a conservative score 3from reviewed success and failure counts. It com-bines this score with the amount of reviewed expe-rience to set the interval between reviews. Limited evidence, or insufficient consecutive successes af-ter an error, keeps the interval at one chunk. Higher scores and more reviewed samples permit longer intervals. Unknown or ambiguous contexts, uncer-tainty from the previous review, execution alerts, and proximity to remembered errors override this interval and trigger review. Stage-transition checks, random audits, and a control-step limit between reviews provide additional review triggers. Ap-pendix A specifies the matching rule, score, inter-val function, and trigger priority. 

Observation-conditioned execution. When no review is required, the executor runs a prefix of the current policy proposal within the remaining control-step allowance since the last review. It then obtains a new observation and proposal before the next scheduling decision. Longer review intervals therefore retain observation-conditioned control be-tween chunks; stored trajectories are not replayed. 

4.2 Error Recovery Path Detecting errors and repairing locally. A re-viewed execution error or intent mismatch activates the recovery path. Every action chunk is reviewed while recovery is active. The reviewer first guides local corrections from the current state, such as re-approaching and re-grasping a dropped object. 

Recovering toward verified waypoints. If local repair does not resolve the fault, the harness can select a waypoint verified earlier in the episode. It first considers the most recent eligible waypoint and can select an earlier one if needed. The policy generates new actions toward the selected goal in the current environment. Selecting a waypoint does not reset the environment. 

Verifying recovery and resuming execution. 

Ordinary scheduling resumes only after the re-viewer confirms that the fault has been resolved. For waypoint-based recovery, verifying the return goal is followed by a separate assessment of the original fault. Recovery completion clears the ac-tive recovery state while retaining the error record and its recovery evidence. Later observations near that error still require review, even when the stage’s overall success record has improved. 

5 Experiments 

5.1 Experimental Setup 

We evaluate FastHarness in RoboDojo simulated manipulation using π0.5 as the student policy and GPT-6 Astra as the reviewer. Each task is exe-cuted repeatedly with varying scene layouts and persistent task memory. Both efficiency and suc-cess are evaluated on four tasks: Build tower, Fold clothes, Bottle disposal, and Classify objects. Base-line success rates for these tasks are taken from the GPT-as-Policy report (Su et al., 2026). We measure reviewer calls, review-skip rate (the fraction of completed chunks executed automati-cally), recorded tokens, and wall-clock time. Un-less otherwise specified, efficiency comparisons use the first evaluated episode and the mean of the final five episodes within each task’s memory chain. Success follows the native task evaluator. Appendix B provides configurations and metric def-initions; Appendices C and D give detailed traces and complete numerical results. 

5.2 Reviewer Use and Execution Efficiency 

Reviewer demand decreases between the initial and later evaluation windows (Figure 3). In Build tower, the call count falls from 40 to a final-five mean of 13.4, with approximately 75% of chunks executed automatically. Classify objects retains greater review demand: calls decrease from 94 to 68.2, while approximately 24% of chunks exe-cute automatically in the final five episodes. The traces show task-dependent reductions in supervi-sion, with review remaining active throughout later execution. Lower review demand is accompanied by re-duced token consumption (Figure 4a). Recorded GPT-6 token use decreases by 57.2% on average across tasks, computed as the mean of the four per-task percentage reductions. The equal-task mean token count falls from 1.83 million to 0.93 million per episode. End-to-end execution also becomes faster (Fig-ure 4b). The equal-task mean episode time falls from 85.5 to 52.0 minutes, a reduction of approx-imately 39%. This measure includes policy infer-ence, robot execution, reviewer service time, and runtime overhead.

5.4 Review Allocation and Runtime Analysis 

To examine how the fast path changes review al-location and where runtime is spent, we analyze the complete 20-episode chains of Fold clothes and Bottle disposal. For review allocation, we compare episodes 1–5 with episodes 16–20 (Figure 6a–b). An unknown-context trigger requests review when memory contains no sufficiently matching example of the current context. The total number of these triggers across each five-episode window decreases from 35 to 16 for Fold clothes and from 142 to 64 for Bottle disposal. Thus, fewer review requests arise from unfamiliar contexts in later exe-cutions. An automatic span comprises consecutive com-pleted action chunks with no intervening GPT re-view. Within a span, π0.5 continues to generate actions from fresh observations between chunks. The median over each window’s spans increases from 30 to 60 control steps in both tasks, corre-sponding to two versus four action chunks. This measures the actual length of uninterrupted auto-matic execution. The full span distributions appear in Appendix E, Figure 9. Reviewer interaction accounts for 82.0% of total wall-clock time in Fold clothes and 89.7% in Bottle disposal, aggregated over all 20 episodes per task (Figure 6c). This timer includes request handling, waiting, and retries; memory operations contribute less than 0.1% in each chain. The concentration of runtime in reviewer interaction makes review fre-quency a useful optimization target. 5.5 Recovery Behavior 

We examine local repair and correction guided by a verified subgoal. The harness reviews each ac-tion chunk until the fault is resolved, then restores ordinary scheduling. 

Local repair after a dropped object. In the Bot-tle disposal task, a bottle can slip from the gripper during transport. Figure 7 illustrates the resulting local repair. In this example, recovery starts at con-trol step 459. Under continuous review, the robot approaches the bottle again and re-grasps it. Nor-mal scheduling resumes at step 509, and automatic execution follows at 534. The episode finishes with a score of 100/100. This sequence shows how a local correction allows execution to continue from the current scene. 

Using an earlier subgoal to guide correction. In one execution of the Classify objects task, the re-viewer detects at step 219 that the next proposed action would release the third rabbit outside the bas-ket (Figure 8). After local corrections, the harness selects a saved waypoint at step 299. The waypoint records an earlier subgoal: two rabbits placed in the white basket. At step 304, the reviewer con-firms that this subgoal is still satisfied. This check establishes which progress has been preserved; the original fault still requires correction. Reviewed ex-ecution continues until normal scheduling resumes at step 344. The episode ultimately succeeds after a separate later local repair. Verifying the saved sub-goal and resolving the triggering fault are separate decisions.

6 Conclusion 

We presented FastHarness, an experience-driven execution harness that adaptively allocates model supervision in agentic robot systems. Its fast path uses accumulated stage experience to reduce redun-dant review, while its recovery path guides error correction and restores routine execution after re-covery is verified. Experiments on four simulated manipulation tasks show that review demand and execution time decrease as experience accumulates. FastHarness achieves a mean task success rate of 97.19%, compared with 80% reported for the hy-brid GPT-as-Policy baseline. These findings high-light adaptive supervision as a practical approach to improving the efficiency and reliability of agentic robot systems without additional model training. 7References

Review triggers. The scheduler selects the first applicable condition in the following priority order: always-review mode, episode start, active recovery, unknown or ambiguous context, optional contact gating, stage change, previous uncertainty, monitor or proposal warning, error proximity, control-step allowance, scheduled interval, and random audit. Contact gating is disabled in the evaluated configuration, and a familiar stage change may proceed without review when Is > 1. A same-stage error within distance 0.04 requires review regardless of its recovery count or the stage’s clean streak. Reported trigger counts follow this priority order; monitoring and audit settings appear in Table 2. 

Interval and control-step accounting. The chunk counter resets before reviewed execution and increments after every executed chunk. A fixed interval Is = k therefore permits at most k − 1 subsequent automatic chunks, subject to earlier triggers. The base allowance of 120 control steps starts at the most recent reviewed observation and includes the ensuing execution. Automatic execution uses a fresh proposal prefix within the remaining allowance. Scheduled chunk intervals and realized automatic control-step spans are thus distinct. 

A.3 Control Loop and Recovery State 

Scheduling uses memory available before review. Recovery phase changes and attempt completion trigger re-review of the same observation and proposal. An unknown outcome or uncertain intent forces review at the next decision. Native task completion is evaluated separately. Algorithm 1 summarizes the control loop. 

Recovery progression. Reviewed execution errors or intent mismatches initiate local repair. Each attempt ends on an explicit success or failure judgment, or after eight executed chunks without success. Two unsuccessful local attempts trigger correction toward the latest eligible waypoint, if available; an unsuccessful waypoint attempt prompts reviewer selection of another target. Eligible waypoints precede the failure and exclude attempted targets. They are saved outside recovery after an 

ok outcome, with a reviewer-supplied goal and prerequisites. Verified return enters after_return . At least one further chunk must execute before a succeeded judgment permits normal execution. All successful recovery judgments require the preceding outcome to be ok .

B.3 Metrics and Aggregation Review and token usage. For Nauto automatic chunks among Nall completed chunks, the review-skip rate is rskip =

Nauto /N all . A review decision may require several service calls during re-planning; terminal audits add calls without executing another chunk. Calls, accepted reviews, and executed chunks are therefore counted separately; the skip rate cannot be inferred as 

1 − calls /chunks. Token usage is the recorded sum of input and output tokens, with cached input counted once. These are usage counts rather than monetary costs. 

Runtime. Total wall-clock time includes policy inference, robot execution, reviewer interaction, and runtime overhead. Reviewer time includes request handling, waiting, and retries. The remaining time is reported as other , which aggregates all components outside reviewer interaction. 

Comparison windows. Efficiency compares the first evaluated episode with the mean of the final five episodes in each chain. For Classify objects, this is episode 1 versus episodes 5–9; its recovery-event analysis covers episodes 1–8. Review allocation and automatic-span distributions compare episodes 1–5 with episodes 16–20 in Fold clothes and Bottle disposal. 

Automatic spans and cumulative usage. An automatic span consists of consecutive completed automatic chunks without an intervening review. We pool spans within each comparison window: the early and late windows contain 21 and 19 spans for Fold clothes, and 18 and 26 for Bottle disposal. Episodes without automatic execution contribute no spans. Trigger counts identify the first applicable scheduling condition and exclude terminal audits. For episode token counts Ti, the running mean is ¯Tn = Pni=1 Ti/n , including all evaluated episodes through n. Appendix E reports these distributions and cumulative-usage curves. Episodes share task memory, and a recovery event may contain several attempts. We therefore report descriptive chain-level results without treating episodes or recovery events as independent trials. Returning to normal scheduling records the end of an intervention; task success remains a separate native outcome.

F Limitations 

Our evaluation covers four simulated RoboDojo tasks using π0.5 and GPT-6 Astra. The memory representation uses RGB observations and proprioceptive state; deployment with different sensor interfaces may require adapting this representation. Absolute runtime savings also depend on reviewer latency and execution hardware.
