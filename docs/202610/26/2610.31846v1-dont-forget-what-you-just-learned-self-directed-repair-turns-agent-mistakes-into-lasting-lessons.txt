Intelligent agents should learn from their mistakes so that experience leads to continuous improvement. Yet today’s agents recover from a mistake only temporarily: in-context reflections are easily forgotten across sessions and compete for limited context, while full-parameter fine-tuning is expensive and can interfere with existing capabilities. We introduce Self-Direction , a mechanism for agents to learn from mistakes that combines the benefits of temporary in-context retries and policy updates. When an agent fails a task, it reflects on its own trajectory in order to extract a lesson and immediately distills it into a lightweight low-rank adapter. By keeping the original weights frozen, Self-Direction 

prevents adapter training from overwriting base-model parameters while training additional parameters equivalent to ∼ 0.02% of the base model’s parameter count for each adapter. The agent then saves these adapters in a persistent library of lessons, automatically routing them to solve related problems later. Experiments with agents based on open-weight models from the Qwen family across open-ended research (GAIA), tool-use workflows (Claw-Eval), and terminal tasks (Terminal-Bench 2.1) show that our method improves overall success rates by 8.9 to 17.0 percentage points and performs competitively with frontier systems. We find that Self-Direction reduces repeated mistakes across future encounters of a task, nearly doubling the reliability of an agent’s corrections. Learned lessons also transfer: a handful of adapters generalize to dozens of new tasks without additional training. Ultimately, this self-directed repair transforms everyday mistakes into lasting lessons.

# 1 Introduction 

Modern agents can often correct their mistakes and complete the task at hand. Yet, this recovery is ephemeral: In a new session, the agent is just as likely to repeat the same mistake (Rabanser et al., 2026; Gonzalez-Pumariega et al., 2026). As agents tackle longer-horizon workflows, each additional step introduces another opportunity for error. Even frontier agents make mistakes across tool use, coding, and general assistant tasks (Yuan et al., 2026; Bandi et al., 2026). Repeatedly correcting the same mistakes is costly, leads to inconsistent performance, and leaves the potential for continuous improvement unrealized. Our goal is not just to fix an agent’s mistake in the current session, but to learn persistent lessons to avoid repeating the mistake in the future .Existing approaches encapsulate lessons either in context or in model weights, but enable only part of the desired behavior. Context-based methods, e.g., demonstrations, prompt optimization, reflection, hard-coded skill files, and persistent agent harnesses, can change behavior quickly during deployment (Shinn et al., 2023; Majumder et al., 2024; Zhao et al., 2024). They enable agents to accumulate experience without access to model parameters, but their lessons remain external: They must be retrieved when relevant, compete for limited context, and may not reliably influence behavior on related future tasks. What is missing is a continuous mechanism to fix mistakes in the current session and avoid repeating mistakes in future sessions, without impacting existing capabilities. To address this gap, we introduce Self-Direction , a mechanism for agents to learn from their mistakes. After a failed execution, the agent examines its trajectory to extract a lesson and then distills the lesson into a lightweight Low-Rank Adaptation (LoRA) repair adapter. Self-Direction turns feedback about a mistake from the environment or a user into a LoRA lesson that can be employed immediately to retry the current task and retained for future use. Self-Direction uses a router to determine if an existing lesson is relevant to the current task based on the similarity between the current task description and descriptions of previously seen tasks, enabling reuse of lessons on future tasks. Each lesson is encoded in a separate adapter while the base model and previously learned adapters remain frozen, preventing new training from overwriting existing parameters. Furthermore, each lesson requires only a modest amount of memory (e.g., ∼ 85 MB for Qwen3.6-27B), allowing the library of lessons to grow with the agent’s experience. # 2 Related Work 

After failing to complete a task, an agent could simply re-run the same task (Brown et al., 2024) or spend additional inference-time compute (Snell et al., 2025). Both methods improve the fraction of tasks solved by at least one attempt. However, these methods retain no lesson from the recovery after the episode ends, leaving the agent just as likely to repeat the same mistake. Methods that do retain lessons differ mainly in where the lesson is stored: in the agent’s context, its harness, or its weights. 

Lessons kept in context. The most direct way to preserve a lesson is to write it down. Reflexion (Shinn et al., 2023), ExpeL (Zhao et al., 2024), CLIN (Majumder et al., 2024), and Voyager (Wang et al., 2024) store verbal reflections, causal abstractions, or executable skills in episodic memory to condition later trials. This enables rapid adaptation without parameter updates but leaves lessons external to the policy: Reuse requires repeatedly retrieving them into a finite context window. This process is fragile, as performance is sensitive to prompt composition (Lu et al., 2022) and models use relevant information less reliably in longer contexts (Liu et al., 2023). Appendix A further discusses the expressive limits of context-based adaptation. 

Lessons kept in the harness. An orthogonal approach modifies the agent’s harness—its prompts, tools, and memory—while leaving the model fixed (Chen et al., 2026; Ning et al., 2026). Recent systems search over agent designs or self-improve by rewriting their code in response to environmental feedback (Hu et al., 2025; Zhang et al., 2026c; Robeyns et al., 2025). Closest to our setting, Zhang et al. (2026b) let a fixed model mine its failure traces to propose minimal, regression-tested harness edits. We share this failure-driven, teacherless trigger but instead incorporate repairs into the policy itself. Harness-only methods change how a fixed policy is invoked, not what it has learned; gains remain in the scaffold, leaving the underlying model no more capable after deployment. Appendix A reviews self-synthesizing and evolving harnesses more broadly. 

Lessons kept in weights. Parameter updates write lessons directly into the policy, though full fine-tuning can interfere with existing capabilities (Luo et al., 2023). Parameter-efficient methods, such as LoRA (Hu et al., 2022), constrain these updates, motivating approaches that convert failures into weights. FailForge (Lv et al., 2026) and SKILL0 (Lu et al., 2026), however, typically rely on global fine-tuning, privileged reference solutions, or stronger external teachers. Test-Time Training (TTT) instead adapts parameters online to the current input (Sun et al., 2020; Akyürek et al., 2025) but applies updates unconditionally and discards them after the episode. Self-Direction differs from both: Triggered only by a verified failure, it derives supervision from the agent’s own failed trajectory without a stronger teacher, then uses a targeted adapter (Ren et al., 2026) to store each repair as a routable entry in a persistent library of lessons. Appendix A compares other parameter-efficient, self-rewarding, and TTT methods.

3.1 Existing Paradigms for Repairing Mistakes 

Motivated by current mechanisms for repairing mistakes outlined in Section 2, we consider four strategies. They differ in where lessons are encoded and whether they persist after the episode: nowhere, in the context, in the weights, or in the harness (see Fig. 2). • Resampling (lesson not stored) : Agents spend extra test-time compute by drawing multiple independent samples from the unmodified base model π0 to hopefully generate a new, correct rollout (Muennighoff et al., 2025). No lesson is stored, even in the current session: Each agent action is selected from the same policy, π0.• Reflection in Context (lesson stored in current session’s context) : Reflecting on mistakes and inserting verbal critiques, error rationales, or raw failed trajectories into the prompt context has been shown to be an effective method for boosting agent performance (Shinn et al., 2023; Majumder et al., 2024). By self-reflecting and loading task-specific procedural lessons into context, agents can avoid mistakes when retrying the task. However, by default, the lesson is forgotten once a new session without the current context begins. • Reflection in Weights (lessons persist across sessions in weights) : As an alternative to loading procedural per-task reflections in context as textual lessons, agents can incorporate the same reflections in weights through a lightweight adapter, which enables the lessons to persist in the policy and can lead to corrective behavior. • Accumulating reflections in Skills.md (lessons are accumulated across sessions in a text file) : Instead of relying on an external mechanism to determine relevant in-context reflections for a task and retrying, agents can learn from mistakes by distilling and accumulating reflections across sessions and tasks in a shared Markdown text file, often called Skills.md . Agents can load the relevant Skills.md into context when the same or similar tasks are encountered. We compare these approaches using open-weight agents across general assistant, coding, and tool-calling agentic tasks. 4Figure 3 Self-Direction pipeline overview. On detecting a mistake, the agent either self-reflects on the failed trajectory and trains a new LoRA adapter or retrieves an adapter already stored in the library of lessons; the selected adapter is then loaded and the task retried. 

3.2 Experimental Setup and Evaluation on GAIA 

Experimental setup. To evaluate mechanisms for repairing mistakes under controlled conditions, we stan-dardize our primary agent architecture on open-weight models from the Qwen family. The main part of this article contains results for Qwen3.6-27B (Qwen Team, 2026a). The agent operates inside a ReAct interaction loop using standard benchmark system prompts outlined in Appendix G (Yao et al., 2022). Appendix F lists all hyperparameters, Appendix G lists the prompts, and Appendix D repeats the loop on the stronger Qwen3.8-27B (with additional results for Qwen3.5-9B) (Qwen Team, 2026b). Open-weight models enable us to directly compare in-weight versus in-context reflections, described in Section 3.1, while keeping the agent’s base model fixed. 

Metrics. In addition to accuracy, measured as the Task Success Rate , we report pass@ k and pass k to separate coverage from consistency across k independent executions of the whole pipeline. Pass@ k is the fraction of tasks solved in at least one run; pass k is the fraction solved in every run. 

Evaluating assistant, tool-calling, and coding agents. Our evaluation spans three distinct domains. GAIA 

(Mialon et al., 2023) comprises 165 validation tasks across three difficulty levels. Agents use web search, page retrieval, Python, a shell, and file inspection; success is verified by matching a short final answer against a reference. Claw-Eval (Ye et al., 2026) evaluates tool-use workflows over mock email, calendar, task-tracking, and business services. Verification considers the whole trace, including tool calls, audit logs, and produced artifacts, together with an LLM judge. A task can therefore fail because of the actions the agent took even when its final message looks correct. Terminal-Bench 2.1 (Merrill et al., 2026) comprises 89 tasks executed through a persistent shell inside a fresh container. Success is verified by hidden tests run after the attempt. We provide additional experiments for browser agents on MiniWoB++ in Appendix B. Additional details on benchmark-specific tool calls are presented in Appendix F.4. In this section, we employ GAIA as a diagnostic testbed to motivate our pipeline design, reserving compre-hensive cross-domain evaluations on Claw-Eval and Terminal-Bench 2.1 for Section 4. 

Findings on GAIA. We evaluate task success across standard retrying, in-context reflections, and in-weight parametric updates on the 165 GAIA validation tasks (see Fig. 2). 5Retrying boosts coverage but lacks persistence: Resampling from the base model by doing parallel rollouts is effective for immediate task recovery, yielding a 10 .9 pp gain with pass@3 compared to the initial base execution. However, retrying leaves model parameters untouched; once an episode ends, the agent remains just as likely to repeat the same mistake when encountering a similar task in future sessions. We also compare our results with Failed Trajectory in Context in Appendix C.2. 

In-weight updates outperform in-context reflections: To enable lessons to persist, we compare adding failure reflections to context versus incorporating them in weights. Encoding reflections in weights achieves higher task success than loading them into context ( +10 .3 pp). As mistakes accumulate, we find that encoding reflections into a single LoRA adapter is not as effective as individual LoRA adapters per task (see Fig. 14), suggesting that LoRA updates per task are effective in capturing repairs without using global parameter updates. A qualitative example of a successful recovery from a mistake on a Level 1 task is presented in Fig. 15. 

Harness summaries (Skills.md) underperform and constrain context budget: As execution failures accumulate, storing textual reflections in context hits severe scaling limits. Storing full failure trajectories and reflections across GAIA tasks exceeds Qwen3.6-27B’s native context window by over 10 × (Appendix E.2). Distilling reflections into a high-level Skills.md file avoids context overflow but task performance is lower than when reflections are retained in weights (see Fig. 2). Across 165 GAIA tasks, Self-Direction improves accuracy from 38.8% to 55.8%, a gain of 17.0 points (paired task-level t-test: t(164) = 5 .79 , p = 3 .50 × 10 −8; 95% CI: [11 .2, 22 .8] pp). We also find that loading an incorrect or mismatched adapter degrades performance below the clean base policy (Appendix E.1), motivating us to include a router to select an adapter relevant to the task at hand based on the similarity between the current task description and the source-task descriptions associated with stored adapters. Additional details about the t-test are presented in Appendix C.9. 

3.3 The Self-Direction Loop 

Motivated by these diagnostic findings, we introduce Self-Direction : a mechanism that enables agents to learn from a failed execution by reflecting on their mistakes and distilling the resulting lessons into a LoRA adapter, which can later be loaded for similar tasks (see Fig. 3). This enables learning from mistakes to scale while preserving the agent’s existing capabilities (see Section 4.3). Self-Direction operates in two main modes: 

Training repair adapters. When an agent encounters a failure, it performs self-directed reflection to synthesize a concise set ( N ≤ 24 ) of procedural instruction-response examples. Crucially, the model acts as its own teacher without relying on external supervisor models and does not require full rollouts; the procedural examples are behavioral corrections (see Appendix I). These examples are distilled into a lightweight LoRA adapter. To maintain numerical stability and keep the base weights unchanged, adapter matrix A is initialized from the leading right-singular vectors of the targeted base weights and frozen, whereas matrix B (initialized to zero) is optimized (see Appendix J). Training each adapter updates additional parameters equivalent to at most approximately 0.02% of the base model’s parameter count, enabling continuous accumulation in a persistent library of lessons L with a modest memory footprint ( ∼ 85 MB for Qwen3.6-27B). Adapter optimization takes ∼ 1.5 minutes on an H200 GPU in our setup; reflection and example synthesis require additional time. Additional details about the reflection, synthesis, and training stages are presented in Appendix F.3. 

Reusing adapters. When the same or a similar failed task is encountered, Self-Direction uses a sentence-embedding router 2 (Reimers and Gurevych, 2019) to compare the incoming task with the task descriptions stored alongside each lesson in L (the similarity is 1 if a new adapter is trained for the current task). The corresponding adapter is then loaded into the frozen base model for re-execution.

# 4 Results 

Beyond GAIA, we expand our evaluation to coding, tool-calling assistant tasks, and browser agent tasks. We find Self-Direction can repair mistakes across diverse settings, avoid repeating mistakes in the future, and scale learning while preserving existing capabilities, with repair adapters that generalize to unseen task categories and difficulties. 

4.1 Self-Direction Repairs Mistakes Across Various Task Types 

First, we measure whether Self-Direction improves task success across diverse agentic environments. We compare it to the base agent over three independent runs across Claw-Eval, GAIA, Terminal-Bench 2.1, as well as browser gym tasks from MiniWoB++. We find Self-Direction improves task success across all task types. On Claw-Eval, mean success increases from 64 .4% ± 3.6% to 73 .3% ± 2.8% , a gain of 8.9 percentage points (Fig. 4). 4.2 Learned Lessons Prevent Repeated Mistakes

We evaluate whether a repair is merely the result of a lucky retry or a persistent lesson in two ways. First, we measure whether a repair remains effective over future repeated encounters of a task. Second, we assess variability in how often a learned lesson repairs a mistake across multiple independent runs.

Next, we ask whether a growing library of lessons preserves the agent’s existing capabilities. 

4.3 Self-Direction Learns New Lessons Without Impacting Existing Capabilities 

Continual lesson acquisition is useful only if learning a new lesson does not disrupt the agent’s existing capabilities. Self-Direction limits this interference in two ways. First, it routes every task to the unchanged base model for the initial attempt; adapter retrieval occurs only after a base agent makes a mistake. Second, each learned lesson is stored as a separate lightweight adapter, leaving the base model and previously learned adapters frozen. Learning a new lesson, therefore, cannot overwrite previously acquired behavior. On a retry, Self-Direction loads an existing adapter only when the current task goal is sufficiently similar to the adapter’s source-task goal under threshold τ . An agent with τ = 1 will load an existing adapter only if the same task is encountered again; otherwise, the agent will train a new adapter. In this setting, 

Self-Direction trains new adapters for each new task and preserves stored base-model and adapter parameters by keeping them frozen. When τ < 1, Self-Direction loads adapters for similar but not necessarily identical tasks, enabling reuse of adapters across new tasks. We find that empirically, except for low thresholds τ < 0.30 ,the router preserves or improves existing capabilities even with a library of lessons containing adapters from the two other unrelated benchmarks. The detailed findings are presented in Appendix C.8. Next, we study a simple strategy of selecting the most similar adapter, without a fixed threshold. We find that selecting the most similar adapter leads to generalization across new tasks. 

4.4 Learned Lessons Transfer to Unseen Tasks Across Difficulties and Types 

Training a new lesson for each failure may not always be practical. Here, we ask whether lessons acquired through Self-Direction transfer to unseen tasks. We explore three types of transfer: to unseen tasks in a continual deployment stream, to unseen harder tasks, and to unseen task categories. 

A library of three lessons boosts task success across GAIA. We simulate a deployment stream by randomly interleaving all 165 GAIA tasks across all levels. The agent begins with an empty library of lessons and applies 

Self-Direction to learn new lessons. With the library capped at three adapters, the complete Self-Direction 

9loop increases task success across the full 165-task GAIA stream from 36.4% to 52.7%, a gain of 16.3 points, as shown in Table 3. The complete three-adapter library occupies only 256 MB, showing that useful experience can be retained with a modest incremental memory footprint. We report additional deployment-stream experiments with libraries containing six or twelve adapters in Appendix C.7. 

Lessons learned on easier tasks transfer to harder tasks. We study how well lessons learned on easier Level-1 GAIA tasks transfer to unseen, harder Level-2 tasks. Specifically, we train 28 adapters on failed Level-1 tasks, freeze the resulting library, and evaluate it on 86 unseen Level-2 tasks. We find that reusing Level-1 lessons recovers nine failures, increasing overall accuracy from 40 .7% to 51 .2% – a gain of 10 .5 percentage points. The base agent achieves a pass@2 rate of 43% on this subset, demonstrating that the learned repairs remain effective even on more challenging tasks. 

Lessons transfer across related task categories. Finally, we test whether lessons cross category boundaries within Claw-Eval. We freeze a library of three adapters learned exclusively from operations tasks and evaluate it on 24 unseen workflow tasks (Table 3). The base agent solves 18 tasks on the initial execution. On the six remaining failures, the operations library solves three, recovering half of the failures without training on a single workflow task. This raises accuracy from 75 .0% to 87 .5% , a gain of 12 .5 percentage points. Qualitative examples of these transfers are presented in Appendix H. Collectively, our findings present Self-Direction as a promising foundation for agents that improve through continual use. Across research, tool-use, browser, and coding environments, Self-Direction repairs mistakes now, prevents repeating mistakes in the future, preserves existing capabilities, and generalizes to harder tasks and tasks in related categories. Self-Direction offers a path towards agents whose deployment experience compounds over time—where each mistake can contribute not only to solving the task at hand, but to building lasting capabilities. 

# 5 Conclusion 

A growing library of lessons holds promise for scaling continuous agent self-improvement. Encoding each lesson as a LoRA adapter provides a practical way to store and reuse experience across deployments and domains. Besides self-improvement, Self-Direction may support model specialization for tailored applications, personalization, and patching security vulnerabilities. Lessons could also be implemented through self-evolving harnesses or stored in Skills.md files for use in context. Future research can explore how to select the most suitable medium for retaining a given lesson and how to compose multiple lessons when addressing a mistake. 

Limitations. Self-Direction begins with a mistake, which must be detected through self-evaluation or grader feedback, or reported by a user. It then retains the resulting lesson. Encoding that lesson in model weights requires GPU resources and storage capacity beyond standard inference to train LoRA adapters. Textual reflections can instead be stored and accumulated until sufficient resources become available. # A Expanded Related Work 

Lessons kept in context. Expanding on the context-based methods discussed in Section 2, systems frequently rely on iterative self-correction without training. For instance, Self-Refine allows a single model to critique and revise its own output (Madaan et al., 2023), whereas GEPA turns this reflective step into an optimizer by attributing outcomes to specific prompt content and evolving candidate pools (Agrawal et al., 2026). Maintaining textual skills has also appeared in deployed systems as markdown skill files (Anthropic, 2026), with recent work co-evolving such skills alongside persistent knowledge bases for cross-model transfer (Tang et al., 2026). Other approaches, like Skill-Pro, refine a skill memory using a PPO-style objective while keeping the underlying model frozen (Mi et al., 2026). However, relying on externalized skills has significant operational downsides. Retrieved skills have been shown to introduce functional failures and efficiency regressions even when they appear relevant (Dong et al., 2026). Furthermore, the limitation is fundamentally expressive: Gupta et al. (2026) argue that concatenating exemplars is only a shallow form of adaptation, as the context can only reach the internal states that a literal prompt induces through frozen weights. 

Lessons kept in the harness. Expanding on the harness-based methods discussed in Section 2, there is extensive debate regarding how to best represent an agent’s harness (Pan et al., 2026; Chen et al., 2026; Wang et al., 2026) and what elements the harness should own at runtime (Jiang et al., 2026). While early work focused on meta-agents programming new agents in code (Hu et al., 2025), recent systems have heavily specialized this self-evolving loop. For instance, Lou et al. (2026) synthesize code harnesses automatically, Sengupta and Wang (2026) treat harness configuration as a direct optimization target, and Lee et al. (2026) optimize a weaker agent’s harness using a stronger external one. Lin et al. (2026) pair every harness edit with a prediction that is later verified against task outcomes. Beyond single-episode optimization, Nie et al. (2026a) distribute this process across deployments and Nie et al. (2026b) evolve harness code over an unlabeled test stream, though adaptation is scheduled per batch rather than conditioned on a verified failure. Other approaches synthesize harnesses just in time (Zhang et al., 2026a), adapt the model-environment interface offline (Xu et al., 2026), compose harnesses into multi-day development loops (Yan et al., 2026), or expose this evolving surface directly in deployed systems (Karten et al., 2026). Ultimately, all of these methods accumulate a lineage of scaffold code rather than a library of parametric repairs. 

Lessons kept in weights. As discussed in Section 2, low-rank adaptation reduces the risk of catastrophic forgetting. However, empirical analysis shows that routing among several adapters can still underperform an oracle (Back et al., 2026). Variations like PiSSA initialize an adapter from the principal singular components of a pretrained weight and train those components, refactoring the stored weight into a residual (Meng et al., 2024). In contrast, we freeze the spectral factor and train only the zero-initialized coefficient matrix, leaving base weights completely untouched such that the adapter remains detachable. This follows the initialization introduced for online parametric memory by Ren et al. (2026), though their adaptation is triggered by context-budget overflow and evolves a single intra-episode state rather than a retrievable library. Furthermore, the training signal for in-weight learning is typically gathered in offline batches, as seen in STaR and ReST (Zelikman et al., 2022; Gulcehre et al., 2023). Methods that learn specifically from mistakes usually rely on a stronger corrector, such as GPT-4 (An et al., 2024), or the model judging itself (Yuan et al., 2024). When a teacher is given privileged information, the resulting performance gap conflates true transferable capability with information asymmetry (Yu et al., 2026). Closest to our setting, FailForge converts persistent failures into a training signal, but uses a stronger teacher, a reference patch as privileged input, and a single global fine-tune after which the textual skill is deliberately discarded (Lv et al., 2026). Finally, Test-Time Training (TTT) is related to our in-weight updates during goal execution. TTT adapts parameters on the current test input under a self-supervised objective (Sun et al., 2020), on text retrieved from neighbors before being reset (Hardt and Sun, 2024), or through a per-task adapter trained on rule-based augmentations (Akyürek et al., 2025). In each of these cases, adaptation is transient and unconditional, whereas our method conditions strictly on verified failures and preserves the repair for future reuse. 15 B Additional Browser and Computer-Use Benchmarks

25 D Self-Direction with a Stronger Base Model 

The benefits of Self-Direction should not depend on beginning with a weak base agent. We test this by applying the same loop to Qwen3.8-27B and comparing it with Qwen3.6-27B on identical GAIA, Claw-Eval, and Terminal-Bench 2.1 task sets. As expected, Qwen3.8-27B solves more tasks during its initial execution on all three benchmarks. Self-Direction nevertheless provides substantial additional gains. On GAIA, it recovers 27 failures and raises accuracy from 59 .4% to 75 .8% (+16 .4 pp). On Claw-Eval, it raises accuracy from 64 .6% to 76 .4% (+11 .8 pp), whereas on Terminal-Bench 2.1, it improves accuracy from 55 .1% to 73 .0% (+17 .9 pp). The corresponding Qwen3.6-27B runs also improve on every benchmark, with gains between 15 .5 and 18 .0 percentage points. These results support the central role of failure as an intervention point. As the base model becomes more capable, fewer tasks enter the mistake subset but the remaining failures still provide useful signals for targeted in-weight repair. Self-Direction , therefore, complements improvements in the underlying model rather than merely compensating for a weaker checkpoint. This experiment establishes robustness across two capability levels within the same model family; broader generalization across model families and scales remains an important direction for future work. 26 E Why Self-Direction Uses Modular In-Weight Lessons 

Self-Direction relies on two design choices. Each failure produces a distinct lesson adapter, and relevant experience is retrieved on a later task. We examine both choices on GAIA. We first compare failure-specific adapters with pooled, mismatched, and randomly initialized LoRA alternatives. We then quantify why retaining the complete learning history directly in context does not scale. 

E.1 Lesson Specificity and Recovery 

Adding or modifying existing parameters is useful only when it captures a lesson relevant to the failure being repaired. Fig. 14 compares the complete Self-Direction policy with several alternative representations of the same failure-derived experience. The full loop recovers 27 .7% of the initial failures. However, a single pooled LoRA recovers only 16 .7% and 14 .6% of attempted failures at ranks 16 and 64, respectively. E.2 Why Not Place Every Lesson in Context? 

Textual memory is useful but accumulating every lesson in the active context is not a scalable form of persistence. The 101 failures in the GAIA Self-Direction run produce 2,428 corrective examples: 672 from Level 1, 1,323 from Level 2, and 433 from Level 3. Using the Qwen3.6 tokenizer, their instruction-response content is estimated to contain approximately 362k tokens, implying that each self-reflection loop produces an additional ∼ 3.6k tokens per failure. F.1 Agent Generation and ReAct Execution 

The agent operates through a ReAct-style loop (Yao et al., 2022) that interleaves model decisions with environment interaction. At each step, the model receives the task and accumulated trajectory, then emits either a tool call or a final response. A tool call is executed by the environment, its observation is appended to the trajectory, and the model is invoked again. A rollout terminates when the model provides a final answer or exhausts its interaction budget. The same decoding configuration is used for the initial base execution, adapter-guided retry, and base fallback (see Tables 9, 10). The larger Terminal-Bench budget accommodates longer coding and environment-manipulation tasks. These values are upper bounds: A rollout terminates early whenever the agent completes the task or emits a final answer without any tool calls.

F.2 Adapter Synthesis and Training 

Each failed execution produces up to 24 corrective examples. Adapter training begins only when at least eight valid examples are available. All base-model parameters remain fixed. Each lesson is represented by a rank-16 LoRA adapter initialized from the targeted base-model weights using the SVD procedure described in Section 3. The first LoRA factor is initialized from the leading right singular vectors and frozen, whereas the second factor begins at zero and is optimized on the corrective examples. The target modules depend on the normalized failure reason rather than the benchmark. Failures involving planning or interaction limits update the attention projections, q_proj and v_proj ; incorrect answers and execution exceptions update the multi-layer perceptron (MLP) down_proj projection. This keeps the in-weight repair localized to the type of behavior implicated by the failure. Reflection uses the same base model with temperature 0.6. Its maximum generation length is 16,384 tokens for all benchmarks. No external teacher model is used. 

Failure normalization. We normalize each failure using the agent’s termination signal, the presence of an extractable response, and the binary verifier outcome. Budget exhaustion and execution exceptions take precedence over output-based labels. Otherwise, an empty response is assigned no_final_response , whereas a completed response rejected by the verifier is assigned wrong_answer . Table 11 summarizes the resulting vocabulary. The normalized reason, therefore, affects adaptation in two ways: It focuses reflection on the procedural deficiency exposed by the failure and determines where the resulting lesson is represented in the adapter. Information boundary. Normalized failure reasons are deliberately categorical and low-bandwidth. Let 

t denote the agent’s termination status, e indicate whether an extractable response was produced, and 

z = V(x, τ ) ∈ { 0, 1} denote the verifier’s binary decision. The reason exposed to reflection and routing is 

r = Normalize( t, e, z ).

The reference answer, hidden-test contents, and verifier-internal artifacts are not arguments to this function. In particular, r contains neither gold-answer tokens nor test outputs, judge scores, rubrics, rationales, or free-form judge feedback. The loop observes only the categorical outcome of verification, not the information used internally to compute it. We additionally enumerated every persisted reason value in the reported GAIA, Claw-Eval, and Terminal-Bench 2.1 runs. The observed values of r were exclusively step_budget , wrong_answer , and exception ; no stored reason contained task-specific text, answers, test results, scores, or judge feedback. Thus, the failure classification and module-routing decisions cannot communicate how to solve the task. They convey only a coarse description of how the preceding execution failed. 

F.3 Adapter Training and Compute Requirements 

Self-Direction performs a small amount of training only after a mistake is detected, triggering self-reflection and adapter training. Each reflection call produces ∼ 24 structured instruction-response examples. Measured with the Qwen3.6-27B tokenizer and the actual chat template used for training, these examples contain an average of 3,622 tokens per adapter. Rationales generated during reflection are retained for analysis but are not included in the training loss. The fixed base model is adapted using rank-16 LoRA with SVD initialization. The LoRA A matrices are initialized from cached right-singular directions of the corresponding base-model weights and remain frozen; only the B matrices are optimized. F.4 Benchmark Tool Interfaces 

Each benchmark is evaluated using its native interaction interface. The initial base execution, adapter-guided retry, and base fallback receive the same tools. Hence, improvements cannot arise from exposing additional capabilities after failure. During reflection, Self-Direction also receives the tools available in the failed execution, enabling it to generate corrective examples that refer to valid actions. GAIA uses a fixed collection of general-purpose research and file-processing tools. Claw-Eval exposes task-specific subsets of a larger service-oriented tool collection and its nine sandbox tasks provide shell and file-manipulation tools in addition. Terminal-Bench 2.1 exposes a single persistent shell inside a fresh task container (see Table 13). For Terminal-Bench, each adapter or base retry begins in a fresh container to prevent filesystem changes from a previous attempt from leaking into the next one. Claw-Eval similarly relies on the official benchmark services and audit logs. GAIA retries retain access to the same task attachments and general-purpose tools. Thus, Self-Direction changes how the agent uses an existing interface, rather than changing the interface itself.

Initializing matrix A with SVD and keeping it frozen offers two benefits: It further reduces the number of trainable parameters in an already lightweight adapter and anchors adaptation in a high-energy subspace of the pretrained model (Ren et al., 2026). Only the adapter’s B matrices are trained, adding trainable parameters equivalent to at most approximately 0.02% 

of the base model’s parameter count.
