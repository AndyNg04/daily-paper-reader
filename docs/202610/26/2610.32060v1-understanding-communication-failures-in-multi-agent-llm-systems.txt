## Understanding Communication Failures in Multi-Agent LLM Systems 

Priya Pitre Jun Hou Yi Fang Naren Ramakrishnan Xuan Wang 

Virginia Tech Blacksburg, VA 24061, USA 

Abstract 

Multi-agent LLM systems aim to improve rea-soning through debate, evidence sharing, and mutual correction, but interaction can also in-troduce failures that final accuracy alone cannot explain. Agents may converge too early, ignore dissent, suppress correct minority answers, or preserve a wrong framing across rounds. We present a corpus-grounded taxonomy of com-munication failures, built from 3,211 failed multi-round trajectories across medical QA, coding, finance, multi-hop reasoning, ethics, and embodied text tasks. Using this taxonomy, we analyze failure distributions across datasets and system designs, round-level error dynam-ics, recovery hardness, majority transitions, minority-signal suppression, and self-reported confidence. We find that failures are dominated by recovery/correction and consensus/decision problems rather than isolated first-round mis-takes, with many emerging after agents first ob-serve peer responses. Based on these findings, we recommend stronger disagreement handling, evidence verification, minority-signal preserva-tion, and recovery checks before finalization. 

1 Introduction 

Multi-agent LLM systems are motivated by a sim-ple but powerful premise: failures of a single model may be easier to catch when several agents di-vide work, exchange evidence, and challenge one another before producing a final answer. This premise now appears across both research and deployment. Multi-agent debate uses interacting models to critique and revise rationales (Du et al., 2024); discussion-based approaches use diverse models to reconcile disagreements (Chen et al., 2024); sampling-and-voting methods instantiate multiple agents to improve robustness; and produc-tion systems such as Amazon Bedrock support su-pervisor agents that coordinate specialized collabo-rators (Amazon Web Services, 2026). Across these settings, communication is the central mechanism through which agents decompose tasks, transfer evidence, resolve disagreement, incorporate tool outputs, and decide when to stop. However, the same communication process that makes multi-agent systems appealing also creates a new failure surface. Discussion can repair individ-ual mistakes, but it can also amplify them: correct answers may be abandoned after peer influence (Wynn et al., 2025), failures may arise from sys-tem design, inter-agent misalignment, and weak verification (Cemri et al., 2026), and the responsi-ble agent or decisive failure step can remain diffi-cult to localize even after the system fails (Zhang et al., 2025). These findings suggest that multi-agent errors are not simply individual model errors repeated in parallel, but interaction-level failures produced through communication, authority, aggre-gation, and recovery. Existing taxonomies and diagnostic benchmarks provide important starting points, but they leave the communication process in multi-agent discus-sion under-specified. Cemri et al. (2026) identifies broad sources of failure such as system design, inter-agent misalignment, and weak verification; (Deshpande et al., 2025) and (Barke et al., 2026) analyze agentic traces and critical failure steps; and attribution-focused work such as (Chen et al., 2026), (Yu et al., 2025) and (Ma et al., 2026) stud-ies which agent, step, or platform component con-tributed to failure. These works show the value of trace-level diag-nosis, but they do not make interaction itself the ob-ject of analysis. This matters because multi-agent failures are often produced between agents rather than inside one agent or component: a correct mi-nority answer can be abandoned, a weak claim can become dominant through repetition, and a useful correction can disappear if it is not taken up be-fore finalization. To address this, we construct a corpus-grounded taxonomy of multi-agent communication failures and use it to study how errors emerge, spread, and recover during deliberation. Our corpus spans ten domains, including medical QA, coding, finance, multi-hop reasoning, ethics, and embodied text environments, while varying model family, agent count, tool access, composition, and orchestration style. We focus on incorrect multi-round trajecto-ries, using correct multi-round trajectories as a con-trast set, to analyze when errors first appear, who in-troduces them, whether recovery is attempted, and how group answers change across rounds. To our knowledge, this is the first communication centric taxonomy focusing on multi-agent LLM debates. Rather than deriving categories from an uncon-strained LLM prompt, we build the taxonomy from trajectory evidence, inspired by Kargupta et al. (2025). Each trace is summarized into a compact evidence card, then mapped into diagnostic cate-gories with an explicit option for unsupported cases. The taxonomy is iteratively expanded when dense or unmapped evidence reveals coherent new failure types. Our analysis shows that multi-agent failures are dominated by recovery and consensus problems rather than isolated first-round mistakes: recovery/-correction failures appear in 94.9% of failed tra-jectories and consensus/decision failures in 83.4%. Round 2 is a critical point where many failures emerge after agents first observe peer responses, and correct minority signals are often suppressed rather than amplified, especially in larger groups. Finally, we show that the taxonomy can support real-time early-warning monitors for persistent wrong framing, premature consensus, and oscil-lating consensus, achieving very high recall before the final answer is produced. Based on these find-ings, we propose recommendations for designing more reliable multi-agent systems. 

2 Related Work 

Multi-agent Taxonomy: Multi-agent LLM sys-tems distribute reasoning across agents that debate, specialize, verify, vote, or use tools for one another. Multi-agent debate, ReConcile, More Agents Is All You Need, and AutoGen share the premise that rationales or aggregation can expose errors a single model might miss (Du et al., 2024; Li et al., 2024; Wu et al., 2024), but recent work shows these gains are conditional: Cemri et al. (2026) finds setup-dependent failures in system design, inter-agent misalignment, and task verification, while Wynn et al. (2025) shows that debate can reduce accu-racy when agents abandon correct answers after peer responses. Related taxonomies and attribution benchmarks, including Cemri et al. (2026); Zhu et al. (2025); Barke et al. (2026); Yu et al. (2025); Kong et al. (2025) platform root-cause and lifecycle studies while Bi et al. (2026); Zhang et al. (2025); Chen et al. (2026); In et al. (2026) localize, transfer, or generate failure patterns across traces. Our work focuses on automatically constructed communica-tion centered taxonomy. Additional details are in Appendix B. Multi-agent error detection: Existing works use failure signals for detection and mitigation. AgentForesight performs online auditing during an unfolding trajectory (Zhang et al., 2026); Problem Drift introduces DRIFTJudge and DRIFTPolicy for debate drift detection and feedback (Becker et al., 2026); From Spark to Fire models error cascades and mitigates them with message-level governance (Xie et al., 2026); InferAct detects misaligned actions before execution (Fang et al., 2025); and AgentDebug and AgentFixer connect detection to feedback, repair recommendations, and validation (Zhu et al., 2025; Mulian et al., 2026). These systems move beyond post-hoc ex-planation, but their signals are often task-, action-, or drift-specific, and many intervene only after failure is visible. Our trigger system is real-time and taxonomy-guided: after each round, it uses communication-error labels to estimate whether continued deliberation will recover or amplify an error. Because the taxonomy spans domains, tools, setups, and multiple errors per trace, it supports propagation-aware intervention rules beyond final correctness or generic judge scores. 

3 Methodology 

Our methodology has three stages: collecting multi-agent trajectories, constructing a corpus-grounded communication-error taxonomy, and applying the taxonomy to a downstream trigger-error detection task. 

Multi-Agent Trajectory Collection We col-lected multi-agent debate traces from eight datasets spanning financial QA, multi-hop QA, medical QA, ethical judgment, multiple-choice reasoning, and code generation: FinQA (Chen et al., 2021), HotpotQA (Yang et al., 2018), MBPP (Austin et al., 2021), MMLU-Pro (Wang et al., 2024), MedQA (Yao et al., 2024), MuSiQue (Trivedi et al., 2022), Ethics (Hendrycks et al., 2020), and Live-CodeBench (Jain et al., 2025). Agents were drawn from open-weight models including LLaMA-3.2-3B, Mistral-7B, Qwen-14B, LLaMA-70B, GPT-OSS-20B, GPT-OSS-120B, and Gemma-12B, with assignments varying by experiment variant. Across all experiment files, we ran 7,300 task instances, 3,543 of which ended incorrectly. We focus on incorrect trajectories with more than one debate round, yielding 3,211 traces for taxonomy construc-tion. For each experiment variant, we used a fixed 100-example sample where available, sampled with seed 42. Accuracy and tested settings are reported in Table 14; full protocol and dataset-specific de-tails are in Appendix A. 

Taxonomy Construction. We followed aTaxoAdapt-inspired (Kargupta et al., 2025) procedure combining top-down initialization with bottom-up expansion. Each failed multi-round trajectory was converted into a compact card containing agent trajectories, round-level errors, failure summaries, candidate tags, and supporting evidence. GPT-5.4-nano handled the main generation and mapping steps, including two-pass card generation: summarizing failure behavior, then producing 3–8 reusable tags with evidence and justification. • Initialize broad dimensions. We speci-fied six top-level dimensions: reasoning/task-understanding, communication/deliberation, con-sensus/decision, recovery/correction, coordina-tion/orchestration, and tool/evidence-use failure. Lower-level labels were induced from the corpus. • Map and deduplicate tags. Candidate tags were mapped to broad dimensions, leaving weak fits unmapped and trajectories multi-label. Near-duplicates were merged using text normalization, stopword removal, token Jaccard similarity, con-tainment, and RapidFuzz token-set ratio. We retained the shortest clear representative tag (ear-liest row breaking ties), along with identifiers, duplicate tags, evidence, justifications, counts, and row indices. • Seed child labels. For each dimension, GPT-5.4-nano proposed 5–6 child labels from 50 sampled representative tags. We manually removed redun-dancy and improved interpretability. GPT-5.4-nano also handled broad-category assignment, parent-label cleanup, and broad-label checking/-correction. • Expand width from unmapped tags. Un-mapped tags after top-down mapping were treated as coverage gaps and clustered using only representative-tag text. We used BAAI/bge-base-en-v1.5 embeddings, optional PCA (at most 50 dimensions), and agglomerative clustering with cosine distance and average linkage. Candidate cluster counts (5, 10, 15, 20, 25, 50, 100) were evaluated by cosine silhouette score and centroid-nearest representatives. Human Annotation and Taxonomy Validation. 

We sampled 200 random failed trajectories, each annotated by three annotators. First, annotators performed open-ended annotation, describing what went wrong without seeing our taxonomy. We then mapped these descriptions to taxonomy labels to measure coverage. Second, annotators were shown the taxonomy and assigned all applicable labels. We report inter-annotator agreement and compare automatic labels against adjudicated human anno-tations. 

Contrast Set. To identify which errors distin-guish successful from failed debates, we sample 500 correct multi-round trajectories from the same six non-coding datasets as the failed trajectories. We use an outcome-blind annotation prompt that identifies errors from trace evidence without know-ing the final outcome, then maps them to our fixed taxonomy. We compare these annotations against failed trajectories, adjusting for differences in dataset distribution. 

Trigger Model. To demonstrate a downstream use of the taxonomy, we train early-warning mod-els to predict whether an error will appear in the next round. We focus on premature consensus, failed recovery after disagreement, and failure to recover after an unknown answer. We use 304 debates paired by question and correctness, with error onset rounds annotated without access to fi-nal outcomes. Our random forest uses answer dy-namics, including disagreement, answer changes, oscillation, and confidence, without message text or dataset identity. We evaluate using leave-one-pair-out validation against rule-based baselines and an LLM judge (Appendix E). 

4 AGENT INTERACT ERROR Taxonomy 

Figure 2 shows the final taxonomy. It has six broad parent categories: reasoning/task understand-ing, communication/deliberation, consensus/deci-sion, recovery/correction, coordination/orchestra-tion, and tool/evidence use. Under these, the tax-onomy contains 24 child labels and 11 final leaf labels. The labels in the taxonomy are unique but context-dependent. The same behavior can be-long to different parts of the taxonomy depending on what it affects in the trajectory. For example, answer drift can be a consensus/decision failure when it makes group agreement unstable, such as when the majority answer changes across rounds or agents converge through momentum rather than verification. However, it can also be a recovery/cor-rection failure when agents had access to a correct answer, correction, or useful evidence, but later discussion pulls them away from it instead of pre-serving the repair. So the label is not based only on the words in the trace; it depends on the role the behavior plays in the failure. We also treat each trajectory as multi-error. 5 Analysis and Discussion 

Human Annotation and Taxonomy Validation. 

We first test whether the taxonomy captures failures that humans identify independently and whether our automatic labels are reliable enough for the analyses that follow. In open annotation, 93.4% of human-identified errors mapped to a fine-grained taxonomy label and 98.1% to a parent category. With the taxonomy visible, annotators reached 0.82 Jaccard agreement at the parent level and 0.73 at the fine-grained level; our automatic pipeline reached 0.91 and 0.84 micro-F1 against adjudicated human labels, respectively. Together, these results sug-gest that the taxonomy covers most failures people notice without being prompted by it, while the au-tomatic labels reproduce human judgments closely enough to support large-scale analysis.

What drives failures? We examine how system-design choices affect failures by comparing config-urations that differ in only one factor on the same questions, using question fixed effects, clustered standard errors, and Benjamini–Hochberg correc-tion (App. D). 

Evidence access has the largest effect. Re-trieval reduces the overall failure rate from 74.6% to 36.4% on HotpotQA and MuSiQue (95% CI: 

−43 .8 to −32 .7 pp). Although tool-enabled sys-tems show a higher proportion of consensus errors among failed debates (Fig. 4), retrieval reduces their overall occurrence, including premature con-sensus and wrong framing. In contrast, increas-ing the team from three to seven agents does not significantly reduce failures. Reasoning errors be-come less common, but failures after abstention and suppression of correct minority answers in-crease. Thus, more agents may provide additional reasoning without improving how groups handle uncertainty or disagreement. Hierarchy reduces os-cillation but not overall failures, while explicit roles have no detectable effect. Qwen-14B also fails more often than GPT on MMLU, mainly through answer drift (App. D; Table 14). Figure 4 also shows that homogeneous teams have more recovery failures but fewer communica-tion failures than heterogeneous teams. This sug-gests that agents using the same model may coor-dinate easily but share blind spots, allowing incor-rect assumptions to remain unchallenged. Overall, 

better evidence reduces failures, while changes to team structure mainly affect how systems fail. Premature consensus, wrong framing, and ignored corrections remain statistically unchanged across team size, roles, hierarchy, and model choice (App. D). These findings suggest that agent design should prioritize evidence verification, disagree-ment handling, and correction rather than simply adding more agents or changing their roles.

Initial-majority transitions. We examine how the initial majority influences the final answer, including whether wrong majorities recover and whether correct minority agents can change the outcome (Table 4). Across datasets, wrong majori-ties are more likely to remain wrong than recover, while correct majorities are usually preserved. Cor-rect minority agents are also suppressed more often than they successfully change the group’s answer. These patterns vary by task: MedQA (which has more evidence based discussions) shows stronger recovery, while Ethics has more corruption and minority suppression. Correct answers also have shorter explanations in MedQA, MuSiQue, and Ethics, suggesting that longer discussions do not necessarily improve outcomes. Debate tends to preserve the majority rather than recognize cor-rect minority answers. This suggests that agent systems should evaluate evidence rather than sim-ply follow agreement, for example by verifying minority answers, checking their supporting evi-dence, and resolving disagreements before making the final decision.

6 Recommendations for Multi-Agent System Design 

Based on our findings, we highlight four design recommendations. • Do not rely on self-reported confidence. Agents become more confident even when their answers are wrong (Table 15). Confidence should therefore not be used alone to determine which agent to trust or when to stop debating. • Use active supervision rather than simple ma-jority voting. Supervisors should question unsup-ported claims, track disagreements, and verify com-peting answers rather than simply follow the ma-jority. Hierarchy alone does not reliably improve accuracy. • Use task-specific verification. Different tasks re-quire different checks: numerical tasks need cal-culation verification, coding tasks need edge-case testing, multi-hop QA needs evidence checking, and ethics-style tasks need stronger protection of correct minority answers. • Intervene based on the error type. 7 Conclusion 

We present a corpus-grounded taxonomy of com-munication failures in multi-agent LLM systems. Our analysis shows that failures arise not only from incorrect reasoning but also from premature con-sensus, ignored corrections, and unsuccessful re-covery. These findings highlight the importance of verifying evidence, preserving disagreement, and correcting errors during deliberation. The taxon-omy also supports early failure detection, providing a basis for more targeted monitoring and interven-tion in multi-agent systems. Limitations 

Our study focuses on incorrect multi-round trajec-tories because our goal is to analyze communica-tion failures that emerge through deliberation. This design is useful for studying failure propagation, recovery, and consensus behavior, but it does not capture all possible issues in correct trajectories or in single-turn multi-agent settings. We partially ad-dress this by using correct trajectories as a contrast set in analyses such as majority-transition dynam-ics and trigger-model evaluation. Our experiments also do not cover the full space of real-world multi-agent environments. We focus on communication-centered deliberation, where agents exchange answers, reasoning, evidence, dis-agreement, and revisions across rounds. As a result, our corpus does not fully capture GAIA-style tool-heavy tasks, software-development agents, shared-blackboard collaboration, or long-horizon environ-ments where agents interact mainly through files, memory, tools, or external state. These settings may surface additional failures around planning, execution, tool chaining, state tracking, persistent memory, and file-level coordination. We therefore view our taxonomy as a communication-focused foundation that should be extended and validated in more open-ended deployed agent environments. The taxonomy is also constructed from the datasets, models, and orchestration styles included in our corpus. Although the corpus spans several domains and system designs, additional domains may reveal new fine-grained failure types. To re-duce overfitting, we use broad parent categories, preserve evidence links for each label, and report taxonomy saturation results showing that high-level categories stabilize relatively quickly. Finally, some stages of taxonomy construction and evaluation use LLMs. This may introduce model-specific bias in label generation, mapping, or semantic evaluation. We mitigate this by us-ing structured trajectory cards, explicit unmapped options, iterative clustering, evidence-backed la-bels, and separate structural checks for granularity, sibling coherence, alignment, relevance, and cover-age. 

Potential risks. This work analyzes failures in multi-agent LLM systems and could be misused to make unreliable systems appear more trustworthy by adding superficial monitoring without meaning-ful validation. To avoid this, we frame the taxon-omy as a diagnostic tool rather than a guarantee of correctness. Our recommendations emphasize verification, disagreement preservation, evidence checking, and human review for high-risk settings. Another risk is that automated failure labels may be treated as definitive explanations of why a system failed. In practice, multi-agent failures can involve several interacting causes, and our taxonomy is multi-label for this reason. We therefore recom-mend using the labels as structured evidence for analysis and debugging, not as single ground-truth causal explanations. 

Reproducibility. We report the datasets, model families, orchestration settings, sampling proce-dure, inference temperatures, and evaluation proto-col used in our experiments. Each experiment vari-ant uses a fixed sample where available and seed 42 for sampling. We also log per-round agent answers, confidence scores, reasoning, consensus decisions, moderator or supervisor outputs, final answers, and correctness labels. To support reproducibility, we describe the taxonomy-construction pipeline, in-cluding trajectory-card generation, candidate-tag extraction, broad-category mapping, deduplication, unmapped-label clustering, width expansion, depth expansion, and final remapping. We also provide prompt templates and trigger-model details, includ-ing features, splits, thresholds, and hyperparame-ters. Some exact costs may vary across providers and time, but we report approximate token usage and inference costs to make the scale of the experi-ments transparent. 

Ethical Considerations 

Our work studies communication failures in multi-agent LLM systems with the goal of improving transparency and reliability. The datasets used are existing benchmark datasets, and our analysis fo-cuses on system behavior rather than human sub-jects. We do not use private user data or attempt to infer sensitive personal attributes. Because multi-agent systems may be used in sensitive domains, including medical, legal, financial, or educational settings, our findings should not be interpreted as showing that debate-based systems are inherently reliable. Instead, the results suggest that multi-agent systems require stronger safeguards, espe-cially around premature consensus, ignored correc-tions, unsupported confidence, and failed recovery. For high-stakes use cases, taxonomy-based moni-toring should be combined with external validation and human oversight. AI assistance in writing. AI writing tools were used to assist with editing, wording refinement, and organization of the manuscript. All technical claims, experimental results, analyses, and final writing decisions were reviewed and controlled by the authors. AI assistance was not used as a substi-tute for conducting experiments, validating results, or determining the paper’s scientific conclusions.

A Experimental Setting 

Model Selection and Evaluation Scale. We evaluated multi-agent LLM systems across eight datasets spanning financial QA, multi-hop QA, medical QA, ethical judgment, multiple-choice reasoning, and code generation: FinQA, Hot-potQA, MBPP, MMLU/MMLU-Pro, MedQA, MuSiQue, Ethics, and LiveCodeBench. Our open-weight agents included LLaMA-3.2-3B, Mistral-7B, Qwen-14B, LLaMA-70B, GPT-OSS-20B, GPT-OSS-120B, and Gemma-12B, with model as-signments varying by dataset and configuration. Open-weight inference was run through a combi-nation of GPU infrastructure and DeepInfra-hosted endpoints, while OpenAI endpoints were used for selected taxonomy-construction, mapping, cleanup, and judge-style classification components. Across all experiment files, we ran 7,300 task instances, of which 3,543 ended incorrectly. Since our fo-cus is on failures that emerge through interaction rather than isolated first-turn errors, we filtered to incorrect trajectories with more than one debate round, yielding 3,211 traces for taxonomy con-struction: 266 from FinQA, 404 from HotpotQA, 320 from MBPP, 325 from MMLU/MMLU-Pro, 281 from MedQA, 755 from MuSiQue, 246 from Ethics, and 614 from LiveCodeBench. For each experiment variant, we used a fixed 100-example sample where available and sampled with seed 42 for reproducibility. 

Inference Configuration. Most multi-agent de-bate experiments used temperature = 0 .7, allowing agents to produce diverse reasoning while keep-ing the overall protocol consistent. We used lower or role-specific temperatures in settings where the agent role required more controlled behavior. In FinQA, tool and role agents used temperatures be-tween 0.4 and 0.6: normal tool agents generally used 0.5, evidence and calculator agents used 0.4, and skeptic agents used 0.6. In MBPP and Live-CodeAgent homogeneous setups, temperatures var-ied by role, typically from 0.3 to 0.8; writer agents used higher temperatures around 0.7–0.8, while reviewers, editors, and finalizers used lower tem-peratures around 0.3–0.5. Moderators and supervi-sors were run more deterministically, generally at temperature 0.0 or 0.2. Taxonomy benchmark and judge-style classification scripts used temperature 0.0. Most non-code tasks used a round-based debate protocol with at most five rounds. In round one, agents answered independently with a final answer and confidence; in later rounds, they saw other agents’ previous answers, confidence scores, and explanations before revising. Standard debates ended at consensus or the round limit; if no con-sensus was reached, a non-intervening moderator selected the final answer using only agents’ final answers and explanations. In hierarchical runs, a supervisor actively reviewed responses, asked clarifying or follow-up questions, provided guid-ance, and made the final decision when needed. We varied interaction design across question-only, tool-enabled, role-based, hierarchical, and homo-geneous code settings, typically with 3, 5, or 7 agents. Role-based runs included agents such as EvidenceReader, Skeptic, Verifier, Synthesizer, Re-triever, Comparator, Deontologist, and Consequen-tialist. Dataset-specific pipelines preserved task con-straints: FinQA allowed calculator calls through explicit CALC: lines; HotpotQA and MuSiQue included evidence/context variants; MedQA used textbook retrieval and option-letter evaluation; MMLU/MMLU-Pro outputs were normalized to one choice letter; Ethics outputs to binary labels; and MBPP/LiveCodeBench used multi-round code generation while hidden tests, errors, and gold code remained unseen until final evaluation. For each run, we logged the prompt, gold answer, final an-swer, correctness, rounds to consensus, moderator or supervisor actions, and each agent’s per-round answer, confidence, reasoning, and raw response. 

Hardware Infrastructure and Cost. ARC-hosted open-weight model evaluations were con-ducted on a GPU cluster with NVIDIA A100 80GB GPUs. Smaller models were run on single GPUs, while larger models required 2–4 GPUs with ten-sor parallelism. Additional open-weight debate-generation runs were served through DeepInfra end-points, which cost approximately $25 in observed billing. Because provider-side billing did not ex-pose uniform token accounting for every model and run, we estimate token usage from logged prompts, responses, number of agents, and num-ber of rounds. The full trajectory-generation stage used approximately 25–35M input tokens and 8– 12M output tokens. The taxonomy-construction stage was more input-heavy: each failed multi-round trace was converted into trajectory cards and then processed through candidate-tag extrac-tion, taxonomy mapping, unmapped-label cluster-ing, width/depth expansion, and cleanup. Across the 3,211 taxonomy traces, this required approxi-mately 25–37M additional input tokens and 6–10M output tokens through OpenAI endpoints. Overall, the full experimental and taxonomy-construction pipeline cost approximately $38–50 in API infer-ence, with most of the direct API cost coming from multi-agent debate generation. E Trigger Model Details 

Data. The trigger set contains 304 debates from eight datasets: 152 question-matched pairs, each with one correct and one incorrect debate on the same question, and 19 pairs per dataset. We prefer debates with at least three rounds; 8 debates have two rounds. Correctness is used only to build the balanced sample and is never shown to the annota-tor or the models. 

Labels. Each debate is annotated once by an outcome-blind LLM annotator ( gpt-6-luna ) for three labels. The annotator sees each agent’s per-round responses, without reference answers, cor-rectness, or duplicated extracted-answer fields. For each label it returns present, absent, or uncertain, and for each occurrence the round, the agents in-volved, and verbatim evidence quotes, which are validated against the transcript. Premature consen-sus uses the taxonomy definition with explicit mini-mum conditions. The taxonomy definition of failed recovery after disagreement refers to the correct final answer, so we use an outcome-blind version: a visible disagreement is never adjudicated on sub-stance, and the debate either ends split or is settled by majority, vote, confidence, authority, or one side going quiet. Couldn’t recover after unknown re-quires an abstention before the last round, followed by a later round in which the agent abstains again or copies another answer without engaging its evi-dence. The onset is the earliest occurrence round. Uncertain labels are excluded for that error. La-beled prevalence is 134/304 (premature consensus), 136/303 (failed recovery), and 92/299 (unknown recovery), split nearly evenly between correct and incorrect debates. To estimate label consistency, premature consensus was annotated in two inde-pendent runs with near-identical definitions: they agree on 81.2% of debates ( κ = 0 .62 ), and on the onset round in 80.6% of debates both runs mark present. 

Prediction task. A row is the state of a debate after round t, for every t before the last round and before the error’s onset. Its label is 1 if the onset is round t+1 and 0 otherwise; debates without the error contribute only negative rows. This gives 767, 705, and 816 rows for the three labels. 

Features. The model uses 40 features: the round index plus answer-dynamics features computed from each agent’s extracted answer and stated con-fidence in rounds 1..t . Split shape: number of answering agents, distinct answers, majority share, margin over the runner-up, normalized entropy, mi-nority size, lone dissenter, near tie, and unanim-ity. Change since round t−1: number and fraction of agents that changed; agents that moved to the current or previous majority, left the majority, or moved to a new answer; majority change; whether the group just became unanimous; and the change in distinct answers, majority share, and entropy. History: flip-backs ( A→B→A) this round and in total, total changes, agents that ever changed, the maximum changes by one agent, agents still holding their round-1 answer, majority changes, answers seen, new answers this round, unanim-ity streak, and rounds spent split. Confidence: whether confidences are reported, and their mean, minimum, standard deviation, change, the majority– minority gap, the mean confidence of agents who changed, and the count below 80%. The model uses no message text and no dataset identity. Model and evaluation. We use 

RandomForestClassifier with 300 trees, minimum leaf size 5, max_features="sqrt" , and balanced class weights. L Taxonomy Saturation 

We analyze how quickly the taxonomy is recov-ered as more failed traces are sampled, treating each unique_identifier as one trace. The full taxonomy contains 6 parent categories, 11 child categories, and 26 mapped leaf labels across 3,211 failed trajectories. For each sample size, we run 10 random trials, except for the full 3,211-trace setting, which is deterministic. Figure 11 shows that the high-level taxonomy saturates quickly. With only 50 sampled traces, we recover all parent and child categories. Fine-grained leaves saturate more slowly: 50 traces re-cover 80.8% of leaves, 200 traces recover 91.9%, and 500 traces recover 95.4%. Near-complete leaf coverage requires much larger samples, with 2,000 traces recovering 99.2% and the full dataset recov-ering all 26 leaves. This pattern suggests that the broad structure of multi-agent failure is relatively stable, while rare fine-grained labels require substantially more data. The slowest labels to recover are extremely rare, including sycophancy, dogmatic disagreement or refusal to revise, tool/evidence output misread, poor information sharing, and false equivalence between distinct answers. Thus, small samples are sufficient for a usable parent/child taxonomy, but large-scale annotation is needed to capture rare leaf-level failure modes. 

M Self-Reported Confidence Dynamics 

Following prior work on verbalized or self-reported confidence in language models (Lin et al., 2022; Tian et al., 2023; Yona et al., 2024), we analyze the confidence scores agents report during delibera-tion. We ask whether confidence tracks correctness, or whether deliberation itself increases confidence even when the group is wrong. Table 15 shows that confidence increases over deliberation, but not in a way that cleanly tracks correctness. Confidence rises for both correct and incorrect traces, with a larger increase for incorrect traces (+10.49) than correct traces (+5.54). This suggests that debate can amplify commitment to an answer even when the final answer is wrong, rather than simply reflecting progress toward the truth. Answer changes are also confidence-amplifying. After an agent flips its answer, confidence increases in both finally correct and finally incorrect traces. The larger increase in correct traces suggests that some flips correspond to productive correction, but the positive increase for incorrect traces shows that agents can also become more confident after mov-ing toward a wrong answer. Finally, correct traces end with higher confidence than incorrect traces, but the gap is modest: incorrect traces still end near 90% confidence. Thus, we show that LLMs are not good at determining their confidence and hence should not be used for self-calibration.

Trace Prompt 1: Question Only Initial Answer 

System prompt. You are a dataset-specific debate agent answering from the question text alone. Use careful reasoning, but do not invent unsupported de-tails. Keep the response concise. 

User prompt. Answer the given question with the shortest answer span you can support. Do not use external context. You may write brief reasoning first if needed. End with two final lines: one line giving the final answer only, and one line giving confidence as a number from 0 to 100. If unsure, still choose the best short answer span. 

Trace Prompt 2: Shared Context or Tool Access Initial Answer 

System prompt. You are a dataset-specific debate agent with access to supporting context or tool output. Use the provided evidence carefully and answer with the shortest correct answer span. Keep the response concise. 

User prompt. Answer the given question using the supplied context or tool output as evidence. You may write brief reasoning first if needed. End with two final lines: one line giving the final answer only, and one line giving confidence as a number from 0 to 100. Do not add explanation after the final answer. 

Trace Prompt 3: Role Based Debate Setup 

System prompt. Each agent receives a role. The evi-dence reader can use supporting context and should extract the exact answer span. The skeptic challenges weak reasoning and searches for inconsistencies. The verifier checks whether proposed answers fit the ques-tion and debate history. The synthesizer combines the debate into one concise answer. 

User prompt. Answer the question according to your assigned role. If you have context access, use the supporting context. If you do not have context access, rely on your role and the debate history. End with the final answer only and a confidence score from 0 to 100. 

Trace Prompt 4: Follow Up Debate Round
