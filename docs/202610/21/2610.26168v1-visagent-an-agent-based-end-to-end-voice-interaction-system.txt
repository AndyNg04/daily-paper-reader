Abstract 

Voice-based public services have evolved from manual switchboards to intelligent platforms to meet modern user needs. However, cur-rent systems remain constrained by rigid menu-driven interaction, fragmented vertical services, and limited extensibility. To address these is-sues, we present VISAGENT, an agent-based end-to-end voice interaction system for large-scale public services that integrates end-to-end speech interaction, hierarchical agent rout-ing, a scalable voice-agent marketplace, and user memory support. The system replaces menu-driven workflows with natural speech and dynamically dispatches user requests to either a general conversational model or spe-cialized domain agents via a two-level routing paradigm that achieves sub-second intent-to-agent selection over hundreds of agents. User memory informs preference-aware agent se-lection and supplies relevant preferences and context to selected agents, supporting person-alized task execution and reducing the need for users to repeat previously provided infor-mation. A voice-agent registration mechanism converts task agents into conversational entities, enabling dynamic onboarding and ecosystem-level extensibility. We validate VISAGENT through a real-world deployment in China’s 114 hotline across multiple service domains. Experimental results demonstrate low-latency full-duplex interaction, robust routing scalabil-ity, and competitive speech naturalness. More broadly, this work advocates a shift from iso-lated voice assistants toward agent-centric con-versational infrastructures, providing a general blueprint for building extensible voice-agent systems in public services and beyond. 

1 Introduction 

Public-service hotlines provide a common entry point for users seeking information and assistance across everyday service domains. In settings such as China’s 114 hotline, users may need help with transportation, accommodation, healthcare, or local services without navigating separate applications. Telephone access is particularly useful when a spo-ken exchange is more convenient than a graphical interface. However, a single access number does not by itself unify the services behind it. Menu nav-igation, repeated transfers, and separate business systems can still require users to understand how services are organized before reaching the appro-priate provider. Speech interaction models and language-model-based agents provide building blocks for a different arrangement. A conversational model can handle open-ended requests, while a domain agent can expose the tools and business processes needed to complete a particular service. Combining them re-quires a framework that determines when conversa-tion is sufficient, identifies the appropriate service domain, and selects an agent from the available providers. The framework must also carry informa-tion across the handoff so that the selected agent can continue the interaction rather than asking the user to start again. VISAGENT combines end-to-end speech inter-action with hierarchical routing to provide con-versational access to public services. The speech interaction model supports low-latency, full-duplex spoken communication and directly handles gen-eral conversation and question answering. Alightweight first-level router directs requests either to this conversational model or to an appropriate service domain. For domain-specific requests, an LLM-based second-level selector identifies a suit-able agent by matching the user’s requirements against the capabilities of agents registered within that domain. This organization connects general conversational assistance with specialized service access through a unified voice interface. An extensible voice-agent marketplace and shared support services provide the basis for in-tegrating heterogeneous agents into this architec-ture. Through a common registration mechanism, providers specify agent descriptions and callable interfaces, making their services available for dis-covery and invocation. Configurable voices enable agents with text-based business interfaces to deliver 1arXiv:2610.26168v1 [cs.CL] 19 Oct 2026 spoken responses suited to their roles and service contexts. A shared user memory service supplies relevant preferences and recent interaction context to both the second-level selector and the selected agent, supporting agent selection and subsequent task execution. Individual agents remain respon-sible for collecting task-specific information and carrying out their own business operations. The deployment of VISAGENT in China’s 114 hotline illustrates a transition from menu-driven service access to intent-driven conversational in-teraction, as shown in Figure 1. Traditional 114 services require callers to follow recorded prompts and navigate keypad menus before being connected to human operators. VISAGENT enables callers to express their requests directly in natural language, which are then routed to domain-specific agents for service execution or to the end-to-end conversa-tional model for general inquiries. This transition preserves the telephone-based access channel while replacing predefined menu navigation with conver-sational access to services. The principal contribution of this work is an agent-centric conversational service architecture that reframes public-service hotlines from menu-driven access channels into extensible voice-agent infrastructures. By establishing a unified frame-work for conversational access, service discovery, agent integration, and shared user context, VIS-AGENT provides an architectural blueprint for in-tegrating heterogeneous service agents into a com-mon voice-based public-service infrastructure. The remainder of this report is organized as follows. Section 2 reviews the research relevant to the de-sign of VISAGENT. Sections 3 and 4 present the overall architecture and its implementation, respec-tively. Section 5 evaluates the speech interaction and routing infrastructure. Section 6 discusses the scope, limitations, and future development of the system, and Section 7 concludes the report. Illus-trative examples are provided in Appendix A. 

2 Related Work 

2.1 End-to-End Speech Interaction 

Conventional voice-based service systems typically adopt a cascaded architecture in which automatic speech recognition, language understanding, di-alogue management, and text-to-speech synthe-sis are implemented as separate components. Al-though such pipelines provide modularity and fa-cilitate component-level optimization, errors intro-duced at an early stage may propagate through the remaining modules, while the sequential execu-tion of multiple components can increase response latency and disrupt conversational continuity. Re-cent speech-language models have sought to reduce these limitations by incorporating speech percep-tion, language reasoning, and speech generation within more closely integrated architectures. This development has enabled spoken dialogue systems to process acoustic input directly, generate spoken responses incrementally, and preserve information that may be lost when speech is reduced to text alone. Representative systems illustrate several direc-tions in this line of research. SpeechGPT connects a large language model with discrete speech repre-sentations to support cross-modal instruction fol-lowing and spoken interaction (Zhang et al., 2023). Mini-Omni further investigates real-time speech generation in a compact multimodal language model (Xie and Wu, 2024), while Moshi introduces a full-duplex spoken dialogue framework capable of processing and generating speech streams con-currently (Défossez et al., 2024). MinMo extends these capabilities through a multimodal architec-ture designed for seamless voice interaction (Chen et al., 2025). Collectively, these studies demon-strate substantial progress in speech understanding, streaming response generation, interruption han-dling, and conversational naturalness. Their pri-mary emphasis, however, remains on the capabili-ties and evaluation of the conversational model it-self. The integration of such models with large col-lections of independently developed service agents introduces additional architectural requirements, including intent-based dispatch, service discovery, interaction handoff, and the preservation of conver-sational context across system components. Neural speech synthesis constitutes another im-portant component of voice-based interaction. Au-toregressive and flow-based synthesis models have improved speech intelligibility, prosody, speaker similarity, and streaming generation. CosyVoice 2, for example, combines language-model-based se-mantic representation with conditional flow match-ing to support scalable speech synthesis and voice generation (Du et al., 2024), while HiFi-GAN pro-vides an efficient neural vocoder for reconstructing high-fidelity waveforms from acoustic representa-tions (Kong et al., 2020). These methods also make it possible to associate service agents with prede-fined or customized voices. 2.2 LLM-Based Agents and Service Routing 

The emergence of large language models has sub-stantially expanded the capabilities of intelligent agents. Earlier task-oriented agents were gener-ally constructed around predefined rules, domain-specific policies, or fixed action spaces. LLM-based agents can instead interpret open-ended in-structions, formulate intermediate decisions, in-voke external tools, and adapt their behavior ac-cording to execution feedback. ReAct established an influential formulation in which language-model reasoning is interleaved with actions and observa-tions (Yao et al., 2022). Subsequent research has examined tool learning, planning, and task decom-position as fundamental capabilities for agents op-erating in external environments (Qin et al., 2024; Huang et al., 2024; Liu et al., 2024). Surveys of LLM-based autonomous agents further character-ize the growing range of architectures for reason-ing, memory, action, and environmental interaction (Wang et al., 2024). Research on multi-agent systems extends this perspective by assigning distinct roles or capabil-ities to multiple agents. Frameworks such as Au-toGen coordinate interactions among specialized 3agents through structured conversational exchanges (Wu et al., 2024). Such systems commonly focus on collaboration among agents assembled for a par-ticular task, including planning, execution, verifica-tion, and refinement. A service platform presents a related but distinct problem. Its agents may be developed and operated by independent providers, expose heterogeneous interfaces, and offer partially overlapping capabilities. The platform must there-fore determine which agent should receive a re-quest before the selected agent begins its own task-specific reasoning and execution. Agent selection in this setting functions as a service-discovery prob-lem rather than as an internal step of a fixed multi-agent workflow. 

2.3 Long-Term Memory and Personalized Service Support 

Persistent memory has become an important re-search topic in language-model-based agents be-cause a finite dialogue context cannot represent a user’s complete interaction history. Generative Agents demonstrated how stored experiences, re-trieval, and reflection can support temporally co-herent behavior (Park et al., 2023). MemGPT pro-posed a hierarchical memory-management architec-ture that coordinates information inside and outside the immediate context window (Packer et al., 2023). MemoryBank further investigated the retention and retrieval of long-term conversational information for personalized interaction (Zhong et al., 2024). These studies establish that agent memory involves more than retaining raw dialogue transcripts: useful memory systems must determine what information should be preserved, how it should be represented, and when it should be retrieved. Related issues have also been studied in task-oriented dialogue. MultiWOZ provides a multi-domain benchmark for dialogue-state tracking and task completion across several service domains (Budzianowski et al., 2018), while SOLOIST inves-tigates the construction of task-oriented dialogue systems through transfer learning and machine teaching (Peng et al., 2021). Such work has ad-vanced the representation of user goals, dialogue context, database constraints, and task states. Most task-oriented dialogue systems, however, operate within a predefined ontology and a relatively fixed set of service backends. Their dialogue state pri-marily represents information required for the cur-rent task or session, whereas a service platform must additionally preserve reusable preferences across interactions and make them available to in-dependently implemented agents. Taken together, existing studies primarily address either general-purpose long-term agent memory or dialogue state within predefined service ontologies, whereas VIS-AGENT employs compact user memory as shared contextual support for agent selection and subse-quent task execution across heterogeneous service agents. 

3 System Overview 

Figure 2 presents the overall architecture of VIS-AGENT. The user interaction layer provides a uni-fied speech-to-speech interface through an end-to-end speech interaction model, supporting low-latency streaming dialogue, full-duplex commu-nication, and user barge-in. Beneath this inter-face, the hierarchical routing layer separates coarse intent routing from fine-grained agent selection. A lightweight Level-1 router assigns a service re-quest to a domain or retains it in the conversational path, after which an LLM-based Level-2 selector identifies an appropriate agent within the selected domain. The voice-agent marketplace organizes agents developed by the platform and third-party providers and exposes them to the routing layer through a common registration interface. Two sup-porting modules extend these core layers. The user memory service maintains explicit preferences, be-havioral preferences, and recent interaction context for use by the selector and the selected agent, while the voice-agent registration mechanism supplies the descriptions, callable interfaces, and voice con-figuration required to convert task agents into con-versational agents and incorporate them into the marketplace. The updated mem-ory becomes available to subsequent routing and service execution, completing the interaction loop between speech input, routing, agent execution, feedback, and long-term personalization. 

4 System Components 

4.1 End-to-End Speech Interaction Model 

The speech interaction component provides the common voice interface through which users ac-cess both general conversation and domain-specific services. As shown in Figure 4, it consists of an au-dio encoder, an input adapter, an LLM, a streaming audio decoder, and a vocoder. The audio encoder extracts acoustic representations from incoming speech, and the adapter maps them into the repre-sentation space consumed by the LLM. The hidden representations generated by the LLM condition the streaming audio decoder, which produces dis-crete acoustic features incrementally. The vocoder subsequently reconstructs these features as an out-put waveform. In parallel with the speech-to-speech path, an auxiliary connectionist temporal classification (CTC) decoder generates intermediate transcrip-tions from the encoded speech representations. These transcriptions provide textual inputs for both hierarchical routing and downstream agent interac-tion. The routing layer uses the transcribed request together with the available dialogue context to de-termine an appropriate processing path, while a selected service agent receives the corresponding text and context for task-oriented interaction. VIS-AGENT therefore employs direct speech-to-speech generation at the user-facing interface while expos-ing a textual integration interface to independently implemented routing and agent components. 

Training configuration. The three-phase train-ing procedure is illustrated in Figure 5. In the first phase, the input adapter is optimized while the remaining model components are frozen, align-ing the acoustic representations produced by the audio encoder with the LLM input space. In the second phase, the audio decoder is trained while the audio encoder, input adapter, and LLM remain frozen. This phase maps the hidden representations of the LLM to discrete acoustic features and incor-porates streaming generation into decoder training. In the final phase, the input adapter, LLM, and au-dio decoder are jointly fine-tuned while the audio encoder remains frozen, allowing the speech input, language processing, and speech output compo-nents to be adapted jointly. The training corpus comprises approximately 64,000 hours of open-source Mandarin speech, 10,000 hours of open-source English speech, and 1,000 hours of private Chinese speech. 

Full-duplex interaction. The implementation processes incoming speech concurrently with re-sponse generation and employs endpoint echo can-cellation to support full-duplex interaction and user interruption. Users can therefore supplement, cor-rect, or redirect an utterance while a response is being generated. Voice activity detection (VAD) identifies utterance boundaries before the resulting transcription and dialogue context are passed to the routing layer. Section 5.2 reports the observed interaction latency, including the VAD interval, sep-arately from model-level latency estimates. 

4.2 Two-Level Agent Routing 

The hierarchical routing layer implements coarse-to-fine request dispatch over the voice-agent mar-ketplace. Directly comparing every request with all registered agents would cause the selector’s input context and inference cost to grow with the size of the marketplace. VISAGENT therefore sepa-rates routing into two decisions: a lightweight first-level router determines whether the request should remain on the conversational path or enter a sup-ported service domain, and an LLM-based second-level selector identifies a suitable agent only among the candidates registered in that domain. This sepa-ration reduces the candidate space presented to the LLM while distinguishing domain identification from fine-grained agent matching.

Everyday conversation, general question answer-ing, and other requests that do not require an exter-nal service agent remain with the speech interaction model, whereas service-oriented requests are as-signed to the corresponding domain. Level 2: memory-aware agent selection. Once a service domain has been identified, VISAGENT retrieves the descriptions of agents registered in that domain and the user-memory entries relevant to agent selection. The selection prompt combines the current request, pertinent dialogue context, domain-specific agent descriptions, capability and coverage constraints, and applicable user preferences. The LLM-based selector then identifies an agent whose registered capabilities satisfy the current request. User memory serves as supplementary selection context and does not override an explicit current requirement or compensate for an agent whose ca-pabilities are incompatible with the requested ser-vice. 

4.3 Voice Agent Marketplace and Registration 

The voice-agent marketplace maintains a catalog of service agents organized by domain. Agents may be operated by the VISAGENT platform or by third-party providers, and multiple agents may of-fer overlapping services while differing in provider, geographic coverage, supported operations, and other service characteristics. The marketplace ex-poses their registered metadata to the routing layer without requiring access to their internal business logic, thereby separating platform-level service dis-covery from provider-specific task execution. 

Registration information. Each registration record specifies the agent’s identity and provider, service domain, natural-language description, ca-pabilities, service tags, coverage regions, endpoint, and function specifications. Voice configuration and presentation. During registration, a provider can associate an agent with either a preset synthesis voice or a customized voice generated from a short reference recording. The current implementation provides more than 40 preset voice styles, along with speech synthe-sis and voice cloning services. A text-based agent can therefore receive transcribed user input and re-turn textual responses, which VISAGENT renders through the configured voice without requiring the provider to implement a separate speech interface. Voice profiles can be selected according to an agent’s role and service context. For example, a legal-consultation agent may use a formal and se-rious voice, whereas an agent providing psycho-logical counseling or emotional support may adopt a calm, gentle, and reassuring voice. Associating a stable voice profile with each agent helps users distinguish among services, improves the contex-tual appropriateness of spoken responses, and gives heterogeneous agents recognizable and consistent identities within the shared voice interface.

Representation and updates. VISAGENT orga-nizes user memory into three complementary types. Explicit preference memory records preferences that users state as generally applicable, such as a preferred service provider. Behavioral preference memory captures recurring choices inferred from multiple interactions. Context memory retains re-cent or task-specific information, such as an active booking, a current travel plan, or the parameters of a recent service request. This separation pre-vents persistent preferences, recurring behavioral patterns, and temporary task context from being treated as equivalent information. After an interaction is completed, VISAGENT constructs a compact execution summary contain-ing the service domain, selected agent, task, in-voked services, request constraints, execution de-tails, and outcome. The summary provides the ba-sis for updating the corresponding memory records without retaining the complete dialogue transcript as long-term memory. Retrieval and delivery. After the first-level router identifies a service domain, the memory ser-vice retrieves records relevant to the current do-main and request. Structured retrieval is used for explicit and behavioral preferences, while semantic retrieval identifies related information from recent context. For each request, the memory service re-trieves only the preferences, agent-use history, and recent task context relevant to the identified domain and current user need. The second-level selector and the selected agent therefore receive a compact, task-relevant memory subset rather than the user’s complete interaction history. 

5 Evaluation 

This section evaluates the principal components of VISAGENT, including speech interaction perfor-mance, interaction latency, speech synthesis qual-ity, and the accuracy and scalability of hierarchical agent routing. 

5.1 Speech Interaction Performance 

We evaluate the speech interaction model on spoken dialogue tasks that assess speech under-standing, reasoning, and oral response generation, and compare its performance with representative speech-enabled models. The evaluation uses URO-Bench, a speech-to-speech benchmark organized into basic and pro tracks, each containing 20 test sets at different levels of difficulty (Yan et al., 2025). We report results on 16 open-source Chinese test sets, including nine from the basic track and seven from the pro track. Table 2 compares the 14B speech interaction model used in VISAGENT with MiMo-Audio, Step-Audio-mini, and Qwen3-Omni (Team et al., 2025; Wu et al., 2025; Xu et al., 2025). As shown in Table 2, the VISAGENT speech in-teraction model achieves subset averages of 71.547 and 66.510 on the basic and pro tracks, respec-tively, exceeding the strongest comparison result in each subset by 0.601 and 6.379 points. Across the 16 individual test sets, it achieves first place on 4 datasets and second place on 8 datasets, underscor-ing its superior capabilities in advanced reasoning, safety, and open-domain conversational response generation. These results indicate that the VIS-AGENT speech interaction model remains strong and balanced performance across diverse spoken dialogue tasks.

The routing evaluation uses 100 user queries and marketplace sizes of 50, 100, and 319 agents. The largest marketplace spans 15 domains, including shopping, education, psychology, law, home ser-vices, medicine, travel, government affairs, finance, culture, pets, dining, tourism, sports, and other services. Each agent is represented by a concise functional description. The single-level baseline supplies the complete uncategorized agent pool to an LLM. The two-level configuration first uses a lightweight classifier to identify the service domain and then supplies only the agents in that domain to an LLM-based selector. DeepSeek V3, Qwen3, and Kimi K2 are evaluated as selectors under both routing configurations. Table 5 shows that all configurations achieve 100% accuracy with latency below one second when the marketplace contains 50 agents. When the marketplace grows to 319 agents, single-level routing requires 8–10 seconds and achieves 98– 99% accuracy. In comparison, the two-level con-figuration maintains latency below one second and achieves 100% accuracy on the evaluated query set. These results highlight the scalability and efficiency advantages of the hierarchical routing architecture for agent selection in an expanding marketplace. 

6 Discussion, Limitations, and Future Work 

System boundaries. VISAGENT provides an in-tegrated system framework for connecting users with heterogeneous service agents through a uni-fied voice interface. It centralizes voice interaction, service discovery, routing, and memory delivery while leaving business execution with the selected provider. This separation supports extensibility, but the platform’s ability to identify a suitable agent does not guarantee that the agent can complete ev-ery request. Completion also depends on available resources, tool behavior, service policies, and the agent’s handling of dialogue and user context. An execution failure may return to routing, but redis-patch cannot by itself remove a business constraint such as unavailable inventory. 

Evaluation limitations. The routing evaluation is based on 100 user queries and marketplace con-figurations containing up to 319 agents, which lim-its the assessment of routing performance at larger scales. Future evaluations will expand both the query set and the agent pool as the marketplace grows. Practical latency is measured at the system level using commercial systems whose underlying hardware configurations cannot be controlled or standardized. The resulting measurements there-fore characterize the end-to-end latency of the eval-uated systems under the test conditions rather than the intrinsic latency of their speech models. The memory service has not yet been evaluated because the available interaction data remain limited. Its observed effectiveness also depends on how indi-vidual agents interpret and apply the retrieved user context, making it difficult to isolate the contribu-tion of the memory service from downstream agent behavior. Future evaluation will therefore assess memory retrieval and memory-assisted agent se-lection separately from preference application and task execution, with standardized agent implemen-tations used to control agent-specific variation. 

Directions for future work. Future work will ex-tend VISAGENT in two directions: cross-service continuation and adaptive replanning. Cross-service continuation will enable the framework to identify relationships between successive service goals, preserve task-relevant context across agent boundaries, and dispatch follow-up requests with-out requiring users to repeat information that has al-ready been collected. This capability is particularly relevant to compound service scenarios, such as requesting hotel accommodation after completing a flight reservation. Adaptive replanning will allow the framework to revise an ongoing service plan when execution fails, resource conditions change, or the user modifies the original requirements. The system could then identify feasible alternatives, re-construct the required sequence of agent calls, and obtain user confirmation before continuing execu-tion. Future research will investigate the context-transfer mechanisms, plan-validation methods, and recovery policies required to implement and evalu-ate these capabilities reliably.
