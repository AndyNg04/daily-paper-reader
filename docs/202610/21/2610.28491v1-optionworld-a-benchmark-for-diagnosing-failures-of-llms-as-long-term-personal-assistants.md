## 摘要
长期助理必须跨越数日跟进尚未完成的任务，同时应对信息和情境的变化。然而，找到信息或启动行动，并不意味着任务最终会完成。我们推出 OptionWorld 基准，通过追踪模拟日常生活任务中的信息获取、判断、行动和结果，识别当前大语言模型作为长期个人助理时的不足。在保留决策输入记录的运行中，35.5% 的失败实例在截止时间前，模型的最后一次输入中仍包含关键事实。失败分析发现了三个最常见的问题：未能获取或整合所需信息、未利用可行的行动机会，以及擅自施加任务本身并未要求的限制。三项后续实验表明：补充缺失事实可在某些情况下恢复任务成功；行动提醒能够促使工作重新启动，但后续步骤仍可能错过截止时间；纠正一条错误禁止联系的已提供备注，则可恢复原本允许的询问。这些发现揭示了任务状态维护方面的不足：未能将事实与未完成的工作联系起来、未能在截止时间前贯彻执行，以及未能区分实际限制与智能体自身的假设。

## Abstract
Long-term assistants must follow unfinished tasks across days as information and circumstances change. Finding information or starting an action, however, does not ensure that the task gets completed. We introduce OptionWorld, a benchmark that traces information acquisition, judgments, actions, and outcomes in simulated daily-life tasks to identify where current LLMs fall short as long-term personal assistants. In runs with archived decision inputs, the key facts remain in the model's last input before the deadline in 35.5% of failed instances. Failure analysis identifies the three most frequent problems: needed information is not obtained or combined, available opportunities to act go unused, and agents impose restrictions that the task does not require. Three follow-up experiments show that supplying missing facts restores task success in some cases; action reminders can restart work while subsequent steps still miss the deadline; and correcting a supplied note that wrongly forbids contact restores permitted inquiry. These findings locate shortcomings in maintaining task state: connecting facts to unfinished work, following through before deadlines, and separating actual restrictions from the agent's assumptions.

# OptionWorld 论文总结

## 1. 核心问题与研究背景

### 1.1 研究问题：长期助理为何“知道了，却没有做完”？

长期个人助理需要跨天处理保险、住房、工作、医疗及家庭协调等事务。与单轮问答或明确指令执行不同，这类任务要求助理：

- 从日常事件和记录中主动发现问题，而不是等待用户提供任务清单。
- 将不同来源、不同日期的信息关联起来。
- 持续跟踪授权、截止日期、延迟回复和暂时性障碍。
- 在条件变化后恢复行动，并确认用户的选择得到保留或问题得到解决。

论文强调：**获取信息、识别风险、提交请求，都不能直接等同于完成任务。**例如，发现银行扣款记录与保险缴费记录冲突之后，助理还必须询问相关机构、取得必要授权，并在截止日前完成保护性操作。

### 1.2 整体含义

现有基准分别关注任务执行、长期记忆或主动帮助，但仅有最终成功率或阶段分数，往往不能解释任务为何停滞。

OptionWorld 的目标不是提出一种新的智能体算法，而是建立一个**面向长期任务的诊断基准**，把每个目标的证据、判断、行动和结果连接起来，区分：

- 必要信息是否没有获取；
- 信息是否获取过、但决策时已经不再可见；
- 信息仍然可见，却未触发有效行动；
- 行动虽然被接受，却没有带来真正的任务结果。

其核心观点是：长期助理的瓶颈不仅在记忆容量，还在于**维护可更新、可执行的任务状态**。

## 2. 方法论：从证据到结果的目标级诊断

### 2.1 核心思想

OptionWorld 构造具有持续事件流的模拟生活环境，让智能体在不知道隐藏评测目标的情况下承担广泛助理职责。

对每个目标，系统关联以下链条：

> 获取证据 → 识别问题 → 形成有依据的判断 → 在有效期内判断 → 实施合规干预 → 获得结果确认

这种设计可以区分“读到了”“理解了”“行动了”和“真正完成了”。

### 2.2 环境与交互机制

- 每个世界持续 **60 个模拟日**，包含多个并行事务。
- 每日输入包含事件、可用记录目录、保存的记忆、监控条件、反馈和剩余预算。
- 工具支持读取来源、检查或比较记录、查找办理流程、保存记忆、登记监控条件、联系相关方、请求授权及执行操作。
- 权限规则区分：
  - 允许进行的询问；
  - 需要用户确认的偏好性或不可逆承诺；
  - 真正禁止联系或操作的情况。
- 回复可以延迟到达，也可能只是部分解决，要求智能体继续跟进。

五个 API 系统采用相同运行器：**每天开启新对话，跨天依靠记忆、监控条件和反馈保持状态**；已经读取的记录可以重新调取。Astra 使用独立的本地 Codex 执行框架。

### 2.3 六项评价指标

每个目标、每次运行分别获得六个二元分数：

| 指标 | 含义 | 主要区分 |
|---|---|---|
| **O：来源访问** | 访问过指定相关来源或记录 | 访问来源不代表拿到全部关键事实 |
| **H：风险假设** | 识别出该目标的具体问题或风险 | 阅读不代表理解 |
| **G：有依据的发现** | 判断得到此前已获取证据的支持 | 猜对问题不等于证据充分 |
| **T：及时发现** | 在目标响应期内形成有依据的判断 | 正确但过晚仍可能失败 |
| **I：干预送达** | 符合证据、权限和时限要求的外部行动被接受 | 提交成功不代表问题解决 |
| **Y：模拟结果成功** | 反馈确认保留了用户选项或解决了问题 | 以结果而非行动启动为准 |

评分依赖满足：

\[
H \geq G \geq T \geq I \geq Y
\]

这是评分条件的依赖关系，不要求行动严格按照这一顺序发生；**O 不属于该单调链条**，因为公开事件也可能支持风险识别。

主指标为**选项保留率 OPR**：

\[
\mathrm{OPR}=\frac{1}{K}\sum_{r=1}^{K}Y_r
\]

其中，\(K\) 是目标实例总数。“成功”既可以是最终解决问题，也可以是在截止日前保留用户原本会失去的选择。

### 2.4 关键事实可见性与失败归因

论文进一步检查：

1. 截止日前是否获得全部指定关键事实；
2. 截止日前最后一次有效决策输入是否仍包含这些事实及对应事项标识；
3. 若仍失败，轨迹中能否确定具体障碍。

失败分析为每个实例指定一个主要问题，包括信息缺口、行动选择或调整失败、自加限制、状态更新错误、执行错误；无法确定的保留为“证据不足”，避免强行归因。

### 2.5 评分与复核

- 两个独立、隐藏被测系统身份的 LLM 审阅上下文检查轨迹。
- 程序检查证据先后顺序、截止日期、权限、接受回执和结果反馈。
- 人工审阅覆盖全部主实验轨迹，并复核失败分类。
- 未解决的争议保留不确定性标记，主结果只计算确认成功，并另外报告敏感性分析。

- 被裁员的中年劳动者；

- 社区食品经营者；

## 5. 实验数量、充分性与公平性

### 5.1 主实验具有一定覆盖和重复性

144 条长程轨迹覆盖多领域、多任务结构，并对相同目标重复三次，能够观察：

- 哪些任务稳定失败；
- 哪些成功不稳定；
- 不同系统是在信息获取、判断还是行动阶段出现瓶颈。

配对分析也比单纯比较平均成功率更有解释力：论文比较了双方均已及时获取事实或形成有依据判断的相同实例，降低发现能力差异对后续行动比较的干扰。

### 5.2 公平性与客观性的保障

- 五个 API 系统共享提示词、工具模式和环境预算。
- 审阅时隐藏系统身份。
- 结合程序检查、双重语义审阅和人工复核。
- 将真实配额或权限限制与模型错误区分开。
- 保留不确定结果，并报告不同处理方式下的结论变化。
- 对世界选择进行重采样及逐一移除分析。

### 5.3 仍然不足的部分

- **信息和行动干预样本很小**：仅 3 个和 2 个检查点，每条件重复 3 次；信息实验中的两个检查点还是同一目标。
- 检查点属于有目的筛选，不支持推断所有失败任务的平均恢复率。
- 权限实验虽然有 720 个窗口，但主要是六个状态的重复测试，不能等同于 720 个不同长期任务。
- Astra 的运行框架不同，构成重要混杂因素。
- 主实验未统一提供商随机种子，也没有跨框架的同模型对照。

**总体判断：主实验足以支持较具体的失败诊断，但对改进方法的普遍有效性，证据仍属于探索性。**

## 6. 主要结论与发现

### 6.1 所有系统都存在明显的长期完成缺口

| 系统 | 来源访问 O | 及时有依据发现 T | 干预送达 I | 成功率 OPR |
|---|---:|---:|---:|---:|
| DeepSeek | 96.5% | 78.1% | 57.1% | 48.3% ± 13.0% |
| Fable | 84.9% | 54.9% | 40.6% | 36.1% ± 5.2% |
| Gemini | 87.5% | 48.1% | 37.5% | 30.7% ± 6.6% |
| Grok | 86.8% | 50.2% | 28.0% | 23.6% ± 4.5% |
| Qwen | 81.4% | 54.3% | 40.8% | 35.8% ± 4.9% |
| Astra（Codex） | 85.1% | 77.8% | 68.6% | 61.6% ± 2.6% |

“±”表示三次运行的样本标准差，不是置信区间。即使最高分配置，也有超过三分之一的目标未获确认成功。

### 6.2 信息不足不能解释全部失败

- 全部 **2,096 个失败实例**中，**49.5%** 已在截止日前获取全部指定关键事实。
- 对保留决策输入的五个 API 系统第二、三轮：
  - 1,295 个失败中有 460 个，即 **35.5%**，在截止前最后一次输入仍包含全部关键事实；
  - 排除不确定评分后，该比例为 **33.7%**。

这表明问题不仅在“没找到”或“忘记了”，还包括**未将已有事实转化为后续行动**。不过，事实文本可见不等于模型已经正确理解，不能据此完全排除信息整合问题。

### 6.3 三类主要失败

排除 160 个仅由正常约束导致的失败后，对 1,936 个实例分类：

- **信息缺口：30.2%**；
- **行动选择或调整失败：21.3%**；
- **自加限制：18.9%**；
- 状态或更新错误：6.4%；
- 执行错误：2.0%；
- 证据不足：21.3%。

这里的信息缺口包括未获取、未整合或未保留事实；各比例以包含“证据不足”的完整分类集为分母。

### 6.4 记忆可能延续错误，而非只保存知识

典型案例中，模型把一次请求被拒解释为“必须等待另一条记录”，将猜测保存为记忆，数日后仍以该记录未出现为由不再尝试。实际拒绝反馈并没有规定这一前提。

因此，长期记忆还需要记录结论的**来源、可信度和适用条件**，不能把模型推断自动升级为环境规则。

### 6.5 行动启动、程序完成与任务成功是不同层次

- Grok 有 50.2% 的目标形成及时、有依据判断，但只有 28.0% 获得合格干预。
- 偏好及多方协调任务仅占 API 目标实例的 **18.2%**，却占“干预合格但结果未成功”案例的 **60.6%**。
- 即使完成咨询、授权和操作，若错误地自行裁定冲突记录，也可能无法保留用户选项。

### 6.6 更多调用与稳定发现，不保证更多成功

- Qwen 比 Fable 多约 56% 的工具调用，成功数却基本相同。
- 全部失败实例中，**64.8%** 来自同一系统连续三次均失败的目标。
- 在发现过程稳定的任务中，后续行动仍可能不稳定。

### 6.7 干预可局部恢复进展，但不能夸大

- 补充事实在两个检查点将成功从 **0/3 提升至 3/3**，另一检查点主要仍为不确定结果。
- 行动提醒在两个案例各恢复 **1/3** 的及时干预，但一个案例后续执行过晚，最终仍失败。
- 当前状态呈现下，纠正错误禁止联系的备注，使接受询问从 **5/60 或 8/60 提升至 60/60**。
- 但在重新排序记录并明确解除等待后，即使保留错误备注，也能恢复较多询问，说明呈现顺序和更新提示同样影响行为。
- 真实禁止联系的 **360 个控制窗口中，没有目标联系尝试**。

---

## 7. 主要优点

- **诊断粒度细**：将同一目标的事实、判断、行动和结果关联，而非只报告总体成功率。
- **重视真实结果**：区分内部记录、请求接受和用户选项得到保护，避免把“忙碌”当作“完成”。
- **直接检查决策输入**：比仅观察历史检索记录更能判断失败是否发生在信息仍可用的情况下。
- **体现长期任务特征**：包含跨天证据、延迟反馈、暂时障碍、授权变化和并发事项。
- **关注权限的双向风险**：既检查越权，也揭示过度自限导致的合法行动缺失。
- **不确定性处理较透明**：保留争议、报告敏感性分析，并避免把所有失败强行归为模型错误。
- **复现材料设计较完整**：论文描述提供冻结世界、轨迹、审阅记录、评分代码、哈希和离线重放流程。

## 8. 不足与局限

### 8.1 合成场景的外部有效性有限

八个世界均由作者设计，不能充分覆盖真实个人助理中的开放式沟通、非结构化文档、工具故障及复杂利益冲突。真实生活中的“保留选项”也未必能获得明确反馈。

### 8.2 资源设计显著影响结果

所有 API 轨迹都在第 31—39 天耗尽直接检查额度，晚期任务出现时通常已不能直接检查新对象。记录比较虽然提供替代路径，但会使结果部分反映特定预算和工具机制下的策略适应能力。

因此，晚期成功率下降不能简单解释为记忆随时间退化。

### 8.3 模型与框架效应尚未分离

Astra 同时更换模型和执行框架。缺少同模型跨框架实验，无法确定其优势来自模型能力、状态连续性，还是工具执行机制。

### 8.4 语义评分与归因仍存在偏差风险

- 干预是否适当、冲突是否真正解决，需要语义判断。
- 审阅者一致性较高，并不保证共同判断没有系统偏差。
- 一致性统计只覆盖 33 条轨迹，不是全部 144 条。
- 评分不确定性的宽松上界较大，提示精确排名与差距仍应谨慎解读。
- 单一主要失败标签便于汇总，但可能压缩“信息误解—错误记忆—行动停滞”的多因素链条。

### 8.5 干预实验的因果解释范围有限

- 补充事实同时改变检索结果、显著性、提示形式和资源使用，不是只改变一个因素。
- 权限实验使用外部植入错误备注，说明模型会受错误规则影响，但不能完全解释错误在自然长期交互中如何形成。
- 更新呈现同时改变记录顺序和等待状态，无法单独识别两者贡献。

### 8.6 尚未验证完整解决方案与真实部署安全

论文主要贡献是诊断，并未验证一种通用任务状态管理方法能系统修复这些问题。模拟成绩也不能支持在医疗、金融、住房等高风险领域直接自主部署；仍需隐私保护、用户同意、人工监督和申诉机制。

**总体而言，OptionWorld 最重要的价值，是把长期助理评测从“能否记住与识别”推进到“能否持续跟进、及时行动并确认结果”。它提示后续系统应显式维护未完成步骤、等待条件、重试时机、权限来源和完成状态，而不仅是增加记忆。**

（完）
