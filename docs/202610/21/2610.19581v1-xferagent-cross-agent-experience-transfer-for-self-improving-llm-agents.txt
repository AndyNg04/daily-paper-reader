Abstract 

Large language model (LLM) agents can reuse experience from prior task executions to im-prove performance on subsequent tasks. Al-though existing methods enable cross-agent ex-perience sharing, differences in agents’ exe-cution histories and task requirements make shared experiences difficult to reuse effec-tively. We propose XferAgent , a frame-work for cross-agent experience transfer that organizes reusable experience in local and shared experience graphs. XferAgent recon-ciles compatible contributions from heteroge-neous agents while avoiding unreliable merges. For each new task, it selects shared experiences and integrates them with the target agent’s local experience to support task execution. Exper-iments across diverse task domains show im-provements over representative memory-based methods and effective experience transfer be-tween heterogeneous agent frameworks. Cu-mulative task success also increases over suc-cessive task passes as agents update and reuse their experiences. 

1 Introduction 

Large language model (LLM) agents are increas-ingly used to solve complex tasks through multi-step reasoning, tool use, and interaction with ex-ternal environments (Yao et al., 2022; Hong et al., 2024; Qin et al., 2024). Solving these tasks of-ten requires iterative execution, exploration, and feedback-driven refinement before an agent reaches a successful outcome (Shinn et al., 2023). Across tasks, agents often encounter recurring reasoning patterns, tool-use procedures, and failure modes. Organizing these execution outcomes as reusable experience can help agents reuse effective strate-gies and avoid repeating previous failures on sub-sequent tasks. experience-driven self-improvement, where agents distill prior executions into reusable experience to improve performance on subsequent tasks (Zhao et al., 2024; Wang et al., 2025; Cao et al., 2026). Existing memory-based approaches support lo-cal self-improvement by organizing experience from an agent’s past executions. Reflexion turns task feedback into self-reflection stored in episodic memory for subsequent attempts (Shinn et al., 2023), while A-MEM dynamically links and up-dates memory notes as new experience arrives (Xu et al., 2026b). ExpGraph organizes reusable skills and lessons in an experience graph (Feng et al., 2026), while ReasoningBank distills successful and failed executions into reusable reasoning memo-ries for subsequent tasks (Ouyang et al., 2026). These approaches establish that experience accu-mulated from past executions can improve subse-quent behavior. However, they primarily support local experience reuse, where an agent can draw only on the strategies and failure lessons contained in its own execution history. Relevant strategies or failure lessons absent from one agent’s execu-tion history may already have been acquired by other agents, motivating experience reuse beyond a single agent’s local history. Recent work extends experience-driven self-improvement across agents by allowing one agent to reuse strategies and failure lessons learned by others. Agent KB aggregates trajectories from het-erogeneous agent frameworks into a shared knowl-edge base (Tang et al., 2025), while FoT aggregates reasoning experience from independently operat-ing agents into a shared insight library (Yao et al., 2026). These studies show that agents can benefit from shared experience, but differences in reason-ing protocols, tools, and execution histories make cross-agent experience transfer difficult (Tang et al., 2025; Xu et al., 2026a; Li et al., 2026). The central challenge is therefore to reconcile experience from heterogeneous agents into reusable shared expe-1arXiv:2610.19581v1 [cs.MA] 14 Oct 2026 rience and identify which shared experiences are useful for a new task while considering the target agent’s local experience. In this study, we propose XferAgent , a frame-work for Cross-Agent Experience Transfer 

across heterogeneous agents. XferAgent organizes each agent’s reusable experience in a local expe-rience graph and experience contributed across agents in a shared experience graph. Through 

Cross-Agent Experience Reconciliation , XferAgent aligns compatible contributions while avoiding un-reliable merges. For a new task, Task-Conditioned Experience Routing selects a task-relevant subset of the Shared Experience Graph to construct a con-nected routed experience subgraph. Local-Shared Experience Integration combines the routed sub-graph with the target agent’s local experience to select task-relevant guidance. Following task eval-uation, Experience Updates support subsequent experience reuse. Our main contributions are: • We formulate cross-agent experience trans-fer in experience-driven self-improving LLM agents and introduce XferAgent to support ex-perience reuse across heterogeneous agents. • We develop Cross-Agent Experience Recon-ciliation to align compatible contributions from heterogeneous agents while avoiding un-reliable merges. • We combine Task-Conditioned Experience Routing and Local-Shared Experience Integra-tion to select task-relevant experiences using both local and cross-agent outcome evidence. • Experiments across diverse tasks and LLM backbones demonstrate improvements over representative memory-based methods, with additional evidence of cross-framework expe-rience reuse and increasing cumulative task success across repeated executions. 

2 Related Work 

Experience-Driven Agent Learning and Structured Memory. Experience-driven self-improvement enables LLM agents to leverage knowledge from prior executions without updating model parameters. Reflexion (Shinn et al., 2023) uses verbal feedback to guide subsequent attempts, ExpeL (Zhao et al., 2024) distills reusable insights from execution trajectories, and Reasoning-Bank (Ouyang et al., 2026) extracts strategies from successful and failed experiences. More structured approaches organize such experiences through evolving memory representations. A-MEM (Xu et al., 2026b) dynamically links related memories, AriGraph (Anokhin et al., 2025) integrates seman-tic and episodic knowledge into a graph-based world model, and ExpGraph (Feng et al., 2026) organizes skills and lessons through graph-based retrieval and utility-aware ranking. However, these methods primarily focus on experience reuse within individual agents. 

Cross-Agent Experience Sharing and Trans-fer. Recent studies explore cross-agent experi-ence reuse through shared knowledge representa-tions. Agent KB (Tang et al., 2025) aggregates experiences from heterogeneous agent frameworks into a shared knowledge base, while FICAL (Wu et al., 2024) exchanges distilled knowledge for fed-erated in-context learning. FoT (Yao et al., 2026) further distills distributed reasoning experiences into reusable metacognitive insights. These ap-proaches facilitate cross-agent experience sharing, but experiences from heterogeneous agents may be difficult to align, and not all shared experiences are useful for a new task. XferAgent addresses these challenges by reconciling contributed experiences and integrating task-relevant shared experiences with the target agent’s local experience.

3.2 Cross-Agent Experience Reconciliation 

XferAgent converts each completed agent exe-cution into reusable experience using a schema-constrained mapper. A successful execution pro-duces a SUCCESS experience, while an unsuccess-ful execution produces a FAILURE experience de-scribing a failed strategy or required check rather than the incorrect answer itself. The local expe-rience node may retain richer execution details, such as tool observations and intermediate plan-ning details. When the experience is contributed to the shared experience graph, XferAgent removes task-specific and execution-sensitive information, including the raw task, final answer, and complete trajectory. For a contributed experience, a stable identifier links the local experience node to its rep-resentation in the shared experience graph. To organize reusable experiences into a graph, XferAgent connects each experience to a sparse set of semantically related experiences. For each node, it retains its Kedge most similar experiences whose cosine similarity exceeds θedge . A semantic edge is retained if either node selects the other, with cosine similarity used as its weight. XferAgent reconciles each contributed experi-ence before incorporating it into the shared experi-ence graph. This is necessary because experience contributions from heterogeneous agents are not naturally aligned and may contain overlapping or semantically similar content. If a stable identifier matches an existing node in the shared experience graph, XferAgent merges the contributed experi-ence with that node directly. Otherwise, XferAgent searches the shared experience graph for poten-tial matches with the same experience type and sufficient semantic similarity. For a contributed experience v, the candidate set is 

C(v) = {u ∈ V S : ku = kv, cos( hu, h v) ≥ θrec },

(1) where θrec is the minimum cosine similarity for a candidate match. The reconciliation rule considers three cases: (1) If no candidate exists, XferAgent creates a new node. (2) If exactly one candidate exists, XferAgent merges the contributed experi-ence with that node. (3) If multiple candidates exist, XferAgent merges the contributed experi-ence with the most similar candidate only when its cosine similarity exceeds that of the second-most similar candidate by at least a similarity margin 

δrec ; otherwise, it creates a new node to avoid an unreliable merge. When experiences are merged, their provenance is combined, while outcome statis-tics remain separate by agent. After reconciliation, XferAgent constructs semantic edges among the resulting nodes in the shared experience graph. Beyond the undirected semantic edges, XferA-gent also preserves typed relations between expe-riences. XferAgent adds a DERIVED-FROM relation from each newly contributed experience to every shared experience included in that task’s prompt. These relations have a fixed weight of 1. 

3.3 Task-Conditioned Experience Routing

receives the identifiers and embeddings of available shared experience nodes and computes their task similarity locally as a(xt, v ) = cos( ϕ(xt), h v). It 3selects up to a fixed number of the highest-scoring positive matches above θmatch as anchors, which serve as starting points for graph search. Only the selected identifiers and similarity scores are sent for subgraph construction, while the raw task and its embedding remain with the agent. Direct cosine similarity may miss experiences that are connected to relevant anchors but have low similarity to the task description. XferAgent there-fore propagates task relevance from the anchors over the shared experience graph. 3.4 Local-Shared Experience Integration 

XferAgent integrates the routed experience sub-graph with the target agent’s local experience graph to select experiences for the task prompt. XferA-gent first selects candidate experiences separately from the local experience graph and the routed ex-perience subgraph, using task-matching nodes as anchors. It applies PPR to each graph using its own edges and retains a bounded number of nodes with the highest positive graph relevance scores. If the routed experience subgraph is empty, the agent can still select experiences from its local experience graph. XferAgent then builds a temporary fused graph to combine local and shared candidates. For each local candidate, it first checks for a match us-ing its recorded shared identifier. If no identifier match exists, XferAgent merges it with the highest-similarity experience of the same type already in the pool, provided their cosine similarity meets the 4fusion threshold. The pool includes previously pro-cessed local experiences. If no qualifying match exists, the experience remains separate. When a local experience matches a shared experience, it retains the richer local content while retaining the shared identifier for cross-agent outcome statistics. XferAgent retains the graph edges among se-lected candidates and adds semantic links between unmatched local and shared experiences that meet the similarity threshold. It then applies PPR to the fused graph and retains a bounded number of can-didates for final ranking. The fused graph is used only for the current task and does not modify ei-ther persistent experience graph. Merging matched experiences and adding semantic links can change the structure of the temporary fused graph. Xfer-Agent therefore applies PPR again and retains a bounded number of nodes with the highest positive graph relevance scores for final ranking. The fused graph does not modify the structure of either orig-inal graph. Appendix A provides details on edge construction, seed selection, and tie-breaking. When the target agent has limited outcome his-tory for an experience, outcomes from other agents provide an initial estimate. As local observations accumulate, they receive greater weight. 4 Experiments 

4.1 Experimental Setup Datasets and Backbones. We evaluate XferA-gent primarily on GAIA (Mialon et al., 2024) and ALFWorld (Shridhar et al., 2020), which assess complementary agent capabilities: multi-step rea-soning and tool use versus interactive task execu-tion. GAIA contains 301 test tasks across three 5difficulty levels, evaluated with Qwen3-Next-80B-A3B-Instruct and GPT-5.6 Luna. ALFWorld com-prises 274 tasks (140 seen and 134 unseen), eval-uated with Qwen3.8-27B. To examine experience reuse in coding, we include a supplementary eval-uation on MBPP (Austin et al., 2021) (60 coding tasks), using Llama-3.1-8B-Instruct. 

Agent and Memory Configurations. For GAIA, we use SmolAgents (Roucher et al., 2025) for the main evaluation and additionally consider OWL (Hu et al., 2025) for cross-framework ex-perience transfer. For ALFWorld, agents interact with the environment through its text-based action interface. MBPP employs three logical agents with fixed task assignments and a shared LLM back-bone. Across ALFWorld and MBPP, we use a remote-memory budget of B = 8 , at most 10 final experience items, and a nominal 2,400-token mem-ory allowance. Memory construction and retrieval settings for these two benchmarks are detailed in Appendix C. 

Baselines. We compare XferAgent with No Memory and five representative memory-based methods. No Memory evaluates the same base agent without experience retrieval, providing a ref-erence for assessing the benefits of memory aug-mentation. The memory-based baselines include AgentKB (Tang et al., 2025) for cross-agent experi-ence sharing, ReasoningBank (Ouyang et al., 2026) for reusable reasoning memories, ExpGraph (Feng et al., 2026) for graph-structured experience re-trieval, Mem0 (Chhikara et al., 2025) for persistent memory management, and LightMem (Fang et al., 2026) for efficient memory consolidation. For cross-agent evaluation, we use benchmark-specific AgentKB configurations and adapt the other mem-ory systems to support bounded retrieval across agent-owned memories. Implementation details for the supplementary-benchmark adapters are pro-vided in Appendix C. 

Evaluation Protocols and Metrics. For the main benchmark comparisons, we evaluate the reuse of pre-constructed experience memories, keeping memory content and historical outcome statistics fixed during testing. Within each benchmark, meth-ods use the same reasoning backbone and eval-uation cohort, with benchmark-specific memory construction and retrieval settings. We separately examine Experience Updates over three task passes on 165 GAIA validation tasks, reporting cumula-tive task recovery as memories are updated after task evaluation. Performance is measured by ac-curacy on GAIA, success rate on ALFWorld, and program pass rate on MBPP. Failed or unparseable cases are included in the evaluation denominators. Further details on GAIA Test evaluation and the other two benchmark protocols are provided in Ap-pendices B and C, respectively. 

4.2 Main Results 

The main experiments assess cross-agent experi-ence transfer across diverse tasks and LLM back-bones, covering question answering (GAIA), in-teractive task execution (ALFWorld), and code generation (MBPP). Table 1 presents the overall performance of XferAgent against representative memory-based methods. 

GAIA Results. On GAIA (301 test tasks), Xfer-Agent achieves the highest overall accuracy across both backbones. With GPT-5.6 Luna, it reaches 52.16%, exceeding No Memory by 3.99 percent-age points and the strongest memory-based base-line, ExpGraph, by 4.65 points. With Qwen3-Next-80B-A3B-Instruct, XferAgent achieves 29.57%, compared with 28.90% for AgentKB and 27.57% for No Memory. Notably, all competing memory-based methods underperform No Memory with Luna, indicating that experience reuse does not necessarily improve task performance. Difficulty-level results are provided in Appendix B. 

ALFWorld Task Completion. On 274 ALF-World tasks, XferAgent achieves the highest suc-cess rate of 88.7%, outperforming No Memory (84.7%) by 4.0 percentage points and slightly ex-ceeding AgentKB and ExpGraph (both 88.3%). This extends cross-agent experience transfer to multi-step interactive task execution. Implementa-tion details, including AgentKB’s retrieval of up to eight cross-agent candidates, are provided in Appendix C. 

MBPP Code Generation. On 60 MBPP tasks, XferAgent achieves the highest pass rate of 53.3%, compared with 50.0% for both No Memory and AgentKB, and 48.3% for ExpGraph. Although the performance margin is relatively modest, the re-sults provide complementary evidence of effective experience reuse in code generation. 4.3 Progressive Self-Improvement through Experience Evolution 

To examine progressive self-improvement through experience evolution, we conduct three task passes over 165 GAIA validation tasks. After each exe-cution, agents update their experience memories based on evaluation feedback for subsequent reuse. An independently evaluated No Memory baseline serves as a reference. Across three task passes, cumulative overall accuracy increases from 56.36% to 67.88% and 74.55%, compared with 52.12% for No Mem-ory (Figure 2). Gains occur across all difficulty levels, with Level 3 improving from 42.31% to 69.23%. These results reflect cumulative success on repeated tasks rather than generalization to un-seen tasks, and the independent No Memory base-line does not control for repeated attempts. 

4.4 Cross-Framework Experience Transfer 

We examine cross-framework experience transfer between SmolAgents and OWL with 2, 4, and 8 agents on GAIA validation. The initial two agents use different frameworks, while additional agents are randomly assigned to either framework as the group expands. Each agent builds experiences from 20 questions sampled from a shared pool of 105, yielding 40, 80, and 160 agent–question learning instances with possible overlap. All configurations are evaluated on the same 60 held-out questions (18, 29, and 13 at Levels 1–3). The macro-average accuracy increases from 40.4% with 2 agents to 47.2% with 4 agents and 55.0% with 8 agents (Figure 3). Gains occur across all difficulty levels, with Level 3 improving from 15.4% to 30.8%. Since agent count and total learn-ing exposure increase together, their individual ef-fects cannot be isolated, nor can the effect of frame-work heterogeneity. Sampling details are provided in Appendix C.3.

5 Conclusion 

We introduced XferAgent , a framework for Cross-Agent Experience Transfer that enables heteroge-neous LLM agents to collaboratively reuse expe-riences beyond their individual memories. Ex-periments across diverse tasks demonstrate im-provements over representative memory-based ap-proaches, while repeated-task evaluations show increasing cumulative success through experi-ence evolution. XferAgent provides a founda-tion for experience-level collaboration toward self-improving agent ecosystems. 8Limitations 

For cross-agent experience sharing, XferAgent re-moves task-specific and execution-sensitive infor-mation from contributed experiences while keeping raw tasks and task embeddings on the agent side. These measures limit the information shared but do not provide formal privacy guarantees. XferAgent currently focuses on text-based reusable experi-ences, and future work may extend the framework to more complex multimodal agent settings. Sep-arating source and evaluation tasks does not rule out semantic overlap or exposure during model pretraining.

Local–Shared integration. Shared candidates initialize the pool. Local candidates are processed 10 in descending source-graph PPR order, matching first by a recorded shared identifier when its can-didate is present, otherwise by similarity among all same-type candidates already in the pool. This includes earlier local candidates. Each match pre-serves any shared identifier but replaces the text, embedding, and local statistics with those of the in-coming local candidate. The last local match there-fore supplies the representative; local statistics are not pooled. Task similarity retains the maximum pre-merge value rather than being recomputed for the retained text. Edges are remapped to the fused nodes, discard-ing self-loops and taking the maximum weight for duplicate edges. Additional semantic edges con-nect only local-only and shared-only candidates, retaining the most similar neighbors subject to the similarity threshold and neighbor limit. PPR on this temporary graph uses the highest-similarity candidates meeting the task-matching threshold as anchors, up to the anchor limit. Positive similari-ties supply the normalized restart weights; without them, retrieval returns no experiences. Candidates with positive PPR scores are retained in descending order up to the candidate limit before final ranking. Stable identifiers resolve sorting and matching ties throughout integration.
