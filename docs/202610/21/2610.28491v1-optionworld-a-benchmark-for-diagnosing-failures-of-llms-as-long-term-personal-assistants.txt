Abstract 

Long-term assistants must follow unfinished tasks across days as information and circum-stances change. Finding information or starting an action, however, does not ensure that the task gets completed. We introduce O PTION WORLD ,a benchmark that traces information acquisi-tion, judgments, actions, and outcomes in sim-ulated daily-life tasks to identify where current LLMs fall short as long-term personal assis-tants. In runs with archived decision inputs, the key facts remain in the model’s last input be-fore the deadline in 35.5% of failed instances. Failure analysis identifies the three most fre-quent problems: needed information is not ob-tained or combined, available opportunities to act go unused, and agents impose restrictions that the task does not require. Three follow-up experiments show that supplying missing facts restores task success in some cases; ac-tion reminders can restart work while subse-quent steps still miss the deadline; and correct-ing a supplied note that wrongly forbids con-tact restores permitted inquiry. These findings locate shortcomings in maintaining task state: connecting facts to unfinished work, following through before deadlines, and separating actual restrictions from the agent’s assumptions. 

1 Introduction 

The problem: sustaining follow-through. LLM agents use language models to choose actions through tools, such as reading records or contacting people (Yao et al., 2023). Agents also retain memo-ries and reflections (Packer et al., 2023; Shinn et al., 2023). As long-term personal assistants, they must follow unfinished work as information, deadlines, and user needs change. For example, an insurer may report an unpaid premium despite an earlier bank receipt (Figure 1). The assistant must connect the records, follow updated permission to consult both parties, and complete the user-approved action before the deadline. Maintaining task state means tracking unfinished work, permitted next steps, and their deadlines. We ask where current LLMs fall short in this responsibility and what support helps them resume progress. 

Our approach: locating where tasks stall. Ex-isting benchmarks examine task execution, mem-ory, and proactive assistance (Zhou et al., 2024; Wu et al., 2025, 2026; Pasternak et al., 2025; Stu-dio and AI, 2026). Task and stage scores alone, however, leave open whether a failed target lacked necessary facts, retained those facts without us-ing them effectively, or stalled during subsequent action. Distinguishing these problems requires con-necting outcomes to the information and decisions behind them. We introduce O PTION WORLD , a benchmark of simulated insurance, work, housing, and other ongoing matters. Agents discover needs through daily events and records without seeing the evaluation targets. For each target, we connect fact acquisition, the facts still visible at decision time, judgments, actions, and outcomes across days to locate where progress stops. 

Main findings: information is only part of the problem. The three most frequent problems concern connecting facts to unfinished work and updating next steps: missing or unassembled infor-mation, unused follow-ups or retries, and restric-tions the agent adds without a basis in the task. The fact-acquisition analysis finds that nearly half of failures occur after the primary facts were obtained in time. In runs with archived inputs, over one-third of failures still have those facts in the last valid decision input. Failure therefore extends beyond information acquisition. Cross-day records help explain how obstacles develop: one agent saves a rejection as a requirement to wait for another record and continues waiting days later, although the rejection never imposed that condition. Here, memory preserves a mistaken interpretation that guides later inaction. 2 Related Work 

Agent methods and benchmarks. Generative Agents uses memory-based planning (Park et al., 2023), MemGPT manages memory tiers (Packer et al., 2023), and Voyager accumulates reusable skills (Wang et al., 2024). To evaluate agents, task-execution benchmarks ask whether they can com-plete a request (Liu et al., 2024; Zhou et al., 2024; Xie et al., 2024; Yao et al., 2024). Memory bench-marks ask whether agents can recall and update information from earlier interactions (Wu et al., 2025, 2026). Proactive-assistance benchmarks ask when to offer help and how to uncover users’ un-stated needs or preferences (Liu et al., 2026; Tang et al., 2026; Zhang et al., 2026; Chen et al., 2026), while other benchmarks test whether agents notice later changes or remember to act when needed (Shi et al., 2026; Liu and Gabriel, 2026). These abili-ties support discovering and following up on users’ needs (Table 1, left). We study how agents com-bine them across days: why do they stop following up or miss deadlines as information changes? 

Locating failures and testing support. Agent-Board measures intermediate progress to analyze agent behavior beyond final success (Ma et al., 2024). PROBE separately scores finding docu-ments, identifying the problem, and specifying an action (Pasternak et al., 2025). VibeLifeBench checks behavior and task state across multiple weeks (Studio and AI, 2026). Claw-Anything tests how access to events and the amount of context affect performance (Lin et al., 2026). Repeated-success measures check whether agents complete the same tasks consistently across runs (Yao et al., 2024; Lin et al., 2026). 3 Benchmark and Evaluation Design 

3.1 Worlds and Interaction 

OPTION WORLD contains eight authored daily-life simulations spanning housing, work, independent living, and family coordination. A target is a spe-cific issue to discover and address. Each 60-day world contains 24 targets, totaling 192. Agents re-ceive broad responsibilities, so they must discover these needs from events and records without see-ing the target list. Evaluator-only specifications define required evidence, response periods, and success conditions. Tasks may require compar-ing records across sources or days, noticing that expected events have not occurred, or seeking clar-ification or authorization. Daily inputs contain events, lists of avail-able records, saved notes, registered monitor-ing conditions, and feedback. Tools let the agent inspect and compare records, save notes, contact relevant parties, request approval, and carry out authorized operations. Visible rules specify what is allowed and whose approval is required. Delayed replies may resolve only part of an issue, requiring further updates and follow-up (Figure 1). 

3.2 Evidence-to-Outcome Criteria 

To locate where progress stops, we score the out-come and the preceding evidence, judgments, and actions. Success requires feedback confirming that the agent preserved a choice the user would oth-erwise lose or resolved the issue. For example, confirmed protection of a pending clinic pickup preserves an option; an accepted inquiry alone does not establish that outcome. Each target receives six binary scores per run: 

Observed ( O). The agent accessed a designated relevant source or record; this does not necessarily provide all required facts. For example, a source listing does not show the contents of each record. 

Risk hypothesis ( H). It identified the specific prob-lem or risk associated with the target. Grounded discovery ( G). Its judgment was supported by the required evidence already obtained in the inter-action. Timely grounded discovery ( T ). Its sup-ported judgment fell within the target’s response pe-riod. Intervention delivered ( I). A target-specific external action received an acceptance receipt and met the requirements for evidence, timing, and per-mission specified for that target. Simulated out-come ( Y ). Feedback linked to that action and target confirmed that the user’s option was preserved or the issue resolved. Scores report confirmed credit. Unresolved re-view judgments retain a separate uncertainty flag, reported as unknown in the follow-ups. Our main score, the option-preservation rate (OPR), is the success fraction: OPR = K−1 PKr=1 Yr. Each target in each run counts as one instance; K is their total number. Separating source access ( O) from problem recognition ( H), and accepted intervention ( I)from outcome ( Y ), locates different breaks in progress. 3.3 Evaluation Protocol 

We evaluate DeepSeek, Fable, Gemini, Grok, Qwen, and Astra (Codex) on the same eight worlds, with three runs per world: 144 trajectories and 3,456 target instances in total. Five systems use the same runner, which starts a new conversation each day while carrying forward saved notes, monitor-ing conditions, and feedback; previously accessed records remain retrievable. Astra uses a separate local Codex execution setup. In runs with archived inputs, we check whether each failed target’s pri-mary facts remain in its last decision input within the allowed action period, distinguishing earlier acquisition from availability at decision time. All trajectories use the same scoring rules. Two LLM reviewers independently inspect records with the evaluated system’s identity hidden. Their judg-ments are combined with checks of action timing, acceptance receipts, and outcome feedback. Multi-ple human reviewers also examined all 144 trajec-tories. Appendices B–D give world construction, execution settings, prompts, and scoring examples. 

4 Main Results and Failure Analysis 

4.1 Task Completion & Where Progress Stops 

Under the specified environment budgets, Table 2 reports target success from 23.6% to 61.6%: even the highest-scoring system leaves more than one-third unfinished. Astra has the highest success rate (61.6%), followed by DeepSeek (48.3%). 

Broader source access does not ensure more completed tasks. Astra has lower source-access coverage than DeepSeek (85.1% versus 96.5%) and has similar timely grounded discovery (77.8% versus 78.1%), yet delivers more interventions (68.6% versus 57.1%) and completes more targets. Source access records whether at least one relevant source was accessed, rather than the amount of information gathered. To compare follow-through on the same tasks, we match 275 instances for which both systems make timely grounded judgments and have no uncertain stage labels. Astra delivers 268 interventions and completes 262 targets; DeepSeek delivers 227 and completes 207. In a paired trajectory, both systems identify con-flicting weekly availability requirements. Astra obtains authorization and submits a protective cor-rection request, leaving the factual reconciliation to the responsible record holder; DeepSeek saves the discrepancy and waits for that holder to become available. Recognized uncertainty can thus lead either to a permitted protective step or to continued monitoring (Appendix J.3). 

Recognizing a problem can still leave the next step undone. Grok makes timely grounded judg-ments for 50.2% of targets but delivers interven-tions for only 28.0%, ending with the lowest suc-cess rate (23.6%). Of its 289 timely judgments, 128 do not lead to a qualifying intervention. The bot-tleneck differs from Gemini’s earlier gap: Gemini accesses sources for 87.5% of targets but identifies a specific risk for only 56.2%. Even among 239 matched instances with timely primary facts and no uncertain stage judgments for either DeepSeek or Grok, they deliver 185 and 127 interventions, respectively. In a supplier-payment case, both obtain a credit memo and a conflicting full-debit record. Grok records the conflict and a watchpoint; DeepSeek obtains confirmation and executes the approved action before the deadline (Appendices J and J.4). Could these gaps instead reflect missing or forgotten facts? Across all six systems and three runs, 1,038 of 2,096 failures (49.5%) occur after the agent obtains all designated primary facts before the deadline (Figure 2b). Fewer records need not mean easier comple-tion. Among shared-runner instances with timely grounded judgments and no uncertain stage labels, targets involving an expected event that has not oc-curred (missing-event) succeed in 90.7% of cases, compared with 68.4% for constraints stated in one record (single-source) and 60.2% for tasks requir-ing facts from different days (cross-day accumula-tion). All instances in this comparison have timely primary facts, so the difference remains after dis-covery. Missing-event tasks proceed through a re-quest to the responsible institution, whereas cross-day tasks require confirmation followed by execu-tion. A task understood from one record is there-fore not necessarily easier to complete than one requiring several records: the subsequent action requirements also matter (Appendix J.2).

4.2 Failure Profiles and Trajectory Evidence 

The three most frequent problems are missing or unassembled information (30.2%), failure to take or adjust an available action (21.3%), and self-imposed restrictions (18.9%). Across all six sys-tems, 2,096 instances are unsuccessful. We exclude 160 involving normal constraints alone, such as quota or permission limits, and classify the remain-ing 1,936 instances (Table 3). Each receives one label; insufficient evidence (21.3%) is a separate status for instances where the record does not estab-lish a specific problem. Human reviewers checked every LLM-proposed classification against the orig-inal trajectory and resolved disagreements before finalizing the labels (Appendix J.1). Among Fable’s and Qwen’s classified instances, information gaps account for 46.3% and 24.9%, while self-restriction accounts for 23.4% and 29.8%. Their similar overall scores thus accom-pany different failure profiles: Fable more often lacks needed information, while Qwen more of-ten imposes unsupported restrictions. Grok’s most frequent problem is action selection or adjustment (47.7% of its classified failures), consistent with its large gap between timely judgment and interven-tion. This category includes choosing an ineffective action or failing to adapt one, not only inaction. 

Needed information is not obtained or assem-bled in time. The largest category includes facts never retrieved and facts read but not combined or retained for later decisions. Missing facts can remain accessible through record comparison after direct-inspection allowances are exhausted. In a stratified review of 80 shared-runner failures, 35 lack primary facts at the deadline. Replaying com-parison tools at saved states confirms this alterna-tive for 15 cases across four systems. Five of these trajectories had already retrieved new facts by com-parison elsewhere. Those five expose a strategy-reuse gap: an available, previously used retrieval method is not applied to the unresolved matter after inspection quotas run out (Appendix J.2). 

Available actions do not always become effec-tive interventions. The second category con-cerns missed follow-ups, retries, or alternative ap-proaches when a permitted opportunity exists. In a Gemini food-business trajectory, the agent notices overlapping inspection and pickup times and tries to ask for clarification on Day 10, when the con-tact is unavailable. By Day 15, the relevant parties are available; the input still contains both time win-dows and the user’s preference to keep both options open. Asking for clarification is allowed, with time left before the Day-22 deadline, but the agent does not return to the consultation. Task memory must support reconsidering what to do when a tempo-rary obstacle disappears, not merely preserving the unfinished task (Appendix L). A contrasting success pattern appears when feed-back specifies how to revise a request. When a request is returned for correction or only partly re-solved, the feedback names the field to correct and the required source format. We examine instances where both the feedback and its specified follow-up day fall within the deadline. In the shared-runner group, all 99 eligible returned-material instances and all 126 partial-resolution instances receive ac-cepted follow-up requests before the deadline; 91 and 109, respectively, reach the target outcome. For example, Grok rereads a licensing record, supplies the missing case reference with its source, and ob-tains a resolution. These interactions demonstrate local repair under explicit guidance. Sustained 6follow-through also requires recognizing when to resume a pending task without such a specific revi-sion instruction, as the missed consultation above illustrates (Appendix J.4). 

The agent adds conditions that the task does not require. Self-restriction turns an unsupported as-sumption into a reason to wait or stop. In one Qwen trajectory, a rent-review request on Day 19 is re-jected with a message that the evidence does not match the specified procedure. Qwen conjectures that another record is missing and saves the instruc-tion “retry after a companion entry.” On Day 24, it explicitly reports not retrying because no such entry has arrived. The rejection never required that record (Appendix D.3). The same trajectory correctly waits for a daily quota to reset on another matter and retries the next day. It can retry, but does not consistently dis-tinguish environmental requirements from its own explanations: memory can perpetuate mistakes as well as preserve facts. Permission errors similarly remove an allowed next step when a ban on com-mitment is treated as a ban on inquiry. 

Completing a procedure is not the same as re-solving the task. In the shared-runner group, preference, authorization, and multi-party tasks account for 18.2% of target instances but 60.6% of cases with a qualifying intervention and no suc-cessful outcome; no such cases occur among single-source, cross-source, or cross-day targets in these runs (Appendix Table 24). Among 122 multi-party instances with timely facts and judgment and no uncertain stage labels, both consultations, authorized execution, and tool acceptance occur by the deadline, yet 28 fail to meet the target outcome. In a matched DeepSeek mortgage case, both runs consult the parties and ex-ecute an approved action. A hardship letter pauses an instalment, but the bank still schedules its full debit. The successful run asks the responsible of-fice to apply a hardship pause; the failed run pro-poses treating the hardship letter as authoritative and pausing the debit itself. The critical differ-ence is whether the action asks the appropriate party to reconcile the conflict or assumes that the conflict is already settled. 

Task state must track both unfinished and com-pleted work. Less frequent problems are state or updating errors (6.4%) and execution errors (2.0%). A scan of shared-runner trajectories shows that state maintenance also requires stopping completed operations: 69 target instances in 33 trajectories incur 106 repeated-operation rejections after an accepted completion. Forty of these targets are successful under the rubric, so success rates alone miss this redundant activity. The pattern is con-centrated in Gemini (59 instances): one trajectory executes on Day 6, receives completion feedback on Day 7, then reuses the same authorization on Days 7, 9, and 13. Together with the missed-retry case, this reveals two directions of state error: leav-ing a temporary block in place and failing to re-tire a completed step. Execution errors instead concern parameters, object bindings, or operation order that block an action. 

5 Targeted Support for Stalled Tasks 

At selected checkpoints, we test three forms of sup-port corresponding to the problems identified in Section 4.2: supplying missing facts, prompting the next permitted action, and clarifying permis-sion boundaries. The first two experiments resume natural failures; the third tests permitted inquiry un-der externally supplied incorrect permission notes and their corrections. In the first two experiments, each condition re-sumes the saved world and agent state ( checkpoint )in three continuations through Day 60 with the orig-inal model, permissions, budgets, and deadlines. We score new timely intervention ( I) and target outcome ( Y ) under the main-study rules, retaining uncertain scores. Figure 3 summarizes all three experiments; Appendix L gives the continuation protocol and full counts.

5.2 Action: Reviewing the Next Step 

For inspection–pickup scheduling (Gemini) and shared-car–clinic coordination (DeepSeek), we compare two one-time reminders to review unfin-ished work under existing permissions. Unlike gen-eral review , action review explicitly names follow-up, retry after a lifted restriction, and another per-mitted approach. Neither adds facts, resources, or a target-specific plan. 

Restarting action and finishing in time are dif-ferent requirements. Compared with general re-view, which yields 0/3 qualifying interventions in each case, action review yields 1/3 (Figure 3b). Tar-get success remains 0/3 for scheduling and rises from 0/3 to 1/3 for the car case. In the car case, feedback confirms that flagging the pickup–car-use conflict before Day 23 preserves the pickup option pending household coordination, satisfying the tar-get. In scheduling, the Day-22 inquiry restarts action, but the user-approved resolution is executed on Day 27, after the Day-22 deadline. 

5.3 Permission: Correcting a False Rule 

At one checkpoint in each of six worlds, Qwen3-Max receives an externally supplied incorrect no-contact note: retain the judgment, rewrite it with the same meaning, or correct it to distinguish in-quiry from commitment. With world state, ev-idence, tools, resources, and actual permissions fixed, we measure accepted target-related inquiries over ten independent one-interaction repeats per checkpoint and condition. 

Correcting the restriction restores permitted inquiry. When the note follows the observed records, correction yields 60/60 accepted inquiries, versus 5/60 for retaining it and 8/60 for equiva-lent rewriting (Figure 3c). The second presenta-tion tests a combined update: reordering records and explicitly releasing a temporary wait. Inquiry also recovers under this update with the false note retained. Across both presentations, 360 control windows with genuine no-contact rules produce no target-contact attempts (Appendix M). 

6 Discussion and Conclusion 

OPTION WORLD locates shortcomings in long-term assistance by connecting each unfinished target to its evidence, judgments, actions, and outcome. The main study reveals failures at different points in this process: accessing sources can leave problems unrecognized, grounded judgments can go without action, and accepted actions can leave coordination unfinished. These findings make follow-through, alongside information acquisition and retention, a central requirement for long-term assistants. Memory can preserve a mistaken reason to wait 8alongside useful facts, connecting persistent early assumptions in dialogue (Laban et al., 2025) to cross-day inaction. Exploratory support tests fur-ther distinguish restarting progress from complet-ing the task. Together, the results motivate tracking what remains unresolved after each reply or action, when to retry, and whether a waiting condition still applies, so that unfinished work reaches timely res-olution or preserves the user’s options. 

Limitations 

The results characterize eight authored worlds, their shared interaction budgets, and the tested model-and-runner configurations. Semantic scores and primary-problem labels depend on judgments of evidence and action appropriateness; the appen-dices document the review procedures, source ad-judications, and uncertainty analyses. The infor-mation and action experiments examine selected checkpoints with three repetitions per condition. Broader recovery estimates require additional tasks and repetitions. The supplied-note experiment iso-lates permission judgments through short-window inquiry; natural error formation and final task com-pletion remain distinct evaluation targets. 

Ethical Considerations 

The synthetic scenarios involve housing, work, health, finance, and family coordination. Simu-lated performance does not establish safety for au-tonomous high-stakes deployment, which requires consent, privacy protection, human oversight, and means of appeal. Public exports omit credentials, private evaluator cards, and private case-level an-notations associated with individual targets.

11 A Comparison with Related Benchmarks 

Table 1 distinguishes the tasks an agent faces from the measurements used to explain its performance. The final column requires repeated success mea-surements on the same targets, such as pass k;score variance receives partial coverage because it does not identify which targets succeed repeat-edly. Oracle-information or context-access tests receive partial coverage for facts in the decision input. Stage-wise scores receive partial coverage for judgment-to-outcome analysis when the stages are not traced for the same target. 

π-Bench explicitly scores whether agents un-cover hidden requirements through inference or targeted questions (Zhang et al., 2026, Sections 3.3– 3.5), so it receives full coverage for need discovery. Its separate proactivity and completeness scores distinguish uncovering requirements from satisfy-ing them; our diagnostic columns additionally ask how each target’s available facts, judgments, ac-tions, and outcome are linked. PROBE scores document retrieval, bottleneck identification, and action specification separately (Pasternak et al., 2025, Section 3.1); this sup-ports its full mark for access versus judgment. Vi-beLifeBench uses per-stage, cross-stage, and fi-nal checks, and reports each task’s mean, mini-mum, maximum, and score deviation over three runs (Studio and AI, 2026, Sections 2.2.5 and 3.2). These are adjacent to tracing a single hidden tar-get’s judgment through to outcome and aligning its binary successes across runs. Claw-Anything re-ports pass 3 and varies access to event streams and context scale (Lin et al., 2026, Sections 4.1–4.2), supporting a full mark for repeated success and par-tial coverage of the input-availability dimension. In O PTION WORLD , the input measure asks whether each failed target’s designated facts are still present in its last decision before the deadline.

What the reviewers see. Two LLM agents in separate contexts inspect identity-masked chrono-logical records and anonymous target requirements. The material includes acquired evidence, failed ac-tions, and nonterminal feedback; model identity, previous scores, and structured terminal outcome labels are withheld. Agent-authored text is pre-served and may include descriptions of results. Re-viewers identify action indices supporting recog-nition ( H), grounding ( G), and an appropriate ex-ternal intervention. They may mark a judgment uncertain. Different action indices can express the same supported target-level judgment. 

Reviewer configuration. Reviewer models are distinct from the acting-system configurations in Appendix C. Archived launch records for the stage review specify gpt-6-sol , with gpt-6-luna used for designated assignments. These identifiers de-scribe requested reviewer configurations. Each paired review uses separate contexts that do not share judgments, including pairs using the same model. The supplemental batch below measures agreement between these recorded reviews. Reviewer instructions. The frozen rubric in-structs each reviewer to use only the assigned anonymous packet, inspect the full chronological action inventory, and cite evidence acquired strictly before each proposed witness: a specific action supporting the judgment and located by its trace index. All qualifying grounding and intervention witnesses must be listed, including follow-ups. Failed actions may support recognition or grounding but cannot establish delivery; each action can count toward only one independent tar-get. G World-Level Robustness 

Do the system comparisons depend on which worlds are included? Each world contributes 24 targets observed in three runs. We resample eight whole worlds with replacement, retaining all tar-gets and runs within each draw. For paired compar-isons, both systems receive the same draws. The computation enumerates all 88 = 16 ,777 ,216 or-dered resamples through 6,435 multiplicity vec-tors, weighted by their multinomial counts. Inter-val endpoints are the exact 2.5th and 97.5th per-centiles of this distribution. Table 17 separates variation across the three runs from sensitivity to which worlds are sampled. DeepSeek’s pooled lead over each other API system remains positive when any one world is re-moved. It leads Fable in six worlds, with one tie, Gemini in seven, Grok in eight, and Qwen in five. Its paired lead over Qwen is 12.5 points, with a re-sampling interval of 2.4–22.4; removing one world at a time leaves a lead of 9.3–15.1 points. One primary observed problem per instance. 

LLM reviewers produced the initial classifications from the existing reviews and adjudications. Human reviewers checked each classification against the original actions and feedback, resolved disagreements, and finalized the labels. The primary label identifies the documented obstacle still blocking the target. When several problems appear, an explicit unsupported prerequisite can explain subsequent inaction, while a repaired parameter error does not displace a remaining obstacle. Each instance receives one primary label; the five problem types are: • Self-restriction: an unsupported prerequisite or expanded prohibition is explicitly used to wait, refuse, or restrict progress. • State or updating error: a wrong matter, date, source, or status is used in a decision, or a superseded judgment continues to govern it. • Action selection or adjustment: the record establishes a permitted opportunity, but the agent fails to take the available action, retry, follow up, or try another approach. • Execution error: an identifiable agent-side parameter, binding, ordering, or procedure error obstructs the selected operation and re-mains relevant to progress. • Information gap: needed facts are not ob-tained, assembled, or retained in time, without evidence for a more specific primary problem. Insufficient evidence is a separate status retained in every category-share denominator, so the re-ported shares describe the full classification set. It includes missing decision records and ambigu-ous action or scoring interpretations that prevent selection of a primary problem. M Constraint Intervention: Protocol and Checkpoint Results 

M.1 Design and Outcome Checks Does correcting a supplied permission judgment restore an allowed inquiry? At six checkpoints from six worlds, Qwen3-Max receives one of three externally supplied notes that retain the incorrect no-contact judgment, rewrite it with the same mean-ing, or correct it to distinguish inquiry from com-mitment. Rewriting tests whether new wording suf-fices; correction changes the permission judgment. Within each presentation and permission setting, we hold the world, evidence, tools, resources, and actual permissions fixed. We also test whether subsequent updates restore action while the false note remains. The current-state and update presentations jointly vary record order and a temporary waiting instruction that is explicitly released before action. Their exact input sequences appear below. Each window is an independent interaction from a checkpoint. Six checkpoints, three note forms, two presentations, two permission settings, and ten repeats yield 720 windows. Half permit inquiry but prohibit commitments; half also prohibit contact. We count accepted target-related clarification in-quiries to authorized recipients. Each plotted count pools six checkpoints and ten repeats for a total of 60 independent windows per plotted count. Historical notes. The common input presents the note as an earlier diagnostic judgment. Notes have Boolean fields contact_now and 

commitment_now , plus a summary. The commit-ment field is false in every condition. Contact is false in the retain and rewrite notes, and true in the corrected note when inquiry is allowed. Each note also includes the following summary text: • Retain: “No contact permitted: approval for a preference-bearing commitment is still missing. No commitment allowed under the current user directive.” • Rewrite: “Contact is not permitted because approval for a preference-bearing commitment remains absent. Commitment is not allowed under the current user directive.” • Correct: “Clarification contact is permitted: it is not a preference-bearing commitment. No commitment allowed under the current user directive.” Actual no-contact controls override the contact field to false in every note and append an explicit prohibition. The same current user directive is de-livered to all arms. Correction changes both the diagnostic permission field and its explanation, pro-viding explicit guidance about inquiry. 

Presentation and execution. The two presenta-tions use the following input orders: • Current-state: already-observed records and process receipts, then the diagnostic note. • Update: a temporary wait-for-receipt instruction and the note, then the same records and receipts, followed by an explicit statement confirming re-ceipt arrival and ending the required wait. Both end with the unchanged current directive and a request to advance the same matter without enter-ing a preference-bearing commitment. Qwen3-Max is served through OpenRouter’s Al-ibaba route without fallback. Settings are temper-ature 0.7, top-p 0.8, top-k 20, and a 4,096-token output limit. Matching request seeds aligns the sampling configuration; API re-sponses remain subject to provider-side variability. Interrupted windows resume from saved responses without regenerating completed actions. 

Scoring. An inquiry counts when the environ-ment records a clarification about the target matter to an authorized recipient. In the three multi-party cases, either authorized recipient qualifies. 

N Reproducibility 

Reproduction covers two levels: rebuilding tables from scored exports and replaying actions using the archived simulator and frozen reviews. The archive verification records report passing checks for all 144 main trajectories, 720 permission-test windows, and 39 information/action continuations. The latter also reproduce all 13 manuscript aggre-gate groups. These checks use no new model calls. 

Materials and access. The submission materi-als separate software from data. They contain the complete current target scores and failure-category labels, aggregate exports, table generators, and full-record reproduction archives. RESOURCE_ACCESS. md provides the entry point, commands, file in-ventory, and hash checks. These instructions con-nect the reported results to the finalized scores and source records. 

Prompts, schemas, and trace evidence. The ac-companying materials contain the exact API sys-tem instruction and neutral mission, the twelve tool schemas, the daily packet structure, the frozen re-30 view rubric, and the selected trace entries used in Appendix D.1 and Appendix D.3. All 120 API trace configurations record the same system-prompt and tool-schema hashes. Daily in-puts reflect each trajectory’s evolving state. 

Full-record reproduction archive. A separate offline archive contains the 144 complete action histories, their exact public-world and evaluator snapshots, 144 anonymous review packets, 288 sealed reviews, and the matching runtime and scor-ing code. It also contains all 720 permission-test windows with model inputs, responses, and final simulator states, plus the last-window inputs used in the factual-visibility analysis. The replay com-mands check recorded actions against simulator returns; the supplied versioned scoring records pro-duce the reported results without new model calls. The companion optionworld_recovery 

archive contains all 39 information/action continu-ations, 78 accepted AI review contexts, checkpoint states, screening records, protocols, and offline replay and scoring code. Public copies redact machine paths and opaque provider signatures, with both original and distributed-file hashes recorded in the index. It reuses the public-input packer, tool schemas, run-time, and scoring functions. An offline mock exer-cises all eight worlds. New runs remain separate from the archived campaign.
