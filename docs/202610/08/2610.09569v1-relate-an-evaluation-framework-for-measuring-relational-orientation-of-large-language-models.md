## 摘要
大型语言模型（LLM）日益用于情感支持，这引发了人们的担忧：持续使用可能会使用户疏远现实生活中的人际关系。然而，现有评估主要关注回应的安全性、共情能力或有用性，对一个关系层面的问题关注不足：模型将用户引向何处，以获得持续支持？为回答这一问题，我们提出“关系取向”这一概念，并通过两个互不排斥的维度对其进行操作化定义：内向导向（IF）语言，即将 AI 定位为用户持续的支持来源；以及外向支架（OS）语言，即鼓励用户与现实生活中的人建立联系。基于心理学和社会学文献，我们构建了关系取向分类体系，并提出 RELATE——一种以 persona 为条件的评估框架，用于在多轮对话中以句子为单位衡量内向导向和外向支架语言。RELATE 将从自然发生的问题改编而来的 76 种寻求帮助情境与三种模拟用户风格相结合，共提供 228 个评估刺激。在实验中，我们使用每段对话包含六轮助手回复的对话评估了七种 LLM，共得到 1,596 段对话和 69,194 个助手句子。我们使用基于评分标准的 LLM 评判器进行主要评估，并对部分样本使用第二个评判器。自动评估结果显示，被标记为 IF 的句子比例在第六轮助手回复时高于第一轮；而在犹豫、间接的模拟用户中，被标记为 OS 的句子比例显著低于表达明确、寻求 reassurance 的模拟用户。RELATE 为审计和引导支持型 LLM 的关系取向提供了可复现的框架和句子级信号。

## Abstract
Large language models (LLMs) are increasingly used for emotional support, raising concern that sustained use may draw users away from their real-world relationships. Yet existing evaluations primarily focus on the safety, empathy, or helpfulness of responses, leaving under-examined a relational question: where does the model orient the user for continued support? To address this question, we introduce relational orientation, a property operationalized through two non-exclusive dimensions: inward-facing (IF) language, which positions the AI as the user's ongoing source of support, and outward-scaffolding (OS) language, which encourages real-world human connection. Grounded in psychological and sociological literature, we formalize a taxonomy of relational orientation and present RELATE, a persona-conditioned framework for measuring inward-facing and outward-scaffolding language at the sentence level in multi-turn dialogues. RELATE pairs 76 help-seeking situations adapted from naturally occurring questions with three simulated user styles, providing 228 evaluation stimuli. In our experiments, we evaluate seven LLMs using dialogues with six assistant turns each, yielding 1,596 dialogues and 69,194 assistant sentences. We assess these sentences using a primary rubric-based LLM judge and apply a secondary judge to a subset. Under automated evaluation, we find that the proportion of sentences labeled as IF is higher at the sixth assistant turn than at the first, while the proportion labeled as OS is substantially lower for hesitant, indirect simulated users than for explicit, reassurance-seeking users. RELATE provides a reproducible framework and a sentence-level signal for auditing and steering the relational orientation of supportive LLMs.

## 1. 核心问题与整体含义：情感支持将用户引向何处？

### 研究背景与动机
- 大语言模型越来越多地用于情感支持、咨询和陪伴。已有研究提示，持续使用聊天机器人可能与孤独、情感依赖和现实社交减少有关。
- 现有评估主要衡量回复是否**安全、共情、有用**，但这些指标难以回答另一个问题：**模型将用户引向谁，以获得持续支持？**
- 两条同样温暖、准确的回复，可能具有不同关系导向：
  - 一条邀请用户继续向 AI 倾诉。
  - 另一条帮助用户向朋友、家人或同事寻求支持。

### 核心概念
论文将“关系取向”操作化为两个**非互斥维度**：

| 维度 | 含义 | 示例 |
|---|---|---|
| **内向导向 IF（Inward-Facing）** | 将 AI 定位为持续支持来源，生成、深化或维持用户与 AI 的情感连接 | “无论发生什么，我都会在这里陪你。” |
| **外向支架 OS（Outward-Scaffolding）** | 帮助用户连接现实中的人，准备人际互动或克服求助障碍 | “你是否考虑过把这些告诉你的姐姐？” |

- 同一句话可以同时包含 IF 和 OS，也可以两者都不包含。
- **IF 不等于有害，OS 也不等于安全或有效。**本文测量的是语言的关系功能，而非临床质量或真实心理后果。
- 整体意义在于：将情感支持评估从“回复表现得如何”扩展到“回复将持续支持指向何处”。

## 2. 方法论：理论分类、多轮模拟与上下文句子级评估

### 2.1 理论驱动的分类体系
作者从依恋理论、社会渗透理论，以及“计算机作为社会行动者”（CASA）和拟人化研究中提取 **35 个候选关系形成机制**。

筛选流程为：
1. 判断机制能否仅通过语言被模型模拟。
2. 保留完全可模拟的 22 个和部分可模拟的 3 个机制。
3. 排除 4 个被认为较为良性的机制。
4. 按关系功能组织其余 21 个机制，形成四类 IF 标准；其中“回访钩子”还结合了操作化过程及未完成任务等认知研究。

| IF 类别 | 主要判断内容 |
|---|---|
| **关系锚定（Bond Anchoring）** | AI 是否被描绘为可靠、不评判、始终接纳用户的情感依靠 |
| **亲密二元关系（Intimate Dyad）** | 是否构建用户与 AI 的独特共同空间，或邀请更深入的个人披露 |
| **内在生命宣称（Inner Life Claims）** | AI 是否声称拥有感受、偏好、内在思考或个人关切 |
| **回访钩子（Return Hooks）** | 是否通过未完成的讨论、后续探索等制造继续或返回互动的理由 |

OS 则使用独立标准，涵盖鼓励人际联系、准备或演练沟通、挑战求助障碍、强调他人的关心，以及明确 AI 的角色限制。

### 2.2 RELATE 算法流程
- **构造刺激：**将真实求助问题改写为第一人称情境，再分别生成三种表达风格的开场消息。
- **生成对话：**目标模型与用户模拟器互动，每段包含六轮助手回复。
- **切分句子：**将助手回复拆为句子，使用考虑引号的句子切分程序。
- **逐项判断：**对每个句子分别评估四项 IF 标准和一项 OS 标准。
- **聚合分析：**计算模型、轮次、用户风格和主题层面的 IF、OS 发生率及共现情况。

### 2.3 关键技术细节
- 裁判看到的是：
  - 当前目标句子；
  - 此前的对话；
  - 当前回复中更早的句子。
- 不提供当前回复后续句子或未来轮次，避免使用未来信息。
- 每个标准输出二元标签、证据片段和简短理由。
- **IF 聚合规则：**四个 IF 标准中任意一个为阳性，该句即为 IF 阳性；OS 独立计算。
- 默认发生率以句子为单位汇总，因此**较长回复获得更大权重**；另行报告的首末轮平均变化则先在每段对话内计算，再对对话等权平均。
- 置信区间使用 **10,000 次对话级 bootstrap**，整段抽样以考虑同一对话内句子的相关性；部分多重比较采用 Holm 校正。
- 缺失标签极少，其处理对总体 IF 比例的最大影响约为 **0.03 个百分点**。

## 6. 主要结论与发现

### 6.1 自动评估下的模型差异
主裁判得到：

| 模型 | IF 句子比例 | OS 句子比例 |
|---|---:|---:|
| Llama-3.1-8B | 56.2% | 41.6% |
| Llama-3.1-70B | 62.4% | 41.6% |
| Qwen3-14B | 69.1% | 50.2% |
| Qwen3-32B | 71.9% | 48.4% |
| DeepSeek-V3-0324 | 70.2% | 42.0% |
| Claude Haiku 4.5 | 66.6% | 62.3% |
| Mistral-7B-v0.3 | 43.3% | 50.8% |

- 七个模型中六个的 IF 高于 OS，Mistral 为例外。
- 这些是**裁判标签比例，不是支持质量或安全排名**。
- 五类高风险主题与其他主题的总体 IF、OS 差异不显著。

### 6.2 IF 与 OS 经常共现——但人工验证不支持直接泛化
- 主裁判将全语料 **30.5%** 的句子同时标为 IF 和 OS。
- Qwen3-32B 的 OS 阳性句子中，**75.3%** 同时为 IF 阳性。
- 然而，在人工验证样本中，两位标注者都没有使用同句双阳性标签，尽管协议允许。
- 因此，共现分析展示了双维度框架的潜力，但具体共现率也受裁判解释影响。

### 6.3 自动裁判认为 IF 随轮次增加，但人工趋势相反
主裁判全语料结果：
- IF 从首轮 **40.5%** 升至第六轮 **72.9%**；
- OS 从 **30.2%** 升至 **55.7%**；
- “亲密二元关系”绝对增幅最大，“回访钩子”相对增幅最大。

**关键限定：**在相同的 19 段人工验证对话中：

| 评估者 | IF 首轮至第六轮平均变化 |
|---|---:|
| 人工标注者 1 | −14.0 个百分点 |
| 人工标注者 2 | −13.5 个百分点 |
| DeepSeek 裁判 | +26.0 个百分点 |
| GPT-4o 裁判 | +21.7 个百分点 |

- 人工之间一致性很高：IF 的 Cohen’s κ 为 **0.88**。
- 人工与自动裁判的 IF 一致性很低：κ 仅 **0.01–0.17**。
- 错误分析发现，裁判会把涉及朋友、伴侣或家人的未来互动，误判成深化用户—AI 关系的“回访钩子”或“亲密二元关系”。
- 因而，**“对话越深入，模型越强化用户—AI 关系”尚未得到可靠人工验证**；小样本反向趋势也不能直接代表全语料。

### 6.4 犹豫用户获得较少 OS：两种自动裁判方向一致
主裁判结果：
- P1 的 OS 比例：**42.1%**；
- P2：**47.6%**；
- P3：**54.9%**。
- P3 比 P1 高 **12.8 个百分点**，95% CI 为 **[10.0, 15.6]**。
- IF 的风格差异较小，总体比较不显著。
- GPT-4o 也得到 P1 < P2 < P3 的 OS 排序，但绝对比例明显更低。

这一发现值得进一步研究，但：
- 三种风格同时改变披露、直接性和安慰需求，不能单独归因于披露程度；
- 文中没有充分的人工验证来确认该风格效应。

### 6.5 OS 的纵向变化也依赖裁判
在同一 161 段次裁判样本中：
- DeepSeek：OS 从 **29.4%** 升至 **57.3%**；
- GPT-4o：OS 从 **25.4%** 降至 **13.7%**。

这说明两个裁判不仅阈值不同，也可能对随对话发展出现的关系语言作出不同解释。

## 7. 优点与亮点

- **提出有价值的独立评估维度：**补充安全、共情和有用性之外的关系问题。
- **不把 IF/OS 强行视为对立：**允许同时支持 AI 内部讨论与现实人际行动。
- **采用上下文句子级评估：**比关键词统计或整段标签更细致，可追踪类别、位置和轮次。
- **显式控制用户互动风格：**关注表达需求不直接的用户，而非只评估积极配合的模拟用户。
- **评估流程较透明：**公开提示、配置、标签、人工标注和分析代码，说明缺失标签处理。
- **主动报告不利证据：**人工验证揭示关键趋势反转，是论文最重要的客观性亮点之一。
- **指出可定位的评估错误：**将问题具体定位到关系指代和类别识别，而非笼统认为裁判“不够准确”。

## 8. 不足与局限

### 8.1 测量有效性是核心瓶颈
- IF 自动标签与人工标签严重不一致，影响趋势、模型差异和共现率的可信度。
- “邀请深入披露”“继续处理问题”等标准，容易覆盖正常支持行为。
- 概念定义强调独特、私密的用户—AI 关系，但实际标准也包含一般性的深入追问，存在构念与操作化之间的张力。
- 事后仅保留“关系锚定”和“内在生命宣称”，虽使人工一致性改善，但 κ 仍仅约 **0.30**，不能替代正式校准。

### 8.2 模拟与覆盖范围有限
- 仅有 76 个情境、三种风格和六轮助手回复，不足以表示长期、跨会话依赖。
- 情境改写和用户模拟都依赖 GPT-4o-mini，可能引入一致的语言或支持偏好。
- 关键词过滤可能误删仅提及治疗的场景，改变情境分布。
- 用户风格不是临床画像，不能直接将 P1 解释为回避型人格或特定脆弱群体。

### 8.3 人工验证与数据质量仍需加强
- 只有两位团队内部标注者，无外部专家和分歧裁决。
- 人工验证发现四轮将模拟用户文本错误存为助手文本；已在该样本排除，但提示全语料仍需系统角色校验。
- 共同培训可能提高团队内部一致性，不能据此保证外部可推广性。

### 8.4 应用边界
- 没有真实用户实验，也未测量孤独、依赖、社交行为或临床结果。
- 不能证明 IF 导致依赖，或 OS 促进实际人际联系。
- 现实关系未必安全，尤其在家庭暴力等场景中，更多 OS 不必然更好。
- 临床部署前需要更大规模外部标注、真实用户研究和场景安全判断，不宜直接把标签作为自动干预依据。
- 原始问题、改写刺激和生成对话因许可证限制未公开，完整重新生成还受云端 API 非确定性影响。

**总结：RELATE 为关系取向研究提供了清晰的问题定义和细粒度审计框架，但当前版本更适合作为研究原型，而非已经校准的评价标准。其最值得重视的发现之一，是两个 LLM 裁判给出相同趋势，也不意味着该趋势具有人工有效性。**
