Personal assistants are evolving from search and text interfaces toward interactive multimodal systems that retain spatial and conversational history to support ongoing tasks. Effective assistants must therefore reason jointly over observed scenes and past dialogue to address complex requests. We formalize this challenge as Spatially grounded Conversational Reasoning (SpaCR), covering cross-scene, recall-oriented, and counterfactual spatial queries that require accurate geometric reasoning and the integration of dialogue with spatial evidence. Existing approaches are poorly suited to this setting. Direct VLMs incur high inference costs and context limits as multimodal histories grow. Keyframe selection and retrieval can omit evidence needed for complete recall, while memory systems must preserve both conversational facts and object geometry to support spatial reasoning. To bridge this gap, we propose Spatially grounded Conversational Memory (SpaC-MEM), an object-centric working memory that applies 3D reconstruction and segmentation to egocentric observations, thereby spatially grounding conversational context directly to physical objects. It compresses long multimodal histories while preserving spatial and conversational evidence and allowing object-specific information to be updated through later dialogue. We further introduce Ego-SpaCR, an egocentric SpaCR dataset comprising 620 video sessions from ScanNet, augmented with 95 conversations averaging 230 dialogue turns each, and 3,100 evaluation queries. Experiments show that SpaC-MEM achieves the highest overall answer accuracy among the evaluated methods and improves object recall, while requiring substantially fewer reference input tokens than native-video baselines. Analysis shows that removing 3D spatial information substantially degrades performance, highlighting the importance of preserving both spatial and conversational evidence for an egocentric assistant.

1 Introduction 

As personal assistants move beyond search and text interfaces toward egocentric multimodal systems, they must remain coherent with both what the user sees and what they say over time (Wang et al., 2023; Liang et al., 2026a). Users naturally refer to objects in view while expressing facts such as ownership and preferences that cannot be inferred visually. As interactions span rooms, sessions, and days, tasks requiring object comparisons, alternative arrangements, or a complete inventory arise, even when the relevant evidence is no longer visible or recoverable. Thus, an effective assistant should preserve both spatial and conversational context to support ongoing tasks, without requiring the user to remember or revisit earlier interactions. Figure 1 demonstrates how a user might identify friends’ belongings while moving through an apartment, then later ask a spatially grounded question dependent on those references, such as “How much of my friend’s stuff on the tables earlier can I fit in this box?” Answering such complex cross-scene spatial queries requires more than retrieving a relevant frame: the assistant must recover conversational facts tied to persistent objects, combine them with prior geometric, qualitative relational, or counterfactual spatial evidence, and account for all relevant objects across the history. We refer to this as Spatially grounded Conversational Reasoning (SpaCR) .

Where Existing Approaches Fall Short. Direct vision-language models (VLMs) repeatedly process growing multimodal histories, exhausting context windows and incurring high inference costs (Tang et al., 2025; Zhu et al., 2026). Keyframe selection and multimodal Retrieval-Augmented Generation (RAG) reduce context but may miss objects or evidence required for questions requiring complete recall. Spatial scene memories primarily retain visual observations without evolving conversational context (Gu et al., 2024; Yang et al., 2025b). Multimodal conversational memories such as M2A retain raw interactions alongside semantic records (Feng et al., 2026), but do not maintain the explicit object geometry needed for complex spatial reasoning. Existing datasets likewise lack key requirements of SpaCR (Table 3). VideoQA approaches (Yang et al., 2025a, 2026; Gu et al., 2026) do not evaluate spatial reasoning over conversational facts, while situated dialogue datasets (Wu et al., 2023) focus on single-scene interactions with limited spatial reasoning. 

A Spatially Grounded Working Memory. To address this gap, we propose Spatially grounded Conversational Memory (SpaC-MEM), a unified object-centric working memory that grounds user-specific conversational information to physical objects in historical egocentric interactions while preserving their spatial evidence (e.g., object size) via 3D geometric reconstruction with segmentation. SpaC-MEM compresses long frame-based histories into a compact representation, while allowing conversational information to be accumulated and updated over time (e.g., changing a chair from discarded to kept). We further introduce Ego-SpaCR, a benchmark for SpaCR over egocentric video, augmented with task-oriented dialogue. Our experiments show that SpaC-MEM achieves the highest overall answer accuracy among the evaluated methods and improves object recall while requiring substantially fewer reference input tokens than native-video baselines. Removing explicit 3D spatial information substantially degrades performance, supporting the use of spatial evidence alongside conversation in memory. Our contributions are summarized as follows: 

• We introduce Spatially grounded Conversational Memory (SpaC-MEM), an object-centric working memory that connects detailed spatial and conversational information via persistent physical objects across historical egocentric user interactions.

• We introduce Ego-SpaCR, a benchmark for SpaCR over egocentric video and task-oriented dialogue, with 95 task-driven conversations in 620 real-world video sessions and 3,100 evaluation questions across varying classes of spatial complexity and recall breadth. 

• We conduct a controlled analysis across Ego-SpaCR, revealing where existing methods fail as queries require increasingly complex spatial reasoning and recall over object sets. 

• We show that SpaC-MEM consistently outperforms existing methods in accuracy and object recall, while substantially reducing input token cost compared to in-context methods. 

2 Related Work 

2.1 Egocentric Video and Dialogue Benchmarks 

Egocentric video captures the environment from the wearer’s viewpoint, recording what they see and interact with (Damen et al., 2018; Grauman et al., 2022). EPIC-KITCHENS (Damen et al., 2018) and Ego4D (Grauman et al., 2022) capture longer-term first-person experiences across different environments. ScanNet further provides RGB-D observations of real scenes together with geometry and object annotations (Dai et al., 2017) as the foundation of spatial understanding evaluation. 

Video question answering (VideoQA). Egocentric VideoQA benchmarks, such as EgoVQA and EgoSchema, cover first-person activities over longer video contexts (Fan, 2019; Mangalam et al., 2023). OpenEQA and SQA3D evaluate questions in situated 3D environments (Majumdar et al., 2024; Ma et al., 2023); VSI-Bench, VSI-SUPER, and VSI-Super-Wild focus on spatial reasoning, long-term spatial recall, and counting (Yang et al., 2025a, 2026; Gu et al., 2026). These VideoQA benchmarks evaluate questions about observations without an evolving history of user-stated facts tied to persistent objects. In SpaCR, language is integral to the evolving history, supplying facts by referring to an object in view, such as ownership or preferences. The assistant must connect those facts to the object’s spatial evidence over time. 

Long-term Dialogue and Situated Conversation. Long-term dialogue benchmarks such as Long-MemEval (Wu et al., 2025) evaluate assistants’ ability to use evolving conversation but do not ground it in spatial environments. Situated dialogue (SIMMC-VR (Wu et al., 2023) and SIMMC 2.0 (Kottur et al., 2021)) connect conversation with spatial properties in simulated environments, but focus on short, single-scene interactions with limited spatial complexity. They do not require reasoning across scene spaces to answer the complex counterfactual spatial queries that users may request. Related recommendation work studies visually grounded fashion dialogue and scene-based in-situ item labeling (Guo et al., 2026; Liang et al., 2026a), connecting user preferences with visual item information. 

2.2 Spatial Understanding with Video Input 

In-Context Spatial Understanding. Recent multimodal models directly process video and language; Gemini supports native video understanding, while Qwen3-VL extends long-context vision-language modeling to long videos and temporal grounding (Google DeepMind, 2026; Bai et al., 2025). These models keep visual and conversational history in context instead of organizing it around persistent physical objects. As a result, recovering every object linked to conversational facts remains difficult. Query-aware frame selection methods such as AKS and FOCUS select informative frames before VLM inference (Tang et al., 2025; Zhu et al., 2026). But selection is conditioned primarily on queries and visuals, without considering the evolving conversation. 

Agentic Spatial Understanding with Object Memory. Object memory methods reconstruct scenes from observations. ConceptGraphs builds open-vocabulary 3D scene graphs from RGB-D input (Gu et al., 2024). However, they primarily target visual understanding. Agentic systems (e.g., VideoAgent) combine captions, object tracking, re-identification, and tool-based memory in agentic retrieval (Fan et al., 2024); Gemini’s

Multimodal RAG and Dialogue Memory. Retrieval-based methods select stored evidence for answering: RAG retrieves text (Lewis et al., 2020), with related dense retrieval work studying manifold-aware distances and LLM-guided Bayesian active learning (Liu et al., 2025; Kim et al., 2026); natural language recommendation also uses LLM relevance judgments to model item relevance (Liu et al., 2026b). Related conversational memory methods organize access through tree-structured semantic queries, preserve temporal order with segment trees, or decompose goals for targeted retrieval (Liu et al., 2026c,a; Liang et al., 2026b). Retrieval can miss evidence needed for complete recall, while summaries can omit geometry required for SpaCR. 

3 SPA CR: Spatially Grounded Conversational Reasoning 

We distinguish SpaCR from existing settings through four required properties: (i) bimodal histories , since users naturally introduce non-visual information while referring to objects they see; (ii) spatial grounding ,so that this information remains attached to the same physical objects across views, sessions, and revisits; (iii) complex spatial reasoning , because later requests may depend on geometric relations or hypothetical arrangements that are not directly visible; and (iv) recall breadth , as tasks may require accounting for the complete relevant object set rather than retrieving isolated evidence.

(iii) Spatial complexity. Users may ask whether a prior object is currently visible, whether objects fit geometrically, are closer to one another, or satisfy hypothetical spatial arrangements. Supporting such requests requires increasingly complex spatial evidence. We define four levels through rk(o):(C1) Object grounding tests whether the assistant can connect a conversational condition hk(o) established earlier to the same physical object in the current view, with rk(o) = 1[o ∈ O tk ]. Users may refer back to previously discussed objects as they reappear during an ongoing task. (C2) Qualitative relations tests whether the assistant can evaluate single- or multi-hop spatial relations R, such as on or near , over conversationally grounded objects. For objects on the same table as a conversationally qualified lamp, rk(o) = ∃u, w ∈ O ≤tk : ( u : table) ∧ (w : lamp) ∧ gk(w) ∧ Ron (o, u ) ∧ Ron (w, u ). Here 

gk qualifies the anchor independently of the target condition hk: for “a lamp that my roommate owns,”

Users may ask whether objects fit or compare their distances for tasks like packing, where qualitative relations alone are insufficient. (C4) Counterfactual spatial reasoning tests whether the assistant can evaluate spatial relations under a hypothetical viewpoint or placement. Answering may require combining geometric evidence from earlier observations to reason about an arrangement that was not directly observed. 

(iv) Recall breadth. Let Rk denote the target objects supporting the answer, excluding anchors used only to evaluate spatial conditions. For a count query, Rk = Sk; an identification or positive existence query needs a single target or witness. We define recall breadth as Bk = |R k|. Counting requires recovering the complete matching set. For zero-count and negative existence answers, Rk = ∅, but all candidates must be ruled out; recall breadth therefore measures target-set size. 

4 Object-Centric Spatially Grounded Conversational Memory

We therefore propose Spatially grounded Conversational Memory (SpaC-MEM), an object-centric conversational working memory that spatially grounds past dialogue in persistent physical objects. 5 Experiments 

To understand the performance and limitations of existing methods in SpaCR, we study three RQs 1:

RQ1 Does SpaC-MEM improve downstream answering model performance on SpaCR compared with existing approaches? 

RQ2 Across object identification, geometric estimation, and spatial reconstruction, which abilities limit current methods on SpaCR? 

RQ3 How do SpaC-MEM’s design choices, including object-centric structure, dialogue association, and geometric reconstruction, contribute to overall performance? We compare against three baseline families spanning direct in-context reasoning, agentic video memory, and retrieval-based conversational memory: (i) In-context spatial understanding. Native-video baselines use Gemini 3.7 Flash (Google, 2026) and Qwen3.8-27B-FP8 (Qwen Team, 2026), each given the video prefix and timestamped conversation before the query at 1 fps. Frame-based baselines use uniform sampling, AKS, and FOCUS (Tang et al., 2025; Zhu et al., 2026), with selected frames capped by a fixed visual-token budget and provided to GPT-5.6 Terra (OpenAI, 2026) and GLM-5.3 Flash (Z.ai, 2026). (ii) Agentic spatial understanding with object memory. We evaluate VideoAgent (Fan et al., 2024) and the agentic video mode of Gemini 3.7 Flash. (iii) Multimodal RAG and conversational memory. We evaluate Multimodal RAG ,

Summary RAG , and M2A (Feng et al., 2026), using GPT-5.6 Terra and GLM-5.3 Flash. We also include Random and Conversation Only controls (Appendix C).

We then construct queries by combining conversational conditions with spatial operations, each represented by a deterministic program Gk that produces a ground-truth answer from corresponding facts and ScanNet geometry. For count queries near geometric boundaries, we allow a bounded answer interval to account for uncertainty in the annotated mesh (cf. App. B). (2) Writer input. For each scene-level batch, the Writer receives the relevant observations, grounded object references, facts to establish, selected queries, and preceding dialogue context. (3) Dialogue. An LLM Writer generates a natural continuation that establishes the required facts before each query while maintaining coherence across visits. (4) Compile state. An independent LLM Reader , without access to the Writer’s annotations, processes the conversation turn by turn to reconstruct grounded facts and updates available. (5) Verification. We retain a query only if all required facts precede qk, all references resolve, and executing 

Gk over the Reader-recovered state reproduces the target answer, followed by human verification. We evaluate all methods using the following two metrics. 

Answer accuracy. Our primary metric is answer accuracy. For object-identification questions, the model returns a natural-language description of the selected object. We use a VLM only to map this description to a ground-truth object, using reference images, bounding boxes, and spatial information. Accuracy is determined by whether the mapped object matches the ground-truth object (see Appendix F for details). 

Object recall. To verify that a method recovers the objects needed rather than guessing the count, we ask each answer model to also return the object descriptions supporting its count and map them to physical objects using the same VLM. Let Rk be the ground-truth objects required for count query qk, and ˆRk the objects returned by the model. 5.2 Results 

RQ1.. We first compare SpaC-MEM with existing methods. As shown in Tab. 2, SpaC-MEM achieves the highest overall accuracy on Ego-SpaCR (52.5%), outperforming the strongest baseline (43.1%) using GPT-5.6 Luna as the answer model. The advantage becomes larger on more demanding spatial queries: SpaC-MEM reaches 61.4% on C4, compared with 37.3% for the strongest baselines, while remaining competitive on the rest. SpaC-MEM also maintains stronger accuracy as recall breadth and the number of prior frames before query increase. Importantly, it achieves this performance using only about one quarter of the reference input tokens required by native-video methods, showing that an explicit object-centric memory can preserve the information needed for SpaCR without repeatedly processing the full multimodal history.

B.2 Tasks, personas, and conversational state 

The five task settings give the conversation a reason to retain information about particular objects. An inventory can concern ownership and provenance; a room tour can establish functions and local names. Lab or office setup introduces responsibilities and access; workspace setup introduces intended uses and preferences; and cleaning and organizing distinguishes condition from a decision about what to do. We pair each task with a compatible persona and one of its three authored narrative variants. The role and way of speaking remain stable across visits. A task or persona frames the dialogue; an object acquires a semantic property only when the conversation establishes it. We write an object-specific fact as ϕ = ( o, p, x ), with physical object o, property p, and value x, and retain when it was stated. The fact pool may include later updates. A correction replaces an earlier value, including for retrospective questions; a state change starts a new period while preserving the earlier value for questions about the past. The query program uses the value applicable to its temporal scope. References are grounded in the observation and dialogue history available at the turn where they occur. A class name can identify an object when the context makes it unique. Otherwise, an appearance, spatial relation, established name, or clarification distinguishes it from similar objects. Descriptions tied to a particular view are used in the window where they were checked; an established name can carry the reference into later visits. This gives the Reader a recoverable link between conversational facts and ScanNet objects.

B.4 Query construction and recall 

The four spatial complexity classes follow Sec. 3. Qualitative and geometric predicates operate on objects and measurements from the same source scene, even when a question aggregates results across scenes. Counterfactual predicates use objects already observed and evaluate a hypothetical viewpoint or placement against the available scene geometry. Recall-oriented questions require the complete set of objects satisfying both the conversational and spatial conditions. We retain that set alongside the final answer so a correct count can be checked against the objects that support it. 

B.5 Ground truth and answer evaluation 

Let Φ<k be the Reader-recovered facts established before qk, resolved for its temporal scope, and G≤tk the ScanNet spatial evidence available up to tk. We compute the canonical answer by executing the question program over that prefix: 

ak = Exec( Gk; Φ <k , G≤tk ). (1) Execution also records the qualifying objects and the spatial measurements that support the answer. This matters for a count: two methods can return the same integer while identifying different objects. For count questions involving measured geometric boundaries, we retain the literal comparison in Gk and record how far each candidate lies from the boundary. Candidates clearly inside contribute to the lower count 

Lk; those within the measurement tolerance also contribute to the upper count Uk. The accepted answer is any integer in [Lk, U k]. We use a 0.04 m tolerance for distance and extent comparisons, reflecting the resolution of the annotated ScanNet mesh. During query selection, we bound the interval width to two counts. When no candidate lies near the boundary, Lk = Uk = ak. This treatment preserves the stated spatial condition while allowing for small measurement differences at its edge. Models still return a single count. We score it by membership in the accepted interval when one applies; other count answers and Boolean answers use exact matching. For object identification, a VLM maps the model’s natural-language description to a physical object using the observations available before the question. The mapped object is compared with the target fixed by Gk. Ambiguous descriptions remain unresolved. Models see neither the hidden object identifiers nor a candidate answer list. 

B.6 Verification and quality review 

We check each realized question against the Reader-recovered prefix. Its required facts must have been stated before the question, its references must resolve at the turns where they are used, and its objects and spatial evidence must be available by the query time. We execute the program again at the realized placement and retain the question when the result agrees with the planned answer. This also checks that conversational updates and optional facts have preserved the intended temporal and semantic conditions. Visual descriptions used for object answers must provide enough evidence for reliable grounding. Human review examines the resulting video and dialogue for semantic grounding, reference resolution, temporal scope, conversational plausibility, and answer correctness. The automated checks and this review address different failure modes: execution checks the formal conditions, while the review checks that the question and conversation express them clearly.

D Reference Input Cost 

Provider-reported input-token counts are not directly comparable across our baselines because different models use different text tokenizers and visual tokenization schemes. We therefore report reference input tokens , a model-independent measure of the context delivered to the final answer model. The goal is not to reproduce provider billing, but to compare how much textual and visual context each method requires at query time. For method m answering query q, we define 

Tref (m, q ) = |tok o200k (sm∥um,q )| + cframe Fm,q ,

where sm and um,q are the system and user prompts actually provided to the answer model, and Fm,q is the number of RGB frames provided with that request. We tokenize all text using the same o200k_base 

tokenizer. All visual inputs are evaluated at 640 × 480 resolution and assigned a common reference cost of one token per 32 × 32 patch, giving cframe = ⌈640 /32 ⌉⌈ 480 /32 ⌉ = 300 reference tokens per frame. For image-based methods, Fm,q is the number of attached images; for native-video methods, it is the number of frames sampled into the causal video input at 1 fps. This measure is computed offline from saved answer requests and is applied identically across methods. It measures the context exposed to the final answer model rather than total pipeline compute: retrieval embeddings, summary generation, memory updates, agent tool calls, output tokens, and evaluation calls are excluded. Internal frame re-inspection by agentic methods is likewise not charged again because it does not change the context of the final answer request. For text-only runs whose complete prompts were not retained, we use the recorded input-token count only when the serving tokenizer matches o200k_base . We report the mean Tref over all scored answer requests for each method. 

E Additional Method Details 

E.1 Object reconstruction and consolidation  

> Geometry..

We use the DA3-Nested-Giant-Large checkpoint of Depth Anything 3 (Lin et al., 2025) as fgeo ,yielding approximately metric geometry. SpaC-MEM places all frames of a scene in one shared coordinate system, with camera intrinsics, poses and depth all estimated from the RGB frames alone. Only pixels whose depth in ˆDt is estimated with high confidence are lifted into 3D. The scene’s axes are aligned with its dominant planes: the vertical axis with the floor plane or, when too little floor is visible, with walls facing different directions or the largest horizontal surface, and the horizontal axes with the dominant wall direction, so that axis-aligned boxes follow the room’s layout. The floor is placed at height zero.  

> Segmentation and lifting..

Wall and floor are excluded from L, since they form the scene’s structure rather than objects. Instances are kept when fseg is sufficiently confident, which keeps spurious detections out of the memory. Where the model also ranks alternative classes, the next most likely ones are kept as runner-up classes. To decide which mask pixels are consistent with the object, SpaC-MEM uses the mask’s interior, 

> 21 Spatially Grounded Conversational Memory for Egocentric Assistants

away from its boundary, as a reference: ˜Mt,i keeps the pixels of Mt,i whose depth lies within the interior’s central depth range, widened by a small tolerance. Edge pixels whose depth matches the object are therefore kept, including thin parts such as chair legs. The centroid μt,i is the mean of ˆPt,i , and the box Bt,i spans ˆPt,i 

along each axis of the scene’s coordinate system, excluding the most extreme few points, which makes it robust to stray points.  

> Observation matching..

Each observation ˆot,i is compared with the objects in the scene’s pool that carry its class label. Their overlap A(ˆ ot,i , ˆo) is the share of the points of ˆot,i that lie within 10 cm of the accumulated points of ˆo. The match at(ˆ ot,i ) is accepted when this share is large enough and clearly exceeds that of every other candidate. All observations of a frame are matched jointly, and each object takes at most one of them, since an object appears only once in a view. This keeps neighbouring objects of the same class apart even when they are seen together. A matched observation adds its points to ˆo, updating s≤t(ˆ o). The class label of 

ˆo is the one best supported across its observations, and other well-supported classes are kept as runner-up classes.  

> Pool refinement..

Two objects in the pool are merged when their 3D points overlap substantially, they never co-occur in the same frame, and they either share a track from fseg or have similar appearance. Overlapping pieces that never co-occur are likely views of one object, and the shared track or appearance keeps distinct objects that happen to overlap apart. Each object is kept once it is confirmed by several observations. Isolated points are removed before the final box is computed, so that each box follows the object’s main body.  

> Class labels and runner-up classes..

Each persistent object carries one class label together with up to two runner-up classes, retained as secondary label evidence. Both the association model and the answering agent are told that these describe a single persistent object rather than additional objects, and that an object carrying a queried class label outright is preferred over one listing it as a runner-up. An object with no credible runner-up carries none.  

> Coordinates..

Each scene retains its own levelled coordinate frame with approximately metric scale. Spatial predicates are evaluated within a scene, and cross-scene queries aggregate their results, so a shared origin and orientation across scenes are unnecessary. 

E.2 Dialogue association and working memory  

> Association model..

For each query, fassoc receives the preceding dialogue and objects observed by the query time, grouped by scene. Each object has an identifier, class labels, centroid and bounding box. Turns are supplied in order with objects visible within two seconds, restricted to the available query prefix; the query itself is withheld. The model resolves class descriptions, pronouns and established names using this context. It returns a turn, object, referring phrase and role for each association, with identifiers constrained to the supplied inputs. Only subject roles enter ˆAk: in “the monitor beside the laptop is Sam’s,” the monitor is the subject and the laptop is a locator . A unique class mention can help resolve a reference but does not establish a subject role by itself. References without an identifiable subject remain unassigned.  

> Contents of the working memory..

Wk holds one record per persistent object observed up to tk, grouped by scene and session and ordered by class label within a scene. Each record carries the object’s class label and runner-up classes, its centroid and axis-aligned bounding box, the frame at which it first came into view, and the camera position at that frame, which the egocentric queries use as the position the user was standing at. Beneath the record sit the dialogue turns associated with the object, verbatim and in conversational order, each annotated so that the phrase referring to this object is marked. A turn about several objects therefore appears under each of them with a different phrase marked, and the answering agent is instructed to read the clause carrying the mark as the statement about that object. A table mapping days to scenes precedes the records, and ˆOtk follows them.

F VLM Judge for Object Identification 

Object-identification queries require a method to name a single physical object in free-form text, for example, “Which single thing I said was an early priority was near a copier?” Correctness must therefore be determined by resolving the generated description to the ground-truth object. A target-only judge that sees only evidence for the correct object is too permissive in this setting: a generic answer such as “the table” may be accepted whenever the target is the only table in the displayed frame, even when several tables satisfy the query’s conversational condition. Such a judge can therefore reward class-level guessing without establishing that the method resolved the spatial condition.  

> Candidate-resolution procedure..

For each identification query, we first construct the candidate set from objects satisfying its conversation-derived condition. This set is fixed by the benchmark program before method evaluation and always contains the ground-truth target. Every candidate is then presented uniformly: one RGB frame is selected where its ground-truth instance mask is largest, only that object is boxed and assigned a letter, and candidates are shuffled with a fixed per-query seed. The judge is not told which candidate is correct. Each candidate is accompanied by its object class, conversation facts, first-seen day, and a compact scene graph computed from ground-truth geometry. The graph contains objects within 3 m of the centroid, ordered nearest first, together with on and supports relations; the benchmark definitions use near ≤ 1.5 m and far 

≥ 3 m. This context allows descriptions such as “the pillow by the whiteboard” to be checked even when the referenced neighbour is outside the selected frame. Given a model answer, the judge returns every candidate consistent with the answer’s own description using object class, appearance, dialogue names and facts, and location claims. To avoid solving the query on behalf of the evaluated method, the judge does not apply the query’s selection rule itself. Thus, a class-only answer or a restatement of the conversational condition remains compatible with every otherwise matching candidate. The judge also ignores location claims that merely repeat the query’s own reference object; only additional location evidence supplied by the answer may eliminate a candidate, and only when that claim is clearly inconsistent with the candidate’s scene graph. An answer is correct if and only if the resolved candidate set contains exactly the ground-truth target. We use three independent judge calls at temperature 0 and take the majority verdict. Count and Boolean queries remain scored deterministically; the candidate-resolution judge is used only for object-identification queries. To validate the judge, 500 identification answers sampled across 12 baselines were independently verified by a human annotator using the same candidate presentation.
