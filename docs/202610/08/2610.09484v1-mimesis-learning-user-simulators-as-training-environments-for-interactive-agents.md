## 摘要
交互式语言智能体的训练与评估通常需要丰富的用户交互，但收集人类反馈成本高昂且难以规模化。模拟用户为此提供了一种可扩展的替代方案，但它们既要模拟真实用户行为，也要为智能体提供有益的学习体验。相比之下，大多数智能体训练框架依赖现成的助手型大语言模型；这些模型乐于助人的特性可能使其相较于真实用户表现得过于配合、表达过于直白，且行为模式趋于同质化。我们推出 MIMESIS，这是一款专为此目的构建的用户模拟器，基于人类对话进行训练，并采用明确的推理监督以及从真实用户交互中提炼出的 13 种现实行为模式。在实证评估中，我们的 9B 模型取得了 65.7 的 SOUL-Index，超过了表现最强的前沿模型。与在 RealUserSim 和 SimulatorArena 上表现最强的基线模型 Claude-Opus-5 相比，MIMESIS 的行为保真度提高了 13.4 分，图灵距离分别降低了 3.6 分。随后，我们冻结该模拟器，并通过与其交互进行多轮强化学习来训练智能体。在八个环境中，与使用 GPT-5.5 训练相比，使用 MIMESIS 训练的智能体在全部九种未见过的用户模拟器上均取得更佳表现，展现出对新用户模拟器更强的泛化能力。此外，我们提出教练式在线策略自蒸馏（Coached On-Policy Self-Distillation，CSD），利用模拟器生成的私有推理轨迹及后续话语，作为智能体满足用户需求情况的反馈。教练将这些信息转化为简洁的指导说明，指出智能体如何更好地预判用户需求，并在交互过程中调整自身行为。CSD 将这类反馈转化为密集的、细化到 token 层面的监督，弥补稀疏任务奖励的不足，并在全部九种评估用户模型上进一步提升表现。

## Abstract
Training and evaluating interactive language agents typically requires rich user interactions, yet collecting human feedback is expensive and difficult to scale. Simulated users offer a scalable alternative, but they must both resemble real user behavior and provide useful learning experiences for agents. In contrast, most agent-training frameworks rely on off-the-shelf assistant LLMs, whose helpfulness can make them overly cooperative, explicit, and behaviorally homogeneous compared with real users. We introduce MIMESIS, a purpose-built user simulator trained on human conversations with explicit reasoning supervision and 13 realistic behavioral patterns derived from real user interactions. Empirically, our 9B model achieves a SOUL-Index of 65.7, surpassing the strongest frontier model. Compared with Claude-Opus-5, the strongest baseline on RealUserSim and SimulatorArena, MIMESIS improves behavioral fidelity by 13.4 points and reduces Turing distance by 3.6 points, respectively. We then freeze the simulator and train an agent by interacting with the frozen simulator using multi-turn reinforcement learning. Across eight environments, training with MIMESIS yields better agent performance than training with GPT-5.5 under all nine unseen user simulators, demonstrating stronger generalization to new user simulators. Moreover, we propose Coached On-Policy Self-Distillation (CSD), which leverages simulator-generated private reasoning traces and subsequent utterances as feedback on how well the agent addresses user needs. A coach converts this information into concise coaching notes that describe how the agent can better anticipate user needs and adapt its behavior over the course of an interaction. CSD turns this feedback into dense, token-level supervision beyond sparse task rewards, yielding further gains across all nine evaluation user models.

## 1. 核心问题与整体含义

### 1.1 研究背景与动机

- 多轮交互智能体不仅需要回答正确，还必须持续维护状态、识别缺失信息、保留约束、理解用户反馈，并从错误中恢复。
- 真人交互数据最直接，但收集成本高、难以复现，也难以支撑大规模强化学习。因此，许多框架使用大语言模型模拟用户。
- 问题在于，**助手型模型不一定是合格的用户模型**：
  - 前沿助手模型往往过度配合、主动披露信息，使任务显得过于简单。
  - 未专门适配的模型又可能不合理地阻碍任务，使任务过难。
  - 这些偏差不仅影响对话风格，还会改变智能体训练时接触到的成功、失败与纠错轨迹。

### 1.2 核心研究问题

论文尝试同时回答两个问题：

1. 能否训练出更贴近真实用户行为、且保留真实交互难度的模拟器？
2. 这种模拟器是否能提供更有价值的训练经验，使智能体面对陌生用户模型时表现更好？

### 1.3 整体含义

- 论文主张，用户模拟器应沿两条轴线评价：
  - **人类行为保真度**：是否像真实用户一样交流、披露信息和回应错误。
  - **下游学习效用**：与其训练的智能体能否迁移到其他用户。
- 这将模拟器的定位从“生成自然语言的角色扮演工具”提升为“决定训练轨迹分布的交互环境”。

## 2. 方法论：核心思想与关键技术

整体采用两阶段流程：**先训练用户模拟器，再冻结模拟器训练智能体**，并非用户与智能体同步共同优化。

### 2.1 阶段一：训练 MIMESIS 用户模拟器

使用 Qwen3.5 的 4B、9B 骨干，依次进行三步训练。

#### （1）用户侧中期训练：反转对话学习目标

- 将历史用户与助手消息作为上下文，预测**人类用户的下一条消息**。
- 助手回复只作为条件，不作为预测目标。
- 目的在于将模型从默认助手角色适配为用户角色，学习真实用户的表达与回应方式。

#### （2）ThoughtTrace 显式思考监督

- 普通日志仅记录“用户说了什么”，通常没有记录“为什么这样说”。
- ThoughtTrace 提供用户自述的发言动机及对助手回复的反应。
- 模型学习先生成私有思考，再生成公开用户话语；交互时仅将公开话语交给智能体。
- 这些自述是潜在用户状态的**代理监督信号**，不等同于完整、客观的人类心理状态。

#### （3）联合多领域强化学习

- 从思考监督后的检查点出发，在论文所称的 **23 个 SOUL 任务与 1 个真实行为任务**上联合训练。
- 所有任务更新同一个模型，而不是分别训练专家再蒸馏。
- 使用 GRPO；具体实现采用 FoldGRPO，避免同一轨迹的重复片段在组内奖励统计中被重复计数。

### 2.2 13 类真实用户行为及其奖励

论文利用 GPT-5.6 对 ThoughtTrace 对话进行行为标注与标签合并，得到：

- 隐藏评价标准、逐步追加要求、不配合澄清、坚持不可行请求；
- 信息不足后责怪助手、突然切换意图、叠加限制、虚假前提；
- 急躁但低信息量的催促、放弃未完成话题、自相矛盾；
- 一次提出过多要求、贬低或特权式施压。

训练将这些行为置于 ABCD 客服场景，要求模拟器与冻结的客服智能体交互，并依据场景事实和服务政策表现行为。

- 另设中性条件，占行为任务数据的 **三分之一**，避免模拟器始终不合作。
- 每段交互最多生成 8 个模拟用户回合。
- 行为奖励由四项加权组成：
  - 行为体现：权重 2.0；
  - 出现时机：1.5；
  - 自然度：1.0；
  - 任务一致性：0.5。
- 总和除以 5；若模型只是描述“我现在要表现某种行为”，而没有真正通过交互体现，则奖励减半。
- **任务一致性只是软奖励，不是硬约束**，因此高总分仍可能包含事实或政策违规。

### 2.3 阶段二：冻结模拟器，训练交互智能体

- 冻结 MIMESIS-9B，训练 Qwen3-8B 智能体。
- 智能体根据公开历史生成回复；模拟器随后生成私有思考和下一条公开用户消息。
- 按完整交互轨迹的任务奖励进行多轮 GRPO 更新。
- 只有智能体生成的 token 参与策略损失；用户消息和工具输出仅作为上下文。

### 2.4 CSD：教练式在策略自蒸馏

CSD 用于补充稀疏任务奖励无法说明的“哪里需要改进”。

**算法流程：**

1. 智能体根据公开历史生成回复。
2. 模拟器生成私有思考与后续公开反应。
3. 教练模型结合上述信息，事后生成简短改进建议。
4. 同一个已采样回复分别由两种上下文评分：
   - 学生：仅看到公开历史；
   - 教师：额外看到教练建议，是当前智能体的停止梯度副本。
5. 计算每个 token 的教师与学生对数概率差，经 sigmoid 转为 0—1 权重。
6. 对原回复做加权似然训练，并与 GRPO 损失相加。

关键区别与边界：

- **不生成替代答案，也不直接匹配教师完整输出分布**，而是重新加权已经采样的回复。
- 教师更认可的 token 被更强地强化；不认可的 token 只是受到较弱强化，**不会被 CSD 直接惩罚**。
- 教练建议属于事后、仅训练使用的信息；部署时智能体仍只依赖公开对话。
- 配置为辅助损失权重 α＝0.01、门控敏感度 β＝5.0。

### 2.5 理论分析

- 加权似然的理想目标，相当于将原策略概率乘以期望教练权重后重新归一化。
- 是否改善回报，取决于**教练权重与动作后续价值是否正相关**，而不只是权重非负。
- 理论没有保证实际共享参数更新每步都改善，也没有保证迁移到不同模拟器或真实用户。

- 三次评估种子不能替代多次独立训练；智能体主要结果未报告多训练种子置信区间。
- 九个评估用户均为模型，不能取代真实人类测试。
- API 模型虽固定推理配置，但不同供应商推理预算并不相等。
- GPT-5.5 同时参与部分训练奖励及评估判断，存在判断偏好影响结果的风险。
- SOUL 既用于训练也用于评估，成绩更能证明该任务体系内的效果；训练评估重叠及去重情况仍值得进一步核查。
- “九种用户模型下均提升”指**跨环境汇总分数**，并非每个用户—环境单元都提升。
- 不同环境奖励尺度不同，论文补充平均排名是合理做法，但汇总分数仍需与环境级结果一起解读。

## 6. 主要结论与发现

### 6.1 通用助手模型会扭曲交互难度

同一个 GPT-5.5 智能体在 τ-bench 上：

- 真人用户：成功率 **63.6%**。
- 前沿 API 模拟用户：**82.4%—84.4%**，明显偏容易。
- MIMESIS-9B：**66.1%**；MIMESIS-4B：**65.5%**，更接近真人。

说明“用户模型更聪明、更配合”不等于“用户模拟更真实”。

### 6.2 模拟器表现显著改善，但并非所有指标第一

| 指标 | MIMESIS-9B | 主要比较 |
|---|---:|---|
| SOUL 总分 | 65.7 | Claude-Opus-5：64.9 |
| RealUserSim 保真度 | 94.0 | Claude-Opus-5：80.6，提升 13.4 分 |
| τ-USI 五项指数 | 80.17 | 高于 GPT-5.5 的 76.69，但略低于 Osim-8B 的 80.44 |
| τ-bench ECE，越低越好 | 0.069 | GPT-5.5：0.188；Osim-8B：0.135 |
| SimulatorArena 图灵距离，越低越好 | 38.7 | Claude-Opus-5：42.3 |
| PRISM 行为均分 | 80.1 | Gemini：79.7；两者差距相对误差较小 |

- 最大优势主要来自多轮信息交换与节奏，而非接近饱和的人格匹配。
- MIMESIS 的图灵距离虽最低，仍远离 0，**不意味着已无法与真人区分**。
- 前沿模型仍在部分社会模拟、角色扮演和显式风格评分上领先。

### 6.3 更好的模拟器带来更好的跨模拟器泛化

九种评估用户下的平均分：

- GPT-5.5＋GRPO：**26.10**。
- MIMESIS＋GRPO：**29.54**。
- MIMESIS＋CSD：**31.09**。

更换模拟器提升约 3.44 分，CSD 再提升约 1.55 分；九种用户的汇总成绩均呈同样顺序，但部分具体环境出现退步。

### 6.4 消融支持各训练阶段的作用

- 显式思考监督恢复了仅话语监督后被压制的推理生成；Mistakes 准确率由无 ThoughtTrace 的 RL 条件 **36.0** 提升至 **63.0**。
- 真实行为训练使：
  - RealUserSim：92.3 → 94.0；
  - τ-USI：73.9 → 80.2；
  - 图灵距离：41.0 → 38.7。
- 行为训练主要改善行为体现及出现时机，对自然度与任务一致性的提升较小。

## 7. 优点与亮点

- **问题定位准确**：识别了助手模型的合作倾向如何改变训练和评价难度，而不只关注生成文本是否自然。
- **连接保真度与学习效用**：既评价模拟器本身，也检验其能否训练更具迁移能力的智能体。
- **监督层次丰富**：结合真实话语、用户自述、行为类别和交互奖励。
- **行为训练有场景依据**：将不合作行为绑定到事实和政策，并加入中性条件，避免纯粹制造障碍。
- **CSD 复用已有回复**：不必额外解码修订答案，同时保持部署阶段不依赖私有反馈。
- **对照较清晰**：分离模拟器选择与优化目标的贡献，并加入 InfoPO。
- **失败分析透明**：明确指出人格特征放大、模拟器拒绝及任务目标偏离，理论分析也没有夸大保证。

## 8. 不足与局限

### 8.1 人类迁移尚未验证

- 最关键的下游泛化实验仍局限于模型用户。
- 多个模型可能共享行为偏差；跨模型有效不一定等于对真人有效。
- 缺少用户满意度、信任、任务完成体验等真实交互结果。

### 8.2 行为分类与反馈存在偏差

- 13 类行为基于单一 ThoughtTrace 样本，并借助 GPT-5.6 分类，可能受初始编码框架和标注模型判断影响。
- 分类偏重困难或非合作行为，未全面覆盖文化、能力、语言及长期使用差异。
- 类别采样不等于真实人口行为频率，不能据此宣称还原了真实用户分布。
- 私有思考是模型生成解释，可能并不对应真实人类心理状态。

### 8.3 行为真实性与任务可行性难以兼顾

- 行为条件可能放大特征：案例中，MIMESIS-9B 将隐私顾虑发展为持续拒绝认证，而真人最终配合。
- 软奖励允许某一维度的高分补偿事实或政策违规。
- 所以“交互更难”并不自动代表“交互更真实”。

### 8.4 CSD 的有效性取决于教练质量

- 错误或价值不对齐的建议可能强化不合适 token。
- CSD 不直接惩罚低权重 token，也不提供新的正确答案。
- 缺少充分的反馈来源分解，例如仅用公开反应、仅用私有思考、去除教练或更换教练。
- 尚不清楚其收益与额外模型评分、API 成本之间的权衡。

### 8.5 评价有效性与统计可靠性仍有限

- LLM 判断指标容易受风格偏好和模型家族影响。
- 智能体训练时间较短，缺少更长训练、更多骨干规模和多训练种子结果。
- Claude-Opus-5 在 PersuadeGym 的角色拒绝导致零奖励；论文正确指出，这些零分是**模拟器失败，而非智能体能力测量**，也提示汇总评估必须严格处理无效环境。

### 8.6 任务奖励不等于用户福祉

- 更高任务回报可能伴随操纵、欺骗或不尊重用户自主性，尤其在说服任务中。
- 论文没有衡量用户长期福利、信任和自主性。
- 因此，更稳妥的结论是：**MIMESIS 改善了所测模拟环境中的保真度与智能体迁移成绩，但真实应用效果及安全性仍需人类实验验证。**
