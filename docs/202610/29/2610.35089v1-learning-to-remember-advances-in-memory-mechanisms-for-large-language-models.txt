Abstract 

Memory has become a central mechanism for extending large language models (LLMs) beyond fixed context windows, stateless interaction, and static paramet-ric knowledge. This survey organizes the literature around three complementary dimensions: the life cycle of memory, the storage substrate, and the system role that memory plays in LLM-based agents, while using cognitive-science-inspired memory concepts as a lightweight conceptual motivation rather than as a separate technical contribution or implementation family. On this basis, we distinguish three mechanism families: nonparametric memory, where information is stored outside model parameters in text, graph, multimodal, or database-like structures; parametric memory, where information is stored or accessed through activations, key-value caches, learned modules, adapter-based parameterizations, or model weights; and memory for agent evolution, where stored experiences support reinforcement learning, continual learning, procedural reuse, context engineering, and agent harness design. Evaluation is treated as a separate cross-cutting component rather than as a memory mechanism. Unlike surveys that focus primarily on retrieval-augmented generation or long-context modeling, this paper emphasizes the full memory life cycle: construction, maintenance, retrieval, consolidation, forgetting, governance, and evaluation. By aligning conceptual motivations, computational memory mechanisms, benchmarks, and deployment concerns, the survey provides a structured roadmap for designing memory-augmented LLM agents that are persistent, adaptive, auditable, and safe to update over time.

# 1 Introduction 

The rapid advancement of large language models (LLMs) has reshaped natural language processing and artificial intelligence. Scaling has improved reasoning, com-prehension, and generation (Brown et al. 2020; Touvron et al. 2023), yet conventional LLMs remain constrained by fixed context windows, static parameters, and weak mechanisms for preserving state across interactions. These limitations make it diffi-cult for models to maintain continuity, accumulate experience, adapt to changing user needs, or reason over long-horizon tasks (Bubeck et al. 2023). Memory mechanisms have therefore become a key research direction for transforming LLMs from stateless generators into adaptive agents. Introducing memory into LLMs enables models to store, retrieve, and revise infor-mation across time. In dialogue and personalization, memory supports persistent user profiles, long-term preferences, and temporal consistency, as illustrated by Memory-Bank (Zhong et al. 2024) and COMEDY (Chen et al. 2025c); in systems with explicit lifecycle operations, such as Mem0 (Chhikara et al. 2025), memory can also support correction or updating of outdated facts. In knowledge-intensive settings, memory helps agents reuse prior evidence, maintain structured knowledge, and reduce repeated retrieval. In long-horizon agent systems, memory further supports planning, reflection, skill reuse, and behavioral improvement across repeated tasks. This survey organizes LLM memory research into a lightweight conceptual-motivation layer, three computational mechanism families, and one cross-cutting eval-uation component. The conceptual layer uses cognitive-science-inspired distinctions such as episodic, semantic, working, procedural, consolidated, and context-dependent memory only to clarify the vocabulary for comparing AI memory designs; it is not treated as a standalone mechanism family or the central contribution of this survey. Among computational mechanisms, nonparametric memory stores information out-side model parameters and includes text memory, graph memory, database-backed memory, and multimodal memory. Parametric memory stores or accesses knowledge through internal states, KV caches, trainable memory modules, adapter-based param-eterizations, or direct parameter updates. Memory for agent evolution treats memory as a reusable experience substrate for reinforcement learning, continual learning, pro-cedural reuse, context engineering, and agent harness design. Separately, evaluation 

studies how these memory mechanisms are measured in plain-text, multimodal, and simulation-based environments. This distinction avoids treating cognitive analogies or benchmarks as additional storage substrates while still making both conceptual grounding and evaluation central to the survey. The central contribution of this survey is a conceptual-motivation–lifecycle– substrate–role–evaluation alignment framework for comparing LLM memory research. Instead of grouping systems only by implementation type, this framework aligns five questions: which conceptual memory distinctions motivate the design without 2themselves constituting a memory mechanism, what lifecycle operations a memory mechanism supports, which substrate realizes the memory, what role the memory plays in an LLM-based system, and how the claimed benefit is evaluated. On this basis, the contributions of this survey are threefold. (1) We provide a consolidated map of LLM memory systems that uses cognitive-science-inspired concepts only as a com-pact vocabulary for motivating three computational memory-mechanism families and the evaluation resources used to test them. (2) We analyze representative methods through a shared set of lifecycle questions: what is written, where it is stored, how it is retrieved, how it is updated or forgotten, how persistent it is, and how it is governed. (3) We synthesize benchmark trends and future challenges, highlighting where existing systems still struggle with reliable writing, temporal updates, privacy, deletion, hallu-cination control, and long-horizon utility. This alignment-oriented framing makes the relationships among conceptual motivation, memory substrates, system roles, evalua-tion protocols, and deployment risks explicit, thereby providing a common basis for comparing otherwise heterogeneous memory-augmented LLM systems. 

## 1.1 Scope and Literature Selection 

This survey focuses on methods in which memory is an explicit design object rather than a generic byproduct of long prompts or model scale. The literature was selected by combining keyword-driven search with backward and forward citation tracing. Search terms included combinations of LLM memory , agent memory , long-term memory ,

episodic memory , semantic memory , procedural memory , graph memory , multimodal memory , KV cache , model editing , memory benchmark , and self-evolving agents . The search covered peer-reviewed venues, preprints, benchmark papers, benchmark repos-itories, system documentation, and project pages when they introduced a concrete memory architecture or operational interface. We include systems that specify how memory is written, stored, retrieved, updated, compressed, forgotten, governed, or evaluated. The reviewed literature covers external memory stores, graph-based memory, multimodal memory, KV-cache and activation memory, weight- or module-level memory, self-evolving agents, cognitive-science mem-ory analogies, and benchmarks that test memory persistence or long-horizon behavior. A method is included when memory is central to the mechanism or evaluation claim, not merely an incidental implementation detail. We exclude methods that only perform one-off retrieval, prompt compression, or long-context inference unless they directly address memory persistence, lifecycle management, update behavior, or memory-guided future action. This scope makes the paper a mechanism-centered survey rather than a general survey of RAG, long-context modeling, or agent frameworks. 

## 1.2 Memory, RAG, and Long Context 

Memory overlaps with retrieval-augmented generation (RAG) and long-context mod-eling, but it is not identical to either. RAG is primarily retrieval-centered: the original RAG formulation retrieves Wikipedia passages from a dense vector index with a neural retriever, while later RAG-style systems may use sparse, dense, or hybrid 3retrieval (Lewis et al. 2020; Karpukhin et al. 2020). Long-context modeling is capacity-centered: the system attempts to process more tokens within a single inference context. Memory is lifecycle-centered: it requires decisions about what to store, how to rep-resent it, when to update it, how to resolve conflicts, how to delete it, and how to evaluate whether it improves future behavior. This distinction is important because a system may have a long context window or a retriever without having reliable long-term memory. The remainder of this paper is organized as follows. Section 2 introduces the organizing framework and memory life cycle. Section 3 briefly explains the cognitive-science-inspired vocabulary used only as conceptual motivation. Section 4 reviews nonparametric memory. Section 5 discusses parametric memory. Section 6 sur-veys memory for agent evolution. Section 7 reviews benchmarks and evaluation environments. Section 8 discusses open challenges, followed by the conclusion. 

# 2 Overview 

Research on memory in LLMs has expanded from early long-context retrieval and dialogue summarization to an ecosystem of memory stores, memory operating sys-tems, graph memories, multimodal memories, parametric memories, and self-evolving agents. To organize this literature, we use cognitive-science-inspired memory concepts only as conceptual motivation , and compare computational methods along three com-plementary dimensions: the life cycle of memory, the form or substrate of memory, and the system role played by memory. Based on these dimensions, Figure 2 presents the taxonomy used throughout this survey. The taxonomy now separates a compact conceptual motivation layer from the computational mechanism families. Cognitive-science-inspired concepts motivate how memory can be decomposed and evaluated, but the computational analysis cen-ters on three families: nonparametric memory, parametric memory, and memory for agent evolution. Evaluation is shown alongside these families as a cross-cutting compo-nent because benchmarks determine whether a proposed memory mechanism actually improves persistence, update behavior, grounding, and long-horizon utility. ## 2.1 Memory Life Cycle 

Although implementations differ, most memory systems can be analyzed through five recurring operations. Figure 1 summarizes these operations as a lifecycle from memory construction to governed reuse in the LLM context. 

• Construction transforms raw interactions, documents, visual streams, or model states into memory units. Text systems summarize conversations into facts or episodes (Zhong et al. 2024; Chhikara et al. 2025); graph systems extract entities, 4relations, and events (Jim´ enez Guti´ errez et al. 2024; Rasmussen et al. 2025); mul-timodal systems segment long videos or screen streams into captioned events (Lin et al. 2025b; Wang et al. 2024b). 

• Management maintains memory quality through compression, deduplication, con-flict resolution, forgetting, temporal decay, permission control, versioning, and cross-session synchronization. Mem0 (Chhikara et al. 2025) and MemOS (Li et al. 2025b) make memory maintenance explicit through update operations and lifecycle governance. 

• Retrieval selects relevant memory and reintroduces it into the active reasoning con-text. Retrieval may rely on sparse retrieval such as BM25 (Robertson and Zaragoza 2009), dense neural retrieval such as DPR (Karpukhin et al. 2020) or the original RAG (Lewis et al. 2020) retriever, later hybrid retrieval, graph traversal, temporal filters, symbolic queries, or LLM-guided search (Wang et al. 2025a). 

• Consolidation and forgetting decide which memories should become durable, be merged into higher-level abstractions, or be discarded. This operation is increasingly important in long-running agents, where unconstrained accumulation causes noise, privacy risk, and retrieval degradation. 

• Evaluation and governance measure whether memory improves downstream behavior and whether the system remains safe, private, and auditable. This dimen-sion connects technical design to benchmark design and deployment requirements. CONSTRUCTION MANAGEMENT RETRIEVAL CONSOLIDATION GOVERNANCE

## 2.2 Foundations, Forms, and Roles of Memory 

The second dimension categorizes where and how memory is represented, while the conceptual-motivation layer clarifies why particular distinctions matter. Con-ceptual motivation is not a separate storage technology; instead, it provides lightweight distinctions such as episodic versus semantic memory, working versus long-term memory, procedural memory, consolidation, forgetting, context binding, and 5prediction-error-driven updating. Nonparametric memory stores information out-side model parameters and is usually interpretable, updateable, and modular, but depends heavily on construction and retrieval quality. Parametric memory stores or accesses information through internal model states, trainable modules, KV caches, adapter-based parameterizations, or weights; it can be tightly integrated with inference but is harder to inspect and edit. Memory for agent evolution stores interaction traces, rewards, failures, workflows, code traces, and other experience artifacts so that agents can improve their future behavior. Evaluation is not a memory substrate; it is the empirical layer used to determine whether these designs produce reliable long-term behavior rather than superficial recall.

# 3 Conceptual Motivation from Cognitive Memory 

This section is deliberately brief because cognitive-science-inspired memory is used here as a source of terminology and design intuition, not as a separate technical mech-anism or a primary contribution of the survey. Figure 2 therefore places it outside the three computational memory families. The relevant value of cognitive memory theory is to sharpen questions that every LLM memory system must answer: whether a stored item is an event, a fact, a temporary task state, or a reusable procedure; whether it should remain local to the current session or become long-term; and whether it should be consolidated, revised, or forgotten. Human memory research motivates this vocabulary without directly prescribing an LLM architecture. Episodic and semantic distinctions help separate event-level traces from abstracted knowledge (Tibon et al. 2026; Dong et al. 2025); working-memory accounts motivate transient state management (Allen et al. 2026); and studies of con-text binding, neural state spaces, and population codes motivate storing metadata such as time, source, scope, and retrieval conditions rather than storing decontextual-ized facts alone (Bausch et al. 2026; Horner 2026; Dupret et al. 2025). These concepts are useful because many LLM-memory failures arise from collapsing different mem-ory types into a single vector store or prompt summary. Table 3 makes this role explicit by mapping cognitive concepts to LLM-memory design implications and the corresponding risks of over-analogy. The same caution applies to consolidation and updating. Work on prediction-error updating and hippocampal–retrosplenial communication suggests that durable memory should be affected by surprise, conflict, and context, not only by semantic similarity (Groves et al. 2025; Gonzalez et al. 2026; Morrow et al. 2026). # 4 Nonparametric Memory 

Nonparametric memory stores information outside the model parameters. It is the most visible family of LLM memory methods because it supports direct inspection, deletion, correction, and cross-session persistence. In this section, we review text memory, graph memory, and multimodal memory. Text memory emphasizes compact natural-language records; graph memory emphasizes structured relations and tempo-ral organization; multimodal memory extends memory to visual, audio, video, screen, and embodied observations. Figure 4 illustrates these representative external mem-ory substrates, including database-backed memory systems that manage metadata, indexing, permissions, and persistent stores. 

## 4.1 Text Memory 

Text memory systems transform conversations, documents, tool traces, or observations into natural-language memory units. Their appeal is practical: text records are easy to inspect, edit, embed, and inject back into prompts. The main weakness is also structural: once events, relations, images, or tool states are collapsed into text, later 9TEXT MEMORY GRAPH MEMORY MULTIMODAL MEMORY SYSTEM / DATABASE MEMORY Fig. 4 Representative nonparametric LLM memory substrates. 4.1.1 Memory Construction and Consolidation 

Construction-oriented systems differ less in the fact that they summarize history than in their write policy. MemoryBank (Zhong et al. 2024) and COMEDY (Chen et al. 2025c) show the value of compact conversational summaries, whereas Mem0 (Chhikara et al. 2025), RecMem (Dai et al. 2026), SimpleMem (Liu et al. 2026a), and Light-Mem (Fang et al. 2025) put more emphasis on salience, delayed consolidation, recursive compression, or staged short-/long-term updates. Personalized and temporal-dialogue systems such as context- and time-sensitive long-term memory (Alonso et al. 2024), Reflective Memory Management (Tan et al. 2025b), MemWeaver (Yu et al. 2025c), and Adaptive Memory Distillation (Ma et al. 2025) further show that memory con-struction must decide not only how to summarize but also what deserves to become persistent, hierarchical, or reflective memory. The critical distinction is whether mem-ory writing is eager, selective, recurrent, or sleep-like. Eager writing maximizes recall but accumulates noise and private data; delayed or selective writing reduces cost and noise but can miss rare facts that become important later. A strong text-memory system therefore needs explicit criteria for salience, conflict, source attribution, and deletion, not only a better summarizer.

4.1.3 Memory Systems and Databases 

End-to-end memory platforms expose memory as an engineering interface rather than as a single algorithm. Letta/MemGPT (Packer et al. 2023) emphasizes paging between limited context and external recall or archival storage; MemOS (Li et al. 2025b) treats memory as a schedulable resource with metadata and lifecycle operations; MIRIX (Wang and Chen 2025), LangMem docs (LangChain Team 2025), Zep (Ras-mussen et al. 2025), MemU repo (NevaMind AI 2025), and OpenMemory repo (Mem0 AI 2025) illustrate the shift toward production memory APIs, user profiles, prove-nance, and cross-session state. These systems are valuable because they make memory auditable and maintainable, but their claims should be separated from benchmarked algorithmic gains: documentation-driven systems often demonstrate interfaces and deployment patterns, whereas peer-reviewed methods more often isolate retrieval, update, or consolidation mechanisms. 11 4.2 Graph Memory 

Graph memory externalizes information into nodes, edges, events, and communities. Compared with flat text memory, graphs make relations and temporal links more inspectable, but they also introduce a new dependency: the memory is only as reliable as the entity extraction, relation typing, schema evolution, and graph-maintenance policy that produced it. Knowledge graphs represent entities and relations as inter-connected nodes and edges (Hogan et al. 2021; Ji et al. 2022); in LLM memory, this representation is attractive because many long-horizon questions require tracing who did what, when, why, and under which constraints. Triple- and KG-based systems such as HippoRAG (Jim´ enez Guti´ errez et al. 2024), HippoRAG2 (Jim´ enez Guti´ errez et al. 2025), RET-LLM (Modarressi et al. 2023), KGT (Sun et al. 2024), Path Pooling (Wang et al. 2025a), and PlugMem (Yang et al. 2026a) mainly improve memory by making relational evidence retrievable. Their advantages are strongest when the task depends on multi-hop relations, personalized facts, or explainable paths. Their vulnerabilities are different from text memory: a single wrong edge can mislead several downstream paths, while aggressive graph com-pletion can turn uncertain inferences into durable facts. This makes confidence scores, provenance, temporal validity, and edge-level deletion more important than in ordinary chunk retrieval. Hierarchical and temporal graph methods, including Graphiti/Zep (Rasmussen et al. 2025), AriGraph (Anokhin et al. 2025), MemGAS (Xu et al. 2025a), Hyper-Mem (Yue et al. 2026), Mnemis (Tang et al. 2026), MAGMA (Jiang et al. 2026), and TraceMem (Shu et al. 2026), move beyond static triples by organizing memory at multiple granularities and across time. This direction is particularly relevant for agents because repeated interactions create evolving communities, goals, tasks, and causal chains rather than isolated facts. The trade-off is maintenance cost: hierarchi-cal graph memories require decisions about when to merge nodes, split episodes, retire obsolete relations, and preserve conflicting versions. Additional work on GraphRAG-style retrieval, graph readers, synthetic KGs, hierarchical generation memory, trainable graph memory, and graph-structured personal assistants (Edge et al. 2024; Li et al. 2024a; Choubey et al. 2024; Yu et al. 2025a; Xia et al. 2025b; Zhang et al. 2025h; Hu et al. 2025a) is best interpreted through this lens: the key question is not whether a graph exists, but whether graph operations provide more reliable memory use than simpler text retrieval under update pressure. 

## 4.3 Multimodal Memory 

Multimodal memory extends memory mechanisms to visual, audio, video, screen, and embodied experiences. Its central challenge is deciding what should remain as raw evidence, what should be captioned or summarized, and what should be indexed as an event. If all perceptual history is textualized, retrieval becomes cheap but grounding becomes fragile; if raw media is retained, the system preserves evidence but faces high storage, indexing, and privacy costs. 12 4.3.1 Image and Visual Memory 

Image and visual memory focuses on retaining static or sparsely changing perceptual evidence, such as image histories, screenshots, object appearances, visual preferences, and GUI observations. Compared with video memory, its main difficulty is less about dense temporal compression and more about grounding: the system must preserve object identity, spatial relations, regions, and source images so that later answers are not based only on lossy captions. DeepImageSearch (Deng et al. 2026) evalu-ates this setting through context-aware image retrieval over visual histories, where an agent must recover relevant images rather than merely recall text summaries. PersonaVLM (Nie et al. 2026) highlights personalized visual memory, storing user-specific multimodal preferences and histories so that long-term personalization can use visual evidence instead of generic user-profile text alone. Related screen and GUI memory systems, such as MGA (Cheng et al. 2025), treat interface observations as reusable visual state, requiring memory to preserve widgets, layouts, and interaction traces. Across these image-centered settings, the key design question is whether the memory keeps enough perceptual anchors–images, regions, screenshots, metadata, or embeddings–to support verification and correction after retrieval. 

4.3.2 Video and Temporal Multimodal Memory 

Video and temporal multimodal memory adds dense time, event boundaries, causal order, object trajectories, audio, and long-horizon consistency to the visual-memory problem. For understanding tasks, systems can be compared by their evidence bound-ary and write policy. Caption- and event-indexing methods such as Multi-RAG (Mao et al. 2025a), HippoMM (Lin et al. 2025b), VideoAgent (Wang et al. 2024b), and Vide-oRAG (Ren et al. 2026) primarily build timestamped textual or event memories from selected frames, audio transcripts, and captions, using retrieval to avoid feeding an entire long video into the model. More explicitly agentic systems expose video memory as a tool interface: VideoAgent (Fan et al. 2024) stores temporal event descriptions and object-centric tracking states as a structured unified memory; VideoARM (Yin et al. 2026) couples an observe–think–act–memorize loop with hierarchical multimodal memory for coarse-to-fine long-video reasoning; and GCAgent (Yeo et al. 2025a) builds schematic and narrative episodic memories that encode temporal and causal event relations for global-context-aware inference. For embodied settings, Embodied VideoA-gent (Fan et al. 2025) extends video memory with depth, pose, and other sensor-derived scene states, making memory persistent and updateable during interaction. Stream-ing systems such as HERMES (Zhang et al. 2026b), EventMemAgent (Wen et al. 2026), Visual Agentic Memory (Li et al. 2026a), and StreamMeCo (Wang et al. 2026a) further shift the focus to online indexing, hierarchical retrieval, KV- or graph-based memory, and compression. These methods show that video memory is not only a ques-tion of storing more frames: it requires selective writing, recoverable visual evidence, temporal grounding, and mechanisms for controlling storage and retrieval cost. For generation and reconstruction, memory becomes a consistency-control mech-anism. MotionRAG (Zhu et al. 2025), StoryMem (Zhang et al. 2025d), MemFlow (Ji et al. 2025), MagicWorld (Li et al. 2025a), Yume (Mao et al. 2025c), and LoGeR (Zhang 13 et al. 2026c) use retrieved motion, visual, story, world, or geometric state to prevent drift across long outputs. Related systems such as WorldMM, MemVerse, MGA, M3-Agent, Infinite Video Understanding, long-video memory models, OneStory, Yume-1.5, EgoLCD, Pack-and-Force Memory, Long-Term Spatial Memory, Mixture of Contexts, and Context as Memory (Yeo et al. 2025b; Liu et al. 2025b; Cheng et al. 2025; Long et al. 2025; Zhang et al. 2025a; Wang et al. 2025i; Li et al. 2024b; Weng et al. 2024; Wang et al. 2024d; An et al. 2026; Mao et al. 2025b; Zhang et al. 2025e; Wu et al. 2025d,b; Cai et al. 2025a; Yu et al. 2025b) show that multimodal memory is not only about recall accuracy. It must also be evaluated by grounding fidelity, temporal coher-ence, identity consistency, and whether the system can trace generated content back to the perceptual or world-state memories that controlled it. 

## 4.4 Comparative Discussion 

The main strength of nonparametric memory is controllability: memory items can be inspected, edited, deleted, versioned, and connected to explicit sources. However, nonparametric memory also exposes the system to retrieval errors, stale facts, noisy summaries, and inconsistent update rules. The most important design choice is not only which database or index is used, but also the memory unit and write policy. A system that stores every interaction risks noise accumulation and privacy leakage, whereas a system that stores only aggressive summaries may lose evidence needed for later contradiction resolution. Text memory is easiest to deploy but may discard structure. Graph memory supports relation-aware reasoning but depends on reliable extraction and maintenance. Multimodal memory preserves perceptual history but must balance compact captions against access to original visual or audio evidence. Table 5 summarizes these trade-offs.

14 5 Parametric Memory 

Parametric memory refers to mechanisms where knowledge is stored, accessed, or updated through internal model states, trainable modules, weights, or activation caches. This category includes both transient working memory and durable internal memory. Activation states and KV caches usually function as short-term or session-level memory: they extend the effective context and improve inference efficiency, but they do not necessarily persist across independent interactions. Weight edits, train-able memory vectors, and learned modules are closer to long-term parametric memory because they can survive across sessions and alter future behavior, while adapter-based methods are best viewed as parameter-efficient adaptation carriers that become memory-relevant only when tied to a concrete update, composition, or retrieval policy. Compared with nonparametric memory, parametric memory is more tightly coupled with the model and can be efficient during inference, but it is often less transparent and harder to edit safely. 15 5.1 Activation and KV-Cache Memory 

Activation and KV-cache methods are often described as memory, but their persistence is usually weaker than that of external stores or weight updates. The KV cache stores keys and values from previous tokens so the model can attend to earlier context without recomputing states; this makes it a form of working memory by default. It becomes long-term memory only when the cache, compressed states, or activation summaries are explicitly stored, retrieved, and reused across sessions. Construction-oriented methods differ in how they extend the context available to the model. Transformer-XL (Dai et al. 2019) uses segment recurrence, Memorizing Transformer (Wu et al. 2022) augments attention with stored key-value pairs, Long-Mem (Wang et al. 2023) retrieves cached KV memories through an auxiliary network, MA-LMM (He et al. 2024) stores online visual features and learned query represen-tations, and Memory 3 (Yang et al. 2024b) frames explicit memory as a storage form beyond parameters and prompt tokens. These methods improve access to prior con-text, but the memory unit is often an activation state rather than an inspectable fact. As a result, they are strong for continuity and efficiency but weak for provenance, user correction, and deletion.

## 5.2 Weight and Module Memory 

Weight and module memory is more persistent than activation memory because it changes parameters or parameter-like states that affect future inference. This persis-tence is valuable when knowledge should be compact and immediately available, but it also makes errors harder to inspect and remove. The main comparison with non-parametric memory is therefore a governance trade-off: internal memory can reduce retrieval overhead, yet it weakens source traceability and precise deletion. Model-editing methods such as ROME (Meng et al. 2022) and MEMIT (Meng et al. 2023) treat selected feed-forward weights as locations for factual associations; WISE (Wang et al. 2024a) separates main and side memory to improve locality and reliability; and MemoryLLM (Wang et al. 2024c) adds a fixed-size latent memory pool inside the transformer. Adapter-based approaches such as LoRA (Hu et al. 2022) are memory-relevant when the adapter is used as a durable carrier of task, domain, user, or preference information, but standard LoRA is not by itself an online memory system because its updates are normally fixed after training. The key criterion is whether the method specifies a write, composition, retrieval, and rollback policy, not merely whether additional parameters exist. Learned and compressive modules, including R3Mem (Wang et al. 2025e), Engram (Cheng et al. 2026), MLP Memory (Geva et al. 2021), Memory Decoder (Cao et al. 2025), GradMem (Kuratov et al. 2026), MeKi (Ding et al. 2026a), and STEM (Sadhukhan et al. 2026), further blur the line between neural computation and memory storage. Some reduce explicit retrieval costs by making memories part of the computation graph; others trade retrieval for test-time optimization or sparse lookup. Related work on activation memory, recurrent memory, sparse memory, function-token memory, explicit working memory, infinitely updatable state, memory–reasoning dis-entanglement, and contextual agentic memory (Xiao et al. 2024a; Behrouz et al. 2024; Gelberg et al. 2026; Behrouz et al. 2026; Lei et al. 2026b; Chen et al. 2026b; Zhao and Jones 2026; Huang et al. 2024; Badger 2026; Zhang et al. 2025g; Behrouz et al. 2025; Chen et al. 2025b; Chukwu and Bindschaedler 2025; Zanzotto et al. 2025; Jin et al. 2025; Xu et al. 2026) reinforces the same point: internal memory should be evaluated by persistence, locality, reversibility, interference, and privacy leakage, not only by loss or speed. 

## 5.3 Comparative Discussion 

Parametric memory is attractive when memory must be close to model computation. KV-cache methods are useful for long-context inference and serving efficiency, but they usually preserve information only for the current or cached session unless explic-itly externalized. This makes them different from persistent memory systems even though both are often discussed under the language of memory. Weight editing and learned memory modules can make memories compact and immediately accessible, 17 but they are difficult to audit and delete. Their benefits should therefore be evaluated together with locality, reversibility, interference, and privacy risk. For safety-critical or privacy-sensitive deployments, parametric memory should be paired with external provenance records, edit logs, and evaluation protocols that test whether an internal update changes only the intended behavior rather than silently spreading to unrelated contexts.

## 6.1 Reinforcement Learning and Continual Learning 

Experience-driven memory methods use previous interaction records as training or adaptation signals for future behavior. Their common goal is not merely to recall the past, but to convert past trajectories, errors, rewards, and reflections into better future action. The key design axis is how explicitly the system separates memory operations from task solving. MemAgent (Yu et al. 2026) trains an agent to update internal 18 memory while processing long contexts; Memory-R1 (Yan et al. 2025c) separates a Memory Manager with ADD, UPDATE, DELETE, and NOOP operations from an Answer Agent; and Mem-α (Wang et al. 2025g) learns to maintain multi-component memories under downstream QA rewards. This separation matters because memory writing becomes an action with consequences, not a passive log. Other systems emphasize deployment-time adaptation and self-evolution. Memento (Zhou et al. 2025), ReMe (Cao et al. 2026), EvolveR (Wu et al. 2025a), MemRL (Zhang et al. 2026e), ProcMEM (Mi et al. 2026), CASCADE (Huang et al. 2025), and SEDM (Xu et al. 2025b) use accumulated experiences, cases, procedural abstractions, or distributed self-evolving memories to improve repeated tasks with-out always fine-tuning the backbone model. Recent work on contextual replay, skill optimization, fast-and-slow learning, long-horizon engineering agents, memory bot-tlenecks, neural garbage collection, predictive forgetting, test-time learning, nested learning, and task-core memory (Liu et al. 2025c; Yang et al. 2026b; Tiwari et al. 2026; Qiao et al. 2026; Xie et al. 2026; Chen et al. 2026a; Wang et al. 2026b; Sidik and Rokach 2026; Li et al. 2026b; Fountas et al. 2026; Tandon et al. 2025; Liu et al. 2025d; Zhang et al. 2025c; Yang et al. 2025; Zheng et al. 2025b; Yan et al. 2025a; Sun et al. 2025; Behrouz et al. 2025; Lan et al. 2025; Lampinen et al. 2025; Zhang et al. 2025b; Wu et al. 2025c; Lin et al. 2025a; Huai et al. 2025) broadens the same theme. The unresolved issue is credit assignment: a system must determine which remembered experience caused improvement, which merely correlated with success, and which should be forgotten before it hardens into a brittle strategy.

## 6.2 Procedural and Skill Memory 

Procedural memory stores reusable action knowledge rather than factual content. Agent Workflow Memory (Wang et al. 2025j), MemSkill (Zhang et al. 2026a), Reason-ingBank (Ouyang et al. 2026), Memento-Skills (Zhou et al. 2026), AgentEvolver (Zhai et al. 2025), FLEX (Cai et al. 2025b), and MUSE-Autoskill (Lin et al. 2026) all con-vert successful or failed experience into workflows, memory-operation skills, reasoning 19 templates, policies, or executable procedures. Compared with episodic memory, pro-cedural memory is more compact and easier to reuse across tasks; compared with parametric adaptation, it can remain inspectable as an external artifact. The risk is that procedures abstract away the evidence that justified them. A workflow that succeeded because of a benchmark-specific shortcut may be stored as a general skill; a reasoning template may preserve a flawed assumption; and a tool-use policy may become unsafe when the environment changes. Procedural-memory systems therefore need skill validation, versioning, retirement, and rollback, not only retrieval. Their evaluation should measure transfer and robustness across tasks rather than repeated success on near-duplicate environments. 

## 6.3 Context Engineering and Harness Engineering 

A third line treats memory as part of the agent runtime. ACON (Kang et al. 2026), AgentFold (Ye et al. 2026), SWE-Pruner (Wang et al. 2026c), LCM (Ehrlich and Blackman 2026), the CL-bench repo (Arc Computer 2025), and the Code as Agent Harness survey (Ning et al. 2026) emphasize that memory is not only stored content but also the surrounding interface that exposes files, traces, summaries, tools, and execution state. Related work on grep-like harnesses, task-specific memory harnesses, agentic file systems, context engineering, and state-conditioned memory compilation for embodied agents (Sen et al. 2026; Pan et al. 2026; Xu et al. 2025c; Zhang et al. 2025f; Ding et al. 2026b) strengthens this point. The main contribution of this branch is operational rather than mnemonic: it decides which intermediate artifacts remain available and which are hidden, pruned, folded, or externalized. This makes harness memory powerful for software agents, web agents, and long workflows, but also makes evaluation difficult because performance gains may come from better tool exposure rather than better memory construction. A useful benchmark should therefore isolate whether the harness improved memory per-sistence, retrieval, and update behavior, or merely supplied more convenient context to the base model. 

## 6.4 Comparative Discussion 

Memory for agent evolution differs from recall-oriented memory because success is measured by behavioral improvement rather than only answer accuracy. RL and continual-learning systems use memory as a feedback substrate; procedural memory abstracts reusable actions; and context and harness engineering preserves the inter-mediate state needed for reliable execution. These approaches are complementary: an agent may use episodic memories to learn a skill, store the skill as procedural mem-ory, and expose the skill through a harness that manages files, tools, and execution traces. They also differ in risk profile. Experience memories may overfit to spurious successes, procedural memories may preserve brittle or unsafe workflows, and harness-level memories may expose stale files or tool states as if they were reliable evidence. The most important comparison is therefore not which method stores more experi-ence, but which method proves that stored experience causally improves later behavior while remaining reversible, auditable, and safe to retire. 20 7 Benchmarks

# 8 Challenges and Future Directions 

## 8.1 Unified Memory Organization 

Current systems often combine text chunks, embeddings, graphs, KV caches, tool traces, and user profiles in ad hoc ways. Future systems need unified schemas that can align episodic, semantic, procedural, multimodal, and parametric memories without losing provenance or update history. A promising direction is to separate memory content from memory metadata: content stores what is remembered, while metadata records source, timestamp, confidence, permissions, access history, and deletion status. Such organization would make memory systems easier to audit, compare, and integrate across applications. 

## 8.2 Reliable Memory Writing 

Long-term systems fail when they write too much, write too little, or write incorrect abstractions. Better memory construction should distinguish durable facts, transient preferences, temporary task states, and uncertain observations. It should also support explicit contradiction handling and confidence-aware revision. Future research should 23 move beyond heuristic summarization toward write policies that are evaluated against delayed downstream tasks, not only immediate extraction quality. 

## 8.3 Retrieval Beyond Similarity 

Nearest-neighbor similarity is insufficient for long-term memory. Useful memories may be old, indirect, private, contradicted, or only relevant under a procedural goal. Retrieval should combine semantic similarity with temporal reasoning, graph traver-sal, task intent, permission constraints, and uncertainty estimation. An important direction is multi-stage retrieval: first identify the task and memory type needed, then retrieve candidate memories, then verify recency, compatibility, and source reliability before injecting them into the model context. 

## 8.4 Multimodal Grounding and Video Intelligence 

Multimodal memory must preserve object identity, spatial relations, audiovisual tim-ing, and links to original perceptual evidence. Caption-only memory is compact but can discard important visual details. Future work should balance compact textual sum-maries with retrievable perceptual anchors such as frames, regions, audio segments, trajectories, or screen states. Evaluation should therefore test whether the system can recover evidence from the original modality rather than only answer questions from textual summaries. Video-centered intelligence exposes an even broader infrastructure gap. Long-video understanding requires persistent temporal indexes that can track events, entities, causal dependencies, and scene changes across hours of perceptual input, while long-video generation requires memory mechanisms that maintain identity, layout, motion, and narrative consistency across extended outputs. World models and embodied agents further require memory substrates that connect perceptual evidence with latent scene state, physical constraints, action effects, and interaction history. Current systems still often depend on sparse frame sampling, caption-based compression, or short-lived context buffers, which weakens causal tracking and makes generated or embodied behavior drift over long horizons. Future research should therefore develop scalable video memory infrastructure that combines online compression, hierarchical temporal event graphs, multimodal retrieval over raw evidence and latent world states, and eval-uation protocols spanning understanding, generation, world modeling, and embodied control. 

## 8.5 Governance, Privacy, and Deletion 

Long-term memory often contains personal, proprietary, or task-sensitive informa-tion. Multi-user, multi-agent, and edge–cloud settings require access control, prove-nance tracking, permission-aware retrieval, conflict management, secure deletion, and privacy-preserving personalized memory management (Chen et al. 2026c). Paramet-ric memory is especially challenging because a single remembered fact may not be directly inspectable or removable. Practical memory systems should therefore expose deletion logs, memory scopes, user consent controls, and policy-aware retrieval filters. 24 These governance mechanisms should be treated as core technical components rather than deployment afterthoughts. 

## 8.6 Failure Amplification and Misaligned Adaptation 

Memory can amplify errors because stored information influences future actions. A hallucinated fact that is written into memory can become a persistent false belief; an incorrectly extracted graph edge can redirect later multi-hop reasoning; and a noisy user profile can bias personalization across sessions. Agent-evolution memory introduces an additional risk: a workflow that succeeds for the wrong reason may be converted into a reusable skill, causing the agent to repeat brittle strategies or exploit benchmark-specific shortcuts. Future systems should therefore treat memory writ-ing as a high-impact operation rather than a passive logging step. Useful safeguards include uncertainty-aware writes, source-linked memories, conflict detection, periodic memory review, and controlled mechanisms for skill retirement or rollback. 

## 8.7 Evaluation Reliability 

Current benchmarks cover long-context retrieval, conversational memory, multimodal understanding, and simulation environments, but evaluation remains fragmented. Future benchmarks should measure memory write quality, update correctness, absten-tion, hallucinated memory use, privacy leakage, temporal consistency, and downstream task success. They should also distinguish between genuine memory use and success through long-context pattern matching. One practical approach is to evaluate agents under controlled memory ablations, where memory contents are removed, corrupted, delayed, or replaced to test whether the model truly depends on the intended memory mechanism. 

# 9 Conclusion 

Memory research for LLMs has moved from simple retrieval augmentation toward a diverse ecosystem of nonparametric stores, graph memories, multimodal memories, parametric memory modules, and self-evolving agent systems. This survey organized the literature around a lightweight cognitive-science-inspired conceptual motivation layer, three computational mechanism families—nonparametric memory, parametric memory, and memory for agent evolution—and a cross-cutting evaluation layer that tests whether these mechanisms produce durable benefits. Across these families, the central design questions are how to construct memory, how to manage and consolidate it, how to retrieve it reliably, how to forget or delete it safely, and how to evaluate its contribution to long-term behavior. The next generation of memory-augmented agents will likely combine text, graph, multimodal, activation, and procedural memo-ries under explicit governance mechanisms, using cognitive concepts mainly as design vocabulary, moving LLMs from reactive generation toward persistent, adaptive, and trustworthy long-term collaboration. 25 Declarations
