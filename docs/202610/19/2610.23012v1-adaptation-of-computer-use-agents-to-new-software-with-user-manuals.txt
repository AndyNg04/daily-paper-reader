## ABSTRACT 

Recent advances in multimodal foundation models have significantly improved the ability to operate real-world software through graphical user interfaces (GUIs) using visual observations and natural language instructions. However, maintain-ing strong performance on unseen applications remains challenging, as practical tasks often require long-horizon procedural knowledge and application-specific operation patterns. In addition, constructing executable tasks and collecting cor-responding trajectories for training still heavily rely on human-annotated data, incurring substantial cost. In this paper, we propose MAGE (Manual-augmented computer use AG ent Execution and learning), a framework that leverages user manuals as a scalable source of procedural knowledge to improve both inference and training. During execution, MAGE retrieves task-relevant manual content and uses a planner to generate explicit procedural guidance for CUAs. To further account for the discrepancies between manuals and actual GUI environments, such as version differences or user settings, MAGE also adapts the agent pol-icy through environment interaction. During training, MAGE converts manuals into executable task-plan pairs and uses the plans to guide environment rollouts toward task-relevant states; the resulting trajectories are then used to optimize the policy without human-authored demonstrations. This unified design enables effective utilization of manuals for both task execution and training, reducing reliance on human-authored training data. Experimental results across six ap-plications demonstrate improvements in task success rates over strong baselines, highlighting the effectiveness of manual-guided planning and policy adaptation in new software environments. We provide the code and reproduction scripts at 

https://github.com/ku-autoai/MAGE.git .

## 1 INTRODUCTION 

Recent advances in multimodal vision-language models (VLMs) (Yin et al., 2024) have enabled Computer Use Agents (CUAs) (Zhang et al., 2024; Lin et al., 2024; Qin et al., 2025; Wang et al., 2025) to operate software from visual observations and natural language instructions. Unlike conventional automation methods that rely on APIs or HTML structures, these agents interact directly with graphical user interfaces (GUIs) in a human-like manner. This enables CUAs to perform various tasks across diverse software environments. However, existing CUAs require additional training to maintain high performance on unfamiliar applications since each application has its own interface and functionalities. Existing adaptation (Qin et al., 2025; Zhang et al., 2025a; Yuan et al., 2025) typically relies on costly human annotations to define diverse executable tasks and collect corresponding action trajectories. Although reinforcement learning (Sutton et al., 1998; Silver & Sutton, 2025; Shao et al., 2024) can reduce the need for human demonstrations, GUI tasks are inherently long-horizon: agents should sequentially uncover available options through clicks, menus, and dialogs rather than observing all relevant information at once. This makes it difficult to obtain sufficient successful trajectories, limiting the training signals required to improve the agent policy. 1arXiv:2610.23012v1 [cs.AI] 16 Oct 2026 To address these limitations, we leverage user manuals as a source of procedural supervision. Manuals describe application functionalities and the procedures required to execute them, including functions hidden behind menus, dialogs, and toolbars. By exposing access routes to such functions, manuals can reduce unguided exploration in long-horizon GUI tasks. Prior approaches have also leveraged external knowledge, such as web tutorials and past interaction experiences, to guide GUI agents (Xu et al., 2025a; Agashe et al., 2025). However, providing external knowledge only during execution does not directly address the challenge of collecting successful trajectories for policy adaptation. Moreover, manuals may be abstract or differ from actual GUI environments due to software versions, user settings, or access permissions. Thus, agents must ground procedural guidance through environment interaction and learn which actions succeed in the current GUI state. Based on this observation, we propose MAGE (Manual-augmented computer use AG ent Execution and learning), a unified framework that leverages user manuals to improve both execution-time planning and training-time policy optimization. During execution, MAGE retrieves task-relevant manual content and uses a planner to generate task-specific procedural plans that guide CUAs. During training, it automatically generates diverse executable tasks and corresponding plans from user manuals. Rather than treating generated plans as expert demonstrations, MAGE evaluates the collected trajectories and optimizes the agent policy using Group Relative Policy Optimization (GRPO). This joint use of manuals for planning and policy learning enables application-specific adaptation without human-authored demonstrations or step-level action annotations. Our main contributions are summarized as follows. • We propose MAGE, a unified framework that uses user manuals as procedural supervision for both execution-time planning and training-time policy learning, combining a planner with CUAs. • We introduce retrieval-augmented planning, which retrieves task-relevant manual content and generates procedural plans to guide long-horizon GUI execution. • We develop a manual-derived training method that constructs task-plan pairs and optimizes the policy from the resulting trajectories without human-authored demonstrations or step-level annotations. • We evaluate MAGE across six applications and demonstrate improvements in task success rates over the corresponding baselines, examining the contributions of manual-guided planning and policy optimization. 

## 2 RELATED WORK 

Computer use agents (CUAs). To mitigate reliance on specific interfaces or predefined structural representations in computer environments, VLM-based agents that understand GUIs purely from visual signals have been proposed, with representative examples including OpenCUA (Wang et al., 2025) and UI-TARS (Qin et al., 2025). Training these foundation models requires large and diverse datasets. For instance, OpenCUA (Wang et al., 2025) integrates datasets from prior works such as ShowUI (Lin et al., 2024) and UGround (Qian et al., 2025), along with general supervised fine-tuning (SFT) data from the Kimi Team (Team et al., 2025), and further incorporates demonstration data collected from Ubuntu, Windows, and macOS environments. Similarly, UI-TARS (Qin et al., 2025) constructs additional training data by allowing human annotators to refine and correct trajectories generated by the model. While such data-centric training strategies significantly improve model performance, adapting these models to new software environments requires additional data collection and annotation tailored to each target domain. This process incurs substantial cost, thereby limiting the scalability and practical applicability of CUAs. 

Reducing human supervision for CUA adaptation. Prior work has explored reducing human supervision for CUA adaptation by augmenting or reusing existing datasets for training, or by leveraging external knowledge to guide task execution. BTL-UI (Zhang et al., 2025a) augments existing datasets with ROI annotations, while ZeroGUI (Yang et al., 2025) and DART (Li et al., 2025) leverage benchmark-derived tasks for reinforcement learning. Meanwhile, RAG-GUI (Xu et al., 2025a) trains a VLM to generate guidelines from web tutorials, guiding a frozen CUA at inference time, and Agent S (Agashe et al., 2025) uses external knowledge for hierarchical planning. However, data-driven approaches still rely on task-specific data, while knowledge-based approaches primarily 2assist execution at inference time without adapting the CUA’s policy. In contrast, MAGE leverages user manuals for both planning and policy optimization, improving task execution without repeatedly generating plans throughout an episode. 

## 3 METHOD 

MAGE is a manual-augmented adaptation framework for CUAs. Given a target program and its user manual, MAGE uses the manual as procedural supervision in two complementary ways: it retrieves task-relevant instructions to guide long-horizon execution, and it generates executable task-plan pairs to support policy training. These two components address the main bottlenecks in GUI adaptation: reliable task execution and scalable collection of successful trajectories. 3.1 PROBLEM DEFINITION

CUAs execute a task by repeatedly selecting the most appropriate action at based on the current observation ot and the past trajectory τ<t = {(oj , a j )|1 ≤ j < t }. However, in many GUI environments, the information required for the task completion is not fully visible in the current screenshot. Important functions are often hidden behind menus, dialogs, toolbars, or keyboard shortcuts, degrading the performance of agents for long-horizon tasks. To address the problem, we propose retrieval-augmented planning which uses procedural guidance from user manuals during task execution. As shown in Figure 1, our task execution consists of two stages. In the first stage, MAGE performs retrieval-augmented planning, following the retrieval-augmented generation framework (Lewis et al., 2020). It first retrieves relevant manual sections to provide detailed procedural information to the planner and generates an execution plan consisting of a sequence of actions with specific information such as button names and keyboard shortcuts. In the next stage, MAGE executes the task similarly to conventional CUAs but with the execution plan. 

Retrieval-augmented planning. MAGE retrieves manual sections relevant to I and generates a task-specific plan. Let M = {m1, . . . , m |M |} denote the set of manual sections. We encode each manual section mi using an embedding model as hi = E(mi). The embedding vectors are indexed in a vector database before executing the CUA. To retrieve the relevant section, MAGE encodes the task instruction as q = E(I) and finds the top-K sections MI with the highest cosine similarity

Retrieval-augmented planning provides procedural guidance, but manuals do not fully specify the actual GUI state of a target environment. In addition, interface elements can be hidden, customized, or restricted depending on application settings, workspace configurations, and user permissions. Thus, even when a manual describes a valid procedure, the agent should learn how to execute it robustly in the observed environment. To address this problem, we utilize user manuals not only for execution-time planning but also for policy training. As shown in Figure 2, the training pipeline consists of three stages: (1) task generation, (2) episode generation, and (3) policy optimization. In the first stage, MAGE uses the manual to construct a set of executable task-plan pairs. This stage is performed once before training begins. Second, the current policy executes these task-plan pairs in the target GUI environment to collect episodes. Third, the collected episodes are evaluated and used to optimize the policy via GRPO (Shao et al., 2024). The second and third stages are repeated iteratively, so that each updated policy produces new episodes for subsequent optimization. 3.3.1 TASK GENERATION 

In this stage, MAGE generates a wide range of executable task instructions from the manual. Since policy optimization requires successful trajectories, training becomes ineffective when the initial policy rarely completes long-horizon GUI tasks. To address this, we generate plans together with tasks to guide execution and steer rollouts toward task-completing trajectories. For each manual section, MAGE uses both the textual content and images as inputs. A multimodal LLM interprets the functional descriptions and examples in the section, and generates a setup task 

Isetup , a setup plan Psetup , a main task Imain , and a main plan Pmain . The setup task is an optional preliminary task that configures the initial GUI state required to execute the main task, while the main task is the final task that requires using the functionality described in the corresponding manual section. Each plan provides step-by-step procedural guidance for executing its corresponding task. By explicitly separating setup tasks, the framework can generate and execute diverse tasks without requiring manually prepared initial environments. The resulting setup and main tasks naturally involve common operations in the target program, such as entering values into spreadsheet cells or navigating application menus. Training on these tasks exposes the agent to frequently used program operations while covering diverse functionalities and usage procedures described in the manual. The prompt template for task generation is provided in Appendix F.1. 43.3.2 EPISODE GENERATION 

In this stage, trajectories are constructed by executing the generated task pairs in the GUI environment. The trajectory collection follows the interaction process described in Section 3.2. When a setup task is included in a task pair, the agent first executes the setup task to configure the required GUI state, and proceeds to the main task only upon successful completion. If there is no setup task, the agent directly executes the main task from the initial state. Each task execution generates a trajectory 

τ = {(o1, a 1), (o2, a 2), . . . , (oT , a T )} consisting of a sequence of observations and actions. To determine task success, we adopt the LLM-as-a-judge paradigm and employ a vision-language model (VLM) as an evaluator. The evaluator assigns a binary success reward Rsuccess ∈ { 0, 1} to each trajectory, where Rsuccess = 1 if the task is judged as successful and Rsuccess = 0 otherwise. However, prior work (Yang et al., 2025) has shown that evaluating full trajectories can be unreliable, as important details may be overlooked and hallucinations may lead to incorrect judgments. To mitigate this issue, we determine task success from the task instruction and the last five screenshots of the trajectory. This design aims to reduce susceptibility to hallucinations and evaluation cost. We provide a detailed analysis of the evaluator in Appendix D.3. For policy optimization, we construct training episodes from the collected task executions. Setup and main tasks are handled as separate training instances rather than being merged into a single trajectory. Accordingly, each task execution produces a separate training episode, defined as a tuple 

(I, P, τ, R success ). Each task is executed multiple times to collect a diverse set of episodes, which are subsequently used for GRPO-based policy optimization. 3.3.3 POLICY OPTIMIZATION WITH MANUAL -D ERIVED EPISODES 

In our adaptation setting, the amount of interaction data and available computation are limited compared to general foundation model training. Thus, we utilize GRPO (Group Relative Policy Optimization) (Shao et al., 2024) to optimize the CUA from collected episodes instead of using other reinforcement learning algorithms requiring a separate value model, such as PPO (Schulman et al., 2017). 

Round-based training. GRPO requires multiple rollouts per task to estimate group-level statistics, and learning becomes more effective as the proportion of episodes with positive rewards increases. However, generating new rollouts at every training step incurs substantial computational cost. We define a round as a cycle of episode generation and GRPO-based training. To address this, we propose a round-based training strategy that builds on an offline learning setup by reusing existing data while incrementally incorporating rollouts generated by the latest policy. In each round, newly generated episodes are added to the existing dataset and used for subsequent training. By repeating this process, rollouts with higher success rates are progressively collected, enabling the dataset to expand and the policy to improve over time. 

Episode sampling. Instead of computing expectations over all episodes within a group, we adopt a sampling-based approximation. For each task, one episode is randomly sampled for training, while its advantage is computed using all available episodes in the group. In this process, setup tasks and main tasks are treated as distinct, independent task instances, and sampling is performed separately for each task. Due to the dependency between setup and main tasks, not all attempts result in valid episodes, and multiple trials for a given task may yield only a limited number of episodes. In particular, when all episodes for a given task have identical rewards or when only a single episode is available, the reward variance becomes zero, making advantage estimation ill-defined. To address this issue, we exclude episode groups with zero reward variance from policy optimization. This approach reduces computational overhead by reusing previously collected episodes rather than generating new rollouts at every training step.

4.1 EXPERIMENTAL SETUP 

Benchmarks and applications. We evaluate MAGE on the OSWorld benchmark (Xie et al., 2024) for five applications: LibreOffice Calc, Impress, and Writer, GIMP, and VSCode. These applications require diverse multi-step GUI interactions including spreadsheet editing, slide modification, doc-ument editing, image editing, and code-related operations. Since OSWorld is a widely used CUA benchmark, tasks on these applications may already be in CUA training data. To examine whether MAGE can also adapt CUAs to applications with potentially limited coverage in their training, we construct 30 new evaluation tasks for Slack, a workplace communication platform. 

Models. We evaluate our framework with two CUA backbones: UI-TARS-1.5 (7B) (Qin et al., 2025) and EvoCUA (8B) (Xue et al., 2026). For retrieval-augmented planning, we use Qwen3-Embedding-0.6B (Zhang et al., 2025b) for manual retrieval and Qwen3.6 (27B) for plan generation. At the beginning of each task, the planner generates a task-specific plan conditioned on the task instruction, initial screenshot, and retrieved manual content. The generated plan remains fixed throughout execution. We use GPT-5.4 for manual-based task generation and trajectory evaluation during training.

Evaluation setup. To account for the inherent stochasticity of CUAs, we evaluate our main models over five independent runs on both OSWorld and Slack and report the mean and standard deviation. For the backbone models used in MAGE, the five runs include results from the official OSWorld dashboard (two for UI-TARS-1.5 and one for EvoCUA). To evaluate MAGE on Slack, we construct a separate test set consisting of 30 task pairs across 15 themes. For Slack evaluation, we use Gemini 3.1 Pro Preview to determine task success from the task instruction and the last five screenshots of each trajectory. OSWorld. As shown in Table 1, MAGE consistently improves performance across all five appli-cations and both backbone models. To assess the statistical significance of the overall success rate improvement, we conduct a two-sided Welch’s t-test. The improvements are statistically significant for both UI-TARS-1.5 ( p = 4 .13 × 10 −4) and EvoCUA ( p = 3 .63 × 10 −4). Notable improvements are observed in Calc and VSCode, with gains of 19.57 %p for UI-TARS-1.5 on Calc and 10.43%p for EvoCUA on VSCode. Many tasks in Calc and VSCode can be performed using keyboard shortcuts or application-specific commands, potentially reducing the need for complex menu navigation. We hy-pothesize that MAGE benefits from retrieving these procedures from user manuals and incorporating them into its plans, helping agents execute tasks more effectively. 

Slack. As shown in Table 2, MAGE improves the success rate on Slack by 22.66%p and 18.66%p for UI-TARS-1.5 and EvoCUA, respectively. Both improvements are statistically significant under 7a two-sided Welch’s t-test over five independent runs ( p = 0 .0094 and p = 0 .0035 , respectively). Notably, these gains are larger than those observed on OSWorld for both backbones. The relatively low performance of both backbone models on Slack may reflect limited exposure to Slack-specific tasks during training. Although their exact training data coverage is unknown, Slack is absent from several widely used CUA benchmarks. By leveraging user manuals for planning and policy optimization, MAGE may compensate for this lack of application-specific training experience, leading to larger performance gains on Slack. These results suggest its potential for adapting to new applications with limited prior training data. 4.3 ANALYSIS 

We provide additional analyses of MAGE using UI-TARS-1.5 as the backbone. 4.3.1 ABLATION STUDY 

We conduct an ablation study to evaluate the contributions of MAGE’s two key components: Retrieval-augmented Planning (RAP) during execution and Policy Optimization (PO) during training. The baseline and MAGE results are averaged over five independent runs, while the other variants are evaluated using a single run. With PO alone, the success rate is 0.42 percentage points (pp) higher than the baseline, whereas with RAP alone, it is 11.06 pp higher than the baseline. Combining RAP and PO provides an additional gain of 8.51 pp over RAP alone, resulting in a total improvement of 19.57 pp over the baseline. ## 5 CONCLUSION 

We presented MAGE, a framework that leverages user manuals for both task execution with manual-guided planning and training with manual-derived tasks. In the execution pipeline, MAGE retrieves task-relevant manual sections and uses a planner to generate a plan conditioned on the task instruction and the initial screen state. The generated plan is provided to CUAs, together with the task instruction and trajectory history, allowing them to incorporate external procedural knowledge during action generation. In the training pipeline, MAGE constructs manual-derived tasks from function-level manual sections, collects self-generated trajectories in the GUI environment, assigns rewards through an automatic evaluator, and performs GRPO-based policy optimization. This design integrates manual-based task construction, agent–environment interaction, reward assignment, and policy optimization without requiring human-authored expert demonstrations. Our experiments demonstrate that incorporating user manuals into planning and policy optimization improves task success across multiple applications. These results suggest that user manuals can be used not only as human-facing documentation, but also as scalable supervision for building more capable CUAs. 9AI U SE STATEMENT
