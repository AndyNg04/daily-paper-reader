## Abstract 

Existing embodied navigation tasks commonly assume that traversability and object states remain fixed during an episode. Yet reaching a goal may require opening a door to access a room and then opening a container to reveal a hidden target. We formulate interactive navigation beyond reachability, unifying channel-induced changes in spatial connectivity, container-induced changes in target visibility, and their sequential dependencies. We introduce MultINav-Bench , a 3K-episode Ob-jectGoal benchmark in MolmoSpaces spanning channel, container, and mixed tasks, with interaction-necessity annotations covering required and unnecessary episodes. Its data generation pipeline automates task construction across multiple task types. The evaluation protocol separately measures navigation success, interaction effectiveness, and cost. We further pro-pose MultINav-Agent , a three-stage agentic framework built on a persistent, state-conditioned interaction graph. Semantic interactive perception grounds entities and interaction states; a vision-language model selects task-relevant actions based on expected changes in connectivity and target observability; and post-interaction verification updates the graph to guide subsequent navigation, exploration, or interaction. Experiments on MultINav-Bench show that MultINav-Agent consistently outperforms adapted baselines across channel, container, and mixed tasks.

## 1 Introduction 

PointGoal, ObjectGoal, and vision-and-language navigation have driven sustained progress in embodied navigation [1, 2, 3]. These tasks test localization, mapping, search, and instruction following, but generally assume that traversability and object states remain fixed within an episode. This abstraction omits a basic property of indoor environments: interaction can change both the space a robot can traverse and the targets it can observe. A closed door could disconnect the target room or force a long detour, while a closed refrigerator, cabinet, or drawer could conceal a nearby target. These effects can be sequential: opening a door permits entry into a room, where opening a container then reveals the target. The agent should therefore reason about how each interaction changes the environment and enables subsequent navigation, exploration, or interaction. Prior work provides foundations in semantic navigation, scene representation, and physical interaction [4, 5, 6]. For example, Interactive Gibson studies movable obstacles and the trade-off between path efficiency and physical disturbance [7]. Beyond free-space recovery, the task-level challenge is to determine whether an interaction restores connectivity or reveals a target, how it enables subsequent actions, and when it is unnecessary. Therefore, we are motivated to formulate the problem of multiple interactive navigation (MultINav) , unifying 

channel interactions that change spatial connectivity, container interactions that change target visibility, and their sequential dependencies. This calls for a navigation-decision framework that jointly reasons about both types of interaction and their sequential dependencies. That is, the agent decides whether to interact, which object to select, when to act, and how to use the resulting state change to proceed toward the goal. Our motivation is shown in Fig. 1. In this paper, we first instantiate the definition of MultINav as a benchmark, namely MultINav-Bench , a 3K-episode ObjectGoal benchmark in MolmoSpaces [8] spanning channel, container, and mixed tasks, with interaction-necessity anno-tations covering required and unnecessary episodes. Its data generation pipeline automates task construction across multiple task types using shared interaction-state specifications. The evaluation protocol separately measures navigation success, in-teraction effectiveness, and cost. To address the MultINav problem, we propose MultINav-Agent , a three-stage agentic framework built on a persistent, state-conditioned interaction graph. The graph retains observed rooms and entities together with their states and relations across observations. Semantic interactive perception grounds entities and interaction states in this representation. A vision-language model uses the graph and decision history to select task-relevant actions based on expected changes in connectivity and target observability. Post-interaction verification revises affected states and relations, guiding subsequent navigation, exploration, or interaction. Our contributions are summarized as follows: • We formulate the problem of MultINav, which unifies channel-induced changes in spatial connectivity, container-induced changes in target visibility, and their sequential dependencies, paving the way for more comprehensive studies on interactive navigation. • We introduce MultINav-Bench , a 3K-episode MolmoSpaces ObjectGoal benchmark spanning channel, container, and mixed tasks, with interaction-necessity annotations covering required and unnecessary episodes. As a versatile system, it provides a data generation pipeline that can automate task construction across multiple task types, and an evaluation protocol that separately measures navigation success, interaction effectiveness, and cost. • We propose MultINav-Agent , a three-stage agentic framework built on a persistent, state-conditioned interaction graph that connects perception, action selection, and verified state updates. On MultINav-Bench, MultINav-Agent consistently outperforms adapted baselines across all task types. 

## 2 Related Work 

Embodied Navigation and Interactive Benchmarks. PointGoal, ObjectGoal, and vision-and-language navigation eval-uate geometric, semantic, and language-specified goals under a fixed episode state [1, 9, 2]. Semantic-navigation methods exploit category maps, scene graphs, and semantic priors for target search [3, 10, 6, 11, 12]; Habitat and AI2-THOR provide complementary environment foundations [4, 5]. This fixed-state abstraction becomes limiting when an action changes the relations used for semantic navigation, such as room connectivity or target exposure. As Table 1 shows, Interactive Gibson, Interactive Visual Navigation, and CaMP retain a navigation endpoint while changing free space or path cost [7, 14, 15]; InterNav also evaluates door-mediated connectivity in PointGoal [16]. Interactive Navigation and Decision. NAMO introduced selecting movable obstacles to make a route feasible [19]. Inter-active Gibson, Interactive Visual Navigation, and CaMP learn obstacle interactions for free-space recovery or path efficiency [7, 14, 15]; adaptive pushing, effect-oriented affordances, and joint perception-interaction-navigation extend this setting to unknown dynamics and richer action effects [20, 21, 22, 23]. Task-and-motion planning complements policy learning by grounding discrete interaction choices in geometric feasibility [24, 25, 26]. These methods establish that navigation can ben-efit from interaction, but generally tie the choice to obstacle clearance, path cost, or control feasibility. Language-grounded planners add language-level task decomposition, learned skill feasibility, and execution feedback [27, 28, 29, 30], while articulated-object systems provide reusable door-opening executors [31, 32]. The remaining question is whether a candidate produces a goal-relevant navigation-state change. CoINS is the closest comparator, but MultINav-Agent selects candidates by their expected graph effect and verifies that effect before replanning. It therefore distinguishes restoring connectivity from exposing a target; in MultINav-Bench, the latter becomes task-level accessibility and is assessed with required/unnecessary and distractor controls. 

Semantic Navigation and Structured Scene Representations. Dynamic and open-vocabulary scene graphs organize places, objects, relations, and traversability while supporting online construction, language queries, and task-relevant res-olution [33, 34, 35, 6, 36]. They support graph-conditioned search and navigation [10, 11, 12]; graph-based and language-guided planners further connect these representations to feasible actions and replanning [37, 38, 39]. However, navigation graphs typically plan over relations observed during construction: even when the representation is updated online, action-induced changes in connectivity or target visibility are seldom treated as task-level state transitions that must be predicted and verified. Recent interactive graphs move toward such updates by modeling task state or articulated/container structure [40, 41, 42, 43, 44, 45]. MultINav-Agent specializes this interface to verified channel effects on connectivity and container effects on target visibility/accessibility under an ObjectGoal endpoint.

3.2 Data Generation and Collection 

Starting from ProcTHOR-10K houses and NavToObj seeds, candidates are synthesized via counterfactual reachability and visibility checks: closing a channel must sever the shortest route to the goal, while concealing a target inside a container must invalidate initial visibility until opened. Candidates pass articulation readback, target-identity verification, and oracle rollout validation before freezing 1,000 balanced episodes per domain. Beyond the frozen light evaluation split designed for benchmark diagnostics, our pipeline supports a full collection mode recording multimodal expert demonstrations. For each verified rollout, full collection captures synchronized ego-centric/allocentric visual streams, continuous base trajectories, 6D end-effector targets, and articulation states formatted into unified HDF5 records. These trajectories provide an expert pretraining corpus for vision-language-action (VLA) models, while an accompanying interactive web inspector enables fine-grained visual auditing of base-manipulator motions. 3.3 Evaluation Metrics 

We decouple terminal goal achievement from intermediate interaction efficiency using five complementary metrics: • SR (%) : Terminal ObjectGoal success under standard distance and visibility thresholds. • SPL : Success-weighted planar path efficiency relative to a feasible oracle route, reported on [0 , 1] using the same terminal navigation-success flag as SR. • ISR (%) : Mean fraction of verified necessary interaction effects on required episodes; partial completion of a valid plan receives partial credit. • IP (%) : Category-level Interaction Precision, the episode-mean fraction of attempts producing a verified physical effect in a target interaction class. The acted-on instance need not match the annotated instance; reopening after closure can receive credit again. • Total Cost : All-episode mean of normalized operation cost, min(( Li + 0 .3Ai + Ei)/30 , 1) on success and 1 on failure, where Ei counts attempts without a qualifying physical effect. The normalization constant B = 30 is fixed before evaluation; it is not a step or time limit and does not stop rollouts (see Appendix E, “Metric Formulas”). 

## 4 MultINav-Agent Framework 

MultINav-Agent maintains a persistent, state-conditioned interaction graph connecting semantic perception, action se-lection, and post-interaction verification (Fig. 3). Verified changes update the graph used to select subsequent navigation, exploration, or interaction. 

4.1 Semantic Interactive Perception 

The graph Gt = ( Vt, Et) represents rooms, interactive entities, objects, and the robot through connectivity, containment, and visibility relations. Perception associates entities across observations, while visual attribute inference estimates interac-tion class and coarse state (open, closed, or uncertain). Interactive nodes retain candidate operations, observation confidence, and recency alongside these state estimates.

Perception builds a persistent, state-conditioned interaction graph; candidate plans are formed; interaction proposals are filtered for reachability, observability, and freshness; a VLM scores admissible plans by task relevance; and post-interaction verification updates the graph to guide subsequent action selection. The graph is state-conditioned because relation validity depends on the observed interaction state: a closed door blocks its mediated room connection, whereas a verified opening permits traversal. Opening a container permits inspection of its interior; target visibility is established only when the target is observed. Newly observed entities extend the graph, while previously observed entities persist beyond the current view. Their stored states and relations provide context for later decisions, with confidence and recency distinguishing historical estimates from fresh evidence (formal definitions in Appendix D, “Interaction Graph and State Updates”). 

4.2 Effect-Guided Action Selection 

At each decision point, the graph and navigation map generate candidates for navigation, frontier exploration, and interac-tion. An interaction candidate specifies an entity, operation, and approach viewpoint. Eligibility checks use route feasibility, available visual evidence, and state reliability. These checks constrain the current executable candidates; remembered entities remain in the graph even when no interaction with them is currently eligible. Each interaction candidate carries a coarse expected effect derived from its interaction class and graph relations: opening a channel may enable traversal, while opening a container may reveal its contents. This describes a possible change, without assuming an unseen target is present. A vision-language model receives the goal, relevant subgraph, candidate states and effects, route costs, and decision history. It ranks eligible actions by their expected contribution to reaching or observing the target, accounting for route prerequisites, plausible target locations, and previous attempts. Navigation and exploration remain available when interaction offers little task progress. The selected candidate resolves to an executable goal or interaction specification; a structured reason code summarizes the model’s task-level judgment.

4.3 Interaction Verification and Graph Updates 

For a selected interaction, the agent reaches the approach viewpoint and grounds the operable region and operation from the current view. Navigation and interaction skills execute the resulting specification. Post-interaction verification reconciles fresh visual observations with execution feedback to assess the achieved state and expected graph effect (executor details in Appendix F, “Additional Implementation Notes”; visual interaction prompting is summarized in Appendix G). Confident evidence updates the affected entity state; conflicting or occluded evidence is marked uncertain. Channel updates revise room connectivity, while container updates incorporate newly observed objects and their containment and visibility relations through perception. Failed or uncertain attempts remain in decision history to discourage immediate repetition. The updated graph regenerates candidates for subsequent navigation, exploration, or interaction. This loop supports sequential interaction dependencies. Opening a door enables entry into a room; observations there can introduce a container candidate; verified container opening exposes objects whose observations support the next navi-gation decision. Each step updates the graph and available actions, composing connectivity and visibility changes during exploration. 

## 5 Experiments 

5.1 Experimental Setup 

We evaluate on MolmoSpaces NavToObj and our MultINav-Bench for non-interactive and interactive navigation, respec-tively. MultINav-Bench contains 3,000 ObjectGoal episodes spanning 639 houses in total, with balanced Channel, Container, and Mixed task splits. 

Evaluation scope. The benchmark provides both raw image-based perception and a restricted ground-truth (RGT) per-ception mode. The primary comparison uses the same RGT interface for both interactive methods: it supplies episode-local object IDs, categories, and spatial observations for currently visible objects. This reduces perception and instance-association errors as a confound when evaluating interaction-aware representations and decisions; agents must still explore, select in-teractions, and update their beliefs from observed outcomes. Hidden objects, simulator joint metadata, and oracle plans are withheld. Implementation details are provided in Appendix A, “Experimental Platform and Reproducibility,” and Appendix F, “Additional Implementation Notes.” 

Interactive baseline and metrics. We compare MultINav-Agent (Ours) with a MolmoSpaces adaptation of MoMa-LLM [40]. Both MultINav-Agent and the MoMa-LLM adaptation use Qwen3.6-35B-A3B-FP8 for high-level decisions and share the same interaction executor. We select this model to support real-time decision-making during navigation. We report SR, SPL, ISR, IP, and Cost as defined in Section 3.3, with formulas in Appendix E, “Metric Formulas.” 

5.2 Main Results 

Non-interactive NavToObj. Without interaction, our method achieves 53.0% SR on MolmoSpaces NavToObj (Table 2). The RING [46] and DualVLN [47] leaderboard results are 48.0% and 21.0%; SPOC [48] and VLFM [49] score 20.15% and 11.90% in local evaluations. All baselines execute valid commands; lower transfer scores stem from continuous control shifts lacking sliding contact feedback. 

Interactive benchmark. Table 3 shows that MultINav-Agent achieves better aggregate values on all five metrics than the MolmoSpaces adaptation of MoMa-LLM. Ours completes 1,249/3,000 episodes, reaching 41.63% SR versus 10.53% (+31.10 percentage points), with SPL increasing from 0.0848 to 0.2903. ISR increases from 23.69% to 49.38%, IP from 27.59% to 46.79%, and normalized Cost decreases from 0.9309 to 0.7743.

5.3 Ablation Study 

All four variants use the same fixed 200-episode subset of the 1,000 Mixed tasks, spanning 165 houses. We sample proportionally without replacement by container class and oracle-restored reference path length, using benchmark metadata only for sampling. The episode list is frozen before evaluation without using policy outcomes; construction details appear in Appendix B.5, “Ablation Subset Construction.”

Table 4 examines interaction memory, action selection, and state updating. Full achieves the highest SR (23.0%) and IP (40.4%), but the variants reveal different trade-offs rather than uniform gains across all metrics. 

Interaction memory. Flat Object Memory reduces IP from 40.4% to 26.7% and SR from 23.0% to 21.0%, despite increas-ing ISR from 41.8% to 43.8%. The graph-based memory therefore shows its clearest advantage in interaction precision, not required-effect completion. This pattern is consistent with relational context helping select effective target-class interactions, while the higher ISR of the flat variant shows that partial progress alone need not translate into goal completion. 

Action selection. Greedy Selection attains higher SPL (0.134 vs. 0.107) and lower Cost (0.933 vs. 0.961), with slightly lower SR (22.0%) and IP (36.9%). Full completes only two additional episodes out of 200, so these results do not establish a decisive success advantage for semantic selection. Instead, they expose a completion-efficiency trade-off: goal-conditioned selection improves the observed SR and IP, whereas the greedy variant performs better on aggregate efficiency. Since SPL and Cost also depend on success, these scores do not isolate efficiency conditional on completion. 

State updating. Perception-only Update produces the largest SR decrease, from 23.0% to 5.5% (17.5 percentage points), alongside lower ISR (26.6%), lower SPL (0.033), and higher Cost (0.988). IP remains 36.6%, indicating that some interac-tions still achieve target-class effects without completing the task. Among the tested variants, this is the strongest evidence for retaining execution-informed graph updates when coordinating channel and container interactions. The smaller SR dif-ferences for memory and selection should be interpreted cautiously on this fixed subset, rather than as established statistically significant gains.

5.5 Real-World Demonstration 

Setup. We conduct the real-world demonstration on a Go2 quadruped in an indoor environment (Fig. 5). Door and re-frigerator opening are performed with human assistance. Egocentric observations, intermediate interaction graphs, and the semantic map record the evolving scene representation throughout the rollout. 

Task and rollout. The task is to find an apple. Starting near a closed door, the robot encounters a channel interaction: the door is opened with human assistance, enabling access to the adjacent space. The robot then explores the newly accessible area, extending its semantic map and interaction graph as rooms and objects are observed. It subsequently navigates to the refrigerator, which is opened with human assistance so that the robot can inspect its contents for the target apple. This sequence links two distinct state changes within a single object-search task: door opening changes spatial connectivity, while refrigerator opening exposes previously occluded contents. The intermediate graphs in Fig. 5 show the corresponding evolution of room, door, container, and object relations. 

## 6 Conclusion 

We formulated MultINav, unifying channel and container interactions within ObjectGoal navigation, and introduced MultINav-Bench (3,000 episodes) together with MultINav-Agent, whose persistent interaction graph with verified state up-dates achieves 41.63% SR versus 10.53% for the adapted baseline and transfers to a real-world Go2 demonstration. Extending to broader interaction types, learned perception, and end-to-end policy training are promising future directions.

Runtime environment. The simulation experiments use NVIDIA A100 GPUs with 80 GB of memory. The real-world demonstration uses one NVIDIA GeForce RTX 4090 with 48 GB of memory. The simulation software stack uses Python 3.11.15, MuJoCo 3.4.0, and PyTorch 2.7.1. 

Evaluation configuration. The simulation uses the MolmoSpaces ObjectGoal protocol, with terminal success requiring both goal distance and head-camera visibility. Episodes span 639 unique houses. Per-domain house counts are 253 (channel), 569 (container), and 369 (mixed). Train/eval separation is enforced at the house level in the collector configuration so that the same house does not appear in both partitions of a formal split.

B.6 Scoring Eligibility and Quality Gates 

Before formal aggregation, the evaluator applies a runtime goal-consistency gate: frozen oracle terminal waypoints must remain consistent with the live pose of the selected instance. Traces that fail are retained for diagnosis but marked scoring-ineligible and excluded from primary denominators. Schema audit on the balanced 3K reports 3,000/3,000 valid episodes, 0 duplicate case IDs, and 0 missing comparable GT path lengths in the offline health report; runtime eligibility is a separate online check. 

B.7 Domain-Specific Collection Gates 

All builders emit the shared episode schema, but use domain-specific acceptance tests. For channel episodes, the collector starts from a fixed Navigate-to scene-start-goal tuple, identifies doors associated with candidate room routes, and validates closed- and open-state path feasibility. Required episodes must recover a feasible goal route after the annotated door effect; unnecessary episodes retain a feasible route while closed distractor doors remain present. A small route-shortening pilot additionally retains cases in which both states are feasible but opening reduces route length; it is diagnostic rather than a balanced MultINav-Bench stratum. For container episodes, the collector binds a specific rigid target to a moving fridge, cabinet, or drawer compartment, closes the relevant articulation, and verifies the target-compartment association. It then validates an interaction pose, the opening effect, and a terminal pose that satisfies the same distance-and-visibility predicate as Navigate-to. Other articulated objects remain in the scene as ambient distractors. For mixed episodes, the full ordered door-container rollout must pass; the post-door state alone is not terminal, and omitting either annotated effect must break the validated chain. Across domains, failed state readback, inconsistent target identity, oracle rollout failure, duplicates, and split leakage cause rejection.

## F Additional Implementation Notes 

Graph observations and attributes. Both MultINav-Agent and the MoMa-LLM adaptation use the same front-end per-ception and the same restricted-GT observation interface in the primary benchmark comparison. The interface provides episode-local IDs, semantic categories, spatial observations, 2D masks or boxes, and 3D boxes for visible entities; it does not expose hidden entities, joint metadata, or oracle plans. The benchmark also supports an image-based raw-perception mode, but that mode is not mixed with the restricted-GT comparison. Instance labels, segmentations, and bounding boxes initialize and associate observed entities. Interactive nodes store the interaction class, coarse state, candidate operation, operable-part description, confidence, and observation recency. Visual attribute inference refines these records from the current view. The coarse candidate effects distinguish channel traversal from container-content revelation; they do not establish the presence of an unobserved target. 

Shared simulation interaction executor. Both interactive methods use the same executor in the primary evaluation. The evaluator applies force-driven transitions to the selected articulated joints, with a kinematic completion fallback when a tran-sition does not reach its requested target. Execution feedback is returned through the public interaction interface; simulator joint metadata are withheld from the policies. Agent graph updates maintain scene estimates, while the terminal evaluator independently checks goal distance and head-camera visibility. 

Scope of aggregate comparisons. Aggregate benchmark comparisons characterize end-to-end behavior; by themselves, they do not isolate graph updates as the cause of a performance difference.

## G Vision-Language Model Decision Protocol and Prompts 

This section details the vision-language model (VLM) architecture, input representation, prompt templates, structured output schema, and decision context employed by MultINav-Agent. 

G.1 Model Configuration and Serving 

MultINav-Agent uses Qwen3.6-35B-A3B-FP8 for high-level decisions, served through an OpenAI-compatible chat-completions API. Visual inputs are formatted as a composite RGB image containing: • Global egocentric view : The full head-camera observation with the candidate interaction target bounded by an explicit visual outline, providing geometric and spatial context relative to the robot and room. • Actionable region inset : A padded, normalized crop around the target entity ( x, y ∈ [0 , 1] ), allowing fine-grained localization of actionable door handles, push panels, or drawer pull surfaces. 

G.2 Subgoal Categorical Reason Codes and Subgraph Context 

When evaluating candidate actions from the state-conditioned graph, the VLM receives serialized topological context containing: 1. Room and Anchor Entities : Discovered room partitions and up to 4 major anchor objects per room (e.g., 

refrigerator , countertop , bed , table ). 2. Candidate Portals and Containers : Articulated doors and containers, their current states ( zt), and their mediated relational effects. 3. Decision Reason Codes : The VLM classifies the semantic justification for each candidate into standardized reason codes: • TARGET_VISIBLE : The goal object is observed in line-of-sight; navigate to terminal observation pose. • UNLOCK_ROUTE : Opening a door is necessary to restore traversal connectivity to an unvisited topological room. • REVEAL_TARGET_CONTAINER : Opening a container (e.g., refrigerator or cabinet) to expose a hidden target object matching semantic category priors. • EXPLORE_TARGET_ROOM : Navigating to a newly connected or unexplored room when direct target evidence is absent.
