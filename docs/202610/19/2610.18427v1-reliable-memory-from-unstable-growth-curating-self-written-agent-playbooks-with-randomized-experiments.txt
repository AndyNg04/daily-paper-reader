# Reliable Memory from Unstable Growth: Curating Self-Written Agent Playbooks with Randomized Experiments

Abstract 

Persistent textual memory lets language-model agents reuse lessons from past tasks to improve on future multi-step tasks without retraining. Systems such as ACE and Dynamic Cheatsheet keep it as a playbook : lessons the agent writes after each task and reads in its prompt. A key challenge is to decide which lessons improve later tasks. Current systems leave the decision to the agent itself, which makes performance unstable: the same procedure can write a play-book that helps or one that falls up to 69.6 points below no playbook. These findings mo-tivate valuing lessons by their measured effect on task success rather than by the agent’s judge-ment. We propose Randomized Block Cura-tion (RBC) 1, which measures this effect with a randomized experiment on practice tasks. It groups related lessons into blocks large enough to move success measurably and, on each prac-tice task, includes or leaves out every block at random. Random inclusion makes tasks with and without a block comparable, so the gap in their success estimates the block’s effect. RBC keeps the blocks that help and, since the same procedure can write a helpful or a harmful play-book, grows several and serves whichever cu-rated, whole or no playbook scores best on fresh practice episodes. Across two memory systems, three models and three benchmarks, RBC raises average success to 66.9, against 55.5 with the whole playbook, 54.1 with no playbook and 53.8 when the agent’s own judge-ment picks the lessons to keep.

growing line of work lets agents improve through persistent textual memory: lessons the agent writes after each task and reads in its prompt later (Shinn et al., 2023; Zhao et al., 2024), which we call a 

playbook . Systems maintain it differently, grow-ing it lesson by lesson (ACE; Zhang et al., 2026), rewriting it as a whole (Dynamic Cheatsheet; Suz-gun et al., 2026) or retrieving lessons by similarity (ReasoningBank; Ouyang et al., 2026), but they share one design (Figure 1a): the agent that writes the lessons also judges which to keep. Few works test this judgement against task suc-cess, and those that do compare whole memories (Nguyen et al., 2026). This matters because added context can distract a model as easily as help it (Shi et al., 2023), and a lesson kept by mistake is served on every later task. This work targets that decision, which lessons of a self-written playbook to serve, in two established memory systems, ACE and Dynamic Cheatsheet. We find their playbooks unstable: served whole, a playbook can fall up to 69.6 points below no playbook, and growing it arXiv:2610.18427v1 [cs.CL] 13 Oct 2026 again on the same tasks in another order can turn a helpful playbook harmful. Whether a playbook helps depends on the growth run that wrote it and is known only by measuring its effect on success. Letting the agent prune lessons it judges harmful does not remove the harm. Judging a lesson re-quires comparing episodes with and without it, but the agent sees only those that use it, and language models are poor and biased judges of their own outputs (Huang et al., 2024; Zheng et al., 2023). So it tags lessons as helpful when they sound right, not when they raise success, even a harmful rule (Sec-tion 4). Context-valuation methods run this com-parison but not for curation: they explain why a model gave one answer (Cohen-Wang et al., 2024) or score memory entries one at a time (Li et al., 2026; Wang et al., 2026), though one entry rarely moves success measurably, and return scores, not a playbook to serve (Figure 1b). We propose Randomized Block Curation (RBC) , which supplies this comparison with a randomized experiment on practice tasks (Fig-ure 1c). RBC groups related lessons into blocks large enough to move success measurably. Includ-ing each block at random on every practice task makes tasks with and without it comparable, so their success gap estimates its effect. RBC keeps the blocks that help within a token budget and, since a playbook’s value depends on its run, grows several and serves whichever curated, whole or no playbook scores best on fresh practice episodes. RBC leaves growth itself unchanged. We test RBC on both systems with three models on three benchmarks. It lifts both on every model, averaging 66.9 task success against 55.5 with the whole playbook, 54.1 with no playbook and 53.8 when the agent picks lessons itself. It also avoids the harm: on ACE it never falls more than 0.8 points below no playbook, while every baseline falls at least 5.4 points below it in some setting. When ACE’s playbooks, which never drop a lesson, grow for twice as long, RBC still beats the whole playbook and no playbook in every setting. In summary, our contributions are as follows. • Analysis. We show that self-written playbooks are unstable across growth runs and that the agent’s own judgement misses the harm. • Method. We propose RBC, which measures each block of lessons in a randomized experiment and serves only what helps. • Experiments. RBC is effective and robust across memory systems, models, benchmarks and rounds of memory updates. 

2 Related Work 

Self-written agent memory. Of the systems above, ACE tags each lesson as helpful or harm-ful, and Dynamic Cheatsheet counts each entry’s successful uses. Other agents reflect on failures or store workflows (Shinn et al., 2023; Wang et al., 2025), memory managers let the model decide what to store and recall (Packer et al., 2023; Xu et al., 2025), and ExpeL (Zhao et al., 2024) scores each insight by the model’s votes. In all of them a lesson stays because its writer believes it helps or because it resembles the task; Guo et al. (2026) find that self-improving agents also misjudge the checks they write, and we find the same for the lessons agents keep. The closest works measure success, but on whole units: Sarukkai et al. (2025) select among sets of trajectories and RSEA (Nguyen et al., 2026) among memory rewrites, accepting one only if held-out success does not drop. RBC instead measures every block at once and chooses among growth runs and no playbook. 

Valuing parts of a context. ContextCite (Cohen-Wang et al., 2024) re-scores one answer on random subsets of sources with a linear fit, the design RBC applies to task success; Data Shapley (Ghorbani and Zou, 2019) and Data Banzhaf (Wang and Jia, 2023) value training data, and SkillSV (Li et al., 2026) and DG-Mem (Wang et al., 2026) value agent skills or memory entries. They stop at a value per entry, and a single entry rarely moves success beyond the noise of a few hundred episodes (Zhao et al., 2026); RBC measures blocks, scores them by task success and decides what to serve within a budget (Appendix F). A block’s effect, its average gain, is its Banzhaf value (Banzhaf, 1965), which random inclusion estimates for every block at once. 

Choosing prompts and harmful context. Prompt optimizers such as DSPy (Khattab et al., 2024) and GEPA (Agrawal et al., 2026) keep what scores best on a development set, and demonstration selection scores each example over random prompts that con-tain it (Chang and Jia, 2023; Nguyen and Wong, 2023); RBC applies this scoring to an agent’s mem-ory, selecting among the agent’s lessons instead of rewriting them, so curating calls no language model (Appendix G). Irrelevant text distracts lan-guage models (Shi et al., 2023; Liu et al., 2024), so a longer playbook can hurt, and prompt compres-sion (Jiang et al., 2023) cuts a context by perplexity, not by effect on success; run-to-run variance is fa-miliar from fine-tuning (Dodge et al., 2020). 

3 Background and Setup 

3.1 Memory systems The memory loop. A self-written memory system lets an agent learn from its own experience. It wraps three steps around the agent: 1. Grow. After each batch of training tasks, the model reads its own trajectories and writes short lessons, which form a playbook P .2. Judge. The model judges which lessons help. 3. Serve. A subset S ⊆ P of the lessons goes into the prompt of later tasks. On a task x, the agent acts over many turns, an 

episode , and earns a success score y(x, S ) ∈ [0 , 1] 

when S is served (reported ×100 ). The value of serving S is its mean success, V (S) = E[ y(x, S ) ] ,and a playbook helps only when V (S) > V (∅).Our two reference points are No playbook ( S =

∅) and the whole playbook (Whole, S = P ). A 

growth run grows one playbook from scratch on the training tasks. Runs differ: with the tasks in another order and new sampling, the same procedure writes a different playbook, one that may help or harm. 

Goal. In this work, we replace the judge and serve steps by measurement. For a playbook P and a token budget B, the best set of lessons to serve is 

S⋆ ∈ arg max S⊆P, tokens( S)≤B V (S), (1) and with several growth runs, the best of their sets 

S⋆, whole playbooks and no playbook. As V is seen only in noisy episodes, we estimate it on prac-tice tasks (Section 3.2) before serving. 

Two systems. We study two established systems that write a playbook in different ways, to test whether a finding depends on how memory is writ-ten; ReasoningBank’s retrieval by similarity serves as a baseline (Section 6). 

ACE. Our main system, ACE (Zhang et al., 2026), grows its playbook lesson by lesson. As the agent solves training tasks, a Reflector reads each trajec-tory and its feedback and writes new lessons; no lesson is ever removed. The Reflector also judges: it tags the lessons used in each episode as helpful or harmful, a record we can check (Appendix A). ACE serves the whole playbook. 

Dynamic Cheatsheet. Our second system (Suz-gun et al., 2026) rewrites its whole playbook, a cheatsheet: after each batch of training tasks, one model call reads it and the batch’s trajectories and writes a new one. It judges by itself, without the reward, which attempts succeeded, counts each en-try’s successful uses (Appendix A.2) and, like ACE, serves its whole playbook. 

3.2 Benchmarks and models Benchmarks. We conduct experiments on three benchmarks. In AppWorld (Trivedi et al., 2024), the agent writes code against the APIs of nine apps. In WebShop (Yao et al., 2022), it finds and buys a described product. In ALFWorld (Shridhar et al., 2021), it reaches a goal in a text household. They are scored by task goal completion, purchase re-ward and success rate. 

Task splits. Each benchmark has three disjoint task sets: training tasks to grow playbooks, prac-tice tasks to test playbooks before serving one, and 

evaluation tasks for the final score: AppWorld 168, WebShop 500 and ALFWorld 134 (Table 3). 

Models and settings. We run three open models: Qwen3.8-27B (Qwen Team, 2026b), Qwen3.5-9B (Qwen Team, 2026a) and Gemma-4-31B (Gemma Team, 2026). A setting is one system, model and benchmark. Per model, ACE has four, two of them on AppWorld, where its Reflector sees whether a task passed ( pass/fail ) or each unit test’s result ( per-test ); Dynamic Cheatsheet, which never sees the reward, has three. Without 9B on ALFWorld (it solves almost no game), that makes eleven ACE and eight Dynamic Cheatsheet settings. Each set-ting has three growth runs. 

4 Self-Written Memory Is Unreliable 

Before repairing self-written playbooks, we ask whether they need repair. We ran three growth runs in each of the eleven ACE settings and checked each step of the loop (serve, grow, judge) against task success. We call a playbook harmful when it scores more than 5 points below no playbook; re-evaluating a playbook moved its score by at most 5.0 points, so such a gap is not noise. 

Finding 1: serving the whole playbook can harm. 

Served whole, a playbook is unstable, even on one model and in one setting. Finding 2: the growth run decides whether the playbook harms. If this harm came from the model or benchmark, regrowing the playbook would reproduce it. It does not always: the same procedure on the same tasks, in another order, can write a helpful or a harmful playbook. On 27B AppWorld with per-test feedback, the three runs score 82.5, 58.9 and 30.0 against 78.4 with no play-book (Figure 2, mixed ): one helps, two harm. Such swings occur in 3 of the 6 settings with a harmful run, all on Qwen, whose runs differ only in task order and sampling. Dynamic Cheatsheet shows them too (Appendix B.2): on 9B WebShop one run gains 13.2 points over no playbook, another loses 14.0. An agent with one playbook cannot tell which kind it holds; only measuring can. 

Finding 3: the agent’s own judgement misses the harm. The obvious defence is to let the agent’s tags prune the playbook: keep the lessons tagged most helpful and drop the rest. What a repair needs. Each finding sets one re-quirement: serve only the parts of a playbook that help, or no playbook (Finding 1); grow several playbooks and let fresh practice episodes choose among them (Finding 2); and measure each part’s effect on task success (Finding 3).

5.1 Measuring the effect of each block Blocks. We measure groups of related lessons, as a single lesson rarely moves success beyond the noise of a few hundred episodes. We embed each lesson with all-mpnet-base-v2 (Reimers and Gurevych, 2019), as ACE does to find duplicates, and cluster the embeddings with Ward’s method (Ward, 1963) into m = 8 blocks C1, . . . , C m (the number matters little; Appendix E.7). A block holds lessons on one topic, which tend to help or harm together. For a set of blocks T ⊆ [m], we write V (T ) for the value of serving their lessons. 

Randomized inclusion. Each practice episode i

draws a task xi and includes each block j indepen-dently with probability p = 12 , zij ∼ Bernoulli( p);the agent is served the included blocks, Ti = { j :

zij = 1 }, and scores yi. Each episode is thus both an ordinary run of the agent and one trial of a two-level factorial design over all m blocks, each block on or off (Box et al., 2005; Figure 4, step 1).

6 Experiments 

We fixed every constant of RBC on four ACE set-tings, using none of their evaluation tasks, and kept it unchanged on the other fifteen. RBC grows 

K = 3 playbooks per setting, the runs of Figure 2, and curates each to a budget B of 40% of its tokens; 20% and 60% scored lower (Appendix E.7). Every score averages three evaluation seeds over tasks, and over the three growth runs where a method serves one run, so each score rests on hundreds to thousands of episodes. 

Baselines. Every method serves from the same playbooks, on the same tasks and seeds, and differs only in how it decides what to serve. k; Ouyang et al., 2026), or at random (Random). The strongest baseline chooses : Best-Full, the acceptance rule of RSEA (Nguyen et al., 2026), serves the best whole playbook or no playbook on practice tasks. 7 Conclusion 

In this work, we showed that self-written playbooks are unstable: one procedure can grow a helpful or a harmful playbook, and the agent’s own judge-ment cannot tell which. We proposed RBC, which measures instead: it serves blocks of lessons at ran-dom on practice tasks to see what each does, and checks the curated set against whole playbooks and no playbook before serving. Task success rises on average from 55.5 with the whole playbook to 66.9, and curating adds to choosing with fewer tokens, above all under long growth. An agent’s memory should be measured, not judged. 

Limitations 

Our evidence covers two memory systems, three benchmarks and three open-weight models, with playbooks we grew; other memory systems, do-mains and larger or proprietary models remain to be tested. Within this scope, RBC values a block by its average gain over the other blocks served with it, which makes curation exact when block effects add; when lessons are hard to separate, as in a memory rewritten as a whole, it falls back on the best whole playbook, which still lifts suc-cess but saves no context. RBC also trades extra episodes for reliability: it grows several playbooks, runs practice rounds and needs practice tasks with an observable outcome. Since its guarantee holds on these practice tasks, it works best when they resemble the tasks the agent will face. We fixed its constants on four ACE settings and kept them unchanged elsewhere. Finally, we study playbooks fixed once grown; extending RBC to memory that grows while it is served is a natural next step.

A Experimental setup 

A.1 ACE as we run it A playbook. Each line of an ACE playbook is one lesson with an id and the agent’s tags, for example:             

> [sai-00001] helpful=166 harmful=0
> :: Always extract dynamic identifiers (e.g.,
> artist_id ,track_id )from the output of previous API calls and use them in subsequent requests. Never assume or hardcode IDs unless they are explicitly static and known in advance.

The actor sees the lesson without the tags. 

Growth. We run ACE’s batched mode (Zhang et al., 2026). On each batch of training tasks, the actor plays every task with the current playbook; the Reflector reads each trajectory with its feed-back and tags the lessons that bore on it as helpful, harmful or neutral; the Curator writes new lessons, which are appended; and near-duplicate lessons are merged. No step removes a lesson, and the whole playbook is served on every call (Whole). Growth runs differ in the order of the training tasks and the actor’s sampling; a run stops once a pass over the training tasks grows the playbook by less than 10%, after at most five passes. 

Feedback. On AppWorld, the Reflector sees either whether the task passed (pass/fail) or the result of each unit test (per-test); the two grow different play-books and count as different settings. On WebShop it sees the reward, on ALFWorld success. 

A.2 Dynamic Cheatsheet as we run it 

We run Dynamic Cheatsheet’s cumulative mode (Suzgun et al., 2026) with the actors and training tasks of our ACE runs. After each batch of train-ing tasks, one model call reads the current cheat-sheet and the batch’s trajectories, judges by itself, without the reward, which attempts succeeded, and writes a new cheatsheet that replaces the old one, with a count of each entry’s successful uses. The cheatsheet is served whole; RBC treats its entries as lessons and is otherwise unchanged.

ACE’s tags and memory systems. ACE’s Reflec-tor tags every lesson an episode used, but the re-sponse is its own judgement, and ACE never re-moves a lesson (Zhang et al., 2026); Tags is the rule its tags imply (Appendix A.4). ExpeL and RSEA. ExpeL (Zhao et al., 2024) keeps an importance count per insight, raised and lowered by the model’s own votes, and drops an insight at zero; its signal is the agent’s judgement, as with ACE’s tags. RSEA (Nguyen et al., 2026) accepts a rewritten memory only if held-out suc-cess does not drop: a measured outcome, but for the memory as a whole and for one run. Best-Full applies its rule to one and to three growth runs (Appendix A.4).
