## 摘要
人机交互正日益成为改进 AI 系统的丰富数据来源：许多模型响应已经令人满意，但其他响应则暴露出可能存在的缺陷；如果能够识别并纠正这些缺陷，它们便可转化为有价值的监督信号。我们通过“编辑器”这一概念研究这一场景：编辑器是一种能力更强的评估过程，可以检查响应并选择确认或修改，但调用成本较高。编辑器可以是人类专家、更强大的 AI 系统，也可以是配备了额外计算资源、上下文、工具或信息的同一模型。核心挑战在于，在尚不确定是否会进行编辑之前，就决定将哪些交互提交给编辑器，因为调用编辑器本身会消耗专家时间、推理成本、延迟或工具使用开销等有限资源。我们将这一问题形式化为编辑发现优化（Edit Discovery Optimization，EDO），旨在减少被跳过的交互中遗漏的编辑机会，同时控制不必要的确认，并遵守编辑器成本预算。我们刻画了总体最优策略，并证明该策略表现为对编辑后验概率设置经过成本调整的阈值。在此基础上，我们提出 EDIT（通过迭代阈值进行编辑发现），这是一种面向部分反馈场景的在线算法，其中仅对被选中的交互揭示编辑标签。EDIT 将自适应编辑评分、确认控制阈值与成本感知选择规则相结合；该算法在每一轮都满足编辑器预算，并将平均确认率控制在目标范围内，误差项随有限时域增长而趋于零，且不对交互流作任何分布假设。在四个推理与事实性问答基准上，与基于 LLM 的直接批量选择方法相比，EDIT 在编辑器成本、第一类错误和第二类错误之间实现了更优的权衡。

## Abstract
Human-AI interactions are becoming a rich source of data for improving AI systems: while many model responses are already satisfactory, others expose failures that could become valuable supervision if identified and corrected. We study this setting through the notion of an editor: a more capable evaluation process that can inspect a response and either confirm it or modify it, but whose invocation is costly. The editor may be a human expert, a stronger AI system, or the same model equipped with additional computation, context, tools, or information. The key challenge is to decide which interactions to send to the editor before knowing whether an edit will actually be made, since invoking the editor itself consumes limited resources such as expert time, inference cost, latency, or tool-use overhead. We formulate this problem as Edit Discovery Optimization (EDO), which seeks to minimize edit opportunities missed among skipped interactions while controlling unnecessary confirmations and respecting an editor-cost budget. We characterize the population-optimal policy and show that it takes the form of a cost-adjusted threshold on the posterior probability of an edit. Building on this structure, we develop EDIT (Edit Discovery via Iterative Thresholding), an online algorithm for the partial-feedback setting in which edit labels are revealed only for selected interactions. EDIT combines an adaptive edit score, a confirmation-control threshold, and a cost-aware selection rule; it satisfies the editor budget at every round and controls the average confirmation rate up to a vanishing finite-horizon term, without distributional assumptions on the interaction stream. Across four reasoning and factual question-answering benchmarks, EDIT achieves a better trade-off between editor cost, Type-I error, and Type-II error than direct LLM-based batch selection.

  - 少漏掉需要修改的回答；

## 2. 方法论：EDO 与在线算法 EDIT

### 2.1 形式化：编辑发现优化 EDO

每条交互由用户问题与模型回答组成，记为 \(Z\)。编辑标签为：

- \(A=1\)：编辑器会修改回答；
- \(A=0\)：编辑器确认回答，无需修改。

核心预测量是：

\[
\eta(z)=\Pr(A=1\mid Z=z)
\]

即看到交互后、调用编辑器前，预测它需要修改的概率。

论文定义了两类错误：

| 指标 | 定义 | 含义 |
|---|---|---|
| 第一类错误 | 被选交互中无需修改的比例 | 审核的“确认负担” |
| 第二类错误 | 被跳过交互中需要修改的比例 | 未审核部分的“编辑遗漏密度” |

EDO 的目标是：**在第一类错误不超过容忍值、预期编辑成本不超过预算的条件下，最小化第二类错误。**

需要特别注意：这里的第二类错误不是通常分类中的假阴性率，也不等于“所有需要编辑的案例中漏掉了多少比例”；后者应通过编辑召回率衡量。

### 2.2 总体最优策略：概率阈值加成本调整

在已知数据分布和真实编辑概率的理想条件下，论文证明最优策略具有以下形式：

\[
\text{选择交互 }z
\quad\Longleftrightarrow\quad
\eta(z)>\alpha^\star+\beta^\star c(z)
\]

其中：

- \(c(z)\)：该条交互的审核成本；
- \(\alpha^\star\)：全局筛选阈值；
- \(\beta^\star\)：成本约束对应的调整系数；
- 阈值边界上必要时允许随机选择。

直观上：

- 越可能需要修改，越值得审核；
- 审核越昂贵，所需的编辑概率就越高；
- 当预算约束不紧时，成本调整项可以消失。

### 2.3 实用算法 EDIT

真实部署时，真实编辑概率未知，而且**只有被选中的交互才会获得标签**。EDIT 将理想规则拆分为三个模块：

1. **编辑评分**：预测哪些回答更可能需要修改；
2. **确认率控制**：根据已审核结果动态调整全局阈值；
3. **预算控制**：根据当前批次成本选择成本乘子。

每一轮的流程如下：

1. 接收一批交互及其已知审核成本。
2. 为每条交互计算编辑评分。
3. 找到使本轮总成本不超过预算的最小成本乘子。
4. 按“评分高于全局阈值加成本调整项”的规则选择交互。
5. 调用编辑器，只观察被选交互的编辑标签。
6. 如果本轮确认率高于目标，就提高阈值；低于目标则降低阈值。
7. 对可学习评分器，使用本轮被选样本的交叉熵损失更新参数。

### 2.4 三种评分器

- **EDIT-RAND**：使用均匀随机分数，检验控制机制本身的作用。
- **EDIT-LLM**：让大模型根据问题与回答，直接估计需要编辑的概率，不提供参考答案。
- **EDIT-REP**：冻结文本编码器，仅在线训练一个逻辑回归线性探针，是论文的主要方案。
  - 默认编码器为 **all-MiniLM-L6-v2**；
  - 编码器约 **2270 万参数**；
  - 表征维度为 **384**。

### 2.5 理论保证及边界

EDIT 保证：

- **每一轮都不超过编辑预算**；
- 不需要独立同分布、交换性等数据流假设；
- 固定阈值步长为 \(\gamma\) 时，平均逐轮确认率满足：

\[
\widehat{\mathrm{Err}}_{\mathrm I}
\leq
\varepsilon+\frac{1+\gamma}{\gamma T}
\]

主实验采用 \(T=250,\gamma=0.1\)，因此理论上的有限时域余量为 **0.044**。

但这一保证：

- 针对的是**逐轮确认率的平均值**，不是每一轮都达标；
- 不是将全部被选样本合并后计算的整体确认率；
- **不提供第二类错误、编辑召回率或在线最优性的保证**。这些仍依赖评分质量。

## 6. 主要结论与发现

### 6.1 主要经验结果

EDIT-REP 总体优于直接 LLM 批量选择，尤其在 MMLU-Pro、GPQA 上较明显。以 Llama 主实验的补充指标为例：

| 数据集 | EDIT-REP 编辑召回率 | LLM-Select 编辑召回率 | 遗漏编辑数量：REP / 基线 |
|---|---:|---:|---:|
| MATH-500 | 0.784 | 0.621 | 143 / 251 |
| MMLU-Pro | 0.703 | 0.238 | 346 / 889 |
| PopQA | 0.411 | 0.223 | 824 / 1087 |
| GPQA | 0.644 | 0.306 | 407 / 793 |

这些数字对应各方法的实际运行工作点，不代表完全相同支出下的净收益。

### 6.2 更一般的发现

- **控制器和评分器承担不同职责**：控制器约束确认率与预算，评分器决定能发现多少编辑机会。
- 随机评分也能满足控制保证，但发现效率明显不足。
- 更强的冻结编码器通常带来更好的编辑排序，Qwen3-4B 表征在四个数据集上取得最低的最终第二类错误。
- EDIT-REP 并非所有指标、所有设置都最好。例如 Qwen3-32B 的 MATH-500 上，EDIT-LLM 的编辑召回率为 **0.939**，高于 EDIT-REP 的 **0.810**。
- **发现更多修改机会不等于已证明模型训练收益**：论文没有验证这些纠错数据能带来多少下游能力提升。

## 7. 优点与亮点

- **问题定义具有实际意义**：将“检查也需要付费”明确纳入交互数据筛选，而不是假设标签免费可得。
- **理论与算法结构衔接清楚**：从总体最优阈值规则推导在线的评分、确认控制与预算分配模块。
- **硬预算约束实用**：逐轮保证不超支，比只约束长期平均成本更适合运营场景。
- **确认率控制不依赖数据分布假设**：适用于非平稳或相关的数据流，且不要求评分器本身准确校准。
- **实现模块化、训练部分轻量**：可以更换评分器，而不改变约束控制机制。
- **补充指标较完整**：不仅报告自定义错误率，还报告召回率、精确率和遗漏数量，减少单一指标造成的误读。
- **进行了人工标签核验**：为“任务错误近似编辑需求”提供了直接证据。

## 8. 不足与局限

### 8.1 缺少发现效率的理论保证

- 理论保证主要针对预算与平均确认率。
- 没有证明 EDIT 在线逼近总体最优策略，也没有提供第二类错误或编辑召回率的遗憾界。
- 当容忍值过严时，算法可以通过减少选择甚至停止选择来维持确认率控制，**约束成立并不意味着发现了足够多的纠错案例**。

### 8.2 选择性反馈可能形成盲区

- 评分器只使用被选交互更新；
- 没有显式探索或选择偏差校正；
- 初始低估的某类错误可能长期得不到审核，导致持续漏检。

### 8.3 “需要编辑”不等于“高训练价值”

- 算法主要优化编辑发生概率，没有区分错误严重性、重复性、纠正难度或预期训练收益。
- 高频、容易预测的小错误可能被优先选择，而罕见但重要的失败模式未必得到足够关注。

### 8.4 真实编辑场景覆盖不足

- 主要实验以任务正确性代替真实编辑行为；
- 人工审核仅有 200 条、由一名人工标注者完成，不能充分反映不同编辑者之间的分歧；
- 缺少代码、开放式写作、多轮对话、工具调用、复杂用户意图等场景；
- 未评估编辑器自身错误、意见不一致或反馈延迟。

### 8.5 成本和部署效益仍需验证

- 单位成本和回答长度只是实际审核成本的粗略近似；
- 成本在选择前已知的假设，对真实人工审核未必成立；
- 尚未统一评估筛选、编辑和后续训练的端到端成本；
- 未验证纠错数据用于训练后的效果，也未系统考察用户群体、专业领域和编辑者能力差异。

**综合评价**：这篇论文的核心价值，是为有限预算下的纠错数据发现提供了一个清晰、可控制的在线框架。其约束保证有说服力，实验也支持模块化设计的有效性；但真实部署中的发现覆盖、总成本与下游训练收益，仍需要进一步验证。
