## 摘要
系统综述遵循 PRISMA 流程，对学术文献进行筛选，并从纳入的研究中提取证据。基于大型语言模型（LLM）的深度研究工具能够检索和总结文献，但不会记录哪些研究被排除，也不会标明提取值的来源。我们开发了一种名为 ReviewPilot 的对话式多智能体系统，可自动完成从论文筛选到信息提取的 PRISMA 工作流程。研究人员可以通过对话定制筛选标准和数据模式，项目记忆功能则会保存其配置及修改记录。系统会为每项筛选决策提供理由，并为每个提取值标注来源。在流行病学专家评审任务中，ReviewPilot 在三种 LLM 上的表现均优于单提示词 LLM 和 AgentSLR，筛选宏平均 F1 最高达 0.776，提取 F1 最高达 0.788。生物医学和人机交互领域的案例研究表明，ReviewPilot 的结果与人工标注者高度一致，这说明它有望应用于流行病学以外的领域。代码见 https://github.com/ZhaoqianXue/ReviewPilot。

## Abstract
Systematic literature reviews follow the PRISMA process of screening scholarly works and extracting evidence from included studies. Deep research tools based on large language models (LLMs) can search and summarize the literature but do not record which studies are excluded or where extracted values come from. We develop a conversational multi-agent system called ReviewPilot that automates the PRISMA workflow from paper screening to information extraction. Researchers can tailor criteria and schemas through dialogue, and a project memory keeps their configurations and revisions. Each screening decision comes with its reason and each extracted value with its source. On epidemiological expert reviews, ReviewPilot outperforms a single-prompt LLM and AgentSLR across three LLMs, with screening macro F1 up to 0.776 and extraction F1 up to 0.788. Case studies in biomedicine and human-computer interaction show close agreement with human annotators, suggesting that ReviewPilot can transfer beyond epidemiology. Code is available at https://github.com/ZhaoqianXue/ReviewPilot.

# ReviewPilot 论文总结

## 1. 核心问题与研究背景

- **研究目标**：让大模型辅助的系统综述不仅能够“搜索与总结”，还能够记录**文献为何被纳入或排除、提取值来自哪里，以及规则修改后哪些结果需要重做**。
- **现实背景**：系统综述通常需要筛查数千篇文献、获取全文并人工填写证据表，工作量大、周期长。同时，研究者需要按照 PRISMA 2020 的报告要求，记录各阶段文献数量和排除理由。
- **现有工具的不足**：
  - 通用深度研究工具偏重生成综述报告，通常不完整记录文献筛选过程。
  - 部分专业工具只覆盖筛选或提取中的单一阶段。
  - 综述标准与提取字段往往需要反复调整，单纯保存聊天记录不足以保证后续输出始终遵循最新规则。
- **论文的整体思路**：提出对话式多智能体系统 **ReviewPilot**，将检索、筛选、全文获取、结构化提取和语义分类连接起来，并加入人工确认、证据检查和项目状态管理。

> 其主要贡献是一个可配置、可检查、可修订的系统综述工作流，而不是新的基础模型或训练算法。对齐 PRISMA 报告流程，也不等于自动保证综述的方法学质量。

## 2. 方法论：核心思想与技术流程

### 2.1 多智能体架构

系统由一个主控智能体协调四个专门智能体及两个工具：

| 组件 | 主要职责 |
|---|---|
| Lead Agent | 协调阶段、检查前置条件和输出、回答项目问题、执行语义分类 |
| Search Condition Agent | 将研究问题转换为检索概念和布尔检索式 |
| Prompt Agent | 生成综述专属筛选指导、提取模式和编码规则 |
| Screening Agent | 去重并判断标题、摘要是否满足标准 |
| Extraction Agent | 从全文提取结构化字段及支持性原文 |
| Literature Search Tool | 执行数据库检索 |
| PDF Download Tool | 获取、检查全文 PDF |

- 各阶段通过输入与预期输出明确的“动作契约”衔接。
- 任务操作流程写入结构化 Markdown 技能文件，再附加到相应模型的系统提示中。
- 主控智能体需要确认依赖结果仍然有效、必要文件和字段存在，才能报告阶段完成。

### 2.2 检索与预处理

- 将研究问题拆分为概念组：
  - 同一概念组内的替代表述用 **OR** 连接。
  - 必须同时满足的不同概念组用 **AND** 连接。
  - 仅用于后续分析、而不决定纳入资格的维度，不强制加入检索式。
- 支持 **PubMed、arXiv、OpenAlex**，记录实际执行的检索式、时间范围、结果数量和错误。
- 预处理包括日期过滤、标题规范化精确去重，以及基于标题和作者特征的 TF-IDF 余弦相似度近似去重，默认阈值为 **0.70**。

### 2.3 自动生成综述专属操作规则

Prompt Agent 将较抽象的纳入标准、字段定义转换为可执行的边界判断规则：

- **筛选指导**：使用研究目标、已确认标准、检索概念及最多 **200 条候选记录**。
- **提取模式草稿**：使用研究目标、用户指定字段及最多 **3 篇纳入论文**的摘要开头。
- **提取编码规则**：使用已确认字段及最多 **25 篇论文**的摘要和字段相关全文句子。
- 筛选指导和编码规则均经过“初稿—第二轮检查修订”。
- 这些生成过程**不直接输入专家筛选标签或参考提取值**，且使用前需要研究者确认。

### 2.4 标题—摘要筛选

对每篇记录，模型综合标题、摘要、纳入标准、排除标准和专属指导，输出理由及五级判断：

1. 明确排除；
2. 倾向排除；
3. 不确定；
4. 倾向纳入；
5. 明确纳入。

- 只有前两类被排除，其他记录进入全文阶段；模型调用失败时也保留记录。
- 判断强调论文**实际开展的工作**，而不是背景、动机或引用中出现的主题。
- 系统要求指出决定性规则和原文证据；无法匹配规则或定位引文的排除会被标记供人工检查，**但不会自动撤销排除**。

### 2.5 全文获取与证据提取

- PDF 获取采用出版商、开放获取平台和预印本等多来源级联，并通过 PDF 有效性和首页标题匹配进行启发式检查。
- 使用 `pypdf` 读取全文、插入页码标记，每篇最多输入前 **400,000 个字符**。
- 按确认后的字段名称、类型、描述和编码规则，返回字段值、逐字摘录及页码。
- 输出接受字段完整性、类型和取值约束检查；通过检查不代表内容正确。
- 系统在规范化 PDF 文本中定位摘录：
  - 至少定位到一段摘录，字段标记为 `verified`；
  - 否则为 `unverified`。

**重要区别**：`verified` 仅表示引文确实出现在文本中，不证明它支持预测值，也不保证覆盖多值字段中的每一个值。

系统还支持：

- 将全文资格判断置于提取模式首位，记录全文阶段的排除理由。
- 无 PDF 时，可选择摘要或网络证据回退；这些结果单独标注来源，不与全文评估混同。

### 2.6 项目记忆与语义分类

- 项目记忆保存聊天、草稿、已确认配置快照、阶段状态、PRISMA 数量及人工修改理由。
- **当前已确认状态优先于旧聊天请求**；配置或记录修改后，受影响的下游结果被标记为过期，等待重新运行。
- 该记忆不是跨项目自动学习，也不会自动从纠错中学习用户偏好。
- 最后，系统针对提取字段提出类别，研究者确认后执行单标签或多标签分类。

### 5.2 充分性与公平性评价

**较好的方面：**

## 6. 主要结论与发现

### 6.1 筛选性能提高

| 模型 | 单提示宏 F1 | AgentSLR 宏 F1 | ReviewPilot 宏 F1 |
|---|---:|---:|---:|
| gpt-6-luna | 0.696 | 0.713 | **0.766** |
| DeepSeek V4.1 Flash | 0.632 | 0.717 | **0.776** |
| GLM-5.3-Flash | 0.567 | 0.654 | **0.757** |

- 相比 AgentSLR 提高 **5.3—10.3 个百分点**。
- 全文审查比例降至约 **26%—29%**，但不能据此推断漏纳更少或人工时间更短。
- 优势并非覆盖每个子集，例如 GPT 模型在 Nipah 上略低于 AgentSLR。

### 6.2 提取准确性与证据可定位性提高

| 模型 | 单提示 F1 | AgentSLR F1 | ReviewPilot F1 |
|---|---:|---:|---:|
| gpt-6-luna | 0.771 | 0.751 | **0.788** |
| DeepSeek V4.1 Flash | 0.767 | 0.735 | **0.782** |
| GLM-5.3-Flash | 0.761 | 0.737 | **0.777** |

- 相比单提示，F1 提升 **1.5—1.7 个百分点**，准确性增益较为温和。
- Verified-correct rate 达 **0.703—0.714**，高于单提示的 0.528—0.561 和 AgentSLR 的 0.405—0.449。
- 干预措施仍较难提取，ReviewPilot 的字段 F1 约 **0.574—0.594**。

### 6.3 跨领域可用性初步成立，但仍需纠错

- 生物医学中，系统对两位标注者的 κ 为 **0.905、0.907**，标注者间为 0.860。
- HCI 中，系统对两位标注者的 κ 为 **0.667、0.793**，标注者间为 0.733。
- 人工检查分别恢复了 **3 条 HCI**、**4 条生物医学**的错误排除，并在两个主题中各修改三个提取字段值。

这些结果支持跨领域应用潜力，同时表明人工审查仍不可缺少。

## 7. 优点与亮点

- **面向真实综述过程**：覆盖配置、执行、检查、纠错与重跑，而非只展示一次性模型输出。
- **规则操作化明确**：将抽象标准转换为定义、近似但不合格的研究类型和边界处理规则。
- **可追溯与可修订结合**：原始结果、修改理由和历史记录保留，方便研究者复核。
- **项目状态管理实用**：区分草稿与确认配置，避免旧聊天指令覆盖最新规则。
- **评测披露较诚实**：明确承认开发与评测重叠、引文定位的局限以及成本遗漏项。
- **工程复现信息较丰富**：提供代码地址、提示、参数和实现细节。

## 8. 不足与局限

- **泛化证据不足**：PERG 参与开发，其他领域只有小规模、非随机、团队内部标注审计。
- **关键阶段未被充分评估**：全文资格判断未独立审计，摘要及网络回退未单独验证，分类质量也缺少系统定量评价。
- **引文存在不等于支持结论**：可能出现真实引文与字段值不相符，或多值字段只有部分值有证据。
- **检索和全文获取可能产生选择偏差**：
  - 仅支持三个来源，并有结果数量上限；
  - 无法量化付费访问障碍对全文缺失的影响；
  - 获取不到全文的研究可能系统性缺席后续分析。
- **指标存在解释限制**：主表未单独报告纳入类敏感性；部分字段采用“预测与参考均为空计一个真阳性”的惯例，需谨慎比较分数。
- **性能提升来源不清楚**：缺少消融，不能把效果归因于“多智能体”本身。
- **实际人机协作收益未证实**：尚未通过前瞻性团队研究衡量检查负担、信任校准、审计质量及总耗时。
- **工程边界仍明显**：全文截断、PDF 文本解析质量及托管模型版本变化，均可能影响结果。

**总体评价**：ReviewPilot 的价值在于把系统综述自动化做成一个可审计、可修订的研究辅助流程。现有结果支持其在所测数据和配置下优于两个基线，但尚不能证明其能够替代独立人工审查，或在未见综述中稳定保持同等收益。
