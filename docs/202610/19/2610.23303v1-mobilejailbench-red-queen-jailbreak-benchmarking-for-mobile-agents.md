## 摘要
基于多模态大语言模型（MLLM）的移动智能体在动态移动环境中的感知、规划和闭环执行能力正迅速增强，其自主性也随之提高。然而，这种自主性同时扩大了攻击面，并加剧了恶意滥用风险，包括隐私泄露、设备入侵和大规模网络钓鱼。现有越狱评估在移动智能体方面存在三个关键缺口：关注对话攻击而非移动工作流，采用难度固定的静态任务集，以及过度依赖攻击成功率，而未进行全面的安全评估。为弥补这些缺口，我们提出 MobileJailBench，这是首个面向移动智能体、能够持续演进的越狱基准测试，包含三个关键组件：（1）由 520 项任务构成的基准，覆盖三种越狱范式和 14 类风险，并基于我们构建的高保真移动沙箱，可在 20 多款常用应用中模拟真实工作流；（2）双动态演进机制，结合基于失败蒸馏的越狱演进与基于弱点驱动的基准扩展；（3）分层裁定框架，用于评估安全意识、执行行为和风险后果。大量实验表明，当前移动智能体尤其容易受到隐式越狱攻击，因为其安全对齐仍大多停留在表层，无法将对话场景中的拒绝行为泛化到动态移动交互中。此外，我们的动态演进机制通过持续发现新的漏洞，进一步明确了实际威胁边界，使 Qwen3.5-122B 的攻击成功率（ASR）达到 100%。MobileJailBench 提供了一个可复现、持续演进的框架，用于追踪移动智能体的真实安全边界。

## Abstract
MLLM-based mobile agents are rapidly gaining autonomy in perception, planning, and closed-loop execution in dynamic mobile environments. However, this autonomy also broadens the attack surface and amplifies the risks of malicious misuse, including privacy leakage, device compromise, and large-scale phishing. Existing jailbreak evaluations leave three critical gaps for mobile agents: they focus on conversational attacks instead of mobile workflows, use static task sets with fixed difficulty, and rely narrowly on attack success rate rather than comprehensive security assessment. To close these gaps, we present MobileJailBench, the first evolving jailbreak benchmark for mobile agents, comprising three key components: (1) a benchmark comprising 520 tasks spanning three jailbreak paradigms and 14 risk categories, built on a high-fidelity mobile sandbox that we construct, enabling realistic workflows across over 20 widely used apps; (2) Dual-Dynamic Evolution, which combines Failure-Distilled Jailbreak Evolution with Weakness-Driven Benchmark Expansion; and (3) Stratified Adjudication Framework for assessing security awareness, execution behavior, and risk consequences. Extensive experiments show that current mobile agents are particularly vulnerable to implicit jailbreaks, as their safety alignment remains largely superficial and fails to generalize from conversational refusal to dynamic mobile interactions. Moreover, our dynamic evolution mechanism sharpens practical threat boundaries by continually uncovering new vulnerabilities, reaching a 100% ASR on Qwen3.5-122B. MobileJailBench provides a reproducible, continuously evolving framework for tracking the true security boundaries of mobile agents.

### 1.1 为什么需要新的安全基准？

基于多模态大语言模型的移动智能体已能读取屏幕、规划任务、切换应用并执行连续操作。其安全失败因此不再局限于有害回答，还可能直接造成：

- 敏感信息泄露；
- 设备设置或数据被不当修改；
- 钓鱼、欺诈和其他跨应用恶意操作。

作者认为，现有越狱评测存在三个关键缺口：

1. **场景不匹配：**主要评估对话提示，难以覆盖界面导航、跨应用上下文和持久状态变化。
2. **基准静态化：**任务规模与难度固定，难以跟随模型能力和攻击策略演化。
3. **指标过于单一：**仅看攻击成功率，不能区分主动拒绝、危险尝试和因操作失败而未造成后果等情况。

论文采用“红皇后”视角：**被评测的智能体不断进步，评测本身也必须持续演化。**

其核心目标不是单纯提高攻击成功率，而是建立一个能够反复回答以下问题的评测体系：

- 智能体是否接受了违规目标？
- 是否开始执行危险行为？
- 是否及时拒绝？
- 最终是否真正造成违规后果？

## 2. 方法论：核心思想与关键技术

整体框架由三部分组成：**移动环境与任务基准、双动态演化机制、分层裁决框架。**

### 2.1 移动环境与统一执行流程

作者构建了一个由 Python 测试框架控制的、**基于浏览器的类 Android 模拟器**，包含 28 个应用：

- 14 个第三方应用，覆盖通信、金融、社交、电商、导航和娱乐；
- 14 个系统应用，如短信、设置、联系人、日历、图库和文件管理器。

智能体通过截图观察环境，通过点击、滑动、输入、长按、返回等 GUI 动作执行任务。

每个任务遵循统一流程：

1. **重置：**恢复干净环境，隔离不同任务。
2. **准备：**写入任务所需文件、联系人及上下文，并保存初始状态。
3. **执行：**智能体读取截图并输出动作。
4. **更新：**模拟器执行动作，重复观察—执行循环。
5. **评估：**比较初始与最终状态，判断任务完成情况及违规后果。

**威胁模型有明确边界：**攻击者只能控制用户指令和指定环境载体，例如剪贴板；不能修改系统提示、模型参数、评测框架或任意篡改模拟器状态。

### 2.2 失败蒸馏越狱演化：FDJE

FDJE 的核心是：**根据失败原因调整攻击，而不是对所有任务使用相同策略。**

其流程为：

- **基线探测：**执行原始任务，区分已经攻破、安全拒绝、操作执行失败。
- **按失败类型分流：**
  - 对拒绝任务，使用正常工作流前缀，将危险目标包装成日常任务的延续；
  - 对执行失败任务，使用导航见证和 GUI 提示，降低界面操作障碍。
- **隐式演化：**对仍未成功的任务，将表面正常的指令与承载风险的环境内容分离，使智能体在正常操作过程中接触风险载荷。
- **反馈优化：**依据执行反馈更新提示前缀；只有新候选的进展评分更高才替换当前最优方案，成功或预算耗尽即停止。

一个重要约束是：**演化过程中，违规后果、任务载荷和二元成功判据保持固定。**因此，提高难度主要来自攻击呈现方式的变化，而非放宽成功标准。

不过，原文对“导航见证”的作用存在表述不一致：流程意在减少攻击中的操作失败，但相关段落又称其改善识别和拒绝恶意指令的能力，具体实现仍需进一步材料澄清。

### 2.3 弱点驱动基准扩展：WDBE

WDBE 将已发现的弱点转化为新任务，包含四步：

1. **构建：**结合轨迹、攻击策略和环境约束，生成任务规格，包括指令、环境准备、验证规则和风险描述。
2. **审查：**检查环境可执行性、行为是否确实有害、数据是否具体，以及受害者和损失机制是否合理。
3. **生成与测试：**生成任务代码，进行编译、静态检查、加载检查和判据正负测试。
4. **模拟执行：**验证任务是否能够通过 GUI 实际完成，再决定接纳或修订。

状态判据至少需要满足：

- 环境不变时，不应误判攻击成功；
- 实施预定义违规状态变化后，应能判定成功。

**代码和判据通过测试不等于 GUI 可达。**因此，正式接纳任务还要求版本匹配的 GUI 执行见证。

作者同时设置“冻结版本边界”：新任务只加入后续版本，避免评测过程中任务集持续改变、损害可比性。

### 2.4 分层裁决框架：SAF

SAF 分别记录四类证据：

| 维度 | 含义 |
|---|---|
| 目标采纳 | 是否明确表达接受违规目标 |
| 安全拒绝 | 是否在危险执行前出于安全原因拒绝 |
| 危险行为 | 是否执行了推进违规目标的动作 |
| 违规后果 | 状态判据是否确认攻击完成 |

裁决分三层：

- **L0：规则定位。**通过安全锚点与动作位置确定候选标签，尤其锁定拒绝发生的时间。
- **L1：双轨语义判断。**同一裁判模型在两个隔离上下文中独立判断，并提供逐字引用。
- **L2：证据审计与仲裁。**检查引用是否确实存在；冲突时进行保守仲裁，证据不足则弃权。

双轨调用**不是两个独立标注者**；其价值主要在于暴露判断不稳定性。逐字匹配也只能证明证据来源真实，不能自动保证语义判断正确。

最终报告：

- **TSR：**正常任务成功率；
- **ASR：**攻击成功率；
- **SVR：**危险行为比例；
- **RHR：**违规目标采纳比例；
- **SRR：**及时安全拒绝比例；
- **SU：**复合任务中，完成正常目标且未完成违规目标的比例。

其中，**SU 仍可能包含危险尝试**，不能理解为全过程安全。对于已经确认成功的违规事件，框架统一赋予目标采纳和危险行为标签，且不计拒绝收益；这些是评测约定，不代表对模型内部认知的直接测量。

## 6. 主要结论与发现

### 6.1 隐式攻击降低拒绝、增加危险行为

作者汇总 20 个模型—智能体条件后报告：

- 平均 SRR：**26.8% → 6.6%**；
- 平均 SVR：**68.9% → 86.6%**；
- 平均 ASR：**59.8% → 56.4%**；
- 20 个条件中，19 个条件的拒绝率下降。

**关键不是“隐式攻击总能提高最终成功率”，而是它更容易让智能体进入危险执行。**最终未成功，可能只是界面操作或任务执行失败，不能直接解释为安全对齐有效。

### 6.2 动态演化能进一步暴露弱点

- 跨模型平均攻击覆盖由 **69.6% 提升至 85.9%**。
- 特定攻击比较中，FDJE 达到 **100%**，Tree 为 **94.3%**。
- 匹配的隐式载荷放置优于不匹配放置：**98.6% 对 87.1%**。

需要区分：摘要与图 3 的特定设置中，Qwen3.5-122B 达到 100%；表 3(a) 的另一汇总设置为 **98.6%**。因此，**100% 不能泛化为全部任务和全部条件下的结果**。

### 6.3 扩展任务具有一定跨模型迁移性

WDBE 新增 50 项任务：

- Qwen-122B 首轮 ASR 为 **96%**；
- 其余九个模型首轮 ASR 为 **36%—82%**。

这说明新增任务不仅针对单一目标模型有效，但并不等于对真实手机环境或未知风险具有全面代表性。

### 6.4 常见防御仍不足

图 3(d) 中，Safe-G 将 ASR 从 **83.6% 降至 57.9%**，但剩余风险仍高。输入过滤在该设置下甚至略高于无防御基线，说明不能假定增加过滤层就必然更安全。

### 6.5 SAF 提高裁判一致性

- 与参考标注的一致率：**97.26%**，单裁判为 **91.14%**；
- 困难样本稳定性：**98.1%**，单裁判为 **95.7%**；
- 对目标采纳的识别更接近参考标注。

这些结果支持分层裁决的价值，但仍取决于参考标注和困难样本的质量。

## 7. 主要优点

- **评测对象更贴近实际风险：**关注设备状态变化，而非仅看回答文本。
- **区分能力失败与安全拒绝：**避免将“不会操作”误判成“足够安全”。
- **两种演化互补：**FDJE 深挖已有任务，WDBE 扩展新工作流。
- **成功判据相对稳定：**固定目标后果，并通过冻结版本管理任务更新。
- **生成任务验证较完整：**同时检查规格、代码、判据和 GUI 可达性。
- **裁决可审计：**保留轨迹引用和事件时间，允许证据不足时弃权，而非强行给出标签。

## 8. 不足与局限

### 8.1 模拟器到真实设备的外推有限

这是类 Android 浏览器模拟器，而非完整 Android 系统，抽象了真实进程隔离和在线服务行为。真实权限机制、网络异常、认证流程、系统弹窗及应用更新等因素可能改变风险，因此**“高保真”不等于真实设备验证**。

### 8.2 动态生成存在偏差与过拟合风险

- 从特定模型弱点生成任务，可能偏向该模型的失效模式。
- 反复搜索可能形成对已知判据和任务分布的适应。
- 跨模型测试缓解了这一问题，但不能替代独立保留集和外部验证。

### 8.3 裁决框架仍有解释边界

- 两条判断轨道使用同一模型，可能存在相关性偏差。
- 引用真实不代表解释正确。
- RHR 衡量的是可观察表达及结果一致性标签，**不是模型内部推理是否被真正“劫持”**。
- 排除未决样本可能引入选择偏差，应同时报告弃权率和覆盖率。

### 8.4 状态终点指标无法覆盖全部伤害

最终状态判据可能遗漏中途泄露、部分完成或其他非终点伤害。SAF 的行为指标有所补充，但 SU 仍可能计入曾进行危险尝试的任务。

### 8.5 安全—效用与成本分析不足

正文对正常任务的基础能力有评估，但对防御引起的误拒绝、额外操作成本和用户体验影响分析较少；算力、调用费用及预算信息不足，也限制了方法成本效益的判断。

**总体评价：**MobileJailBench 最有价值的贡献，是建立了“可执行工作流—动态弱点发现—证据化安全诊断”的评测闭环。其结果有力提示：对显式恶意请求的拒绝，并不能保证智能体在移动交互中持续安全；但具体攻击成功率仍应限定在相应模拟器、任务版本、模型与搜索预算之内。
