## 1 Introduction 

As multimodal assistants mature, a shift is underway from a reactive paradigm, in which the assistant waits for an explicit query, to a proactive one, in which it takes the initiative and engages the user unprompted (Wang et al., 2025a; Thinking Machines Lab, 2026). Consider a user wearing AI glasses: the assistant observes their surroundings in real time and decides for itself when to speak—perhaps to flag a safety hazard, or to remind the user to restock an item. No query is ever issued. Beyond producing an appropriate answer, the assistant must produce it at the right, self-determined moment. Central to this shift is the changing role of memory (Figure 1). In the reactive paradigm, memory supplies 

what to say : it augments the user’s query with related context to ground and personalize the answer (Lewis et al., 2020; Packer et al., 2023). The user asks “do I still have sparkling water at home?” and the assistant retrieves the relevant memory to answer. In the proactive paradigm, memory also determines when to speak .Passing sparkling water in a store, the assistant recalls that the user finished the last bottle yesterday, and that recollection is itself what makes a reminder warranted. Memory is no longer only a source of content; it is also the trigger that governs whether to intervene at all. We call this setting memory-driven proactive assistance 

(MPA): given a continuous stream of the user’s current situation (egocentric video in our benchmark) and a long-term memory of their past, and given no query, the system must decide at each moment when to speak and what to say. 1arXiv:2610.22671v1 [cs.CL] 15 Oct 2026 (a) Reactive Memory Augmentation Trigger: explicit user query

Recent work studies proactive assistance conditioned on user context, but in a regime that sidesteps the central difficulty: the fact justifying an intervention is handed to the model directly, as a short profile (Ran et al., 2026) or a stated goal (Zhang et al., 2025). A deployed assistant faces something different. That fact is one fragment among a year of accumulated experience, and locating it is part of the task. The two regimes differ by orders of magnitude in how much memory must be searched, and performance does not survive the transition. Moreover, success is judged asymmetrically . A proactive intervention is an interruption : a reminder that arrives at the wrong moment, or that the user never needed, spends attention the user never offered (Deng et al., 2023). Silence is therefore correct almost all of the time, and a response counts only when its content is grounded and its timing is right. A restock reminder is unwanted when fired too early (user still in class), too late (shopping done), or repeatedly. This shapes both evaluation and design. Evaluation must credit exactly one well-timed response and must include moments where silence is correct, since otherwise a system that always speaks is indistinguishable from one that speaks well. And the system itself must judge not whether a memory is relevant , but whether it justifies intervening .To study this regime we introduce the ProPerMem benchmark : egocentric video paired with a controlled, distractor-rich year-long memory of the user’s past ( ∼618K tokens on average), spanning everyday scenarios (kitchen, shopping, commuting) and reasons to speak up (restocking, safety hazards, unfinished tasks). Each sample is annotated with a human-verified trigger window fixing when a response is due and a ground-truth reminder fixing what it should say; a clip counts as correct only when the assistant speaks once , inside that window, with grounded content. The benchmark also includes clips on which nothing warrants a response, so abstention is measured rather than assumed. Because the memory is synthesized under our control, we can construct conditions that naturalistic data does not admit, above all supplying a sample’s exact justifying evidence. This enables us to run a controlled study of what the task actually demands: a 2 × 2 over memory content (oracle evidence vs. retrieval) and timing (given vs. chosen by the assistant; Section 4). Two findings emerge. First, every model we evaluate performs poorly (at most 15%), including frontier models given summarized or retrieval-augmented memory, so the gap is not an artifact of model scale. Second, the two axes are 2independently necessary: with oracle evidence delivered inside the trigger window GPT-5.3-Chat reaches 96.0%, but only 38.0% if it must choose the timing itself, and 15.3% if the evidence is retrieved rather than given. Generation is not the bottleneck; delivering the right memory at the right time is, and dropping either factor is catastrophic. Guided by this, we design ProPerAgent with a plug-and-play harness that addresses both axes at once. ProPerAgent organizes the user’s past into episodic and semantic memories as a graph and traverses it to surface memory related to the current scene; a gate then discards what is accurate but not worth interrupting for, so the generator sees evidence only when a reminder is warranted. A lightweight RL post-training stage adapts the generator to the harness and curbs early and repeated firing. ProPerAgent raises strict accuracy from below 10% to 37.5% on an open-source model and 38% on GPT-5.3-Chat with no training at all; post-training reaches 42.4%. In summary, our contributions are as follows: • We identify what makes memory-driven proactive assistance hard . A controlled factorial study separates the problem’s two axes and shows they are independently necessary: removing either collapses performance from a 96% oracle ceiling to 38% and 15% respectively. • We build the instrument that makes this measurable: the ProPerMem benchmark , pairing egocentric video with year-long, distractor-rich personal memories and human-verified trigger windows, with a protocol that scores whether, when, and what an assistant says, and credits a system only if it stays silent the rest of the time. • We show the diagnosis is actionable . ProPerAgent, built on a plug-and-play harness, retrieves from a graph-organized memory and gates the result on whether it justifies interrupting—not merely whether it is relevant—lifting strict accuracy from below 10% to 37.5% on an open-source model and 38% on GPT-5.3-Chat without any training; a lightweight RL stage reaches 42.4%. 

## 2 Related Work 

Memory augmentation. Memory augments a model with knowledge beyond its context, retrieved from an external store and, in recent systems, organized as a long-term episodic and semantic record of a user’s past (Guu et al., 2020; Karpukhin et al., 2020; Lewis et al., 2020; Izacard and Grave, 2021; Asai et al., 2024; Edge et al., 2024; Packer et al., 2023; Park et al., 2023; Zhong et al., 2024; Huang et al., 2026; Yang et al., 2025; Lin et al., 2025; Long et al., 2025; Yeo et al., 2025; Luo et al., 2025; Jiang et al., 2025). Across this line the query is in hand: memory is retrieved to answer or ground an explicit request, and success is measured by the quality of that answer. In our setting there is no explicit query; the system must continuously interact with its memory as the surroundings unfold and decide whether to intervene at all, so the evidence must be found before it can be used. 

Proactive assistance: settings, evaluation, and method. Proactive assistants differ in how much of what to say is handed to them in advance (Table 1). In most settings the evidence licensing a response is given, so only the timing is ever in question: prior work supplies an explicit question at fixed timestamps (Lin et al., 2024; Niu et al., 2025; Wang et al., 2025d), a question answered at a model-chosen time (Wang et al., 2025a), a task-guidance goal (Zhang et al., 2025), or a short user profile (Ran et al., 2026). 1 Because the content is given, their evaluation grades mainly timing: needless speech is scored as an aggregate precision term (Zhang et al., 2025; Gong et al., 2026), and hit-style measures credit any interval containing one correct response (Ran et al., 2026). Their methods, in turn, learn when to speak from the supplied content (Chen et al., 2024; Wang et al., 2025b), some with reinforcement learning (Wang et al., 2025c; Ran et al., 2026). Our setting removes this given-content assumption: with no query and the evidence buried in a long personal memory, the system must find what to say before it can decide when , which forces evaluation to grade content and timing jointly and requires a method built for retrieval rather than given context. Most similar is concurrent work (Gong et al., 2026), which proposes EgoServe, a benchmark for proactive assistance over continuous egocentric video, with the training-free EgoMemo agent. ## 3 The ProPerMem Benchmark 

We introduce ProPerMem , a benchmark for memory-driven proactive assistance (MPA) . Unlike reactive benchmarks that pair an explicit query with a target answer, ProPerMem asks a system to watch an egocentric video stream, consult a long-term memory of the user’s past experiences, and emit a grounded proactive intervention only when warranted and only at the right time . We first formalize the task (Section 3.1) and define the evaluation metrics (Section 3.3); the data construction pipeline is deferred to Appendix C, with human annotation details (annotator count, review questions and response distributions, verdict aggregation, and acceptance rate) in Appendix C.1. 

3.1 Problem Definition 

Setup. A proactive assistant observes a user’s experience as an online multimodal stream V = ( v1, v 2, . . . ),where vt is the observation at timestep t, and has access to a long-term memory M2 accumulated from the user’s past experiences. The setting is causal and query-free : at each timestep t the system conditions on a recent observation window Vt−n:t = ( vt−n, . . . , v t) together with M, and receives no explicit user query.

Correctness. The long-term memory determines a set of admissible trigger windows 

W(M) = { W1, . . . , W m }, Wj = [ tsj , t ej ],

where each window Wj corresponds to one worth-intervening matter, with start and end times tsj and tej . If a matter’s target appears intermittently (e.g., visible over 2–8 s and again over 40 –48 s), Wj is defined by its first appearance ( 2–8 s here): the desired behavior is to intervene at the earliest appropriate moment, and later reappearances do not open new windows: once that earliest appropriate moment has passed, re-raising the same matter is a redundant interruption rather than a new opportunity to help. In ProPerMem, visible segments separated by at most 8 s are treated as one appearance, and each clip contains exactly one such window (Appendix C). An intervention (ti, a i) ∈ E(π) is correct if it fires within its corresponding window ( ti ∈ Wj ) and its content is faithful to the relevant memory and grounded in the current frame (Judge (ai | mj , v ti ) = 1 , where mj ⊆ M is the evidence attached to window j); otherwise it is incorrect. The desired behavior is exactly one correct intervention per window and silence elsewhere: firing outside Wj is early- or late-triggering, and repeated firing is over-triggering.

3.3 Evaluation Metrics 

Each instance in our dataset has a single trigger window W = [ ts, t e], so we state the metrics per clip. Let 

{f1, . . . , f k} be the timestamps at which a system fires. Following Section 3.1, a fire is correct if it is in-window 

(ts ≤ fi ≤ te + δ, the right moment, with a timing tolerance δ defined below) and its content is Good , i.e. the intervention afi is judged sensible by an LLM judge 3 conditioned on the window’s evidence m ⊆ M and the current observation vfi (Judge (afi | m, v fi ) = 1 , the right content). 

Clip-level behaviors. We then summarize a system’s firing behavior on each clip with the following measures: • Hit : the clip has at least one correct fire ( ∃ fi ∈ [ts, t e + δ] with Good content), i.e. the system ever says the right thing at the right time, ignoring any extra or mistimed fires. • Early-trigger : the system fires before the window ( ∃ fi < t s), i.e. it speaks before the reminder is warranted. • Late-trigger : the system fires after the window ( ∃ fi > t e + δ), i.e. it speaks once the moment has passed. • Over-trigger : the system fires more than once ( k > 1), i.e. it interrupts the user repeatedly. • Perfect (primary metric): the system fires exactly once , in-window and Good , i.e. a Hit with no early-, late-, or over-trigger:

Timing tolerance. Since the sliding-window paradigm decides only every 2 s (Section 4.1), a fire at the first decision step after te may still be the right moment; we therefore set δ = 2 s by default. Requiring exactly one intervention is deliberate. Because each utterance is an interruption, repetition is a failure even when the content is right: an assistant that delivers the correct reminder three times has interrupted the user twice for nothing. 4.1 Proactive Paradigms 

A proactive assistant must make a decision at every moment of an unbounded stream, so how it consumes the stream shapes what it can see at each decision. We study the two paradigms in which such assistants are commonly deployed. Both are online and causal, and they differ only in how visual context is carried across decisions, so any way of supplying memory, including ProPerAgent, can be plugged into either. Under both paradigms, the agent can see its own past intervention history. Figure 4 summarizes the prompt structure of both paradigms and where each memory method enters it; full prompts are in Appendix A for ProPerAgent and Appendix B for the baselines. 

Sliding-window paradigm (Wang et al., 2025a). In our implementation, the agent continuously observes the stream through a short sliding window, making a decision every 2 s from the four most recent frames: the current frame and the three preceding ones, sampled at 1 s intervals. Each window is processed independently, and no visual context is carried from one decision to the next. The cost of a decision is therefore constant regardless of how long the stream runs, but the model cannot draw on what it saw outside the current window. 

Streaming paradigm (Chen et al., 2024; Wang et al., 2025c). In our implementation, the agent receives one new frame every second and appends it to a persistent visual context, reusing the KV cache so that each step only processes the new frame, and it may respond at any frame. Each turn consists of one new frame and the agent’s response to it. 4.2 RQ1: Does having the memory suffice? 

We first ask whether simply having the memory is enough. We evaluate a range of open-source and proprietary models under four settings, all letting the model decide its own timing (it may fire at any step): None-history 

(only the current view, no memory), All-history (the entire history kept in context at all times; if it exceeds the context window, it is truncated to the most recent portion that fits), Summary (a 200–300-word summary of the history kept in context; generation prompt in Appendix D.4), and Standard RAG (the top-k retrieved events, injected at every decision frame based on what the agent observes; we sweep k ∈ { 1, 2, 5, 10 , 30 , 50 }

and report the best). 4 Results under the windowed paradigm are in Table 3. Across all models and all settings, Perfect stays low, and the breakdown is telling. Without any history (None-history), Perfect stays below 1% for every model (at most 0.6%), confirming that the task genuinely hinges on memory. Yet simply dumping the entire history into the context (All-history) or condensing it into a summary (Summary) fares little better: Summary reaches at most 4.4% and All-history at most 6.1% (both on claude-sonnet-5). With the full history in context, models often surface related content (e.g., 83.9% Hit 

for GPT-5.3-Chat) but fire almost everywhere (99.9% over-trigger; Table 20). The few memories relevant to the current scene are buried in a long, distractor-rich history, and such simple means cannot tell when they warrant an intervention. Standard RAG helps only marginally: for Qwen3.8-27B it lifts Hit to 42.5% (Table 5), so the right content is sometimes surfaced, yet Perfect reaches only 7.0%; even the strongest frontier baseline, claude-sonnet-5 at its best k, reaches only 15.0%, showing that retrieval alone does not solve the joint problem of when to speak and what to say. The same conclusion holds under the streaming paradigm on Qwen3.8-27B (Appendix E, Table 15), confirming that the difficulty is not an artifact of one paradigm.  

> Observation 1.

No. Having the memory does not suffice: with the full history, a summary, or retrieved fragments in context, even frontier models fall far short of a usable assistant. 

4.3 RQ2: If not, what is missing — the content, the timing, or both?

## 5 Method 

Section 4 shows that the crux of memory-driven proactive assistance is to deliver the right memory at the right time : the correct memory surfaced at the wrong moment, or the right timing paired with poorly constructed or irrelevant memory, each collapses performance, and only with both does the generator reach its ceiling. Inspired by this finding, we design ProPerAgent (abbreviated PPA in figures) with a plug-and-play harness that aims to surface the relevant memory precisely when it matters, together with an RL post-training stage  

> on the generator only

that adapts it to the harness and further improves performance. We describe the harness in Section 5.1 and the post-training in Section 5.2. 

5.1 The ProPerAgent Harness 

ProPerAgent keeps the paradigms of Figure 4 unchanged and aims to provide the right evidence at the right time, changing only what fills the <evidence> slot. Its two components address the two axes of Section 4.3. For 

> content

, ProPerAgent organizes the user’s past into a graph of episodic and semantic memories and matches it against the objects the user is observing, so that the delivered memory is structured and captures the key information rather than a set of noisy raw passages. For timing , a gate fills the slot only when the retrieved memories are worth intervening on, refining them into a single piece of evidence; otherwise the slot is set to 

none , so that memories that are irrelevant or not worth intervening on do not mislead the generator. The presence of evidence thus becomes one of the signals for when to intervene, while the generator still makes the final decision from the evidence and the current view. Concretely, ProPerAgent wraps the generator in a short agentic loop and pairs it with a retrieval module that supplies memory on demand (Figure 5 and Algorithm 1). Memory construction. We organize the user’s long-term memory as a graph with two layers: an 

episodic layer of object-keyed memories of past events, so that an object in view directly retrieves related experiences, and a semantic layer of stand-ing user facts such as preferences and constraints. Each memory carries an open-loop flag marking an unresolved intention, constraint, or issue that may warrant intervention. The construction follows standard KG-memory practice (Gutiérrez et al., 2025; Yeo et al., 2025) (details in Appendix I). 

Retrieval and gate. Given the observation entity as a query, we embed-match it to seed entities and pull their one-hop episodic and semantic facts as 

candidate evidence, and run Personalized PageR-ank on the graph to reach relevant facts beyond one hop. However, many retrieved memories, though real, are not a good reason to remind or inter-vene: the object may merely co-occur with a past mention, or its open loop may already be resolved. Feeding them all to the model would distract it and cause false triggers. We therefore pass the can-didates through the gate , a single LLM call that reads them against the observed object, filters out those not worth intervening on, keeps the ones that are, and refines them into a single clear piece of evidence (or abstains); this refined evidence (or nothing) is what the generator consumes. Effectively, the gate asks the question retrieval cannot answer: not whether a memory is relevant, but whether it justifies intervention; removing the gate costs 13.3 points (37.3 →24.0, Section 6.3) and ProPerAgent as a whole cuts the false-trigger rate on silent clips from 77.3%/84.0% for RAG to 15.3% (windowed/streaming). 

5.2 Post-Training 

The harness is designed to deliver the right memory at the right time, but it cannot be perfectly accurate. Section 4 shows the generator has a tendency of its own: with correct evidence available at every step, letting it choose the moment still collapses Perfect (77.3 →26.0, 96.0 →38.0; Table 4). To further lift performance, we post-train the generator , teaching it to adapt to the harness and to acquire a sensible firing policy. 

Rollout. We adopt the tool-integrated formulation. At a decision step the generator receives the current frame(s) and, following the harness protocol, issues a retrieval call with the observed object; the harness executes retrieval and the gate and returns the refined evidence as a tool message, after which the generator produces its reason and answer (fire with a grounded reminder, or stay silent). The evidence is injected by the tool rather than generated by the model, so we mask the evidence tokens when computing the loss: only the tokens the generator itself produces (its observation call, reason, and answer) contribute to the policy gradient. 

Reward. The reward is verifiable from the benchmark annotations. Let yt ∈ { fire , silent } be the model’s action at step t and a the reminder it emits. 6.2 Main Results 

We compare ProPerAgent against a range of baselines in Table 5, and Figure 6 further visualizes Qwen3.8-27B with Standard RAG under different retrieval depths k. Two clear trends emerge. First, simply wrapping a base model in the ProPerAgent harness—without any training—already improves performance by a large margin: on Qwen3.8-27B, Perfect rises from 7.0% (Standard RAG at its best k) to 37.5% in the windowed setting and from near zero to 33.3% in the streaming setting. A similar improvement holds on a frontier model: wrapping GPT-5.3-Chat in ProPerAgent (inference-only) reaches 38% Perfect (Appendix F, Figure 12). This is because the harness delivers structured, gated memory, surfacing the right evidence only when it is worth intervening, so the generator no longer has to sift the relevant cue from a long, noisy memory on its own. Second, adding RL post-training further lifts Perfect (windowed 37.5 →42.4 , streaming 33.3 →40.6 ), with the clearest gains in firing discipline: over-trigger drops markedly (windowed 22.3 →13.5, streaming 32.8 →25.3) and so does early-trigger (windowed 20.9 →19.3, streaming 26.1 →24.0). Because the reward uses 12 the same judge as our metric, one might expect the gain to reflect judge-specific adaptation. It does not. If the policy had learned to satisfy the judge, more of its interventions would be scored good and Hit would rise; instead Hit is flat (54.6 to 54.0). What improves is when and how often the model speaks, over-triggering and early firing, which are checked against the annotated trigger window rather than scored by the judge. This shows that, on top of the harness, the generator better learns to combine the returned evidence with the current observation to judge whether and what to say, rather than firing prematurely or repeatedly. 

Why do straightforward memory baselines fail? Figure 6 visualizes Standard RAG on Qwen3.8-27B under different retrieval depths k, which further explains why RAG baselines fail and demonstrates the advantage of ProPerAgent. Panel (a) shows that the gradual improvement in Hit comes with a disproportionate increase in over-triggering. Panel (c) exposes the mechanism: as k grows, fires per clip rises rapidly, so the model improves recall largely by speaking more often, including at irrelevant or mistimed steps. Consequently, these extra fires overwhelm the recall gain and Perfect collapses in panel (b). In contrast, ProPerAgent shifts the Pareto frontier toward a better trade-off, preserving useful-memory recall while suppressing unnecessary interventions. This shows that ProPerAgent’s gated memory mechanism more effectively delivers the right memory at the right time, leading to the desired proactive behavior. 

6.3 Further Probing 

To better understand ProPerAgent, we probe its generalization, its behavior on negative samples, and the contribution of each component (Figure 7). Generalization. Transferred without adaptation to 100 samples from the unseen Epic-Kitchens dataset, the harness lifts Perfect from at most 11.0 (always-on RAG) to 41.0 windowed and 37.0 streaming, and the Ego4D-trained generator further reaches 49.0 and 41.0, showing that the learned firing policy transfers across domains. Negative samples. On 150 clips whose relevant memory is removed, so that the assistant should stay silent throughout, straightforward memory baselines still fire on most clips (77.3%/84.0% for Standard RAG, windowed/streaming), whereas ProPerAgent fires on only 15.3%, and RL lowers this further to 14.0%/14.7%. Ablation. On 150 samples randomly chosen from the test set, starting from the harness without RL (37.3 windowed), removing the gate costs 13.3 points, confirming its role in delivering memory at the right time; replacing the structured graph memory with Standard RAG, even with the gate kept, costs 16.6 points, confirming the need for the right memory; and hiding the model’s own past responses causes the largest drop (to 8.0), showing that the speaking history is key to curbing over-triggering. Streaming shows the same trends. 

## 7 Conclusions 

We studied memory-driven proactive assistance, where memory determines not only what an assistant says but whether and when it should speak at all. A controlled study isolates what the task demands: the right memory and the right timing are independently necessary, and missing either collapses performance from a 96% oracle ceiling to under 40%. Acting on this diagnosis, ProPerAgent, with its gated harness, lifts strict accuracy from below 10% to 37.5% with no change to model weights, and to 42.4% with lightweight RL post-training. 13 Limitations 

First, the long-term memories in ProPerMem are synthesized and text-based (rendered caption streams) rather than recorded multimodal histories. This reflects a practical constraint: generating year-long multimodal video of a user’s life remains challenging, and existing long videos are insufficient to support a controlled study with deterministic trigger windows. Synthesis lets us know exactly which memories justify each intervention, which is what enables the oracle conditions of Section 4.3; extending the benchmark to naturalistic multimodal histories is left to future work. Second, we evaluate task performance rather than latency, since end-to-end latency in production depends on many factors, including hardware, infrastructure, and network conditions, and thus varies case by case. System-level optimizations, such as skipping unnecessary retrieval steps or combining fast and slow models, are left to future work. Third, each clip contains a single trigger window. Although most baselines already perform poorly in this setting, richer scenarios with multiple and more diverse triggers per stream, as well as adversarial content in the long-term memory, are promising directions for extending the benchmark.

Figure 8 The ProPerMem data construction pipeline. We scan a target object over the full Ego4D clip, merge visible segments separated by at most 8 s into a single appearance, and use its first and last visible timestamps to define the trigger window (Step 1). An LLM proposes episodic and semantic memory evidence, which is iteratively checked by a worth-triggering gate to form a grounded memory bubble (Step 2). We then condition a categorized event timeline on a personalized persona and render its events into a stream of visual-action and conversation captions (Step 3), before model QC and human review (Step 4). 

Step 1: Trigger localization. We first use an LLM (GPT-5.6-sol) to select a target object whose appearance constitutes a natural opportunity for a proactive intervention (e.g., passing S.Pellegrino sparkling water on a shelf). We then scan the target object over the entire egocentric clip and record its visibility trace, merging visible segments separated by gaps of at most 8 s (e.g., brief look-aways or occlusions) into a single appearance. Each clip is selected to contain one such appearance, whose first and last visible timestamps, ts and te, define the candidate trigger window W = [ ts, t e], thereby grounding when an intervention is appropriate. Under this merging, W is exactly the first-appearance window of Section 3.1. 

Step 2: Memory bubble generation. For each target object we generate a memory bubble : a small piece of synthetic but plausible personal history that makes seeing the object now worth a proactive intervention. Conditioned on the target and localized frames, an LLM proposes episodic evidence (e.g., “I finished the last bottle yesterday”), semantic evidence (e.g., “I keep sparkling water at home”), or both, which together support an intervention at the trigger window. Each proposal passes a worth-triggering gate that checks grounding, target specificity, and whether seeing the object genuinely warrants a reminder. The retained bubbles span a range of everyday reasons (Figure 2). 

Step 3: Long-horizon life-stream construction. A memory bubble in isolation would make the triggering evidence trivial to find. We therefore weave it into a coherent, long-horizon life stream . We first synthesize a personalized owner persona (biography, relationships, preferences, and routines). Conditioned on this persona, we then construct a year-long timeline of events. These events fall into four types: main-arc milestones (e.g., starting a new job), persona-derived interests (e.g., a weekend hiking trip), neutral daily distractors (e.g., doing the laundry), and the evidence (the memory bubble from Step 2). Finally, each event is rendered into a sequence of timestamped first-person captions, where [V] denotes visible actions and [C] denotes conversational content. For example, a dinner event in which the last sparkling water is consumed can become 

[V] I take the last S.Pellegrino from the fridge , followed by [V] I pour it into my glass at dinner and [C] I should restock sparkling water . Together, they form a realistic long-horizon human history, where the related memory evidence occupies only a very small portion of the long-term memory M.

Step 4: Verification. Each sample then passes model-based quality control (checking that the memory is grounded in the video, specific to the target, genuinely warranted at the trigger moment, and not contaminated by unrelated objects in the life stream), followed by human review that accepts, fixes, or rejects it. This 22 yields human-verified trigger windows and ground-truth reminders , so that both the timing and the content of a proactive intervention can be evaluated rigorously. The final benchmark comprises 1,804 human-verified instances, with long-term memories averaging 618K tokens (with timestamps). 

C.1 Human Annotation Details 

All 2,168 candidate samples produced by Steps 1–3 were sent to human review, and 2,153 of them received at least one judgment. A total of 32 trained annotators took part, contributing 5,982 judgments. Most samples were reviewed independently by three annotators (1,889 samples, 87.7%); a small pilot batch and a few remaining samples received one or two reviews, and no sample received more than three. Annotators worked in a dedicated interface that plays the egocentric clip alongside the target description, the memory evidence, and the machine-proposed trigger window, and they answered the following questions for each sample. • Target visibility. Is the target object clearly visible in the clip, and is it the object described? (95.8% of judgments: yes.) • Trigger window. Is the machine-proposed trigger window correct? Annotators either keep it, adjust its boundaries on the video timeline, or mark it as unusable. When adjusting, annotators move the boundaries to the onset and end of the target’s single appearance (Step 1), treating brief look-aways of at most 8 s as part of it. (82.7% kept, 14.2% adjusted, 3.1% unusable.) • Reason to remind. Given the user’s memory, does the reason for the reminder hold up, i.e., is the reminder genuinely warranted at this moment? (93.0%: yes.) • Memory–event consistency. Does the rendered life-stream evidence describe the same event as the memory that justifies the reminder? (98.4%: yes.) Based on these answers, each annotator gives an overall verdict: accept (keep the sample as is), fix (keep it after correcting the trigger window), or reject (drop it). We aggregate verdicts by majority vote. Under this rule, 1,804 samples (83.8% of the reviewed samples) are accepted.

## G Post-Training Details 

Data. We post-train Qwen3.8-27B on 3,465 unique timestamp-level states from 904 source clips, disjoint from the fixed evaluation UIDs. The data comprise 1,283 in-window fire states, 642 early states, 1,283 already-spoken states, and 257 no-evidence guard states. Across deploy-ment paradigms, each training state is anchored at a labeled frame, and we roll out the policy at that frame. The re-sponse history preceding the labeled frame is supplied as oracle history. 

Optimization. We use MS-Swift GRPO with LoRA rank/alpha 16 /16 on the language projections; the vision encoder and aligner remain frozen. We use G = 4 rollouts per prompt for 963 updates (one pass over the data). We train in BF16 with AdamW, a constant learning rate of 10 −6, no warmup, weight decay 0.01 , betas (0 .9, 0.999) ,gradient clipping at 1.0, group-normalized rewards, GRPO clipping ϵ = 0 .2, and KL coefficient 0.01 . Rollouts use temperature 1.0, top-p = 0 .95 , and a 528-token total response budget, with 48 tokens for observation and 160 for the final answer. Training uses seven H100 GPUs (four FSDP2 trainer GPUs, two TP2 rollout GPUs, and one frozen-gate GPU) and completes in 14.6 hours. 29 H LLM Judge Prompt

## I ProPerAgent Memory Construction Details 

I.1 Memory Construction Pipeline 

ProPerAgent converts the user’s captioned life stream into an episodic–semantic memory graph before inference. The episodic layer preserves individual experiences and their temporal provenance, while the semantic layer stores durable facts that recur across experiences. Table 18 summarizes the construction pipeline. 

Table 18 Episodic–semantic memory construction pipeline.   

> Stage Input Output

Event segmentation Chronological life-stream captions Captions are grouped into events; a temporal gap greater than 

60 s starts a new event. Faithful rewrite Captions within one event A coherent first-person event passage that preserves objects, states, locations, quoted speech, intentions, and outcomes. Episodic extraction Rewritten event passage OpenIE entities and subject–relation–object triples, together with day, time, event ID, and source-caption provenance. First-person intentions are also mirrored onto their target object. Semantic abstraction Chunks of episodic events Deduplicated standing triples describing durable habits, pref-erences, constraints, safety rules, relationships, and recurring intentions. Graph indexing Episodic and semantic triples Normalized entity and semantic-triple embeddings, entity co-occurrence edges, semantic co-mention edges, and embedding-based synonym edges. 

For an episodic triple, the subject and object become graph entities and the predicate records their relation. 30 The event passage remains attached as provenance, so retrieval can return either a compact fact or the surrounding narrative. Mirroring makes an open loop reachable from the visible object: for example, an intention stated as [I, intend to, buy milk] is additionally represented as [milk carton, needs, restocking] .Facts that express an unresolved intention, constraint, or object state receive an open-loop flag, which is used as a retrieval cue rather than an automatic decision to intervene. Semantic triples are extracted from groups of 40 events and retain only reusable standing information, including habits, preferences, dietary and safety constraints, standing rules, relationships, and recurring intentions. 

I.2 Retrieval at Inference Time 

After the first policy turn identifies the object(s) in focus, ProPerAgent embeds each object name and matches it to the closest entity nodes. The matched nodes seed two complementary retrieval paths. First, one-hop lookup returns episodic triples attached to the matched entities, together with semantic triples selected by entity links or direct embedding similarity. Episodic facts are ranked using entity similarity, open-loop cues, and recency. Second, personalized PageRank propagates the entity seeds over the graph to recover related event passages that may not share the exact observed object name. Entity co-occurrence, semantic co-mention, and embedding-based synonym edges support these multi-hop paths, while generic hub entities are down-weighted. The retrieved memory is rendered for the shared Gate in the following order: event passages, standing semantic facts, and individual episodic triples. This ordering gives the Gate both the causal event narrative and the compact facts needed to decide whether a specific open loop is actionable in the current scene.
