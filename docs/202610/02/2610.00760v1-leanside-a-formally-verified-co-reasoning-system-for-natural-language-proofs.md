## 摘要
大型语言模型日益被用作演绎推理任务的协作者，但其输出可能产生幻觉，或使用户偏离预期的推理路径。形式化证明助手能够提供机器检验的验证，但学习门槛较高，而且要求比人类书写的证明更加细粒度的推理。我们探索了一种结合两者优势的交互界面：用户可以用自由形式的自然语言撰写和修改证明，同时由经过验证的后端检查其推理，并按照用户所需的粒度提供反馈。我们以本科数学教育为背景研究这一交互界面，开发了 LeanSide——一种经过形式化验证的协同推理系统。该系统会自动将学生的推理形式化为 Lean 代码，并将验证器的输出转换为易于理解的反馈。我们通过课堂部署开展用户研究，并分析了哪些系统特性有助于学生推进解题，以及哪些特性会使他们陷入困境。基于这些发现，我们提出了在人工智能协同推理系统中使用经过形式化验证的后端的设计启示。

## Abstract
Large language models are increasingly used as collaborators on deductive-reasoning tasks, but their outputs can hallucinate or pull users away from intended reasoning. Formal proof assistants provide machine-checked verification, but have a steep learning curve and require more granular reasoning than human written proofs. We explore an interface that combines these strengths, allowing users to write and revise free-form natural-language proofs while a verified backend checks their reasoning and returns feedback at the user's granularity. We study this interface in the context of undergraduate mathematics education by developing LeanSide, a formally verified co-reasoning system, which auto-formalizes student reasoning into Lean and informalizes verifier output into understandable feedback. We conducted user studies through classroom deployment and analyzed which system properties helped students make progress and which caused them to get stuck. We use these findings to derive design implications for using a formally verified backend in human-AI co-reasoning systems.

# LeanSide 论文总结

## 1. 核心问题与研究意义

- **研究问题**：能否让不会使用 Lean 的学生，直接用自然语言撰写和修改数学证明，同时获得机器核验的反馈？
- **背景与动机**：大语言模型能理解自然语言、提供建议，但可能给出貌似可信的错误推理，或把学生带离原有思路；Lean 等证明助手能严格检查形式化证明，却要求用户学习专门语言，并写出远比课堂证明细致的步骤。
- **整体含义**：论文探索的不是“自动替学生完成证明”，而是**以形式化验证支撑学生自己的推理过程**：系统尽量忠实地理解学生写下的内容，检查其有效性，再把结果转换成学生能够检查和利用的反馈。

## 2. 方法论：LeanSide 如何工作

- **交互流程**：学生输入文字或上传手写证明 → 系统将证明转成 Lean 表述并尝试验证 → 将表述和验证结果译回自然语言 → 学生检查系统是否理解了自己，并据此修改证明。
- **预处理与拆分**：系统先处理指代不明、语句究竟是“声明”还是“断言”等歧义，再把连续推理拆为与学生表达内容相对应的最小推理单元。界面会显示部分消歧结果，供学生核对。
- **逐步形式化与验证**：每个断言被转换成对应的 Lean 引理命题；引理证明器逐一尝试证明，之后由证明组装器检查已验证的步骤能否完成整道题。生成代码失败时，基于 Lean 的报错进行有限次数的重试。**生成一个可供编译的命题框架，不等于该断言已被证明**；最终反馈取决于后续验证。
- **课程粒度的辅助库**：为兼顾响应速度和课堂要求，研究者建立了小型引理库，包括对应评分标准的引理，以及学生通常无须写出、但证明器需要的辅助引理。
- **反馈与透明性**：界面把学生原步骤和系统译回的表述并列展示，并提供局部错误、证明未完成提示、下一步提示及“推理跳跃过大”警告；Lean 代码面板可选查看。关键设计是让学生先判断**“系统验证的是不是我原本想说的命题”**，再决定是否信任验证结果。

- **场景**：在一门本科高阶线性代数课程中部署 **13 周**，按课程进度发布 **14 道题**，涵盖向量范数、矩阵性质、特征值和优化等内容。
- **用户研究**：论文分析 **23 场一对一研究会话**。学生在会话中选题、提交证明、阅读反馈并反复修改；研究者结合操作记录、访谈及数学专家评审分析结果。学生可以查阅课程资料和搜索结果，但不能主动使用其他 AI 工具解题。
- **评测对象与标准**：分析了 **137 份提交的证明**及其步骤。评估重点包括：形式化是否忠实于原意、系统判断是否符合专家对课程题目的评定、错误信息是否易懂，以及学生修改后是否取得进展。

## 5. 实验规模与充分性

- **数量**：研究涉及 14 道部署题目、23 场有效会话、137 份证明；论文还对忠实性、正确性、反馈可理解性及证明修改过程进行了步骤级分析。
- **充分之处**：真实课堂中的反复提交，比只评测一次性、规范写成的证明更贴近学生实际使用。数学专家审查系统生成的 Lean 代码与反馈，也使研究能够区分“没有忠实理解”与“理解了但没能证明”。
- **不足之处**：样本来自同一课程、同一所大学，题型相对集中；没有随机对照组、系统性基线或消融实验，因此不能据此确定 LeanSide 相对于其他工具能提高多少学习成效，也不能单独量化各模块的贡献。

## 6. 主要结论与发现

- **验证整体较可靠，但不是无条件可靠**：专家评定的 57 份含错误步骤的证明均被系统标为错误；56 份完全正确的证明中，41 份被正确标记，另有 11 份被误标为含错误、4 份被误标为未完成。24 份步骤正确但未完成的证明中，22 份被正确识别。
- **忠实性对错误步骤尤其关键**：正确步骤中有 **18/1038** 个被评为形式化不忠实；错误步骤中则为 **22/117** 个。一个典型原因是系统在形式化过程中悄悄修正了学生的小错误，导致“验证通过”的内容并非学生原话。
- **“指出有错”不等于“解释清楚错误”**：专家认为，**61/97** 条步骤级错误信息恰当地说明了问题；未完成证明的错误信息仅 **3/13** 条达到这一标准，而下一步提示为 **11/13** 条。主要障碍是 Lean 的底层证明义务与学生所需的课堂解释粒度不一致。
- **学生可以借助反馈推进，但仍需自行判断**：论文报告，多数被编码的修改带来了有效进展。学生利用局部报错修补证明，也借助系统译回的表述发现歧义、把模糊直觉写得更严谨；下一步提示和推理跳跃警告有时同样有效。相反，当反馈过于底层、学生缺少整体策略，或形式化偏离原意却未被发现时，学生会受阻甚至走偏。
- **信任建立在核对过程上**：学生并非看到“验证通过”就立刻确信证明正确；他们通常在逐步确认系统表述符合原意后才更有信心。多数学生认可背后存在 Lean 代码的价值，但认为直接阅读代码没有带来额外所需信息。

## 7. 优点

- **研究目标贴合真实交互**：重点处理学生尚未写完、含歧义或含错误的证明，而非只处理润色完成的范例。
- **把忠实性放在验证之前**：逐步对应并展示系统理解，避免把“Lean 验证了某个命题”误当作“Lean 验证了学生原本的想法”。
- **兼顾技术与使用体验**：同时考察机器判断、反馈能否被理解、学生实际如何修改，揭示了形式化验证接入自然语言界面后的关键设计问题。
- **明确划定适用角色**：论文没有把形式验证包装成完整导师；它指出局部有效性检查的优势，也承认高层策略指导需要其他方法补足。

## 8. 不足与局限

- **外部适用性有限**：参与者主要来自技术相关专业，题目集中于线性代数与优化；其他学科、年级及非技术背景用户的表现尚不明确。
- **依赖课程定制**：评分标准引理和辅助引理需要准备与人工检查。预期之外的正确证明路线或省略的变量类型，也可能被误判为错误。
- **形式正确不自动保证原意正确**：自动修正、歧义解释、声明类型误分类，以及证明器采用与学生预期不同的理由，都可能使绿色“已验证”标记产生误导。
- **反馈和策略支持不足**：底层 Lean 报错经自然语言转换后仍可能难懂；系统善于定位局部问题，却不擅长判断整体思路是否值得继续。
- **缺少受控效果与成本证据**：没有系统性基线、消融、长期学习效果或明确算力与时延报告。论文有力展示了这种交互方式的潜力及失效情形，但尚不能证明其教学效果优于现有替代方案。
