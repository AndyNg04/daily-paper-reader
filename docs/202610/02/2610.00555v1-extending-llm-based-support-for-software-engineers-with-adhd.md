## 摘要
尽管已知注意缺陷多动障碍（ADHD）会带来任务启动、持续专注和任务完成方面的挑战，软件工程工作流程往往并未针对 ADHD 开发者的需求进行设计。与此同时，大语言模型（LLM）日益广泛地集成到编程工具中，但现有系统既未考虑神经多样性，也无法支持开发任务的结构化推进。本文介绍 Tether 2.0，这是一款基于 LLM 的助手，旨在通过覆盖规划、编码、调试和审查的工作流程交互，为 ADHD 软件工程师提供支持。该工具之所以命名为 Tether 2.0，是因为它基于原始 Tether 系统的开源代码和基础构建而成。我们的方法结合了结构化交互模式、感知活动的上下文和持久化记忆，以支持任务推进与连续性。我们通过专家反馈以及一位 ADHD 软件工程师的实际使用，对该系统进行了评估。结果表明，Tether 2.0 能够支持需求澄清、任务分解、渐进式实现、调试和任务完成，同时帮助用户保持进度，并在受到干扰后继续工作。这些发现表明，若在设计中融入工作流程结构和上下文感知交互，基于 LLM 的助手便能为软件开发中的方向把握、持续推进和学习提供支持。

## Abstract
Software engineering workflows are often not designed to accommodate the needs of developers with Attention Deficit Hyperactivity Disorder (ADHD), despite known challenges related to task initiation, sustained attention, and completion. At the same time, large language models (LLMs) are increasingly integrated into programming tools, but existing systems do not account for neurodiversity or support structured progression across development tasks. In this work, we present Tether 2.0, an LLM based assistant designed to support software engineers with ADHD through workflow oriented interaction across planning, coding, debugging, and review. The tool was named Tether 2.0 because it builds upon the open source code and foundations of the original Tether system. Our approach combines structured interaction modes, activity aware context, and persistent memory to support task progression and continuity. We evaluate the system through expert feedback and hands on use with a software engineer with ADHD. Our results indicate that Tether 2.0 supports requirement clarification, task decomposition, incremental implementation, debugging, and completion, while enabling users to maintain progress and resume work after interruptions. These findings suggest that LLM based assistants can support direction, sustained progress, and learning in software development when designed with workflow structure and context aware interaction.

## 2. 方法论与系统设计

- **构建思路：**在原有开源工具 Tether 的基础上扩展为 Tether 2.0，保留其活动感知、对话交互和检索增强等基础，增加跨开发阶段的结构化引导与持久上下文。
- **四种交互模式共享同一会话历史：**
  - **Planner（规划）：**澄清目标、约束和技术选择，将任务拆成可执行、可追踪的清单。
  - **Builder（实现）：**围绕清单提供概念解释、示例代码和渐进式实现指导。

- **上下文与记忆：**系统记录活动窗口、应用名称、窗口标题及空闲状态，将原始活动记录汇总为近期工作模式，再用于生成回复；对话历史和任务清单被持久保存，以便跨模式、跨会话恢复进度。FAISS 向量库检索 ADHD 相关资料，为回复提供参考。

## 6. 主要结论与发现

- 五点量表中，受访者对**任务拆解**的评价最高（均值 **4.00**），其次是任务启动（**3.81**）和减轻开始复杂工作时的认知压力（**3.75**）；中断后重新投入为 **3.63**。
- 持续专注与任务完成均为 **3.31**，采用意愿为 **3.13**，分心风险为 **3.19**。总体上，参与者认为工具对**开始和组织工作**的帮助比对长期保持专注、完成收尾更明确。
- 实际使用者尤其认可规划清单、进度勾选、活动觉察和积极提醒，认为它们有助于启动任务和回到工作中；同时提出希望更好地识别长时间偏离任务的情况。
- 作者据此认为，**结构化工作流、上下文感知和持久记忆**是有前景的支持机制，但效果会随个人偏好、经验水平和工作环境而变化。

## 7. 优点与亮点

- **针对明确的工作流缺口：**不把 ADHD 支持简化为提醒，也不把编程支持局限于代码答案，而是覆盖从需求澄清到审查收尾的过程。
- **重视中断后的连续性：**共享会话历史、持久清单和活动摘要有助于减少重新回忆任务状态的负担。
- **兼顾指导与学习：**调试模式同时提供引导推理和直接建议，揭示了不同支持强度的设计空间。
- **评估视角互补：**同时收集跨领域人士意见与目标用户的使用体验，并报告认知噪声、过度依赖等不利可能性。

## 8. 不足、偏差风险与应用限制

- **效果证据有限：**主观评分与访谈不能替代完成时间、任务质量、学习效果或长期福祉等客观指标；两周、单名目标用户的体验还可能受新奇效应影响。
- **缺少公平对比与消融：**无法判断收益分别来自四种模式、清单、提醒、活动监测还是 LLM 本身，也无法估计相对现有工具的增益。
- **支持可能反成负担：**额外应用、通知及对话可能增加分心和认知负荷；直接给出修复方案还可能使初级开发者过度依赖助手。
- **个体与场景差异大：**ADHD 需求并不一致，高中断团队、不同经验水平及已有个人工作策略的开发者，未必同样受益。
