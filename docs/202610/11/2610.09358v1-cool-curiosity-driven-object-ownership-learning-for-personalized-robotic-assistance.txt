Figure 1: COOL enables personalized object search by combining long-term memory, ownership in-ference, and spatial grounding. Given a natural-language request such as “Find my backpack” (left), the robot first retrieves prior observations linking people and object instances, then infers the likely owner from accumulated human–object interaction evidence (middle), and finally grounds the se-lected object in the map to navigate to its most likely location (right). 

Abstract: Robots are increasingly expected to provide personalized services in everyday environments. To do so, they must ground natural-language commands such as Where is my backpack? or Find my bottle and execute them by reasoning about object instances, people, locations, and ownership. This is challenging be-cause ownership is rarely labeled explicitly and must be inferred from long-term, behavioral evidence of human–object interactions. To address this, we present 

COOL , a novel robotic framework for autonomously learning object ownership from everyday observations and maintaining a long-term spatial memory of its environment. To keep its memory current, COOL uses an agent-based curiosity-driven data collection strategy that guides the robot toward the most promising locations to gain information and refresh stale observations. Offline experiments, ablation studies, and real-world evaluations show that COOL can infer owner-ship relations from real-world interactions and use this knowledge for ownership-conditioned navigation and task execution. Code, prompts, and evaluation data are available at: https://samirahuber.github.io/cool .

Keywords: Spatial Memory, Object Ownership, Robotic Assistance 

## 1 Introduction 

In everyday human environments, robots are increasingly tasked with providing personalized ser-vices through natural-language commands. In such settings, users may issue instructions such as 

Where is Simba’s backpack? or Find my bottle . Executing such commands requires more than ob-ject detection and navigation: the robot must identify the intended object instance, determine who it is associated with, and know where it is likely to be located. This is particularly challenging in shared environments such as offices or homes, where ownership is often ambiguous because objects may be visually similar, shared, borrowed, or moved over time. Ownership is rarely directly ob-servable: people do not continuously label their belongings, and ownership can become ambiguous

Object ownership must therefore be inferred indi-rectly from repeated observations, spatial context, and human–object interactions. A service robot must collect and maintain long-term evidence about people, objects, places, and interactions. Existing work addresses parts of this problem, but not the full ownership-learning pipeline. Memory-based navigation systems store spatial, semantic, or temporal observations for object search and embodied question answering, but do not model persistent ownership relations [1, 2, 3, 4, 5, 6, 7]. Conversely, personalized object-search systems often require explicit user input, demonstrations, or visual references [8, 9, 10, 11, 12, 13, 14, 15]. What remains missing is a robotic system that autonomously learns ownership from long-term observations and uses it for task execution. In this paper, we address this gap by treating ownership as a latent relation inferred from long-term robot observations rather than as an explicit label. Our framework associates repeated detec-tions of people and objects, records human–object interactions, and converts accumulated evidence into ownership-conditioned actions for personalized object search. Specifically, we present COOL 

(Curiosity-Driven Object Ownership Learning for Personalized Robotic Assistance ), an integrated framework for ownership-aware object search in shared human environments. COOL maintains a long-term spatial memory that links people, object instances, locations, and interaction histories over time. It continuously clusters repeated observations using re-identification, detects human–object interactions as ownership evidence, and records where people and objects have been observed. A curiosity-driven agent guides the robot toward under-observed areas to refresh stale or incomplete memory. At query time, a user-facing agent resolves commands such as Find Simba’s backpack 

by retrieving relevant observations, inferring likely person–object relations, and selecting the corre-sponding object instance (see Fig. 1). We evaluate COOL through offline experiments, ablations, and real-world tests in an office environ-ment. These experiments assess the framework’s ability to associate repeated observations of the same people and objects and infer ownership relations from human–object interaction evidence. It updates object locations over time and uses this knowledge for object search and navigation. Com-bining long-term spatial memory, re-identification, interaction detection, and active data collection enables robots to autonomously acquire ownership knowledge and apply it to personalized tasks. In summary, the main contributions of this paper are: (1) Ownership inference : a dynamic frame-work for inferring person–object ownership from long-term robot observations, without explicit labels, demonstrations, or dialogue. (2) Persistent spatial memory : a structured memory link-ing people, object instances, locations, and human–object interaction histories. (3) Ownership-conditioned task execution : a tool-using agent that answers ownership-conditioned questions and executes navigation commands from memory. (4) Memory refresh : an autonomous data-collection agent that seeks informative locations and refreshes stale observations. 

## 2 Related Work 

Memory-based Navigation. Recent work gives embodied agents long-term memory for object search, exploration, and embodied question answering. These methods store prior observations as maps, graphs, vector memories, or scene graphs, and often combine them with large language models (LLMs) or vision-language models (VLMs) for retrieval and reasoning [1, 2, 3, 4, 5, 6]. Retrieval-augmented navigation and multimodal retrieval-augmented generation (RAG) reuse prior episodes or perceptual streams for navigation and temporal reasoning, while general LLM memory systems focus on textual recall and memory consolidation [7, 16, 17, 18, 19, 20]. Unlike prior work, COOL links persistent people, objects, locations, and interaction histories to infer person–object ownership relations for personalized robot assistance. 

Re-Identification. Visual re-identification links observations of the same entity across time using image embeddings. Many general-purpose backbones provide strong visual features [21, 22, 23, 24], while Person ReID models such as OSNet are optimized for identity matching [25, 26, 27]. Tracking-by-detection methods link detections across nearby frames using motion, appearance, and confidence cues [28, 29, 30]. Recent work improves robustness under deployment shift, hetero-2Figure 2: Our framework integrates curiosity-driven data collection with persistent spatial memory and ownership-conditioned reasoning. A curiosity-driven agent (top) decides when to stay and ob-serve or move to more informative locations, the memory module (blue) clusters repeated person and object detections and stores human–object interactions, while a user agent (red) retrieves this evidence to infer ownership and execute personalized commands such as Find my bottle .geneous sensors, and multimodal object appearance [31, 32, 33, 34, 35, 36, 37, 38, 39]. COOL differs by using tracking and re-identification as components of long-term robot memory, linking repeated observations of people and object instances to spatial observations and interaction histories for ownership-conditioned navigation. 

Object Ownership. Recent work has studied social relations and personalization cues for robotic assistance. Early systems model owner–object relations with probabilistic inference, visual cues, or demonstrations [8, 9]. Recent personalized search and navigation methods use dialogue, user feed-back, open-vocabulary grounding, or image/language-specified object instances [10, 11, 12, 13]. Other methods localize personal objects from limited examples or on-device visual matching [14, 15]. COOL infers owner–object associations from long-term robot observations and uses them to decide where to search for or navigate to objects associated with a specific person. 

Human–Object Interaction (HOI). HOI recognition identifies how people interact with objects. Recent work extends HOI beyond closed-set triplets toward open-vocabulary and open-world recog-nition with vision-language or multimodal language models [40, 41, 42, 43]. Related embodied work uses interaction reasoning for long-horizon hand-object manipulation from language [44]. In con-trast, COOL stores detected interactions with person, object, place, and time information, and uses these histories as evidence for ownership-conditioned navigation. 

## 3 Method 

The key contribution of COOL is ownership inference: enabling mobile robots to reason about which objects belong to which people from situated, long-term observations (Fig. 2). During operation, the robot grounds visual observations in a metric map and stores them in a spatial memory (Sec. 3.1). The system’s reasoning is driven by two specialized language agents (Fig. 3). First, a user agent 

(Sec. 3.2) queries this memory to resolve entities, infer ownership relations, answer ownership-related questions, and issue navigation commands. Second, a curiosity agent (Sec. 3.3) actively expands and refreshes the memory through curiosity-driven data collection. 

3.1 Persistent Person and Object Memory 

A persistent memory links repeated detections of the same people and object instances over time. This association is necessary because ownership evidence is accumulated across multiple observa-tions. At each observation step, the robot detects visible people and objects in its RGB-D camera stream using YOLO11m-seg [45], selected based on the results of an ablation study reported in App. F.1. We then assign these observations to persistent clusters with a pipeline that consists of three stages: First, the system performs short-term association by preserving identity through BoT-Sort [46] track continuity. If the track ID is lost, a short-term spatial cache reassigns nearby same-3Figure 3: Agent-based reasoning in COOL: we use two language agents to operate on a shared long-term spatial memory. This stage handles frame-to-frame continuity and brief de-tector dropouts. Second, we perform nearest-neighbor retrieval based on embeddings of people and objects. Specifically, we represent people with OSNet ×1.0 body-appearance embeddings and ob-jects with ConvNeXt-Tiny [21] visual embeddings. These feature extractors were selected based on ablation studies comparing several embedding models and input preprocessing variants. For person re-identification, OSNet provided the strongest performance among the off-the-shelf models. We fine-tuned it on our data to further improve its clustering performance. For object re-identification, ConvNeXt-Tiny achieved the highest F1 score among the evaluated feature extractors (App. F.2, App. F.3). Face embeddings provide high-specificity matches, while body embeddings preserve continuity when the face is not captured. 

3.2 Agent-Based Ownership Inference and Navigation 

We formulate ownership as a latent, dynamically inferred relation between a person cluster p and an object-instance cluster o. Unlike explicit labels, this relation is not stored as a fixed database attribute. Instead, COOL infers it at query time from the robot’s accumulated memory of observa-tions and human–object interactions. This design allows ownership estimates to update when new evidence is collected, ambiguous histories become clearer, or ownership changes. 

Ownership Inference. Given a query q, such as Who owns the mug? or Go to Simba’s mug , the system first resolves the referenced entities using structured memory tools (see Appendix B). Let P

denote the set of persistent person clusters and O the set of persistent object-instance clusters. For each candidate person–object pair (p, o ) ∈ P × O , COOL retrieves an ownership evidence set 

Ep,o = {ei = ( pi, o i, a i, ℓ i, t i, c i)}, (2) 4where each event records the involved person and object clusters, the detected interaction type ai,the map location ℓi, timestamp ti, and an optional caption ci. Interactions are inferred from detected person–object bounding-box pairs using a VLM, inspired by recent HOI pipelines [40]. These events capture direct human–object interactions, repeated person and object co-occurrences, and their observed locations. Direct physical interactions, such as drinking, using, or picking up, provide stronger ownership evidence than holding or weak co-presence. A tool-using language agent reasons over the retrieved evidence through a constrained multi-turn retrieval loop. Using structured tool calls, the agent retrieves candidate entities and evidence records and must define the ownership state: owned by person p, shared , or unknown . It is instructed to weigh evidence according to interaction specificity, repetition, recency, and consistency across locations. Repeated direct interactions by the same person increase confidence in ownership, while a single weak interaction or mere spatial co-presence is insufficient. Evidence distributed across people is labeled as shared , while weak or conflicting evidence is labeled as unknown .

Ownership-conditioned Navigation. The inferred relation is used to select an object instance and map it to a reachable navigation goal. Detections are grounded in a pre-recorded metric map using 

slam toolbox [48]. Each detection is assigned a 3-D position by back-projecting the median depth inside the YOLO bounding box. Let wpr (t) and wRr (t) denote the robot position and orientation in the map at time t, and let r pobj (t) denote the object position in the robot frame. The corresponding global object position is wpobj (t) = wpr (t) + wRr (t)r pobj (t). (3) For possessive commands such as Go to Simba’s mug , the agent first infers the relevant owner–object relation, selects the object instance most strongly associated with the named person, and retrieves its most recent reliable map position. For generic commands without an owner reference, such as Go to the blue mug , the agent selects the most recently observed matching instance unless additional disambiguating evidence is available. 

3.3 Curiosity-Driven Data Collection 

Since ownership is inferred from long-term evidence rather than explicit labels, the robot must decide where to spend its sensing time to observe useful events: people interacting with objects, objects appearing in new locations, and previously stored observations becoming stale. We therefore formulate curiosity-driven data collection as an active memory-refresh problem. The robot must balance three competing goals: revisiting locations where ownership evidence is likely to occur, checking locations where new changes are expected, and refreshing under-observed areas. To this end, we use a language-agent-based exploration loop rather than random wandering or a fixed patrol schedule. At defined intervals, the agent observes the current room and determines whether the scene has changed compared to its recent history. Changes include variations in object counts, visible people, object locations, and human–object interactions. If the agent expects near-term ownership-relevant activity, or has recently arrived and needs more observations, it issues a 

stay command. Staying allows the perception pipeline to accumulate repeated detections, improve person and object association, and capture interaction events that may provide ownership evidence. Conversely, if the scene remains static, the agent issues a move command. To select the next room, the agent queries spatial memory with three tools and scores candidate rooms using three signals: 

(1) Historical Hotspots identify rooms with a high empirical rate of scene changes or human–object interactions. They are likely to contain direct ownership evidence. (2) Expected Change returns the time elapsed since the last detected change in each room. Rooms that have not changed recently but historically change often are likely to provide new evidence if revisited. (3) Staleness identifies rooms whose observations are old or sparse. Visiting stale rooms prevents the robot from relying on outdated object locations and helps update ownership-conditioned navigation targets. This makes curiosity explicitly tied to the ownership inference objective: the robot preferentially collects evidence that can strengthen, revise, or disambiguate person–object relations, while also maintaining fresh object-location estimates for navigation. ## 4 Experiments and Results 

We implement the hardware-agnostic framework in ROS 2 and evaluate it on a Boston Dynamics Spot robot [49] equipped with RGB-D perception and LiDAR-based SLAM. Navigation is exe-cuted with Nav2 [50, 51] and uses the SmacPlanner2D global planner [52] over the 2-D occupancy grid. We use Qwen3-VL-4B [53] for both agents as the backbone, which is commonly used in robotics [54, 55, 56, 57]. The model runs on an RTX 4090. For the longest queries (2k input to-kens), we observe an end-to-end latency of ∼2 s. We store embeddings and text rather than raw images, minimizing storage requirements to 11 KB per observation. Since embeddings can enable re-identification, we obtained consent from all subjects. 

4.1 Offline Reasoning Benchmark: Synthetic Dataset Synthetic Dataset. We evaluate the memory-reasoning capabilities of COOL on a synthetic office benchmark to systematically test ownership reasoning components. The benchmark represents one day of robot perception in a shared office (see Appendix C). It contains rooms, people, objects, timestamped observations, and human–object interactions. We generated an initial trace using an LLM and manually reviewed it for plausibility. The log was evaluated by examining the recorded activities and their temporal sequence to determine whether they were consistent with a realistic office workday. Implausible activities, sequences, or transitions were identified and corrected based on human judgment. We use this synthetic dataset because, to our knowledge, no existing dataset combines navigation coordinates with ground-truth ownership data and recurring people and objects [58, 59]. From this state, we derive 79 natural-language questions. These questions probe the system’s ability to reason over time and space, aggregate interaction histories, infer owner–object associations, and resolve navigation targets, helping identify the strengths and failure modes of each subcomponent. All questions were reserved for final evaluation. We compare COOL with four variants. Semantic similarity is used to evaluate the answers. 

(1) Plain LLM receives a flattened database snapshot. (2) Rule-based maps questions to pre-defined SQL queries using keywords and regular expressions. (3) No interaction runs the agent without interaction-related tools. (4) Heuristic uses recency and proximity rules. COOL achieves the highest overall accuracy (Table 1). This shows the benefit of structured tool-based memory access over flattened database prompting. 

Limited ownership reasoning in baselines. Rule-based , Plain LLM , and Heuristic score 0% on ownership, while No Interaction reaches 33% with high variance. COOL achieves 100% in this oracle-memory setting, showing that reliable ownership inference requires structured access to in-teraction and observation histories.

Table 4 shows that COOL achieves the highest F1 score of 85.0% and is the only strategy with both precision and recall above 80%. Sweeping strategies reach high recall but poor precision (90.6%/48.7%), since they visit constantly and most visits have nothing to report, whereas Entropy shows the opposite pattern (93.3%/70.7%). COOL efficiently prioritizes active rooms, requiring only 30 moves compared to 182 for sweeping strategies and 91 for Round-Robin, while observing 2.11 changes per move versus 0.36–0.65 for coverage-driven policies. ## 5 Limitations 

COOL infers person–object ownership relations from observed behavior rather than explicit own-ership labels. This enables autonomous ownership learning, but ownership remains uncertain when evidence is sparse or ambiguous, for example when objects are borrowed, moved, or only briefly handled. In such cases, the system can report ownership as unknown or shared, but additional cues such as clarification questions, visible name labels, or explicit user confirmations may be needed. The system stores long-term observations of people, objects, locations, and interactions, which raises privacy and social acceptability concerns. Deployments in shared spaces should therefore include clear consent procedures, data minimization, access control, and retention policies. Finally, our real-world evaluation is limited to a single office environment with a small number of people, objects, and ownership-conditioned navigation tasks. Broader studies across more environments, longer de-ployments, and more diverse shared-object scenarios are needed to assess generalization. 

## 6 Conclusion 

We presented COOL, a robotic framework for learning object ownership in shared human envi-ronments from long-term observations. Rather than relying on explicit labels, demonstrations, or dialogue, COOL infers ownership from accumulated evidence about people, object instances, and human–object interactions. This allows the system to adapt to ownership changes and incorporate new evidence. It combines persistent spatial memory with two agents for data collection and task execution. The curiosity-driven agent autonomously explores the environment to refresh stale or incomplete memory and gather ownership-relevant evidence. The user agent interprets ownership-conditioned requests by grounding them in spatial memory, inferring the relevant owner–object re-lation, and directing the robot toward the inferred target location. Our evaluations show that in-teraction memory, ownership-based navigation, and active observation jointly support ownership-aware assistance. On a physical robot, COOL improved ownership reasoning, resolved personalized search requests, collected relevant evidence more efficiently, and handled visually similar objects and changing object locations in an office environment. This suggests that persistent, interaction-aware memory and active observation can support personalized robotic assistance. Future work will explore interactive clarification, broader multi-user deployments, and mobile manipulation, extend-ing the system beyond object localization toward retrieval and handover. 9Acknowledgement

## B Structured Database Tools 

The agents interact with the memory system through a fixed set of structured tools. Each tool defines typed inputs and outputs, allowing the agent to search tracked entities, inspect observations, query interaction histories, and resolve navigation targets. These tools also provide access to the robot’s current pose, enabling decisions to be grounded in the robot’s spatial context. Navigation is executed only after a target has been resolved to a reachable position on the map.

## C Offline Reasoning Benchmark 

The synthetic office benchmark is used to evaluate reasoning abilities over structured robot memory. It consists of a memory trace for one simulated workday. The trace contains rooms, people, objects, timestamped observations, and human–object interaction events. Each object and person has a stable identity. Each observation is associated with a time and a metric position in the map. The question set is derived from this trace and is used only for final evaluation. How it is used. The benchmark is used to evaluate the user agent. For each question, the agent can call structured tools to access memory. The tools expose observations, interactions, entities, rooms, 17 and navigation targets. The agent then returns a natural-language answer. Answers are scored with semantic similarity against manually specified reference answers. All questions are held out until final evaluation. 

Question categories. Interaction questions ask about human–object interaction events. Location questions ask where people or objects were observed. Navigation questions require resolving a room, person, or object to a reachable goal. Lookup questions require retrieving an entity by name or identifier. Ownership questions require inferring likely ownership from interaction and observation histories. 

Example questions. Examples include: • Where was notebook 002 at 16:20 on 2026-04-27? • Who picked up headphones 001 ?• What interaction happened with whiteboard 001 at 09:58? • Who used notebook 001 , and how many times? • Navigate to the person who used the coffee machine most frequently. • Navigate to Simba’s bottle. 

C.1 Robustness Evaluation Details 

To evaluate robustness to perception errors, we perturb the results returned by the memory database at query time while leaving the underlying database unchanged. This isolates the effect of perception errors from errors introduced during data collection or database construction. Unless otherwise specified, perturbations are applied independently for each evaluation seed. Table 9 summarizes the simulated failure modes. Detection dropout randomly removes a fraction of observation rows, simulating missed detections. False-positive injection adds observations with incorrect identities, simulating spurious detections or identity hallucinations. Embedding noise adds Gaussian noise to stored feature vectors, reducing the reliability of similarity retrieval. Track frag-mentation splits observations associated with an identity into synthetic track identifiers and removes the associated identity names, simulating loss of temporal identity consistency. Face occlusion removes the available face image information from selected observations. Temporal jitter randomly perturbs timestamps within the specified range, simulating synchronization errors. Action noise replaces interaction/action labels with incorrect labels, while class confusion swaps object categories between visually similar classes and removes the associated captions. Finally, sys-tematic identity swapping applies a consistent bijection between identities throughout the evaluation, simulating a persistent identity-assignment error. 18 Table 9: Perturbations used in the robustness evaluation.

## D Real-World Tasks 

The real-world experiments consist of five task setups. Each setup targets a specific capability of the robot memory system and the tool-using agent. 

D.1 Detailed Tasks Task 1: Room Navigation. The robot receives a target room name. The target room is selected from four different rooms. The robot starts from multiple positions across the environment. The agent must ground the room name to a spatial region on the map. It must then resolve a reachable navigation goal inside the room. The robot must navigate at least 1 m into the target room. 

Task 2: Object Relocation. The robot observes a ball at five different positions. A person is observed with the ball at two different locations. The agent must re-identify both the ball and the person across observations. It must infer the correct owner–object association. It must then query the latest known position of the ball and navigate to it. 

Task 3: Owner-based Distinction. The robot observes two bottles in different locations. One person interacts with one bottle in the kitchen, another person interacts with the other bottle at his workplace. The agent must distinguish between the two bottles and the two people. It must infer the correct owner–object association. It must then query the latest known position of the target bottle and navigate to it. 

Task 4: Visual Ambiguity. The robot observes two visually similar backpacks in different locations. Each backpack is associated with a different person through prior interaction evidence. The agent must distinguish between the two backpacks and the two people. It must infer the correct owner– object association. It must then query the latest known position of the target backpack and navigate to it. 

Task 5: Ownership-Preserving Update. The robot observes two visually similar backpacks in different locations. Each backpack is associated with a different person through prior interaction evidence. One backpack is later moved to a new location. The agent must re-identify the moved backpack without changing its ownership association. It must distinguish between the two back-packs and the two people. It must infer the correct owner-object association. It must then query the latest known position of the target backpack and navigate to it. 

D.2 Success criterion 

A run is counted as successful if the agent selects the correct target entity or room, and the robot reaches and stops at the corresponding navigation goal. For room navigation, the robot must stop at least 1 m inside the target room. For object-based tasks, the robot must navigate to the latest known position of the correct target object. A run is counted as failed if the agent selects the wrong entity, queries an outdated location, or navigates to the wrong goal. 19 D.3 Execution protocol 

The task was conducted over 10 hours of naturalistic office activity, involving 10 people and 20 objects across four rooms. Each task is evaluated over 10 runs. Runs differ in the robot’s starting pose and, where applicable, the target instance. The memory state is initialized with the observations and interactions required by the task. The agent receives only the task instruction. It must use the structured tools to query memory and resolve the navigation target.

E.1 Change Definition 

Ground truth is computed per room by comparing consecutive observations of that room, indepen-dently of where the robot actually is. 

Entity-level changes. For each room we compare the set of people and the set of objects present at timestep t with those at t + 1 . Any addition or removal is a change. Its severity is classified as 

major if a person entered or left, a fixture changed, or at least two objects changed; minor if exactly one object changed or only the activities changed. Major changes are the ownership-relevant ones. 

Activity-level changes. Activity-level changes are detected by comparing the interactions between consecutive observations, i.e. the set of subject:action:target tuples observed in a room. A room is labelled as changed at the activity level if this set differs between t and t + 1 . The severity of an activity-only change is minor .21 E.2 The 15 Evaluation Worlds

E.4 Metrics 

Three of the four reported quantities are conditional on presence , which we state explicitly because it determines how the numbers must be read. • Recall — major-change recall given presence : TP major /(TP major +FN major ) over the major changes the robot was present for. It answers “when the robot was there, did it notice?”, not “how many changes did it see?”. • F1 — change-detection F1 over the steps the robot actually observed, i.e. of the per-decision judgement “has this room changed since I last saw it?”. Also conditional on presence, and therefore maximised by camping : a policy that never leaves the busiest room scores very well on it. Every table below therefore prints a move budget and an uncondi-tional column next to it. • Det. — agent-relative detection rate: the fraction of cases in which the room differed from the agent’s own last observation of it and the detector said so. • Yield — change events observed per room move. • Moves — room moves per 3-day run (of at most 182 ). • Cov. (unconditional) — fraction of the reachable change events the strategy witnessed, taking the number of steps at which any room changes as 100% .• Missed (unconditional) — change events never observed: the room was not visited after the change, or was visited without a detection.

E.7 Isolating the destination choice 

In Table 4 each baseline uses its own detector prompt and its own rule for when to move, so the comparison is between complete exploration systems. To isolate the destination choice we re-ran every baseline with COOL’s detector and COOL’s stay-or-move decision, varying only the rule that selects the next room. Granting this decision improves every baseline, by 0.120 F1 on average (range 0.056–0.162). The effect is not simply ”move less”: it releases Entropy from its statistical camp (13 → 45 moves) while restraining the sweeping policies (182 → 74 moves) and the hazard policy (112 → 8). Under this condition COOL’s destination rule is no longer the strongest on F1 (Table X): a hazard-greedy destination reaches 90.7% F1 at 8 moves, and four rules clear 80% on both precision and recall. Those gains come either from camping — the hazard-greedy variant leaves 715 changes unobserved, and Entropy 668 — or from moving two to four times more. COOL leaves the fewest changes unobserved among strategies with a comparable movement budget (389 at 28 moves). We therefore attribute most of the benefit to the detector’s stay-or-move decision, which is transferable, and the remainder to the navigator’s additional restraint on movement: argmax retains the same stay decision yet still makes 102 moves against COOL’s 28, because it always relocates once the detector releases the robot, whereas the navigator frequently elects to remain. 28 Destination rule Recall Prec. 31 G Fine-Tuning 

We fine-tune OSNet from an MSMT17-pretrained [71] checkpoint using manually labeled person detections collected from the Spot robot’s front fisheye camera. The training dataset contains 808 la-beled detections from 19 identities. We split the dataset into 605 training samples and 203 validation samples. Training uses identity-balanced batches, AdamW [72], a cosine learning-rate schedule, and a combined cross-entropy and triplet loss. We select the best checkpoint at epoch 24 using validation pairwise F1, with validation loss as a tie-breaker.
