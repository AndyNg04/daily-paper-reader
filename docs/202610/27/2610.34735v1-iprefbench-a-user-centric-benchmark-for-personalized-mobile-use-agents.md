## 摘要
能够真正了解用户并代表用户采取行动的智能体，长期以来一直是人工智能助手的发展愿景。计算机使用智能体能够在不同应用中熟练执行指令明确的任务，使这一愿景逐渐成为现实。然而，现实中的用户请求往往信息不充分。为了针对特定用户正确行动，智能体必须从用户的活动历史中推断缺失信息，并向用户询问其他只有用户才能提供的信息，同时避免作出缺乏依据的假设或提出不必要的问题，从而增加用户负担。我们提出 iPrefBench，这是一个用于评估个性化移动端使用智能体“推断”和“询问”能力的基准测试。该基准在可执行的 iOS 环境中运行，并配有可交互的模拟用户。iPrefBench 以包含 3,051 条过往活动事件的连贯用户画像为基础，涵盖 26 款应用中的 130 项信息不充分的用户任务。根据构建方式，每项被省略的、依赖用户信息的要求，要么能够从历史记录中推断得出，要么只能通过询问用户获取。iPrefBench 从两个方面评估个性化移动端智能体：智能体能否针对用户正确完成任务（即个性化任务完成），以及是否会在必要时征求用户意见（即用户与智能体的交互）。对 7 个前沿智能体的评估揭示了任务执行能力与个性化能力之间存在显著差距。智能体的操作完成得分较高（最高达 91.6%），但完整任务成功率较低（最高为 47.7%），原因在于个性化能力不足。尤其是对于只能通过询问获取的信息，智能体表现欠佳，未能询问足够多的必要信息。我们的研究结果凸显了个性化智能体面临的一项挑战：判断哪些信息应当推断，以及何时应当询问。我们希望 iPrefBench 能成为一项有价值的测试平台，助力开发出了解用户并与用户协作的智能体。

## Abstract
An agent that truly knows and acts on behalf of its user has been a long-standing promise of AI assistants. Computer-use agents bring this promise within reach by capably executing fully specified tasks across apps. However, real-world user requests are often underspecified. To act correctly for the particular user, an agent must infer some missing information from the user's activity history and ask for other information that only the user can provide, without making unsupported assumptions or burdening the user with unnecessary questions. We present iPrefBench, a benchmark for evaluating the infer and ask capabilities of personal mobile-use agents in an executable iOS environment with an interactive simulated user. Grounded in a coherent persona with 3,051 past activity events, iPrefBench comprises 130 underspecified user tasks across 26 apps. Each omitted user-dependent requirement is, by construction, either history-inferable or ask-only. iPrefBench evaluates personalized mobile agents on both whether agents complete tasks correctly for the user (i.e., personalized task completion) and whether they seek user input when necessary (i.e., user-agent interaction). Evaluation of 7 frontier agents reveals a substantial gap between execution and personalization. Agents achieve high action completion scores (up to 91.6%) but low full task success (up to 47.7%) because personalization lags behind. They especially struggle with ask-only information, failing to request enough necessary information. Our findings highlight a challenge for personalized agents in knowing what to infer and when to ask. We hope that iPrefBench can serve as a valuable testbed for building agents that know their user and work with them.

## 1. 核心问题与整体含义

### 1.1 研究背景与动机
- 现有计算机使用智能体通常在**指令完整、目标明确**的任务上接受评测，例如用户直接提供餐厅、时间和人数。
- 现实请求往往不完整，例如“帮我订明天常去的餐厅”。智能体需要区分：
  - **可以从历史推断的信息**：常去哪家餐厅、惯用支付方式等。
  - **只能向用户询问的信息**：本次用餐时间、人数、临时出行日期等。
- 两种极端行为都不理想：
  - **不问就猜**：操作成功，但偏离用户真实意图。
  - **凡事都问**：增加用户负担，削弱个人助手的自主性。

### 1.2 论文的研究定位
- 提出 **iPrefBench**，在可执行的 iOS 环境中，联合评估个性化智能体的**历史推断能力与必要澄清能力**。
- 关键问题不是单纯“能否找到缺失信息”，而是：
  1. 是否识别到某个用户相关决策尚未确定；
  2. 是否知道应该依据历史推断，还是询问用户；
  3. 是否最终按照用户意图完成任务。
- **这是一篇基准与评测研究，而非提出新模型或训练算法的论文。**

## 2. 方法论：核心思想、技术细节与评估流程

### 2.1 对缺失信息明确标注来源
对于每项任务，作者将指令未说明的用户相关要求划分为两类，每项要求都有预设正确值及唯一的解决来源：

- **历史可推断信息（Inferable）**
  - 正确值可以从用户活动历史中的稳定事实、主导行为模式或近期趋势恢复。
- **只能询问信息（Ask-only）**
  - 历史无法支持，必须通过用户交互获得。

例如“订明天常去的餐厅”：
- 餐厅名称由历史推断；
- 本次时间与人数向用户询问。

这一划分使基准不仅能判断答案是否正确，还能判断**提问是否必要**。

### 2.2 可执行环境与用户模拟
- 基于 iOSWorld，使用包含 **26 款模拟应用**的 iOS 模拟器，覆盖餐饮、购物、支付、旅行、办公、消息和健康等场景。
- 智能体以**纯视觉方式**观察截图，通过点击、输入、滑动、返回主屏幕、等待等动作操作；不能读取无障碍标识、界面元数据或隐藏状态。
- 新增 `ask_user` 动作，让智能体向模拟用户发送自然语言问题。
- 智能体默认获得完整活动历史，但不能直接读取结构化用户画像。
- 隐藏画像包含 **13 个维度、92 个条目**，用于支撑用户模拟和结果评判。
- 模拟用户还持有任务专属隐藏上下文，并被要求**只回答被问到的信息，不主动补充其他缺失条件**，避免替智能体完成歧义识别。

### 2.3 三类扰动任务
为避免把历史偏好当成永远有效的规则，基准加入：

| 扰动类型 | 场景 | 考察能力 |
|---|---|---|
| 指令扰动 | 用户这次明确要求与历史习惯不同 | 当前指令优先于历史 |
| 偏好扰动 | 近期行为已偏离长期习惯 | 识别偏好随时间变化 |
| 环境扰动 | 偏好商品缺货、餐厅不可订等 | 说明障碍，并询问替代方案或停止 |

### 2.4 任务构建流程
1. **自动生成候选任务**：编码智能体参考应用源码、用户历史、画像和已有完整指令任务，生成 188 项候选。
2. **人工细化**：8 名审阅者检查任务自然性、缺失信息来源、历史证据和评分标准，去重并增加覆盖。
3. **执行验证**：2 名验证者实际操作模拟器，检查可完成性与评分标准，最终保留 130 项任务。

对于历史证据较弱的偏好，作者会调整种子数据以形成清晰依据；对于必须询问的值，则尽可能使其不同于应用默认值，降低“碰巧猜对”的概率。

### 2.5 评估指标与公式含义
**任务完成方面：**
- **动作完成得分**：成功执行的操作标准占比，不要求用户相关参数正确。
- **个性化得分**：用户相关决策正确的比例，另分为可推断与只能询问两类。
- **完整任务成功率（SR）**：只有全部操作及个性化标准都通过，任务才算成功。
- 得分按任务宏平均，由 LLM 根据截图、动作轨迹、最终回答和隐藏真值逐项判断。

**用户交互方面：**
- 将每条提问拆成独立信息请求；一句话问两个参数算两个请求，重复询问重复计数。
- **Recall = 已询问覆盖的不同 Ask-only 要求数 ÷ 全部 Ask-only 要求数。**
- **Precision = 已询问覆盖的不同 Ask-only 要求数 ÷ 全部信息请求次数。**

因此，漏问降低召回率；询问历史已有答案、无关信息或重复提问降低精确率。两项指标在整个基准上进行微平均。

## 6. 主要结论与发现

### 6.1 执行能力明显强于个性化能力
- 动作完成得分达到 **77.5%—91.6%**，完整成功率却只有 **26.2%—47.7%**。
- 最佳模型仍未成功完成一半任务，说明“操作正确”不能替代“符合用户意图”。

### 6.2 最大瓶颈是识别“必须询问”
- 所有模型在 Ask-only 信息上的表现均低于历史可推断信息。
- 默认每任务仅调用 `ask_user` 约 **0.08—0.35 次**，交互召回率最高仅约 44%。
- 同时精确率只有约 60%—77%，说明智能体既漏问，也存在不必要提问。
- 补充实验中问题表述质量接近满分，瓶颈主要是**决定何时问，而非如何组织问题**。

### 6.3 强制澄清有效，但带来过度询问
加入执行前澄清阶段后：

| 模型 | 完整成功率 | 交互召回率 | 交互精确率 |
|---|---|---|---|
| Sonnet 5 | 39.2 → 53.8 | 25.7 → 85.0 | 60.4 → 42.5 |
| Qwen3.8-27B | 26.2 → 35.4 | 21.2 → 69.0 | 70.6 → 60.9 |

说明“鼓励多问”可以缓解漏问，却不能自动学会判断提问必要性。

### 6.4 更多历史不等于更好的不确定性判断
- 少量相关历史即可显著提升推断表现，之后收益趋于平缓。
- 例如 Qwen3.8-27B 的可推断个性化得分，从无历史时约 35% 提升至前 50 条相关事件时约 63%。
- 但 Ask-only 表现几乎不改善；更多历史甚至可能让模型减少必要询问。

### 6.5 四类主要失败
- **静默接受默认值**：未意识到日期等参数尚未确定。
- **遗漏推断**：没有注意到任务涉及某项历史偏好。
- **静默猜测**：意识到缺失信息，仍自行假定。
- **错误推断**：使用了历史，但忽略近期偏好变化等因素。

环境障碍则更容易触发询问：偏好选项不可用时，提问次数约为整体平均的 **2.3 倍**。

## 7. 优点与亮点

- **研究问题清晰且实用**：直接针对真实个人助手中“该推断还是该询问”的矛盾。
- **信息来源标注具有诊断价值**：不仅判断结果对错，还能分析错误发生在需求识别、推断还是澄清阶段。
- **结果与交互分开评估**：避免“猜对答案”或“把所有问题都交给用户”被视作理想行为。
- **采用可执行 GUI 环境**：比纯文本或静态问答更接近实际手机操作。
- **覆盖动态偏好与不可用情形**：强调历史是证据，而不是不可违背的指令。
- **质量控制较完整**：两轮人工审查、实际执行验证、人工裁判对照及跨模型裁判验证。
- **评测可信度有量化支持**：
  - 模拟用户问答有效率为 96.6%；
  - 裁判与人工在评分标准、任务成功标签上的一致率分别为 95.7%、97.0%。

## 8. 不足与局限

### 8.1 单一用户与模拟环境限制外部有效性
- 所有任务围绕一个虚构用户展开，无法证明对不同文化、生活方式、表达习惯及复杂偏好同样有效。
- 模拟应用不包含真实服务中的全部复杂性，如身份验证、支付风控、网络异常和权限问题。
- 每项任务重新初始化，未评测长期交互中的持续记忆、偏好学习和错误修正。

### 8.2 信息来源划分比现实更确定
- 每项缺失要求被指定唯一来源，且历史证据经过人工强化，便于测量，但减少了现实中的模糊性。
- 真实情况下，即使历史支持某项偏好，高风险操作也可能仍需确认。
- 按当前指标，询问可推断信息会被视为多余，**未充分区分冗余提问与合理的安全确认**。

### 8.3 模拟用户与自动裁判仍可能引入偏差
- 模拟用户严格不主动补充信息，有利于隔离能力，但不同于可能主动纠正或补充意图的真实用户。
- 同一模型同时承担模拟用户和主要裁判，存在相关偏差风险；人工及替代裁判验证只能缓解，不能完全消除。
- 人工验证的 100 条轨迹分给两名标注者独立处理，未报告同一批轨迹上的人际一致性。

### 8.4 指标未覆盖全部用户体验
- 精确率将不同请求次数等同计数，没有区分回答难度、打断成本和风险程度。
- 多个问题合并一次问，与多次打断用户，在信息请求指标上未必有差异。
- 评分主要基于截图和轨迹，而非完全依赖程序化状态检查。
- 完整成功率采用“全部通过”标准，适合严格衡量完成，但对任务评分项数量和粒度敏感。

### 8.5 比较范围与复现信息仍有限
- 没有系统比较专门优化澄清决策、显式不确定性建模或长期记忆管理的方法。
- 完整历史作为默认输入，有利于控制检索因素，但不直接反映隐私受限、按需检索的真实部署方式。
- 缺少重复实验、成本与延迟信息，难以判断性能差异的稳定性和实际部署代价。

**总体评价：**iPrefBench 的主要价值在于建立了一个可诊断的评测框架，揭示个人智能体在“识别未决事项—判断信息来源—正确执行”链条上的系统性不足。它为个性化交互提供了有用测试平台，但尚不能替代多用户、真实应用和风险敏感条件下的验证。
