## 摘要
纵观计算技术发展的多个浪潮，公众对新技术的信任，往往伴随着治理机制的出现而建立；这些机制使主要风险变得清晰可辨且可控。生成式人工智能改变了这一模式：这类系统能够综合异质来源的信息，用户也越来越将其视为具有推理能力的系统。因此，核心问题从“系统是否正确执行？”转变为“我们能否信任它得出结论的过程？”本文提出一种面向用户的透明度机制——过滤式决策日志（Filtered Decision Logs，FDLs），使决策形成过程清晰可见，同时避免暴露原始思维链。FDL 为每条响应配套提供：（i）简明的决策理由；（ii）按影响力排序、源自工具输出的支持性数据点；以及（iii）相关性指标，表明哪些来源对结论影响最大。为将证据筛选落到实处，我们提出一种基于轨迹的方法，将可观测性遥测数据重建为溯源树，并利用四项确定性的语义与结构信号对证据进行排序——最终答案相似度、平均相关性、持续性和结构邻近度——再通过自适应加权评分将这些信号结合起来。我们在三个领域展示了 FDL：职业咨询（5 个工具）、投资分析（4 个工具）和旅行规划（4 个工具）。在一项包含 50 名参与者（25 名学生、25 名从事人工智能开发的职场人士）的形成性评估中，92% 的参与者认为，按影响力排序的证据有助于理解系统的建议并建立对系统的信任。反事实工具移除实验表明，移除排名最高的来源比移除排名较低的来源更能改变答案，从而验证该排序能够反映决策对来源的依赖程度。我们总结认为，按证据排序的透明度有助于用户识别误导性信号和缺失背景信息，使其能够更有把握地接受、纠正或重新运行系统决策。

## Abstract
Across multiple waves of computing, public trust in new technology has followed the emergence of governance mechanisms that made dominant risks legible and manageable. Generative AI shifts this pattern: these systems synthesize across heterogeneous sources, and users increasingly experience them as reasoning systems. The central question changes from "did it perform correctly?" to "can we trust how it arrived at its conclusion?"   This paper introduces Filtered Decision Logs (FDLs), a user-facing transparency mechanism that makes decision formation visible without exposing raw chain-of-thought. FDLs pair each response with (i) a concise decision rationale, (ii) influence-ordered supporting data points derived from tool outputs, and (iii) relevance indicators showing which sources most shaped the conclusion. To operationalize evidence selection, we propose a trace-based method that reconstructs observability telemetry into a provenance tree and ranks evidence using four deterministic semantic and structural signals - Final Answer Similarity, Average Relevancy, Persistence, and Structural Proximity - combined via adaptive weighted scoring. We demonstrate FDLs across three domains: career advising (5 tools), investment analysis (4 tools), and travel planning (4 tools). In a formative evaluation with 50 participants (25 students, 25 working professionals in AI development), 92% rated the influence-ranked evidence as helpful for understanding and trusting the system's recommendation. Counterfactual tool-removal experiments confirm that removing the top-ranked source changes the answer more than removing a low-ranked source, validating that the ranking tracks decision dependence. We conclude that evidence-ranked transparency helps users identify misleading signals and missing context, enabling more confident acceptance, correction, or re-run of system decisions.

## 2. 方法论：Filtered Decision Logs（FDLs）

### 2.1 核心思想与展示内容

论文提出**过滤式决策日志（FDL）**，与模型答案同时展示，包含：

1. **简洁决策理由**：基于证据说明建议依据，而不展示原始思维链。
2. **排序后的支持性数据点**：将工具返回的 JSON、文档或数据库结果整理为可读证据。
3. **相关性指标**：
   - 高：分数 ≥ 0.70；
   - 中：0.40 ≤ 分数 < 0.70；
   - 低：分数 < 0.40。

用户可以展开评分细节，或排除某个来源后重新提问，比较推荐如何变化。

### 2.2 双流水线架构

系统将回答生成与证据评分分开：

- **智能体流水线**：采用 Amazon Bedrock 上的 Claude 3 Sonnet，按照 ReAct 模式调用工具并生成答案，同时记录执行轨迹。
- **FDL 流水线**：事后读取轨迹，使用嵌入模型和确定性计算对证据排序，不让生成模型自行报告“哪些证据最重要”。

这种分离减少了对模型自述的依赖，但**计算过程独立并不自动保证评分准确或解释忠实**。

### 2.3 七阶段算法流程

1. **提取工具数据节点**：遍历执行轨迹，识别工具返回结果。
2. **建立父节点映射**：恢复节点间的层级关系。
3. **提取推理祖先链**：收集每条证据对应的、具有文本输出的 LLM 祖先阶段。
4. **计算文本嵌入**：使用 Amazon Titan Embed Text v2，并缓存结果。
5. **计算综合分数**：组合四项语义和结构信号。
6. **排序与筛选**：按分数降序排列，选择前 K 项并分配等级。
7. **格式化展示**：输出证据卡片、理由和信号分解。

若轨迹树未能完整记录工具调用，则从全局对话消息中补提取工具结果。不过，论文没有充分说明这一回退方式如何完整恢复复杂的依赖关系。

### 2.4 四项评分信号

| 信号 | 计算方式 | 设计意图 |
|---|---|---|
| 最终答案相似度 FA | 工具输出与最终答案嵌入的余弦相似度 | 衡量证据内容是否在答案中有所体现 |
| 平均相关性 AVG | 工具输出与各 LLM 祖先文本相似度的平均值 | 衡量证据与多个推理阶段的整体关联 |
| 持续性 PERSIST | 相似度超过阈值 0.30 的祖先阶段占比 | 衡量相关信息在多个阶段的持续程度 |
| 结构邻近性 DEPTH | `1 /（1 + LLM 祖先数量）` | 对结构上更直接的证据赋予较高分 |

综合分数为：

**S = 0.40 × FA + 0.30 × AVG + 0.20 × PERSIST + 0.10 × DEPTH。**

这些权重是作者设置的经验先验，并非通过训练或系统优化得到。

### 2.5 自适应权重与分数解释

- 如果某证据没有 LLM 推理祖先，AVG 与 PERSIST 无法计算，系统将其权重按比例重新分配：
  - FA 权重变为 **0.80**；
  - DEPTH 权重变为 **0.20**。
- 每个证据独立评分，**所有分数不要求相加为 1**。
- 分数 0.70 不意味着“贡献了答案的 70%”，也不意味着“来源有 70% 的概率正确”。

此外，论文对**决策理由及可读证据描述如何生成、如何验证其忠实性**的说明，相比评分部分不够充分。

## 6. 主要结论与发现

- **证据排序具有初步可用性**：用户通常先检查最高排名来源，有助于快速定位需要审查的信息。
- **排除并重跑具有直观价值**：职业咨询中，移除社交媒体后，建议由“政策分析师”转为“数据科学家”，让用户观察到来源变化与建议变化的关系。
- **排序获得有限的行为验证**：三个场景中，移除最高排名来源均比移除最低排名来源造成更大的答案变化。
- **用户主观反馈积极**：92% 的参与者认可其帮助，但这不等于理解准确率提升 92%，也不证明用户形成了更合理的信任。
- **论文最有价值的贡献是交互模式**：把透明度从静态解释转为可检查、可质疑、可重新运行的证据工作流。

## 7. 优点与亮点

- **聚焦实际问题**：关注当前工具调用中的运行时证据，而不是与单次建议较远的训练数据归因。
- **工具级解释容易理解**：用户更容易判断“财经新闻是否可靠”，而非理解 Token 级贡献。
- **减少模型自述依赖**：评分管线与答案生成分离，计算规则明确，便于检查和复现。
- **交互具有可操作性**：不仅显示解释，还允许用户通过排除来源验证不同条件下的建议。
- **考虑轨迹拓扑差异**：通过自适应权重处理缺少推理祖先的情况。
- **工程实现较完整**：包含轨迹提取、评分、界面、重跑和软件测试。
- **明确承认部分边界**：指出分数不具有可加性，不是因果归因，也不保证答案正确。

## 8. 不足与局限

### 8.1 指标有效性有限

- **语义相似不等于实际使用**：某条来源可能与答案主题一致，但答案实际上来自其他来源或模型已有知识。
- **相关不等于支持**：余弦相似度可能无法区分支持、反驳与否定关系。
- **四项信号未必独立**：FA、AVG 和 PERSIST 都依赖语义相似度，论文没有证明其互补性。
- **权重和等级阈值缺少校准**：没有说明为什么 0.70 应被视为“高影响”，或这一阈值能否跨领域通用。
- **分数范围存在说明缺口**：余弦相似度理论上可能为负，文中未明确说明是否做了裁剪或归一化；因此其“0—1 分数”和“充分利用整个区间”的表述需要更严格说明。

### 8.2 轨迹结构未必等于信息依赖

- 执行轨迹中的父子关系通常反映调用或编排结构，不一定代表证据实际流向。
- 工具结果在推理阶段之后产生时，调用它的祖先文本未必已经包含该结果；因此 AVG 和 PERSIST 的依赖解释需要更严格的时间与数据流定义。
- 复杂多智能体、共享上下文和并行调用更适合用依赖图表示，单一树结构可能遗漏交叉引用。

### 8.3 工具移除验证仍较弱

- 仅移除最高和最低来源，不能验证完整排序是否正确。
- 缺少相同配置重复运行的对照，无法排除生成随机性。
- 用答案嵌入变化评价基于嵌入构建的排序，验证维度较单一，仍需任务结果、人工判断等独立指标。
- 删除证据会改变上下文及工具调用路径，答案变化不能简单解释为被删除来源的纯粹因果贡献。

### 8.4 用户研究存在偏差风险

- 样本集中于 AI 从业者和计算机相关学生，难以代表普通用户。
- 没有客观理解测试、任务成功率或过度信任指标。
- 精确数字、进度条与颜色可能制造“量化即可靠”的印象。
- 四名学生认为 AVG、PERSIST 难以理解，说明技术分解仍存在认知门槛。

### 8.5 真实应用与安全边界

- 使用模拟数据，未验证真实 API 的噪声、缺失、冲突、过期数据与长文档处理能力。
- 仅测试一个回答模型和一个嵌入模型，泛化性未知。
- 暴露工具证据可能泄露个人信息、商业数据或越权内容，需要访问控制与脱敏。
- 用户可能通过排除不喜欢的来源强化确认偏差；系统应区分“来源不可靠”与“来源结论不合偏好”。
- 文中将 FDL 描述为较高治理能力、可独立信任的机制，论断强于现有实验支持：**可重复计算不等于归因正确，来源可检查也不等于来源真实。**

**总体评价**：这是一项有实用潜力的透明度界面原型研究。其“证据排序＋来源排除＋重新运行”的设计值得借鉴，但目前应将评分视为辅助审查的启发式信号，而非经过充分验证的因果解释或可靠性保证。
