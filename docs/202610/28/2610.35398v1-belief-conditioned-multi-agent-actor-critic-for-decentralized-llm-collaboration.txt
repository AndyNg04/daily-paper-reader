## Abstract 

Recent work has explored optimizing LLM collaboration through Multi-Agent Reinforcement Learning (MARL), but many approaches still rely on predefined workflows, limiting efficiency and scalability. Decentralized LLM collaboration is challenging because agents execute independently with limited communication, share a joint objective, and must infer useful information from communication traces. In this paper, we propose BCMAAC , a Belief-Conditioned Multi-Agent 

Actor-Critic method that maintains beliefs over contextual information and uses them to facilitate training. Experiments on Minecraft game-playing, web searching and tool-using tasks show that BCMAAC improves task performance and collab-orative behavior compared to naive actor-critic baselines. The improvements are particularly pronounced in multi-turn tasks with richer contextual information, where belief modeling provides a clear advantage. 

## 1 Introduction 

Recent advances in LLMs have motivated researchers to use them as intelligent agents and interact with environment in multiple turns Yao et al. [2022]. Many works use reinforcement learning with verifiable rewards (RLVR), where rewards are derived from verifiable signals such as rules and unit tests [Lambert et al., 2024, Guo et al., 2025, Kimi Team et al., 2025, Liu et al., 2025, Guo et al., 2025]. Compare with reinforcement learning from human feedback (RLHF) that trains a reward model using human preference data, RLVR typically has lower cost, greater scalability, and more objective feedback in scenarios where task success can be automatically verified [Lambert et al., 2024, Guo et al., 2025]. Existing works have employed multi-LLM collaboration to improve performance. Prompt-based approaches for multi-agent systems have demonstrated improved problem-solving through role assignment and agent-to-agent communications [Du et al., 2024, Qian et al., 2024, Wu et al., 2023]. However, they often follow a manually designed interaction protocols. Recent work has combined reinforcement learning approaches with LLM collaboration. For instance, CoLLM-CC [Liu et al., 2026] is a multi-agent actor-critic (MAAC) methods that utilize centralized value estimation while keeping decentralized execution. Despite the advantages of MAAC in LLM collaboration, it faces many challenges. Given the partial observability of the task, the policy is a pre-trained LLM, and actions are generated as sequences of natural language tokens. Action selection relies not only on task reasoning but also on inferences about the environment and the other agents’ internal states, thereby increasing the difficulty of decision-making and optimization. Furthermore, the problem of long-horizon sparse rewards is another challenge, making it difficult to capture effective learning signals in a timely manner. This manifests as rewards that are typically delayed, sparse, and concentrated in the terminal state,

making it hard for the model to determine which intermediate communications, inferences, or the environmental interactions indeed contributed to the final success. We study decentralized LLM collaboration optimized with RLVR, focusing on environmental state estimation and the other agents’ intention inference. We propose BCMAAC, a belief-conditioned multi-agent actor-critic method. BCMAAC uses a recurrent belief encoder to maintain latent belief context from structured side information and conditions this context onto each LLM actor; during the training phase, a centralized critic aggregates the multi-agent belief context to estimate the value, while the execution phase remains decentralized, with each agent relying solely on its own history and local belief context for decision-making. Our contributions can be summarized as follows. (i) We propose BCMAAC. BCMAAC learns execution-time belief context from structured side information and uses it for both actor conditioning and centralized value estimation. (ii) We show that explicit belief context is particularly useful for long-horizon, partially observable collaboration, where useful actions depend on persistent hidden state, the specific information of other agents, and delayed or sparse feedback. This gives agents an intermediate representation for deciding what to do and communicate across turns. (iii) Experiments on collaboration tasks show that BCMAAC outperforms MAAC. And the ablation show that both task-belief and partner-action auxiliary signals help improve performance. 

## 2 Related Works 

LLM-based multi-agent collaboration. Recent work uses multiple LLM agents to solve tasks that are difficult for a single model. Multi-agent debate improves the answer by independent reasoning and iterative refinement [Du et al., 2024]. ChatDev organizes role-specialized agents along a structured software-development pipeline [Qian et al., 2024]. AutoGen provides a general framework in which conversable agents cooperate with tools and optional human input [Wu et al., 2023]. CAMEL relies on role-playing between agents, which cooperate through prompting [Li et al., 2023]. These systems demonstrate the benefits of communication and task decomposition. However, their collaboration strategies are largely specified by prompts, leaving the collaboration pattern fixed and unable to improve with task experience. 

RL for LLM collaboration. Besides prompt engineering, recent studies also train multi-LLM systems. MAGRPO jointly trains cooperating LLM agents on joint rewards without a critic [Liu et al., 2025]. Dr. MAS investigates stability issues arising in GRPO-style critic-free training of multi-agent LLM systems. They improve performance by normalizing each agent’s advantage with its own reward statistics [Feng et al., 2026]. MAPoRL trains multiple LLMs with verifier-based rewards to encourage collaborative behavior [Park et al., 2025]. MARFT gives a general formulation for reinforcement fine-tuning of LLM multi-agent systems [Liao et al., 2025]. Most closely related is MAAC, which formulates LLM collaboration as cooperative MARL. It adopts centralized training with decentralized execution, with a centralized critic and shared rewards, for long-horizon collaboration [Kraemer and Banerjee, 2016, Liu et al., 2026]. Unlike prompt-defined systems, these methods allow collaboration policies to adapt to task feedback. Nevertheless, they usually use raw interaction histories as context. The actor and critic must reconstruct task state and the knowledge of other agents from long textual histories, making representation learning difficult. 

Partner modeling and belief learning in MARL. Early methods condition an agent’s policy on observed opponent behavior or infer another agent’s hidden goal [He et al., 2016, Raileanu et al., 2018]. Later work learns more general representations of agents’ latent characteristics from their behavioral histories [Rabinowitz et al., 2018, Papoudakis et al., 2021]. Also some research improves agent collaboration by learned communication [Foerster et al., 2016, Sukhbaatar et al., 2016, Das et al., 2019]. These methods usually assume low-dimensional observations, compact policies, or continuous communication. In contrast, LLM agents act over long textual histories and communication, making belief and partner modeling more challenging. 23 Background 

3.1 Decentralized LLM Collaboration 

In decentralized LLM collaboration, given a task, each agent is provided with a natural language prompt. The process can be described as a multi-turn interaction. Each agent maintains its own context locally and generates a response based on its own policy. The responses of all agents are aggregated within the environment into a joint action, after which the environment updates the task state based on this joint action and returns new observations, feedback, and rewards. When generating actions, each agent rely on its own local observations, historical context, received messages, and tools to which it has access. Agents can exchange information through the communication channels. The communication itself is part of the action. And decentralized execution supports parallel reasoning and reduces context pressure on individual agents.

## 5 Experiments 

5.1 Setup Minecraft Collaboration. Minecraft games (Figure 2) are long-horizon testbeds with explicit physical state and partial observability. Each agent observes only its local view and received messages, where the agents maintain environment beliefs, track the other agents’ progress, avoid redundant exploration, and coordinate actions through communication. In Bridge Building , two agents start on opposite sides of a damaged gap and should construct a safe connected path within limited turns. The gap contains visually ambiguous pillars that may either provide useful support or indicate hazardous regions, where nearby construction incurs large penalties. Because pillar types are initially hidden, agents must explore informative viewpoints, communicate discoveries, and coordinate bridge segments from both sides. In Resource Gathering , resource cells contain different amounts of wood, stone, and iron, and agents must satisfy all collection targets within a fixed horizon. Agents have asymmetric extraction capabilities, so they may observe resources that only the other agents’ can collect. Effective collaboration therefore requires separating actionable observations from information that should be communicated. At each turn, agents specify broadcast resource facts, movement paths, and extraction targets, and extraction is only allowed near the final location. 

Web Collaboration. In Web Collaboration, agents operate in an open-ended environment. The relevant state is not a location or block layout, but the progress of the search process: what evidence each agent has collected, which sources still look promising, whether the available evidence is enough to support an answer, and what the other agent are likely to do next. As the dominant reward is given after the final answer is checked, agents receive little direct feedback while searching. They should decide whether to continue gathering evidence, share partial findings, wait for more information from the other agents, or commit to an answer. In Cross-Lingual Gathering , agents gather cross-lingual information sources [Longpre et al., 2021] and produce a final answer. 5.2 Results 

Table 1 reports the main evaluation results. BCMAAC achieves the best performance on all six tasks. Trained multi-agent methods substantially outperform single-agent AC on tasks that can be ef-fectively decomposed across agents, particularly Resource Gathering , Bridge Building , Multi-Source Gathering , and Stateful Tool , indicating that these tasks are not merely tests of individual model capa-bilities, but require task decomposition, complementary information, and cross-agent collaboration. In contrast, collaboration based solely on prompts (Parallel, Pipeline) fails to consistently improve performance, indicating that simply adding agents without learning effective collaboration meth-ods is insufficient . For standard deviations, BCMAAC exhibits comparable or lower variability than MAAC overall, indicating that it can improve stability; BCMAAC-P and BCMAAC-B show higher standard deviations than full BCMAAC on many tasks, indicating that BCMAAC with two auxiliary objectives not only improve average performance but provide a complementary regularization effect. Tasks with low parallelism are an exception, the most typical being Filesystem Wrangling : the Editor can only act on paths that the Explorer has already found and communicated in the previous turn, making the two roles more akin to a sequential pipeline than a parallel division of labor. Consequently, a single-agent AC (66.9%) that handles both reading and writing and eliminates the need for cross-agent handoffs is inherently strong, even outperforming the decentralized MAAC (58.9%). Even so, BCMAAC can still track the Editor’s readiness status, outperforming the single-agent approach with 73.0%, indicating that what truly matters is effective collaboration. Compared to MAAC, BCMAAC’s largest gain occurs in Stateful Tool (59.2% →77.5%, +18 .3), followed by Resource Gathering (78.4% →92.8%) and Filesystem Wrangling (58.9% →73.0%). Both 

Stateful Tool and Resource Gathering require maintenance of hidden state, the former must track which facts the executor still lacks and when to submit them, while the latter must remember resource locations and coordinate with agents of different capabilities. This is exactly the setting where belief context helps. While MAAC already performs strongly on Bridge Building , yet BCMAAC still improves from 80.6% to 94.4%, indicating that structured belief remains beneficial for collab-oration quality. On Web tasks, BCMAAC also consistently outperforms MAAC. Cross-Lingual 

8Gathering shows moderate gains (45.1% →53.2%), while Multi-Source Gathering is even greater (47.6% →58.5%), consistent with the task structure, as multi-source question-answering relies more on complementary evidence. 

Our ablation studies demonstrate that the two auxiliary signals are complementary. BCMAAC-P and BCMAAC-B perform between MAAC and the full BCMAAC on all tasks, indicating that both partner-action prediction and task-belief supervision can improve upon the original MAAC critic. BCMAAC-B performs better on Resource Gathering , Cross-Lingual Gathering , Multi-Source Gath-ering , and the two Tool tasks, all of which center on maintaining the state of resources/evidence/tools and the other agents’ readiness; BCMAAC-P performs better on Bridge Building , where coordinating the other agents’ actions and dividing construction tasks is particularly important. The full BCMAAC achieves the best overall performance, demonstrating that combining the modeling of task beliefs with partner actions yields the best collaboration. 

5.3 Analysis 

Figure 3 shows the performance on six tasks. Overall, BCMAAC converges faster, achieves higher rewards, and is more stable than MAAC on most tasks, as the structured belief context improves advantage estimation. In Filesystem Wrangling , BCMAAC overtakes MAAC and maintains a markedly higher, less volatile reward. This is consistent with better tracking of Editor readiness and more accurate timing of hard actions. In Resource Gathering , BCMAAC likewise improves more smoothly, suggesting that the belief encoder captures resource states, remaining objectives, and the other agents’ capabilities useful for intermediate decisions. In Bridge Building and Stateful Tool , the methods are initially similar, but BCMAAC converges to a higher final reward. Gains are smaller on the Web tasks: BCMAAC maintains a modest advantage in Multi-Source Gathering , while Cross-Lingual Gathering 

remains noisy and shows improvement at end. The task-belief and partner-action objectives help track retrieved evidence and answer readiness, reducing redundant searches and premature responses. Results suggest that BCMAAC benefits from latent collaboration state explicitly rather than recon-structing it solely from raw histories. Its centralized critic estimates returns from structured joint beliefs, while the auxiliary objectives provide dense turn-level supervision when communication and exploration produces little immediate reward. In nearly fully observable tasks, or when short histories are sufficient, the advantage of BCMAAC may be limited. Its effectiveness depends on whether the reduction in estimation error outweighs the information lost through compression. In the partially observable, long-horizon tasks studied in this paper, this trade-off falls clearly on BCMAAC’s side. 

## 6 Conclusion 

We study decentralized LLM collaboration and introduce BCMAAC. BCMAAC maintains structured belief context during execution, performs centralized value estimation from joint belief context during training, and preserves decentralized decision-making at inference time. BCMAAC consistently outperforms MAAC and improves training stability across Minecraft, Web, and tool-based collabo-ration tasks. The gains are strongest when agents must track latent state, integrate the information of other agents, coordinate delayed actions, and combine evidence from multiple sources. These results establish structured belief conditioning as an effective mechanism for decentralized LLM collaboration. Our study has a few limitations. Although our framework is applicable to multiple agents, all six tasks are two-agent tasks, as the characteristics of the tasks we designed are best suited for pairing the two agents into complementary roles. For example, in Filesystem Wrangling , the toolset splits cleanly into read-only commands and write commands, so an explorer with read-only permissions and an editor with write permissions can be paired accordingly.

Resource Gathering. The map of the dataset sizes include 8 × 8, 9 × 9, and 10 × 10 . Each cell may contain a tuple of (wood, stone, iron) resources. The task goal is gathering enough required instances. Each turn, an agent’s decision is limited to a movement path and at most 2 extraction targets. The two agents have asymmetric tools: one can harvest wood while the other can harvest stone and iron. Thus, communication is necessary, as an agent may observe resources that are useful to its teammate. Success is defined as achieving the task goal. 

Bridge Building. All maps of dataset are 13 × 11 grids. The agent view radius is 3. The task goal is to connects the two anchor regions. The maps differ in things like pillar layout and positions of anchor. Each map contains candidate pillars, including true supports and fake hazardous supports. Agents should discover useful supports through local observation and probing, or communicate probe results and coordinate construction. Each response may probe up to 3 candidate pillars and issue bridge-construction commands within a command budget. Success is defined as achieving the task goal. 

Cross-Lingual Gathering. This task is built from a Chinese MKQA subset [Longpre et al., 2021]. Each instance contains paired English and Chinese retrieval corpora and a two-piece support chain. One agent searches English Wikipedia passages, then identify an English page title or bridge clue. The other searches Chinese passages. It is responsible for producing the final answer from target-language evidence. The retriever returns the top 4 passages, each prompt shows up to 6 visible pieces, and communication can include up to 3 evidence items. Success is defined as finding the final answer. 

Multi-Source Gathering. This task uses HybridQA examples [Chen et al., 2020], with training instances drawn from the train split and evaluation instances from the development split. The task is balanced across passage-to-table, table-to-passage, and passage-to-table-to-passage reasoning chains. One agent can inspect passage evidence while the other can inspect table-row evidence. Each instance contains a table, a set of passage pieces, and cross-source support annotations. The final answer often depends on combining one table row with one or more passage pieces. The retriever returns the top 4

pieces, communication is limited to 3 evidence item. Success is defined as finding the final answer.

A.2 Structured Context and Auxiliary Targets 

For BCMAAC, each environment exposes compact structured side information xi,t constructed only from information visible to agent i at execution time. It never exposes the global answer nor hidden training labels. The belief targets vary across tasks. In Resource Gathering, they mark the resource cells that match the agent’s tool ability. In Bridge Building, they mark the true supports among pillars. In the Web tasks, they mark the evidence pieces. In the Tool tasks, they mark the required progress slots, such as whether the target action is done. The partner-action signal is teammate action-type prediction, implemented with a four-class taxonomy in every task. Bridge Building uses place/scout/communicate/no-op. Resource Gathering uses gather/move/communicate/no-op. Auxiliary labels are used only during training. Notice that at execution time agents keep only their actor and recurrent belief encoder.
