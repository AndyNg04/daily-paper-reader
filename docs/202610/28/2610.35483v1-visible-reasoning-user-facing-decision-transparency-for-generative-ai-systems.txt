# Visible Reasoning: User-Facing Decision Transparency for Generative AI Systems 

Sanjay Krishna Anbalagan 1, Xinrui Nie 1, Anughna Kommalapati 1, Vijay Kumar Kanamarlapudi 1, Sreekanth Radhakrishnan 1, Xiaodan Zhao 1, and Umesh Mohan 1

Amazon Web Services, USA 

Abstract. Across multiple waves of computing, public trust in new technology has followed the emergence of governance mechanisms that made dominant risks legible and manageable. Generative AI shifts this pattern: these systems synthesize across heterogeneous sources, and users increasingly experience them as reasoning systems. The central question changes from “did it perform correctly?” to “can we trust how it arrived at its conclusion?” This paper introduces Filtered Decision Logs (FDLs) , a user-facing transparency mechanism that makes decision formation visible with-out exposing raw chain-of-thought. FDLs pair each response with (i) a concise decision rationale, (ii) influence-ordered supporting data points derived from tool outputs, and (iii) relevance indicators showing which sources most shaped the conclusion. To operationalize evidence se-lection, we propose a trace-based method that reconstructs observability telemetry into a provenance tree and ranks evidence using four deter-ministic semantic and structural signals— Final Answer Similarity, Average Relevancy, Persistence, and Structural Proximity —combined via adaptive weighted scoring. We demonstrate FDLs across 

three domains : career advising (5 tools), investment analysis (4 tools), and travel planning (4 tools). In a formative evaluation with 50 partic-ipants (25 students, 25 working professionals in AI development), 92% 

rated the influence-ranked evidence as helpful for understanding and trusting the system’s recommendation. Counterfactual tool-removal experiments confirm that removing the top-ranked source changes the answer more than removing a low-ranked source, validating that the ranking tracks decision dependence. We conclude that evidence-ranked transparency helps users identify misleading signals and missing con-text, enabling more confident acceptance, correction, or re-run of system decisions.

# 1 Introduction 

New technology is rarely trusted simply because it exists; it becomes trusted when its risks can be governed. In earlier eras, governance co-evolved with adop-tion. Reliability concerns about mechanized work led to audits and verification; privacy concerns about networked information led to encryption and consent frameworks; and security concerns about cloud services led to compliance stan-dards and operational controls. In each case, governance made risk tractable, and trust followed. Generative AI changes the surface area of uncertainty. The user is not judg-ing a deterministic procedure but a system that synthesizes across heteroge-neous sources and produces persuasive outputs under incomplete information. For many tasks, users cannot easily validate correctness, and it is often am-biguous whether a failure arose from missing context, irrelevant evidence, tool errors, or flawed reasoning. Output-only interfaces force a brittle trust posture: either the user accepts an answer with insufficient grounds or rejects it without knowing how to correct it. This challenge becomes sharper in modern agentic applications. Tool-augmented LLM agents [14,15] call external tools—APIs, databases, search engines—to gather real-time data before producing a response. When an investment advisor agent synthesizes stock prices, financial news, company fundamentals, and economic indicators into a recommendation, the user faces a fundamental question: which data sources actually shaped this answer, and how much? Without this information, the user cannot verify whether the recommendation is grounded in solid fundamentals or recent news hype, cannot challenge the recommendation by identifying potentially misleading sources, and cannot re-run the agent with different data source configurations to explore alternatives. A human analogy clarifies the expected interaction. When people ask a par-ent for career advice, trust is grounded in shared context; when they ask an expert, trust is contingent on justification—users expect data points and rea-soning before accepting the recommendation. In expert settings, transparency is not merely an explanation; it is a mechanism for verification, disagreement, and refinement. We argue that generative AI systems should support a comparable interaction: users should be able to inspect the evidence that shaped an answer and decide whether to accept it, provide missing context, or re-run the system with corrected constraints. This paper introduces Filtered Decision Logs (FDLs) as a user-facing trans-parency artifact that provides evidence-backed decision transparency without exposing raw chain-of-thought. FDLs are built for the practical reality of mod-ern systems: many generative applications already use tools and sub-agents, and many platforms already provide observability telemetry [8]. The missing piece is a method that transforms this telemetry into user-comprehensible, influence-ranked evidence—a “governance surface” that lets users evaluate the logic behind outputs rather than validating outputs alone. # 2 Related Work 

Our work intersects three research threads—training-data influence, explanation and rationale methods, and provenance and observability—but focuses on a dis-tinct object: runtime evidence influence in tool-using agent traces, surfaced as a user-facing governance interface. 

2.1 Training-Data Influence and Data Valuation 

Influence functions, introduced by Koh and Liang [1], trace a model’s prediction back to training examples most responsible for that prediction. Data Shapley, proposed by Ghorbani and Zou [2], evaluates training-data value using Shapley-based allocation principles. These methods answer a different question than ours: in tool-using generative systems, users need to know which runtime artifacts— retrieved documents, API responses, database rows—shaped the answer in the current run, not which training examples shaped the model’s parameters. Our influence scoring operates at the runtime tool-output level, complementing rather than replacing training-data attribution. 

2.2 Rationales, Interpretability, and Chain-of-Thought 

Rationale extraction methods, such as those proposed by Lei et al. [3], learn to identify concise text fragments that justify a prediction. In large language models, chain-of-thought (CoT) prompting, introduced by Wei et al. [4], im-proves performance by eliciting intermediate reasoning steps. Wang et al. [5] further improved CoT by sampling multiple reasoning paths and selecting the most consistent answer. These approaches improve reasoning performance and can provide natural-language explanations, but they do not directly solve the governance question 4 S.K. Anbalagan et al. 

in tool-using systems: which external artifacts influenced the answer, and how strongly? Moreover, exposing raw chain-of-thought is not necessarily suitable as a user-facing governance mechanism. Turpin et al. [6] demonstrated that CoT traces do not always faithfully represent the model’s actual decision process— models can produce coherent reasoning chains that lead to the correct answer for the wrong reasons. For governance purposes, self-narrated reasoning is a status update, not auditable evidence. We draw on the concept of user-in-the-loop explanation interfaces. Chromik et al. [7] showed that users can overestimate their understanding from AI ex-planations alone, motivating more evidence-grounded transparency mechanisms. FDLs address this by providing quantified, verifiable evidence items rather than narrative explanations that may create an illusion of understanding. 

2.3 Feature Attribution and Explainability 

Feature attribution methods such as LIME, introduced by Ribeiro et al. [10], and SHAP, proposed by Lundberg and Lee [11], explain individual predictions by approximating local model behavior. LIME generates local linear approximations around a prediction to identify which input features contributed most, while SHAP uses Shapley values from cooperative game theory to provide theoretically grounded feature importance scores. These methods operate at the token or feature level; FDLs operate at the tool level , making them interpretable by non-technical users who understand “the news article had a 0.64 influence score” but not “token 47 had attention weight 0.03.” 

2.4 Provenance, Observability, and Evaluation 

Distributed tracing standards, such as OpenTelemetry [8], model execution as connected parent–child spans within a trace. Emerging frameworks like Lang-fuse [9] emphasize continuous, introspectable trace capture by instrumenting agents at runtime. Evaluation frameworks such as RAGAS, proposed by Es et al. [12], provide automated evaluation of retrieval-augmented generation using LLM-as-evaluator patterns. Our work complements these efforts by transforming connected traces into influence-ordered evidence per answer—a specific trans-parency artifact designed for end users rather than developers. 

2.5 Why Not Ask the Model? 

A natural question is: why not simply ask the LLM which evidence it used? We distinguish three paradigms for decision transparency based on evaluation independence —whether the transparency mechanism depends on the same gen-erative process it is meant to make transparent (Table 1). The analogy is a financial audit: the auditor does not ask the company “were your transactions legitimate?”—they examine the receipts, trace the money flow, and independently verify what happened. FDLs provide this evaluation indepen-dence: the scoring mechanism is entirely separate from the reasoning mechanism. Visible Reasoning 5

# 3 Filtered Decision Logs as a Governance Interface 

We define a Filtered Decision Log (FDL) as a transparency artifact displayed alongside a model response. An FDL answers three user questions: (1) What is the system’s conclusion? (2) Why did it reach that conclusion? (3) What evidence most shaped the conclusion? FDLs operationalize this through three components: 

Decision rationale. A concise natural-language summary describing why the answer was produced, anchored in evidence items rather than raw intermediate reasoning. 

Supporting data points. Derived from tool outputs—retrieved documents, API responses, database results. Instead of exposing raw JSON traces, the system presents readable evidence statements with semantic descriptions (e.g., “NVIDIA Corporation: Revenue $130.5B, Margin 55.9%”). 

Relevance indicators. Categorical labels—High ( ≥ 0.70), Medium (0.40–0.70), Low ( < 0.40)—grounded in the deterministic scoring method described in Sec-tion 5. Color coding provides immediate visual triage. 

Interaction pattern: Accept or Re-Run. FDLs support an accept/re-run interac-tion (Fig. 1). The user inspects the influence ranking, optionally expands signal breakdowns, and if a source appears misleading, excludes it and re-runs the agent. The system generates a new recommendation with fresh influence scores. This transforms governance from a hidden internal process into a collaborative loop. 

Important clarification on scores. Influence scores are absolute alignment and proximity measures computed independently for each evidence item. They do not sum to 1.0 or 100%, and they are not causal attribution —a score of 0.70 means “high semantic alignment with the answer and reasoning chain,” not “this source contributed 70% of the answer.” This distinction is critical: the scores indicate how much a source’s content appears in the output, not a causal decomposition of the generative process. 6 S.K. # 4 System Architecture 

The FDL framework consists of two independent pipelines. This separation is the foundation of evaluation independence: the agent never knows it will be evaluated, and the FDL pipeline never influences the agent’s reasoning. 

4.1 Agent Pipeline 

The agent pipeline receives a user query, calls external tools, reasons over the results through multiple iterations, and produces a final answer. The execution trace is recorded as a context tree —a hierarchical data structure where each node represents a pipeline stage. Our prototype uses a tool-augmented LLM agent built on Amazon Bedrock (Claude 3 Sonnet) with the ReAct pattern [14]: the agent iteratively reasons about which tools to call, executes them, observes results, and continues until it produces a final answer. > Fig. 2. The 7-stage FDL influence pipeline. Each stage is a pure function operating on a typed scope. The pipeline uses no generative AI—only embeddings (Stage 4) and deterministic computation.

4.2 FDL Pipeline 

The FDL pipeline is a separate 7-stage linear pipeline (Fig. 2) that processes the context tree using no generative AI —only embeddings and deterministic computation: 1. extractDataNodes : Walk the execution trace to identify tool result stages. 2. buildParentPointers : Construct a parent pointer map for upward traversal. 3. extractAncestorChains : For each data node, collect LLM reasoning ances-tors with text and depth. 4. embedEvidence : Compute embedding vectors using Amazon Titan Embed Text v2 [13]. A cache prevents redundant API calls. 5. computeInfluenceScores : Calculate four signals and combine into compos-ite scores (Section 5). 6. rankAndSelectTopK : Sort by score descending, select top-K, assign indi-cators. 7. formatFDLResponse : Produce the final FDL with rationale, ranked evi-dence, and signal breakdowns. 

4.3 Provenance Reconstruction 

The pipeline begins by reconstructing a provenance tree from the agent’s execu-tion trace. Modern agent frameworks record execution as connected parent–child 8 S.K. Anbalagan et al. 

spans [8,9]. We walk this tree recursively to identify data nodes—stages whose logs contain tool result data. A practical challenge is that tool execution often occurs dynamically within a single orchestration stage. We address this with a fallback extraction strategy: when the tree walk finds fewer data nodes than expected, the system extracts tool results directly from the global conversation messages array. This ensures framework-agnostic provenance reconstruction regardless of how the agent struc-tures its execution trace. 

# 5 Deterministic Influence Scoring 

Each evidence item is scored on four orthogonal signals computed using cosine similarity between embedding vectors produced by Amazon Titan Embed Text v2 [13], ensuring determinism—the same inputs always produce the same scores. Unlike LLM-as-evaluator approaches [12] where re-running the same evaluation can produce different results, FDL influence scores are reproducible.

Unlike AVG which averages, PERSIST measures breadth of influence. A tool referenced in 4 of 5 reasoning steps (PERSIST = 0 .8) scores higher than one referenced intensely in only 1 step. Default T = 0 .30. Inspired by the persis-tence concept in influence functions [1], adapted from training-time to runtime evidence.

We count only LLM reasoning ancestors (stages with text output), not pipeline plumbing stages, to avoid diluting the signal with framework overhead. 

5.2 Composite Score 

The four signals are combined with configurable weights: 

S(d) = α · FA( d) + β · AVG( d) + γ · PERSIST( d) + δ · DEPTH( d) (5) Default weights: α = 0 .40, β = 0 .30, γ = 0 .20, δ = 0 .10, summing to 1.0. The weights encode a prior: direct semantic similarity (FA) is the strongest signal, followed by consistency across reasoning (AVG), breadth of reference (PERSIST), and structural proximity (DEPTH). This weighted combination is conceptually related to how SHAP [11] combines feature contributions, but operates at the tool level with configurable weights rather than Shapley-value-based allocation. 

Scores are not additive. Each evidence item’s score is computed independently. Scores do not sum to 1.0 across items and do not represent causal attribution. A score of 0.70 means “high semantic alignment with the answer,” not “this source contributed 70% of the answer.” 

5.3 Adaptive Weight Redistribution 

The default weights assume a multi-step reasoning pipeline where all four signals contribute. In simpler topologies (e.g., single-tool queries), AVG and PERSIST are structurally zero —not because the tool was uninfluential, but because there are no LLM ancestors to measure against. Without adaptation, scores are capped at α + δ ≈ 0.50. We address this with per-evidence adaptive redistribution. For data node d

7.3 Results 

Overall, 46 of 50 participants (92%) rated the influence-ranked evidence as help-ful (Table 4). All 25 working professionals gave a positive rating, while 21 of 25 students did so. 7.4 Qualitative Observations 

Three patterns emerged from participant comments and observed behavior: 

Sorted order aids triage. Participants consistently started by examining the top-ranked source, confirming that influence ordering reduces cognitive load. Multiple participants noted that without the ranking, they would have had to read the entire response and mentally reconstruct which sources were used—a cognitively expensive task that the FDL panel automates. 

Exclude-and-re-run builds understanding. Several participants spontaneously ex-cluded the top source to “see what happens without it,” demonstrating that the re-ask pattern is intuitive and does not require instruction. In the career scenario, participants who excluded social-media-profile and observed the recommenda-tion shift from policy to quantitative careers reported the highest confidence in their understanding of the system’s reasoning. 

Signal breakdown builds confidence in practitioners. Working professionals who expanded the signal breakdown reported higher confidence in the influence score, particularly when FA (Answer Relevance) was high—they could verify that the tool’s data appeared in the answer. The 100% approval rate among professionals suggests that practitioners with AI development experience find the transparency mechanism immediately useful for their workflow. 

# 8 Discussion 

8.1 What We Claim—and What We Do Not 

We do not claim that our four-signal scoring algorithm is optimal for computing influence. The weights ( α, β, γ, δ ) are configurable priors, not learned parameters. Visible Reasoning 15 

Different domains may benefit from different configurations. The scoring method is a concrete, implementable starting point, not a final answer. 

What we do claim is that the idea of providing sorted, quantified influence evidence fundamentally changes the user’s relationship with AI rec-ommendations: 1. Sorted order helps users decide : When evidence sources are ranked by influence, users quickly identify which data drove the recommendation and whether that aligns with their expectations. 2. Accept/re-run empowers users : The ability to exclude sources and re-run transforms users from passive consumers (“the AI said X”) into active decision-makers (“the AI said X because of source Y; without Y, it says Z; I prefer Z”). 3. External measurement builds justified trust : Because influence scores are computed by a separate, deterministic pipeline—not self-reported by the LLM [6]—users can trust the scores even when they question the recommen-dation. The counterfactual validation (Table 3) provides objective evidence that the ranking tracks something real about decision dependence, and the formative evaluation (Table 4) confirms that users find this transparency useful in practice. 

8.2 Evidence-Level Feedback as a Calibration Signal 

The exclude/re-run interaction generates a natural feedback signal: which sources users exclude most often, and whether they accept or reject the revised recommendation. This evidence-level feedback could be used to calibrate rank-ing weights or train a lightweight preference model that learns domain-specific weight profiles. We do not claim to have trained such a model; we note that the interaction pattern produces the data needed to do so. 

8.3 Inspiring Further Research 

Our goal is to inspire more researchers to explore influence scoring for tool-augmented agents. The design space includes: 

– Learned weights : Can influence weights be learned from user feedback? 

– Causal influence : Can we move beyond correlation (embedding similarity) to causal attribution via counterfactual agent runs? 

– Multi-agent influence : How should influence propagate across agent dele-gation boundaries? 

– Temporal influence : In multi-turn conversations, how does source influence decay or accumulate? 

– Domain-specific weighting : Can weight profiles be pre-configured per do-main based on expert input? 16 S.K. Anbalagan et al. 

8.4 Limitations – Embedding-based signals : Cosine similarity captures semantic overlap but not causal influence. A source may be semantically similar to the answer with-out having caused it—a limitation shared with feature attribution methods like LIME [10] and SHAP [11]. 

– Deterministic mock data : Evaluation scenarios use deterministic mock tools. Real-world tools produce variable outputs that may affect score stabil-ity. 

– Single-model evaluation : All experiments use Claude 3 Sonnet via Amazon Bedrock. Different models may exhibit different tool usage patterns. 

– Formative evaluation : Our study is formative (guided sessions with thumbs-up/down feedback) rather than summative (controlled experiment with statistical significance testing). A rigorous evaluation agenda is outlined in Section 11. 

– Weight sensitivity : Default weights were chosen based on intuition about signal importance, not empirical optimization. 

# 9 Ethical Considerations and Scope 

All evaluation scenarios use synthetic mock data and do not constitute real ca-reer, financial, or travel advice. The FDL framework is a governance interface ,not a correctness guarantee—it helps users inspect evidence, not validate truth. In production deployments, evidence exposure must respect access controls and data redaction policies: not all tool outputs may be appropriate to surface to all users. We note that our investment advisor scenario, while useful for demonstrat-ing influence transparency, should not be interpreted as endorsing AI-generated financial advice without appropriate regulatory compliance and human over-sight.

# 11 Evaluation Agenda 

We outline a rigorous evaluation agenda for future work: 1. Controlled user study : Between-subjects design comparing FDL-augmented vs. standard interfaces, measuring trust, understanding, and actionability with statistical significance testing. 2. Score validation : Compare FDL rankings against human expert rankings to measure alignment. 3. Ablation study : Vary the number of signals (FA only, FA+AVG, all four) and measure the effect on user trust. 4. Real-world tools : Replace mock tools with live APIs to evaluate score sta-bility. 5. Cross-model evaluation : Test with multiple LLM providers to assess gen-eralizability. 

# 12 Conclusion 

We presented Filtered Decision Logs (FDLs), a user-facing transparency mech-anism that makes decision formation visible in tool-augmented generative AI systems. By operating as an external measurement pipeline—separate from the agent’s reasoning process—FDLs provide deterministic, verifiable transparency that users can trust independently of the recommendation itself. Through three evaluation scenarios spanning career advising, investment analysis, and travel planning, we demonstrated that influence scoring with sorted evidence and accept/re-run interaction transforms users from passive consumers into active decision-makers. Counterfactual tool-removal experiments confirm that the influence ranking tracks actual decision dependence, and formative evaluation with 50 participants (92% approval) indicates that practitioners and students find the transparency mechanism useful. The key contribution is not the specific scoring algorithm but the interaction pattern : showing users which tools influenced the LLM’s response, in sorted or-der, with the ability to exclude sources and re-run. We hope this work inspires further research into influence scoring for tool-augmented agents—a critical ca-pability as AI systems increasingly make recommendations affecting people’s careers, finances, and daily lives.
