Abstract 

Memory enables language model assistants to maintain continuity across sessions and gener-ate personalized responses, but knowing more about a user does not necessarily produce re-sponses they prefer. Existing evaluations assess memory capabilities without directly establish-ing whether memory use benefits the user. To study this gap, we collect approximately 1,000 pairwise judgments from 87 participants us-ing their own ChatGPT queries and personal memories. We find that memory-conditioned responses are not consistently preferred over responses generated without memory and in some cases, users strongly prefer the latter. Au-tomatic evaluators also show limited agreement with users and favor memory-conditioned re-sponses substantially more often than users do. Motivated by these gaps, we introduce a memory-aware reward model that learns from user judgments, achieving 72.8% preference prediction accuracy and outperforming the ex-isting baselines. Our findings motivate eval-uation and optimization objectives that align memory use with the preferences of the people whose information is being used. 

1 Introduction 

Memory has emerged as a key component of con-versational language models, enabling them to re-tain and reuse information beyond their context length and across multiple conversation sessions. Existing work has explored mechanisms for stor-ing past experiences, managing information across context windows, and retrieving knowledge to sup-port subsequent reasoning and action (Zhong et al., 2023; Packer et al., 2023). These capabilities sup-port continuity across interactions and tasks. In per-sistent assistants, memory allows models to employ information about the user including their persona, their expressed preferences, and past requests to generate more personalized and contextually appro-priate responses. Much of the progress in long-term memory has been measured by and optimized for benchmarks like LongMemEval (Wu et al., 2025), Locomo (Ma-harana et al., 2024), and PersonaMem (Jiang et al., 2025a) that evaluate whether models can compress and recover information from past interactions to the current session. However, accurate recall and successful preference inference do not ensure ap-propriate memory usage. Consider a user who previously requested explanations tailored to their profession and now asks for a general overview of a topic. Reusing that preference may appear rel-evant and personalized, yet narrow the answer in a way the current request does not warrant. Re-cent studies document such failures through over-personalization and inappropriate memory use (Hu et al., 2026; Feng et al., 2026a; Pulipaka et al., 2026). These errors cannot be characterized solely as failures of memory accuracy or retrieval. They mainly concern how available information should be used for LLM response. To understand whether memory-based person-alization produces responses that users prefer, we collect approximately 1,000 response-pair judg-ments from 87 participants . Participants con-struct personal memory profiles from their own ChatGPT interactions and recent experiences, then evaluate paired responses to queries drawn from their interaction histories. Each pair uses the same query and generator, with one response receiving retrieved memories and the other generated with-out them. Long-term LLM memory. Long-term memory systems enable language model assistants to ac-cumulate and reuse information beyond a single context window. Existing approaches span external retrieval (Zhong et al., 2023; Packer et al., 2023; Chhikara et al., 2025), graph-based memory stores (Xu et al., 2025; Jiang et al., 2026), learned poli-cies for memory management (Wang et al., 2025; Yan et al., 2026), and parametric memory (Wang et al., 2024; Lei et al., 2026). A growing set of benchmarks evaluates these capabilities through recall and multi-session reasoning (Maharana et al., 2024; Wu et al., 2025; Tan et al., 2025), dynamic user profiling and personalized responses (Jiang et al., 2025a,b), and tracking evolving user or world states (Liu et al., 2026a; Li et al., 2026b; Fan et al., 2026). These evaluations primarily measure whether information can be retained, recovered, and updated, leaving less clear how an assistant should behave once relevant memories are avail-able in context. Recent work moves beyond re-call to examine whether past chat history supports downstream actions (He et al., 2026; Shen et al., 2026; Feng et al., 2026b). Our work extends this focus by analyzing user preference and learning rubric-based proxies for memory usage grounded in real human preferences. 

Personalization and Over-personalization. 

LLM personalization has traditionally represented users through profiles, personas, demographic or preference attributes, and collections of prior interactions, which are then used to condition generation or predict individual preferences (Salemi et al., 2024; Kirk et al., 2024; Dong et al., 2024; Ryan et al., 2025a). However, incorporating personal information does not always improve a response: recent work identi-fies over-personalization as a failure of using user information when it can feel unnecessary, distracing, sycophantic, or even privacy-intrusive (Hu et al., 2026; Feng et al., 2026a). OP-Bench evaluates irrelevant personalization, repetition, and sycophancy, while PersistBench examines cross-domain memory leakage and memory-induced sycophancy (Hu et al., 2026; Pulipaka et al., 2026). We instead treat appropriate memory use as a preference learning problem. Rather than assuming a fixed notion of when personalization is desirable, we collect response-level preferences from users over controlled variations of memory-conditioned responses and use these judgments to recover signals for how user memory should shape a response. 

RLHF and post-training. Post-training aligns language models with human preferences through learned reward signals or direct preference opti-mization (Ouyang et al., 2022; Bai et al., 2022; Rafailov et al., 2023). Standard formulations assess candidate responses to a single prompt, whereas recent work extends preference modeling to multi-turn conversations and agent trajectories (Shani et al., 2024; Shi et al., 2024), or conditions judg-ments on user-specific summaries and learned user representations (Nam et al., 2026; Shenfeld et al., 2025; Li et al., 2024). Beyond scaler re-ward model, rubric-based reward model raises for its interpretability, sample-efficiency, performance (Gunjal et al., 2026; Liu et al., 2025b, 2026b; Ryan et al., 2025b). We extend preference-based align-ment to cross-session memory, learning a rubric-based reward model that conditions on user mem-ory and learns whether and how it should influnce the current response. 

3 Data Collection 

We recruit participants from Prolific for a roughly 30-minute annotation task, paid at 14 USD per hour, and collect approximately 1,000 response-pair judgments (1,047 in total: 972 preference judg-ments and 75 test–retest repeats). We exclude the repeats from training and evaluation and filter the annotations for quality, leaving 821 judgments from 87 participants , of which 673 are strict pref-erences and 148 are ties. Each judgment records an annotator’s preference between two responses to the same query in the context of their personal memories. Evaluation separates participants across training, validation, and test within each split (Sec-tion 5). 

3.1 Personal Context Collection 

Participants accessed the study through Prolific and constructed an editable memory profile by running an extraction prompt in their own ChatGPT ac-count. The prompt draws on previous ChatGPT sessions and existing memories to (1) produce user profile such as age, occupation, location, etc. (2) infer user preferences around 10 topics including entertainment, lifestyle, communication, etc. (3) extract 100 their recent queries, excluding those dependent on unavailable attachments or prior con-3text. Participants then entered specific events from the preceding month through typing or editable voice transcription, with a target of 30 events. Note that we carefully avoid uploading any per-sonal data to our servers: full conversation histories and attachments were not uploaded and we explic-itly instruct the model and participants to avoid including sensitive information. Appendix E.1 re-produces the complete prompt, and Figures 2–3 show the collection interfaces. PII removal and de-identification procedures are described in Ap-pendix A.4. 

3.2 Response Pair Construction 

For each participant, we construct a candidate pool of 100 recent queries. For each query q, we retrieve a context Mq consisting of nine memory entries us-ing text-embedding-3-small and randomly select a response generator from GPT-5.2, Gemini-3.1-Pro, and Claude-Opus-5. The selected model generates two responses in separate calls: one conditioned on the retrieved context Mq and one without memory. The two responses thus share the same query and generator but differ in access to personal context. For memory-conditioned responses, we vary the instructions governing memory use across three prompting regimes: conservative , ordinary , and ag-gressive . The ordinary prompt instructs the model to incorporate memories where relevant and appro-priate. The conservative prompt imposes a stricter criterion, instructing the model to use memories only when they would meaningfully improve the answer to the current query. The aggressive prompt encourages proactive incorporation of personal con-text whenever possible. Appendix E.2 provides the complete prompt templates. We also screen the 100 candidate pairs to select 15 that have substantial, memory-grounded differ-ences in responses for human annotation. An LLM evaluator receives each query, its retrieved mem-ories, response without memory, response with memory (using ordinary prompt) and assesses the magnitude of their substantive differences, the ex-tent to which memory supports those differences, and the presence of unsupported changes. We rank pairs by prioritizing substantial, memory-grounded differences and retain the 15 highest-ranked pairs. 

3.3 Response Preference Annotation 

Participants viewed the query and Response A and Response B side by side. They then select the an-swer they would prefer to receive on a five-point scale: A much better, A slightly better, about the same, B slightly better, or B much better. Optional notes allowed them to explain their choice. Instruc-tions emphasized overall preference without pre-scribing greater personalization as desirable (Ap-pendix A.3). Appendix B presents two complete examples with contrasting preferences. Finally, we exclude incomplete response pairs, recorded attention-check failures, or other abnor-mal annotator behaviors, removing 151 of the 972 primary judgments and retaining 821 from 87 par-ticipants. 

3.4 Annotator Consistency 

Ten participants returned three days later to repeat judgments for identical queries and stored response pairs, with prior choices hidden. We measure di-rectional agreement: whether the same response is preferred in both sessions, regardless of changes in preference strength. Overall agreement was 68.0% across 75 comparisons. Initially much pref-erences were more consistent than slightly prefer-ences (73.9% versus 58.6%; Table 1). 4 Method 

4.1 Preliminaries Reward models. Reward modeling turns human judgments into a scoring function for selecting or optimizing model outputs. Given query q and response y, a scalar reward model Rθ(q, y ) rep-resents response quality through a learned utility. Pairwise preferences are commonly modeled as 

Pθ(ya ≻ yb | q) = σ(Rθ(q, y a) − Rθ(q, y b)) ,

Rubric-based reward models. Rubrics express response quality through explicit criteria, such as correctness, relevance, or respect for user con-straints. An evaluator assesses these criteria, and an aggregation rule converts its judgments into a reward or preference. This separates specifying desirable behavior from assessing whether a re-sponse exhibits it (Gunjal et al., 2026; Liu et al., 2025b). A simple scalar formulation is Rw(q, y ) = 

w⊤ϕ(q, y ), where ϕ contains feature scores that is typically assigned by an external evaluator (e.g., LLM Judge) and w is the weight vector of features.

Feature initialization. Preference annotations are used to induce candidate evaluation criteria. Each induction pass receives ten preference-labeled quadruplets from training set: the query, the re-trieved memory set, both candidate responses, and which response the annotator chose. Then LLM then generates ten rubric dimensions that explain the difference between the two responses, such as response quality, formatting, or memory us-age, etc. We run five independent passes, yield-ing roughly fifty raw proposals, many of which describe the same property in different words. 6 Results and Analysis 

6.1 User Preferences for Memory Use 

We first examine whether access to personal mem-ories produces responses that users prefer. Table 2 summarizes memory versus no-memory compar-isons across prompting regimes and response gen-erators. 

Memory access does not ensure a preferred re-sponse. Under ordinary prompting, annotators prefer the memory-conditioned response in 38.7% of comparisons and the response generated without memory in 41.9%, with the remaining comparisons judged about the same. Thus, supplying personal context does not yield a clear advantage in this set-ting. These results directly illustrate the distinction motivating our study: knowing more about a user does not necessarily produce an answer they prefer. 

More aggressive personalization receives less favorable preferences. Across conservative, or-dinary, and aggressive prompting (Appendix E.2), preference for memory-conditioned responses de-creases from 43.3% to 38.7% and 34.6%, respec-tively. Under aggressive prompting, users prefer the no-memory response in 49.3% of comparisons. Encouraging more personalization therefore does not necessarily improve the user experience. Even conservative prompting produces only a small de-scriptive advantage over responses without mem-ory, suggesting that appropriate memory use re-quires more than a general instruction to person-alize selectively. This pattern is consistent with concerns about over-personalization raised in re-cent work (Hu et al., 2026; Feng et al., 2026a). 

The direction of preference varies across gen-erators. Under ordinary prompting, memory-conditioned responses are preferred more often than no-memory responses for GPT and Claude, whereas the pattern reverses for Gemini (Table 2). The aggregate result therefore conceals differences in the direction of preference. Rather than showing that memory is uniformly unhelpful, these findings suggest that its value depends on how the generator incorporates personal context into its answer. These results concern the screened comparisons described in Section 3.2, which prioritize sub-stantial, memory-grounded response differences. Within this setting, they establish our first evalua-tion gap: memory-based personalization does not consistently translate into user-preferred responses.

6.3 Learning to Predict Response Preferences Learned rubric weights improve prediction ac-curacy. Our model achieves 72.8% accuracy, out-performing the majority baseline (55.0%), direct LLM judging (58.1%), and rubric-based LLM judg-ing (59.6%; Table 3), approaching the test-retest consistency of 73.9%. This improvement is ob-served across all three response generators, with accuracies of 66.0%, 75.0%, and 82.2% on GPT, Gemini, and Claude generated pairs, respectively. For each of these models, our method exceed the baselines significantly, highlighting the effective-ness of learning to aggregate multiple rubric dimen-sions from human preferences, rather than relying on an LLM judge to implicitly weigh these criteria through prompting alone. 

Both presentation and memory appropriateness drive preferences. Table 4 lists the five most in-fluential features in a descriptive fit of our model. The two largest coefficients are presentational: the memory-conditioned response is more likely to be preferred when it has more headings ( +0 .646 ) and is relatively longer ( +0 .571 ). This is consistent with (Dubois et al., 2024; Singhal et al., 2023) which shows that human have a strong preference for longer responses and it’s hard to distangle qual-ity from length, where in our case, we are also need to distangle length and memory usage. Memory-related features are also important by taking three out of top five influential features. Memory relevance and assumption proportionality have coefficient +0 .386 and +0 .323 , respectively, and unwarranted personal assumptions, ranked fifth, has a negative coefficient of −0.201 . This shows that annotator prefers response when the personal context is relevant and the resulting infer-ences are justified, rather than unwanted assump-tions of user beyond query indicates. 

Combining memory features and response at-tributes improves prediction. Following the ab-lation described in 5, we divide the features into two blocks: memory-related features and response-related features. The memory-only and response-only models achieve 62.5% and 67.0% pooled ac-curacy, respectively, while combining both fea-ture groups increases accuracy to 72.8%, outper-forming the two ablations by 10.3 and 5.8 per-centage points. Importantly, all variants use the same evaluator inputs and feature scores, differ-ing only in the features retained for regression. The improvement over the response-only model therefore demonstrates that memory-related criteria provide additional predictive information beyond general response attributes. 7 Conclusion 

We investigated how users want personal memories to shape assistant responses, using judgments from 87 participants evaluating answers to their own queries with their own memories. In our screened comparisons, memory-conditioned responses were not consistently preferred, and more aggressive personalization received less favorable judgments. Existing automatic evaluators favored memory-conditioned responses more often than users did, highlighting a mismatch between rewarding per-sonalization and capturing its value to the user. To address this gap, we introduced a memory-aware reward model that learns to aggregate in-terpretable rubric features from user preferences. The model achieved 72.8% accuracy on clear-preference comparisons with held-out participants, outperforming direct LLM judging and pretrained reward baselines. Combining memory-related cri-teria with general response attributes improved prediction over either feature group alone, indi-cating that evaluating memory use requires con-sidering both its appropriateness and the quality of the resulting answer. These findings establish user-grounded preference learning as a promising direction for evaluating memory-augmented assis-tants. Extending this supervision to post-training remains an important next step toward assistants that learn when and how remembered information improves the response a user wants to receive. 

Limitations 

Our study has several limitations. First, our dataset captures user context through memory profiles con-structed from participants’ own ChatGPT interac-tions and recent events they entered. While this ap-proach grounds preference judgments in authentic personal experiences, it covers a particular form of user memory. Persistent assistants may encounter more diverse information distributed across con-versations, documents, applications, and everyday activities. Extending our findings to these settings will require richer, multi-source, longitudinal col-lection of user context, together with preferences grounded in that context. Second, our data and rubrics focus on single-turn conversational responses with retrieved memories supplied as context. In multi-turn conversations and agentic tasks, appropriate memory use may depend on the interaction trajectory, the actions an assistant takes, and changes in the user’s goals or 8circumstances. Memory acquisition, updating, and deletion may also shape users’ expectations of sub-sequent behavior. Our test–retest study provides an initial assessment of preference consistency, but does not capture longer-term dynamics. Extending the framework will require trajectory-level judg-ments and evaluation criteria that account for both evolving user preferences and the consequences of memory use across interactions. Finally, our experiments evaluate memory-aware preference modeling in an offline setting. An im-portant next step is to use this supervision in as-sistant post-training and assess whether improve-ments in preference prediction translate into better memory-use behavior and user experience. This would establish how the learned criteria transfer from evaluating candidate responses and predicting user preference to guiding generation. 

Ethical Considerations 

Our study involves human participants and per-sonal information derived from their interactions with an AI assistant. The study was approved by an institutional research ethics committee. Par-ticipants were recruited through Prolific for a 30-minute task, compensated at USD 14 per hour, and provided informed consent before data collection. Participants could edit their memory profiles be-fore submission and both the AI assistant and the participant were instructed to exclude sensitive in-formation and direct identifiers. Full conversation histories and attachments were not uploaded to the study platform. Appendix A.4 describes our de-identification protocol for data release, including consistent replacement of identifiers, generaliza-tion of identifying details, and contextual review across each participant’s records. Our work aims to help assistants use personal memories in ways that better reflect users’ prefer-ences. However, predicted preference should not be interpreted as consent to collect, retain, or dis-close personal information. Moreover, preferences learned across participants may not reflect an indi-vidual user’s expectations. Applications of the pro-posed approach should preserve explicit user con-trol over memory and respect privacy constraints independently.

A.4 PII Removal and De-identification Protocol 

Personal memories can identify their owners through explicit identifiers or combinations of otherwise ordinary details. Our de-identification protocol therefore covers both direct identifiers and contextual disclosure, while preserving the information needed to interpret response preferences. Its scope includes profiles, event memories, queries, candidate responses, free-text annotations, and accompanying metadata. 

Collection-time minimization. The persona extraction prompt explicitly prohibits real names, email addresses, telephone numbers, exact home addresses, specific company and school names, social accounts, and identification numbers. It instructs the extractor to replace such details with abstract descriptions, such as “a tech company” or “a well-known university,” and applies the same restriction to profile tags. The query-extraction instructions also exclude sessions whose initial query contains substantial PII or unsafe sensitive information. These instructions reduce disclosure at collection; prompt compliance alone is not a guarantee of de-identification. 

Text and metadata handling. The release protocol requires direct identifiers to be removed or replaced with typed placeholders, such as [PERSON_1] , [ORGANIZATION_1] , and [LOCATION_1] . Replacements must remain consistent within a participant’s records, including across a memory, its query, and both candidate responses. Exact dates, fine-grained locations, and distinctive employment or biographical details require generalization when their combination could identify a person. The same rules cover third parties mentioned in memories. Recruitment identifiers, contact details, and operational metadata are excluded from released records; random study identifiers preserve participant grouping without exposing recruitment identifiers or linkage keys. 

Review and preservation of preference meaning. Release review combines automated screening for identifier patterns and named entities with contextual human inspection of complete records. The review must consider combinations of details across a participant’s memories, rather than assessing each field in isolation. Redaction must preserve task-relevant constraints, entity relationships, and the contrast between candidate responses. If removing identifying or sensitive information changes the basis of a preference, the comparison is withheld rather than retaining its label for a materially altered example. Release documentation records the affected fields and exclusions without reproducing removed identifiers.
