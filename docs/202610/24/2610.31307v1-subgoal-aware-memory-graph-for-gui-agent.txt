# Subgoal-aware Memory Graph for GUI Agent

## Abstract 

GUI agents aim to automate complex user tasks by interacting with mobile interfaces, but ef-fective decision-making in long-horizon set-tings requires reusing prior experience rather than relying solely on the environment ob-servations. Existing memory-based methods typically store experience either at the single-action level or as entire trajectories. Single-step actions are often too fine-grained to carry meaningful semantics, since the success of an individual action does not necessarily imply progress towards the overall goal. In contrast, whole trajectories are often too coarse-grained and difficult to reuse across different tasks. We propose a subgoal-aware memory graph that distils past trajectories into structured, reusable evidence at the level of subgoals. We define a subgoal as consecutive actions shar-ing a single intent, the granularity at which progress toward the task becomes meaning-ful. To reduce redundancy and support cross-task reuse, we organise subgoal experiences as nodes in a graph, where related memories can be merged, extended, and retrieved based on the environment observation. On SPA-Bench, our method improves success rate by 11.11% over the baseline. 

## 1 Introduction 

GUI agents aim to complete complex user goals by interacting with graphical user interfaces, from web pages (Zheng et al., 2024; Deng et al., 2023; Zhou et al., 2024) to mobile phone screens, such as ordering items on a shopping app, setting up an alarm, or navigating settings (Zhang et al., 2025; Wang et al., 2024a; Hong et al., 2024; Rawles et al., 2023, 2025). In benchmarks like SPA-Bench (Chen et al., 2025), a single task can require more than 30 GUI actions across several screens. In such

long-horizon settings, relying solely on the envi-ronment observation is insufficient because many subgoals recur across tasks and apps, and without reusing prior interaction experience, an agent must re-explore the same workflows from scratch (Xie et al., 2025; Zhu et al., 2026). A straightforward solution is to equip the agent with an episodic memory it can query at infer-ence time (Packer et al., 2023; Park et al., 2023). Existing memory-based methods, however, typi-cally store experience either at the single-action level (Xie et al., 2025) or as entire trajectories (Zhu et al., 2026), and both granularities are problematic on mobile GUIs. Single-step actions are too fine-grained to carry semantics on task progress, since whether a tap or swipe “succeeds” locally tells the agent little about whether the overall goal is be-ing approached. Whole trajectories, on the other hand, are too coarse-grained, since a full episode, as stored in representations such as HyMEM (Zhu et al., 2026), is tied to a specific task path, making it rarely reusable across tasks that share intermediate steps but diverge in specifics. We argue for an intermediate abstraction level, namely subgoals , which we define as contiguous sequences of actions that jointly express a coher-ent sub-intent. Unlike raw actions, subgoals re-flect progress toward the goal. As illustrated in Figure 1, the same subgoal can either succeed or fail depending on the underlying behaviour, a dis-tinction that is invisible at the single-action level. Unlike whole trajectories, subgoals transfer natu-rally across related tasks, since many tasks share the same underlying subgoals. Building on this granularity, we organise past ex-perience into a subgoal-level memory graph. Each raw trajectory is first segmented into a chain of subgoals. Rather than storing the full action se-quence, we represent each subgoal as a transition between its boundary visual states (the starting and ending screenshots), annotated with a subgoal de-arXiv:2610.31307v1 [cs.AI] 22 Oct 2026 Figure 1: The same subgoal can succeed (left) or fail (right) depending on the underlying behaviour. scription, a success label, a behaviour summary of the underlying actions, and an effect description obtained by comparing the boundary states. Bound-ary states are then embedded and merged across trajectories when visually similar, so that each sub-goal becomes a directed edge between two shared memory nodes. The resulting graph consolidates reusable visual states and the semantic transitions between them, and can be incrementally extended with new trajectories. On the SPA-Bench (Chen et al., 2025) English single-app level-3 split, our subgoal-aware memory graph achieves an improvement of 11.11% over a memory-free baseline with the same Qwen3-VL-8B-Instruct (Bai et al., 2025) backbone. 

## 2 Related Work 

GUI agents. App agents interpret natural-language goals and operate smartphones through actions such as tapping, scrolling, and text en-try (Rawles et al., 2023, 2025; Wang et al., 2024b; Luo et al., 2025; Beechey et al., 2026). One line of work fine-tunes vision-language models to ob-tain end-to-end GUI agents (Hong et al., 2024; Qin et al., 2025; Tang et al., 2025; Christianos et al., 2024), achieving strong in-distribution accuracy at the cost of substantial training. A complemen-tary line of work keeps the underlying LLM frozen. AppAgent (Zhang et al., 2025) maintains a hand-curated, per-app knowledge base, whereas Mobile-Agent (Wang et al., 2024a) introduces visual per-ception tools to predict actions. Our work targets this frozen-LLM setting, where the agent’s capa-bilities are shaped by what is supplied through its context rather than by weight updates. 

Memory for GUI agents. Memory mechanisms aim to give GUI agents access to relevant past ex-perience at inference time, so that decisions are informed by what worked or failed in earlier roll-outs. Existing memory designs for GUI agents cluster at two representational granularities. GUI-Explorer (Xie et al., 2025) mines per-step (observa-tion, action, outcome) triples through autonomous exploration, and such single-action units carry lit-tle information on task progress, and a memory of them quickly accumulates redundant entries with-out exposing reusable structure. HyMEM (Zhu et al., 2026) organises continuous trajectory em-beddings into a graph and EchoTrail-GUI (Li et al., 2025) retrieves whole successful episodes as in-context demonstrations. However, full trajectories are tied to the path of a single task. Our work tar-gets the intermediate subgoal granularity that these designs leave underexplored. Subgoals are contigu-ous action segments that mark progress toward task completion and recur across different tasks. We organise them in a graph whose nodes are shared visual states, rather than per-task or per-action en-tries. 

## 3 Method 

Our goal is to equip a GUI agent with a memory that distils past interaction experience into reusable, subgoal-level guidance. ternating between GUI screenshots si and executed actions ai. Given a corpus T = {τ1, . . . , τ m} of such trajectories, we construct a memory graph 

M that the agent can query during task execution: given the environment screenshot sq, the memory returns a small set of subgoal-level guidance items that are appended to the agent’s prompt. We in-stantiate M as a directed graph whose nodes corre-spond to clusters of visually similar GUI states and whose edges encode subgoals observed in past tra-jectories, each edge connecting the state at which a subgoal began to the state at which it ended. The construction and retrieval pipeline comprise three stages: subgoal extraction (Section 3.1), graph con-struction (Section 3.2), and memory retrieval (Sec-tion 3.3). 

3.1 Subgoal Extraction and Annotation Segmentation. We segment each trajectory into a chain of subgoals , where a subgoal spans one or more consecutive actions that jointly realise a coherent sub-intent, for example, “open the search bar and submit a query” or “add the selected pair of sunglasses to the basket” . Segmentation is per-formed by an LLM that takes the full action se-quence as input and returns segment boundaries. We keep the first and last screenshots of each seg-ment as its visual anchors and discard the interme-diate frames, as the boundary screenshots already capture the start and end states relevant for down-stream retrieval. 

Subgoal metadata. Each extracted subgoal g ∈G is represented as a typed tuple 

g = ⟨ sfrom , s to ;

text , effect , behaviour , success ⟩

whose fields are populated as follows. • sfrom , s to : the boundary screenshots, used as visual anchors during graph construction. • text : a natural-language summary of the sub-goal’s intent. • effect : a one-sentence description of the ob-served visual change from sfrom to sto .• behaviour : a concise summary of the under-lying action sequence, highlighting the domi-nant interaction pattern. • success ∈ { yes , no , uncertain }: a subgoal-level success label assigned by an LLM judge. 

3.2 Subgoal-aware Memory Graph Construction 

Given the annotated subgoals from Section 3.1, we now organise them into a persistent, queryable memory structure. The goal is to support behaviour reuse across tasks: when the agent encounters a state it has seen before, it should be able to retrieve which subgoals were previously attempted from that state, whether they succeeded, and through what action behaviour. We cast this as a directed graph whose nodes are GUI states and whose edges are subgoal transitions. Construction proceeds as follows: (1) merging visually similar screenshots into shared nodes so that experience accumulates rather than fragments; (2) attaching each subgoal as a directed edge carrying its full annotation; and (3) deduplicating redundant edges within each node to keep the graph compact. 

Environment state merging. We map the bound-ary screenshots of each annotated subgoal, sfrom 

and sto , into a shared memory-node space accord-ing to visual similarity. For each such screenshot s,we compute its image embedding and compare it against the existing memory nodes. If the nearest node mj satisfies cos( s, m j ) ≥ τ , where cos( ·, ·)

denotes cosine similarity between image embed-dings, the screenshot is absorbed into mj . Other-wise, a new memory node is instantiated. Each node maintains its constituent screenshots together with a running mean embedding used for subse-quent matching. 

Directed subgoal edges. After environment state merging, each annotated subgoal becomes a di-rected edge from its source memory node to its target memory node. The edge stores the subgoal intent, the observed visual effect between the end-point screenshots, the success label, and the be-haviour pattern of the executed action sequence. Crucially, the graph preserves both successful and failed attempts from each state, so retrieval can later provide failed alongside successful examples. 

Build-time deduplication. To keep the mem-ory compact as more trajectories are added, we remove repeated outgoing subgoals within each source node. Two outgoing subgoals are treated as duplicates only when they point to the same target node, carry the same success label, and describe the same intent, i.e., the cosine similarity between text embeddings of their intent descriptions exceeds θ.When a duplicate is detected, the later edge is dis-carded. Subgoals that differ in target, outcome, or intent are kept as separate evidence. 

3.3 Memory Retrieval 

At each decision step, retrieval is triggered with the current screenshot sq. We embed sq and compare it against the embedding maintained at each memory node, and keep the top-k nearest nodes by cosine similarity. For each retrieved node, we collect all of its outgoing subgoal edges, and both successful and failed subgoals are returned, each tagged with its outcome, so that the agent can avoid known failure modes as well as imitate known successes. The retrieved subgoals are then formatted into a short memory block and added to the agent’s prompt.

Table 1 reports the per-attempt success rate (SR), averaged over three independent runs. With the same backbone and setup, our subgoal-graph mem-ory improves success by 11.11% over the memory-free baseline, suggesting that retrieving past ex-perience is useful for long-horizon mobile tasks. Moreover, neither action-level nor task-level mem-ory yields meaningful gains over the baseline. We further ablate the graph structure by re-placing it with a flat memory store, where sub-goals from different environments are not organised through shared visual-state nodes. This reduces SR to 30.77%. We argue that the graph structure allows redundant memories to be merged across trajectories, keeping the retrieved context precise. 

## 5 Conclusion 

We proposed a subgoal-aware memory graph for mobile GUI agents. The core idea is to store past experience at the level of subgoals, rather than raw actions or whole trajectories. To make these sub-goals reusable across trajectories, we fuse visu-ally similar environment states into shared memory nodes and attach subgoal transitions between them. This allows the agent to see what has been tried from similar states and what outcome each subgoal produced. At inference time, the agent retrieves subgoals from the graph and uses them as guidance for the current task. This provides a simple and practical memory structure for mobile interaction. Limitations 

Our method assumes that GUI environments can be approximated by a discrete state space, such that screenshots can be meaningfully clustered into a compact set of shared memory nodes. This assump-tion is reasonable for typical mobile applications with relatively stable layouts, but becomes limited in highly dynamic interfaces, such as video play-ers, where consecutive states change continuously, and visual similarity is a noisier proxy for semantic equivalence.
