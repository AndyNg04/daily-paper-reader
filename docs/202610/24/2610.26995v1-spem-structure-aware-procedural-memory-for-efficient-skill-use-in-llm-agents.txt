# SPEM: Structure-Aware Procedural Memory for Efficient Skill Use in LLM Agents 

## Ran Zhou, Zehui Kong, Fanyu Lin, Jiaheng Liu, Zhen Zhang, Yuxiang Ren ∗

School of Intelligence Science and Technology, Nanjing University Correspondence: renyuxiang@nju.edu.cn 

Abstract 

LLM-based agents increasingly rely on reusable skills. How-ever, scaling skill libraries makes efficient and accurate skill use difficult. Full skill loading incurs high token and run-time overhead. In contrast, flat semantic retrieval treats skills as independent text entries, ignoring dependencies, execution order, state transitions, and data-flow constraints. We pro-pose SPEM, a lightweight structure-aware procedural mem-ory framework for efficient skill use in LLM-based agents. SPEM maintains Atomic Skill Memory for individual skills and Skill-DAG Memory for reusable compositions derived from successful executions. For a new task, SPEM reuses high-confidence Skill-DAG templates when available. Oth-erwise, it retrieves atomic skills and invokes Skill-GNN for state- and structure-aware skill selection. Successful execu-tions are written back as new Skill-DAGs, allowing procedural memory to accumulate over time. Experiments on ALFWorld and SkillsBench show that SPEM achieves the best overall effectiveness–efficiency trade-off, reaching 87.1% ALFWorld success and 38.38% SkillsBench reward while reducing token and runtime costs against strong baselines. 

## Introduction 

Large language model (LLM) agents are increasingly used as executable systems. They call tools, reuse skills, and in-teract with complex environments. In software engineering, data analysis, web automation, and embodied tasks, agents rely on reusable skills, such as file parsing, preprocessing, and API calling (Schick et al. 2023; Mialon et al. 2023; Yao et al. 2023). As skill libraries scale to hundreds or thousands of candidates, the central challenge changes. It shifts from whether useful skills exist to how an agent can retrieve, or-ganize, and reuse the required skills efficiently (Patil et al. 2023; Qin et al. 2024; Shi et al. 2025). Existing approaches face four limitations under large-scale skill libraries. First, loading all skill descriptions is infeasible due to high token cost, context bloat, and runtime overhead, with important details often lost in long contexts (Liu et al. 2024a). Second, flat retrieval optimizes semantic relevance but ignores structural dependencies like prerequisites, order, state transitions, and data flow across skills (Lewis et al. 2020; Karpukhin et al. 2020). Third, successful composi-tions are not stored as reusable procedural memory. Even

Finally, as agent systems are deployed more frequently and model capabili-ties continue to improve, efficiency becomes a primary con-cern. Repeated model invocations for retrieval, planning, and reorganization incur unnecessary token consumption, latency, and computational overhead. These limitations call for a framework that can retrieve skills compactly, organize them structurally, and accumulate reusable procedural mem-ory over time. We therefore study efficient skill use under large-scale skill libraries. Our goal is to improve task success while reducing token cost, runtime overhead, and repeated skill organiza-tion. To this end, we propose SPEM, a lightweight structure-aware procedural memory framework. SPEM maintains two complementary memory layers. Atomic Skill Memory rep-resents individual executable skills with their semantic, in-terface, and feedback signals. Skill-DAG Memory stores reusable skill compositions distilled from successful exe-cutions. Given a new task, SPEM first retrieves relevant pro-cedural memory and reuses a high-confidence Skill-DAG template when available. Otherwise, or when the current guidance becomes insufficient, Skill-GNN constructs a task-conditioned candidate graph. It then performs state-aware skill selection over retrieved atomic skills. After execution, successful trajectories are compressed into Skill-DAGs and written back to memory for future reuse. We evaluate SPEM on SkillsBench and ALFWorld (Li et al. 2026b; Shridhar et al. 2021). SkillsBench tests large-scale skill retrieval and technical task execution. ALFWorld evaluates long-horizon dependencies, structured skill use, and cross-task reuse in interactive environments. We com-pare SPEM with full skill loading, flat vector retrieval, and graph-based skill selection baselines. Our contributions are fourfold: 

• We propose SPEM, a dual-layer procedural memory framework that combines Atomic Skill Memory for fine-grained skill access with Skill-DAG Memory for reusable procedural structures. 

• We design a Skill-GNN module for state-aware skill se-lection over task-conditioned candidate graphs. 

• We introduce trajectory-DAG extraction to distill suc-arXiv:2610.26995v1 [cs.AI] 19 Oct 2026 cessful executions into reusable Skill-DAG templates and update procedural memory through execution feedback. 

• We evaluate SPEM on ALFWorld and SkillsBench, achieving 87.1% ALFWorld success and 38.38% Skills-Bench reward while reducing token and runtime costs over strong structure-aware baselines. 

## Related Work 

From Tool Calling to Large-Scale Skill Retrieval. Early tool-augmented language models focused on tool invoca-tion, argument generation, and reasoning with returned re-sults. Pioneering works like ReAct, Toolformer, and surveys established the paradigm via reasoning-action interleaving, self-supervised learning, and systematic analysis (Yao et al. 2023; Schick et al. 2023; Mialon et al. 2023). As external ca-pabilities grow from a few tools to large API or skill libraries, retrieval becomes essential. Gorilla, API-Bank, ToolBench, ToolLLM, and related methods reduce context overhead and calling errors through documentation retrieval, embed-ding, hierarchical search, task-specific construction, or query rewriting (Patil et al. 2023; Li et al. 2023; Xu et al. 2023; Qin et al. 2024; Hao et al. 2023; Du, Wei, and Zhang 2024; Yuan et al. 2023; Chen et al. 2024). However, most retrieval methods still treat capabilities as independent textual entries. They mainly optimize semantic relevance. Skill retrieval is harder due to procedural knowledge, execution conditions, input-output constraints, and task experience. Benchmarks like SkillsBench and SWE-Skills-Bench show that excessive or mismatched skills increase context cost and can hurt per-formance (Li et al. 2026b; Han et al. 2026). Thus, large-scale skill use demands compact, relevant, and executable selec-tion, not just semantic similarity. 

From Structured Skills to Evolving Procedural Memory. 

As skills become reusable assets, recent work organizes them with explicit structures. SkillNet represents skills through a unified ontology and relation network. AgentSkillOS man-ages skills through classification, retrieval, capability trees, and dynamic skill management (Liang et al. 2026; Li et al. 2026a). Graph-based methods further model relations among tools or skills. ToolNet supports graph navigation over large tool collections; Graph of Skills retrieves dependency-aware skill bundles from a skill dependency graph; and GraSP con-structs DAG-style skill structures with precondition and ef-fect relations for long-horizon tasks (Liu et al. 2024b, 2026; Xia et al. 2026). These methods show that explicit structures help recover dependencies and execution relations. However, many of them use structure mainly for the current task or as a static organization layer. They give limited attention to how successful executions should be distilled, updated, and reused as evolving procedural memory. SPEM instead converts suc-cessful trajectories into reusable Skill-DAG templates and updates their reliability through execution feedback. 

Lightweight Skill Retrieval and Selection. Large-scale skill use imposes constraints on context, latency, and com-putation. Recent work explores lightweight skill routing, representation, and reuse. SkillRouter uses compact mod-els for recall-then-rerank selection over large skill sets. For-mal Skill replaces verbose Markdown descriptions with ex-ecutable skill structures. CUA-Skill encapsulates GUI op-eration knowledge into reusable skills for dynamic retrieval and parameter instantiation (Zheng et al. 2026; Zhang et al. 2026; Chen et al. 2026). Other methods emphasize reusable experience. ProcMEM converts interaction experience into procedural memories. SkillDAG maintains typed relations among skills and evolves across episodes. Compositional Skill Routing retrieves skills for decomposed subtasks and composes them with a dependency-aware DAG planner (Mi et al. 2026; Bai et al. 2026; Gao 2026). These studies show that lightweight skill use is not merely reducing retrieved skills, but jointly concerns compact representation, efficient selection, execution constraints, and experience reuse. SPEM addresses this gap through a unified procedural memory framework that combines bounded atomic retrieval, reusable Skill-DAG Memory, and Skill-GNN organization. 

## Method 

Given a task request and a large-scale skill library, SPEM provides compact, executable skill guidance through two memory layers: Atomic Skill Memory for individual skills and Skill-DAG Memory for reusable compositions distilled from successful executions. As shown in Figure 1, SPEM reuses a matched Skill-DAG template when available. Oth-erwise it retrieves atomic skills and invokes Skill-GNN for state-aware reranking when needed. Successful executions are written back as new Skill-DAGs. This enables procedu-ral memory to accumulate over time. The full protocol is provided in Section A.1 of the supplementary material. 

Dual-Layer Procedural Memory 

SPEM separates procedural knowledge into two complemen-tary memory layers. Atomic Skill Memory supports fine-grained access to individual skills, while Skill-DAG Memory supports direct reuse of successful skill compositions. The supplementary material provides the full schema and update rules in Section A.2.

Procedural Memory Retrieval. Given a task request q,SPEM first searches Skill-DAG Memory for reusable tem-plates: 

Cd(q) = {Gj ∈ M d | sim( eq , e j ) ≥ τ }, (5) where eq is the task embedding and τ is the template match-ing threshold. If Cd(q) is non-empty, the highest-scoring Skill-DAG is injected as structured procedural guidance. If no template satisfies the threshold, SPEM retrieves a bounded set of atomic candidates:

This retrieval strat-egy avoids full-library loading while preserving two comple-mentary modes of reuse: direct reuse of successful Skill-DAG templates and flexible organization of atomic skills for novel task states. 

Structure-Aware Skill Selection with Skill-GNN 

When reusable templates are unavailable or insufficient for the current execution context, SPEM uses Skill-GNN to per-form structure-aware ranking and selection over retrieved atomic candidates. The goal is to identify semantically rel-evant skills. It also aims to select skills that are compatible with the task state and dependency relations among candi-dates. 

Candidate Skill Graph Construction. Given a task re-quest q, retrieved atomic candidates Ca(q), and the current execution context, SPEM constructs a task-conditioned can-didate graph 

Gq = ( Vq , Eq , R), (7) where Vq contains task, context, and candidate skill nodes. 

Eq contains typed edges, and R denotes relation types. Skill-node features combine semantic embeddings with lightweight execution feedback. Task and context nodes en-code the request, current state, and execution history. Edges connect task–skill, context–skill, and skill–skill pairs, captur-ing relevance, state compatibility, semantic relatedness, and available dependency cues. Additional construction details are provided in Section A.5 of the supplementary material.

Cold-Start Deployment. SPEM supports both trajectory-rich and trajectory-scarce deployment settings. When target-domain trajectories are available, Skill-GNN is trained with trajectory-prefix supervision, where each prefix defines the current procedural state and the next executed skill is used as the target. When trajectories are scarce or unavailable, SPEM uses a library-level warm start constructed only from the skill library: 

eD0 = {(˜ qi, s i)}si∈M a , (10)

This initialization uses no task outcomes, verifier rewards, or evaluation trajectories. During early deployment, Atomic Skill Memory retrieval and available Skill-DAG templates provide the primary guidance, while the warm-started Skill-GNN is used only for bounded reranking. As successful exe-cutions accumulate, trajectory-DAG extraction converts them into new Skill-DAG templates and trajectory-prefix training samples, gradually adapting the system from retrieval-only guidance to state-aware graph selection. Since Skill-GNN is inductive over dynamically constructed candidate graphs, it can generalize to unseen tasks, unseen skill combinations, and newly extracted Skill-DAG variants. Additional protocol and leakage-prevention details are provided in Section A.4 of the supplementary material.

## Experiments 

Experimental Setup 

Benchmarks. We evaluate SPEM on two complementary skill-use benchmarks. ALFWorld (Shridhar et al. 2021) is an interactive text-based embodied environment. It requires multi-step household task completion, testing long-horizon dependencies, state transitions, and procedural reuse. Skills-Bench (Li et al. 2026b) evaluates technical agent tasks with large skill libraries. It tests whether agents can retrieve and apply task-relevant skills under limited context budgets. 

Metrics. For ALFWorld, we report Success, Steps, Tokens, and Runtime. Success ( ↑) is the task success rate within the maximum step budget. Steps ( ↓) is the average number of environment interactions. Tokens ( ↓) is the average token consumption during agent execution, and Runtime ( ↓) is the average agent-only execution time. For SkillsBench, we report verifier reward R (↑), average input tokens T (↓), and agent-only runtime S (↓). Follow-ing the benchmark protocol, R is determined by the official verifier. For fair accounting, S measures the agent execution phase and excludes environment setup, dependency instal-lation, Docker build time, and verifier runtime. For SPEM, online skill retrieval or reranking invoked during execution is included in the measured agent phase. 

Baselines. We compare SPEM with four baselines that form a controlled progression in skill access and structure awareness. Vanilla Skills loads the full skill library, testing whether exhaustive context alone is sufficient. Vector Skills 

retrieves top-k skills by embedding similarity, isolating the effect of flat semantic retrieval. GoS serves as a representa-tive static graph-retrieval method, using a prebuilt skill graph to retrieve structurally related skills. SkillDAG serves as a re-cent sota baseline for dependency-aware skill selection with a self-evolving graph structure. SPEM (Ours) further intro-duces dual-layer procedural memory, trajectory-DAG extrac-tion, and on-demand Skill-GNN reranking. These baselines allow us to distinguish gains from more context, semantic retrieval, static graph structure, typed graph selection, and reusable procedural memory. 

Implementation Details. For fair comparison, all methods use the same benchmark splits, skill libraries, agent inter-face, execution environment, and verification protocol. We evaluate with two backbone LLMs, MiniMax-M2.7 (Mini-Max 2026) and GPT-5.2-Codex (OpenAI 2025), representing weaker and stronger model settings. On ALFWorld , we use the dev split with 140 episodes and set the maximum number of environment steps to 30. All skill-based methods use the same library of 37 

alfworld-* skills. SPEM builds Atomic Skill Memory from this library, constructs Skill-DAG Memory only from successful non-evaluation trajectories, and trains Skill-GNN with trajectory-prefix supervision under disjoint training and evaluation instances. On SkillsBench , we follow the GoS execution setting with Docker-based environments, Harbor agent execution, verifier-based evaluation, at most two attempts per task, and two concurrent trials. Following the benchmark convention, tasks that remain unresolved due to infrastructure failures after the allowed retries are excluded rather than counted as model failures, leaving the same 67 valid model tasks for all methods. All methods use the same skills_200 

skill library. SPEM builds Atomic Skill Memory from the same library and applies library-level warm start plus Skill-GNN reranking. Detailed hyperparameters, leakage-prevention rules, retry handling, and additional inference de-tails are provided in Section B of the supplementary material. 

Main Results 

Overall effectiveness–efficiency trade-off. Table 1 shows that SPEM achieves the best overall trade-off across both benchmarks and backbone models. On ALFWorld, SPEM obtains the highest success rate under both MiniMax-M2.7 and GPT-5.2-Codex, improving over GoS by 2.1 and 1.8 per-centage points, respectively, while also achieving the low-est runtime. On SkillsBench, SPEM achieves the best re-ward with GPT-5.2-Codex and the second-best reward with MiniMax-M2.7, where SkillDAG obtains a higher reward but requires substantially more tokens and runtime. In particu-lar, compared with SkillDAG under MiniMax-M2.7, SPEM reduces input tokens by 26.3% and runtime by 24.3%, while remaining competitive in reward. 

Efficiency becomes more important with stronger models. 

As the backbone model becomes stronger, structure-aware baselines such as GoS and SkillDAG also obtain competitive rewards, especially on SkillsBench. This makes efficiency a critical differentiator rather than a secondary metric. Under GPT-5.2-Codex, SPEM improves SkillsBench reward over GoS from 37.50% to 38.38%, while reducing input tokens by 15.7% and runtime by 12.3%. On ALFWorld, SkillDAG achieves fewer steps, but it incurs much higher token and run-time costs. In contrast, SPEM maintains the highest success rate with much lower execution overhead, suggesting that reusable procedural memory is most useful when it provides compact guidance rather than longer plans or larger context.

Analysis of DAG-Template Effectiveness 

We analyze whether the extracted Skill-DAGs are both com-pact and useful. As shown in Figure 3(a), trajectory-DAG extraction compresses successful trajectories from 13.4 av-erage steps to 6.0 backbone steps, pruning 54.9% of opera-tions while preserving the executable core. This preliminarily demonstrates the compression effect of DAG templates. We then evaluate the availability and effectiveness of DAG tem-plates. As shown in Table 2, on ALFWorld, SPEM achieves template hit rates of 56.43% and 60.71% under MiniMax-M2.7 and GPT-5.2-Codex, respectively. Among template-hit tasks, the success rates are 74.68% and 85.88%, respectively. These results indicate that DAG templates can accumulate reusable procedural structures for later tasks. Unlike ALF-World, SkillsBench contains highly heterogeneous technical tasks, where exact procedural-template reuse is naturally lim-ited. Therefore, we mainly use SkillsBench to evaluate large-scale atomic-skill retrieval and structure-aware reranking, and use ALFWorld to analyze Skill-DAG template reuse. Fi-nally, we conduct an exact-template analysis on ALFWorld. This isolates the effect of a correct DAG skeleton itself. For each successfully completed task, we extract its trajec-tory and directly provide the DAG when re-executing that task. This setting tests whether DAG templates can improve execution efficiency. As shown in Figure 3(b), exact-DAG guidance preserves success on all evaluated tasks while re-ducing average steps from 11.42 to 6.26, token consumption from 23.77K to 11.93K, and runtime from 28.01s to 20.88s, corresponding to reductions of 45.2%, 49.8%, and 25.5%, respectively. This suggests that templates provide effective procedural guidance for improving task efficiency.

• DAG extraction makes procedural memory compact. Re-placing extracted Skill-DAG backbones with complete ex-ecution traces lowers success to 63.0%. It also increases token and runtime cost, because full traces contain redun-dant exploration and environment-specific details. 

• The full SPEM achieves the best results across all met-rics. This demonstrates that reusable Skill-DAG tem-plates, structure-aware skill selection, and compact tra-jectory extraction are complementary. 

Scalability to Larger Skill Libraries. Figures 3(c) and (d) further examine whether structure-aware skill selection remains effective as the skill library grows. Retrieval-only selection degrades rapidly when the library size increases, especially at 1000 and 2000 skills, where semantic similar-ity alone struggles to rank the required skills near the top. In contrast, Skill-GNN consistently achieves higher Hit@K, Recall@K, and MRR across all library sizes. For example, at 2000 skills, Skill-GNN improves Hit@1 from 0.0 to 0.51 and MRR from 0.112 to 0.573 over retrieval-only selection. Although both methods become harder to rank as the candi-date pool expands, the gap remains substantial, showing that graph-based contextualization helps preserve reliable skill selection under large-scale skill libraries. Additional backbone comparisons and hyperparameter sensitivity analyses can be found in Section C of the sup-plementary material. 

## Conclusion 

We presented SPEM, a reusable and structure-aware skill memory framework for LLM-based agents. Instead of treat-ing skills as a flat prompt collection, SPEM organizes them into Atomic Skill Memory for individual capabilities and Skill-DAG Memory for reusable procedural structures. Skill-GNN further enables state-conditioned skill selection over dynamically constructed candidate graphs, allowing the agent to adapt its guidance during execution while remain-ing inductive to new tasks and skill combinations. Experi-ments on ALFWorld and SkillsBench show that SPEM im-proves both task effectiveness and execution efficiency across weaker and stronger backbone models. The results suggest that effective skill use requires more than semantic retrieval. Agents benefit from compact procedural guidance that cap-tures both which skills are relevant and how they should be composed. Although current performance still depends on retrieval quality and the agent’s ability to execute retrieved guidance, SPEM provides a practical step toward scalable, adaptive, and reusable skill memory for LLM-based agents.
