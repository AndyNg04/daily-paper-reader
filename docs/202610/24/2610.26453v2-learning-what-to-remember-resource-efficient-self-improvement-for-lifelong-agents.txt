## Abstract 

Self-improving agents aim to continuously improve their behavior by learning from experience after deployment. However, accumulating and reusing more experi-ence does not necessarily lead to better decisions, particularly when generation, interaction, and memory resources are jointly constrained. Under such stringent constraints, we find that several existing lifelong-memory methods provide limited benefits over simple retrieval or even no-memory agents. This reveals a funda-mental challenge for resource-efficient self-improvement: agents must learn not only which past experiences are relevant, but which are actually worth reusing to improve future decisions. When memory capacity and opportunities for reasoning and recovery are limited, retrieving an ineffective experience can consume scarce resources and hinder downstream execution. To address this challenge, we propose 

TokenWorth , a lightweight feedback-driven memory adaptation framework that learns query-dependent memory worth from sparse execution feedback. Without updating the backbone model, TokenWorth uses the learned worth to guide both experience retrieval and bounded memory management, enabling the agent to continually adapt how it reuses accumulated experience. Across three LifelongA-gentBench environments and both local and API-based deployments, TokenWorth achieves the highest task success rate while using the fewest output tokens among the evaluated methods under the specified resource budgets. These results suggest that effective self-improvement under resource constraints depends not on accumu-lating more experience, but on learning what is worth remembering. Our code is publicly available at https://github.com/AIGNLAI/TokenWorth .

## 1 Introduction 

Self-improving agents continually accumulate and reuse experience from evolving task streams to improve their behavior after deployment [35]. Such experience-driven adaptation is particularly valuable for long-running agents facing evolving user needs, environments, and tasks [4, 6, 16]. However, accumulating more experience does not necessarily translate into better decisions. In practice, generation is constrained by latency, computation, or inference cost; interaction opportunities are finite; and only a bounded amount of historical experience can be stored or reused [8, 11, 29]. This raises a fundamental question: how can agents effectively improve from experience when generation, interaction, and memory resources are jointly constrained? 

Our evaluation reveals that existing memory mechanisms often struggle under such constraints. As shown in Figure 1(a), several sophisticated lifelong-memory approaches provide limited improve-ment over simple retrieval or even no-memory agents, and can substantially underperform in some environments. To study this challenge systematically, we formalize resource-constrained lifelong agents : agents that must continually adapt from experience while operating under bounded generation, interaction, and memory budgets. As illustrated in Figure 1(b), we jointly constrain the resources available for task execution and experience reuse. Specifically, the agent operates with a bounded output budget and limited interaction rounds, while its external memory is constrained in capacity, retrieval count, and injection length. The backbone remains frozen throughout the task stream, allowing us to study experience-driven adaptation under a controlled, stringent resource budget. Why does experience-based adaptation become fragile under such constraints? When only a small amount of experience can be retained or reused, and opportunities for reasoning and recovery are limited, each memory decision becomes more consequential. Semantic relevance alone may be insufficient: an experience can appear relevant to the current query yet provide little downstream utility. Conversely, useful experience that is not retained or selected cannot be recovered by simply injecting more context or extending the interaction. Resource scarcity therefore exposes a fundamental distinction between accumulating experience and effectively learning from it. The central challenge is not merely to retrieve relevant experience, but to determine which experiences are actually worth 

retaining and reusing to improve future decisions. To address this challenge, we propose TokenWorth , a lightweight feedback-driven memory adap-tation framework that learns query-dependent memory worth from sparse execution feedback. To-kenWorth combines an interpretable online base scorer with a residual Recursive Feature Machine (RFM), allowing stable global patterns of memory usefulness to be complemented by nonlinear, query-specific corrections. The learned worth guides both memory retrieval and bounded memory-bank management, enabling the agent to continually adapt its experience-reuse policy without backbone updates or additional language-model calls. We evaluate TokenWorth on three LifelongAgentBench environments covering database interaction, operating-system tasks, and knowledge-graph reasoning, under both local and API-based deployments. Across all six environment–deployment combinations, TokenWorth achieves the highest task success rate among the evaluated methods while using the fewest output tokens. These results suggest that resource-efficient adaptation depends not on accumulating more experience, but on learning what is worth remembering. Our contributions are threefold: • We formulate resource-constrained lifelong agents and investigate experience-driven adaptation under stringent joint constraints on generation, interaction, and memory. 2• We propose TokenWorth , a lightweight online framework that learns query-dependent memory worth from execution feedback and uses it consistently for memory retrieval and bounded memory management. • We evaluate TokenWorth across three LifelongAgentBench environments under both local and API-based deployments, demonstrating improved task success and generation efficiency under stringent resource constraints. 

## 2 Related Work 

Experience-Driven Self-Improvement in Language Agents. Self-improving language agents aim to continually improve from accumulated interaction experience, enabling adaptation after deployment without necessarily updating backbone parameters [6, 35]. Early agent systems demonstrated that past trajectories, reflections, or reusable skills can improve future decisions, including Reflexion [19], ExpeL [33], Voyager [24], and SocioDojo [4]. More recent work has developed explicit memory and skill mechanisms for continual adaptation, such as MemoryBank [37], Mem0 [5], MemRL [32], MemSkill [30], and AutoSkill [27]. Meanwhile, LifelongAgentBench [34], AgentCL [21], Skill-LearnBench [36], and XSkill [10] provide systematic evaluations of experience-driven adaptation. While these studies explore how agents accumulate and exploit experience, we investigate how agents can learn which experiences are worth reusing to support effective adaptation under stringent resource constraints. 

Resource-Constrained Agent Adaptation. Resource efficiency has been extensively studied for LLM inference and serving, including memory-efficient execution [11] and collaborative inference under computation and communication constraints [29]. Recent work has extended resource consider-ations to agent adaptation. Hajimiri et al. [9] study whether online memory and skill modules remain beneficial under fixed inference-token budgets, while Wu et al. [25] investigate continual learning with hard-bounded on-device memory. BudgetMem [31] considers query-aware routing across runtime memory budgets, and Chen and Cheng [3] model agentic memory value using multiple factors for retention and retrieval. These studies highlight the importance of resource-aware experience reuse, but primarily focus on individual constraints, runtime budgeting, or memory valuation in isolation. In contrast, we study experience-driven self-improvement under stringent joint constraints on generation, interaction, and memory. We propose TokenWorth , which learns query-dependent memory worth from online execution feedback to guide both retrieval and bounded memory management, enabling continual adaptation without backbone updates.

## 4 TokenWorth: Feedback-Driven Memory Adaptation 

4.1 Overview 

Figure 2 illustrates the feedback-driven adaptation process of TokenWorth . Given a query qt, the agent first recalls a small candidate set from its bounded memory bank. TokenWorth estimates the query-dependent worth of each candidate using a learnable linear base scorer and an RFM-based residual correction, selecting the highest-valued experience for task execution. After receiving the environment reward, the worth model is updated online, and the learned worth further guides memory-bank management. Through this feedback loop, the agent continually adapts how past experience influences future decisions without updating its backbone. TokenWorth consists of three components. First, an interpretable linear scorer captures stable memory-utility patterns, while a residual Recursive Feature Machine (RFM) models nonlinear, query-specific corrections [2, 18]. Second, fast value updates and slower AGOP-based feature adaptation balance stability and adaptivity under sparse feedback. Third, learned worth guides both retrieval and bounded memory management. 

4.2 Learning Query-Dependent Memory Worth 

Effective experience-driven adaptation requires identifying which past experiences are worth reusing for future decisions. Unlike a fixed memory-utility score, the usefulness of an experience depends on the current query and must be inferred from sparse execution feedback. Each task is executed only once, feedback is observed only for the memory actually used, and execution failure may arise from factors beyond the selected memory itself. To balance stability and adaptivity under such feedback, TokenWorth decomposes memory worth into two complementary components. A lightweight linear base scorer captures stable and interpretable patterns across the task stream, while an RFM learns nonlinear residual structure not captured by the base scorer. The linear component is updated conservatively around an informative prior, whereas the RFM adapts more flexibly to local query–memory interactions. 4TokenWorth

Learning which memory to use for the current query addresses only part of experience-driven adapta-tion. Under a bounded persistent capacity Bmax , the agent must also determine which experiences deserve to remain available for future tasks. TokenWorth therefore extends the same query-dependent notion of worth from immediate retrieval to long-term memory management. Only successful, externally verified interactions are considered as new memory candidates. For a candidate memory m, we estimate its broader worth over a small set of recent probe queries Pt:

TokenWorth follows a coverage–quality principle for memory admission. When capacity remains available, successful experiences are admitted to build initial coverage. Once the bank is full, a candidate is admitted if it is sufficiently novel, or if its probe-averaged worth exceeds that of the best existing memory and satisfies a positive-score ratio criterion. Candidates failing this admission gate may still replace a low-utility nearest neighbor when they provide a sufficiently large worth improvement. Detailed admission and replacement criteria are provided in Appendix B. This feedback-driven memory lifecycle continually reallocates limited capacity toward experiences estimated to be useful for future tasks, allowing the agent to adapt its experience-reuse policy over time. All adaptation occurs within the lightweight memory controller; TokenWorth requires no backbone updates, task replay, counterfactual execution, or additional language-model calls. 

## 5 Experiments 

5.1 Experimental Setup Benchmarks. We conduct our main evaluation on three environments from LifelongAgentBench [34]: database interaction (DB), operating-system interaction (OS), and knowledge-graph interaction (KG). These environments cover heterogeneous forms of interactive decision making under an online lifelong protocol, where agents can continually adapt their experience-reuse policies based on preceding interactions. In all environments, the memory bank is initialized empty, each task is executed once, and memory decisions depend only on experience observed from previous tasks. We additionally evaluate generalization beyond LifelongAgentBench using online lifelong variants of BigCodeBench [38] and ALFWorld [20]. These results are reported in Appendix C. 

Backbone and deployment. We evaluate TokenWorth under two complementary deployment settings. In the local setting, all methods use Qwen2.5-14B-Instruct [17] as the frozen backbone, where generation and interaction are constrained by computation and latency. In the API-based 

setting, all methods use DeepSeek-V4-Flash [26] through an external API, where model generation and repeated interaction directly incur inference cost. The backbone remains frozen throughout evaluation, so adaptation occurs solely through external memory mechanisms. 

Resource-constrained protocol. Following Sec. 3, we evaluate all methods under a stringent joint resource budget that constrains generation, interaction, persistent memory capacity, and memory injection. ## 6 Conclusion 

We study experience-driven adaptation in lifelong agents under joint constraints on generation, inter-action, and memory. We propose TokenWorth , a lightweight feedback-driven memory adaptation framework that learns query-dependent memory worth from online execution feedback and uses it for retrieval and bounded memory management. Across three LifelongAgentBench environments and local and API-based backbones, TokenWorth achieves the highest task success rates among evaluated methods while using the fewest output tokens. Additional experiments show competitive performance on coding and embodied-agent tasks. These results suggest that resource-efficient self-improvement depends not on accumulating more experience, but on learning what is worth remembering. Since feedback is observed only for selected memories, their causal contributions remain unidentified. Developing budget-efficient credit assignment remains an important direction for future work. 9Acknowledgments and Disclosure of Funding

A.1 Benchmarks 

Our main experiments use three environments from LifelongAgentBench [34]: database interaction (DB), operating-system interaction (OS), and knowledge-graph interaction (KG). Tasks are processed sequentially, and only experience from preceding tasks may be reused. DB requires structured database operations and answers grounded in retrieved observations. OS requires multi-step system management through Bash commands. KG follows an AgentBench-style protocol in which the agent interacts with a knowledge graph through structured tool calls, while SPARQL queries are executed by the backend. The environments thus cover heterogeneous forms of interactive decision making under a shared online lifelong-learning protocol. We additionally evaluate online lifelong variants of BigCodeBench [38] and ALFWorld [20]; their results are reported in Appendix C. Beyond language agents, class-incremental learning has examined the impact of task ordering on continual adaptation [12] and the variability of performance across evaluation sequences [14]. These studies highlight the importance of evaluation protocols in continual learning, while our experiments focus on online memory adaptation under fixed resource budgets. 

A.2 Baselines 

We compare TokenWorth with a no-memory agent (Standard), retrieval-augmented generation (RAG), and representative memory- and skill-learning methods. 

Standard. The frozen backbone solves every task independently, without persistent cross-task memory. 

RAG. RAG [15, 22, 23] stores successful experiences and retrieves them by lightweight textual relevance, without online value learning. 

MemRL. MemRL [32] uses execution feedback to learn utility signals for episodic memories, serving as a value-aware baseline. 

Mem0. Mem0 [5] supports memory extraction, storage, retrieval, and update in long-running agents. 

MemP. MemP [7] retains procedural task experience for later reuse. 

MemSkill. MemSkill [30] converts experience into reusable memory skills and evolves them online. 

Reflexion. Reflexion [19] stores verbal reflections derived from task feedback for reuse in subse-quent tasks. 

EvoSC. EvoSC [28] consolidates and evolves agent experience. 

EvoSkill. EvoSkill [1] extracts reusable skills from interaction trajectories and updates its skill repository. Within each environment and deployment setting, methods share the same task sequence, backbone, environment interface, and resource budget. We preserve baseline-specific auxiliary operations such as reflection, memory construction, and skill extraction; their generated output tokens are included in both the per-task budget and the reported OutputTok. Baseline implementations are adapted to satisfy the common resource limits. 13 A.3 Backbones and Deployment Settings Local deployment. All methods use the frozen Qwen2.5-14B-Instruct [17] backbone on NVIDIA A800 GPUs. 

API-based deployment. All methods use the frozen DeepSeek-V4-Flash [26] backbone through an external inference API. In both deployments, the memory bank starts empty, task order is fixed within an environment, and no backbone parameters are updated. ## C Generalization Beyond LifelongAgentBench 

We evaluate online lifelong variants of BigCodeBench [38] (code generation) and ALFWorld [20] (text-based embodied decision making). Each run starts without stored experience from benchmark tasks. Tasks are processed sequentially, with retrieval using only preceding experience. Memory is updated after the current task has been evaluated, without access to future tasks. The language-model backbone remains frozen throughout each run. 

BigCodeBench. We use BigCodeBench Full v0.1.4 in the Instruct format, comprising 1,140 

coding problems. Each method makes a single pass through the same deterministic sequence: the 992 problems in Full excluding Hard, followed by the 148 problems in the Hard subset. Within these two groups, we preserve the order of the pinned Full and Hard dataset files, respectively; no random shuffling is applied. The memory bank is carried across the two groups without resetting. For each problem, the agent generates one solution, which is sanitized and evaluated using Big-CodeBench’s official execution-based evaluator inside a Docker worker. A problem succeeds only when the evaluator returns pass ; generated-code failures and execution timeouts count as unsuccess-ful outcomes. Evaluator infrastructure errors invalidate the run. We report pass@1 over all 1,140 problems, counting each problem once. Memory is updated after evaluation, and previously evaluated problems are not revisited. The local deployment uses Qwen2.5-14B-Instruct. The API deployment uses DeepSeek-V4-Flash with thinking explicitly disabled. Both deployments use temperature zero. Reference solutions and unit tests are excluded from the model’s memory and input prompts. 

ALFWorld. We use Qwen2.5-14B-Instruct as the frozen backbone, with temperature zero and top-p equal to one. A complete run contains 574 episodes: 300 training episodes selected by task-type-stratified sampling, all 140 validation-seen episodes, and all 134 validation-unseen episodes. The phases run in this order. The base seed is 42; the sampling and ordering routines use seeds 42, 43, and 44 for the three phases, respectively. Within each phase, game paths are sorted, shuffled within task-type groups using the phase seed, and selected by round-robin traversal of the groups. The resulting ordered episode manifest is fixed and shared across methods, and the runner checks that the environment follows this order. Each selected episode is executed once. An episode succeeds when TextWorld’s external won flag indicates task completion. The success rate reported here is the total number of successful episodes divided by 574 , including all three phases; it is not an unweighted average of phase success rates. Memory persists across phase boundaries and is updated after every completed episode, including validation-seen and validation-unseen episodes. Thus, this is an online lifelong protocol rather than evaluation with memory frozen after training. Expert trajectories are excluded from memory. 

Resource accounting. We follow the resource-constrained evaluation principle in Sec. 3, using benchmark-specific limits. Within each benchmark and deployment, methods share the backbone, ordered task stream, solver-call output limit, and, for ALFWorld, interaction controller. Memory 17 contexts are bounded by the complete injected block, including its headings and separators. Injection lengths below are measured in characters . The two adapters enforce output limits per model call ,rather than pooling all calls into a single per-task output allowance. Method-specific auxiliary calls, including memory construction, reflection, and skill extraction, have a separate limit of 512 output tokens per call. Their actual usage is recorded in addition to solver usage, including action repairs in ALFWorld. TokenWorth makes no auxiliary language-model calls. Consequently, the methods share per-call limits but need not consume equal total output tokens per task or episode. 

BigCodeBench configuration. The solver output limit is Omax = 1280 tokens per call for both the local and API deployments. Auxiliary API calls have thinking disabled. TokenWorth uses a memory capacity of Bmax = 50 records, injects at most Kmax = 1 record, and caps the complete injection block at Lmax = 4096 characters. Each stored experience is also capped at 4096 characters. BM25 recalls at most Kc = 12 candidates for learned worth ranking. All TokenWorth representation, learning, and memory-management parameters are identical across the local and API deployments; the solver output budget and thinking setting follow the selected deployment. 

ALFWorld configuration. The interaction limit is Jmax = 50 environment steps per episode. Each action-generation call has an output limit of Omax = 128 tokens. An inadmissible action permits at most one repair call for that step, also capped at 128 output tokens. These are per-call limits, not a 128-token allowance for the entire episode. The same action controller is used for all methods, with memory-dependent loop removal disabled. TokenWorth uses Bmax = 128 records, Kmax = 1 , a complete injection budget of Lmax = 4200 characters, a per-experience limit of 4096 characters, and a BM25 candidate pool of at most Kc = 12 .

Online learning configuration. Both benchmarks use the same deterministic 512-dimensional hashing representation of tokens and character 3–5-grams. Only a memory actually injected into the agent receives outcome supervision. KRR and AGOP updates are scheduled every 75 and 225 accumulated feedback examples, respectively, with FIFO buffers of 128 and 256 examples. These counters track feedback examples, not elapsed tasks or episodes. Each scheduled residual fit requires at least four feedback examples; this minimum does not trigger an immediate fit at the fourth example. Under these settings, the first scheduled KRR fit occurs at feedback example 75. The residual coefficient is ηt = 0 .10 min(1 , u t/3) , where ut is the number of completed KRR fits: its influence ramps linearly over the first three fits. KRR uses ridge regularization 0.01 and Laplacian-kernel scale 1. AGOP uses smoothing 0.25 , clips the updated diagonal metric to [0 .05 , 8] , normalizes it to have mean one, and immediately refits KRR. The base scorer is refitted every 50 feedback examples, using a FIFO of 256, regularization 0.1, and smoothing 0.5. Successful interactions can create new experiences; unsuccessful interactions provide negative feedback to injected memories without creating successful-experience records.
