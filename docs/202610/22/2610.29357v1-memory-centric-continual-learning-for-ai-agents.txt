# Memory-Centric Continual Learning for AI Agents 

Autonomous agents powered by foundation models can reason, plan, and use tools, but their fixed weights and context limits hinder sustained learning from experience over long-term deployment. While external memory systems attempt to bridge this gap, they mostly act as passive retrieval caches, evaluated primarily by whether they can recall stored facts or past interactions. Whether memory can drive genuine continual learning remains an open question. In this paper, we introduce Memory-Centric Continual Learning (MCCL), arguing that memory should be judged by whether it improves future actions, not merely what it retrieves. MCCL has three main parts. First, a three-axis taxonomy organizes memory by where state is stored ( substrates ), what form it takes ( assets ), and how it is managed (policies ). This defines a two-loop lifecycle that updates memory state in an inner loop while refining management policies in an outer loop based on task feedback. Second, an evaluation protocol measures retention under interference, adaptation to change, and task transfer to isolate genuine behavioral gains from simple context expansion. Third, a memory scaling framework models how agent performance scales with experience, storage capacity, and compute budgets across non-parametric and parametric memory. Together, these components reframe agent memory from passive lookup to continuous learning, offering a principled route toward self-improving autonomous agents.

21. The Landscape: Why Agents Need Continual Learning via Memory 

## 1 The Landscape: Why Agents Need Continual Learning via Memory 

Autonomous agents powered by foundation models have demonstrated strong capabilities in multi-step reasoning, planning, and tool use across digital and physical domains [1, 111, 144]. However, current agents cannot reliably improve from experience over long deployments. Although modern agent harnesses can systematically track execution logs, timestamps, and environment states, they often treat accumulated history as raw text to be retrieved and inserted back into the prompt. Simply retrieving raw text does not guarantee behavioral improvement. As interaction trajectories grow, unmanaged context dilutes relevant signals, increases inference latency, and degrades model attention [120]. Conventional adaptation methods face clear trade-offs. Expanding context windows is bounded by session limits and suffers from attention degradation over long contexts. Meanwhile, continual fine-tuning requires substantial computation, risks catastrophic forgetting of general abilities, and lacks reliable mechanisms to roll back errors [39, 74]. Without mechanisms to distill, update, and transfer accumulated experience, deployed agents cannot retain what they learn. Consequently, they repeatedly commit the same errors, struggle with conflicting or outdated information, and fail to improve across sequential tasks [13, 47, 148]. Agent memory has emerged as a primary approach to support persistence across sessions and personalization [19, 86, 87]. However, despite rapid progress, most existing methods focus on specific engineering implementations rather than systematic continual learning. Many approaches adopt an information retrieval view, treating memory simply as an external database or a Retrieval-Augmented Generation (RAG) cache designed to feed past tokens back into the prompt [61, 73]. Furthermore, existing classifications often blur distinct system choices, including where memory is physically stored, what form knowledge takes, and how memory operations are managed. Evaluation also remains limited. Many benchmarks primarily test whether an agent can recall or answer questions over a static past history, rather than whether experience accumulated during deployment improves subsequent actions under interference and drift [29, 75, 125]. Moreover, as memory stores grow, unmanaged external memory suffers from retrieval noise, memory pollution, and negative transfer when task distributions shift [15, 153]. To bridge this gap, we propose the framework of Memory-Centric Continual Learning (MCCL). We argue that addressing the stability–plasticity dilemma does not strictly require continuous gradient updates to foundation model weights. Instead, memory itself can serve as an evolving learning infrastructure through which an agent incorporates feedback, refines strategies, and resolves knowledge conflicts during deployment, while keeping the base model intact. In this framework, continual learning operates as a coupled dynamical system. An inner memory-state loop updates stored knowledge from sequential deployment experience, while an outer policy-adaptation loop 

refines memory management policies based on task performance. By connecting task outcomes back to memory management, MCCL provides a principled route toward Recursive Self-Improvement (RSI) , where agents not only accumulate experience but also improve how that experience is organized and used. We summarize our core contributions as follows. 1. A unified taxonomy of memory architecture. We clarify existing classifications through a three-axis taxonomy: where experience persists ( substrates : contextual, activation, external addressable, and adaptive parametric), what form it takes ( assets : episodic, semantic, and procedural), and how operations are managed ( policies : prescribed, deliberative, and learned). This separates physical storage from cognitive representation and operational control (Section 2). 2. The memory lifecycle as an engine for continual learning. We formalize memory dynamics across five core stages: selective formation, structural consolidation, reactivation and uti-lization, knowledge revision and selective forgetting, and feedback-driven policy evolution. This formulation explains how raw interactions turn into generalizable knowledge while mitigating memory pollution and drift (Section 3). 3. A behavioral evaluation framework. We distinguish retrieval-level checks from genuine continual learning outcomes. We introduce a four-gate retention cascade (preservation, access, utilization, and effect) to diagnose failure points, use matched stateful-versus-reset comparisons ( Δ𝑃 𝑡 ) to isolate the effect of accumulated memory, and establish evaluation 32. ## 2 A Unified Framework: Architecting Memory for Continual Learning 

Classical continual learning theory has primarily focused on the stability–plasticity dilemma within model weights, seeking to mitigate catastrophic forgetting during sequential gradient updates [78, 112]. In contrast, foundation-model-based agents decouple computation from persistent storage, distributing experiential adaptation across physical media, semantic abstractions, and control mechanisms. However, existing taxonomies often mix these levels, confusing where an experience is stored with what form it takes and how it is managed [49, 169]. To establish a principled foundation for memory-centric continual learning, we organize the design space around three core axes, covering 

where experience persists, what reusable form it takes, and how memory operations are managed (Figure 2). 42.1 Memory Substrates: Physical Foundations for Stability and Plasticity • Memory Substrates (WHERE): Physical Storage Media. Substrates define the physical medium where experience persists. They govern trade-offs between write latency, volatility, capacity, and durability, determining whether experience is held in active context, model activations, external stores, or model parameters. • Memory Assets (WHAT): Cognitive Representations. Assets describe the form knowledge takes. Independent of physical substrates, assets balance specific detail against general abstraction, grouping experience into episodic traces, semantic facts, or procedural skills. • Memory Policies (HOW): Mechanisms for Memory Management. Policies define the rules for writing, consolidating, retrieving, updating, and forgetting memories. They span fixed heuristics (prescribed), runtime language model reasoning (deliberative), and feedback-driven control (learned), determining whether memory management remains static or adapts over time. These three axes are complementary dimensions rather than isolated categories. A concrete agent memory system combines specific choices across all three axes, such as compiling episodic traces into an external addressable store governed by deliberative policies powered by Large Language Models (LLMs). Decoupling these dimensions clarifies that possessing an external substrate does not by itself yield transferable capability, nor does storing an episodic asset indicate that an agent has an effective policy to retrieve and use it. By formalizing this three-axis architecture, we establish a principled framework to diagnose where existing architectures succeed or fail under non-stationary streams, and to compose hybrid systems that support RSI. 

2.1 Memory Substrates: Physical Foundations for Stability and Plasticity 

Memory substrates define where experience persists and how it can be accessed and modified. Existing taxonomies commonly separate internal from external memory, or computation-coupled from addressable memory [49, 169]. We distinguish substrates by where state physically persists, rather than how it appears during inference. For example, text retrieved from a database remains external memory even when placed in a prompt; conversely, offloading the KV cache to disk changes its storage location but keeps it an activation-level representation. Following this principle, we identify four basic substrates: contextual memory, activation memory, external addressable memory, and adaptive parametric memory. This distinction is independent of memory assets and policies. A substrate specifies how long experience can persist, how it can be addressed, and at what granularity it can be updated. It does not, by itself, tell us whether those updates yield transferable improvement; that depends on the assets built from experience and on the policies that govern their formation and use. 

Contextual memory. The most direct memory substrate is the sequence of tokens currently visible to the model. Thoughts, actions, and observations can be recorded in a shared prompt so that the trajectory influences subsequent decisions through self-attention [144]. Ever-growing traces are replaced with subgoal-level summaries or compressed reasoning states [46, 128], and deletion, com-pression, and rewriting are exposed as agent actions [161]. These methods require little architectural modification and offer nearly immediate plasticity, with relatively high fidelity over short horizons. Their stability, however, is bounded by the session limit. As trajectories grow, older observations consume context tokens and degrade model attention. Even within the supported context window, performance can drop sharply with sequence length, evidence position, and task complexity [45, 69]. Summarization and compaction extend the effective horizon but introduce an irreversible, often lossy selection step [20]. 

Activation memory. A second family compresses history into machine-native states, including hidden activations, KV caches, recurrent states, and dedicated memory slots. Hidden states are reused across segments, and KV entries are selectively retained under a fixed budget [22, 70, 162]. Previously computed internal representations are placed in a retrievable memory bank [114, 130], and latent pools or designated slots are introduced that can be repeatedly read and updated [54, 117]. Compared with textual context, these states participate in the forward pass at higher bandwidth and need not be translated back into natural language. Gating, state transitions, and isolated slots can also confine rapid adaptation to a restricted state channel, leaving the pretrained backbone unchanged. This efficiency shifts the capacity cost to runtime memory and limits controllability: 52.2 Memory Assets: Representations for Cross-Task Transfer activation memories are tied to a particular model, layer structure, and representation space, and their contents are difficult to inspect, edit at the level of individual facts, or transfer across models [59]. Fixed-dimensional latent states also face capacity limits as experience accumulates. Offloading activation states or the KV cache to disk does not turn them into external text memory, because they can still only be processed as internal representations by the original model. 

External addressable memory. External memory separates storage from model computation. Experience persists as independently maintained entries that can be explicitly retrieved and modified. Implementations range from natural-language logs and summaries to vector indices, relational tables, knowledge graphs, hierarchical trees, code repositories, and collections of specialized stores. Observation streams are combined with higher-order reflections, language-level diagnoses are retained from failed trials, and information is moved between a bounded active context and larger archival stores [86, 87, 95]. Memory extraction, dynamic organization, and structured retrieval are further developed in recent systems [19, 42, 90, 136]. This substrate offers a direct route to non-parametric continual learning: new experience can survive across sessions without altering the foundation model, individual records can be revised or versioned, and capacity can grow independently of model size. Structural separation changes rather than resolves the stability–plasticity dilemma. External stores avoid catastrophic forgetting caused by parameter updates, but an old memory can become inac-cessible when its retrieval rank declines, producing a form of functional forgetting . Summarization, deduplication, and conflict resolution may also overwrite earlier records or change whether they still count as valid evidence. As the store grows, redundant, stale, and conflicting entries raise retrieval noise. Indexing, provenance tracking, and deletion become more expensive as well. Irrelevant or conflicting retrieval can be actively harmful [13, 110], and current memory agents do not reliably combine retrieval, online updating, long-range use, and selective forgetting [48, 106]. 

Adaptive parametric memory. Parametric substrates encode deployment experience in model weights, detachable adapters, or designated fast parameters. Static pretrained weights are not sufficient for this category; the defining property is that parameters can still be updated from experience after deployment. Consecutive edits are isolated in a side parameter space, and behavior obtained with visible context is distilled into a model that no longer receives that context [113, 118]. Test-time neural memory and rapidly updated LoRA parameters are used to preserve behavioral effects after the corresponding evidence has left the active prompt [8, 89]. Once internalized, it can be used during a standard forward pass without external retrieval and may generalize beyond the specific instance that produced the update. It is therefore attractive for stable, frequently reused, and well-validated knowledge or skills. This efficiency at read time comes at the cost of more expensive and less controllable writes. Param-eter updates require optimization, generated supervision, or specialized test-time learning rules. Once an experience is distributed across weights, its scope is difficult to localize, and record-level expiration, provenance tracking, and deletion become substantially harder than in an external store. Repeated adaptation can cause catastrophic forgetting of earlier knowledge or consolidate transient feedback and self-generated errors into persistent behavior. Continual instruction tuning forgets across domain knowledge, reasoning, and reading comprehension, and successful factual edits can still degrade unrelated general abilities [39, 74]. Side memories, low-rank adapters, and slow–fast parameter decompositions reduce forgetting by restricting the update scope, but introduce routing failures, module-merging conflicts, and long-term drift of their own. 

Hybrid substrates. Practical memory systems increasingly combine substrates with comple-mentary roles, where tokens and activations support immediate adaptation, external stores provide durable and auditable retention, and parameter updates selectively internalize stable skills [8, 86, 89, 114]. Existing hybrid systems still leave several design choices open, including where new experience first enters, when it moves to a more durable store, how queries are routed, which state is authoritative during conflicts, and where erroneous updates can be rolled back.

Contextual tokens and activation states may participate in memory formation, but they count as assets only once they persist in a reusable form across tasks; otherwise they remain working state on a substrate. As with substrates, possessing an asset is not itself evidence of cross-task learning. Episodes, facts, and skills specify the form in which experience can transfer; whether transfer occurs is a question for memory policies. 

Episodic assets. Episodic assets preserve what happened . Their basic unit is a particular experience situated in its temporal, environmental, and task context. An episode may include observations, goals, actions, tool calls, intermediate reasoning, feedback, and outcomes, or a compressed segment derived from these elements. Compared with more abstract assets, episodes retain the conditions under which an experience was obtained. They therefore support case-based reuse, resumption of interrupted tasks, and retrospective inspection of the evidence behind a later belief or strategy. Observations and higher-order reflections are stored in a memory stream, trial outcomes and lin-guistic diagnoses are retained after failed attempts, and both prior trajectories and insights extracted from collections of experience are retrieved for later reuse [87, 95, 163]. Structured event records and production memory stores further retain temporally grounded episodes across sessions [19, 72]. Episodes are particularly valuable for rare events and one-shot observations for which reliable abstraction is not yet possible. They permit highly plastic writes because the agent need not decide immediately whether an observation expresses a general rule, while their high fidelity supplies evidence for later correction. The same fidelity, however, produces substantial storage and retrieval costs. As the collection grows, trajectories that are superficially similar but decisionally different compete for retrieval, while complete traces carry observations and actions irrelevant to the current problem. Stored experience is most useful when its structure matches the target task; in other settings, long-context baselines remain competitive [120]. 

Semantic assets. Semantic assets preserve what is known . Their reusable units are facts, concepts, relations, constraints, preferences, and environment models abstracted from particular observations. Unlike episodic assets, they suppress much of the temporal and surface detail of the originating event so that knowledge can be reused across sessions and tasks. A recurring user preference, a tool authentication requirement, or a relation between two entities can thus be invoked without replaying the full interaction from which it was inferred. Stripping temporal and situational detail yields compression and broader reuse, and structured se-mantic assets additionally support entity-level revision, relational inference, and multi-hop retrieval. Dynamically indexed notes are linked so that new entries can modify the contextual representation of existing ones; current and historical relations are maintained in temporal knowledge graphs; and structured retrieval is framed as non-parametric continual learning [42, 88, 136]. Hierarchi-cal schemas and operating-system-style stores likewise organize reusable facts beyond a single episode [53, 90]. These approaches indicate that semantic memory is not a static knowledge base but a knowledge state that must be continually formed, connected, and revised. The central weakness of semantic assets arises from the same abstraction that enables transfer. Premature consolidation may convert an accidental correlation into a general claim, while removing context may discard when, where, and with what confidence that claim is valid. Appending new information can leave mutually competing facts in memory, whereas overwriting an earlier entry can destroy historical provenance. Retrieving updated evidence also does not guarantee recognition of an implicitly invalidated belief or corresponding adaptation in downstream behavior [14]. In practice, existing semantic stores often keep the extracted claim while omitting provenance, temporal scope, confidence, and links to the episodes that support it. 

Procedural assets. Procedural assets preserve how to act . Their reusable units include workflows, strategies, plan templates, tool-use rules, and executable programs. They may be represented as natural-language instructions, code, parameterized workflows, or behavioral policies internalized in model parameters. The distinction from semantic assets is functional rather than syntactic: semantic assets describe a state of the world, whereas procedural assets prescribe how that state should be changed under particular conditions. The same piece of text can therefore be semantic if retrieved as a fact and procedural if retrieved as an instruction. 82.3 Memory Policies: Prescribed, Deliberative, and Learned Control Because they directly constrain action generation, procedural assets provide the most immediate form of behavioral transfer. Environment-verified skills are stored as composable code, parameter-ized workflows are induced from successful trajectories for reuse across tasks and domains, and generalizable strategies are extracted from successful and failed experience instead of retaining only raw trajectories [85, 111, 121]. Evolving context playbooks and learned memory skills further compile repeated execution into reusable action knowledge [83, 155, 159]. Procedural assets can also be composed, allowing previously acquired skills to become components of more complex behavior and reducing repeated exploration. This compilation nevertheless locks in assumptions from the original experience. A workflow may remain valid only for a particular tool version, interface, or set of environment dynamics. Retrieving a skill for a superficially similar task with different preconditions can produce negative transfer, while unverified self-reflection may turn an accidental success into a persistent rule. Explicit skill maintenance is not uniformly superior to retaining prior context, and gains are more reliable on tasks with clear workflows than on open-ended ones [40, 166]. In current systems, preconditions, expected outcomes, environment dependencies, verification status, and versioning are often left implicit. Long-lived skill libraries therefore tend to accumulate skills rather than merge, deprecate, or regression-test them. 

Cross-asset consolidation. The three asset classes are not mutually exclusive storage compartments. They describe experience at different levels of abstraction. Episodic assets retain concrete evidence; regularities recurring across episodes may be consolidated into semantic assets; and repeatedly validated action regularities may be compiled into procedural assets. This transformation improves compression and cross-task reuse while progressively removing details of the original context. Asset formation therefore exposes a fundamental trade-off: representations close to individual episodes preserve evidence but depend on precise matching, whereas abstract knowledge and skills are cheaper to invoke but allow erroneous generalizations to affect a wider range of tasks. Consolidation is rarely a clean, one-way pipeline in existing systems. Semantic claims and procedural skills often lose their links to supporting episodes, and new experience cannot always qualify, revise, or revoke what was previously consolidated. A single record can also contain all three components, such as a task trajectory, an environmental fact inferred from it, and a corrective procedure learned after failure. At retrieval time, such a record is better classified by how it is used than by how it is physically stored. 

2.3 Memory Policies: Prescribed, Deliberative, and Learned Control 

As agents operate over longer horizons, memory is no longer only a problem of storing more information or retrieving it more accurately. The central challenge is how memory should change over time, deciding what should be retained, consolidated, revised, or forgotten, and how these decisions should adapt to new experience and feedback. We refer to the mechanisms governing such decisions as memory policies. They determine when and how memory state evolves, and they correspond to the how column of Figure 3. We distinguish three control regimes. Prescribed policies apply fixed rules, heuristics, and scoring functions. Deliberative policies use the LLM to decide, for each case, whether to write, retrieve, or revise, given the task, memory state, and context. Learned policies update memory control from outcomes and feedback. The regimes are compositional rather than exclusive: a system may prescribe capacity limits, deliberate over conflicts, and learn retrieval utilities. They also align with the prescribed, deliberative, and learned control tiers used later in the lifecycle comparison (Section 3). 

Prescribed policies. Prescribed policies treat memory management as resource allocation under limited context, cache, and store capacity. Control is specified before deployment through rules such as FIFO, LRU, sliding windows, or fixed Top-𝑘 retrieval, so utility is approximated by position, recency, and budget rather than estimated future value [133]. Salience-based scoring is a richer but still prescribed variant: recency, importance, and relevance are combined to select episodic records [61, 87], and entries are admitted or forgotten according to novelty, importance, or decay thresholds [103, 167]. Hierarchical designs go beyond single-shot Top-𝑘 by controlling movement across memory tiers, yet the tools, thresholds, and control rules remain predefined [86]. Prescribed 93. The Memory Lifecycle as the Engine of Continual Learning control is efficient, predictable, and easier to inspect. Its limitation is rigidity: what counts as novel, important, or disposable is not subsequently revised according to task outcomes. 

Deliberative policies. Deliberative policies place the LLM inside the memory-control loop because numerical scores cannot fully capture the semantic value of an experience. The model is asked, for each case, whether to store, retrieve, resolve a conflict, or rewrite, using the current task, memory state, and context. Handcrafted scoring is replaced by case-by-case judgments, while the outer tool protocol remains fixed [19, 86, 136]. A stronger deliberative pattern lets experience revise subsequent control in natural language: verbal post-mortems are stored to steer later attempts, and successful and failed traces are abstracted into reusable strategies [85, 95]. Write boundaries are tightened, consistency is verified against constraint memory, or the memory collection itself is reorganized [30, 55, 67, 82]. The resulting control is flexible and interpretable, but inference-intensive and dependent on prompt following. Rewriting a strategy in language still leaves the controller untrained, as most such systems lack credit assignment from later task outcomes back to earlier memory decisions. 

Learned policies. Learned policies treat memory control as an experience-updated decision prob-lem. The agent may still use standard operations, such as write, retrieve, compress, revise, and forget, but a trainable controller selects among them, and those selections improve from outcomes and feedback. Discrete memory actions are learned from reward [139, 149, 161], and purely similarity-based retrieval is replaced with utility values that reflect historical contribution to success [160]. Reinforcement learning provides the credit assignment that static controllers lack, because the true value of a write or deletion often appears only several steps later [18, 145, 151]. Two levels of learning should be distinguished. In many existing systems the controller is optimized offline and then frozen, so memory content continues to evolve while the operational policy remains static. Recent RSI frameworks instead attempt rule-level modification, where the language model is prompted to inspect and revise its own prompt templates or execution scaffolding [2, 147, 157, 159]. Recuris further shows that a Meta-Agent can synthesize validation-gated updates from execution failures, recursively refining operational rules and the skill library [150]. Although reflection-based prompt adaptation offers substantial semantic flexibility, such methods typically rely on heuristic textual edits and trial-and-error screening against a validation set. Under long-horizon delayed task feedback, they struggle to establish fine-grained temporal credit assignment and to keep the meta-policy stable. A more systematic form of continual policy evolution would update the memory-management policy from ongoing environmental feedback while suppressing policy drift. The next section turns to how experience-level rule evolution can be combined with structured closed-loop policy learning across the lifecycle.

3.1 Formation and Selective Writing 

Formation is the first point at which ongoing experience can acquire persistent influence over future behavior. It determines not only which observations should enter long-term memory, but also how they are represented and what source, temporal, and contextual information is preserved for later use. 

Selective Writing and Plasticity Control. Memory-centric continual learning begins with an admission decision, because not every interaction should modify persistent memory. Writing too freely can accumulate incidental, redundant, or erroneous observations and increase interference over time. Writing too conservatively can discard experience that would have supported later adaptation. Selective writing therefore defines the agent’s plasticity boundary by deciding which deployment-time experiences may exert persistent influence on future behavior. Selected session-level information can be promoted into persistent memory, and storage operations can be exposed as actions that are optimized from downstream outcomes [21, 149]. These examples show that admission can range from staged promotion to learned action selection. In either case, the cost of a poor write can persist, as admitting unreliable experience propagates errors while rejecting useful experience removes evidence needed for future learning. The objective is therefore not to store as much as possible, but to admit useful experience without giving transient or unreliable observations unnecessary long-term influence.

Instead, they help later reasoning determine where the memory came from, whether it still applies, and how strongly it should be trusted. Without such information, a hallucinated observation may later be reused as fact, an accidental success may become a general strategy, or a temporary state may be applied outside the context in which it was observed. This causes memory pollution, where an error introduced at formation continues to degrade later behavior and may be reinforced through repeated retrieval, revision, and consolidation. Formation therefore determines both which experience enters persistent memory and what evidence is carried forward with it. The next question is how these formed memories should be organized and transformed as experience accumulates. 

3.2 Organization, Compression, and Consolidation 

Organization and consolidation form the integration stage of the memory lifecycle. Once experience has entered persistent memory, the system must decide which observations belong together, when accumulated evidence is ready for further transformation, and whether repeated experience should 12 3.2 Organization, Compression, and Consolidation remain episodic or become more reusable knowledge. These decisions improve stability and reuse, but they also introduce risks, as premature or overly aggressive consolidation can turn incomplete evidence into persistent generalizations. Here, consolidation refers to the durable organization or transformation of experience across interactions, rather than the compression of active short-term context alone. 

Choosing the Unit of Experience. Consolidation first requires a decision about the unit over which experience is organized. Continuous interaction arrives as a stream, yet memory systems must decide which observations should be treated as part of the same event, episode, or semantic segment. This choice determines which pieces of evidence can later be compared, linked, or transformed together. Recent systems use dynamically detected events or temporally grounded episodes instead of relying only on fixed turns or windows [88, 170]. Fine-grained units preserve local detail but can split dependencies across several memories. Broader units make longer-range relations easier to capture, but they may also combine observations that should remain separate. Experience boundaries therefore shape what later consolidation can learn from, determining which evidence is considered jointly and which patterns can eventually be stabilized and reused. 

When to Consolidate. A coherent experience unit does not automatically justify immediate con-solidation. If transformation occurs too early, the system may generalize from insufficient evidence, repeatedly rewrite unstable knowledge, or amplify an early mistake. If it occurs too late, related experience remains fragmented and becomes harder to reuse. Recent approaches make this timing decision explicit in different ways. LycheeMemory V2 waits for semantic segment boundaries before encoding accumulated interaction into long-term memory, whereas RecMem uses recurrence across related observations as a signal that consolidation is warranted [23, 62]. These methods treat consolidation timing as an explicit memory-control decision rather than a routine background process. Their triggers, however, are still prescribed rather than learned from downstream outcomes. This distinction separates the question of when evidence is ready for consolidation from the later policy-level question of whether the rule that makes this decision can itself improve from feedback. 

From Episodes to Reusable Abstractions. Consolidation also determines the level at which past experience remains available for future use. Individual episodes preserve what happened and the conditions under which it happened, but continual learning often requires regularities that can be reused beyond a single case. Collections of trajectories can be distilled into reusable natural-language insights or executable skills [111, 163]. Evidence from continual experience internalization, although obtained in a parametric setting, similarly suggests that principle-level experience may remain more robust across repeated updates than instance-specific traces [15]. Abstraction can therefore improve transfer, but it should not be treated as a mandatory replacement for episodic memory. Episodes preserve context and supporting evidence, whereas more abstract knowledge trades some of that detail for broader applicability. Consolidation is thus a change in the form and scope of knowledge, not merely a reduction in storage size. It determines when an experience should remain a case to be recalled and when repeated evidence is strong enough to support a more general principle, schema, or procedure. 

Lossy Consolidation and Evidence Preservation. The same transformation that improves reuse can also remove information that later becomes important. Repeated LLM-based rewriting has been shown to initially improve and then reduce memory utility, while retaining raw episodes can remain competitive with systems that repeatedly force consolidation [153]. Compression can also remove the contextual conditions needed to decide whether an abstracted memory still applies. RaMem describes this failure as context collapse and restores information such as event time, participants, and session scope before compressed memories are used as evidence [142]. Consolidation should therefore preserve links to supporting evidence rather than replace that evidence by default. Higher-level abstractions should remain traceable to the episodes from which they were derived so that later retrieval, verification, or revision can recover from a poor generalization. Consolidation can stabilize and generalize experience, but it can also become a source of distortion, interference, and implicit forgetting when abstraction removes information that remains useful. 13 3.3 Retrieval and Utilization 

3.3 Retrieval and Utilization 

Retrieval and utilization (i.e., uptake) connect accumulated experience to the agent’s current reason-ing and actions. Their effectiveness depends on recovering sufficient evidence, matching it to the current decision, and using it appropriately. These functions concern the use of existing memory rather than changes to its persistent content. 

Reactivating Relevant Evidence. Retrieval must recover usable evidence, not simply records with similar wording. A task may depend on several related events, their temporal order, or the circumstances in which earlier observations were made. Selecting the right memory source is therefore only part of the problem. The system must also recover enough supporting context to interpret what it finds. Temporal graph memories, reflective memory managers, and contextual-reinstatement methods offer different ways to select or recover such evidence [88, 103, 142]. These mechanisms connect retrieval to the representation and evidence-preservation choices discussed above. A compact summary may be sufficient for one task, whereas another may require access to its supporting episodes. Recovering that context helps establish the meaning and scope of the memory without rewriting it. The goal is not to return as much history as possible, but to recover enough relevant evidence and to keep its source and context checkable. 

Matching Memory to the Decision State. A memory can be relevant to a task yet unhelpful at a particular decision point. During planning, the agent may need a reusable procedure or a record of earlier constraints. During tool execution, it may instead need exact parameters or the conditions required for an operation to succeed. Verification may call for evidence that tests a tentative conclusion, while failure recovery may benefit from records of unsuccessful attempts. Retrieval should therefore consider the current subgoal, the evidence already available, and the uncertainty that prevents the next decision. This also dictates when retrieval is beneficial, since additional memory may resolve a specific information gap, repeat existing context, or introduce distracting details. Relevance to the overall task is therefore not enough. The retrieved evidence should address what the agent needs to decide at that moment, rather than simply resemble its current query. 

From Access to Effective Use. Utilization (often termed uptake in retrieval workflows) concerns whether and how retrieved evidence actually shapes reasoning or action. A record appearing in the context does not establish that the agent used it, and its use does not guarantee behavioral improvement. Even after a relevant record is preserved and retrieved, the agent may overlook it in context, misinterpret its valid scope, or misapply a past strategy under conditions where it no longer holds. Studies of continual agents and experience reuse highlight this gap between retaining experience and benefiting from it later [15, 96]. Consequently, four sequential conditions must remain conceptually distinct: preservation (retaining the record in storage), access (retrieving it into the decision context), utilization (incorporating it into reasoning), and behavioral effect (achieving a net task improvement, formalized as the retention cascade in Section 4). Appropriate utilization may involve applying a memory, restricting its use to supported conditions, or rejecting it when more reliable evidence contradicts it. When memory use reveals an error or outdated assumption that would also harm future tasks, the system must decide whether and how to modify persistent memory. That maintenance decision is the subject of revision and forgetting. 

3.4 Revision and Forgetting 

Revision and forgetting maintain persistent memory as new evidence arrives and earlier knowledge loses its validity or usefulness. Revision changes what is recorded or treated as current, while forget-ting regulates continued access and influence. These operations contribute to the state transition in Equation (3.1). They may be triggered by incoming experience or by problems discovered during memory use. 

Resolving Conflicts and Tracking Current Validity. Before modifying memory, the system must determine what the new evidence changes. A disagreement may indicate an error, a change over time, or a difference in context. These cases require different responses. Correcting a false observation is not the same as preserving a historically accurate observation while marking it as no longer current. Graphiti separates temporal validity from the retention of historical evidence, while UMA processes 14 3.5 Feedback-Driven Policy Evolution successive observations to maintain an evolving memory state [88, 158]. Source reliability and applicability must also be considered; newer information should not automatically replace older evidence. When the available evidence does not resolve a conflict, preserving the competing records with their sources may be preferable to forcing an update. The goal is to maintain usable current knowledge without erasing the conditions under which earlier memories were valid. 

Making Knowledge Revision Persistent. Once a correction is justified, it should be reflected in persistent memory so that later tasks do not repeatedly encounter the same inconsistency. Revision can add missing information, correct an existing record, narrow its scope, change its validity, or reorganize its links to other memories. Systems implement these changes through direct updates or through mechanisms that retain earlier evidence and versions [64, 99, 158]. These options need not be mutually exclusive. A system can update its current knowledge while retaining the history needed to inspect or reverse the change. Revision should also account for derived memories. If an episode supports a summary or reusable procedure, correcting the episode alone may leave that derived knowledge inconsistent. Links to supporting evidence help identify which derived memories may also need review. The objective is not frequent rewriting, but a justified change whose scope matches the evidence and whose consequences remain traceable. 

Expiration, Suppression, and Deletion. Not every maintenance decision concerns factual truth. A memory can remain accurate yet become redundant, rarely useful, or overly costly to keep active. Forgetting regulates whether and how such records continue to influence later behavior. Hard deletion permanently removes a record from its persistent store; expiration deactivates it according to a predefined retention window or inactivity schedule; and soft suppression retains the record while lowering its retrieval priority or accessibility. MemoryBank uses time-dependent memory strength decay, whereas VerMem supports soft deletion with retained history [99, 167]. These capacity- and utility-driven forgetting mechanisms differ fundamentally from epistemic temporal invalidation during revision. Invalidation updates the temporal or contextual scope of a claim to record that it no longer holds in the current state, without erasing the historical evidence or evicting the record. Although both operations can reduce a memory’s future influence, factual validity (whether a claim still holds) and retrieval availability (whether a record remains accessible) are distinct properties. Choosing among these operations requires diagnosing whether the issue is outdated knowledge, unwanted retrieval interference, or storage cost. 

Selective Forgetting and Capability Preservation. Intentional forgetting aims to reduce unwanted influence, whereas catastrophic forgetting refers to the unintended loss of knowledge or capabilities that remain useful after further learning [74]. In external memory, useful information may also become functionally unavailable even when the record survives [148]. The presence of a D ELETE 

action in systems such as AgeMem and UMA establishes a possible operation, not an effective policy for selective forgetting [149, 158]. Nor does deleting a source record necessarily remove its influence from summaries or procedures derived from it. Conversely, consolidation can discard useful evidence without any explicit deletion [142, 153]. Where future usefulness is uncertain and continued retention is permitted, reversible suppression or archival may be preferable to irreversible removal. Maintenance should preserve still-useful knowledge, reduce harmful influence, and retain enough evidence to recover from a premature update or deletion. The next question is whether the policies that make these choices can themselves improve from feedback.

## 4 Evaluating Memory-Augmented Agents as Continual Learners 

Sections 2 and 3 specify how experience can persist, what reusable form it can take, and how it is admitted, consolidated, used, revised, and governed. Those design choices do not, by themselves, establish that continual learning has occurred. A changed store, a retrieved record, or a higher single-task score can all arise without a durable, experience-induced change in later behavior. This section therefore treats evaluation as an evidentiary problem, asking what empirical observations would justify a continual-learning claim given the architecture and lifecycle established in prior sections. We first specify three core behavioral outcomes (retention, adaptation, and transfer) and then establish the protocols needed to measure them without confounding memory with expanded context windows, extra test-time computation, or transient, isolated success. 

4.1 What to Measure: Retention, Adaptation, and Transfer 

Access-level metrics remain useful, but they answer a narrower question than learning. Content correctness and retrieval scores diagnose whether experience was written and can still be found; a single-task outcome shows only that memory helped on the current probe (Table 1). Continual learning additionally requires that an experiential gain persist under delay and interference, remain revisable when the world changes, and transfer beyond remembered episodes [71, 112]. The remainder of this subsection operationalizes those three outcomes. 4.1.2 Adaptation: Learning Must Remain Revisable under Change 

When facts, preferences, tools, or rules change, retention without revision becomes a source of error. Section 3.4 already treats conflict resolution, persistent update, and selective forgetting as lifecycle operations. Evaluation asks a more targeted question, examining whether behavior faithfully follows a valid update after an environment change without indiscriminate damage to still-useful capabilities. The relevant evaluation chain is temporal rather than a single write (detection, revision, recovery, and preservation), which should be quantified via detection delay, steps to recovery, stale-error duration, and collateral degradation on unchanged probes. For external stores, the question is whether the current record supersedes the stale one and whether retrieval ranks it above obsolete evidence. Exposed maintenance operations establish that updates are possible, but conversational QA after a long history does not demonstrate recovery under controlled drift [19]. For parametric and latent memories, injection accuracy and sequential fact updates are retention and write diagnostics, not evidence that an acting agent detected an unannounced change or resumed correct tool use [24, 117]. Evaluated models can verbalize that a fact has changed yet fail to propagate that judgment to the final prediction [107]. A credible adaptation claim therefore requires matched pre-change and post-change probes, together with simultaneous reporting of recovery and selective preservation. 

4.1.3 Transfer: Learning Must Extend beyond Remembered Episodes 

Section 2 classifies reusable experience as episodic, semantic, or procedural assets. Transfer evalua-tion asks whether those assets support later behavior beyond storing an answer. Three increasingly demanding cases should be separated: replaying the same or a near-duplicate episode, solving an unseen variant from the same task family, and applying shared structure to a distinct target task. Source and target partitions must exclude duplicate instances and target answers, document the shared structure, such as a workflow, causal rule, tool convention, or subskill, while keeping the base model, tools, context budget, and compute matched. Otherwise nearest-neighbour reproduction and extra context can be mistaken for learned transfer. Abstraction directly supports reuse, as demonstrated by the successful transfer of insights, work-flows, and executable skills across related tasks and environments [111, 121, 163]. The same evidence shows why mean target accuracy is insufficient. Raw trajectory memory can produce negative forward transfer where abstract insights do not, with harm concentrated on cases that a no-memory agent could not already solve [47]. Dedicated memory and skill-maintenance methods are only selec-tively helpful and can be matched or outperformed by ordinary in-context accumulation [6, 40, 166]. Transfer should therefore be reported as zero-shot target gain or forward transfer, interactions or tokens to a target threshold, and explicit negative-transfer rates [71, 91]. For external memory, analysis should identify whether the retrieved asset is a case, rule, workflow, or skill, and whether success depends on answer overlap. For neural memory, it should test whether updated latent or parametric state improves a held-out target without degrading unrelated tasks. 

4.2 How to Measure: Protocols for Experience, Controls, and Time 4.2.1 Benchmarks Must Contain Learnable Experience 

A parallel distinction applies to benchmark design. The presence of “history” does not imply the presence of learnable experience. Many suites pre-supply dialogue logs, profiles, or knowledge bases and then test whether related questions can be answered after the history is given [29, 75, 125, 167]. Such protocols diagnose long-horizon access. They usually cannot decide whether a new capability was formed during evaluation. Evidence strength rises with the experience that the protocol actually exposes (Table 2). Fixed history supports “remember and use.” Continual writing of state supports “internal state accumulates.” Feedback that improves later behavior, under the matched and sequential controls below, approaches continual learning. Procedural streams ask whether success and failure trajectories improve later workflows [165]; semantic and personalization streams ask whether facts and preferences persist and can be revised [75, 101, 125]; dynamic-rule streams ask whether invalidated experience is corrected in time [6, 48]. A benchmark may excel on one stream while remaining silent on the others. Externally grounded outcomes and user corrections also support stronger learning claims than self-generated reflections, which can be stored and later retrieved as if they were facts [87, 95].

4.2.3 Sequential Evaluation Separates Durable Learning from Transient Success 

The retention and adaptation definitions above already require the same capability to be measured across memory states. Chronological length does not substitute for that invariance. Endpoint scores after a long history show that information can be used, but not when the benefit appeared or whether it disappeared and recovered [75, 125]. A short protocol that probes a capability before acquisition, immediately afterward, and after a controlled update is stronger evidence than a long trajectory with a single terminal score. Four observation regimes support progressively stronger claims. Snapshots test a final memory state; streams report online reward on changing tasks; reprobes repeat the same capability or a calibrated task variant; and interventional panels combine reprobes with an event ledger and matched stateful–reset trajectories. AgentCL and CL-Bench illustrate the value of a stable observation target, where first-pass, frozen-memory, and held-out probes systematically isolate acquisition, reuse, and transfer [6, 96]. Between probes, the ledger should record elapsed time, writes, semantic overlap, conflicts, feedback, tool or rule changes, and retrieval or update cost. Delay plus overlapping updates tests retention; changes in facts, preferences, or tools test adaptation; held-out tasks that preserve latent structure test transfer. Evidence for one evaluation setting should not be treated as validation across all three. A compact blueprint follows. Define capability anchors and measure them before and immediately after acquisition; schedule checkpoints on a declared delay–interference grid; run stateful and reset conditions with identical backbone, tools, context, retrieval, and inference budgets; and populate a matrix 𝑅 𝑡 ,𝑖 that re-evaluates capability 𝑖 after update 𝑡 . Diagonal entries measure acquisition, lower-triangular entries expose retention and backward influence, and held-out variants test transfer. Reporting the event ledger beside this matrix prevents apparent gains from obscuring task drift or hidden computational overhead. 

4.2.4 Fragmented Benchmarks Limit Cross-Study Conclusions 

Existing suites occupy different cells of this design rather than a common scale. Access-oriented histories, incremental ingestion, and sequential interactive tasks are not interchangeable measure-ments of the same construct, and they rarely match context budgets, retrieval depth, or inference compute. Numerical comparison across papers is therefore unreliable unless the protocol specifies the behavioral outcome in Section 4.1, the experience regime above, and the matched and sequential controls that isolate memory. Scores should be read within that evidentiary scope, not as a generic ranking of memory systems. 

4.3 The Memory Scaling Law: Capacity, Interference, and Learning Efficiency 4.3.1 Non-Parametric Memory Scaling Law: Experience, Capacity, and Compute 

Non-parametric memory makes deployment experience a resource for continued capability growth with fixed model weights. Agents preserve interaction facts [19], distill reasoning strategies, and consolidate experience for later tasks [85, 146]. The resulting capability depends on how much relevant experience is available and how efficiently the memory system retains and uses it. We propose a Memory Scaling Law relating attainable performance to experience, persistent ca-pacity, and read–write compute. Its central prediction is a sequence of resource-limited regimes, where performance improves as relevant experience accumulates and subsequently saturates when capacity or read–write compute constrains its effective use. Expanding the limiting resources shifts these saturation points. The information structure of experience determines how quickly capacity demand grows, while reuse determines how much computation is worth investing in writing and 21 4.3 The Memory Scaling Law: Capacity, Interference, and Learning Efficiency consolidation. 4.3.2 Parametric Memory Scaling Law 

Parametric memory writes deployment experience into model parameters or persistent neural states rather than into an external store. Representative designs include trainable memory layers [9], plug-and-play memory modules [12], memory states updated at test time [8, 58], side memories isolated from the backbone [24, 113, 117], and direct editing or fine-tuning of backbone weights [80, 138]. These approaches confront the same fundamental question as non-parametric memory regarding how performance scales with experience and resources, and at what write and compute cost. They differ in one essential respect. All writes share the same parameters, so new writes alter how earlier content is read out. Accumulating experience therefore adds usable content while simultaneously increasing the probability that existing content is overwritten. We build this property into the scaling relation and propose a parametric counterpart to Equation (4.2).

Evidence for the capacity term. Experiments that hold the foundation model fixed and enlarge only the memory parameters support the shape of the capacity term. Memory Layers at Scale enlarges the Memory+ value count from 1M to 64M in a 1.3B configuration (Figure 12(a)) [9]. NaturalQuestions accuracy rises from 13.68 to 20.78 and TriviaQA F1 from 42.89 to 62.14, well above a dense model of the same configuration without memory layers (7.76 and 32.64). Between 16M and 64M, however, NaturalQuestions improves by only 0.64 while TriviaQA still improves by 3.47, indicating that the same capacity range places different tasks at different points on the power law. The same work scales memory parameters to 128B on foundation models of at most 8B, showing that memory capacity can far exceed backbone size (though these Memory+ layers are trained jointly during pretraining, so sequential deployment writes remain to be tested separately). Direct functional evidence comes from LoRA memorization. Treating LoRA rank 𝑟 as a capacity probe, a recent study reports a power law ΔL = 𝐶 𝑟 𝛼 ℓ−𝛽 + 𝑏 that links the loss reduction to rank and sequence length ℓ across models, datasets, and semantic densities ( 𝑅 2 > 0.98) [138]. The relation contains both a capacity variable and a load variable. If 𝛼 ≈ 𝛽 , it reduces to a function of 𝑟 /ℓ, the dependence on the load ratio that Equation (4.8) predicts; whether the two exponents coincide is therefore a direct test of the proposed form. The same study shows that capacity alone does not determine what is stored. By storing past interac-tions, execution outcomes, and environmental states, memory gives agents a stable basis for future decisions. 5.1 Lifelong Personalization and Companion Agents 

Personal agents must adapt as users change. Over time, schedules shift, learners build skills or form misconceptions, health symptoms evolve, and interpersonal bonds deepen. To remain useful, an agent must update its internal model of the user and use this state to guide dialogue, planning, and tool calls. 

Personal assistants. Assistants use cross-session logs to maintain conversational continuity and match individual style. Retrieving user profile items directly improves generation on tasks like email drafting and news summarization [92], while modeling complete interaction histories captures personal tone and habits [68]. Crucially, assistants must track when facts expire. Recent systems update user facts across conversations [7], decay memory strength over time [167], record user feedback alongside its valid context [152], and organize changing user states through causal links [84]. These mechanisms ensure that assistants preserve core preferences while promptly reflecting new changes. 

Tutoring agents. Tutoring agents track what a student knows and where they struggle. For exam-ple, ScaffoldLM stores pedagogical goals, step-level progress, and inferred misconceptions in an assessment memory, selecting the next hint based on the learner’s latest response [63]. Similarly, versioned student profiles track skill mastery, error patterns, and review schedules to calibrate hints and spaced practice [25]. Updating student profiles in real time allows agents to adjust lesson pacing, hint specificity, and problem difficulty on the fly. 

Health follow-up and emotional companionship. Memory directly underpins long-term care and companionship. In a ten-week study of 147 real-world users (1,252 calls), the CareCall system used memory to revisit past health complaints and life events. This continuity encouraged users to disclose more health details and build trust [51]. Studies on Replika users show that social bonding varies widely in depth and pace, meaning companion agents cannot rely on static facts alone [97, 98]. 31 5.2 Evolving Problem-Solving in Long-Horizon Digital Environments Effective companionship requires referencing shared moments and conversational routines. For instance, recent agents infer implicit emotional needs and retrieve relevant shared memories to offer proactive comfort [34]. 

From personalized generation to tool use. Personalization extends beyond text generation to planning and tool execution. Dual-reflection mechanisms build user memory banks that accu-rately route past preferences to current prompts [103]. In tool-augmented setups, benchmarks like Mem2ActBench test whether agents can translate past dates, locations, and habits into correct API parameters [93]. Through memory, personalization becomes a continuous feedback loop: each interaction updates the user model, which in turn steers the agent’s next action. 

5.2 Evolving Problem-Solving in Long-Horizon Digital Environments 

Digital tasks often span multiple web pages, applications, and execution steps. Web research requires tracking checked links and active filters; desktop tasks coordinate code editors, terminals, and spreadsheets; and software engineering requires navigating evolving codebases. In these settings, continual learning serves two needs: resuming interrupted workflows and transferring problem-solving strategies across tasks. Memory tracks progress to ensure task continuity, while abstracting successful runs into reusable skills and debugging routines. 

Web automation. Web navigation offers an ideal testbed for workflow reuse. For example, AWM distills reusable workflows from successful web trajectories and feeds them into future runs [121]. Across 200 domains (such as shopping and travel), this approach raised success rates by 24.6% on Mind2Web and 51.1% on WebArena while cutting overall action steps. Online-learned routines— like filtering products or comparing flight routes—readily transfer to new websites with similar structures. 

Desktop and cross-application tasks. Desktop agents require both state tracking and skill reuse across applications. Systems like OS-Copilot store verified tool scripts in procedural memory [131], while other architectures combine past execution traces with hierarchical planning to navigate unfa-miliar interfaces [1]. Similarly, Trace2Skill distills raw trajectories into executable skill documents, demonstrating reuse across spreadsheet operations, vision-language tasks, and math reasoning [83]. For task continuity, OpenHands logs commands, file diffs, browser events, and user inputs into a unified event stream [115]. This complete history lets coding agents resume interrupted jobs without losing context. Together, these systems show that combining execution logs with procedural skills supports complex, multi-app workflows. 

Software engineering. Software engineering scales these demands to entire codebases. Coding agents must understand repository structures while logging inspected files, failed patches, and unit test outputs. SWEMem uses issue progress to selectively compress context, keeping context windows manageable during extended debugging sessions [36]. To transfer knowledge across bugs, SWE-Exp extracts debugging strategies from both successful and failed repairs to guide new GitHub issues [16]. Thus, memory maintains local focus within a single bug fix while transferring repair strategies across the repository. 

Experience distillation and strategy reuse. Through trial and error, digital agents turn raw exe-cution traces into reusable strategies. Recent frameworks extract high-level rules from repeated attempts, attach clear trigger conditions to guidelines, and index strategies derived from both successes and failures [35, 85, 163]. Terminal outputs, browser states, and test suites provide imme-diate feedback to test whether an extracted rule works. In short, memory gives digital agents two capabilities: it keeps long-horizon jobs from derailing, and it turns past mistakes into faster future execution. 

5.3 Continuous Exploration in Embodied and Open Worlds 

Embodied agents must track a dynamic physical world while expanding their motor skills. Robots navigating homes must remember shifted furniture; robotic arms must adapt to unfamiliar tools; and open-world agents must set new goals as they explore. These tasks require two memory systems: a world-state memory that updates with visual observations, and a skill memory that stores reusable behaviors. Together, they allow agents to map their surroundings and master complex actions. 32 5.4 Collaborative Evolution via Shared Multi-Agent Memory 

Long-term navigation and scene understanding. Mobile robots rely on spatial memory to navigate and track dynamic scenes. For example, RememBR indexes video clips with spatial and temporal tags, allowing robots to answer queries about past object locations during navigation [5]. Similarly, EmbodiedVideoAgent combines egocentric video, depth, and pose data into an object-centric memory, updating object states as interactions occur [31]. This structured memory boosts benchmark scores on Ego4D-VQ3D, OpenEQA, and EnvQA, and directly guides grasping, navigation, and placement. Historical observations thus become an editable 3D world model. 

Open-world exploration. In open worlds like Minecraft, agents must learn complex behaviors without human supervision. Voyager implements this by proposing new tasks, writing executable skill code, and saving verified skills into a library [111]. This skill bank helped Voyager discover 3.3 × more items and unlock tech-tree milestones 15.3 × faster than baselines. Crucially, the saved skill library lets agents solve unseen tasks from scratch in brand-new worlds. In text worlds like ScienceWorld, CLIN abstracts action outcomes into causal rules to guide future planning [76]. By saving executable code and causal patterns, exploration continually feeds subsequent skill acquisition. 

Cross-task and cross-embodiment adaptation. Manipulating physical objects requires sample-efficient learning. RoboCat addresses this by pooling experience across different simulated and real robot arms [11]. The model learns a generalist policy, generates self-supervised data on new tasks, and feeds these runs back into training. Across this self-improving training loop, success rates on unseen tasks (after fine-tuning on 500 demonstrations) rose from 36% with the initial model to 74% with the final RoboCat model. Pooling data across diverse robot hardware shows that cross-embodiment memory drastically cuts the demonstrations needed for new tasks. 

Robot fleets. Robot fleets turn shared deployment into collective policy updates. In a 16-robot setup, autonomous trajectories and human teleoperation interventions are pooled to train a single generalist policy, which is then flashed back to the fleet [116]. Across eight manipulation tasks— including grocery restocking routines lasting 3–5 minutes—accumulated fleet data pushed success rates to 95%. Field deployment thus acts as a continual training engine, linking individual robot trials to fleet-wide policy improvements. 

5.4 Collaborative Evolution via Shared Multi-Agent Memory 

Multi-agent systems require shared memory to coordinate specialized roles. Software teams must log architectural decisions; data teams need to track data provenance; and scientific teams must record hypotheses, lab results, and reviews. Storing these records in a shared memory pool prevents redundant effort and lets agents reuse established workflows and team roles. Memory acts as the team’s shared workspace, linking past findings to current tasks. 

Cross-task collaboration procedures. Shared procedural memory allows teams to reuse proven collaboration patterns. G-Memory organizes multi-agent interaction histories into a three-tier graph of dialogues, queries, and insights, letting agents retrieve both raw traces and abstract lessons [154]. Across five benchmarks, this structured memory improved embodied task success and question-answering accuracy. Similarly, LegoMem splits memory into orchestrator and worker tiers: orchestrator memory sharpens task decomposition, while worker memory improves tool-use accuracy [43]. Reusing execution traces even helps teams of smaller LLMs match the performance of proprietary models. 

Member expertise and selective sharing. Teams also benefit from remembering which agent is good at what. ## 6 Open Challenges in Memory-Centric Continual Learning 

6.1 Predicting Experience Value and Long-Term Credit Assignment 

Current agents still rely on handcrafted heuristics rather than learned policies 𝜋 mem . The main obstacle is delayed credit assignment. When an agent records an event at step 𝑡 , it must decide three things: whether to save it, how to format it, and what metadata to keep. As a result, final task success reflects a long chain of memory actions, not a single write. This delay blurs the credit signal. Agents can easily reflect using prompts, but they struggle to train policies that decide what to keep, update, or delete [10, 140, 149]. Agents must weigh the future payoff of an experience against storage size, search latency, and the risk of confusion [49, 73, 96, 124, 156]. Recent surveys map out how memory is written, managed, and read [28, 49, 50, 129, 169]. Yet we still lack a principled way to balance these costs and benefits over time. Most existing methods rely on simple shortcuts: (1) rules based 34 6.2 The Stability–Plasticity Dilemma in Dynamic Environments on recency, frequency, or text similarity [73, 129]; (2) learning to call tools like store, search, or summarize [119, 149, 155, 161]; or (3) hard budgets on context size [124, 156, 169]. These shortcuts only look at the current prompt or immediate reward. They ignore delayed returns, distribution shifts, and interactions between co-retrieved memories. Saving bad data pollutes the store, triggers negative transfer, and hurts future tasks [47, 96, 122, 124, 143, 148]. Three practical hurdles prevent delayed rewards from training 𝜋 mem :• Predicting value before writing. At write time, the agent does not know future queries or tasks. Dropping an experience loses information permanently. Keeping bad data pollutes the store. The policy must forecast long-term utility using only local, present clues [10, 28, 96, 124]. • Tracing failure back through the pipeline. Final errors stem from many sources: poor admission, lossy summarization, bad retrieval, or weak reasoning. When an agent fails, it is hard to isolate whether memory or reasoning caused the error [3, 10, 28, 50, 140, 153]. • Path dependence across runs. Every write or delete alters the memory state for future sessions. Different rollouts no longer share the same environment. This variance breaks standard reinforcement learning assumptions and destabilizes training [140, 143, 148, 149, 153]. Solving these hurdles requires optimizing for long-term net value. For write-time prediction, agents can learn value models on task streams, using scaling curves to judge marginal returns [10, 96, 132, 169]. To trace errors, systems can log write decisions, run ablation tests, and keep links from summaries back to raw source episodes [10, 28, 50, 96]. To handle path dependence, agents can branch rollouts from identical memory checkpoints and use hindsight critics [102, 124, 140, 149, 156]. The ultimate goal is closed-loop control: task feedback should update not just what the agent remembers, but how it manages memory. 

6.2 The Stability–Plasticity Dilemma in Dynamic Environments 

External memory gives agents a way to learn continually at the system level. Like classic continual learning, it aims to acquire new capabilities, preserve old knowledge, and transfer skills [73, 135]. As noted in Section 2.1, parametric learning updates model weights, while agent memory updates external records at inference time. However, external stores do not remove the stability–plasticity dilemma; they simply relocate it [47]. Here, interference occurs during retrieval and prompt construction. A loose write policy (Section 3.1) boosts plasticity by saving new records quickly, but it also clutters storage with duplicate and conflicting entries. Under fixed retrieval budgets, this clutter crowds out useful memories. In the cascade of Section 4.1.1, saving more records (Gate 1) hurts retrieval accuracy (Gate 2). Even when retrieved, outdated facts can lead the model to ignore correct updates or apply old rules to wrong tasks (Gate 3) [47, 56, 65, 153]. Stability means keeping valid memories easy to find and use. Plasticity means updating old facts without breaking what already works. This trade-off sharpens as memory expands. More interactions can help agents learn [85], and periodic cleaning keeps stores lean [146]. Yet larger stores always raise the risk of retrieval noise. We should judge memory scaling by task gains under fixed compute budgets, not by raw storage volume. Measuring these trade-offs requires long-term benchmarks. Recent benchmarks test specific skills, such as fact updates in LongMemEval [125] or task transfer in Evo-Memory and LifelongAgent-Bench [122, 165]. As outlined in Section 4, evaluations should track retention, forward transfer, and negative interference across shifting task streams. Beyond final accuracy, tracking survival rates, retrieval ranks, and actual memory usage against frozen-memory baselines shows whether memory truly helps or quietly harms performance. The core question is direct: How can agents keep memories accurate and relevant as experience grows? 

Promising paths include write filters that prevent clutter, consolidation that checks raw evidence, and retrieval that matches the exact conditions where an experience applies [47, 65, 153]. 35 6.3 Synergistic Continual Learning through Experience Memory and Parametric Learning 

6.3 Synergistic Continual Learning through Experience Memory and Parametric Learning 

Continual learning requires coordinating external experience with internal model weights. Today, agents treat them as two separate systems. External memory stores new facts quickly without touching model weights [19, 95, 136]. Parametric fine-tuning bakes patterns into weights for broad generalization, but risks catastrophic forgetting [94, 127]. Recent work connects the two sides by extracting reasoning paths into external memory or fine-tuning lightweight adapters [42, 44, 85, 164]. Yet information flows mostly one way: from raw episodes into weights or static stores. Systems cannot easily edit, roll back, or delete parametric knowledge once written. Human memory works differently. In biology, recalling a consolidated memory makes it flexible again, meaning the brain must actively restabilize it (a process called reconsolidation) [81]. Neural networks lack this feature; once weights change, they stay fixed until the next gradient step. The key missing piece is the bridge between raw experience and parametric weights . An agent should first test and summarize experiences in external storage. Only repeatedly verified patterns should enter model weights. Conversely, when existing weights fail on new evidence, the agent must pull that knowledge back into explicit text to inspect and fix it. This cycle follows Complementary Learning Systems (CLS) theory: fast learning in the hippocampus and slow integration in the cortex interact via replay to balance plasticity and stability [57, 77, 123]. Furthermore, the brain does not store every event; synaptic tagging-and-capture shows that novelty and reward flags decide which synapses undergo lasting change [33]. Future systems should build a two-way learning loop across three clear steps: 1. Selection : Filter raw traces by novelty, utility, and frequency—like synaptic tagging—before keeping them. 2. Consolidation : Replay, abstract, and bake verified memories into model weights via modular adapters. 3. Revision : Test weights against new facts, reopen outdated knowledge for correction (like reconsolidation), and use schemas to absorb new rules quickly [105]. Instead of treating memory and weights as separate silos, agents need clear algorithms that pass knowledge back and forth between them. 

6.4 Trustworthy Memory Governance in Lifelong Deployment 

While methods for writing and searching memory have matured, memory safety and control lag behind. Few studies address access control, rollback, or secure deletion, even though real-world deployment risks center on these exact areas [26]. Without explicit governance, security risks spread across every stage of the memory lifecycle: • Formation : Attackers can inject malicious text through poisoned web pages or prompt injection. Without write checks, agents save these instructions as trusted facts, corrupting future actions (Section 3.1) [17, 27, 104]. • Consolidation : When agents summarize logs into general rules, they often drop timestamps and source links—a failure known as context collapse (Section 3.2). As a result, a single poisoned prompt can turn into a permanent, trusted behavioral rule. • Retrieval : Corrupted memories can hijack tool calls and override user instructions during normal tasks [137], or leak private data across users in shared stores [141]. This shows why retrieving a memory is different from using it safely (Section 3.3). • Forgetting : Deleting a raw record does not remove its downstream traces, such as sum-maries, fine-tuned weights, or knowledge graphs (Section 3.4) [66]. Bad behavior can persist long after the original entry is gone [26]. Memory control is hard for three reasons: (1) Expanding scope : As agents gain more tools and autonomy, attack surfaces constantly shift [168]. (2) Delayed impact : The gap between a poisoned write and an attack can be weeks or months. Summarization hides original sources, making it hard 36 7. Conclusion to trace who wrote what [66]. (3) Direct trade-offs : Strict privacy checks and audit logs slow down search and increase token costs [60]. Recent work introduces basic defenses: write permissions, provenance logs, user-isolated retrieval, and verified rollback [66]. Yet evaluation still falls short. Most benchmarks only score task success, giving developers little reason to build safe memory systems [26]. In addition, self-reflection remains hard to verify from the outside, and shared memory in multi-agent setups lacks clear access rules [109, 141]. To build reliable agents, governance must cover the full lifecycle: • Formation : Verify sources and permissions before writing, rather than filtering data after problems occur [66]. • Consolidation : Borrow ideas from database recovery and belief revision to prevent agents from dropping critical source context during summarization [26]. • Retrieval : Sandbox tool execution and enforce role-based access for shared multi-agent stores [109, 141]. • Forgetting : Use clear metrics—such as stress tests and recovery targets—to prove that deleted data and its side effects are truly gone [26]. Governance cannot remain an afterthought; it must become a testable, built-in guarantee of agent systems. 

## 7 Conclusion 

In this paper, we reframe agent memory as an evolving learning infrastructure for continual learning, rather than a passive storage or retrieval component. We argue that experience accumulation cannot be equated with static recall, but requires a closed-loop dynamic of retention, adaptation, and transfer, explaining why current memory agents fail under delay, interference, and environmental drift. To address this, we establish a unified framework spanning physical substrates, reusable assets, and lifecycle policies, coupled with a behavior-centric evaluation methodology to isolate genuine experiential gains and a memory scaling law that relates those gains to experience and memory resources. By adopting this memory-centric lens, the field shifts its central question from whether an agent can remember to whether it can continually learn, paving a more principled path towards building resilient, self-improving intelligent systems.
