## 摘要
用户常常在不知道相关数据存储于哪个数据库或表中的情况下请求生成图表。这类请求可能含义模糊，用户也可能提出后续问题以深入分析，或通过迭代对已有图表进行优化。因此，实用的助手必须能够从异构数据库中发现相关数据源，在需要时提出澄清问题，并跟踪不断变化的用户意图，同时保留此前对话轮次中确立的约束。然而，近期的文本到可视化智能体通常依赖预先定义且固定不变的智能体框架，即使在不同任务中反复出现失败，这些框架也不会随之调整。为解决这一局限，我们提出 RSIV-Harness：在保持语言模型权重固定的同时，利用递归自我改进，根据智能体自身的失败轨迹修订其外围框架。为兼顾自我改进的灵活性与稳定性，我们提出一个四层框架，通过锚点检查和记忆检查评估拟议的框架修订；对通过检查的修订进行完善，否则恢复至效果最佳且经过验证的框架。我们还提出 ODAC-Vis，这是一个包含 640 项任务的基准，用于开放域、含义模糊及对话式文本到可视化任务，并联合评估开放域数据发现、歧义消解、多轮可视化优化以及可执行图表生成。实验表明，与初始框架相比，RSIV-Harness 仅经过一轮迭代便提升了全部六项评估指标，其中可执行性（+28.02 个百分点）和图表结构（+34.01 个百分点）的提升尤为显著，展现出其从任务解决经验中学习、将跨任务反复出现的失败转化为显著性能提升的能力。

## Abstract
Users often request charts without knowing which database or table holds the relevant data. Such requests may be ambiguous, and users may ask follow-up questions to deepen their analysis or iteratively refine existing charts. A useful assistant must therefore discover relevant data sources among heterogeneous databases, ask clarifying questions when needed, and track evolving user intent while preserving constraints established in earlier turns. Yet recent text-to-visualization agents typically rely on static agent harnesses that are predefined and remain unchanged despite recurring failures across tasks. To address this limitation, we introduce RSIV-Harness, which keeps the language model weights fixed and applies Recursive Self-Improvement to revise the surrounding harness from the agent's own failure traces. To balance flexible self-improvement with stability, we introduce a four-layer framework that evaluates proposed harness revisions through anchor and memory checks, refining those that pass and restoring the best validated harness otherwise. We further introduce ODAC-Vis, a benchmark with 640 tasks for Open-Domain, Ambiguous, and Conversational text-to-visualization that jointly evaluates open-domain data discovery, ambiguity resolution, multi-turn visualization refinement, and executable chart generation. Experiments show that a single round of RSIV-Harness improves all six evaluation metrics relative to the seed harness, with particularly large gains in executability (+28.02 points) and chart structure (+34.01 points), demonstrating the ability to learn from task-solving experience and turn recurring failures across tasks into substantial performance improvements.

## 1. 核心问题与研究背景

### 1.1 真实对话式制图面临的挑战

论文关注开放域对话式文本到可视化，即用户通过自然语言提出分析需求，由系统发现数据、查询并生成图表。实际使用中存在三个相互关联的问题：

- **数据源未知**：用户通常不知道目标数据库或表，系统需要在多个数据库中定位数据，必要时跨库组合。
- **需求含糊**：例如“展示销售趋势”没有确定销售口径、时间粒度或图表类型，需要先澄清。
- **多轮约束累积**：用户可能不断深入分析或修改图表，系统必须保留此前确定的筛选条件、指标和视觉编码。

### 1.2 现有方法的不足与本文定位

- 现有基准往往分别研究数据库检索、歧义处理或多轮制图，缺少统一的端到端评估。
- 现有智能体通常使用静态 **Harness（模型外围运行框架）**。即使反复出现提前生成代码、错误检索模式或跨库操作违规等问题，其提示词、工具和控制逻辑仍然不变。
- 单次任务中的错误修复并不等于跨任务学习；更新模型权重又会增加成本。

**本文的整体含义**是：将改进对象从模型参数转移到外围运行框架，通过“失败分析—自动修改—验证—提交或回退”，实现可持久保留的系统级改进。

## 2. 方法论：核心思想与算法流程

### 2.1 固定模型、演化外围框架

RSIV-Harness 将可修改对象划分为五类：

| 组件 | 主要作用 |
|---|---|
| Prompt | 定义任务指令、行为规范和输出要求 |
| Tool | 提供数据库发现、查询和代码执行接口 |
| Memory | 保存对话状态、任务证据及相关上下文 |
| Skill | 提供领域知识和查询、制图技能 |
| Middleware | 管理执行流程、上下文压缩、安全和错误反馈 |

模型权重保持不变，外层改进过程根据执行轨迹，自主决定修改哪些组件以及如何修改。

### 2.2 内循环：完成当前对话轮次

内循环采用 **ReAct** 式的推理—行动—观察流程：

1. 读取当前请求、历史对话及已获得的数据证据。
2. 调用工具寻找相关数据库、表和字段。
3. 判断应当提出澄清问题，还是直接生成制图程序。
4. 对程序进行检查并在沙箱中执行。
5. 若执行失败，将具体错误反馈给模型，在预算内重写程序。

关键设计包括：

- 每个对话轮次具有最大行动步数和代码修复次数。
- 同一轮修复保留已获得的数据源证据，避免重复探索。
- 若引入上下文更新机制，压缩后仍应保留有效证据、被排除的数据源及对话约束。
- **内循环只修复当前程序，不修改 Harness**；持久性修改由外循环完成。

### 2.3 外循环：从跨任务轨迹生成候选修改

外循环流程如下：

1. 在固定、分层抽取的训练任务面板上运行当前框架。
2. 收集轨迹，并按照违反的任务要求聚类失败。
3. 结合受保护的成功记录和上一轮拒绝原因，分析改进方向。
4. 由提案模型生成候选框架，每次限制修改数量，并要求说明修改组件及其针对的失败证据。
5. 通过记忆检查和验证锚点检查后提交；否则继续有限次修正，最终失败则回退。
6. 提交后重新运行训练面板，更新受保护记录，供下一轮使用。

### 2.4 四层稳定机制

| 机制 | 具体作用 |
|---|---|
| **Refine：改进规则** | 接受候选后部署新版本，更新受保护记录，并继续关注未解决失败 |
| **Restart：重启规则** | 拒绝候选后恢复历史最佳验证版本，保留拒绝原因，不更新保护记忆 |
| **Anchor Check：锚点检查** | 候选在固定验证面板上的任务成功率，不得低于历史最佳分数的容忍下界 |
| **Memory Check：记忆检查** | 对历史成功的“任务—轮次—指标”记录分层抽样，限制候选发生退步的记录数 |

两个关键判断可用文字概括为：

- **锚点约束**：候选验证分数至少达到“历史最佳验证分数 ×（1－容忍比例）”。
- **记忆约束**：抽样保护记录中，低于历史基线的记录数不能超过预设阈值。

其中，“当前部署版本”可以略低于历史最佳，但必须位于容忍区间；“冠军版本”只有在验证分数严格提高时才更新。

### 2.5 理论保证的范围

论文证明了接受后更新记忆、拒绝后回退、最佳锚点分数不下降，以及抽样保护记录退步数有界等性质。

**这些保证主要是规则执行层面的不变量**，不意味着：

- 未见任务上的性能必然提升；
- 所有历史成功行为都不会退步；
- 当前部署版本的成绩始终单调上升；
- 系统能够无限递归改进。

  - 表 3 初始 DeepSeek 框架可执行性为 **64.98**，表 4 的 \(H_0\) 为 **51.36**；其他对应指标一致，文中未解释原因。
  - 领域划分叙述强调领域隔离，但表 2 给出训练、验证分别使用 **124、96** 个领域，总共又仅有 139 个领域、其中 15 个测试领域。训练与验证是否完全领域互斥需要澄清。

## 6. 主要结论与发现

### 6.1 DeepSeek 上六项指标相对初始框架全部提高

以下采用表 3 数据：

| 指标 | 初始框架 | RSIV-Harness | 提升 |
|---|---:|---:|---:|
| 可执行性 | 64.98 | 93.00 | +28.02 |
| 数据库路由 | 48.25 | 62.26 | +14.01 |
| 响应模式 | 51.25 | 67.00 | +15.75 |
| 执行准确率 | 24.51 | 31.52 | +7.01 |
| 澄清质量 | 3.72 | 5.15 | +1.43 |
| 图表结构 | 41.46 | 75.47 | +34.01 |

- 相比各列最强竞争基线，RSIV-Harness 在 **六项中的五项**领先。
- 执行准确率 **31.52** 略低于 Direct Prompt 的 **31.91**。
- 因而，“六项全部提升”应理解为**相对初始框架**，而非全部超过最强基线。

### 6.2 跨模型迁移有效，但存在边界

- 同一框架迁移到 GPT 后，相比静态 GPT 框架改善五项指标。
- 执行准确率从 26.07 降至 25.29。
- 与最强 GPT 基线相比，大多数指标仍稍低，仅澄清质量最好。

这支持框架改进具备**一定可迁移性**，但尚不能证明其与骨干模型无关。

### 6.3 稳定规则与组件协同有贡献

- 去除稳定规则后，六项指标均下降，可执行性下降 9.73 点、图表结构下降 9.53 点。
- 单组件分析中，Middleware 对可执行性等指标作用突出，Prompt 对路由和图表结构改善明显。
- 完整框架在五项指标上优于所有单组件配置，路由指标与最佳单组件持平。

### 6.4 “可运行”仍显著领先于“分析正确”

最终可执行性达到 **93.00**，执行准确率却只有 **31.52**。这说明框架演化主要解决了程序和流程可靠性问题，**数据选择、查询语义和分析正确性仍是核心瓶颈**。

## 7. 优点与亮点

- **问题贴近实际工作流**：联合研究找数据、澄清需求和多轮修改，而不是只生成一次图表。
- **改进对象明确且模块化**：不依赖权重更新，可针对工具接口、控制流程等实际故障源进行修复。
- **区分局部修复与持久学习**：避免将单次重试成功等同于智能体获得长期能力。
- **采用可回退的验证机制**：兼顾整体任务成功率与局部历史能力保护。
- **监督可执行、可追踪**：每个代码轮次关联查询结果和参考图表，比单纯文本评价更扎实。
- **评估使用模型自身历史**：能体现错误沿多轮对话传播的真实影响。
- **结论包含负面结果**：报告了执行准确率未超过 Direct Prompt、跨模型迁移并非全面领先等限制。

## 8. 不足与局限

### 8.1 长期自我改进尚未得到验证

- 仅一轮演化不足以证明“递归自我改进”的长期效果。
- 所谓防振荡保证仅限制**本轮抽样保护记录**的退步，不覆盖完整历史与未知任务。
- 保护记忆容量有限，旧记录可能被淘汰；已有记录保留原始基线，也不必然保护后续达到的最佳水平。
- 最佳分数单调主要来自版本管理规则，而非对真实泛化能力的理论保证。

### 8.2 基准存在合成和模板偏差

- 对话由模板与 LLM 构造，可能偏向规则清晰、澄清后唯一确定的需求。
- 真实用户的反悔、回答不完整、多个合理答案及隐含偏好覆盖不足。
- 示例中“将柱状图改为折线图”被视为需要重新确定指标，但实际交互中也可能合理地默认继承原指标。这提示部分歧义标签具有设计者假设。

### 8.3 指标有效性有局限

- 澄清 BLEU-4 衡量词面重合，难以准确反映问题是否真正消除歧义；未采用长度惩罚也可能影响评价。
- 图表结构的等权评分不能充分代表易读性、视觉误导风险和实际决策价值。
- 查询结果等价只验证当前数据库上的结果，不必然证明查询在其他数据实例上语义正确。

### 8.4 公平比较与可复现性仍需加强

- 缺少调用预算、成本、随机性和关键超参数披露。
- 缺少具体修改补丁、完整失败聚类及版本演化记录，难以深入核验自动改进来源。
- 表格及划分描述不一致需要作者澄清；正文保留 ACM 年份、会议名及 DOI 占位符，也反映稿件尚需整理。

### 8.5 真实应用范围尚有限

- “开放域”仍指一个可访问的固定数据库集合，不等于现实中的开放网络或企业数据平台。
- 仅覆盖 SQLite、SQL 和 Plotly，未检验大型仓库、异构 API、权限治理、隐私和数据更新。
- 没有真实用户研究，尚不能证明其降低了澄清负担、提高了分析效率或用户信任。

**总体评价**：本文最有价值的贡献是提出并验证了一个方向——**将跨任务失败转化为经过回归检查的外围框架修改**。现有证据较有力地支持代码可执行性和图表结构改善；但长期递归收益、语义正确性、真实用户价值和成本优势，仍需更广泛且更严格的实验验证。
