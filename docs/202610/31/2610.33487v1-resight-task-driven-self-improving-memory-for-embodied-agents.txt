ABSTRACT
Robots can use historical observations to answer spatiotemporal queries in fa-
miliar environments, but the presence of relevant evidence does not imply that
existing tools support the operations a task requires. We introduce ReSight, a
task-driven self-improving memory system for embodied agents that expands the
capabilities for processing and accessing historical observations as task demands
arise. ReSight retains keyframes and their spatiotemporal associations, separating
observation evidence from extensible derived fields so that stored observations
can be reprocessed for new needs. An execution agent and a coding agent share
this memory through different interfaces: the former calls registered tools within
a bounded online budget, while the latter uses a programmable workspace and a
larger exploration budget to inspect evidence, write programs, and acquire mod-
els as needed. To realize capability expansion in ReSight, we develop Explore–
Distill–Mount (EDM), which identifies capability gaps from execution and ex-
ploration records without task reference answers and converts exploration-derived
solutions into reusable memory builders, query tools, and skills, extending mem-
ory representations and access capabilities as needed. Experiments on three public
benchmarks demonstrate effective base memory access and capability expansion.
With the execution model and online budget held fixed within each benchmark,
EDM reduces mean position error on OC-NaVQA from 33.10 m to 24.72 m and
improves high-level success on FindingDory from 38.3% to 63.8%. With the tools
and skill frozen, success still improves by 28.3 percentage points on FindingDory
episodes excluded from exploration and distillation. Experiments on real robot
patrol memories further demonstrate reuse of these capabilities for subsequent
queries and new memories, with fewer online tool calls on average.

INTRODUCTION
Long-horizon robot tasks such as fetching and delivery often begin with a decision about where
to go to satisfy a request. In previously visited environments, past observations can inform this
choice. Finding emergency equipment requires recalling where it was seen; finding an object that
has moved also requires distinguishing observations from different times. Such place selection
depends on spatiotemporal question answering over memory, whose outputs can guide subsequent
navigation and manipulation. We study tasks whose relevant evidence is already present in retained
observations: how can an agent find, interpret, and combine that evidence to answer the current
query?
Embodied memory takes several forms, including scene graphs for structured queries and visual
memories associated with time and position (Gorlo et al., 2026a; Hu et al., 2026).
Retained
keyframes also allow object localization and representation construction to be deferred until query
time (Zhou et al., 2026; Maggio et al., 2026). These approaches provide a basis for finding relevant
observations, but the computation required by a task may exceed the capabilities of the available
tools. Semantic retrieval may return images of a corridor, while distinguishing similar doors re-
quires reading their signs. After retrieving several observations of an object, determining where it
stayed longest requires organizing events across time. A task exposes a capability gap when the
execution agent cannot readily perform these operations with its existing tools and online budget.
We introduce ReSight, which combines revisitable spatiotemporal evidence with extensible mem-
ory capabilities. Unlike a fixed memory interface, ReSight can later acquire operations such as text
reading, interaction-history reasoning, and object localization by reprocessing observations that are
already stored. Its spatiotemporal evidence memory retains selected keyframes and their temporal
associations, together with available observations such as poses and depth. Scene and object de-
scriptions, along with visual and text features, form initial semantic fields for retrieval. Subsequent
needs can prompt new processing of stored images to derive text, event, or geometric fields while
preserving their links to source observations. This late binding allows interpretation and compu-
tation to evolve after observations have been stored, and lets memory builders and query tools be
developed together for a new task requirement.
ReSight separates online response from capability development through two agents (Figure 2). The
execution agent treats the evidence memory as a database accessed through registered tools, using
skills to guide retrieval, inspection, and answering within a bounded online budget. The coding
agent treats the same memory as a programmable workspace: it can inspect files and images, write
and execute code, and download and install models and dependencies. A separate, larger explo-
ration budget allows it to develop solutions for requirements that are difficult for the current execu-
tor. The two agents work with the same evidence, carrying out bounded execution and open-ended
exploration, respectively, providing a basis for turning exploration-derived solutions into reusable
capabilities for the executor.
ReSight implements task-driven capability expansion through Explore–Distill–Mount (EDM). Prior
work uses execution traces to improve programs, skills, and memory-management mechanisms (Lu
et al., 2026; Lee et al., 2026; Zhang et al., 2025b). EDM combines execution-side capability gaps
with coding-agent exploration traces to extract reusable tools, skills, and memory builders for re-
tained sensor evidence. Builders reprocess stored observations to produce persistent fields and in-
dices; corresponding query tools and skills are mounted on the execution agent so it can use the new
capabilities.
Our contributions are as follows:
• We introduce ReSight, which retains revisitable spatiotemporal observations and provides
distinct access interfaces for execution and coding agents, allowing historical observations
to be reprocessed for new task demands and memory representations and access capabilities
to be extended as needed.
• We propose Explore–Distill–Mount (EDM), which identifies capability gaps from execu-
tion and exploration records without task reference answers and converts the coding agent’s
exploration-derived solutions into reusable tools, skills, and memory builders.
• We evaluate ReSight’s base memory access, task-driven capability expansion, and frozen-
capability reuse on three public benchmarks and real robot patrol memories. With the

RELATED WORK
2.1
SPATIAL REPRESENTATIONS AND TARGET LOCALIZATION
Open-vocabulary maps associate language-aligned features with spatial locations for text queries
and target localization (Huang et al., 2023; Peng et al., 2023; Jatavallabhula et al., 2023). Con-
tinuous semantic fields, multimodal feature memories, and 3D object instances offer alternative
representations (Shafiullah et al., 2023; Zou et al., 2025; Takmaz et al., 2023). Scene graphs orga-
nize object relations and spatial hierarchies (Gu et al., 2023; Werby et al., 2024), while dynamic
point clouds, spatiotemporal maps, and description histories capture environmental changes (Liu
et al., 2025; Schmid et al., 2024; Gorlo et al., 2026a). Task-driven representations adjust semantic
granularity according to predefined tasks or subsequent queries (Maggio et al., 2024; 2026).
2.2
LONG-HORIZON VISUAL MEMORY AND RETRIEVAL
Observation descriptions, event records, and object tracks can form queryable long-term memo-
ries (Anwar et al., 2024; Xie et al., 2024; Fan et al., 2024); multi-view snapshots, visual embed-
dings, and keyframe-augmented scene graphs retain visual context (Yang et al., 2024; Hu et al.,
2026; Werby et al., 2026). Semantic-spatial retrieval and memory fusion further select and integrate
relevant information (Mao et al., 2025; Hu et al., 2025b). Recorded tours can supply goal frames
for navigation (Chiang et al., 2024), and retrieved RGB-D keyframes support on-demand target
localization (Zhou et al., 2026); prediction error can guide which events are stored (Gorlo et al.,
2026b). ReSight retains sensor observations as reprocessable evidence and adds structured fields as
subsequent needs arise, allowing memory processing and access capabilities to expand.
2.3
PROGRAMMATIC PROBLEM SOLVING AND HARNESS EVOLUTION
Programmatic agents compose perception, control, and computation through code (Liang et al.,
2023; Sur´ıs et al., 2023), amortize generation costs through tool reuse (Cai et al., 2024), and accu-
mulate skills from execution feedback (Wang et al., 2023; Lu et al., 2026). Automatic improvement
spans prompts and experiential contexts (Agrawal et al., 2026; Zhang et al., 2025d), as well as agent
programs and their organization (Hu et al., 2025a; Robeyns et al., 2025; Zhang et al., 2025c); syn-
thesized code can also constrain action selection or implement policies directly (Lou et al., 2026).
Recent harness evolution draws improvement signals from execution traces and demonstrations (Lee
et al., 2026; Lin et al., 2026; Zhang et al., 2026a; Che et al., 2026), updating tools, runtime mech-
anisms, and component organization (Chen et al., 2026; Zhang et al., 2026b), as well as memory
construction and retrieval programs (Zhang et al., 2025b). EDM synthesizes tools, skills, and mem-
ory builders from execution-side capability gaps and coding-agent exploration traces, extending
retained sensor evidence with spatiotemporal fields and access capabilities reusable during online
execution.

3.2
SPATIOTEMPORAL EVIDENCE MEMORY
ReSight anchors memory in retained RGB keyframes and their associated observations and acqui-
sition context. Available data vary with the robot’s sensors and the benchmark, including temporal
associations, depth, poses, calibration, and synchronization information. We preserve these records
at ingestion, especially information that is difficult to recover reliably from images, for subsequent
processing. Let O denote the retained records, F(0) the initial fields, and X (r) the derived fields and
indices accumulated after r extensions. The memory is
M(r) = (O, F(0), X (r)).
(1)
Initial fields record or reference observation times and available poses, and include descriptions and
features produced during memory construction. A VLM generates scene and object descriptions
for selected keyframes without conditioning on subsequent queries. These capture global scene
semantics and object categories, attributes, and spatial context, respectively. We encode both types
of description into text embeddings and the images into visual embeddings. Fields are linked to
images by frame identifiers; events spanning multiple frames refer to the corresponding observation
sets. Observation poses record camera locations, while object positions can be computed from depth
or multiple views.
Text queries retrieve candidates independently from visual, scene-description, and object-
description embeddings, then combine them by reciprocal rank fusion (RRF). Image queries use
the visual channel. Appendix A.2 details fusion, filtering, and candidate grouping.
Subsequent tasks can introduce fields for OCR, events, or geometry. Memory builders generate
these fields and their query indices from retained observations, and new tools expose the operations
required by a task. We use late binding to describe determining how observations are interpreted and
processed after storage: new programs can reprocess retained records to extract information absent
from initial fields. Initial and Extensions distinguish when fields are introduced, independently of
their source. Depth, for example, may be supplied by a sensor or dataset, or estimated from retained
images.

3.4
EXPLORE–DISTILL–MOUNT
EDM converts execution traces and exploration traces into capability-library updates, implementing
demand-driven harness evolution. Let H denote the execution configuration, including callable
tools, skills that guide their use, and memory builders that produce persistent fields and indices. With
retained records O and the execution model fixed, let sB(q; H) denote the expected task score under
configuration H and online budget B, with higher scores indicating better performance. EDM’s
design objective is to improve performance on capability-gap tasks:
max
∆H Eq∼Dgap[sB(q; H′) −sB(q; H)] ,
H′ = Mount(H, ∆H).
(2)
Here ∆H is the capability extension, H′ the mounted configuration, and Dgap the distribution of
tasks requiring capability expansion. EDM extracts reusable operations from exploration traces and
integrates them with the host. Figure 3 follows one task, counting phone booths from a reference
photo, through the three steps.
Explore: develop a solution.
The coding agent receives an evidence memory with all queries
posed on it and solves them jointly in one session. It inspects images, invokes models, and writes
programs, returning an answer to every query with the programs, notes, and evidence behind it. New
fields may first appear at this stage. For example, the coding agent can run OCR to locate a room
sign and verify the extracted text against the image. Exploration and distillation use observations
and exploration traces without task reference answers.
5


Distill: extract reusable capabilities.
Exploration may interleave scripts, shell commands, direct
file inspection, and decisions based on intermediate results. Distillation turns reusable parts of
this process into operations callable through the execution agent’s registered interface. Failed or
inefficient runs in the executor’s traces locate the difficulties to address. The coding agent reads
the executor’s tool inventory and these traces, reuses existing capabilities, and packages missing or
partially supported operations as tools with explicit inputs and outputs. Reusable preprocessing is
packaged as memory builders.
Mount: integrate with execution.
The distilled tools are registered with the execution agent.
When a skill is mounted, the executor receives it in its system prompt: a short text on when and how
to use the tools. Builder-generated fields and indices are exposed through query tools. For a new
builder b with output Xb, the memory update is
Xb = b(M(r)),
M(r+1) = (O, F(0), X (r) ∪Xb).
(3)
Model initialization and whole-memory processing can precede mounting; query-dependent com-
putation runs when a tool is called. Builders can be rerun when memory data change. Subsequent
tasks use the same execution model and online budget with the updated capabilities.

EXPERIMENTS
We evaluate base memory access on GOAT-core, capability expansion on OC-NaVQA and Finding-
Dory, and reuse on new queries and memories in real-robot patrol experiments.
4.1
EXPERIMENTAL SETUP
ReSight denotes the complete system; w/o EDM and w/ EDM compare the same executor before and
after capability mounting. We also evaluate RAVEN as a second host. Within each OC-NaVQA and
FindingDory comparison, GPT-5.6-sol (Sol) and the online decision-round cap remain fixed. Opus-
5 coding-agent results provide an exploration reference under a separate compute budget. Retrieval
settings appear in Appendix C.3.
4.2
BASE MEMORY DESIGN ON GOAT-CORE
We evaluate ReSight’s initial memory fields and multi-channel retrieval against MoM’s SigLIP2-
only visual-retrieval configuration.
Following the MoM protocol, we evaluate image, object, and language target queries across four
GOAT-core scenes, for a total of 480 queries (Zhou et al., 2026). All reproduced configurations
share the localization backend and return up to five candidates per query. We report SR@5 with a
1.5 m success threshold on the navigation plane. ReSight’s retrieval configuration returns candidates
directly, while its agent configuration can perform further retrieval and inspect images.
Direct retrieval achieves 90.8% SR@5 with Sol annotation and 89.8% with Qwen, above MoM’s
visual-only 81.5%; the agent achieves a similar 90.6% (Table 1). These results support the effec-
tiveness of the initial memory and retrieval design.
4.3
CAPABILITY EXPANSION WITH EDM
We assess EDM on OC-NaVQA and FindingDory through before-and-after comparisons, addition-
ally distilling and mounting capabilities for RAVEN as a second host on FindingDory.
OC-NaVQA.
This benchmark contains 210 questions from seven sequences, covering binary, text,
position, and temporal queries (Gorlo et al., 2026a). Position questions require object coordinates,
whereas ReSight’s base executor returns an observation’s camera pose. EDM adds object-position
estimation among other capabilities; evaluation details appear in Appendix C.3.
EDM reduces mean position error from 33.10 m to 24.72 m and increases the fraction within 10 m
from 19.7% to 36.6% (Table 2). The object-position tool combines image segmentation, depth
backprojection, and multi-view aggregation to return target coordinates with supporting frames (Fig-
ure 4(a)).

Reuse on held-out episodes.
We freeze the tools and skill distilled on episodes 91–100 and eval-
uate them on 597 queries from episodes 81–90, which were excluded from exploration and distilla-
tion, with no further capability updates. EDM raises overall success from 37.5% to 65.8% (+28.3
percentage points), while reducing tokens per query by 69.4% (Table 4). The gain is comparable
to the 25.5-point gain on episodes 91–100, supporting reuse across episodes. Appendix C.3 gives
the protocol. Distilling from the same execution traces without exploration programs, notes, or an-
swers reaches 46.4%: its event tool detects pauses of the robot base, which follow placements but
miss pickups, and miscounts interactions in 3 of 10 episodes (Appendix C.3). These results sup-
port the added value of exploration-derived solutions for building reusable temporal capabilities that
generalize to held-out episodes.

5
LIMITATIONS
Our evaluation uses predefined query sets and task categories, enabling controlled comparisons of
memory access and capability expansion.
Real-world deployment can introduce new, long-tail
queries as users’ needs change. While our experiments demonstrate capability reuse across held-
out episodes and new robot memories, they only partially capture this evolving task distribution.
Evaluating repeated capability expansion over longer deployments and a broader range of emerging
queries is an important direction for future work.
6
CONCLUSION
We introduced ReSight, which retains revisitable visual evidence and expands memory process-
ing through EDM. Its dual-agent architecture separates bounded execution from programmatic ex-
ploration, distilling reusable tools, skills, and memory builders. Experiments demonstrate effec-
tive memory access, improved spatiotemporal question answering, and capability reuse across new
queries and robot memories with fewer online tool calls.

B
EXPLORE–DISTILL–MOUNT IMPLEMENTATION
B.1
DIAGNOSING CAPABILITY GAPS FROM EXECUTION
After exploration, distillation inventories the host’s tools, memory fields, and execution traces in a
capability ledger. Each operation used during exploration is classified as directly supported, com-
posable from existing operations, partially supported, or missing. A script flags queries whose traces
show a difficulty, such as a forced final answer, repeated identical calls, or an answer given without
inspecting frames, and queries on which the executor’s answer disagrees with an explorer’s answer.
A gap map groups the flagged queries by cause and relates each gap to the operations and exploration
programs that address it.
Diagnosis uses execution traces and answer-disagreement flags to identify candidate gaps, without
task reference answers or evaluation scores.

Distillation without exploration.
This configuration repeats Distill and Mount for episodes 91–
100 with the exploration stage removed. The coding agent receives the same execution traces, host
tool inventory, interface specification, and tool implementation constraints as the full run. Both
FindingDory configurations use three distillation steps: capability ledger and gap map, tool synthe-
sis with code self-tests, and skill writing. It receives no exploration programs, notes, answers, or
session records, so its flags contain no answer disagreements. In this configuration, directly viewing
memory images or reading memory annotation files is prohibited. Its code may process the self-test
recordings, and the agent may inspect the resulting text diagnostics and tool outputs to debug the
tools; transcripts are audited for compliance. The distilled tools and skill are mounted and evaluated
with the protocol above.
The run produces four tools: an event index, a revisit roster, a multi-frame zoom, and a place time-
line. The event index segments intervals in which the robot base stops moving. These stops follow
placements, so the index records one interval per interaction and no pickup. It reports 9, 9, and 11
interactions in three of the ten episodes, whereas every episode contains ten and the full run’s event
tool finds ten in each. The count of ten interactions applies to held-out episodes 81–90, whereas
the illustrated episode 98 from episodes 91–100 contains eleven pick-and-place interactions; these
event counts are independent of the 15-round online decision budget. Durations are measured as the
length of a stop instead of the span from pickup to placement. Table 8 gives success by query type;
the largest gaps to full EDM are ordered revisitation, duration tracking, and interaction order. The
configuration answers 110 queries that the unmounted executor misses and misses 57 that it answers
(exact McNemar p = 5 × 10−5); against full EDM the counts are 28 and 144 (p = 5 × 10−20). Its
tools return short tables and the executor submits after 4.1 rounds on average, which lowers tokens
per query to 26.9k.
