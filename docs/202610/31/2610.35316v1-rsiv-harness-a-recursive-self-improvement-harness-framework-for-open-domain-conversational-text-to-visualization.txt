## Abstract 

Users often request charts without knowing which database or table holds the relevant data. Such requests may be ambiguous, and users may ask follow-up questions to deepen their analysis or iteratively refine existing charts. A useful assistant must therefore discover relevant data sources among heterogeneous databases, ask clarifying questions when needed, and track evolving user in-tent while preserving constraints established in earlier turns. Yet recent text-to-visualization agents typically rely on static agent harnesses that are predefined and remain unchanged despite recur-ring failures across tasks. To address this limitation, we introduce RSIV-Harness, which keeps the language model weights fixed and applies Recursive Self-Improvement to revise the surrounding harness from the agent’s own failure traces. To balance flexible self-improvement with stability, we introduce a four-layer framework that evaluates proposed harness revisions through anchor and mem-ory checks, refining those that pass and restoring the best validated harness otherwise. We further introduce ODAC-Vis, a benchmark with 640 tasks for Open-Domain, Ambiguous, and Conversational text-to-visualization that jointly evaluates open-domain data dis-covery, ambiguity resolution, multi-turn visualization refinement, and executable chart generation. Experiments show that a single round of RSIV-Harness improves all six evaluation metrics relative to the seed harness, with particularly large gains in executability (+28.02 points) and chart structure (+34.01 points), demonstrating the ability to learn from task-solving experience and turn recurring failures across tasks into substantial performance improvements.

## 1 Introduction 

While extensive research on natural language interfaces for auto-mated visualization within the database and data mining commu-nity [4, 5, 14, 19, 25, 36, 40, 42], recent agent systems increasingly wrap large language models in an agent harness [8, 10, 11]: a sur-rounding layer of system rules, tool interfaces, and control policies that govern schema access, SQL generation, and chart rendering. In-dustrial and academic agents [13, 33] show that such harnesses can coordinate retrieval, query planning, execution feedback, and visu-alization. Yet most harnesses are authored once and kept fixed after deployment, while public benchmarks still largely assume a known target database and a well specified single-turn request [4, 19, 42]. These gaps limit deployment in enterprise data lakes and rigorous measurement of open-domain conversational text-to-visualization. 

Benchmark and task coverage. In enterprise data lakes, an-alysts often begin without a known target database, must resolve ambiguous requests through dialogue, and iterate on SQL and charts over multiple turns before trusting the output (Figure 1). Existing benchmarks address these needs only in isolation: open-domain and cross-database text-to-SQL [5, 36], controlled ambi-guity in conversational querying [18, 28], and multi-turn text-to-visualization [4, 19, 27, 32]. To our knowledge, no public benchmark integrates them for end-to-end evaluation with executable query and chart supervision throughout the dialogue. 

Deployment and adaptation. State-of-the-art visualization agents improve reliability through fixed multi-stage workflows or within-task execution feedback [14, 25]. Three adaptation problems therefore remain. First, recurring failure modes such as premature code generation, schema search misuse, and cross-database bound-ary violations persist across tasks because the harness is not revised from accumulated traces. Second, improving reliability often re-quires retraining or replacing the base model rather than evolving the surrounding harness under fixed weights. Third, learning from failed tasks may introduce regressions, causing the harness to fail on tasks it previously solved correctly. 

Our solution. We introduce ODAC-Vis and RSIV-Harness as a co-designed benchmark and method response. RSIV-Harness keeps the language model weights fixed. It revises only the surrounding harness: the system surrounding the model, including its prompt, tool, memory, skill, and middleware. At each turn, an inner loop either clarifies the request or generates a visualization program, and retries with observed errors within a bounded budget. Rather than following predefined edit rules, the outer loop autonomously determines which harness components to revise and how, guided by observed failure patterns. To prevent such open-ended evolution from degrading previously acquired capabilities, we introduce a four-layer stability framework that accepts revisions only when they satisfy both validation-anchor and regression-memory checks, reverting to the best validated har-ness otherwise. We establish formal guarantees that accepted revi-sions refresh protected records, rejected revisions preserve those records and restore the champion, the best validation score remains nondecreasing, and regression on sampled protected records stays bounded. To evaluate this experience-driven evolution under realis-tic open-domain conversational visualization challenges, we further introduce ODAC-Vis, a benchmark for Open Domain, Ambiguous, and Conversational text-to-visualization. ODAC-Vis jointly eval-uates source discovery across a fully exposed database collection, ambiguity resolution, and multi-turn visualization refinement, with domain-held-out evaluation and executable query-and-chart super-vision at each code-generating turn. Together, ODAC-Vis provides a unified testbed for these interconnected challenges, while RSIV-Harness enables agents to learn from recurring task failures and improve their behavior across tasks. 

Contributions. Our work makes four main contributions: 

• ODAC-Vis Benchmark. We present the first benchmark in which agents must generate visualizations without being given the target database or table, clarify ambiguous requests, and support follow-up refinement. 

• RSIV-Harness Method. We propose a recursive self im-provement framework that enables agents to evolve from their own task-solving experience. An inner ReAct loop handles conversational visualization tasks, while an outer loop evaluates execution traces, identifies recurring failures across tasks, and autonomously proposes targeted revisions to the surrounding harness. 

• Stability Rules & Formal Guarantees. We develop a four-layer stability rule framework to ensure stable evolution without restricting how harness revisions are proposed. We formally guarantee protected-memory updates upon accep-tance, champion restoration without memory modification upon rejection, nondecreasing champion validation scores, and bounded regression on sampled protected records. 

• Empirical Study. Extensive experiments on held-out do-mains show that a single round of recursive self-improvement improves all six evaluation metrics over the seed harness. Cross-backbone transfer and ablation studies further exam-ine the generality of these improvements and the contribu-tions of individual components. These findings demonstrate that agents can turn accumulated task failures into substan-tial improvements on previously unseen tasks. 

## 2 Related Work 

This work is closely related to conversational text-to-visualization and to recursive self-improvement of agent harnesses. In this sec-tion, we review the prior literature in these two main directions. 

## 2.1 Text-to-Visualization and Conversational Data Access 

Natural language (NL) interfaces for visualization (Vis) have pro-gressed from direct code generation [22] to curated benchmarks and agentic pipelines. Early text-to-vis datasets such as nvBench and VisEval [4, 19] provide large-scale NL-Vis pairs, enabling auto-matic validity and readability checks but not source discovery over a full database collection. Subsequent work extends coverage along three largely separate axes. Ambiguity-aware benchmarks such as nvBench 2.0 and CLARITY [18, 28] inject lexical, schema, or value ambiguity into querying, yet still assume a specified schema and stop at SQL execution. Complementary models improve robustness to lexical and phrasal variability [15] and to ambiguity in interac-tive text-to-visualization [16, 37]. Multi-turn visualization datasets including Dial-NVBench, Text2Vis, and PMVisBench [27, 32, 38] support conversational refinement or progressive intent elabora-tion, but provide fixed table or schema context rather than open-domain routing across heterogeneous sources. CoVis studies neural and LLM-driven multi-turn interactions for conversational text-to-visualization [31], and FeVisQA studies free-form question an-swering over data visualizations [30]. On the querying side, cross-domain semantic parsing benchmarks such as Spider, BIRD, SParC, and CoSQL [9, 40–42] establish standard splits for schema gen-eralization and multi-turn SQL dialogue, while TACO [5] moves toward unspecified databases and cross-database SQL composition. Text-to-NoSQL translation extends natural-language querying to non-relational stores [12]. None of these resources jointly evaluate RSIV-Harness Conference acronym ’XX, June 03–05, 2018, Woodstock, NY 

open-domain source discovery, typed ambiguity resolution, exe-cutable query and chart supervision, and multi-turn conversational interactions, which motivates our ODAC-Vis benchmark. Visualization agents improve reliability through staged work-flows and within-task validation rather than cross-task adaptation. nvAgent decomposes processing, composition, and validation in a fixed collaborative workflow [25], and MultiVis-Agent adds logic rules for bounded tool use and cross-modal refinement [13, 14]. Open-domain SQL systems such as Abacus-SQL combine retrieval with multi-turn query generation [36], and recent agentic NL2SQL frameworks employ multi-agent decomposition, rewriting, and execution-grounded repair [1–3, 20, 26, 33, 34]. These systems nonetheless ship with prompts, tools, and control policies fixed before deployment and do not revise the surrounding harness from recurring failures observed across tasks. 

## 2.2 Agent Harnesses and Recursive Self-Improvement 

LLM agents are increasingly mediated by a surrounding harness :system rules, tool interfaces, middleware, and control policies that govern how a frozen model interacts with an environment [8, 10, 11]. Industrial and academic text-to-SQL agents instantiate such harnesses through schema retrieval, query planning, execution feedback, and validator loops [14, 25, 33, 34], yet most are hand engineered once and left unchanged after release. Recursive self-improvement has recently been studied along three complementary lines. Weight-centric RSI agents such as AREX [17] alternate an inner task loop with an outer audit-and-refine loop, but sustain gains through agentic mid-training and rein-forcement learning over model parameters rather than deployment-time harness edits. Harness-evolution methods keep the base model frozen and instead revise prompts, tools, and control programs from execution traces [6, 10, 23, 43, 44], including test-time pro-gram search, weakness-driven proposal with regression testing, and observability-driven component editing; yet they neither sup-port clarification over open database collections nor regression-validated harness commits for coupled query-and-chart execution in multi-turn dialogue. Inference-time self-correction methods such as Reflexion, Self-Refine, and DSPy [7, 21, 29] improve individual trajectories through verbal feedback, iterative drafting, or com-piled prompt pipelines, but do not commit persistent harness revi-sions validated across a task distribution. RSIV-Harness addresses these gaps by learning from recurring failures across tasks to au-tonomously evolve the agent harness, while using regression-aware checks to preserve previously successful behaviors. 

## 3 The ODAC-Vis Benchmark 3.1 Overview and Motivation 

We introduce ODAC-Vis, a benchmark for Open Domain, Ambiguous, and Conversational text-to-visualization. Each task simulates an analyst who requests a chart in natural language without naming a target database, may need to clarify underspecified intent, and may refine the analysis or the chart over subsequent turns. The benchmark exposes all 206 SQLite databases from the Spider test collection [41] and requires a model to discover relevant sources, compose SQL when multiple databases are needed, and emit exe-cutable Python that queries data and renders a Plotly chart. 

Open domain and cross-domain. Unlike prior text-to-vis datasets that bind each instance to a known table or schema [4, 19, 27, 32], ODAC-Vis treats the full database collection as visible at inference time while keeping the gold target as one or more specific databases per task. Models must route to the correct sources with-out being told which database to open, and cross-database tasks require SQL-only composition through ATTACH , temporary tables, joins, semi-joins, unions, or scalar subqueries rather than post-hoc Python merges. Evaluation uses a domain-held-out split: domains seen during training never appear in validation or test, so success requires generalization rather than memorizing a fixed schema cata-log. Complexity is stratified into single-table (30%), single-database join (50%), and cross-database (20%) tiers within each split. 

Ambiguity. Each task contains one to three ambiguity points drawn from eight template-defined types. Data semantics: 

• Column selection : “Show revenue” when both gross and net sales columns are valid measures. 

• Aggregation granularity : “Show the trend” when the request can be grouped by month or by quarter. 

• Filter logic : “Top performers” when ranking by revenue or by profit, or when conjunctive and disjunctive filters differ. 

• Unit scale : “Plot sales” when values may be shown in raw units, millions, or percentages. 

Visualization semantics: 

• Chart type : “Visualize growth” when a line chart (trend) and a bar chart (comparison) are both reasonable. 

• Encoding mapping : “Highlight categories” when color or point size could encode the same dimension. 

• Axis label : “Show enrollment” when the y-axis may label counts or normalized rates. 

• Interactivity : “Make it filterable” when filtering by dropdown selection or brush interaction is intended. Every ambiguity is backed by at least two schema-supported al-ternatives that yield distinguishable query or chart outcomes, and each is resolved through a clarification question followed by a user reply that uniquely selects one alternative. Dialogues never expose database or table names during clarification. 

Conversational structure. Tasks follow one of two scenarios, which set the analytical role of the dialogue. In drilldown , later requests deepen the current analysis. In iterate , later requests revise the current chart. Ambiguity is placed independently of that role. Each task contains one to three ambiguity points on randomly chosen request turns other than the final turn, so clarification may open the dialogue or arise during a later drilldown or iteration. A turn that contains an ambiguity requires the model to ask the user a clarification question on that turn. On the next turn the user answers the question, and the model writes the visualization code for user’s intent. A turn without ambiguity requires the model to write the visualization code directly. Conversations are capped at eight user–assistant exchanges. The two scenarios appear in equal proportion within each split. ## 3.2 Dataset Construction Methodology 

ODAC-Vis was constructed through a principled, LLM-assisted pipeline with expert validation, prioritizing quality, coverage, and faithfulness in open-domain, ambiguity-aware, multi-turn conver-sational text-to-visualization scenarios. ## 3.3 Benchmark Statistics 

Table 2 summarizes the released ODAC-Vis corpus. The benchmark contains 640 multi-turn tasks over 206 Spider databases and 139 domains, stratified partitioned into 448 train, 96 validation, and 96 test instances. Rather than maximizing instance count alone, the ODAC-Vis prioritizes distributional control : every split preserves balanced scenario and complexity quotas, validation and test are held to equal size for stable anchor evaluation, and test domains are disjoint from train and validation so that success requires locating the right sources rather than memorizing a fixed schema catalog. Most tasks remain short enough for interactive analysis, yet the corpus deliberately retains longer clarify-and-code trajectories and a full cross-section of typed ambiguities so that models cannot succeed through single-turn chart guessing alone. Table 1 situates ODAC-Vis against six representative text-to-visualization and data-access benchmarks. Existing resources typi-cally isolate one deployment challenge at a time: single-turn text-to-vis sets assume a known table or database; conversational bench-marks add dialogue but keep the schema fixed; ambiguity-aware corpora annotate alternative encodings without requiring clarifi-cation turns; and open-domain text-to-SQL benchmarks such as TACO [5] evaluate cross-database retrieval and composition in SQL alone, without executable chart supervision. ODAC-Vis is designed to stress-test the full analyst workflow in one benchmark: models must discover target sources from a fully exposed 206-database collection under a domain-held-out split, resolve typed ambigui-ties through clarify dialogue, compose evidence across databases when needed, and emit verified Python programs with reference charts at every code turn. To our knowledge, it is the only corpus in the comparison that jointly supports Python chart generation, open-domain access, cross-domain evaluation, multi-turn dialogue, verified ambiguity gold, and cross-database SQL composition. 

## 3.4 Dataset Quality Analysis 

Benchmark comparisons are only meaningful when the underlying supervision is faithful to the stated task. We therefore conduct a controlled quality audit of ODAC-Vis together with two widely used text-to-visualization resources: Dial-NVBench [32], which models multi-turn visualization dialogue over a fixed given table or schema, and NVBench 2.0 [18], which injects ambiguity into the request and retains multiple valid chart specifications per request. Each instance receives three independent scores on a 0–100 scale: 

• Relevance : whether the gold answer targets the analysis im-plied by the request. 

• Plausibility : whether the answer satisfies stated constraints and forms a coherent query or chart specification. 

• Readability : presentation quality of the answer text and, when applicable, the reference chart. ## 4.1 Design Philosophy and Architecture Overview 

Existing visualization systems still face a fundamental limit that blocks practical deployment. A traditional pipeline fixes its proce-dure before the first request, so a failure that keeps recurring can be removed only by rewriting that procedure or by retraining the model. Harness agents improve on this design: a frozen model can choose its next action from the observation it has just received. The harness that governs the choice is nevertheless fixed at deployment, so the agent stays rigid and has little flexibility once the scenario grows more complex than the behavior written for it. To address this limitation, we propose RSIV-Harness, which keeps the harness as the acting layer of a frozen model and adds self-improvement that revises the harness from failures accumulated across tasks. RSIV-Harness implements a hierarchical, bi-level recursive self-improvement process, comprising an inner task-solving loop and an outer self-improvement loop (Fig. 4). The inner loop answers one assistant turn by following the harness that is currently deployed. The outer loop reads the traces of many such turns and proposes a revision of that harness. A four-layer stability rule framework then accepts or rejects the revision before it can replace the deployed harness. The inner loop therefore supplies the evidence, the outer loop turns that evidence into a candidate, and the rules decide which harness the next inner loop will use. Self-improvement starts from a minimal harness, leaves the outer loop free to choose what to refine and how to refine it, and uses the refine, restart, anchor check, and memory check rules as the hard constraints that keep this freedom stable.

## 5 Experiments 5.1 Experimental Setup 

5.1.1 Dataset. All experiments use ODAC-Vis. We use the train split to drive the outer loop of RSIV-Harness. The stratified train-ing panel 𝑆 contains 48 tasks from train only domains. Their failure traces are analyzed to propose harness edits. The anchor check evaluates every candidate on a panel of 48 validation tasks. Each panel contains one task for every combination of the three difficulty tiers, the eight ambiguity types, and the two conversation scenarios. All of the test split is reserved exclusively for final evaluation. It comprises 96 tasks over 15 held-out domains that never appear in train or validation, so reported scores measure open-domain source discovery, ambiguity handling, and multi-turn chart generation rather than memorization of a fixed schema catalog. All baselines and evolved harness variants are evaluated on this test split un-der model history: each turn conditions on the model’s own prior assistant outputs within the same task. 

5.1.2 Baselines. We compare RSIV-Harness against four progres-sively more sophisticated baselines: direct prompting, static har-nesses, ReAct, and MultiVis-Agent: 

• Direct Prompt. A single LLM call per turn with no tool access. The model receives the full schema catalog together with the conversation history and NLQ of this turn. 

• Static Harnesses. The minimal seed harness 𝐻 0 of RSIV-Harness, held fixed and never evolved. A seed already fitted to ODAC-Vis would contaminate the attribution of every later edit, since a gain could no longer be separated from the seed. The minimal seed forces every component the outer loop adds to earn its place against measured traces. 

• ReAct [39]. An ReAct baseline equipped with carefully de-signed, task-specific tools. At each turn, it runs a thought-action-observation loop. 

• MultiVis-Agent [14]. A state-of-the-art multi-agent system for text-to-visualization, adapted to ODAC-Vis task with minimal modifications. 

• RSIV-Harness (Ours). Our Proposed method. An inner ReAct loop clarifies the request or generates a visualization program, while an outer loop improves the harness from traces under a four-layer stability rule framework. RSIV-Harness Conference acronym ’XX, June 03–05, 2018, Woodstock, NY

## 5.3 Ablation Study 

5.3.1 Stability Rule Analysis. To isolate the effect of stability rules, we repeat one round of harness evolution with DeepSeek-V4.1-Flash after removing the stability rule framework, keeping all other set-tings unchanged. The resulting harness is then frozen and evaluated on the test split using the same model. As shown in Table 4, re-moving the stability rules leads to performance degradation across all six metrics: executability drops by 9.73 points, database routing by 3.12, stance accuracy by 2.50, execution accuracy by 3.50, clar-ification quality by 2.74, and chart structure by 9.53. The largest declines occur in executability and chart structure, while the re-ductions in routing, stance, and clarification quality indicate that the framework contributes to multiple aspects of conversational visualization rather than merely filtering invalid programs. These results highlight the importance of stability rules in guiding harness evolution, helping preserve previously successful behaviors while enabling improvements from accumulated task failures. 

5.3.2 Harness Component Analysis. To assess component contribu-tions, we replace each component of the 𝐻 0 with its evolved coun-terpart—prompt, tool, memory, skill, or middleware—while keeping the others unchanged. Table 4 reveals complementary strengths. The evolved prompt improves routing (62.26), clarification (3.76), and chart structure (71.13), while the tool interface supports rout-ing (62.26) and stance accuracy (65.25). Memory benefits routing (59.92) and chart structure (67.69), whereas skills improve execution accuracy (29.18) and chart structure (69.47). Middleware achieves the best single-component results in executability (90.66), stance accuracy (66.50), execution accuracy (30.35), and chart structure (72.41), highlighting the role of control flow and execution feed-back. The complete harness still exceeds every single component variant in five metrics. The combined result therefore arises from coordination among components rather than from one isolated edit.

## 6 Conclusion 

We presented ODAC-Vis and RSIV-Harness as a benchmark and method for open domain conversational text to visualization. ODAC-Vis evaluates source discovery, ambiguity resolution, and multi turn chart refinement under held out domains. RSIV-Harness improves the harness around a fixed language model through recursive anal-ysis of failure traces. Its stability rules provide explicit guarantees for protected record refresh, champion restoration, anchor mono-tonicity, and bounded regression. On the test split, a single round of recursive self-improvement improves the DeepSeek-based har-ness across all six evaluation metrics. The same frozen harness also transfers competitively to GPT-6 Luna. Ablations further show that the stability rules improve all reported metrics and that the harness components make complementary contributions. These findings establish harness evolution as a practical path for improving con-versational visualization agents.
