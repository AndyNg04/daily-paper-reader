## 摘要
随着基础模型从信息生成发展到数字化工作执行，智能体日益能够借助各类工具、应用程序和工作流完成复杂任务。然而，现有研究尚缺乏关于智能体如何可靠完成委派工作的统一视角。为弥补这一不足，我们提出一种以工作为中心的系统级视角，将工作智能体视为由基础模型和运行时框架构成的系统，在有状态的工作空间中执行任务并交付可验证的成果。我们引入工作持续性和工作开放性两个互补维度，用以刻画工作条件，并依据任务范围和组织方式将数字工作划分为五种形式。在此框架基础上，我们归纳出可靠执行工作所需的五类核心能力，并探讨模型优化、运行时框架优化及二者的联合优化方法。我们还从工作成果的视角分析现有评估方法和指标。最后，我们讨论了未来研究方向，包括持续性工作委派、对开放环境的适应，以及工作执行与能力提升之间的相互作用。本文为理解、优化和评估工作智能体提供了统一框架，助力开发能够交付可靠、可验证且具有实际价值的工作成果的系统。

## Abstract
As foundation models evolve from information generation to digital work execution, agents are increasingly capable of completing complex tasks across tools, applications, and workflows. However, existing research lacks a unified perspective on how agents reliably accomplish delegated work. To address this gap, we present a work-centric, system-level perspective that views work agents as systems combining foundation models and runtime harnesses to execute tasks in stateful workspaces and deliver verifiable outcomes. We introduce two complementary dimensions, work persistence and work openness, to characterize working conditions, and classify digital work into five forms according to task scope and organization. Building on this framework, we identify five core capability families required for reliable work execution and examine approaches to model optimization, harness optimization, and their joint optimization. We further analyze existing evaluation methods and metrics from the perspective of work outcomes. Finally, we discuss future research directions, including sustained work delegation, adaptation to open environments, and the interaction between work execution and capability improvement. This paper provides a unified framework for understanding, optimizing, and evaluating work agents, supporting the development of systems capable of delivering reliable, verifiable, and practically valuable work outcomes.

## 2. 方法论：系统框架、工作条件与优化路径

### 2.1 六要素系统框架

论文使用六个要素描述委托工作：

| 要素 | 主要内容 |
|---|---|
| **任务 \(T\)** | 目标、约束、资源、权限及完成条件；持续任务还包括责任期限和续期条件 |
| **模型 \(M\)** | 理解信息、推理、权衡方案并提出行动 |
| **运行时支撑系统 \(H\)** | 上下文构建、工具调用、记忆、技能、执行控制和错误恢复 |
| **工作空间 \(E\)** | 文件、应用、记录、消息、任务及其他参与者构成的有状态环境 |
| **工作成果 \(O\)** | 答案、文件、应用状态变化、流程结果，以及持续维护的条件和事件响应 |
| **验证 \(V\)** | 根据可观察证据，检查成果是否满足任务要求 |

其中，**智能体本身由模型和运行时支撑系统构成**，其余要素界定它承担的工作及验收标准。

论文的两个核心表达式可用文字概括为：
- **执行过程**：模型与运行时系统从任务和初始工作空间出发，闭环产生行动轨迹、当前状态和阶段性成果。
- **验证过程**：验证器结合任务要求、初始与当前状态、执行记录及成果，形成评估结果。

这些公式用于描述系统关系，并非新的训练目标或求解算法。

### 2.2 两个工作条件维度

- **工作持续性（Persistence）**：责任何时可以结束。
  - 低持续性：交付答案、确认修改或提交通过测试的补丁后结束。
  - 高持续性：仍需等待审批、回应后续事件，或在约定时间内持续维护。
  - **持续性不等于执行时间长**：一次长时间运行仍可能交付即结束；每周只运行几分钟的季度维护任务则可能具有高持续性。

- **工作开放性（Openness）**：执行前已有多少任务世界被明确指定。
  - 低开放性：材料、工具和规则预先给定。
  - 高开放性：需要自行发现相关文件、版本、依赖、人员、接口和权限。

两个维度在概念上独立：任务可以只要求探索，也可以只要求持续维护，或同时要求二者。

### 2.3 五类工作形式与五类核心能力

**五类工作形式**按责任范围和组织方式划分：
1. **对话级**：输出答案、分析、判断或方案。
2. **原子动作级**：完成目标明确的局部状态修改。
3. **多步骤级**：通过相互依赖的操作实现完整目标。
4. **工作流级**：承担阶段推进、审批、政策遵循及参与者交接。
5. **工作空间级**：发现并追踪跨文件、记录和应用的关系，必要时维护一致性。

这里的“原子”指目标范围局部，不代表只需一次鼠标或 API 操作；系统内部有多个执行阶段，也不必然属于工作流级，关键是这些阶段是否构成用户要求的业务过程。

**五类核心能力**形成反馈闭环：
- 感知与理解；
- 推理与决策；
- 规划与协调；
- 执行与状态管理；
- 验证、恢复与重规划。

一个重要技术细节是区分：
**已尝试行动 → 接口已接受调用 → 效果已提交到目标状态 → 效果已验证**。  
接口返回成功并不等于任务完成；效果不确定时，应先检查状态，再决定重试，避免重复发送消息或重复修改记录。

### 2.4 三条优化路径与双循环

- **模型优化**：通过预训练、中期训练、SFT、强化学习、教师指导和历史反馈学习，增强知识及行动策略。
- **运行时优化**：改进观察接口、工具说明、中间件、执行流程、上下文、记忆和技能库。
- **联合优化**：交替更新模型和外部支撑机制，判断经验应进入权重、上下文、技能文档还是执行代码。

作者建议采用四种配置进行归因比较：原模型／原运行时、更新模型／原运行时、原模型／更新运行时、两者同时更新。**这是建议的实验协议，不是本文完成的统一消融实验。**

进一步，论文区分：
- **工作执行循环**：推进当前责任并记录状态。
- **能力改进循环**：从执行经验中诊断问题、提出更新并独立测试。

更新还必须检查其对未完成工作、已有审批和下游参与者的影响，而不能只看新任务分数。

## 6. 主要结论与发现

- **可靠工作能力属于完整系统，而不只属于基础模型**：接口、状态记录、运行时控制与验证都会显著影响结果。
- 工作范围扩大时，难点不只是步骤增加，更是**依赖关系增加并可能发生变化**。
- 开放性提高了发现证据、关系和权限的要求；持续性提高了保留责任、跨会话恢复及重新验证的要求。
- 评估必须区分：
  - 检查什么：答案、文件、环境状态或流程；
  - 判断什么：正确性、完整性、质量及约束遵循；
  - 如何判断：规则、模型裁判、智能体裁判或专家；
  - 如何汇总：成功率、部分得分、相对偏好或加权指标。
- **成果被接受，不等于实际产生经济收益**。还需考察成果是否被使用，以及用户说明、监督、纠错和集成付出的总成本。
- 持续自我改进必须兼顾已有责任；对新任务有效的更新，可能因迁移、重新检查和协调成本而不值得立即部署。
- 个人智能体、人类数字孪生和组织工作系统分别强调持续目标、个人判断保真度和跨角色交付，不能使用单一质量分数替代全部评价。

## 7. 优点与亮点

- **统一性强**：将问答、工具调用、办公、代码和企业流程纳入同一工作交付框架。
- **关键概念区分清楚**：尤其是持续性与长程执行、业务工作流与内部执行流程、调用成功与效果验证之间的区别。
- **面向真实工程问题**：覆盖中断恢复、重复副作用、过期证据、权限发现及跨对象一致性。
- **优化归因较细致**：避免把缺失证据、工具缺陷和策略错误一概归因于模型能力。
- **评估视角完整**：关注非目标状态保护、过程合规、裁判可靠性、人工监督和实际使用价值。
- **研究建议可操作**：四配置对照、相同状态恢复测试、固定验收标准和独立任务验证，有助于后续实证研究。

## 8. 不足与局限

- **原创实证验证不足**：核心分类和双循环框架主要由概念分析及已有研究支撑，尚无统一实验检验。
- **概念缺乏量化操作标准**：持续性、开放性如何测量、不同标注者能否一致分类，仍未充分解决。
- **分类并非严格互斥**：工作空间级任务可能同时包含工作流和多步骤任务；“最宽责任范围”的归类方式便于整理，但可能压缩任务差异。
- **定义较宽**：连经过任务要求检查的最简单问答系统也被纳入工作智能体，增强了统一性，却降低了概念边界的区分度。
- **长期真实部署证据仍有限**：跨季度责任、复杂组织审批、真实用户变化及在线更新成本，尚需长期现场研究验证。
- **评估器偏差风险突出**：语义或智能体裁判可能漏查数值、引用和依赖错误；若训练与验收共享类似裁判，还可能放大共同盲点。
- **安全治理讨论不够系统**：虽然涉及权限和保密，但对提示注入、权限升级、数据泄露及不可逆行动控制缺少专门体系。
- **经济收益难以归因**：benchmark 成功率、人工耗时或任务价格代理都不能直接代表部署收益，需要真实工作场景中的因果比较。

**总体评价**：本文的主要价值是提供一套理解、诊断、优化和评估工作智能体的统一语言，而不是证明某个新算法优于现有方法。其最重要的启示是：**应以持续责任下“被验证、被接受并实际使用的工作成果”为目标，而非仅追求更好的模型输出或更高的局部 benchmark 分数。**
