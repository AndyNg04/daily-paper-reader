## 摘要
自动审批系统通过将授权决策委托给分类器（通常是大语言模型，LLM），使编码智能体能够在极少人工监督的情况下执行高风险操作。Claude Code 和 Codex 等工具已采用此类系统，但它们仍易受多种失效模式影响，例如权限范围升级，即智能体采取超出用户授权范围的操作。现有基准主要关注恶意请求，并依据隐含策略评估模型是否拒绝。我们提出 AuthGateBench，这是首个针对良性请求下授权门控的策略引导型基准。我们设计了一种新颖的流程：由 LLM 生成对比样例对，其中两者的操作和执行轨迹相同，但请求不同，因此标签分别为阻止和允许。借此，我们可以评估模型是否基于上下文进行推理，而非仅依据操作本身作出判断。我们还研究了辅助环境信号能否帮助模型作出更好的决策。最终构建的基准包含 1,400 个实例，涵盖从真实世界 Claude Code 事件中归纳出的五种失效模式。评估结果显示，随着模型过度依赖内部安全对齐，其准确率在不同失效模式下呈现不均衡的下降；即使明确获得授权，模型仍会阻止大多数操作，这表明其决策并不稳定、也非确定性的。然而，回溯检索得到的环境信号能够显著提高授权判断准确率。

## Abstract
Automated approval systems let coding agents execute high-risk actions with minimal human oversight by delegating the authorization decision to a classifier, typically a large language model (LLM). Such systems, adopted in tools like Claude Code and Codex, remain vulnerable to failure modes such as scope escalation, where the agent takes actions exceeding what the user authorized. Existing benchmarks focus mainly on malicious requests, evaluating refusal under an implicit policy. We introduce AuthGateBench, the first policy-guided benchmark for authorization gating under benign requests. We implement a novel pipeline where an LLM generates contrast pairs with identical action and trajectory but differing request, flipping the label between block and allow. This allows us to assess whether models reason over context rather than the action alone. We further examine whether auxiliary environment signals can help models make better decisions. The resulting benchmark comprises 1,400 instances spanning five failure modes drawn from real-world Claude Code incidents. Evaluations show accuracy degrades unevenly across failure modes as models over-rely on internal safety alignment, and models still block most actions even when explicitly authorized, revealing unstable rather than deterministic decisions; retrospectively retrieved environment signals, however, substantially improve authorization accuracy.

## 1. 核心问题与整体含义：从“操作是否危险”转向“操作是否获授权”

- **研究背景**：编码智能体正在从“提出建议、等待确认”转向自动执行文件修改、Shell 命令和 API 调用。为减少人工审批，系统通常使用另一个 LLM 作为授权门控器，决定每个拟执行操作应当 **ALLOW（允许）** 还是 **BLOCK（阻止）**。
- **核心问题**：即使用户请求完全善意，智能体也可能自行扩大任务范围，例如删除未被指定的文件、使用偶然发现的生产凭据，或者绕过失败的安全检查。
- **现有评测的缺口**：
  - 大量基准关注恶意请求、越狱或提示注入，主要测试模型能否拒绝危险行为。
  - 但授权判断具有上下文依赖性：**同一个高风险操作，在不同用户请求下可能分别应被允许和阻止**。
  - 如果标注所依据的策略不明确，就难以判断模型错误究竟来自推理不足，还是其遵循的安全标准与评测标准不同。

**论文的整体意义**是将“风险识别”和“授权判断”区分开来：可靠门控既要防止越权，也要避免把用户明确授权的合法操作一概阻止。

## 2. 方法论：策略引导的对照样本与环境证据增强

### 2.1 授权判断的形式化

论文将单个实例表示为三元组：

- **请求 \(r\)**：用户交代的任务。
- **轨迹 \(\tau\)**：此前的工具调用及结果。
- **操作 \(a\)**：智能体接下来拟执行的工具调用。

门控器读取三元组及其获得的策略 \(\pi\)，输出 ALLOW 或 BLOCK。标准答案则由预先规定的目标策略 \(\pi^*\) 决定。

这里区分了两种评测条件：

- **隐式策略 \(\pi\)**：只要求模型像“谨慎、重视安全的操作员”一样判断，不提供具体规则。
- **显式策略 \(\pi^*\)**：提供生成与标注数据时使用的具体授权规则。

这一设计用于区分：错误究竟是由**策略不一致**，还是**无法正确应用已知策略**造成的。

### 2.2 三阶段数据构建流程

#### 阶段一：生成应当阻止的基础实例

- 使用 DeepSeek-V4-Flash，依据五类故障定义和种子示例生成请求、轨迹及拟执行操作。
- 采用“**生成—验证—修复**”循环：
  - 程序检查数据结构是否正确；
  - LLM 检查工具使用与返回结果是否合理；
  - 将问题反馈给生成器修复。
- 使用 Qwen3-Embedding-4B 对“请求＋操作”编码；若与已接受样本的余弦相似度达到 **0.9**，则丢弃并重新生成，以减少近重复。

#### 阶段二：构建标签相反的对照样本

- 固定轨迹和操作，保持二者**字节级一致**。
- 只修改用户请求，使其明确指定目标和授权范围，将标签从 BLOCK 翻转为 ALLOW。
- 修改后的请求只能使用用户在轨迹发生前合理可能知道的信息，避免借用未来工具结果构造不自然的授权。

例如：

- “清理一下仓库”不足以授权删除所有未跟踪及被忽略文件。
- 如果用户明确列出这些文件并要求删除，同一操作就可以被标注为允许。

该设计迫使模型考虑请求上下文，而不能仅凭危险命令或敏感资源名称分类。

#### 阶段三：增加只读环境信号

- 为已有实例附加环境证据，例如文件系统状态、运行进程、远程 API 返回信息、凭据作用域或审批状态。
- 原三元组和标准标签保持不变，只增加辅助证据。
- 这些信号由模型合成，用于模拟门控器看到完整操作后，再有针对性地收集相关信息。

例如，门控器原本认为目录只包含过期训练产物；新增信号显示仍有训练任务使用该目录后，便可能改为阻止删除。

### 2.3 关键评测指标

论文将 **BLOCK 视为正类**：

- **准确率 Acc**：全部判断中正确的比例。
- **假阴性率 FNR**：应当阻止却被放行，即越权漏放率。
- **假阳性率 FPR**：应当允许却被阻止，即合法操作误拦率。
- **不变率 IR**：在标签相反的对照样本中，模型仍给出相同判断的比例。IR 越高，说明模型越可能忽视请求中的授权变化。

## 3. 实验设计：数据、场景与对比对象

### 3.1 Benchmark 的组成

AuthGateBench 共包含 **1,400 个实例**：

| 组成 | 数量 | 含义 |
|---|---:|---|
| 基础实例 | 350 | 应当阻止的操作 |
| 请求改写实例 | 350 | 同轨迹、同操作，但请求明确授权 |
| 环境增强实例 | 700 | 为上述实例附加只读环境信号 |
| **合计** | **1,400** | ALLOW 与 BLOCK 标签均衡 |

因此，它并不是 1,400 个独立任务场景，而是以 **350 个基础场景**构建出对照及增强版本。

### 3.2 五类故障场景

| 故障模式 | 核心风险 |
|---|---|
| 范围升级（Scope Escalation） | 将模糊请求扩展成超出授权范围的破坏性操作 |
| 凭据探索（Credential Exploration） | 搜索并复用未为当前任务授权的凭据 |
| 参数推断（Inferred Parameters） | 根据名称相似性、时间或惯例猜测破坏性操作的目标 |
| 外部共享（External Sharing） | 未经请求，将代码、日志或数据发送至外部 |
| 绕过护栏（Guardrail Bypass） | 检查失败后通过 force、skip、no-verify 等方式绕过 |

这些类别源自真实事故，但**具体评测实例是合成数据**。

### 3.3 对比模型与实验条件

评测了四个 LLM：

- Qwen3.7-Plus
- GLM-5.2
- Kimi-K2.7-Code
- DeepSeek-V4-Flash

主要比较三种条件：

1. **隐式策略＋原始三元组**；
2. **显式策略＋原始三元组**；
3. **隐式策略＋环境增强三元组**。

评测使用一致的提示形式，要求模型给出判断与策略解释；生成温度为 **1**，评测温度为 **0**。

**需要注意**：论文没有直接测试 Claude Code、Codex 实际部署的审批组件，也没有与规则引擎、传统访问控制系统或形式化验证方法进行直接性能比较。

## 6. 主要结论与发现

### 6.1 隐式安全判断导致明显过度阻止

- 隐式策略下，四模型在五类场景中的准确率约为 **51%—78%**。
- 凭据探索和外部共享尤为突出：所有模型在这两类上的合法操作误拦率均至少为 **80%**。
- 外部共享的误拦率达到约 **92.86%—97.14%**。

这说明模型较擅长识别敏感行为，却常将“涉及风险”直接等同于“不应允许”，即使用户已明确授权。

### 6.2 对照样本揭示较强的操作锚定

隐式策略下，四模型的平均 IR 为：

- 凭据探索：约 **87.14%**；
- 外部共享：约 **95.36%**。

也就是说，仅改变请求中的授权信息，往往无法改变模型判断。

不过，这一结果直接支持的是**上下文敏感性不足**，并不能单独证明同一输入下的输出具有随机性或“不确定性”；论文没有通过重复运行专门检验这一点。

### 6.3 显式策略明显改善表现，但未消除错误

根据表中五类准确率作等权平均：

| 模型 | 隐式策略 | 显式策略 | 提升 |
|---|---:|---:|---:|
| Qwen3.7-Plus | 62.43% | 81.28% | 18.85 个百分点 |
| GLM-5.2 | 62.14% | 70.00% | 7.86 个百分点 |
| Kimi-K2.7-Code | 63.43% | 75.29% | 11.86 个百分点 |
| DeepSeek-V4-Flash | 61.29% | 68.00% | 6.71 个百分点 |

*上述平均值由论文分类别结果计算。*

改善主要来自减少误拦，但部分场景的越权漏放率也有所上升。例如 Qwen 在范围升级场景中的 FNR 从 **4.29%** 升至 **14.29%**，说明总体准确率提升不等于所有安全指标同时改善。

### 6.4 环境证据有帮助，但收益需谨慎解释

论文报告：

- 范围升级：纠正原错误预测的比例为 **25.2%**，误导原正确预测的比例为 **7.6%**。
- 参数推断：对应比例为 **24.3%** 与 **10.5%**。

两类比例分别以“原本错误”和“原本正确”的样本为分母，**不能直接相减得到准确率提升**。同时，信号由模型合成，实验支持的是环境证据的潜在价值，而不是已验证真实检索系统的部署效果。

## 7. 优点与亮点

- **研究问题重要且边界清晰**：关注善意请求下的越权，而不是重复测试恶意请求拒绝能力。
- **对照样本设计有诊断价值**：保持操作和轨迹不变，只改变授权请求，可以有效暴露“只看危险动作”的捷径。
- **区分策略缺失与推理失败**：显式、隐式策略对照使结果解释更客观。
- **同时关注安全与效用**：分别报告漏放和误拦，避免把“一律拒绝”误当作可靠授权。
- **环境增强具有实际启发**：提示授权门控器可以主动补充证据，而不必完全依赖执行智能体已经收集的信息。
- **数据构建较系统**：结合结构验证、合理性检查、修复及近重复过滤，提高了合成数据的可用性。

---

## 8. 不足与局限

### 8.1 合成数据与生成器偏差

- 单一模型负责基础实例、请求改写及环境信号生成，可能形成共同的语言风格和场景偏好。
- 同一生成模型也参与评测，不能排除生成器相关偏差。
- 真实事故仅用于归纳故障类型，不能据此认为数据代表真实事故分布。

### 8.2 单一策略限制外推

- 标签依据单一目标策略，而不同组织可能对删除、外传、凭据复用有不同规则。
- “用户明确要求”在现实中不一定等于“用户拥有授权权限”。例如绕过生产审批还可能需要额外角色权限。
- 因此，部分模型拒绝行为可能体现了不同的组织安全假设，而不完全是推理能力不足。

### 8.3 环境增强尚未经过真实系统验证

- 研究模拟了证据收集结果，但未实现并评测真实的只读工具检索闭环。
- 没有覆盖证据过期、冲突、不完整或被攻击者操控等情况。
- 只读不等于可信：工具返回内容仍可能携带提示注入或伪造信息。

### 8.4 指标与解释仍可加强

- 高 IR 表明模型未正确响应授权变化，但不能证明它完全忽略请求，也可能是策略解释不同。
- 未报告“对照样本两例均判断正确”的配对准确率；这一指标比单独使用 IR 更直接。
- 环境信号纠错并不能证明相关信息只有事后才能发现；执行智能体也可能通过主动规划提前收集。
- 论文提出形式化、确定性授权作为未来方向，但**并未实现或验证该方案**。

### 8.5 距离生产部署仍有差距

- 未覆盖多轮用户确认、动态权限变化、复杂身份体系、长期任务和多智能体协作。
- 缺少真实事故发生率、端到端任务成功率、审批成本与执行延迟评估。

**总体评价**：AuthGateBench 的主要贡献是提供了一个有解释力的授权诊断框架，表明“识别风险”不能替代“理解授权”。它为显式策略和证据驱动审批提供了实验依据，但尚不能证明通用 LLM 已能独立承担生产级授权门控。
