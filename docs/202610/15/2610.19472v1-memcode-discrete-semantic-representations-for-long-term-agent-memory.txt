## Abstract 

Long-term memory remains a fundamental bottleneck for large language model (LLM) agents across sessions. Existing systems typically adopt a write-then-retrieve paradigm, storing context-dependent dialogue fragments and retrieving them via nearest-neighbor search in continuous embedding space. This design yields unstable access units and systematically misses logically related but lexi-cally distant evidence. We propose MemCode, a long-term agent memory frame-work that couples retrieval-oriented writing with discrete associative retrieval. MemCode rewrites dialogue into self-contained atomic memory units (AMUs), maps AMUs into a learnable codebook with isomorphic semantic quantization (ISQ), and uses codebook co-occurrence topology as a retrieval path comple-mentary to vector search. For long-term memory stores, MemCode separates on-line atomic writes from asynchronous offline consolidation. On LongMemEval-S and LoCoMo with GPT-4o-mini and Qwen3-30B-A3B-Instruct-2507 backbones, MemCode achieves the best overall accuracy while keeping per-dialogue mem-ory construction within roughly 40 ∼130 seconds, making it 3 ∼21 × faster than LightMem and over an order of magnitude faster than A-MEM and MemoryOS. 

## 1 Introduction 

Large language model (LLM) agents are rapidly evolving from single-turn systems into persistent assistants that interact with users over extended sessions [1, 2]. However, neither model parameters nor context windows provide a satisfactory substrate for this need. Parameters are largely static after training, while long contexts incur quadratic attention costs [3] and exhibit degraded utilization as sequences grow [4]. It fundamentally elevates the role of agent memory that, distinct from both parameters and context, must accumulate, organize, and recall information across sessions to support personalization, consistency, and long-horizon reasoning. As a result, external memory has emerged as a central component for agent systems. Most memory systems follow a retrieval-augmented generation (RAG) paradigm [5, 6]: past interactions are writ-ten into storage, retrieved at query time, and re-injected into the model context. In this setting, two design choices are tightly coupled: 1) what to write, and 2) how to retrieve it. Prior systems address these choices primarily from memory persistence. Mem0 [7], LangMem [8], and A-MEM [9] im-prove writing and organization through Create, Read, Update, and Delete (CRUD) operations, typed memories, and evolvable note networks; MemoryOS [10] and LightMem [11] improve scalability through scheduling and compression. However, we argue that the key bottleneck for RAG-style long-term memory is not storage scale alone, but jointly modeling what to write and how to retrieve it, as illustrated in Figure 1. This coupling becomes sharper as conversations grow. A memory item may be easy to store but expensive to use if it lacks the necessary context, such as missing speakers or times. Our goal is to create independently retrievable memory units that maintain pointers to raw dialogue, avoiding irreversible abstraction bottlenecks. Specifically, the writing pipeline is retrieval-oriented memory modeling, focusing on creating retrieval-accessible targets that remain understandable and indexable after separation from the orig-inal dialogue. Context-dependent fragments are weak storage units; instead, atomic facts are de-sirable. Long-term recall is usually cued by events and relations, not exact wording. In addition, the retrieval issue revolves around access representation. Most systems use continuous vectors for memory, retrieving content via top-K nearest-neighbor searches [12], as illustrated by the upper pipeline in Figure 1. This works for close memories in surface semantics but inherits the geometric bias of continuous representations: logically related but lexically distant content may be missed, consistent with evidence that dense retrievers can be brittle when retrieval conditions shift across tasks [13]. In contrast, human memory distinguishes itself through pattern separation, allowing the hippocampus to encode similar continuous inputs into discrete traces for associative recall of partial cues [14, 15]. Systems that just mimic human multi-level memory without discrete anchors may still misalign architecture and retrieval. Our proposed MemCode retains the RAG-style pipeline while adding a discrete representation layer alongside continuous vectors, utilized throughout writing, retrieval, and long-term maintenance. During writing, we employ LLM-based ingestion and abstraction to transform dialogue into self-contained AMUs with source pointers. Each AMU serves as a minimal semantic unit that can be independently retrieved. Independent semantic quantization (ISQ) anchors each AMU to a discrete symbolic state within a learnable codebook. During retrieval, global codebook co-occurrence of-fers an alternative access path for logically related yet geometrically distant memories, while source pointers enhance context reconstruction. MemCode also separates online writing from offline con-solidation, allowing clustering and synthesizing AMUs without disrupting real-time retrieval.

2.1 RAG-Based Long-Term Memory for Agents 

Most long-term memory schemes for agents are built on RAG, which combines external stores with generative models to reduce knowledge cutoffs and hallucination; in cross-session memory, the same pattern writes, indexes, and invokes historical interactions [16]. Gao et al. [17] identify retrieval precision and context utilization as central limits that long-term memory inherits. Prior work has explored diverse ways to write and organize memories. Mem0 [7] maintains a dy-namic fact store through LLM-driven CRUD operations. A-MEM [9] organizes memories as an evolvable note network with explicit association edges, while LangMem [8] separates semantic, episodic, and procedural memory. These methods move beyond simple caches, but most machin-ery still sits above a continuous vector index. This leaves two gaps: 1) pronouns and relative-time expressions can make memory units hard to retrieve once detached from the original dialogue; 2) nearest-neighbor access is poorly matched to memories that are logically related but distant in sur-face semantics. Other systems focus on storage management and lifecycle maintenance. Memo-ryOS [10] divides memory into short-, medium-, and long-term levels with heat-driven eviction, LightMem [11] lowers token cost through offline compression, and MEMORY-VQ [18] uses VQ-VAE to compress precomputed token representations for memory-augmented models. These meth-ods improve storage use and throughput, but operate mainly at scheduling, compression, and eviction layers rather than retrieval-oriented memory organization. A long-term memory store can still grow redundant fragments with overlapping semantics, weakening later retrieval [19]. 

2.2 VQ Codebooks as Discrete Memory Anchors 

In machine learning, vector-quantized variational autoencoders (VQ-VAE) [20] provide a standard discretization tool. VQ-VAE maps continuous encodings to discrete embeddings in a finite code-book through a nearest-neighbor quantizer and uses the straight-through estimator (STE) for the non-differentiable quantization step. A finite codebook encourages distinguishable semantic primi-tives and has been widely used in image generation and speech coding [21]. Discrete codebooks can therefore serve as compact anchors for high-dimensional continuous representations. This codebook view is also compatible with neurocognitive memory intuition. Yassa and Stark [14] describe how the hippocampal dentate gyrus separates similar inputs into sparse traces, while the hippocampal CA3 subfield supports pattern completion from partial cues [15]. For agent memory, the relevant lesson is narrower: discrete anchors can separate similar facts and support associative retrieval be-yond geometric nearest neighbors. Dialogue memory, however, requires a retrieval-oriented use of VQ rather than direct lossy compression: because AMUs contain timestamps, entity identifiers, and state descriptions as factual anchors, MemCode applies stride-1 ISQ to preserve token-level alignment and uses the resulting discrete codes as associative retrieval keys.

Large clusters are split by time. Before entering the LLM, a gate skips count-sensitive clusters, restricts update-sensitive clusters, and avoids cross-speaker mixing. Passing clusters are assigned to AGGREGATE, MERGE, or UPDATE, with fewer new facts than archived facts. After write-back, Pointer Forward-ing marks old facts as archived and records their new fact indices, forming a two-level evidence chain with the original Λsrc . At retrieval, old facts are replaced by new ones. If the temporal span of a cluster g ∈ G exceeds the minute level, the new fact is prefixed with [Time Span: Tstart to 

Tend ], where Tstart = min u∈g tabs (u) and Tend = max u∈g tabs (u). The archive policy combines consolidation mode, number of parent facts, time span, and speaker source to decide whether to replace or retain a fact, reducing the risk of irreversible information loss.

4.2 Main Results 

Tables 1 and 2 show that MemCode improves the accuracy–efficiency trade-off across both back-bones and benchmarks. It achieves the highest overall accuracy while reducing construction run-time to roughly 1/21 –1/3 of LightMem’s runtime and 1–2 orders of magnitude below A-MEM and MemoryOS. The category breakdown shows where the gains arise: atomic writing improves precise localization and speaker-aware facts, the codebook path supports structured temporal and composi-tional retrieval, and consolidation partially restores long-range continuity lost by atomic segmenta-tion. Appendix Tables 10–12 further show that backbone choice changes the memory store itself: Table 11 shows that Qwen3 writes denser AMU/codebook traces, while Tables 10 and 12 connect this density to better open-ended coverage but more distractors for exact temporal and multi-hop evidence. Consolidation raises Open to 51.04%, but the synthesized material still comes from extracted facts, leaving limited headroom. In efficiency, MemCode needs only 40.70 seconds on LoCoMo, about one twentieth of LightMem’s runtime; with consolidation, 109.40 seconds remains below all baselines, so the offline stage retains the same parallelism advantage. Boundary of consolidation . Consolidation synthesizes fragmented facts into denser memories, improving LoCoMo Multi by 4.26 and 7.09 points. UPDATE also reduces interference by archiving outdated states. The trade-off is temporal granularity: multiple time points may be compressed into one entry, causing a slight Temporal drop. Since extraction already normalizes absolute time, temporal results after consolidation still outperform or match most baselines. Qwen3 shows larger Multi gains but also a clearer Temporal drop, indicating that different backbones use compressed memories differently. This frames consolidation as an exchange between denser global memory and finer temporal resolution, not a uniformly monotonic gain. Appendix Table 9 shows that the LoCoMo GPT-4o-mini result is stable across repeated runs. Taken together, the two benchmarks separate two regimes. When answers are grounded in explicit entities, dates, speaker bindings, or linked facts, MemCode’s AMUs and discrete topology outper-form raw retrieval and compressed-memory baselines. When answers depend on implicit affect or broad narrative continuity, Full Text and LightMem remain competitive; consolidation narrows this gap by restoring continuity at a small temporal-granularity cost. ## 5 Conclusion 

Continuous nearest-neighbor retrieval leaves systematic gaps in structured long-term memory queries. Our proposed MemCode keeps the RAG-style paradigm but couples atomic abstraction with semantic quantization, topology-aware dual-path retrieval, and asynchronous consolidation. This gives facts stable, discrete anchors and exposes associations beyond vector nearest neighbors. Across LongMemEval-S and LoCoMo, MemCode achieves the best overall accuracy under two backbones while preserving construction efficiency. The component and BM25 replacement abla-tions further clarify the mechanism: extra lexical candidates or larger vector budgets do not recover the same temporal and multi-hop gains unless retrieval follows the discrete co-occurrence struc-ture written during memory construction. This keeps the claim narrow: the advantage comes from matching memory writing, indexing, and reconstruction, not from increasing context volume at query time. The remaining gaps in open questions reflect a clear limitation of AMU-based abstrac-tion: MemCode preserves explicit entities, times, speakers, and factual links well, but it may miss implicit motivations, emotions, and pragmatic cues that are better preserved in the raw dialogue.

## B Implementation Settings 

MemCode uses a lightweight local memory stack. Dialogue and atomic-memory metadata are stored in SQLite, including raw utterances, extracted AMUs, codebook IDs, and code-to-AMU links. Dense retrieval uses a FAISS L2 index over 768-dimensional bge-base-en-v1.5 embeddings [37], while the discrete path uses a 1024-entry VQ codebook and maintains code frequency and code co-occurrence statistics in the metadata store. The online stage writes AMUs asynchronously, assigns both dense vectors and discrete code indices, and reconstructs evidence at query time by combining vector retrieval with topology-aware codebook expansion. E.4 Dual-Path Retrieval: Novelty Analysis and Case Studies 

We measure what the codebook second path adds by computing the proportion of facts indepen-dently hit by the codebook path but not covered by the vector path. Figure 4 shows that the added content is closer to facts that the vector path structurally misses than to candidates the vector path could already find at lower ranks. In particular, 69.3% of facts added by the codebook path are still absent from vector top-100, while simply doubling vector Top-K brings only a 1.4% marginal gain. The difference between the two paths is therefore not retrieval depth but representation: the vector path favors fragments with similar surface semantics, while the codebook path uses co-occurrence topology to activate memories that are logically related but more distant on the surface. 

Figure 4: Dual-path retrieval: novelty analysis and case studies. The three cases in Figure 4(C) show the same complementarity in concrete tasks. The failures fol-low different patterns: in the counting question, the vector path misses another independent entity (Coco); in the location question, it misses a low-frequency proper noun (Whispering Falls); in the shared-attribute question, it misses parallel facts scattered across dialogue fragments. Entity omis-sion, suppression of low-frequency proper nouns, and cross-fragment attribute dispersion all follow from geometric nearest-neighbor bias. Codebook topology compensates for them by modeling co-occurrence relations. Together with the BM25 control, this novelty evidence supports a more specific claim: the codebook path recovers structured evidence that both vector and lexical paths often miss. 

E.5 Additional Codebook Space Analysis

26 G Responsible Use and Existing Assets 

Broader impacts. MemCode is intended to make long-term agent memory more reliable, auditable, and efficient. Better memory systems can improve personalized assistance, reduce repeated user ef-fort across sessions, and make retrieved evidence easier to inspect through source pointers and struc-tured memory records. The same capability also raises risks when deployed on real user histories: a persistent memory store may retain sensitive personal information, propagate extraction mistakes into future personalization, or retrieve outdated facts after user preferences or circumstances change. These risks are especially relevant because MemCode targets cross-session memory rather than iso-lated question answering. Responsible deployment should therefore treat the memory store as user data rather than as ordi-nary model cache. Practical safeguards include explicit user consent for memory creation, user-visible inspection and deletion controls, retention limits, access control for stored memories and source dialogue, and deployment-time filters for sensitive categories. MemCode’s source point-ers, archived-fact records, and conservative consolidation gates provide auditability and reduce ir-reversible rewriting, but they do not replace product-level privacy controls or jurisdiction-specific compliance review.
