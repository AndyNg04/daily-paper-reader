## 摘要
在长时程工具调用任务中，LLM 智能体的失败不仅源于工具使用错误，也可能是由于与用户交互无效。然而，现有基准测试大多假设用户具有合作意愿且行为稳定，因此情绪变化对智能体可靠性的影响尚未得到充分研究。我们提出 $τ$-Emotion-Bench，这是一个涵盖十个领域的基准，用于在受控的、由情绪调节的用户交互中评估工具调用智能体，同时保持底层任务目标不变。为扩展基准构建和智能体训练的规模，我们提出 Tracer，这是一种可扩展的智能体数据生成流程，可构建有依据且符合策略要求的任务，并通过交互式智能体—用户—环境框架收集轨迹。该框架允许不满的用户终止低效交互，从而提供关注交互过程的信号，筛除过度依赖用户的轨迹，并鼓励有效使用工具。使用两种用户模拟器进行的实验表明，前沿智能体仍不可靠，其平均任务成功率与稳定完成任务的能力之间存在显著差距。Tracer 生成的监督数据能够持续提升不同规模的 Qwen3 模型，泛化至未见领域，并迁移至 $τ$-Bench 和 $τ$-Trait。行为分析进一步表明，较高的任务成功率与工具执行和必要用户跟进之间更佳的平衡相关。总体而言，$τ$-Emotion-Bench 和 Tracer 提供了一个可扩展框架，可用于评估智能体在多样化用户行为下的可靠性，并通过关注交互过程的监督数据改进工具调用智能体。

## Abstract
In long-horizon tool-calling tasks, LLM agents can fail not only because of tool-use errors, but also because of ineffective interaction with users. Yet existing benchmarks largely assume cooperative and behaviorally stable users, leaving the effect of emotional variation on agent reliability underexplored. We introduce $τ$-Emotion-Bench, a ten-domain benchmark for evaluating tool-calling agents under controlled emotion-conditioned user interactions while preserving the underlying task objective. To scale both benchmark construction and agent training, we introduce Tracer, a scalable agentic data-generation pipeline that constructs grounded, policy-valid tasks and collects trajectories through an interactive agent--user--environment harness. By allowing dissatisfied users to terminate inefficient interactions, the harness provides an interaction-aware signal that filters trajectories with excessive user dependence and favors effective tool use. Experiments with two user simulators show that frontier agents remain unreliable, with substantial gaps between average task success and consistent task completion. Tracer-generated supervision consistently improves Qwen3 models across scales, generalizes to unseen domains, and transfers to $τ$-Bench and $τ$-Trait. Behavioral analyses further show that higher task success is associated with a better balance between tool execution and necessary user follow-up. Overall, $τ$-Emotion-Bench and Tracer provide a scalable framework for evaluating agent reliability under diverse user behaviors and improving tool-calling agents through interaction-aware supervision.

## 1. 核心问题与研究背景

### 1.1 研究动机

现有工具调用基准逐渐引入多轮对话、状态化环境和领域政策，但往往仍假设用户配合、行为稳定，主要依据最终任务结果评价智能体。这会遗漏两类问题：

- **交互低效但最终成功**：智能体反复追问、要求用户提供可通过工具查询的信息，仍可能获得成功奖励。
- **用户情绪影响任务推进**：焦虑、愤怒、不信任或急迫可能改变用户的信息披露、耐心和配合程度，使原本可解的任务失败。

因此，论文研究的是：**在任务目标不变的情况下，情绪条件化用户交互如何暴露工具型智能体的可靠性问题，以及这种交互反馈能否用于生成更有效的训练数据。**

### 1.2 整体含义

论文提出两个相互配合的组件：

- **τ-Emotion-Bench**：评测智能体面对不同用户情绪与行为表达时的任务完成能力。
- **Tracer**：生成可执行、符合政策的任务，并利用用户不满终止机制筛选训练轨迹。

需要注意，标题中的“真实世界用户情绪”主要指**面向现实情境设计的情绪类型与行为条件**，并不意味着主要实验来自真实用户交互数据。

## 2. 方法论：核心思想与关键技术

### 2.1 情绪条件化的智能体—用户—环境框架

论文沿用 τ-Bench 的部分可观测任务框架：

- **智能体动作**：工具调用、自然语言回复。
- **观测**：工具返回结果、用户消息。
- **环境**：可执行工具、数据库和领域政策。
- **用户模拟器**：根据任务、情绪条件及对话历史产生回复。

其核心表达为：

\[
u_t \sim \pi_{\text{user}}(\cdot \mid u,e,h_t)
\]

其中，\(u\) 是任务指令，\(e\) 是情绪条件，\(h_t\) 是交互历史。**情绪条件在单次任务内固定，但表达可随交互进展变化；任务目标和环境保持不变。**

用户可输出：

- `###STOP###`：认为任务完成、正常结束。
- `###UNSATISFIED###`：因冗余追问、信任受损、忽略情绪需求等提前退出。

若用户在任务成功前因不满退出，轨迹获得 **−1 奖励**；其他未成功轨迹为 0，满足成功条件的轨迹为 1。这里的交互信号主要通过**终止机制和轨迹筛选**发挥作用，而非连续、细粒度的效率奖励。

### 2.2 Tracer 任务生成流程

1. **构建工具依赖图**
   - 节点对应工具，边表示接口和领域政策允许的工具衔接。
   - 使用模型生成候选图，再人工选择和核验。

2. **采样多步工作流**
   - 组合 1–3 个独立意图，每个随机游走包含 2–6 次工具调用。
   - 去重后，十个领域共得到 **42,138 条工具轨迹模板**。
   - 训练与评测使用不同轨迹模板。

3. **环境落地与自然语言改写**
   - 在可执行环境中填充实体和参数，生成参考轨迹。
   - 将工具流程反向改写为自然用户请求，并加入可满足的偏好。

4. **生成并匹配情绪**
   - 根据任务情境描述用户可能的感受。
   - 感受生成器不访问环境数据库，降低泄露用户未知信息的风险。

5. **验证与人工修订**
   - 检查目标明确性、信息充分性、可执行性及政策一致性。
   - 优先通过确定性回放验证，结果不明确时才采用模型裁决。
   - 所有最终评测任务均经过人工检查。

### 2.3 情绪建模

论文设置五类情绪：

- 愤怒、恐惧、厌恶、悲伤、愉悦。

共包含 **22 种细粒度情绪**，再结合三个三值行为维度：

- 礼貌：温暖、中性、冷淡。
- 紧迫性：低、中、高。
- 信任：信任、谨慎、怀疑。

因此共有：

\[
22 \times 3^3 = 594
\]

种条件。每种条件生成 10 条自然语言锚点，共 **5,940 条**；通过文本嵌入、多头分类器和近邻相似度投票，为任务选择情绪条件。用户模拟器接收自然语言指令，而不是离散标签。

### 2.4 训练轨迹筛选

- 使用 **Qwen3.8-27B thinking** 作为轨迹生成智能体。
- 使用 **Qwen3-235B-A22B-Instruct** 作为情绪用户模拟器。
- 只保留最终数据库状态符合参考结果、且用户未不满终止的成功轨迹。
- 对 Qwen3-1.7B、4B、8B 进行监督微调，保留教师模型的推理过程。

这属于**带交互约束的成功轨迹筛选与监督学习**，不是直接开展强化学习。

## 6. 主要结论与发现

### 6.1 前沿模型仍缺乏稳定性

| 用户模拟器 | 最佳模型 | Avg@3 | Pass³ |
|---|---|---:|---:|
| Qwen3 用户 | DeepSeek-V4.1-Flash | 55.9% | 32.2% |
| GLM-5.2 用户 | GLM-5.3 | 78.6% | 66.5% |

- 模型平均成功率与三次稳定成功率存在明显差距。
- 领域差异显著，例如 GLM-5.3 在 Qwen 用户下，篮球 Pass³ 为 62.0%，电信仅 2.9%。
- 更换模拟器显著改变绝对分数，说明评测结果具有较强的模拟器依赖性。

### 6.2 Tracer 显著提升小模型

Qwen 用户下，Tracer-High 的 Pass³：

- 1.7B：**1.2% → 10.4%**。
- 4B：**3.9% → 17.2%**。
- 8B：**8.4% → 19.8%**。

GLM 用户下，Avg@3：

- 1.7B：11.1% → 36.3%。
- 4B：31.2% → 51.4%。
- 8B：37.6% → 54.7%。

### 6.3 存在迁移收益，但绝对水平仍低

- Tracer-Low 在六个未见领域的平均 Pass³ 分别达到 **2.7%、7.7%、8.3%**，均为相应规模所比较训练方法中的最高值。
- 8B 的 Pass¹ 为 20.7%，略低于 EnvScaler 的 20.8%，不能表述为所有指标全面领先。
- 在 τ-Bench、τ-Trait 上也观察到提升。

### 6.4 主要失败仍是执行问题，而非缺少共情

- 故障主要集中于误读意图、动作顺序错误、错误参数和遗漏动作。
- 情绪忽视在所分析故障中占比低于 1.7%。
- 共情语言通常伴随更多追问，其与成功率的关系随情绪和模型变化，**不能据此断言共情导致失败**。
- 更高成功率与适度的工具调用—必要追问平衡相关，而不是工具调用越多越好。

用户幻觉分析发现错误比例较低，但这主要证明任务信息一致性，**不等于证明模拟用户具有真实人类情绪行为的效度**。

## 7. 优点与亮点

- **问题定位贴近应用**：将过度追问、程序摩擦、用户退出纳入智能体可靠性研究。
- **评测与训练机制统一**：同一交互框架既暴露失败，也提供轨迹筛选信号。
- **任务可执行且有政策约束**：比纯文本对话打分更容易核验实际结果。
- **质量控制较扎实**：确定性回放、人工复核、内部 ID 替换和任务修订降低构造错误。
- **多维迁移验证**：覆盖不同规模、未见领域、外部基准和另一用户模拟器。
- **行为解释较克制**：论文承认训练轨迹分布与泛化能力之间的证据仍是相关性的。

---

## 8. 不足与局限

### 8.1 情绪真实性与代表性有限

- 主要依据 LLM 生成的情绪指令，而非真实用户行为数据。
- 模拟器被要求强烈体现情绪，可能产生夸张、刻板化表达。
- 情绪与礼貌、紧迫性、信任共同变化，难以独立识别情绪因素。
- 情绪分布不均：Tracer-High 中兴奋、平静、自豪合计约 70.6%，部分负面情绪样本极少；理论上有 594 种条件，不代表均衡覆盖。

### 8.2 机制归因和评价效度仍需加强

- 训练收益可能同时来自教师模型质量、推理过程蒸馏、任务生成方式、数据筛选和额外混合数据。
- 用户模拟器和错误裁判使用同一模型家族，存在共享偏差风险。
- 以用户是否满意作为训练约束，可能鼓励迎合或牺牲必要确认，尤其需要在金融、医疗等场景检查安全后果。

### 8.3 数据隔离与人类验证有限

- 前四领域训练与评测共用数据库，虽轨迹不同，仍不能排除实体熟悉度带来的收益。
- 人类试验仅涉及少量选定任务，不是大规模真实用户研究。
- 附录个别人类轨迹缺少严格的操作前确认，也出现无工具依据的陈述，因此更适合证明任务大体可解，不能作为完整合规的性能上界。

### 8.4 应用与资源边界

- 仅验证监督微调，尚未验证强化学习。
- 主要是结构化客服工具环境，尚未覆盖网页、GUI、编码等开放式任务。
- 单次任务情绪条件固定，难以模拟真实用户的情绪转变。
- 缺少真实延迟、经济成本及长期满意度评估；“样本量较少”也不等于整体生成与训练成本低。

**综合判断**：论文最有价值的贡献，是把“用户是否愿意继续配合”转化为可操作的评测与训练约束。现有结果较有力地支持 Tracer 数据能够改善任务执行与迁移表现，但对于情绪的独立影响、交互筛选机制的因果贡献，以及真实用户场景中的有效性，仍需更严格的消融和人类验证。
