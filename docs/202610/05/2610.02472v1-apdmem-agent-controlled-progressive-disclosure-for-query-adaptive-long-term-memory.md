## 摘要
个性化大语言模型（LLM）助手必须能够针对复杂程度各异的查询，从长期对话历史中找回稀疏证据。我们提出 APDMem（智能体控制的渐进式披露记忆），这是一种将渐进式披露应用于记忆检索的分层长期记忆架构。APDMem 不依赖扁平化记忆存储或固定的检索粒度，而是将对话历史表示为四个细节逐步递增的层级：主题摘要、个性化关键信息、轮次级证据记录和原始消息。在推理时，控制器对记忆层级进行渐进式披露：首先读取高层摘要，仅在需要时才深入检索更细致的证据。这实现了自适应的成本—保真度权衡：简单查询可以提前结束，而复杂的时间推理、多跳推理或精确证据查询则会触发更深入的检查。笔记合成器会将检索到的证据整理成面向查询的结构，在生成最终答案前汇总事实、排列事件顺序并标记矛盾。在 LongMemEval 上的实验表明，APDMem 在长上下文记忆推理任务中表现出色，同时仅访问了全部对话内容的 8%。

## Abstract
Personalized LLM assistants must recover sparse evidence from long conversation histories across queries of varying complexity. We introduce APDMem (Agent-controlled Progressive Disclosure Memory), a hierarchical long-term memory architecture that applies progressive disclosure to memory retrieval. Rather than relying on a flat memory store or fixed retrieval granularity, APDMem represents conversation history as four progressively detailed layers: thematic summaries, personalized key facts, turn-level evidence notes, and raw messages. At inference time, a controller applies progressive disclosure to the memory hierarchy: it first reads high-level summaries and drills into finer evidence only when needed. This creates an adaptive cost-fidelity trade-off: simple queries can terminate early, while complex temporal, multi-hop, or exact-evidence queries trigger deeper inspection. A note synthesizer converts retrieved evidence into a query-focused structure that consolidates facts, orders events, and flags contradictions before final answer generation. Experiments on LongMemEval show that APDMem achieves strong performance for long-context memory reasoning while accessing only 8% of the total conversations.

## 1. 核心问题与研究背景

### 1.1 论文要解决什么问题？

个性化 LLM 助手需要从长期、多会话的历史交互中恢复用户信息，但相关证据往往**稀疏、分散，而且细节需求随问题变化**：

- 简单偏好问题，可能读取关键事实即可回答。
- 跨会话、多跳问题，需要结合多个会话中的信息。
- 时间或知识更新问题，需要识别事件顺序与最新状态。
- 精确回忆问题，需要恢复具体名称、数字甚至原始措辞。

现有记忆系统通常采用固定粒度的事实、摘要、片段或图结构，容易面临两种风险：**压缩过度而丢失细节，或检索过多而增加成本与噪声**。

### 1.2 整体思路与意义

APDMem 将长期记忆访问从“一次检索相关内容”转变为：

> **先定位相关记忆，再由智能体决定需要读取多深的证据。**

其核心是“渐进式披露”：先暴露粗粒度信息，仅在证据不足时读取更细层级。它同时自适应决定：

- **检索广度**：需要查看多少个会话。
- **检索深度**：每个会话需要读到什么粒度。

论文的主要价值是提出并验证一种**查询自适应的记忆访问架构**，而不是新的训练算法或基础模型。

## 2. 方法论：核心思想、技术细节与算法流程

APDMem 由三个主要组件组成：**多分辨率记忆底座、渐进式披露控制器、结构化笔记合成器**。

### 2.1 四层记忆底座

每个会话表示为四层记忆：

| 层级 | 内容 | 主要用途 | 构建方式 |
|---|---|---|---|
| **L0** | 逐轮主题摘要、关键词、标签 | 搜索与定位候选会话 | 入库时生成 |
| **L1** | 个性化关键事实 | 获取用户信息、偏好、计划和约束 | 首次访问时生成并缓存 |
| **L2** | 按轮次排列的原子事实笔记 | 细粒度证据定位与时间顺序分析 | 首次访问时生成并缓存 |
| **L3** | 原始用户—助手消息 | 恢复精确名称、措辞及遗漏细节 | 入库时直接保留 |

关键技术细节：

- **消解指代**：将代词替换为明确实体，降低脱离上下文后的歧义。
- **时间标准化**：以会话日期为锚点，将相对时间转换为绝对日期。
- **惰性物化**：仅预先生成 L0、保留 L3；L1、L2 按需生成，避免为从未访问的会话支付处理成本。
- **保留原始证据**：摘要遗漏信息时，仍可深入 L3 恢复。
- **透明存储**：以 Markdown 分层保存，而不是必须转换为专用图数据库；但系统仍需要词法、向量索引等检索设施。

### 2.2 混合检索

控制器首先在 L0 上检索，采用：

- **BM25 词法检索**：匹配名称、日期、地点等精确信息。
- **稠密向量检索**：使用 Nomic-v1.5、768 维向量，匹配语义相关内容。
- **倒数排名融合（RRF）**：融合两类检索排名。
- **关键词字段加权**：增强实体密集型查询的精确匹配。

会话分数由该会话中最佳匹配摘要单元决定；多个查询的结果也采用最佳匹配分数聚合。

主要参数包括：

- 候选会话 Top-K 为 **20**。
- 每次搜索自动深入 **3 个**候选会话。
- L0 使用 **4 轮窗口、1 轮重叠**。
- 最多读取 **20 个原始轮次**。

### 2.3 渐进式披露控制器

控制器通过工具调用执行检索和推理：

- `search`：搜索 L0。
- `read_facts`：读取 L1。
- `read_turns`：读取 L2。
- `read_raw`：读取 L3。
- `interpret_dates`：解析相对时间。
- `decompose`：拆分复杂问题。
- `reflect`：检查证据是否充分，并提出补充查询。

典型流程如下：

1. **准备查询**：解析时间约束，必要时分解成子问题。
2. **搜索候选会话**：在 L0 上进行混合检索。
3. **逐步取证**：先读取 L1；不充分时继续读取 L2、L3。
4. **反思与补检索**：检查缺失信息、枚举完整性、重复项及跨会话证据。
5. **停止并起草答案**：证据充分、检索不再带来新增证据，或达到预算后停止。
6. **整理证据并生成最终答案**。

论文将目标表达为：**在证据足以回答问题的前提下，最小化累计访问成本**。这里的成本—保真度优化是架构层面的目标，实际由提示词驱动的控制器近似实现，并非通过显式训练得到最优策略。

所有实验设置最大控制器迭代数为 **20**。实际中位数约为 GPT-4.1 的 **5 次**、GPT-4.1-mini 的 **3 次**。需注意，一次迭代可包含多个工具调用，因此迭代上限不等于严格的工具调用或 token 上限。

### 2.4 结构化笔记合成

合成器接收查询、检索证据与控制器草稿，将内容组织为：

- 相关事实及其会话来源、日期。
- 时间顺序与最新状态。
- 矛盾及更新记录。
- 枚举、去重与不确定项目。
- 答案提示。

最终生成器基于笔记和草稿独立核验证据，减少直接阅读杂乱片段时的遗漏与错误。

- Mem0。
- RAPTOR。

主实验使用 **GPT-4.1、GPT-4.1-mini** 两种骨干模型。效率实验使用 GPT-4o-mini；异构部署实验额外测试 GPT-5.2 控制器。

## 6. 主要结论与发现

### 6.1 少量深入访问可以保持较高准确率

GPT-4.1 配置平均深入读取 **3.7/47.7 个会话，约 8%**，同时达到 **87.8%** 准确率。

这里的 8% 指**深入访问的会话比例**，不是全部检索扫描、摘要访问或原始内容读取比例。

### 6.2 披露深度确实随问题变化

在 **1,838 次会话深入访问**中：

- **73.7%** 停止于 L1。
- **6.1%** 停止于 L2。
- **20.2%** 深入 L3。

单会话精确回忆更常需要原文；知识更新和多会话推理通常可以更多依赖关键事实。

### 6.3 控制器与原始证据访问都重要

相对完整系统的 87.8%：

- 去掉控制器：**83.2%**，下降 **4.6 个百分点**。
- 仅用原始消息的普通 RAG：**77.0%**，下降 **10.8 个百分点**。
- 去掉 L3：**82.6%**，下降 **5.2 个百分点**。
- 去掉 L1 或反思工具：均为 **84.6%**。
- 去掉 L2：**87.4%**，影响较小。

论文表中的“下降百分比”是相对降幅，应与百分点下降区分。

### 6.4 证据发现是主要瓶颈

骨干从 GPT-4.1-mini 升级为 GPT-4.1 后，检索错误率从 **22.2% 降至 10.6%**，生成错误仍约为 8%—10%。

固定 GPT-4.1-mini 生成器：

- 同款轻量控制器：**79.8%**。
- GPT-4.1 控制器：**86.8%**。
- GPT-5.2 控制器：**87.8%**。

这支持“**强控制器＋轻量生成器**”的异构部署策略，但是否更便宜仍需结合模型单价判断。

### 6.5 证据组织有独立价值

固定检索结果后：

- 去掉草稿：下降 **1.2 个百分点**。
- 去掉结构化笔记：下降 **2.6 个百分点**。
- 两者都去掉：下降 **4.2 个百分点**。

说明准确率提升不仅来自检索，也来自生成前的证据整理。

## 7. 优点与亮点

- **同时适应检索广度和深度**：可跨会话找证据，也可在单个会话中逐层恢复细节。
- **兼顾压缩与保真**：抽象层用于高效定位，原文层保留精确证据。
- **惰性生成降低无效构建**：减少为未访问会话生成细粒度记忆的成本。
- **结构透明、便于审计**：Markdown、会话日期和逐轮证据有利于调试及溯源。
- **证据组织针对常见难点**：显式处理时间、矛盾、枚举和去重。
- **实验分析较全面**：包含组件消融、多次运行、人工验证和检索行为分析。
- **提供可操作的部署启示**：模型能力可优先配置给证据检索控制器，而非仅升级最终生成器。

## 8. 不足与局限

### 8.1 摘要仍是检索瓶颈

L0 是主要入口。若摘要遗漏关键实体或细节，相应会话可能根本无法进入候选集合；即使 L3 保留了原文，也未必能够访问到。关键词增强与反思只能部分缓解。

### 8.2 停止机制可能把搜索停滞误认为证据充分

“没有新证据”不必然意味着“已经找到全部证据”。这一风险对计数、完整枚举和分散证据问题尤其明显。控制器缺乏经过校准的充分性判定。

### 8.3 效率优势尚未完成端到端验证

- 冷启动在线 token 成本仍较高，平均延迟为数十秒。
- 缺乏与基线的在线成本对比。
- 未报告完整回答链路的总成本、尾延迟或缓存命中收益。
- 因而“访问少量会话”与“实际运行便宜、快速”不能直接等同。

### 8.4 实验覆盖较窄

仅验证 LongMemEval-S，缺少：

- 更大规模历史和长期持续更新。
- 真实用户、多语言及专业领域场景。
- 多模态、工具执行和个性化行为任务。
- 更系统的预算、缓存和参数敏感性实验。

### 8.5 表示与推理规则存在风险

- L1 限制为 5—25 条事实、输入最多 12,000 字符，与提示词要求“不遗漏任何事实”之间存在张力，长会话可能被截断或压缩。
- 指代消解和日期转换依赖 LLM，错误可能在多个层级传播。
- 笔记提示将“最新日期”等同于当前真相，对历史回顾、假设讨论或信息撤回等情形可能过于简单。
- 草稿有助于回答，也可能对笔记合成器造成锚定偏差。
- 没有显式跨会话关系建模，复杂关系推理仍依赖控制器逐次搜索。

### 8.6 部分组件的成本收益和因果贡献仍需厘清

- L2 的准确率增益较小，需要进一步证明其定位、延迟或成本收益。
- 普通 RAG、分层 RAG和智能体系统之间可能还有检索组织及上下文构造差异，不能把全部性能差距纯粹归因于层级结构。
- 成本表中模型能力与 token 使用量并非单调关系，不能概括为“模型越强，检索越省”。

### 8.7 生产部署问题尚未验证

论文保留原始对话和多层衍生记忆，但未系统评估隐私权限、删除同步、敏感信息隔离及历史消息中的提示注入风险。

**总体评价：**APDMem 有力证明了“按需逐层取证”在长期记忆问答中的价值，尤其适合既需要跨会话整合、又需要精确回忆的助手。其准确率与组件有效性证据较扎实，但真实部署的端到端效率、复杂更新语义、安全性和跨场景泛化仍需进一步验证。
