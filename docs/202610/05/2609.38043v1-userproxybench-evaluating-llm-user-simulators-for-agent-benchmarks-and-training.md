## 摘要
交互式智能体基准测试和多轮强化学习越来越多地让另一个语言模型扮演用户。这个模拟用户决定向智能体提供哪些信息以及何时提供，但当前基准测试只对智能体评分，并不直接衡量用户是否正确履行了分配给它的角色。我们提出 UserProxyBench——一个构建于 tau-bench 系列之上的评估层，以及用户忠实度分数（User Fidelity Score，UFS）。UFS 使用以任务为依据的评分标准，衡量用户对基准测试私有用户指令的遵循程度，且评分独立于智能体是否成功。将智能体固定为 GPT-5.5、仅改变用户代理，在 375 项企业任务上的平均任务奖励会相差 15.2 分；与此同时，24.4% 的成功交互轨迹包含违反用户规范的情况。最主要的失败类型是过早披露：用户在收到请求前便提供信息。这种行为对任务奖励影响甚微，但在成功交互轨迹中，会使智能体平均少调用 1.06 次工具，从而在保持奖励不变的同时改变受评估的交互过程。最后，我们在七种用户代理中发现了一条经验性的成本—忠实度前沿，使实践者能够选择满足所需忠实度水平的成本最低的模拟器。

## Abstract
Interactive agent benchmarks and multi-turn reinforcement learning increasingly place a second language model in the role of the user. This simulated user controls what information the agent receives and when, yet current benchmarks score only the agent and do not directly measure whether the user correctly executed its assigned role. We introduce UserProxyBench, an evaluation layer over the tau-bench family, and the User Fidelity Score (UFS), which measures adherence to the benchmark's private user instructions using task-grounded rubric criteria scored independently of agent success. Holding the agent fixed at GPT-5.5 and varying only the user proxy across 375 enterprise tasks changes mean task reward by 15.2 points, while 24.4% of successful episodes contain a user-specification violation. The dominant failure is premature disclosure: users provide information before it is requested. This behavior has little effect on task reward, yet among successful episodes it causes the agent to make 1.06 fewer tool calls on average, changing the interaction being evaluated while preserving the reward. Finally, across seven proxies we identify an empirical cost-fidelity frontier, enabling practitioners to select the least expensive simulator that satisfies a required fidelity level.

### 研究背景与动机
- 在 τ-bench 等交互式智能体基准、多轮强化学习系统中，通常由一个 LLM 扮演智能体，另一个 LLM 扮演用户。
- **模拟用户并非被动提供对话，而是评测环境的一部分**：它决定信息披露时机、提供哪些事实，以及是否执行用户侧操作。
- 现有评测主要关注智能体是否完成任务，却较少检验模拟用户是否遵守角色设定。例如，用户提前透露姓名和电话号码，会省去智能体本应完成的信息收集步骤，即使最终任务奖励不变，实际评测难度也已经改变。

### 核心研究问题
论文关注的是：**模拟用户是否忠实执行了基准规定的用户契约？任务成功率能否代替这种检查？**

这里的“保真度”指**功能性保真度／契约遵循**，而不是模拟用户像不像真人。高保真模拟器应遵守其私有背景、知识边界、目标、信息披露规则及工具操作要求。

### 整体含义
论文将用户模拟器从“默认可信的评测配件”转变为“需要独立评估的环境组件”。其核心观点是：

> 智能体成功，不意味着用户模拟正确；评价交互式智能体时，必须同时检查任务结果与交互环境的有效性。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 UserProxyBench 与用户保真度分数
UserProxyBench 是构建在 τ-bench 系列之上的**用户侧评估层**，不替代原有智能体任务奖励。

论文定义 **User Fidelity Score，UFS**：
- 为每个任务建立一组适用的用户行为标准。
- 一条交互轨迹只有在**全部适用标准均通过**时，才被判定为用户保真度合格。
- UFS 是所有可评分轨迹中，完全合格轨迹的比例。

因此，它采用严格的“全通过”判定，而非逐条标准得分的平均。智能体任务奖励记为 \(R_\tau\)，与 UFS 分开报告。

### 2.2 任务相关评分标准的构建
评分流程如下：

1. **收集任务依据**
   - 私有用户蓝图：角色、已知与未知信息、目标及任务指令。
   - 通用用户模拟规则。
   - 用户可调用的工具。
   - 一条示例交互，用于识别可能出现的情境，**不作为正确答案依据**。

2. **生成原子化标准**
   - Claude Opus 4.8 为每个任务生成约 **4–8 条**标准。
   - 每条标准必须引用原始指令中的直接依据、能根据轨迹判定真假，并且只评价用户行为。

3. **独立审核标准**
   - GPT-5.6-Sol 检查依据、可判定性、用户归因、可实现性、冗余及范围等问题。

4. **逐条评价轨迹**
   - Claude Opus 4.8 在不知道模拟用户模型身份的情况下评分。
   - 评分标准生成者与最终评分者使用同一模型；独立验证模型审核的是标准，而非全部最终判分。

最终保留 **2,141 条标准**，平均每任务约 **5.7 条**，覆盖四类失败：

| 失败类别 | 主要含义 |
|---|---|
| 事实与状态依据错误（groundedness） | 编造未知信息、虚构设备状态、声称执行了实际未执行的操作等 |
| 提前披露信息 | 未被询问就提供信息、提前完成诊断信息披露、倾倒用户背景 |
| 偏离目标 | 过早停止、接受不符合要求的结果、放弃目标 |
| 遗漏信息或操作 | 不提供已被请求的信息、跳过被要求的用户操作 |

其中，提前披露的判定来自明确规则：“逐步披露信息，等待智能体询问具体信息后再提供”，不是研究者隐含的风格偏好。

### 2.3 无需 LLM 裁判的工具操作检查
- 在 Telecom 场景，论文额外将实际用户工具调用与基准规定的“金标准写操作”比较。
- 这一检查可以发现“口头声称完成操作，实际没有执行”的问题。
- 因其他领域不具备同样的检查信号，该结果作为独立诊断报告，未并入跨领域 UFS。

### 2.4 成本约束下的模拟器选择
论文提出：给定最低保真度要求 \(q\)，选择 **UFS 不低于 \(q\) 的最低成本模拟器**。

由此形成经验性的“成本—保真度前沿”：如果另一个模型既更便宜、又更忠实，则当前模型被严格支配。这是一种选型原则，而不是新的模型训练算法。

## 6. 主要结论与发现

### 6.1 更换用户模拟器，会改变同一智能体的评测成绩
- 固定 GPT-5.5 后，跨领域平均任务奖励从 **0.644 到 0.796**，相差 **15.2 个百分点**。
- 领域内奖励跨度：
  - Telecom：13.2 个百分点。
  - Airline：28.0 个百分点。
  - Retail：29.8 个百分点。
  - Banking：4.6 个百分点。

这表明，测得的智能体成绩不仅由智能体能力决定，也受模拟用户行为影响。

### 6.2 成功轨迹仍可能包含用户违规
- **24.4% 的智能体成功轨迹未通过 UFS**。
- 在 Telecom，所有轨迹中有 **39.7%** 同时表现为“智能体成功、用户保真度失败”。

一个突出例子是：Sonnet-4-6 与 GPT-4.1-mini 在 Telecom 的任务奖励同为 **0.947**，但 UFS 分别仅为 **0.474** 与 **0.737**。

### 6.3 最常见的违规，恰恰不容易被任务奖励发现
| 失败类别 | 观察到的失败数 | 出现该类失败时，平均成功率差值 |
|---|---:|---:|
| 提前披露 | 480 | −0.043 |
| 偏离目标 | 134 | −0.515 |
| 依据错误 | 109 | 约 −0.15 |
| 遗漏信息／操作 | 52 | 约 −0.22 |

- 上述类别可能在同一轨迹中重叠，数量不应直接相加理解为独立失败轨迹数。
- 提前披露最多，但与成功率下降的关联最弱；其成功率差值中位数甚至为正。
- 这些是分组观察比较，**不是随机干预意义上的因果效应**。

### 6.4 奖励不变，交互过程仍会改变
在成功轨迹中，提前披露信息的用户对应：
- 智能体平均少 **1.06 次工具调用**。
- 平均少 **0.26 次提问**。

七个模拟器之间：
- 平均智能体轮数变化约 **26%**，提问次数变化约 **25%**。
- 平均轮数与 UFS 的相关系数为 **0.955**，与任务奖励的相关系数为 **0.594**。

这说明 UFS 比终局奖励更能反映交互过程的变化，但不能据此断言“轮数更多就一定更好”，也不能直接证明训练后的策略会受到何种影响。

### 6.5 模型选型存在成本—保真度权衡
- 要求 UFS ≥ 0.84：**Gemma-31B** 是测试模型中的最低成本合格者，UFS 为 **0.845**。
- 要求 UFS ≥ 0.86：选择 **Gemini-3.5-Flash**，UFS 为 **0.864**。
- 要求 UFS ≥ 0.75：**GPT-4.1-mini** 更便宜，UFS 为 **0.752**。
- Sonnet-4-6、Qwen3.6-35B、GPT-5.4-mini 在总体成本—UFS 平面上被严格支配。

该结论只适用于本文测试任务、配置与价格条件。

## 7. 优点与亮点

- **问题定位重要**：揭示了交互式评测中经常被忽略的用户侧有效性问题。
- **概念边界清楚**：将“遵守任务契约”与“像真人”分开，避免把不同目标混为一谈。
- **控制实验直观**：固定智能体和任务，只更换用户模型，清楚展示模拟器对成绩的影响。

- **兼顾实用性**：成本—保真度前沿直接服务于评测和训练环境的预算决策。
- **主动揭示评分盲点**：用机械操作检查发现 LLM 裁判漏检，没有将 UFS 包装为完美指标。

## 8. 不足与局限

### 8.1 LLM 评判仍有明显盲点
- 标准生成与最终评分使用同一模型，存在共享偏差和一致性误判风险。
- Telecom 检查发现 **54 条轨迹遗漏金标准写操作**：
  - 其中 **23 条仍通过全部适用语义标准**。
  - **20 条通过了直接相关的标准**。
- 因此，高 UFS 不保证工具执行正确；评价工具型用户应结合状态验证与确定性检查。

### 8.2 UFS 的聚合方式具有局限
- “全部通过”使一条较轻违规与多条严重违规都记为失败，无法体现严重程度差异。
- 每任务标准数量不同，任务越多标准，完全通过可能越难。
- 总体 UFS 会隐藏失败结构：
  - 去掉披露标准后，Qwen 从第六升至第三，Gemma-26B 从第四降至最后。
  - 披露类与非披露类 UFS 的相关性仅为 **0.071**。
- 因而应同时查看领域表现、失败类别和关键操作合规率，而不是只看一个总分。

### 8.3 外部有效性有限
- 只覆盖四个企业领域、七个模拟器和一个智能体。
- 未验证真人交互、其他任务类别及不同人群。
- 高契约保真度不代表能够覆盖真实用户的语言差异、无障碍需求、误解或对抗行为。

### 8.4 强化学习影响尚未直接验证
- 论文证明了轨迹特征变化，但没有实际比较不同 UFS 模拟器训练出的策略。
- “提前披露可能削弱信息收集能力的学习”是合理担忧，尚不是本文已证实的训练结论。

### 8.5 成本与复现条件具有时效性
- 服务价格、模型版本与推理设置会改变成本前沿。
- 自托管成本使用公开服务价格折算，不等于真实本地部署总成本。
- 算力与运行时长报告不足，限制了资源层面的完整复现。

**综合评价：**本文的重要贡献是建立“用户模拟器也需要独立验收”的评测框架，并提供任务奖励掩盖用户违规的实证证据。其结果支持把 UFS 与任务奖励联合报告，但 UFS 仍需更大规模的盲评人工验证、重复采样、跨智能体验证和真实训练实验，才能成为更可靠的通用选型依据。
