## 摘要
大型语言模型（LLM）计算机操作智能体通常使用清晰的书面指令进行评估，尽管语音正日益成为与此类系统交互的常用接口。语音输入引入了额外的故障点：在智能体开始推理之前，转录错误就可能改变任务关键实体、约束或目标；而传统的自动语音识别（ASR）指标无法直接衡量成功执行任务所需的信息是否得到保留。我们推出 Talk2Agent，这是一项基准测试，用于评估语音接口将人类口述指令传达给基于 LLM 的计算机操作智能体的效果。Talk2Agent 将 WildClawBench 和 OSWorld 中的任务转换为人工口述版本，并评估多种语音接口，包括专用 ASR 模型、具备音频处理能力的 LLM、上下文偏置以及基于 LLM 的本体修复。由于反复执行长时程计算机操作任务成本高昂且具有随机性，我们进一步提出一种无需执行、以任务为条件的评估框架：将原始任务评分器映射到可由提示词表达的意图，并衡量语音接口处理后保留了多少与任务相关的信息。在 WildClawBench 上，Talk2Agent 的无需执行原生投影提供了一种实用且以执行效果为依据的语音接口质量衡量方法；在 32 小时真实人类语音数据上，与下游任务完成情况的相关性较高，且其皮尔逊相关系数比 WER/CER 高 0.246。

## Abstract
Large language model (LLM) computer-use agents are typically evaluated with clean written instructions, despite speech being an increasingly popular interface for interacting with such systems. Speech input introduces an additional failure point: transcription errors can alter task-critical entities, constraints, or targets before the agent begins reasoning, while conventional ASR metrics do not directly measure whether the information required for successful execution has been preserved. We introduce Talk2Agent, a benchmark for evaluating how effectively voice interfaces convey human-spoken instructions to LLM-based computer-use agents. Talk2Agent builds human-spoken versions of tasks from WildClawBench and OSWorld and evaluates a range of voice interfaces, including dedicated ASR models, audio-capable LLMs, contextual biasing, and LLM-based ontology repair. Because repeatedly executing long-horizon computer-use tasks is costly and stochastic, we further propose an execution-free, task-conditioned evaluation framework that projects the original task grader onto prompt-addressable intentions and measures how much task-relevant information is retained after the voice interface. On WildClawBench, Talk2Agent's execution-free native projection provides a practical, execution-grounded measure of voice-interface quality, correlating with downstream task completion and improving Pearson correlation by 0.246 over WER/CER on 32 hours of real human speech.

## 1. 核心问题与整体含义

### 研究背景与动机
- 现有计算机操作智能体基准通常使用**干净的书面指令**，但真实用户越来越多地通过语音下达任务。语音接口因此引入了一个独立于智能体推理能力的故障环节。
- 文件名、路径、应用名称、数值、目标实体和操作约束等信息，对任务执行往往至关重要。即使转写整体流畅，只错一个关键实体，也可能导致任务失败。
- 传统词错误率、字符错误率（WER/CER）主要衡量字词差异，无法充分回答：**转写结果是否保留了完成任务所需的信息？**
- 直接运行智能体虽然最贴近实际，但长程任务执行成本高，且结果受到规划能力、环境故障和运行随机性的共同影响。

### 论文的核心定位
Talk2Agent 提供两个互补的评估层次：
1. **执行评估**：将语音接口的文本输出交给固定下游智能体，用原任务评分器衡量实际效果。
2. **无需执行的诊断**：把原评分器映射到指令中的任务意图，评估语音接口保留了多少任务相关信息。

其主要贡献不是提出新的语音识别算法，而是建立**真人语音基准，以及以任务评分逻辑为依据的接口评估方法**。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 基准构建与评估流程
整体流程为：

> 原始书面任务 → 口语化脚本 → 真人录音 → 语音接口输出文本 → 固定智能体执行，或进行意图保留评估。

- 使用 GPT-5.4 将原提示改写为适合朗读的脚本，将列表、JSON 等结构转换为自然口述。
- 改写应保留关键实体、约束、符号和输出要求，并通过人工审核检查任务意图是否改变。
- 语音接口输出原则上不再修改，直接交给固定下游智能体，以控制智能体差异。

### 2.2 两类接口增强策略
- **上下文偏置（Contextual biasing）**
  - 从智能体可见的工作区内容、GUI OCR 等来源提取任务相关词汇。
  - 用这些词汇辅助识别罕见名称、技术术语和实体。
  - 不使用评分秘密，降低评测信息泄漏风险。
- **本体修复（Ontology repair）**
  - 使用 LLM 对转写进行后处理。
  - 仅在任务局部上下文支持的情况下，修复技术术语、实体和标点。
  - 论文将其作为受控干预，而非新提出的纠错算法。

### 2.3 无需执行的任务条件评估
作者将每个任务的评分标准拆分为：
- **可由指令表达的意图**：语音接口可能保留、改变或遗漏的要求。
- **固定评估条件**：影响评分，但不能由语音接口改变的条件。

对于保留意图集合，评估方法先假定固定条件满足，再扣除固定条件本身产生的基线分数，从而隔离指令信息的价值。

框架提供三类诊断：

| 指标 | 含义 | 主要作用 |
|---|---|---|
| 丢失意图数量 | 统计改变或遗漏的要求数量 | 衡量信息损失范围 |
| 原生投影（Native projection） | 将保留意图代入原评分逻辑，并除以全部意图保留时的分数 | 保留任务要求之间的联合关系 |
| Shapley 保留率 | 计算每项意图对评分的 Shapley 贡献，再汇总保留部分的贡献 | 衡量被保留的可归因任务价值 |

关键技术细节：
- 原生投影保留评分器中的求和、乘积、门控、阈值、上限和下限等结构，而不只是逐条要求计分。
- Shapley 值通过集合函数的 Möbius 表示计算，将意图之间的交互贡献分配给单个意图。
- 连续评分条件被简化为“未满足”和“完全满足”两个端点。
- 转写中的每项意图被标注为**保留、改变、遗漏或无法确定**。
  - 改变、遗漏视为丢失。
  - 对无法确定的意图，枚举其可能保留情况，计算分数上下界；需要单一汇总值时才使用区间中点。

**两项指标不能互相替代**：Shapley 衡量单项要求的归因价值；Native 衡量这些要求能否按原评分逻辑共同产生得分。Native 也不是实际任务成功概率。

## 6. 主要结论与发现

### 6.1 任务条件指标更贴近细粒度执行结果
在 WCB 任务—接口层面：
- WER/CER 对应的高分方向指标：PCC **0.220**；
- 最佳通用指标 AER：**0.286**；
- Flat retention：**0.349**；
- Shapley：**0.399**；
- Native：**0.466**。

因此，Native 相比 WER/CER 提高 **0.246 个相关系数单位**，相比 AER 提高 **0.180**。

但接口均值层面，AER 为 **0.916**，高于 Shapley 的 **0.902** 和 Native 的 **0.870**。论文没有证明任务条件指标在所有聚合尺度上都最优。

### 6.2 上下文偏置和修复并非普遍提升执行
- WCB 中，Gemini 加偏置的执行均值为 **43.15%**，但加入本体修复后降至 **38.68%**。
- Parakeet 在完整 60 任务上的各配置约为 **24%–25%**，变化较小。
- OSWorld 中，本体修复使 GPT-4o 和 Whisper 的执行均值分别提高 **0.79、0.70 个百分点**；Parakeet 偏置的效果很小，且随下游智能体变化。

### 6.3 接口改善可能被下游瓶颈掩盖
在 15 个工作区信息丰富任务上，Parakeet 本体修复带来：
- 无偏置：执行分数提高 **11.85 个百分点**；
- 有偏置：提高 **16.09 个百分点**。

但在全部 50 个非安全任务上，执行变化不到 0.3 个百分点，意图保留指标却明显改善。这表明接口信息修复与最终执行改善并非一一对应，后者还受智能体能力和环境因素限制。

### 6.4 单项恢复不等于联合要求满足
全集无偏置修复后：
- Shapley：**54.84%**；
- Native：**23.24%**。

这一差距说明：许多单项有价值的要求被恢复，但仍有联合条件未满足。

### 6.5 存在初步跨场景迁移证据
OSWorld 的 Whisper 本体修复使意图准确率提高 **7.96 个百分点**，方向与执行改善一致，但执行增益明显更小。

**表述注意**：31.82 小时是 WCB 与 OSWorld 的合计真人录音时长；相关性提升 0.246 的详细验证来自 WCB 的匹配执行实验，且执行端使用 TTS，不能直接概括为“在 32 小时真人语音执行上验证”。

## 7. 优点

- **问题贴近应用**：直接关注语音接口是否损坏任务关键实体和约束。
- **评分依据明确**：复用原 benchmark 的评分逻辑，而非另行定义泛化的语义相似度。
- **保留非加性关系**：Native 能表达“多个条件同时满足才得分”等任务结构。
- **诊断互补**：丢失数量、Shapley、Native 分别覆盖损失范围、归因价值与联合满足程度。
- **降低结果泄漏风险**：意图评估不接触执行结果，干预子集预先选择。
- **客观报告负面结果**：没有把偏置和修复包装成普遍有效的策略。
- **覆盖互补场景**：结合命令行长任务与 GUI 短任务，并引入真人语音。

## 8. 不足与局限

### 数据与交互真实性
- 录音主要是照读改写脚本，不是真实用户自发口述。
- 缺少停顿、自我纠正、指代、多轮澄清及交互式补充等现象。
- 安静环境和质量筛选可能低估噪声、口音及设备差异带来的困难。
- WCB 说话人群体较小；原始英语任务及中英双语朗读者的覆盖有限。

### 验证与因果解释
- WCB 真人语音数据与 TTS 执行验证之间存在分布差异。
- Native 的细粒度相关性为 0.466，虽优于对照，仍只是中等程度，不能替代最终执行评估。
- 接口之间的分数差异仍可能被智能体能力和环境随机性影响。
- 安全任务中，遗漏危险意图可能提高安全对齐评分，说明“信息保留越多越好”并非普遍成立。

### 评估器与方法限制
- 保留标签由 LLM 判定，存在判断偏差；文中未报告完整的人类一致性验证。
- GPT-5.6-Luna 同时用于 WCB 执行和保留判定，虽不共享结果，仍可能存在模型特定偏好。
- 原生投影继承原评分器的不足：评分器漏掉的重要要求也可能不被充分衡量。
- 连续条件二值化会丢失部分完成程度。
- 精确 Shapley 和不确定区间计算可能随意图数量增长而变复杂，论文未充分报告计算效率。
- OSWorld 迁移表中的“意图准确率”缺少与 Native、Shapley 同等详细的定义和相关性分析。

### 应用与复现限制
- 指标需要访问并分析任务评分器；开放式真实用户任务未必具备这样的评分规则。
- 未充分评估识别延迟、隐私、费用，以及错误修复造成的新错误。
- 算力、调用成本和完整运行细节未量化，限制了成本收益判断。

**总体评价**：Talk2Agent 最有价值的贡献，是把语音接口评价从“转写是否相似”推进到“原任务所需信息是否保留”。它适合作为执行评测的低成本补充和错误诊断工具，但尚不能替代真人语音下的端到端验证。
