## 摘要
长期运行的智能体不仅必须记住关于用户的事实，还必须记住随着双方共同历史不断发展，特定智能体应如何与该用户协作。现有基准主要针对用户事实与偏好，或可在不同用户间复用的经验进行监督，却未明确涵盖这种特定于关系的智能体记忆。此外，大多数既有研究仅通过基于长期交互历史的最终答案问答来评估模型，因此评估仍不完整且缺乏可靠性。为此，我们提出 DyadMem，并引入用户条件关系型智能体记忆（User-conditioned Relational Agent Memory，URAM）这一新定义。DyadMem 沿着相同的多会话轨迹，对用户侧记忆和 URAM 进行联合标注，涵盖 6 类记忆。总体而言，该基准包含 3,065 个情节、50,961 个会话和 61,210 个问答实例，并提供大量会话级 Capture 与 Update 黄金标注、查询级 Recall 支持，以及 Gold-Memory 和 Full-Pipeline 两种问答设置。在 16 个开放权重模型和 4 个专有模型上的评测显示，Gold-Memory 问答表现始终较强，而 Full-Pipeline 问答性能则大幅下降。这一差距明确印证了我们细粒度评估设计的必要性。此外，多项定量结果进一步揭示，即使是前沿大语言模型，也存在 Capture 召回率低、Recall 不完整以及不安全删除等问题。我们还开展了严格实验，以验证 URAM 的有效性，并观察到其对全部 20 个模型均有积极作用。总之，DyadMem 是一个双领域、全流程的记忆基准，投入了大量标注工作，旨在推动该领域的发展。

## Abstract
Long-term agents must remember not only what is true about a user, but also how a particular agent should work with that user as their shared history evolves. Existing benchmarks primarily supervise user facts and preferences or experience reusable across users, leaving this relationship-specific agent memory implicit. Additionally, most prior works measure the model solely with final-answer QA over long interaction histories, making the assessment still incomplete and unreliable. To this end, we introduce DyadMem with the proposed new definition User-conditioned Relational Agent Memory (URAM). DyadMem jointly annotates user-side memory and URAM along the same multi-session trajectories, resulting in 6 memory categories. To summarize, it includes 3,065 episodes, 50,961 sessions, and 61,210 QA instances, with extensive session-level Capture and Update gold annotations, query-level Recall support, and two QA settings: Gold-Memory and Full-Pipeline. Across 16 open-weight and 4 proprietary models, Gold-Memory QA is consistently strong, yet Full-Pipeline QA drops sharply. Such a gap explicitly supports our fine-grained evaluation design. Additionally, several quantitative results further reveal low Capture recall, incomplete Recall, and unsafe-deletion issues arising from even the frontier LLMs. We further conduct a rigorous experiment to validate the effectiveness of our URAM and observe the positive effects for all 20 models. In summary, DyadMem is a dual-domain, full-pipeline memory benchmark with extensive annotation efforts for advancing the domain's development.

## 1. 核心问题与整体含义：长期记忆不只是“记住用户”

### 研究背景与动机
长期个人智能体需要跨会话保留信息，但现有研究主要关注两类记忆：

- **用户侧记忆**：用户的身份、偏好、事实、约束及其变化。
- **通用智能体经验**：可跨用户、跨任务复用的工作流程、策略与失败教训。

论文指出，两者之间存在一个未被充分显式建模的对象：**这个智能体在与这个用户的共同经历中，学到了怎样与其协作。**

例如，“用户对海鲜过敏”是用户侧记忆；“经过几次反馈后，助手应先给出明确判断，再解释理由”则是针对这段协作关系的记忆。同一用户面对不同智能体时，由于共同经历不同，也可能需要不同的协作方式。

### 论文试图解决的两个问题
1. **记忆内容覆盖不足**：现有基准缺少对关系特定的智能体侧记忆的明确监督。
2. **评估粒度不足**：只看最终问答准确率，无法区分问题来自记忆提取、更新、检索还是答案生成；正确答案也可能掩盖不完整的记忆库或无证据的猜测。

因此，DyadMem 的核心意义是：**同时评估“智能体知道用户什么”和“智能体应如何与该用户协作”，并把长期记忆拆解为可定位错误的完整生命周期。**它主要是一项基准与评估框架贡献，而非新的记忆模型或训练算法。

## 2. 方法论：关系型记忆与全流程评估

### 2.1 核心思想：URAM
论文提出 **用户条件关系型智能体记忆**（User-conditioned Relational Agent Memory，URAM），与用户侧记忆共同存储于同一条交互轨迹的记忆库中。

| 记忆类别 | 类型 | 内容 |
|---|---|---|
| 用户侧 | `user_profile` | 用户属性、偏好、习惯、目标、约束 |
| 用户侧 | `fact` | 用户提供的、独立实体或外部世界的持久客观信息 |
| URAM | `agent_identity` | 助手的长期角色、输出规范与行为边界 |
| URAM | `agent_method` | 针对该用户形成的可复用协作步骤和流程 |
| URAM | `agent_knowledge` | 从共同实践、反馈中形成的判断规则与经验 |
| 共享记忆 | `episodic` | 具体交互、事件、尝试、反馈及结果 |

其中，“双领域”指**用户侧与关系型智能体侧两个记忆领域**，不是两个生活主题领域。

### 2.2 数据构建流程
采用“**计划引导、对话优先**”的合成数据构建方式：

1. 从约 20 万个人设池中选取用户设定，并增强长期协作特征。
2. 规划记忆变化形式，例如修改、撤销、带条件的限制和多次状态演化。
3. 使用 GPT-5.4 生成完整多会话英文对话，检查时间、角色与逻辑一致性。
4. 根据实际生成的对话，标注每次会话的 Capture 记忆。
5. 按时间顺序重放会话，标注 Update 的删除、添加及替换关系。
6. 从最终有效记忆库生成问题、参考答案及完整证据集合。
7. 经自动检查与人工审核后，保留有效样本。

关键约束包括：记忆应独立可理解、保留条件与例外、解析相对时间，并且不能将未来确认的信息倒填到过去。

### 2.3 记忆生命周期与算法流程
- **Capture——提取**：只读取当前完整会话和时间锚，输出原子记忆，不提供此前会话。
- **Update——更新**：将当前提取结果并入旧记忆库，删除失效或被吸收的条目，添加修订后的条目，再去重。
  - 状态修改一般表示为“删除旧条目＋添加新条目”。
  - 临时限制不应直接抹掉长期偏好，而应保留适用条件、期限和例外。
- **Recall——检索**：根据问题，从最终有效记忆库返回有序证据索引。
- **QA——回答**：使用提供的证据生成答案。

记忆状态转移可以理解为：**旧库与当前 Capture 合并 → 应用删除 → 应用新增 → 去重，得到新库。**

### 2.4 独立评测与端到端评测
- **独立 Capture**：与当前会话的标准提取结果比较。
- **标准条件下的独立 Update**：输入标准旧库和标准 Capture，隔离上游错误。
- **独立 Recall**：在标准最终记忆库上检索。
- **Gold-Memory QA**：直接提供标准支持记忆，测试“证据齐全时能否回答”。
- **Full-Pipeline QA**：从模型自行提取、更新得到的库中检索，最多提供 16 条记忆，再回答。

Gold-Memory 与 Full-Pipeline 的准确率差称为 **Gold-to-Pipeline gap**。它衡量整体流程损失，**不能直接作为各阶段错误的因果分解**。

### 2.5 评分技术
- Capture：记忆条目的精确率、召回率、F1。
- Update：添加 F1 与删除 F1 的算术平均，即 op-F1。
- Recall：主指标为 Recall@n，n 是该问题的标准支持条目数；另报告更宽检索范围、检索精确率和首位命中率。
- 内容匹配：BGE-M3 向量相似度结合 NLI 判断；允许不同记忆粒度，主 F1 不强制类型标签相同。
- QA：使用 GPT-5-mini 判断语义一致性，并额外衡量：
  - **Grounded accuracy**：正确且得到所供记忆支持。
  - **过度拒答率**：题目可回答但模型拒答。
  - **无证据正确率**：得到正确性得分的答案中，缺少记忆支持的比例。

## 6. 主要结论与发现

### 6.1 给对记忆时会回答，完整流程却明显退化
| 指标 | 开放权重模型平均 | 专有模型平均 |
|---|---:|---:|
| Gold-Memory QA | 90.61% | 91.22% |
| Full-Pipeline QA | 47.73% | 57.35% |
| 准确率损失 | 42.88 个百分点 | 33.87 个百分点 |
| Capture 召回率 | 15.13% | 18.26% |
| 独立 Update op-F1 | 18.55% | 24.47% |
| Recall@n | 50.57% | 54.59% |
| 不安全删除率 | 84.12% | 78.05% |

这说明在该评测设置下，瓶颈不仅是答案生成，还包括**漏记、错误维护和证据检索不完整**。

“不安全删除率”是预测删除中错误删除的比例，**不表示整个记忆库有相同比例被删坏**。

### 6.2 检索到一条相关记忆，不等于找全证据
领先模型首位命中率约为 85%—89%，但 Recall@n 仍低于 63%。完整支持集合的检索比找到一个相关条目困难得多。

### 6.3 URAM 有益，但并非所有下游指标都改善
- 20 个模型的受控 Update 差异点估计均为正。
- 其中 GLM-5.2、Kimi-K3、GPT-5.6-Sol 的区间包含零，不能声称全部显著改善。
- **17/20 个模型的下游 QA 提升，3 个下降**。
- QA 平均提升约 3.2 和 3.7 个百分点。

因此，元数据中“URAM 对全部模型有效”需要限定：**全部模型的更新点估计改善，而非全部模型的问答都改善。**

### 6.4 最终问答排名会受到回答风格影响
更愿意回答的模型可能凭借无证据但碰巧正确的答案，超过更保守的模型。加入 grounded accuracy 后，部分排名反转。因此最终准确率必须与拒答率、证据支持率一起阅读。

### 6.5 记忆类型差异大于生活主题差异
- `agent_identity`、`agent_method` Capture F1 约为 50%。
- `episodic` 约为 16%。
- 五个生活领域的 Capture F1 仅约在 22.7%—26.3% 之间。

显式协作规则更容易提取，而异质事实与事件记忆更困难；但这仍是描述性比较，不是严格的因素因果分析。

## 7. 优点：概念与评估设计的亮点

- **记忆对象定义有价值**：区分用户事实、通用经验与关系特定的协作规则。
- **全生命周期监督**：让提取、维护、检索、使用的失败可以分别观察。
- **独立与端到端评测互补**：既隔离能力，又衡量错误累积的实际后果。
- **追踪证据与演化链**：支持检查旧条目为什么失效、新条目从何而来。
- **关注删除风险**：比只统计新增记忆更贴近长期系统可靠性。
- **区分正确与有依据**：减少最终 QA 掩盖记忆问题的风险。
- **人工质控与裁判校准较扎实**：初始 4,000 条轨迹保留 3,065 条，多裁判排序相关性至少 0.988。

## 8. 不足与局限

### 8.1 合成数据的外部有效性有限
- 对话被刻意设计为长期协作和显式规则丰富的场景，未必代表普通用户。
- 仅覆盖英文、正常生活任务，缺少多语言、多模态、工具执行及高风险条件。
- 所有问题均可回答，无法评测证据不足时合理拒答的能力。
- 第三人称、全为困难题的 QA，与真实用户自然追问存在差距。

### 8.2 Capture 低召回可能部分受标注定义影响
- 标注要求高覆盖，连具体请求、建议与反馈也大量保留为 episodic。
- 生产系统常会主动筛选高价值信息；低召回可能混合了能力不足与存储策略差异。
- 标注提示允许利用历史进行指代消解，但测试 Capture 不提供此前会话，可能存在上下文条件不对称。
- 缺少记忆质量、存储成本、延迟之间的完整权衡。

### 8.3 URAM 对照不能完全分离收益来源
用户条件版本同时增加了用户侧记忆并改变提取约束，因此收益可能来自更多上下文、更多条目或更贴近标准目标，不能全部归因于关系型表示本身。还需要等预算的额外对照。

### 8.4 自动评分可靠，但绝非无误
- 人工一致率为 86.52%，说明仍存在明显评分误差。
- 排名稳定不等于绝对分数稳定：不同裁判给出的准确率可相差十余个百分点。
- 对 Capture/Update 的语义匹配器，未提供同等充分的人工校准。
- 附录若干案例存在相近回答被判不同标签、解释与回答内容不一致的现象，值得进一步复核。

### 8.5 文本中的协议一致性与复现信息不足
提供的文本存在几处需要澄清的问题：

- 正文 QA 得分描述出现正确与错误对应 0/1 的疑似笔误；不同附录对部分正确得分的描述也不完全一致。
- URAM 对照中 episodic 是否排除、Update 是否读取原对话，正文与提示说明存在不一致。
- 表 3 部分 op-F1 增量与 Add/Del 增量的算术关系不一致，例如 DeepSeek 一行需要核查。
- 数据和流水线声明将公开发布，但本文所给内容不足以确认实际发布状态及完整运行配置。

### 综合评价
**DyadMem 最强的贡献，是把长期记忆从“最终答案是否正确”推进到“关系特定记忆是否被可靠构建、维护、检索和使用”。**其结果有力支持长期记忆系统存在多阶段瓶颈，但对真实产品表现、URAM 的独立因果收益，以及模型细微排名的解释，仍应保持审慎。
