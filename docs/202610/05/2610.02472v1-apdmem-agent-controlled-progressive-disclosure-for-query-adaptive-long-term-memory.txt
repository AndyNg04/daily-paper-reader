## APDMem: Agent-Controlled Progressive Disclosure for Query-Adaptive Long-Term Memory 

Chin-Lun Fu Anagha Kulkarni Hong Ni Behrouz Madahian 

Machine Learning Center of Excellence, JPMorgan Chase & Co.   

> chin-lun.fu@jpmchase.com ,anagha.p.kulkarni@jpmorgan.com hong.ni@jpmchase.com ,behrouz.madahian@jpmchase.com

Abstract 

Personalized LLM assistants must recover sparse evidence from long conversation his-tories across queries of varying complexity. We introduce APDMem (Agent-controlled 

Progressive Disclosure Mem ory), a hierarchi-cal long-term memory architecture that applies progressive disclosure to memory retrieval. Rather than relying on a flat memory store or fixed retrieval granularity, APDMem rep-resents conversation history as four progres-sively detailed layers: thematic summaries, per-sonalized key facts, turn-level evidence notes, and raw messages. At inference time, a con-troller applies progressive disclosure to the memory hierarchy: it first reads high-level summaries and drills into finer evidence only when needed. This creates an adaptive cost– fidelity trade-off: simple queries can termi-nate early, while complex temporal, multi-hop, or exact-evidence queries trigger deeper inspection. A note synthesizer converts re-trieved evidence into a query-focused struc-ture that consolidates facts, orders events, and flags contradictions before final answer genera-tion. Experiments on L ONG MEM EVAL show that APDMem achieves strong performance for long-context memory reasoning while access-ing only 8% of the total conversations. 

1 Introduction 

Large Language Model (LLM) agents have shown strong performance on complex, multi-step tasks. However, personalized agents must operate across long-term, multi-session interactions, where rele-vant information may be scattered across many past conversations (Xu et al., 2026; Liu et al., 2025; Yu et al., 2026). Such agents must remember user pref-erences, factual details, temporal sequences, and recurring themes over time (Chhikara et al., 2025; Xu et al., 2025; Fang et al., 2026; Liu et al., 2026; Rasmussen et al., 2025). Without effective mem-ory, agents suffer from contextual amnesia: they may fail to recall prior facts, lose track of evolving goals, or overlook cross-session connections. Prior works on memory systems improve long-term recall by transforming conversation history into specialized representations: MemoryBank uses a structured memory store for personalized dialogue (Zhong et al., 2024); MemGPT manages information via virtual context and external mem-ory (Packer et al., 2024); A-MEM builds inter-connected, evolving memory networks (Xu et al., 2025); and Zep constructs temporal, entity-centric memory graphs (Rasmussen et al., 2025). Other systems reduce cost through compression or con-solidation: LightMem uses staged memory process-ing (Fang et al., 2026), while SimpleMem retrieves over compact semantic memories (Liu et al., 2026). While these designs reduce retrieval cost, they also introduce additional memory machinery and re-quire committing conversational context to external memory stores, graph nodes, or other abstractions. We introduce APDMem (Agent-controlled 

Progressive Disclosure Mem ory), a hierarchical memory system for efficient context recall in per-sonalized agents. APDMem treats long-term mem-ory access as a query-adaptive disclosure problem rather than a one-shot retrieval problem. Inspired by progressive disclosure (Nielsen, 1993), it ex-poses coarse information first and reveals finer ev-idence as needed. APDMem stores conversations as lightweight Markdown layers—thematic sum-maries ( L0), personalized key facts ( L1), turn-level evidence notes ( L2), raw messages ( L3)—rather than converting them into a specialized database, graph, or compressed-only representation. Unlike existing systems that fix the retrieved representation in advance, APDMem only materi-alizes thematic summaries at ingestion time while preserving raw messages underneath. At infer-ence time, the Progressive Disclosure Controller 

expands on demand into finer details like person-alized key facts, turn-level evidence notes, or raw arXiv:2610.02472v1 [cs.CL] 1 Oct 2026 messages. After sufficient evidence is collected, the controller drafts an answer. For final answer gener-ation, Organized Notes Synthesizer structures the evidence retrieved by the controller along with the draft answer into organized notes. These notes con-solidate relevant evidence, align it with the query and provide the answer generator with structured grounding context instead of raw retrieved snippets, reducing noise and improving answer accuracy. APDMem frames long-term memory retrieval as a query-adaptive disclosure problem: it must de-termine which conversations matter and how much detail to expose. Concretely, APDMem introduces two coupled dimensions: (1) hierarchical mem-ory organization (coarse summaries linked to finer-grained evidence) and (2) progressive disclosure as an explicit architectural principle governing how that hierarchy is accessed. That is, the agent is designed to open only the minimum memory level required, exposing coarse views first and revealing finer evidence only when needed, with the disclo-sure depth controlled through tool-mediated inter-actions. Our primary contributions are: • Coarse-to-fine memory formulation. We in-troduce a Multi-Resolution Memory Substrate 

that preserves raw messages beneath progres-sively abstract memory layers. • Agent-controlled query-adaptive memory disclosure. We introduce a Progressive Dis-closure Controller that decomposes queries, handles temporal constraints, and drills into deeper memory layers when needed. • Organized Notes for grounded generation. 

We introduce an Organized Notes Synthesizer 

that grounds retrieved evidence and the con-troller’s draft answer into structured notes. • LongMemEval validation. We show that APDMem achieves strong performance on LongMemEval (Wu et al., 2025) while access-ing only 8% of the conversations. 

2 Related Work 

2.1 Memory Representations for LLM Agents 

Personalized agents require persistent memory to maintain continuity across interactions (Zhang et al., 2026; Xu et al., 2026). Prior works frame this as a long-term memory problem: agents must re-tain user-specific facts and temporal context across sessions to avoid contextual amnesia (Chhikara et al., 2025; Fang et al., 2026; Liu et al., 2026). Memory systems differ mainly in how they repre-sent past interactions. Profile- or fact-based meth-ods store distilled user information (Zhong et al., 2024; Chhikara et al., 2025); episodic systems re-trieve prior interaction traces (Packer et al., 2024; Xu et al., 2025); graph-based systems such as Zep organize temporal entity-relation memories (Rasmussen et al., 2025); and compression-based systems such as LightMem and SimpleMem re-duce cost through staged consolidation or com-pact semantic memories (Fang et al., 2026; Liu et al., 2026). These approaches often require graph conversion, compression, or specialized memory objects, creating trade-offs between efficiency, fi-delity, and complexity. APDMem instead stores conversations as transparent Markdown layers pre-serving the original conversation while providing compact abstractions for retrieval. 

2.2 Progressive Disclosure 

Memory systems organize information at differ-ent granularities—such as summaries, passages, chunks, or episodic traces—to improve retrieval over large contexts (Sarthi et al., 2024; Gao et al., 2023; Izacard and Grave, 2021; Khattab and Za-haria, 2020; Lewis et al., 2020; Asai et al., 2024; Trivedi et al., 2023). APDMem builds on this idea through progressive disclosure (Nielsen, 1993), ex-posing coarse memory views first and revealing finer evidence only when needed. To our knowl-edge, APDMem is the first system to make progres-sive disclosure an explicit architectural principle for agent memory, with an agent controlling disclo-sure depth through tool-mediated interactions. 

2.3 Evidence-Grounded Generation 

Complex queries involving temporal constraints, ambiguous references, user-specific details, multi-hop reasoning, or enumeration often require iter-ative retrieval and verification (Yao et al., 2023; Schick et al., 2023; Press et al., 2023; Trivedi et al., 2023). Prior work has shown the value of orga-nizing or reasoning over retrieved evidence before answer generation (Yu et al., 2024; Gao et al., 2023; Asai et al., 2024). Inspired by Chain-of-Note (Yu et al., 2024), APDMem converts retrieved evidence into organized notes that consolidate relevant facts, temporal order, contradictions, enumeration evi-dence, and answer hints into a structured grounding context for the answer generator. 3 APDMem 

As shown in Figure 1, APDMem consists of three components: (1) a Multi-Resolution Memory Sub-strate that stores each conversation across four lay-ers of increasing abstraction (§3.1); (2) a Progres-sive Disclosure Controller that searches, drills into, and reflects over the memory hierarchy through tool-mediated interactions (§3.2); and (3) an Or-ganized Notes Synthesizer that structures retrieved evidence for final answer generation (§3.3). 

3.1 Multi-Resolution Memory Substrate 

Given a conversation history, we partition it into 

N sessions S = S1, . . . , S N , where each session 

Si is a contiguous conversation episode consist-ing of turns, and each turn is a user–assistant ex-change. APDMem represents each session as a four-layer memory tuple, Si = ( L0, L 1, L 2, L 3).

L0 contains thematic summaries with resolved pro-nouns, normalized dates, keywords, and tags, and serves as the primary indexing layer. L1 contains 

personalized key facts : session facts about user in-formation, recommendations, plans, preferences, and constraints. L2 contains turn-level evidence notes : turn-level factual bullets that preserve tem-poral order for fine-grained evidence reasoning. L3

contains raw messages : the verbatim user–assistant messages retained for exact evidence recovery. 1

Lazy materialization. Only L0 and L3 are mate-rialized at ingestion time, whereas L1 and L2 are generated on demand when first requested by the progressive disclosure controller and then cached for reuse, reducing write-time cost.

3.2.1 Controller Workflow 

A typical trajectory proceeds in three phases. 

Query preparation. Queries with relative dates (e.g., “last summer”) are normalized against the question timestamp via interpret_dates ; multi-hop or compound queries are split into focused subqueries via decompose .

Progressive disclosure. search retrieves the top-

K candidate sessions over L0 (hybrid lexical + dense retrieval fused with RRF; Appendix G). An 

auto-drill step selects the most promising unex-plored sessions and read_facts retrieves their L1

key facts. If these facts are insufficient, the con-troller descends further: read_turns surfaces L2

evidence in temporal order, and read_raw retrieves 

L3 messages restricted to the most relevant turns within selected sessions. At each step, retrieved session information is stored in evidence set V.

Reflection and drafting. APDMem uses reflec-tion (Yao et al., 2023; Shinn et al., 2023) to avoid both premature answering and unbounded search. 

reflect summarizes V, identifies missing evi-dence, and assesses whether additional retrieval is likely to help. If more evidence is needed, it proposes follow-up queries and the controller re-enters the progressive disclosure phase. Once V

converges (§3.2.2), the controller produces a draft answer adraft from the final evidence set VT , which is then passed to the Organized Notes Synthesizer. 

3.2.2 Convergence Control 

The controller loop terminates when (1) reflec-tion finds no new evidence, |V t| = |V t−1|, or (2) step budget Tmax is reached. Tmax caps the maxi-mum number of controller iterations and therefore bounds the additional tool calls the controller can make before it must stop escalating and return the best available answer. 2

3.3 Organized Notes Synthesizer 

The Organized Notes Synthesizer converts the query q, evidence set V, and controller’s draft an-swer adraft into organized notes, a compact inter-mediate representation. Inspired by Chain-of-Note (Yu et al., 2024), this step uses the draft to verify, correct, or supplement the controller’s initial rea-soning. These notes organize relevant facts, tempo-ral ordering, contradictions, enumeration evidence for counting queries, and an answer hint into a query-focused grounding context. 

Answer generation. The answer generator re-ceives the organized notes and adraft to produce the final response. This synthesize-then-generate de-sign preserves the controller’s retrieval trajectory while allowing the final answer to correct errors or omissions surfaced during evidence synthesis.

4.3 Effectiveness of Progressive Disclosure 

We analyze whether progressive disclosure achieves its design goal: locating relevant evidence with minimal memory access. Unless stated other-wise, statistics use the GPT-4.1 configuration; the error decomposition additionally contrasts GPT-4.1-mini with GPT-4.1 to study how backbone strength affects retrieval versus generation failures. 

Retrieval selectivity. Figure 2(a) shows that the controller drills into only 8% of the haystack on average (3.7 out of 47.7 sessions per question). Single-session categories are the most selective (SS-Asst.: 2%, SS-User: 6%), while multi-session questions require broader access (12%). Despite this selectivity, APDMem achieves 87.8% overall accuracy, confirming that the Progressive Disclo-sure Controller enables precise evidence identifica-tion without exhaustive search. 5 Conclusion 

We present APDMem , a lightweight hierarchical memory architecture that frames long-term mem-ory access as a query-adaptive disclosure prob-lem. A controller first reads coarse abstractions and drills into finer-grained evidence only when needed, while a notes synthesizer organizes the surfaced evidence for grounded answer generation. On LongMemEval, APDMem achieves a substan-tial improvement over prior work, reaching 87.8% accuracy with GPT-4.1. Our key findings are: (i) disclosure depth adapts to question type, with most questions answered from the high-level key-fact layer, while certain detail-oriented question cate-gories benefit from raw-message access; (ii) con-troller ablations show that agent-controlled pro-gressive disclosure is a significant contributor to performance; and (iii) APDMem offers a practi-cal efficiency–accuracy trade-off, balancing token cost and latency while maintaining strong answer accuracy. 

Limitations 

APDMem’s retrieval recall depends on the qual-ity of the L0 thematic summaries: if a summary omits a relevant detail, the corresponding turn may receive lower BM25 and dense-retrieval scores. The keyword-field boost (Appendix G) and the controller’s reflect tool provide partial recovery mechanisms, but initial ranking remains sensitive to summary fidelity. To this end, developing a sys-tematic summary-quality evaluation and monitor-ing for L0 is a natural and important direction for future work. As one potential mitigation, summary quality can be assessed using an LLM-as-a-judge style evaluation (e.g., checking faithfulness and coverage against the underlying raw messages). Lazy materialization of L1 and L2 may intro-duce cold-start latency when a session is accessed for the first time. To mitigate first-access latency, 

L1 and L2 can be proactively materialized (e.g., offline or in the background). That said, our design intentionally follows progressive disclosure and lazy materialization: precomputing everything can be unnecessarily costly when many sessions (and fine-grained layers) are never queried. In produc-tion, this becomes an explicit cost–latency trade-off: deployments that prioritize low tail-latency can pre-warm likely-to-be-accessed sessions, while cost-sensitive settings can keep on-demand genera-tion to minimize wasted computation. Finally, APDMem does not explicitly model cross-session relationships in the way graph-based memory structures can. Exploring lightweight mechanisms for cross-session linking is a promis-ing direction for future work.

D Setting the Controller Step Budget 

The controller step budget Tmax is an explicit inference-time budget parameter. It caps the max-imum number of convergence-control iterations and therefore bounds the maximum number of ad-ditional tool/LLM calls the controller can make before it must stop escalating and return the best available answer. 

Experimental setting. In all experiments, we set 

Tmax = 20 . This is intentionally a generous cap: when the controller converges earlier, it terminates before reaching the budget, while Tmax prevents rare difficult queries from incurring unbounded cost or latency. Table 6 reports the observed iteration distribution under this setting. With Tmax = 20 , nearly all queries terminate before reaching the cap. Thus, in our experiments, the budget does not materially affect answer quality for most examples, but it still provides an explicit worst-case compute bound. 

Choosing Tmax in other applications. Tmax con-trols a quality–cost trade-off: larger values allow the controller to continue searching and reflecting on difficult queries, whereas smaller values reduce worst-case latency and tool/LLM usage. In prac-tice, we recommend setting Tmax as follows:

F Human Validation of the LLM-as-a-Judge 

All accuracy results in our main experiments use the LongMemEval LLM-as-a-judge protocol. Fol-lowing prior work, we use the official judge prompt with GPT-4.1-mini at temperature 0.0, applied uni-formly to APDMem and all baselines. Since our reported gains depend on this evaluation protocol, we conducted an additional human validation study to verify that the judge is reliable in our setting. 

Human verification. We manually validated a stratified subset of 120 question–prediction pairs, with 20 examples from each of the six LongMemEval-S categories. One author, blind to the judge decision, labeled each prediction as C OR - 

> RECT

or W RONG according to whether it matched the gold answer, using the same criterion as the judge. To stress-test reliability, we over-sampled examples that the judge labeled W RONG , enriching the subset with borderline cases where disagree-ments are more likely. 

Agreement. Human and judge labels agreed on 119 of 120 examples, corresponding to 99.2% agreement and Cohen’s κ = 0 .98 , indicating near-perfect agreement. Agreement was consistently high across all categories, as shown in Table 9. The single disagreement was a case where the human annotator marked the prediction as correct while the judge marked it as wrong, suggesting that the judge is not biased in favor of APDMem. Over-all, this validation provides direct evidence that the LongMemEval judge is reliable in our setting and mitigates the concern that the reported gains are driven by an unvalidated LLM-as-a-judge protocol.
