Large language model (LLM) agents accomplish complex tasks through multi-turn interactions with external tools. However, malicious content embedded in user queries, tool descriptions, or environment observations can manipulate their decisions and induce unsafe actions. Adversarial co-evolution has emerged as an effective approach to strengthening LLM safety, but existing work primarily focuses on language-level safety or indirect prompt injection in web tasks. In this paper, we introduce AgentSafeEvo ,a co-evolutionary reinforcement learning framework for agent safety built on an attacker–defender game spanning diverse tasks and attack types. The attacker learns to construct adversarial agent tasks that expose weaknesses in the defender’s tool use, while the defender learns to complete tasks safely under these attacks. We further introduce learnability-guided task weighting, which uses within-task defender-reward variability to adjust each task’s contribution to attacker and defender updates. Extensive experiments on agent safety and general capability benchmarks demonstrate that our method improves adversarial robustness while maintaining general agent capabilities.

## 1. Introduction 

The emergence of large language model (LLM) agents marks a shift from text generation to active interaction with external environments. Through multi-turn interactions with external tools, agents can search for information, process documents, and manage schedules to complete complex, multi-step tasks [1, 2, 3]. However, tool use broadens the attack surface beyond user queries to include tool descriptions and environment observations. Malicious content alters task instructions, misrepresents tool behavior, or misleads subsequent decisions, inducing unsafe actions during execution [4, 5]. A central challenge is therefore to improve agents’ robustness across diverse tasks and attack types without compromising task performance. Research on LLM safety has explored adversarial training to reduce harmful responses to jailbreak prompts. However, training on a fixed attack set leaves the attack distribution unchanged as the defender’s capabilities evolve [6]. Adversarial co-evolution addresses this limitation through an iterative attacker–defender game. The attacker learns to generate attacks that induce unsafe behavior, while the defender learns to resist these attacks. Throughout training, the attacker refines its attacks against the evolving defender using feedback on attack outcomes, while the defender learns from the newly generated attacks. Existing safety-oriented approaches have primarily focused on language-level safety [6, 7, 8, 9]. For example, Self-RedTeam [6] trains a single model in both attacker and defender roles through online self-play. MAGIC [9] instead alternately optimizes separate attacker and defender models for adversarial prompt rewriting and safe response generation. For LLM agents, safety depends not only on responses but also on the decisions and actions taken during multi-turn tool interactions. In this paper, we introduce AgentSafeEvo , a co-evolutionary reinforcement learning framework for adaptive attack generation and robust defense across diverse agent tasks and attack types. AgentSafeEvo couples adversarial task generation with defensive learning through an attacker– defender game over multi-turn tool interactions. The attacker learns to construct adversarial agent tasks designed to induce unsafe behavior, while the defender learns to resist these attacks and com-plete tasks safely. Both models are updated using feedback on the safety and utility of the defender’s execution, allowing task generation to adapt to the defender’s evolving capabilities. Figure 1 contrasts AgentSafeEvo with language-level co-evolution. Adversarial co-evolution relies on generated tasks not only to challenge the defender but also to guide its learning. Task-level zero-sum rewards favor tasks that lower the defender’s average reward, without directly accounting for within-task reward variation. The defender learns from these reward differences, but task-wise normalization largely removes differences in their scale across tasks. We therefore introduce learnability-guided task weighting , assigning larger relative weights to tasks with greater within-task variation in defender rewards. These weights adjust each task’s contribution to the attacker and defender policy updates. Co-evolution across diverse tasks and attack types requires an attacker capable of constructing valid adversarial agent tasks. To develop this capability, we construct an agent safety training dataset spanning 50 agent scenarios, approximately 7,000 tools, and a broad range of attack types. Each adversarial task combines a user query with a corresponding tool-environment configuration, providing structured supervision for attacker initialization. The dataset also includes seed instances for subsequent co-evolutionary training. ## 2. Related Work 

Co-Evolutionary Learning for Large Language Models. Co-evolution has emerged as a general approach to improving LLMs by allowing different models or roles to adapt continually to one another during training [11, 12, 13, 14]. Existing work spans both competitive and collaborative settings. For example, SPAG [11] improves reasoning through competitive language games, whereas MAPoRL [12] jointly trains multiple LLMs to enhance collaborative problem solving. Co-evolution has also been applied to LLM safety, where attack and defense models are optimized together as jailbreak strategies and corresponding safeguards evolve [15, 6, 9, 8]. Such an adaptive training paradigm can expose models to increasingly challenging attacks that may not be captured by static adversarial datasets. However, existing methods primarily target harmful language generation in relatively isolated interactions, providing limited coverage of safety risks arising from multi-turn agent interactions, tool use, and changes to external environments. ARLAS [10] extends co-evolution to agent safety through indirect prompt injection in predefined web environments. Its attacker learns to inject malicious instructions into observations of given tasks. Our framework incorporates adversarial task construction into co-evolution, with the attacker generating user queries, tool definitions, and environment observations across diverse attack types. 

Safety Evaluation and Alignment of LLM Agents. As LLM agents interact with users, tools, and external environments, their safety depends on multi-turn decisions and accumulated interaction out-comes rather than isolated outputs. Existing benchmarks examine complementary dimensions of these risks: ToolEmu [16] and R-Judge [17] assess tool-use safety and risk awareness, while AgentHarm [18] and InjecAgent [19] focus on harmful-task compliance and indirect prompt injection. AgentDojo [20] evaluates prompt-injection attacks and defenses in interactive tasks. Agent-SafetyBench [21] assesses the safety of agent responses and actions across diverse interactive environments. MCP Security Bench (MSB) [22] examines attacks targeting tool signatures, parameters, and responses in Model Context Protocol environments. Beyond evaluation, prompt-based defenses such as Prompt Sandwiching [23] and Spotlighting [24] separate trusted instructions from untrusted content, while classifier-based methods such as Prompt Guard 2 [25] and PIGuard [26] filter potentially malicious inputs before they influence agent behavior. Training-based alignment has also been explored through sandboxed agent interactions to address threats originating from both user requests and tool responses [27]. 

## 3. Methods 

We focus on LLM agents that solve complex tasks through multi-turn interactions with external tools. During these interactions, agents may encounter untrusted content in user queries, tool descriptions, or environment observations, which can manipulate their decisions or induce unsafe actions. We consider six attack categories: direct prompt injection, indirect prompt injection, tool-description injection, misinformation, harmful tool execution, and user-query jailbreak. To improve robustness against these attacks, we introduce an adversarial training framework that jointly optimizes an attacker model ( 𝜋 𝐴 ) and a defender agent ( 𝜋 𝐷 ) over multi-turn tool-interaction trajectories, allowing their attack and defense capabilities to co-evolve.

## 4. Experiments 

4.1. Experiment settings 

Models. We use Qwen3-8B [32] as the backbone for both the attacker and defender. Qwen3.8-27B [30] serves as the reward model, providing both safety and utility judgments. 

Training data. For the SFT phase, we sample approximately 20,000 source tasks from TOUCAN [28], a large-scale tool-agent dataset comprising over 1.5 million trajectories synthesized from 495 real-world MCP servers. We use Gemini 3 Flash Preview [29] to transform approximately 10,000 of these tasks into adversarial tasks according to specified attack intents and synthesize a construction trace for each example. These examples are combined with approximately 10,000 benign examples for attacker initialization. The red-team dataset covers six attack categories comprising 13 subtypes, with the complete taxonomy provided in Appendix B.3. For the RL phase, we synthesize 6,000 red-team and 6,000 benign seed instances from sampled TOUCAN tasks. 

Baselines. We compare AgentSafeEvo against the following baselines: (1) the original Qwen3-8B model; (2) the prompt-based defense Spotlighting with Delimiting [24], which marks tool outputs as untrusted content using explicit delimiters; (3) the detector-based defense Prompt Guard 2 [25], which detects prompt injections in tool outputs and filters flagged content before it reaches the agent; and (4) the training-based baseline Static Adversarial Training (Static-AT), which keeps the SFT attacker fixed and updates only the defender during RL. Further details on these baselines are provided in the Appendix D.2.

4.3. Main Results 

Consistent improvements across agent safety benchmarks. Table 1 shows that AgentSafeEvo achieves the best mean performance across all reported metrics on the four safety benchmarks for Qwen3-8B. Compared with Static-AT, the strongest safety baseline, it reduces ASR from 31.01% to 17.84% on Agent-SafetyBench and from 38.64% to 31.25% on MSB. The harm score on AgentHarm also decreases from 30.00 to 6.53. On AgentDojo, UA increases from 61.43% to 66.52% while ASR remains low at 6.18%. NRP on MSB also rises from 40.64 to 46.00. The higher UA on AgentDojo indicates better task completion under attack, while the higher NRP on MSB reflects an improved combination of task performance and attack resistance. 

General capability gains beyond safety alignment. As shown in Table 2, AgentSafeEvo also achieves the highest accuracy on ALFWorld and ToolHop for Qwen3-8B. Compared with Static-AT, accuracy increases from 30.89% to 43.72% and from 39.43% to 48.04%, respectively. BFCL-V3 accuracy is 65.98%, compared with 66.13% for the original model and 66.73% for Static-AT. Static-AT improves ToolHop accuracy over the original model, but its ALFWorld accuracy remains close to the original level. 4.4. Ablation Studies 

We compare AgentSafeEvo with four ablated variants: (i) training only the defender with a fixed SFT attacker and without task weighting; (ii) retaining co-evolution without task weighting; (iii) removing defender weighting only; and (iv) removing attacker weighting only. Table 3 reports the results across safety and general capability benchmarks. 

Effect of co-evolution. Comparing variants (i) and (ii), co-evolution improves all reported metrics over defender-only training. ASR decreases by 8.10 and 5.75 percentage points on Agent-SafetyBench and MSB, respectively, while accuracy on ALFWorld increases from 30.89% to 36.70%. The frozen attacker already generates tasks online, but its task-generation policy remains unchanged throughout defender training. The improvements therefore indicate that online task generation alone does not account for the benefits of co-evolution. These results support updating the task-generation policy during defender training. 

Effect of learnability-guided task weighting. Compared with unweighted co-evolution, shared task weighting improves all reported metrics. ASR on Agent-SafetyBench decreases from 22.91% to 17.84%, while NRP on MSB increases from 41.48 to 46.00. On ALFWorld, weighting only the attacker or only the defender reduces accuracy from 36.70% under unweighted co-evolution to 29.05% and 34.25%, respectively. Applying the same task-specific weights to both policies instead raises accuracy to 43.72%. Both one-sided variants achieve lower ASR on Agent-SafetyBench than AgentSafeEvo. Weighting only the attacker also yields lower ASR on MSB, at 28.47% compared with 31.25% for AgentSafeEvo. AgentSafeEvo achieves the highest NRP on MSB and the highest accuracy on both general capability benchmarks among the evaluated variants. Attacker weighting shapes the evolving task distribution, while defender weighting adjusts each task’s contribution to policy updates. The ablations suggest that using the same task-level signal for both policies helps coordinate task generation and defensive learning. Since NRP accounts for task performance under attack as well as attack resistance, these results support shared weighting for improving robust task execution and general capabilities, rather than minimizing ASR alone.

## 5. Conclusion 

In this paper, we introduced AgentSafeEvo, a co-evolutionary reinforcement learning framework for LLM agent safety that couples adversarial task construction with safe task execution over multi-turn tool interactions. The improvements over a fixed online attacker highlight the value of using defender feedback to update the task-generation policy as the agent’s capabilities evolve. Further gains come from learnability-guided task weighting, which uses within-task defender-reward variability to reweight both policies’ updates. These findings suggest that adversarial co-evolution can strengthen the robustness of tool-using LLM agents while preserving their general capabilities. Future work will extend AgentSafeEvo to collaborative multi-agent settings, focusing on safety risks arising from communication and task delegation.

## Ethics Statement 

This work aims to improve the safety of tool-using LLM agents while preserving their ability to complete legitimate tasks. AgentSafeEvo generates adversarial tasks and uses them to train defenders against unsafe behavior in multi-turn tool interactions. These tasks may contain harmful instructions or attempts to manipulate an agent’s decisions. Their purpose is to expose failure modes and provide training signals for improving agent safety. This study does not involve the collection or use of personal data. We recognize the dual-use risks of this approach. An attacker trained to identify weaknesses in LLM agents could also be repurposed to construct malicious prompts or manipulate tool interactions. The framework and its generated tasks are intended to support safety research, defensive training, and evaluation. Any release or reuse of attacker models and adversarial data should account for their potential to facilitate misuse. Finally, improvements on the evaluated benchmarks do not establish safety in all deployment settings. Practical deployment requires further assessment of the tools, permissions, and environments available to the agent.

Harmful tool execution. Harmful tool execution concerns tasks whose underlying objective is unsafe and is advanced through observable tool actions [16, 18]. ## D. Experimental Settings 

D.1. Training Setup 

During the SFT phase, we use LLaMA-Factory [44] to fine-tune Qwen3-8B as the attacker policy. During the RL phase, we jointly optimize the attacker policy 𝜋 A and the defender policy 𝜋 D using a training pipeline built on PettingLLMs [45] and verl [46]. We use vLLM v0.19.1 [47] for rollout generation. Tables 7 and 8 summarize the corresponding hyperparameter settings. 

D.2. Baselines 

We compare our method against three baselines: (1) Spotlighting [24], (2) Prompt Guard 2 [25], and (3) Static Adversarial Training (Static-AT). 

Spotlighting. We adopt the delimiting variant of Spotlighting [24]. Before each tool output is appended to the agent’s context, it is enclosed within the special markers « and ». The system prompt designates the enclosed span as untrusted external content and instructs the model not to interpret any instructions within it as authoritative. This transformation is applied uniformly to all tool outputs, without requiring prior detection of whether an injection is present. Rather than removing or rewriting the retrieved content, Spotlighting preserves the complete tool output while making its provenance and boundary from trusted instructions explicit. 

Prompt Guard 2. We employ Llama Prompt Guard 2 [25], a lightweight mDeBERTa-based sequence classifier, to detect tool outputs for prompt injections. Each serialized tool-output message is classified independently as benign or malicious. Benign outputs are passed to the agent unchanged, whereas malicious outputs are replaced with <Data omitted because a prompt injection was detected> before the next agent step. The detector operates solely on the tool-output text and does not access the original user task or prior conversation history.

## E. Evaluation 

In this section, we detail the evaluation benchmarks and settings used in our experiments. We consider two evaluation settings: (1) agent safety and (2) general agent capabilities. For evaluation, we set the sampling temperature to 0.6 and top_p to 0.95. 

E.1. Agent Safety Benchmarks 

We assess the safety of agents on four benchmarks: Agent-SafetyBench [21], AgentHarm [18], AgentDojo [20], and MCP Security Bench (MSB) [22]. Because these benchmarks target different safety properties, we report benchmark-specific metrics. Agent-SafetyBench is evaluated using the Attack Success Rate (ASR). AgentHarm is evaluated using the harm score. AgentDojo is evaluated using ASR and Utility under Attack (UA), whereas MSB is evaluated using ASR and Net Resilient Performance (NRP). ASR measures whether an attack successfully induces unsafe behavior; UA measures whether the agent completes the intended user task under attack; and NRP combines task performance under attack with attack success. 

Agent-SafetyBench. Agent-SafetyBench evaluates both the content of an agent’s responses and the safety of its actions executed in the environment. It contains 2,000 test cases across 349 interactive environments, covering eight risk categories and ten common failure modes. Each case specifies an initial instruction or dialogue, a set of available tools and environment states, and the potential risks associated with the interaction. 

> 24 AgentSafeEvo: Adversarial Co-Evolution for LLM Agent Safety

The agent is then evaluated through interaction with the corresponding environment, including the responses it generates and the actions it takes. We report ASR for this benchmark. 

AgentHarm. AgentHarm evaluates whether agents complete explicitly harmful tasks under direct prompting and jailbreak conditions. It contains 110 explicitly malicious base behaviors and 440 task variants across 11 harm categories, including fraud, cybercrime, and harassment. The benchmark uses 104 synthetic tools, and each behavior requires coherent multi-step execution, typically involving between two and eight distinct tools. We use manually written grading rubrics to assess harmful-task completion, and report the resulting harm score. 

AgentDojo. AgentDojo focuses on indirect prompt injection in dynamic and stateful environments involving external actions. It contains 97 realistic user tasks and 629 security test cases spanning workspace, Slack, travel, and banking scenarios. Each task requires the agent to plan and execute a sequence of actions to satisfy a legitimate user request. During execution, external tools may return relevant information that also contains malicious instructions, creating a conflict between task completion and resistance to prompt injection. We report ASR and UA for this benchmark. 

MCP Security Bench. MCP Security Bench (MSB) evaluates security risks that arise when agents operate through the Model Context Protocol. It contains more than 2,000 attack instances spanning 12 attack types and ten application domains. These attacks target MCP tool signatures, parameters, and responses, as well as retrieval results and combinations thereof. Because each attack is carried out through real MCP tools, MSB captures security failures that may occur during tool discovery, invocation, and response processing, rather than only in text-based interactions. We report ASR to measure attack success. Since ASR alone does not indicate whether an agent can continue performing the intended task under attack, we also report NRP, which combines task performance under attack with resistance to attack into a joint measure of robustness. 

E.2. General Agent Capability Benchmarks 

We evaluate general agent capabilities using BFCL-V3 [33], ALFWorld [34], and ToolHop [35]. Their evaluation emphasizes different outcomes: correct function calls, completion of environment goals, and correct answers to multi-hop queries, respectively. We report accuracy for all three benchmarks. 

Berkeley Function Calling Leaderboard. BFCL-V3 focuses on function-call correctness: deciding whether to invoke a function, selecting the appropriate function, and supplying valid arguments. It covers non-live, live, and multi-turn settings, including simple, multiple, and parallel function calls, as well as cases in which none of the available functions is relevant. Its multi-turn tasks also require the agent to retain conversational context and adapt calls to earlier execution results. Accuracy is determined by the correctness of the selected functions and their arguments, together with execution outcomes where applicable. 

ALFWorld. ALFWorld focuses on goal-directed planning in text-based household environments. The agent must explore its surroundings, locate and manipulate objects, and track changes in the environment over a sequence of actions. Success depends on reaching the specified goal state. We follow AgentBench-FC 2, a function-calling adaptation of AgentBench described in AgentRL [36]. This setting expresses environment actions as structured function calls while retaining the original task dynamics. We evaluate 109 ALFWorld tasks and report task-completion accuracy. 

ToolHop. ToolHop focuses on multi-hop reasoning over interdependent tools. It contains 995 user queries and 3,912 locally executable tools. The agent must decompose a query into subproblems and use intermediate tool outputs to determine the inputs to subsequent calls. This tests whether the agent can resolve dependencies across calls and combine the retrieved information to answer the original query. We report accuracy using the benchmark’s reference-answer evaluation.
