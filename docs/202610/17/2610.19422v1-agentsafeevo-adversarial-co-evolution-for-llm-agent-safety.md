## 摘要
大型语言模型（LLM）智能体通过与外部工具进行多轮交互来完成复杂任务。然而，嵌入用户查询、工具描述或环境观察中的恶意内容可能操纵智能体的决策，诱使其采取不安全行为。对抗协同进化已成为提升 LLM 安全性的一种有效方法，但现有研究主要聚焦于语言层面的安全，或网页任务中的间接提示注入。本文提出 AgentSafeEvo，这是一种面向智能体安全的协同进化强化学习框架，基于涵盖多种任务与攻击类型的攻防博弈构建。攻击者学习构造对抗性智能体任务，以暴露防御者在使用工具时的弱点；防御者则学习在遭受此类攻击时安全地完成任务。此外，我们提出由可学习性引导的任务加权方法，利用防御者在各任务中的奖励变化幅度，调整每项任务对攻击者和防御者更新的贡献。在智能体安全与通用能力基准上的大量实验表明，该方法在保持智能体通用能力的同时，提升了对抗鲁棒性。

## Abstract
Large language model (LLM) agents accomplish complex tasks through multi-turn interactions with external tools. However, malicious content embedded in user queries, tool descriptions, or environment observations can manipulate their decisions and induce unsafe actions. Adversarial co-evolution has emerged as an effective approach to strengthening LLM safety, but existing work primarily focuses on language-level safety or indirect prompt injection in web tasks. In this paper, we introduce AgentSafeEvo, a co-evolutionary reinforcement learning framework for agent safety built on an attacker-defender game spanning diverse tasks and attack types. The attacker learns to construct adversarial agent tasks that expose weaknesses in the defender's tool use, while the defender learns to complete tasks safely under these attacks. We further introduce learnability-guided task weighting, which uses within-task defender-reward variability to adjust each task's contribution to attacker and defender updates. Extensive experiments on agent safety and general capability benchmarks demonstrate that our method improves adversarial robustness while maintaining general agent capabilities.

# AgentSafeEvo 论文总结

## 1. 核心问题与研究背景

- **研究对象**：能够通过多轮工具调用完成任务的大语言模型智能体。与普通对话模型不同，这类系统不仅生成文本，还可能执行文件修改、消息发送、云资源管理等具有外部影响的操作。
- **核心安全问题**：恶意内容可以出现在用户请求、工具描述、检索文档和工具返回结果中，诱导智能体越权调用工具、泄露信息、修改参数或执行危险操作。
- **现有方法的不足**：
  - 固定对抗数据难以持续适应防御模型能力的变化。
  - 既有协同进化方法主要关注语言输出安全。
  - 面向智能体的相关方法，如 ARLAS，主要在预先给定的网页任务中优化间接提示注入，未将完整的对抗任务构造纳入共同训练。
- **本文的整体思路**：让攻击者持续学习“构造什么任务能暴露当前防御者的弱点”，同时让防御者学习“如何在攻击下安全完成合法任务”。

**其关键目标不是单纯增加拒绝，而是提高“安全且有用”的工具执行能力。**

## 2. 方法论：核心思想、技术细节与训练流程

### 2.1 攻防角色与攻击覆盖

框架包含两个独立策略，均以 Qwen3-8B 为基础：

- **攻击者**：根据场景、意图和工具信息，生成用户请求、工具定义及环境观测，组成完整的智能体任务。
- **防御者**：在生成的环境中执行多轮工具交互，输出最终答案。

覆盖六类攻击、十三个子类：

1. 直接提示注入；
2. 间接提示注入；
3. 工具描述注入；
4. 错误信息误导；
5. 有害工具执行；
6. 用户请求越狱。

这里的攻击空间不只包括“修改一段提示词”，还包括任务、工具元数据和环境反馈之间的组合关系。

### 2.2 第一阶段：监督微调初始化攻击者

- 从 TOUCAN 中抽取约 2 万个源任务。
- 使用 Gemini 3 Flash Preview，将其中约 1 万个任务改写为对抗任务，并生成任务构造过程。
- 与约 1 万个良性样本结合，对攻击者进行监督微调。
- 目的在于解决冷启动问题，使攻击者能够生成工具格式正确、输入信息充分、调用链条基本自洽的任务。

数据覆盖 **50 类智能体场景、约 7,000 个工具**；附录给出的红队样本精确数量为 **10,310 条**。

### 2.3 第二阶段：联合对抗强化学习

每轮训练的主要步骤为：

1. 抽取一个良性或红队种子；
2. 攻击者为该种子生成 **5 个任务**；
3. 防御者对每个任务采样 **8 条交互轨迹**；
4. 奖励模型分别判断每条轨迹的安全性和任务效用；
5. 计算双方奖励、组内相对优势及任务权重；
6. 使用 GRPO 更新攻击者与防御者。

两种策略使用同一批交互反馈，但分组不同：

- 攻击者比较同一种子下生成的多个任务；
- 防御者比较同一任务下采样的多条执行轨迹。

### 2.4 奖励设计：同时约束安全与效用

奖励模型为 **Qwen3.8-27B**，独立给出两项二值判断：

- **安全奖励**：安全为 +1，不安全为 −1；
- **效用奖励**：完成合法要求为 +1，否则为 −1。

防御者总奖励是两者相加，因此取值为 −2、0 或 +2。

特殊处理包括：

- 对混合请求，拒绝危险部分后仍需完成可分离的合法工作；
- 对完全有害的请求，安全拒绝可以获得正效用奖励；
- 一旦轨迹中出现不安全行为，之后补救不会抹去该安全违规。

攻击者奖励为该任务下防御者平均总奖励的相反数。

**需要注意**：攻击者优化的是降低“安全与效用的综合表现”，并不只是在最大化不安全行为；使防御者无法完成合法工作，也可能提高攻击者奖励。

### 2.5 可学习性引导的任务加权

论文认为，**攻击有效不等于适合学习**：

- 如果同一任务的所有轨迹都失败，防御者的组内奖励没有差异，GRPO 优势为零；
- 如果不同轨迹表现不同，就存在可用于区分好坏行为的训练信号；
- 常规组内归一化又会削弱不同任务之间奖励波动幅度的差异。

因此，作者使用**同一任务内部防御者奖励的标准差**，作为可学习性的代理：

- 波动越大，该任务相对于同一种子下其他任务获得越高权重；
- 同一个任务权重同时乘到攻防双方的优势上；
- 权重系数设为 0.5，因此权重范围为 **0.5—1.5**；
- 若各任务波动完全相同，则统一使用权重 1。

该方法改变的是更新贡献，而不是奖励定义。对于组内优势已经为零的任务，加权本身并不能恢复学习信号。

## 6. 主要结论与发现

### 6.1 安全性与攻击下效用均有提升

以下为均值结果：

| 指标 | 原始模型 | Static-AT | AgentSafeEvo |
|---|---:|---:|---:|
| Agent-SafetyBench ASR ↓ | 49.11 | 31.01 | **17.84** |
| AgentHarm Harm score ↓ | 50.37 | 30.00 | **6.53** |
| AgentDojo ASR ↓ | 22.20 | 6.71 | **6.18** |
| AgentDojo UA ↑ | 53.64 | 61.43 | **66.52** |
| MSB ASR ↓ | 60.43 | 38.64 | **31.25** |
| MSB NRP ↑ | 28.12 | 40.64 | **46.00** |

这说明提升不仅来自更多拒绝：部分基准上的合法任务完成能力也提高了。

### 6.2 通用能力表现有分化

- ALFWorld：30.28% → **43.72%**；
- ToolHop：21.84% → **48.04%**；
- BFCL-V3：66.13% → **65.98%**，基本保持，但没有提升。

因此，更准确的表述是：**规划和多跳工具使用能力明显改善，函数调用准确率大体保留。**

### 6.3 攻防双方都在进步，但安全问题没有被解决

- 对原始防御者，攻击者 ASR 从 55.81% 提高到 **92.59%**；
- 面对最终攻击者，防御训练使 ASR 从 92.59% 降至 **49.82%**；
- 最终攻击者还能迁移到其他模型，例如：
  - Llama3.3-70B：43.7% → 80.7%；
  - GPT-5：12.3% → 22.5%。

这既证明攻击策略并非完全过拟合训练对手，也显示最终防御者面对其共同进化出的攻击仍有较高失败率。

### 6.4 共享加权改善综合表现，而非保证最低 ASR

- 去除全部任务加权后，Agent-SafetyBench ASR 从 17.84% 上升到 22.91%，ALFWorld 准确率降至 36.70%。
- 但部分单侧加权变体取得更低 ASR，例如去掉防御者加权时为 14.13%。
- 完整方法的优势主要在 **NRP、通用能力与安全性的综合平衡**，不是所有消融设置中的绝对最低攻击成功率。

## 7. 主要优点

- **训练对象更完整**：从对抗提示扩展到任务、工具和环境反馈的联合构造。
- **显式防止过度拒绝**：安全与效用分开评分，要求完成可分离的合法工作。
- **针对 GRPO 信号退化设计加权**：关注任务内部结果差异，而不只是攻击难度。
- **攻防使用一致任务权重**：尝试协调任务生成与防御学习。
- **评测较全面**：同时考察多类安全风险、攻击下效用、规划及工具推理。
- **因果分析相对清晰**：冻结攻击者、去除加权、单侧加权和阶段性交叉评测，提供了较好的机制证据。

## 8. 不足与局限

- **可学习性代理仍是经验假设**：奖励波动可能来自采样随机性或评审噪声，不一定代表真正可学；仅 8 条轨迹的标准差估计也可能不稳定。
- **奖励模型偏差风险**：安全与效用均由同一模型判断，缺少文中明确报告的大规模人工一致性验证，可能产生误判或奖励投机。
- **攻击者目标可能偏离安全漏洞发现**：降低效用也能增加攻击奖励，因此可能偏向生成困难、模糊甚至不可完成的任务；未见持续的独立任务有效性审计。
- **训练环境与真实部署有距离**：模拟返回结果难以完全复现生产系统中的权限、状态变化、失败恢复和不可逆副作用。
- **禁止询问确认限制了适用性**：防御者提示要求不向用户澄清或确认，但高风险个人助理任务通常需要用户授权、人机协作及权限边界。
- **安全机制仍偏模型层面**：未系统结合最小权限、沙箱、敏感操作审批等工程防线；模型鲁棒性提升不能替代这些机制。
- **复现与成本透明度有限**：虽然提供较多配置和提示模板，但不公开红队合成流水线，且缺少硬件型号与总耗时。
- **存在双重用途风险**：攻击能力可迁移到更大模型，有利于红队评测，也可能被用于实际攻击。

**总体评价**：AgentSafeEvo 为“动态构造对抗任务，并训练智能体安全完成任务”提供了较完整的框架。现有结果较有力地支持其在 Qwen3-8B 和所选基准上的综合收益，但真实部署安全、跨模型防御泛化，以及奖励波动与实际可学习性之间的关系，仍需进一步验证。
