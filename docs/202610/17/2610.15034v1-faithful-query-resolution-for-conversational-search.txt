## Abstract 

Conversational query rewriting makes context-dependent requests explicit for retrieval, but additional context can introduce an in-formation need the user did not express. This raises a question about the interaction between query fidelity and retrieval breadth. This paper examines that interaction in behavior-adaptive con-versational search, using iKAT SCAI 2026 as the evaluation set-ting. We compare five query-generation configurations within a behavior-adaptive assistant using BM25 and SPLADE retrieval. A minimal-faithful resolver preserves the user’s wording and resolves only context-dependent references; weighted reciprocal rank fu-sion combines its rankings with those from a learned rewriter and the raw utterance. Offline evaluation shows that adding these formulations recovers recall over the faithful query alone, with a slight reduction in nDCG@10. Across our five iKAT SCAI 2026 submissions, the weighted configuration obtains the highest mean retrieval scores, reaching nDCG@5 of 0.534, a 5.3% relative im-provement over the strongest alternative. However, this retrieval advantage does not coincide with the highest conversational satis-faction scores. These findings motivate separating faithful query interpretation from retrieval expansion, while assessing their effects on conversational utility independently. 

## Keywords 

Conversational search, query resolution, reciprocal rank fusion, iKAT SCAI 2026, personalization 

## 1 Introduction 

Conversational search systems must interpret an utterance in the context of earlier turns. Resolving a pronoun can make an information need explicit; adding plausible topics or personal facts can change it. For example, the correction “I mean black garlic.” already names its subject. Rewriting it as “how to use black garlic in gourmet cooking” introduces a use case that the user has not specified. This distinction motivates a simple ques-tion: How much context should a resolver add, and how should alternative queries contribute to retrieval? 

The Interactive Knowledge Assistance Track (iKAT) combines conversational retrieval with a personal textual knowledge base (PTKB) [1]. In iKAT SCAI 2026, the assistant interacts with sim-ulated users through Sim.API [6], retrieves ClueWeb22 passages, and returns responses, citations, and PTKB provenance. A shared controller supports five submitted configurations that differ pri-marily in query generation. This setting lets us examine query resolution inside a working conversational system, alongside the limits of its response behavior. Our study separates two decisions. Resolving references makes the current request interpretable while preserving its wording. 

Broadening retrieval adds independently generated queries and controls their influence through fusion weights. Our offline experi-ments favor faithful resolution over the earlier combined resolver on nDCG@10, but additional queries recover recall. The weighted configuration also obtains the highest official mean retrieval scores among our submissions. These observations support a design choice within this system; they do not establish that minimal rewriting is optimal across conversational search tasks. We make two contributions. (1) Query design: we describe minimal-faithful resolution and its integration with weighted hy-brid retrieval, and report the observed ranking–recall tradeoff. (2) Evaluation: we compare five interactive submissions and distin-guish retrieval gains from response quality, explicitly separating offline evaluation scores from official LLM judgments. 

## 2 Background 

Conversational retrieval uses earlier turns to interpret the current request, as in the TREC Conversational Assistance Track [3]. iKAT adds user-specific knowledge through a PTKB [1], making personal context available alongside the conversation. PersonaRAG [11] uses user-centric agents to adapt retrieval and generation to user data and interactions. These settings motivate the query-design question we examine: which contextual information is needed to resolve the current utterance, and which additions broaden the search beyond what the user expressed? Preserving the request still leaves a retrieval problem: the user’s wording may differ from that of relevant passages. Our system combines BM25 [9] and SPLADE [4] rankings using reciprocal rank fusion (RRF) [2], which does not require comparable retrieval scores. Query rewriting can supply alternative formulations, each producing a ranking that contributes to the fusion. We examine how these alternatives complement a faithful query and how their relative weights affect the retrieved evidence. The effect of that evidence also depends on the ensuing inter-action. User simulation supports evaluation of how an assistant answers, clarifies, and responds to feedback. UXSim [12] com-bines structured simulation components with an adaptive LLM agent, separating behavioral constraints from language genera-tion on the user side. In our iKAT evaluation, Sim.API [6] sup-plies the simulated users, while our behavior detector adapts the assistant to their observed interaction. This setting lets us com-pare retrieval scores with response assessments across the same submissions, examining whether broader retrieval also improves the simulated conversations. arXiv:2610.15034v1 [cs.IR] 10 Oct 2026 Zerhoudi et al. 

## 3 Query Fidelity and Breadth 

Query generation has two roles in this system: interpreting the request and retrieving enough evidence to answer it. Our system handles these roles separately. We distinguish three issues that guide the design and determine what the evaluation can establish. 

Resolving Context Faithfully. A user can leave an entity unnamed or refer to a previous answer. The resolver must recover that ref-erence before retrieval can match the intended subject. However, additional context can introduce a different task, a preferred use case, or a personal constraint that the user does not mention. A useful query therefore needs enough context to be interpretable while remaining faithful to what was asked. The minimal-faithful resolver restricts its edits to this interpretation step; inspection of query examples motivated the restriction, without establishing how often over-elaboration occurs. 

Combining Alternative Formulations. A faithful query can still miss relevant passages because it retains the user’s vocabulary. Addi-tional formulations can retrieve complementary evidence. When each ranking receives the same weight in RRF, however, passages repeatedly retrieved by alternative queries accumulate support that can outweigh the faithful query’s results. This motivates assigning the faithful query greater weight while preserving alternatives in the candidate pool. The weight determines each query’s contri-bution to the fused ranking. Its effect depends on the quality and overlap of the retrieved lists. 

Assessing Conversational Utility. Retrieval scores measure proper-ties of passage rankings, while a useful interaction also depends on how the assistant answers, clarifies, and responds to feedback. Simulated interaction introduces a further distinction between performance under the specified user model and behavior with real users. Zerhoudi et al. [13] evaluate simulated search sessions against real interaction data, illustrating that simulator realism is itself an evaluation target. We do not assess Sim.API’s behavioral fidelity here. The supplied response assessments measure perfor-mance in these simulated conversations; human preferences are not measured in our study. These issues yield two research questions. RQ1: Does faith-ful resolution improve offline retrieval, and what changes when other queries are added? RQ2: Does the selected configuration im-prove official retrieval and response scores? The first examines the ranking–recall tradeoff under a shared offline retriever; the second examines whether the selected configuration’s retrieval ordering coincides with response-quality gains in interactive runs. 

## 4 System and Evaluation 

We address these questions through our offline experiments and five official submissions. The system design separates faithful resolution, alternative query generation, and interaction control; the evaluation keeps offline retrieval and official interaction scores distinct. 

## 4.1 Experimental Design 

The offline comparison varies the query formulation while retaining the hybrid retriever. The manual query provides a reference for the same retrieval stack, and the faithful-only condition exposes what is lost when alternative formulations are removed. We combine the re-trieved rankings using RRF, giving passages retrieved by the faithful query twice the contribution of passages at the same rank retrieved by an alternative query. This comparison changes both the query set and the weight, so it does not isolate the effect of weighting alone. The official comparison uses independently generated interactive runs. It tests the submitted configurations as deployed, including their query-generation choices and robustness revisions. Official retrieval and response assessments are reported separately because they measure different outcomes. Neither comparison establishes a causal effect on human satisfaction. 

## 4.2 System 

The system combines a reference-preserving query generator with a behavior-adaptive controller and a hybrid retriever (Figure 1). 

4.2.1 Preserving the Information Need. The minimal-faithful re-solver receives the current utterance, history, and PTKB. It resolves pronouns and elliptical expressions to their antecedents, retaining the rest of the user’s wording. An utterance that is already inter-pretable remains unchanged. In the black-garlic example, it retains “I mean black garlic.”; for “Which of the aforementioned ones is nat-ural, not pill-based?”, it substitutes the previously listed alternatives. These prompt examples illustrate the intended behavior. Resolver accuracy has not been measured through independent annotation. M1 is our 3B query rewriter, trained with group relative policy optimization (GRPO) [10] using retrieval rewards against iKAT-2023 qrels. The query generator places the faithful query first, appends M1 rewrites and the raw utterance, and removes duplicate query strings. Additional formulations broaden the candidate pool without requiring the faithful query itself to include speculative context.

## 4.4 What Does Faithful Resolution Change? 

Motivation. A standalone query can become less faithful as it be-comes more explicit. The offline comparison examines whether preserving the utterance helps ranking, and whether additional queries restore passages missed by the narrower formulation. 

Results. The faithful query obtains nDCG@10 of 0.231, compared with 0.221 for the combined resolver and 0.171 for the focused resolver (Table 2). Its recall is lower than the combined resolver’s. The combined configuration adds M1 and the raw utterance and doubles the contribution of faithful-query passages at the same rank. It increases recall from 0.448 to 0.519, while nDCG@10 decreases from 0.231 to 0.228. The combined resolver retains the highest non-reference recall, 0.581. 

Discussion. These results show a ranking–recall tradeoff, with no uniform offline winner. Inspection of resolver examples moti-vated the restriction on added context, but does not measure the frequency or causal contribution of over-elaboration. The P@1 and P@3 calculations counted every passage with a relevance judgment as relevant, including passages judged non-relevant. We therefore do not report those precision scores. The nDCG and recall func-tions use relevance grades explicitly. We report mean offline scores without confidence intervals.

## 5 Practical Considerations 

Query generation, passage ranking, personal-fact selection, and interaction control are separate components in our system. The experiments inform choices within these components, while the submitted runs evaluate their combined behavior. Faithful Query Resolution for Conversational Search 

## 5.1 Architectural Choices 

Passage ranking. Our experiments with pretrained cross-encoders, listwise LLM reranking, dense reranking, and pseudo-relevance feedback did not establish an improvement over the fused ranking. HyDE [5] improved recall without a corresponding nDCG gain. A query-conditioned nonlinear scorer inspired by Hypencoder [7] also underperformed its baselines in a five-fold comparison over conversations. These findings informed the decision to retain the BM25 and SPLADE fusion. The experiments used different setups, so they do not establish a general ranking of these approaches. An in-domain cross-encoder remains untested. 

Personal-fact selection. We compared generate-then-verify selec-tion and an LLM relevance score with a calibrated threshold against a conservative binary selector. The best calibrated F1 was 0.38, com-pared with 0.46 for binary selection. We therefore retained the bi-nary selector for facts extracted from the conversation. The decider selects provided PTKB statements separately, so this comparison evaluates one part of the memory component. Its effect on the sub-mitted runs’ personalization scores was not measured separately. 

Search refinement. The controller can request a refined search, but the configured query generator uses the turn context and takes precedence over the controller’s proposed query strings. A refine-ment request therefore does not ensure that the next query incor-porates the controller’s suggested changes. This limits how the controller can adapt retrieval to the evidence already returned. We did not compare alternative refinement mechanisms, so its effect on mixed-initiative scores remains an open question. 

## 5.2 Interpreting the Results 

The offline experiments compare query formulations under a shared retriever. They support the observed tradeoff between ranking qual-ity and recall on iKAT-2023. The combined configuration changes both the query set and the relative contribution of the faithful query, so the comparison does not establish how much each change con-tributes to the result. A comparison that varies the contribution while keeping the query set fixed would separate these effects. The interactive scores describe the complete submitted configu-rations, including interaction control and later robustness changes. Better retrieval in R5 did not coincide with the highest satisfac-tion score. This finding motivates evaluating retrieval and response quality separately; it does not identify which component caused the response differences. The evaluation uses simulated users and LLM-based assessments. Human preferences and agreement with human relevance judgments were not evaluated. 

## 6 Conclusion 

Faithful query resolution preserves the current information need, while weighted fusion adds retrieval breadth through separate query formulations. In our iKAT SCAI 2026 submissions, the weighted configuration obtains mean official nDCG@5 of 0.534, exceeding the strongest alternative by 5.3%. Our offline experiments show the cost of that breadth as a slight nDCG@10 reduction rela-tive to the faithful query alone. The response assessments do not show a corresponding satisfaction advantage. Query fidelity and retrieval breadth can be controlled separately, while their effects on conversational utility require separate assessment.
