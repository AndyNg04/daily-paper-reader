## 摘要
强大的个体智能体并不必然带来有效协作。通信必须使一方智能体传达的内容与另一方智能体的理解和使用方式相契合。这种依赖关系使通信边成为自然的优化单元。我们提出成对自动通信优化（Paired Automated Communication Optimization，PACO），在基于黑箱语言模型构建的系统中，联合优化每条边两端的指令及其共享的通信约定。PACO 固定模型权重、智能体角色和工作流拓扑。它使用状态感知的折扣多臂老虎机选择待优化的边，并依据执行反馈指导成对修订，再通过分阶段端到端执行对修订结果进行评估。优化后的指令可集成到现有智能体提示中，部署时无需额外调用模型。在一个由四个智能体组成的工作流上，针对多个不同的多智能体基准进行评估，结果表明，PACO 的表现始终优于领先的提示优化方法和通信基线。在 HotpotQA 上学习到的配置无需针对目标数据集进行优化，便能在跨数据集迁移中保持优势。这些结果表明，即使系统其他部分保持不变，优化智能体之间的通信方式也能显著提升协作效果。

## Abstract
Strong individual agents do not guarantee effective collaboration. Communication must align what one agent conveys with how another interprets and uses it. This dependency makes the communication edge a natural unit of optimization. We introduce Paired Automated Communication Optimization (PACO), which jointly optimizes the instructions at both ends of each edge and their shared communication convention in systems built on black-box language models. PACO keeps model weights, agent roles, and workflow topology fixed. A state-aware discounted bandit selects edges for refinement, while execution feedback guides paired revisions evaluated through staged end-to-end execution. The optimized instructions integrate into existing agent prompts without additional model calls at deployment. On a four-agent workflow evaluated across diverse multi-agent benchmarks, PACO consistently outperforms leading prompt-optimization and communication baselines. Configurations learned on HotpotQA retain their advantage in cross-dataset transfer without target-specific optimization. These results demonstrate that optimizing how agents communicate can substantially improve collaboration within an otherwise fixed system.

## 1. 核心问题与研究背景

- **核心问题：单个智能体能力强，并不意味着多智能体系统协作有效。** 信息交接可能出现两类失效：
  - **发送端遗漏**：没有传递下游推理所需的证据、约束、来源或不确定性。
  - **接收端误用**：即使消息包含正确信息，下游仍可能误解关系、错误聚合，或丢失关键引用。
- 论文用平均数计算说明这种依赖：上游报告两个数的均值为 10，下游另有一个数 100。上游若不提供样本数，下游无法正确加权；即使提供样本数，下游若错误地平均两个均值，仍会得到 55，而非正确答案 40。
- 现有研究主要优化工作流拓扑、智能体提示或消息表示，也有方法考虑智能体之间的兼容性。本文进一步追问：**既然问题跨越发送和接收两端，是否应该把“通信交接”本身作为优化单元？**
- 论文提出的整体思路是：**在不改变模型权重、角色、拓扑和信息权限的情况下，通过联合优化通信边两端的行为，改善系统级协作。** 这里的协作指语言模型智能体之间的协作，并非直接研究人机协作。

## 2. 方法论：PACO 的核心思想与算法流程

### 2.1 将一条通信边定义为可优化的“通信包”

论文提出 **PACO（Paired Automated Communication Optimization，成对自动通信优化）**。对于有向边 \(u\rightarrow v\)，其通信包包括：

- **发送端指令**：规定上游如何筛选、组织并传递任务信息。
- **接收端指令**：规定下游如何解释、核验并使用消息。
- **共享通信约定**：统一字段含义、证据来源、关系表达和不确定性处理规则。
- **消息表示属性**：例如自然语言或类型化记录。

这些内容被嵌入智能体已有提示。普通更新只允许修改选中边的通信包，其他通信模块和固定角色指令保持不变。

**优化目标是完整工作流的任务得分，而不是消息格式合规率或单个智能体的局部表现。** 搜索受 Token 预算约束，但没有把部署成本直接纳入质量目标。

### 2.2 保留多个候选配置，而非只沿当前最优配置搜索

- PACO 维护由完整通信配置组成的候选池。
- 配置必须具有足够好的内部验证集表现，同时能对部分样本提供互补优势。
- 每个验证样本为达到该样本最佳得分的配置分配“胜场”；系统据此采样下一步的父配置。
- 冗余配置会被删除，但保留样本覆盖能力。因此，搜索可以从不同优势的配置继续演化，允许中间路径出现非单调变化。

### 2.3 用状态感知的折扣多臂老虎机选择通信边

- 将每条边视为一个可选择的“臂”，根据历史修订的端到端收益分配搜索机会。
- 选择指标综合：
  - **收益估计**：优先优化过去产生较大改进的边。
  - **探索奖励**：为尝试不足、或仅经过小样本评估的边保留机会。
- 历史收益采用指数折扣，降低较旧观察的影响；配置不同，历史统计也独立维护。
- 论文明确指出：样本量修正是**启发式探索机制，并非经过校准的统计置信界**。

### 2.4 两轮执行反馈驱动的成对修订

每个普通优化步骤执行两轮候选生成：

1. 在小规模试验批次上执行父配置。
2. 提议模型读取当前通信包和执行反馈，生成 **2 个第一轮候选**。
3. 执行候选，选择得分最高且可评估的候选作为第二轮生成基础。
4. 根据第一轮实际执行效果，再生成 **2 个第二轮候选**。
5. 两轮候选共同进入后续筛选。

关键细节：

- 即使第一轮候选全部退步，其中最好的候选仍可作为第二轮修订起点。
- **所有增益始终相对于原始父配置计算**，不是逐轮累加。
- 提议模型能看到任务输入、消息、输出和改进方向等反馈，但看不到参考答案、隐藏推理或逐样本数值评分。
- 内部验证集执行不会作为候选生成示例。

### 2.5 分阶段端到端评估与协同修订

为控制搜索成本，采用三级评估：

| 阶段 | 样本数 | 筛选规则 |
|---|---:|---|
| 试验阶段 Pilot | 4 | 增益大于 0.01，最多晋级 2 个候选 |
| 晋级阶段 Promotion | 8 个新样本 | 选择具有正增益的最佳候选 |
| 内部验证 \(H\) | 100 | 最多评估 1 个候选，用于归档、候选池维护及最终选择 |

- Pilot 与 Promotion 在同一步内互不重叠，且均来自搜索集。
- 内部验证支持基于“即使剩余样本全部满分也无法达标”的确定性上界提前停止。
- 普通步骤若刷新内部验证集历史最佳成绩，会触发一次允许修改多条边的**协同修订**，但不递归触发。
- 最终冻结内部验证均分最高的配置，用于独立测试。

**部署时不增加消息改写或澄清调用，但提示和消息可能变长，因此不代表 Token 成本不增加。**

### 6.2 跨数据集迁移

| 数据集 | Vanilla Answer F1 | GEPA Answer F1 | PACO Answer F1 |
|---|---:|---:|---:|
| DROP | 42.25 | 49.09 | **54.95** |
| MuSiQue-Ans | 29.60 | 44.50 | **45.06** |

- PACO 相对 GEPA 在 DROP 提高 **5.86** 个 F1 点，在 MuSiQue-Ans 提高 **0.56** 个点。
- 两个目标集的 Answer EM 均为 **35.75**，领先所比较方法。
- 结果支持通信配置具有一定迁移性，但 MuSiQue 的 F1 优势较小，尚无统计显著性证据。

### 6.3 消融与机制发现

- 5M 预算下，PACO Joint F1 为 **49.35**：
  - 仅发送端：47.29。
  - 仅接收端：46.24。
  - 三部分独立更新：48.42。
  - 均匀选边：41.41，三次运行均值。
  - 单轮修订：48.57。
- 这些结果支持：
  - 成对协调优于只修改一端或分别修改。
  - 自适应选边在有限预算下具有较明显价值。
  - 第二轮执行反馈提供较小的额外收益。

消息诊断还发现：

- Resolver 对已识别正确引用的延续率由 **37.0% 提高至 80.8%**。
- Verifier 的延续率由 **65.8% 提高至 93.7%**。
- Scout 的引用发送率却从 **80.1% 降至 65.1%**。

因此，改进并非简单来自“传递更多引用”，而更可能涉及信息选择、组织和下游使用方式的对齐。不过，引用保留率本身不等于语义理解或正确推理。

## 7. 主要优点

- **优化单元契合问题结构**：将发送、接收和共享语义联合修改，直接针对跨智能体交接失配。
- **适用于黑箱模型**：无需权重更新，便于接入既有系统。
- **使用端到端任务反馈**：避免把格式整齐或局部输出质量误当成整体协作能力。
- **搜索机制兼顾效率与多样性**：候选池、选边调度和分阶段筛选共同控制昂贵评估。
- **允许非单调探索**：保留互补配置，并允许从第一轮退步候选继续修订，降低纯贪心搜索的限制。
- **迁移验证有实际意义**：目标任务不参与优化，有助于区分可迁移通信规则和源任务适配。
- **报告较透明**：附录披露提示、预算、反馈边界、无效预测规则，并主动说明案例选择和诊断指标的解释限制。

## 8. 不足与局限

### 8.1 覆盖范围有限

- 仅验证一个模型系列、一条四智能体链和三个文本问答数据集。
- 未验证复杂 DAG、并行分支、循环反馈、动态拓扑、异构模型或大规模智能体系统。
- 没有代码、网页操作、工具调用、长期规划及人机协作实验。
- 原始证据被分片且只能逐级传递，强化了交接瓶颈；完整上下文共享场景中的收益可能不同。

### 8.2 机制归因和统计证据仍不足

- 主要比较缺少系统性的多种子统计与显著性检验，尤其限制对小幅领先的解释。
- 配对方法同时改变发送、接收、共享约定和表示，无法明确拆分各部分贡献。
- 协同修订虽允许多边更新，但实际主运行中成功刷新最优的协同修订都只修改 Resolver → Integrator，尚不能证明多边协同的独立收益。

### 8.3 存在评估和优化偏差风险

- 内部验证集只有 100 条，反复参与搜索与最终配置选择，存在选择性过拟合风险。
- 评分包含严格输出与引用可接受性规则，性能提升可能同时来自推理改善、引用保存和格式有效性提升。
- 搜索期与最终 HotpotQA 使用的输出解释流程有所区别，搜索轨迹分数不能直接等同于最终测试分数。
- 部分无本地证据的下游输出出现输入中未识别到的正确引用；论文也承认无法据此确定其来源，因此不能把引用计数理解为严格的信息流证明。

### 8.4 应用与复现限制

- 依赖可靠任务评分和大量端到端执行，难以直接用于无标准答案、评价昂贵或高风险在线场景。
- 没有联合优化质量、成本与延迟；更长提示和消息增加部署开销。
- 学得指令部分涉及局部推理和答案选择，不完全是“通信格式优化”；一些强调非空答案的规则与固定角色中的证据不足时返回非成功状态要求可能形成张力。
- 黑箱模型输出具有随机性，提供方生成种子未固定；论文称代码将在接收后发布，独立复现仍有门槛。
- 基准提升不代表安全性或事实可靠性得到保证，错误信息仍可能沿链传播。

**综合评价：PACO 的主要价值，是把“通信边上的双端协调”明确建模为提示搜索单元，并在固定问答工作流中展示了有效性。它为现有多智能体系统提供了一条无需改权重、无需增加部署调用的改进路径，但其跨拓扑普适性、统计稳健性及成本收益仍需更广泛验证。**
