## ABSTRACT 

Memory enables large language models (LLMs) to use information beyond their parameters, such as past user conversations, long documents, or an agent’s earlier actions. For a frozen LLM, access to this accumulated knowledge is limited to what a memory system places in its context window. However, gathering and combining relevant information needed for each query while keeping the model’s context short remains challenging for existing systems. Here we introduce M EMORILLA , a mem-ory system that gathers information from an entire document collection into a fixed number of query-dependent ‘memory tokens’ for a frozen LLM. M EMORILLA 

encodes documents (such as user chats, book chapters) once into reusable embed-dings, then learns to retrieve and place query-specific information in the LLM’s input embedding space. Using only 16 memory tokens, M EMORILLA achieves the best average performance against baselines including Mem0 and MemoRAG across benchmarks spanning personalization, long-document and knowledge-intensive question answering. Notably, on FactKG, it reaches 84.33% accuracy versus 80.43% with full-context inference, while using 108 × fewer tokens to represent the source documents. Furthermore, M EMORILLA can facilitate continual learning in agentic systems where the document count (the agent’s past turns) increases throughout the trajectory. In a TextWorld environment, we show that M EMORILLA 

reduces the agent’s tendency to wander between rooms it has already explored, and improves its average success rate from 18.6% with full-history in-context learning to 24.2%. Overall, M EMORILLA aids frozen LLMs in accumulating and using knowledge effectively across long-context interactions and takes a step towards building continually learning AI systems. 

## 1 INTRODUCTION 

Memory is central to how large language models (LLMs) are used. Personal assistants must recall a user’s history across months of conversations, question-answering systems must reason over documents far longer than the model’s context window, and agents must act on everything they have observed. None of this information exists in the model’s parameters, and a frozen LLM can use it only through its context (Hu et al., 2025). A memory system bridges this gap by encoding accumulated information, storing it persistently, and retrieving what each query needs into the context (Wu et al., 2025). The central challenge for such a system is to give a frozen LLM access to an entire, growing collection of knowledge while keeping its context short (An et al., 2025; Du et al., 2025). Existing memory systems address these issues only in part. Agentic memory systems such as MemGPT (Packer et al., 2023), Mem0 (Chhikara et al., 2025) and A-MEM (Xu et al., 2025) organize past interactions into summaries or structured records, and MemoRAG (Qian et al., 2025) uses a

Latent compression methods such as ICAE (Ge et al., 2024), IC-Former (Wang et al., 2024a), AutoCompressors (Chevalier et al., 2023) and ComMer (Zeldes et al., 2025) represent documents as a few soft tokens in the LLM embedding space, but they form these tokens without the query, so the same tokens must serve every question. xRAG (Cheng et al., 2024) incorporates query relevance but only by compressing a single retrieved document. Methods that store model-specific hidden or key–value states, such as LongMem (Wang et al., 2023), MemoryLLM (Wang et al., 2024b), M+ (Wang et al., 2025), and Cartridges (Eyuboglu et al., 2026), tie the memory to one model and require training the LLM, a side network, or a separate cache for each corpus. What is missing is a memory system that will retrieve query-relevant information from document embeddings directly into the input embedding space of a frozen LLM. Benefits of such an approach would be that the frozen LLM can retain all of its capabilities, and rely on only a few query relevant latent embeddings to answer questions or solve tasks instead of processing long textual contexts in a slow and lossy manner (Liu et al., 2024). In essence, improving the speed and quality of LLM responses and also the decision making in LLM agents based on past experiences. 

Present work. Here we introduce M EMORILLA , a memory system that learns to retrieve query-relevant information from document embeddings directly into the input embedding space of a frozen LLM (Figure 2). First, a frozen embedding model encodes each document, such as a user conversation or a book chapter, once into a persistent memory store. Next, for each query, a trainable memory module attends to every embedding in the persistent memory store and performs a query conditioned memory readout for the LLM. Unlike RAG which retrieves a subset of documents as textual tokens, MEMORILLA learns to recall what matters from the entire collection for a query, and expresses it as 

K = 16 latent memory tokens for a frozen LLM, and does not require the documents to enter the context as text. Because the store uses the same embeddings as a dense retrieval index, encoding adds no cost over retrieval, and with 512 documents on one H100, M EMORILLA has 27 × lower end-to-end latency than full context answer generation (0.74s against 19.9s, Appendix F). Our benchmarks mirror three settings in which deployed LLMs need memory (Figures 1 and 3). In personalization, an assistant must adapt to preferences a user rarely states directly, whether answering questions that depend on traits revealed across past conversations (PersonaMem-v2, PersonalizationV4) or writing in the style of the user’s earlier text (LaMP-4, LaMP-7). Because a user’s preferences rarely share wording with the query, similarity-based retrieval struggles to find and combine relevant information. Notably, on LaMP-4, M EMORILLA reaches 18.15 ROUGE-L against 14.21 for full context while using 474 × fewer document tokens. In knowledge-intensive question answering, such as checking a claim against a knowledge base, M EMORILLA outperforms full context on FactKG (84.33% against 80.43%) with 108 × fewer document tokens. In long-document understanding, the answer is buried in thousands of tokens of text and often phrased differently from the question, so a system must find and connect relevant content across the entire document. ## 2 MEMORILLA 

A persistent latent memory must preserve a document collection across queries while recalling different information for each query. M EMORILLA meets these requirements through three operations: 

encoding , storage , and retrieval . Given N document chunks D = {d1, . . . , d N }, a frozen encoder produces a query-independent representation that is stored once. For instance, D can be a collection of N user-LLM conversations, chapters of a lengthy book, or health records. For each query q, a trainable memory module reads this store and returns K query-conditioned soft memory tokens, which a frozen LLM consumes together with the query text. We use a three-stage curriculum that moves from general content preservation to diverse language tasks and then to the evaluation domains. See Appendix B.2 for training hyperparameters. 

Stage 1 trains the memory module on 1.98 million English Wikipedia paraphrase reconstruction examples. Each passage is divided into document chunks, and the module must preserve enough information in its fixed memory budget for the frozen LLM to generate a paraphrase. This stage provides a general initialization before the module encounters task-specific supervision. 

Stage 2 continues training on 1.34 million examples drawn from ten datasets covering reading comprehension, open-domain question answering, and summarization. The variation in source structure and answer format teaches the module to recall different information from the same type of stored representation. Table 1 lists the component datasets and their sizes. 

Stage 3 fine-tunes the resulting module on a unified mixture of the training splits from all eight evalu-ation benchmarks. One multi-task checkpoint is used directly for FactKG, TriviaQA, NarrativeQA, PubMedQA, LaMP-4, and LaMP-7. PersonaMem-v2 and PersonalizationV4 receive additional benchmark-specific fine-tuning because their validation losses required more epochs to plateau, while the other benchmarks plateaued or began to overfit earlier. 

## 3 EXPERIMENTS 

3.1 BASELINES 

We compare M EMORILLA against RAG approaches based on cosine similarity, Mem0 (Chhikara et al., 2025), and MemoRAG (Qian et al., 2025). xRAG (Cheng et al., 2024) and ComMer (Zeldes et al., 2025) (via its reported results, Table 12) compress the context into latent input embeddings for the LLM. Finally, we also compare against LLMLingua-2 (Pan et al., 2024), which is a task-agnostic text based prompt compression method. All baselines we run use a frozen Qwen3-Embedding-4B encoder for document embeddings and a frozen Qwen3-8B decoder for generation. Mem0 and MemoRAG additionally use a frozen Qwen3-4B-Instruct-2507 to build their memories, matching the 4B scale of the encoder with which M EMORILLA reads the same collections (Appendix C). 3.2 BENCHMARKS 

We evaluate M EMORILLA on eight supervised benchmarks spanning (a) personalization, (b) long-document QA, and (c) knowledge-intensive QA tasks that demand memory. For personalization, we consider PersonaMem-v2 (PMv2) (Jiang et al., 2025), LaMP-4, LaMP-7 (Salemi et al., 2023) and our own PersonalizationV4 (PV4) benchmarks as they require integrating information scattered across a user’s prior chats or writing history to form a coherent user representation. For long-document QA, we choose NarrativeQA (Koˇ cisk` y et al., 2018) and TriviaQA (Joshi et al., 2017) to test the method’s ability to compress long documents in their entirety into a usable representation for downstream QA. Finally, for knowledge-intensive QA, we consider FactKG (Kim et al., 2023) and PubMedQA (Jin et al., 2019) to test factual grounding from structured or semi-structured evidence of varying quantity and format. Table 10 (Appendix D.2) reports how many document tokens each method gives the LLM per query across all the benchmarks. 3.3 EVALUATION 

We use accuracy for classification tasks, exact match and token-level F1 (lowercased, whitespace-tokenized) for short-form QA, and ROUGE, BLEU, F1, and METEOR for open-ended text generation. PMv2 and PV4 are evaluated on their short-answer questions. The model’s generation is embedded with the frozen encoder and scored as correct if the gold answer is its cosine nearest neighbor among the question’s predefined answer choices, which we report as short-answer accuracy. All supervised LLM evaluations use a decoding temperature of 0. ## 4 QUANTITATIVE RESULTS 

MEMORILLA outperforms all baselines on average while using 394 ×, 113 × and 49 × fewer document tokens than full context, RAG-50 and MemoRAG in geometric mean (Figure 1). It also lies on the Pareto frontier of every benchmark, while the compact baselines xRAG, LLMLingua-2 and Mem0 average only 41.92, 40.75 and 38.02 against 49.68. Figure 3 breaks this down by benchmark, where MEMORILLA leads on five and and is second on NarrativeQA and PV4. 

Relational evidence. On FactKG (Figure 3a), M EMORILLA reaches 84.33% against 80.43% for full context, 80.38% for MemoRAG and 78.98% for xRAG, with 108 × and 36 × fewer tokens than the first two. Because full context receives every document, the margin cannot stem from discarded evidence, and Section 5 shows that M EMORILLA ’s margin over RAG-50 grows with the number of entities and widens overall with the number of composed facts. 

Long-document and personalization QA. On TriviaQA (Figure 3b), M EMORILLA reaches 57.00 EM against 56.60 for MemoRAG and 52.60 for full context with 19 × and 743 × fewer document tokens. On PMv2 short-answer (Figure 3c), M EMORILLA reaches 44.60% against 30.90% for xRAG, the strongest baseline. Every other baseline stays within about three points of closed-book (25.64%), including full context, which uses 1,974 × more document tokens than M EMORILLA . On LaMP-7, every baseline except xRAG (46.84) stays within one ROUGE-L point of the closed-book model, whereas M EMORILLA improves it from 43.13 to 48.37. Finally, M EMORILLA achieves 18.15 ROUGE-L on LaMP-4 (Figure 3e) with 474 × fewer tokens than the full context baseline. 

Where memory does not help. On the remaining three benchmarks (Figures 3f–3h), a baseline leads, but only by supplying the LLM with 18 to 690 times more document tokens. MemoRAG leads NarrativeQA in ROUGE-1 and ROUGE-L (21.80 and 20.51 versus 19.68 and 19.31) with 50 × more document tokens, consistent with its access to verbatim passages, and PV4 (67.88% versus 66.65%) with 690 × more. On PubMedQA, whose four abstracts total only 324 tokens, LLMLingua-2 reaches 69.00% and four other baselines 67.00%, versus 59.00% for M EMORILLA .

Full context is not an upper bound. Full context trails M EMORILLA on every benchmark except PubMedQA and on 20 of 21 metrics in Table 11, and RAG-50 exceeds it on 15, so supplying the entire collection hurts more often than it helps. 6Preprint

## 5 WHAT DOES MEMORILLA LEARN ?

Conceptual understanding vs. factual recall. Figure 4a breaks down NarrativeQA performance by question type. MEMORILLA outperforms RAG-50 by +4.91 ROUGE-L on “why” questions and +7.02 on “how,” both requiring reasoning about narrative structure and causality. Conversely, RAG-50 leads by +3.45 on “who” and by +2.93 on “which,” where retrieval can locate the entity name verbatim. One explanation is that compression preserves global structure for conceptual reasoning but loses the exact surface tokens that retrieval excels at pinpointing (although question type also varies with answer length and entity frequency). The same trade-off would explain why MemoRAG, which reads selected passages, leads our ROUGE scores on this benchmark while trailing on F1. Figure 6 illustrates the complementary strength in personalization, where M EMORILLA uses semantically relevant medical history despite no lexical overlap with the query. 

Multi-entity relational reasoning. On FactKG, M EMORILLA ’s advantage over RAG-50 grows monotonically with entity count, from +4.23pp at 1 entity to +7.59pp at 4+ (Figure 4b). RAG-50 drops from 78.73 to 51.75 as the number of composed facts increases from 1 to 4, while M EMORILLA 

remains in the 80–89 range (Figure 4c). Compression encodes relational structure holistically, whereas retrieval degrades when the reasoning chain spans multiple documents. Because 73.5% of FactKG claims have more than 50 chunks, part of this gap reflects evidence RAG-50 never retrieves, but full context, which reads every chunk, still trails M EMORILLA overall (80.43 against 84.33). 

MEMORILLA and RAG solve different questions. On FactKG, we observed that 15.9% of questions are answered by M EMORILLA alone against 10.0% by RAG-50 alone, and on PMv2 short-answer the split is 27.1% against 9.2%. In Figure 5, we show that the union of M EMORILLA and RAG (which is an oracle upper bound), could lead to substantial gains in performance than either approach alone, which motivates the design of hybrid retrieval and latent-memory systems as potential future work. 7Preprint

What neither method solves. We also examine the questions that both M EMORILLA and RAG-50 answer incorrectly. On PV4, many of these require linking facts that each appear somewhere in the user’s history, which suggests that the remaining errors come from combining information rather than from failing to find it. On FactKG, both methods are biased toward judging claims false. True claims make up 89.5% of the claims both methods get wrong but only 28.7% of those both get right, which points to a miscalibrated decision threshold rather than missing evidence. 

## 6 CONTINUAL LEARNING WITH MEMORILLA 

Beyond the supervised learning settings where the document collection can be static, we showcase the potential of M EMORILLA in scenarios where an LLM agent has to continuously learn and adapt from its environment. One such environment is TextWorld (Côté et al., 2018), a suite of partially observable text games in which an agent explores up to 65 rooms, manipulates objects and pursues multi-step goals for at most 50 turns, with reward arriving mainly on a win. After each turn, M EMORILLA 

stores the completed turn as a new document and condenses the growing document embedding store into K = 8 memory tokens placed before the prompt (Figure 7 and Appendix G). 6.1 EXPERIMENTAL SETUP 

The agent is a frozen Qwen3-4B-Instruct-2507 decoder paired with the frozen Qwen3-Embedding-4B encoder. Only the memory module is trained, from random initialization and with GRPO on environment reward (see Appendix G.1). We compare against two baselines. Full-history in-context learning (ICL) gives the decoder the complete interaction history without memory, and an untrained memory module isolates the contribution of RL. Unlike in the supervised setting, the memory supplements the text rather than replacing it. Every condition keeps the full history under the same input budget (16,000 tokens in training, 4,096 in evaluation), so any improvement reflects what the memory learns to extract, not access to additional information. In the medium and hard games, the history grows from 800 tokens at the first turn to about 3,200 and then levels off, since the median rollout ends at turn 33 and only 5 of 40 rollouts reach turn 50. 8Preprint 6.2 RESULTS

Untrained memory instead falls below ICL on both metrics, avg@3 (0.153) and pass@3 (0.225), so the gain comes from learning rather than from the added tokens. ## 7 DISCUSSION AND CONCLUSION 

MEMORILLA separates persistent knowledge storage from the context required for each query. New documents can be added without updating the LLM, while the memory module learns to extract relevant information through a fixed number of latent tokens. This design supports assistants that draw on growing histories without proportionally increasing the decoder’s context. Our analyses suggest that the learned representations capture relationships across documents and recover personal context beyond lexical similarity. In TextWorld, reinforcement learning improves a frozen agent’s decisions even when the interaction history is already available as text. Together, these findings support learned memory as a means of improving how LLMs use accumulated information, with the memory interface optimized through either answer supervision or environment reward. 

Conclusion. In this work, we introduced M EMORILLA , a latent semantic memory system that gives frozen LLMs access to query-dependent information from large corpora as ‘soft’ memory tokens. M EMORILLA demonstrates that a frozen LLM can use accumulated knowledge through a learned, query-dependent interface, rather than relying only on retrieved text or an expanding prompt. MEMORILLA leads retrieval, compression and agent memory baselines on average at 20 to 4,212 ×

fewer document tokens across personalization, long-document QA, and knowledge-intensive tasks. Additionally, M EMORILLA also enables continual learning in agentic RL, where training only the memory module teaches an agent a new environment without overwriting prior knowledge. 

Limitations and Future Work. MEMORILLA can lose fine-grained factual details, likely because the document encoder was never trained for memory compression. Future work exploring combinations of latent memory and text retrieval could combine the global structure that memory captures with the exact entities that retrieval recovers. Furthermore, encoders trained specifically for compression could close the remaining gap on fine-grained details. Our experiments pair a Qwen encoder with a Qwen decoder, and testing how well the memory mechanism transfers across model families is also an interesting future area of research. Our evaluation covers personalization, long-document QA and knowledge-intensive QA, so M EMORILLA may not carry over directly to domains such as coding. Nonetheless, for personalization tasks, because the persistent memory store holds only embeddings, a multimodal encoder could extend the same interface to images, audio and video, giving assistants a memory of what a user has seen and heard. Since each user’s memory is a separate store, it can be kept on device or deleted on request, which eases privacy concerns. Finally, because LLM decoding dominates latency, the efficiency gains show up mainly for large collections. ## A RELATED WORK 

Textual memory. Textual memory keeps source records readable and retrieves relevant records at inference. RAG (Lewis et al., 2020) and REALM (Guu et al., 2020) retrieve passages from a document index. Systems built for longer histories retain the same basic interface while organizing the records differently. MemGPT (Packer et al., 2023) moves information between context tiers, MemoryBank (Zhong et al., 2024) stores conversations and summaries, and Mem0 (Chhikara et al., 2025) and A-MEM (Xu et al., 2025) maintain structured records across sessions. These systems preserve provenance and exact details, but the LLM can reason only over material that retrieval places in its context. Evidence outside the selected set remains unavailable, and widening that set yields limited returns. In-Context RALM (Ram et al., 2023) finds that most question-answering gains come from the first one or two retrieved documents. MemoRAG (Qian et al., 2025) uses compressed global memory to generate retrieval clues, but its final generator still reads selected passages. Textual memory is therefore effective when evidence can be localized, while signals distributed across a collection remain constrained by document selection. M EMORILLA instead computes a query-conditioned latent state from the full collection, complementing retrieval when exact evidence is needed. 

Latent compression. Latent compression replaces replayed text with compact continuous state. ICAE (Ge et al., 2024) and IC-Former (Wang et al., 2024a) encode a long input into reusable vectors consumed by frozen target LLMs, while AutoCompressors (Chevalier et al., 2023) fine-tune an LLM to produce and consume recursive summary vectors. These representations can be cached because they are computed without a query, but they cannot change what they emphasize for different queries. Gist tokens (Mu et al., 2023) and 500xCompressor (Li et al., 2025) make the same tradeoff using layer-specific key–value states rather than standard input embeddings. xRAG (Cheng et al., 2024) makes the representation query relevant by first selecting a document through retrieval and mapping its embedding to one LLM token, which retains document selection as the access mechanism. A second line improves the alignment between compression and generation. PISCO (Louis et al., 2025) and COCOM (Rau et al., 2024) jointly adapt their compressors and generators, while CLaRa (He et al., 2025) learns reusable document vectors before training a query reasoner with the generator. These methods gain a learned latent interface but require an adapted generator. Other methods obtain reuse within a narrower memory domain. TokMem (Wu et al., 2026) optimizes a separate token for each procedure, while ComMer (Zeldes et al., 2025), USER-LLM (Ning et al., 2025), and Embedding-to-Prefix (Huber et al., 2025) construct latent state for user histories. M EMORILLA instead accepts unseen document collections without further optimization and converts an LLM-independent store into new query-conditioned input embeddings for a frozen LLM. 

Model memory. Model memory stores information in architecture-specific state. Memo-ryLLM (Wang et al., 2024b) maintains a self-updating latent pool, M+ (Wang et al., 2025) retrieves from long-term storage using the current hidden state, and LongMem (Wang et al., 2023) retrieves cached key–value states through a trained side network. Their shared internal representation sup-ports query-conditioned recall, but also couples the memory and its reader to a particular model. Other methods preserve state during model execution rather than across an independent document collection. LM2 (Kang et al., 2025) updates a gated memory matrix during autoregressive inference. Titans (Behrouz et al., 2025) combines fixed task-level parameters with a contextual neural memory updated while processing a sequence. MELODI (Chen et al., 2025) and Activation Beacon (Zhang et al., 2025) compress state across context windows and transformer layers to extend long-sequence processing. Cartridges (Eyuboglu et al., 2026) makes model-specific key–value caches reusable and composable, but requires offline optimization for each new corpus. These approaches demonstrate the value of persistent latent state, while their architecture-specific interfaces limit reuse across models and collections. M EMORILLA instead keeps memory external and supplies it to a frozen LLM as input embeddings.

xRAG. xRAG (Cheng et al., 2024) maps the embedding of the top retrieved chunk to a single soft token in the input space of the decoder through a trained bridge. We reimplement the bridge in our codebase as a layer normalization followed by a two-layer MLP with a GELU activation, which maps the 2,560-dimensional chunk embedding to the 4,096-dimensional decoder input space with 27,276,288 trainable parameters. The chunk is retrieved by cosine similarity with the shared encoder. Only the bridge is trained, from scratch on each benchmark’s training split with the same answer-token loss as M EMORILLA . We train for 5 epochs with AdamW at a learning rate of 10 −4,a weight decay of 0.01, a warmup ratio of 0.1, an effective batch size of 16, a maximum sequence length of 8,192 tokens and seed 23. 

ComMer. ComMer (Zeldes et al., 2025) compresses user-history documents into latent represen-tations with a learned compressor, merges them and passes them to a frozen LLM for personalized generation. We compare against its reported LaMP-4 and LaMP-7 results in Table 12. 

Mem0 and MemoRAG. Mem0 (Chhikara et al., 2025) extracts and consolidates memories at write time, while MemoRAG (Qian et al., 2025) forms clue queries from a global memory to guide retrieval. We run the official implementations with the settings in Table 6. Both use a frozen Qwen3-4B-Instruct-2507 to write their memory, as the fact extractor of Mem0 and as the memory model of MemoRAG. This matches the 4B scale of the Qwen3-Embedding-4B encoder with which M EMORILLA reads the same collections, so every method processes the documents with a 4B model and answers with the same frozen Qwen3-8B decoder. MemoRAG runs in its supported long-context memory mode, in which the memory model reads the uncompressed collection rather than a compressed version of it. Its retrieval uses each benchmark’s own chunks and the shared encoder, so the clue mechanism is its only difference from RAG-k. We sweep the retrieval depth of Mem0 over k ∈ { 10 , 30 , 50 } and of MemoRAG over its native setting and caps of 5 and 50 chunks, and report each at its best depth per metric.

D.1 PERSONALIZATION V4 D ATA PIPELINE 

PersonalizationV4 is a synthetic benchmark for evaluating multi-document user modeling. Each user has one LLM-generated persona profile seeded from the Faithful Persona-based Conversational Dataset (Jandaghi et al., 2023). The resulting profiles are 10k to 22k characters long (median 15.5k) and describe demographics, personality, work, hobbies, communication style and how preferences change over time. All of the user’s data is derived from this profile through the five steps below, and Table 8 traces one held-out user through each of them. 1. Question categories. GPT-5.1 reads the persona and extracts 10 persona-specific categories that questions can test. 2. Chat topics. GPT-5.1 writes exactly 200 one-sentence scenarios per user in which the user asks the assistant for help, covering every part of the persona. 3. Dialogues. GPT-5-mini expands each topic into one two-turn dialogue with one user turn and one assistant turn. The user embodies the persona implicitly without stating its traits. Exactly 200 dialogues are generated per user and all form the collection that the memory module reads; there is no truncation step. 4. Questions. For each category, GPT-5.1 is asked to write 15 questions from the persona alone. It writes 14 in 1,234 of the 1,490 released category files and 13 to 15 in all but one, which has 5. Each question has a reference answer and four distractors. The instructions in Table 9 require every question to combine at least two persona facts in a new scenario and every distractor to be a plausible preference that matches the reference answer in length, structure and specificity. This gives 133 to 145 questions per user (mean 141.3). 5. Randomization. The reference answer’s position among its distractors is shuffled with a fixed seed of 42. Questions are posed without their candidate answers, and the model answers in free text. The reference answer and distractors are used only by the short-answer scorer, which counts a response as correct when its nearest candidate under the Qwen3-Embedding-4B encoder is the reference answer. We release 149 users: 119 training users and 30 held-out evaluation users, none of whom appear in training. One training user whose generated persona was a refusal is withheld from the release. Every question for these held-out users is evaluated: 139 to 143 per user and 4,237 in total, all in the test split. The PersonalizationV4 dataset is linked on our project website. The hard subset ( n=629 ) is defined from the untrained Qwen3-4B-Instruct-2507 decoder’s multiple-choice answers and contains questions it answers incorrectly without documents, with the top-1 retrieved document, or in both settings; 299 of the 629 questions are answered incorrectly in both settings. 20 Preprint Table 8: One held-out PersonalizationV4 user through the pipeline. ## F COMPUTATIONAL ANALYSIS OF MEMORILLA 

Consider a collection of N documents serving Q queries. M EMORILLA pays the encoder once on the write path, producing N embeddings that persist and are reused by every later query. Dense retrieval builds the same index, so this cost is shared rather than added. The two methods differ on the read path. RAG places the selected text in the decoder, so its prefill grows with retrieval depth, while M EMORILLA runs one cross-attention read over the stored embeddings and always hands the decoder K=16 tokens. Table 14 reports measurements on one H100-80GB at batch size 1 with a Qwen3-8B decoder. Growing the collection by 512 × decreases the memory-module forward time by 0.06 ms and M EMORILLA end-to-end latency by 1.9 ms, while full-context decoding grows by 19,184 ms and exceeds the enforced 32,768-token limit, requiring YaRN. Transfer stays under 0.04% of query latency because a 200 document collection is 1 MB, and the store is 7,266 × smaller than the corresponding KV cache on PV4 (50,455 document tokens at 144 KiB per token for Qwen3-8B in bf16, 6.9 GiB, against 200 embeddings of 2,560 bf16 values). Absolute latency is dominated by decoding rather than by memory, so the benefit is not a faster single query but a serving cost that stays flat as collections grow and amortizes across the Q queries that read them.

## G CONTINUAL LEARNING WITH MEMORILLA : A DDITIONAL DETAILS 

TextWorld games require an agent to maintain state across a partially observable trajectory, navigate a map, manipulate objects, and execute ordered action sequences. Observations are room descriptions and action outcomes, actions are short text commands, and games span up to 65 rooms. From the second turn on, M EMORILLA embeds each completed turn as one document, holding its observation truncated to 200 characters and its action (74 tokens on average), reads these documents with the current observation as the query, and places the resulting K=8 memory vectors before the prompt. The 20 extreme, huge, long and mega test games instead embed one document per five completed turns with full observations, keep the last four documents, and use the mean document embedding as the query. Figure 13 shows a prompt and the documents compressed into the memory vectors, and Section 6.1 reports how the trajectory grows across a rollout. We train on 800 prompts and evaluate on held-out validation and test splits of 40 games each (30 distinct, since the five medium and five hard games appear twice). Games come in six tiers (medium, hard, long, mega, huge, extreme) with 15–65 rooms and 6–74-step quests; the 800 training prompts are 202 medium, 558 hard and 10 from each longer tier. Rollouts sample up to 50 environment turns with at most 128 new tokens per turn, and evaluation samples three completions per held-out game at temperature 0.6 using the same SkyRL (Cao et al., 2025) generation harness for every condition. The random-memory baseline uses the M EMORILLA architecture with untrained weights, so it adds eight latents to the same prompt without having learned what to place in them. For agentic settings, we train the memory module from environment rewards while keeping the encoder and decoder frozen (Figure 7). At each TextWorld turn, the interaction trajectory is embedded as a document collection, fmem maps it to memory vectors, and the frozen decoder samples the next action. We optimize only θmem with Group Relative Policy Optimization (GRPO) (Shao et al., 2024), a critic-free variant of PPO (Schulman et al., 2017).
