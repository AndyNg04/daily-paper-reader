## 摘要
人们通常通过“有趣”之类的软属性表达偏好，但这类属性难以在计算偏好建模中操作化。潜在表示可能掩盖人们对这类属性的理解方式，从而限制透明度和用户控制。我们将软性形式化为某一描述所允许的有效解释的多样性，并提供实证支持以佐证这一表征。我们提出一种软性度量，用于指导澄清过程，并判断何时生成计算近似。我们将这一方法应用于 AttriFy：一个混合主动式系统，可将描述转换为针对文本语料的可执行 Python 函数。交互式仪表板将对话与候选函数及计算结果关联起来，使用户能够检查、接受、拒绝并完善各种解释。我们开展了一项探索性被试内研究，邀请 32 名参与者，将由软性引导的澄清方法与大语言模型基线进行比较，以评估它们对可解释属性构建的支持效果。本研究将软性确立为一种基础，用于构建明确且可由用户引导的属性维度，以支持后续的偏好 elicitation 与决策。

## Abstract
People commonly express preferences through soft attributes such as is interesting,'' which are difficult to operationalize for computational preference modeling. Latent representations can obscure how such attributes are interpreted, limiting transparency and user control. We formalize softness as the diversity of valid interpretations a description permits and provide empirical support for this characterization. Our proposed measure estimates softness to guide clarification and determine when to generate computational approximations. This is instantiated in AttriFy, a mixed-initiative system that translates descriptions into executable Python functions over text corpora. An interactive dashboard connects the dialogue to proposed functions and computed values, enabling users to inspect, accept, reject, and refine interpretations. An exploratory within-subjects study with 32 participants compares our softness-guided clarification approach with an LLM baseline in supporting interpretable attribute construction. This work positions softness as a basis for constructing explicit, user-steerable attribute dimensions for downstream preference elicitation and decision-making.

## 1. 核心问题与研究背景

### 1.1 论文要解决什么问题？
用户经常用“有趣”“原创”“有说服力”等描述表达自己关注的性质，但这些**软属性（soft attributes）没有唯一、预先确定的计算定义**。

例如，评价作文的“原创性”可能指：
- 思想新颖；
- 写作风格独特；
- 篇章结构不同寻常；
- 包含较多不同观点。

直接将这些描述映射到潜在向量，容易隐藏系统采用了哪一种解释；直接映射到固定属性，又可能无法体现用户真正关注的维度。

### 1.2 论文的基本立场
论文将这一问题视为**用户与系统共同构建操作性定义的交互式规格说明问题**，而不只是寻找用户头脑中已经存在的固定含义：
- 用户可能无法一开始就说明自己的标准；
- 用户可能在看到候选定义和计算结果后，才发现重要区别；
- 用户的意图也可能在交流中发生变化。

因此，关键不仅是“如何计算”，还包括：
> **何时应该继续澄清，何时可以提出计算近似，以及用户如何检查和修正这种近似。**

### 1.3 研究范围
- 主要面向文本语料上的属性构建，实验场景为学生作文。
- **属性构建不等于偏好学习**：论文构建的是“衡量哪些性质、如何衡量”，不直接学习这些属性的权重、偏好方向或最终排序规则。
- 生成的函数是用户可审查的操作化方案，而非软属性的唯一正确解释。

## 2. 方法论：软性估计与 AttriFy 系统

### 2.1 核心思想：用解释多样性刻画“软性”
作者将软性定义为：

> **一个描述在没有进一步说明时，允许多少种不同的合理解释。**

软性高，意味着系统若直接生成函数，就需要自行补充更多假设；软性低，则更适合提出具体计算方案。

这里的软性并不是事实回答的不确定性，也不是函数正确性的概率，而是**描述的解释开放程度**。

### 2.2 软性估计算法

算法主要包含五步：

1. **整合当前描述**
   - 将多轮用户表达重述为一到两句话的当前属性规格。
   - 保留用户约束，优先采用较新的修订，删除撤回的要求，不主动添加测量标准。

2. **生成十种操作性解释**
   - 使用较高温度采样，生成十种合理的衡量方式。
   - 每种解释包括属性名称和具体描述。
   - 对明确描述，允许十个候选高度相似，而不是强行制造差异。

3. **编码解释**
   - 使用 `sentence-transformers/all-MiniLM-L6-v2` 获取句向量。
   - **实际嵌入的是属性名称，而不是完整操作描述或 Python 代码。**

4. **计算 Vendi 多样性分数**
   - 根据解释向量的余弦相似度矩阵计算特征值。
   - 对归一化矩阵的特征值计算熵，再取指数，得到“有效不同解释数量”。
   - 理想情况下，解释完全相同时约为 1，十种解释相互正交时为 10。

5. **映射为 0–100 分**
   - 将 Vendi 分数按“减 1、除以 9、乘以 100”的方式线性缩放，再截断和取整。
   - 每轮重新生成解释，因此分数可以下降、保持或上升，不预设对话一定会降低软性。

### 2.3 用软性控制交互策略

| 软性分数 | 是否生成函数 | 后续动作 |
|---|---|---|
| ≥65 | 不生成 | 继续澄清 |
| 30–65 之间，不含边界 | 生成候选函数 | 用户审查后继续澄清 |
| ≤30 | 生成候选函数 | 邀请用户补充建议或转向新主题 |

阈值依据形成性研究中的人类评分进行校准，但属于**交互策略选择**，不能证明候选函数正确。

### 2.4 AttriFy 的工作流与智能体
系统采用“**扩展—约束—引导**”循环：
- **扩展**：开放问题帮助用户发现尚未考虑的属性。
- **约束**：澄清问题区分竞争性解释，补充范围、条件或标准。
- **引导**：允许用户主动纠正、补充或改变方向。

三个主要智能体分别负责：
- **软性智能体**：估计分数并选择下一步动作；
- **问题智能体**：生成开放问题、澄清问题或建议邀请；
- **函数智能体**：借助 CodeAct 将当前讨论转为数值型 Python 属性函数。

候选代码经过 AST 验证、资源受限沙箱中的样本执行和失败重试。但这些检查主要确认代码可运行，**不保证语义上符合用户意图**。

### 2.5 可视化与用户控制
界面包括：
- **聊天面板**：查看、接受、拒绝或要求细化候选函数；
- **交互历史**：关联对话、软性变化和函数来源；
- **属性表**：查看每篇文本的计算值及分布；
- **覆盖图**：用 PCA 和 DBSCAN 展示当前属性下相似的文本群体。

系统还利用最大聚类中的文本样本生成开放问题，尝试发现能够进一步区分文本的新属性。

## 3. 实验设计、数据与对比方法

### 3.1 实验一：软性概念的形成性研究
- **参与者**：招募 70 人，最终保留 62 人。
- **材料**：
  - 50 条作文属性描述；
  - 20 段五轮澄清对话；
  - 对话分为收敛、低位稳定、平台、重新开放、反转五类。

研究包含三项任务：
1. **解释任务**：每人解释十条属性描述，共 620 条回答；排除无关回答后保留 592 条。
2. **判断任务**：共 620 次单项评分、496 次三项排序。
3. **对话任务**：逐轮评价软性，共 1,550 次评分。

两名编码者独立对解释分组，并用稀释抽样统一到九条回答的样本规模，估计每条描述的解释数量。

### 3.2 实验二：软性算法与人类判断的一致性
- 对 50 条描述分别运行算法三次，取均值。
- 在 20 段对话、100 个对话轮次上比较算法分数与人类评分。
- 主要考察相关性和重复运行可靠性。

这部分的参照是**论文自行建立的人类判断数据**，并非现成的公共软性 benchmark。

### 3.3 实验三：AttriFy 与 LLM 基线的用户研究
- **参与者**：招募 41 人，最终纳入 32 人。
- **设计**：被试内比较，每人使用两种工具，每种工具操作 15 分钟。
- **场景**：叙事作文与议论文。
- **数据来源**：ASAP 2.0，完整语料包含 24,278 篇学生作文。论文并未据此说明每个实验区块都使用全部作文。
- 工具顺序与数据集分配在四个分配单元间平衡。

**基线设置：**
- 使用开放式 LLM 对话；
- 与 AttriFy 共用函数生成服务、属性表和覆盖图；
- 同样支持接受、拒绝和细化候选属性；
- 不使用软性门控，每轮用户输入后都生成属性提案；
- 不提供 AttriFy 的结构化交互历史。

**评价指标：**
- 意图表达与澄清、透明度、控制感、所有权等自报告评分；
- NASA-TLX 工作负荷；
- 函数生成、接受、拒绝、修订等行为记录；
- 自由文本反馈；
- 属性冗余度，以及生成函数在 200 篇作文上的执行表现。

统计比较使用 Wilcoxon 符号秩检验，并进行 Holm–Bonferroni 多重比较校正。

## 6. 主要结论与发现

### 6.1 软性与解释多样性存在较强联系
- 人类平均软性评分与解释数量的 Spearman 相关为 **0.73**。
- 平均评分与成对比较结果的相关为 **0.91**。
- 但个体评分一致性有限：Krippendorff’s α 为 **0.34**。
- 两名编码者对具体解释分组的一致性较低：平均 ARI 约 **0.24**，尽管解释数量估计更可靠。

因此，研究较好地支持了**聚合层面的相对软性排序**，但对解释空间的精确边界支持较弱。

### 6.2 算法能近似人类软性判断
- 与 50 条描述的人类评分相关为 **0.742**。
- 与 100 个对话轮次的人类评分相关为 **0.642**。
- 去除各对话自身均值后，相关仍为 **0.547**。
- 三次运行均值的可靠性 ICC 为 **0.959**。

这些结果支持估计器在当前场景中的可用性，但不能直接外推到其他领域。

### 6.3 AttriFy 改变了生成过程，但未显示显著体验优势

| 指标 | AttriFy | 基线 |
|---|---:|---:|
| 平均函数生成事件 | 5.2 | 8.7 |
| 平均生成属性数 | 8.8 | 11.2 |
| 平均接受属性数 | 7.8 | 10.2 |
| 接受率 | 88% | 91% |

- 生成事件、生成属性数和接受属性数均显著减少。
- 属性冗余描述性指标更低：近重复属性平均约 **0.8 个，对比 2.1 个**。
- 但意图澄清、控制感、所有权等问卷比较，校正后**均未发现显著差异**。
- NASA-TLX 工作负荷也没有显著差异。
- 工具偏好存在明显顺序影响，不能据此认定用户更偏好某个系统。

### 6.4 澄清不一定降低软性
在 AttriFy 同一主题内的 184 对连续回答中：
- 46.2% 的软性上升；
- 48.4% 下降；
- 5.4% 不变。

这意味着：**增加细节可能暴露更多关系、例外和组合方式，使操作化反而更复杂。**

### 6.5 用户接受不代表函数测量有效
重新执行生成函数发现：
- 63% 使用硬编码词表；
- 26% 使用表面统计；
- 38% 在超过一半的作文上输出零值。

零值较多不必然代表函数无效，但说明高接受率不足以证明属性有区分力或忠实反映用户意图。

## 7. 优点与亮点

- **问题定位准确**：关注偏好学习之前“属性本身如何定义”的基础环节。
- **概念具有操作性**：将软性与解释多样性联系，并结合人类研究与计算估计提供证据。
- **区分明确**：不把可执行性、用户接受和语义正确性混为一谈。
- **交互设计完整**：连接自然语言、候选函数、执行结果和历史来源，支持用户追踪与修正。
- **考虑数据覆盖**：根据当前属性下难以区分的文本群体引导探索，而不仅反复澄清单一概念。
- **结果报告较克制**：明确呈现无显著优势、澄清可能失败以及浅层实现等负面发现，没有把减少生成数量包装为质量提升。

## 8. 不足与局限

### 8.1 测量有效性仍不充分
- 核心指标反映的是 **LLM 生成解释与句向量模型识别差异的能力**，未必等于用户真正关心的解释差异。
- 只嵌入简短名称，可能遗漏完整操作描述中的阈值、范围和组合规则。
- 固定十个候选限制了对开放解释空间的覆盖。
- 未通过其他测量方法比较或独立外部数据充分验证阈值的稳健性。

### 8.2 函数实现存在“浅层代理”风险
- “原创性”“真诚”“论证质量”等复杂性质容易被词表、计数等简化替代。
- 可运行且容易解释，不意味着测量了目标构念。
- 系统可能把用户引向容易计算的属性，而非用户真正重视的性质；部分参与者反馈了这种限制感。

### 8.3 接受行为的解释需要谨慎
- 用户可能因为检查成本高或信任 AI 而接受不合适的实现。
- 更重要的是，研究教程将“接受”解释为**与自身偏好相关**，而非验证测量正确，因此接受率本就不能直接作为功能对齐指标。
- 缺少独立标注或具体文本判断任务，无法确认用户是否真正理解实现后果。

### 8.4 外部有效性有限
- 两项研究都集中在英语作文属性。
- 用户研究参与者几乎都是经常使用 LLM 的人，不能代表普通用户。
- 刺激材料由 LLM 辅助生成，可能偏向模型容易表达和识别的软性模式。
- 尚未证明系统适用于专业文本、高风险评价、多语言环境或长期真实工作流。

### 8.5 下游价值尚未验证
- 没有证明最终属性能改善推荐、排序或决策。
- 较少、较不冗余的属性，不一定覆盖了更多用户需求。
- 论文的“近似差距”可视化主要表示生成时仍存在的解释开放程度，并不是经过验证的实际测量误差。

**总体评价：**这项工作的主要价值在于提出“软性—澄清—操作化”的研究框架，并实现了可检查、可修正的属性构建系统。现有证据支持软性作为交互信号的合理性，也说明它能改变生成过程；但尚不足以证明其优于开放式 LLM 对话，更不能证明最终函数更忠实地测量了用户意图。
