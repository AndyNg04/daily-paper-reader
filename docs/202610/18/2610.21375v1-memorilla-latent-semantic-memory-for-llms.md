## 摘要
记忆使大语言模型（LLM）能够利用其参数之外的信息，例如过往的用户对话、长篇文档或智能体先前采取的行动。对于冻结的 LLM，它只能通过记忆系统放入上下文窗口的信息来获取这些累积的知识。然而，现有系统仍难以在保持模型上下文简短的同时，为每个查询收集并整合所需的相关信息。本文提出 Memorilla，这是一种记忆系统，可从整个文档集合中收集信息，并将其编码为数量固定、依赖于查询的“记忆 token”，供冻结的 LLM 使用。Memorilla 先将文档（如用户聊天记录、书籍章节）编码为可重复使用的嵌入表示，再学习检索查询相关信息，并将其置于 LLM 的输入嵌入空间中。仅使用 16 个记忆 token，Memorilla 在涵盖个性化、长文档问答和知识密集型问答的 8 项基准测试中的 5 项上，取得了优于包括 Mem0 和 MemoRAG 在内的基线方法的最佳性能。值得注意的是，在 FactKG 上，Memorilla 的准确率达到 84.33%，而全上下文推理为 80.43%；同时，它表示源文档所需的 token 数量减少了 108 倍。此外，Memorilla 还能支持智能体系统中的持续学习，在这类系统中，文档数量（即智能体的历史交互轮次）会随着执行过程不断增加。在 TextWorld 环境中，我们发现 Memorilla 能减少智能体在已探索房间之间徘徊的倾向，并将其平均成功率从全历史上下文学习时的 18.6% 提升至 24.2%。总体而言，Memorilla 有助于冻结的 LLM 在长上下文交互中有效积累和运用知识，并朝着构建具备持续学习能力的 AI 系统迈出了一步。

## Abstract
Memory enables large language models (LLMs) to use information beyond their parameters, such as past user conversations, long documents, or an agent's earlier actions. For a frozen LLM, access to this accumulated knowledge is limited to what a memory system places in its context window. However, gathering and combining relevant information needed for each query while keeping the model's context short remains challenging for existing systems. Here we introduce Memorilla, a memory system that gathers information from an entire document collection into a fixed number of query-dependent 'memory tokens' for a frozen LLM. Memorilla encodes documents (such as user chats, book chapters) once into reusable embeddings, then learns to retrieve and place query-specific information in the LLM's input embedding space. Using only 16 memory tokens, Memorilla achieves the best performance against baselines including Mem0 and MemoRAG on five of eight benchmarks spanning personalization, long-document and knowledge-intensive question answering. Notably, on FactKG, it reaches 84.33% accuracy versus 80.43% with full-context inference, while using 108x fewer tokens to represent the source documents. Furthermore, Memorilla can facilitate continual learning in agentic systems where the document count (the agent's past turns) increases throughout the trajectory. In a TextWorld environment, we show that Memorilla reduces the agent's tendency to wander between rooms it has already explored, and improves its average success rate from 18.6% with full-history in-context learning to 24.2%. Overall, Memorilla aids frozen LLMs in accumulating and using knowledge effectively across long-context interactions and takes a step towards building continually learning AI systems.

## 1. 核心问题与研究背景

### 1.1 论文要解决什么问题？

冻结的大语言模型无法直接利用参数之外的新知识，例如用户过去的聊天记录、长篇文档，以及智能体此前的行动与观察。这些信息必须通过上下文提供给模型，但现有方案存在两类主要矛盾：

- **信息完整性与上下文成本的矛盾**：把所有历史都放入提示词，计算和存储成本会不断增长，也可能因无关信息干扰而降低回答质量。
- **局部检索与跨文档整合的矛盾**：RAG 只提供若干相关片段，容易漏掉分散在不同文档中的偏好、关系或推理链。

已有潜在压缩方法虽然能把文档压缩为少量向量，但不少方法在压缩时不知道当前问题，因此同一组压缩表示必须服务于所有查询；另一些方法则需要修改模型参数或使用模型专属缓存，限制了复用能力。

### 1.2 整体思想与意义

Memorilla 的核心是将**长期存储**与**当前查询所需的上下文**分离：

- 长期保存的是每篇文档的嵌入向量；
- 每次查询时，从整个嵌入集合中提取相关信息；
- 将这些信息转化为固定数量的连续“软记忆 token”，交给冻结的 LLM。

它探索的并不是如何让模型读取更多文本，而是：**能否学习一个更有效的记忆接口，使模型只读取少量、针对当前问题组织的信息？**

## 2. 方法论：核心思想、技术细节与算法流程

### 2.1 总体架构

系统包括三个组成部分：

| 组件 | 作用 | 是否训练 |
|---|---|---|
| 文档／查询编码器 | 将文档和问题编码为向量 | 冻结 |
| 记忆模块 | 按查询从文档向量中提取信息，并生成软记忆 token | 训练 |
| LLM 解码器 | 根据记忆 token 和问题生成答案或行动 | 冻结 |

主要配置为：

- 编码器：**Qwen3-Embedding-4B**；
- 解码器：**Qwen3-8B**；
- 记忆预算：**16 个 token**；
- 可训练参数：约 **1.94 亿**。

这里的记忆 token 是输入嵌入空间中的连续向量，并非可直接阅读的自然语言摘要。

### 2.2 算法流程

#### 第一步：文档编码与持久化存储

- 将用户对话、书籍段落、知识图谱三元组等划分为文档块。
- 使用冻结编码器，将每个文档块映射为一个 2,560 维向量。
- 保存整个文档向量矩阵，后续查询重复使用。
- 新增或修改文档时，只需重新编码相关部分，不必更新 LLM。

因此，其写入成本与构建常规稠密检索索引相似。

#### 第二步：初始化并调节记忆槽位

- 设置 \(K\) 个可学习的记忆槽位，默认 \(K=16\)。
- 将当前问题编码为一个查询向量。
- 槽位通过交叉注意力接收查询信息，再结合残差连接和层归一化，形成查询条件化的槽位。

由于查询只有一个向量，这一步对不同槽位提供共享的查询更新；不同槽位的身份主要由各自的可学习初始值保留。

#### 第三步：读取整个文档集合

- 查询条件化的槽位通过 **两层交叉注意力模块**读取所有文档向量。
- 每层包含交叉注意力、残差连接、层归一化和前馈网络。
- 默认使用 **8 个注意力头**。

与 RAG 的离散 top-k 文档选择不同，该模块执行的是对整个文档集合的**连续、查询相关的信息汇聚**。不过，读取全部嵌入并不意味着能够无损保留全部原始文本。

#### 第四步：映射到 LLM 输入空间

- 将槽位向量投影到解码器的输入嵌入维度；8B 解码器对应 4,096 维。
- 把生成的 16 个记忆向量放在问题文本嵌入之前。
- LLM 通过原有自注意力机制读取这些向量，无需修改其网络结构。

**固定的是进入解码器的记忆长度，而不是外部存储量或读取成本。**随着文档数量增加，嵌入存储和标准交叉注意力读取仍需要处理更多数据。

### 2.3 监督训练

训练损失为目标答案的负对数似然，仅计算答案位置的损失。虽然编码器和解码器参数冻结，训练时仍需通过解码器计算梯度，以更新前端记忆模块。

训练分为三个阶段：

1. **通用信息保持预训练**  
   使用约 **198 万条 Wikipedia 改写重建样本**，训练记忆模块保留足够信息以生成原文改写。
2. **多任务预训练**  
   使用约 **134 万条样本、10 个数据集**，覆盖阅读理解、开放域问答和摘要。
3. **下游多任务微调**  
   混合八项评测任务的训练集进行训练；其中 PMv2 和 PV4 再分别额外微调 5 个 epoch。

### 2.4 智能体强化学习版本

在 TextWorld 中：

- 每轮结束后，将观察和行动加入记忆；
- 使用 **8 个软记忆 token**辅助下一步行动；
- 编码器与 4B 解码器冻结，仅训练记忆模块；
- 从随机初始化开始，使用 **GRPO** 和环境奖励训练；
- 每组采样 **16 条 rollout**，采用组内标准化优势和 PPO 式裁剪目标。

这一版本还增加了文档间自注意力层。尤其需要注意：**记忆 token 是对完整文本历史的补充，而不是替代**，因此不能把该实验的收益解释为历史压缩收益。

## 3. 实验设计：数据集、场景与对比方法

### 3.1 八项监督学习 benchmark

| 场景 | 数据集 | 主要任务 | 主要指标 |

重要评测设置：

- PMv2 测试集为 **5,000 个问题**；
- PV4 为作者构建的合成数据集，测试集含 **30 个用户、4,237 个问题**；

- 个性化任务的训练用户和评测用户严格分离。

PMv2 和 PV4 并非直接进行多选生成，而是先让模型自由回答，再用编码器判断其回答最接近哪个候选答案，以此计算准确率。

### 3.2 对比方法

主要对比：

- **Closed-book**：不提供外部文档；
- **RAG-1、RAG-5、RAG-50**：按余弦相似度检索；
- **Full Context**：提供全部文档，超长时扩展窗口或截断；
- **LLMLingua-2**：文本 token 删除式压缩；
- **xRAG**：将一个检索文档的嵌入映射为一个软 token；
- **Mem0**：提取并维护结构化文本记忆；
- **MemoRAG**：利用全局记忆生成检索线索；
- **ComMer**：引用其个性化生成任务的已报告结果。

主要自行运行的基线共用冻结的 Qwen 编码器和 8B 解码器；Mem0、MemoRAG 额外使用 4B 模型构建记忆。

### 3.3 智能体场景

TextWorld 要求智能体：

- 探索最多 65 个房间；
- 找到并使用物品；
- 完成有先后顺序的行动；
- 每次轨迹最多执行 50 轮。

对比完整历史 ICL、随机未训练记忆和强化学习后的记忆模块。测试包含 **40 个游戏条目，实际对应 30 个不同游戏**，每项采样 3 次。

- **其他消融**：编码器规模、LoRA 参数适配对照；
- **分析实验**：问题类型、实体数量、事实组合深度、RAG 互补性；
- **智能体实验**：3 种条件，40 个测试条目，每项 3 次采样，名义上约 **360 条测试 rollout**。

整体实验覆盖面较广，但论文没有汇总独立训练次数，无法准确给出总实验组数。

### 5.2 充分性与公平性评价

**较充分之处：**

- 同时覆盖个性化、长文档、事实验证和交互式决策；
- 包含准确率、生成质量、上下文长度与延迟，而非仅报告单一指标；
- 有参数量匹配的架构消融，能一定程度排除“只是模型更大”的解释；
- 提供随机记忆、文档噪声和无文档 LoRA 对照；
- 明确报告性能落后的任务，没有将结果描述为全面领先。

**需要谨慎之处：**

- Memorilla 获得大规模预训练和下游监督，xRAG 则按任务从头训练，文本检索基线也没有接受同等适配。比较反映的是完整系统效果，**不能完全隔离架构本身的贡献**。
- ComMer 使用不同模型，其引用结果不构成严格控制变量比较。
- LoRA 对照使用 4B 解码器，主 Memorilla 使用 8B 解码器，无法完全排除基础模型能力差异。
- 主要监督结果采用单一随机种子，缺少系统性的多种子方差、置信区间和显著性检验。
- TriviaQA、PubMedQA 和 TextWorld 的测试规模有限，较小差距的稳定性需要进一步验证。

## 6. 主要结果与发现

### 6.1 主要 benchmark 结果

| 数据集 | Memorilla | 重要对照 | 结果解读 |
|---|---:|---:|---|
| PMv2 准确率 | **44.60%** | 最强基线 xRAG：30.90% | 个性化推断提升明显 |
| PV4 准确率 | 66.65% | MemoRAG：**67.88%** | 略低于最强文本方案 |
| FactKG 准确率 | **84.33%** | 全上下文：80.43% | 提高 3.90 个百分点 |
| TriviaQA EM | **57.00** | MemoRAG：56.60 | 数值领先，但差距很小 |
| NarrativeQA ROUGE-L | 19.31 | MemoRAG：**20.51** | 不是所有指标领先 |
| LaMP-4 ROUGE-L | **18.15** | 全上下文：14.21 | 风格建模有效 |
| LaMP-7 ROUGE-L | **48.37** | xRAG：46.84 | 个性化生成有效 |
| PubMedQA 准确率 | 59.00% | LLMLingua-2：**69.00%** | 短证据压缩有明显损失 |

作者报告，Memorilla 在八项 benchmark 的主要指标中 **五项领先**，跨任务平均分最高。

### 6.2 效率收益

- 固定使用 **16 个文档来源记忆 token**；
- 相比全上下文，文档 token 数的几何平均压缩比约 **394 倍**；
- FactKG 约 **108 倍**，NarrativeQA 约 **4,212 倍**；
- 512 篇、每篇约 250 token 的文档下，端到端延迟约 **0.74 秒**，全上下文约 **19.9 秒**，约快 **27 倍**。

这些压缩比指的是**输入解码器的文档表示长度**，不包括外部嵌入存储和编码成本；延迟收益也依赖具体推理实现。

### 6.3 学到了什么？

- **更擅长概念性整合**：NarrativeQA 的 “why”“how” 问题更有优势；RAG 在 “who”“which”等精确实体回忆问题上更强。
- **多实体关系任务表现较好**：FactKG 中，相对 RAG-50 的优势随实体数量增加而扩大。
- **查询条件化很关键**：PMv2 架构消融中，参数匹配的分段池化为 31.10%，Memorilla 为 44.04%；Q-Former 接近，为 43.34%。
- **更多槽位不必然更好**：训练时从 16 增至 128 个槽位没有稳定收益。
- **潜在记忆与 RAG 互补**：两者答对的问题并不完全相同，但文中的联合结果是 oracle 上界，并非已实现的混合系统。

### 6.4 智能体结果

TextWorld 中：

- 平均成功率 avg@3：**18.6% → 24.2%**；
- 三次中至少成功一次的 pass@3：**25.0% → 37.5%**；
- 耗尽上下文预算的轨迹比例：**71% → 58%**；
- 随机未训练记忆反而降低表现，说明收益依赖学习。

更准确的解读是：训练后的记忆能帮助冻结智能体整理已有历史、减少重复探索；它尚不能证明广义的开放世界持续学习能力。

---

## 7. 优点与亮点

- **清晰分离存储与读取**：新文档只需编码，解码器上下文不会随历史长度同比增加。
- **查询相关的全集合汇聚**：比固定摘要更灵活，也避免直接受限于 top-k 文档选择。
- **冻结骨干、接口简洁**：不修改 LLM 层或注意力机制，降低了侵入式改造成本。
- **兼顾静态问答与智能体决策**：同一记忆思路可通过答案监督或环境奖励优化。
- **消融较有针对性**：对参数规模、查询条件化、真实证据依赖和记忆容量进行了检验。
- **呈现了适用边界**：明确显示短文本医学问答和精确实体回忆可能更适合文本方案。

## 8. 不足与局限

### 8.1 信息保真度与可解释性

- 每个文档先压缩为一个向量，再汇聚到少量槽位，精确名称、数字和细节可能丢失。
- 软记忆无法像检索片段一样直接阅读和核查，证据归因、错误追踪及引用生成较困难。
- 文中关于“编码关系结构”的解释得到行为结果支持，但仍主要是间接证据，不能视为已揭示内部机制。

### 8.2 泛化与模型可移植性尚未充分验证

- 主要结果均来自同一 Qwen 模型家族；
- 虽然外部嵌入存储与解码器相对解耦，**训练后的投影和记忆模块仍与目标解码器有关**，不能直接认为可无成本迁移；
- 下游任务都经过监督微调，未充分证明对全新领域或任务的零样本泛化；
- 缺少代码、表格、精确数值推理和多模态实证。

### 8.3 数据与评分偏差风险

- PV4 完全由 LLM 生成，只有 149 个用户，其中测试用户为 30 个，可能带有模板化和生成器偏差。
- 以人设推断“合理偏好”不完全等同于现实用户的真实选择。
- PMv2、PV4 使用同一编码器体系进行输入表示和答案近邻评分，可能使结果偏向特定语义表示；需要人工评价或独立评分模型交叉验证。
- 不同任务指标的简单平均只能作为概览，不代表统一、严格可比的能力尺度。

### 8.4 可扩展性与成本边界

- 固定 16 个 token 不等于总成本恒定：存储量随文档数增长，标准交叉注意力也需读取更多嵌入。
- 主延迟测试最多 512 篇文档，尚未验证百万级记忆、高并发或频繁更新场景。
- 未报告训练总成本，难以判断低频使用场景是否划算。
- 全上下文基线使用非分页 KV cache 的推理实现，27 倍收益不应直接推广到所有优化服务栈。

### 8.5 持续学习与隐私结论仍有限

- TextWorld 规模较小，部分测试游戏重复，且不同难度采用不同历史编码策略；
- 没有系统测试长期任务序列、遗忘或旧能力保持，冻结 LLM 只能避免其参数被改写，不能保证系统行为完全不退化；
- 嵌入不是匿名数据，仍可能包含敏感信息；可删除外部记忆有助于治理，但不能自动解决隐私问题。

**总体评价：**Memorilla 有说服力地展示了“持久化文档嵌入＋查询条件化软记忆”在短上下文知识使用中的潜力，尤其适合分散偏好和跨文档语义整合。它更适合作为文本检索的补充与可训练记忆接口，而非无损、通用、恒定成本的长期记忆替代方案。
