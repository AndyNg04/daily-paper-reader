Abstract
Reusable skills improve multimodal agents without updating model weights, but their effectiveness
depends on both the evidence presented and the procedure used to read it. We introduce ViewCraft,
which jointly evolves an executable evidence interface and its reading procedure. The interface
selects, transforms, and organizes observations; the reader interprets the resulting views. Failure
traces guide revisions, replay and paired evaluation retain useful changes, and interface projection
recovers visual edits from eligible rejected joint proposals. Across eight benchmarks, ViewCraft
improves over direct execution by an average of 6.1 points in task score, with gains on every
benchmark. The advantage persists at a matched input-token budget. On all five multi-source
tasks, the learned interface uses 8–15% fewer input tokens than Initial skill. The learned skills also
transfer across executors and outperform direct execution in every evaluated transfer, supporting
evidence construction and reading as a coupled, reusable skill. Code is available on GitHub.

Introduction
Multimodal reasoning needs relevant, legible evidence and a procedure matched to its organization.
A missed video segment or cropped-away field obstructs downstream reasoning; a reader written for
the original input may also overlook timestamps or spatial relations introduced by a new view. We
ask whether the interface exposes the needed evidence and whether its reader uses that organization.
An end-state counting question illustrates both requirements. Early and late frames establish which
objects moved; timestamped rows expose that comparison. The reader must match objects across
rows before counting those that remained stationary. Figure 1 shows temporal and counting repairs.
Skill evolution improves frozen executors through reusable procedures and workflows [3–10]. Mul-
timodal systems add visual experience, prompts, and tools [1, 2, 11–15]. We make the evidence
interface a saved, executable mapping that selects, transforms, and composes observations for each
question, enabling readers to replay the mapping’s revisions and evaluate their effects.
Evidence-interface probes.
Neither a single selector nor more frames consistently wins: selector
rankings reverse with frame budget, and Motion-score declines after its peak (Figure 2). The probes
use 96 VideoHolmes questions from 26 non-test films and 240 field crops from FunSD training forms;
none of these probe samples overlaps with the main test sets.
A stronger reading reminder lowers mean accuracy on unchanged inputs. Reducing the resolution of
oracle field crops also lowers field-value ANLS despite preserving the requested content. Selection
and legibility therefore offer concrete targets for an editable evidence interface (Appendix A).
We introduce VIEWCRAFT, which jointly evolves the evidence presented to a frozen executor and the
procedure used to read it. The resulting skill preserves how observations are selected and organized,
together with the procedure for interpreting their relationships.
Our contributions are threefold:
• We formulate multimodal skill evolution as jointly refining what agents see and how they read
it. The reusable skill pairs an executable evidence interface with its reader, incorporating
instance-conditioned evidence selection, transformation, and presentation.
• We introduce VIEWCRAFT, which uses failure traces, visual replay, and paired development
evaluation to evolve the interface and reader while freezing the executor. Interface projection
retests visual edits from eligible rejected joint proposals with the incumbent reader to retain
useful interface changes together with the existing reading procedure.
• Across eight benchmarks, ViewCraft improves over Direct by 6.1 points on average and
remains 5.2 points ahead at a matched input-token budget. It also outperforms restricted and
same-space search baselines, and the learned skills transfer across executors.

Related Work
2.1
Feedback-driven agent optimization
Automatic prompt optimizers generate, select, or evolve instructions from task feedback [3, 5, 15–
17], while DSPy and GEPA optimize compound LM programs from execution trajectories [4, 18].
Language agents also retain verbal feedback, distilled experience, or executable skills [19–22], and
systems such as ADAS, AFlow, and AgentSquare search broader workflows or module configurations
[8, 9, 23]. Most of this state is textual or structural. ViewCraft makes the evidence interface itself
part of the persistent state and evolves it together with its reader.
2.2
Multimodal skill evolution
Multimodal skills incorporate spatial priors and interleaved support [11], state cards and keyframes [12],
and grounded experience for planning and tool use [13]. Visual prompting and adaptive selection
expose relevant regions and moments [24–29]. Skill optimizers refine reusable procedures through
execution feedback [3, 4, 10], while WikiSkill accumulates knowledge across updates [30]. The
Multimodal Prompt Optimizer (MPO) jointly optimizes textual and non-textual prompts [1], and
Dynamo co-evolves reasoning skills and visual tools [2]. Rejecting a joint proposal can also discard a
visual revision that would remain useful with the incumbent reader.
ViewCraft saves an executable evidence interface together with its reader (Table 1). Replay
reconstructs the views, and interface projection retests the visual component of eligible rejected
joint proposals with the incumbent reader. Table 4 compares this design with MPO and Dynamo
adaptations operating in the same search space as ViewCraft.

3.3
Failure-guided proposals
Traces record the question, sent views with geometry and provenance, response, and score. They
guide revisions such as selecting a missed event or cropping an unreadable field. Interface contracts
describe the views, answer format, and available requests; the reader specifies how to use them.
External guards check execution budgets and valid requests (Cexec), and support for question-derived
evidence requirements (Cground). A frozen verifier checks question-derived requirements against the
sent views, without reference answers (Appendix H). Replay filters rendering edits in ϕ or ψ that
leave the views unchanged. Reader-only and answer-text-only edits bypass this pixel check.

After a joint candidate changes visual fields but loses task score (∆R < 0), ViewCraft retests
candidate (ϕ, ψ) with incumbent θ only if evidence support has not fallen (∆C ≥0) and submission
and gate allowances remain. This interface projection consumes another submission and paired
evaluation (Algorithm 1). Acceptance advances w; rejection restores the incumbent.
At test time, the saved skill supplies views, actions, and reading rules without optimization. Strategy
retains rejected proposals after rollback; only accepted expressions affect execution.
4
Experiments
4.1
Setting and comparisons
We evaluate eight visual benchmarks using frozen, source-disjoint splits: MMComposition [31],
ReasonMap [32], FUNSD [33], STI-Bench [34], Video-Holmes [35], SlideVQA [36], OpenEQA [37],
and MMIU [38]. The first three concentrate evidence in a single image or form; the remaining five
require selecting and comparing observations distributed across sources.
Score accounting.
Main comparisons pool three repetitions: each independently evolved terminal
skill is tested once, while Direct and Initial skill are each executed three times. Binary scores use
S/(3n); continuous scores average the same repeated evaluations. FunSD uses field-value ANLS.
Appendix A specifies construction, execution, and scoring.
Direct uses a bare call; Initial skill uses the empty-start interface. Text-only and Interface-only
independently search the two sides under the clean partition. Terminal θ-only and (ϕ, ψ)-only restore
one side of the joint result to its initial state, testing dependence within the learned pair.
Training traces guide proposals; gate items determine acceptance. Test questions remain outside
both stages, and no form, film, or deck crosses the frozen splits.
Each evolving method runs 24 task–seed searches under shared proposal and rollout budgets.

4.3
Search strategies at matched budget
Joint search leads alternating search by +1.3 points (cluster-bootstrap CI [+0.6, +2.1]). All eight
task-level gaps are positive (exact sign-test p = 0.008), as are the three seed means (Appendix B).
The ladder in Table 4 separates access to the executable interface, candidate selection, failure
guidance, and retention. Random same-space proposals improve over prompt-space search; UCB
selection and failure-guided proposals add successive gains. The complete retention pipeline then
reaches the highest score. ViewCraft’s mean task score exceeds that of the strongest same-space
baseline by +2.6 points, with a confidence interval of [+1.3, +3.9].
ViewCraft also leads Dynamo-gen and random proposals in the shared expression space. The ladder
increments and corresponding paired statistics are reported in Appendix B.
The ordering in Table 3 reflects how components adapt to one another. Independent search combines
separately learned partners; staged search fixes an interface before its reader adapts; alternating
search revisits them in turn. A single joint proposal can revise both the relation exposed by the
interface and the reading rule used to interpret that relation.

4.4
Mechanisms and evaluation cost
The reader and view contract form the most frequently accepted pair, with 58 co-edits (Figure 5a).
Defining what panels contain frequently accompanies a change in how to read them. Solo accepts
retain one-sided revisions; terminal crossings test clause-content co-adaptation.
Mechanism effects and their overlap.
Replay filters inert renderings, projection recovers useful
interfaces from rejected joint proposals, and the evidence tiebreak resolves equal task scores. Removing
a single stage costs 0.7–0.9 points; removing all stages costs 1.6 (Appendix Table 24). Every paired
interval excludes zero. The joint loss reveals overlap among stages.
Asymmetric projection has the highest mean score among the retry designs (Appendix Table 15).
Keeping the verified interface while reverting the reader gains +0.6 points over the symmetric
direction. Replay saves 30 joint-arm gate evaluations; all 21 projection retries enter the saved skill.
Removing the evidence tiebreak lowers held-out scores on every benchmark (Appendix Table 24).
The verifier agrees with human consensus on 89% of audited judgments (Appendix H).
Most of the improvement survives with answer and protocol contracts fixed: the contract-frozen
condition remains within 0.5 points of full ViewCraft on average. Format-normalized rescoring also
preserves the advantage on FunSD (Appendix Table 16).
The gate links local edits to retained skill quality by scoring complete responses on paired items.

Transfer and input cost
The learned pairing remains useful after changing the executor.
On held-out questions, every
transferred skill exceeds its target executor’s Direct baseline by at least 1.5 points (Table 5).
Three transfers exceed target-evolved skills: GPT-5.5 improves Gemini on STI-Bench and Sonnet on

5
Conclusion
ViewCraft makes evidence construction a persistent, editable part of a multimodal skill. The central
design choice is to evolve what the executor sees together with how it reads. Frame selection
determines which moments are available, layout exposes relationships across observations, and
resolution controls whether fine details remain legible. A reading procedure turns these views
into comparisons, counts, and decisions. The probes and recorded repairs connect these concrete
operations to the two questions that motivate the work: whether the necessary evidence is visible,
and whether the reader can use its spatial and temporal organization. Joint evolution improves both
parts while keeping the executor frozen. It outperforms single-coordinate search and same-space
adapted baselines, and its advantage over Direct persists at matched input budget. Replay and
paired evaluation make candidate views inspectable and tie retention to task outcomes; interface
projection recovers useful visual edits from rejected joint candidates. The resulting state can be
applied to new questions and transferred across executors. On all five multi-source tasks, learned
selection also sends 8–15% fewer input tokens than Initial skill. These results identify an actionable
unit of reuse: a pair consisting of an executable evidence interface and a reading procedure that uses
the evidence rendered by that interface to answer new questions.

Evaluation protocol
All conditions use frozen splits, the same executor, and paired item identities. Direct uses one bare
call; Initial skill uses the empty-start execution interface. Table 6 lists source units and scoring rules.
Sampling uses the full test set below 500 questions, half at 500–1000, and a quarter above 1000,
preserving whole source media and category coverage. The selection is frozen before runs.
Score accounting.
Every accuracy in the main comparisons is the pooled mean over three repetitions
with denominator 3n: evolving conditions are run as three independent searches (different seeds),
each final skill evaluated once on the held-out set; Direct and Initial skill are executed three times
each (repetition applies uniformly across conditions). For binary metrics this makes every entry
an integer multiple of 1/(3n). FunSD, SlideVQA, and OpenEQA use continuous scores (field-value
ANLS, ANLS, and LLM-Match respectively), so their means are unconstrained. We obtain MMIU’s
pooled score of 685/720 ≈0.951 by aggregating the results of all three runs.

Evidence-interface probes.
The probes use a frozen executor on 96 VideoHolmes questions from 26
non-test films and 240 field crops from FunSD training forms. These samples have zero overlap with
the main test sets. Three selectors use the same questions at four frame budgets; plain and enhanced
prompts are compared over these settings. In the oracle-crop comparison, requested content is held
fixed while the resolution of the images delivered to the executor varies.
Wrong-film probe.
Replacing the frames for 64 previously correct questions with another film yields
12 correct and 52 wrong answers, with no abstentions or mismatch flags (Figure 2c).

FunSD is converted to field-value QA. Question-class entities become field
labels; the reference answer is the vertically-nearest answer-class entity. Table 6 gives the constructed

splits. The split unit is the form: no form appears in two splits, so every field question derived from

Implementation.
Executor: gemini-3.8-flash, greedy decoding, one call per observation step; budgets
per domain: 12–24 steps, 4–9 images per request. Optimizer: the same model, temperature 0.7, up
to 4 attempts per round, the complete executed skill in Appendix I. Verifier for Cground: the same
model in verification mode (binary yes/no per requirement, options withheld), two calls per gate
item. Stopping: fixed 4 rounds. All conditions share these settings. Cross-executor transfers and the
case-study instance use the run with the median gate score among three seeds; both the results in

D
Discrete proposal space
The clean partition assigns all inference and decision rules to θ: polarity handling, verdict-table logic,
when-to-zoom decisions, and mark-reading procedures. The interface contains executable rendering
operations in ϕ (selection, transformation, crop admission, canvas), layout and view metadata in ψ,
and answer/action surface formats. Crop admission controls whether a requested crop is rendered;
deciding whether to request it belongs to the reader. The terminal crossing restores all reasoning
clauses with θ, including those stored in interface files.
Clause-content assigns inference and decision rules to θ; mark placement and names of rendered
colors belong to the interface vocabulary. Storage keeps exported files intact. The strict partition
moves every render-referencing clause to the interface before the crossing is computed (Table 19).
In the exported instance, answer_contract contains both the single-letter format and decision
rules for choosing that letter; protocol_contract contains both JSON action syntax and domain
guidance. The former’s polarity/verdict clauses and the latter’s reading/zoom policy belong to θ
under the re-partition. View descriptions, color identities, and action schemas remain in the interface.

A complete evolved skill
The MMComp instance consists of SKILL.md, VIEW.yaml, and LAYOUT.yaml. These are storage
containers, not the logical coordinate split: reasoning clauses in any file belong to θ, as specified
in Appendix D. The reader first grounds option nouns and builds a verdict table. The crop rule
is zoom_gain > 1.05 or region_frac < 0.12; canvas expressions color notes by option
ordinal. The view contract explains those colors, and the answer contract requires the final option
letter. These files make the relation between the reader, visual configuration, and interface concrete.
The complete contents are typeset below, including four runtime slots: {pool_size}, {max_-
crops}, {ans_header}, and {ans_example}. The domain configuration binds these at load
time. For MMComp, pool_size=8 source units per item and max_crops=2, matching max_-
crops_per_step; the protocol template supplies the answer header and example. The frozen
artifact includes the template and these bindings. The Markdown and YAML files are typeset below
to make them readable while preserving their original content.

Reading procedure: SKILL.md
mmcomposition Reading Procedure
What this domain contains
Items are single composite images — multi-panel layouts, presentation slides, side-by-side photo pairs,
captioned images, or scene photos. The question probes spatial relationships, outlier detection, caption
matching, or scene description. Answer options (A/B/C/D or Left/Right style) are always embedded in the
question text you receive — never refuse on the grounds that options are missing.
Step 1 — Noun-grounding pre-pass (ALWAYS, before any other reasoning)
Before interpreting the image content against the question, do this explicitly:
1. Parse each answer option and extract the key concrete nouns (objects, people, animals, scene elements).
2. For each option, state whether its key noun(s) are visible or absent in the image.
3. Count how many options describe objects that are entirely absent from the image.
4. Note the question’s polarity:
• ’which does NOT apply’ / ’pick the incorrect’ / ’does not apply’ / ’wrong description’ →NEGATION-
FRAMED: proceed to Step 1-V (Verdict Table) immediately.
• ’which aligns / which is correct / right description / accurately describes’ →AFFIRMATIVE: proceed
to Step 1-V as well, marking each option APPLIES or ABSENT.
• ’yes/no’ →after confirming subject locations with notes, fill in: ’The [subject] IS / IS NOT [relation]
the [object]’ before mapping to A/B.
5. Write this grounding check in your note field: ’Objects in options: [list]. Visible: [list]. Absent: [list].
Question asks for: [correct/incorrect/yes/no].’
This pre-pass prevents over-elimination (answering all letters) and polarity flips.
Step 1-V — MANDATORY VERDICT TABLE (for all multi-option questions)
Before committing to any letter, write a verdict table in your note field. Format exactly:
VERDICT TABLE
A: [one-line visual evidence or NOT FOUND IN IMAGE] →APPLIES / ABSENT
B: [one-line visual evidence or NOT FOUND IN IMAGE] →APPLIES / ABSENT
C: [one-line visual evidence or NOT FOUND IN IMAGE] →APPLIES / ABSENT
D: [one-line visual evidence or NOT FOUND IN IMAGE] →APPLIES / ABSENT
QUESTION POLARITY: [asks for INCORRECT / asks for CORRECT]
FINAL LETTER: [the letter whose verdict matches the polarity]
Rules:
• For negation-framed questions (’does NOT apply’, ’pick the incorrect’, ’wrong description’): the FINAL
LETTER is the one marked ABSENT (or the most specifically wrong if multiple are absent).
• For affirmative questions (’which is correct’, ’accurately describes’, ’right description’): the FINAL LETTER
is the one marked APPLIES.
• If ALL options are absent (full domain mismatch): rank by specificity of false claim — the option making
the most concrete/specific false assertion is ’most incorrect’; that letter is FINAL LETTER.
• The answer field must contain exactly the FINAL LETTER from this table. No other letter may appear
in the answer field.
• Drop one note on the image for each option (at the region where the object was sought — even if absent,
mark the empty region). Note ordinal 1=A, 2=B, 3=C, 4=D. The canvas will color each note ring distinctly
so you can visually confirm letter-to-region mapping.

Step 2 — Initial full read
Attach and read image 0. Identify:
• How many panels/sub-images are present
• Question type: spatial-relation | outlier | caption-match | scene-description | left-right | mismatch-detection
• Whether text in the image is legible at full scale
• Whether any embedded screen/monitor/framed photo contains the relevant content (screen-within-screen
pattern)
Step 3 — Decide if one pass is enough
Answer immediately (after the verdict table) when:
• The scene content is unambiguous at full scale AND the noun-grounding pre-pass resolves the question
• The answer options are purely verbal and the image content is already understood
Do NOT answer immediately when:
• Slide or panel text is small and needs reading
• Two panels look similar and fine detail distinguishes them
• A spatial relationship depends on object overlap or occlusion
• A TV/monitor/framed image is embedded and may contain the described content
Step 4 — Zoom protocol (when needed)
For outlier / slide questions: zoom each panel individually to read titles, headers, colour schemes.
For caption-match: zoom embedded text and the dominant subject.
For left-right / spatial: zoom the region of interest. Place a note at the key anchor before answering.
For screen-within-screen: detect bright rectangular inset (TV, monitor, framed photo). Zoom to that inset
at the tightest crop that captures the full screen content. Treat the inset as a separate visual context and
re-run the noun-grounding pre-pass on it.
For mismatch / all-absent scenarios: zoom the most ambiguous region if any option’s objects might be
present but small. If after zooming objects are still absent, proceed to Step 1-V rule for all-absent.
Step 5 — Note before answering
Drop one note per option on the image at the region where that option’s key object was found or sought. Note
ordinal corresponds to option letter (1st note = A, 2nd note = B, 3rd = C, 4th = D). For absent objects,
drop the note at the region where the object would be if it existed. The canvas colors these rings distinctly so
you can visually confirm your letter mapping.
Step 6 — Answer
Read your VERDICT TABLE. Copy the FINAL LETTER to the answer field. That letter and only that
letter goes in the answer field.
State the single letter only (or the exact number of letters the question format requires — usually one). Never
answer ’Left’ or ’Right’ as a standalone string. Never list all four option letters unless the question explicitly
asks for all that apply.
Anti-patterns to avoid
• Do NOT answer ABCD when only one answer is required, even if all options describe absent objects —
select the single most specifically incorrect option.
• Do NOT skip the noun-grounding pre-pass (Step 1) or the verdict table (Step 1-V).
• Do NOT claim options are missing — they are always in the question text.
• Do NOT answer ’Left’ or ’Right’ if the options are A/B/C/D.
• Do NOT skip zooming on slide/panel grids or embedded screens.
• Do NOT issue more zoom steps than needed once the answer is clear.
• Do NOT let a letter appear in the answer field before the verdict table is complete.

• Do NOT select a letter based on what ’sounds plausible in the real world’ when the image shows a
completely different scene — always rank by visual contradiction to the actual scene.

You are a visual reasoning agent. Each step you output exactly ONE JSON action block.
