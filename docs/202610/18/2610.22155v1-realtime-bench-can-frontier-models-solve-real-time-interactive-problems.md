## 摘要
实时交互要求智能体感知不断演变的环境，并在时间约束下采取行动。然而，现有针对实时流式模型的评测主要关注对话质量和流式感知，尚未检验模型在严格时间约束下有效采取行动的能力。我们推出 Realtime-Bench，这是一个精心筛选的动态任务套件，在其中，行动延迟会直接影响任务成败。在 Wall Clock 设定下，环境随实际推理延迟推进，最佳成功率仅为 44%，最佳 Pass^3 也只有 36%，表明实时交互仍然极具挑战。为区分服务延迟与模型的实时流式能力，我们将 Wall Clock 与 Paused Clock 进行比较；后者消除了推理延迟，作为理想化参照。此外，我们引入 Token Clock，使模拟时间依据生成的 token 数量推进，从而独立于实际服务速度，检验模型的时间感知能力。我们发现，时间成本会限制模型在不断演变的环境中的成功率；在时间压力下，增加推理投入的效果不一，反映出决策质量与及时执行之间的权衡。这些发现为提升实时多模态智能体提供了方向，包括具备时间感知的自适应推理，以及持续感知与行动。

## Abstract
Real-time interaction requires agents to perceive evolving environments and act under temporal constraints, yet existing evaluations of real-time streaming models focus on conversational quality and streaming perception, leaving effective action under strict temporal constraints untested. We introduce Realtime-Bench, a suite of carefully curated dynamic tasks where delayed actions directly affect success. Under Wall Clock, where environments advance according to actual inference latency, the best success rate reaches only 44% and the best Pass^3 is only 36%, demonstrating that real-time interaction remains challenging. To separate serving latency from models' real-time streaming capability, we compare Wall Clock with Paused Clock, which removes inference delays as an idealized reference, and introduce Token Clock, which advances simulated time according to generated token counts, testing temporal awareness independently of physical serving speed. We find that temporal costs limit success in evolving environments and that higher reasoning effort has mixed effects under time pressure, reflecting a trade-off between decision quality and timely execution. These findings suggest directions for improving real-time multimodal agents, including adaptive reasoning with temporal awareness and continuous perception and action.

### 1.2 研究问题与意义

论文主要研究：

1. 前沿模型在环境持续变化、行动机会有限的任务中能否可靠成功？

**整体意义**是把评价重点从“决策是否正确”扩展为“决策能否及时生效”，并为研究推理质量、计算开销与行动时机之间的权衡提供可控实验平台。

## 2. 方法论：能力框架与三种时钟

### 2.1 三个互补的实时能力维度

| 能力 | 定义 | 典型要求 |
|---|---|---|
| **RT-Perceive：时间状态感知** | 跟踪环境变化、信息新鲜度与机会窗口 | 判断刚才看到的库存现在是否仍然有效 |
| **RT-Deliberate：自适应思考** | 根据剩余时间与继续计算的预期收益调整推理长度 | 截止时间临近时缩短思考 |
| **RT-Act：时间感知行动选择** | 判断何时等待、何时行动，以及动作执行时是否仍然有用 | 在购买窗口内确认，而不是继续观望 |

这是一套**评测与分析框架**，论文没有提出新的模型训练算法。

### 2.2 三种时钟协议

| 协议 | 推理期间环境如何变化 | 主要用途 |
|---|---|---|
| **Wall Clock：真实时钟** | 按实际推理与服务延迟继续推进 | 衡量当前部署条件下的实时表现 |
| **Paused Clock：暂停时钟** | 推理期间冻结环境 | 提供不承担推理时间成本的理想化参照 |
| **Token Clock：令牌时钟** | 按生成 token 数折算模拟时间 | 在统一计费规则下研究思考的时间成本，减少服务速度干扰 |

Token Clock 的关键关系为：

\[
\kappa=Bf,\qquad \Delta t=\frac{n}{Bf}
\]

- \(f\)：每模拟秒的观测帧数；
- \(B\)：一个观测间隔对应的计费 token 数；
- \(n\)：提交动作前产生的计费 token 数；
- \(\Delta t\)：动作执行前的模拟延迟。

主实验设置为 **\(f=1\) FPS、\(B=64\)**，即每生成64个计费 token，环境推进1秒。生成200个 token 的动作约在3.125秒后执行：对拍卖可能来得及，对贪吃蛇转向可能已经过晚。

### 2.3 交互与执行流程

1. 模型接收当前截图、可交互元素标记及保留的历史。
2. 模型输出一个 GUI 动作，例如点击、输入、按键、拖动或等待。
3. 评测系统根据时钟协议计算延迟，并先推进环境，再执行动作。
4. 如果推理跨越多个观测间隔，则跳过中间帧，下一次提供最新的计划观测帧。
5. 达到成功、失败、任务截止时间或评测时限后终止，以终态判分。

重要实现细节：

- 截图最长边缩放至768像素，并提供 **Set-of-Marks（SoM）**，降低坐标定位对实时决策评测的干扰。
- Token Clock 根据 API 报告计入推理 token 与输出 token；Gemini Live 不计生成音频。
- GUI 执行本身的物理延迟不推进环境时间。
- 历史按块压缩，尽量保持上下文前缀稳定，以支持缓存复用。
- 无效动作被替换为等待；模型每次观测最多提交一个动作。

## 6. 主要结论与发现

### 6.1 真实时钟下，可靠性仍然有限

- GPT-6-Astra 高推理设置取得最高 **Pass\(^3\)=36%**。
- 摘要中的“最佳成功率44%”是最高单次运行结果；其三次平均成功率为 **42.67%**。
- Jev平均延迟约 **0.469秒**，但 Pass\(^3\) 仅为8%。

这说明：**低延迟是重要条件，但不是充分条件；快速做错同样无法完成任务。**

### 6.2 时间成本显著压低表现

以 Claude Opus 5 高推理投入为例：

- Paused Clock：70%；
- Wall Clock：14%；
- Token Clock：30%。

即使把服务速度因素替换为统一的 token 时间成本，表现仍明显低于暂停环境。任务求解能力与及时行动能力之间存在较大落差。

### 6.3 更高推理投入并非总是更好

- 在 Paused Clock 下，6个模型均因更高推理投入而提升。
- 在 Token Clock 下：
  - Claude Opus 5：44%降至30%；
  - Kimi-K3：24%升至36%。

说明额外推理的收益依赖模型和任务，不能简单采用“思考越多越好”的策略。

### 6.4 放宽时间预算通常有益，但不保证成功

低推理投入下：

- Claude Opus 5 从 \(B=32\) 时的30%升至无推理时间成本时的62%；
- Kimi-K3 从22%升至60%。

不过部分模型变化非单调，且即使暂停推理时钟，仍有大量任务失败，表明问题还包括视觉理解、状态跟踪、规则掌握与行动选择。

### 6.5 三类反复出现的失败

- **思考不适应紧迫程度**：只剩10秒落子，却生成1,845个 token，折合28.8秒。
- **未更新动态状态**：贪吃蛇已经偏离目标行，仍沿旧方向行动直至撞墙。
- **错误判断行动必要性**：道路开始塌陷后继续等待，或在预订按钮可用时等待至房间保留失效。

这些是基于轨迹的行为归因，**不是对模型内部认知机制的直接证明**。

## 7. 优点与亮点

- **研究问题具有实际价值**：将行动时效性纳入智能体评测，比单纯正确率更接近动态应用需求。
- **三时钟设计具有解释力**：既保留真实部署意义，又提供去除服务速度干扰的可控参照。
- **强调闭环交互**：行动影响后续状态，而非仅对视频进行被动问答。
- **考察推理投入的边际收益**：直接揭示更多计算与错失行动窗口之间的矛盾。
- **关注跨运行稳定性**：Pass\(^3\) 比最佳单次成绩更能体现可靠程度。
- **实现细节较透明**：说明了动作接口、token 计费、跳帧、上下文管理与提示词。
- **定性标注较谨慎**：设置证据等级和排除规则，并提醒失败类别并非互斥、分母也不同。

## 8. 不足与局限

### 8.1 基准覆盖与生态真实性有限

- 任务规模较小，主要是人工构建网页与改编游戏，不能代表开放真实世界的全部实时需求。
- 未覆盖机器人控制、真实多人协作等复杂场景。
- **不是直接的人机协作研究**：其与 human–AI 的关联主要在智能体能力基础，而非用户信任、协作绩效或人类体验。

### 8.2 交互机制不能完全代表连续流式智能体

- 所有模型统一以1 FPS观测，快速事件可能在两帧之间发生，限制了可达到的表现。
- 推理期间跳过中间观测，不能充分测试持续接收信息、打断推理和在线修订动作的能力。
- 因此，结果更准确地反映**该离散观测、逐动作提交框架下的表现**，不宜直接推广至所有实时架构。
- 排除 GUI 物理执行延迟，也使 Wall Clock 并非完整的端到端现实时间成本测量。

### 8.3 Token Clock 不是纯粹的“时间感知能力”测量

- token 数同时受分词器、推理实现、输出格式和 API 统计口径影响，并不对应完全相同的计算量。
- 相同 token 速率消除了物理服务速度差异，但未消除模型间所有计算与表示差异。
- 主结果依赖人为选定的 \(B=64\)，应结合其他速率的消融共同解读。

### 8.4 对比与统计仍存在偏差风险

- 不同 API、缓存支持和网络状态影响真实时钟结果。
- 决策模型使用候选动作选择；Jev还使用结构化文本而非截图，输入与行动机制并非完全统一。
- 失败分类由作者制定代码本、Codex辅助标注并人工复核，但未报告独立标注者一致性。
- 失败类型使用不同实验条件和分母，不能将其百分比当作统一的互斥因果分解。

### 8.5 部分数字需要澄清

- 正文称 Gemini 3.8 Flash 的 Wall Clock 成功率由低推理的24%升至高推理的32%；但附录表2中：
  - 高推理三次为24%、24%、26%；
  - 低推理三次为28%、26%、28%。
- 若这些属于不同实验批次，论文也未充分解释，因而该模型的具体推理收益不能直接统一解释。
- 附录称 Jev仅评估30个网页任务，但成功率统计分母不够清晰，跨模型比较应谨慎。

**总体评价：**本文的主要贡献是提出有价值的评测框架，并提供“推理质量不等于实时交互能力”的实验依据。后续需要更大任务集、更完整统计报告，以及真正支持连续感知和动态推理预算的智能体，进一步验证其结论与改进方向。
