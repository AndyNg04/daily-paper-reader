## Abstract 

LLM-powered recommender agents use reasoning and memory for personalization, but centralized access to user information raises privacy concerns, while isolated agents cannot learn from others’ experiences. We formulate Federated Recommender Agents , a setting where local agents collaborate through natural-language knowl-edge while keeping interaction histories and personal memories local. We propose FedRecAgent , which enables this collaboration without updating LLM parameters. Its central challenge is determin-ing which reasoning to integrate, since similar behavioral contexts can lead to different choices. FedRecAgent represents local experi-ences as Condition–Transition–Reasoning (C–T–R) units and hier-archically integrates reasoning by condition and transition. Within this structure, it consolidates related explanations and discrimi-nates reasoning across alternative transitions. Each client main-tains semantic and decision memories to capture preferences and conditional choice tendencies, guiding the retrieval and selection of shared reasoning for recommendation. Experiments across three domains under dense and sparse settings demonstrate improved recommendation performance over federated and LLM-based base-lines, while ablations support the contributions of personalized memories and structured reasoning integration.

## 1 Introduction 

Recently, Large Language Model (LLM)-powered recommender agents have emerged as a promising approach to personalized rec-ommendation by leveraging pretrained knowledge and reasoning capabilities to interpret user interactions [1, 6, 7, 22, 32, 33, 35, 36, 39, 48]. These recommender agents can capture user prefer-ences and behavioral contexts from past experiences and utilize the accumulated knowledge (e.g., memory) to inform subsequent recommendation decisions. However, such personalization often requires personal information, including user profiles, interaction histories, and preferences, raising privacy concerns when this infor-mation is processed by centralized servers or external LLM services. These concerns are further underscored by privacy regulations, such as GDPR [29] and CCPA [26], which impose restrictions on the collection, processing, and sharing of personal information. A naive remedy is to deploy recommender agents independently on local devices to keep personal information private. However, this approach limits their ability to leverage diverse behavioral pat-terns and decision-making experiences observed from other users. Therefore, a collaborative recommendation framework that keeps personal information local while enabling recommender agents to leverage knowledge derived from one another’s experiences is needed. From this perspective, Federated Recommendation (Fe-dRec) is proposed as a promising approach to enabling collaboration across local devices while keeping user data private [2, 4, 20, 27, 43]. Existing FedRec methods have enabled such collaboration through numerical aggregation of model parameters [4, 10, 20, 43, 44] or collaborative signals [8, 23]. However, FedRec clients typically operate on resource-constrained personal devices, and repeatedly updating the parameters of LLM-based agents can incur substantial computational and memory over-head. Meanwhile, recent recommender agents can accumulate and update natural-language knowledge derived from user experiences without modifying model parameters. By extending this approach, we envision a new para-digm for FedRec in which agents share natural-language knowl-edge rather than model parameters, enabling collaborative learning without repeated LLM fine-tuning (Figure 1). We refer to this new research setting as Federated Recommender Agents .Realizing such language-based knowledge collaboration between the federated recommender agents introduces three key challenges: (C1 ) continuously accumulating personalized knowledge, ( C2 ) ex-tracting shareable knowledge, and ( C3 ) integrating knowledge gen-erated by different agents. 

C1 : First, local agents must continuously accumulate and utilize knowledge from new user experiences without updating LLM pa-rameters. In particular, they need to maintain personalized knowl-edge that captures not only what users prefer but also how they tend to make decisions across different behavioral contexts. 

C2 : Second, agents must determine how to represent knowledge extracted from local experiences so that other agents can interpret and reuse it without directly accessing user interaction histories or specific preferences. Unlike model parameters, recommendation knowledge expressed in natural language lacks predefined shared identifiers for alignment. We therefore need to define a consistently structured unit of knowledge sharing that makes explicit what each contribution describes. For recommendation, such a unit should capture patterns in the user’s history and explain why those in-teractions may lead to the observed next choice, while abstracting away specific item identities and user-specific preference details. 

C3 : Third, we need to establish criteria for how these knowledge units should be integrated . Recommendation knowledge describes how users with particular interaction patterns proceed to their next choices. However, similar patterns may lead to different decisions, such as continuing familiar interests or exploring new directions. A common representation alone therefore does not determine which contributions should be combined. Integration must account for both the preceding interaction patterns and the subsequent deci-sion directions, consolidating related reasoning while preserving explanations for distinct choices. To address these challenges, we propose FedRecAgent , a struc-tured reasoning federation framework for Federated Recommender Agents. FedRecAgent keeps both client-side and server-side LLM pa-rameters fixed, enabling personalization and collaboration through updates to experience-derived natural-language knowledge. Specif-ically, each client manages shareable knowledge units and private memories from local experiences. Each shareable unit follows a Condition–Transition–Reasoning (C–T–R) structure: Condition de-scribes the behavioral context, Transition captures the observed de-cision transition, and Reasoning explains the corresponding choice. These units abstract away specific item identities and user-specific preference details. Meanwhile, each local agent maintains two com-plementary private memories on its device: semantic memory , cap-turing user preferences, and decision memory , capturing choice ten-dencies across behavioral contexts. The server organizes uploaded units by condition and transition and integrates their reasoning into a hierarchical global knowledge bank. During recommenda-tion, each client uses its private memories to retrieve and select shared reasoning from the bank for personalized ranking. The main contributions of this paper are summarized as follows: 

• Federated Recommender Agents. We formulate a new re-search problem, termed Federated Recommender Agents , in which LLM-powered recommender agents collaboratively leverage knowl-edge acquired from other agents while keeping private user infor-mation local. To address this problem, we propose FedRecAgent ,a framework that enables federated collaboration through the sharing and integration of natural-language knowledge rather than model parameters. 

• Structured Reasoning Federation. In FedRecAgent, we design private dual memories to accumulate personalized knowledge and formulate C–T–R as a consistent unit for knowledge sharing that abstracts away private user and item details. We further establish condition–transition alignment as the criterion for hi-erarchical reasoning integration. 

• Experiments. We evaluate FedRecAgent across three recommen-dation domains under both dense and sparse settings, comparing it with representative federated and LLM-based recommenda-tion methods. Ablation studies and additional analyses further examine the effectiveness of the proposed components. 

## 2 Related Work 

Federated Recommendation. Federated recommendation (Fe-dRec) enables collaborative preference learning while keeping user interaction data on local devices. Early approaches primarily re-lied on federated optimization of collaborative filtering models by sharing model parameters or item representations instead of raw interaction histories [2, 43]. Subsequent studies have explored personalized model adaptation [4, 20, 44, 52], collaborative infor-mation aggregation [8, 10], continual preference learning [21, 46] and cold-start recommendation [18, 45]. Despite these advances, collaboration has largely relied on learned representations or model updates rather than explicit, reusable reasoning knowledge. Recently, foundation models have been incorporated into Fe-dRec to leverage their semantic understanding of users and items. [42] combines federated retrieval with LLM-based reranking, while [50] introduces an efficient framework for federated LLM-based recommendation. [9] explores personalized LLM adaptation for federated cross-domain recommendation, whereas [19] and [47] Federated Recommender Agents Conference’17, July 2017, Washington, DC, USA 

leverage pretrained vision-language representations and person-alized multimodal fusion. Although these approaches incorporate knowledge, they primarily focus on recommendation modeling, representation fusion, or model adaptation rather than federating reasoning knowledge derived from personalized agent experiences. 

LLM-based Recommender Agents. Recent advances in LLMs have enabled recommender agents that leverage reasoning, plan-ning, and tool utilization for personalized recommendation. [32] employs autonomous planning and tool use, while [48] models users and items as interacting agents to capture collaborative pref-erences through reflection. Other studies investigate deliberative reasoning [33], dynamic item relationships [39], and multi-agent collaboration [35]. Recent studies have also emphasized persistent memory and per-sonalized adaptation. [22] incorporates memory for cross-domain recommendation, [1] models iterative feedback between users and recommendation agents, and [36] maintains user-specific mem-ory to adapt to individual instructions and feedback. [6] further introduces collaborative memory to capture relational informa-tion across users and items. [40] examines how adversarial textual perturbations can corrupt agent memories and manipulate rec-ommendations. However, these studies do not primarily address how recommendation agents can share reusable reasoning while keeping user histories and personal memories local. This requires separating knowledge intended for cross-user collaboration from private personalization information. 

LLM-based Federated Agents. Recent studies have extended fed-erated learning to LLM-based agents, enabling collaboration with-out centralizing local experiences. Some approaches optimize agent models or policies through parameter-based federation [3, 51]. In contrast, knowledge-based approaches exchange natural-language knowledge instead of model parameters. [34] aggregates tool-use knowledge extracted from local data, while [5] uses textual feed-back to optimize local prompts and aggregates them through server-side summarization. Other studies explore federated reasoning in-sights [41], reusable skills [38], and semantic knowledge abstrac-tions [17]. [12] further studies the applicability of shared transi-tion rules across heterogeneous agent environments. These studies demonstrate the potential of knowledge-level collaboration among LLM-based agents. However, federating reasoning knowledge for recommendation requires distinguishing different decision transitions across sequen-tial interactions. Even under similar behavioral contexts, users may continue their current interests, return to previous ones, or explore new alternatives. Thus, contextual similarity alone is insufficient to determine which reasoning contributions should be integrated. Furthermore, utilizing shared reasoning requires accounting for individual preferences and decision-making tendencies. FedRecA-gent addresses these requirements by organizing shared reasoning into hierarchical condition–transition branches and leveraging local private memories for recommendation. 

## 3 Problem Formulation 

We formulate a federated recommender agent setting in which local LLM agents maintain private user data and personal natural-language knowledge, while collaborating through shareable knowl-edge integrated by a central server-side LLM agent.

Local Recommender Agents. We adopt a user-level federated setting, where each client corresponds to a single user 𝑢 ∈ U . Each client device hosts a local LLM-based recommender agent that in-terprets the user’s interaction experiences to construct shareable and private natural-language knowledge. The shareable knowledge is abstracted for reuse across users, and the private knowledge captures user-specific preferences and decision tendencies. The agent maintains and updates its private knowledge as new experi-ences become available, and uses it together with shared knowledge from the server for recommendation. Raw interaction histories and private knowledge remain on the client device. 

Federated Knowledge Exchange. Client agents upload their shareable knowledge to a central server, where a server-side LLM agent integrates contributions from clients into reusable shared knowledge and distributes it back to client agents. Both client and server LLM parameters remain frozen; adaptation occurs through updates to private and shared natural-language knowledge. Train-ing episodes are grouped into synchronous communication rounds

Within each round, clients process these episodes chronologically, updat-ing private knowledge after each episode while using the shared knowledge finalized in the previous round. The server integrates uploaded knowledge once at the end of each round.

## 5 Experiments 5.1 Experimental Setup 

We briefly summarize the experiment setup due to limited space. Please refer to Appendix A.1 for the experimental details. 

5.1.1 Datasets . We use three real-world datasets from the Ama-zon Review Data [25]: CDs & Vinyl (CDs), Musical Instruments (Music), and Office Products (Office). These domains are widely used in recommendation and LLM-based agent studies [14, 40, 48]. Following prior user-sampling protocols [22, 40, 48], we construct dense and sparse subsets for each domain, yielding six datasets. 

5.1.2 Evaluation Metrics and Protocol . We report NDCG@ 𝐾 

(N@ 𝐾 ) [15], 𝐾 ∈ { 1, 5, 10 }, and Mean Reciprocal Rank (MRR) [30], scaled by 100. We use per-user chronological leave-one-out evalua-tion [13, 16, 20, 44, 48]: the last interaction is held out for testing, the second-to-last for validation, and the rest for training. Each ground-truth item is ranked against nine random negatives, with all ten candidates presented in random order. Personalized memories and the shared bank use only training data and remain fixed during evaluation. Unless otherwise specified, results are averaged over users and five random seeds; the main table also reports standard deviations across seeds. 

5.1.3 Baselines . We compare FedRecAgent with 11 baselines in three categories: (1) Conventional federated recommendation: 

PFedRec [43], GPFedRec [44], FedRAP [20], and FedCIA [8]; (2) Fed-erated adaptations of sequential models: we adapt GRU4Rec [11], SASRec [16], and BERT4Rec [28] to the federated setting, denot-ing them as FedGRU4Rec, FedSASRec, and FedBERT4Rec; and (3) Federated adaptations of LLM-based methods: we select LLMRank [13], AgentCF [48], AFL [1], and I2Agent [36] for their amenability to federated adaptation, and denote our adaptations as FedLLMRank, FedAgentCF, FedAFL, and FedI2Agent. 

5.1.4 Implementation Details . We implement all methods in Py-Torch with CUDA on up to five NVIDIA RTX 4090 GPUs. The client and server backbones are Qwen3-4B-FP8 and Qwen3-8B-FP8 [37], abbreviated as Qwen3-4B and Qwen3-8B. The smaller client follows prior work on deploying 8-bit 3B–4B LLMs in resource-constrained environments [24, 31, 49], while the larger server supports shared knowledge integration. Client and server prompt batch sizes are 32 and 4, respectively. We use all-MiniLM-L6-v2 for semantic similarity, evaluating 𝜏 𝐶 , 𝜏 𝑇 ∈ { 0.3, 0.5, 0.7} and retrieval budget 

𝑏 ∈ { 1, 2, 3, 4, 5}. We set 𝑅 = 4 communication rounds, maximum history length 𝐿 = 10, and minimum preceding history ℎmin = 8. The server uses at most 𝐵 = 10 reasoning records for distillation and 𝐻 = 2 discrimination iterations with up to 𝑄 = 10.

## 6 Conclusion 

In this paper, we formulate Federated Recommender Agents, a set-ting where personalized LLM agents collaborate through natural-language knowledge while keeping private user information local. We propose FedRecAgent, which maintains private dual memo-ries of preferences and choice tendencies, shares C–T–R knowledge units, and hierarchically integrates reasoning by condition and tran-sition. These memories guide personalized retrieval and selection of shared reasoning without updating LLM parameters. Experiments demonstrate improved recommendation performance over base-lines, while further analyses support the effectiveness of private memories and structured reasoning integration.

## A.1 Experimental Details 

Data and Evaluation. Following [22, 40, 48], we construct subsets of CDs & Vinyl, Musical Instruments, and Office Products; Table 7 reports their statistics. Interactions are ordered chronologically within each user, reserving the last two for validation and testing. Training episodes use only the preceding training interactions. For LLM-based methods, items in interaction histories and candidate sets are represented by their titles. 

Sequential Knowledge Updates. We process training episodes chronologically to reflect knowledge accumulation from new ex-periences. Unlike repeated local-epoch optimization, our setting updates natural-language memories and shared knowledge while keeping LLMs frozen. Each eligible episode is processed once, with its information retained through memory updates rather than re-peated replay. History windows may overlap, but each training interaction serves as the next-item target only once. For client co-ordination, episodes are grouped into common intervals by target timestamp. Within each interval, clients process episodes sequen-tially using the previous round’s shared knowledge, and the server aggregates their contributions at the end. Evaluation uses the final memories and knowledge bank. 

Baseline Configurations. We compare existing federated rec-ommenders with federated adaptations of sequential and LLM-based methods, preserving their core modeling and agent mecha-nisms within the client–server setting. The LLM-based methods are selected for their amenability to this adaptation. For conven-tional and sequential recommenders, we tune learning rates over 

{10 −1, 10 −2, 10 −3, 10 −4 } using SGD, with up to 300 communication rounds and ten local epochs per round. Sequential models use cross-entropy loss, and other model-specific settings follow the original implementations. For conventional and sequential recommenders, we use a batch size of 2048 and full client participation (sampling ra-tio 1.0). Federated sequential baselines use FedAvg for aggregation. For LLM-based baselines, FedLLMRank [13] compares prompting configurations using interaction history, recency emphasis, and in-context examples. FedAgentCF [48] follows the same chrono-logical round schedule as FedRecAgent and exchanges only item memories. The server LLM merges these memories and broadcasts them to initialize clients’ local item memories for the next round. Inference combines learned user and item memories with the ten most recent interactions. FedAFL [1] uses the client LLM for both the recommender and user simulator, with FedSASRec providing recommendation priors and reward-model guidance.
