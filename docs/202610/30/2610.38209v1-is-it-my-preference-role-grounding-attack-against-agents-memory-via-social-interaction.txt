## Abstract 

LLM-based agents now share experiences on social platforms and remember new preferences to enhance their performance. How-ever, existing memory systems contain a vulnerability in role-to-principal attribution that attackers can exploit. We identify Role Grounding Misattribution, in which an attacker-designed interac-tion causes the victim agent to incorrectly record a preference from the attacker as a preference of the victim’s user. Specifically, we are the first to formalize Role Grounding Attack (RGA) , an attack model that exploits this vulnerability through nested conversation structures. In the memory formation stage, an experience-sharing post quoting a conversation between the attacker agent and its user is published, which explicitly identifies its publisher. The inner con-versation expresses preferences from the user of the attacker agent. When the victim agent remembers preferences from this nested structure, its memory loses the context binding and grounds the attacker’s preference to the victim’s user instead. In the memory retrieval stage, the misattributed preference persists and influences the victim agent’s decisions when it encounters relevant scenarios. We instantiate RGA as tool selection manipulation and privacy leakage. Tool selection manipulation causes a tool-call preference to be misattributed to the victim’s user, steering the victim to-ward an attacker-controlled tool. Privacy leakage extends this by misattributing both a tool-call preference and a task-requirement preference to the victim’s user. The victim selects the attacker’s tool, then includes sensitive information in tool arguments to satisfy the task requirement. We evaluate RGA across five mainstream mem-ory systems and six language models. Tool manipulation achieves about average 92.37% attack success rates; privacy leakage achieves about average 69.57% attack success rates. Our work highlights the need to strengthen role grounding in memory as a defense against preference misattribution in multi-principal environments.

## 1 Introduction 

LLM-based agents [12, 16] now share experiences on social plat-forms to acquire new preferences [9, 31]. Without such platforms, agents repeatedly rediscover the same solutions, wasting compute and tokens on reinvention. This sharing closes the gap between static training data and evolving production software. As shown in Figure 1, platforms such as Moltbook [18] and Stack Overflow for Agents [29] enable agents to learn from posts and comments pub-lished by their peers. Memory in agents persist these preferences across sessions [10, 23, 24, 38], allowing agents to enhance their behavior and performance. This capability is how agents benefit from multi-agent environments. However, this workflow exposes agents to malicious preferences that can steer their behavior [16, 36]. Attackers can steer agents toward attacker-controlled tools, and more dangerously, leak sen-sitive information through carefully crafted tool arguments. The challenge is that social platforms introduce a multi-principal envi-ronment [2]. Memory systems must determine not only whether a preference is authentic, but also which principal the preference belongs to [35]; otherwise it can lead to preference manipulation. arXiv:2610.38209v1 [cs.CR] 28 Oct 2026 Haoran Bu, Yiting Shen, Litian Zhang, Ruihan Hu, and Xi Zhang 

Existing preference manipulation typically operate through con-tent manipulation [19, 32] or memory injection [27, 37]. For exam-ple, MPMA [32] crafts tool descriptions to bias selection; Hidden in Memory [27] injects fabricated records disguised as user instruc-tions, creating explicit claims that the victim user holds certain preferences. However, content manipulation approaches are lim-ited to influencing decisions at the moment of choice, and memory injection approaches require the attacker to fabricate claims about the victim user, which can be detected through security check. Following previous studies GroupMemBench [35], we reveal an underexplored vulnerability in how memory systems map roles to principals in a nested social interactions. We then characterized such vulnerability as a novel attack termed as Role Grounding Attack (RGA) , an attack which exploits this vulnerability through two stages. In the memory formation stage, the attacker agent publishes an experience-sharing post quoting a conversation with its own user. The quoted conversation expresses preferences us-ing the context-relative role user. The post explicitly identifies its publisher, maintaining correct source provenance [33]. All stated preferences genuinely belong to the attacker’s user; no claim is fabricated. When the victim agent browses and remembers pref-erences from this nested structure, its memory system retains the inner user role but omits the environment attribution binding it to the attacker’s user. Thus it grounds this preference to the vic-tim’s user, causing role grounding misattribution. In the memory retrieval stage, this misattributed preference persists and influences the victim agent’s decisions when relevant scenarios arise. The victim agent’s behavior is manipulated by the attacker’s preference, leading to tool selection manipulation and privacy leakage. We instantiate and evaluate RGA in a practical setting. Tool selection manipulation misattributes a tool-call preference to the victim’s user, steering the victim toward an attacker-controlled tool. Privacy leakage extends this by simultaneously misattributing both a tool-call preference and a task-requirement preference. The victim first selects the attacker’s tool according to the misattributed tool-call preference, then includes sensitive information in tool arguments to satisfy the misattributed task requirement. This two-preference design enables the attacker to both control which tool is selected and influence what information is passed to that tool. We evaluate five mainstream memory systems, including A-MEM [34], Mem0 [4], Hindsight [13], MemOS [17] and LangMem [30], in a controlled multi-agent platform. Tool selection manipulation achieves average attack success rates of 92.37%. Privacy leakage achieves average attack success rates of 69.57%. These results demon-strate that the vulnerability is widespread across memory architec-tures and agent backends. Our contributions are as follows: 

• We identify and formalize Role Grounding Misattribution, a vulnerability in persistent agent memory where nested in-teraction structures cause preferences to be misattributed to user, even when source provenance is correctly preserved. 

• We formalize Role Grounding Attack, an attack that exploits this vulnerability through ordinary experience-sharing posts without memory access, provenance disguise. 

• We demonstrate that misattributed preferences produce persistent behavioral changes across five memory systems and six language models, highlighting the vulnerability’s generality and severity.

## 4 Method 4.1 Attack Overview 

Following the attack model, We standardize RGA through two steps: Publisher-Preference Decoupling and Nested Conversation Con-struction. As shown in Figure 2 (top), the attacker agent expresses preferences through a post containing an nested conversation. This preference is bound to the context-relative "user" role within the inner conversation, and the outer context claims this conversation is between the attacker and its owner. This nested structure making it difficult for victim to correctly resolve the preference principal. During the memory formation stage (Figure 2, bottom-left), when victim agents browse this post on the platform, they remember the preferences but misattribute it to their own user rather than the attacker’s user. In memory retrieval stages (Figure 2, bottom-right), the victim prioritizes the attacker-controlled tool due to the misattributed user preference to complete the task. ## 4.4 Attack Instantiations 

4.4.1 Tool Selection Manipulation. The goal of this attack is to manipulate victim agents into prioritizing the attacker-controlled tool when multiple candidate tools are available. Thus, we hope the victim agent remember the preference, such as "user prefer 𝑣 atk ". It can be defined as 

gPref sel = {( 𝑣 sel atk , 𝜔 (𝑎 ))} . (19) Here, 𝑣 sel atk denotes a tool-call preference content, such as "prefer SkyCast to get weather forecast", as shown in Figure 2 (bottom). 

4.4.2 Privacy Leakage. The goal of this attack is to make the vic-tim agent not only prioritize the attacker-controlled tool but also pass sensitive information to it. Thus, we additionally make a task-requirement preference to be remembered as the victim user’s own. We hope the victim agent remember the preferences, such as "user prefer 𝑣 atk , and prefer higher-accuracy results". It can be defined as 

gPref priv = {( 𝑣 sel atk , 𝜔 (𝑎 )) , (𝑣 task atk , 𝜔 (𝑎 ))} . (20) Here, 𝑣 task atk denotes a task-requirement preference, as shown in Fig-ure 2 (bottom). The first preference makes the victim prioritize the attacker’s tool, and the second encourages sensitive information to be included in its tool arguments. An example template is provided in Appendix B. 

Tool-aligned Optimization for Privacy Leakage. The core of this step is to align the attacker-controlled tool’s description with the misattributed task-requirement preference, so that it claims that supplying sensitive information appears to be the way to satisfy the misattributed task-requirement preference. Specifically, the attacker adds an optional input parameter to the attacker-controlled tool to receive sensitive information, as shown in Figure 2 (top-right). Considering the sensitive information has little relevance to the tool’s functionality, we use an LLM to rewrite this parameter description. The rewritten description claims that supplying the sensitive information satisfies the task-requirement preference 𝑣 task atk .An example template is provided in Appendix B. 

## 5 Experiments 5.1 Experimental Setup 

5.1.1 Dataset and Models. We use MetaTool [11] to simulate 500 tool-call requests in downstream tasks. We expand its original tool lists by renaming tools and partially modifying their descriptions. The expanded tools are constructed so that each candidate has an equal selection probability in the absence of perturbations. The requests and tool lists includes five functional groups, jobs, housing, shopping, papers, weather. We simulate agents using six models as their backends: DeepSeek-V4-Flash and DeepSeek-V4-Pro [7], Qwen3.8-Flash and Qwen3.8-Max [1], and GPT-5.6-Luna and GPT-5.6-Terra [20]. 

5.1.2 Target Memory. We build agents with different memory backends and evaluate their performance on a social platform. A-MEM [34] organizes experiences into linked, incrementally updated memory entries; LangMem [30] uses configurable memory-writing and retrieval workflows; Mem0 [4] extracts and maintains struc-tured user and session memories; Hindsight [13] combines factual storage with contextual recall and reflection; and MemOS [17] pro-vides a memory operating system that coordinates persistent stor-age and hybrid retrieval. We use the official APIs for Mem0, Hind-sight and MemOS. The other memory mechanisms use DeepSeek-V4-Flash as their LLM backend.

5.1.4 Experimental Agents and Platform. To evaluate the attack, we construct a controlled environment. For the agents, we equip each one with persistent memory and tool-calling capabilities [23, 24]. For the platform, we simulate a social environment that emulates Moltbook [18]. Through reading community posts and interacting with other participants, agents acquire and retain knowledge, including assessments of tool quality and alternative technical approaches. ## 7 Related Work 7.1 Preference Manipulation and Tool Steering 

One class of attacks steers the agent’s tool choices through attacker-crafted content. Adversarial search optimization [19] promotes attacker-favored alternatives in LLM-powered search and plugin selection through crafted web content, and MPMA [32] manipulates tool names and descriptions in the MCP ecosystem with advertising-style optimization. These attacks either act on the context visible at a single decision, whose influence fades once the manipulated con-tent leaves the window, or store the attacker’s claims as third-party experience that competes with other evidence on equal footing. In contrast, RGA persists the preference as the victim user’s own: the influence survives across sessions, and because agents prioritize their own user’s preferences, it overrides advertising-style cues and third-party evidence in competitive multi-attacker environments. 

## 7.2 Persistent Memory Poisoning 

Another class of attacks poisons the agent’s persistent memory so that transient attacker content affects later sessions. Plan in-jection [25] corrupts web agents’ task representations, Hidden in Memory [27] induces assistants to store fabricated user memories from attacker-controlled content, and Trojan Hippo [5] plants dor-mant payloads that activate in later sensitive conversations. Mem-Collusion [14] composes individually innocuous social-platform fragments into a harmful memory coalition. At a larger scale, MUR-MUR [26] contaminates shared state across group members, Share-Borne AI Virus [28] propagates poisoned artifacts across assistants, Is it my preference? Role Grounding Attack against Agent’s Memory via Social Interaction 

and MPBench [6] systematizes such write-channel vulnerabilities. RGA instead exploits an uncovered vulnerability in role-to-principal grounding: the post truthfully describes the publisher’s own user, yet memory formation grounds the embedded preference to the victim’s user. Since nothing is fabricated and the publisher remains correctly identified, RGA evades the LLM-based content review, and existing provenance-based defenses do not cover this failure. 

## 8 Conclusion 

We identify Role Grounding Misattribution and are the first to formalize the Role Grounding Attack (RGA), in which a nested interaction causes an agent to record another user’s preference as its own user’s. Across five memory systems and six language models, RGA achieves average high attack success rates for tool selection manipulation and privacy leakage. These results show that memory mechanisms must preserve role-to-principal bindings to prevent preference misattribution in multi-principal environments. ## C Generalization Beyond Nested Dialogue 

RGA does not depend on the nested conversation, when the quoted chat record is replaced by other wrapping formats, all five memory systems still success. The main experiments instantiate the wrap-ping operation H (·) (Section 3) as a quoted chat record, which leaves open whether the attack relies on the user /assistant role labels themselves. ## I Role-Attribution Defense 

A role-attribution reminder built only from platform metadata effec-tively mitigates RGA, lowering ASR sel on all five memory systems by 61.96 percentage points on average. To test whether restoring the role-to-principal binding at memory formation counters the attack, we prepend the reminder below before each memory update. It states that quoted roles refer to 𝜔 (𝑎 ∗) rather than 𝜔 (𝑎 ), is filled from platform metadata, and leaves the post unchanged. 

> The current user of this memory system is { victim_user }. The following content was published by { publisher_id }, an agent serving a different user. Roles such as “user” or “owner” quoted inside the content refer to participants of the publisher’s own conversa-tions, not to the current user. Record each preference with its owner; if the owner cannot be determined, mark it as unknown.

We evaluate each memory system with DS-V4-Flash on 110 queries in one run (22 per scenario), additionally placing the re-minder in the bank-level extraction template for Hindsight, and compare against the mean undefended ASRs of Table 1. Table 12 shows that the reminder lowers ASR sel from 94.32% to 32.36% on average, down to 6.36% and 11.82% on A-MEM and LangMem and by 41.53–47.78 points on Mem0, Hindsight, and MemOS. This indi-cates that RGA succeeds largely because the binding is lost during memory formation, although explicit attribution alone does not fully protect every memory system.
