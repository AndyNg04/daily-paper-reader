## 摘要
LLM 智能体正日益应用于长时程任务，并与多样化的外部环境交互。尽管能力不断提升，这些智能体仍容易受到间接提示注入等现实攻击的影响；此类攻击通过嵌入外部环境中的恶意指令操纵智能体。现有风险评估工作主要关注注入内容，而注入出现的位置所产生的影响尚未得到系统刻画。研究注入位置需要智能体执行更长时程的任务，并与多样的环境界面交互。因此，我们构建了三个智能体测试平台，覆盖工具使用、编程和日常工作流领域，并包含多种注入界面。在保持注入内容不变的情况下，我们发现智能体对不同注入位置的易感程度有所差异。我们将这一现象称为“信任区域效应”：智能体会隐式地对其环境中的不同区域赋予不同程度的信任。例如，由 GPT-5.4 驱动的智能体，平均而言，遵循放置在代码仓库文档文件（即 README 或 TODO 文件）中的不安全注入指令的频率，是遵循相同指令（若其放置在代码文件或数据文件中）的 2.6 倍。基于这一发现，我们开发了基于学习的攻击者，使其能够生成注入内容并选择更合适的注入位置。我们的方法表明，注入的位置和内容都会影响间接提示注入攻击的强度。据我们所知，本研究首次系统刻画了不同注入位置的有效性，涵盖粗粒度的环境界面和细粒度的位置。智能体对其环境各处隐式赋予的信任并不均衡，这一现象为未来的攻击与防御设计提供了重要见解。

## Abstract
LLM agents are increasingly adopted in long-horizon tasks and interact with diverse external environments. Despite their growing capabilities, these agents remain vulnerable to real-world attacks such as indirect prompt injections, which manipulate agents through malicious instructions embedded in external environments. While existing risk assessment work has primarily focused on the injection content, the effect of where an injection appears has not been systematically characterized. Studying injection placement requires agents to operate over longer-horizon tasks and interact with diverse environmental surfaces. Thus, we build three agentic testbeds spanning tool use, coding, and daily workflow domains with diverse injection surfaces. Holding the injection content fixed, we find that agent susceptibility varies across injection placements. We refer to this phenomenon as the trust region effect: agents implicitly assign different levels of trust to different regions of their environments. For example, an agent powered by GPT-5.4 follows an unsafe injection instruction placed in a repository documentation file (i.e., a README or TODO file) 2.6 times more often on average than the same instruction placed in a code or data file. Building upon this observation, we develop learning-based attackers that generate injection content and select better injection placements. Our approach demonstrates that both where an injection is placed and what content it contains can affect the strength of indirect prompt injection attacks. To the best of our knowledge, this work provides the first systematic characterization for the effectiveness of different injection placements, spanning both coarse-grained environmental surfaces and fine-grained positions. The uneven trust that agents implicitly place across their environments provides important insights for future attack and defense design.

## 1. 核心问题与整体含义

### 1.1 研究背景与动机

- LLM 智能体需要读取代码仓库、网页、邮件、共享文档和团队消息等外部内容，以完成长时程任务。
- 攻击者可以将恶意指令隐藏在这些内容中，诱使智能体偏离用户目标，即**间接提示注入**。攻击者不必控制用户提示或系统提示，用户也可能完全看不到攻击内容。
- 既有研究主要优化恶意指令的措辞，对**不同环境载体及其内部位置如何影响攻击效果**，缺少跨场景的系统比较。

### 1.2 论文要回答的问题

1. 固定攻击内容，只改变其位置，攻击成功率是否发生变化？
2. 这种位置差异是否跨模型、跨任务领域存在？
3. 大模型能否直接预测最容易攻击的位置？
4. 学习攻击内容与学习注入位置，能否共同提升攻击效果？

### 1.3 “信任区域效应”的含义

- 论文发现，智能体对不同来源中的指令表现出不同程度的服从，例如更容易遵循 README 中的指令，而忽略数据文件中的相同指令。
- 这里的“信任”是对**外部可观察行为的解释性命名**，不是对模型内部信任变量的直接测量，也不是优化算法中的“信赖域”概念。
- 整体意义在于：智能体安全不能只分析恶意文本本身，还必须分析它所处的环境、语义角色与上下文位置。

## 2. 方法论：核心思想与技术流程

### 2.1 威胁模型与位置表示

- 智能体接收正常任务，通过工具调用读取环境并执行操作。
- 攻击者可以修改某个外部环境载体，但不能直接修改用户指令、系统提示或模型参数。
- 一次注入由两个部分组成：
  - **内容**：希望智能体执行的恶意指令。
  - **位置**：环境载体及其内部位置。
- 位置分为两个层级：
  - **粗粒度载体**：README、代码文件、邮件正文、网页、Slack 消息等。
  - **细粒度位置**：载体文本的开头、中间、结尾。

研究位置效应时，在相应任务与攻击目标下保持载荷不变，只改变载体和内部位置，以尽量分离“内容效果”与“位置效果”。

### 2.2 多载体测试平台

测试平台遵循两项设计原则：

- **载体覆盖**：正常任务应自然涉及多个异质信息来源，因此将较短任务组合或扩展为长时程任务。
- **注入可达性**：尽量选择智能体会读取的载体，避免将“没有看到攻击”误判为“抵抗了攻击”。

不同领域采用不同筛选方式：

- 编程领域：正常运行每个任务三次，保留三次均被访问的文件。
- 工具使用领域：依据正确工具调用序列收集可遇到的载体。
- 工作流领域：由任务设计预先确定相关应用载体。

### 2.3 评价指标

- **攻击成功率（ASR）**：预定义攻击目标是否实现。
- **正常任务效用（Utility）**：原始用户任务完成程度，范围为 0—1。
- 主要位置测量采用**条件 ASR**，即“确认智能体已读取注入内容之后，攻击成功的概率”。

这一口径有助于分离“是否送达”和“是否服从”，但不能直接等同于真实部署中的端到端攻击概率。

最终攻击结果与正常任务效用主要通过**确定性的脚本验证器**判断，而不是让另一个大模型主观评分。

### 2.4 两阶段学习型攻击器

攻击器以正常任务、恶意目标和候选位置为输入，输出结构化的“攻击内容＋载体＋内部位置”。

1. **监督微调预热**
   - 使用模板攻击构造监督样本。
   - 学习输出有效格式、目标相关内容和合法位置。

2. **第一阶段：主要优化内容**
   - 根据训练集上的平均 ASR，为载体类别建立固定排序。
   - 每个任务选择排名最高的可用载体，内部位置固定为结尾。
   - 攻击器虽然预测位置，但执行时会被上述先验覆盖。
   - 使用 GRPO 强化学习，主要优化攻击内容。

3. **第二阶段：联合优化内容与位置**
   - 从第一阶段模型继续训练。
   - 不再覆盖模型预测的位置，直接执行其选择。
   - 内容质量与位置选择共同影响奖励。

奖励包括结构格式正确性、攻击成功、成功时保留正常任务效用，以及可选的 LLM 辅助质量评分。**训练中的辅助评分使用了 LLM，但主要实验结果的验证并不依赖 LLM 裁判。**

## 6. 主要结论与发现

### 6.1 环境载体显著影响攻击效果

- GPT-5.4 对 README、TODO 中不安全指令的服从频率，平均为相同指令位于代码或数据文件时的 **2.6 倍**。
- 工作流中，GitHub、Slack 通常比 Confluence、Jira 更容易成为有效载体。
- 工具使用中，网页、评论等载体在部分模型上更有效。
- 但载体排序随模型变化，**不存在已被证明适用于所有智能体的统一“最危险位置”**。

### 6.2 文本结尾通常更容易生效

| 领域 | 开头 ASR | 中间 ASR | 结尾 ASR |
|---|---:|---:|---:|
| 编程 | 12.6% | 11.1% | **13.0%** |
| 工作流 | 2.3% | 3.3% | **5.7%** |
| 工具使用 | 39.5% | 40.1% | **51.2%** |

该结果与近因效应一致，但论文没有直接验证其内部机制。编程领域的差距较小，也不宜夸大。

### 6.3 失败更多表现为忽略，而非明确拒绝

在已经送达但未成功的工具使用攻击中：

- GPT-4o：81.3% 被忽略，0.7% 被明确拒绝，18.0% 尝试后失败。
- GPT-5.4：66.8% 被忽略，33.2% 被明确拒绝。

因此，“这次没有执行恶意指令”不能简单解释为“安全机制成功识别并拒绝了攻击”。

### 6.4 强模型并不可靠地擅长选择攻击位置

- 提示 GPT-5.4 选择位置，未稳定超过简单频率先验。
- 工具使用领域单次尝试预算下，先验 ASR 为0.53，GPT 选择器为0.42。
- 说明位置效果需要实测，不能只依赖模型直觉。

### 6.5 内容与位置均有独立贡献

控制实验显示：

- 固定模板、由随机载体改为先验载体：
  - 留风险：25.6% → 34.7%；
  - 留任务：38.8% → 77.1%。
- 固定先验位置、由模板改为学习内容：
  - 留风险：34.7% → 62.7%；
  - 留任务：77.1% → 81.8%。

这是论文支持“内容与位置都重要”的较直接证据。

### 6.6 两阶段训练有效，但不稳定优于强先验

- 相比“只优化内容、测试时让模型自行选位置”，两阶段方法：
  - 留风险提升约 **20.7—24.8 个百分点**；
  - 留任务提升约 **4.6—48.1 个百分点**。
- 但固定先验位置的内容优化基线，在若干设置下仍更强。

因此，更准确的结论是：**位置训练能改善未经有效训练的位置选择策略，而不是学习位置策略始终优于经验先验。**

### 6.7 学习内容具备跨模型迁移能力

- 针对 GPT-4o 训练的两阶段攻击器，在 GPT-5.4 的30个测试上下文上达到 **33.3% ASR**。
- 三种模板攻击均为0%，即使使用学习攻击器选择的相同位置也没有成功。
- 这项实验主要证明**学习内容的迁移价值**，不能把全部增益归因于位置优化。
- 正常任务效用保持88.9%，与无攻击基线相同；这不意味着攻击无害，而是恶意行为可以与正常任务完成同时发生。

## 7. 优点与亮点

- **研究维度清晰**：将注入位置从攻击内容中分离出来，补充了既有评估盲点。
- **覆盖两个位置层级**：同时分析环境载体与文本内部位置。
- **重视送达控制**：区分“没有读到”与“读到但未服从”，提高测量解释性。
- **验证器客观**：主要通过执行结果与应用状态判定成功。
- **有针对性的混淆分析**：检查读取顺序、任务长度、文件长度，而非仅报告表面相关。
- **基线较强、结论相对克制**：没有回避简单先验有时胜过学习策略的事实。
- **兼顾实际威胁**：评估未见任务、未见风险和跨模型迁移，并关注攻击是否保留正常任务功能。

## 8. 不足、局限与应用启示

### 8.1 机制解释有限

- “信任区域”仍是行为层面的描述。
- 载体间差异可能同时来自语义角色、任务相关性、格式和指令习惯，尚未通过内部表示分析或更严格干预将它们分离。

### 8.2 覆盖与分布偏差

- 人工组合任务、编程任务的项目检查前导指令，会影响智能体的阅读习惯。
- README、TODO 位于仓库上层，其效果可能混合了文档类型与目录层级因素。
- 为保证送达而选择稳定访问的载体，有利于控制实验，却不完全代表开放环境中的实际攻击机会。
- 未系统覆盖动态网页、多模态内容、长期记忆和更广泛企业系统。

### 8.3 指标与统计限制

- 条件 ASR 不能替代端到端风险，应与载体暴露概率一起报告。
- 小样本、低送达载体和缺少重复试验，使部分模型与位置排序存在不确定性。
- 正常任务效用是离散评分，可能无法反映恶意行为的全部损害。
- 固定攻击下接近零的 ASR，不能外推为对自适应攻击“免疫”。

### 8.4 学习方法与复现限制

- 内容优化基线的测试时自选位置没有得到同等强化学习训练，因此两阶段方法对它的提升，部分可能来自修复训练—测试不匹配。
- 两阶段训练包含额外训练过程；未披露等算力、等交互预算控制，难以完全分离课程顺序与训练预算的影响。
- 训练奖励含“权威性呈现”等辅助评分，可能引入裁判偏好。
- 缺少算力、费用和充分重复实验信息，限制成本评估与精确复现。

### 8.5 对实际防御的启示

论文没有验证具体防御方案，但其结果提示：

- 外部内容不能因位于 README、团队聊天或共享文档中就获得更高指令权限。
- 安全测试应联合覆盖**攻击内容×环境载体×内部位置**。
- 应分别记录注入送达、被识别、被忽略、被执行及最终损害。
- 对敏感操作，仍需依赖权限隔离、动作审批和工具侧约束，而不能只依赖模型是否口头拒绝恶意指令。

**总体评价**：论文最有价值的贡献是通过受控实验，确认注入位置是智能体安全评估中的重要变量；学习型攻击器提供了补充证据，但其稳定优越性、内部机制与真实部署泛化能力仍有待进一步验证。
