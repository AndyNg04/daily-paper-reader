## 摘要
大型语言模型驱动的智能体正通过人机协作日益广泛应用于工作场所。在这个新的工作时代，理解哪些提示特质有助于任务成功至关重要。此外，我们需要揭示现代专业人士所需的关键技能，并为教育者提供关于如何在学生中培养这些技能的指导。现有的人机协作指南要么基于自上而下的理论，要么基于对人机交互的情境特定观察。然而，由于大语言模型的能力正在快速提升，理论可能无法解释新兴的交互模式，而经验性指南也可能迅速过时。在这项工作中，我们探索了一种自动化的、数据驱动的方法来揭示模式，我们将其称为特质，这些特质与任务结果一致，是有效人机交互的特征。我们提出了主特质分析算法，这是一种受主成分分析启发的算法，用于从大语言模型对话模式中推导常见特质。我们的算法使用基于大语言模型的处理阶段来分析人机协作会话轨迹的语料库，推导出数据集中的常见特质，并根据每个特质对每个人类协作者的使用风格进行评分。该方法还允许在特质发现过程中注入领域专业知识，并选择最具区分度的特质，即那些在协作者之间表现出最大差异的特质。我们在两个人类人工智能协作编码数据集上评估了PTA：一个教育场景（学生与人工智能导师合作）和一个专业场景（开发人员与人工智能编码代理合作）。我们发现，PTA推导出的特质在解释两个场景中的协作者行为方面具有显著意义，并能帮助预测任务结果。然而，由于泛化性结果及用户特质随时间变化的不确定性，特质是否能被视为技能仍有待观察。

## Abstract
Large Language Model-powered agents are increasingly used in the workplace via human-artificial intelligence (AI) collaboration. In this new era of work, it is important to understand the kinds of prompting traits that contribute to task success. Moreover, we need to uncover key skills required for modern professionals and inform educators on how to foster these skills among students. Existing guidelines for human-AI collaboration are built from either top-down theory or context-specific observations of human-AI interactions. However, since LLM capabilities are rapidly improving, theory may not be able to explain emerging interaction patterns, and empirical guidelines may become obsolete quickly. In this work, we explore an automated, data-driven approach to uncover patterns, which we term traits, of effective human-AI interaction that are aligned with task outcomes. We propose Principal Trait Analysis, a Principal Component Analysis-inspired algorithm for deriving common traits from patterns in LLM conversations. Our algorithm uses LLM-based processing stages to analyze corpora of human-AI collaborative session traces, deriving common traits across the dataset and scoring each human collaborator's usage style by each trait. The approach also allows domain expertise to be injected during trait discovery and selects the most distinguishing traits to be those that exhibit the highest variance across collaborators. We evaluate PTA on two human-AI collaborative coding datasets, an educational setting (students working with an AI tutor) and a professional setting (developers working with an AI coding agent). We find that PTA-derived traits are significant in explaining collaborator behavior across both settings and can help predict task outcomes. However, whether traits qualify as skills remains to be seen, due to inconclusive results on generalizability and how user traits change over time.

- 现有指南主要依赖自上而下的理论框架（如学习理论、人机协作框架）或自下而上的经验观察（如对话行为编码），但两者均有明显不足：
  - 理论框架固定于设计时点，难以跟上 LLM 能力的快速进化；
  - 经验观察标注成本高、维护困难，且行为类别未必与可量化的结果挂钩。
- 作者提出一种**自动化的数据驱动方法**——**主特质分析（Principal Trait Analysis, PTA）**，直接从人机协作会话语料中挖掘与任务结果对齐的交互模式（称为“特质”），为“AI 使用技能”的推导提供新思路。

## 2. 方法论：PTA 的核心思想、关键技术细节

- **总体思想**：PTA 受主成分分析（PCA）启发，将 PCA 中“提取方差最大的主成分”映射为“从文本对话中提取最具区分度的行为特质”。
  - PCA 处理数值矩阵，PTA 处理文本会话轨迹；
  - PCA 产生主成分向量，PTA 产生可解释的文本特质描述；
  - PCA 计算样本在主成分上的投影（载荷），PTA 通过 LLM 评分每个会话对特质的符合程度；
  - PCA 选择方差最大的正交主成分，PTA 通过贪心策略选择相关性强且彼此冗余度低的特质。

- **算法流程（共四阶段）**：
  1. **行为观察提取（Stage 1）**：
     - 使用 LLM 读取每个会话，生成最多 5 条简短的、可泛化的行为观察（如“学生先尝试再求助”）。
     - 支持两种模式：**通用观察**（无先验指导）和**透镜观察**（注入领域理论，如自我调节学习、ICAP 框架、软件工程知识体系等）。
  2. **特质推导与聚类（Stage 2）**：
     - 将所有观察通过文本嵌入模型转换为向量；
     - 先做 **k-means 聚类**（K1=100 微簇），再用 LLM 为每个簇命名并生成描述；
     - 再对簇描述做 **层次凝聚聚类**（合并相似微簇到 K3 个候选）；
     - 最后用余弦相似度阈值（τ=0.85）去除近似重复，得到候选特质集合 C。
     - 该阶段相当于“构造 PCA 中的主成分向量”。
  3. **特质评分（Stage 3）**：
     - 对每个（会话，候选特质）对，使用 LLM-as-a-judge 在 1–5 的 Likert 量表上打分，形成评分矩阵 Z；
     - 每个特质单独调用一次 LLM，避免极性偏差；
     - 按协作者对会话分数求平均，得到协作者级别的特质分数矩阵 Z′。
     - 该过程类比 PCA 中样本在主成分上的载荷投影。
  4. **主特质选择（Stage 4）**：
     - 用贪心算法从候选中选出 K=10 个主特质，平衡**相关性**（relevance）与**冗余度**（redundancy）。
     - 相关性指标结合两个统计量：
       - **itemTotal**：特质分数与其余特质总分和的相关系数；
       - **communality**：因子分析中特质方差被公共因子解释的比例；
       - 两者经标准化后相加得到 ρ[j]。
     - 逐步选择时：
       - 在分数空间，减去候选特质与已选特质间的平均绝对相关系数，惩罚分数高度相关的候选；
       - 在文本嵌入空间，选择与已选特质文本描述最不相似的候选（通过余弦距离度量）。
     - 该算法在伪代码 Algorithm 1 中给出。

## 3. 实验设计

- **数据集**：
  - **StudyChat（教育场景）**：某大学 AI 课程中 171 名学生与 LLM 导师的 1,540 个辅导对话，覆盖两个学期（Fall 2024、Spring 2025），每学期有不同学生、作业和考试。以学生后续考试成绩为结果变量。
  - **SWE-Chat（专业场景）**：来自 SALT-NLP 的真实用户与编码智能体交互记录，共 2,774 个会话，每位开发者至少两个会话，以会话是否成功为结果变量。

- **基准（Baseline）**：
  - **先验结果回归**：以协作者先前任务的平均结果作为单特征基线。
  - 在 StudyChat 中还对比了两个手工编码特征集：
    - **对话行为计数**（8 类宽泛对话行为）；
    - **Bloom 分类法**（6 个认知过程层级的评分）。
  - SWE-Chat 没有可用的既有预测性编码方案，因此仅与先验回归比较。

- **评估指标与实验设置**：
  - **StudyChat**：由于样本量小，采用样本内拟合，报告加入 10 个 PTA 特质后相对于仅用先验的 R² 提升，并通过 F 检验判断显著性；每个学生贡献两个样本（后两场考试）。
  - **SWE-Chat**：采用项目反应理论（IRT）模型建模会话成功概率，将协作者能力特征与任务难度特征分离；按协作者划分 4 折交叉验证，报告留出集上的平均预测 R² 提升。

- **PTA 超参数与模型**：
  - K=10，K1=100，K2=10，τ=0.85，ε=0.25；
  - 观察提取和聚类命名使用 GPT5.5；评分使用自托管的 Qwen3-4B；
  - 嵌入使用 ModernBERT（形成微簇）和 MPNet（特质去重与选择）。

- **实验变体**：
  - 每个数据集都分别评估了**通用特质池**和**透镜集成特质池**（融合多个领域透镜的候选特质）。

## 6. 主要结论与发现

- **PTA 特质能显著解释与预测结果**：
  - **StudyChat**：在 Fall 2024 学期，10 个 PTA 特质显著提升考试成绩解释力（通用池 ΔR²=0.102, p=.030；透镜池 ΔR²=0.103, p=.028）；但 Spring 2025 学期只有透镜池接近显著（p=.059），通用池不显著。
  - **SWE-Chat**：PTA 特质持续显著提升会话成功预测能力（透镜池 ΔR²=0.048, p<.001；通用池 ΔR²=0.035, p<.001）。
  - 相比对话行为计数和 Bloom 分类法基线，PTA 特质的解释力更强且更显著。
- **显著特质具有可解释性但方向存在矛盾**：
  - 例如 StudyChat 中“概念理解导向”“问题背景详细阐述”与成绩正相关，而“任务上下文具体性”“目标导向引导”等与成绩负相关；
  - SWE-Chat 中“工作流控制-委派”（高控制力、命令式）与积极结果相关，而“委托具体性”“证据驱动的质量监督”等与负面结果相关；
  - 作者认为聚类可能过于激进，导致语义相近但行为不同的观察被合并，从而产生解释性矛盾。
- **时间分析不支持“技能”判定**：
  - StudyChat 中部分特质（如概念理解导向）随时间略有上升，但可能是任务难度增加的副作用；
  - SWE-Chat 中所有特质随时间几乎平坦或轻微下降，未见明显学习曲线。
- **总体结论**：PTA 是一种灵活、可解释的数据驱动方法，能在人机协作语料中发现有意义的特质，但这些特质目前**不能视为稳定、可迁移的“技能”**，因为跨学期泛化性不足、时间演化不明显，且部分结果存在矛盾。

## 7. 优点

- **数据驱动与自动化**：摆脱了对人工编码框架的依赖，可随 LLM 能力变化自动重新推导特质。
- **可扩展性**：通过 LLM 提示与文本聚类流水线，能够处理大规模会话语料。
- **可解释性**：最终特质以自然语言标题和描述呈现，便于教育者或开发者理解。
- **允许注入领域知识**：通过“透镜”机制融合教育理论或软件工程实践，比纯无监督方法更贴近场景语义。
- **与 PCA 的类比对方法论有启发意义**：将主成分分析思想适配到文本数据上，概念清晰、流程完整，并设计了专门的贪心选择算法来平衡相关性与冗余度。
- **跨场景验证**：同时覆盖教育学习与专业开发两个重要场景，展示了方法的通用性。

## 8. 不足与局限

- **泛化性存疑**：同课程的跨学期验证表现不稳定，说明特质可能依赖具体课程内容或时期，难以推导出通用技能。
- **结果解释的矛盾性**：部分特质即使含义积极，回归系数却为负，可能与外部混杂因素或聚类粒度过粗有关。
- **聚类可能过于激进**：将语义相似但行为不同的观察合并，导致特质定义混杂，降低了解释力。
- **缺少人类评估与严格消融**：特质质量没有经过人工验证，也没有系统研究各阶段设计选择的敏感性。
- **基线覆盖不完整**：SWE-Chat 场景没有可比较的替代特征基线，使得结果强度的解释受限。
- **时间分析存在混淆因素**：如 StudyChat 中后期作业更复杂可能天然导致更多深度提问，无法确定是技能增长还是任务效应。
- **算力资源信息缺失**：无法评估方法的实际计算成本与可重复性要求。
- **应用限制**：主要在计算机科学教育和小规模专业数据上评测，未涉及其他学科或长期实践；结论对“技能”的判定仍然是不确定的。
