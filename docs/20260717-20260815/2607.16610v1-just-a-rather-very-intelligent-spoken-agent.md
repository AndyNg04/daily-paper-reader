## 摘要
长时程AI代理正变得越来越强大，然而它们与用户的互动却出奇地单薄。在大多数工作流程中，用户给出初始指令后，只能收到选择性的文本更新，并且无法清楚了解代理正在做什么或何时该介入。这使得当前代理生态系统中缺少一个部分：一个始终在线的Jarvis式调解器，让用户能够持续联系到代理。这样的调解器应支持与用户的实时语音交互，在不打断工作代理的情况下回答问题，主动报告进度或困惑，并在有用时将用户指导注入代理的执行中。在这项工作中，我们引入了JarvisBench，一个用于衡量长时程代理工作流中调解的双重价值的基准。JarvisBench包含两个互补的轨道：一个代理协作轨道，衡量调解是否改善了下游任务的完成；一个用户交互轨道，衡量调解是否使当前执行对用户更易理解、更具响应性、更易于访问。我们用一个模块化的参考Jarvis原型实例化了该基准，并在OpenClaw中执行的34个纯文本WildClaw任务上对其进行了评估。使用GPT-5.5、Claude Opus 4.7、基于Gemini和基于GPT的工作代理的初步结果表明，Jarvis式调解能够为用户问题提供基于轨迹的响应，并在适当时刻注入稀疏用户指导时提高任务性能。结果还表明，其有效性很大程度上取决于调解器的LLM大脑，这既凸显了这一缺失中间层的前景，也凸显了更广泛社区努力的必要性。演示页面：https://cchen1436.github.io/jarvis

## Abstract
Long-horizon AI agents are becoming increasingly capable, yet their interaction with users remains surprisingly thin. In most workflows, users give an initial instruction, receive only selective textual updates, and lose a clear sense of what the agent is doing or when to step in. This leaves a missing part in the current agent ecosystem: an always-on Jarvis-style mediator that keeps the agent continuously reachable to the user. Such a mediator should support real-time spoken interaction with the user, answer questions without interrupting the worker, proactively report progress or confusion, and inject user guidance back into the agent's execution when useful. In this work, we introduce JarvisBench, a benchmark for measuring the dual value of mediation in long-horizon agent workflows. JarvisBench contains two complementary tracks: an agent-collaboration track that measures whether mediation improves downstream task completion, and a user-interaction track that measures whether mediation makes ongoing execution more understandable, responsive, and accessible to users. We instantiate the benchmark with a modular reference Jarvis prototype and evaluate it on 34 text-only WildClaw tasks executed in OpenClaw. Preliminary results with GPT-5.5, Claude Opus 4.7, Gemini-based, and GPT-based worker agents suggest that Jarvis-style mediation can provide trace-grounded responses to user questions and improve task performance when sparse user guidance is injected at appropriate moments. The results also show that effectiveness depends strongly on the mediator's LLM brain, highlighting both the promise of this missing middle layer and the need for broader community effort. ### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长时程AI代理（Long-horizon AI agents）能力日益强大，但其与用户的交互范式仍停留在“回合制”（turn-based）：用户给出初始指令后，代理长时间自主运行，用户只能收到稀疏的选择性文本更新，难以感知代理正在做什么、何时遇到困难、何时应当介入。
- **核心问题**：当前智能体生态系统中缺失一个“始终在线”的Jarvis式调解层（mediator）——它应作为用户与工作代理之间的持续沟通桥梁，支持实时语音交互、主动汇报进度、回答用户提问，并在适当时机将用户指导注入代理执行过程中。
- **核心论点**：问题不在于代理需要更强的模型或更大的代理团队，而在于用户与代理之间缺少一个连续、可达的通信层。Jarvis式调解不仅能改善用户体验（用户侧价值），还能提升下游任务完成度（代理侧价值），即“调解的双重价值”。

### 2. 方法论：JarvisBench 基准与 Jarvis 参考原型

论文将Jarvis式调解形式化为一个**即插即用（plug-and-play）基准**，而非固定架构，核心设计如下：

#### 2.1 JarvisBench 双轨评估框架

- **Track 1：Agent-Collaboration（代理协作轨道）**
  - 衡量调解器是否提升下游任务完成度。
  - 同一工作代理在两种设置下对比：原始OpenClaw执行循环 vs. 加入Jarvis调解的循环。
  - Jarvis监控工作代理的ReAct轨迹，识别“失败敏感检查点”（如重复工具失败、进度停滞、模糊观察、高风险不可逆操作、低置信度收尾等），触发时向专家用户摘要汇报，将简明反馈注入工作代理上下文。
  - **关键约束**：Jarvis不独立执行任务、不参与辩论、不替换工作代理的计划，仅作为沟通桥梁。
  - **指标**：Overall Score（%）、Relative gain（Δ）、# Full-score、# Interv.（注入的干预次数）。

- **Track 2：User-Interaction（用户交互轨道）**
  - 衡量调解器是否让执行过程对非专家用户更易理解、更具响应性。
  - 固定工作代理，替换Jarvis大脑，隔离评估调解器的用户侧能力。
  - 非专家用户提出短的自然语言问题，交替包含“进度导向问题”和“主题导向问题”，前者测试Jarvis能否基于执行轨迹解释代理当前行为，后者测试Jarvis能否基于原始任务请求回答背景问题。
  - **评估方式**：使用LLM裁判（LLM-judge）分别对进度回答（对照可见轨迹）和主题回答（对照任务上下文）打分。
  - **指标**：Progress（1–5）、Prog. ≥4、Topic（1–5）、Topic ≥4、Latency（语音响应延迟）。

#### 2.2 模块化 Jarvis 参考原型

- **级联全双工语音接口**：流式ASR + 语义语音活动检测（SoulX-Duplug）+ 流式TTS（Chatterbox）。支持始终在线监听、用户打断及Jarvis主动发起语音交互。语音栈可替换为omni模型等替代方案。
- **轨迹监控与上下文管理**：Jarvis接收工作代理的ReAct式文本更新，采用**对话上下文**与**执行上下文**分离的设计。对话上下文存储用户-Jarvis交互记录；执行上下文存储代理行为、观察、失败与当前计划。两者分离保证了对话自然性与轨迹可追溯性。
- **交互检查点机制**：协作暂停机制。Jarvis在选定边界记录当前可观察状态，暂停代理下一步动作，允许用户提问/提供指导/选择不干预，交互结束后恢复执行。两个轨道的检查点调度策略不同：交互轨道固定调度以引出两类问题；协作轨道稀疏且失败敏感触发。

### 3. 实验设计

#### 3.1 数据集与任务套件

- **基准**：WildClawBench（Ding et al., 2026a）——在实时OpenClaw环境中的长时程真实工具型任务。
- **任务范围**：使用34个纯文本任务，排除依赖图像/视频/音频/OCR/视觉解谜/媒体生成能力的任务。覆盖网络搜索、文档综合、多轮沟通、日程安排、代码库与文件检查、安全对齐等场景。
- **工具环境**：浏览器访问、Shell执行、文件系统操作、邮件与日历API。

#### 3.2 用户模拟器

- **非专家用户**：基于GPT的模拟器，知晓原始任务请求但不提供任务求解指导，在交互轨道中最多提出4个问题（进度/主题交替）。
- **专家用户**：轻量级监督者，仅在Jarvis检测到干预值得状态时调用，响应被限制为简明、纠正性内容，确保Jarvis是沟通桥梁而非替代求解器。

#### 3.3 对比系统

- **Agent-Collaboration Track**：4个工作代理（GPT-5.4-mini、GPT-5.5、Gemini-3.1-Pro、Claude Opus 4.7）× 2种设置（原始基线 vs. +Jarvis调解），Jarvis大脑固定为GPT-5.4，专家用户模拟器为GPT-5.4。
- **User-Interaction Track**：固定工作代理为GPT-5.4-mini，替换5种Jarvis大脑：Qwen3-30B-A3B-Instruct、Qwen3-32B-Thinking、GPT-OSS-120B、GPT-5.4-mini、GPT-5.4。

#### 3.4 判断协议

- 协作轨道按WildClaw原始评估协议判定任务完成度。
- 交互轨道由LLM分别用进度/主题两套提示词判定，延迟测量从用户语音问题结束到Jarvis语音回复开始。

### 6. 主要结论与发现

- **调解提升了所有工作代理的任务完成度**：在协作轨道中，Claude Opus 4.7从64.01%提升至75.79%（+11.78%），Gemini-3.1-Pro从43.14%提升至54.78%（+11.64%），GPT-5.5从50.54%提升至58.45%（+7.90%），GPT-5.4-mini从44.24%提升至49.11%（+4.86%）。
- **干预次数稀疏**：每任务约0.5–1.3次干预（18–44次总量），证明提升来自“在关键时刻提供用户指导”，而非以第二个求解器替代工作代理。
- **专家用户的建议无需高度专业**：即使无法访问完整ReAct轨迹，基于Jarvis报告的简单建议也足以帮助工作代理摆脱局部失败模式。
- **调解效果强烈依赖大脑能力**：GPT-5.4作为中介在所有工作中效果最好，弱模型可能出现不当干预；开放模型在进度回答上可具竞争力（GPT-OSS-120B进度得分最高），但主题回答仍明显落后。
- **Jarvis式调解不仅是语音接口问题**：调解器大脑需要在吸收持续变化的执行轨迹的同时维持对话质量，这是当前LLM面临的挑战性场景。
- **语音通道的角色**：语音不是唯一的任务接口，而是持续可用的用户监督通道，其价值在于同时提升用户感知与任务成功率。

### 7. 优点

- **问题定位精准**：识别出现有代理生态系统中被忽视的“中间层”缺口，并给出清晰的系统级定义。
- **双轨评估设计**：同时测量调解对任务完成度与用户体验的双重价值，避免了仅优化一端的偏颇。
- **即插即用基准**：不绑定单一架构，支持替换LLM大脑、语音栈、工作代理、监控策略等组件，具有良好的扩展性与社区可用性。
- **模块化原型**：对话/执行上下文分离、检查点机制、语义VAD的设计具有实操可复现性。
- **丰富的定性分析**：附录中的失败模式分析（GPT-5.5、Claude、Gemini各自的薄弱环节）为后续研究提供了有价值的诊断信息。
- **稀疏干预原则**：限制Jarvis的角色为沟通桥梁，避免了“多代理系统”混淆归因的问题。

### 8. 不足与局限

- **实验规模有限**：仅34个文本任务，未覆盖视觉/音频等模态；结果标记为“preliminary”，缺乏大规模验证。
- **用户模拟器偏差**：用户行为由GPT模拟，与真实用户在语音习惯、提问方式、理解偏差上的差异未知；真实用户体验需进一步测试。
- **算力与成本未披露**：缺乏资源消耗数据，难以评估实际部署成本与可行性。
- **无统计显著性检验**：未报告多次运行的方差、置信区间或显著性指标。
- **强模型依赖**：调解效果高度依赖强闭源LLM，弱模型（如Qwen系列）在交互轨道上表现明显不足，可能限制其在实际系统中的通用性。
- **仅支持文本型工作代理更新**：调解器通过文本ReAct轨迹交互，对多模态工作代理的适配性未验证。
- **初始化不完整任务的局限**：论文明确表示未刻意删除必要初始信息，因此未评估“代理是否应在歧义时主动提问”这一相关但更复杂的方向。

### 总结

JarvisBench首次系统性地定义并度量了长时程AI代理场景中“用户-代理调解层”的价值，通过双轨评估（协作+交互）与模块化参考原型，初步证明了Jarvis式调解在提升任务完成度和改善用户体验两方面的潜力。该工作不仅在工程上提供了可复现的参考系统，还揭示了调解器对LLM大脑能力的强依赖以及不同模型在长时程任务中的典型失败模式。尽管实验规模有限、用户模拟存在偏差，但它为“用户-代理持续沟通”这一缺失的中间层开辟了清晰的研究方向。
