## 摘要
主动智能体被期望通过感知环境上下文来预测用户需求并提供自主协助，而无需明确的指令。这类智能体的一个基本能力是识别并跟踪用户即将发生的事件，从而提供持续且针对特定事件的协助。例如，通过记录计划徒步旅行的时间和地点，智能体可以提前发送天气提醒或在出发前提供导航支持。然而，现有关于主动智能体的工作在很大程度上忽略了以事件为中心的协助，而且主动协助的开放性给可靠评估带来了挑战。为弥补这些空白，我们引入了 ProEvent，这是第一个面向事件中心的基准，旨在评估智能体基于持续的即时通讯聊天记录主动维护用户时间表的能力。ProEvent 提供了综合但逼真的聊天内容，其中考虑了用户之间的动态互动、并发聊天线程以及现实世界中的噪声，并在响应时机、单步响应正确性和多步响应正确性方面评估主动智能体。对八个 LLM 和管道的实验表明，当前智能体经常过度反应，并且在事件取消方面表现不佳。值得注意的是，即使是 GPT-5.1，也只有 26.7% 的场景能正确反应。进一步的定性分析揭示了当前 LLM 作为主动智能体的根本性局限，尤其是在检测隐含事件和从用户第一人称视角进行推理方面。

## Abstract
Proactive agents are expected to anticipate user needs and provide autonomous assistance by perceiving environmental context without explicit instructions. A fundamental capability of such agents is to identify and track users' upcoming events, enabling continuous and event-specific assistance. For example, by recording the time and location of a planned hike, an agent can deliver weather reminders in advance or provide navigation support before departure. However, existing works on proactive agents largely overlook event-centric assistance, and the open-ended nature of proactive assistance poses challenges for reliable evaluation.   To bridge these gaps, we introduce ProEvent, the first event-centric benchmark designed to assess an agent's ability to proactively maintain a user's timetable based on ongoing instant messaging chats. ProEvent provides synthesized yet realistic chats that consider the dynamic interaction among users, concurrent chat threads, and noise in the real world, and evaluates proactive agents on response timing, single-step response correctness, and multi-step response correctness. Experiments on eight LLMs and pipelines reveal that current agents frequently overact and struggle with event cancellation. Notably, even GPT-5.1 only reacts correctly in 26.7% of scenarios. Further qualitative analysis reveals fundamental limitations of current LLMs as proactive agents, particularly in detecting implicit events and reasoning from the user's first-person perspective.

## 2. 论文提出的方法论

**核心任务定义：**

- 任务：给定用户收到的 N 组聊天记录 D，智能体需将用户时间表从状态 Sₜ₋₁ 更新到 Sₜ：`Sₜ = f(Sₜ₋₁, Dₜ)`
- 时间表由若干结构化事件（含开始/结束时间、地点、参与者、描述）组成。
- 智能体输出三类时间表操作：
  - **Insert**：插入新事件
  - **Update**：修改指定事件的属性
  - **Delete**：删除指定事件

**数据构造流程（四步）：**

1. **联系人池构建**：预定义 56 个联系人档案（角色、事件类型），确保对话一致性，覆盖 7 个事件大类、56 个子类别。
2. **聊天合成**：
   - 先生成**调度轨迹**（scheduling trajectory），记录每个时间步的事件真实状态；
   - 轨迹通过三个原子操作生成：简单修改（协商调整）、时间表链接（引用已有/历史事件）、细节移除（暂定事件信息不全）；
   - 基于轨迹构建**聊天骨架**，用 GPT-OSS-120B 生成符合真实状态的对话。
3. **噪声注入**：三类噪声——消息级噪声（无关消息穿插）、聊天级噪声（整段无关聊天）、事件级噪声（时间表中其他事件干扰）；同时注入俚语、话语标记和表情符号以增强真实性。
4. **聊天场景构建**：将多个聊天合并并按固定时间窗口切分，模拟真实世界中的并发聊天线程和周期性上下文采集场景，并基于事件状态差异推导每个时间步的 ground truth 操作。

**评估套件（三个维度）：**

| 维度 | 指标 | 说明 |
|------|------|------|
| 响应时机 | FDR（误检率）、MNR（漏检率） | 衡量智能体是否在正确时间触发/等待 |
| 单步正确性 | Precision、Recall | 每个时间步的操作集合匹配度 |
| 多步正确性 | ESR（事件成功率）、TSR（时间表成功率） | 累积多步后事件的最终正确性，可消解单步评估歧义 |

## 3. 实验设计

**基准与数据规模：**

- ProEvent 包含 **2463 个单步问题**、**1279 个多步案例**，来自 **1249 段高质量聊天**，平均每段 7.86 轮。
- 场景特征：并发聊天 1-3 个（25%）、4-6 个（30%）、7-9 个（24%）、≥10 个（21%）；噪声内容覆盖 38% 无关话题、38% 无关事件讨论、24% 失败的安排尝试。

**对比方法（8 个模型/管道）：**

- 开源 LLM：Qwen-3（8B/32B/235B）、DeepSeek-V3.2、DeepSeek-R1
- 闭源 LLM：GPT-5.1
- 主动管道：Proactive（鼓励更主动响应）、ProCoT（显式推理是否必要响应）

**主要实验内容：**

1. **整体性能对比**（8 个模型 × 6 类指标）
2. **操作类型细分分析**：分别评估 Insert / Update / Delete 的精确率与召回率
3. **复杂因素消融**：
   - 协商轮数（T=3/5/7）对性能的影响
   - 并发聊天数（N=1/3/5）对性能的影响
   - 噪声类型（无关话题 vs 无关事件 vs 失败安排）的影响
4. **隐式指令消融**：对 GPT-5.1 和 Qwen-3-32B 使用"直接表达+更新提示"两个干预，验证模型是否具备潜在推理能力
5. **误差分布分析**：比较 GPT-5.1 与 Qwen-3 的各类错误比例
6. **数据质量评估**：自动结构验证 + 人工标注（标注者 100% 一致）+ GPT-5.4 真实感评判

## 6. 论文的主要结论与发现

1. **当前 LLM 距离可靠主动协助仍有显著差距**：即使最强模型 GPT-5.1，也仅在 **26.7%** 的场景中整体正确（TSR）。
2. **LLM 存在系统性过度反应倾向**：几乎所有模型的 FDR 显著高于 MNR；例如 DeepSeek-V3.2 的 FDR 高达 96.5%，是 MNR（21.9%）的 4 倍以上。ProCoT 策略可将 FDR 从 93.4% 降至 40.8%，说明"先判断必要性再行动"的显式推理可有效缓解过度反应。
3. **隐式事件取消是高难场景**：模型要么漏删、要么在证据不足时误删。强模型（DeepSeek-R1、GPT-5.1、ProCoT）的删除精确率可达 97.1%、77.1%、99.5%，说明强推理能力有助于区分真正取消与暂时性调整。
4. **真实聊天复杂度显著降低性能**：协商轮数增加和并发聊天增多都使召回率下降；噪声内容语义的影响大于噪声位置——与用户无关的事件讨论和失败安排尝试分别显著降低召回率和精确率。
5. **LLM 缺乏第一人称用户视角**：当用户本人退出活动时，模型倾向于执行 Update 将用户从参与者列表中移除，而非执行 Delete 将该事件从用户时间表中删除——表明模型从第三人称而非用户中心视角进行推理。
6. **隐性叙事的指令容易被忽略**：GPT-5.1 虽具备推理能力，但性能高度依赖信息显式程度；通过"更新提示"可将召回率提升 32.0%。
7. **弱模型缺失两种关键推理能力**：与 GPT-5.1 对比，Qwen-3 会出现**时间推理错误**（日期与星期换算错误）和**更新对象不匹配**（修改错误条目或检索无关历史事件），反映出对工具辅助推理和记忆增强推理的需求。

## 8. 不足与局限

- **合成对话仍欠自然**：论文自述合成的对话仍偏结构化、重复性强，缺乏真实人类对话的自发性和多变性，这可能造成评估结果与真实部署场景的偏差。
- **跨聊天协调未建模**：当前假设一个事件的所有协商发生单段聊天内，而现实中的活动策划常涉及跨多个聊天、多位参与者的复杂协调。
- **算力与成本信息缺失**：未披露实验所消耗的 GPU 资源、API 调用成本或时间开销，降低了实验的可复现性参考价值。
- **小样本消融局限**：部分深入实验（如噪声分类、显式表达消融）在 300 或更小的抽样集上开展，统计显著性未作报告。
- **依赖 LLM 作为评估器**：地点正确性判断依赖 GPT-5.1 辅助评估（虽与人类 100% 一致），但可能引入特定模型偏好；噪声注入实验中"用 GPT-5.4 判断真实性"同样存在一致性验证不足的问题。
- **事件取消场景标注定义**：Delete 的正确触发时机依赖人工标注的主观定义，对于"临时调整"与"真正取消"的边界可能存在标注不一致的隐患（尽管标注者取得了一致）。
- **局限于中文/英文语境？** 论文未报告多语言覆盖，当前事件与对话均为英文为主的环境，语言与文化的泛化性有待验证。
