## 摘要
工具使用大语言模型（Tool-use LLMs）越来越多地被要求代表用户执行任务，但现有基准通常侧重于画像回忆、风格模仿、通用工具使用或响应级个性化。我们提出了UserToolBench，这是一个用于工具使用大语言模型中个性化决策的基准。UserToolBench测试模型是否能够从交互历史中推断潜在的用户偏好，识别何时需要澄清，并在信息不完整的情况下生成与用户一致的工具调用轨迹。该基准基于经过隐私净化的真实交互痕迹构建，结合了结构化人物画像、公共API风格的工具生态系统和长周期多轮轨迹。它包含10个用户画像、36个工具集、1,065轮对话、170个独特工具，以及涵盖信息缺失、单工具和多工具场景的评估导向任务类型。与强工具使用大语言模型的实验表明，当前模型在个性化委托方面仍存在困难。多工具协调、缺失约束推断和长周期行为一致性仍是主要瓶颈。这些结果表明，个性化评估应超越询问输出是否听起来像用户特定，转而询问大语言模型是否为其所代表的用户做出正确决策。

## Abstract
Tool-use LLMs are increasingly asked to act on users' behalf, but existing benchmarks usually focus on profile recall, style imitation, generic tool use, or response-level personalization. We introduce UserToolBench , a benchmark for personalized decision making in tool-use LLMs. UserToolBench tests whether a model can infer latent user preferences from interaction history, recognize when clarification is needed, and produce user-aligned tool-call trajectories under incomplete information. The benchmark is built from privacy-sanitized real interaction traces and combines structured persona profiles, public API-style tool ecosystems, and long-horizon multi-turn trajectories. It includes 10 user profiles, 36 tool sets, 1,065 turns, 170 unique tools, and evaluation-focused task types covering lack-of-information, single-tool, and multi-tool settings. Experiments with strong tool-use LLMs show that current models still have difficulty with personalized delegation. Multi-tool coordination, missing-constraint inference, and long-horizon behavioral consistency remain major bottlenecks. These results suggest that personalization evaluation should move beyond asking whether outputs sound user-specific and instead ask whether LLMs make correct decisions for the users they represent.

### 2. 论文提出的方法论：核心思想与关键技术细节

**核心思想：画像隐藏（Profile-Hidden）评测协议**

- **公式化定义**：参考轨迹在画像可见条件下生成：
  y⋆ = f_ref(p, h, q, T)
- **评测时画像不可见**：被测模型仅观测 (h, q, T)：
  ŷ = f_θ(h, q, T)
- 这种构造/评测不对称性，使得模型无法直接复制画像文本，必须从历史交互中恢复偏好信号。

**数据构建流程**：

- **画像来源**：基于隐私净化的真实交互痕迹，经 LLM 辅助抽象为结构化人物画像（包含沟通风格、偏好类别、预算习惯、旅行风格、日程习惯、服务偏好等字段），不保留原始对话。
- **工具生态**：从公开 API 风格的 1,248 个工具名出发，经 LLM 聚类为 618 个唯一工具，再经人工筛选出 36 个场景级工具集，每个工具集含 2.45 个参数槽（平均），并标注"决策相关参数"（如预算、位置偏好、时间范围、服务风格等）。
- **轨迹生成**：采用里程碑式合成流程，四个人物角色协作——用户模拟器（画像一致地发出自然请求）、规划器（画像可见时生成参考工具调用轨迹）、助手 LLM（根据规划器输出回复）、检查器（验证工具选择、参数有效性和画像一致性）。
- **长程构建**：每 4 个里程碑后，已验证的历史记录被并入上下文，促使后续请求依赖更早的交互，形成跨主题依赖和长程一致性场景。

**任务类型设计**：三类共 799 个评测实例（表 2a）：

| 任务类型 | 占比 |
|---|---|
| 信息缺失（Lack-of-Information, LOI） | 34.79% |
| 单工具（Single-Tool, ST） | 33.17% |
| 多工具（Multi-Tool, MT） | 32.04% |

**评测指标**：

- **Exact Trajectory Accuracy（严格）**：要求工具名、所有决策相关参数、工具顺序完全匹配参考轨迹；LOI 任务要求正确判断该澄清还是该推断。
- **Relaxed Task Completion Accuracy（宽松）**：只要求调用合法工具、参数格式正确、可完成任务且不违反可恢复的明确约束，允许替代性工具顺序。

### 6. 论文的主要结论与发现

1. **当前最强模型也远未解决个性化委托**：GLM-5 精确准确率最高仅 49.36%，没有模型达到 50% 以上。
2. **任务可执行 ≠ 决策对齐**：例如 DeepSeek V4 Pro 宽松准确率 72.55% 但精确准确率仅 42.49%，大量输出是"可执行但不符合用户偏好"的。
3. **多工具委托是最大的瓶颈**：精确准确率从单工具的 51.30% 骤降到多工具的 25.24%，涉及工具选择、顺序、参数传递、偏好持续性等多重错误叠加。
4. **缺失约束推断是独立于通用工具能力的技能**：GPT-5.4 的 LOI 准确率（42.22%）最高但总体准确率偏低，Qwen 3.6 Plus 单工具表现好（58.02%）但 LOI 仅 19.52%，说明两条能力线并不重合。
5. **累积历史并不会自动改善表现**：GPT-5.4 从首三分之一 52.12% 降到末三分之一 31.33%，但 Gemini 3.5 Flash 反而提升，说明选择性检索与更新用户状态才是关键。

### 7. 优点

- **画像隐藏协议设计**：避免了传统个性化评测中"画像复制"的捷径，真实考察偏好推断能力；
- **多维度诊断框架**：严格/宽松双指标 + 多标签错误分类 + 严重度审计，弥补了单一参考轨迹的局限性；
- **面向真实任务**：基于隐私净化的真实交互痕迹构建，比纯合成数据更贴近实际使用场景；
- **长程设计**：跨主题依赖（28.17%）和长程依赖（16.90%）标注，能捕捉短期评测无法发现的模型退化；
- **严格的质量控制**：LLM 检查 + 人工验证界面 + 明确的包含/排除标准，保证轨迹有效性和画像一致性；
- **工具轨迹多样性审计**：表 3 证明相同工具集下不同画像确实诱导出不同的工具调用行为，验证了基准的判别力。

### 8. 不足与局限

- **规模有限**：仅 10 个用户画像、300 主题、1,065 轮，覆盖面不足以代表大规模真实用户群体；
- **合成对话的分布偏移**：LLM 生成的对话可能带有提示词特有的词汇和话语规律，与真实用户-助手对话在修复行为、犹豫表达、话题漂移等方面存在差距；
- **单参考轨迹的评估偏差**：精确匹配会惩罚同为偏好兼容的替代轨迹，二分匹配无法表达偏差严重程度（虽有多标签和严重度诊断补充，但未根治）；
- **模拟 API 环境局限**：工具生态是模拟的公共 API 风格环境，不能完全反映真实世界的 API 复杂性和不可预测性；
- **动态偏好覆盖不足**：偏好反转、冲突目标、临时例外、情境依赖优先级等尚未系统化评估；
- **隐私与伦理边界**：尽管画像已做隐私净化，但高度结构化的画像仍可能隐含敏感模式，论文也明确指出不应用于医疗、金融等高风险自主决策场景。
