## 摘要
随着能力的迅速提升，AI智能体可以逐渐从在单个应用内运行转变为跨用户设备随时间采取行动。然而，现有的智能体系统在这种场景下仍存在不足。这是因为观察结果分散在不同的设备和时刻，但主流系统并未围绕这一事实设计：将设备视为工具的单一智能体缺乏对所有设备跨时间的有效状态管理，而多智能体系统虽在智能体之间进行协调，但未维护跨设备、跨时间请求所需的紧凑携带状态。我们认为，智能体应维护一个有效设计的状态，以紧凑、可行动的形式组织交互证据、陈述事实和持续请求，从而根据当前观察决定其行动。为了比较状态设计，我们构建了一个跨设备和时间的用户-智能体交互基准。我们将这一原则实例化为Unified Agent，一个跨设备和时刻携带交互证据的有状态智能体，并将其与当前观察结合以采取行动。在默认设置下，它显著优于我们对四种已发表设计的改编。在多模态大语言模型（MLLM）家族、能力和推理努力的变化中，它始终领先于所有对比系统，证明了状态设计优势在MLLM设置中稳健。我们的代码和数据将在GitHub上公开提供。

## Abstract
As capabilities rapidly increase, AI agents can move from running inside one app to acting across a user's devices over time. Yet existing agent systems still fall short in this scenario. This is because observations are scattered across devices and moments, but mainstream systems are not designed around this fact: a single agent that treats devices as tools lacks effective state management for all devices across time, and multi-agent systems coordinate across agents but do not maintain the compact carried state a cross-device, cross-time request needs. We argue that the agent should maintain an effectively designed state that organizes engagement evidence, stated facts, and the standing request in a compact, action-ready form for deciding its action given the current observation. To compare state designs, we construct a benchmark of user-agent interaction across devices and time. We instantiate this principle in Unified Agent, a stateful agent that carries interaction evidence across devices and moments and uses it with the current observation to act. In the default setting, it significantly outperforms our adaptations of four published designs. Across changes in multimodal large language model (MLLM) family, capability, and reasoning effort, it remains ahead of all compared systems, demonstrating that the state-design advantage is robust across MLLM settings. Our code and data will be publicly available on GitHub.

## 1. 核心问题与整体含义

随着多模态大语言模型（MLLM）能力的快速增强，AI 智能体有望从“在单一 App 内运行”升级为“跨用户多个设备、跨时间段地管理任务”。然而，现有主流智能体系统并未围绕这一场景设计：

- **观测分散性**：用户的交互信息散布在不同设备和不同时刻，任何单一时刻的局部观测（如某个设备摄像头画面）都不足以支撑后续决策。
- **单智能体系统的问题**：将设备视为工具的单一智能体，缺乏对全部设备跨时间的有效状态管理，无法在关键线索消失后（如用户不再指向某设备、屏幕已熄）继续回答依赖先前证据的请求。
- **多智能体系统的问题**：多智能体虽可在智能体间协调，但未维护跨设备、跨时间请求所需的紧凑携带状态（carried state），仍会因信息分散在多个设备与时刻而失败。

论文的核心论点：**跨设备智能体必须维护一个良好设计的状态**——将交互参与证据（engagement evidence）、用户陈述的事实（stated facts）和持续请求（standing request）组织为紧凑、可直接用于行动的形式，以便在给定当前观测时做出正确决策。

## 2. 方法论

### 2.1 核心思想：显式携带状态（Carried State）

Unified Agent 维护一个跨时间、跨设备更新的显式状态 \(S_t\)，随每个时刻的新观测 \(O_t\) 被折叠更新，并连同当前观测一同用于决策：

- **状态更新**：\(S_t = U(S_{t-1}, O_t)\)
- **行动决策**：\(a_t = D(S_t, O_t)\)

### 2.2 状态的三条信息流

| 信息流 | 作用 | 内容 |
|--------|------|------|
| 交互参与证据（Engagement evidence） | 支持识别相关设备 | 设备关联的交互线索（如指向、身体朝向、手在设备上的接触次数），按设备累计 |
| 陈述事实（Stated facts） | 支持后续信息回忆 | 按主题、在可识别时按设备存储用户明确陈述的事实 |
| 持续请求（Standing request） | 支持决定下一步行动 | 最近一次可执行的用户请求 |

### 2.3 行动流程

Unified Agent 遵循“感知–折叠–行动”（perceive–fold–act）流水线，六个任务组织为观察–思考–行动三层：

1. **观察层**：检测用户和设备；
2. **思考层**：识别正在交互的设备（Eng）、推断用户意图（Int）、回忆相关信息（Inf）；
3. **行动层**：选择响应的设备（Rsp）、决定下一动作（Nxt）。

Unified Agent 通过语言指令指定哪些设备应响应以及做什么，具体执行由各设备自身的原生控制完成，从而保持与异构设备的兼容性。

## 7. 优点

1. **问题定义清晰**：首次明确提出“跨设备、跨时间用户–智能体交互”问题，并将六个决策任务（Eng、Int、Inf、Rsp、Nxt）系统化组织。
2. **状态设计具有理论依据**：以“证据导向”而非“答案缓存”的方式设计状态，兼顾紧凑性与可行动性；状态规模保持有界，而 Full context 线性增长（最终达到 Unified Agent 状态的 11 倍）。
3. **基准构建严谨**：匹配对设计、构造期验证、严格的信息隔离（评测系统无法接触 ground truth）保证了评估的精确性和公平性。
4. **消融设计精准**：每个变体仅改变一个指定因素，有效隔离各状态成分的因果贡献。
5. **泛化验证充分**：跨 MLLM 家族、能力、推理努力以及真实照片场景的多维验证增强了结论的可信度。
6. **隐私友好**：显式紧凑状态比保留原始历史记录更符合数据最小化原则，且可审查、可选择性修正。
7. **不依赖额外机制**：不同于需要检索器、专用记忆网络或多智能体调度的方案，Unified Agent 仅凭所携带状态的表示与使用方式即可获得性能优势，系统复杂度增加极小。
