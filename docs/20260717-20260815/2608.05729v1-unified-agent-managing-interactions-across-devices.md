## 摘要
随着能力的迅速提升，AI智能体可以逐渐从在单个应用内运行转变为跨用户设备、跨时间地采取行动。然而，现有的智能体系统在这种场景下仍显不足。原因是观测数据分散在不同的设备和时刻，但主流系统并非围绕这一事实设计：将设备视为工具的单智能体缺乏对所有设备跨时间的有效状态管理，而多智能体系统虽能协调各智能体，却无法维护跨设备、跨时间请求所需的紧凑携带状态。我们认为，智能体应维护一种有效设计的状态，将交互证据、已陈述事实和当前请求以紧凑、可行动的形式组织起来，以便根据当前观测决定其行动。为了比较不同状态设计，我们构建了一个跨设备和时间的用户-智能体交互基准。我们将这一原则实例化为统一智能体（Unified Agent），一个带有状态的智能体，它跨设备和时刻携带交互证据，并结合当前观测进行行动。在默认设置下，它显著优于我们改编的四种已发表设计。在跨多模态大语言模型（MLLM）系列、能力和推理努力的变化中，它始终领先于所有对比系统，表明状态设计优势在多种MLLM设置下具有鲁棒性。我们的代码和数据将公开在GitHub上。

## Abstract
As capabilities rapidly increase, AI agents can move from running inside one app to acting across a user's devices over time. Yet existing agent systems still fall short in this scenario. This is because observations are scattered across devices and moments, but mainstream systems are not designed around this fact: a single agent that treats devices as tools lacks effective state management for all devices across time, and multi-agent systems coordinate across agents but do not maintain the compact carried state a cross-device, cross-time request needs. We argue that the agent should maintain an effectively designed state that organizes engagement evidence, stated facts, and the standing request in a compact, action-ready form for deciding its action given the current observation. To compare state designs, we construct a benchmark of user-agent interaction across devices and time. We instantiate this principle in Unified Agent, a stateful agent that carries interaction evidence across devices and moments and uses it with the current observation to act. In the default setting, it significantly outperforms our adaptations of four published designs. Across changes in multimodal large language model (MLLM) family, capability, and reasoning effort, it remains ahead of all compared systems, demonstrating that the state-design advantage is robust across MLLM settings. Our code and data will be publicly available on GitHub.

# 统一智能体：跨设备管理交互（Unified Agent: Managing Interactions across Devices）

## 1. 核心问题与研究动机

- **问题背景**：AI 智能体的能力日益增强，正在从"在单个 App 内运行"走向"跨用户多个设备、跨时间持续服务"。例如，用户可能在电脑、笔记本、手机等多个设备上反复比较餐厅信息，之后只凭一句"帮我订我一直在看的那家餐厅"下达请求，且此时已遗忘餐厅名称，也不再指明具体设备。
- **核心矛盾**：观测（observation）天然地分散在不同的设备和时间点，而现有主流智能体系统并未围绕这一事实设计：
  - **单智能体系统**：将设备视为工具，但缺少跨时间、跨设备的状态管理，每个请求都被当作全新请求，一旦关键线索（如手指指向、亮屏）消失，历史证据无法回溯。
  - **多智能体系统**：虽然能在多个智能体之间协调分工，却不维护跨设备、跨时刻请求所需的**紧凑携带状态（compact carried state）**，在请求依赖分散证据时同样会失效。
- **核心主张**：智能体应维护一个**有效设计的显式状态**，将交互参与证据（engagement evidence）、已陈述事实（stated facts）和待办请求（standing request）组织成紧凑、可行动（action-ready）的形式，与当前观测共同驱动决策。

## 2. 方法论

### 2.1 核心思想

Unified Agent 是一种**有状态智能体**，其核心是携带一个跨设备、跨时间更新的紧凑状态 $S_t$。状态保存的是后续动作所需的"证据"，而非全部原始历史，也不存储解码后的最终答案。

### 2.2 状态表示

状态 $S_t = (C_t,\ P_t,\ K_t,\ r_t)$ 由四个部分组成：

| 组成部分 | 符号 | 含义与作用 |
|---|---|---|
| 活动计数（活动证据） | $C_t$ | 每个设备上非空活动观测的累计计数，用于衡量用户对各设备的参与强度 |
| 指向/接触线索 | $P_t$ | 保留"指向设备"的线索（渲染场景中为指向手势，真实照片中为手与设备的接触），作为细粒度参与证据 |
| 陈述事实 | $K_t$ | 按"设备-话题"对存储的首个陈述事实；设备未知时按话题存储，保证同一话题在不同设备上的取值可区分 |
| 待办请求 | $r_t$ | 记录最近一次可执行的请求动作（及查询话题） |

### 2.3 状态更新与决策流程

- **状态更新**（Folding）：每个时刻 $t$，智能体将当前观测 $O_t$ 折叠进状态：
  - $S_t = U(S_{t-1},\ O_t)$
  - 更新规则：活动与指向线索更新参与证据；在活动非空的帧中，仅当某个"设备-话题"对尚无事实记录时才新增事实；新的可执行指令替换待办请求。
- **行动决策**（Acting）：智能体同时读取更新后的状态与当前观测以输出行动：
  - $a_t = D(S_t,\ O_t)$
  - 当前观测 $O_t$ 提供当下信息，状态 $S_t$ 提供跨时刻累计证据，两者互补；设备能力不存储在状态中，而是单独提供。
- **行为接口**：智能体通过共享决策接口以自然语言指定哪些设备做出响应及执行什么操作，各设备使用自身的原生控件完成指令执行。

### 2.4 六项任务框架（Observe–Think–Act）

论文将每个交互时刻组织为六个可独立评估的任务（图 2）：

1. **检测用户和设备**（Detect）——感知任务
2. **识别参与设备**（Eng）
3. **推断用户意图**（Int）
4. **回忆相关信息**（Inf）
5. **选择响应设备**（Rsp，允许空集）
6. **决定下一步动作**（Nxt）

## 3. 实验设计

### 3.1 Benchmark：UA-BENCH

- **构成**：100 个匹配对（matched pairs），共 200 个片段（episodes），覆盖多种室内场景、布局、设备摆放、话题与动作。
- **场景形式**：3D 渲染的家庭场景（基于 Habitat / HSSD-200），包含渲染用户、屏幕设备（电脑、笔记本、手机）及可选取物机器人（Unitree G1）。
- **片段结构**：每个片段 12 帧。开场帧（f1）、请求帧（f10–f11）与回忆帧（f12）在匹配对内完全共享；中间帧（f2–f9）交换参与设备角色及关联数值。
- **匹配对设计**：两段片段共享相同结构，但将参与设备与干扰设备角色互换，使 Eng、Inf、Rsp、Nxt 目标不同，而 Int 保持不变，从而精确隔离"早期交互证据"对后期决策的影响。
- **观测输入**：仅设备摄像头视图 + 用户话语 + 公开任务描述（设备名册与能力卡）；语义地图、渲染元数据等仅在构建期用于验证，**不提供给被测系统**。
- **真实照片补充**：一个"家庭桌面预订餐厅"场景的匹配对，验证了方法在实际照片上的有效性。

## 6. 主要结论与发现

1. **状态组织设计的核心优势**：Unified Agent 在默认设置下的总体表现显著优于所有对比系统，包括最强的 Full context 控制组，Overall 得分为 0.668，与已发表基线的总体增益区间为 0.194–0.408（95% CI 全部 > 0）。在保留更少信息的条件下实现了更高性能。
2. **不同任务需要不同信息**：消融实验表明，参与证据（含计数与指向）支撑 Eng 识别，先前状态支撑 Inf 回忆，设备能力约束支撑 Rsp 路由。
3. **状态设计优势跨 MLLM 设置稳健**：在模型家族（Gemini vs. GPT）、能力（Luna vs. Sol）与推理努力（低 vs. 中）的所有 4 种设置中，Unified Agent 均保持最高总体分，排序稳定。
4. **真实照片上同样有效**：Unified Agent 能基于累积参与证据识别参与设备并回忆正确时间，而其他对比系统（包括 Full context）均未能保持该能力。

## 7. 优点

- **问题定义清晰且有价值**：明确提出"跨设备、跨时间用户-智能体交互"问题，并给出可操作的问题形式化与六任务分解。
- **状态设计精妙**：三层状态（参与证据、陈述事实、待办请求）各司其职，紧凑且可行动，不存储原始历史，有界增长，显式可审计、可选择修正。
- **方法轻量普适**：无需学习记忆、检索或微调，仅依赖提示设计，兼容不同 MLLM 与智能体系统。
- **基准设计严密**：匹配对设计精确隔离早期交互证据变量；构造期监督信息与评估期输入严格分离；所有评测目标由构造确定，无模型标注偏差。
- **实验方法严谨**：多种 MLLM 设置验证泛化；共享感知协议确保公平对比；统计检验充分（聚类 bootstrap + Holm 校正 + 稳健性检验）。
- **隐私友好**：数据最小化设计，仅保留行动所需的最小证据，而非完整交互历史。

## 8. 不足与局限

- **资源信息缺失**：未报告任何 GPU 型号、训练/推理时间、能耗等算力信息，不利于复现成本评估。
- **合成基准的生态效度问题**：UA-BENCH 基于 3D 渲染场景，与真实世界交互仍有差距；真实照片部分仅为单个案例，不足以证明大规模实用性。
- **基线改编可能不尽公平**：论文承认对已发表基线进行了适配，但适配版本未必代表各基线的最优状态。
- **感知错误的下游放大**：Eng 等任务依赖共享感知记录，当感知不准确时（如 Gemini 的指向设备准确率仅 70.4%），状态方法的下游收益可能被低估；论文未深入分析感知错误对状态更新的级联影响。
- **状态设计的语义重叠问题**：活动计数与指向线索之间的相关性未被彻底分析，两者可能冗余而非互补。
- **范围限制**：仅研究"一个用户-一个智能体"场景，未涉及多用户共享设备、多智能体协作或更复杂的真实物理环境（如用户移动、多人对话）。
- **未来工作方向**：探索更丰富的状态结构、跨设备事实的一致性维护、隐私保护下的选择性遗忘，以及将方法扩展到更多 MLLM 与真实世界场景。
