## 摘要
基于LLM的聊天系统已成为设计实践中的宝贵工具，能够实现快速构思和灵活的任务支持。然而，这些系统将设计师的话语视为通用序列，通过近期性而非对话者如何组织知识的模型来维持上下文。在设计对话中，这种差距会随着关系上下文在轮次之间衰减、相同词语在不同设计师之间得不到消解，以及对话循环或重启而非深化而加剧。我们提出了CogChat，一个实时聊天框架，将对话式AI落地于根据每位设计师输入构建的个人异构知识图谱中。该系统将类型化实体和关系提取到异构图中，然后应用HGT（异构图形变换器）选择结构相关的节点用于响应生成，并生成意图性和探索性两类探询问题。技术评估表明，基于HGT的实体选择优于无落地LLM交互和朴素知识图谱增强，后者引入的噪声会降低响应质量。一项针对九位专业设计师的受试者内研究表明，将对话落地于关系结构化、设计师特定的语义上下文，可以改善上下文保留、个性化意图解释和对话深度，同时降低认知负荷。这些发现表明，将设计师表达的概念和关系结构化为动态知识图谱，可以保留跨轮次逐渐消退的关系上下文，为基于LLM的交互中的长期上下文管理指明了一条基于图谱的方法。

## Abstract
LLM-based chat systems have become valuable tools for design practice, enabling rapid ideation and flexible task support. Yet these systems process designer utterances as generic sequences, maintaining context through recency rather than through any model of how the speaker organizes knowledge. In design conversation, this gap compounds as relational context decays between turns, identical words go unresolved across designers, and the conversation loops or restarts rather than deepens. We present CogChat, a real-time chat framework that grounds conversational AI in a personal heterogeneous knowledge graph constructed from each designer's input. The system extracts typed entities and relations into a heterogeneous graph, then applies a HGT (Heterogeneous Graph Transformer) to select structurally relevant nodes for response generation and to generate both intentional and exploratory probing questions. Technical evaluation shows that HGT-based entity selection outperforms both ungrounded LLM interaction and naive KG augmentation, which introduces noise that degrades response quality. A within-subjects study with nine professional designers indicates that grounding conversation in a relationally structured, designer-specific semantic context improves context retention, personalized intent interpretation, and conversational depth while reducing cognitive load. These findings suggest that structuring a designer's expressed concepts and relations as a dynamic knowledge graph can preserve relational context that fades across turns, pointing toward a graph-grounded approach to long-term context management in LLM-based interaction.

# CogChat 论文核心总结

## 一、核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的 LLM 对话系统在应对设计对话时，存在一个根本性缺陷——**缺乏对用户（设计师）知识组织方式的建模**。系统仅将用户话语视为普通文本序列，通过“近期性（recency）”而非“关系结构（relational structure）”维护上下文。
- **三大具体失败表现**：
  1. **信息丢失**：跨轮次的关系上下文不断衰减。例如，系统会忘记“warm”指的是触感纹理而非色温，这种情境化含义正是设计推理的核心。
  2. **个性化失败**：不同设计师对同一词语（如“heavy”）有不同理解（视觉密度 vs 信息过载），但系统只做通用语义处理。
  3. **效率低下**：由于没有保留上下文和消解词义，设计师需要反复解释已确立的内容，对话陷入循环而非深化。
- **整体含义**：这些问题的根源在于**缺乏对设计师认知空间的持久、结构化表示**。设计认知是异质的——感知、语义和功能元素共存于同一判断中。将这种结构压平为 token 序列，丢失了设计推理的连贯性。作者提出，**保留关系上下文需要的是结构，而不仅仅是更大的上下文窗口**。

## 二、提出的方法论：核心思想、关键技术细节

- **核心思想**：构建一个**实时、设计师个人化的异构知识图谱（KG）**，将设计师输入中的实体和关系结构化，并用 **HGT（Heterogeneous Graph Transformer）** 对图谱进行嵌入，从而基于图谱结构选择相关节点注入 LLM，驱动响应生成和探询提问。
- **系统管线（每轮对话执行五步）**：
  1. **知识图谱构建**：基于 GraphRAG 从用户话语和助手响应中提取类型化实体和关系（设计导向本体：CONCEPT、DESIGN_ELEMENT、MATERIAL、PROPERTY、ACTION），节点用 512 维 CLIP（ViT-B/32）嵌入初始化。跨轮次通过 `answered_by` 边显式保留“问题→回答”的关系。
  2. **链接集创建与子图采样**：构造正链接（同一话语共现或设计师积极反馈强化）和负链接（硬负样本：结构邻近但未连接的同类实体、被 dislike 的实体、聚类内未连接节点；随机负样本）。然后对当前消息提到的实体进行 1-hop 和 2-hop 子图采样，按边权重比例采样以保留反馈强化的连接。
  3. **HGT 嵌入**：对采样子图应用 HGT，使用**类型特定的 Query/Key/Value 投影**和**关系特定的注意力权重**。模型配置为 3 层、8 个注意力头，输出 256 维嵌入。每轮基于最新链接集用 **BCE loss + 排序 loss** 进行增量训练，使嵌入空间持续适应用户概念演变。冷启动时（<5 节点）直接注入全部节点，跳过 HGT。
  4. **上下文响应生成**：计算消息嵌入与各节点 HGT 嵌入的**余弦相似度**，选择 top-𝑘（约 20）实体注入 LLM 提示。每个实体配有类型、关键关系、子图邻域的自然语言摘要，提供关系化上下文。另有**连续性分数**（连续度 = 节点集合重叠 + 嵌入相似性的加权组合），低于阈值时在提示中附加上下文警告。
  5. **探询问题生成**：对当前消息嵌入与所有节点嵌入的相似度做 **min-max 归一化**，按分布的均值 𝜇 和标准差 𝜎 将节点分为三区域：
     - **≥ 𝜇+𝜎** → 意图性问题（针对高相关但未充分说明的概念，解决歧义）
     - **𝜇±𝜎 之间** → 探索性问题（结构相关但尚未讨论的领域）
     - **< 𝜇−𝜎** → 排除（上下文不相关）
     每个问题附 2–3 个建议答案，设计师的回应进入下一轮抽取，形成正反馈环。
- **公式要点**：
  - HGT 注意力：`Attention(v,e,u) = softmax( (W_Q_τ(v) h_v)^T (W_K_τ(u) h_u) / √d_k · W_R_φ(e) )`——类型与关系特定的注意机制。
  - 相关性：`rel(v) = cos(h_q, h_v)`——嵌入余弦相似度。
  - 连续性：`continuity = α · (|N_recent ∩ N_current| / |N_recent|) + (1−α) · cos(h̄_recent, h̄_current)`。

## 六、主要结论与发现

- **技术层面**：HGT 选择性实体落地在四个基准上均优于无落地（Baseline）和全量注入（KG-only）。全量图注入（KG-only）会引入噪声，在模糊查询上误差累积；HGT 通过过滤使上下文聚焦。增益随任务复杂度增加而扩大（Chat Hard Δ23.2，Reasoning Δ22.4）。长程记忆基准中，KG+HGT 在 LongMemEval（Overall 62.3 vs 57.0 vs 30.7）和 LoCoMo（88.7 vs 86.1 vs 84.2）均领先。
- **用户研究结论**（对应三个研究问题）：
  - **RQ1 上下文保留**：CogChat 显著减少轮次（5.1 vs 9.4，−45.9%）和会话数（1.0 vs 2.1），负反馈大幅降低（0.22 vs 3.67 次）；BERTScore 语义相似度最高（.887），Token 级 IoU 近两倍于 KG-only——HGT 能复用设计师的词汇而非泛化改写。
  - **RQ2 个性化解释**：CUQ 评分三条件均显著，CogChat 最高（77.8 vs 64.9 vs 46.7）；探询成功率 .70 vs .55 vs .17，表明 HGT 生成的探询问题被感知为高度相关；访谈中设计师反映 CogChat 能保留“water properties”等个性化语义并转化为具体设计选项。
  - **RQ3 认知负荷与深度**：NASA-TLX 中 Mental Demand、Effort、Frustration 均显著降低（KG-grounded 条件优于 Baseline），任务完成时间显著缩短（14.1 vs 17.9 vs 19.5 分钟）；8/9 参与者认为 CogChat 对话最深。
- **关键论断**：**KG 结构是上下文保留的基础，HGT 嵌入选择是将其转化为可用上下文的关键**。并非“记忆容量”而是“上下文策展（context curation）”决定了 LLM 设计对话的质量瓶颈。

## 七、优点（方法/实验亮点）

- **新颖的问题定位**：准确识别出 LLM 对话系统在设计中失败的结构性根源（无认知结构建模），而非单纯归因于上下文窗口。
- **方法设计优雅**：将“设计师表达的关系”而非“行为信号”作为个性化基础；HGT 的类型/关系特定注意力天然适配设计认知的异质性。
- **探询机制有理论依据**：区分意图性（解决歧义）和探索性（扩展概念边界）两类问题，且由图谱分布的统计特性驱动分区——自适应于对话阶段和图的稀疏/稠密状态。
- **消融设计清晰**：三条件对比（B / K / H）有效分离了“图谱记忆”与“选择性落地”的各自贡献，且排除了 LLM 熟悉度混淆。
- **人机协同反馈环**：探询答案回馈到下一轮抽取，图谱通过用户正负反馈调整边权重，形成持续演化的描述符。
- **界面设计贴心**：双击词语查看图谱关系，让设计师能验证系统理解是否与自己的意图一致，增强透明度和信任。

## 八、不足与局限（实验覆盖、偏差风险、应用限制）

- **图谱抽取依赖底层 LLM**：抽取依靠 GPT-4o 的 GraphRAG，在高度抽象或纯视觉对话中可能无法捕捉细腻视觉意图；建议未来探索多模态知识图谱。
- **冷启动局限**：图很小时（<5 节点）CogChat 相对强 LLM 的优势很小，需待图结构积累后才彰显；未说明何时节点数达到“足够”水平。
- **样本量与任务时长**：仅 9 人、单会话短任务；效果量虽大（W>0.7），但缺乏长期纵向验证，无法证明“长期个性化”。
- **图衰减未解决**：如何修剪过时节点、消解矛盾约束、处理意图转向（pivot），仍是长期部署的未解难题。
- **评估偏差**：侧重过程、感知和自我报告，缺乏对生成设计工件本身（如最终图像）的盲审客观评价。
- **变量混淆**：探询问题和偏好组织在三个条件间部分共享，未能完全分离其独立贡献；未来需针对性消融。
- **应用范围**：贡献集中于关系稠密、歧义重的对话场景；对简单保留任务，KG-only

对简单保留任务，KG-only（全量注入）或许已足够，HGT 的选择性优势可能不显著；但缺乏对此类场景的针对性验证。整体来看，CogChat 在关系复杂、歧义密集的设计对话中表现出显著优势，其核心贡献在于用结构化的图谱记忆和基于 HGT 的上下文策展替代了单纯的上下文窗口扩展，为面向专业领域的个性化对话系统提供了新范式。不过，抽取质量、冷启动和长期演化等问题仍是制约其实际部署的关键。
