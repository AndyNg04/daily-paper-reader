## 摘要
工具使用型代理中的间接提示注入是一个具体的生产威胁：LLM代理从集成（通过工具调用访问的第三方服务，如Gmail、Salesforce或Jira）中读取响应内容，用户既不编写也不控制这些内容。现有基准测试低估了这种威胁：大多数仅覆盖少数集成，且同一攻击载荷在多次运行中重复使用，开源防护模型则是在聊天风格数据而非工具响应内容上训练的。我们提出了AGENTREDBENCH，一个动态的LLM驱动的红队基准测试，涵盖了9个功能族、24个企业集成中的215个微妙的不明确授权场景（用户请求授权边界处的攻击）以及5种攻击类型。在八模型面板（Anthropic、OpenAI、Google）上，无防护的攻击成功率（ASR）从32%（Claude Sonnet 4.6）到81%（Gemini 3 Flash）不等。为了使场景集不进入训练语料库并保持标题ASR随时间变化的意义，我们公开了代码库、集成模式和AGENTREDGUARD模型；标准场景通过维护者中介渠道进行评估，并具有不可变的版本控制。我们随基准测试一同发布了AGENTREDGUARD：一个在包含多种集成的对抗性工具响应内容语料库上训练的防护模型。AGENTREDGUARD将面板ASR从69.9%降至2.4%，假阳性率为0.37%，在检测性能的两个指标上均优于所有具有非平凡检测能力的开源基线（Llama Guard、PromptGuard 2、ProtectAI）。跨集成和跨攻击类型的保留测试均证实了这种增益可推广到训练子集之外。

## Abstract
Indirect prompt injection in tool-use agents is a concrete production threat: LLM agents read from integrations (third-party services such as Gmail, Salesforce, or Jira accessed through tool calls) whose response content the user neither writes nor controls. Existing benchmarks under-measure the threat: most cover only a handful of integrations with the same attack payload replayed across runs, and open-source guards are trained on chat-style data rather than tool-response content. We introduce AGENTREDBENCH, a dynamic LLM-driven redteaming benchmark of 215 subtle underspecified authorization (attacks at the boundary of what the user's request authorises) scenarios across 24 enterprise integrations in nine functional families and five attack types. Across an eight-model panel (Anthropic, OpenAI, Google), no-guard ASR (attack success rate) ranges from 32% (Claude Sonnet 4.6) to 81% (Gemini 3 Flash). To keep the scenario set out of training corpora and preserve headline ASR meaning over time, we release the codebase, integration schemas, and AGENTREDGUARD model openly; the canonical scenarios are evaluated through a maintainer-mediated channel with immutable versioning. We release AGENTREDGUARD alongside the benchmark: a guard trained on an integration-diverse corpus of adversarial tool-response content. AGENTREDGUARD cuts panel ASR from 69.9% to 2.4% at 0.37% false-positive rate, outperforming every open-source baseline with non-trivial detection (Llama Guard, PromptGuard 2, ProtectAI) on both axes. Cross-integration and cross-attack type holdouts both confirm the gain transfers beyond the training subset.

## 1. 核心问题与整体含义（研究动机和背景）

LLM 智能体在 SaaS 集成场景中面临严重的间接提示注入威胁：智能体通过工具调用读取来自第三方服务的响应内容（如 Gmail、Slack、Salesforce、Jira 等），用户无法控制这些内容，而攻击者可以通过向这些服务写入恶意数据来操纵智能体行为。现有基准测试存在三大局限：覆盖集成数量少（通常仅几十个）；攻击内容模板化、缺乏动态性；缺乏对多集成链式攻击的评估。同时，开源安全防护模型（如 Llama Guard、WildGuard）均基于聊天对话数据训练，对工具响应内容这一分布几乎完全没有检测能力。因此，需要更全面、动态的基准测试以及专门针对工具响应层的防护模型。

## 2. 方法论

### 核心思想
- 提出 **AGENTREDBENCH**：一个 LLM 驱动的**动态红队基准测试**，攻击内容由攻击 LLM 根据集成模式、攻击类型和裁判反馈逐次生成，而非固定模板。
- 提出 **AGENTREDGUARD**：一个轻量级微调文本分类器，在包含对抗性工具响应内容的多集成语料上训练，用于在推理时拦截注入攻击。

### 关键技术细节
1. **攻击分类（5 种类型）**：
   - **主动攻击类型（3 种）**：
     - `output_channel_url_relay`：在回复中嵌入攻击者可控的 URL。
     - `destination_hijack`：替换写操作的目标（收件人、频道、负责人）。
     - `content_hijack`：在写操作正文中植入攻击者内容（目的地正确但内容被控制）。
   - **边界委托模式（2 种）**：
     - `tool_argument_hijack`：诱导设置额外工具参数（如优先级）。
     - `tool_family_creep`：诱导调用同一集成中的其他工具。这些模式在所有模型中失败率极低（0-2%），用以证明显式约束的有效性。

2. **动态攻击生成**：攻击 LLM（固定为 Claude Haiku 4.5）根据场景元数据、集成模式和裁判反馈，在 5 次尝试预算内生成攻击载荷。86% 的场景在第一次尝试即成功，60% 的失败尝试后内容有实质性改变。

3. **AGENTREDGUARD 架构**：
   - 基础模型：**MiniLM (23M 参数)** 为主，对比 **DeBERTa-v3-small (142M)**。
   - 输出攻击概率分数，决策阈值默认 0.5，保守部署点 0.99。
   - 训练数据：14,846 条攻击行 + 4,807 条良性生产形状语料（包含真实 HRIS/ATS/CRM 硬负样本、Haiku 生成的结构模式等）。
   - 四个集成（slack, linear, salesforce, calendar）完全保留用作跨集成泛化测试。

4. **流程**：攻击 LLM → 编排器注入 → 目标智能体运行（可选加防护） → LLM 裁判评分。

## 3. 实验设计

### 数据集/场景
- **标准场景集**：215 个微妙不明确授权攻击场景，覆盖 **24 个企业集成**（9 个功能族：通信、生产力、日历、CRM、存储、ATS、HRIS、可观测性、营销等）。
- 攻击类型分布：92 个 URL 中继、42  个目的地劫持、81 个内容劫持（边界委托模式因模型均失败而少用）。
- 额外：**49 个多集成链式攻击场景**（作为起点，但主要实验未完成评估）。

### 基准（被评估模型）
- 8 个前沿 API 模型：Anthropic（Claude Sonnet 4.6, Haiku 4.5）、OpenAI（GPT-5.4, GPT-5.4-mini, GPT-5.4-nano）、Google（Gemini 3.1 Pro, Gemini 3 Flash, Gemini 3.1 Flash Lite）。

### 对比方法
- **四个开源防护**：Llama Guard 3 (8B)、PromptGuard 2 (22M)、ProtectAI (184M)、WildGuard (7B)，均使用阈值 0.5 评估。

- **攻击成功率 (ASR)**：包含 partial 判决的场景。
- **假阳性率 (FPR)**：在 4,807 条良性语料上测量。

## 6. 主要结论与发现

### 无防护风险严重但不平均
- 无防护 ASR 从 **Claude Sonnet 4.6 的 32%** 到 **Gemini 3 Flash 的 81%**。
- 对齐训练（而非规模）是主要原因：Sonnet 与 Haiku 同为 Anthropic 但差距 47.4 个百分点。
- 7 个模型 ASR 均超过 60%，迫切需要推理时防护。

### AGENTREDGUARD 显著优于所有开源基线
- **检测性能**（保留测试集）：
  - AGENTREDGUARD-MiniLM: TPR **99.75%**，FPR **0.37%**。
  - ProtectAI 是唯一有非零检测的开源基线（TPR 15.03%，但 FPR 高达 25.05%）。
  - Llama Guard、PromptGuard 2、WildGuard 的 TPR 均 < 0.3%。
- **ASR 降低**：将面板平均 ASR 从 69.9% 降至 **2.4%**，降低 67.5 个百分点。所有 8 个模型均大幅降低，Sonnet 降到 0%。
- **效用**：在 2,500 条生产硬负样本上 FPR 为 0%，无过度拒绝；延迟仅 9.5 ms。
- **泛化**：跨集成保留测试 TPR 99.75%；每个攻击类型保留时检测率 ≥ 99%。

### 对齐训练与推理时防御可叠加
- Sonnet 虽有最佳对齐，但无法完全防御；AGENTREDGUARD 进一步将其 ASR 从 32.1% 降至 0%。

## 7. 优点

1. **动态攻击生成**：打破固定模板局限，攻击内容逐次不同，更接近真实攻击者行为。
2. **广泛的企业集成覆盖**：24 个集成、9 个功能族，远超此前工作。
3. **细粒度攻击分类**：专门针对“不明确授权”这一微妙类别，而非传统注入。
4. **轻量高效防护**：23M 参数，CPU 微秒级延迟，可直接部署于生产环境。
5. **严格泛化验证**：跨集成和跨攻击类型的保留测试证明泛化能力而非记忆。
6. **开源与可重复性**：代码、模式、模型权重开放，标准场景集通过不可变版本控制。
7. **联合安全-效用评分**：要求任务完成才计为成功防御，防止过度拒绝。

## 8. 不足与局限

1. **场景选择偏差**：215 个场景经 Haiku 预过滤（至少一次成功），因此绝对 ASR 是上界，随机场景样本的 ASR 可能更低。相对排序是主要主张。
2. **攻击者适应有限**：5 次尝试内无法发现全新的攻击类别，当目标根本拒绝调用写工具时，重试只产生措辞变体。
3. **多集成链式攻击未充分评估**：49 个场景已提供但实验被推迟，论文未报告结果。
4. **未涵盖的攻击面**：不包括模型权重攻击、UI 重渲染攻击、直接提示注入用户消息等。
5. **反事实行为未建模**：ASR 降低计算基于“防护会标记哪些步骤”，未模拟智能体被拦截后的实际行为（重试、改变计划、放弃）。
6. **端到端任务完成率未完整测量**：在线防护下的任务完成率评估被推迟。
7. **供应商特定披露要求**：攻击仅针对通用 LLM 代理循环，未涉及第三方软件自身漏洞，因此无需供应商披露，但也意味着不覆盖特定漏洞。
8. **计算资源有限**：未评估 Claude Opus 等更大模型，因预算限制。
