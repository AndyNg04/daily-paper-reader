## 摘要
LLM智能体越来越多地部署在需要跨长交互历史持续推理的长周期任务上。规模化实现这一目标要求智能体能够在会话间持久化存储、检索和更新自身记忆。一个丰富的智能体记忆系统生态已经出现，涵盖平面检索、LLM中介提取、事实存储整合以及智能体控制流。然而，它们的系统级行为仍未被刻画。我们首次对智能体记忆进行系统性表征。首先，我们引入一个面向系统的分类法，沿四个维度对智能体记忆系统进行分类。其次，我们构建一个阶段感知的性能分析框架，将成本归因于构建、检索和生成阶段。第三，我们在两个基准套件上刻画了十个代表性系统，揭示了设计选择如何使成本在写入和读取路径之间转移。最后，我们推导出10条系统建议，涵盖构建调度、能力下限、通过查询量进行摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM 智能体被广泛用于长周期任务（如个人助理、代码代理、深度研究代理），需要跨会话持久化存储、检索和更新交互历史。传统方法依赖长上下文窗口，但面临三大根本限制：① 历史长度必然超过固定上下文预算；② 预填充成本随历史长度二次增长；③ 长序列中推理和回忆保真度显著下降（“U形”性能曲线）。因此，外部记忆系统成为必要。
- **核心问题**：当前涌现了大量智能体记忆系统（平面检索、LLM 中介提取、事实存储整合、智能体控制流等），其设计选择差异巨大，但**系统级行为（计算成本、延迟、能耗、扩展性）从未被刻画**。现有基准仅关注下游准确性，忽略了这些关键的系统特性。
- **整体含义**：本文首次对智能体记忆进行系统性表征，揭示设计选择如何不对称地分布成本，为部署决策提供量化依据。

## 2. 方法论：核心思想、关键技术细节

### 2.1 面向系统的四轴分类法
将智能体记忆系统沿四个维度分类：
- **Construction（构建机制）**：absent（无构建）、deterministic（确定性索引）、LLM-mediated（LLM提取）、agentic（智能体控制写入）。
- **Storage（存储结构）**：原始上下文、倒排索引、密集向量、知识图谱、多存储组合等。
- **Retrieval（检索流程）**：单次稀疏/密集搜索、多阶段流水线（结合稀疏/密集/图遍历/重排序/过滤）、智能体控制流程。
- **Mutability（可变性）**：append-only（仅追加）、consolidating（合并/更新）、mutate（变异）。

据此识别四种范式：
- **Paradigm I: Long-context memory**（如 long_context）——无外部记忆，依赖原始上下文。
- **Paradigm II: Flat RAG memory**（如 BM25、embedRAG）——确定性索引，无 LLM 构建。
- **Paradigm III: Structure-augmented RAG memory**——使用 LLM 提取结构化信息，又分 append-only（GraphRAG、HippoRAG v2）和 consolidating（Mem0、SimpleMem）。
- **Paradigm IV: Agentic control flow**（如 A-Mem、Letta、MIRIX）——LLM 控制记忆写入和读取，可深度嵌套。

### 2.2 阶段感知剖析框架
将智能体记忆执行分解为七阶段：**Ingestion → Construction → Storage → Retrieval → Prompt Assembly → Generation → Maintenance**。剖析工具将成本归因于三个逻辑阶段：
- **Memory Construction**（写入路径）
- **Retrieval**（读取路径中的搜索部分）
- **Generation**（最终答案生成）

记录 API 遥测（token 数、模型调用数、延迟）和硬件遥测（GPU 利用率、功率、显存、HBM 带宽、SM 活动、张量核心活动），实现对每阶段能耗和延迟的归因。

## 6. 主要结论与发现

本文提炼出 **8 条洞见** 和 **10 条建议**，核心发现包括：

1. **（洞见1）长上下文全历史预填充成本巨大**，外部记忆系统可大幅降低，但不同系统在相同硬件上服务延迟差距达两个数量级。
2. **（洞见2）构建阶段能量主导整个生命周期**：对于 LLM 中介的记忆系统，构建能耗超过 300 次查询的总能耗。能量每正确答案跨系统差异 >47×。
3. **（洞见3）构建是预填充和嵌入主导的工作负载**，与 QA 服务冲突（构建需要吞吐，QA 需要低延迟），嵌入流量范式间差异巨大（大批量 vs 顺序小批量）。
4. **（洞见4）构建 LLM 可降级，但受输出合约约束**：无严格合约的系统可平滑降级；有严格合约的系统存在能力下限，低于则存储损坏。
5. **（洞见5）无单一系统在构建成本、服务延迟和准确性上同时最优**：每个系统占据独特的权衡前沿。
6. **（洞见6）会话间构建引发新鲜度-延迟权衡**：慢构建系统在异步调度下累积陈旧度，快构建系统保持新鲜。
7. **（洞见7）每用户存储增长斜率比初始占用更关键**：Paradigm IV 系统在 LLM token 成本上呈超线性增长，长期成本由算法增长斜率决定。
8. **（洞见8）LLM 有界的系统（算法不限制深度）会产生更宽的延迟尾部分布**，需要外部迭代上限。

## 8. 不足与局限

- **单节点范围**：所有实验限于单 GPU 单机，未探索多节点/多智能体一致性、分布式协调问题。
- **多模态缺失**：仅处理文本，未覆盖图像、音频等多模态记忆，作者指出这会放大已识别的问题。
- **系统选择有限**：虽然包含 10 个系统，但仍有其他记忆架构（如 Zep、RAPTOR）未纳入。
- **适配偏差风险**：尽管作者做了最小调整，但某些系统（如 Letta）的默认设计并非针对 MAB 任务，提示差异可能略微影响结果。
- **未评估维护阶段的全生命周期成本**：大多数系统缺乏默认遗忘策略，长期行为（如内存碎片、重写开销）未被定量表征。
- **所有系统运行在相同硬件上，但部分系统可能更适合专用加速器**（如图数据库），未探索。
