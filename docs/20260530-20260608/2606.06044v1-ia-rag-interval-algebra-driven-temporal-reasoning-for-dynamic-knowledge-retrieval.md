## 摘要
检索增强生成（RAG）在利用外部知识增强大语言模型（LLM）方面表现出强大的有效性。然而，现有的RAG和图RAG框架大多将知识视为静态，或将时间与粗粒度的时间戳或元数据关联，无法捕捉丰富的时间结构，如持续时间、重叠和包含关系。我们提出IA-RAG，一个分层时序RAG框架，将知识建模为时间区间，并在形式化时序约束下执行检索。IA-RAG将事实表示为区间事件单元（IEU），并将其组织成分层主题森林，其中时序依赖关系由艾伦区间代数控制。为了处理不完整或不确定的时间边界，IA-RAG进一步引入了子图时间收紧机制，通过连接事件子图内的逻辑约束来细化模糊区间。此外，IA-RAG通过区间代数引导的遍历支持隐式时序语义检索。在多个时序问答基准（包括TimeQA、TempReason和ComplexTR）上的实验表明，IA-RAG在时序检索和推理方面取得了强劲性能，尤其是在复杂的组合时序推理任务上。我们的代码已发布在https://github.com/xiaoAugenstern/LogicalRAG_TemporalQA。

## Abstract
Retrieval-Augmented Generation (RAG) has shown strong effectiveness in grounding Large Language Models (LLMs) with external knowledge. However, existing RAG and Graph RAG frameworks largely treat knowledge as static or associate time with coarse-grained timestamps or metadata, failing to capture rich temporal structures such as duration, overlap, and containment. We propose IA-RAG, a hierarchical temporal RAG framework that models knowledge as time intervals and performs retrieval under formal temporal constraints. IA-RAG represents facts as Interval Event Units (IEUs) and organizes them into a hierarchical Thematic Forest, where temporal dependencies are governed by Allen's Interval Algebra. To handle incomplete or uncertain temporal boundaries, IA-RAG further introduces a Sub-graph Time Tightening mechanism that refines fuzzy intervals through logical constraints within connected event subgraphs. In addition, IA-RAG supports implicit temporal semantic retrieval through interval-algebra-guided traversal. Experiments on multiple temporal question answering benchmarks, including TimeQA, TempReason, and ComplexTR, demonstrate that IA-RAG achieves strong temporal retrieval and reasoning performance, particularly on complex compositional temporal reasoning tasks. Our code is released at https://github.com/xiaoAugenstern/LogicalRAG_TemporalQA.

- **核心问题**：如何设计一个能够**显式建模区间时间关系**并支持**形式化时间推理**的 RAG 框架？

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 核心思想
- 将每个事实表示为**区间事件单元（Interval Event Unit, IEU）**，包含时间区间 `[t_start, t_end]`、模糊标志 `fuzzy` 等字段。
- 构建**区间感知事件图**，图中边由艾伦区间代数（13 种互斥关系）定义。
- 通过递归聚合构建**分层主题森林**，支持从粗粒度到细粒度的层次化检索。
- 引入**子图时间收紧机制**，利用连通子图中的逻辑约束细化模糊区间。
- 采用**区间代数引导的遍历策略**，根据检索单元与查询窗口的相对位置动态选择前向、后向或双向遍历。

### 关键技术细节

1. **区间事件单元提取**
   - 对文档进行分块（1200 token, 64 token overlap），提取每个事实的句子、上下文、时间区间、模糊标志。
   - 明确表达映射为精确区间，模糊表达（如“early 1990s”）映射为粗粒度区间并标记 fuzzy=True。
   - 用局部语义邻域策略（cosine similarity > 0.8）进行 IEU 去重，由 LLM 判定是否为同一事件。

2. **区间感知事件图构建**
   - 语义兼容的 IEU 对（cosine similarity > τ_sem）计算艾伦区间关系，形成有向边。
   - 使用 LLM 对模糊 IEU（fuzzy=1）进行**子图时间收紧**：在其连通组件内，根据邻居的明确关系推导更精确的时间边界，更新 fuzzy 标志。

3. **分层主题森林构建**
   - 连通组件自动聚合成**宏观事件单元（MEU）**，递归构建多层（最多 4 层），形成父-子包含关系的树状结构。
   - 根节点对应最抽象的叙事主题，叶节点对应原子 IEU。

4. **查询驱动的事件检索**
   - 用 LLM 解析查询时间窗口 Tw。
   - 在 MEU 和 IEU 两个层面独立检索 Top-K 语义相似单元（使用 BGE-M3 嵌入）。
   - 根据检索单元时间区间 Ti 与 Tw 的相对位置，动态选择遍历方向（前向/后向/双向），遍历艾伦关系邻居，补充检索结果。

### 算法流程（文字说明）
```
输入：文档语料库 → 
  ① 分块并提取 IEU（含时间区间、fuzzy 标志）；
  ② 构建区间感知事件图（基于艾伦关系）；
  ③ 对模糊 IEU 执行子图时间收紧（LLM 推理）；
  ④ 递归聚合连通组件，构建分层主题森林（MEU 层）；
  ⑤ 给定查询 q：
     a. 提取查询时间窗口 Tw；
     b. 在 MEU 和 IEU 层语义检索 Top-K；
     c. 对每个检索单元，根据 Ti vs Tw 选择遍历方向，收集邻居；
     d. 合并初始检索结果与邻居，送入 LLM 生成答案。
输出：答案文本。
```

## 6. 论文的主要结论与发现

1. **性能领先**：IA-RAG 在 TimeQA 和 ComplexTR 上达到最佳 accuracy 和 recall（TimeQA: 61.72%/69.25%；ComplexTR: 65.95%/77.42%），大幅超越所有基线（ComplexTR 上比最强基线 DyG-RAG 高 +10.33% acc）。

3. **层次化检索提升效率**：IA-RAG 在较低 token 消耗下获得高准确率，表明层次森林减少了噪声输入。
4. **子图时间收紧消除模糊**：移除该模块后性能下降，证明局部时间推理能有效细化不确定边界。
5. **区间代数引导遍历优于纯语义或无条件遍历**：方向性检索减少了无关邻居的干扰。

## 7. 优点

- **创新性**：首次将艾伦区间代数系统性地引入 RAG，填补了区间拓扑推理的空白。
- **方法论完整**：构建了从 IEU 提取、图构建、层次森林到检索生成的完整 pipeline，各模块设计合理且相互支撑。

- **层次化检索**：粗到细的检索策略既提高了定位精度又控制了计算开销。
- **实验全面**：覆盖三个不同复杂度数据集、多种基线、消融、敏感性、案例分析，结论可信。
- **可复现性**：代码已开源，附录提供了详细提示模板和参数，便于复现。

## 8. 不足与局限

- **时间提取噪声敏感**：IEU 提取依赖 LLM 对模糊时间表达的解析，可能引入错误（如“early 1990s”的映射精度）。
- **因果关系缺失**：框架仅建模时间拓扑，未显式建模事件间的因果/演化关系，限制了更复杂的时序推理（如“因为 A 所以 B”）。
- **TempReason 上非最优**：在 TempReason 上准确率（80.21%）略低于 DyG-RAG（84.75%），说明在简单点时间匹配任务中，IA-RAG 的复杂机制可能反而带来噪音或检索不足。
- **计算复杂度较高**：需要多层 LLM 调用（提取、去重、收紧、回答问题），对资源要求较高，不适合实时场景。
- **数据集规模有限**：ComplexTR 仅 329 题，结论泛化性需更大规模验证。
- **对比基线未包含最新大型模型直接推理**：虽然遵循了领域惯例，但与 GPT-4o 等直接推理的对比可进一步说明 RAG 的必要性。
