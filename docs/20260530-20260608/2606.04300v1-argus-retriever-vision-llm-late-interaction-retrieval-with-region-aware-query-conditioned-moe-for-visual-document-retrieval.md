## 摘要
后期交互视觉-语言检索器将每个文档页面表示为多个视觉标记嵌入，并使用MaxSim对查询进行评分。在ColPali、ColQwen、ColNomic和Nemotron ColEmbed等系统中，文档嵌入是在未看到查询的情况下生成的，因此同一页面对于表格查找、图表问题和布局敏感的证据请求会以相同的方式表示。我们提出了\textbf{Argus}，一个构建在Qwen3.5-VL之上的查询条件后期交互检索器系列。Argus添加了一个区域感知的混合专家模块：查询编码器同时生成检索嵌入和紧凑的上下文向量，文档页面被池化为空间区域，一个查询感知的路由器在每个区域上选择潜在专家，然后进行MaxSim。输出仍然是一个与ColPali风格检索兼容的多向量索引，但文档表示现在依赖于查询（即$\mathbf{D}(q)$）。所有Argus模型使用1024维的检索头，而最近最先进系统使用2560维和4096维的头，并且仅使用约9%的可用公开监督数据进行训练，而非全部数据。9B模型在ViDoRe V1上达到\textbf{92.67} NDCG@5，在V1+V2组合排行榜上达到\textbf{86.0} NDCG@5，这是在组合排行榜上公开的后期交互模型的最高报道值。在ViDoRe V3上，Argus-9B包装在Qwen3.6-27B代理检索流水线中，进一步将其NDCG@10从60.28提升到\textbf{64.80}，表明同一个检索器既可以作为强大的独立系统，也可以作为迭代LLM代理的搜索基元。

## Abstract
Late-interaction vision-language retrievers represent each document page as many visual token embeddings and score queries with MaxSim. In systems such as ColPali, ColQwen, ColNomic, and Nemotron ColEmbed, the document embeddings are produced without seeing the query, so the same page is represented identically for a table lookup, a chart question, and a layout-sensitive evidence request. We introduce \textbf{Argus}, a family of query-conditioned late-interaction retrievers built on Qwen3.5-VL. Argus adds a region-aware Mixture-of-Experts module: the query encoder produces both retrieval embeddings and a compact context vector, the document page is pooled into spatial regions, and a query-aware router selects latent experts per region before MaxSim. The output remains a multi-vector index compatible with ColPali-style retrieval, but the document representation is now dependent on the query (i.e., $\mathbf{D}(q)$). All Argus models use a 1024-dimensional retrieval head, compared with the 2560-dimensional and 4096-dimensional heads of recent state-of-the-art systems, and are trained on roughly 9\% of the available public supervision rather than the full pool. The 9B model reaches \textbf{92.67} NDCG@5 on ViDoRe V1 and \textbf{86.0} NDCG@5 on the combined V1+V2 leaderboard, the highest reported value for an open late-interaction model on the combined leaderboard. Wrapped in a Qwen3.6-27B agentic retrieval pipeline on ViDoRe V3, Argus-9B further improves its NDCG@10 from 60.28 to \textbf{64.80} over public tasks, showing that the same retriever serves both as a strong standalone system and as a search primitive for iterative LLM agents.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：在视觉文档检索（Visual Document Retrieval, VDR）中，传统后期交互检索器（如 ColPali、ColQwen）将每个文档页面编码为多个视觉 token 嵌入，查询编码为多个 query token 嵌入，通过 MaxSim 计算相关性。这些系统的文档嵌入**不依赖查询**，即同一页面在回答表格查找、图表问题或布局敏感证据请求时表示完全相同。
- **局限**：这种“查询无关”的表示无法针对不同查询自适应调整文档特征。例如，同一页面中既包含表格也包含图表，查询“表格中的数字”与“图表的趋势”所需关注的区域不同，但固定表示无法区分。
- **研究动机**：受跨编码器（cross-encoder）自适应能力启发，Argus 设计了一种**查询条件化的文档表示** $D(q)$，使同一页面能根据查询动态调整其多向量嵌入，同时保留后期交互实用的索引和评分性质。

## 2. 方法论

### 2.1 核心思想
- 基于 Qwen3.5-VL 骨干网络，引入**区域感知的查询条件化混合专家（MoE）模块**。
- 查询编码器不仅产生检索嵌入 $Q$ 用于 MaxSim，还产生一个池化的上下文向量 $z_q$ 用于路由。
- 文档页通过骨干网络在**两个深度**提取特征：中间层 $L-5$ 用于路由（保留布局和结构信息），最终层 $L$ 用于检索。
- 将文档特征图池化为 $r \times r$ 区域，每个区域包含内容特征 $R_r$、坐标 $c_r$ 和查询上下文 $z_q$。
- **查询感知路由器**为每个区域选择 top-2 专家，然后对专家输出进行加权混合，再通过门控残差融合与原始特征合并，最终投影得到 $D(q)$。
- 评分仍使用 MaxSim，兼容 ColPali 风格的多向量索引。

### 2.2 关键技术细节
- **区域大小** $r=4$，**专家数量** $K=4$（匹配运行文本、表格、图表、图片/公式四种内容类型），路由选择 top-2。
- 路由器输入：$u_r = R_r + W_{coord} c_r + W_{query} z_q$，即区域内容 + 坐标 + 查询上下文，通过两层 MLP 产生路由 logits，使用带噪 softmax 得到专家权重。
- **专家库**：4 个小型前馈模块（LN → Linear → GELU → Linear）+ 一个始终激活的共享专家。
- **门控残差融合**：$F = G_{final} + \sigma(\alpha) S_{shared} + \sigma(\beta) S$，两个标量门控可学习，初始化为 0.5。
- 所有 Argus 模型使用 **1024 维**检索头（对比最强基线用 2560 维或 4096 维）。

### 2.3 训练损失
- 联合损失：$\mathcal{L} = \mathcal{L}_{NCE} + \lambda_{bal} \mathcal{L}_{bal}$，其中 $\mathcal{L}_{NCE}$ 是 InfoNCE 对比损失（in-batch 负例），$\mathcal{L}_{bal}$ 是负载均衡损失（鼓励均匀使用专家）。
- 先运行**路由器预热阶段**（仅训练路由器和专家，不启用检索损失），防止专家崩溃。

- Argus-9B 在 **ViDoRe V1+V2 组合榜**上达到 **86.0 NDCG@5**，为开源后期交互模型最高，超过 Nemotron-8B-v2（84.7）和 Ops-Colqwen3-4B（84.6），尤其在 V2 领域外任务上优势明显。

- **代理检索**将 Argus-9B 的 NDCG@10 从 60.28 提升至 64.80，表明其可作为迭代搜索基元。
- 使用 1024 维头且训练数据仅为 9.3% 源池，即可达到 SOTA，证明设计高效。
- 组件消融确认查询条件、区域位置、共享专家三者均不可或缺。

## 7. 优点

- **创新性**：首次在后期交互 VLM 检索器中引入查询条件化的文档表示，通过区域 MoE 实现自适应，避免固定表示局限。
- **实用性**：保持与 ColPali 兼容的多向量索引，离线缓存查询无关特征，仅路由器、融合和 MaxSim 在查询时运行，成本可控。
- **效率**：较小的嵌入维度（1024）带来更低的存储和查询延迟，同时达到甚至超越更高维度模型的准确率。
- **消融实验全面**：验证了查询条件、区域坐标、共享专家、专家数量、路由层深度等设计选择。
- **代理集成**：展示检索器与 LLM 代理结合可进一步提升召回，拓宽应用价值。
- **开源**：代码和数据已公开，促进可复现性。

## 8. 不足与局限

- **存储与延迟开销**：继承后期交互的索引大小（每页 4.2 MB）和查询时 MaxSim 计算；虽然相对基线较小，但仍比单向量检索大。
- **查询条件化限制**：标准 ColPali 可一次索引整个语料库，而 Argus 的 $D(q)$ 依赖查询，需要两阶段（先检索候选再精细评分），增加系统复杂度。
- **实验覆盖**：V3 仅覆盖 8 个公开任务，私有的 Nuclear 和 Telecom 任务未纳入；代理实验仅使用单一 Qwen3.6-27B 模型和固定搜索预算，泛化性待验证。
- **解释性**：潜在专家无显式标签（如“表格”、“图表”），路由决策缺乏语义可解释性，仅靠训练隐式发现。
- **训练效率**：使用 loRA 和 9.3% 数据即达 SOTA，但未比较全参数微调或更大数据规模下的收益，可能仍有提升空间。
- **语言覆盖**：MIRACL-Vision 仅 10 种语言，未涵盖更多低资源语言；中文、印尼文等语言上 Argus-9B 不是最佳（如中文低于 Nemotron-8B-v2），可能存在语言偏差。
