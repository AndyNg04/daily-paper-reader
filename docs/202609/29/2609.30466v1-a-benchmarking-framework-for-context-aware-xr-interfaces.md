## 摘要
日常使用的扩展现实（XR）系统旨在让用户在合适的时间和地点，以情境感知的方式获取所需功能，并在用户切换情境时尽量减少手动重新配置。然而，这类界面难以评估：现有的原型开发和用户研究流程缺乏系统、可重复的方法，无法跨用户和场景比较不同的自适应方法。我们提出 ContextXR，一种面向情境感知 XR 界面的新型基准测试框架。ContextXR 将 XR 应用表示为由功能单元构成的连通图；每个功能单元都是一组语义连贯的相关能力，共同支持同一用户意图。基于这一表示，我们构建了 MineXR++ 数据集，在已有 XR 界面数据的基础上增加功能单元级标注，并定义了三项情境感知推荐的典型任务：情境因素分析、初始功能单元推荐和下一功能单元推荐。我们的评估协议采用模拟交互指标，根据到达目标功能所需的导航与搜索成本对推荐方法进行评分。通过对全局流行度方法、关系检索方法和基于大语言模型（LLM）的方法开展基准测试，我们证明 ContextXR 能够支持对情境感知 XR 界面进行系统、可复现的评估。

## Abstract
Everyday Extended Reality (XR) systems aim to provide context-aware access to the right functionalities at the right time and place, with minimal manual reconfiguration as users switch context. Yet these interfaces are hard to evaluate: current prototyping and user-study workflows offer no systematic, repeatable way to compare adaptation methods across users and scenarios. We present ContextXR, a novel benchmarking framework for context-aware XR interfaces. ContextXR represents an XR application as a connected graph of functional facets, each a semantically coherent group of related capabilities that together support a shared user intent. On this representation, we build MineXR++, a dataset augmenting prior XR interface data with facet-level annotations, and formulate three canonical tasks of context-aware suggestion: context factor analysis, initial facet suggestion, and next facet suggestion. Our evaluation protocol scores suggestion methods by a simulated interaction metric, the navigation and search cost of reaching the desired functionality. Through experiments benchmarking global popularity, relational retrieval, and LLM-based methods, we demonstrate that ContextXR enables the systematic, reproducible evaluation of context-aware XR interfaces.

## 1. 核心问题与研究动机

- 日常扩展现实（XR）界面需要随用户、任务和环境变化，及时呈现所需功能。否则，用户每次切换情境都要手动关闭旧界面、查找应用并重新配置。
- 现有研究多依赖专门制作的原型和单次用户研究，难以在**相同数据、任务和指标**下，跨用户、跨场景比较不同适配方法。
- 论文将研究重点限定为**“应该呈现哪些功能”**，而非功能的空间摆放、呈现时机或情境识别。其核心主张是：推荐整个应用过于宽泛，推荐单个原子操作又过于零碎；需要一种介于两者之间的功能表示和可重复的评估基准。

## 2. 方法论：ContextXR 框架

- **功能单元（functional facet）表示：**将支持同一用户意图的一组原子能力归为一个功能单元。例如，“查看食谱”包含查看食材、步骤和烹饪时间等能力。功能单元既能对应用户可理解的目标，又能关联具体界面行为。
- **功能单元图：**以应用内的功能单元为节点，以能够打开另一功能单元的导航能力为有向边。例如，“浏览食谱 → 查看食谱 → 烹饪食谱”。应用入口也被表示为特殊的功能单元。这使框架能够区分“直接呈现目标功能”和“提供通往目标功能的入口”。
- **推荐任务形式化：**以用户、任务、环境组成情境 \(q=(u,t,e)\)；系统从候选功能单元中推荐一个集合，与该情境下用户期望使用的集合比较。论文定义了三项任务：分析各情境因素与功能需求的关联；在进入情境时推荐初始功能集合；利用当前已使用功能推荐下一功能。
- **模拟交互评估：**主要指标是到达目标功能的**导航与搜索成本**。无推荐时，用户需要打开应用菜单、寻找应用并在应用内导航；有推荐时，目标功能可能是直接命中、需要从同应用的推荐功能继续导航，或完全未命中而退回手动查找。成本模型还计入扫描推荐列表的开销，因此并非只奖励命中数量。论文同时报告 Recall@10、F1@10 和 Hit@10，作为精确匹配表现的补充指标。
- 这一成本模型使用固定步骤成本和简化的用户策略，适合在统一假设下比较方法，**不等同于实测的人类操作时间**。

## 3. 数据、Benchmark 与对比方法

- **数据集：MineXR++。**论文在 MineXR 的设想式 XR 布局数据上增加功能单元标注。原始数据来自 **31 名参与者**在办公室、客厅、厨房、咖啡店四类环境中设计的 **109 个布局、695 个组件**。扩充后的功能数据库覆盖 **42 个应用、273 个功能单元、1,007 项能力**；其中 **101 个功能单元**实际出现在参与者布局中。标注主要由一位作者完成、另一位作者复核。
- **Benchmark：**以上述布局中用户放置的功能单元作为目标集合，评估情境因素分析、初始推荐和逐步推荐三项任务。推荐实验均要求辅助方法给出 **10 个功能单元**。初始推荐中的流行度和关系检索方法采用按场景划分的五折交叉验证，避免同一待测场景的观察记录进入训练折。
- **对比方法：**无辅助的手动访问；忽略情境的全局流行度；综合用户、任务、环境及其组合的历史统计，并借助文本嵌入作相似情境迁移的关系检索；以及零样本和不同历史样例匹配条件下的少样本 LLM。LLM 使用 **Gemini 3 Flash，温度为 0.2**。逐步推荐还将当前已放置的功能作为输入。

## 5. 实验数量、充分性与公平性

- 论文包含**三项主要实验**：一项情境因素分析，以及初始推荐、下一功能推荐两项方法比较。推荐比较覆盖手动基线、流行度、关系检索、零样本 LLM，以及按用户、任务、环境和两因素组合划分的多种少样本条件。没有展示跨多个独立数据集的验证，也未报告对成本参数或推荐数量的系统敏感性实验。
- **设计上的公平性：**各辅助方法在同一功能目录、目标集合及 top-10 设置下接受评估；按场景划分训练与测试有助于降低记录级数据泄漏；逐步推荐先在场景内汇总，可避免较长序列主导平均结果。
- **比较时需注意：**少样本条件要求存在匹配历史案例，可评估场景数不同。例如，初始推荐中“用户＋任务”仅覆盖 **2 个场景**，其最高数值不能直接视为稳定优势。论文也未提供显著性检验或置信区间。整体而言，这些实验足以演示框架如何比较方法和分析信号来源，但不足以证明结果能稳定推广到更广泛的真实 XR 使用环境。

## 6. 主要结论与发现

- **功能需求具有多因素差异。**在实际出现的 101 个功能单元中，按论文的关联强度分析，47 个主要与用户相关，14 个主要与任务相关，12 个主要与环境相关，另有 8 个呈混合关联、20 个未显示高于基线的关联。用户因素突出，但不能替代其他因素。
- **初始推荐：**手动访问的平均模拟成本为 **21.20**；全局流行度、关系检索和零样本 LLM 分别将成本降低 **6.4%、13.3% 和 16.7%**。在有较广场景覆盖的少样本设置中，匹配用户及“用户＋环境”的 LLM 分别降低 **22.6% 和 22.7%**。
- **下一功能推荐：**相对手动访问，全局流行度降低成本 **11.7%**，关系检索降低 **25.9%**，零样本 LLM 降低 **24.5%**；匹配用户样例的少样本 LLM 降低 **31.1%**，取得最低模拟成本。关系检索则获得该任务中最高的 Recall@10、F1@10 和 Hit@10。
- 结果表明，**精确命中率与访问效率并不完全一致**：即使没有直接推荐目标功能，一个合适的同应用入口也可能减少导航成本。作者据此建议在情境开始时重视个体历史，并在交互推进后结合当前会话轨迹调整推荐。

## 7. 优点

- 将应用功能组织为“能力—功能单元—应用”的层次，并加入导航关系，为细粒度 XR 功能推荐提供了可计算、可解释的对象。
- 同时提供数据标注、标准任务、基线与评估协议，使后续方法可以在共同设置下比较。
- 以访问成本补充传统检索指标，能够评价部分相关的推荐入口及整组推荐对用户查找功能的帮助。
- 区分初始与逐步推荐，揭示历史个性化信息和当前交互证据在不同阶段的作用。

## 8. 不足与局限

- **数据代表性有限：**目标集合来自少量参与者在实验环境中设计的*设想式*布局，不一定等同于长期真实使用需求；四类环境及实际使用的功能单元数量也限制了覆盖范围。
- **标注与真值存在偏差风险：**功能单元的划分及组件映射包含人工判断；“用户曾放置”只能作为目标功能的代理，不能保证其后续确实需要或经常使用。
- **模拟成本尚未经真实交互充分验证：**固定扫描、导航和调整成本未充分覆盖注意力、认知负荷、动作方式、界面拥挤或误推荐干扰，因此成本下降不应直接解释为同幅度的真实体验改善。
- **应用链路未被端到端测试：**框架假定用户、任务和环境标签已知，未纳入情境感知错误；也不评估功能的空间布局、呈现时机、信任感及长期适应。
- **结果稳定性与部署成本仍待检验：**部分少样本条件数据极少，缺少统计不确定性和资源消耗报告；更大规模、跨场景及真实用户实验是验证结论的关键下一步。
