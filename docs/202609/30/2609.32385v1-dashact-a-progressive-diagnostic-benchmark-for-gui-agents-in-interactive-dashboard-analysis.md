## 摘要
交互式仪表板要求用户通过有状态的交互逐步揭示并关联证据。尽管图形用户界面（GUI）智能体有望自动完成这一过程，现有仪表板基准主要报告最终答案或任务成功率，难以判断失败究竟源于分析过程的维持、动作的选择，还是视觉目标的定位。我们提出 DashAct；据我们所知，这是首个能够在同一仪表板任务内对这些失败进行细粒度诊断的基准。DashAct 包含 357 条经人工核验的交互轨迹，并标注了里程碑之间的依赖关系和层级化目标。其渐进式诊断级联首先评估端到端执行，再恢复经核验的上下文以评估下一动作预测，最后提供目标语义和局部视图以评估视觉定位。通过逐步恢复成功所需的条件，DashAct 衡量智能体恢复完成任务的能力所需的最低限度支持，而非对孤立技能单独评分。实验表明，即使逐步增加支持，当前模型仍面临困难。级联评估结果揭示了端到端得分所掩盖的瓶颈，并为改进 GUI 智能体提供了可操作的指导。

## Abstract
Interactive dashboards require users to reveal and connect evidence across stateful interactions. Although graphical user interface (GUI) agents could automate this process, existing dashboard benchmarks primarily report final answers or task success. They provide limited insight into whether failures arise from maintaining the analytical process, selecting actions, or grounding visual targets. We introduce DashAct, to our knowledge the first benchmark to diagnose these failures at a fine-grained level within the same dashboard task. DashAct contains 357 human-verified interaction trajectories with milestone dependencies and hierarchical target annotations. Its progressive diagnostic cascade evaluates end-to-end execution, restores verified context for next-action prediction, and provides target semantics and a local view for visual grounding. By progressively restoring the conditions for success, DashAct measures the minimum support an agent needs to recover rather than scoring isolated skills. Experiments show that current models struggle even as support is added. The cascade outcomes reveal bottlenecks hidden by end-to-end scores and provide actionable guidance for improving GUI agents.

# DashAct 论文总结

## 1. 核心问题与整体含义

- **研究背景**：回答交互式仪表板中的分析问题，往往需要智能体依次打开面板、设置筛选、悬停或选中图表元素，并把不同界面状态下获得的证据汇总成答案。交互不仅是操作界面，也是获取分析证据的过程。
- **核心问题**：现有基准多关注最终答案或任务成功率。任务失败时，难以判断智能体究竟是没有维持正确的多步分析过程、选错了下一步动作，还是知道要做什么却未能点中目标。
- **论文定位**：DashAct 是一个**诊断性评测基准，而非新的智能体训练方法**。它在同一批任务上逐步提供更多已核验信息，观察模型在什么条件下恢复成功，从而定位端到端得分掩盖的瓶颈。

## 2. 方法论：数据标注与渐进式诊断

- **任务与过程表示**：每个任务由交互式仪表板、自然语言问题和参考答案组成；执行过程是一串界面观察、动作及最终回答。作者将必要的中间进展标为“里程碑”，记录其动作类型、预期界面变化，以及相关视图和具体目标的边界框。里程碑间的先后依赖构成有向无环图，允许没有依赖的步骤以不同顺序完成。
- **数据构建**：标注员探索真实仪表板并录制可执行轨迹；GPT-5 起草问题、答案和过程标注后，由人工回放、修订并交叉复核。人工还检查答案能否从轨迹中获得，以及视图和目标框是否准确。
- **三级渐进式评测**：
  1. **端到端执行**：智能体从初始界面自主交互并作答，统计里程碑覆盖率、全部里程碑完成率和答案准确率。在线里程碑判定允许与参考轨迹不同、但达到预期效果的有效路径。
  2. **已核验上下文中的下一动作预测**：提供正确的历史动作和当前完整仪表板截图，让模型预测动作类型、目标坐标及必要参数；分别评估动作类型、目标命中和完整动作成功率。这一步消除了此前自主执行错误的影响。
  3. **指定目标的局部定位**：进一步提供目标的语义描述及其所在视图的裁剪图，只要求预测目标位置。它主要检验在已知“找什么、在哪个视图找”时，能否精确定位。
- **诊断逻辑**：比较同一里程碑在不同支持条件下首次成功的阶段，将其归为自主完成、依赖已核验上下文恢复、依赖目标及视图提示恢复，或始终未解决。需要注意，**各阶段改变了输入和任务要求，得分不能简单视为同一种能力的逐级提升率**。

## 3. 实验设计：数据、场景与对比模型

- **主要基准 DashAct**：包含来自 **175 个真实仪表板**的 **357 个问题及人工核验轨迹**；仪表板平均有 **11.07 个视图**，每条参考轨迹平均有 **2.52 个里程碑**，范围为 1—11 个。仪表板主要来自 Tableau Public，覆盖零售、金融、医疗、教育等领域。
- **补充数据**：将 DashboardQA 中符合“单个仪表板内分析”条件的问题改编为同样的交互评测，共 **242 个问题、83 个仪表板**；其详细结果在补充材料中，正文主要分析 DashAct。
- **对比对象**：三级评测使用 **9 个核心多模态模型**，包括 Gemini 3 Flash Preview、GPT-5、Claude Sonnet 5，以及 OpAgent、GUI-Owl、Qwen3-VL、OpenCUA、UI-TARS 等开源模型；第三级另加入 **2 个专门的 GUI 定位模型**：POINTS-GUI-G 和 UGround-V1-7B。
- **统一条件**：所有模型仅使用截图，不提供 DOM、HTML 或无障碍树；采用语义等价的提示、统一动作格式和归一化坐标。端到端任务每题运行一次，最多 **20 轮**。

- **实验覆盖**：在主要数据集上，对 9 个核心模型进行三级评测；第三级增加 2 个定位模型。作者还按里程碑数量、视图与视图内目标两个空间层级、控件与可视化标记两类目标进行分析，并对 **889 个可跨三级比较的里程碑实例**做恢复类型统计，辅以案例分析。补充材料报告改编后的 DashboardQA 结果。

## 6. 主要结论与发现

- **完整分析远比局部进展困难**：表现最好的 Gemini 3 Flash Preview 在端到端阶段达到 **62.7% 里程碑覆盖率**，但全部里程碑完成率和答案准确率分别只有 **42.9%**、**42.6%**。这表明完成部分步骤不等于完成分析；随着所需里程碑增加，答案准确率下降尤为明显。
- **恢复正确上下文仍不足以保证选对动作**：第二级最高的完整动作成功率仅 **31.3%**（Gemini 3 Flash Preview）。有些模型动作类型准确率很高，却仍因目标坐标或其他动作要素错误而失败。
- **视觉定位是突出瓶颈**：第二级最高目标命中率为 **37.1%**；即使在第三级明确目标及所在视图后，最高也仅 **58.4%**。所有受测模型定位界面控件的表现均优于定位图表中的可视化标记。
- **不同模型的失败位置不同**：例如，有的模型较容易找到正确视图，却难以点中其中的具体目标；有的模型只有在恢复正确界面状态后才能继续。渐进式诊断因此比单一成功率更能说明改进方向。

## 7. 优点与亮点

- **围绕同一任务做逐级诊断**，把多步过程、当前动作和局部定位联系起来，而非拼接互不相关的单项测试。
- **标注兼顾依赖与空间层级**：里程碑依赖、预期界面效果、视图框和目标框，使“走错步骤”“找错视图”“点错元素”能够得到更细的分析。
- **真实、异构且经过人工复核**：使用实际仪表板和可回放轨迹，并允许在线评测认可不同于参考轨迹的有效操作路径。
- **揭示可操作的改进方向**：结果分别指向状态与证据管理、隐藏界面发现、跨视图搜索，以及利用悬停提示等反馈修正定位。

## 8. 不足与局限

- **任务与平台覆盖仍有限**：主要来源于 Tableau Public；357 个主集任务虽具有多领域内容，却不能直接代表其他仪表板平台或企业内部分析环境。
- **参考过程与标注可能带有路径偏差**：人工标记必要里程碑及依赖，难以穷尽所有合理分析路径。在线判定虽允许替代路径，但仍依赖标注和评估器的判断。
- **在线里程碑评估存在模型评审风险**：第一级使用 Gemini 3.1 Flash-Lite 结合规则结果判断是否完成里程碑；正文称补充材料提供与人工判断的一致性分析，但自动判定仍可能误判复杂的界面变化。
- **级联诊断不能完全做因果归因**：第三级同时提供目标语义与所在视图，并改变截图范围，因此从第二级到第三级的恢复不能进一步区分是动作选择、目标推断、跨视图搜索，还是图像裁剪带来的收益。
- **终点答案不完全由里程碑解释**：完成全部标注步骤后仍可能因数值记忆、跨状态证据整合或计算错误而答错；基准揭示了这一现象，但没有将最终答案错误进一步系统拆分。
- **复现成本与稳定性有待关注**：实时网页、外部模型 API 和动态界面可能变化；加之正文缺少详细算力成本及重复运行统计，复现实验和判断小幅模型差异仍需谨慎。
