## 摘要
服务于不同用户的大语言模型（LLM）智能体往往需要解决相似的任务，但彼此隔离的用户历史记录可能使可复用的经验无法被其他智能体利用。汇集记忆虽能扩大经验的可获取范围，却也可能引入与接收用户需求相冲突的偏好。我们提出 ShareMem，一种在共享可复用经验的同时，将其应用建立在接收用户自身偏好之上的记忆架构。共享经验指示智能体如何行动以及应查询哪些偏好；接收用户的记忆则提供这些偏好的具体取值。两阶段整合机制先在本地提炼经验，再将通过筛选的修改纳入共享池。执行过程中，范围优先检索在统一的条目预算下联合选择本地与共享经验，而用户绑定通道则支持初始偏好检索和智能体主动发起的偏好检索。我们使用四种基础模型，在网页导航（Mind2Web）、在线个性化交互（VitaBench~2.0）和多会话编程（MemoryCode）任务上评估 ShareMem。与配置相匹配的用户本地记忆基线相比，ShareMem 在全部四种模型上分别提高了步骤成功率、平均任务成功率和对话宏观编程得分。消融实验表明，两阶段整合有助于缩小共享池规模、减少归纳阶段的令牌消耗并提升下游性能，同时支持经验指导与主动偏好检索具有互补性。进一步分析表明，当相关的本地经验匮乏时，共享带来的收益最大；而来源经验的质量及跨用户偏好干扰则限制了有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

# 论文总结：ShareMem——跨用户共享经验，同时遵循当前用户偏好

## 1. 核心问题与研究动机

- **核心问题**：服务不同用户的 LLM 智能体常处理相似任务，却无法利用彼此隔离的历史经验；若直接汇集记忆，又可能把其他用户的偏好误用于当前用户。
- 论文将前者称为**“经验可达性瓶颈”**，并强调“能够检索到一条记忆”不等于“这条记忆适用于当前用户”。例如，编程步骤可以复用，贡献该步骤的用户所偏好的命名规则却未必能复用。
- ShareMem 的总体主张是：**跨用户共享“如何做、需要核对哪些偏好”，具体偏好值则只从当前用户的记忆中获取。**

## 2. 方法论：ShareMem 如何工作

- **分离记忆类型**：每个用户拥有自己的偏好记忆和本地经验；跨用户共享池只存放经过抽象的任务经验。经验用语义槽位代替来源用户的具体值，并提示执行时应查询哪些偏好维度。
- **两阶段经验整合**：
  1. 从一次合格的任务轨迹或历史会话出发，先检索最多 \(k_w=5\) 条相近的本地经验，由 LLM 管理器决定新增、替换、删除或不修改。
  2. 只有被本地阶段接受的修改，才进入共享阶段；共享管理器再参照相近的共享经验，独立决定如何更新共享池。因此，本地的删除或替换不会被机械地同步到共享池。
- **范围优先的联合检索**：执行任务时，先按适用范围组织候选经验，例如 Mind2Web 按“同网站→子域→域→其他网站”排序。在每一级内，本地与共享经验共同竞争，最终受统一的 **\(K=5\) 条**预算约束；低优先级经验只能填补剩余名额。
- **绑定当前用户的偏好通道**：任务开始时先检索最多 \(k_p=10\) 条当前用户偏好；执行过程中，智能体还可针对未解决的具体字段主动再次查询。经验可以指导“该查什么”，但不能替代查得的当前用户偏好；当前任务要求和实际环境观察也优先于经验。

## 4. 资源与算力

- 论文报告了基础模型、检索模型 BGE-M3 与 BGE-Reranker-v2-M3，以及部分记忆构建的令牌开销；**没有明确报告 GPU 型号、GPU 数量、训练或推理耗时，也没有给出完整的实验算力与费用统计**。

## 5. 实验数量、充分性与公平性

- **覆盖面较广**：主实验涉及 3 个不同基准、4 种基础模型和多种记忆配置；还进行了写入策略、可编辑维护、范围优先检索、检索预算、主动偏好检索、本地经验覆盖率、来源质量、在线准入阈值及跨用户偏好干扰等分析。多数主要结果使用三个运行种子或三个固定子集。
- **较公平的部分**：论文明确设置 Local 作为匹配的本地记忆基线，并在相应对照中固定任务、模型、检索上限或经验池；对偏好共享基线还标记来源、保留当前用户偏好名额，避免将其设为明显弱的“无标记混合”方案。
- **需要审慎解读的部分**：若干消融重建了经验池，因而同时改变记忆内容与写入策略；“关闭主动检索”也改变了可获得的信息及交互机会。MemoryCode 使用抽样子集，部分进一步分析只针对 Qwen。这些实验支持方法的整体有效性，但并非每项都能严格隔离单一机制的因果效应。

## 6. 主要结论与发现

- 相对 **Local**，ShareMem 在四种模型上均提高了 Mind2Web 的步骤成功率（**+2.35～+4.10 个百分点**）、VitaBench 的 Avg@3（**+1.25～+2.46 个百分点**）和 MemoryCode 的平均 D-MS（**+0.16～+2.91 分**）。但其他指标并非全面领先，例如 Gemini 在 VitaBench 的“三次全成功”指标略低于 Local。
- **共享收益取决于本地经验缺口**：Mind2Web 中，同网站本地经验覆盖率从 0% 提高至约 99% 时，ShareMem 相对 Local 的步骤成功率增益从 **+4.10** 降至 **−0.13 个百分点**。
- **整合质量比记忆数量更重要**：两阶段、可编辑的整合产生更小的共享池、更低的构建令牌开销，并在相关消融中优于直接写入或仅追加存储。
- **经验指导与主动偏好查询具有互补性**：在 Qwen 的 MemoryCode 消融中，启用主动查询时，加入经验指导带来 **9.48 分**的 D-MS 增益；仅有初始偏好召回时，该增益为 **1.37 分**。这比较的是本地加共享经验的合并效果，而非单独的跨用户共享增益。
- **更多跨用户偏好访问未必更好**：Share-all 的平均成绩通常不及 ShareMem；审计还发现，即使其他用户偏好附有来源标签并被声明为“非权威提示”，智能体仍可能采用其具体取值。

## 7. 优点与亮点

- **问题划分清晰**：将可迁移的操作知识与不可直接迁移的个人取值分开，比单纯扩大记忆访问权限更贴近个性化任务的实际风险。
- **设计具有可操作性**：两阶段更新、可编辑共享池、统一检索预算和用户绑定偏好查询形成了完整的构建—检索—执行流程。
- **不仅报告平均性能，也分析适用边界**：本地覆盖率、演示与智能体轨迹质量、在线准入阈值及偏好误用审计，有助于解释共享何时有效、何时失效。
- **对照较有针对性**：Share-all 在保留当前用户偏好名额、标记外来来源的条件下仍出现干扰，使“限制外来偏好访问”的论证更有说服力。

## 8. 不足与局限

- **真实部署验证不足**：Mind2Web 主实验依据记录的网页状态预测动作，并非真实浏览器中的端到端在线执行；用户也由数据分配模拟。跨组织部署中的权限、同意、隐私泄露和恶意记忆注入尚未得到系统验证。
- **依赖经验来源质量**：将高质量演示换成智能体轨迹后，ShareMem 的性能下降明显；冷启动在线结果也低于离线结果，说明共享可能传播低质量经验。
- **偏好隔离主要依靠抽象与访问边界**：提示词要求移除具体个人值，但论文未证明共享经验不可能残留可识别信息或隐含偏好；用户绑定检索也不能解决当前用户记忆本身不完整、过时或检索失败的问题。
- **收益并非普遍显著**：本地已有充分相关经验时，增益接近于零；某些模型、指标上的提升较小，且 ShareMem 不总优于完整上下文或完整偏好等参考方案。
- **成本与可复现信息仍有缺口**：虽然给出了部分令牌开销和协议说明，但缺少硬件、时延及完整费用数据，难以直接判断大规模多用户部署的性价比。
