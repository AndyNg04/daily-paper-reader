## 摘要
配备工具的自主 AI 智能体的兴起带来了显著的安全风险，包括非预期的工具误用，以及通过间接提示注入（IPI）攻击实施的对抗性操纵。在实践中，OpenAI Codex 和 Claude Code 等已部署的智能体系统结合粗粒度权限规则与基于大语言模型（LLM）的判断，保护工具调用。然而，这两种机制都存在重要局限：静态策略必须预先考虑可能的用户意图，因此难以扩展到开放式任务；LLM 驱动的授权虽能支持动态决策，却会产生不一致的结果，且仍易受到定向 IPI 攻击。为实现可扩展且更一致的授权，我们提出 MetaPermit：一种将语义推断与安全策略执行解耦的基于策略的工具访问控制框架。通过分析智能体与用户的交互，我们提炼出一组精简且与任务无关的元属性，用以刻画用户意图、执行上下文和拟议工具调用之间的关系。借助这些元属性，MetaPermit 无需枚举用户意图即可对工具使用进行授权。运行时，LLM 为每项拟议工具调用推断元属性值，固定策略则根据这些值决定允许或拒绝调用；推断出的属性值及所适用的策略规则使每项决策均可审计。我们使用两种广泛部署的开放权重大语言模型，在涵盖七个任务套件和五种攻击方法的 AgentDojo 与 AgentDyn 基准上评估 MetaPermit。结果表明，与 LLM 驱动的授权相比，MetaPermit 的授权决策一致性提高了 31%；与最先进的防御方法 CaMeL 和 IPIGuard 相比，MetaPermit 在任务完成能力和 IPI 攻击鲁棒性两方面均表现更优，其中任务完成能力的提升最高达 109%，且未执行任何恶意工具调用。

## Abstract
The rise of autonomous AI agents equipped with tools has introduced significant security risks, ranging from unintended tool misuse to adversarial manipulation through Indirect Prompt Injection (IPI) attacks. In practice, deployed agent systems such as OpenAI Codex and Claude Code protect tool invocations through a combination of coarse-grained permission rules and LLM-based judgments about individual proposed actions. Both components, however, have important limitations: static policies must anticipate possible user intents and therefore do not scale to open-ended tasks, while LLM-driven authorization supports dynamic decisions but produces inconsistent outcomes and remains vulnerable to targeted IPI attacks. To provide scalable and more consistent authorization, we propose MetaPermit, a policy-based tool access-control framework that decouples semantic inference from security enforcement. By analyzing agent-user interactions, we derive a compact, task-independent set of meta-attributes that capture the relationships among the user's intent, the execution context, and the proposed tool call. These meta-attributes allow MetaPermit to authorize tool use without enumerating user intents. At runtime, an LLM infers the meta-attribute values for each proposed tool call, while a fixed policy evaluates these values to allow or deny the call, making each decision auditable through the inferred values and the applied policy rule. We evaluate MetaPermit on the AgentDojo and AgentDyn benchmarks, across seven task suites and five attack methods, using two widely deployed open-weight LLMs. The results show that MetaPermit produces 31% more consistent authorization decisions than LLM-driven authorization and outperforms the state-of-the-art defenses CaMeL and IPIGuard in both task completion, with improvements of up to 109%, and robustness to IPI attacks, with no malicious tool calls executed.

# MetaPermit 论文总结

## 1. 核心问题与研究动机

- **研究问题**：如何在 AI 智能体执行开放式任务时，阻止间接提示注入（IPI）诱导的恶意工具调用，同时不妨碍正常任务完成。
- **现有方案的两难**：预先编写的静态权限策略较可预测，但难以穷举用户意图，也难以区分同一工具的合法与恶意参数；让 LLM 直接作出授权判断虽然灵活，却可能受注入内容影响，且重复判断不够稳定。
- **整体思路**：论文不让 LLM 决定“放行还是拒绝”，而让它描述拟议调用与用户请求的关系，再由固定策略作出决定。这是一种将**语义推断**与**安全执行**分离的工具访问控制设计。

## 2. 方法论与技术流程

- **五个有限取值的元属性**分别刻画：用户是否要求行动、请求是否清晰、行动风险高低、工具是否服务于用户目标，以及**具体调用参数是否符合用户目标**。其中，前两个仅依据可信的原始用户请求判断；参数对齐属性使系统能够区分“向正确收款人转账”和“使用同一工具向攻击者转账”。
- **逐次调用的授权流程**：
  1. 智能体提出工具调用后，推断模块读取原始用户请求、可信工具描述、拟调用参数及先前工具结果，输出元属性向量。
  2. 固定的、有顺序的属性策略按“首个匹配规则”给出允许或拒绝结果；无规则匹配、输出无效或不完整时默认拒绝。
  3. 执行闸门仅转发获准调用；被拒调用不会执行，拒绝原因则作为反馈返回给智能体，供其修正行动。
- **策略重点**：工具不相关、参数不对齐、高风险且含糊的请求等会触发拒绝规则；清晰且必要、参数对齐的调用可获准。论文在全部任务套件中使用同一组五个属性和固定规则，而非逐任务制定策略。
- **保证的边界**：给定同一个属性向量，策略结果是确定且可追溯的；但属性由 LLM 推断，**策略无法证明属性判断在语义上正确**。

## 3. 实验设计与对比方法

- **基准与场景**：使用 AgentDojo 的 Workspace、Travel、Banking、Slack 四个套件，以及 AgentDyn 的 Shopping、GitHub、DailyLife 三个动态任务套件；共 **157 个无攻击用户任务**、**1,509 个任务／注入任务配对**。对每个适用配对使用五种攻击模板，形成每个模型 **7,545 个攻击案例**。
- **模型**：主要比较使用 MiniMax-M2.7 和 Qwen3-235B；另用 Qwen3-8B 检查较小模型上的迁移表现。任务智能体与相应防御组件使用同一模型。
- **对比对象**：无防御智能体、基于能力与数据流约束的 **CaMeL**、基于工具依赖图的 **IPIGuard**；另以**直接输出允许／拒绝的 LLM Guard**进行机制消融。
- **指标**：任务完成率（UA）、攻击成功率（ASR），以及同时完成正常任务且攻击失败的 *Secure-Usable* 比例。最后一项有助于识别“仅因任务没有完成而显得安全”的防御。

## 4. 资源与算力

- MiniMax-M2.7 和 Qwen3-235B 通过托管 API 调用；本地 Qwen3-8B 实验使用 **1 张 RTX 5090**，通过 vLLM 运行。
- 论文说明每个任务最多执行 **15 次工具循环**，但**未明确报告完整实验的 GPU 总用量、总运行时长、API／Token 总开销或训练时长**。该工作主要评估推断与策略执行，并未报告为 MetaPermit 训练新模型。

## 5. 实验规模、充分性与公平性

- **覆盖规模较大**：主要比较跨 **7 个套件 × 5 种攻击 × 2 个主要模型**，每模型有 7,545 个攻击案例；另包含 Qwen3-8B 全矩阵测试、直接授权对比、属性移除、拒绝反馈、白盒恶意调用探测等消融。稳定性测试对 **50 个授权查询各重复 20 次**。
- **有助于公平比较的设计**：主要实验对智能体和防御组件使用相同模型；报告 UA、ASR 及联合指标；保留基准原始检查器，并额外审计其误报；MiniMax 结果还提供置信区间和配对显著性检验。
- **仍需审慎解读**：完整攻击案例通常每例只运行一次；推断模块未固定采样参数，跨运行波动仍可能存在。CaMeL、IPIGuard 在所用后端上对程序或工具调用格式较敏感，因此结果体现的是这些配置下的表现，不能直接概括为它们在所有后端上的最优性能。直接 LLM Guard 消融虽使用相同授权查询和模型，两者提示词并非严格只差输出格式。

## 6. 主要结论与发现

- **MiniMax-M2.7**：MetaPermit 的 UA 为 **53.92%**、基准检查器测得的 ASR 为 **0.08%**；CaMeL 分别为 **25.83%／0.27%**，IPIGuard 为 **30.27%／0.91%**。相较 CaMeL，其任务完成率约高 **109%**。
- **Qwen3-235B**：MetaPermit 的 UA 为 **50.13%**、ASR 为 **0%**；CaMeL 为 **42.21%／0.46%**，IPIGuard 为 **41.96%／3.14%**。
- **安全结果的细节**：MiniMax 的六个官方“攻击成功”案例，经作者审计均只是目标字符串出现在模型的 `<think>` 内容中，未执行攻击诱导的工具调用；因此论文同时保留官方 **0.08% ASR**，并报告按执行行为审计的 **0/7,545**。这不等于对所有未来攻击作出零风险保证。
- **稳定性与机制证据**：20 次重复推断中，MetaPermit 有 **42%** 的查询始终得到同一最终判决，直接 LLM Guard 为 **32%**；属性向量本身仅有 **6%** 始终相同。这说明固定策略能过滤部分属性推断波动，而不是消除波动。对 **95 个**直接提供的恶意调用进行白盒探测时，均未进入允许区域。

## 7. 优点

- **授权边界清晰**：LLM 负责有限范围的语义判断，不能改写规则或直接签发最终许可；策略结果及触发规则便于审计。
- **兼顾工具与参数**：不仅判断工具是否必要，也检查收款人、地址、路径等具体参数是否有用户目标依据。
- **重视“安全且有用”**：联合指标和拒绝反馈实验表明，设计目标并非简单阻断所有行动，而是在拒绝异常调用后让智能体有机会完成原任务。
- **提供失效分析**：对检查器误报、基线任务失败方式及属性翻转作了额外检查，使主要结果更容易解释。

## 8. 不足与局限

- **核心语义判断仍依赖 LLM**：攻击者虽不能修改固定策略，却可能诱导模型给出错误属性；论文的安全性是特定测试条件下的经验结果，并非形式化保证。
- **策略并非无需适配**：五个属性与规则是从所评估任务的常见授权条件中提炼的。新业务若涉及复杂授权链、委托关系或特殊风险，仍需设计、验证新属性和规则。
- **开放动态任务的效用损失明显**：尤其在 AgentDyn 套件上，MetaPermit 虽通常优于所测防御基线，但部分任务完成率仍较低；较小的 Qwen3-8B 上，ASR 也未降至零。
- **部署成本与外部有效性待验证**：每次候选工具调用都需额外推断，论文未完整量化延迟与成本；攻击主要来自既定基准和模板，尚不能据此推断对更广泛、持续适应策略的攻击均有效。
