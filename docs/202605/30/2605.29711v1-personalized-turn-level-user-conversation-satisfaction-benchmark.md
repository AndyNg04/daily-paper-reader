## 摘要
用户对AI助手的满意度高度个性化：相同的回答可能让一个用户满意，而让另一个用户失望，这取决于每个用户的期望和之前的提问。现有的自动评估方法大多衡量通用的回答质量，因此难以判断回答是否在特定轮次满足用户。我们将此问题作为个性化轮次级用户对话满意度评估进行研究。我们构建了一个对话满意度评估器，它结合了紧凑的用户记忆与目标轮次上下文，以生成满意度分数和指向不满意的理由。针对人类满意度标注的元评估显示，与基于监督、检索和通用LLM判官基线相比，个性化记忆和事后分数校准提高了序数一致性和不满意轮次检测。我们进一步引入了PersTurnBench，这是一个个性化轮次级用户对话满意度基准，它使用经过验证的评估器通过重放来评估生成模型。通过固定重放状态，PersTurnBench能够对通用生成模型和记忆增强的个性化系统进行受控比较，而无需为每个候选模型收集新的人类标签。该评估器和基准使研究人员能够在个性化满意度方面比较候选生成模型，而无需为每个模型收集新的用户反馈。

## Abstract
User satisfaction with AI assistants is highly personalized: the same response may satisfy one user but disappoint another depending on what each user expects and what they have asked for before. Existing automatic evaluation methods mostly measure generic response quality, making it difficult to judge whether a response satisfies a user at a specific turn. We study this problem as personalized turn-level user conversation satisfaction evaluation. We build a conversation satisfaction evaluator that combines compact user memories with target-turn context to produce satisfaction scores and dissatisfaction-oriented rationales. Meta-evaluation against human satisfaction annotations shows that personalized memory and post-hoc score calibration improve ordinal agreement and dissatisfied-turn detection over supervised, retrieval-based, and generic LLM-as-a-judge baselines. We further introduce PersTurnBench, a personalized turn-level user conversation satisfaction benchmark that uses the verified evaluator to assess generation models via replay. By holding the replay state fixed, PersTurnBench enables controlled comparison of generic generation models and memory-augmented personalized systems without new human labels for every candidate model. The evaluator and benchmark let researchers compare candidate generation models on personalized satisfaction without collecting new user feedback for every model.

*   **研究意义**：该研究旨在构建一个能在**特定对话轮次**、针对**特定用户**来评估满意度的自动化工具。这不仅能让开发者更精细地定位导致用户不满的关键轮次，还能在不进行昂贵的新一轮人工评测的情况下，低成本、可复现地比较不同生成模型在个性化满意维度的表现。

### 2. 方法论

论文提出了一套完整的“个性化轮次级对话满意度评估器”构建流程，并在其基础上建立了基准（PersTurnBench）。

*   **核心思想**：将用户的**历史交互数据**（来自不同任务的对话及满意度评分）压缩成“用户记忆”，并将其作为评估当前轮次回复的关键上下文。
*   **评估器关键组件**:
    1.  **用户记忆构建**: 对于目标用户，收集其在源任务场景中的历史数据（对话、轮次级满意度分数、不满原因）。记忆构建器进行“对比总结”，而非简单描述，例如提炼出“使评分从3分升至4分的要素”或“从4分升至5分的要素”，从而形成一个该用户专属的、可执行的评分规范。
    2.  **轮次级判定**: LLM判官接收**用户记忆**、**用户画像**、**当前任务背景**、**对话上下文**和**待评估回复**，预测一个1-5的满意度分数，并给出诊断性理由。
    3.  **事后分数校准**: 为了解决LLM给出的原始分数与用户评分习惯（如有的用户打分偏严）的系统性偏差，论文引入校准步骤。
        *   **均值偏移校准**: 调整一轮对话中所有回复的原始分数均值，使其与该用户的历史平均分一致。
        *   **CDF校准**: 保留原始分数的组内排序，但将其映射到用户历史分数的累积分布函数上。此方法对检测不满意轮次效果最佳，是PersTurnBench的官方分数。
*   **PersTurnBench基准协议**: 采用“重放”模式。固定历史对话状态和用户记忆，只让候选模型填充当前轮次的回复，然后用冻结的、已验证的评估器进行评分。这确保了不同模型在同一个性化场景下的公平比较。

### 3. 实验设计

实验分为“评估器验证”和“基准构建”两个主要阶段。

*   **数据集**:
    *   **主数据集**: 一个真实的、中文的任务导向对话数据集，包含90名用户的6474个轮次，覆盖菜谱、礼物、旅行和技能学习四种规划任务。包含用户画像、轮次级1-5分满意度标注和不满意原因。
    *   **辅助数据集**: URS（多意图评估基准），用于补充验证，但其只提供会话级满意度。
*   **评估器验证的对比基线**:
    *   **有监督基线**: BERT分类器、序数BERT。
    *   **检索基线**: 检索用户历史中最近似轮次的评分、基于检索增强生成（RAG）的LLM判官。
    *   **通用LLM判官**: 零样本、少样本、任务-规范以及SPUR风格和Prometheus风格的判官，均不接收个性化记忆。
*   **评估指标**: 皮尔逊相关系数、斯皮尔曼相关系数、二次加权Kappa（序数一致性）、不满意轮次检测的F1值（F1-DSAT）。

### 6. 主要结论与发现

1.  **个性化评估的重要性**: 通用评估方法在个性化满意度任务上表现不佳，而引入用户记忆能显著提升与人类标注的一致性，尤其是在检测不满意轮次方面。
2.  **记忆与校准互补**: 结构化用户记忆对于进行语义上准确的满意度判定至关重要；事后CDF校准则能有效纠正分数尺度偏差，两者结合效果最佳。
3.  **基准的区分度**: PersTurnBench能够有效地区分不同能力的生成模型。它不仅报告平均满意度，还报告不满意率，能揭示模型在关键失败案例上的差异。
4.  **简单的记忆增强可能无效**: 在生成阶段，简单地将检索到的原始历史对话片段前置给模型，并不能提升其在基准上的满意度评分。

### 7. 优点

*   **问题切入角度新颖且实用**: 直击当前对话系统评估“忽视个性化”和“粒度太粗”的痛点。
*   **方法论设计巧妙**:
    *   用户记忆的“对比式”构建比简单的“描述性”总结更有信息量，将历史标签转化为了可执行的评分规范。
    *   事后校准策略简单有效，分离了“语义判断能力”和“分数尺度匹配”两个问题。
*   **评估协议严格**: 跨场景评估和重放基准的设计，使得评估严格受控，避免了信息泄露和变量干扰，保证了结果的可复现性和公平性。
*   **资源高效**: 提供了一种低成本、可复现的模型筛选方法，可作为昂贵人工评测的前置步骤。

### 8. 不足与局限

*   **数据局限性**: 主数据集为中文，参与用户以学生为主，且任务局限于规划类场景。结论向其他语言、人群和更开放的对话领域的泛化能力有待验证。
*   **评估不是终极真理**: 自动化评估器只是人类满意度的近似，不能完全替代直接的用户研究。论文也明确指出应将其作为筛查工具。
*   **协议限制**: 重放协议是单轮替换，无法模拟多轮交互下的动态用户适应过程。
*   **校准假设**: 事后校准依赖“用户历史评分分布能代表未来”的假设，这一假设在任务模式发生剧烈变化时可能会失效。
*   **解释性诊断的偏差**: 判官生成的不满理由虽有诊断价值，但它可能与用户的真实首要不满原因存在偏差（如将“未满足需求”错误地诊断为“细节不足”），这在案例研究中得到了证实。
