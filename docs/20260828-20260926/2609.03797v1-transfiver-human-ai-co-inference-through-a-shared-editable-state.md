## 摘要
长期的人机交互十分困难，因为指导推理的信息由模型隐式更新，且用户无法直接检查或控制。我们提出用于交互式、可验证、可编辑表示的 TRANSparent 框架（Transfiver），一种通过共享可编辑状态进行人机协同推理的架构。其核心思想是：特定于交互的信息维护在单一的持久状态 $(S_t)$ 中，由模型和人类共同更新。Transfiver 区分两种状态演化模式。在隐式流式更新中，模型解释正在进行的交互，并决定新信息是修正现有状态项还是创建新状态项。在显式定向编辑中，人类检查并修改被寻址的项。两者作用于同一底层状态，因此人类修正会改变后续计算所读取的状态，而不是添加另一条指令或单独记录。该架构将普通使用前学习到的共享参数 $(θ)$ 与持久状态 $(S_t)$ 分离，后者在部署期间演化而无需重新训练参数。将 Transfiver 扩展到丰富的自然语言、关系型和大规模共享状态仍是开放问题。

## Abstract
Long-term human-AI interaction is difficult because the information that guides inference is updated implicitly by the model and is not directly inspectable or controllable by the user. We introduce the TRANSparent Framework for Interactive, Verifiable, Editable Representation (Transfiver), an architecture for human-AI co-inference through a shared editable state. Its central idea is that interaction-specific information is maintained in a single persistent state $(S_t)$ that both the model and the human update.   Transfiver distinguishes two modes of state evolution. In an implicit stream update, the model interprets ongoing interaction and decides whether new information revises an existing state item or creates a new one. In an explicit directed edit, a human inspects and modifies an addressed item. Both act on the same underlying state, so a human correction changes the state that subsequent computation reads, rather than adding another instruction or separate record.   The architecture separates shared parameters $(θ)$, learned before ordinary use, from the persistent state $(S_t)$, which evolves during deployment without parameter retraining. Extending Transfiver to rich natural-language, relational, and large-scale shared states remains open.

# Transfiver 论文总结

## 1. 核心问题与整体含义

- **研究动机**：长期人机交互中，引导模型推理的交互信息由模型**隐式更新**，用户既无法直接检查也无法控制。当一条信息过时（如会议改期、密码更换、项目规则变更），用户知道需要修正，但修正往往只是"往上下文窗口里再加一句话"，而非真正改变模型实际读取的状态。
- **关键矛盾**：当前多数设计允许"用户可见可编辑的状态"与"产生下一轮输出的计算状态"**相互分离**，因此用户修正未必生效——隐藏的计算路径可能仍携带旧信息。
- **整体含义**：Transfiver 提出一种架构级要求——**用户看到和编辑的状态，必须就是模型计算、更新和回答所依赖的那个状态**。论文将其定位在与 Transformer 或状态空间模型同级的架构层面，目标是让"记忆、推理与输出"统一在一个持续演化的状态中。

## 2. 方法论

### 核心思想

- 交互特定信息维护在**单一持久状态 $S_t$** 中，由模型与人类共同更新。
- 将**共享参数 $\theta$**（使用前离线学习）与**持久状态 $S_t$**（部署期演化）分离，部署期状态变化**无需参数重训练**。

### 两种状态演化模式

- **隐式流式更新（stream update）**：无地址供给。事件到达后，模型自行判断它是修正已有状态项还是创建新项（如密码被替换、决定被取代、主张被撤回）。
- **显式定向编辑（directed edit）**：人类选中可见项并给出新值，系统须使修正生效、不影响无关项、并支持精确恢复。

### 状态表示

- 完整概念状态：$S_t = (\{s_{t,i}\}, R_t, \Gamma_t)$，其中每个状态项 $s_{t,i} = (\kappa_i, v_{t,i}, o_{t,i}, \tau_{t,i}, w_{t,i}, u_{t,i}, p_{t,i}, \sigma_{t,i})$，分别表示身份、内容、占用、事件时间、地位（standing）、使用证据、来源、生命周期。
- 关系稀疏；上下文消息 $m_{t,i} = G_\theta(z_t, s_{t,i}, \{(r_{ij}, s_{t,j})\})$ 只影响当前读取，除非有新事件否则不写入邻居，以保证派生影响**可逆且可归因**。

### 核心契约与审计

- **历史充分性（history sufficiency）**：若两个历史留下相同状态 $S_t$，则任何合法后续输入诱导的未来行为分布应相同。形式化：$S(H_t)=S(H'_t) \Rightarrow \text{Law}(F_\theta(H_t,c))=\text{Law}(F_\theta(H'_t,c))$。
- **无隐藏持久路径**：保存 $(\theta, S_t)$ 并在新进程中恢复，相同输入应复现相同下一状态与预解码输出。
- **可追踪性**：记录每个状态项对输出的贡献 $\hat{L}_{t,i}$，用 $\epsilon_{path}(t)=\|L_t-\hat{L}_t\|$ 检验答案是否来自可见状态。
- **编辑审计指标**：target（目标是否按预期改变）、locality（无关输出是否不变）、rollback（撤销是否恢复原状态）、path（贡献是否加总为实际输出）。
- **对称性与回滚**：槽位重排不改变输出分布；编辑-撤销精确恢复序列化状态则未来行为分布不变（命题 1）。

### 小测试模型

- 状态 $S=(K,V,O,A)$：槽键、值、占用、可训练空槽锚点；无持久循环隐状态。
- 寻址：$b_{t,i}=\langle \bar{q}_t,\bar{K}_i\rangle+\log(O_i+\epsilon)$，经 softmax 得到注意力权重，含一个学习的"不支持"哨兵 $\bot$。
- 每个槽贡献 $L_{t,i}=\alpha_{t,i}W_o(\tanh(W_vV_i)\odot\tanh(W_qh_t))$，预解码 logits 恰为 $\sum_i L_{t,i}+L_{t,\bot}$。
- 转移学习写入概率与硬前向地址（直通梯度估计）；分层路由器先决定"触碰已有身份还是新建身份"，再选择锚点。
- 语义接口受限：将占用槽解码为公开的 (key, value) 分类模式，允许用户替换一个可见项，编辑后的键值写入规范 K、V 张量，后续仍走同一读出。

### 设计原则

- **"先推导再新增"**：新失败不应自动催生新的语义标志、状态字段或模块；应先检验已有区分（内容、上下文、来源、时间、使用、重要性、关系）在表达性学习读取下是否已足够。
- **禁止固定语义权重**：用户依赖的判断（信任程度、何时失效、优先级）不得由固定数值规则替代；但"文本来自用户/模型/文档"这类随输入到达的交付地址是允许的确定性路由。

## 3. 实验设计

### 合成测试（附录 A）

- **上下文与重叠测试**：同一 key 在 context 0 和 context 1 中写入不同值，事件随机交错；查询指定 key 与 context，正确答案是命名 context 中的值，而非最近写入值。
  - 两种条件：context 作为每个事件字段（较易）vs. 仅由一条 header 事件宣告、需在状态中携带（较难）。
  - 值域 16 路，chance = 1/16 = .0625，预设定阈值为 $10\times$chance + 3SE = .095。
  - 5 个 seed，每个 seed 评估 512 条查询。
- **四规则读取测试**：512 token 的 episode，58 个 key 各写 4 次，分 8 个编号 section 作为粗时间戳。查询使用四种规则：最近值、最早值、截至某 section 的值、第 n 个值。同一 episode 中四规则同时出现、彼此答案不同。
  - 读取仅使用每个候选的 5 个数值（是否有关系、关系形成时间比例、在 key 自身关系中的时间秩、section 差、时间秩与命名数字之差）+ 一个四路规则指示器，送入 385 参数（预设上限 400）的小网络。
  - 5 个独立训练模型，每规则 1,280 查询，共 5,120 查询。

### 真实交互记录（第 7.1 节）

- 使用公开多轮人机对话 benchmark，用户先陈述一个值、后续替换它；保留 44 条含旧值与新值标注证据轮的项目。
- 三种开放模型：**Mistral-7B、Qwen2.5-7B、Phi-3-mini**。
- 对比两种处理被取代条目的方式：
  - **prompt deletion**：组装本轮上下文时省略该条目（任何检索系统可用的操作）。
  - **state retraction**：调用 `retract`，读取不再选中该条目，但条目仍留在状态中。
- 两臂展示相同数量的条目，被移除的槽由相同排序回填，确保公平。

### 主要结果

- **四规则读取**：held-out 准确率 1.000 / 1.000 / .984 / .996；替换命名规则后，原规则准确率归零而模型改答替换规则（1.000 / 1.000 / .996 / .984）；替换命名数字后同样跟随替换值（.980 / .992）。key 重命名与 episode 内位置移动下预测完全不变（最大分数变化 0.0）。
- **真实记录**：当前值准确率两臂相同（如 Mistral 均为 .659）。下一轮中，prompt deletion 下旧条目在 31/44 项中回归，准确率下降（.659→.432 等）；state retraction 下旧条目不再回归，准确率保持（.659–.705）。恢复早期值仅 state 臂能做到（14–17/44）。restore after retraction 为 31/44，save-reload 视图一致为 44/44，且这三项在三模型间完全一致（属存储性质而非读者性质）。
- 对照：同时扣留两条证据轮时所有模型均为 0/44。

## 6. 主要结论与发现

- 一个**冻结的持久状态**足以保留支持四种互相冲突的时间读取规则所需的时序结构；替换命名规则或引用会相应重定向读出。
- **状态撤回与提示删除有本质差异**：prompt deletion 不改变状态，被删条目在后续轮次会回归；state retraction 使条目不再被选中但仍保留，从而既能保持下一轮准确率，又能回答"该值以前是什么"。
- **"可用"不等于"会用"**：恢复早期值率（14–17/44）远低于旧条目可见率（31/44），说明仅让条目可见不足以使其被正确读取。
- **save-restore 一致性在读取所消费的那部分状态上成立**：序列化包含内容、地位与关系，事件时间按相对顺序恢复；但来源、重要性与使用计数尚未序列化。
- 历史充分性、干预与恢复要求使 Transfiver 的核心主张**可证伪**。
- 扩展到自由形式自然语言、关系型与大规模共享状态仍是开放问题。

## 7. 优点

- **问题定位清晰且根本**：将"可见状态 ≠ 计算状态"确立为架构级研究对象，而非工程补丁；图 1 的对比直观有力。
- **契约化、可证伪**：历史充分性、干预局部性、回滚精确性、路径完整性等要求均给出形式化定义与审计方法，避免空泛的"可解释性"主张。
- **架构分离干净**：$\theta$ 与 $S_t$ 分离，部署期无需梯度更新即可"从单次事件学习"，同时避免 ROME/MEMIT 式的参数编辑风险。
- **人类权威明确**：模型可判断事件涉及哪个条目，但 retire/restore/correct 的权威归用户，与 Supersede 等"让模型成为更好的记忆管理者"路线形成互补。
- **设计约束克制**："先推导再新增"与禁止固定语义权重的原则，有助于防止架构随失败案例无限膨胀。
- **实验设计中的若干细节严谨**：真实记录实验控制展示条目数、测试分区预先固定且只打开一次、跨模型一致性行作为存储性质的验证。

## 8. 不足与局限

- **架构完整实现缺失**：小测试模型仅覆盖 $S=(K,V,O,A)$，没有关系历史、生命周期、来源、重要性等字段，与式 (1) 的完整状态差距很大。
- **真实记录实验覆盖有限**：仅 44 条、三个 7B 模型、单一 benchmark；缺少与 RAG、MemGPT、Larimar、Memory Layers 等的端到端同条件对比。
- **序列化不完整**：来源、重要性、使用计数尚未序列化，save-restore 结论只覆盖读取所消费的部分状态。
- **合成任务偏差风险**：键、值、section 均为符号；带数字的两条规则只在两个 section 上测试；5 个 seed 中 1 个失败且符号检验不显著。
- **读出与答案路径的分离**：四规则测试只证明区分可从状态中恢复，未证明模型自身的答案路径使用该读出。
- **未报告算力资源**：无法评估训练与推理成本，也难以判断可复现性。
- **潜在新失败模式**：错误身份分配、不同含义被强制合并、单一含义被拆分、虚假来源维护、自读历史污染、安静但重要信息被丢弃。
- **治理与安全义务**：持久用户特定状态带来隐私、删除、导出、访问控制、不确定性展示等要求；个性化还可能适应有害用户行为，产生超出隐私的安全风险。
- **可扩展性未验证**：面向自由形式语言、复杂关系与大规模状态的能力仍是开放问题。
