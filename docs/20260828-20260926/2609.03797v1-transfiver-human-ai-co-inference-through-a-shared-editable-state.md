## 摘要
长期的人机交互十分困难，因为指导推理的信息由模型隐式更新，且用户无法直接检查或控制。我们提出用于交互式、可验证、可编辑表示的 TRANSparent 框架（Transfiver），一种通过共享可编辑状态进行人机协同推理的架构。其核心思想是：特定于交互的信息维护在单一的持久状态 $(S_t)$ 中，由模型和人类共同更新。Transfiver 区分两种状态演化模式。在隐式流式更新中，模型解释正在进行的交互，并决定新信息是修正现有状态项还是创建新状态项。在显式定向编辑中，人类检查并修改被寻址的项。两者作用于同一底层状态，因此人类修正会改变后续计算所读取的状态，而不是添加另一条指令或单独记录。该架构将普通使用前学习到的共享参数 $(θ)$ 与持久状态 $(S_t)$ 分离，后者在部署期间演化而无需重新训练参数。将 Transfiver 扩展到丰富的自然语言、关系型和大规模共享状态仍是开放问题。

## Abstract
Long-term human-AI interaction is difficult because the information that guides inference is updated implicitly by the model and is not directly inspectable or controllable by the user. We introduce the TRANSparent Framework for Interactive, Verifiable, Editable Representation (Transfiver), an architecture for human-AI co-inference through a shared editable state. Its central idea is that interaction-specific information is maintained in a single persistent state $(S_t)$ that both the model and the human update.   Transfiver distinguishes two modes of state evolution. In an implicit stream update, the model interprets ongoing interaction and decides whether new information revises an existing state item or creates a new one. In an explicit directed edit, a human inspects and modifies an addressed item. Both act on the same underlying state, so a human correction changes the state that subsequent computation reads, rather than adding another instruction or separate record.   The architecture separates shared parameters $(θ)$, learned before ordinary use, from the persistent state $(S_t)$, which evolves during deployment without parameter retraining. Extending Transfiver to rich natural-language, relational, and large-scale shared states remains open.

## 1. 核心问题与整体含义（研究动机与背景）

- **长期人机交互的根本困难**：在数月甚至更长的使用中，指导模型推理的信息会被模型隐式更新，用户既无法直接检查，也无法直接控制。旧信息（如已变更的会议时间、已停用的密码、仅适用于某项目的规则）可能继续影响输出。
- **“谁来负责修正”的问题**：现有工作多让模型成为自身记忆的更好管理者（如训练智能体跟踪变化事实、惩罚过时答案），但用户才是知道“会议已改期”的人。用户做出的修正应当是作用于模型实际读取状态的“操作”，而不是向上下文窗口再追加一句话——后者可能在后续轮次被重新组装时丢失。
- **状态分离导致的失效**：许多系统允许用户检查/编辑的状态与真正产生输出的状态分离，因此用户提交的编辑不一定生效，隐藏的计算路径仍可能携带旧信息。
- **Transfiver 的定位**：提出 TRANSparent Framework for Interactive, Verifiable, Editable Representation，要求“用户看到并编辑的状态”就是“模型计算所依赖的状态”。交互特定信息存在于单一持久状态 \(S_t\) 中，由模型和人类共同更新。架构层面与 Transformer 或状态空间模型同级，也可嵌入更大系统，但必须保持为唯一的持久交互特定状态。
- **贡献概括**：提出 Transfiver 的信息模型与人机呈现方式；把“记忆、推理、输出合一的活状态”转化为历史充分性与因果干预契约；提供小型可运行实现；在真实交互记录上验证状态撤回与提示删除的差异。

## 2. 方法论：核心思想、关键技术与流程

- **核心思想**：单一持久状态 \(S_t\) 同时承担记忆、推理、输出与可编辑接口。模型和人类都更新同一状态；人类修正直接改变后续计算读取的内容，而不是追加指令或单独记录。
- **状态的信息模型**（成熟形态）：
  - \(S_t = (\{s_{t,i}\}_{i=1}^{N_t}, R_t, \Gamma_t)\)
  - 每个项 \(s_{t,i} = (\kappa_i, v_{t,i}, o_{t,i}, \tau_{t,i}, w_{t,i}, u_{t,i}, p_{t,i}, \sigma_{t,i})\)，分别表示身份、内容、占用、事件时间、standing、使用证据、来源、生命周期。
  - \(R_t\) 保存当前关系，\(\Gamma_t\) 保存关系或事件历史；关系稀疏。
  - 事件编码 \(z_t\) 是每步唯一的新信息；上下文消息 \(m_{t,i}\) 可影响当前读取，但不会写入邻居，除非转移观察到关于该邻居的新事件，从而保持派生影响可逆、可归因。
- **两种状态演化模式**：
  - **隐式流式更新**：无地址提供。事件到达时，系统自行判断它是对已有项的修订还是新项。适合密码更换、决定被取代、声明撤回等场景。
  - **显式定向编辑**：用户选择可见项并给出新值。要求修正生效、不影响无关项、支持精确恢复。
  - 两者作用于同一底层状态；系统需同时具备两种能力，并分别评估。
- **离线学习与在线演化分离**：
  - 离线训练：\(S_{t+1}=T_\theta(S_t,z_t)\)，\(\theta \leftarrow \theta-\eta\nabla_\theta\sum_{t=1}^{H}L(y_t,y_t^\star)\)。
  - 部署期：\(\theta\) 固定，\(S_{t+1}=T_\theta(S_t,z_t)\)；定向编辑直接修改 \(S\) 的指定地址，不改变 \(\theta\)。
  - “从一次事件学习”意味着持久状态改变，而非梯度重训练。
- **设计约束**：
  - 禁止用固定数值替代本应属于用户的判断（如来源信任度、项何时不再有效、优先级）。
  - “先推导，再添加”：新失败不应自动引入新语义标志或状态字段，应先检查现有区分（内容、上下文、来源、时间、使用、重要性、关系）在表达性学习读取下是否已能产生所需行为。
- **可验证契约**：
  - **历史充分性**：若两个历史使系统进入相同状态，则任何未来延续下行为分布相同。形式化：\(S(H_t)=S(H'_t)\Rightarrow \mathrm{Law}(F_\theta(H_t,c))=\mathrm{Law}(F_\theta(H'_t,c))\)。
  - 持久变量不得存在于 \(S_t\) 之外；保存 \((\theta,S_t)\) 并在新进程恢复后，相同输入应产生相同下一状态与预解码输出。
  - 可选路径追踪：\(\hat L_t=\sum_{i\in I(S_t)}\hat L_{t,i}\)，路径完整性 \(\epsilon_{\mathrm{path}}(t)=\|L_t-\hat L_t\|\)。
  - 审计指标：目标改变率 \(\mathrm{target}(i,q)\)、局部性 \(\mathrm{locality}(i,q)\)、回滚 \(\mathrm{rollback}(i,q)\)、路径完整性 \(\mathrm{path}(t)\)。
  - 对称性：槽位重排不应改变输出分布，下一状态分布应相应置换；生命周期操作不应依赖任意存储索引。
- **小型测试模型**：
  - \(S=(K,V,O,A)\)：槽键、值、占用、可训练空槽锚点；无持久循环隐藏状态。
  - 寻址：\(b_{t,i}=\langle\bar q_t,\bar K_i\rangle+\log(O_i+\epsilon)\)，经 softmax 得到注意力 \(\alpha_{t,i}\) 与不支持哨兵 \(\alpha_{t,\bot}\)。
  - 每个槽产生 \(L_{t,i}=\alpha_{t,i}W_o(\tanh(W_vV_i)\odot\tanh(W_qh_t))\)，预解码 logits 为 \(\sum_i L_{t,i}+L_{t,\bot}\)。
  - 转移学习写入概率与硬前向地址，使用直通梯度估计；分层路由器先选择“触及已有身份”还是“创建新身份”，再选择可用锚点。
  - 语义接口有限：将占用槽解码为公开分类模式 (key, value)，允许用户替换一个可见项；编辑写入规范 \(K,V\) 张量，后续答案走同一读出。

## 3. 实验设计：数据集/场景、Benchmark 与对比方法

- **合成测试 A.1：上下文与重叠**
  - 场景：同一内容置于两个不同上下文，地址由 key 和 context 两半组成。一个 episode 在 context 0 写四个事实，在 context 1 写相同四个 key，其中两个 key 在两个上下文中故意取不同值；两个上下文的事件随机交错。
  - 条件：较易条件中 context 是每个事件的字段；较难条件中仅由一个 header 事件宣布 context，后续事件不带 context 字段，必须由状态携带。
  - 规模：值空间 16 路，chance=0.0625，预指定阈值 \(10\times\text{chance}+3SE=0.095\)；5 个种子，每种子 512 个评估查询，评估种子与训练种子不相交。
  - 指标：上下文条件准确率、近因崩溃、翻转查询上下文返回另一值、同一 key 放在不同项、撤回上下文改变先前答案、恢复上下文精确返回、重叠度、每 episode 创建项数。
- **合成测试 A.2：从同一状态读出四种规则**
  - 场景：episode 长 512 token，58 个 key 各写 4 次，夹杂无关填充，分为 8 个编号 section 作为粗时间戳。每 episode 末尾 8 个查询。
  - 四种规则：最近值、最早值、截至某 section 的值、第 n 个值；后两者携带数字（本评估中为第二或第三）。四种规则在同一 episode 中出现，每规则两个查询，彼此答案不同。
  - 读取器：冻结状态，对每个 key 的 205 个允许值取 5 个数字——是否有关系到候选、关系形成距今时间比例、在 key 自身关系中的时间排名、形成 section 与查询命名 section 之差、时间排名与查询命名数字之差；外加四路规则指示器。送入一个 385 参数的小网络（预先上限 400），逐候选打分，取最高分。
  - 规模：5 个独立训练模型，每规则 1280 查询，共 5120 查询；测试分区预先固定，只打开一次，禁止重试与再生。
  - 控制：替换命名规则、替换命名数字、重命名所有 key、在 episode 内移动项。

  - 指标：干预时当前值准确率、恢复更早值、旧条目下一轮返回、下一轮当前值、撤回后恢复、保存重载后相同视图。

  - 合成上下文任务以 chance 和预指定阈值作为基线；四规则任务以四值之一（0.250）为主要基线，均匀猜测 0.005 为参考。

## 6. 主要结论与发现

- **单一冻结持久状态可保留足够时间结构**：在四规则读出测试中，5 个模型在最近值、最早值、截至某 section、第 n 个值上的准确率分别为 1.000、1.000、0.984、0.996；替换命名规则后，原规则准确率降至 0，而读出转而回答替换后的规则（0.984–1.000）；替换命名数字后，原数字准确率降至 0，转而回答替换数字（0.980–0.992）。说明状态中的时间区分可被不同读取规则恢复。
- **上下文分离可行**：在“context 每事件给出”条件下 5 个种子中 4 个成功；在“context 由 header 宣布并由状态携带”条件下 5 个种子全部成功。成功时同一 key 在两个上下文中占据不同条目，答案跟随查询中的 context 而非最近写入；撤回 context 会改变先前答案，恢复占用向量可
