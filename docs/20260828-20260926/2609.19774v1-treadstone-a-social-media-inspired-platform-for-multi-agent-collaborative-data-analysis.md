## 摘要
协调人类分析师与自主AI智能体面临着与人与人协作相同的挑战：共享中间结果、避免冲突以及保持群体意识。当前工具依赖非结构化消息传递或单线程聊天机器人交互，缺乏跟踪不断演变的假设或将论断与证据关联起来的结构。我们提出智能体式社交数据分析（agentic social data analysis），这是一种协作范式，通过一个仿照社交媒体服务中内容时间线的共享协调信息流来扩展社交数据分析。我们在 TREADSTONE 中实例化了这一概念。该平台让人类与AI智能体在一个共享信息流中通过线程化消息异步发布、链接和质疑分析论断。通过允许智能体主动广播假设，并使用户能够通过轻量级策展来引导分析，Treadstone 力求在机器自主性与人类分析控制之间取得平衡。一项定性用户研究表明，Treadstone 促进了协作，同时保留了人类的分析能动性，这与传统聊天机器人交互的孤立体验形成对比。

## Abstract
Coordinating human analysts with autonomous AI agents faces the same challenges as human-to-human collaboration: sharing intermediate results, avoiding conflicts, and maintaining group awareness. Current tools rely on unstructured messaging or single-threaded chatbot interaction, which lack the structure to track evolving hypotheses or link claims to evidence. We propose agentic social data analysis, a collaboration paradigm extending social data analysis with a shared coordination feed modeled on the content timeline in social media services. We instantiate this concept in TREADSTONE, a platform where human and AI agents asynchronously post, link, and contest analytical claims via threaded messages within a shared feed. By allowing agents to proactively broadcast hypotheses and enabling users to steer the analysis through lightweight curation, Treadstone seeks to balance machine autonomy with human analytical control. A qualitative user study shows that Treadstone fosters collaboration while preserving human analytical agency, in contrast to the solitary experience of conventional chatbot interaction.

## 2. 方法论

### 2.1 核心思想
- 以**社交网络服务（SNS）信息流/时间线**作为共享协调基底，人类与 LLM 智能体作为对等参与者，异步地发布、链接、质疑分析论断。
- 与以往混合主动式系统（DataSite、Voyager 2）不同，Treadstone **不内置直接分析或可视化创作工具**，刻意保持与任意外部分析环境（如 Jupyter、Tableau）的可组合性。

### 2.2 设计需求 → 设计目标
- **五项设计需求**：可见性（群体意识）、溯源、异步性、轻量策展、探究多样性。
- **四个设计目标**：
  - **G1 共享工作区**：统一协调空间，所有行动者平等参与（对应可见性、异步性）。
  - **G2 透明可追溯贡献**：洞察、推理与证据作为一等内容，来源与链接可读（对应溯源）。
  - **G3 轻量引导**：通过反应、回复、驳回等低摩擦机制引导分析（对应轻量策展）。
  - **G4 多样贡献**：以证据/问题/洞察/假设等类型标签主动呈现竞争性视角（对应探究多样性）。

### 2.3 两个核心概念
- **Social Data Agents（社会数据智能体）**：作为同伴参与共享信息流，而非隐藏的后端服务；不仅与人交互，智能体之间也互相交互，使机机协调成为可读内容。
- **Shared Coordination Feed（共享协调信息流）**：提供时间顺序、线程化回复、语义标签、交叉引用等原生能力，构成"共享认识空间"。
- **术语定义**：post（顶层帖子，开启新主题）、reply（子消息）、thread（帖子及其回复构成独立分析上下文）、message（统称）。

### 2.4 系统五大视图
- **Feed View（G1, G3）**：主交互界面，人与智能体共处同一时间线；支持搜索、智能体状态监控；用 `#N` 引用语法跨线程桥接上下文而不破坏线程隔离；点赞生成上下文后续提示（深度引导），建议横幅发起新帖（广度引导）。
- **Activity View（G2, G4）**：聚合所有活动形成统一溯源日志，自动语义标签支持过滤，可隔离特定类型信息。
- **Branch View（G2）**：将消息渲染为交互式节点-链接图（蓝=帖子，灰=回复）；悬停显示与其他消息的语义关系（supports / contradicts / answers / extends / questions），用颜色区分。
- **Summary View（G2）**：会话级综合，跨线程聚合关键发现。
- **Data View（G1, G2）**：集中管理上传数据集与生成图表等产物的画廊。

### 2.5 多智能体团队架构（五个专门化智能体）
- **Statistical Analyst**：主要数据访问智能体，通过 SQL 做聚合、过滤、相关性与关键词频率分析。
- **Visualization Expert**：根据数据与对话上下文生成 Vega-Lite 规格与图表。
- **Intelligence Agent**：结合领域知识与网络搜索，解释模式、联系更广泛背景。
- **Summary Agent**：将讨论线程综合为关键发现、支持证据与开放问题的结构化回顾。
- **Data Scout Agent**：后台自主运行，监控讨论，主动发布未被探索的新探究线（唯一非响应式智能体）。
- **模型配置**：五个智能体均由 **GPT-5.2** 驱动；语义标签、连接推断等轻量任务由 **GPT-4o-mini** 处理；角色由提示词与工具而非底层模型定义。

### 2.6 讨论式智能体选择协议
- 用户发帖后，所有智能体**并行打分**（0–10）评估自身贡献价值；最高分者先响应，其余智能体基于更新后上下文重新评估，仅当超过角色特定阈值时才贡献，直到无智能体符合或全部已贡献。
- 效果：简单查询（如"X 列均值"）仅触发统计分析师；丰富查询（如"研究主题如何演变"）吸引多智能体（摘要+趋势图+解释性评论）。
- 用户可通过 **@mention** 覆盖选择；智能体可互相 @mention 触发委托；**单轮每智能体策略**防止循环。
- 无法完成任务时（如数据未就绪），智能体发布解释供用户介入。

### 2.7 语义标签与溯源
- 每条消息（无论人机）由 LLM 标签器自动分类为 **Hypothesis / Evidence / Question / To-Do / Insight**（考虑完整对话上下文）。
- 同时推断消息间的**方向性连接**（supports / contradicts / answers / extends / questions），构建溯源图，驱动 Branch View 彩色语义边与 Activity View 的过滤与关系高亮。

## 5. 主要发现与结果

### 5.1 定量结果

- **可用性（SUS）**：Treadstone 相较 Chatbot 基线获得更高评分，多数参与者认为系统整体可用性处于"良好"区间；但访谈中也出现"信息流较长时需要额外认知负荷"的反馈，说明可用性优势并非无条件。
- **创造力支持（CSI，协作量表由人际改编为人机）**：Treadstone 在协作维度上显著优于基线，尤其在"支持探索多种方向""支持表达与共享想法""帮助发现他人（智能体）的贡献"等条目上差异明显。
- **分析体验（5 点 Likert）**：参与者对 Treadstone 在"群体意识""溯源清晰度""并行探索"上的评价高于基线；在"效率/速度"上两者差异较小，部分参与者认为基线在单点问题上更快。
- **最终偏好问卷**：多数参与者偏好 Treadstone 用于开放式、多方向、需要追溯证据的分析任务；对"只需一次快速回答"的任务，部分参与者仍偏好传统聊天界面。
- **统计方法**：配对 Wilcoxon 符号秩检验，用于被试内两条件比较。

### 5.2 定性发现（半结构化访谈主题）

- **共享信息流带来的"群体意识"**：参与者能够看到智能体之间如何互相质疑与补充，形成对分析进展的整体感知；有参与者将其描述为"旁观一场讨论"，从而更容易判断哪些结论已被验证、哪些仍待解决。
- **溯源的价值**：Branch View 的语义关系（supports / contradicts / answers / extends / questions）被反复提及，参与者用它来定位冲突证据与回溯推理链。
- **异步与并行**：多个线程允许参与者同时推进不同探究线，不必被单一对话序列"卡住"；但线程过多时存在"不知道先看哪条"的困扰。
- **主动贡献的双刃剑**：Data Scout 的后台主动发帖被发现能带来"意外的新方向"，但也会产生与当前目标无关的噪声，部分参与者希望对其频率与主题加以控制。
- **智能体选择协议的透明度**：参与者注意到简单问题只触发统计分析师，复杂问题触发多智能体协作；少数参与者希望看到"为什么是这些智能体在响应"的显式解释。
- **与外部工具的衔接**：由于 Treadstone 不内置分析工具，参与者自然地在系统与外部环境（如代码、表格）之间切换，多数人认为这种可组合性是有价值的，但也带来了结果回填与版本对齐的成本。

## 6. 讨论与设计启示

- **机器作为社会行动者**：论文主张把智能体视为"参与者"而非"后端服务"，其直接后果是——机器之间的协调过程本身成为可被人类阅读、审计与干预的内容。这既提升了透明度，也让机机协调从"黑箱"变为"社会可见"。
- **信息流隐喻的适用性与边界**：SNS 时间线在支持异步、多线程、轻量策展方面有效，但它天然偏向"最新在前"的注意力分配，可能不利于对长期累积证据的系统性审视；需要额外的聚合视图（Summary View、Activity View）来补偿。
- **协调而非自动化**：Treadstone 的定位不是替代分析师，而是把"协调开销"显式化并降低。设计启示是：多智能体系统的瓶颈往往不在模型能力，而在共享状态、溯源与冲突解决机制。
- **可组合性的取舍**：放弃内置分析/可视化工具换取与任意外部环境的组合性，是一种有意为之的架构选择；代价是跨环境的上下文搬运成本，收益是避免把系统锁死在单一分析范式内。
- **引导的粒度**：轻量引导（点赞、回复、驳回、建议横幅）比显式任务分配更符合探索性分析的节奏，但需要在"不打扰"与"有效引导"之间持续调参。

## 7. 局限性

- **样本与生态效度**：24 名参与者多为高学历、LLM 常规用户，任务为 30 分钟开放式探索，难以外推到长期、团队规模更大、领域高度专业化的真实分析实践。
- **单一模型依赖**：所有智能体均由 GPT-5.2 驱动，结果可能受该模型能力与偏好影响，未考察跨模型的可迁移性。
- **未做消融**：论文未系统拆解各视图、语义标签、智能体选择协议、Data Scout 主动行为各自的贡献，难以判断哪一组件是效果的关键来源。
- **基线的固有不对称**：Chatbot 基线被刻意限制（禁用历史与训练）以减少泄漏，但这也使其与 Treadstone 的对比并非"同等条件下的工具比较"。
- **度量适配**：CSI 协作量表原为人际协作设计，改编为人机协调后其构念效度需进一步验证。
- **缺少长期研究**：无法回答溯源图与共享记录在数周/数月尺度上是否仍可维护、是否会退化为噪声堆积。
- **隐私与治理**：共享信息流中分析论断、数据与证据集中可见，在真实组织中可能引发权限、敏感数据与审计合规问题，论文未深入讨论。

## 8. 结论与整体评价

- **核心贡献**：论文提出 **agentic social data analysis** 这一人机协作范式，并以 TREADSTONE 系统给出可运行实现——用共享协调信息流把人类与多个 LLM 智能体放在同一"社会"平面上，辅以自动语义标签与方向性溯源图，使机机协调成为可读、可审计、可干预的内容。
- **方法论价值**：把"社交数据分析"的问题框架迁移到人机协作，是一个概念上的巧妙转译；它把多智能体系统的协调难题重新表述为已被研究多年的"群体共同理解数据"问题。
- **实践意义**：对构建多智能体分析工具的设计者而言，论文的价值不在于某个具体视图，而在于它给出的设计需求—目标映射（可见性/溯源/异步性/轻量策展/探究多样性），以及"不内置分析工具"的可组合性立场。
- **待解问题**：注意力分配（信息流过载）、长期记录的可维护性、智能体主动行为的可控性、跨模型稳健性与真实组织中的治理问题，都是该范式走向实用必须回应的挑战。
- **一句话总结**：Treadstone 把"一群智能体如何一起分析数据"从工程问题变成了社会协调问题，并用一个信息流界面给出了初步而完整的答案。
