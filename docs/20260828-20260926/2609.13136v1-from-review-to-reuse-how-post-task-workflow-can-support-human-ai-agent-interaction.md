## 摘要
AI智能体可以通过将单个自然语言请求转化为跨越工具、文件和应用程序的多步骤过程来自动化任务。用户往往只能根据碎片化的执行信息和最终输出来判断该过程。为使已完成的过程更易于理解、验证和复用，我们研究了任务后工作流：对智能体已完成执行的可编辑、基于图的表示。我们首先分析了来自 n8n 的 10,803 个公开工作流模板，以刻画真实世界的自动化实践，然后开发了 Trace2Flow，一个研究探针，用于将智能体执行轨迹转化为可交互的任务后工作流。在一项研究中，参与者（N = 20）审查了包含提示或智能体错误的智能体执行。我们发现，与仅提示条件相比，任务后工作流提升了他们的理解和错误检测能力，并且验证主要是在用户跨多个证据来源进行交叉核对时取得成功。对于后续任务，调整工作流在成功率、时间和难度上与调整先前提示相当，并且往往更受偏好。

## Abstract
AI agents can automate tasks by turning a single natural-language request into a multi-step process spanning tools, files, and applications. Users are often left to judge that process from fragmented execution information and the final output. To make the completed process easier to understand, validate, and reuse, we investigate post-task workflows: editable, graph-based representations of an agent's completed execution. We first analyzed 10,803 public workflow templates from n8n to characterize real-world automation practice, then developed Trace2Flow, a research probe that translates agent execution traces into interactive post-task workflows. In a study, participants (N = 20) reviewed agent executions with prompt or agent errors. We found that post-task workflows improved their understanding and error detection over a prompt-only condition, and that validation succeeded mainly when users cross-checked across multiple evidence sources. For follow-up tasks, adapting the workflow matched adapting the prior prompt in success, time, and difficulty, and was often preferred.

## 1. 核心问题与整体含义

- **研究动机**：LLM 驱动的 AI 智能体可将一句高层自然语言提示转化为跨工具、跨文件、跨应用的多步骤执行流程。然而，这种"高层委托"的便利性把负担转移给了用户——用户必须审查智能体如何理解意图、核验其动作与产出、并识别潜在错误。
- **核心矛盾**：现有智能体界面（如 Claude Cowork）虽暴露了动作轨迹、工具调用、中间输出等单点执行痕迹，但信息是碎片化、线性且密集的；用户难以把这些分散信息拼接成"任务究竟是怎样完成的"整体图景。论文引用 Dhanorkar 等的发现：开发者很少实时监控编码智能体，事后审查（post-hoc review）才是实践中主要的监督形式。
- **整体含义**：论文提出并实证考察"任务后工作流"（post-task workflow）——将智能体**已完成**的执行转化为可编辑的、基于图的表示，作为一种**描述性而非规定性**的制品（descriptive, not prescriptive）。它保留自然语言提示的灵活性，同时把动作、中间产物与依赖关系组织成连贯结构，服务于两个方向：
  - **向后看（looking backward）**：理解执行、验证结果、定位错误；
  - **向前看（looking forward）**：复用、改编已验证流程以完成相关新任务。
- **两个研究问题**：
  - **RQ1**：任务后工作流如何帮助用户理解智能体做了什么、验证任务结果、识别可能的执行错误？
  - **RQ2**：对于相关的新任务，用户更偏好复用改编已有工作流，还是重新用提示委托智能体？

## 2. 方法论

### 2.1 核心思想

将智能体的完整执行轨迹（execution trace）翻译为**可执行、可编辑的图结构工作流**，节点表示任务操作，边表示数据/控制依赖。与既有"从提示或演示生成工作流"的研究不同，本文的工作流在**任务完成后**才呈现，作为解释性制品，不限制智能体在提示阶段的开放性。

### 2.2 设计目标（源自文献原则 + 形成性研究）

- **DG1**：让执行过程可见、可追溯——在单一图中共呈现动作、步骤、工具调用，可追溯结果如何产生、查看每步输入输出、按需重跑单步。
- **DG2**：支持基于工作流的改编与复用——仅修改必要输入、步骤或工具，保留其余流程。
- **DG3**：补充而非替代自然语言委托——提示委托与自动生成工作流无缝衔接。

### 2.3 Trace2Flow 系统

- **双界面**：① 聊天界面（模仿 Claude Cowork，含进度清单与当前活动指示器，任务完成后有 "Workflow" 按钮）；② 工作流画布（图结构，选中节点可查看/编辑输入、参数、输出；可增删节点、改连线、重跑全流程）。
- **轨迹到工作流的翻译（三阶段）**：
  1. **Grounding（接地）**：检视执行轨迹，将任务相关工具执行匹配到工作流节点规格，保留预期输入输出及一个真实观测到的示例输出，形成任务特定的节点目录（node catalog），约束后续生成。
  2. **Generation（生成）**：以原始提示、执行轨迹、接地节点规格为输入，由 LLM 重建为紧凑的**中间表示（IR）**，决定需要哪些操作、如何配置、数据如何在节点间传递（如 `list_1.files` 表示下游节点消费 `list_1` 的 files 输出）。
  3. **Compilation（编译）**：将 IR 转为画布所需的结构化表示，实例化节点、把符号引用转为显式输入绑定与图边，并校验引用的节点存在、输出与下游输入兼容；若校验失败，把 IR、编译结果与错误反馈给 LLM 再做一次重生成尝试。

## 3. 实验设计

### 3.1 真实工作流实践分析（基础研究）

- **数据**：截至 2026 年 7 月收集的 **10,803 个 n8n 公开工作流模板**。
- **任务域分类**：人工审阅 100 个随机样本后建立四类目的导向标签（客户运营、内容生产、数据分析、个人助理 + 其他），再用 LLM（gpt-5.6）对全部模板分类。结果：客户运营 3,061（28%）、数据分析 2,336（22%）、个人助理 2,340（22%）、内容生产 2,103（19%）、其他 963（9%）。
- **复杂度分析**：中位数 17 个节点、12 条边、最长路径 8 步；平均节点度 1.4（稀疏连接），环数中位数为 0；17% 为纯顺序，49% 含恰好一个分支/合并，24% 含至少一个环。
- **节点功能分类**（基于 n8n 官方 195 个节点及其支持操作，用 LLM 分类）：任务动作（94%）、工作流控制（87%）、数据处理（82%）、AI 支持操作（51%）。高频节点：Code 54%、Set 52%、HTTP Request 50%、If 45%、AI Agent 34%。

### 3.2 形成性研究（两份问卷）

- AI 智能体用户问卷：**42 份有效回答**（每周至少使用一次）。
- 工作流自动化用户问卷：**39 份有效回答**。
- 发现：智能体用户难以理解执行、核验结果、定位错误，需要步骤级与中间信息可见性；工作流用户认为图表示有助于理解多步流程、定位失败、测试/修改单步；任务相似时偏好工作流复用，任务差异大或探索性时偏好自然语言委托。

### 3.3 用户研究（主实验）

- **设计**：被试内（within-participant），两条件（chat vs. workflow），条件顺序与任务对分配做平衡。
- **被试**：招募 22 人，**20 人完成并纳入分析**（12 男 8 女，18–32 岁）；7 人有近一个月内的工作流自动化经验，13 人无。均要求每周至少使用一次 AI 智能体工具。补偿 €15 礼品卡，通过伦理审查。
- **任务集**：基于真实 n8n 工作流构造 **5 个任务对（T0–T4）**，每对含一个审查任务与一个结构相近、仅局部改动的后续任务，覆盖数据分析（T0、T3）、客户运营（T1、T4）、内容生产（T2），涉及本地文件、网页、Slack、Google Sheets 等工具。
- **错误注入**：每个审查任务选取一种错误——2 个**提示错误**（T2、T3：需求遗漏或表述错误）、3 个**智能体错误**（T0、T1、T4：误解或未遵循提示）。
- **Wizard-of-Oz 复现**：所有被试对同一任务看到完全相同的执行轨迹、错误与（工作流条件下的）同一工作流。
- **流程**：T0 任务对做教程 → 每人完成 2–3 个会话（前两会话覆盖两种条件，时间允许则加第三会话）→ 审查任务中判断是否成功完成并说明理由、描述主要步骤/工具/流程、自评理解度（5 点）→ 完成后续任务 → 半结构化访谈。

### 3.4 测量指标与分析方法

- **RQ1**：步骤精确率/召回率、工具精确率/召回率、流程理解准确率（预设问题）、自评理解度（5 点）、验证成功（二元）；另对屏幕录像做人工编码，识别 output check / workflow check / cross-check 三类审查行为。
- **RQ2**：任务成功（二元）、完成时间、感知难度（5 点）；分析提交的提示、改编的工作流、录像与访谈。
- **统计**：非二元指标在被试内按条件聚合后使用**双侧 Wilcoxon 符号秩检验**；两个二元结果（验证成功、后续任务成功）保留会话级观测（N=46），使用**逻辑混合效应模型**：`Success ~ Condition + TID + Session Number + (1 | Participant ID)`。

### 3.5 对比方法

对比并非与多种算法/系统比较，而是**同一系统内两种交互条件的对照**：chat 条件（仅聊天界面 + 可参考原提示重写新提示）vs. workflow 条件（额外可访问并改编任务后工作流）。核心 baseline 即"仅提示"这一当前智能体界面的典型形态。

## 6. 主要结论与发现

### RQ1：审查与验证

- **理解提升**：工作流条件下步骤召回（M=.94 vs .78，p<.01）与工具召回（M=.84 vs .66，p<.05）显著更高；精确率两条件均高且无显著差异；流程理解准确率（M=.82 vs .57，p<.05）与自评理解度（M=4.47 vs 3.88，p<.05）显著更高。
- **验证成功率**：工作流条件 15/23（65%）vs. chat 条件 7/23（30%），条件效应显著（β=2.62，SE=1.04，p<.05）；任务整体效应显著（χ²(3)=8.66，p=.034），T3 显著高于 T4（OR=85，p=.019）；会话序号不显著。
- **任务级差异**：T2（路由错误，17% vs 83%，Δ+66%）、T3（缺失分支，67% vs 100%，Δ+33%）工作流帮助最大；T1（需判断 CV 中虚构地点，33% vs 50%，Δ+17%）帮助最小，因为错误取决于内容正确性而非执行结构；T4 最难（0% vs 33%），工作流暴露了"未使用已有评论做过滤"的缺失依赖，但线索较隐蔽，多数人仍忽略。
- **审查模式（关键发现）**：仅做输出检查成功率 1/10（10%）；仅做工作流检查 0/2（0%）；输出+工作流分别检查 4/8（50%）；跨来源交叉核对时整体 17/23（74%），工作流条件下达 11/13（85%）。**验证成功主要来自多证据来源的交叉核对**，而非单纯看到更多信息。
- **访谈**：20 人中 17 人认为工作流有帮助（2 人认为价值有限，1 人觉得图更令人困惑）；14 人强调流程透明（"分步结构与控制流"），7 人看重可打开单步查看输入输出与工具调用结果（"不只是最终回复，还有工具调用回复"）；成功识别 T2/T3 错误的参与者中 70% 明确提到工作流的作用（如"少了第三个分支"）。

### RQ2：后续任务的复用与改编

- **结果相当**：任务成功 17/23（74%，workflow）vs 13/23（57%，chat），条件效应不显著；完成时间略长（6分12秒 vs 5分24秒），感知难度相近（1.77 vs 1.48），均无显著差异。
- **偏好分化**：9 人偏好改编工作流、6 人偏好改提示、5 人视情况而定。偏好工作流的理由：更易定位需改动处、任务已被拆成显式步骤、可先测试单步再整体运行、感觉更"具体可控"（如"工具箱"vs"脆弱的"提示）。偏好提示的理由：学习成本高、不熟悉模块不敢删改、改动多时工作流编辑繁琐。
- **关键观察**：6 位偏好提示的参与者中，若要求从零写新提示，仅 1 人（P15）仍偏好提示——说明其偏好实质是**提示复用**而非提示本身；而原提示在实践中未必易得，这使工作流作为持久制品的价值凸显。
- **经验与改编范围**：7 位有工作流经验者中 6 人偏好工作流；13 位无经验者中 3 人偏好工作流、6 人偏好提示、4 人视情况（作者标注为探索性）。局部小改动倾向工作流，需大规模重构时倾向提示。

### 讨论层面的结论

- 任务后工作流可视为一种**事后程序性透明**（post hoc procedural transparency），价值不在暴露更多信息，而在**组织**分散于提示、轨迹、工具活动与最终输出之间的信息。
- 工作流在**错误体现在执行结构上**时最有效（错误路由、缺失分支、缺失依赖）；当错误依赖对底层内容正确性的判断时，工作流帮助有限。
- 工作流可成为承载已完成流程的**持久制品**，与提示复用并存而非取代。

## 7. 优点

- **问题定位精准**：把"智能体自主性提高后用户被遗留的监督工作"具体化为理解、验证、复用三个可操作环节，并用"向后看/向前看"框架组织研究问题。
- **描述性而非规定性的设计立场**：明确区别于把工作流当作执行规格（会限制提示灵活性）的既有路线，保留了自然语言委托的开放性与工作流的结构性两者优势。
- **真实实践驱动**：以 10,803 个真实 n8n 模板刻画任务域、复杂度与节点功能，既支撑设计空间，又直接指导研究任务集的构造，使实验任务贴近真实自动化实践。
- **严谨的实验控制**：被试内设计 + 条件与任务对平衡 + Wizard-of-Oz 复现 + 多来源三角互证（量化指标、屏幕录像编码、访谈、产出物），并区分二元/非二元结果采用不同统计策略（混合效应模型控制被试随机截距与任务效应）。
- **对负面结果的诚实处理**：后续任务中未发现显著差异时，不强行宣称工作流更优，而是转而分析偏好形成条件（经验、改编范围、提示可得性），并指出提示偏好实质是"提示复用偏好"，这一洞察具有实践价值。
- **边界自觉**：明确指出工作流无法替代对底层数据的核验，并提出"每步应链接到其消费与产出的确切数据与制品"的设计改进方向。

## 8. 不足与局限

- **样本与统计功效**：仅 20 名被试（工作流经验者仅 7 人），亚组比较功效不足，作者自认属探索性；二元结果每格仅 5–6 个会话，混合效应模型的部分估计（如 OR=85）不稳定，置信区间可能极宽。
- **任务覆盖有限**：5 个任务对规模与结构复杂度受控（最长路径 5–10 步，简化过），后续任务仅做局部改动，无法推断更大工作流或需大范围重构时的表现；错误
