Abstract
Managing concurrent tasks across separate agent
sessions quickly exhausts human attention, mo-
tivating always-on personal agents behind a sin-
gle continuous interface. Yet when every context
shares identical frozen backbone weights, fun-
neling interleaved dialogues and external events
into one linear session induces cross-topic con-
straint bleed and head-of-line stalling. Conversely,
router–ticket hierarchies incur lossy prose hand-
offs, heavy routing overhead, and blind merges—
collapsing true-conflict repository merges to
a 33.3% three-run mean despite high isolated
branch passes. Rather than scheduling anthropo-
morphic roles, we introduce CLONACT, a router-
less architecture that virtualizes context blocks
directly through a pluggable single-pass non-
generative Context MMU, in-place Context Cells,
a footprint-aware Synaptic Bus with an isolated
trial merge gate, and a wave-flushed Shared Trunk.
Across three programmatic multi-stream bench-
marks and three model families, our portable trial
merge gate lifts true-conflict merges to 63.3%,
while CLONACT’s routerless virtualization attains
this ceiling with 45.9% fewer prompt tokens and
prevents compact-model router collapse. Under
continuous surge streams, CLONACT matches top
completion (95.0%) with the lowest median wait
and zero timed-out status checks.

Motivated by effective single-agent loops in existing de-
ployments (Sarkis, 2026), we decouple cross-task multi-
plexing from top-down task decomposition and propose
CLONACT (Figure 1c; Section 3, Figure 3), which schedules
context blocks, rather than anthropomorphic roles, directly
as virtualized resources. All System-2 execution and dia-
logue Context Cells share identical frozen weights πθ with
zero generative router layer, while a pluggable single-pass
non-generative Context MMU—instantiated either with a
lightweight probability-scoring classifier or same-weight
single-token log-probability probing of πθ—routes user
turns and external events directly to independent Context
Cells. Each cell clarifies requirements with the user in
a zero-directory read-only state and, upon confirmation,
promotes in-place to lazy-mounted Git worktree execu-
tion along its exact alignment token spine—avoiding ticket
rewriting while retaining stable prefixes compatible with
provider-side caching. Across concurrent cells, a footprint-
aware Synaptic Bus blocks raw tool noise while synchro-
nizing shared AST and resource footprints ahead of a three-
stage isolated trial merge gate, atop a byte-locked Shared
Trunk that grounds workspace conventions across cells.

leaved intake and shared-workspace concurrency, we con-

Synaptic-Bench-150, pairing live repository, database, and
office sandboxes with deterministic tool-count Step-Hooks;
AppWorld-Micro-30, an uncoupled everyday-errand con-
trol; and Synaptic-Stream-60, feeding continuous 240-event
omnichannel streams under moderate and 2.5× surge ar-
rival rates. Across 1,800 episodic rollouts, 170 diagnostic

portable trial merge gate lifts true-conflict merges from
33.3% to 63.3% across three runs (10.0% →80.0% in

CLONACT matches top completion (95.0%) with the lowest
median wait and zero timed-out status checks, while dual-

Pre-registered ablations validate target-slice causal disso-
ciation and same-weight log-probability gating, and cross-
backbone runs improve pooled resolution by +11.5 pp over
DSH-SuperAgent while preventing compact-model router
collapse.
Our contributions are threefold:
• We propose CLONACT, a routerless architecture that
schedules homogeneous System-2 Context Cells as vir-
tualized resources via a pluggable single-pass Context
MMU, in-place align-to-execute promotion, footprint-
aware synaptic reconciliation, and a wave-flushed Shared
Trunk (Section 3).
• We introduce Synaptic-Bench-150, AppWorld-Micro-
30, and Synaptic-Stream-60, zero-overlap multi-stream
benchmarks combining un-partitioned intake, determin-

continuous arrival streams under deterministic state ora-

• We isolate the causal roles of trial-merge settlement and
routerless virtualization across three model families, re-
solving bleed and merge cliffs while exposing explicit
dual-tier cost and backbone-floor trade-offs (Section 4).

Any homogeneous-weight concurrent agent decomposes
into (a) an upper-layer context orchestrator O and (b) the
shared single-session execution kernel πθ. At event t, O
maintains active execution contexts {Ck}Kt
k=1—discrete mes-
sage sequences over roles {system, user, assistant, tool}—
via three control operations: (i) ingress routing and sandbox
promotion, mapping et to a context Ck and deciding when to
mount an isolated write directory (e.g., a Git worktree); (ii)
cross-context visibility, governing what state flows between
sibling contexts Cj ↔Ck (j̸ = k); and (iii) workspace
settlement, reconciling sandbox mutations into Wt. Un-
like human teams where distinct roles reflect heterogeneous
human expertise, every context here queries the identical
distribution πθ(· | Ck) (θ1 = θ2 = θ): capability asym-
metries arise solely from which tokens O populates inside
Ck.
Trivial Base Case and Paradigm Specializations. When
a single task runs undisturbed (Kt = 1, zero mid-flight
interleaving or concurrent writes), O reduces to identity
pass-through to the underlying single-session harness. Un-
der concurrent streams, existing paradigms instantiate O
at opposite extremes: (1) Flat single-session (DSH-Mono;
Yao et al., 2023) fixes Kt ≡1, appending all events into C1
over one working directory; (2) Delegation-first subagent
forking (DSH-Subagent-Fork; Qiao, 2026) prompts C1 to
spawn or prefix-fork child contexts on demand; (3) Multi-
role peer teams (DSH-AgentTeam; Hong et al., 2024; Wu
et al., 2024) coordinate a lead context and isolated workers
via natural-language blackboards and peer mailboxes; and
(4) Resident router–ticket–worker (DSH-SuperAgent; Qiao,
2026; DeepSeek Harness Team, 2026) places a persistent
generative coordinator Crouter in front to filter events and
summarize dialogues into isolated worker mandates.

2.3. Design Principles for Context Scheduling
Existing paradigms trade one term of Equation (1) for the
other: single-session execution eliminates merge gaps at the
cost of cross-stream bleed and blocking, whereas role and
router hierarchies buy isolation through lossy prose hand-
offs, 2.6× routing overhead, and blind merges. Driving
both terms toward zero requires scheduling context blocks
directly under four design principles: (i) sub-second non-
generative multiplexing (Section 3.1), removing autoregres-
sive decoding from per-event ingress routing; (ii) same-
brain trajectory continuity (Section 3.2), promoting interac-
tive alignment into isolated execution along one continuous
token spine without ticket rewriting; (iii) footprint-aware
pre-merge reconciliation (Section 3.3), isolating raw tool
noise while synchronizing shared symbol footprints and
trial-testing joint merges before updating the main branch;
and (iv) prefix-locked workspace grounding (Section 3.4),
sharing verified workspace conventions across virtualized
contexts behind a byte-identical left prefix updated only at
idle wave boundaries.

4. Experiments and Mechanistic Analysis
Across 1,800 paired episodes, 170 supplementary diagnos-
tic control and oracle rollouts, 36 continuous 240-event
streams (720 live task deliveries, 8,640 routed events), and
150 inner-kernel controls with zero runner errors or contam-
ination, we test four hypotheses linking Section 2 and Sec-
tion 3: (i) virtualizing context blocks without a generative
router resolves the bleed-versus-merge dilemma with lower
prompt-token expenditure while imposing zero penalty on
uncoupled errands; (ii) under continuous conflict-free wall-
clock arrivals, congestion triggers a queueing phase transi-
tion where CLONACT sustains low median wait and high
verified completion without sacrificing real-time status ob-
servability; (iii) CLONACT’s four scheduling primitives ex-
hibit orthogonal causal dissociation on their predicted target
slices; and (iv) offloading ingress gating and eliminating
prose ticket serialization transfers across model families and
prevents compact-model router collapse.

5. Related Work
Multi-Agent Topologies, Agent OS, and Concurrency
Control. Collaborative agent systems use role hierarchies,
peer chats, and router–worker pipelines (Hong et al., 2024;
Wu et al., 2024; Qian et al., 2024; Qiao, 2026; DeepSeek
11


Context as a Resource
Harness Team, 2026). Toolformer, ReAct, Reflexion, Code-
Act, SWE-agent, and OpenHands develop tool use and agent
execution methods (Schick et al., 2023; Yao et al., 2023;
Shinn et al., 2023; Wang et al., 2024b; Yang et al., 2024;
Wang et al., 2025). Separate failure and scaling studies iden-
tify coordination failures and task-dependent gains from
multi-agent architectures (Cemri et al., 2025; Kim et al.,
2025); Anthropic reports deployments where consolidating
subagents improved quality and efficiency (Sarkis, 2026).
The benefits of role decomposition therefore depend on
the task and coordination regime. AIOS (Mei et al., 2025)
schedules inference, tools, and storage across agent applica-
tions; CLONACT instead multiplexes interleaved user turns
within one workspace. HAI-Agent studies handoff inter-
ventions (Wang et al., 2026), whereas our in-place promo-
tion avoids prose ticket rewriting. Our isolated execution
and trial-merge validation adapt Optimistic Concurrency
Control (Kung & Robinson, 1981) to code and workspace
reconciliation.
Context Management and KV-Cache Reuse. Memory
systems include OS-inspired paging (Packer et al., 2023),
skill libraries (Wang et al., 2024a), and long-term memory
stores (Xu et al., 2025; Chhikara et al., 2025). Trajectory
management spans observation masking (Lindenbauer et al.,
2025), information reduction (Xiao et al., 2026), compres-
sion (Kang et al., 2026; Zhu et al., 2026; Liu et al., 2026),
branching histories (Wu et al., 2025a), and learned mem-
ory or folding policies (Yu et al., 2026; Sun et al., 2026).
KVCOMM and LRAgent study cache sharing with internal
KV access (Ye et al., 2025; Jeon et al., 2026). PagedAtten-
tion and SGLang provide serving-level memory and reuse
mechanisms (Kwon et al., 2023; Zheng et al., 2024). Our
black-box scheduler retains stable prefixes compatible with
provider caching; these serving papers do not establish how
a commercial API shares cache tensors. We report provider
cache-hit telemetry separately from this architectural moti-
vation.
Interactive and Asynchronous Agent Benchmarks. Cod-
ing and app benchmarks evaluate task execution (Jimenez
et al., 2024; Trivedi et al., 2024; Wu et al., 2025b); other set-
tings emphasize dynamic user interaction (Yao et al., 2025;
Vijayvargiya et al., 2025; Raghavendra et al., 2026), asyn-
chronous app events (Froger et al., 2026), mock-tool stream-
ing queues (Qiao, 2026), or paired-agent coding (Khatua
et al., 2026). Building upon these substrates, Synaptic-
Bench-150, AppWorld-Micro-30, and Synaptic-Stream-60
combine un-partitioned single-window intake, deterministic
tool-step Step-Hooks, multi-rate arrival streams, and cross-
modal/repository state coupling alongside a zero-coupling
control.
6. Conclusion and Limitations
We studied how to coordinate concurrent, always-on per-
sonal agents behind a single continuous interface when all di-
alogue and execution contexts share identical frozen System-
2 weights. Controlled comparisons across five kernel-locked
paradigms show that linear single-session loops suffer cross-
topic bleed and head-of-line stalling, whereas anthropo-
morphic router–ticket hierarchies introduce lossy handoffs,
heavy routing overhead, and blind merges. By scheduling
context blocks directly as virtualized resources, CLONACT
unifies non-generative ingress multiplexing, in-place align-
to-execute promotion, footprint-aware synaptic reconcilia-
tion with a portable trial merge gate, and byte-locked prefix
retention. Across episodic, streaming, and multi-model eval-
uations, this separation achieves the trial-merge accuracy
ceiling at roughly half the router token footprint, matches
top surge-stream completion with zero-timeout observabil-
ity, and highlights the central principle that homogeneous-
weight concurrency is a context-scheduling problem rather
than an organizational role-design problem.
Limitations. Three boundaries define immediate directions
for future work. First, control-plane generalization and pric-
ing: our cross-backbone evaluation (Table 4) pairs all three
System-2 models with a shared lightweight System-1 classi-
fier, and flat uncached System-1 calls can offset System-2
token savings under high event-to-task ratios (such as Surge
Stream-60) when cached System-2 prefix reads are deeply
discounted; extending same-weight log-probability gating
beyond DeepSeek-V4.1, auditing classifier calibration, and
batching or prefix-caching System-1 calls remain open op-
timizations. Second, workspace granularity and cold-start
ambiguity: fine-grained symbol tracking currently parses
Python ASTs (falling back to file/CLI footprints elsewhere),
write cells mount Git worktrees uniformly even for pure
app-API writes, and terse pronoun-heavy follow-ups during
the initial 1–2 turns before cells accumulate distinct foot-
prints can require explicit disambiguation; multi-language
Tree-sitter tracking and modality-gated worktree mount-
ing are direct systems extensions. Third, backbone ceiling
and streaming scope: training-free context scheduling re-
mains bounded by the frozen backbone’s undisturbed single-
task ceiling p⋆
θ, and Synaptic-Stream-60 evaluates S = 3
conflict-free streams to isolate queueing dynamics (requir-
ing epoch-versioned prefixes under unbroken load), leaving
larger-scale streaming combined with live repository merge
conflicts for future evaluation.
Impact Statement
This paper presents work whose goal is to advance the relia-
bility and computational efficiency of concurrent tool-using
language model agents by scheduling context blocks di-
rectly as virtualized resources. By eliminating redundant

context prefixes across concurrent tasks, our architecture

sandboxing, authorization boundaries, and unintended side

Deterministic Tool-Count Step-Hooks. Wall-clock timers introduce severe speed confounds across agent architectures:
an amendment fired at t = 60s catches a fast single-session loop after it has already finished editing, while catching a
slower router–worker pipeline before its worker even starts. In tracks O-3, C-3, and H-2, our harness intercepts cumulative
tool-execution callbacks ct at the DSH worker transport layer and fires mid-flight user amendments, requirement refinements,
or full goal overturns at exact pre-registered step thresholds ct = τhook, guaranteeing that every paradigm encounters
interruptions at an identical stage of execution progress.

by programmatic state assertions partitioned into two tiers (an episode passes iff all Tier-1 and Tier-2 checks pass):

SQLite table hashes and git status –porcelain / commit-SHA equality during alignment and lookup turns, (ii) noise &
duplicate hygiene verifying zero side effects from bystander chatter and single-execution idempotency under duplicate
webhook bursts, and (iii) clean rollback verifying zero residual edits on aborted/overturned tasks.

on the canonical main branch (for C-2, running the union test suite of both concurrent features jointly after all merges

C. Implementation Specifications, Hyperparameters, Cost Breakdown, and Verbatim Prompts
Execution-Kernel Parity Across All Paradigms. To eliminate low-level scaffolding confounders, every paradigm and
ablation arm runs atop the identical Node.js worker runtime (@deepseek-ai/dsh pinned at v0.2.1-rc.3) sharing identical
atomic tools (read, write, edit, glob, grep, and 5s auto-backgrounded bash with job polling), automatic watermark
compaction (dsh-compaction-basic), tool-output pruning, macOS Seatbelt (sandbox-exec) isolation, and the identical
<workspace_agents_md> workspace conventions block. No external regex pre-filtering is applied to any arm, and billed token
telemetry (uncachedInputTokens, cacheReadTokens, cacheWriteTokens, outputTokens) is extracted uniformly from DSH’s
session_projcache SQLite table (summing MMU classifier tokens for CLONACT). The four baselines are instantiated as
strong, faithful realizations of their paradigms:
• DSH-Mono (Single-Session Loop): Runs one persistent DSH session in the primary workspace with subagent
tools disabled; mid-flight events arriving during active tool execution inject via DSH’s native steer next-step inbox
mechanism.
• DSH-Subagent-Fork and DSH-Subagent-Neutral (Subagent Delegation Variants): Equips the primary DSH
session with dsh-tool-subagent (spawn), dsh-subagent-fork-in-process (inheriting completed KV prefixes), and
dsh-tool-subagent-control. DSH-Subagent-Fork uses a Delegation-First system prompt adapted from Qiao (2026),
with harness-specific tool names and worktree isolation/merge instructions, whereas DSH-Subagent-Neutral (evaluated
on Synaptic-Stream-60) exposes the identical subagent tools under a neutral system prompt to test voluntary delegation.
• DSH-AgentTeam (Steelman Lead + Blackboard + Peer Mailbox): Pairs a write-gated Team Lead session with
on-demand isolated-worktree Teammate sessions sharing (a) an append-only team_board (recording task DAG status,
touched files, and findings via tail-injected notices that preserve KV-cache prefixes) and (b) peer-to-peer team_mailbox
messaging. Upon completion, if sequential git merge encounters conflict markers, the Lead/Merger is explicitly
permitted to inspect team_board and conflict markers to resolve conflicts before testing.
• DSH-SuperAgent (Official Router–Ticket–Worker Prototype): Runs the unmodified dsh-superagent-prototype
repository (DeepSeek Harness Team, 2026, detached commit 8c32a9d), including its native Engine, MasterAssessor,
thread-keyed followupOwners pass-through, and isolated DshExecutor worktrees under symmetric channel allowlists
(raising maxWorkers to 16 on Synaptic-Stream-60 to prevent artificial worker-slot throttling under 20-request streams,
and promoting verified worker commits only at quiescent stage/turn boundaries).
