Abstract
User simulators offer a scalable way to evaluate interactive agents, but how to assess their
quality remains underexplored. In particular, it is unclear whether existing user simulator
evaluation frameworks reliably detect meaningful failures in simulated user behavior. This
uncertainty makes it diﬀicult to interpret simulator evaluation. To understand what a high
benchmark score tells us about simulator quality, we (meta-)evaluate the metrics them-
selves. To instantiate this meta-evaluation, we deliberately perturb simulated replays to in-
duce failures such as altered goals, omitted constraints, premature stopping, and acceptance
of broken work, then test whether the metrics penalize these failures. Evaluation methods
from three prior studies detect only 5∼6 of the 10 perturbations; their combined scores even
favor populations instructed to accept broken work over unmodified controls. Motivated by
these gaps, we propose a new evaluation suite that combines utility of user simulators for
evaluating agents and two measures of fidelity to real users: population-level fidelity assesses
collective interaction patterns, while trace-level fidelity assesses the preservation of individual
users’ goals, constraints, and persona. Under the same detection criterion, our evaluation
suite detects all 10 perturbations. Evaluating six user simulators on 351 real multi-turn ses-
sions in which 348 distinct users across 23 languages and agents work together to create and
refine artifacts such as full-stack web apps, games, design assets, and automated workflows,
we find that population-level measures can miss when a simulated user pursues the wrong
goal, ignores a constraint, or behaves out of character, highlighting the need to assess fidelity
at comprehensive granularities.
1. Introduction
With the capability advances, LLM agents help users write code, create documents, and revise other
artifacts (Kimi Team, 2026; OpenAI, 2026; Anthropic, 2026; Yang et al., 2024; Xie et al., 2024)
through multi-turn interactions (Dou et al., 2025; Wu et al., 2026; Baumann et al., 2026). During
these interactions, users clarify what they want, inspect the work produced, and provide feedback.
Evaluating this process requires a user who can respond to the agent’s progress, but recruiting real
users for every evaluation is costly and makes comparisons diﬀicult to repeat. User simulators offer
a practical way to run these interactions at scale and are used in both offline agent evaluation and

training (Barres et al., 2025; Qian et al., 2025; Suh et al., 2026). However, using simulated users
in place of real users can change measured agent success rates (Seshadri et al., 2026).
To assess whether simulators can reliably stand in for real users in multi-turn interactions, recent
studies have developed several ways to evaluate user simulators, including similarity to human
language and behavior, consistency with user specifications (Zheng et al., 2026; Jain & Sandhu,
2026), and agreement with human assessments of agent performance (Dou et al., 2025; Lu et al.,
2026; Zhou et al., 2026; Wu et al., 2026). What remains less clear is whether these measures reliably
identify behavior that makes a simulator unsuitable for agent evaluation where artifacts deeply
involved in the interaction. For example, a simulated user may sound natural while approving a
broken artifact or overlooking an important requirement. Evaluating fidelity is also diﬀicult because
a replay should preserve the original user’s needs while responding to an agent whose actions may
differ from the original session. We therefore need to examine how evaluation metrics respond when
these aspects of simulation go wrong.
To understand what a high benchmark score tells us about simulator quality, we (meta-
)evaluate the metrics themselves.
Specifically,
we introduce failures through controlled
perturbations (Sai et al., 2021) to the simulator’s setup, then replay each session with the assigned
agent. We test whether the metrics assign lower scores to these perturbed replays than to controls
generated from the same source sessions and agent assignments.
We design 10 perturbations
based on three sources of motivation. First, we draw on reported failure modes, including overly
helpful simulated users (Naous et al., 2026), premature information disclosure (Zhou et al., 2026;
Jain & Sandhu, 2026; Liu et al., 2026), and self-preference in LLM evaluation (Zheng et al., 2023;
Panickssery et al., 2024; Spiliopoulou et al., 2025). Second, we draw on failures observed in our
analysis of 442,516 real sessions and 20,100 replays. Third, we include basic defects that evaluation
metrics should readily detect. These include changing the user’s goal, removing constraints, forcing
early termination, encouraging acceptance of broken work, and favoring a selected agent. We ask
whether the existing user simulator evaluation metrics penalize these changes and what replays
are retained when using their score for filtering.
The results reveal several gaps in the evaluation suites from SimulatorArena, VISTA, and SWE-
Together (Dou et al., 2025; Lu et al., 2026; Wu et al., 2026). We count a perturbation as detected
if at least one metric in an evaluation suite shows a reliable score decrease relative to the control
(Section 6.1.1). Under this criterion, the evaluation suites adapted from SimulatorArena, VISTA,
and SWE-Together (Dou et al., 2025; Lu et al., 2026; Wu et al., 2026) detect six, five, and six of
the ten perturbations, respectively. All three evaluation suites fail to detect the agent favoritism
perturbation (more favorable feedback from the simulated user toward a selected agent) despite
the shifts it causes in agents’ scores and ranks. The composite scores for these metrics even favor
perturbed replays that accept broken work. These findings suggest that high scores on existing
criteria do not necessarily establish that a simulator provides useful feedback for help evaluating
interactive agents.
Motivated by these findings, we introduce a new evaluation suite that measures user simulators at
three levels illustrated in Figure 2. Downstream ranking agreement checks whether simulated
interactions recover a supplied reference ranking of agents. This assesses the simulator’s utility for
agent evaluation, but gives limited information about why it succeeds or fails. We therefore also
measure population-level fidelity, which compares collective interaction patterns with those of
real users, and trace-level fidelity, which checks whether each replay preserves the user’s goals,
constraints, and persona. The two fidelity levels help distinguish broad behavior shifts from failures
within individual sessions. Together, these measures provide a stronger and more holistic assessment
of how well a simulator supports agent evaluation at a broader range of failures than any of the
existing benchmarks we evaluated.

We show that our evaluation suite detects all ten tested perturbations under the same criterion
in Sec 6.1. We also test whether our evaluation scores can help filtering out simulator failures. We
report the fraction of control traces retained at a threshold that admits 5% of perturbed samples.
Our metric retains 98% of control populations in the agent favoritism filtering experiment, com-
pared with 10% for Sim2Real, the best external benchmark. Under the same conditions, action
distribution retains 100% of control populations in the approval-of-broken-work experiment, com-
pared with 26% for the best external benchmark. At the trace level, the persona score retains
68% of real-user traces, compared with 28% for the best external benchmark. Finally, we apply the
evaluation suite to six simulators on 351 real sessions. None of the six simulators we evaluated leads
across all three levels. The simulator from SimulatorArena achieves the highest downstream rank-
ing agreement, while our proposed profile-based simulator lead on population-level and trace-level
fidelity. These results show the value of examining all three levels when assessing a simulator.
Our contribution are four-fold:
• A perturbation-based meta-evaluation protocol for examining what user-simulator evaluation
metrics detect and retain in Section 4.
• A new evaluation suite grounded in real user sessions that combines downstream ranking agree-
ment with population- and trace-level fidelity in Section 5.
• A 351 real-user sessions used in our evaluation to support future research on user simulation for
agent evaluation.
• An empirical study of existing evaluation criteria, their use in data selection, and the strengths
and weaknesses of six simulators in Section 6.2.
2. Related Work
User simulators for agent evaluation.
Task-oriented benchmarks such as τ 2-bench use an
environment-grounded user simulator in interactive agent evaluation (Barres et al., 2025). Simula-
torArena studies open-ended assistant interactions using simulated users and compares simulator-
derived assessments with human judgments (Dou et al., 2025). SWE-Together reconstructs devel-
oper sessions and uses a state-conditional user simulator to preserve task intent while adapting feed-
back to the new agent (Wu et al., 2026). SWE-DIVE converts coding benchmarks into multi-turn
evaluations in which a simulated user responds to the agent’s replies and codebase changes (Brehme
et al., 2026), and Cowork-Gym synthesizes persistent work environments with a stateful simulated
user that observes the workspace (Zou et al., 2026).
Lost in Simulation documents discrepan-
cies between agent success rates measured with simulated and real users (Seshadri et al., 2026).
Disclosure-Gated User Simulation examines how disclosure mechanisms affect companion-agent
evaluation (Liu et al., 2026). These settings motivate assessing both simulated behavior and its
use in agent evaluation.
Evaluating the simulator.
Surveys distinguish behavioral consistency from downstream util-
ity (Pietquin & Hastie, 2013) and discuss simulation of general and individual users (Ni et al.,
2026). Prior work considers behavioral realism, consistency with user specifications, and similarity
to real-user populations (Dou et al., 2025; Lu et al., 2026; Wu et al., 2026; Zhou et al., 2026).
ARGUS evaluates behavioral consistency with scenario requirements (Zheng et al., 2026), while
UserProxyBench measures adherence to task-specific user instructions and separately checks user
tool execution in Telecom (Jain & Sandhu, 2026). UserArena evaluates shopping user simulators
at five levels, from output validity to sequential behavior, personalization, and outcomes (Zhao
et al., 2026). CUE assesses whether simulated users reproduce the success and failure patterns of
real interactions (Kantharuban & Mueller, 2026), and AutoSim compares simulator-derived rank-
3


ings of conversational search systems with rankings based on relevance judgments (Zerhoudi et al.,
2026). Section 4.4 describes the evaluation criteria used in our comparisons. These studies provide
complementary criteria; we examine how such criteria respond to controlled replay perturbations
and what data they retain when used as filters.
Meta-evaluation of LLM judges.
Meta-evaluation is the systematic assessment of an evalua-
tion’s quality and utility (Stufflebeam, 2001). Our meta-evaluation treats the scoring criteria them-
selves as objects of study, following prior work on metric validity and perturbation testing (Mathur
et al., 2020; Sai et al., 2021; Muller et al., 2025). It compares scores for control and perturbed in-
teractions generated from the same source sessions, then examines selection under score thresholds.
Perturbations act on the simulator’s setup, allowing the resulting interaction to evolve; the test
therefore concerns an interactive generation condition rather than a static textual edit.

3.2. Evaluation Principles
Evaluating user simulators for interactive agents requires examining the downstream utility and
fidelity to the users they represent.
We organize these requirements into three complementary
levels.
Downstream evaluation utility (L1).
Simulated interactions should support valid assessments
of agent performance in the intended setting (Pietquin & Hastie, 2013). Prior work shows that
simulator-based evaluations can misestimate agent success rates relative to evaluations with real
users (Seshadri et al., 2026).
Reliable agent comparisons therefore require simulated users to
respond appropriately to differences in agent performance. Their feedback and stopping decisions
should reflect the quality of the agent’s work under comparable standards across agents. In artifact-
producing tasks, evaluation must account for how well the resulting work meets user needs: plausible
dialogue alone provides insuﬀicient evidence of successful performance (Bodhwani et al., 2026; Jain
& Sandhu, 2026; Zheng et al., 2026). These requirements motivate evaluating downstream utility
directly: whether simulated interactions support reliable comparisons of agent performance. This
complements behavioral fidelity by checking whether the simulator serves its intended purpose as
an evaluation tool.
Population-level fidelity (L2).
Simulated populations should reproduce relevant patterns of
real-user behavior. These include how users introduce requirements, provide information, respond
to progress and errors, and decide that work is complete.
Reported failures include excessive
cooperation (Zhou et al., 2026; Chopra et al., 2026) and premature or unconditional information
disclosure (Jain & Sandhu, 2026; Liu et al., 2026). In workspace interactions, fidelity also concerns
how feedback relates to the state and quality of artifacts. Systematic differences in these patterns
change the evaluation conditions agents encounter.
Trace-level fidelity (L3).
Individual interactions should preserve the represented user’s intent,
constraints, and persona (Ni et al., 2026) while responding to the agent’s actions. Prior work high-
lights fidelity failures such as goal and constraint violations, premature termination, ungrounded
confirmations, fabricated observations, and claims of actions that were never performed (Zheng
et al., 2026; Jain & Sandhu, 2026). Population-level similarity can conceal these failures within
individual replays, motivating evaluation against the particular user each replay represents. In our
real-user traces, users inspect produced artifacts and base their acceptance or requests for changes
on whether the work meets their requirements. For artifact-producing tasks, fidelity therefore con-
cerns both preserving the source user’s requirements and applying their judgment criteria when
assessing the resulting work.
Existing benchmarks typically cover only parts of these principles. Population-level comparisons,
such as those used within Sim2Real, characterize collective behavior, but matching aggregate pat-
terns can leave changes to individual users’ intent, constraints, or persona unobserved (Zhou et al.,
2026). Individual fidelity therefore requires examining whether each replay preserves the particu-
lar user it represents. VISTA evaluates consistency with user specifications, while SWE-Together
checks whether simulated guidance preserves the original task scope. However, consistency and
scope preservation alone do not establish whether the simulator reproduces the represented user’s
degree and manner of participation (Lu et al., 2026; Wu et al., 2026). SimulatorArena and SWE-
Together assess agent outcomes alongside message similarity or preservation of source-user intents,
but assessing these separately does not directly establish whether the user’s acceptance or criticism
is justified by the work produced (Dou et al., 2025; Wu et al., 2026).

Motivated by the above-mentioned limitations, we develop a meta-evaluation framework to quan-
titatively evaluate existing user simulator evaluation suites in Section 4, and then propose a new
evaluation suite to overcome those issues in Section 5.
4. Perturbation-Based Meta-Evaluation
Assessing the reliability of an evaluation method is itself a challenging problem. Agreement with
human judgments can depend strongly on the outputs used for assessment and carry substantial
statistical uncertainty (Mathur et al., 2020; Deutsch et al., 2021). Moreover, agreement on overall
quality does not establish that a metric captures each relevant evaluation dimension (Sai et al.,
2021).
For user simulation, this challenge is compounded by the replay setting: source traces
do not prescribe responses to new agent actions, and appropriate feedback depends on evolving
dialogue, workspace state, and artifacts.
We therefore propose a perturbation-based meta-evaluation. Following criteria-targeted pertur-
bation testing (Sai et al., 2021), we modify simulator setups to challenge the principles in Section 3.2.
Figure 1 shows the procedure: generate paired control and perturbed replays, then examine whether
evaluation scores penalize the targeted changes (sensitivity) and how well a score distinguish control
from perturbed candidates (filtering).
4.1. Session Data
Our meta-evaluation uses real user–agent sessions involving goal-directed work on deliverables as
source sessions. We use two sets that differ primarily in interaction length. The easy set contains
shorter interactions (median: 7 user turns; 10th–90th percentile range: 5–11). The hard set involves
longer-running projects with more complex tasks and deliverables (median: 26 user turns; 10th–
90th percentile range: 8–65).
4.2. Replay Setup
For each source-session–agent pair and each perturbation, we compare a control replay generated us-
ing the baseline setup below with a perturbed replay generated using the corresponding intervention
from Section 4.3.
Control replay.
We extract a session profile from the source dialogue, final workspace, and up-
loaded materials, describing the intended deliverable, constraints, preferences, persona, and stop-
ping conditions. The simulator uses this profile to represent the source user in a new interaction
with the assigned agent. See Appendix A.3 for a profiling example.
The interaction begins with the original opener and associated files in a persistent sandbox.
Later uploads are available for attachment during interaction. At subsequent turns, the simulator
receives the profile, developing dialogue, and current workspace evidence, including text-file con-
tents, metadata, and tool-error summaries. It generates feedback or stops, with instructions to
ground acceptance in evidence supporting the agent’s claims. Each replay ends when the simulator
stops or reaches the cap of 30 user turns.
Perturbed replay.
We modify a specified part of this baseline setup, such as the profile, response
instructions, or turn budget for perturbation. The source session, opener, initial files, and assigned
agent remain the same.

Both replay use gpt-5.6-terra as the simulator model. Each condition runs with a fresh agent
instance and a separate workspace, allowing its dialogue and artifacts to develop independently.

4.3. Perturbation Design
We design 10 perturbations drawing on three sources: failure modes reported in prior work, failures
observed in our replay analyses, and basic defects that an evaluation should readily detect. We
organize these perturbations according to the evaluation principles introduced in Section 3.2. We
describe each intervention below, with implementation details in Appendix B.
Downstream evaluation utility (L1).
Agent favoritism instructs the simulated user to favor
a particular agent by excusing errors, accepting imperfect deliverables, and giving warmer feed-
back. Profile extraction artifact turns dissatisfaction with the original agent into a persistent user
trait (Tennenholtz et al., 2026), making the simulator remain critical even when the replay agent
meets requirements.
Population-level fidelity (L2).
Approve broken work instructs the simulated user to approve
deliverables despite errors or missing requirements. Premature stop truncates replays early, reduc-
ing opportunities for users to inspect deliverables and request corrections. Front-loading moves
requirements and acceptance criteria that would otherwise emerge during interaction into the open-
ing messages.
Trace-level fidelity (L3).
Adversarial goal replaces the intended goal and deliverable with a
plausible alternative, directing later feedback toward the altered task.
All constraints removed
removes hard requirements from the profile while preserving those expressed in the original opener.
Persona swap replaces the source user’s writing style with a contrasting register while preserving
the goal and requirements. Co-debugger instructs the simulated user to diagnose problems and
suggest fixes, providing technical assistance beyond the represented user’s role. Language switch
changes the simulated user’s language after the original opener.

Filtering.

pool, revealing what simulations receive high scores and survive selection.
At the trace level, we test whether scores distinguish perturbed replays from control replays and
real-user traces. For agent differentiation and population-level fidelity, we compare populations
containing only control replays with matched populations constructed by replacing 10%, 25%, 50%

all metrics use the same sampled replay pairs and replacement choices.
For each metric, filtering retains traces or populations whose scores meet or exceed a threshold.
Across all comparisons, we report AUROC to measure how well scores distinguish the control or
real-user group from the perturbed group.
For trace-level filtering, we additionally report the fraction of control replays or real-user traces
retained when the threshold allows 5% or 10% of perturbed replays to pass. Higher retention at
the same perturbed-survival rate indicates more effective filtering.
5. Evaluation Framework
As shown in Section 6.1, existing evaluation suites fail miserably on perturbations: they overlook
biased feedback toward particular agents, changes to user goals or constraints, and acceptance
of broken work, or even rewarding perturbed replays. These failures leave gaps in assessing agent
differentiation, population-level fidelity, and trace-level fidelity. We therefore propose an evaluation
framework that measures these three aspects and provides more detailed feedback on simulator
behavior. Below, we describe how each component is implemented.

agents and compares the resulting ranking with an independent reference ranking. L2 compares
behavioral statistics across simulated and real-user populations. L3 checks whether each replay is

evidence. We report these three component scores and combine them into an overall evaluation

5.3. Trace-level fidelity (L3)
Trace-level fidelity (L3) measures whether each simulated replay preserves the original user’s goal,
requirements and persona while responding to the agent’s actions. We evaluate each replay against
its real-user session using 3 metric families:
1. Intent preservation. We check whether the simulated user continues pursuing the original
goal. An LLM judge compares the real and simulated conversations, using workspace evidence
to understand what was produced, and classifies the replay as having no drift, minor drift or
major drift. Major drift includes replacing the original goal or abandoning it before an attempt.
An agent’s failure to complete the requested task does not itself constitute user intent drift. The
intent score is the proportion of evaluated replays without major drift.
2. Constraint preservation.
We check whether the simulated user maintains the real user’s
explicit requirements. An LLM judge first extracts hard constraints from the real user’s messages,
such as output language, deliverable format and required features. It then checks each constraint
against the simulated conversation and final workspace, recording whether the user retained it
and whether the deliverable satisfied it.
3. Persona consistency. We check whether the simulator preserves both how the user commu-
nicates and how they judge the agent’s work. Style similarity is assessed by comparing profiles
extracted from the real and simulated sessions. For judgment criteria in the application, an LLM
judge checks whether the simulated user’s decisions follow the original user’s criteria, labeling
each criterion as enacted, violated or not triggered. Criteria conformance is

5.4. Score aggregation
We summarize simulator performance while keeping each evaluation level visible.
The current evaluation suite (bench-v0) reports each level on a 0–100 scale and uses the geometric
mean of L1, L2 and L3 as its overall evaluation suite score. We report all three levels alongside
the overall evaluation suite score because an aggregate can conceal different failure modes. A level
score is an evaluation index, not a calibrated probability of fidelity.

6.2. Application of the Evaluation Framework
We apply the evaluation suite discussed in Section 5 to existing simulators to compare their strengths
and identify recurring behavioral weaknesses.
6.2.1. Evaluation setup
We evaluate six simulators on the same 351 real sessions. SimulatorArena and τ 2-bench use their
published simulation recipes, while the Sonnet 5, Terra and Luna baselines use profile-conditioned
simulation. MIMESIS-9B (Phan et al., 2026) is a trained user simulator that receives a profile-
derived goal and the agent’s text. We use the same set of 9 agents for all L1 comparisons. The
L1 reference comes from real-user satisfaction scored by the same reactions judge on about 1,000
separate real sessions per agent. All four L2 families use real-user behavior from the same 351 evalu-
ation sessions as their reference. Here we compare simulation strategies and backbones, whereas the
meta-evaluation in Section 4.2 holds the simulator backbone fixed to study controlled perturbations.
Table 4 reports the component and overall scores.
6.2.2. Comparison of existing simulators
Sonnet 5 has the highest overall score (70) and L2 score (87). Terra has the highest L3 score (84),
followed by Sonnet 5 (83). SimulatorArena has the highest L1 score (57) and Kendall agreement
(τ = 0.67), compared with 0.44 for Sonnet 5.
Luna and τ 2-bench have different behavioral weaknesses. τ 2-bench has higher population-

versus 74). These results identify different priorities for improvement: population-level behavior

7. Conclusion
User-simulator evaluation benefits from behavioral diagnostics and a separate check of the intended
agent-evaluation application. The perturbation results show that a metric’s sensitivity does not
guarantee useful filtering, while the favoritism and profile-artifact perturbations show that substan-
tial changes in selected agents’ scores and ranks can coexist with weak responses from the available
trace diagnostics. We therefore report fidelity, per-agent effects and agreement with the supplied
ranking together, with each claim tied to its evaluation protocol and evidence.

B. Perturbation Details
This appendix supplements the replay setup and perturbation design in Section 4.
Table 5 groups the perturbations by their motivation and summarizes their scopes. The descriptions below
explain their behavioral effects under the three evaluation principles. Appendix A.2 illustrates simulator
failures motivating the perturbation design.
Downstream evaluation utility (L1).
• Agent favoritism makes the simulated user more lenient toward a particular agent, excusing its errors,
accepting imperfect deliverables, and giving warmer feedback. This can make the agent appear more
capable than its work warrants.
• Profile extraction artifact encodes dissatisfaction with the original agent as a persistent user trait. The
simulated user distrusts the replay agent and keeps requesting corrections even when the work meets the
user’s requirements, undervaluing the agent’s performance.
Population-level fidelity (L2).
• Approve broken work makes the simulated user approve deliverables despite errors or missing requirements
and continue requesting the next item. The feedback remains polite and on-task but no longer reflects
the quality of the delivered work.
• Premature stop truncates replays to roughly half the source session’s length, capped at 15 user turns.
This shortens interactions and reduces opportunities for inspection, feedback, and correction.

C.3. Population-level behavioral fidelity (L2)
C.3.1. Dialogue-act taxonomy and action distribution
An LLM classifier assigns a dialogue act to each user turn using the turn and up to 8 preceding turns as
context. The classifier uses 10 categories:
• INITIAL_REQUEST: the opening task or deliverable request.
• REFINE: request a change to work that basically functions.
• REPORT_BUG: report broken or incorrect work.
• ADD_SUBTASK: introduce additional scope or work.
• CLARIFY_Q: ask the agent a clarifying question.
• PROCEED: acknowledge or ask the agent to continue.
• SWITCH_TASK: move to a different task.
• META_SOCIAL: social or conversational remarks.
• PROVIDE_INFO: supply information or answer the agent’s questions.
• OTHER: turns outside the preceding categories.
The reported population action-distribution comparisons use a fixed reference of approximately 5,000
real-user sessions.
35


C.3.2. Interaction dynamics
MATTR-50 is computed for sessions with at least 50 tokens. Question-turn rate is the fraction of user turns
containing a question mark; code-turn rate is the fraction containing a code fence or a recognized code
signature.
If a required statistic is zero, the dynamics family is undefined. The L2 aggregate is then also undefined,
rather than assigned a score of zero.
C.3.3. Outcome sensitivity
We flag preceding agent turns using execution-error indicators such as nonzero exit codes, tracebacks, and
error messages. Negative responses are labeled REPORT_BUG, REFINE or SWITCH_TASK; positive responses are
labeled PROCEED or META_SOCIAL. Other acts are excluded from the conditional probabilities in Section 5.
Both real and simulated responses use Claude Sonnet 4.6 for this outcome-sensitivity calculation.
C.3.4. Information provenance
An LLM judge identifies key information points in each conversation and attributes them to the user or
agent. Information points include requirements, decisions, corrections, bug diagnoses, technical values and
milestones. We compare the fraction of user-origin points between real and simulated populations to capture
differences in the information users supply, including over-helpful technical assistance.
