Calm Agent: Reframing Agent Interaction around
Intermittent Human Attention
Dian Jin1,2, Zixun Fu3, Guan Wang3, Yancheng Yuan3∗
1Research Institute for Intelligent Wearable Systems, The Hong Kong Polytechnic University
2School of Fashion and Textiles, The Hong Kong Polytechnic University
3Department of Applied Mathematics, The Hong Kong Polytechnic University
Abstract
AI agents can carry out auxiliary tasks while users fo-
cus on other work. Yet users still need to understand
task state, make changes, and respond when help is re-
quired. We argue that agents for ongoing auxiliary tasks
should be designed around intermittent human attention:
tasks should continue between interactions, and users
should be able to return with little effort to understand
and control them.
We develop this position as Calm
Agent. It connects three on-demand interaction modes:
Delegate, Adjust, and Check, through a persistent task
representation. Generative interaction provides controls
and feedback suited to open-ended goals, while existing
controls support routine actions. We illustrate these prin-
ciples with Orvlet, a desktop prototype for background
execution and compact task interfaces. We identify chal-
lenges in adapting interfaces while preserving continuity,
coordinating attention across tasks, providing responsive
interaction, and learning user habits over time. The aim
is to support continuing task control while protecting
attention for primary work.

Introduction
AI agents currently can use tools and complete complex
multi-step tasks in browsers and desktop applications
[1, 2]. These capabilities allow users to delegate auxiliary
tasks while continuing their primary work. For example,
a user writing a paper may also want background music or
a collaborator’s local time. Such tasks can remain active
for a long time, although the user needs to interact with
each one only briefly.
Delegating execution leaves an important interaction
problem. Users need to open a new agent interface, read
earlier messages to understand the current state, and
describe the need for change in natural language. These
actions actually share the limited and valuable attention
on primary work (Fig. 1). Research on interruptions [3, 4]
also shows that switching tasks can add extra effort and
require recovery when attention return. As agents take

on more ongoing tasks, the way users access and manage

Our position is that a agent for ongoing auxiliary tasks
should be designed to avoid capturing too much valuable
human attention. A task should remain available and
continue within its delegated scope while the user focus
on their promary work. When the user returns to the
auxiliary task, the current state of agent and its relevant
controls should be directly accessible rather than recon-
structing the task from a conversation. When a user input
is necessary, the agent should make this need apparent.
This position focus on how tasks continue between inter-
actions and how easily users can return to understand
and control them.
Calm Technology [5, 6] provides a concept foundation:
technology should move between the center and periphery
of attention as needed. Open-ended agent delegation adds
a further requirement: The system need to interpret a
goal, identify suitable actions to achieve the goal, receive
feedback from the environment, and keep these parts
connected to execution as the task develops. Generative
UI [7–9] can help provide task-specific interfaces, while
language and direct manipulation offer complementary
ways to express goals and make precise changes [10, 11].
These capabilities need to support a coherent relationship
with a continuing task.
We develop this position as Calm Agent. We define
three interaction modes for Calm Agent: Delegate, Adjust,

2
Related Work
2.1
Calm Technology and Attention
Weiser and Brown’s Calm Technology [5] describes move-
ment between the center and periphery of attention. Pe-
ripheral Interaction [12] and Calm Design Patterns [6]
explore how information and simple actions can remain
accessible with limited attention. Recent work on ambient
analytics connects peripheral awareness with opportuni-
ties for closer inspection [13].
The SEEV model [14] explains visual attention alloca-
tion through Salience, Effort, Expectancy, and Value. It
connects the visual prominence of information and the
effort of attending to it with the expected occurrence of
new information and its relevance to the task. These fac-
tors provide a useful perspective on access to background
tasks.
These previous research explains how interaction can
fit around a primary activity. However, open-ended dele-
gation adds a problem of determining what the peripheral
interface should contain. The relevant state and actions
depend on the delegated goal and can change during
execution. Therefore, an agent interface must connect pe-
ripheral presentation to goals and available actions. Calm
Agent addresses this connection by organizing periph-
eral access around a persistent task that can be revised,
controlled, and checked.
2.2
Generative and Hybrid Interfaces
Generative UI [7, 8] uses language models to produce in-
terfaces for user requests. DynaVis [15] generates smaller
widgets for visualization editing. Jelly [9] uses an evolving
1https://github.com/CLaSLoVe/Orvlet
task-driven data model to generate interfaces and trans-
late natural language and direct manipulation into model
changes. Its model-based approach demonstrates how
interface adaptation can be organized around a persistent
structure.
Direct manipulation and mixed-initiative interaction
provide broader foundations for combining graphical ac-
tions with language [16, 17]. Studies [11] identify dif-
ficulties in expressing intentions through prompts, and
DirectGPT [10] shows how direct manipulation can reduce
interaction time and prompt-writing effort.
These approaches establish how users can create and
change task interfaces. For an ongoing auxiliary task, the
interface must also support brief visits while execution
continues elsewhere. A generated interface may fit the
goal but still require users to reopen a workspace, locate
changed controls, and wait for regeneration, which dis-
couraging its practical use. The design gap concerns the
continuity of access across these visits: which controls
should persist, which changes require generation, and
how displayed state stays connected to execution. Calm
Agent uses Delegate, Adjust, and Check to organize this
relationship around the same ongoing task.
2.3
Agent Feedback and Control
GUI agents raise questions about how people maintain
awareness and control during automated execution [18].
AgentLens [19] combines background mobile execution
with selective overlays and adapts between full, partial,
and generated interfaces when interaction is needed. It
provides an important example of minimally invasive, just-
in-time communication. Choosing a suitable presentation
at an intervention point, however, leaves a further design
question: how should users access the same task between
interventions, including when they initiate a check or ad-
justment themselves? Calm Agent makes this continuing
access explicit through a task representation shared by
goal revision, direct control, and state inspection.
Research on proactive programming assistance exam-
ines the trade-off between useful support and interruption
[20].
Work on overhearing agents studies how agents
obtain context and decide when to intervene [21]. For
explicitly delegated auxiliary tasks, intervention must also
remain connected to the user’s existing goal. A clarifica-
tion, a request for a decision, and an unsolicited suggestion
place different demands on attention. Calm Agent con-
nects necessary attention requests to the same task that
users can revisit on their own initiative.
Together, these research areas motivate a framework
that connects open-ended delegation, persistent controls,
and selective attention requests across the lifetime of a
task. Calm Agent develops this framework for periods
when the user is primarily occupied elsewhere. Its focus is
the relationship between continuing execution and inter-
mittent participation, including both user-initiated visits
and agent-initiated requests.

3
The Calm Agent Position
A task may run for minutes or hours while the user gives it
attention for only a few seconds at a time. We argue that
agent interfaces should support this difference in duration.
Users need both the ability to leave a task and an effective
way to return. We develop three design principles from
this position, then describe the interaction modes and
task representation that support them.
3.1
Design Principles
P1: Maintain the Task between Interactions.
Task execu-
tion and context should persist independently of whether
the interface is open. Within the delegated scope, the
agent should maintain the goal, update observable state,
and record changes relevant to later interaction.
If
progress requires user input, it should preserve the task
and expose that need. The user should not have to keep
a conversation active to keep the task available.
P2: Support Brief, Purposeful Interaction.
The interac-
tion method should fit what the user wants to do. Lan-
guage supports open-ended goals; an available control
supports a specific adjustment; a state display supports
inspection. Generative interaction should select useful
information and actions for the task. Once a control is
available, routine use should retain its meaning and avoid
unnecessary interface regeneration.
P3: Make Returning Informative and Actionable.
When
users return, they should be able to understand the cur-
rent situation and identify what they can do next. The
interface should show observed state, available actions,
and any need for input. Its prominence should fit the
need for attention. A compact display can support this
principle, but its value depends on whether users can
understand and act on the task with little effort.
Together, these principles set concrete criteria for as-
sessing a design: a task should remain available while the
user is away, its state should be legible without reviewing
the full history, routine adjustments should be supported
directly, and necessary interventions should be noticed in
time. Section 5 examines the open challenges in meeting
these requirements.
3.2
Three On-Demand Interaction Modes
Delegate, Adjust, and Check describe the user’s purpose
when interacting with an ongoing task (Fig. 2). Initial
delegation establishes the task. Later interactions can use
any mode, in any order, depending on the user’s needs.
Delegate: Express or Revise a Goal.
The user uses lan-
guage to express an intention that the available controls
do not capture. The agent interprets the goal or revised

Adjust: Use an Available Control.
The user invokes an

task, such as pausing playback or changing a timer value.
Adjust refers to a user action; automatic retries and run-

Check: Inspect the Current State.
The user reads task
feedback without issuing a new instruction. A brief view
may be enough to establish that the task is running,
waiting for input, or complete. Further detail should be
available when the user needs to understand a change or
decide how to respond.
Agent-Initiated Attention and Clarification.
The three
modes describe what the user does; an attention request
describes how an interaction begins. The agent may re-
quest participation when essential information is missing
or a task needs a decision. The user can then inspect
the request through Check, clarify the goal through Dele-
gate, or respond with an available control through Adjust.
Agent-initiated attention therefore connects to all three
modes rather than forming a fourth mode. A clarification
should ask for the information needed to proceed and
remain attached to the existing task. If a decision can
wait, the task should retain that request until the user
returns. The timing and prominence of these requests are
design choices discussed in Section 5.2.

and feedback. When the user invokes an available action,
the system can reuse its binding. A runtime update may
only require changing a displayed value. The design princi-
ple is to adapt the interface when interaction needs change,
while keeping familiar controls stable during routine use.
For example, switching background music to instrumen-
tal jazz changes the selection criteria, but does not neces-
sarily change the need for playback controls. The agent
can interpret the revised preference while retaining the
meaning and location of those controls. A track change
may then update the displayed title without changing
the layout. For intermittent interaction, this continuity
matters: users should be able to reuse what they learned
during an earlier visit. If an action is no longer available,
the interface should indicate that change rather than
silently assign a different meaning to the same control.
The connection must also remain meaningful as the
environment changes. A displayed control should refer
to an action that is currently available, and feedback
should reflect observed execution. If the agent cannot
establish the current state, the interface should make that
uncertainty visible. These requirements support the user’s
ability to return and act on the task.
4
The Orvlet Prototype
Orvlet provides a concrete example of the Calm Agent
principles on the desktop. It combines an isolated back-
ground browser, compact task interfaces, and stored task
context. We use its design and several implemented sce-
narios to show how the principles shape interaction.
Fig. 4 shows how a writer can access Orvlet’s input bar
and music controls while editing a manuscript.
4.1
Background Task Execution
Orvlet operates the relevant webpage or tool in the back-
ground. For a media request, it performs the webpage
actions and checks playback before presenting the result.
The original service provides the task capability, while
the compact interface provides access to selected controls
and state. Collapsing this interface leaves the background
activity running, supporting P1.
Fig. 5 shows the execution path. New goals can require
planning; existing controls invoke their action bindings.
Outcome checks and runtime updates feed into task con-
text, which supports later requests and the visible inter-
face. The implementation can optionally use Jev [22] to
route requests to available capabilities fast.
4.2

edge, with a label, status, and main action (Fig. 6e).

Scenarios
Controlling Music.
A user asks to play quiet background
music and returns to writing. Orvlet starts playback in a
predefined music card with playback and volume controls
(Fig. 6a).
Monitoring Concurrent Time-Related Tasks.
A user co-
ordinating work between Beijing and London asks for
a dual-timezone clock and a break countdown. Orvlet
presents the detailed timezone view in a card while stack-
ing pills for the timezone summary and countdown along-
side primary work (Fig. 6b).
Checking and Refreshing a Repository’s Star Count.
A
user asks for a GitHub repository’s star count. Orvlet
presents the count, repository identifier, data source, and
a refresh control in a compact card, paired with a summary
pill (Fig. 6c).
Comparing Stock Prices.
A user asks to compare Apple
and Tesla share prices. Orvlet presents both prices, their
changes, and the price difference in a single card alongside
the trading session, data source, and a summary pill
(Fig. 6d).
4.4
Interaction Implications
Table 1 contrasts representative interaction configurations
for an ongoing auxiliary task. The comparison identi-
fies where users access controls and recover task context.
These configurations can be combined; for example, a
conversational interface can also provide persistent task
controls.
The design question is how much work a brief visit re-
quires: locating the task, understanding its state, choosing
an action, and returning to primary work. Orvlet brings
these activities into a persistent point of access. The
challenges below concern extending this approach across
changing tasks, execution conditions, and user habits.
5
Challenges
Calm Agent places competing demands on a single inter-
face: it must be compact yet informative, adaptable yet
familiar, responsive during ongoing execution, and able
to request input without repeatedly disrupting primary
work. We identify four open challenges in meeting these
requirements.
5.1
Adaptive Interfaces with Interaction
Continuity
A compact interface offers limited space for open-ended
tasks with many possible states and actions. Showing only
frequent controls risks hiding rare but necessary decisions,
whereas exposing every option increases the effort of a
brief visit. While evolving task-driven interfaces provide
a foundation for adaptation [9], supporting intermittent
return requires deciding which elements should adapt and
which should remain stable.
As user intentions and execution environments evolve,
the system must determine whether a revision alters an
action’s meaning, its target, or merely a parameter. It
must avoid both visually unchanged controls whose effects
have shifted and unnecessary redesigns that discard famil-
iarity. Progressive disclosure can keep surfaces compact,
yet critical state distinctions, such as a blocked task or
an unavailable action, must remain immediately legible
to users who did not observe the transition.
5.2
Attention Requests across Concur-
rent Tasks
An agent must decide both whether human input is nec-
essary and how prominently to request it. Asking about
every ambiguity shifts interpretation work back to the
user, whereas acting on unsupported assumptions risks
unwanted outcomes; distinguishing missing information
that changes the agent’s action from choices resolvable
within the delegated scope remains open. Even when
input is needed, its timing and prominence should reflect
the cost of delay and the user’s current activity [4, 18]:
deferrable questions can remain quietly accessible, while
time-sensitive decisions warrant stronger signals.
Concurrency compounds this problem across tasks. In-
dividually reasonable requests may arrive together or
interrupt primary work in succession, a tension made con-
crete by the stacked pills in Orvlet. Grouping requests
lowers interruption frequency but risks delaying urgent
decisions, whereas prioritizing one task makes others easy
to overlook.
Coordinating timing and salience across
concurrent tasks without obscuring unresolved decisions
remains a key challenge.

5.3
Responsive Interface Generation and
Execution
A brief interaction turns into a long wait if interface
generation begins only after planning and execution finish.
Preparing the interface and its underlying behavior in
parallel, such as drafting a card while the agent resolves
a data source, can reduce latency, but these processes
share dependencies: valid actions and values often remain
unknown until execution produces evidence.
A staged interface can surface received intent and
known information early, enabling controls as their back-
ing behavior becomes ready. Doing so requires clearly
distinguishing pending operations from ready controls
and reconciling partial results whenever the user revises
the goal mid-execution. Without careful coordination,
asynchronous updates risk causing layout shifts or invalid
actions just as the user attempts to interact.

5.4
Understanding
and
Adapting
to
Users over Time
Repeated use enables an agent to interpret requests with
less explanation and tailor interfaces to user habits, such
as preferred terminology, frequent controls, or level of
detail.
Yet brief interactions provide incomplete and
ambiguous evidence: a control may be used often simply
because it is easy to reach, and an ignored notification
does not necessarily indicate a preference for silence.
Long-term adaptation must therefore separate explicit
preferences from inferred habits and account for task con-
text. A preference for minimal displays during focused
work may not apply when exploring a task in detail, and
explicit corrections should revise the current assumption
without erasing habits that remain useful elsewhere. De-
ciding which learned preferences transfer to a new request,
while tracking their confidence and keeping assumptions
easy to correct, remains an open problem.
6
Conclusion
This paper presents Calm Agent, a design framework for
ongoing auxiliary tasks under intermittent human atten-
tion. Its contribution is to connect task continuity with
three on-demand interaction modes: Delegate, Adjust,
and Check. A persistent task representation links these
modes to execution, while agent-initiated requests bring
users back when clarification or a decision is needed. The
Orvlet prototype illustrates this framework through back-
ground execution, compact task controls, and task-linked
clarification. We identify four open challenges in inter-
face adaptation and continuity, attention requests across
concurrent tasks, responsive generation and execution,
and long-term user adaptation. Together, these contri-
butions frame agent interaction around brief, purposeful
participation while protecting attention for primary work.
