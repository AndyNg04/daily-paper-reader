## 摘要
尽管可穿戴显示设备能够让用户随时随地使用数字工作空间，但交互仍受限于两种方式：缺乏触觉反馈且容易引发疲劳的空中手势，以及携带不便的控制器。我们提出 MidasTUI，这是一种系统，可通过简短的交互示范，将任意日常物品即时转化为临时有形用户界面。例如，用户可以像使用鼠标一样在桌面上滑动耳机盒，无需携带专用输入设备即可进行临时交互。MidasTUI 利用可穿戴显示设备的摄像头和基于 Transformer 的时序分类器，检测用户何时握持并移动物品；随后根据手部运动推断用户意图使用的输入方式（如滑块、鼠标或键盘），并将追踪到的手部—物品交互映射至应用功能。评估结果表明，该系统能够可靠地泛化至不同物品和不同用户。进一步的对比用户研究显示，与空中交互相比，以日常物品为基础的交互能够减轻身体负担，并提升用户感知到的易用性和操控感。

## Abstract
While wearable displays can bring digital workspaces anywhere, interaction remains limited by mid-air gestures that lack tactile feedback and induce fatigue, or controllers that are cumbersome to carry. We present MidasTUI, a system that instantly transforms arbitrary everyday objects into opportunistic tangible user interfaces through brief interaction demonstrations. For example, a user can slide an earbud case across a table as a mouse, enabling opportunistic interaction without carrying a dedicated input device. MidasTUI detects when a user is holding and moving an object using the wearable display camera and a Transformer-based temporal classifier. It then infers the intended input modality (e.g., slider, mouse, keypad) from hand movement and maps the tracked hand-object interaction to an application function. Our evaluations demonstrate reliable cross-object and cross-user generalization. A comparative user study further shows that grounding interaction in everyday objects reduces physical burden and improves perceived usability and control relative to mid-air interaction.

## 1. 核心问题与研究动机

- **研究问题**：在不携带鼠标、手柄等专用输入设备的情况下，用户能否通过几秒钟的动作演示，把手边的日常物品变成可穿戴显示设备的实体控件？
- **背景**：空中手势随时可用，但缺乏触觉反馈和稳定的物理参照，长时间操作容易疲劳；专用控制器通常更易操控，但增加了携带和充电成本。已有的有形用户界面（TUI）往往依赖预注册物体、预设绑定或额外传感器，难以在新环境中临时使用。
- **核心思路**：把“这个物品是什么”与“用户想怎么用它”分开。例如，耳机盒不是因为被识别为耳机盒才成为鼠标，而是因为用户在桌面上像移动鼠标一样滑动它。论文进一步考察：**这种物理支撑能否改善交互体验，以及它会带来多少时间开销。**

## 2. 方法论：从动作演示到应用输入

系统采用四阶段流程：**检测手物共同运动 → 推断输入类型 → 注册与跟踪 → 映射到应用功能**。

1. **Move Together：检测手与物体是否共同运动。** 系统从头显透视摄像头获取连续图像，用手部掩码定位手—物区域并裁剪为 224 × 224。FastViT-T8 逐帧提取 384 维特征，时序分类头汇总窗口信息，经 sigmoid 输出共同运动的概率，并用二元交叉熵训练。部署选用 **8 帧窗口和 Transformer 分类头**。握持后的平移、旋转和抬起属于正例；悬停、靠近和未带动物体的接触属于负例。
2. **Summon：从短演示推断输入类型。** 新物体触发约 **3 秒**的动作采集。系统记录 26 个手部关节的三维坐标，将每帧的 78 维位置与一阶、二阶帧间差分拼接成 234 维特征，再用一维残差卷积网络（ResNet1D）对变长序列分类。通用模型从 10 种预定义类型中给出 **Top-3 候选**，由用户确认；每类积累约 2–3 次带标签演示后，可微调个性化模型。**Transformer 用于检测手物共同运动，输入类型识别使用的是 ResNet1D。**
3. **TUI Manager：管理激活、复用与跟踪。** 用户先在桌面上标定四角，只有区域内的操作才会触发 TUI。系统用 DINO 图像嵌入比较当前与已注册的手—物图像；最佳匹配相似度高于 **0.75** 时直接复用原绑定，否则重新演示。运行时通过空闲、接合、接触、悬停、释放五种状态控制事件输出。例如，抬起充当鼠标的物体时，光标停止移动，用户可以放回物体后继续操作。
4. **应用映射：把手部运动转换为控制事件。** 交互原语按连续／离散、平移／旋转、1D／2D／3D、绝对／相对映射组织。分类器能识别 10 类演示，但应用原型实际实现了 **鼠标、滑块、旋钮、按键板和笔**五种控件。例如，手掌的二维位移驱动相对光标，沿轴位置控制绝对滑块值，拇指与食指的相对方向变化驱动旋钮。每只手可独立运行检测器，支持一手选工具、另一手调参数等非对称操作。

## 4. 硬件与算力

- **采集与部署**：使用 Meta Quest 3 和 Unity／Meta XR SDK；运行原型时，头显配对一台搭载 **Intel Core i7 和 NVIDIA RTX 3080** 的笔记本。最终检测模型在该部署环境报告 **42 FPS**，并非头显独立运行的性能。
- **推理测试**：在 **NVIDIA RTX A6000** 上，8 帧窗口下各检测模型耗时约 **5.2–5.8 ms／片段**；Transformer 为 **5.6 ms／片段**，视觉骨干单独约 5.0 ms。8 帧在 30 FPS 下对应约 **267 ms 的观测窗口**，不能把 5.6 ms 等同于动作触发的端到端延迟。

## 5. 实验数量与证据充分性

- **实验规模**：共三项主要评估。Move Together 有 **4 种时序头 × 3 种窗口＝12 组配置**，并对 8 帧设置测量效率；Summon 有 **4 档通用模型消融、1 档个性化对照**，通用模型采用 16 折 LOPO；用户研究有 **2 种交互条件**，10 人各完成两种条件。
- **相对公平之处**：时序头共享视觉骨干；LOPO 将目标用户排除在通用模型训练之外；用户研究共享设备、应用和任务，并平衡顺序以减轻练习效应。
- **证据边界**：实验足以支持**原型可行性**及其在特定任务中的体验差异，但不足以证明它可在任意环境中稳定运行，或优于其他实体输入方式。个性化结果使用了目标用户数据，应理解为**获得少量个人样本后的性能**，不能视为零样本泛化。

## 6. 主要结论与发现

- **短时序有助于检测共同运动。** 8 帧 Transformer 的准确率为 **92.1%**、F1 为 **0.918**、AUROC 为 **0.968**，均为表中最佳。考虑时间顺序的模型整体优于简单平均，增加窗口长度也没有稳定带来收益。
- **动作动态与个性化都能改善输入类型识别。** 通用模型从仅用关节位置的 **72.2% Top-1**，经逐步加入速度、Mixup、加速度后提升至 **80.9%**；Top-3 为 **90.8%**。个性化模型达到 **97.5% Top-1**。典型错误包括摇杆与开关互相混淆，以及将按键板误判为触控板。
- **实体交互更舒适、主观可用性更高，但完成任务更慢。** 相比空中交互，MidasTUI 的身体需求评分中位数为 **40 vs. 81**，费力程度和挫败感也显著下降；平均 SUS 为 **73.2 vs. 58.2**（\(p<0.01\)）。但平均完成时间为 **13.14 vs. 11.20 分钟**（\(p<0.01\)），约慢 **17%**。拿取、放下和切换物品是作者提出的可能解释，论文未单独量化这些开销。
- **偏好强于性能证据。** 10 人中有 **8 人**总体偏好 MidasTUI，9 人认为它更稳定。论文没有通过独立的客观精度任务验证这一感受，也没有证明双手操作比单手更高效。

## 7. 优点

- **不靠物体类别决定用途**：把手—物接合检测、输入类型推断和物体复用分开，使新物体无需预先绑定，已注册物体也不必反复演示。
- **在识别不确定时保留用户控制权**：Top-3 候选避免完全依赖单一预测；用户确认还能提供个性化所需的标签。划定桌面交互区域则有助于减少对物体日常用途的干扰。
- **同时评估模型和真实交互流程**：既报告识别、消融和部署速度，也观察用户在复合任务中的工作负荷与完成时间。**主观更好用、客观更耗时**这一结果，比单独报告识别准确率更能说明设计取舍。

## 8. 不足与局限

- **“任意物体”超出了现有证据。** 五件低表现小物体未纳入主要检测结果，汇总指标不能代表戒指、钥匙和 SD 卡等易被手遮挡物体。训练数据来自一名作者，评估参与者均为右利手；跨物体结果也不宜直接解读为严格的留一物体验证。
- **对比研究无法分离各项设计的贡献。** 两种条件同时改变了桌面支撑、实体物体、控制映射和双手分工。缺少桌面裸手触控、专用鼠标或预绑定 TUI 等基线，无法判断体验改善中有多少来自物理支撑，又有多少来自演示绑定机制。
- **样本与场景有限。** 用户研究仅有 10 人、一个拼贴任务和一组指定物品，未覆盖用户在陌生环境中自行寻找控件、长期办公或频繁变换场地的情况。双手效益、客观精度和长期疲劳改善仍需专项验证。
- **部署仍有门槛。** 当前原型需要桌面与四角标定，首次绑定要演示并确认候选。遮挡、视角变化、杂乱背景和有限桌面空间都可能影响操作；参与者也报告了释放后误触发、点击不稳和旋钮细调困难。系统不能测力，也不能凭演示自由生成预定义类别之外的新控件。
