Abstract
While wearable displays can bring digital workspaces anywhere,
interaction remains limited by mid-air gestures that lack tactile
feedback and induce fatigue, or controllers that are cumbersome to
carry. We present MidasTUI, a system that instantly transforms ar-
bitrary everyday objects into opportunistic tangible user interfaces
through brief interaction demonstrations. For example, a user can
slide an earbud case across a table as a mouse, enabling opportunis-
tic interaction without carrying a dedicated input device. MidasTUI
detects when a user is holding and moving an object using the
wearable display camera and a Transformer-based temporal classi-
fier. It then infers the intended input modality (e.g., slider, mouse,
keypad) from hand movement and maps the tracked hand-object
interaction to an application function. Our evaluations demonstrate
reliable cross-object and cross-user generalization. A comparative
user study further shows that grounding interaction in everyday
objects reduces physical burden and improves perceived usability
and control relative to mid-air interaction.
Keywords
wearable displays, tangible user interfaces, hand-object interaction

Introduction
Wearable displays support productivity beyond the traditional desk-
top by bringing virtual applications into “on the go” everyday en-
vironments [24, 64]. However, interaction with these displays us-
ing spatial interfaces still largely depends on gaze [40, 50] and
mid-air gestures [43, 82], which often suffer from limited preci-
sion and physical fatigue due to the lack of tangibility and hap-
tic feedback [27, 36, 38]. Dedicated input devices, such as con-
trollers [49, 65] and mice [26], as well as companion devices such as
tablets [4, 63] can provide more accurate and comfortable control,
but at the cost of portability and battery life, and they may not
always be readily available.
To provide more convenient yet accurate and comfortable con-
trol, researchers explored turning everyday physical objects into
tangible user interfaces (TUIs) [12–14, 19, 20, 34, 47, 55, 85], lever-
aging their ready availability and inherent tangibility to support
effective spatial interaction [39, 66]. Tangible objects also support

asymmetric bimanual interaction, where each hand can be assigned
to a different function [51, 81]. This division of labor between
the hands has been shown to improve efficiency in compound
tasks [25, 37, 41, 73] but difficult to achieve with mid-air gestures,
which largely afford symmetric input. However, most of these TUI
interactions are object-centric and require external sensing de-
vices [10, 17, 57, 80] or extensive upfront setup [13], in which
each object’s geometric [30, 33, 62], texture [19], kinetic capabil-
ity [20, 85], or semantic information [12, 47] must be pre-registered
and bound to predetermined digital controls before use [13, 31, 55].
This requirement makes such systems less suited to ad-hoc, ev-
eryday scenarios, since users cannot simply pick up an unfamiliar
object in a new environment and begin interacting, and the bind-
ings may transfer poorly across objects whose shapes and affor-
dances were not anticipated at design time [20]. In addition, many
existing TUI systems focus on design exploration [20, 47], rapid
prototyping [42], or conceptual demonstrations [14, 35], with less
emphasis on real-time usable systems for sustained productivity
scenarios such as work on wearable displays. These limitations
mean that prior systems remain confined to selected object sets
and pre-authored scenarios, falling short of the truly opportunistic,
“pick up anything and use it” interaction that wearable displays
demand in everyday environments.
In this work, we present MidasTUI, a novel hand-centric ap-
proach that transforms available everyday objects into opportunis-
tic tangible user interfaces without extensive configuration. Unlike
previous object-centric TUI systems that rely on specific objects or
pre-authored bindings, MidasTUI adapts to whatever objects are at
hand, allowing the user to simply grab an object and manipulate it
as they would a familiar input device [28]. For example, a user can
pick up an earbud case and slide it across a coffee table as a mouse,
enabling precise and comfortable interaction (Figure 1). MidasTUI
also extends naturally to bimanual use, where the user can hold a
different object in each hand to drive distinct functions in parallel.
At a high level, MidasTUI detects when the user is holding and
moving an object using the wearable display camera, infers the in-
tended input modality (e.g., slider, mouse, keypad) from the user’s
hand movement, and maps the tracked interaction to an application
function.
Rather than relying on predefined mappings or explicit config-
uration, MidasTUI treats user demonstration as a mechanism for
defining how objects function as input. This approach operates
through a four-stage pipeline and was tested with 16 participants.
First, Hand–Object Engagement Detection (the Move Together model)
uses a FastViT spatial backbone with a Transformer temporal head
to determine whether the user’s hand grabs and moves a nearby
object (F1=0.92 across 20 objects, < 6 ms per inference). Second,
Input Modality Inference (the Summon model) infers the intended
input modality from hand movement: a generalized model provides
immediate top-3 suggestions without per-user data (80.9% top-1
across 10 classes), and a personalized model adapts to the user’s mo-
tion style, reaching 97.5% accuracy. Third, the TUI Manager stores
and manages recognized TUIs and their interaction models. Lastly,
Interaction-to-Application Function Mapping binds each TUI inter-
action to an application function according to its dimensionality
(1D/2D/3D), motion primitives (linear/rotary), flow (continuous,
discrete), and control mapping (absolute/relative). Beyond technical
feasibility, we also investigate whether interaction with everyday
objects provides practical benefits over bare-hand mid-air input.
We recruited 10 participants to compare MidasTUI with Mid-Air
interaction in an exploratory photo-editing task involving tool
switching, parameter adjustment, and object manipulation in MR.
Although MidasTUI introduced additional acquisition and interac-
tion overhead, participants reported better usability and control,
and highlighted less physical fatigue, stable spatial references, and
useful bimanual interaction as key advantages.
In summary, this work contributes: (1) a demonstration-driven
approach that enables users to define input behavior for everyday
objects through interaction, supporting opportunistic tangible inter-
action on wearable displays; (2) two novel models, Move Together for
hand–object engagement detection and Summon for input modal-
ity inference, along with the corresponding datasets we collected
to train and evaluate them; (3) technical evaluations showing ro-
bust performance across a diverse set of everyday objects; and (4)
A user study comparing MidasTUI with mid-air interaction in a
realistic photo-editing task, showing that everyday-object tangibil-
ity reduces perceived physical burden and improves usability and
control.

Related Work
2.1
Ad-hoc Interaction for Wearable Displays
With the development of head-mounted displays (AR/VR) and smart
glasses, wearable displays are emerging as a promising platform
for daily work and leisure tasks, offering mobile, extendable, and
“on the go” workspaces that adapt to user needs and contexts [8, 24,
56, 64]. However, providing input that is both readily available in
everyday contexts and efficient enough for sustained use remains
challenging.
Prior work has explored ad-hoc input techniques by leveraging
the user’s body, including gaze [40, 50, 71], head movement [45,
79] and mid-air gestures [43, 67, 82]. These techniques are always
available but often suffer from fatigue, low precision, lack of haptic
feedback, and limited expressiveness [27, 38, 49]. Other work has
leveraged dedicated input devices such as controllers [49, 65] and
mice [26], companion devices such as tablets [4, 63], and nearby
grounded surfaces [15, 52, 77]. They can provide more accurate
and comfortable control through tangible affordance and physical
support [2, 11, 52, 81]. However, dedicated devices must be charged
and carried, and grounded surfaces lack portability, neither of them
is always readily available in everyday environments.
Our work instead explores how everyday objects can be appro-
priated as input devices through user demonstration, combining the
availability with the ability to flexibly define their input behavior.
2.2
Utilizing Everyday Objects as Tangible User
Interfaces
Tangible user interfaces (TUIs) bind physical objects to digital con-
trols, leveraging the user’s familiarity with manipulating real-world
artifacts to support efficient and embodied interaction [18, 39].
Beyond providing passive haptic feedback, tangible objects also
support asymmetric bimanual interaction, where each hand can
be assigned to a different function [5, 51]. Such coordination im-
proves efficiency and reduces completion time and cognitive effort

A large body of work has explored repurposing everyday objects
as TUIs, motivated by their ubiquity, low cost, and rich physical
affordances [66]. Some research takes a user-authored approach, let-
ting users explicitly bind objects to digital functions through demon-
stration, voice commands, or interactive teaching [12, 13, 31, 55, 72].
While effective for customization, these systems place the burden
of configuration on end-users, making them unsuitable for sponta-
neous, ad-hoc interaction in dynamic everyday environments.
Other systems pursue automatic object-function binding, which
can be further grouped into two strategies. Object-centric meth-
ods map specific physical properties of an object, such as geome-
try [20, 30, 33], texture [19], kinetic capability [20, 85], or semantic
category [12, 47], to predetermined interface roles. However, they
typically rely on external sensing hardware [10, 17, 57, 80] or exten-
sive upfront setup [13] to register each object’s properties before
use. This requirement makes such systems less suited to ad-hoc,
everyday scenarios, since users cannot simply pick up an unfamil-
iar object in a new environment and begin interacting. In addition,
object-centric systems depend on the “right” object being available,
may adapt poorly to user intent, and often transfer poorly to ob-
jects whose shapes and affordances were not anticipated at design
time [20].
In contrast, hand-centric methods recognize tool-use gestures
from the hand alone, generalizing across whichever object is held [28,
60, 61, 85]. However, existing hand-centric systems rely on pre-
defined gesture vocabularies that may not reflect how people nat-
urally handle objects. As a result, interaction semantics are deter-
mined by the system designer rather than emerging from the user’s
own manipulation behavior. Moreover, much of this work remains
oriented toward design exploration [20, 47], rapid prototyping [42],
or conceptual demonstrations [14, 35], rather than sustained, real-
time use in productivity scenarios.
Our work builds on user-authored and hand-centric approaches,
but takes a different perspective on how interaction should be de-
fined. Rather than treating demonstration as a configuration step
or relying on predefined gesture vocabularies, we treat user demon-
stration as a mechanism for defining interaction semantics. In our
approach, the system interprets how users manipulate objects as an
expression of intended input modality, enabling real-time, object-
independent interface creation without explicit configuration. This
shifts the role of everyday objects from predefined interface ele-
ments to flexible interaction substrates, whose function emerges
from user action rather than being pre-authored.
2.3
Hand–Object Interaction Detection
A prerequisite for enabling opportunistic tangible interaction with
everyday objects is the ability to reliably detect when a user is
holding and manipulating an object, and to infer the intended input
from that interaction. Prior work has approached this problem with
instrumented sensing, including smartwatches [10, 46] and cus-
tomized wearable sensors [17, 23, 57, 80], which provide reliable sig-
nals at the cost of additional hardware. To support uninstrumented
use, camera-based approaches detect hand–object contact [19, 54]
or recognize predefined manipulation gestures [60, 61, 85]. How-
ever, robust camera-based detection in unconstrained, in-the-wild
settings remains challenging due to occlusion, object diversity, and
the fine-grained nature of hand–object contact.
Existing datasets of camera-based hand–object interaction [6,
44] primarily target functional grasp recognition, capturing how
the hand contacts an object to perform a specific task such as
pouring or opening. These benchmarks are not directly applicable
to our setting, which goes beyond functional purpose and instead
focuses on whether the hand and object are moving together. We
therefore collect our own Move Together dataset, on which we train
a detector that identifies correlated motion between the hand and
a nearby object. This signal requires no object instrumentation
or predefined gesture vocabulary, and generalizes across object
shape, size, and material, allowing engagement to be treated as an
object-independent interaction cue.
Once engagement is detected, the system must further infer
what kind of input the user is performing. Prior work shows that
fine-grained hand motion features can be modeled to recover user
intent for tasks such as grasp-onset prediction [68], selection-intent
detection [84], ray-landing prediction [78], and dynamic gesture
recognition [48, 76], typically using temporal models over kine-
matic features (joint angles, velocity, acceleration). However, these
methods classify within a fixed vocabulary tied to a specific task.

intended behavior.

MidasTUI System
MidasTUI enables tangible interaction on wearable displays using
everyday objects, without requiring dedicated input devices. It
is a camera-based, hand-centric, user-authored system organized
into four stages: (1) Hand-Object Engagement Detection, (2) Input
Modality Inference, (3) Interaction Tracking, and (4) Interaction-to-
Application Function Mapping. We describe each stage below.
3.1
Hand–Object Engagement Detection Model
3.1.1
Interaction Principle. The first stage of the MidasTUI pipeline
determines whether the user intends to use an physical object as
an input modality for interacting with the wearable display. Rather
than requiring an explicit selection gesture (e.g., ray-cast or gaze
dwell) or a dedicated input device (e.g., mouse or touchpad), we
infer engagement implicitly: when a user grasps an object and be-
gins to move it, the correlated motion of the hand and the object
signals interaction intent. We call this the hand–object engagement
detection model, or Move Together for short. The system con-
tinuously monitors the scene through the headset’s passthrough
cameras. For each frame, it identifies whether the hand and the
object exhibit correlated motion through a move together classifier.
If so, the system concludes that the user intends to engage with the
object, has picked it up, and activates the MidasTUI pipeline for
that object; otherwise, no TUI interaction is registered (e.g., when
the hand hovers over or rests on the object without displacing it).

3.2
Input Modality Inference Model
3.2.1
Interaction Principle. Once the Move Together detector con-
firms that the user has engaged with a physical object, the system
enters the input modality inference stage, which we call Summon.
In this stage, the user effectively “summons” an interface by demon-
strating how they intend to use the object as an input device. The
key idea is that everyday objects afford different interaction styles:
for example, a soap bar can be slid like a mouse, while a bottle cap
can be twisted like a dial. The user’s natural demonstration of these
movements therefore reveals the interaction modality they intend
to invoke.
MidasTUI adopts a two-stage recognition strategy. A general-
ized model, trained on data from other users, provides immediate
predictions without requiring per-user calibration. It presents the
top three most likely interaction modalities for the user to choose
from. As the user makes selections over time, these choices become
labeled examples for training a personalized model adapted to that
individual’s motion style, progressively improving accuracy from
80.9% to 97.5%, which we discussed in Section 4.2.

3.2.2
Interaction Demonstration. During the Summon stage, the
user holds the engaged object and performs the motion they wish
to use for input. For example, a user might slide a pendrive back
and forth to indicate slider control, or rotate a pill box to indicate
rotary input (Figure 3). The system records the 3D hand motion
throughout this demonstration using the headset’s built-in hand
tracking, capturing the world-space positions of 26 hand joints at
each timestep.

Classification Model. We use a 1D residual convolutional network
(ResNet1D) that operates directly on the temporal feature sequence
S′ ∈R𝑇×234. The architecture consists of a stem convolution with
kernel size 7, followed by three downsampling residual stages that
progressively increase the channel dimension while reducing tem-
poral resolution through stride-2 convolutions. A length-aware
masked global average pooling layer aggregates the variable-length
sequence, and a final fully connected layer produces a probability
distribution over 𝐶= 10 input device classes (Figure 3): slider, knob,
switch, mouse, touchpad, pen, joystick, d-pad, keypad, and pointer. To-
gether, these classes span continuous and discrete interaction flows,
linear and rotary motion primitives, one- to three-dimensional con-
trol, and both absolute and relative mappings. Architecture details
for both classifiers are provided in Appendix A.2.
3.2.4
Training and Adaptation. We train a generalized model for
immediate use and adapt it to individual users as labeled demon-
strations accumulate.
Training. We use a 1D residual convolutional network adapted
from ResNet [32] to model temporal hand-motion features. The
model is trained end-to-end using cross-entropy loss [21]. We fur-
ther apply Mixup regularization [83], which constructs virtual train-
ing examples by linearly interpolating pairs of input sequences and
labels.
Data augmentation includes random temporal cropping, Gauss-
ian noise injection, scale jitter, and random time reversal. Training
configurations for both classifiers are provided in Appendix A.3.
Generalized Model. The generalized model is trained on demon-
strations from all participants except the target user and evaluated
using leave-one-participant-out cross-validation over 16 partici-
pants. At inference time, the model returns a ranked list of the top
three most probable interaction classes, from which the user selects
the intended modality.
Personalized Model. Each user selection serves as a new labeled
training example. After 2–3 demonstrations per class have been
collected through natural use, the system fine-tunes a personalized
model on this user-specific data. By observing user’s motion style
during training, the personalized model can better account for
cross-user variability that limits the generalized model (Section 4.2).
Once the input modality is determined, the system transitions to
interaction mode, in which the object’s movements are continuously
interpreted as input events for the active application.
3.3
TUI Manager
Following hand-object engagement detection and input modality
inference, the TUI Manager governs how an engaged object is ac-
tivated, recognized across sessions, and tracked during runtime
control. It is built around three coupled mechanisms: (i) an interac-
tion area calibration that defines where TUI control is valid, (ii) a
TUI registry that lets previously inferred objects be re-summoned
without re-demonstration, and (iii) a state machine that converts
hand-object motion into digital control events for two hands.
3.3.1
Interaction Area Calibration. MidasTUI restricts TUI activa-
tion to a user-calibrated interaction area on arbitrary tabletop. At
setup, the user defines the area by pointing the index fingertip at
four corners in clockwise order. At runtime, the system maps a
3D hand position onto the quadrilateral interaction area via in-
verse bilinear interpolation, producing normalized coordinates
(𝑢, 𝑣) ∈[0, 1]2. A control–display (CD) gain then maps relative
displacements within this physical region to cursor displacements
traversing the full screen.

Only objects manipulated within this area are treated as potential
TUIs. When an object moves inside the region, the system checks
whether it has already been registered and, if so, activates its as-
sociated interaction. Manipulations outside the area are treated as
normal everyday interactions and do not trigger TUI behavior. This
spatial filtering reduces unintended activation by preventing the
system from interpreting every touched object as an input device,
while preserving everyday interaction habits by allowing the same
object to serve both ordinary physical and digital control functions
depending on where it is used. For example, a cup manipulated
within the interaction area may be interpreted as a knob control
for parameter adjustment, while outside the area it can still be used
for drinking, enabling seamless transitions between instrumental
and everyday object use.
3.3.2
TUI Registration and Recognition. After the system detects
hand-object engagement for an object manipulated within the inter-
action area, it first determines whether that object has already been
assigned an input (Figure 2), as MidasTUI maintains a list of objects
registered as TUIs for instant and repeated use. If the object has not
yet been registered, the system proceeds to the second stage, input
modality inference, to infer the intended input modality. The object
is then registered as a new TUI and added to the registered TUI
list. If the object has already been registered, the system skips the
inference stage and directly enters the interaction tracking stage.
This allows previously inferred objects to be reused with their exist-
ing control mappings, avoiding redundant inference and reducing
interaction overhead.
To recognize whether an engaged object has already been reg-
istered, the system crops the camera view around the hand after
hand-object engagement is detected. The cropped hand-object view
is then compared against the list of registered hand-object views.
We measure object similarity using DINO [9], which provides high-
level visual embeddings that capture semantic visual similarity
between images. High similarity scores indicate a match to a previ-
ously registered object. Based on this similarity, the system deter-
mines whether the current object corresponds to an existing TUI
or should be treated as a newly encountered object. Specially, if the
best match exceeds 0.75, the system reuses the stored modality and
immediately activates the corresponding control mapping, so the
user simply picks the object up and starts using it. If no existing
TUI passes the threshold, the system enters an interaction demon-
stration window: it auto-starts a 3-second hand-motion capture,
returns the top-3 candidate input modalities, and stores the user’s
selection together with the hand-object view.
3.3.3
Interaction Tracking and State Machine. Once an object is
activated, MidasTUI must decide moment-by-moment whether the
ongoing hand-object behavior should initiate, maintain, pause, or
terminate control. We adopt the event-driven structure used in
touch and pointer input systems [1], but operate over hand and
finger motion observed by the headset cameras and hand tracker
rather than over capacitive contacts [58, 59, 75]. Figure 4 illustrates
the shared interaction state structure used across input modalities.
While specific thresholds and transitions vary by modality, they
follow a common set of interaction phases. For each modality, the
system monitors a small set of motion cues (surface displacement,
angular change, palm vertical velocity, and per-finger vertical ve-
locity) and updates the interaction state accordingly. Following
standard pointer-event vocabulary, our state machine uses five
states: Idle, Engaged, Touch, Hover, and Release.
Interaction states. Idle: the object rests on the surface with no
engagement and no control output. Engaged: hand-object engage-
ment is confirmed and a modality is bound, but the system is still
observing whether motion is sufficiently stable and intentional to
start emitting control events. Touch: the modality-specific activa-
tion condition is met and the system continuously emits control
output or fires discrete events. Linear primitives (slider, mouse)
activate on ≥5 mm of on-surface displacement; rotary primitives
(knob) activate on ≥5◦of angular change. Discrete clicks are de-
tected from the index fingertip’s smoothed vertical velocity: the
finger must first cross a downward threshold of −0.05 m/s, then
an upward threshold of +0.02 m/s, with a minimum vertical travel
of 8 mm. To suppress false clicks during whole-hand lifting, the
wrist must remain below 0.08 m/s during the click, and succes-
sive clicks are separated by a 300 ms cooldown. Hover: the user
remains engaged with the object but lifts and repositions it before
re-contacting the surface. As with mouse clutching during relative
control, this lets users reset the workspace without affecting out-
put. Hover is engaged when the smoothed palm vertical velocity
exceeds 0.05 m/s upward. While in Hover, cursor movement stops,
slider values freeze and pen strokes terminate; on landing back into
Touch, sliders resume from the held value and a new pen stroke
begins. Release: the system aborts the current interaction when
the hand leaves the object, when the engagement signal becomes
unreliable, when motion no longer matches the inferred modality,
or when tracking is lost for an extended period. After Release, the
system resets to Idle.
3.4
Interaction-to-Application Mapping
While the tracking stage decides when hand-object motion is valid
input, the mapping stage decides how that input is interpreted. Mi-
dasTUI does not bind objects to specific UI widgets; instead, it binds
them to interaction primitives organized along four dimensions,
and applications consume those primitives. This indirection lets the
same physical interaction generalize across applications that share
common control structures, including graphics editing, document
review, note taking, and web browsing.
3.4.1
Interaction Primitive Design Space. We characterize inter-
action primitives along four dimensions: temporal form, motion
primitive, interaction dimensionality, and control mapping.
Temporal form. An interaction may be continuous or discrete.
Continuous interactions emit a stream of values while active, such
as cursor movement, parameter adjustment, or drawing. Discrete

Motion primitive. Motion may be primarily linear or rotary. Lin-
ear primitives are driven by translation along one or more axes
on the surface (slider, mouse), while rotary primitives use angular
change around a dominant axis (knob).
Interaction dimensionality. Primitives may be 1D (scalar adjust-
ment such as a slider), 2D (planar position, such as cursor or pen),
or 3D (spatial input, such as free-space pointing).
Control mapping. Mapping may be absolute or relative. Absolute
mappings tie physical position directly to an input location or
discrete region, as in the pen, slider, and keypad control. Relative
mappings translate physical changes into incremental updates, as in
the knob and mouse control. Relative mappings are useful when the
virtual control range exceeds the comfortable physical workspace.
3.4.2
Representative Interaction Primitives. Productivity and cre-
ative interfaces are built around a small recurring set of controls.
Figure 5 illustrates how MidasTUI realizes five of them in a photo-
editing application on the wearable display.
Keypad. Keypad is a discrete, absolute 2D control for commands
or mode selection (Figure 5b). Objects with a planar surface, such
as a book cover, are mapped to an 𝑛×𝑛grid of virtual keys. Par-
ticipants tapped different regions of the physical surface to select
the corresponding virtual keys. The selected key is determined
by the 2D position of the pointing fingertip on the surface, while
a downward fingertip motion, detected from its vertical velocity,
triggers the selection.
Slider. The slider primitive is a continuous, absolute 1D control
for scalar parameters such as size, hue, or zoom (Figure 5c). Par-
ticipants translated the engaged physical object along the slider
axis on the tabletop. The position of the manipulating hand’s palm
center along this axis is mapped directly to the corresponding value
within the slider’s range. The value remains unchanged while the
object stays stationary or is lifted from the surface.
Knob. Knob is a continuous, relative 1D rotary control for pa-
rameters such as element orientation and opacity (Figure 5d). Par-
ticipants rotated the engaged physical object on the tabletop to
adjust the controlled parameter. The rotation angle is inferred from
the angle between the thumb and index fingertips, and changes in
this angle are mapped to relative changes in the parameter. Lifting
the hand and re-contacting the object clutches the control, allowing
incremental rotary adjustments beyond the comfortable range of a
single motion.
Mouse. Mouse is a continuous, relative 2D control with control-
display gain (Figure 5e). Participants moved the engaged physical
object across the tabletop to move the cursor. Cursor movement
is derived from changes in the 2D position of the manipulating
hand’s palm center. Lifting the object and re-contacting the surface
clutches the control, allowing extended cursor travel within a small
physical area. An index-finger click on the engaged object triggers
a selection, and a double-click toggles drag.
Pen. Pen is a continuous, absolute 2D control for drawing, trac-
ing, handwriting, and highlighting (Figure 5f). Participants moved
the engaged object across the tabletop to draw. The drawing point
on the application window is determined by an absolute spatial
mapping from the 2D position of the manipulating hand’s palm
center on the tabletop to the corresponding 2D position in the ap-
plication window. Surface contact determines stroke state: lifting
the object ends the current stroke, and the next contact begins a
new one.
Selecting among same-primitive widgets. A single physical ob-
ject can be reused to control multiple UI widgets that share the
same interaction primitive. For example, several sliders may control
opacity, hue, and brush size. In such cases, the non-dominant hand
uses mid-air pinch-and-swipe gestures to switch among candidate
widgets of the same function. The selected widget then receives
the input generated by the physical object. For example, the non-
dominant hand swipes up and down to switch between the four
sliders shown on the left side of the application window (Figure 5a).
3.4.3
Bimanual Coordination. Productivity and creative tasks rarely
map onto a single tangible control. Users often need to adjust a
value while switching widgets or alternate between tool selection
and content manipulation. MidasTUI supports such workflows with
a bimanual mode that runs two Move Together predictors in parallel,
allowing each hand to control a separate TUI. While both hands can
enable any of the five supported controls, MidasTUI also affords
asymmetric configurations grounded in classical bimanual division
of labor [25]. In one configuration, the dominant hand performs

MidasTUI Comparative Exploratory Study
We conducted a user study to evaluate MidasTUI in a photo-collage
task in MR. We compared MidasTUI with mid-air hand interaction
to investigate whether, when users interact with a wearable display
without a dedicated input device, the tangible interfaces enabled by
MidasTUI using everyday objects provide advantages over perform-
ing the same interactions entirely in mid-air. Participants completed
a photo-collage involving selection, tool switching, object manipu-
lation, and parameter adjustment. We further examined one- and
two-handed interaction to understand whether tangible interfaces
can support and benefit from bimanual manipulations.
5.1
Tasks
We designed a photo-collage task representative of lightweight
work on wearable displays (Figure 9). Participants were shown
a reference collage and asked to reproduce it from a collection
of visual elements on a 2D virtual window. The task consisted of
five main editing stages. Participants first selected and dragged
image elements to their target locations, changed their size by
parameter control, then rotated selected elements to match the
target orientation, adjusted their opacity to reproduce the desired
visual composition, and finally created a color palette and added a
small amount of freehand drawing to the collage.
These operations required the five application controls supported
by our prototype: cursor, keypad, slider, dial, and pen. Cursor input
was used for selecting and repositioning visual elements. The key-
pad supported discrete input such as tool selection, color picker,
and layer selection. The dial controlled rotation and opacity while
the slider controlled parameters such as size and color hues. The
pen supported freehand drawing. The task therefore required par-
ticipants to switch between discrete and continuous input as well
as between coarse positioning and fine parameter adjustment.
5.2
Interaction Techniques
We compared two hand interaction techniques: Mid-Air and Midas-
TUI. Mid-Air served as the baseline because both techniques are
controller-free and rely on hand tracking, while MidasTUI addi-
tionally grounds interaction in everyday physical objects.
5.2.1
Mid-Air Gestures. In the Mid-Air condition, participants in-
teracted with the application using bare-hand gestures tracked by
the headset (Figure 10a). Participants controlled a visual ray ren-
dered between the thumb and index finger, which was cast onto
the virtual window to control the cursor. To select tools, partici-
pants moved the cursor to the target and pinched to select it [53].
The same point-and-pinch interaction was used to activate buttons,
manipulate sliders and dials, drag visual elements, and drawing.
We supported both one- and two-handed interaction. In the
one-handed condition, participants performed manipulations se-
quentially using a single cursor controlled by the dominant hand.
In the two-handed condition, each hand controlled an independent
cursor using the same interaction technique, enabling symmetric
bimanual interaction.
5.2.2
MidasTUI. In the MidasTUI condition, participants performed
the same operations by manipulating everyday objects as tangible
proxies for virtual controls. Participants were provided with five
everyday objects corresponding to different interaction primitives:
(1) an earbuds case for cursor control, (2) a charger adapter for
slider input, (3) a pill box for dial input, (4) a book for keypad input,
and (5) an eye-drop bottle for pen input (Figure 10).
To register an everyday object as a TUI and activate its associated
function, participants first brought the object into the interaction
area (i.e., the tabletop), grasped it, and briefly demonstrated the
intended movement for the target operation for approximately
3–4 s. For example, participants moved the earbuds case across
the tabletop to register it for cursor control. Once an object had
been registered and assigned a function, it could be reused with-
out demonstration. Translation of an engaged object provided cur-
sor, slider, or pen input; rotation provided dial input; and tapping
supported confirmation or discrete keypad input as described in
Section 3.4.2.
MidasTUI also supports both one- and two-handed interactions.
In the one-handed condition, participants switched among tangible
controls sequentially using the dominant hand. In the two-handed
condition, participants could manipulate different physical objects
with each hand, enabling asymmetric bimanual interaction. For
example, the non-dominant hand could move the cursor to select
an object while the dominant hand adjusted its rotation using the
dial control.

6
Discussion
Our evaluations provide evidence at two complementary levels.
The technical evaluations show that MidasTUI can reliably detect
hand-object engagement and infer demonstrated input modalities
across diverse objects and users. Our comparative exploratory user
study further evaluates the resulting tangible interaction in prac-
tice, showing that grounding input in everyday objects reduces
perceived physical burden and improves perceived usability and
control relative to Mid-Air interaction, but also increases task com-
pletion time. Together, these results suggest that using everyday
objects as opportunistic TUIs offers a balance between availability,
physical grounding, control, and interaction efficiency. Based on
our findings, we first discuss what the technical evaluations reveal
about hand-object engagement detection and input modality infer-
ence. We then consider the interaction-level benefits and costs of
tangible interaction observed in the user study. Finally, we derive
broader design implications for opportunistic tangible interaction.
6.1
Hand–Object Engagement Detection
Two findings from the Move Together evaluation shape how en-
gagement detection should be designed. First, all three order-aware
temporal heads outperform the position-invariant Mean baseline
at every window size (Table 1), and the gap widens as the window
grows (F1 0.918 vs. 0.872 at 𝐾=8; 0.896 vs. 0.788 at 𝐾=32). Aver-
aged frame appearance thus carries substantial signal, but it is not
enough to reliably separate intentional engagement from incidental
contact such as hovering or resting a hand on an object; the tempo-
ral order of hand–object motion supplies the remaining evidence.
Second, longer windows do not improve detection: TCN and BiL-
STM remain roughly flat from 𝐾=8 to 𝐾=32, while the Transformer
and Mean heads degrade. An 8-frame window (∼267 ms at 30 fps)
therefore appears sufficient to capture the onset of correlated mo-
tion. Combined with the low per-clip inference cost (Table 2), this

short window lets the detector respond shortly after a grasp-and-
move begins rather than waiting for a longer gesture to complete,
which is important for making opportunistic TUIs feel responsive.
6.2
Input Modality Inference
The Summon results (Tables 3 and 4, Figure 8) point to two conclu-
sions. First, input modality is conveyed mainly by how the hand
moves rather than by its static pose: adding velocity and accel-
eration to joint positions raises generalized top-1 accuracy from
72.2% to 80.9%. Second, the remaining errors are structured rather
than random. They concentrate in a few pairs of modalities with
similar short hand motions, most notably joystick↔switch (short
directional motions) and keypad→touchpad (brief downward fin-
ger movements). Because the correct class in these cases is usually
ranked second or third, a ranked list recovers many of them: top-3
accuracy reaches 90.8%, and joystick recall rises from 0.64 to 0.86.
The large gain from personalization (97.5% top-1) further suggests
that much of the remaining error comes from cross-user differences
in motion style rather than from modalities that are inherently
indistinguishable. These findings motivate pairing top-3 sugges-
tions with lightweight personalization. Users can recruit an object
immediately by choosing from a short list, and each choice pro-
vides a labeled example; once 2–3 demonstrations per class have
accumulated, the system can adapt to the individual user without a
separate calibration session.
6.3
Benefits and Costs of Opportunistic
Tangibility
The strongest interaction-level benefit of MidasTUI was physical
grounding. Participants reported lower physical demand, effort,
and frustration than with Mid-Air interaction, and their comments
repeatedly emphasized the value of manipulating objects on a phys-
ical surface rather than sustaining unsupported movement in free
space. These findings suggest that everyday objects are useful be-
cause they are readily available, provide passive haptic feedback
and stable physical references during interaction.
Participants also generally perceived MidasTUI as more precise,
stable, and responsive than Mid-Air interaction. This perceived
sense of greater physical control suggests that tangible grounding
can improve the experience of fine-grained manipulation. Partici-
pants’ responses further suggest potential benefits of asymmetric
bimanual interaction. Several participants preferred using different
objects with the two hands and described this as reducing switch-
ing burden or helping with compound operations. Their responses
suggest that opportunistic TUIs may be particularly useful when
the two hands assume complementary roles.
These benefits, however, came with an interaction-time cost.
Participants completed the task faster with Mid-Air than with Mi-
dasTUI. One possible explanation is that tangible interaction in-
troduces additional acquisition and transition overhead, as users
must locate, grasp, manipulate, and release physical objects when
moving between tangible controls. Nevertheless, participants rated
switching between tools more favorably with MidasTUI than with
Mid-Air interaction, despite the need to physically acquire different
objects. One possible explanation is that distinct physical objects
externalize interaction state by providing spatially separated cues
for different control roles, reducing the need to navigate abstract
interface modes.
Overall, these results reveal a trade-off between rapid access
and physically grounded control. For wearable interaction, instant
tangible interfaces may be particularly valuable in tasks where
comfort, stability, and sustained use outweigh the need to minimize
short-term task completion time.
6.4
TUI Interaction Design Implications
Our results point toward a shift in interaction design, where input
is defined by user motion rather than object properties. We suggest
several design implications for opportunistic TUI.
Design for Physical Grounding. The value of everyday ob-
jects as opportunistic TUIs is that they are always available in the
environment. Our user study further suggests that their physical
presence changes the interaction experience by reducing physical
demand and increasing perceived stability and control. Opportunis-
tic TUI systems should therefore favor mappings that meaningfully
exploit physical support and contact, rather than treating everyday
objects only as visually trackable proxies. For example, sliding or
rotating an object on a tabletop may offer greater benefits than
manipulating the same object in mid-air, as the surface provides a
stable reference and passive haptic feedback that can support more
controlled interaction.
Minimize Acquisition and Transition Overhead. Although
participants preferred MidasTUI on physical support and control,
task completion was slower than with Mid-Air interaction. Future
systems should therefore reduce the cost of recruiting and switch-
ing among physical controls. Possible strategies include persistent
object-function mappings, faster reactivation of previously regis-
tered objects, reuse of a smaller number of physical objects across
multiple controls, or hybrid techniques that combine tangible and
Mid-Air interaction depending on the operation.
Choice of Objects as TUIs. Although engagement detection
performed well overall, camera-based hand-object sensing remains
sensitive to object properties. Small objects, for example, may yield
less stable detection because they offer limited visible contact area
and are more easily occluded by the hand. Other object features
such as shape and graspability may also affect detection reliability.
We suggest that opportunistic TUI systems do not treat all every-
day objects as suitable, but instead favor objects whose physical
form supports both robust visual detection and meaningful passive
haptics in real practice.
Choice of Supported Input Modalities. Similarly, not all input
modalities are equally suitable for everyday objects as TUIs, even
if users can demonstrate them. Because most everyday objects are
passive and rigid, they are better suited to motion-based input than
to elastic or force-based interaction. In lightweight camera-based
systems, force sensing is difficult, making isometric interaction less
practical. By contrast, isotonic interactions based on visible transla-
tion or rotation are more compatible with both camera sensing and
the physical affordances of everyday objects.

Ground TUI Interaction in Hand Movement. Object-to-function
mappings can be grounded in the structure of the user’s hand move-
ment rather than relying on specific object’s attributes to enable
more adaptive and convenient interaction. In our system, digital
functions are inferred from how the hand moves with or on the
object, such as translating or rotating. This suggests that oppor-
tunistic TUI systems should prioritize motion patterns that are easy
to recognize, repeat, and associate with control behavior, preserving
flexibility across diverse objects.
Compatibility with Ordinary Object Use. Opportunistic TUIs
should preserve the ordinary functions of everyday objects rather
than override them. The system need to avoid treating every touched
object as an input device, which would cause unintended activations
and interfere with normal use. Instead, objects should transition
smoothly between ordinary and TUI functions based on context
and intent, for example through a designated interaction area or
an explicit demonstration. This allows the same object to serve
as a virtual control when deliberately recruited, while remaining
available for its everyday purpose.
6.5
Limitations and Future Work
The generalized Summon model was evaluated with 16 participants,
so its performance across a broader range of users remains to be
established. Future work could expand the participant pool and
investigate few-shot adaptation methods to improve cross-user
generalization.
MidasTUI also relies on robust visual sensing of hand-object
interaction, making it sensitive to occlusion, viewpoint changes,
clutter, and object appearance. Move Together is especially weaker
on small objects such as rings, keys, and SD cards, which are often
heavily occluded by the hand. This suggests the current detector
works better when at least part of the object remains visible during
manipulation. Robustness could be improved through multimodal
sensing, stronger temporal reasoning, personalized adaptation, or
added cues such as hand pose or tactile signals.
Although our task set covers representative interface controls,
it does not capture the full diversity of real-world productivity
workflows. The current interaction vocabulary is limited to a small
set of modalities, such as sliding, rotation, and discrete pressing
or tapping, and does not reflect the richness of everyday object
manipulation. The supported digital controls are likewise narrow
compared with the range of functions in modern applications. Ex-
panding both the detectable interaction modalities and the sup-
ported digital controls would enable opportunistic TUIs to support
a broader range of productivity and creative tasks.
Our user study was designed as an exploratory evaluation of
how MidasTUI is experienced in a realistic compound task. We
therefore focused on participants’ perceived workload, usability,
control, and interaction preferences when interacting with Midas-
TUI and Mid-Air. The study involved 10 participants and a single
photo-collage task, so the observed trade-offs may not generalize to
all applications or longer-term use. Although participants generally
perceived MidasTUI as more precise and stable, these results were
interpreted as subjective assessments of control quality. In addition,
one- and two-handed interaction were not tested as independent
controlled conditions, so observations regarding bimanual inter-
action remain exploratory. Finally, participants used a fixed set
of everyday objects in a controlled tabletop environment. Future
work could extend this evaluation with more controlled studies
focused on precision-demanding tasks, broader task domains, and
longer-term use.
7
Conclusion
We presented MidasTUI, a demonstration-driven approach that
turns everyday objects into tangible controls for wearable displays.
Rather than relying on pre-authored mappings, the system infers
input behavior from how users manipulate objects. We achieve this
through two recognition models, Move Together for hand-object
engagement detection and Summon for input modality inference,
together with a TUI manager and a mapping layer that bind recog-
nized interactions to common controls.
Our evaluations demonstrate robust performance across diverse
everyday objects and previously unseen users. A comparative user
study further showed that MidasTUI reduced perceived physical
burden and improved usability and control relative to Mid-Air inter-
action, although it required longer task completion time. Together,
these results demonstrate the potential of everyday objects as in-
stant tangible interfaces for wearable displays, offering physical
grounding and opportunistic interaction without additional input
hardware. MidasTUI ultimately points toward a future in which
wearable devices turn the surrounding physical environment into
an interaction resource, with instant interface behavior emerging
from users’ familiar actions.

A.1
Research Transparency
A.1.1
Data and Code Availability. The training datasets for both
the Move Together classifier, which detects hand–object engage-
ment, and the Summon classifier, which infers input modality, are
available through the project’s OSF repository via this link. The
repository contains: (i) the hand-object engagement detection cap-
ture used to train the classifier, and (ii) the Summon capture used
to train the input-modality classifier, consisting of per-frame 3D
hand-joint sequences from 16 participants across 10 interaction
classes.
A.2
Model Architecture Details
A.2.1
Move Together Model. The Move Together classifier takes a
clip of 𝐾consecutive RGB frames and predicts a binary engagement
label. It consists of a spatial backbone and a temporal aggregation
head.
Spatial Backbone. We use FastViT-T8 [69], a hybrid vision trans-
former that interleaves RepMixer token-mixing blocks with convo-
lutional feed-forward layers. Each frame 𝐼𝑡∈R3×224×224 is indepen-
dently encoded to a 𝐷-dimensional feature vector via global average
pooling, where 𝐷= 384 (the native FastViT-T8 feature dimension).
The backbone is initialised with ImageNet-pretrained weights and
fine-tuned end-to-end. Total backbone parameters: 3.26M.
Temporal Heads. We evaluate four temporal aggregation heads
(Section 4.1). Here, 𝐷=384 denotes the backbone output dimension.
The 256-dimensional hidden representations are formed within the
heads; the BiLSTM and Transformer use input projections from 384
to 256 dimensions.
• Mean. Mean-pooling over the 𝐾frame features, followed
by a two-layer MLP (𝐷→256 →1) with ReLU and dropout.
Parameters: 0.19M (head only).
• TCN. Two 1-D causal convolutional layers (kernel size 3,
𝐷→256 →256) with BatchNorm, ReLU, and dropout, fol-
lowed by a linear classifier on the last timestep. Parameters:
0.26M.
• BiLSTM. A linear projection with LayerNorm and GELU
(𝐷→256), a 2-layer bidirectional LSTM (hidden dim 256,
output dim 512), and a per-frame linear classifier (512 →1)
with LayerNorm and dropout. Unlike the other heads, the
BiLSTM produces per-frame predictions; chunk-level output
is obtained by averaging. Parameters: 2.83M.
• Transformer. A linear projection (𝐷→256), learned posi-
tional encoding, and a 2-layer Transformer encoder (4 heads,
feed-forward dim 1024, GELU, pre-norm) followed by Layer-
Norm and a linear classifier on the last position. Parameters:
1.80M.
Hand-Guided Crop. Input frames are cropped around the hand
region using a binary hand segmentation mask from the last frame
in the clip. The crop is a square bounding box centred on the mask
centroid with 30% padding. During training, random jitter (±15% of
crop size) and scale perturbation (0.8–1.2×) are applied; at inference,
the crop is deterministic. The same crop parameters are shared
across all 𝐾frames in a clip for temporal consistency.
A.2.2
Summon Model. The Summon classifier takes a variable-
length sequence of 26-joint hand positions and predicts one of 10
input-device classes.
Input Representation. Each frame contains the (𝑥,𝑦,𝑧) world-
space coordinates of 26 tracked hand joints (78 dimensions). Frame-
to-frame velocity (78d) and acceleration (78d) are concatenated,
yielding s′
𝑡∈R234 per frame. The first and last 10% of each sequence
are trimmed to remove transition noise.
Architecture. We use a 1-D ResNet with the following structure:
• Stem: Conv1D (kernel 7, padding 3) →BatchNorm →ReLU.
Maps 234 input channels to 𝐶=64.
• Stage 0: 2 residual blocks at 𝐶=64. Each block: Conv1D(3)
→BN →ReLU →Dropout →Conv1D(3) →BN + skip
connection.
• Stages 1–3: Each stage doubles channels and halves tempo-
ral resolution via stride-2 convolution, followed by 2 residual
blocks. Channel progression: 64 →128 →256 →512.
• Pooling: Length-aware masked global average pool over
valid timesteps.
• Classifier: Dropout(0.4) →Linear(512 →10).
Total parameters: 4.74M.
A.3
Training Configuration
A.3.1
Move Together Training. Table 5 lists the training hyperpa-
rameters for the Move Together classifier. All four temporal heads
share the same backbone, optimiser, and learning rate schedule; they
differ only in batch size (16 for BiLSTM due to its higher memory
footprint, 32 for the rest) and warmup duration. We use mixed-
precision training (FP16) with gradient clipping at max norm 1.0.
Data augmentation is applied at the clip level: a hand-guided crop
with random jitter and scale perturbation ensures spatial consis-
tency across frames, while colour jitter and horizontal flips are
sampled once per clip and applied uniformly to all 𝐾frames for tem-
poral coherence. Early stopping on validation F1 with patience 10
prevents overfitting, as AUROC degrades after epoch 10–15 despite
stable F1.
A.3.2
Summon Training. Table 6 lists the training hyperparame-
ters for the Summon classifier. The model is trained with a higher
learning rate (10−3 vs. 10−4 for Move Together) since the ResNet1D
head has no pretrained backbone. Label smoothing (0.1) and Mixup
(𝛼=0.2) are applied to regularise against the small per-class sample
size (∼84 training sequences per class in LOPO). Temporal augmen-
tation includes random cropping (up to 30% of frames removed),
Gaussian noise injection on joint coordinates, scale jitter, and time
reversal. The first and last 10% of each sequence are trimmed before
feature extraction to remove transition artefacts at the start and
end of demonstrations. Early stopping on validation accuracy with
patience 100 accommodates the slower convergence of the 1-D
ResNet on variable-length sequences.
