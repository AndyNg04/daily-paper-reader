## 摘要
个性化大语言模型智能体依赖智能体框架——即外围的记忆与控制代码——将用户历史信息与下游决策联系起来。现有方法通常采用两种方案之一：为所有用户使用单一共享记忆工作流，这种方案部署高效，但无法根据不同用户历史调整证据的检索与解读方式；或者针对每位用户优化框架，这种方案能够定制用户行为，但在部署时需要反复进行成本高昂的候选评估，而且原始日志提供的监督信号稀疏且噪声较多。为解决这一权衡，我们提出 HyperHarness，这是一种学习共享的“历史到框架”生成器的框架，可直接根据用户历史合成可执行的个性化检索代码和答案引导代码。给定用户获准使用的历史信息，HyperHarness 会提示一个构建型大语言模型编写个性化检索与引导函数；同时，训练用户的下游任务得分用于迭代改进共享生成器，无需参考框架，也无需更新回答模型。在部署时，冻结的生成器仅凭历史信息，即可通过单次处理为每位未见过的用户构建框架，从而免去针对每位用户进行基于任务得分的搜索。在三个基准（PersonaMemv3、Mem-PAL 和 MemoryCD）及三种回答模型（Qwen3.5-9B、Qwen3.8-27B 和 GPT-5.6-Luna）上，HyperHarness 在九种设置中的七种取得最高综合得分，在其余两种中排名第二；与最强基线相比，得分最高提升 5.95 分，同时相较于长上下文提示，将匹配设置下的回答阶段 token 数减少 90.32%。分析表明，优化能够针对每种执行器调整上下文分配，迁移至未见过的用户群组，并摊销适配成本。

## Abstract
Personalized LLM agents rely on an agent harness, the surrounding memory and control code, to connect user history with downstream decisions. Existing methods typically employ either a single shared memory workflow across all users, which is efficient to deploy but cannot adapt how evidence is retrieved and interpreted across diverse histories, or per-user harness optimization, which customizes behavior for each user but requires costly repeated candidate evaluation at deployment and suffers from sparse, noisy supervision in raw logs. To address this trade-off, we present HyperHarness, a framework that learns a shared history-to-harness generator to synthesize executable, user-specific retrieval and answer-guidance code directly from user histories. Given a user's permitted history, HyperHarness prompts a construction LLM to write personalized retrieval and guidance functions, while downstream task scores across training users supervise iterative refinements to the shared generator without reference harnesses or answering-model updates. At deployment, the frozen generator constructs a harness for each unseen user in a single pass from history alone, eliminating per-user task-scored search. Across three benchmarks (PersonaMemv3, Mem-PAL, and MemoryCD) and three answering models (Qwen3.5-9B, Qwen3.8-27B, and GPT-5.6-Luna), HyperHarness achieves the highest aggregate score in seven of nine settings and ranks second in the remaining two, improving over the strongest baselines by up to 5.95 points while cutting matched answer-time tokens by 90.32% over long-context prompting. Analyses show that optimization tailors context allocation to each executor, transfers to unseen user clusters, and amortizes adaptation costs.

## 1. 核心问题与研究动机

- **研究问题**：能否仅凭新用户获准使用的历史记录，为其生成一套个性化的记忆检索与作答规则，而不必在部署时反复测试候选方案？
- **现有方法的取舍**：长上下文、固定 top-k 检索和滚动摘要便于部署，但给所有用户套用同一流程，难以区分长期偏好、短期意图和偶然浏览。逐用户优化可以调整执行流程，却需要为每位用户反复生成、运行和评估候选方案；新用户的原始日志也不直接说明哪套规则最有效。
- **论文的核心转变**：将优化对象从“某个用户的框架”改为“跨用户共享的框架生成器”。个性化的产物不只是用户画像或提示词，而是**可执行的决策规则**：何时查历史、查什么、保留哪些证据，以及何时应避免使用个人信息。

## 2. 方法论：跨用户优化，按用户生成代码

- **构建个人框架**：共享生成器先将许可范围内的历史整理成结构化证据，再由冻结的构建模型 `gpt-6-sol` 编写用户状态和个性化函数。生成代码可决定是否触发检索、如何构造查询、检索多深、过滤哪些记录，以及如何根据证据生成作答引导。
- **分离检索与引导**：对每个请求，`recall` 从当时许可访问的记忆库中选择证据，`apply` 决定如何解释和使用这些证据；冻结的作答模型根据请求、证据和引导回答。例如，检索可以找到用户浏览过的内容，而引导可以提醒模型不要把浏览直接当成喜欢。运行时不增加中间决策模型调用，也不事后改写答案。
- **训练共享生成器**：优化目标是训练用户的下游得分，先按用户计算，再对用户等权平均。优化器读取现有生成器、生成的个人程序、任务得分和执行轨迹，提出对历史预处理、构建提示或共享运行逻辑的修改。候选版本为同一评估面板重新生成框架，通常只有均分提高才替换当前版本。每次运行评估初始版本及最多十轮优化，**不需要参考框架，不更新构建模型或作答模型的权重**。
- **部署与执行边界**：新用户只经历一次框架构建流程，不使用其测试问题、参考答案或任务得分做搜索。“一次构建”不等于只调用一次模型：宿主可在预算内检查语法和试运行，并要求修复无效代码。构建完成后，个人代码在测试请求间保持固定；记忆库则可按任务协议纳入后来已获准访问的记录。宿主掌控数据边界、操作集合和预算，个人代码只能通过受限 Python 沙箱中的指定接口运行。

## 6. 主要结论与发现

- **总体成绩**：HyperHarness 在 **9 种设置中 7 项第一、2 项第二**。最大优势出现在 Qwen3.5-9B 的 PersonaMemv3 上（**54.51 对 48.56，领先 5.95 分**）；同模型在 Mem-PAL 上领先 **3.39 分**。两项第二均出现在 Qwen3.8-27B 上，分别落后 GEPA **0.31** 和 **0.04** 分。
- **词元效率**：在 MemoryCD 的匹配对比中，使用 Qwen3.5-9B 对 223 名用户的 2,676 个请求作答，平均词元量从长上下文的 **32,512 降至 3,147，减少 90.32%**，任务得分相当。这一数字不包含框架构建和共享训练；在另一个采用 200 条历史上限的扩展分析中，共享训练加逐用户构建的累计词元成本约在 **9–35 名用户**时低于逐用户优化基线，交叉点取决于基准、基线和成本口径。
- **有用的上下文取决于作答模型和任务**：优化后，九种设置中的七种缩短了模型输入。以 Qwen3.5-9B 的 PersonaMemv3 为例，相比初始生成器，得分提高 **7.96 分**，输入词元减少 **17.4%**。在 MemoryCD 的匹配查询上，即使检索历史相同，Qwen3.8-27B 和 GPT-5.6-Luna 也分别采用了更长和更短的作答引导。
- **跨用户泛化并不一致**：用户簇隔离后，HyperHarness 在 PersonaMemv3 和 Mem-PAL 上仍优于所比较的基线；在同时存在跨领域和用户群体变化的 MemoryCD 上，两种 Qwen 配置都落后于长上下文。对短历史的 Mem-PAL，无关文本替换比等量删除更有破坏性：在 50% 替换条件下，两者相差 **9.16 分**。

## 7. 优点

- **将适配成本前移**：用一组训练用户的任务反馈优化共享生成器，使新用户无需提供带答案的任务或承担逐用户搜索。无需修改作答模型权重，也可用于托管的黑盒模型。
- **个性化规则可检查**：与只生成静态画像相比，可执行代码还能表达按请求触发检索、区分正负反馈、在无关请求中不使用历史等规则。执行轨迹可以核查某个分支是否实际运行、哪次检索用完了预算。
- **不仅报告平均分，也分析行为与失败**：论文区分初始化与作答成本，并分析检索长度、引导长度、用户簇迁移和噪声。案例也披露了失败：尽管两名用户的总体推荐分数上升，图中展示的两个具体推荐列表在优化前后仍均为零分。

## 8. 不足与局限

- **应用范围有限**：验证集中在受限的检索与作答引导接口，不能外推到开放式、多工具或长期持续运行的智能体。代码固定、记忆可更新的设计也未验证偏好长期漂移后是否需要重建框架，以及何时重建。
- **收益归因和复现仍有不确定性**：优化器可同时修改多处组件，每次重新构建又会引入随机性，因而难以判断收益有多少来自用户专属代码、共享流程改进或采样差异。有限的优化轨迹、扰动样本和种子也限制了对稳定性的判断。
- **跨域、数据与评价偏差**：MemoryCD 的簇隔离结果说明，训练用户上有效的规则在分布变化后可能不如简单的长上下文。Mem-PAL 的机器翻译子集与 PersonaMemv3 部分依赖模型评审的设定，也不能完全代表真实用户的体验与偏好。
- **实际部署仍有额外约束**：成本优势取决于用户规模、每位用户的请求数和模型定价；小规模部署未必能摊薄先期优化。生成程序可读、可校验，不等于隐私已经得到保障。实际部署仍需处理历史授权、访问隔离、删除请求，以及个人信息被写入代码、用户状态或日志后的保留与清理。
