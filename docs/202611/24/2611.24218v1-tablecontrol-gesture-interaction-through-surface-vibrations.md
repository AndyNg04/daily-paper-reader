## 摘要
将手势感知集成到家具中，可以让用户通过熟悉的表面与数字应用和实体设备交互。我们介绍 TableControl，这是一种交互式演示系统，可通过表面振动实现连续手势识别，并在微控制器上运行完整的处理流程。系统使用四个隐藏的压电传感器，将信号采集与预处理、神经网络事件检测和手势分类相结合。系统识别出的敲击、向上滑动和向下滑动手势标签会传输至主机，而底层传感器信号不会被传输。访客可以通过动手操作体验两个示例应用：一款无尽跑酷游戏，以及一盏支持开关和亮度调节的实体台灯。仪表板会显示识别出的手势、类别概率和处理耗时。

## Abstract
Integrating gesture sensing into furniture offers a way to interact with digital applications and physical devices through familiar surfaces. We present TableControl, an interactive demonstration of continuous surface-vibration-based gesture recognition with the complete processing pipeline running on a microcontroller. Using four concealed piezoelectric sensors, the system combines signal acquisition and preprocessing with neural event detection and gesture classification. The resulting labels for knock, swipe-up, and swipe-down gestures are transmitted to a host computer without streaming the underlying sensor signals. Visitors explore two example applications through hands-on interaction: an endless runner game and a physical table lamp with on/off and brightness control. A dashboard displays recognized gestures, class probabilities, and processing times.

## 1. 核心问题与研究动机

- **研究问题**：能否在不改变桌面外观、也不要求用户佩戴设备的情况下，把普通桌面变成手势输入界面，并在微控制器上连续完成识别，而不是把原始振动信号传给主机处理？
- **研究背景**：敲击和滑动会在桌面产生可被隐藏式传感器捕获的机械振动。已有工作已证明可以从录制好的振动片段识别手势；TableControl 进一步处理连续信号中“何时发生了手势”和“发生了哪种手势”两个问题，并将识别结果接入实际应用。
- **论文定位**：这是一篇交互演示论文，主要贡献是**完整识别流程的端侧部署与应用集成**，而非提出新的手势识别基准或证明模型优于现有方法。

## 2. 方法论：从桌面振动到应用指令

- **采集与预处理**：桌面下方安装 4 个压电传感器，通过带 18 位模数转换器的采集板以每通道 1 kHz 采样。RP2350 微控制器使用两个各容纳 200 ms 数据的缓冲区交替采集与处理。各通道经过 225–375 Hz 的二阶 Butterworth IIR 带通滤波，滤波器状态跨数据块保留；滤波结果写入环形缓冲区，供后续两个识别阶段读取。
- **第一阶段——事件检测**：轻量神经网络每隔 100 ms 检查一个 100 ms 窗口，判断其中是否存在手势。若检测被接受，则以该窗口的中点作为估计事件时间。
- **第二阶段——手势分类**：系统等待环形缓冲区收齐事件前 50 ms、后 450 ms 的信号，再对这段 500 ms 数据逐通道做 Z-score 标准化，分类为敲击、上滑或下滑。等待分类期间不接受新的检测；分类器输出的最大类别概率可用于拒绝低置信度预测。
- **模型与应用接口**：两个网络均采用一维深度可分离卷积，检测器有 3 个卷积块、2,198 个可训练参数，分类器有 6 个卷积块、8,311 个参数。主机通过 USB 串口或 Wi-Fi 接收 JSON 消息，内容包括手势标签、类别概率、时间戳和处理耗时，**不包含原始振动信号**。主机负责游戏运行或台灯控制，不参与手势识别。

## 3. 实验设计：数据、评测基准与对比

- **数据与噪声条件**：训练和离线评估使用作者此前在单一实验室采集的数据集中的敲击、上滑和下滑子集。除干净数据外，作者将单独录制的音乐、交谈和播客所引起的传感器振动信号加到手势记录中，设置 20、10、5、0、−5、−10 dB 六档标称信噪比。检测器训练还加入了数量相同的背景负样本。

- **对比与演示**：论文讨论了 Smatable 等相关系统，但没有在同一数据和硬件条件下进行定量对比，也没有比较单阶段与两阶段方案。两项演示分别是无尽跑酷游戏和实体台灯控制：滑动用于跳跃、下蹲或调光，敲击用于启动教程、重置游戏或切换台灯开关。仪表板展示识别结果与耗时，但演示未报告量化用户研究。

## 4. 资源与算力

- **端侧推理**：使用 RP2350 微控制器和 TensorFlow Lite Micro，执行 32 位浮点推理。每个网络各测量 10 次推理，检测器平均耗时 **14.7 ms**，分类器平均耗时 **107.1 ms**。

## 5. 实验数量与充分性

- **实验规模**：可归纳为 1 个数据集上的 2 项离线识别任务、端侧计时，以及 2 个交互演示。数据包含 **19 种条件**（1 种干净条件，加上 3 类噪声各 6 档信噪比），这是数据条件的数量，不是 19 组独立的部署实验。论文未报告消融实验。
- **客观性与公平性**：按参与者划分训练集和测试集，比随机拆分同一批参与者的片段更适合衡量对未见用户的泛化。检测器评测所用的平衡样本条件与日常使用不同：真实连续信号中背景通常远多于手势，准确率无法直接说明误触发是否可接受。由于没有同条件基线，也无法判断该方案相对其他方法的性能优势。
- **证据充分性**：现有证据可以支持“完整流程可在微控制器上连续运行并驱动应用”这一可行性结论，但不足以证明系统适用于不同桌面和日常环境。仅报告平均性能，也难以判断哪些用户、手势或噪声条件最容易出错。

## 6. 主要结论与发现

- **端侧流程可行**：从采集、滤波到事件检测和手势分类均可在微控制器上执行。同一组手势能驱动数字游戏和实体台灯，主机无需接收原始振动流。
- **准确率是分阶段指标**：留一被试离线评估中，事件检测器和手势分类器的平均准确率分别为 **82.5%** 和 **85.7%**。这两个数字都不等于连续使用时一次手势被正确检测并执行的成功率。
- **交互延迟不只来自推理**：从估计事件时间到分类完成平均为 **598.2 ms**，包括缓冲和等待分类窗口收齐的时间，不包括传输、应用渲染或台灯响应。因此，约 0.6 秒并非用户实际感受到的完整响应时间，缩短推理时间也不是唯一的优化途径。

## 7. 优点

- **降低了交互界面的存在感**：传感器隐藏在桌面下方，既保留桌面外观，也不占用操作区域；用户无需佩戴设备或使用专用控制器。
- **计算分配符合连续感知的需求**：轻量检测器持续运行，较大的分类器仅在接受到候选事件后执行；双缓冲与环形缓冲区则让采集和计算得以交替推进，并保留跨数据块的信号历史。
- **展示了应用复用与诊断能力**：游戏和台灯共用同一套识别结果接口；仪表板让演示者看到类别概率与各阶段耗时，有助于区分识别错误和响应迟缓。

## 8. 不足与局限

- **场景覆盖有限**：训练数据来自单一实验室，叠加录制噪声也不能替代真实部署测试。不同桌面材质、厚度、传感器安装位置及桌上物品都可能改变振动传播，论文尚未验证这些变化下的表现。
- **误触发与漏检缺少连续评估**：摆放物体、日常敲碰和其他桌面活动可能被当成手势。文中未报告长时间运行的误触发率、连续手势漏检率，或调整置信度阈值后误触发与漏检之间的权衡。
- **快速交互受到限制**：分类窗口需等待事件之后的 450 ms 信号，且等待分类期间不接受额外检测。这一设计可能漏掉紧邻手势，也可能限制跑酷游戏中需要即时反应的操作。
- **扩展能力与优化收益仍未证实**：系统只演示了 3 种手势，不提供触点定位；没有通过基线和消融实验验证传感器数量、滤波频段、窗口长度或两阶段设计各自的贡献。更短的分类窗口和模型量化是作者提出的后续方向，而不是已验证的优化结果。
