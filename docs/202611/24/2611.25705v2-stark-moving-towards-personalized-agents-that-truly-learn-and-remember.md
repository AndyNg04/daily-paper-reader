## 摘要
长期记忆对于与用户长期交互的个性化智能体系统至关重要。然而，当前架构只能记录发生了什么，而将对事件缘由的推理留待底层 LLM 后续完成。但这些事件不仅能传达用户经历了什么，还能反映这些经历如何塑造其行为模式。我们提出 STARK，一种双图记忆架构，它不仅将事件视为节点，还将其视为连接行为洞见的边。STARK 维护一个情景图，用于记录在时间、因果和语义上相互关联的交互片段；同时维护一个洞见图，用于表示由 LLM 提取的行为信号，并根据支持这些信号的事件数量为其评分，再通过促成这些洞见的事件将它们连接起来。在推理阶段，系统直接从由“事件即边”结构提供依据的洞见节点中检索行为知识，从而避免重复遍历情景图。“事件即边”的结构还可自然地将知识图谱投影到关系嵌入空间，使系统能够在共享情境下实现跨用户迁移，并为冷启动用户推断缺失的洞见。评估结果显示，在 LongMemEval 信息抽取任务上，STARK 的评审得分较当前最优方法提高 1.48 分；在 LoCoMo 开放域问题任务上提高 0.93 分。在公开的 LongLaMP 摘要生成基准上，当图稀疏度为 5% 时，跨用户迁移使开放式任务的评审得分提高 0.7 分，ROUGE-L 提高 3 分。

## Abstract
Long-term memory is essential for personalized agentic systems that interact with users over long time periods, yet current architectures only capture what happened while leaving the reasoning of why it happened to be derived later by underlying LLMs. These events can, however, convey not only what a user experienced but also how that experience shaped their behavioral patterns. We introduce STARK, a dual-graph memory architecture which treats these events not just as nodes but also as edges between behavioral insights. STARK maintains an Episodic Graph which records interactions as temporally, causally, and semantically linked episodes; and an Insight Graph which represents LLM-extracted behavioral signals scored by how many events support them, connected by the very events that led to them. At inference, behavioral knowledge is retrieved directly from insight nodes grounded by event-as-edges, eliminating repeated episodic traversal. The event-as-edge structure also naturally enables projecting the knowledge graph into a relational embedding space where cross-user transfer becomes possible under shared contextual circumstances, allowing the system to infer missing insights for cold-start users. Evaluations show that STARK improves by 1.48 judge score on LongMemEval information extraction and 0.93 on LoCoMo open domain questions over state of the art. On the public LongLaMP abstract-generation benchmark, cross-user transfer improves open-ended judge scores by 0.7 points and ROUGE-L by 3 at 5% graph sparsity.

## 1. 核心问题与研究动机

- **记住发生过什么，不等于学会下次怎么做。** 现有智能体往往把历史对话存成文本、事实条目或事件图。遇到新任务时，模型仍需从旧记录重新推断用户的偏好、目标、约束，以及哪些策略曾奏效。这既增加查询开销，也可能让不同查询得出不一致的判断。
- **长期记忆需要同时支持事实回溯和经验复用。** 例如，谈判助手既要能查到某项合规约束何时提出，也要能在下一次谈判前提醒用户：在类似条件下，哪些方案曾被接受、哪些做法曾失败。
- **冷启动是另一个问题。** 新用户缺乏个人历史，但同一领域的用户可能面对相似约束、追求相似目标。STARK 尝试迁移这些共性，同时保留“用户自己的经验”和“从他人经验推断的建议”之间的区别。这里的“学习”主要指更新外部记忆及其证据，而不是持续微调底层大模型。

## 2. 方法论：双图记忆、证据评分与跨用户迁移

### 2.1 双图架构与“事件即边”

- **情节图（Episodic Graph）记录事实。** 节点包括用户、事件、里程碑和组织等，类型可按需扩展；带时间戳的时序、因果和行动关系支持按时间、实体或因果链检索。写入时区分“对话发生日期”和“事件实际发生日期”。
- **洞察图（Insight Graph）保存可复用的行为信号。** 偏好、价值观、目标和约束都是独立节点，可通过 `prefers`、`wants`、`avoids`、`learned` 等关系连接。系统在写入时提炼这些信号，不必在每次查询时都从对话中重新概括。
- **同一事件在两张图里承担不同角色。** 事件在情节图中是节点，其 ID 在洞察图中可作为边标签，表示“两条洞察之间的关系是在这次事件中观察到的”。检索到洞察后，系统可以沿边回查原始事件。这个结构提供的是**可追溯证据**，而非对用户动机的因果证明。

### 2.2 证据评分与检索流程

- **每条洞察维护四维证据向量** \((s,n,w,c)\)：\(n\) 是不同支持事件的数量；\(w\) 是已有明确结果的支持事件中的成功比例，无明确结果时取 0.5；\(s\) 随证据数量对数增长，且在 \(w\) 超过阈值时获得加成；\(c\) 随证据数量增加，但会因结果不一致受到惩罚。未完成或只有部分结果的事件计入 \(n\)，不计入 \(w\)。
- **LLM 提取证据，规则计算分数。** 写入经过两次顺序调用：先抽取事件，再提炼洞察并列出支持事件及其结果。聚合器确定性地更新分数。洞察排序使用 \(s\times c\times(0.5+w)\)，因此与失败相关的信号不会仅因 \(w=0\) 就被丢弃。
- **检索按意图分配预算。** 系统先提取查询实体并判断问题偏向行为、事实还是两者混合，再分别检索洞察与事件、补充事件出处，最后在 **4,000 token** 预算内组装上下文。矛盾信号可并存，按情境、证据和时效区分；若无足够依据判定，则呈现取舍。没有可靠结果信号的数据集不启用证据评分。

### 2.3 跨用户结构迁移

- **私有实体隔离，共享行为信号。** 用户专属实体加前缀，行为信号不加前缀，使不同用户能连接到同一信号节点。训练共享嵌入时，将大多只出现一次的事件 ID 边归并为 `surfaced` 关系；用户自己的图仍保留原始事件出处。
- **用 TransR 学习关系特定的表示。** TransR 先将头、尾实体投影到各关系的子空间，再用距离衡量三元组是否合理。这让同一信号在“偏好”和“曾出现”等关系下具有不同含义。
- **两条迁移路径互补。** 一是将用户已有的共享信号向量按关系加权聚合成“偏好指纹”，从最相似的用户处检索候选洞察；二是用链接预测直接补全缺失信号，适合个人历史更少的用户。迁移结果单独标注；在谈判试点中，它们作为可接受或忽略的建议呈现，而不是被自动当成用户偏好执行。

- **评价方式**：选择题和判断题采用精确匹配；开放式回答由 GPT-5.1 按 1–5 分评分；摘要生成另外报告 ROUGE 指标。生产试点在每个供应商区组内随机化三种条件的运行顺序，用关闭迁移的组分离迁移与个人记忆的贡献。

## 4. 资源与算力

- **未披露 GPU 型号、数量、显存或总 GPU 时长**，也未给出全部实验的 API 用量或总成本。因此，文中时延不能直接用于估算完整复现所需算力。

- **生产开销**：每段对话写入需要两次 LLM 调用，约 **6.2 秒、4.3K token**；一次检索约组装 **74 个实体、3.8K token**，耗时 **710–770 毫秒**，跨用户迁移额外约 **90 毫秒**。这些检索数据不同于消融表中的端到端响应生成时延。

## 5. 实验数量与充分性

- **实验规模**：论文包含 **5 个公开基准的主对比**、**1 个三条件生产试点**、**6 个历史保留比例 × 6 种迁移设置**，以及在 5 个代表性任务上分别移除 TransR、洞察图、证据评分、情节图或整个图结构的消融。附录还比较了共享实体策略和 4 种关系嵌入模型，并提供图增长和检索案例。
- **公平性较强的部分**：记忆系统统一骨干模型和检索预算；LongLaMP 按作者划分训练和测试；闭合题有不依赖模型裁判的评价；生产试验加入关闭迁移的中间组，而非只比较“有记忆”和“无记忆”。
- **证据仍有边界**：实验足以说明双图各司其职，并在所测任务上带来收益，但公开基准大多只报告点估计，缺少多随机种子、置信区间和独立人工复评。全上下文组与检索组的输入截断规则不同，因此结果反映的是整套记忆方案相对直接输入历史的表现，不能把全部差距归因于双图结构。

## 6. 主要结论与发现

- **长期事实记忆提升明显，但并非所有任务都同样受益。** LongMemEval 信息抽取达到 **4.38/5**，较 MAGMA 高 **1.48 分**；LoCoMo 开放域问答达到 **4.08/5**，较 Zep 高 **0.93 分**。LongMemEval 的弃答仅为 **2.81 对 2.75**，说明检索到相关节点并不等于能判断证据是否足够作答。
- **消融支持两张图的分工。** 移除情节图后，LongMemEval 信息抽取从 **4.38 降至 2.60**；移除洞察图后，RealPref 开放题从 **4.19 降至 2.95**；只关闭证据评分时，后者降至 **3.70**。在不启用证据评分的 PAL-Bench 上，STARK 的 Top-2 指标为 **41.3%**，相较 MAGMA 的 **40.0%** 只有小幅提升。
- **迁移在个人历史极少时有帮助，但绝对质量仍有限。** LongLaMP 仅保留 **5%** 图操作时，TransR 组合方案相对不匹配组将开放式评分从 **1.3 提高到 2.0/5**，ROUGE-L 从 **12 提高到 15**。随机匹配也达到 **1.7/5**，说明部分增益来自领域共性，而不全是精准匹配；在这一设置下，仅用实体链接预测也达到 **2.0/5**，组合方案主要再提高了 ROUGE-L。
- **生产试点显示业务收益。** 相比关闭记忆，完整系统使谈判轮次减少 **18%**、周期缩短 **15%**（作者报告配对检验均 \(p<0.05\)），达到或超过谈判目标的比例增加 **9 个百分点**。关闭迁移后，轮次和周期的降幅分别约为 **11%** 和 **9%**；完整系统对新员工的改善更大。

## 7. 优点

- **把事实、行为判断和证据来源分开存储。** 洞察可以直接检索，又能回溯支撑事件；与只保存用户画像相比，更便于审核和纠错。
- **不强行合并冲突经验。** 不同情境下的相反偏好可以同时保留；未完成事件不按失败处理，失败经验也能继续作为约束或提醒被检索。
- **实验能区分组件贡献。** 事实、偏好和迁移任务分别对应不同组件，消融结果与设计预期基本一致。真实试点还包含关闭迁移的条件，使业务收益不只依赖离线评分来推断。

## 8. 不足与局限

- **有来源不代表推断正确。** 事件、因果关系和结果标签都可能由 LLM 误抽取；“方案被接受”也不等于“该方案导致了成功”。证据向量是启发式排序分数，论文未证明其中的置信度经过校准，或能稳定区分“证据多”与“推断可靠”。
- **跨用户泛化证据有限。** 公开迁移实验只覆盖学术摘要生成，生产验证只覆盖一个谈判场景，均依赖共享目标和情境。保留 5% 图操作不等于完全无历史；零历史用户如何获得可靠、个体化的表示，以及如何避免把领域惯例误当成个人偏好，缺乏充分量化验证。
- **隐私隔离不等于正式隐私保证。** 系统不跨用户传输原始对话和情节记录，但共享信号的名称、描述、嵌入和聚合指纹仍可能泄露信息。作者未给出成员推断风险上界；删除请求对共享嵌入的影响要到下一次全量重训才清除。
- **统计与规模证据仍需补充。** 生产试点只有 40 名经理，200 个供应商区组嵌套在经理之下；配对检验是否充分处理同一经理下结果的相关性并不清楚。作者也指出，固定容量的 TransR 在图变密时可能退化。观察到洞察节点增长趋缓和检索时延稳定，并不能证明更大规模下仍能维持同等质量与成本。
