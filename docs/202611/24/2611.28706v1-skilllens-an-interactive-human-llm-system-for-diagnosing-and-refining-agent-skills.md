## 摘要
大型语言模型（LLM）智能体日益依赖可复用技能，但要维护这些技能，开发者需要将修改与行为变化及任务结果联系起来。现有工作流程将证据分散在不同版本、评测用例和执行轨迹中。我们提出 SkillLens，这是一种用于诊断和改进智能体技能的人机交互系统。我们对五位开发者和研究人员开展的形成性研究发现，他们在确定故障优先级、重建用例级证据以及在多次修改中保留上下文方面面临挑战。SkillLens 将性能变化、用例状态迁移、技能差异、调用序列、执行轨迹和输出关联起来，形成可追溯的工作流程，同时确保模型生成的解释和改进方案均由人工审核。在一项包含 20 名参与者的组间用户研究中，我们发现，与基线方案相比，SkillLens 通过更易用、负担更小的工作流程，帮助开发者诊断和改进智能体技能。这些发现凸显了在技能迭代过程中关联版本比较、用例级证据与经人工审核的改进方案的价值。

## Abstract
LLM agents increasingly rely on reusable skills, yet maintaining them requires developers to connect revisions with changes in behavior and task outcomes. Existing workflows fragment evidence across versions, evaluation cases, and execution traces. We present SkillLens, an interactive human-LLM system for diagnosing and refining agent skills. A formative study with five developers and researchers identified challenges in prioritizing failures, reconstructing case-level evidence, and preserving context across revisions. SkillLens links performance changes, case transitions, skill diffs, invocation sequences, traces, and outputs in a recoverable workflow, while keeping model-generated explanations and refinements under human review. Through a between-subjects user study with 20 participants, we show that SkillLens supports developers in diagnosing and refining agent skills through a more usable and less demanding workflow than the baseline. These findings highlight the value of linking version comparisons, case-level evidence, and human-reviewed refinement across skill iterations.

# SkillLens：用于诊断和改进智能体技能的人机交互系统

> **核心判断：**SkillLens 的贡献不是自动找出最佳技能版本，而是把版本变化、用例证据、人工判断和后续验证串成一条可追溯的工作流。用户研究较有力地支持了部分主观负担的下降，但没有证明它能产出更好的最终技能版本。

## 1. 核心问题与研究动机

- **研究对象是可复用的智能体技能（Skill）**，即智能体可按需调用的一组持久化指令、脚本、示例和支持资源。一项技能修改不仅可能改变最终答案，还可能影响技能是否被选中、调用顺序以及中间工具操作。因此，修好一个用例也可能让原本正确的用例退化。
- **难点不只是修改技能，而是判断该改什么、为什么改，以及改完是否值得保留。** 总体准确率只能显示净变化，可能掩盖同时出现的改善和退化；版本差异、路由记录、执行轨迹和输出又往往分散在不同工具中。通用 LLM 可以总结日志，但开发者仍要反复提供上下文，并回到原始记录核实解释。
- 作者访谈了 **5 名有技能开发或维护经验的开发者和研究人员**，归纳出三类困难：① 将错误与相关技能联系起来并确定排查优先级；② 还原单个用例中从技能改动到执行行为与输出的证据；③ 跨多轮修订保留上下文，判断该保留、继续修订还是回滚。

## 2. 方法论：从版本比较到人工授权复测

SkillLens 是一个交互式诊断工作台，而非新的技能优化算法。四个视图共享比较上下文，让开发者逐步缩小排查范围，同时保留证据来源和此前的判断。

| 视图 | 核心机制 |
|---|---|
| **Performance：性能对比** | 区分 **Base**（比较基准）、**Target**（正在检查的运行）和 **Work-on**（实际要修改的版本），避免查看历史结果时误改旧版本。对比前检查基准、用例范围和评估设置是否兼容，并展示“正确→错误”“错误→正确”“持续正确”“持续错误”及未评分用例。 |
| **Summary：模式归纳** | 按单个技能或日志中实际记录的**连续、有序调用序列**聚合用例。LLM 根据技能差异、调用、轨迹和输出提出错误或改善类别；连线粗细表示关联用例数，**不表示调用顺序或因果强度**。 |
| **Context：用例取证** | 并排展示同一用例在两个版本中的评估结果、输出、技能差异和执行轨迹。区分**触发证据**（技能是否被路由选中或进入上下文）和**执行证据**（是否实际调用、调用顺序及后续工具操作），并标明证据是原始记录、由日志重建、模型建议，还是不可用。 |
| **Refinement：修订与验证** | 开发者确认、修改或拒绝模型提出的分类和解释，形成可检验的假设，再审查并编辑候选技能差异。复测可选 **Sample Run**（抽样）、**Full Run**（全量）或 **Multiple Runs**（匹配条件下重复执行）；之后依据改善、退化与证据覆盖范围决定接受、拒绝或重新审视假设。 |

- **评估口径：**准确率的分母仅包含有明确正确性标签的用例，并单独报告评分覆盖率。未评分不能被当作正确或错误；不同历史版本的运行，也不能当作同一版本的统计重复。
- **实现与分工：**前端使用 React 和 TypeScript，后端使用 FastAPI；稳定标识符关联版本、用例和证据，人工分类与决策以仅追加的方式保存。LLM 负责提出可编辑的解释和修订建议，人负责核验、授权及决策。即使修改后结果改善，也不能仅凭一次复测认定原先的解释成立。

## 3. 实验设计：数据、基准与对照

- **基准与场景：**使用检索增强问答基准 **FRAMES**，其完整数据集含 824 道多跳问题，每题需要整合 2–15 篇维基百科文章的信息。实验选用其中**固定的 100 个用例**，以及**一个网页搜索技能族的 v1–v8 历史版本**，考查检索、阅读、信息整合和答案核验过程中的技能维护。
- **对照条件：**20 名参与者按性别和经验背景分层后随机分配，每组 10 人。SkillLens 组使用联动视图和集成修订流程；基线组使用扁平表格、原始记录和预配置的聊天式工具链。**基线并非无 LLM 对照**，比较的是两套完整工作流，而非是否使用模型。
- **任务流程：**参与者先接受约 15 分钟的教程与练习，再在 **40 分钟**内自主选择版本区间和排查目标，提交可追溯的证据与备选解释，实施技能修改、完成多轮执行，并说明应保留、继续修订还是回滚。仅提交复测计划不算完成。
- **评价指标：**分别记录完成率、完成者用时、两名编码者独立评定的证据质量（0–2 分），以及参与者如何使用复测结果做决策；另收集 SUS 可用性、改编的 NASA-TLX 工作负担和任务信心评分。NASA-TLX 六个维度的检验使用 Holm 校正。

## 5. 实验数量、充分性与公平性

- **规模：**论文包含 **1 项 5 人形成性访谈**和 **1 项 20 人、两个条件的组间对照研究**。后者仅覆盖一个基准子集、一个技能族和一个正式场景。历史版本与参与者的多轮执行是任务材料和过程记录，不等同于多个独立的跨数据集实验。
- **公平性：**两组共享初始材料、任务要求、时限和研究人员支持；分层随机分配有助于平衡背景，用共同提交表单评分也避免了按界面字段数量给分。参与者自行选题更接近真实维护，但不同人选择的版本区间和修改目标难度可能不同；各自修改后的运行自然也不产生完全相同的证据。
- **充分性：**实验适合初步检验完整工作流是否可用、是否减轻负担，但**没有跨技能族验证、长期部署或组件消融**，无法判断联动视图、LLM 摘要和结构化复测各自贡献了多少。完成率、用时和证据质量主要作描述性分析，不宜将组间趋势解读为已证实的优势。

## 6. 主要结论与发现

- **主观负担：**经 Holm 校正，SkillLens 组报告的心理需求更低（2.60 vs. 4.10，调整后 *p* = .023）、时间压力更低（3.20 vs. 4.90，*p* = .048），自评任务表现更高（5.90 vs. 4.20，*p* = .004）。身体需求、努力程度和挫败感未见统计显著差异。
- **复测如何影响决策：**记录显示，SkillLens 用户会在保留修改前检查触发修订的用例之外是否也出现改善或退化；部分基线用户则依据一个或少数用例的改善保留了修改，即使更广泛的错误模式仍未解决。这是对**决策依据范围**的观察，不代表 SkillLens 产出的最终技能更好。
- **信心并不等同于质量：**对“假设得到证据支持”给出高信心评分的参与者，SkillLens 组为 7/10，基线组为 0/10；但 SkillLens 组对维护决策与后续计划有高信心的仍仅 4/10。更容易找到证据，并不意味着下一步该怎么做就变得明确。

## 7. 优点

- **把总分变化落实到可核验的用例。** 同时呈现改善和退化，并将其连接到技能差异、调用顺序与原始执行记录，比单看准确率或听取模型摘要更便于发现回归。
- **把观察、解释和行动分开。** 技能与错误同时出现只是关联；模型解释需要人工确认；确认后的假设还需经过限定范围的测试。历史判断、提案与复测结果可回看，有利于后续质疑和修正。
- **维护任务较完整。** 对照实验要求参与者实际编辑技能、执行复测并作出维护决策，而不只评价界面或提交计划。系统也明确区分了“修好当前用例”和“改善整个技能族的泛化表现”。

## 8. 不足与局限

- **覆盖和统计精度有限。** 每组仅 10 人，两组各有 8 名男性、2 名女性；单一网页搜索技能族与 40 分钟实验难以代表编码、数据分析、多模态任务或长期团队维护。
- **存在可比性和测量限制。** 自主选题带来任务难度差异；时间统计排除未完成人员，不能直接外推为所有用户的效率收益。证据评分只有三级，两组中位数均已达满分，难以区分较细的质量差异；主观信心也不能代替客观正确性。
- **无法判断收益来自哪个组件，也未验证最终质量。** 实验没有拆分视图联动、模型建议和复测管理的作用，也没有提供足够的跨任务或留出用例结果来证明修订后的技能更准确、更稳健或更易泛化。
- **依赖完整且可比的运行记录。** 如果缺少技能快照、路由记录、执行日志或可靠评分，系统可以标明证据缺失，但不能补回事实。即使有匹配条件下的重复运行，也主要用于观察结果是否稳定，不能自动排除其他原因。
