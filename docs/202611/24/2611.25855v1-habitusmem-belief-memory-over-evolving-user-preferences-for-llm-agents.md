## 摘要
个性化大语言模型智能体必须依据用户当前的偏好采取行动，而这些偏好会随着交互不断变化，且用户很少会完整陈述。现有记忆系统会存储并检索交互历史中的内容，却将判断哪些偏好仍然有效、适用于何种情境的任务留给智能体。此类内容无法表明某项偏好是否仍然有效或适用于何处，因此智能体常常会依据过时或不适用的偏好采取行动。我们转而将记忆视为助手对用户的信念。依据布迪厄关于惯习的论述——惯习是持久但可修正的倾向——我们将用户建模为一个潜在偏好状态，每次交互（包括当前请求）既揭示该状态，也对其加以更新。信念概括了历史记录对这一状态所提供的支持；记忆则由与智能体当前决策相关的各项信念构成，每项信念均附有相应证据、适用范围和状态。我们基于这一理念实现了 HabitusMem：一种经过训练的写入器，可将这些信念表述为文本记录，供参数冻结的智能体使用。在两类智能体上，HabitusMem 在 PersonaMem-v2 和 VitaBench 2.0 两个基准测试中的表现均优于其他记忆系统。受控分析表明，学会根据请求进行条件化是回答效果提升的主要原因，而辅助训练任务则能改善工具使用能力。

## Abstract
Personalized LLM agents must act on a user's current preferences, which change across interactions and are rarely stated in full. Existing memory systems store and retrieve content from the interaction history and leave the agent to work out which preferences still hold and where they apply. Such content does not indicate whether a preference is still current or where it applies, so agents often act on outdated or misapplied preferences. We instead treat memory as the assistant's belief about the user. Following Bourdieu's account of habitus as durable but revisable dispositions, we model the user as a latent preference state that every interaction, including the current request, both reveals and updates. The belief summarizes what the history supports about this state, and memory consists of the individual beliefs that bear on the agent's current decision, each with its evidence, scope, and status. We implement this view in HabitusMem, a trained writer that states these beliefs as text records for a frozen agent. Across two agent families, HabitusMem achieves the best results among memory systems on both PersonaMem-v2 and VitaBench 2.0. Controlled analyses show that learned request conditioning drives the answering gain, while auxiliary training tasks improve tool use.

# HabitusMem：面向演变中用户偏好的信念记忆

**一句话概括：** HabitusMem 不直接把历史片段交给智能体，而是先判断“用户现在可能想要什么、依据是什么、在哪些情境下适用”，再把与当前决策有关的判断写成短记录。它在两种智能体上均取得了所比较紧凑记忆系统中最高的问答准确率和平均工具执行奖励，但没有在所有指标上胜出。

## 1. 核心问题与研究动机

- **个性化的难点不是记住过去，而是判断过去何时仍然有效。** 用户很少在每次请求中重述偏好；同一项历史行为也可能反映长期习惯、一次性安排，或他人的需求。例如，给家人买过某种茶，不等于用户自己喜欢；用户要求“不再使用某偏好”，也不等于该偏好从未存在。
- **传统记忆将关键推断留给下游智能体。** 检索、摘要和事实抽取能告诉智能体用户说过什么、做过什么，却不一定说明证据有多强、偏好是否已被替代或撤回，以及它是否适用于当前任务。工具执行中，即使大方向正确，一个错误的规格、数量或地址也可能让任务失败。
- **论文的转变是从“表征历史”转向“表征助手对用户的判断”。** 作者借用布迪厄的“惯习”概念，将用户偏好视为由经验塑造、相对持久但仍可修正的倾向。当前请求有双重作用：它既可能揭示新情况，例如地址变更，也决定哪些已有偏好值得传给智能体。

## 2. 方法论：从交互历史生成面向决策的信念记录

### 理论框架

- **状态估计：** 将用户在时刻 \(t\) 的偏好、当前处境和约束视为潜在状态 \(z_t\)。概念上，助手先根据上一时刻的信念预测当前状态，再用新观察修正判断，形成基于历史的后验信念。
- **决策选择：** 理想记忆是在固定智能体和文本预算下，让其回答或行动的期望损失最低的消息。证据决定一项判断有多可信，请求决定这项判断是否影响当前行动。论文证明，在其他条件相同的情况下，能读取请求的编码器至少可以复现静态编码器，因此其**最优可达风险**不会更高；这不保证训练出来的写入器一定更好。
- **理论与实现的区别：** HabitusMem 不计算数值后验，不校准偏好置信度，也不通过运行智能体轨迹直接优化决策损失。实际方法是用参考记忆监督训练语言模型，让它生成定性的文本判断。

### 记录格式与推理流程

- 每条记录包含四个字段：**判断**（偏好、事实或约束）、**证据**（支持判断的交互）、**适用范围**（何时应采用）、**状态**（有效、已被替代或已撤回）。其中，“撤回”表示不应继续使用，并不必然表示原判断为假。
- 推理时，系统先按位置和预算截取原始日志：PersonaMem-v2 主要保留开头，VitaBench 2.0 保留开头和最近交互。随后，基于 **Qwen3.5-9B + 单个 LoRA 适配器**的写入器读取历史与当前请求，贪心生成记录，再交给参数冻结的智能体。工具任务的提示特别要求保留明确的历史选择和商品、规格、数量、地址、时间等履约细节。
- **部署时不维护递归更新的信念库。** 历史或请求变化时，写入器从截取后的原始日志重新生成；只有相同的“历史–请求”组合才能复用缓存。递归状态更新是训练任务，不是部署流程。

### 两阶段训练

- **第一阶段：** 先用 DeepSeek-V4-Flash 生成的 **1,598 条**记忆学习记录格式，再用 PersonaMem-v2 官方训练集的偏好标注，将与请求对应的记录放到静态记忆首位，训练出父写入器。
- **第二阶段：** 由冻结的父写入器和数据构建规则生成辅助监督，在同一个适配器上联合训练四项任务：**直接写入**（从历史和请求推断判断）、**状态更新**（根据新交互修订已有记录）、**请求投影**（筛选回答所需的判断）、**行动投影**（保留执行所需的精确参数）。默认混合包含 **40,766 行**，其中行动投影样本重复三次。训练最小化参考文本的逐词元负对数似然；目标构建检查格式，但不逐条核实事实。

## 3. 实验设计：基准、场景与对比方法

| 基准 | 数据与任务 | 评估指标 |
|---|---|---|
| **PersonaMem-v2** | 英文 32k 设置，官方测试集 **5,000 个查询**，覆盖知识、写作、邮件、翻译、社交等 **9 类场景**，包含偏好变化和遗忘请求 | 个性化多选问答准确率；外部 Qwen3.5-9B 裁判给出的开放生成分数 |
| **VitaBench 2.0** | **56 名用户、771 个子任务**，覆盖配送、到店消费和在线旅行等工具任务；每个子任务试验 **4 次** | 平均奖励（Avg@4）、至少一次成功（Pass@4）、四次全部成功（全成功率） |

- **下游智能体：** Qwen3.5-397B-A17B 和 DeepSeek-V4-Flash-0731，均不随记忆方法微调。VitaBench 使用外部 Qwen3.5-9B 模拟用户并按任务量规评定执行轨迹。
- **对照方法：** 五种紧凑记忆系统——RAG、Rewrite、Mem0、A-MEM、MemListener；另有无记忆和直接提供完整历史两种参照。VitaBench 还加入由人工标注偏好构建的**真值画像**，这是带额外信息的参照，不是普通记忆基线。
- **跨基准评估：** 写入器在 PersonaMem-v2 官方训练集上训练，两项基准使用同一个适配器。VitaBench 结果因此提供了从个性化问答训练迁移到工具使用的证据。

## 4. 资源与算力

- **训练：** 论文报告四任务联合训练阶段耗费 **76.3 GPU 小时**。父写入器训练 1 个 epoch，最终四任务训练也为 1 个 epoch；两阶段的有效批大小均为 8，序列截断长度为 12,288 token。
- **推理：** PersonaMem-v2 上评估 5,000 个不同请求，写入器在单张 GPU 上用时约 **24 小时**。每次读取的中位长度为 **7,125 token**，生成中位长度为 **443 token**。
- **压缩收益及其代价：** 下游智能体收到的记忆中位长度为 **515 token**，相比完整历史的 **31,855 token**，下游历史输入缩短约 **61.9 倍**。这不等同于端到端算力降低 61.9 倍，因为新请求仍需额外运行写入器。
- **未明确披露：** 给定文本未说明 GPU 具体型号、训练并行所用卡数、各训练阶段的墙钟时间，也未提供包括教师生成和下游智能体评估在内的总算力。

## 5. 实验数量、充分性与公平性

- **主实验：** 两项基准 × 两种智能体，共 **4 个基准–智能体组合**。问答每个组合比较 8 种条件，工具使用每个组合比较 9 种条件（额外包含真值画像）。
- **组件与诊断实验：** 问答部分另有 **2 种请求干预、5 种移除组件或字段的训练条件、5 种训练谱系对照和 2 种匹配对照**。工具部分复测训练谱系和匹配对照，但未逐项复测留一消融。附录还比较了 **3 种训练配比**、多种输入输出预算与提示设置，并对每个被测写入器构造 **90 个受控探针**，另给出两个案例。
- **较有说服力的设计：** 使用官方测试划分；工具实验统一执行指令与四次试验协议；直接写入对照匹配了优化步数；统计分析使用配对 McNemar 检验或按任务簇配对 bootstrap。这些设置有助于区分请求内容、训练任务和记录格式的作用。
- **证据边界：** 实验足以支持“在所测条件下是有竞争力的紧凑记忆”，但不足以证明普遍最优。每个写入器只训练一次，没有覆盖训练种子方差；按相同 epoch 比较的留一消融会因样本数减少而改变优化步数。部分工具结果来自归档运行，配对检验也只使用共同完成的子任务，因此不能把所有表格差值都视为稳健提升。各系统的端到端算力没有明确匹配。

## 6. 主要结论与发现

- **多选问答：紧凑记忆中最佳，但不及完整历史。** Qwen 和 DeepSeek 上的准确率分别为 **53.7% 和 48.4%**，比各自最强紧凑基线高 **4.8 和 4.6 个百分点**；完整历史则达到 **56.9% 和 52.7%**。开放生成方面，HabitusMem 的裁判分数为 **0.326 和 0.382**，高于完整历史的 **0.227 和 0.302**。
- **工具使用：平均奖励和重复成功更突出，但并非所有维度都最好。** 两个智能体的平均奖励为 **0.3291 和 0.3573**，均为紧凑记忆方法中最高；前者低于 Qwen 的完整历史，后者高于 DeepSeek 的完整历史。四次全成功率分别为 **13.10% 和 12.84%**，均为非特权条件中最高，但 Qwen 对完整历史的领先仅 **0.13 个百分点**。至少一次成功率也并非最佳，说明覆盖更多任务与稳定完成同一任务是两件不同的事。
- **回答增益主要来自学会利用当前请求。** 固定写入器后，删除请求或换成无关请求，会让准确率从 **53.7% / 48.4%** 降至约 **40% / 34%**；相比之下，仅给未适配写入器添加正确请求，提升很小。
- **辅助任务呈现取舍，而非全面增益。** 相比匹配优化步数的纯直接写入，四任务混合在两种智能体上分别提高配对工具平均奖励 **3.3 和 4.5 个百分点**；但纯直接写入的问答准确率和生成分数反而更高。工具侧没有逐项留一实验，不能把提升归功于某一个辅助任务。
- **结构化字段有助于回答，但不保证智能体遵守。** 完整格式相对纯文本对照提高了问答和生成表现。受控探针中，写入器在 10 个撤回样例里均正确标记撤回，但两个智能体仅分别答对 **1 个和 2 个**，表明“记录正确”与“使用正确”之间仍有明显差距。

## 7. 优点

- **把三个容易混淆的问题分开：** 某项偏好是否有证据、是否仍然有效、是否适用于当前决策。四字段设计让错误更容易追溯到证据缺失、范围误判或状态误用。
- **把记忆质量与实际决策联系起来：** 不只评价信息能否被复述，还检验品牌、规格和地址等细节能否支撑真实式的多步执行，以及结果能否跨试验复现。
- **模块化且便于替换：** 文本接口不要求微调下游智能体；同一个写入器在两种模型家族和两项基准上使用。
- **诊断能区分写入器与使用者的问题：** 附录既检查生成记录，也检查智能体是否据此做对决策，并明确指出送礼探针的答案键存在歧义，没有把所有错误归因于写入器。

## 8. 不足与局限

- **历史选择依赖位置与预算。** 只看开头或头尾可能漏掉中段的重要修订。缩短输入预算显著降低准确率；新请求又需要重读和重写，因此下游上下文虽短，在线延迟与长期成本仍需评估。
- **证据可读，不等于事实可靠。** 教师目标只做格式检查，不逐条验证事实；证据字段也不是经校准的置信度。错误归纳、证据遗漏或引用不准确都可能传给下游。
- **撤回标记不等于隐私删除。** 原始日志仍被保留，案例中的记录甚至会重述已撤回内容，以帮助智能体识别其改写形式。这能服务某些“不再使用”任务，但不能证明系统满足真正的数据删除要求；工具执行中也不应把未经确认的推断视为可靠授权。
- **评估存在模型和量规偏差。** 开放生成评分、用户模拟和部分轨迹评估依赖模型。送礼探针保留了用户此前明确表达的兴趣，标准答案却排除相关建议，因此该探针不能单独衡量礼物归属识别能力。
- **应用外推有限。** 仅测试两种智能体和两项基准，尚未验证真实长期使用中的邮件代写、推荐、日程安排等应用。工具任务的绝对全成功率仍约 **13%**，当前证据更支持把它视为改善偏好传递的模块，而不是可靠的自主执行保障。
