Abstract 

Multi-agent systems often rely on predefined collaboration structures, limiting their ability to adapt to diverse task requirements. We in-troduce DynaFlow , a framework that integrates free-form executable workflow synthesis into the action space of the main agent. The agent decides when collaboration is needed and gen-erates task-specific programs that coordinate sub-agents through sequential or parallel exe-cution, structured information exchange, and verification. Execution results and traces in-form subsequent actions, enabling the agent to adapt collaboration as reasoning progresses. We train only the main agent through super-vised fine-tuning on distilled trajectories, fol-lowed by refinement on examples filtered for unsupported premises, biased verification, and information-flow defects. All sub-agents re-main fixed, separating orchestration learning from executor capability improvement. Across six benchmarks spanning mathematical reason-ing, scientific question answering, and multi-hop retrieval, DynaFlow achieves 88.08% over-all accuracy in Forced mode, outperforming the strongest evaluated baseline by 10.90 percent-age points with the same Qwen3.5-27B back-bone. Workflow analysis finds more explicit use, verification, and refinement of upstream outputs after training, highlighting cross-stage information flow as a key dimension of multi-agent orchestration.

MAS-Orchestra formulates orchestration through function calls, yet generates the complete coordi-nation structure in a single decision without ob-serving intermediate execution results (Ke et al., 2026). These limitations motivate combining free-form workflow synthesis with repeated orchestra-tion decisions informed by execution feedback. We therefore investigate executable workflow synthesis as a native action of the task-solving agent, along-side ordinary tool use. The same agent decides (i) when to collaborate, (ii) constructs task-specific programs, and (iii) uses their returned outputs and traces to determine how to proceed. To this end, we introduce DynaFlow (Figure 2), a framework that integrates free-form executable workflow synthesis into the task-solving agent’s action space. We refer to this agent as the main agent , which coordinates sub-agents responsible for executing delegated subtasks. The Main Agent can answer directly, use ordinary tools, or generate a task-specific workflow program. Through a mini-mal execution interface, it defines sub-agent respon-sibilities, sequential or parallel dependencies, and how intermediate outputs are passed, aggregated, and verified directly in code. A budget-constrained runtime executes the program and returns its out-puts and execution trace. The Main Agent then uses this feedback to guide subsequent actions, includ-ing synthesizing follow-up workflows that adapt collaboration to the observed results. We decouple orchestration learning from sub-agent training by updating only the Main Agent on distilled workflow demonstrations while keep-ing all sub-agents fixed. This focuses learning on coordinating existing capabilities and allows pre-trained models to be reused as executors without retraining. The training process begins with dis-tilled workflow demonstrations. Since answer cor-rectness alone does not guarantee reliable coordina-tion, we then refine the policy on a curated subset that excludes demonstrations flagged for unsup-ported premises, biased verification, or incomplete information transfer. This training process makes orchestration quality an explicit criterion for se-lecting demonstrations, guiding the Main Agent toward more reliable task coordination and infor-mation use. Across six benchmarks spanning mathematical reasoning, scientific question answering, and multi-hop retrieval, DynaFlow achieves 88.08% overall accuracy in Forced mode, exceeding the strongest evaluated baseline using the same backbone by 10.90 percentage points. In Dynamic mode, it maintains accuracy close to Forced execution while answering 47.1% of questions without invoking a workflow. Further analysis finds that training leads to more explicit use, verification, and refinement of upstream outputs. Together, these results sup-port learning both how to organize collaboration and when to invoke it, and identify cross-stage information use as a key dimension of effective orchestration. 

2 Related Work 

Agentic Workflows and Orchestration. A work-flow specifies model and tool calls through in-structions, control flow, and information depen-dencies. Control flow determines execution order and branching, while data flow specifies which in-termediate outputs later calls receive. Orchestra-2tion organizes these calls to solve a task. AutoGen provides programmable agent interactions, while Magentic-One and Apodex 1.1 support runtime coordination and replanning (Wu et al., 2024; Four-ney et al., 2024; Apodex Team, 2026b). Graph-and code-based representations support automated workflow design (Zhuge et al., 2024; Zhang et al., 2025c), and executable code can express tool-use actions and orchestration logic (Wang et al., 2024; O’Connor, 2026). These advances provide expressive mechanisms for collaboration, while verification-centered systems emphasize checking intermediate decisions and their supporting evi-dence (Apodex Team, 2026a; MiroMind Team, 2026). We therefore focus on learning when to invoke collaboration and how to construct task-specific workflows that preserve, check, and reuse intermediate results. We further examine how train-ing changes workflow patterns, focusing on stage dependencies and the use, verification, and refine-ment of intermediate results. Comparing these changes alongside design quality and task accu-racy helps characterize the properties of effective orchestration and their relationship to improved performance (Figures 5 and 4; §5.3). 

Learning Task-Specific Orchestration. Task-specific orchestration raises two related questions: how to learn workflow generation and how to adapt designs using execution feedback, a mecha-nism also studied in agent–environment interaction and strategy-guided exploration (MiroMind Team, 2025; Li et al., 2026c). MAS-GPT learns query-specific system generation through supervised train-ing, while FlowReasoner and Mas-Orchestra use reinforcement learning (Ye et al., 2025; Gao et al., 2025; Ke et al., 2026). MAS-Zero revises system designs using intermediate results, and DyFlow plans successive subgraphs using feedback (Ke et al., 2025; Wang et al., 2025b). FlowSteer learns graph-editing policies from canvas feedback (Zhang et al., 2026a). MetaAgent-X further jointly trains designers and executors (Zhang et al., 2026c). DynaFlow integrates free-form executable work-flow actions into the task-solving policy, coupling collaboration decisions with workflow construc-tion and subsequent decisions based on execution feedback. Its learning framework explicitly selects demonstrations for orchestration quality and trains only the Main Agent, emphasizing reliable infor-mation transfer and independent verification with fixed sub-agents. 

3 DynaFlow 

DynaFlow integrates free-form executable work-flow synthesis into the Main Agent’s action space. The Main Agent selects whether and how to col-laborate, while workflow outputs and execution traces inform subsequent decisions (Figure 2). We formalize this decision process before describing orchestration learning with fixed sub-agents. 

3.1 Free-Form Workflow Orchestration 

Given a question q and task instruction I, the Main Agent follows a policy πθ over three action forms:

The same policy therefore decides whether to answer, use a tool, or construct and invoke a workflow in light of the task and available feedback. We evaluate this policy under two execution modes. In Dynamic mode, the first decision se-lects between a direct answer and a workflow call; in Forced mode, the first substantive action must invoke a workflow. Forced execution evaluates workflow construction without the initial routing decision. Both modes allow subsequent tool calls and follow-up workflows. Once a workflow is in-voked, the Main Agent is restricted to coordination and summarization, with substantive problem solv-ing delegated to sub-agents. The program P defines sub-agent roles, stages, and dependencies through agent calls, parallel 

execution, and optional phase labels. Independent calls can run concurrently, while dependent calls receive upstream outputs explicitly. Each sub-agent receives only the instructions and inputs specified by P . 5.1 Overall Performance 

DynaFlow achieves the highest overall accuracy, reaching 88.08% in Forced mode and 87.94% in Dynamic mode (Table 1). Both exceed the strongest baseline by over 10 percentage points and outperform their Base counterparts, with only the Main Agent trained and all sub-agents fixed. 

Mathematical reasoning. DynaFlow achieves the strongest results across competition and multilin-gual mathematics. Forced execution solves all 90 AIME questions, achieving 100% across the 2024, 2025, and 2026 sets, while both modes exceed the strongest baseline on PolyMATH by 3–4 percent-age points. 5.2 Effect of Training and Execution Mode 

We examine how training affects workflow-based solving under matched execution settings (Table 2; Figure 3). Base, Forced underperforms Base, Di-rect on every benchmark except HotpotQA, where workflows enable retrieval. After Stage 1, Forced execution reaches or exceeds the Base, Direct ref-erence on all six benchmarks and surpasses Direct within the same checkpoint by 8.73 points overall, including retrieval gains on HotpotQA. We thus find that orchestration training turns workflow ac-cess into effective collaboration, yielding gains be-yond the trained Main Agent’s standalone perfor-mance. This pattern is consistent with prior find-ings that collaboration benefits depend on task char-acteristics and coordination structure (Kim et al., 2026). Stage 2 further improves both Forced and Dy-namic performance. Our workflow analysis finds higher design quality and more frequent use and re-finement of upstream results with fewer sub-agents on average than Stage 1 (Figures 4 and 5; §5.3), linking the performance gains to more focused co-ordination. 

5.3 Workflow Quality and Task-Specific Organization Connected stages and improved information use. 

Figure 5(a,c) shows that Base typically delegates to a single sub-agent or constructs calls without dependencies, whereas trained programs usually combine parallel and sequential stages. Hybrid workflows increase from 3.4% for Base to 83.2% after Stage 1 and 85.6% after Stage 2. The share of programs that pass upstream outputs and ex-plicitly instruct downstream agents to use them rises from 12.6% for Base to 93.3% after Stage 1 and 97.7% after Stage 2 (Figure 5(d)). Training thus improves information use in workflow design: the Main Agent increasingly specifies how inter-mediate results should inform subsequent solving and verification, enabling systematic reuse across stages. 

Higher-quality information flow and verifica-tion. Our analysis of Stage 1 errors identifies three recurring patterns: unsupported premises in-troduced by the Main Agent, verification guided to-ward an expected conclusion, and incomplete or in-correct transfer of intermediate information. These observations motivate selecting Stage 2 demonstra-tions that avoid premise injection, verification de-fects, and information-flow defects (§3.2). After training on the selected data, we find higher pro-portions of defect-free workflows across all four design criteria. Major information-flow defects decline from 1.9% in Stage 1 to 0.9% in Stage 2 (Figure 4), while workflows that specify correction or refinement of intermediate results increase from 28.1% to 35.9% (Figure 5(e)). 5.4 Adaptive Workflow Invocation 

The Dynamic–Forced accuracy gap narrows from 10.75 percentage points for Base to 1.02 after Stage 1 and 0.14 for DynaFlow (Table 2). With sub-agents fixed, this trend highlights the contribution of Main Agent training to selective collaboration. In Dynamic mode, DynaFlow answers 47.1% of questions directly while achieving 87.94% accu-racy, close to 88.08% under Forced execution. Av-eraged over all questions, including those answered directly, it uses 2.44 sub-agents per question versus approximately 4.16 under Forced execution, a re-duction of about 41% (Figure 1). These results sug-gest that a unified Main Agent policy can adapt its solution strategy to task requirements while main-taining performance with fewer sub-agents. We regard the choice between direct answering and workflow execution as an integral part of orchestra-tion: additional agents do not necessarily improve performance, and collaboration should be invoked according to the needs of each question. 

6 Discussion 

We view reliable information use alongside task de-composition as central to orchestration; gains with fixed sub-agents support learning to coordinate ex-isting capabilities (§5.2). Stage 2 gains accompany better information transfer and more frequent re-finement of intermediate results, consistent with screening for unsupported premises, constrained verification, and information-flow defects (§5.3). Our analysis of GPQA-Diamond failures illustrates how correct intermediate results can be lost or over-ridden during verification and final synthesis. Dy-naFlow workflows incorporate complementary ev-idence gathering, independent checks, and refine-ment of intermediate results. Future work could train sub-agents for reliable information transfer and independent verification, and extend first-turn supervision to multi-turn trajectories containing disagreements and erroneous results. Such super-vision could strengthen the Main Agent’s ability to independently assess conflicting outputs, iden-tify errors, and select actions for error recovery, workflow revision, and final-answer selection. 

7 Conclusion 

DynaFlow combines free-form executable work-flow actions with two-stage Main Agent training through trajectory distillation and demonstration se-lection based on orchestration quality, keeping sub-agents fixed. Across six benchmarks, it achieves 8the highest overall accuracy among evaluated meth-ods; Dynamic execution answers nearly half the questions directly with accuracy close to Forced execution. Workflow analysis characterizes how training changes structure and the use of intermedi-ate results.

11 A Experimental Setup Details 

Benchmarks. The evaluation contains 688 ques-tions: 30 from each of AIME 2024, 2025, and 2026; 200 from PolyMATH; 198 from GPQA-Diamond; and 200 from HotpotQA. PolyMATH and HotpotQA are sampled with seed 42. AIME requires integer answers, PolyMATH includes mul-tilingual mathematical questions with free-form an-swers, GPQA-Diamond uses multiple-choice scien-tific questions, and HotpotQA requires connecting evidence across retrieval steps. 

Models and baselines. The Agent uses Qwen3.5-27B, and all workflow sub-agents use its Base checkpoint without orchestration training. Both operate with thinking enabled; only the Agent re-ceives orchestration training. CoT, five-sample CoT-SC, Self-Refine, and AFlow use the same backbone. AFlow uses the released MATH work-flow on AIME and PolyMATH and the released HotpotQA workflow on HotpotQA and GPQA-Diamond. These workflows are transferred without an additional workflow search on the evaluation tasks. Base + Web search provides a comparison with direct retrieval access. 

B Workflow Runtime 

The Main Agent passes a JavaScript program to the Workflow tool. Programs define sub-agent in-structions and pass intermediate outputs through ordinary code. The interface provides agent for sub-agent calls, parallel for concurrent calls, 

pipeline for dependent stages over multiple items, and phase for stage labels. A sub-agent receives the instruction and inputs specified by the program; the Main Agent’s interaction history is not auto-matically inherited. Calls may request structured outputs through a JSON schema. Workflow com-pletion returns the program result together with execution information, which the Main Agent can use to revise the workflow or produce a final an-swer. During evaluation, Direct answers without tools, Dynamic selects between direct answering and workflow execution, and Forced requires work-flow invocation before substantive problem solving. The corresponding prompts are provided in Ap-pendix F. 

C Training Details 

GLM-5.3 Max provides the teacher trajectories. The Stage 1 training set contains 2,257 first-turn demonstrations from HotpotQA and BrowseComp. Supervision covers the first-turn reasoning and ac-tion; instructions, questions, and tool definitions are masked from the loss. Only the Main Agent is fine-tuned, while all sub-agents remain fixed. Stage 2 continues from the Stage 1 checkpoint on 712 complete workflow demonstrations selected from the Stage 1 training set: 449 from HotpotQA and 263 from BrowseComp. Both stages train for two epochs using the objective in Eq. (2), with a smaller learning rate in Stage 2 and no separate validation split. Table 3 summarizes the training configuration, and Appendix E describes data se-lection. We use ms-swift 4.6.0.dev0 for training with 4-bit NF4 QLoRA, double quantization, BF16 computation, and gradient checkpointing. The Qwen3.5-27B backbone has approximately 27 bil-lion parameters, with 116,727,808 trainable param-eters in our configuration. LoRA targets eligible lin-ear layers through all-linear , while the visual en-coder and alignment module remain frozen. Each stage runs on two NVIDIA H100 80GB GPUs, with a single training process sharding the model across both devices. Based on full job wall-clock time, Stage 1 and Stage 2 consume about 52 and 17 GPU-hours, respectively, totaling about 69 GPU-hours. This budget covers fine-tuning only, exclud-ing teacher trajectory generation, evaluation, and LLM-based judging.

E Orchestration Quality Selection 

The selection judge is deepseek-flash , with thinking enabled, high reasoning effort, and tem-perature 0. It receives the question, the workflow program generated in the first turn, and any launch arguments, without the Main Agent’s reasoning, final answer, reference answer, or execution results. The rubric checks three defects: premise injec-tion , where unsupported answer-relevant claims are supplied as established facts; verification defects ,where instructions or output constraints favor an expected conclusion or prevent independent correc-tion; and information-flow defects , where missing context, incorrect references, or substituted values prevent required information from reaching down-stream agents. The judge cites excerpts from the workflow pro-gram or launch arguments to support each reported defect. We verify these excerpts against the sup-plied text as part of the quality screening. From the 2,257 workflow-containing demonstrations, we retain 712 complete first-turn examples for Stage 2.

14 Dimension Categories and definitions 

Execution structure Code only : no agent reasoning node, only code or tools; Single agent : exactly one agent reasoning node; Serial : multiple agents operate mainly in sequence, with later stages depending on earlier ones; 

Parallel : agents operate mainly independently in parallel, without substantial sequential dependencies; Hybrid : parallel branches and sequential agent dependencies are meaningfully combined. Role specialization None : fewer than two agents; Homogeneous : agents mainly perform the same role or type of attempt; Complementary : agents differ in roles, perspectives, subtasks, or methods; Mixed :homogeneous attempts and complementary roles coexist. Dependency pattern None : no agent depends on another agent’s output; Chain : outputs mainly form a sequential chain; 

Fan-out : one upstream result feeds multiple downstream agents; Fan-in : one downstream agent combines multiple upstream results; Multi-stage : multiple dependency forms or sequential stages are combined. Output reuse None : no upstream output is passed downstream; Passed : an upstream output is supplied, but its meaningful use is not explicitly required; Consumed : the actual upstream output is supplied and the downstream instruction explicitly requires using, analyzing, comparing, refining, critiquing, or transforming it. We compare selected Base and DynaFlow work-flows under Forced execution with fixed sub-agents, complementing the analysis of information use and task-specific organization in §5.3. Each diagram is reconstructed from the workflow program and execution record; captions specify the displayed invocation and distinguish executed calls from con-ditional branches. 

Complementary computation and explicit ver-ification. For the palindrome-counting problem from AIME 2026 (Figure 8), Base delegates to one solver, which returns 59 after an arithmetic error. DynaFlow assigns enumeration, dynamic programming, and inclusion–exclusion to parallel solvers, then passes their outputs to a verifier for comparison and independent recomputation. All three solvers and the verifier obtain 62. This case il-lustrates how complementary methods and explicit use of intermediate results support mathematical verification. 

Preserving research evidence for scientific adju-dication. For the reaction-product question from GPQA-Diamond (Figure 9), Base runs two anal-yses sequentially without passing results between them. DynaFlow assigns four research calls to dis-tinct chemical constraints and checks the candidate products for each reaction. Both checks challenge their initial candidates, and the decision agent re-ceives the research evidence alongside the verifi-cation results. Preserving these complementary in-puts enables final synthesis to account for both the proposed answers and the objections raised during verification. 

Connecting entity identification to subsequent retrieval. For the HotpotQA question requiring person identification and year retrieval (Figure 10), the displayed Base call searches for investment firms and their founding years. DynaFlow instead uses three search routes to identify candidate en-tities, deduplicates and ranks them, and passes their names, quotations, and sources to candidate-specific resolution agents. Subsequent checks as-sess the selected proposal. This organization con-nects retrieval steps through explicit intermediate entities and supporting evidence, as discussed in §5.1. 

Linking solution stages to audits and conditional repair. For the geometric optimization problem from AIME 2025 (Figure 11), the displayed Base invocation checks a supplied derivation and returns fixed numeric fields. DynaFlow connects geomet-ric construction, parallel optimization, expression fitting, and independent audits. Optimizer outputs inform the fitted candidate, while audit findings de-termine whether to invoke a repair step. 19 I Extended Related Work 

Multi-Agent Collaboration and Orchestration. 

LLM-based multi-agent systems (MAS) have pro-gressed from predefined role-based collabora-tion toward adaptive, task-specific orchestration. Early approaches establish structured interactions through specialized agents, communication proto-cols, and iterative reasoning (Chen et al., 2024; Qian et al., 2024; Du et al., 2024; Wang et al., 2025a). Recent methods further explore dynamic agent selection, communication topology optimiza-tion, and automatic workflow construction (Liu et al., 2024; Zhang et al., 2025b; Li et al., 2026b). Similar principles of specialization and selec-tive information integration have been explored in multimodal learning, including cross-spectral aug-mentation (Tan et al., 2024b), modality-decoupled representations (Feng et al., 2025a), sparse mixture-of-experts (Feng et al., 2025b), attention-guided alignment (Tan et al., 2026), and dynamic cross-modal coordination (Lin et al., 2026). Unlike approaches relying on predetermined col-laboration structures, DynaFlow learns to synthe-size executable workflows according to individual task requirements and adapt subsequent decisions using execution feedback. 

Efficiency and Reliable Information Flow. Ef-fective collaboration requires balancing reasoning quality, computational efficiency, and reliable in-formation exchange. AgentPrune reduces redun-dant communication (Zhang et al., 2025a), while broader MAS efficiency studies investigate topol-ogy optimization and resource allocation (Li et al., 2026a). Meanwhile, analyses of multi-agent fail-ures highlight challenges involving task decom-position, information propagation, and verifica-tion (Cemri et al., 2025). Related research has explored robust infor-mation selection through saliency-guided trans-fer (Tan et al., 2024a), semantic label verifica-tion (Zhang et al., 2025d), uncertainty-guided expert selection (Zhang et al., 2025e), and generalization-preserving or collaborative contin-ual learning (Zhang et al., 2025f, 2026b). Reliable evidence integration and structured information de-pendencies also arise in multimodal hallucination mitigation (Shu et al., 2026), dense video corre-spondence (Wu et al., 2026), and constrained visual generation (Wu et al., 2025). These studies highlight complementary aspects of information selection, coordination, and relia-bility. DynaFlow addresses these challenges at the agent-workflow level by selectively invoking col-laboration, explicitly organizing dependencies, and training the Main Agent on demonstrations filtered for orchestration quality. 

Positioning of DynaFlow. DynaFlow unifies task-specific workflow synthesis, adaptive collabo-ration decisions, and feedback-driven orchestration within a single policy. Unlike methods that opti-mize fixed workflows or separately train multiple agents, DynaFlow updates only the Main Agent while keeping sub-agents fixed. Its emphasis on explicit information transfer and independent ver-ification enables flexible collaboration tailored to individual tasks. 20
