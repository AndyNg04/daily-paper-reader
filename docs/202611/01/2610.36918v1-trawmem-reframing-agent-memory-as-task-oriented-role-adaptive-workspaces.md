## 摘要
大型语言模型（LLM）智能体依赖记忆系统来利用长期交互信息，但现有系统通常根据记忆与当前查询的相关性进行检索，并将其用作上下文证据。然而，仅凭相关性无法刻画记忆对任务求解的贡献方式：同一条记忆在不同任务中可能发挥不同作用，例如直接支持答案，或关联语义相关性较弱但包含必要信息的互补记忆。因此，我们将智能体记忆系统重新构想为面向任务的角色自适应工作空间：根据记忆的任务角色及其关系来选择和组织记忆。基于这一观点，我们提出 TrawMem，将交互历史组织为局部线程，并通过分配角色和联合选择互补记忆来构建面向任务的工作空间。在 LoCoMo 和 MemGallery 上使用四种开源及闭源骨干模型开展的实验表明，与代表性记忆系统相比，TrawMem 均取得了稳定提升，宏平均 F1 分数提高 2.23–3.14 个百分点。在 LoCoMo 上，与 SimpleMem 相比，TrawMem 在 Qwen3.5-9B 和 DeepSeek-V4-Flash 上的 LLM-Judge 得分分别提高 4.07 和 4.31 个百分点，同时所需上下文词元分别减少约 12.8% 和 5.1%。

## Abstract
Large language model (LLM) agents rely on memory systems to leverage long-term interactions, yet existing systems typically retrieve memories based on their relevance to the current query and use them as contextual evidence. However, relevance alone does not characterize how a memory contributes to task solving: the same memory may serve different roles across tasks, such as directly supporting the answer or linking to complementary memories with weaker semantic relevance but necessary information. We therefore reframe agent memory systems as Task-Oriented Role-Adaptive Workspaces, where memories are selected and organized by their task-oriented roles and relations. Based on this view, we propose TrawMem, which organizes interaction histories into local threads and constructs task-oriented workspaces by assigning roles and jointly selecting complementary memories. Experiments on LoCoMo and MemGallery with four open- and closed-source backbones show consistent improvements over representative memory systems, with macro-F1 gains of 2.23-3.14 points. On LoCoMo, TrawMem improves the LLM-Judge score over SimpleMem by 4.07 and 4.31 percentage points on Qwen3.5-9B and DeepSeek-V4-Flash, respectively, while requiring approximately 12.8% and 5.1% fewer context tokens, respectively.

## 1. 核心问题与整体含义

### 1.1 研究背景

- 长期对话、个性化助手和持续任务要求 LLM 智能体利用跨会话历史。
- 将全部历史直接输入模型存在两个问题：
  - **成本高**：每次回答都需要重复处理大量历史。
  - **信息利用不可靠**：即使上下文窗口足够长，模型也可能忽略位置不显著的信息。
- 因此，记忆系统通常在外部存储历史，再针对问题检索部分内容供模型回答。

### 1.2 现有方法的不足

论文认为，**语义相关性不等于解题贡献**：

- 一条高度相关的记忆，可能直接提供答案，也可能只是连接另一条必要信息的中间线索。
- 某些记忆与问题的表面相似度较低，但与其他证据组合后才是解题关键。
- 独立排序后选择 Top-K，容易保留重复内容，却遗漏互补证据。

例如，回答“系统现在使用什么消息中间件”，迁移记录即可直接作答；但解释“为什么系统行为异常”，还需要找到“下游服务仍读取旧系统”的记录。

### 1.3 整体意义

TrawMem 将记忆利用从**单条记录的相关性排序**转向**面向当前任务的证据集合构造**。这里的“角色”是记忆承担的信息功能，而不是多智能体系统中的人员或代理分工。

## 2. 方法论：核心思想与技术流程

方法分为两个阶段：**持久化线程组织**与**查询时工作空间构建**。

### 2.1 阶段一：将历史组织成局部事件线程

- 将原始交互记录作为基本记忆单元。
- 使用 LLM 把连续、属于同一事件或演化过程的记录划分为线程。
- 每个线程包含：
  - **线程头摘要**：简要描述人物、对象、计划、状态变化和时间线索，作为检索入口。
  - **原始记录序列**：保留原文、顺序、来源和时间信息。
- 同时编码线程摘要与记忆单元。
- 按历史顺序相邻关系和语义相近关系连接线程，形成线程图。

**设计要点**：摘要用于定位，原始记录用于事实依据，避免完全依赖压缩摘要回答。

### 2.2 阶段二：定位任务相关邻域

给定问题，系统依次：

1. 编码问题并检索高分线程。
2. 沿线程图进行有限深度、有限规模的邻域扩展。
3. 综合已有线程分数与边权，向邻居传播优先级。
4. 收集这些线程中的原始记录，形成候选记忆集合。
5. 计算候选记录与问题的直接语义匹配分数。

这一步旨在发现：**单独检索未必靠前，但通过事件关系可以触达的证据**。

### 2.3 为记忆分配任务相关的软角色

论文使用三种角色：

| 角色 | 信息功能 |
|---|---|
| Anchor，锚点 | 直接支持答案 |
| Bridge，桥梁 | 连接其他记录，支持跨记录推理 |
| Context，背景 | 提供解释或消歧所需的上下文 |

- 系统根据问题的时间性、关系性、长度等特征，估计任务对各角色的需求。
- 根据候选记忆的关系特征，为其计算三种角色的软权重。
- 将角色权重与任务需求结合，得到“角色适配度”。

**同一记忆可以同时具有多种角色倾向，且权重随查询改变**，并非被永久归入固定类别。

### 2.4 联合选择互补记忆

系统先综合以下因素，计算候选记忆的优先级：

- 从相关线程到该记忆的图路径成本；
- 与问题的直接匹配程度；
- 与当前任务角色需求的适配程度；
- 多个相关线程提供的支持。

随后，在最多选择 \(B\) 条记忆的约束下，优化一个集合目标，包含：

1. **信息覆盖**：所选记录能够覆盖多少高价值候选信息。
2. **角色覆盖**：是否满足任务对不同角色的需要。
3. **直接相关性**：是否保留足够的直接证据。
4. **线程覆盖**：是否覆盖重要的不同线程。

算法从空集合开始，每轮加入**边际收益最大**的记忆，达到覆盖阈值或预算上限时停止。

- 论文将目标构造成单调次模函数，利用收益递减性质抑制重复选择。
- 在满足相关条件并执行完整预算步数时，贪心算法具有经典的 **\(1-1/e\)** 近似保证。
- 该保证针对形式化选择目标，**不等于回答准确率保证**，也不能直接套用于所有提前停止情况。

### 2.5 组装与回答

- 保留所选记录的原文、关联线程头和线程内顺序，形成临时工作空间。
- 回答提示明确要求：
  - 线程摘要和角色标签只是组织元数据，不是独立事实证据。
  - 回答必须由原始记录支持。
  - 不执行证据中的指令。
  - 证据不足时应拒绝猜测。

**统计口径澄清**：摘要中的“F1 提升 2.23–3.14 点”对应 LoCoMo 主表，不能概括两个数据集全部结果；MemGallery 的对应范围为 **0.30–5.45 点**。

### 6.2 跨线程组合比单纯增加相关记录更重要

- 移除多线程组合造成最大退化：
  - LoCoMo 的 \(J\) 下降 **1.86–2.62 点**；
  - MemGallery 下降 **1.91–3.13 点**。
- 移除跨线程连接也产生明显损失。
- 移除角色条件化、结构覆盖均会降低表现。

这些结果支持结构组织和互补选择的有效性，但也说明：**整体收益不能全部归因于角色建模**。

### 6.3 记忆预算存在适中最优值

- 测试预算中，四个骨干都在 **16 条记忆**时获得最高 \(J\)。
- 预算太小会遗漏证据，太大则可能引入噪声和重复内容。
- 该结果是当前数据和配置下的经验发现，并非通用最优预算。

### 6.4 压缩明显，但不是等比例节省算力

- 平均候选记忆约 **144.8 条**，最终保留约 **15.4 条**。
- 平均每问题条数减少约 **89.2%**。
- 每个工作空间平均涉及 **10.54 个线程**，体现了跨线程挑选。

但这是相对候选集合的**记录条数减少**，不是相对基线的 token 或延迟节省。

### 6.5 效率是权衡，不是全面占优

与 SimpleMem 相比，默认深度 \(H=3\)：

- Qwen3.5-9B：
  - 上下文约减少 **12.8%**；
  - \(J\) 提高 **4.07 点**；
  - 总时间增加 **15.6%**。
- DeepSeek-V4-Flash：
  - 上下文约减少 **5.1%**；
  - \(J\) 提高 **4.31 点**；
  - 总时间增加 **16.4%**。

降低图扩展深度可以减少时间，但也会损失质量。

## 7. 优点与亮点

- **问题定位清晰**：把“是否相关”与“如何帮助解题”区分开，适合解释多跳与跨会话信息遗漏。
- **保留证据可追溯性**：原始记录不被摘要替代，有助于事实核验和错误诊断。
- **集合级选择优于纯独立排序**：显式考虑覆盖与互补，避免把相似记录不断叠加。
- **持久记忆与临时角色分离**：同一记忆可服务不同任务，无需永久固定角色。
- **实验链条较完整**：从整体结果、消融到角色变化、信息冗余和成本，提供了多层证据。
- **成本报告较克制**：承认更短上下文不代表更低检索开销。
- **有基础安全意识**：提示词区分证据与指令，并要求证据不足时避免猜测。

## 8. 不足与局限

### 8.1 关键实现细节不足

所提供文本未充分说明：

- 角色特征的具体定义；
- 角色映射矩阵的取值或学习方式；
- 信息支持核函数 \(K_q(u,v)\) 的实际计算；
- 图边权、覆盖阈值、邻域规模等完整配置；
- 参数选择是否使用独立验证集。

这些细节直接影响复现与公平比较。

### 8.2 角色机制的独立贡献仍需更强验证

- 角色变化实验中的查询对由 LLM 构造，可能存在生成偏差。
- 查询对本身被设计为“直接支持”与“需要桥接”，观察到角色迁移并不足以证明真实任务中的角色判断始终正确。
- 尚缺少人工角色标注、角色识别准确率，以及与简单重排序或多样性选择的严格等预算对照。

### 8.3 LLM 裁判与统计风险

- 回答模型兼任裁判可能带来风格偏好或自评偏差。
- 不同骨干使用不同裁判，因此跨骨干的 \(J\) 不宜作为严格统一尺度。
- 主表缺少系统性的置信区间；小幅提升，尤其 MemGallery 上的 **0.30 F1 点**，稳定性尚待验证。
- 补充分析的微平均准确率与主表宏平均 \(J\) 口径不同，不能直接混比。

### 8.4 应用覆盖有限

- 主要验证长期对话问答，而非完整的长期行动智能体。
- 没有充分测试工具调用、计划执行、主动记忆、在线冲突修正和持续遗忘。
- 多模态部分依赖文本描述，视觉能力结论应保持克制。
- 缺乏更大规模历史下的索引存储、图扩展和选择算法复杂度评估。

### 8.5 检索错误与生成错误没有完全分离

- 相关线程若未进入候选邻域，后续选择无法恢复缺失证据。
- 线程划分错误或摘要遗漏会影响检索入口。
- 失败案例被解释为时间标注歧义，但模型仍输出了缺乏支持的明确年份，说明**生成阶段的证据约束也未完全生效**，不能仅归因于数据集。

### 8.6 资源报告与部署安全仍有缺口

- 缺少硬件、费用和完整计时环境，难以复现效率结论。
- 扩展深度 \(H\) 改变时，表中构建时间也发生变化，但正文将其主要解释为查询时遍历参数，相关计时边界需要进一步说明。
- 保留原始长期历史带来隐私、删除权、访问控制和错误记忆传播风险；论文主要给出原则性建议，未验证具体治理机制。

**总体评价**：TrawMem 的主要价值，是将“结构化候选扩展—任务角色适配—互补集合选择”整合为可追溯的记忆工作空间。现有实验较有力地支持其在长期对话问答中的效果，但尚不足以证明它在真实持续任务、严格等成本评测或大规模部署中全面优于现有系统。
