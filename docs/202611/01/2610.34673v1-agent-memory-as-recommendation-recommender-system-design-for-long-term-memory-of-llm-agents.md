## 摘要
需要跨多个会话为用户提供服务的大语言模型（LLM）智能体，必须针对每个请求，从存储的记忆中选出少量内容，放入容量有限的上下文窗口。这一选择在很大程度上决定了智能体能否正确作答，并且在 Web 规模下会对每个请求执行。记忆选择面临三项挑战：不断增长的大型记忆库、单次请求的成本预算，以及需要汇集全部相关证据的多会话问题。许多记忆系统会为每段历史记录调用数百至数千次 LLM，以构建笔记或图谱；而各系统的设计彼此独立，因此难以判断究竟哪个组件带来了准确率提升。这些挑战与推荐系统的特性相呼应，因此我们将智能体记忆形式化为带预算的列表推荐：将请求视为用户、将存储的记忆视为物品、将上下文窗口视为推荐列表。该形式化将记忆系统纳入推荐级联的统一设计空间，并将准确率分解为各阶段所控制的完整性。在此基础上，我们提出 AgentMemRec，将推荐系统中的候选生成、学习排序和列表构建方法迁移到智能体记忆中，无需调用任何 LLM 即可选择记忆。在 LongMemEval 的多会话问题上，AgentMemRec 的表现优于包括 A-Mem、HippoRAG 2、DynamicRAG 和 T-Mem 在内的记忆与上下文选择方法，准确率高出 10 至 31 个百分点。与每个查询调用 64 次的 LLM 重排器相比，AgentMemRec 的准确率相当，而服务成本低 3.2 倍；在 LoCoMo 上，它无需在写入时调用 LLM，表现也优于 Mem0 和 Zep。分解分析表明，性能提升源于所构建的列表更常包含全部证据。因此，推荐系统设计为 LLM 智能体的长期记忆提供了一种有效且高效的基础。

## Abstract
Large language model (LLM) agents that serve users across many sessions must choose, for every request, the few stored memories that enter a limited context window. This choice largely decides whether the agent answers correctly, and it runs on every request at Web scale. This selection faces three challenges: a large and growing store, a per-request cost budget, and multi-session questions that need all of their evidence. Many memory systems build notes or graphs with hundreds to thousands of LLM calls per history, and each is designed on its own, so it is unclear which component yields the accuracy. These challenges mirror the properties of recommendation, so we formalize agent memory as budgeted slate recommendation, with the request as the user, stored memories as items and the context window as a slate. The formalization places memory systems in one design space of recommender cascades and factorizes accuracy into the completeness that each stage controls. Guided by it, we propose AgentMemRec, which adapts candidate generation, learning to rank and slate construction from recommender systems and selects memories without any LLM call. On multi-session questions of LongMemEval, AgentMemRec outperforms memory and context-selection methods, including A-Mem, HippoRAG 2, DynamicRAG and T-Mem, by 10 to 31 points of accuracy. It matches an LLM reranker that makes 64 calls per query at 3.2 times lower serving cost, and on LoCoMo it outperforms Mem0 and Zep without any LLM call at write time. The factorization attributes the gains to slates that more often hold all of the evidence, so recommender-system design offers an effective and efficient foundation for the long-term memory of LLM agents.

# 论文总结：将智能体长期记忆建模为推荐问题

## 1. 核心问题与研究背景

论文研究的是：**长期服务用户的 LLM 智能体，应如何从不断增长的历史记忆中，为当前问题选择一组既完整、又符合上下文和计算预算的证据？**

这一问题有三个难点：

- **记忆规模大、上下文预算小**：LongMemEval-M 中，一段历史约有 500 个会话、150 万 tokens，而实验中回答模型通常只能读取约 2,700 tokens 的记忆。
- **每次请求都要支付选择成本**：如果依靠 LLM 逐条判断记忆是否相关，成本会随候选数量和请求量增长。
- **价值取决于证据组合，而非单条相关性**：跨会话的计数、排序或状态更新问题，往往必须找齐多个会话中的证据。少一条，就可能回答错误。

现有方法常在写入阶段调用 LLM 构建笔记、事实或知识图谱，但结构越复杂并不必然意味着证据选择越完整，也难以分辨性能来自哪个组件。

论文的整体观点是：**长期记忆选择可以借鉴推荐系统的级联设计，将主要精力放在“廉价召回足够多的候选，再准确选齐证据”，而不一定先构建昂贵的结构化记忆。** 这里的“推荐”主要指候选生成、排序和列表构建，并非传统的用户—物品协同过滤。

## 2. 方法论：形式化框架与 AgentMemRec

### 2.1 将记忆选择形式化为预算约束的列表推荐

论文建立如下对应关系：

| 推荐系统概念 | 智能体记忆中的对应对象 |
|---|---|
| 请求或用户状态 | 当前问题、问题日期与智能体状态 |
| 物品库 | 历史对话轮次，或引用原始轮次的记忆记录 |
| 推荐列表（slate） | 输入回答模型的记忆上下文 |
| 列表成本 | 渲染后上下文的 token 数 |
| 列表收益 | 回答被评审模型判定为正确的概率 |

目标是在每次请求的 token 预算内，选择使期望回答准确率最高的记忆集合。

系统进一步被分为四个阶段：

1. **记忆构建**：将历史转为可检索单元及其附加信息。
2. **候选召回**：从记忆库中得到候选池。
3. **记忆排序**：对候选进行相关性排序。
4. **上下文构建**：在预算内选取并组织记忆。

### 2.2 用“证据完整性”分解准确率

论文定义：

- **候选池完整率** \(r_{\text{pool}}\)：候选池包含全部标注证据的概率。
- **排序完整率** \(r_{\text{rank}}\)：在候选池已有全部证据时，最终上下文仍保留全部证据的概率。
- **上下文完整率** \(r_{\text{slate}}\)：最终上下文包含全部证据的概率。

由于最终上下文来自候选池：

\[
r_{\text{slate}}=r_{\text{pool}}r_{\text{rank}}
\]

设完整上下文和不完整上下文上的平均准确率分别为 \(a_c\) 和 \(a_i\)，则：

\[
\mathrm{Acc}
=a_i+(a_c-a_i)r_{\text{pool}}r_{\text{rank}}
\]

其含义是：**当缺失证据会显著损害回答时，提高召回和排序阶段的证据完整性，是提升准确率的重要路径。**

需要注意，这一分解本身是全期望公式的恒等式；不同系统的 \(a_c\)、\(a_i\) 也会变化，因此不能无条件地只优化完整率。

### 2.3 AgentMemRec 的算法流程

默认版本直接使用原始对话轮次，不需要 LLM 生成记忆。

#### ① 双通道召回

- 使用 **BM25** 进行词法检索。
- 使用 **bge-m3** 向量余弦相似度进行稠密检索。
- 通过 **倒数排名融合 RRF** 合并两路结果，参数为 60。
- 取前 **128 条轮次**作为候选池。

候选规模根据开发集上的最终上下文完整率选择，而非仅根据候选召回率选择，以兼顾召回覆盖和干扰项数量。

#### ② 轻量学习排序

使用 **LightGBM LambdaRank**，每个“问题—候选轮次”包含 10 个特征：

- **5 个相关性特征**：向量相似度、稠密排名、BM25 排名、融合排名、交叉编码器分数。
- **5 个轮次特征**：是否为用户发言、会话内位置、距问题日期的时间、文本长度、与问题共享的关键词。

训练使用 152 道开发问题在 LongMemEval-S/M 上的候选池，共 **19,456 个训练样本对**。配置包括 300 棵树、31 个叶节点、学习率 0.05。

#### ③ 按预算贪心填充

- 顺序遍历排序后的候选。
- 若加入该轮次后不超出 token 预算，则加入。
- 放不下的轮次跳过，继续尝试后续候选。
- 最后按会话分组、按日期组织上下文。

默认预算为 **2,700 tokens**，不为每个问题单独学习截断位置。

### 2.4 理论依据及其边界

论文给出两个条件性结论：

- 如果证据相关性相互独立，且完整与不完整上下文的收益不随具体组成变化，则集合选择可转化为一个 **0-1 背包问题**；当单元成本相同时，按证据相关概率排序即可最优。
- 如果继续添加记忆不会降低收益，则预算填充不劣于同一排序下任何能够放入预算的前缀截断。

**这些结论不等于证明实际贪心算法普遍最优**：现实中轮次长度不同、会话标题成本共享，而且干扰记忆可能降低回答质量。

### 2.5 可选写入增强

论文还提供一个非默认扩展：

- 用 Qwen3-32B 为每个会话生成带类型、日期、实体和原文引用的记录。
- 通过记录额外召回最多 32 条原始轮次。
- 为相对时间表达添加日期标签。

该扩展**写入阶段会调用 LLM**，但选择阶段仍不调用生成式 LLM。LoCoMo 上最强的 77.0% 结果使用了这一扩展。

## 6. 主要结论与发现

### 6.1 准确率与昂贵 LLM 重排相当

在主要多会话测试集上：

| 场景 | AgentMemRec：Qwen / DeepSeek | Ref：Qwen / DeepSeek |
|---|---:|---:|
| LongMemEval-S | **80.7% / 89.4%** | 79.8% / 89.1% |
| LongMemEval-M | **70.0% / 81.3%** | 66.6% / 76.2% |

- 相较本文运行的记忆与上下文选择基线，S 上提升约 **10—31 个百分点**，M 上约 **11—33 个百分点**。
- 与 Ref 相比，多数比较达到统计持平；M 上 DeepSeek 的优势被 GPT-4o 评为显著，但更换评审模型后为持平。

### 6.2 主要收益来自证据选得更完整

- LongMemEval-S 上，AgentMemRec 的候选池完整率为 **0.981**，最终上下文完整率为 **0.940**。
- Ref 的上下文完整率为 **0.915**，HippoRAG 2 和 A-Mem 约为 **0.502**。
- 在双方上下文都完整的问题上，系统之间的准确率差异不显著。

这支持论文的关键判断：**当前瓶颈很大程度上是证据选择，而不只是记忆表示或回答能力。**

### 6.3 廉价宽召回与学习排序具有互补性

- 128 条候选提高了全部证据进入候选池的机会。
- LambdaRank 能利用相关性与时间、角色、位置等特征，把分散证据提升到预算内。
- 单独使用召回顺序或交叉编码器，均明显弱于学习排序组合。

### 6.4 LoCoMo 的收益需要区分配置

- 无写入增强、2,700 tokens 时，AgentMemRec 达到 **75.2%**，高于所报告的 Mem0、Zep 和本文 HyperMem 复现结果。
- 使用可选记录及约 3,800 tokens 上下文时达到 **77.0%**，与 T-Mem 复现的 **77.4%** 持平。
- 不能把后一结果描述为“完全不调用 LLM 的记忆管线”。

### 6.5 填满上下文不是普遍最优

- 在 AgentMemRec 的实际排序上，自适应预算未显示超出生成噪声的显著收益。
- 但控制实验发现，加入“看似相关却不能回答问题”的干扰轮次会显著降低准确率。
- 当证据跨三个及以上会话时，列表组成的影响更明显，提示需要集合感知的选择方法。

## 7. 优点与亮点

- **统一分析框架**：将复杂记忆系统拆成构建、召回、排序、上下文组装，便于定位成本和性能来源。
- **机制解释清晰**：通过证据完整性解释提升，而非只展示最终分数。
- **工程方案实用**：BM25、向量检索、RRF、交叉编码器和 LightGBM 都是成熟组件，便于部署。
- **成本核算较具体**：不仅统计 LLM 调用，还报告实际 GPU 时间、延迟和包含召回后的成本。
- **评估较重视不稳定性**：识别了温度为零仍存在的输出波动，并采用预算扰动、评审校准和统计检验。
- **主动检验理论边界**：展示干扰记忆和多证据场景下的失败条件，而非将逐条排序或固定预算表述为普遍最优。

## 8. 不足与局限

### 8.1 理论与优化目标的局限

- 单条排序最优性依赖独立证据、固定收益等较强假设，实际跨会话证据通常存在关联。
- 准确率分解是描述性恒等式，本身不构成“完整率提高必然导致相同比例准确率提升”的因果证明。
- 实际采用逐条贪心填充，未直接求解变长单元和共享成本下的最优集合选择。
- 金标轮次只是证据的代理；现实系统中可能存在替代证据、冗余证据或标注遗漏。

### 8.2 数据和比较偏差

- 排序器依赖基准证据标签，可能学习到会话开头、用户角色等数据集特征。
- 开发与测试存在部分共享会话；作者通过未共享金标会话的子集实验缓解风险，但仍不等于完全用户隔离。
- 全部 500 题上的 83.2% 包含训练开发题，应优先参考独立测试集上的 **82.5%**。
- LoCoMo 只有 10 段对话，迁移证据仍较有限；LLM 评审也不能替代全面人工核验。

### 8.3 真实应用覆盖有限

- 主要验证历史问答，尚未充分覆盖持续交互中的长期任务成功率、主动记忆更新、遗忘与冲突处理。
- 未评估隐私、删除请求、恶意记忆注入等生产问题。
- 检索依赖已有索引；论文没有证明记忆库任意增长时，端到端成本仍保持不变。
- 成本主要是选择阶段成本，不能直接等同于整个智能体系统的总成本降低 3.2 倍。

### 8.4 后续研究方向

更有潜力的扩展包括：**集合感知重排、证据依赖建模、干扰项惩罚、回答模型感知的预算分配，以及从实际用户反馈中持续学习。**

总体而言，论文最有价值的贡献不是证明结构化记忆无用，而是表明：**在所测试的长期对话问答场景中，优先保证证据召回与组合完整性，能够比昂贵的记忆构建获得更好的准确率—成本权衡。**
