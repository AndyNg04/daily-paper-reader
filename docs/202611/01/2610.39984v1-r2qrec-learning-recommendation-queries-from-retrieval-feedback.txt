## Abstract 

Query-based recommendation separates expressing user needs from locating matching items. Its central learning problem is how to turn item interactions into effective retrieval requests when interac-tion logs do not annotate queries. We present R2QRec, which uses a fixed retrieval system to construct query supervision and evaluate recommendation outcomes. Retrieval verification first selects gen-erated expressions that recover observed items as supervised fine tuning targets, allowing retrieval behavior to determine the target wording. Policy refinement then evaluates generated query sets by the observed item’s rank in their fused recommendation list. Log-rank feedback distinguishes outcomes beyond the recommendation cutoff, while a KL penalty constrains policy change relative to the supervised reference. The stages have distinct roles: verification identifies expressions to imitate, and policy refinement improves the combined ranking produced by newly generated queries. Only the query generator is trained; the retriever and item index re-main fixed, and no query annotations or learned reward model are required. Across three public datasets, R2QRec achieves state-of-the-art overall recommendation performance among the evaluated methods. Extensive experiments demonstrate the effectiveness of the proposed design and its generalization across generators and domains.

recommender systems, query generation, retrieval feedback, rein-forcement learning, large language models 

## 1 Introduction 

Recommendation on Web platforms requires finding items that satisfy a user’s needs, even when those needs do not specify a con-crete retrieval request. Interaction histories and other available user context provide evidence of preferences, inducing several plausible directions for the next recommendation. Existing approaches ex-press these preferences through discriminative item scores [7, 13] or distributions on discrete item identifiers [4, 20]. Query-based recommendation makes this intermediate prefer-ence expression explicit in natural language, then uses a retriever to find matching items across the catalog [6, 16]. A single user can have multiple interests [14]. For example, a reading history containing Thinking, Fast and Slow , The Power of Habit , and Out-liers may suggest interests in cognitive science, behavioral change, or human achievement. Large language models (LLMs) can draw on semantic knowledge to turn these plausible interests into sepa-rate retrieval requests, with prior work demonstrating the value of

Title-supervised and prompting-based recommenders provide two ways to obtain retrieval text. GPT4Rec trains its generator to predict target item titles before using the generated text for retrieval [16]; BIGRec also uses target item text for supervised adaptation [1]. QueRec [6] generates personalized queries through prompting without LLM fine-tuning. We study a complementary learning formulation: next-item interactions supply query super-vision and evaluate the recommendation outcomes of generated queries (Figure 1). An observed interaction identifies an item to recover, but does not prescribe a unique query to reproduce. Several expressions may retrieve the same item, while the interaction log does not annotate which expression to imitate. We address this supervision problem through item-verified supervision : generated expressions that retrieve the observed item successfully become training targets. The item label thereby specifies an admissibility criterion for queries without fixing their wording. Admissible individual expressions and useful query combina-tions pose different ranking problems. Even the complete vector of target ranks across queries does not determine the fused recommen-dation outcome: the positions of competing items across the lists also matter. These choices define R2QRec , a compact framework linking item-level supervision to recommendation-level evaluation. Item-verified supervision constructs the expressions to imitate; fusion-aware refinement evaluates newly generated combinations; the supervised reference constrains policy change through a KL penalty. The same frozen retrieval interface supplies both supervision and outcome evaluation, while only the query generator is updated. This makes recommendation queries a learned interface between user context and item retrieval. At inference, the generator expresses user preferences as several queries, the retriever executes them, and reciprocal rank fusion combines the resulting item lists [3]. Our contributions are summarized as follows: 

• Item-supervised query learning. We formulate query supervi-sion through the retrieval admissibility of generated expressions, allowing an observed interaction to supervise multiple phrasings without query annotations. 

• Fusion-aware refinement and analysis. We show that individ-ual target ranks do not determine fused recommendation utility, motivating feedback on query combinations. A cutoff-risk de-composition characterizes the depth weighting of the log-rank objective. 

• Controlled evidence for the learning design. Experiments distinguish the effect of supervision source from subsequent policy refinement and evaluate recommendation quality across three domains.

## 3 R2QRec 3.1 Query Generation and Retrieval 

R2QRec learns a query generator 𝑄 𝜙 (𝑞 | 𝑠 𝑢 ) from item retrieval outcomes while keeping the retriever 𝑅 (𝑖 |𝑞 ) fixed (Figure 2). The generator expresses the user context as natural-language retrieval queries. We denote a generated query set by 𝑞 = (𝑞 1, . . . , 𝑞 𝐾 ), where each 𝑞 𝑗 defines a retrieval request. At inference, we infer 𝐾 queries and combine their retrieval results by rank fusion. The query bud-get 𝐾 can be varied at inference without changing the learned parameters. The frozen retriever 𝑅 maps each query to a ranked list over 

I \ 𝐻 𝑢 . Let rank 𝑅 (𝑖 | 𝑞 𝑗 ) denote the item’s rank in this list. Queries and item documents are encoded in the same semantic embedding space, and item embeddings can be cached. While the generator learns to express preferences in free-form text, it retrieves relevant items in this embedding space. Finally, Reciprocal Rank Fusion (RRF) [3] combines the 𝐾 retrieval lists. We return the top-𝑁 items in the fused ranking as recommendations. Let 𝜌 𝐹 (𝑖 | 𝑞 ) denote the rank of item 𝑖 after applying this fusion to the query set 𝑞 . We use the same retrieval pool, history masking, fusion settings, and tie handling when evaluating training query sets.

## 3.6 From Item Feedback to Recommendation Utility 

The design separates three questions: what an observed item can supervise, how query combinations affect item competition, and which recommendation depths the loss emphasizes. An item label specifies a retrieval target without prescribing a unique expression. Item-verified supervision uses it to define admissible queries; Ap-pendix C.1 formalizes this selection by conditioning on acceptance. Admissibility alone does not characterize the outcome of combin-ing queries. Lemma C.1 gives two sets of retrieval lists with identical target-rank vectors but different fused target ranks. The difference arises from competing items across the lists: even the full vector of individual target ranks, and therefore its best or mean, cannot determine the fused outcome in general. Fusion-aware refinement observes this combined ranking when comparing generated sets. ## 4.2 Implementation Details 

We implement R2QRec in PyTorch and train on a single NVIDIA A800 GPU with 80 GB memory. We search the SFT acceptance threshold 𝜏 from 50 to 1,000, using the same training-only candidate pool and SFT settings for each threshold. Each domain’s threshold is selected by validation NDCG@10 after SFT and fixed before policy refinement. Both training stages use LoRA [10] on the attention query, key, value, and output projections (𝑊 𝑄 ,𝑊 𝐾 ,𝑊 𝑉 ,𝑊 𝑂 ). We set the adapter rank to 𝑟 = 16 and the scaling parameter to 𝛼 = 32. The backbone and retrieval encoder remain frozen. SFT runs for three epochs with learning rate 2 ×10 −4, per-device batch size 2, gradient accumulation over eight batches, and a 3% warmup ratio. The SFT checkpoint remains fixed as the KL reference. We search 𝐺 from 1 to 32, 𝛽 from 0 to 1, and inference query count 𝐾 from 1 to 20. For all baseline models, we carefully tune hyperparameters on the validation sets and report test performance using the best validation-selected configuration. Results are av-eraged over five random runs. Reported improvements over the best-performing baselines are statistically significant ( 𝑝 < 0.05), assessed using a two-sided 𝑡 -test. 

## 4.3 Baselines 

We compare two groups of baselines. Discriminative and gener-ative recommendation. SASRec [13] and BERT4Rec [25] model interaction sequences; LightGCN [7] learns from the interaction graph; UniSRec [9] incorporates item text for transferable sequen-tial recommendation. TIGER [20] and LETTER [28] generate item identifiers. Query-based recommendation. BM25 [22] and Inpu-tRetrieval perform lexical and dense retrieval, respectively, from the same user context and item documents as R2QRec, without an LLM. BIGRec [1] generates target-item text and grounds it to the catalog. GPT4Rec [16] trains a query generator using item text; the concurrent QueryAgent-R1 [24] uses an agentic search proce-dure to refine e-commerce query recommendations. QueRec [6] combines personalized-query retrieval with collaborative scores through adaptive reranking, without LLM fine tuning. Trainable text-generation baselines use their respective training objectives. GPT4Rec and BIGRec use the same Qwen2.5-7B backbone, frozen MiniLM retriever, 𝐾 = 5 query budget, and rank-fusion proce-dure as R2QRec. The zero-shot generator uses the same backbone, prompt, and retrieval pipeline as R2QRec, without task training.

## 5 Related Work 5.1 Query Learning for Recommendation 

Query-based recommendation connects language generation with item retrieval, with the closest approaches differing in how they train or construct the generated text. GPT4Rec fine-tunes a lan-guage model to predict target item titles, then uses the generated text with BM25 to retrieve recommendations [16]. Its generator learns target-title likelihood; retrieval ranks do not supervise its parameter updates. BIGRec similarly uses target item text for super-vised adaptation before grounding generated text to actual items [1]. Rather than adapting the generator to target text, QueRec [6] gen-erates enriched item descriptions and personalized queries through prompting without LLM fine tuning, and integrates semantic re-trieval with collaborative signals. This approach uses an LLM to express preferences, but does not learn its query generation policy from the retrieval outcomes. Rec-R1 couples LLM-generated text with fixed recommendation models [17]. Concurrent QueryAgent-R1 combines memory-based user profiling with a search agent for proactive e-commerce query recommendation [24]. The focus of R2QRec is how item-level observations supervise an intermediate query interface. Retrieval verification converts those observations into query targets without prescribing their wording, while pol-icy refinement evaluates generated sets at the fused ranking used for recommendation. This connects supervision construction and recommendation-level outcome optimization through a fixed re-trieval system. 

## 5.2 Other Recommendation Approaches 

Discriminative recommenders score items through learned repre-sentations, with sequential models deriving user representations from interaction histories. GRU4Rec uses recurrent networks [8], SASRec applies causal self attention [13], and BERT4Rec uses masked item prediction [25]. LightGCN captures collaborative structure through graph propagation [7], while UniSRec uses item text to support transfer across domains [9]. RecFormer extends this approach to textual item sequences [15]. Generative recommenders instead predict item identifiers or text. P5 casts recommendation tasks as text generation [5]; TIGER generates semantic IDs obtained through residual quantization [20]; and OneRec develops genera-tive recommendation at industrial scale [4]. LETTER learns item tokenization with semantic and collaborative regularization [28]. R2QRec generates retrieval requests that can each match multiple items. Tags provide another semantic connection between users and items [29, 30, 32]. SemRec combines structural and seman-tic relationships in social tagging data for item recommenda-tion [30]. R2QRec instead learns to compose language requests, with observed-item retrieval outcomes supervising their wording. Natural-language interfaces broaden how users interact with recommenders [34]. Agentic approaches further introduce memory, tool use, and interaction between agents [2, 12, 27, 31, 33]. The candidate-ranking protocols considered here provide a small item set to the LLM, allowing direct reasoning about candidate con-tent. R2QRec instead generates retrieval queries without candidate enumeration in its prompt, and ranks the supplied candidates by retrieval when evaluated in this setting. 

## 6 Conclusion 

We presented R2QRec, a framework for learning recommendation queries from item interactions through a fixed retrieval system. Its design separates two learning decisions: retrieval verification iden-tifies useful expressions to imitate, and policy refinement evaluates newly generated query sets through their combined item ranking. The same retrieval interface supports both stages, while only the query generator is updated. Controlled comparisons show the ben-efit of retrieval-verified supervision over title imitation and the further gain from policy refinement. The resulting query interface supports recommendation over the full item set without requiring query annotations or a learned reward model. Future work can adapt the query budget to user context and ex-amine alternative fusion functions within query learning. Another direction is to study query refresh policies for changing user inter-ests and item collections. The separation between query generation and retrieval also supports exploring additional retrieval backends. Broader questions of verifier reliability when LLMs arbitrate be-tween prior knowledge and retrieved evidence are also relevant to retrieval-augmented systems more generally [26].
