# ABSTRACT 

LLM-based user simulation can support interface design, accessibility research, and interactive-agent evaluation, but standard computer-use agents are optimized for task completion rather than reproducing how people perceive, reason, and act. We introduce C OGENT (COG nitive ag ENT ), a modular cognitive architecture for simulating user interaction with desktop interfaces. C OGENT draws on established cognitive theories, such as Norman’s action cycle and ACT-R, to enable explain-able, intervenable, and modular user simulation by decomposing the simulation process into cognitive modules with explicit representations of perception, memory, user state, intentions, and action selection. We begin by presenting six interven-ability demonstrations, each tracing how a single edit to memory, a user attribute, or a processing module propagates through the cognitive pipeline to produce a behavioral change. We evaluate C OGENT ’s behavioral and attributional fidelity across three benchmarks – AgentNetBench, A11y-CUA, and SENSE-42 – finding that it achieves statistically significant fidelity gains over computer-use baselines in reproducing recorded human behavior and recovers the relational structure among human self-reported psychological states. Together, these demos and evaluations demonstrate C OGENT ’s utility toward more faithful, explainable, intervenable, and modular LLM-based cognitive simulations. 

# 1 INTRODUCTION 

Large language models (LLMs) are increasingly used to simulate people. Commercial platforms such as Aaru, Artificial Societies, Simile, and Viewpoints.ai offer population, audience, and user simulations (Aaru, 2026; Artificial Societies, 2026; Simile, 2026; Viewpoints.ai, 2026). Academic work uses LLMs to represent survey respondents, students, economic actors, and agents participating in extended social interaction (Argyle et al., 2023; Horton et al., 2023; Park et al., 2023; Zhou et al., 2024b; Mannekote et al., 2025a;b). In τ -bench and UserBench, AI components also role-play users to evaluate another agent (Yao et al., 2024; Qian et al., 2025). These applications raise a common question: what aspects of a person should a simulated user reproduce? 

Reaching the goal is not the same as behaving like a user. People can reach the same outcome through different routes. One recalls a shortcut, another searches for a visible control, and another asks for help after an unsuccessful attempt. Their choices depend on what they notice, what they know, how they interpret the situation, and how their state changes with experience. Computer-use agents are optimized for the outcome, so they leave the route unmodeled. Recent comparisons with human users report exactly this failure: simulated users diverge from real ones, and the evaluations built on them inherit the divergence (Seshadri et al., 2026; Zhou et al., 2026). For interface research and cognitive science, the route is the object of study, not a nuisance. 

Prompted personas expose no mechanism to study. Asking a model to “act frustrated” produces text that reports frustration, but nothing connects that report to behavior. Goldenberg & Gross (2026) argue for a functional account of emotion, one defined by its role in subsequent behavior. A simulation of frustration therefore needs an explicit pathway: experience updates the state, and the state changes persistence or action. # 2 RELATED WORK 

LLMs as human simulations. Research on LLM-based human simulation spans a growing range of behavioral settings, from eliciting survey responses to sustaining interaction in social and task environments. One line of work examines whether conditioning a model on demographic characteris-tics, preferences, or situational information can reproduce human judgments and choices. Studies of synthetic survey respondents, economic agents, and consumer samples approach simulation at this level (Argyle et al., 2023; Horton et al., 2023; Sarstedt et al., 2024). Interactive simulations introduce an additional requirement: behavior must develop through experience and exchanges with others. Generative Agents uses memory, reflection, and planning to support continuing social activity, while Sotopia provides environments for evaluating goal-directed social interaction (Park et al., 2023; Zhou et al., 2024b). Simulated users also serve as interaction partners in agent benchmarks, where their responses shape another agent’s opportunities to act (Yao et al., 2024; Barres et al., 2025; Qian et al., 2025). Across these settings, a central question is which aspects of human behavior the simulation preserves. Reported discrepancies between simulated and human users, including differences in the evaluations they produce, motivate validation against human observations (Seshadri et al., 2026; Zhou et al., 2026). For sustained interaction, this also calls for examining how knowledge and internal states influence behavior as a situation unfolds. 

LLMs and computer use. Computer-use agents are progressing toward autonomous interaction across web and desktop environments through advances in visual grounding, intermediate reasoning, and learning from demonstrations (Qin et al., 2025; Wang et al., 2025). Existing agents already incorporate processes associated with deliberate human problem solving: UI-TARS uses task decom-position, reflection, and milestone recognition within a single model (Qin et al., 2025). Alongside this integrated approach, modular architectures distribute responsibilities among components. Agent S2 develops this direction by combining generalist planning with specialist grounding (Agashe et al., 2025). 2Preprint In parallel, benchmarks have expanded from predicting actions on websites, as in Mind2Web, to executing multi-step tasks in realistic web environments and workflows spanning desktop applications, as in WebArena and OSWorld (Deng et al., 2023; Zhou et al., 2024a; Xie et al., 2024). Successful task completion remains the central objective of these interactive benchmarks. Human-referenced evaluation also examines efficiency in OSWorld-Human and accessibility-related interaction patterns in A11y-CUA (Abhyankar et al., 2025; Gubbi Mohanbabu et al., 2026). Fidelity to human behavior receives less attention than task competence. For user simulation, the growing capabilities of computer-use agents therefore need to be accompanied by evaluation of how their action choices and trajectories correspond to those of people, including variation associated with knowledge, strategy, and user state. 

Cognitive architectures and interaction. A substantial body of cognitive-architecture research supports modeling cognition through distinct, interacting components. ACT-R makes memory, goals, and perceptual-motor processing explicit, while the Standard Model of the Mind synthesizes shared commitments across ACT-R, Soar, and Sigma, including distinctions among working memory, long-term memory, perception, and motor systems (Anderson et al., 2004; Laird et al., 2017). Such decompositions connect behavioral predictions to specific assumptions about how information is processed. Within human–computer interaction, Norman’s action cycle relates goals and action execution to the interpretation of feedback (Norman, 1986). Accounts of display-based action, ex-ploratory learning, and cognitive walkthroughs further explain how visible cues and prior knowledge guide interface use, while soft-constraints theory examines the tradeoff between relying on memory and consulting the environment (Payne, 1991; Polson & Lewis, 1990; Rieman, 1996; Wharton et al., 1994; Gray & Fu, 2004). This tradition is now informing language-agent design: CoALA organizes memory, internal and external actions, and decision making within a common framework, and brain-inspired architectures apply process decomposition to planning (Sumers et al., 2024a; Webb et al., 2025). Together, these approaches provide a foundation for constructing agents whose behavior arises through inspectable interactions among cognitive processes. COGENT applies this perspective to user simulation, making perception, memory, user state, and action selection explicit and editable within desktop interaction. 

# 3 COGENT’ S DESIGN 

Prior LLM-agent architectures establish important foundations for modular reasoning, memory, reflection, and user simulation, from general frameworks such as CoALA (Sumers et al., 2024b) and Concordia (Vezhnevets et al., 2023) to usability-oriented systems such as SimUser (Xiang et al., 2024) and UXAgent(Lu et al., 2025). Building on these foundations, COGENT focuses on modeling how cognitive processes shape human interaction behavior, with an emphasis on making these processes explicit, inspectable, and configurable. Specifically, we followed three design principles. 

Explainability means that downstream modules use upstream artifacts in a traceable way, connecting model assumptions to behavior (Epstein, 1999; Anderson et al., 2004). Intervenability supports changing those assumptions and examining their consequences (Epstein, 2008): researchers can edit memory, configure attributes, or replace processing modules. Modularity supports assembling users from reusable components with declared interfaces, following component-based generative simulation systems such as Concordia (Vezhnevets et al., 2023). 

Cognitive inspiration and processing cycle. Two theories inspired the architecture. ACT-R motivates specialized processes exchanging information through explicit representations; Norman’s action cycle organizes the progression from intention to action and interpretation of its consequences (Anderson et al., 2004; Norman, 1986). Observation captures the interface. Within Cognition ,Perception identifies noticed regions and produces a subjective image, Retrieval activates stored knowledge, and Comprehension constructs a situation model. Within Control , Monitor assesses completion, Appraise updates dynamic states, and Executive maintains an intention or chooses to rest, request help, or give up. Appraisal accounts motivate relating state updates to interpreted experience (Scherer, 2005). Action Reasoning generates candidates from remembered procedures, perceived controls, and exploratory probes, retaining their sources and expected outcomes. Execution grounds the selected referent and dispatches the fixed mouse or keyboard operation; the next observation supplies feedback. 3Preprint

Their roles draw on accounts of memory access and capacity, situation comprehension, and goal maintenance (Cowan, 2001; Zwaan & Radvansky, 1998; Miller & Cohen, 2001). The five-module grouping and LLM implementations realize these functions through typed records. Appendix A, particularly Appendix A.1, details the theoretical motivations and processing operations. 

Information boundaries. Each process receives preceding-stage outputs and the shared-store information declared for its role. Retrieval identifies existing memory items. Comprehension builds its situation from subjective percepts, recalls, and recent experience; Control evaluates that interpretation and updates intentions and states. Action candidates refer to noticed controls or retain recalled procedure templates. Among downstream modules, Execution alone receives the original screenshot for locating the already selected referent; checks preserve the operation and payload. These boundaries make an intervention’s downstream path traceable while separating selection from physical grounding. Pretrained knowledge also contributes to interpretation, motivating the memory studies discussed in Section 7. Appendix A.2 specifies the module interfaces. 

# 4 INTERVENABILITY DEMONSTRATIONS 

Researchers can configure a user simulation by changing the environment in which the agent acts or by changing the simulated user. For the latter, C OGENT provides three distinct forms of intervention: editing memory, setting user attributes, and replacing processing modules. We present six paired intervenability demonstrations, two for each form, to show how these edits propagate through the architecture and produce differences in behavior (Figure 2). Each pair contains one recorded trajectory per condition, with intermediate records connecting the intervention to the agent’s actions and the task outcome. 

Memory: Configure what the user knows. Memory configuration specifies the knowledge available to the simulated user, including semantic knowledge about interface elements and procedural knowledge about how to act. The two demonstrations illustrate how these forms of knowledge affect recognition and the choice of an action. Demo (a): icon knowledge shows how prior knowledge changes search in an unfamiliar dock. With empty memory, the agent first clicks Document, then tries other dock icons before opening File Manager after six inputs. With full calibration memory, containing semantic knowledge about the icons and an executable procedure, the agent recognizes File Manager and opens it on the first click. Demo (b): procedural memory shows how a remembered procedure changes the route to the same outcome. With empty memory, the agent clicks the window’s visible close button. Attributes: Configure traits and states. User attributes represent traits held fixed during a simulation and states updated as interaction unfolds. Researchers can edit a trait to change a stable behavioral tendency or set an initial state to change how the user enters a situation. The two demonstrations edit carefulness and initial frustration, respectively. Demo (c): carefulness shows how a stable trait changes whether the agent checks its work before submission. With low carefulness, the agent submits the prepared appointment request directly. With high carefulness, it reviews the request before confirming submission. Both conditions succeed, using one and two inputs, respectively. 

Demo (d): frustration shows how an initial state changes persistence after an unsuccessful attempt. With low initial frustration, the agent retries access to an initially unavailable report and completes the task after two inputs. With high initial frustration, it attempts access once and then the Executive 5Preprint selects ask_help , pausing the task. This help-seeking decision is recorded internally and produces no additional physical input. 

Modules: Replace individual processes. Researchers can replace processing modules to imple-ment alternative accounts of perception, appraisal, action selection, or execution. This allows a simulation to incorporate a specific model of how a user processes information or performs an action. The following demonstrations illustrate this flexibility through changes to motor execution and percep-tual input. Demo (e): motor execution shows how replacing the motor process changes the movement used to carry out the same intention. With direct positioning, the cursor reaches the Continue button in 0.0077 seconds, with no sampled intermediate positions. With a minimum-jerk process, it moves through 35 distinct intermediate positions over 0.5606 seconds. Both conditions click the intended button. Demo (f): color perception shows how changing perceptual input changes the strategy used to identify a target. With the original screenshot, the agent distinguishes green Ready items from red Unavailable items and opens the Ready item in one click. With a deuteranopia-transformed screenshot, the status colors are difficult to distinguish, so the agent first clicks Show status labels ,then uses the revealed text to identify and open Ready with a second click. Both conditions succeed through different information-seeking behavior. The details of the demo can be found in Appendix B. These demonstrations illustrate how researchers can edit a simulated user in individual scenarios. More generally, in Appendix D, we examine how such module edits affect simulated behavior at the distribution-level across a broader set of tasks. 

# 5 EXPERIMENTS 

We evaluate behavioral fidelity against human choices and interaction sequences, and attribute fidelity against human-reported states and their behavioral relationships. Behavioral evaluations compare C OGENT with a direct computer-use agent (CUA), a baseline prompted to simulate a human user (CUA-U SER ), and a baseline with a fixed model-call budget (CUA-User-CB). CUA-User-CB generates five independent action proposals using the same prompt as CUA-U SER and the recent executed actions. This budget approximately matches C OGENT based on overall step and model-call counts on A11y-CUA. A majority vote decides on the final action, with ties resolved by first appearance and no additional model call. All use GPT-5.4; their prompts, intermediate representations, and model-call counts differ (Appendix G.1). 

AgentNetBench. On 100 OpenCUA/AgentNet tasks, agents predict 1,208 recorded human actions from screenshots and preceding context (Wang et al., 2025). Human actions determine subsequent states, holding the observation sequence fixed. Exact-action agreement checks the normalized operation and relevant keys or text; pointer actions must fall within an accepted target region. Action-type agreement uses 1,111 targets mapping to the eight physical-action classes. Direct baselines retain screenshot/action context, whereas COGENT retains cognitive state. COGENT and CUA-U SER 

receive the same fixed participant-context description. An annotated subset additionally distinguishes choosing a workable alternative from matching the recorded human choice. Appendix C gives scoring, alternative-action annotations, and full results (Table 4). 

A11y-CUA. We evaluate 43 Windows tasks with a 30-step budget and independent outcome review (Gubbi Mohanbabu et al., 2026). The main comparison uses the tasks for all four agents, including successful, failed, and unverifiable attempts: 172 agent trajectories and 339 successful sighted-human references. Appendix E reports cohort analyses for the original three agents; task selection and outcome assessment appear in Appendix E.2, and the full ledger in Appendix E.7 (Table 15). 

Metrics and uncertainty. Both behavioral benchmarks use eight physical-action classes. Jensen– Shannon (JS) distance compares pooled action counts. A11y sequence distance uses normalized Levenshtein distance over the common prefix of each agent–human pair; comparisons average humans within task and then tasks equally. # 6 RESULTS 

6.1 BEHAVIORAL FIDELITY 

Across the two behavioral benchmarks, C OGENT more closely matches human action choices and interaction patterns than CUA or CUA-U SER .On AgentNetBench, C OGENT achieves significantly higher next-action prediction accuracy and lower action-distribution distance than both baselines (Table 1). Exact-action agreement is 59.8%, compared with 52.2% for CUA and 53.7% for CUA-U SER . Action-type accuracy is also higher, at 84.1% versus 79.0% and 80.9%, respectively. All four prediction gains are statistically significant. The predicted action-type distribution is also closer to the human distribution: pooled JS distance is 0.0445 for C OGENT , compared with 0.1252 for CUA and 0.1210 for CUA-U SER . Both reductions are statistically significant. Together, these results suggest that C OGENT better predicts both a user’s specific next action and the overall mix of actions users choose across recorded interface states. Relational structure and calibration. The ordering of 21 pairwise attribute relationships shows strong agreement with the human pattern ( ρs = 0 .860 ), and this agreement is statistically significant (Figure 3). Correlation-magnitude MAE is 0.397. Thus, the agent largely preserves which attribute relationships are relatively stronger or weaker, but the strength of those relationships remains a calibration target. # 7 DISCUSSION AND FUTURE WORK 

Cognitive models of interaction. COGENT represents a simulated user through executable as-sumptions about knowledge, interpretation, state, and action. A researcher can change what the agent remembers, inspect its understanding of a display, or replace a perceptual or motor process while retaining the surrounding interfaces. The atomic demonstrations show concrete instances of these operations. For cognitive science, this supports a workflow in which a proposed mechanism is implemented, its behavioral consequences are traced, and predictions are compared with human observations. Interface studies can use the same structure to examine how a design interacts with different knowledge or attribute configurations. The evaluations address complementary levels of correspondence. Next-action prediction holds observed states fixed and tests human choices; executed trajectories include the consequences of the agent’s own actions; attribute analyses examine internal relationships and their connection to behavior. Task outcomes, action distributions, and sequence correspondence each describe part of interaction. The 43-task A11y comparison includes unsuccessful attempts, while the shared-success analysis targets behavior conditional on all agents succeeding. This distinction makes cohort choice part of the scientific question. 

Calibrating internal dynamics. Calibration needs to address relationship ordering, magnitudes, and associations with behavior. Shared linguistic meanings among attribute definitions and dynamics induced by task experience can both contribute to state relationships. Held-out tasks and participants, simpler update baselines, and multiple independent simulator runs would help distinguish these contributions. Future studies can compare predicted trajectories of frustration, effort, or attentiveness with repeated human reports and test whether the corresponding changes in action emerge under matched conditions. SENSE-42’s neurophysiological measurements provide a further direction for explicit predictions connecting modeled processes to neural observations. 

Module edits and controlling knowledge. The module edits in Appendix D apply the same operation as the demonstrations in Section 4 across a full task set. Under the default configuration, withholding previous-action assessment lowers exact-action agreement ( pH = .010 ) without changing the pooled action distribution ( pH = 1 .000 ), restricting candidates to interface affordances lowers agreement mainly through invalid predictions, and full-screen visual access, step-local memory, and objective-level control produce no detectable change. Follow-up edits can separate assessment from consolidation, examine prediction failures under restricted candidate sources, and activate memory and appraisal through calibration. Modularity can be examined by combining independently specified memories, traits, and process implementations in configurations held out from development. Pretrained knowledge also influences interpretation when the explicit memory store is empty. Unfa-miliar interfaces and separate semantic and procedural interventions would help distinguish declared memory from latent familiarity. Specialized perception, retrieval, appraisal, and motor models could replace LLM-backed operations when there is a specific empirical target, such as a visual-search distribution or movement-time curve. Controlled comparisons across model-call budgets would further clarify the contribution of process organization. 

Population coverage and use. The present evaluations use one model family, selected desktop tasks, and available human reference populations. A11y fidelity targets successful sighted-user interaction; the color-perception demonstration changes information access within the simulator. Extending human reference groups would support comparisons across populations and accessibility needs. Repeated runs, preregistered human studies, and sensitivity analyses across models and prompts can establish when simulated responses preserve the direction and magnitude of an interface 9Preprint effect. # A ARCHITECTURE AND MODULE INTERFACES 

A.1 COGNITIVE MOTIVATIONS AND PROCESSING OPERATIONS 

Two cognitive theories inspired the architecture: ACT-R and Norman’s action cycle. ACT-R explains cognition through specialized perceptual, memory, goal, and motor systems whose coordination depends on information made available through buffers (Anderson et al., 2004). This motivates separating the processes that notice, remember, interpret, choose, and execute, while giving them explicit representations through which to interact. Norman’s account of action distinguishes forming an intention, specifying and executing an action, and then perceiving, interpreting, and evaluating its consequences (Norman, 1986). We use this cycle to organize C OGENT ’s five modules: Observation, Cognition, Control, Action Reasoning, and Execution (Figure 1). A cycle proceeds from observing the interface toward selecting and executing one physical input, unless the modeled user judges the task complete, pauses, or cannot produce an executable action. The next observation supplies evidence about an executed input’s consequences. The modules coordinate through three shared stores. Memory contains long-term facts, procedures, and experiential summaries, together with a bounded working memory of active information and recent experience. Separating stored knowledge from currently available information follows cogni-tive accounts of memory access, while bounding active contents is motivated by working-memory capacity limits (Anderson et al., 2004; Cowan, 2001). The situation model represents the user’s current interpretation of what is happening. We adapt this construct from research on comprehension and memory (Zwaan & Radvansky, 1998) to distinguish an interpreted interface from its observable display. The user-attribute store contains stable traits and dynamic states, each specified by a meaning and value. Traits condition processing across interactions, whereas states can change with experience. These stores provide continuity between cycles and expose distinct targets for intervention. 

Observation and Cognition: from a display to an interpretation. Norman’s distinction between perceiving a system state and interpreting it motivates separate representations of the available display, noticed information, and understood situation (Norman, 1986). Observation captures a screenshot of the current interface. Within Cognition, Perception identifies the regions and cues the modeled user notices and produces a subjective visual workspace. Retrieval uses this evidence and the user’s context to activate items from long-term memory. Comprehension integrates the percept, recalled knowledge, and recent experience into the situation model, including an interpretation of the previous action’s effect. This separation allows the same visible interface to produce different understandings depending on what the user notices and remembers. It also allows an interpretation to remain incomplete or mistaken and to be revised after further interaction. 

Control: from an interpretation to an intention. Evaluating a situation and deciding what to pursue require more than recognizing the visible interface. Following Norman’s distinction between interpretation and evaluation, Monitor assesses whether the session objective has been achieved from the user’s subjective evidence (Norman, 1986). Appraise then updates dynamic states in response to that experience, drawing on appraisal accounts in which an event’s significance for the individual shapes affective responses (Scherer, 2005). Executive uses the situation, monitoring result, and updated attributes to maintain or revise an intermediate intention, or to rest, request help, or give up. The maintained intention provides context for subsequent action selection, consistent with accounts of cognitive control that emphasize the active maintenance of goals (Miller & Cohen, 2001). Separating these operations gives frustration a role in persistence, while Action Reasoning selects the physical input. 

Action Reasoning: from an intention to an operation. Human interaction can draw on remem-bered procedures, information available in the display, and exploratory action. The distinction between knowledge in memory and knowledge available in the environment is central to accounts of interactive behavior (Gray & Fu, 2004; Payne, 1991); exploratory learning supplies another route when a procedure is unfamiliar (Rieman, 1996). Motivated by these accounts, Action Reasoning generates candidates from three sources: recalled executable procedures, noticed interface controls, and tentative probes supported by the current situation. Each candidate retains its source, supporting evidence, and expected outcome. Selection commits to one atomic motor intention, such as clicking 16 Preprint a particular control or entering a specified string. This makes the basis of a choice inspectable and allows memory-based and display-based strategies to coexist within the same architecture. 

Execution: from an operation to feedback. Execution realizes the selected intention as a mouse or keyboard input. Separating selection from realization follows both Norman’s action cycle and ACT-R’s distinction between central and perceptual-motor processing (Norman, 1986; Anderson et al., 2004). A grounding component locates the selected referent, after which the motor component prepares and dispatches the input. The motor implementation can be replaced or perturbed, providing a place to instantiate hypotheses about movement generation and variability (Flash & Hogan, 1985; van Beers et al., 2004). The subsequent observation closes the cycle: Comprehension interprets what changed, and Control evaluates its significance. An executed input is thus recorded separately from its perceived outcome and from the judgment that the task is complete. These theories motivate the functional decomposition and the representations passed between modules. The particular grouping into five modules, the serialized processing schedule, and the use of LLMs within several processes are implementation choices. C OGENT realizes this functional decomposition through typed records and LLM-backed operations, making its processing assumptions available for testing and revision. A.2 INFORMATION BOUNDARIES 

Information boundaries preserve the dependencies between processing stages: action selection draws on perceived controls, and execution realizes the selected intention. Each process receives a declared interface containing outputs from preceding stages and the memory, attributes, or task context specified for its role. Access to shared stores follows the same interfaces, providing continuity across cycles. This design takes inspiration from the mediated exchange of information in ACT-R (Anderson et al., 2004) and makes the effects of an intervention traceable through the processing sequence. 

Perceptual and memory access. Observation captures a single immutable frame for the cycle. Perception receives that image together with task context, working memory, and relevant attributes, and returns noticed regions, state cues, and a masked subjective image. Retrieval receives the resulting cues and the modeled memory store; returned recalls must identify existing items, and an empty store yields no recall. Comprehension receives the subjective image and records, recalled items, working memory, and the previous action record. These inputs define the evidence available for constructing the situation model, so the visible options for later cognitive processing depend on the controls identified by Perception. Preserving the identities of recalled items also allows researchers to distinguish an activated memory record from newly inferred content. 

Evaluation and intention. Control operates on the situation and experience established by Cog-nition. Monitor assesses completion by comparing subjective evidence with the session objective. Appraise receives the interpreted experience, monitoring result, and declared attributes. It updates dynamic states while treating traits as fixed. Executive receives the resulting state and situation, along with permitted task context and working memory, and chooses an intention or a pause. These separate responsibilities distinguish an interpretation of an event, its effect on the user, and the decision about what to pursue next. 

Action selection and physical execution. Action Reasoning receives subjective perceptual evi-dence, the situation, current intention, working memory, recalled procedures, and relevant attributes. Pointer candidates must refer to currently noticed actionable regions, and executable memory proce-dures retain their stored operation templates. Execution receives the selected atomic intention. Its grounding component receives the original screenshot and the selected referent, with its role limited to locating that referent for the fixed operation. Programmatic checks reject changes to the fixed operation and payload before dispatch. This restricted access supports accurate physical grounding while preserving the cognitive decision about what to do. The next observation supplies evidence about the result. These interfaces specify the evidence supplied to each process and make departures from the intended processing path easier to identify. LLM parameters also supply pretrained knowledge: a model may 17 Preprint recognize an icon or infer a procedure when the explicit memory store is empty. Section 7 considers experiments for separating the contributions of supplied information and pretrained knowledge.

D.2 MODELING SCENARIOS AND THEIR EFFECTS 

Perception: make the entire screen available to reasoning. The raw downstream image edit implements an idealized full-access assumption: visual information from every screen region is available to downstream cognition. It replaces Perception’s attention-masked image with the original screenshot while retaining the structured percept and noticed-region records. This allows reasoning to use visual evidence beyond the regions selected by the default perceptual process. Exact-action 21 Preprint accuracy is 58.26% and action-type accuracy is 82.00%; neither differs significantly from full COGENT (pH = .978 and 1.000 ). The JS difference is also not statistically significant ( pH =1.000 ). Thus, this full-access edit produces no statistically significant change in the evaluated fidelity measures. 

Memory processing: reason without carried working-memory records. The memoryless edit models a user whose working-memory contents do not persist between processing cycles and whose stored knowledge does not supply recalled procedures. It clears working-memory records before each cognitive cycle, disables retrieval and memory-based action proposals, and removes the preference for memory candidates. The supplied recent screenshot–action history remains available. Because authored long-term memory is empty in the full configuration, the active contrast primarily concerns carried working-memory contents. Exact-action accuracy is 56.87% and action-type accuracy is 81.40%; neither accuracy difference nor the JS difference is statistically significant (all pH = 1 .000 ). 

Control: maintain a fixed task-level intention. The objective-only control edit models a user who pursues the stated task objective without forming intermediate intentions. The Executive maintains the objective itself as the current intention and does not select meta-actions such as requesting help; Appraisal is frozen. With no configured dynamic attributes, the active change concerns executive control. Exact-action accuracy is 58.73% and action-type accuracy is 82.02%. Although both point estimates exceed the full configuration’s, the differences are not statistically significant after correction ( pH = .161 and 1.000 ), and neither is the JS difference ( pH = 1 .000 ). The results therefore provide no significant improvement on the primary accuracy measures. A secondary analysis finds higher annotated-valid action accuracy, at 61.54% versus 59.87%, a gain of 1.67 percentage points (exploratory unadjusted p = .009 ). This measure credits any annotated workable action, including alternatives to the recorded human choice. 

Action Reasoning: consider only interface-grounded candidates. The interface-only action edit models a user whose action choices are generated from recognized interface affordances, without separate memory-based or exploratory proposals. It restricts Action Reasoning to the interface candidate source. Since the full configuration generates no memory candidates in this experiment, the operative restriction removes exploratory proposals. Exact-action accuracy falls to 53.11% and action-type accuracy to 75.84%, significant reductions of 4.21 and 5.36 percentage points (both 

pH = .010 ). JS distance does not change significantly ( pH = 1 .000 ). The invalid-output rate increases by 7.24 points (exploratory unadjusted p = .001 ). On the 5,468 decisions where neither condition has an adapter error, the exact-accuracy difference is +0 .11 percentage points and is not statistically significant (Table 8). This pattern links the aggregate accuracy loss to the reliability of producing a valid prediction when candidate sources are restricted. 

Comprehension: interpret the current screen without assessing the preceding action. The no lagged feedback edit models a user who interprets the current interface without explicitly evaluating whether the previous action produced its expected outcome. It withholds prior-action records from Comprehension’s assessment process and suppresses the resulting outcome assessment and experience records. Current-screen interpretation and action history for other processes remain available. Exact-action accuracy falls to 53.63%, a significant reduction of 3.69 points ( pH = .010 ); action-type accuracy and JS distance do not change significantly (both pH = 1 .000 ). On the 5,905 decisions where neither condition has an adapter error, exact accuracy remains 3.88 percentage points lower, a statistically significant reduction under the exploratory, unadjusted comparison (Table 8). Of the 223 lost exact matches, 106 concern human stopping decisions, illustrating how explicit outcome assessment can affect when the simulated user stops as well as which physical action is predicted. D.4 IMPLICATIONS FOR SIMULATION 

These edits specify alternative processing assumptions whose consequences can be examined across tasks. Restricting action candidates and removing explicit previous-action assessment significantly reduce exact-action agreement in this configuration, whereas full-screen visual access, removal of carried memory, and objective-level control yield no statistically significant changes on the primary accuracy measures after correction. None of the five edits significantly changes pooled action-type JS distance. The contrast between these measures shows why evaluating edits requires both action-level agreement and aggregate distributions: changes in when an action occurs, whether a valid prediction is produced, or when a user stops can coexist with similar overall action frequencies. The findings apply to a bounded-history configuration with empty authored memory and attributes. Calibration memory, active dynamic states, and longer interaction histories provide further settings in which to examine the same edits. The five replicates capture repeated model predictions over the same task corpus; additional models and task domains would broaden the settings in which these processing assumptions can be examined. 23 Preprint
