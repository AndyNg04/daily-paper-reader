## 摘要
基础模型能够对复杂的物理任务进行推理，但如何将这种智能转化为可靠的机器人执行仍面临挑战。我们认为，一个关键但常被忽视的因素是机器人使用接口（RUI），它决定了智能体如何表达并执行物理动作。为系统研究其影响，我们提出 RUIBench，其中包含 30 项操作任务，分属五个任务套件，涵盖世界知识、上下文学习、探索发现、动态交互和接触丰富的操作。我们还开发了 RUIKit，这是一个统一框架，将六种动作抽象与两种交互形式相结合，在共享感知与控制条件下构成 13 种接口。在仿真中，仅改变 RUI，就能使前沿智能体的成功率从 45% 提升至 81%，并使经过微调的 4B 模型的成功率从 13% 提升至 47%。我们的分析表明，有效的接口能够减少不必要的决策，同时保留必要的反馈，其效果受智能体行为和物理不确定性的影响。我们还发现了验证差距：智能体常在出现可观测失败的情况下仍宣称任务成功，这表明除了对单个动作进行验证之外，还需要进行任务级验证。总之，这些发现确立了 RUI 设计在具身智能体可靠性中的关键作用。

## Abstract
Foundation models can reason about complex physical tasks, yet translating this intelligence into reliable robot execution remains challenging. We argue that a critical, often overlooked factor is the robot-use interface (RUI), which determines how agents express and execute physical actions. To systematically study its impact, we introduce RUIBench, comprising 30 manipulation tasks across five suites spanning world knowledge, in-context learning, discovery, dynamic interaction, and contact-rich manipulation. We further develop RUIKit, a unified framework that crosses six action abstractions with two interaction forms, yielding 13 interfaces under shared perception and control. In simulation, changing only the RUI shifts a frontier agent's success rate from 45% to 81%, and that of a fine-tuned 4B model from 13% to 47%. Our analysis reveals that effective interfaces reduce unnecessary decisions while preserving essential feedback, with their benefits shaped by agent behavior and physical uncertainty. We further uncover a verification gap, where agents frequently declare success despite observable failures, revealing the need for task-level verification beyond individual actions. Together, these findings establish RUI design as a critical factor in embodied agent reliability.

## 1. 核心问题与研究动机

- **基础模型会规划，不代表机器人能可靠执行。** 同一个任务可以通过逐步移动夹爪、指定末端位姿、调用抓取技能，或编写带反馈的程序来完成。这些接口不仅改变指令的表达方式，也决定了哪些决策由模型承担、哪些可以交给执行端，以及出错后何时有机会纠正。
- 论文把**机器人使用接口**（Robot-Use Interface，RUI）作为独立的实验变量。以往的具身基准多在固定接口下比较模型，而不同系统往往同时更换感知、控制和动作接口，难以判断性能差异究竟来自哪里。
- 论文给出的答案不是“抽象越高越好”或“程序一定优于逐动作调用”，而是：**好的接口应减少不必要的模型决策，同时让关键反馈能及时改变下一步动作；任务是否完成，则需要另行核验。**

## 2. 方法论：RUIBench 与 RUIKit

- **RUIBench 定义任务和评测协议。** 智能体可以读取任务说明、提示和适用的演示，但不能直接访问仿真器中的物体真值。运行时主要通过 RGB-D 图像和机器人状态感知场景：用 SAM 3 检测和分割物体，再用带噪深度恢复三维位置。
- **RUIKit 将接口拆成两个维度。**
  - **动作抽象：一次动作指定什么？** 六种表示分别是关节角（Joint）、相对平移或旋转（Delta）、固定幅度步进（Step）、绝对末端位姿（Pose）、图像像素点（Point）和预定义语义技能（Skill）。它们不构成严格的层级，例如 Delta 更便于局部微调，而 Skill 可封装完整的抓取或放置操作。
  - **交互形式：何时把控制权交回模型？** 逐动作模式下，每次回复对每条机械臂至多发出一个动作；程序模式下，模型在沙箱中执行 Python，可组合相同的动作原语，并用循环、分支和中途观测调整后续动作。**技能封装单个操作，程序组织多个操作，两者可以组合。**
  - 两个维度交叉得到 **12 种固定接口**，另加开放全部动作抽象与交互形式的 **RUI-Free**。在固定智能体和任务的比较中，评测协议、感知与控制后端以及 24 个共享工具保持一致。
- **评测流程**：初始化任务 → 模型观察并发出动作或程序 → 执行并返回反馈 → 模型继续、宣告完成或放弃，亦可因达到预算而终止 → 独立评分。仿真中每次模型回复计入固定 **8 秒**，这期间机械臂保持姿态，但环境继续演化。评分器检查目标是否达成、任务规则是否遵守、是否出现物理仿真异常；评分结果不告知智能体，`task_done` 也不等于任务成功。

## 3. 实验设计：任务、场景与对照

- **基准任务**：RUIBench 包含 **30 项操控任务**，分为五类，每类 6 项：世界知识（如汉诺塔）、上下文学习（如按图搭房子）、探索发现（如寻找藏起来的物体）、动态交互（如 Simon Says）和富接触操控（如插显卡）。每项任务有 15 个开发实例和 20 个测试实例，主实验使用前 5 个测试实例。
- **仿真与真机**：仿真基于 Isaac Sim / Isaac Lab，25 项任务使用单台 Franka Research 3，5 项使用双 ARX X5。真机实验在单台 Franka Research 3 上进行，每类选一项任务，每项使用 5 种固定布局，按真实时间运行，由人工依据书面标准独立评判。
- **比较对象**：两种前沿编码智能体 Claude Code（Claude Opus 5.5）和 Codex（GPT-6 Astra）均比较全部 13 种接口；小模型 Qwen3.5-4B 比较 12 种固定接口下的零样本与 LoRA 微调表现。小模型未评测 RUI-Free，因为没有对应训练数据。
- **消融与诊断**：在逐动作和程序之间加入“**动作序列**”对照：可批量执行，但中途不能观测，执行结束后才返回结果。另比较技能执行后的“不检查、报告失败、报告并自动纠正”，并用独立的事后评审判断智能体误报成功时，失败是否已能从它收到的最终画面中看出。

## 4. 资源与算力

- **微调数据**：每种固定接口训练一个 LoRA 适配器，共 12 个；每个使用 300 条轨迹，其中 90 条来自 Qwen3.8-Max 的成功回合，210 条来自脚本策略。约半数脚本回合注入执行偏差并演示恢复，训练与测试种子不重叠。
- **训练配置**：LoRA 秩为 64、缩放参数为 128，视觉编码器冻结；训练 10 个 epoch，学习率为 \(10^{-4}\)，采用余弦衰减，每批 32 个请求。
- **成本披露**：附录列出的租赁计价为 H200 **2.68 美元/GPU 小时**、B200 **4.06 美元/GPU 小时**。每种接口的一次性微调成本约 **200–900 美元**；小模型推理按一张常驻 GPU 的整回合运行时间计费，包含机器人执行时间。
- **未披露项**：论文未明确报告各次训练实际使用的 GPU 数量、具体训练时长或总 GPU 小时，也未披露前沿 API 模型的服务端算力。因此，租赁成本不能直接视为完整的算力报告。

## 5. 实验数量与充分性

| 实验 | 规模 |
|---|---:|
| 前沿智能体仿真主实验 | 2 个智能体 × 13 种接口 × 30 项任务 × 5 个实例 = **3,900 回合** |
| 4B 小模型仿真评测 | 12 种接口 × 150 回合 = **每种评测设定 1,800 回合**，分别报告零样本与微调 |
| 真机评测 | 2 个智能体 × 13 种接口 × 5 项任务 × 5 种布局 = **650 回合** |
| 交互形式消融 | 3 种执行形式各 **90 回合** |
| 动作级检查消融 | 3 种检查设定各 **60 回合** |
| 任务负对照 | **70 个任务实例**；完整脚本全部成功，移除相应信息后仅成功 6 个 |

- **主实验适合回答“接口是否重要”**：在同一任务实例上配对比较，复用感知与控制栈，并独立评定结果，减少了场景难度、系统实现和智能体自报造成的混淆。
- **证据不足以给出普适的接口排名**：主实验每项任务只用 20 个测试实例中的 5 个，关键消融和完成判断诊断只用首个测试实例。真机回合虽多，却集中在同一机械臂与 5 项任务上；主要结果以点估计呈现，小幅差异不宜过度解读。

## 6. 主要结论与发现

- **接口造成的性能差异可以大于所测智能体的平均差距。** Claude Code 在仿真中的成功率随接口从 **45.3%（逐动作 Step）到 80.7%（Program-Delta）**，相差 35.4 个百分点；两种前沿智能体跨接口平均只差 2.1 个百分点。Codex 的最佳配置则是 **RUI-Free（80.7%）**，说明最佳接口取决于智能体如何使用它。
- **批量执行和程序内反馈有互补收益。** 在 Claude Code 的 Delta、Step、Point 消融中，逐动作、无中途观测的动作序列、可观测并分支的程序，成功率依次为 **57.8% → 65.6% → 75.6%**，中位回复轮数为 **29 → 16.5 → 14**。但程序的收益并不自动出现：Claude Code 平均每段程序执行 3.3 个动作，Codex 仅 0.9 个；两者从程序模式获得的平均成功率增益分别为 **11.0** 和 **2.7** 个百分点。
- **小模型更容易学会直接指定目标的接口。** Qwen3.5-4B 跨固定接口平均从零样本的 **1.9%** 提升至微调后的 **27.3%**。微调后，逐动作 Joint 为 **12.7%**，逐动作 Pose 达 **46.7%**，逐动作 Skill 为 **41.3%**。程序模式平均低于逐动作模式（**25.1% 对 29.6%**）。这里的接口间差距比较的是**分别训练的适配器**，不是同一个微调权重在测试时直接切换接口。
- **仿真优势不一定迁移到真机。** 在五项对应任务上，Claude Code 的程序模式在仿真优于逐动作模式（**90.0% 对 66.7%**），到真机却落后（**36.0% 对 42.0%**）。两种智能体在真机上的最佳动作抽象均为 Delta。真机案例显示，深度噪声、标定偏差和抓取滑移会让“放置后观察并微调”比直接执行完整计划更重要。
- **看见失败，不等于会据此判断任务未完成。** Claude Code 和 Codex 在**失败回合**中仍宣告完成的比例分别为 **82.1%** 和 **70.9%**。在可用最终画面评判的 23 项任务上，独立评审仅凭智能体已收到的图像，就能识别两者 **70.2%** 和 **80.9%** 的错误完成声明。报告动作失败或自动重试虽减少了误报，却没有提高任务成功率：例如，每块多米诺骨牌都放下了，不代表整条链能按要求倒下。

## 7. 优点

- **交叉设计让解释更清晰。** 同一动作原语可用逐动作或程序方式调用，比比较两套端到端系统更能说明差异来自动作表示，还是来自执行与反馈的组织方式。
- **既测结果，也测执行过程。** 成功率、回复轮数、API 成本和完成声明分开统计，能够区分“做得慢”“做不成”和“没做成却认为成功”。
- **用负对照和真机实验检验基准。** 移除演示或中途观测后，脚本成功率大幅下降，支持任务确实需要预期的信息；真机结果则检验了仿真排名能否迁移，而不是默认两者一致。

## 8. 不足与局限

- **真机外推有限。** 真机只覆盖单臂、单站点与 5 项任务，没有验证仿真中的双臂任务。真实物体、计时方式和评分流程也与仿真不同，因此不能把性能下降完全归因于某一种传感误差或控制问题。
- **结果依赖智能体与接口的匹配。** 两个前沿智能体使用程序的方式明显不同；小模型则为各接口单独微调，训练轨迹虽等量，但示范质量与决策结构不一定等价。仿真统一采用每回复 8 秒，有利于受控比较，但也会影响多轮交互在动态任务中的相对代价。
- **反馈消融不是对观测能力的完全隔离。** 完整程序相比动作序列还可循环、分支并据观察调整执行，因此额外收益更适合解释为**可用于调整动作的程序内反馈**，而不能全部归因于多看了几帧。
- **任务级验证仍未解决。** 事后视觉评审排除了最终帧难以判定结果等情形，不能替代对过程约束、时序或物理接触的核验。论文展示了验证缺口，但没有验证一个通用的在线任务级验证器。
- **富接触和快速动态任务仍难。** 插显卡、折叠衣物等任务对微小位姿误差敏感，部分动态任务又要求快于模型回复的反应。仅更换高层接口未必足够，还需要更快的局部闭环、更精细的感知或更低层的控制。
