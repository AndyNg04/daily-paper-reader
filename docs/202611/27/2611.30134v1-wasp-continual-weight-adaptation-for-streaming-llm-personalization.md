## 摘要
个性化大语言模型（LLM）应持续适应用户不断变化的偏好。然而，如何从含噪的交互历史中提取偏好变化，同时支持低成本更新，仍是一项挑战。我们提出 WASP（流式个性化权重适配），这是一种循环框架，可直接从原始用户交互中捕捉细粒度偏好，并生成个性化 LoRA 适配器，而无需进行成本高昂的逐用户优化。具体而言，WASP 通过训练一个共享超网络来实现这一目标：该网络维护紧凑的用户表示，并通过一次前向传播输出适配器权重。随着新交互不断到来，WASP 会更新这一表示，而无需重新处理完整的交互历史，从而实现持续适配，且每次更新的成本不受历史长度影响。在个性化基准和按时间顺序排列的交互流上的实验表明，在计算和存储预算固定的情况下，WASP 能够在较长时间跨度内维持高质量的个性化效果。总体而言，这些结果证明了流式个性化的高效性，并有助于实现注重隐私保护的端侧部署。

## Abstract
Personalized large language models (LLMs) should continually adapt to users' evolving preferences. Yet extracting preference changes from noisy interaction histories while supporting inexpensive updates remains challenging. We introduce WASP (Weight Adaptation for Streaming Personalization), a recurrent framework that captures fine-grained preferences directly from raw user interactions and generates personalized LoRA adapters without expensive per-user optimization. Specifically, WASP achieves this by training a shared hypernetwork that maintains a compact user representation and outputs adapter weights in a single forward pass. As new interactions arrive, WASP updates this representation without reprocessing full interaction history, enabling continual adaptation with per-update costs independent of history length. Experiments on personalization benchmarks and chronological interaction streams show that WASP sustains high-quality personalization over long horizons under fixed compute and storage budgets. Together, these results support efficient streaming personalization and facilitate privacy-preserving on-device deployment.

# WASP：面向流式大语言模型个性化的持续权重适配

## 1. 核心问题与研究动机

- **核心问题**：当用户偏好逐渐变化、相关信号又分散在大量交互中时，如何让大语言模型吸收新证据、保留仍然有用的旧偏好，同时避免每次更新都重读历史或重新微调？
- **现有方案的取舍**：全历史提示会占用上下文窗口，并增加生成成本；检索和摘要可以缩短输入，但可能遗漏细粒度信号；逐用户 LoRA 微调把偏好移出提示词，却需要为每个用户执行优化，持续更新时开销较高。
- **论文的核心思路**：把个性化从“反复读取历史”转为“持续更新固定大小的用户状态”。WASP 用一个跨用户共享的超网络（即输出模型权重的网络）读取新增交互，并从更新后的状态生成个性化 LoRA。**在新增数据量有上限时，单次更新成本不随累计历史长度增长**；这并不意味着累计计算量不随交互次数增加。

## 2. 方法论：从新增交互到个性化权重

1. **先学习任务，再学习个性化。** 作者先用训练用户的问答对训练一个共享 LoRA，不输入用户历史；随后把它合并到 Qwen2.5-7B-Instruct，并冻结主模型。这样，同一任务内的个性化收益更容易与“学会任务格式”的收益区分开。
2. **用结构化潜在 token 表示用户。** 用户状态由 \(L\times 2M\times R\) 个向量构成，分别对应主模型的层、被适配的模块、LoRA 的 A/B 因子和秩分量。初始 token 是可学习的层嵌入与槽位嵌入之和。默认 LoRA 秩为 8，适配注意力的 `q_proj` 和 `v_proj`。
3. **只编码新交互，用注意力更新旧状态。** 每次更新先用学习到的门控，将上一轮用户状态与初始结构嵌入按比例混合。冻结主模型对新交互做逐 token 编码，再对各层隐状态取平均并投影。超网络先让同一槽位在不同主模型层之间做自注意力，再通过交叉注意力读取新增交互。相比对所有状态 token 做全连接注意力，跨层分组减少了注意力配对数。
4. **一次前向生成 LoRA，无需逐用户反向传播。** 更新后的 token 一方面作为下一轮的用户状态，另一方面由模块和因子专用的线性头解码为 LoRA 权重。共享超网络在离线阶段端到端训练，不需要预先优化好的用户适配器作为监督。训练目标包含下游回答损失，以及当个性化模型比冻结基座表现更差时增大的损失差惩罚。
5. **用“惊讶度”决定何时更新。** 系统比较当前个性化模型和基座对新观察到的真实回答的损失，对差值做归一化并累计；超过阈值时，批量处理待更新交互并清零累计值。阈值较低通常更新更频繁。这个机制依赖观察到回答或等价的监督信号；触发时的成本也取决于缓冲了多少新数据，而不只取决于是否触发。

## 3. 实验设计：数据集、基准与对照

| 实验场景 | 数据集与任务 | 评估方式 |
|---|---|---|
| 静态个性化 | **LaMP + LongLaMP，共 10 项任务**：3 项分类、1 项评分预测、6 项文本生成 | 使用固定、非时序历史生成适配器；分别在随机用户划分和分布外（OOD）用户划分上测试。指标包括准确率、F1、MAE、RMSE 和 ROUGE |
| 持续个性化 | **Amazon Reviews 2023（Amazon23）**评论生成；**时序 LongLaMP 摘要生成（AbsGen）** | 按时间切块，用前序块预测下一块。每块最多 8 条交互或 4,096 token；每项任务有 200 名测试用户。先按用户汇总、再对用户平均，并报告 ROUGE、METEOR 和 BLEU |
| 显式偏好变化 | 基于 **MovieLens 25M** 构造的半合成数据 | 用两个交互块建立、确认或反转电影类型偏好；分别测试偏好重申、修订和保留，共 3,000 个评估 episode |

- **对照方法**：无个性化基座；上下文方法 Full-History、BM25 RAG 和画像增强 PAG；参数方法 MT-LoRA 和逐用户微调 OPPU；超网络方法 P2P 和 SHINE。效率实验还纳入反复重建画像的 P2P-reappend，以及逐块生成并累积适配器的 SHINE-R。
- **关键的内部对照**：静态基准中的 WASP 从给定历史直接生成适配器；时序实验中的静态 WASP **只看首块**，之后不更新。后者与递归 WASP 的对比检验的是“持续吸收新交互是否有用”，并不等于在相同历史访问条件下比较递归与全历史重算。

## 4. 资源与算力

- **硬件**：训练使用 **32 张 NVIDIA H20 GPU**；推理使用 **8 张 NVIDIA RTX PRO 6000 Blackwell GPU（单卡 96 GB）**。论文未披露训练墙钟时长、总 GPU 小时、能耗或实际终端设备上的运行数据。
- **训练规模**：静态设置先做 4,000 步任务适配，再训练超网络 20,000 步，批大小均为 64。持续设置的任务适配为 1,200 步；递归版本从静态模型初始化，最多训练 4,000 步，每批 32 个 episode，并在最长 16 块的训练序列上反向传播。**无需逐用户训练指的是部署后的适配，不代表共享模型的训练成本低。**
- **运行开销**：论文报告每用户固定存储 **8.7 MB**。在累计历史达 20K token 时，P2P 重建画像和生成权重的更新 FLOPs 约为 WASP 的 **3.5 倍**，从累计历史重新微调的 OPPU 则超过 **100 倍**。固定秩适配器的生成 FLOPs 与无个性化基座相当，但报告的峰值内存仍多 **2.2 GB**；这些结果不能直接换算成手机上的延迟或功耗。

## 5. 实验数量与证据充分性

- **覆盖规模**：主实验包括 10 项静态任务的两种用户划分、2 项真实时序任务和 1 项半合成偏好修订任务。另有历史长度、用户历史打乱、效率扩展性、注意力分组、更新阈值、任务适配和历史编码器等至少 7 类补充分析。按“任务 × 划分”计，静态部分有 20 个评估组合，但并非 20 次独立复现。
- **较公平的设计**：主对照共享任务适配后的基座；静态方法接收相同历史；时序评估禁止访问未来交互，并按用户等权汇总。Full-History 在效率评估中复用 KV 缓存，不是每次从零重算。
- **仍不充分的部分**：真实时序实验只有评论和学术摘要两个场景。OPPU 每次从基座重训，不代表所有在线 LoRA 更新方法的成本；效率表虽覆盖部分流式基线，但质量主表没有在匹配更新预算下全面比较这些方法。主要结果也未给出置信区间或多随机种子方差，因此小幅领先不宜视为稳健优势。

## 6. 主要结论与发现

- **静态分类是最明确的优势。** WASP 在随机划分上的平均准确率/F1 为 **74.2%/67.9%**，在 OOD 划分上为 **70.2%/61.2%**，均为表中最高。相对 Full-History，分别提高 **11.7/12.9** 和 **8.1/10.4** 个百分点。但它没有赢下所有单项任务；生成方面更接近“有竞争力”：随机划分的平均 ROUGE-1 并列第一，OOD 划分的整体生成均分并不领先。
- **按时间更新有益，但并非全面胜过所有基线。** 递归版比仅看首块的 WASP 在两项任务的全部 8 个指标上都更好。相较所有对照，Amazon23 的 4 个指标中有 3 个最佳；AbsGen 的两项 ROUGE 最佳，但 METEOR 和 BLEU 不及 Full-History。随交互推进，递归版相对静态版的优势总体扩大，支持其能持续利用新证据，但不能仅凭曲线确定具体旧偏好是否被保留。
- **有用户特异性的直接证据。** 在“正确历史同时不劣于打乱历史和无个性化基座”的检验中，WASP 的十任务汇总比例为 **58.0%**，略高于 SHINE 的 **57.7%**；不同用户适配器的余弦相似度也更低。半合成 MovieLens 上，递归版的偏好反转准确率为 **100%**、保留准确率为 **99.7%**，但这些结果限于受控的两块交互设置。
- **更简单的架构已足够。** 仅用跨层自注意力的设计整体优于加入层内混合的变体。惊讶度阈值 \(h=0.25\) 比 \(h=1\) 在四项平均指标上略好，支持更新频率与质量之间存在权衡，但两个阈值不足以刻画完整的成本—质量曲线。

## 7. 优点

- **把用户历史长度与单次适配开销解耦。** 固定大小的状态和固定秩适配器，使系统既不必扫描完整历史，也不必随交互增加而叠加更多 LoRA；这是比单一基准分数更有实际意义的设计贡献。
- **把任务能力、用户差异和偏好变化分开检验。** 任务适配基座控制格式学习；打乱历史检验模型是否真的利用了目标用户的信息；受控偏好反转则检验模型能否修改某一项偏好，同时保留未变的偏好。
- **同时评估质量与部署开销。** 论文报告了更新和生成 FLOPs、峰值内存及每用户存储，有助于判断方法何时值得用，而不只说明它在某个任务上分数更高。

## 8. 不足与局限

- **真实助手场景覆盖有限。** 评论和学术摘要主要反映写作风格、主题及评价倾向，不等同于长期多轮助理对话。半合成实验中的标签明确、偏好突然反转且历史很短，不能据此推断模型能处理稀疏、含蓄、相互冲突或逐渐变化的偏好。
- **评测指标不能完全衡量偏好对齐。** ROUGE、BLEU 等主要衡量与参考文本的重合，难以判断回答是否真正符合个人意图。论文也未充分量化错误反馈、异常交互或近期样本偏差对状态的影响。在线更新假定能取得真实回答；若只把助手自己的输出当成反馈，现有结果不能说明系统仍会正确适配。
- **固定状态的长期记忆容量尚不明确。** 固定大小带来可预测的开销，但稀有旧偏好何时会被覆盖、经历多次反转后能否恢复，仍缺少直接测量。主要结果也只验证了单一规模的主模型和固定秩 LoRA，跨模型及其他高效适配方法的泛化尚未建立。
- **端侧与隐私仍是潜力，不是已验证的部署结果。** 实验运行在高显存 GPU 上，未测量手机等设备的延迟、能耗或热限制。原始历史可以留在本地，并不意味着用户状态或 LoRA 权重不会泄露敏感信息；论文没有提供正式隐私保证或泄漏评估。
