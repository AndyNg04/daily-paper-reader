Abstract 

Personalized large language models (LLMs) should continually adapt to users’ evolving preferences. Yet extracting preference changes from noisy interaction histories while support-ing inexpensive updates remains challenging. We introduce WASP ( Weight Adaptation for 

Streaming Personalization), a recurrent frame-work that captures fine-grained preferences di-rectly from raw user interactions and generates personalized LoRA adapters without expen-sive per-user optimization. Specifically, WASP achieves this by training a shared hypernetwork that maintains a compact user representation and outputs adapter weights in a single for-ward pass. As new interactions arrive, WASP updates this representation without reprocess-ing full interaction history, enabling continual adaptation with per-update costs independent of history length. Experiments on personaliza-tion benchmarks and chronological interaction streams show that WASP sustains high-quality personalization over long horizons under fixed compute and storage budgets. Together, these results support efficient streaming personaliza-tion and facilitate privacy-preserving on-device deployment. 

1 Introduction 

Large language models (LLMs) have demonstrated remarkable generative capabilities, yet their one-size-fits-all nature limits their ability to meet the needs and preferences of individual users. LLM personalization addresses this limitation by using a user’s interaction history to tailor model responses to their preferences (Salemi et al., 2024b; Liu et al., 2025). However, tracking evolving preferences through long, noisy interaction histories is chal-lenging because relevant signals are often implicit and scattered across many interactions (Jiang et al., 2025; Kim and Kim, 2026). Moreover, interaction histories may contain sensitive information, mak-ing it desirable to keep them on the user’s device. Assistant

Practical personalization must therefore capture fine-grained preferences while supporting inexpen-sive updates as histories grow. Meeting these re-quirements would enable efficient streaming per-sonalization and facilitate on-device deployment, allowing sensitive user data to remain local (Liu et al., 2025; Tan et al., 2026) (Figure 1). Existing personalization methods often condi-tion generation on full user histories, retrieved in-teractions (Kumar et al., 2024), or summarized pro-files (Richardson et al., 2023). As histories grow, processing this historical context increases infer-ence latency and consumes valuable context win-dow capacity. Moreover, as new interactions arrive, these methods must repeatedly reprocess the accu-mulated history to incorporate new user evidence. Alternatively, some methods encode user prefer-ences into lightweight, user-specific parameters (Tan et al., 2024b; Zhang et al., 2025). While this reduces the need to include histories in the context, conventional per-user fine-tuning requires separate optimization and parameter storage for every user, making it costly to support large numbers of users. Updating these parameters also requires retraining, making continual adaptation costly as preferences 1arXiv:2611.30134v1 [cs.AI] 23 Nov 2026 evolve (Tan et al., 2026). Such training can incur substantial latency on resource-constrained devices, while offloading it to the cloud raises concerns about exposing sensitive user data (Wang et al., 2025). Together, these limitations expose a central challenge: how can a personalized model incorpo-rate new user evidence while retaining useful past information without repeatedly reprocessing the full interaction history? To address this challenge, we propose WASP, a recurrent framework that represents each user with a fixed-size set of parameter-structured latent to-kens. These tokens persist across updates and serve as a compact user state that captures the user’s evolving preferences. At each update step, a hyper-network uses the current user state to attend directly to token-level representations of newly arrived in-teractions. This allows the framework to extract new evidence about the user and incorporate it into the state. The updated tokens then form the user state for the next step and are decoded into per-sonalized LoRA adapter weights (Hu et al., 2022) in a single forward pass. In this way, the latent tokens retain useful information from past interac-tions, incorporate new evidence, and generate an updated personalized adapter without reprocessing the entire interaction history. This recurrent de-sign supports effective personalization over a long interaction horizon under fixed compute and stor-age budgets, facilitating on-device deployment that keeps sensitive user histories local. We evaluate WASP on LaMP (Salemi et al., 2024b), LongLaMP (Kumar et al., 2024), and chronological user interaction streams (Hou et al., 2026; Tang et al., 2008). Across these settings, WASP achieves the strongest average classification performance, remains competitive on long-form generation, and generalizes to unseen users. More importantly, WASP adapts effectively to incoming interactions through recurrent updates and main-tains stable performance as histories grow. With a fixed-size user state and bounded update costs, WASP supports efficient, continual personalization suitable for resource-constrained on-device deploy-ment. 

2 Related Work 

LLM Personalization. LLM personalization leverages users’ interaction histories to infer their preferences and tailor model responses (Salemi et al., 2024b; Liu et al., 2025). Context-based meth-ods retrieve relevant past interactions or summarize histories into textual profiles, which are included in the model’s input to guide generation (Kumar et al., 2024; Richardson et al., 2023; Salemi et al., 2024a; Qiu et al., 2025). These approaches can be further enhanced through RL-based reasoning and user modeling (Wu et al., 2025; Amirizaniani et al., 2026; Zhao et al., 2025; Wan et al., 2025; Nam et al., 2026; Salemi et al., 2025). Alternatively, parameter-based approaches encode user prefer-ences in user-specific adapters, group-level LoRAs, or representation interventions (Tan et al., 2024b,a; Zhang et al., 2025; Liu et al., 2026a; Tan et al., 2026). While these methods capture user hetero-geneity, efficient adaptation over growing interac-tion histories remains challenging. 

Continual Personalization. Continual personal-ization tracks preference drift while retaining rele-vant past information (Li et al., 2026). Parameter-update methods constrain forgetting through reg-ularization (Kirkpatrick et al., 2017; Wang et al., 2023), discount outdated feedback (NS-DPO), lo-calize LoRA edits (RAIE), or distill follow-up user messages (SDPO) (Son et al., 2025; Zeng et al., 2026; Kleine Buening et al., 2026). SPRInG combines selective fine-tuning with replay re-trieval, while TAP-PER optimizes compact user prefixes (Kim and Kim, 2026; Cao et al., 2026). These approaches still incur gradient-based adap-tation costs. Alternatively, AI Persona revises tex-tual profiles, and PAHF updates preference records from clarification and corrective feedback (Wang et al., 2024; Liang et al., 2026). These methods avoid weight updates but still rely on stored textual context to condition generation. These limitations motivate amortized adaptation that encodes evolv-ing preferences directly in model parameters. 

Context-to-Parameter Adaptation. Hypernet-works generate model parameters from context to amortize adaptation (Ha et al., 2017). P2P maps summarized user profiles to personalized Lo-RAs (Tan et al., 2026), while task-conditioned hy-pernetworks generate adapters from task embed-dings, descriptions, demonstrations, or unlabeled prompts (Karimi Mahabadi et al., 2021; Charakorn et al., 2025; Phang et al., 2023; Liang et al., 2025). Doc-to-LoRA and SHINE distill encoded context into adapters using Perceiver and Transformer hy-pernetworks, respectively (Charakorn et al., 2026; Liu et al., 2026b), while HY-WU uses structured parameter tokens for conditional weight genera-2Figure 2: WASP generates updated LoRA weights from a fixed-size user state by processing only the incoming interactions at each step. (a) Parameter-structured LoRA tokens carry the user state across updates. (b) Each WASP step combines inter-layer self-attention with cross-attention to new evidence. (c) Module-specific heads decode the updated tokens into LoRA adapters. 

tion (Tencent HY Team, 2026). Most of these meth-ods compile context snapshots without explicitly modeling how the context evolves over time. In continual settings, updating snapshot adapters can require reprocessing accumulated history. Genera-tive Adapter instead accumulates context-derived weight updates in a fixed-size additive state without an explicit forgetting gate (Chen et al., 2025), while Doc-to-LoRA and SHINE-R concatenate chunk-level adapters, increasing effective rank and per-user storage (Charakorn et al., 2026; Liu et al., 2026b). These update and storage costs limit their suitability for streaming personalization, motivat-ing a fixed-size recurrent preference state that sup-ports selective revision.

We address two challenges: (1) mapping raw query–response sequences to effective adapters that capture fine-grained preference signals; and (2) enabling the adapter to evolve online, integrating new evidence while retaining relevant past information, at a cost independent of history length for a fixed amount of new data.

To separate personalization gains from those due to learning task formats, we first adapt the pre-trained backbone W0 to the target tasks, follow-ing OPPU (Tan et al., 2024b). 4.3 Continual Preference Updates 

Static generation reconstructs an adapter from the available history at every update. To avoid repeat-edly encoding the accumulated history, we instead carry the latent preference tokens across successive interactions.

Surprise-based update. Updating after every chunk is unnecessary when the user’s preferences remain consistent with the current adapter. For each incoming query–response pair, we measure surprise as the difference between its response loss under the current personalized model W ⊕ ∆W

and under the task-adapted base model W . We average and normalize these differences over Ct to obtain ut, then accumulate the resulting surprise: 

St = max(0 , S t−1 + ut), update if St ≥ h. (7) When an update is triggered, all pending interac-tions are processed together and St is reset. The threshold h controls the trade-off between update frequency and personalization quality. 

5 Experiments 

We study WASP in two settings. Static person-alization tests whether our hypernetwork can ef-fectively map interaction histories to personalized adapters; we therefore evaluate WASP stat on fixed, non-chronological interaction histories. Continual personalization tests whether the recurrent user state can incorporate new evidence while retaining useful past information; we evaluate WASP cont on chronologically ordered interactions. 

Datasets. For static personalization, following P2P (Tan et al., 2026), we deploy LaMP (Salemi et al., 2024b) and LongLaMP (Kumar et al., 2024). LaMP comprises three classification tasks, one rating-prediction task, and three text-generation tasks, while LongLaMP comprises three long-form generation tasks. Each instance contains a user interaction history, a query, and a ground-truth re-sponse. For continual personalization, we study two long-form text-generation tasks: review genera-tion on Amazon Reviews 2023 (Amazon23) (Hou et al., 2026) and temporal abstract generation from LongLaMP (AbsGen) (Kumar et al., 2024). We order each user’s interactions chronologically and partition them into successive chunks. We also evaluate explicit preference following on a semi-synthetic MovieLens dataset with con-trolled changes in users’ genre preferences (Ap-pendix D.3). 

Baselines. We compare methods that condition on the full user history (F ULL -H ISTORY ), retrieved interactions (RAG), or summarized profiles (PAG). We also compare parameter-based methods: MT-LORA fine-tunes one shared adapter on interac-tions pooled across training users, whereas OPPU fine-tunes a separate adapter on each test user’s his-tory (Tan et al., 2024b). P2P (Tan et al., 2026) and SHINE (Liu et al., 2026b) use hypernetworks to generate fixed adapters from compressed represen-tations of user history. In the efficiency study 6.3, we additionally consider their continual variants, P2P reappend and SHINE-R. All methods use the same task-adapted Qwen2.5-7B-Instruct backbone. Baseline details are provided in Appendix E. 

Evaluation Settings. For static personalization, we follow P2P (Tan et al., 2026) and evaluate on both random and out-of-distribution (OOD) user splits. The random split samples test users to reflect the overall user distribution, while the OOD split selects users whose profiles differ most from those of the training users. The latter provides a more challenging test of generalization to unseen users. For continual personalization, we partition each user’s interactions into chronologically ordered chunks Cu, 1, . . . , Cu,T , each containing a sequence of query–response pairs. When evaluating on 

Cu,t +1 , methods may access only preceding chunks 

Cu, 1: t. We average performance first across chunks for each user, then across users within each task, preventing users with longer histories from dispro-portionately affecting the results. 

Evaluation metrics. We report accuracy and F1 for classification, MAE and RMSE for rating pre-diction, and ROUGE-1 and ROUGE-L for text gen-eration. In the continual setting, we additionally report BLEU and METEOR for text generation. To assess efficiency and scalability, we measure up-date and generation FLOPs, per-user storage, and peak memory. Full implementation and hyperpa-rameter details are provided in Appendix C.

We therefore adopt the simpler and more efficient inter-layer-only design.

8 Conclusion 

We present WASP, a recurrent framework for streaming LLM personalization. It carries a fixed-size latent user state across updates to incorpo-rate new user evidence and generate personalized LoRA weights without reprocessing accumulated user histories. Trained end-to-end, WASP delivers effective personalization across users and over long interaction horizons while maintaining personal-ization quality under fixed compute and storage budgets. These results highlight the potential of re-current weight generation for resource-constrained on-device personalization. 

Limitations 

We identify two limitations of WASP. First, our evaluation focuses on implicit preferences and in-cludes a preliminary experiment on explicit pref-erence revision (Appendix A.3). Preference fol-lowing when relevant cues are sparse amid unre-lated dialogue is a direction for future study (Jiang et al., 2025). Second, we focus on fixed-rank LoRA adapters in this work. Although the frame-work could be extended to other parameter-efficient methods, such as adapter modules and prefix tun-ing, their effectiveness and efficiency in recurrent personalization remain to be evaluated.

A.2 User-Specific Personalization 

Strong task performance alone does not neces-sarily imply effective personalization: a method may learn a population-level adapter without cap-turing meaningful differences among users (Qiu et al., 2025). We therefore compare performance when conditioning on the target user’s history ( self )against both a shuffled history from another user (shuffle ) and the task-adapted base model. We define the personalization rate as win_both =Pr( self ⪰ shuffle ∧ self ⪰ base ), which measures how often the correct user history improves over both controls. Table 5 reports the user-specific personalization results on the random split. WASP achieves the highest aggregate personalization rate across all ten tasks, with the strongest F1, ROUGE, and MAE results. To further assess inter-user variation, we measure the cosine similarity between adapters gen-erated for different users. WASP yields the lowest inter-user cosine similarity (0.572), while P2P’s near-unity similarity (0.998) indicates that its gen-erated adapters are almost identical across users. Together, these results suggest that WASP trans-forms fine-grained history signals into distinct and useful user adaptations rather than a largely shared adapter encoding population-level preferences. 

A.3 Targeted Preference Revision 

Our continual personalization experiments show that WASP cont maintains stable performance over long streams of real-world interactions. Because these interactions reveal preferences only indirectly, it is difficult to determine which preferences the model revises after an update. We therefore use a semi-synthetic MovieLens benchmark with explicit genre preferences and controlled changes between two chunks (Appendix D.3). We compare WASP cont with the base model, Full-History, OPPU, and WASP stat . After the second chunk, we measure accuracy on held-out movies according to whether the update confirms the user’s preference for that genre ( restate ), re-verses it ( revise ), or leaves it unmentioned ( reten-tion ). Table 6 shows that WASP cont follows the new preference when a genre’s ratings reverse while retaining earlier preferences for genres absent from the update.

D Dataset Details 

D.1 Task Details LaMP-1: Personalized Citation Identification. 

This is a binary classification task. Given a target paper and two candidate references, the model pre-dicts which candidate the author is more likely to cite. The user history contains the author’s previ-ous publications and provides evidence about their research interests and citation preferences. 

LaMP-2N: Personalized News Categorization. 

The model assigns a news article to one of 15 cat-egories. The history contains articles previously written by the user together with their category la-bels, allowing the model to infer the user’s topical distribution and labeling patterns. 

LaMP-2M: Personalized Movie Tagging. 

Given a movie description, the model selects one of 15 tags. Personalization is based on the user’s historical movie–tag pairs, which capture individual differences in how users describe otherwise similar content. 

LaMP-3: Personalized Product Rating. Given a review, the model predicts the integer rating as-signed by the user on a 1–5 scale. The history comprises the user’s earlier review–rating pairs and exposes their rating calibration in addition to the sentiment expressed in the current review. 

LaMP-4: Personalized News Headline Genera-tion. The model generates a headline for a news article. Historical article–headline pairs character-ize the user’s lexical choices, preferred level of specificity, and headline style. 

LaMP-5: Personalized Scholarly Title Genera-tion. Given a scientific abstract, the model gen-erates the paper title. The user’s previous abstract– title pairs provide domain and stylistic evidence for producing a title consistent with that author. 

LaMP-7: Personalized Tweet Paraphrasing. 

The model rewrites an input text as a tweet while preserving its meaning. The user’s prior tweets provide evidence about tone, phrasing, and other recurring stylistic choices. 13 LongLaMP-1: Personalized Abstract Genera-tion. Given a paper title and a list of key research items, the model generates the paper’s abstract. The user history contains the author’s earlier papers, each given as its title and abstract, and therefore tests whether a method can preserve an author’s long-form academic style while producing domain-appropriate content. 

LongLaMP-2: Personalized Topic Writing. 

Given the summary of a Reddit post, the model generates the full post. The user history contains the author’s earlier posts, each given as its sum-mary and full text, and supplies evidence about the author’s voice, organization, and typical level of detail. 

LongLaMP-3: Personalized Review Writing. 

Given a product description, an overall rating, and a short review summary, the model generates the full review text. The user history contains the user’s earlier reviews, each given as the product descrip-tion and the full review text, requiring the model to capture both writing style and opinion patterns. 

Amazon23: Amazon Reviews 2023. We build our continual personalized review-generation dataset from Amazon Reviews 2023 (Hou et al., 2026). Following LongLaMP’s review-writing for-mulation (Kumar et al., 2024), the model generates a full review from the product description, con-ditioned on the user’s previous reviews. Unlike LongLaMP, which uses an earlier Amazon Reviews release, Amazon23 provides newer interactions, richer item metadata, and fine-grained timestamps. 

AbsGen: Personalized Abstract Generation. 

We use the temporal version of LongLaMP abstract generation (Kumar et al., 2024), ordering each au-thor’s papers by publication time. At every step, the model generates the abstract of the next paper from its title and research items, conditioned only on earlier publications. This preserves LongLaMP’s long-form generation format while turning each author profile into a chronological personalization stream. 

D.2 Temporal Data Construction 

For each user, we sort interactions chronologically and split the history into non-overlapping chunks of at most 8 items or 4,096 tokens. Each chunk produces one update: after reading C1, . . . , C t, the adapter is evaluated by generating the items in the next chunk, Ct+1 . Thus, an item is first a prediction target and later becomes part of the history. We discard users with fewer than two chunks. We use disjoint user splits, reserving 200 users per task for validation and another 200 for test-ing. During training, each user’s chronologically ordered chunks are divided into non-overlapping episodes of at most 16 consecutive chunks. Within each episode, the model updates the adapter one chunk at a time, and the loss is backpropagated through the full sequence. At each update, the model learns to generate four sampled items from the next chunk. During inference, C1 initializes the adapter and C2 provides a warm-up update; scoring starts at C3 and covers all items in up to 16 chunks. 

D.3 Explicit Preference Dataset Construction 

We use MovieLens 25M (Harper and Konstan, 2015) to construct histories for synthetic users who like or dislike each of four genres (Horror, Comedy, Romance, and Sci-Fi). We select movies associ-ated with a single target genre. Each history entry records the movie title, its genre labels, and the user’s like or dislike judgment. Each episode consists of two chunks for one user (Figure 7). The first chunk establishes the user’s initial preferences with two movies per genre. The second covers zero to four genres. For each genre it covers, ratings on two new movies either reverse the initial preference ( revise ) or confirm it ( restate ). Genres omitted from the update provide retention 

targets, for which the initial preference still applies. We fill each chunk to ten movies with randomly labeled titles outside the target genres. After each chunk, we probe each genre with two previously unseen movies. Given a movie’s title and genre labels, the model answers Yes or No when asked whether the user would like it. Of the 24 = 16 possible initial preference con-figurations, we use 14 to construct 96000 training episodes and reserve two complementary configu-rations for 3000 evaluation episodes. Holding out the starting configurations prevents complete pref-erence trajectories from appearing in both splits.

E Baseline Details 

All baselines use the same task-adapted Qwen2.5-7B-Instruct backbone. For the static experiments, each method receives the same non-chronological user history. In the continual experiments, methods may access only Cu, 1: t when predicting examples in Cu,t +1 .

Retrieval-Augmented Generation (RAG). Fol-lowing LaMP and P2P (Salemi et al., 2024b; Tan et al., 2026), we use BM25 to retrieve the k = 2 

history items most relevant to the current query and prepend them to the task input. If R(qu, Hu, k )

denotes retrieval and [·∥· ] concatenation, the result-ing input is [R(qu, Hu, k )∥qu]. No user-specific parameters are trained. 

Profile-Augmented Generation (PAG). 

PAG (Richardson et al., 2023) first summa-rizes a sample of the user’s history into a textual profile su. At inference time, this profile and the same top-k retrieved interactions used by RAG are prepended to the query, giving 

[su∥R(qu, Hu, k )∥qu].

Full-History. This baseline flattens the complete available history and prepends it to the current query. When the sequence exceeds the backbone’s context window, we retain the most recent interac-tions that fit. In continual evaluation, the prompt contains the accumulated prefix Cu, 1: t; for the ef-ficiency analysis, we reuse its key–value cache across updates. 

One PEFT Per User (OPPU). OPPU (Tan et al., 2024b) optimizes a separate LoRA adapter on each target user’s history while keeping the backbone frozen. Unlike hypernetwork methods, it requires user-specific backpropagation and storage. In the continual setting, we retrain a fresh adapter from the task-adapted model on the complete accumu-lated prefix at every update, so its update cost grows with history length. 

Multi-Task LoRA (MT-L ORA). We train a shared LoRA on query–response pairs pooled across training users without user histories, and merge it into the base model. 

P2P. P2P (Tan et al., 2026) compresses the avail-able history into a textual profile and maps it to a personalized LoRA. For the efficiency analysis, we adapt it to the continual setting as P2P reappend ,which appends each new chunk to the accumulated history, rebuilds the profile, and regenerates the adapter, causing update cost to grow with history length. 

SHINE. SHINE (Liu et al., 2026b) compresses the history into fixed memory tokens and directly generates a LoRA.
