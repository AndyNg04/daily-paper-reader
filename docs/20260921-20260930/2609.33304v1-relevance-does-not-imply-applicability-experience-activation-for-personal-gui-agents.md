## 摘要
个性化图形用户界面（GUI）智能体依赖交互历史，从含糊的指令中推断用户意图，并预判反复出现的日常任务。现有方法检索与任务相关的历史记录，并将其附加到策略模型的上下文中，隐含地假设与任务相关的经验对任务中的每一次决策都有用。我们发现，这种帮助主要体现在首次决策：检索到的历史记录显著改善了一个任务执行过程的起始步骤，却对其余90%的步骤几乎没有持续助益，也难以指导智能体判断是否应主动提出建议。相关记录或许能告诉智能体从何入手，却不能说明过去的哪个操作适用于当前屏幕，或某项日常任务现在是否该执行。根本问题在于，相关不等于适用：相关性由任务决定，而适用性取决于决策时的具体情境。因此，我们将个性化重新表述为经验激活，并提出无需训练的框架 ExpActivator，仅激活适用于当前情境的经验。在执行过程中，ExpActivator 在冻结的 GUI 骨干模型的潜在空间中，将每个新屏幕与历史状态进行匹配，并提供对应操作作为参考。在执行之前，它仅在当前时间和场景提供充分依据时激活重复出现的意图，否则不采取行动。在四种 GUI 骨干模型上，ExpActivator 使轨迹内步骤成功率平均提高28%；在历史信息 token 用量仅为约五分之一的情况下，均取得最佳的个性化执行效果；其马修斯相关系数约为最强主动式基线的2.3倍。经验的价值来自适时激活，而非简单地附加到上下文中。

## Abstract
Personal Graphical User Interface (GUI) agents rely on interaction history to infer what a user wants from ambiguous instructions and to anticipate recurring routines. Existing approaches retrieve task-relevant history and append it to the policy's context, implicitly assuming that experience relevant to a task remains useful for each decision within it. We find that this help is largely spent at the first decision: retrieved history strongly improves the opening step of an episode, yet provides little sustained benefit over the remaining 90\% of steps, and offers weak guidance on whether a proactive suggestion is warranted. A relevant record may tell the agent where to begin, but not which past action applies to the current screen or whether a routine is due now. The underlying issue is that relevance does not imply applicability}: relevance is determined at the task level, whereas applicability depends on the situation at decision time. We therefore recast personalization as experience activation and introduce ExpActivator, a training-free framework that activates only the experience applicable to the current situation. During execution, ExpActivator matches each new screen to historical states in the frozen GUI backbone's latent space and supplies the corresponding action as a reference. Before execution, it activates a recurring intent only when the current time and scenario provide sufficient support, and otherwise abstains. Across four GUI backbones, ExpActivator improves within-trajectory step success by 28\% on average, achieves the best personalized execution on every backbone while using about one-fifth as many history tokens, and reaches approximately 2.3$\times$ the Matthews correlation coefficient of the strongest proactive baseline. Experience pays where it is activated, not where it is appended.

# 论文总结：相关不等于适用——个性化 GUI 智能体的经验激活

## 1. 核心问题与整体含义

- 个性化 GUI 智能体需要借助用户历史理解“点我常喝的咖啡”这类模糊指令，也可能在用户没有下达指令时，判断是否该提醒其执行惯常任务。
- 现有方法通常**按任务检索相关历史，再将整条记录或其摘要加入模型上下文**。论文指出，这混淆了两个问题：历史记录与当前任务是否*相关*，以及其中某个动作是否*适用于当前屏幕*、某项惯例是否*恰好该在此时建议*。
- 作者发现，常规检索主要改善每个任务的第一步；进入不断变化的界面后，对其余约 90% 的步骤帮助很小。因此，论文将个性化的重点从“一次检索、持续附加”转向“**在每次决策时激活适用经验**”。

## 2. 方法论：ExpActivator

ExpActivator 是一个**无需训练**的框架，保留 GUI 策略模型及所用编码器的参数不变，分别处理执行中的动作选择和执行前的主动建议。

- **步骤级激活：为当前屏幕寻找动作参考。**
  1. 根据用户指令与历史目标的文本相似度，先选出最多 **8 条**相关、且具有可读轨迹的历史记录。
  2. 用当前 GUI 骨干模型的视觉特征表示屏幕：对空间区域的特征分块、减去历史图像的均值并归一化，再比较当前屏幕与候选轨迹中各历史屏幕的余弦相似度。
  3. 在所有候选轨迹的所有步骤中选出最相近的历史状态，把该状态对应的动作提供给冻结的策略模型。模型仍须结合**当前截图、指令与已执行动作**，自行采纳、调整或拒绝参考动作。
  4. **每观察到一个新屏幕就重新匹配**；参考动作可以在不同历史轨迹之间切换，而不要求当前任务照着某条旧轨迹逐步重放。首次动作另由相关历史记录对应用进行加权投票，提供打开应用的参考。

- **任务级激活：决定是否主动建议。**
  1. 将语义相近的历史意图组成可能重叠的“惯例邻域”。
  2. 对每个惯例计算当前情境的支持度：仅计入**相同场景**的历史发生记录，并按其与当前时刻的**24 小时循环时间距离**赋予权重。
  3. 只有惯例达到最低总发生次数、同场景次数和时间加权支持度时，才允许激活；若没有合格惯例，便**保持沉默**。
  4. 在合格惯例中，按“情境支持度／惯例发生次数”排序，选取同场景的代表性历史意图供模型生成建议。**建议不等于自动执行**。

## 3. 实验设计

- **数据与任务：**使用 AndroidIntent 基准，涵盖 **82 名用户、135 个应用、13 类场景**。每名用户按时间顺序以前 80% 的记录作历史，共 **15,966 条**；后续记录用于评估。
  - 个性化执行：**775 个任务、7,915 个步骤**，指令刻意保留歧义。
  - 主动建议：**315 个情境**，其中应建议的正例 215 个、不应建议的负例 100 个。
- **模型与对照：**在四个冻结的开源 GUI 骨干——Qwen3-VL-8B、MAI-UI-8B、Qwen3.5-9B、GUI-Owl-1.5-8B——上，比较无历史的 Base，以及 Recent、Retrieve、LLM-UM、HIM-Agent；另列出专有模型 QwenVL-Max 的结果作外部参照。
- **指标：**执行任务报告动作类型准确率、步骤成功率（SSR）和偏重早期步骤的累计成功率（CSR）；主动建议报告建议语义质量、精确率、平衡准确率（BA）及马修斯相关系数（MCC）。由于主动建议正例占 68%，作者特别使用 BA、MCC 检验方法能否区分“该建议”与“不该建议”，而非只看 F1。

## 4. 资源与算力

- 方法**不训练或微调模型**；历史目标和屏幕特征可离线缓存，推理时执行屏幕匹配并调用一次冻结策略模型。文中说明**每次运行使用一张 GPU**，采用 BF16、vLLM 及贪心解码，并列出了图像与上下文长度等设置。
- 论文**未明确给出 GPU 型号、总 GPU 时数、推理耗时或完整计算成本**。因此，“历史 token 更少”可以支持其提示词成本优势，但不能直接等同于端到端运行时间或算力开销按同等比例下降。

## 5. 实验数量、充分性与公平性

- 实验覆盖四个骨干上的两类任务和多种历史机制；另有**首步与轨迹内步骤拆分、历史规模分层、选择动作与附加整条轨迹的对照、更新频率对照、时间／场景／频率消融、阈值敏感性分析和案例研究**。主要差异采用按用户配对的 bootstrap 置信区间检验。
- 公平性方面，同一骨干内的方法使用相同历史与推理设置，并在相同评估步骤上比较；候选配置在留出的历史记录上校准。这些设计较好地隔离了“如何使用历史”的影响。
- 但外部有效性仍有限：**仅评估一个基准**；QwenVL-Max 是外部参考，并非与开源骨干完全配对的对照。此外，执行评估主要依据记录动作逐步评分，并提供基准中的先前动作序列，不能直接证明在真实设备上自主连续执行时也能获得同等收益。

## 6. 主要结论与发现

- **常规检索的收益集中于开局。**以 Qwen3-VL-8B 为例，Retrieve 将首步成功率从无历史的 **28.26%** 提高至 **62.06%**，但在其后 **7,140 个步骤**上的成功率为 **18.35%**，与无历史的 **18.43%** 基本相同。
- **逐屏激活带来持续收益。**ExpActivator 在同一骨干上的轨迹内 SSR 达 **26.67%**，比无历史高 **8.24 个百分点**；跨四个骨干，轨迹内相对提升平均约 **28%**。四个骨干上的总体执行指标均取得组内最佳结果。
- **更少的历史上下文也可更有效。**在 Qwen3-VL-8B 上，ExpActivator 每步增加约 **145 个历史 token**，而所比较基线增加约 **418—844 个**；其总体 SSR 为 **30.92%**，高于最强基线的 **22.63%**。
- **主动建议需要“会克制”。**ExpActivator 在四个骨干上均取得最高建议精确率；其 MCC 相对各组最强主动建议基线平均约为 **2.3 倍**。消融显示，时间权重和场景条件有助于判断何时建议，频率归一化主要影响建议哪项惯例，而不改变是否触发。

## 7. 优点

- **问题定位清楚：**通过首步与后续步骤拆分，具体揭示了任务级检索为何难以持续指导 GUI 操作。
- **机制与问题对应：**执行时按屏幕选动作，建议前按时间与场景设门槛；两者都把历史使用落实到决策时刻。
- **易于接入：**不需训练记忆控制器或策略模型，且以简短参考动作替代大段历史上下文。
- **验证较有针对性：**固定候选历史比较“选择”与“整段附加”，并测试过期屏幕、低频更新和情境条件缺失，支持核心机制的作用。

## 8. 不足与局限

- **真实交互泛化尚待验证：**离线动作匹配与真实设备中的误操作累积、页面变化、弹窗及恢复策略之间仍有差距。
- **视觉近似未必意味着动作适用：**相似页面可能包含不同商品、账号或动态内容；历史动作虽只是参考，仍可能造成错误引导。
- **主动建议的情境维度较窄：**主要依赖小时与预设场景类别，较难表达星期、节假日、近期意图或用户临时改变习惯；固定支持门槛也可能漏掉稀少但重要的惯例。
- **覆盖与成本证据有限：**只在 AndroidIntent 上验证，主动建议样本仅 315 个；未报告完整的端到端延迟和算力消耗，也未评估个人历史存储、隐私保护及用户对建议的实际接受度。
