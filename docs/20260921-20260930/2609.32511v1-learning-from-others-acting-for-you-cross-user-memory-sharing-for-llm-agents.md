## 摘要
服务于不同用户的大语言模型（LLM）智能体常常需要解决相关任务，但彼此独立的用户历史记录可能使可复用的经验无法供其他智能体利用。汇集记忆虽能扩大经验的可用范围，却也可能将与接收用户需求相冲突的偏好迁移过去。我们提出 ShareMem，一种在共享可复用经验的同时，以接收用户自身偏好为依据应用这些经验的记忆架构。共享经验指明如何行动以及应查询哪些偏好；接收用户的记忆则提供这些偏好的具体取值。两阶段整合先在本地提炼经验，再将经接受的编辑纳入共享记忆池。在执行过程中，范围优先检索在统一的条目预算下联合选择本地经验和共享经验，而用户绑定通道则支持初始偏好检索和智能体主动发起的偏好检索。我们使用四种基础模型，在网页导航（Mind2Web）、在线个性化交互（VitaBench~2.0）和多会话编程（MemoryCode）任务上评估了 ShareMem。与相应的用户本地记忆方案相比，ShareMem 在全部四种模型上分别提升了步骤成功率、平均任务成功率和对话宏级编程得分。消融实验表明，两阶段整合有助于缩小共享记忆池、减少经验归纳的 token 用量并改善下游性能，同时支持经验指导与主动偏好检索之间的互补性。进一步分析表明，当相关的本地经验稀缺时，共享带来的收益最大，而经验来源的质量以及跨用户偏好干扰限制了有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

# 论文总结：ShareMem 跨用户记忆共享

## 1. 核心问题与整体含义

- **研究问题**：不同用户的 LLM 智能体会遇到相似任务，但用户历史彼此隔离，使已经学到的操作经验难以复用；直接汇集记忆又可能把贡献者的个人偏好错误地用于接收用户。
- 论文将前者称为**经验可达性瓶颈**，并强调“能够检索到信息”不等于“信息适用于当前用户”。其核心主张是：**跨用户共享可迁移的行动方法，但具体偏好取值必须来自当前用户。**

## 2. 方法论：ShareMem 如何工作

- **分离两类记忆**：每位用户保有自己的偏好库和本地经验库；跨用户共享池只保存可复用经验。经验描述任务触发条件、操作流程、需要核实的偏好维度及异常处理，不应保存源用户的具体偏好值。
- **两阶段经验整合**：
  1. 从合格的交互轨迹出发，检索最多 \(k_w=5\) 条相近本地经验，由 LLM 管理器决定新增、替换、删除或不修改。
  2. 仅将**已接受的本地编辑**作为证据送入共享池；共享管理器再结合相近共享经验，独立决定如何更新。它并非机械复制本地编辑。
  3. 管理器按提示将姓名、地址、商品等来源特定值抽象为语义槽位，并保留“需要查询哪类偏好”的指导。
- **范围优先的联合检索**：先按任务适用范围排列候选，例如 Mind2Web 依次考虑同网站、子域、域及其他网站；再在每一优先级内联合排序本地与共享经验。两者共用最终 **\(K=5\) 条**的预算，不预留来源配额；低优先级候选只能填补空位。
- **绑定当前用户的偏好通道**：任务开始时检索最多 \(k_p=10\) 条当前用户偏好；执行中，智能体还可针对尚未确定的字段主动发起更具体的查询。共享经验可以提示“应查询什么”，但不能提供或决定“用户偏好是什么”；当前任务要求与当前用户偏好优先于经验指导。

## 3. 实验设计与对照

- **基准与指标**：
  - **Mind2Web**：网页操作；主要报告元素准确率、动作 F1、步骤成功率。主实验将训练示例和评测任务分配给 20 名模拟用户，共评测 252 个任务；评测基于记录的网页状态，**不是实时浏览器执行**。
  - **VitaBench 2.0**：56 名用户、771 个按时间推进的服务子任务；报告三次试验的平均成功率 Avg@3、至少成功一次的 Pass@3 和三次全成功的 Pass3。成功子任务可在线更新经验。
  - **MemoryCode**：多会话编程；三个固定的 20 对话子集，报告对话等权平均的规则满足得分 D-MS。经验与偏好在评测前固定。
- **基础模型**：Qwen 3.6-27B、DeepSeek v4-flash、Gemma 4-26B、Gemini 3 Flash；经验检索使用 BGE-M3 与 BGE-Reranker-v2-M3。
- **受控对照**：无长期记忆（NONE）、仅当前用户偏好（PREF）、偏好加本地经验（LOCAL）、再开放其他用户偏好的共享方案（SHARE-ALL），以及 ShareMem。Mind2Web 没有偏好通道，因此不设 PREF、SHARE-ALL。此外还比较了 AWM，以及各基准上的 RAG、历史重写、完整历史上下文或完整偏好等参考方案。

## 4. 资源与算力

## 5. 实验数量、充分性与公平性

- 实验覆盖 **3 个基准 × 4 个基础模型**的主结果，并包含三次运行或三个固定子集；还开展了写入路径、可编辑整合、检索范围与预算、主动偏好检索、本地覆盖率、来源质量、在线准入阈值及跨用户偏好干扰等多组分析。**不能将这些交叉条件简单相乘视为独立实验次数**。
- 受控比较尽量匹配任务、模型、评分方式和检索预算；覆盖率实验固定任务而改变用户分配，来源质量实验固定训练任务覆盖范围，这些设计有助于解释收益来源。
- 但证据边界也较清楚：部分消融会重建经验池，因而不只改变单一因素；主动检索消融同时改变信息访问与交互机会；部分深入分析仅在 Qwen 或少数模型上完成。论文报告了部分配对显著性检验，但并未对所有主结果给出相应的不确定性检验。

## 6. 主要结论与发现

- 相比匹配的 **LOCAL**，ShareMem 在四个模型上均提高了 Mind2Web 步骤成功率（**+2.35～4.10 个百分点**）、VitaBench Avg@3（约 **+1.25～2.46 个百分点**）和 MemoryCode D-MS（**+0.16～2.91 分**）。不过提升并非遍及所有指标：例如 Gemini 在 VitaBench 的 Pass3 略低于 LOCAL。
- 两阶段、可编辑整合在所测 MemoryCode 子集上形成更小的共享池、更低的归纳 token 开销，并优于直接写入或只追加方案。经验指导与执行时主动查询当前用户偏好表现出互补性。
- **共享最能弥补本地经验缺口**：Mind2Web 同网站本地覆盖率从 0% 升至约 99% 时，共享相对 LOCAL 的步骤成功率增益由 **+4.10** 降至 **−0.13 个百分点**。
- **更多可访问内容不必然更好**：低质量轨迹会削弱共享收益；向智能体提供其他用户偏好，即使标注来源并保留当前用户检索名额，仍观察到错误套用。ShareMem 也并非全面优于强参考方案：其 VitaBench 结果低于历史重写和完整上下文方案，MemoryCode 结果低于提供完整提取偏好的方案。

## 7. 优点

- 将**可复用流程**与**个人偏好取值**明确拆开，针对跨用户共享中“相关但不适用”的问题设计了可执行的记忆边界。
- 两阶段整合与统一条目预算兼顾共享池的紧凑性、构建成本及检索竞争；范围优先策略利用网站或任务领域等可解释元数据。
- 不只报告平均性能，还通过覆盖率、来源质量、准入阈值和偏好误用审计，分析了**何时有效、为何失效**。

## 8. 不足与局限

- **实验场景有限**：三项基准分别采用模拟用户分配、基准规定的服务交互和固定编程偏好；Mind2Web 主实验不是实时网页执行。结果尚不能直接证明在真实组织、长期部署或更复杂权限关系中的效果。
- **依赖经验与元数据质量**：来源轨迹不可靠会明显削弱共享收益；范围优先检索也依赖可用的正确网站或领域标签。在线场景只从满分子任务更新经验，可能带来成功样本选择偏差。
- **隔离偏好不等于完整隐私保障**：方法通过抽象规则和用户绑定检索降低具体偏好误用，但论文未给出对共享文本泄露、成员推断或恶意数据注入的形式化保证。
- **收益有边界且成本披露不足**：相关本地经验充足时，共享的边际收益趋近于零；某些模型、指标上的改进很小。缺少完整算力与时延数据，也限制了对部署成本的判断。
- **干扰审计需谨慎解读**：误用率来自对已暴露且失败案例的模型筛查与重复判定，并非全部任务中的真实误用率；未被筛查发现的案例无法计量。
