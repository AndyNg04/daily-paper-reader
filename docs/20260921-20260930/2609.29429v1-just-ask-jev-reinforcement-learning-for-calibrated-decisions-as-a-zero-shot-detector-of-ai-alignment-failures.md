## 摘要
对齐失效检测器用于筛查已部署的语言模型，并为对齐基准评分。现有检测器大多是生成式评判模型，需要针对每项判据进行一次解码；而读取词元概率的分类器（如 Llama Guard）每次调用仍只能对一个固定标签评分。Jev 是一个通过用于校准决策的强化学习（RLCD）训练的模型，能够在单次调用中，以经过校准的概率回答关于同一输入的多个指定类型的问题。但它能否检测对齐失效尚未得到评估。我们提出 RLCDAlignBench，在十类对齐失效上评测 Jev：迎合、越狱、欺骗、提示注入、幻觉、隐私侵犯、社会偏见、奖励黑客、掩饰不确定性和权力寻求。该评测涵盖 44 个基准和 5 个目标模型，使用各基准的评分器提供标签，其中两个基准还采用人工标注。许多此类失效具有关系性，需要参照用户信念或注入指令等信息来判定，而仅凭模型回复无法获知这些参照信息。因此，我们的核心思路是分别改变向 Jev 提出的问题和提供给它的输入：一方面调整问题的措辞和答案类型，另一方面调整输入中包含的字段。仅使用一个通用问题，Jev 就在零样本条件下达到 0.886 的 AUROC 中位数，并在大多数基准上优于监督学习基线。问题措辞影响很小，输入上下文的影响更大，而后者主要来自编码了标签信息的字段。Jev 与人工标签的一致程度和参考评分器相当，还揭示了现有基准中的标签缺陷，且成本仅为大语言模型评判器的六十三分之一。代码和数据：https://github.com/sumleo/RLCDAlignBench。

## Abstract
Detectors of alignment failures screen deployed language models and score alignment benchmarks. Most are generative judges that spend a decoding pass on every criterion, and classifiers that read token probabilities, such as Llama Guard, still score one fixed label per call. Jev, a model trained with reinforcement learning for calibrated decisions (RLCD), answers many typed questions about one input with calibrated probabilities in a single call. Whether it detects alignment failures has not been measured. We present RLCDAlignBench, which benchmarks Jev on ten alignment failures: sycophancy, jailbreaks, deception, prompt injection, hallucination, privacy violation, social bias, reward hacking, concealing uncertainty, and power seeking. It spans 44 benchmarks and five target models, labelled by each benchmark's scorer and, on two, by humans. Many of these failures are relational, defined against a reference, such as the user's belief or an injected instruction, that the response alone does not reveal. Our key idea is therefore to vary what Jev is asked separately from what it sees: the question's wording and answer type on one side, the fields of the input on the other. A single generic question reaches a median AUROC of 0.886 zero-shot and beats supervised baselines on most benchmarks. Question wording matters little, while context matters more, mostly through fields that encode the label. Jev matches the reference scorer's agreement with human labels, surfaces label defects in existing benchmarks, and costs 63x less than LLM-judge scorers. Code and data: https://github.com/sumleo/RLCDAlignBench.

# 论文总结：Jev 能否低成本检测 AI 对齐失效？

## 1. 核心问题与研究意义

- **核心问题**：一个无需针对具体失效类型重新训练、且一次调用可回答多个问题的模型，能否可靠地检测语言模型的对齐失效？
- **研究动机**：现有检测器多依赖生成式大模型逐项评审，成本较高；即使读取分类词元概率，通常也只能在一次调用中评估一个固定标签。
- **关键困难**：谄媚、欺骗、提示注入等失效具有“关系性”。例如，判断回答是否迎合用户，需要知道用户表达了什么观点；判断是否遵循注入指令，需要看到原本任务与注入内容。只检查回复可能无法判定失效。
- **整体意义**：论文不仅检验 Jev 是否能充当零样本检测器，还区分了两类失败原因——**问题没有问对**，还是**输入缺少判定所需的参照信息**；同时指出，检测结果也可能受基准标签本身的缺陷影响。

## 2. 方法论与技术流程

- **检测模型**：使用 Jev（版本 `jev-1.13.0`）。它通过“用于校准决策的强化学习”（RLCD）训练，接收一个待判断的 *state*，并在**一次 API 调用**中回答多个指定类型的问题，返回答案概率，而非生成文字判词。本文评估现成模型，**没有重新训练 Jev**。
- **构建检测任务**：将已有对齐基准中的目标模型交互整理为“输入、输出、标签”。参考评分器给出是否发生失效的二元标签；Jev 只看到指定的输入字段，不看到该标签。
- **分别改变“问什么”与“看什么”**：
  - *问什么*：比较固定模板的通用问题、描述具体判据的针对性问题，以及不同答案类型——是/否（NOUL）、选项分布（CHOICE）和三级评分（SCORE）。
  - *看什么*：以目标模型的输入和输出为默认状态，每次只增加或改变一个字段，例如攻击提示、模型目标、真实答案或隐私秘密清单，从而比较该字段的作用。论文进一步区分部署监控器可能掌握的**可部署信息**与直接参与标签定义的**标签关键字段**。
- **概率读出与评价**：主要以 Jev 返回的 \(P(\text{yes})\) 等概率作为失效分数，比较其区分正负例的 AUROC；需要作二元告警时，再用阈值将分数转成判定。研究也比较直接保留概率与只取最高概率答案的效果。
- **避免挑选问题造成虚高**：每个基准测试约 15–40 种策略。针对性策略在一半样本上选出，再在另一半样本上评估，并重复分组切分；阈值也在独立折上选择和测试。

## 3. 实验设计与对比方法

- **RLCDAlignBench** 涵盖十类失效：谄媚、越狱、欺骗、提示注入、幻觉、隐私侵犯、社会偏见、奖励黑客、掩饰不确定性和权力寻求。
- 共纳入 **44 个已有基准、7,193 个检测实例、5 个开放目标模型**（规模约 2–7B）。每类失效固定使用一个目标模型。因单一类别或少于五个少数类样本，6 个基准不进入汇总指标，留下 **38 个可用基准**；其中 **31 个**具有通用 NOUL 问题。
- 标签主要来自各基准原有的规则、LLM 评审器或多轮评分器；StrongREJECT 和 HarmBench 另有人工标注可用于核对。论文还使用部分基准的第二评审器标签检查评分稳定性。
- **对比方法与指标**：比较全判正例、回复长度，以及用基准内标签训练的 TF-IDF 逻辑回归；报告 AUROC、F1、预期校准误差（ECE）、与人工标签的 Cohen’s κ，并分析延迟和 API 成本。TF-IDF 使用了 Jev 未见过的域内标签，因此是一个有监督参照，而非同条件的零样本方法。

## 4. 资源与算力

- 论文报告 Jev 实验约进行了 **2.34 万次调用**，平均每次携带 **11.4 个问题**，客户端延迟中位数约 **0.31 秒**；全文 Jev 调用费用约 **2.27 美元**。按标价计算，在 19 个使用 API 大模型评审器的基准上，单轮 Jev 费用约 **0.30 美元**，原评审器约 **18.96 美元**。
- **未明确报告 GPU 型号、GPU 数量、目标模型生成耗时或 Jev 的训练算力与时长**。论文说明，重建目标模型输出需要 GPU，重跑部分评分器需要 API 或本地模型；这些消耗不包含在上述 Jev 调用费用中。

## 5. 实验规模、充分性与公平性

- 实验覆盖 **10 类失效、44 个基准**；除问题类型和措辞比较外，还进行了 **49 组输入字段配对对照**、阈值与校准分析、人工标签核对、标签审计和成本核算。覆盖面和消融维度较丰富。
- **设计上的审慎之处**：同一实例、同一标签下只改变一个输入字段；针对性问题采用分半选取和异半评估；置信区间按相关样本分组重采样，并排除了直接在代码中读取标签关键元数据的“捷径”策略。
- **仍需谨慎解读**：各失效类型只对应一个目标模型，不能完全区分“失效类型难度”与“目标模型输出特征”；不少标签未经人工验证。与大模型评审器的成本比较也受评审器定价、调用次数及记录完整性影响，不能概括为所有部署场景都便宜 63 倍。

## 6. 主要结论与发现

- **零样本排序能力较强**：单个通用 NOUL 问题在 31 个适用基准上的 AUROC 中位数为 **0.886**；相较于 TF-IDF 和长度两项基线中表现更好的方法，中位优势为 **0.132 AUROC**，在 **25/31** 个基准上领先。
- **保留概率比精修措辞更重要**：针对性提问的样本外 AUROC 中位增益仅 **+0.006**，置信区间跨越零；将分布压成最高概率答案通常损害排序。三级 SCORE 的软概率读出较通用 NOUL 有小幅优势。
- **输入信息的作用取决于其性质**：可部署参照信息仅在少数基准上显著改善表现；真实答案、秘密清单等标签关键字段有时带来较大提升，但提升可能意味着 Jev 更容易复现**标签定义**，不等于更准确地识别真实对齐失效。
- **排序好不代表阈值和概率校准好**：通用问题的逐基准 ECE 中位数为 **0.168**，高于完美校准的有限样本参照值 **0.074**。其 F1 中位数在默认阈值 0.5 下为 **0.706**，采用交叉验证阈值后为 **0.822**；用 10 个标注样本拟合阈值可达到 **0.793**。不过，在已验证标签子集上，10 样本阈值反而使 F1 下降约 **0.025**，因此不能一概推荐调阈值。
- **人工核对与标签审计**：在 StrongREJECT 人工标签上，通用 Jev 与参考评分器的一致性接近（κ 分别为 **0.809** 和 **0.811**），Jev 的排序 AUROC 更高。高置信度分歧还帮助发现基准将“答题正确”误当作“非谄媚”、将“注入任务答对”误当作“注入成功”等问题，以及部分标签依赖输入中不可见的注释。
- **成本有优势，但有条件**：在上述 19 个 API 评审基准的标价口径下，Jev 单轮总体便宜约 **63 倍**；改用更便宜的评审器价格重算后，优势缩小。

## 7. 主要优点

- 将**提问设计、答案读出和输入上下文**拆开研究，比单报一个检测分数更能解释性能来源。
- 单次调用支持多个判据，概率输出可直接用于排序、设阈值和低置信度样本转交人工或其他评审器。
- 同时检验评分器标签、人工标签和具体分歧案例，避免把“与既有评分器一致”简单等同于“判断正确”。
- 采用样本外策略选择、配对消融，并公开缓存响应和离线重评脚本，提高结果的可核查性。

## 8. 不足与局限

- **模型与场景覆盖有限**：只评估一个商业 RLCD 模型版本、英文基准及 2–7B 目标模型；对其他检测器、更强目标模型、多语言和真实持续部署的外推尚不明确。
- **标签质量限制结论**：多数基准依赖原评分器；论文自身发现多个标签缺陷。一些高 AUROC 衡量的是复现评分规则，而不是识别研究者真正关心的失效。
- **小样本与偏斜问题**：6 个基准无法进入汇总，部分保留基准也高度类别不平衡；某些失效类型的中位数仅由一两个适用基准支撑。
- **部署所需信息未必可得**：真实答案、完整秘密清单、模型内部置信度或可靠的信念参照，未必存在于实际监控流程中；缺少这些信息时，某些失效本身难以从可见状态判断。
- **概率不能直接视为跨任务可用的风险值**：逐基准校准不足，统一使用 0.5 阈值可能漏报；少量标签调阈值也并非在所有标签类型上都有效。
- **成本与审计有边界**：63 倍是特定价格及评审器组合下的总体比值，不包含重建目标输出等成本；标签分歧审计主要由单人判读，个别解释性结论仍有主观性。
