## 摘要
使用工具的大语言模型（LLM）智能体越来越多地执行需要用户授权的状态变更操作。然而，现有方法尚未提供一种有原则的机制，以便在指令仅有部分内容发生变化时选择性地更新先前的授权。为此，我们提出一种基于授权闭包图（Authorization-Closure-Graph，ACG）的框架，将授权及其依赖关系表示为不断演化的版本化状态。ACG 会选择性地使受修订影响的授权失效，同时保留授权状态中未受影响的部分，并计算最小修复方案，仅识别执行所需但尚缺失的证据或授权。这使智能体能够适应修订后的指令，同时避免使用过期授权和提出不必要的授权请求。我们在两项自然任务中使用三个先进的 LLM 对 ACG 进行了评估；结果表明，ACG 持续提高了操作安全率和任务成功率。代码见 https://github.com/weiliang822/ACG。

## Abstract
Tool-using large language model (LLM) agents increasingly perform state-changing actions that require user authorization. Yet existing approaches do not provide a principled mechanism for selectively updating prior authorization when only part of an instruction changes. To this end, we propose an Authorization-Closure-Graph (ACG)-based framework that represents authorization and its dependencies as an evolving, versioned state. ACG selectively invalidates authority affected by a revision while preserving unaffected portions of the authorization state, and computes a minimal repair that identifies only the missing evidence or authority required for execution. This enables agents to adapt to revised instructions while avoiding stale authority and unnecessary authorization requests. We evaluate ACG across three advanced LLMs in two natural tasks, and ACG consistently improves action safety rate and task success rate. Code is available at https://github.com/weiliang822/ACG.

# 论文总结：授权闭包图（ACG）

## 1. 核心问题与整体含义

- **研究背景：**工具型 LLM 智能体不仅回答问题，还会订票、退款、修改账户等。即使任务最终完成，执行过程中的某次写操作也可能缺乏充分的用户授权。
- **核心问题：**用户只修改部分指令时，智能体如何判断哪些旧授权已过期、哪些仍然有效？逐次检查工具调用难以维护跨步骤的授权状态；将整个任务重新授权又可能带来不必要的重复请求。
- **论文目标：**把授权视为随对话和环境证据持续演化的状态，在防止沿用过期授权的同时，尽量保留不受变更影响的授权。

## 2. 方法论：版本化授权、选择性更新与最小修复

- **授权闭包图（ACG）：**用有向无环图记录三类节点：用户授权、权威环境证据，以及由前两者推导出的结果或后果。依赖边表示下游节点的有效性取决于上游节点。节点记录数值、版本、是否可用、是否获授权及其引用的父节点版本。
- **区分“信息当前有效”与“操作已获授权”：**例如，新报价 120 美元可以是有效证据，但在用户仍限定最高 100 美元时，并不意味着可以付款。派生节点按继承授权、满足边界条件或单独确认后果三种模式判断权限。
- **六类可信更新操作：**`COMMIT` 建立授权，`GROUP` 确定一组动作的共享及成员专属范围，`REVISE` 修改授权，`REVOKE` 撤销授权，`OBSERVE` 更新权威证据，`CONFIRM` 确认已披露的具体动作及其后果。除环境证据更新外，授权类操作须来自经认证的用户响应。
- **选择性失效：**当指令或证据变化时，只更新直接变化的节点及其依赖后代，并按拓扑顺序重新计算；不在影响范围内的节点保持原状。例如，只修改乘客 B 的出行日期，不应撤销乘客 A 未受影响的授权。
- **检查与修复流程：**系统将智能体提出的工具调用映射为规范动作，只检查该动作所需的依赖闭包。已知不可被用户许可覆盖的业务规则违规则 **阻止**；缺少证据或授权则返回 **最小修复请求**；条件齐备才进入 **授权执行**。所谓“最小”，是从当前缺失项中去掉可由上游缺失项通过无条件继承补全的冗余请求，**并不保证整个对话轮数最少**。
- **执行前再验证：**修复后重新检查原动作；执行前核对所依据的节点版本、权限和业务规则，并消耗一次性执行额度，防止旧确认被复用。论文对检查结果的保证以规则规范、权威证据和确认接口可信为前提。

## 3. 实验设计

- **自然任务基准：**使用 **τ²-bench** 的 Airline（50 项任务）和 Retail（114 项任务），覆盖预订、取消、行程变更、退换货及账户更新等场景。
- **执行模型与对照：**分别测试 DeepSeek-V4-Flash、GPT-5.6-Terra 和 Gemini-3.6-Flash；对比无执行拦截的 Raw，以及 AgentSpec、ToolGuard、Progent。用户由独立的 DeepSeek-V4-Flash 调用模拟。
- **指标：**任务成功率（Succ）、已执行受保护写操作中的安全比例（AS）、同时成功且没有不安全写操作的任务比例（STS），以及出现不安全写操作的任务数（#U）。
- **机制验证：**在 Airline 自然任务上消融修复、跨动作保留授权、选择性失效、最小请求、后果确认和组授权；另构造 **ClosureBench**，测试反复修订、证据变化及多个授权同时变化时的行为，并比较不同修复预算。

## 4. 资源与算力

- 论文**未报告 GPU 型号、数量、训练时长或总计算量**；方法主要是执行时的规则检查与图更新，并非训练新模型。
- 文中报告 ACG 的智能体交互开销约为**每任务 6.2 万—9.9 万输入加输出 token**，且无需额外调用守卫模型。该统计不包含模拟用户和独立安全审查的调用，不能视为系统总成本。

## 5. 实验数量、充分性与公平性

- 主实验为 **2 个领域 × 3 个模型 × 5 种方法**，每种方法、每个模型覆盖全部 164 项自然任务；即每种方法约有 **492 次任务运行**。每项任务只运行 **1 次**。
- 三组自然任务消融均覆盖 50 项 Airline 任务和 3 个模型。ClosureBench 共构造 1,224 个案例，表中报告其中 **936 个**，并测试 6 档修复预算。
- **充分性：**跨模型、跨领域的主实验，加上自然任务消融和固定规则的压力测试，为机制提供了较完整的证据；安全性还采用两名独立审查者、分歧交由人工裁决。
- **客观性边界：**各方法使用同一任务清单和共享运行设置，但基线经过适配，不同方法也会改变后续对话轨迹；单次运行不足以估计波动。自然任务安全标签依赖模型审查，虽有盲审和人工仲裁，仍可能存在判断偏差。

## 6. 主要结论与发现

- ACG 在**六个模型—领域组合中均取得最高 AS**，在其中**五个组合取得最高 STS**；相较 Raw，任务成功率在五个组合中提高或持平。它并非在每项成功率指标上都领先，例如 DeepSeek 的 Retail 任务成功率低于 Raw。
- 六个组合的不安全任务数合计由 Raw 的 **75** 降至 ACG 的 **8**。Airline 场景下，ACG 对三个模型均同时提升了操作安全与安全任务完成表现。
- 消融结果支持两项机制的互补性：**保留未受影响的授权**减少重复授权，**只请求当前依赖上必要的缺失项**减少冗余修复；单独采用其中一项不能完全替代另一项。
- 在报告的 ClosureBench 案例中，ACG 于 **4 个修复额度**下达到 **91.7% STS**，于 **8 个额度**下达到 **100% STS**；复用过期批准则产生大量不安全执行。

## 7. 优点

- **问题界定清晰：**关注“部分指令变化后授权如何演化”，而不只判断孤立调用是否合规。
- **权限粒度较细：**同时处理证据新鲜度、授权范围、组内共享字段、成员专属字段及需要单独同意的实际后果。
- **检查与执行衔接严谨：**保留原工具调用、版本再验证和一次性额度，有助于避免确认内容与实际执行内容脱节。
- **机制可检验：**给出选择性保留和当前缺失项最小覆盖的形式化性质，并用消融及受控案例检验其作用。

## 8. 不足与局限

- **高度依赖规范质量：**工具参数映射、依赖、业务规则和重要后果由开发者编写；遗漏或写错规则时，图上的授权成立不代表现实操作安全。
- **依赖可信基础设施：**需要可靠的环境证据、用户身份认证及确认接口；外部服务若不支持条件更新或事务，最终检查与实际写入之间仍可能发生状态变化。
- **真实场景覆盖有限：**自然实验仅有两个客服领域，用户为模拟模型；ClosureBench 的变化是受控构造，不能说明真实用户以同等频率产生这些情况。
- **成本与统计证据仍不完整：**自然任务每项仅试验一次，未报告结果方差；token 开销也未覆盖模拟用户、审查和完整系统部署成本。
- **理论保证有明确范围：**“最小修复”仅是当前固定动作、当前缺失集合上的依赖去冗余；它不保证用户一定同意、不保证交互最终结束，也不能撤销已经完成的外部写操作。
