## 摘要
基于大语言模型的 Web 智能体能够自主完成用户任务，但欺骗性界面可能诱导其产生违背用户利益的结果。现有防御方法主要通过阻止、引导或重新规划来干预智能体行为。我们发现一种不同的失效模式：即使某项操作符合任务要求，也可能因当前 Web 状态而造成未经授权的后果。这表明，应将与任务相关的 Web 状态本身视为运行时控制目标。为此，我们提出 Veer，一种部署在智能体侧的运行时防御机制。它将任务规划交由基础智能体负责，并在拟执行的操作会造成未经授权的后果时干预 Web 状态。在修改实际运行环境之前，Veer 会构建一条通向安全且与任务相关的状态的前瞻性干预轨迹，并结合运行时状态锚定与验证来执行该轨迹。在 TrickyArena 和 WebDecept 上，Veer 在全部三种评测设置中均取得最高的安全任务完成率；在 TrickyArena-Single 和 TrickyArena-Multi 上分别比次优防御方法高出 15.9 和 25.0 个百分点，同时将 WebDecept 上的暗黑模式成功率降至 0.3%。这些优势在不同暗黑模式类型以及全部 12 种智能体、模型和基准测试配置下均得以保持。消融实验表明，主动状态干预带来的提升最大，前瞻性推演和时序证据也带来了额外改进。这些结果表明，与任务相关的 Web 状态是保护 Web 智能体免受欺骗性结果影响的有效运行时控制目标。

## Abstract
LLM-based Web agents can autonomously complete user tasks, yet deceptive interfaces can steer them toward outcomes that conflict with users' interests. Existing defenses primarily intervene on agent behavior through blocking, guidance, or replanning. We identify a distinct failure mode: a task-valid action can still realize an unauthorized consequence because of the current Web state. This motivates treating task-relevant Web state itself as a runtime control target. We introduce Veer, an agent-side runtime defense that leaves task planning to the base agent and intervenes on Web state when a proposed action would produce an unauthorized consequence. Before modifying the live environment, Veer constructs a prospective intervention trajectory toward a safe task-relevant state and executes it with runtime grounding and verification. Across TrickyArena and WebDecept, Veer achieves the highest safe task completion in all three evaluation settings, exceeding the next-best defense by 15.9 and 25.0 percentage points on TrickyArena-Single and TrickyArena-Multi, respectively, while reducing dark-pattern success on WebDecept to 0.3%. These gains persist across dark-pattern types and all 12 agent, model, and benchmark configurations. Ablations show that active state intervention provides the largest gain, while prospective rollout and temporal evidence contribute additional improvements. These results establish task-relevant Web state as an effective runtime control target for protecting Web agents from deceptive outcomes.

# 论文总结：Veer——在行动前修正网页状态

## 1. 核心问题与研究意义

- **核心问题**：Web 智能体拟执行的动作即使符合用户任务，也可能因当前网页状态而产生未经授权的结果。例如，用户要求购买笔记本电脑，“结账”本身是合理动作；但如果购物车中已被自动加入延保，直接结账就会一并购买延保。
- **研究动机**：已有防御主要警告、拦截或要求智能体重新规划动作，却未充分处理“**动作合理、状态不安全**”的情况。论文因此提出：除控制智能体动作外，还应把决定动作后果的、与任务相关的网页状态作为运行时干预对象。
- **整体含义**：防御不一定要阻止任务继续；若能先移除多余选项、撤销不必要的同意等，再让基础智能体继续工作，就有机会同时维护安全与任务完成率。

## 2. 方法论：如何在行动前改变状态

Veer 是部署在基础智能体与浏览器环境之间的运行时防御层，**不接管基础智能体的常规任务规划**，只在拟执行动作可能造成未经授权后果时介入。

1. **判断动作在当前状态下的后果**  
   Veer 结合用户原始指令、当前页面、历史交互中仍有效的证据，以及基础智能体提出的动作，预测该动作会实际造成什么结果，再判断结果是否获得用户授权。用户授权仅从原始指令提取；网页内容可以帮助确定任务所指对象，但不能替用户新增许可。判断分为“已授权”“未授权”“不确定”；不确定时进行有次数限制的证据收集，仍无法确认则不直接放行动作。

2. **确定需要改变和保留的状态**  
   对未授权后果，Veer 构造干预目标 \(I_t=(R_t,S_t^*,P_t)\)：\(R_t\) 是造成风险的当前状态，\(S_t^*\) 是期望达到的安全状态，\(P_t\) 是必须保留的任务进度或能力。例如，取消自动加入的延保，同时保留已选中的笔记本电脑。

3. **先规划完整修正轨迹，再操作真实网页**  
   Veer 在修改页面之前，列出所需的浏览器操作、每步预期效果及步骤依赖。对于“关闭多个设置后点击保存”一类问题，它会预先考虑整个修正序列，而不是在真实网页上随意试错。这里的“前瞻性推演”是**预先声明预期状态变化和依赖关系**，并不依赖训练好的网页模拟器。

4. **逐步校准、验证与必要时重规划**  
   执行每一步前，Veer 在实时页面中重新定位控件并检查前置条件；执行后，对照预期效果核验状态变化。若实际效果不符，就停止沿用后续步骤，并在原干预目标不变的前提下重新规划。只有安全目标已达到、风险状态已解决且任务相关状态得到保留，才把控制权交还基础智能体。

## 3. 实验设计与对比方法

- **TrickyArena**：覆盖购物、新闻、音乐和健康应用。其中单一暗黑模式设置有 **88** 个任务—条件配置；多暗黑模式设置有 **68** 个配置，每个配置同时包含 2—4 种欺骗条件。
- **WebDecept**：**45** 个购物任务分别置于 **7** 种欺骗场景中，共 **315** 个任务—场景配置；场景包括弹窗、横幅、购物车附加商品、重定向和价格漂移等。论文另报告排除重定向与价格漂移后的 **225** 个“基准真值给出安全完成路径”的配置。
- **对比方法**：无防御基础智能体，以及 ICP、Guardrail、DUDE-S2、Spotlighting、VIGIL、SafePred，涵盖提示警告、界面审查、动作审核、后果预测与重新规划等防御方式。
- **评价指标**：暗黑模式成功率 **DPSR**（越低越好）、任务成功率 **TSR**（越高越好），以及主要指标**安全任务完成率 STC**（任务完成且未发生任何被评估的欺骗结果，越高越好）。

## 7. 方法与实验亮点

- **控制点新颖**：区分“动作是否符合任务”与“动作在当前状态下会造成什么后果”，针对传统动作拦截较难处理的风险来源。
- **明确兼顾任务进度**：干预目标同时写明风险状态、安全目标和应保留的状态，避免把“安全”简单等同于停止执行。
- **适配黑箱网页**：只使用基础智能体可用的浏览器操作和可观察证据，不要求访问网站源码、后端状态或暗黑模式标签。
- **执行机制审慎**：先规划依赖步骤，再在真实页面逐步定位与核验；预期和现实不一致时停止后续步骤并重规划。
- **评价兼顾安全与效用**：以 STC 衡量“完成任务且未受诱导”，避免只靠降低欺骗成功率、却大幅牺牲任务完成率来宣称防御有效。

## 8. 不足与局限

- **依赖可观察、可修正的状态**：若风险完全由不可见的服务端状态决定，或页面没有可用的修正入口，Veer 难以实施状态干预。
- **授权判断可能模糊**：用户指令若未充分说明偏好，系统可能无法确定某一附加后果是否获准；保守地不放行动作也可能影响任务完成。
- **仍依赖基础智能体**：Veer 修正状态后会交还控制权，不保证基础智能体后续导航、信息检索或任务执行一定正确。
- **泛化与成本尚待验证**：实验限于两个受控基准及所选模型和智能体；尚缺更广泛真实网站、动态界面下的效果与延迟、费用评估。
- **结果解读须注意基准特性**：WebDecept 的可行子集排除了两个场景，不能据其结果推断所有欺骗条件都可安全完成；TrickyArena 的个别条件下 Veer 仍会失败，例如附录中新闻领域的某一混淆条件，**3/3** 个配置仍发生欺骗结果。
