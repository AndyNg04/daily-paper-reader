## 摘要
基于大语言模型的智能体越来越多地在需要与用户、工具和外部系统交互的环境中运行。然而，大多数安全评估都假设用户是被动的、控制方式是静态的，忽略了影响真实智能体行为的交互动态。我们提出 DUMA-Bench，这是一套用于衡量双重控制交互下智能体安全性的基准与评估协议。在双重控制交互中，智能体和用户都能影响共享环境的状态。DUMA-Bench 扩展了 τ²-bench，引入涵盖八类漏洞的对抗性环境，包括检索增强生成（RAG）投毒、跨智能体操纵和不安全输出处理。我们在八个领域和多种用户行为模式下，评估了来自五个模型家族（OpenAI、Anthropic、DeepSeek、Qwen 和 Z.ai）的 14 个模型。实验结果表明，引入双重控制交互后，攻击成功率从 26.9% 上升至 41.1%。这些结果表明，智能体安全性并非仅由模型本身决定，而是在模型、用户与环境的交互中形成的。DUMA-Bench 为研究真实智能体部署中的安全性提供了此前缺失的评估层。

## Abstract
LLM-based agents increasingly operate in environments where they interact with users, tools, and external systems. Yet most security evaluations assume passive users and static control, ignoring the interactive dynamics that shape real agent behavior. We introduce \textbf{DUMA-Bench}, a benchmark and evaluation protocol for measuring agent security under \emph{dual-control} interaction, where both the agent and the user can influence the shared environment state. DUMA-Bench extends $τ^2$-bench ~\cite{barres2025tau} with adversarial environments covering eight vulnerability classes, including RAG poisoning, cross-agent manipulation, and unsafe output handling. We evaluate \textbf{14 models from five model families} (OpenAI, Anthropic, DeepSeek, Qwen, and Z.ai) across eight domains and multiple user-behavior regimes. Across our experiments, introducing dual-control interaction increases the attack success rate from \textbf{26.9\%} to \textbf{41.1\%}. These results show that agent security is not solely a property of the model but emerges from the interaction between the model, the user, and the environment. DUMA-Bench provides a missing evaluation layer for studying security in realistic agent deployments.

# DUMA-Bench 论文总结

## 1. 核心问题与整体含义

- **研究问题**：现有智能体安全评测往往让模型面对固定输入，或假设用户不参与后续操作；但实际部署中，用户、智能体、工具和外部内容会持续相互作用，共同改变环境状态。这种差异可能使传统评测低估安全风险。
- **核心观点**：智能体安全不只是模型自身的属性，还取决于用户如何参与、外部内容如何进入工作流，以及工具操作如何改变环境。论文因此关注从“被动用户”切换到“用户与智能体共同控制环境”后，安全评测结论会发生什么变化。

## 2. 方法论

- **双重控制评测**：DUMA-Bench 基于 τ²-bench 的交互框架，设置两种评测模式：
  - **Solo**：没有活跃用户参与，主要由智能体与环境交互。
  - **Dual-control**：用户模拟器与智能体多轮交流；双方的消息及可用工具操作共同塑造后续轨迹。
- **可执行安全任务**：每个任务包含安全策略、可变环境状态、领域工具、对抗性材料、用户情境和可执行断言，而非仅是一条攻击提示词。
- **评分方式**：
  - **状态断言**检查执行后是否发生违规工具操作或环境变化，可确定性复现。
  - **通信断言**检查回复是否泄露受保护信息或包含不安全内容；论文用温度为 0 的 GPT-4o 裁判评判此类断言。
  - 一个任务计为通过，须其计分范围内的**所有断言均通过**；任一断言失败即视为攻击成功。因此，攻击成功率（ASR）是违规运行次数占总运行次数的比例。
  - 论文另用 **pass^k** 衡量重复运行的可靠性：它估计同一任务的 *k* 次独立运行全部通过的概率，*k* 越大，标准越严格。

## 3. 实验设计

- **Benchmark 内容**：共 **35 个可执行任务、8 个安全领域**，涉及邮件检索投毒、跨智能体协作者笔记操纵、不安全输出、CRM 敏感数据过度披露、基础设施资源滥用、营销钓鱼活动、客服身份冒充和影子工具诱导。
- **评测对象**：来自 OpenAI、Anthropic、DeepSeek、Qwen、Z.ai 五个模型家族的 **14 个模型**。所有模型使用相同任务定义和工具接口。
- **主要对比**：比较 Solo 与 Dual-control 两种**评测制度**下的安全表现，而不是比较两种防御方法。用户侧统一采用 GPT-4o-mini 模拟；另在跨厂商模型子集上比较用户模拟器温度 **0、0.5、1.0** 对结果的影响。

## 6. 主要结论与发现

- 总体 ASR 从 **Solo 的 26.9% 升至 Dual-control 的 41.1%**，增加 **14.2 个百分点**；相应的单次通过率从 **73.1% 降至 58.9%**。论文报告这一总体差异具有统计显著性。
- 影响具有明显的**领域差异**：营销钓鱼领域 ASR 从 **2.2% 升至 61.5%**，而邮件 RAG 钓鱼领域从 **61.0% 略降至 57.9%**。因此，交互评测不仅改变总体风险水平，也改变哪些漏洞更容易被观察到。
- 用户模拟器温度变化对所测子集的**总体 ASR 影响较小**，但个别领域仍有局部波动。模型能力与安全稳健性也并非简单正相关：部分模型，尤其论文所测的 GPT-5 系列，在切换评测模式后 ASR 增幅较大；这不能直接证明能力或推理模式是原因。

## 7. 优点

- 将**安全威胁与双重控制交互**结合，补足了仅测静态攻击或仅测交互任务的评测空缺。
- 使用带工具和可变状态的**可执行场景**，比单轮提示词更接近真实工作流。
- 以确定性状态检查为主要评分依据，同时用通信断言捕捉“未执行违规操作、但文字泄密”等失败。
- 报告总体、领域、模型、用户行为变化和重复运行可靠性，避免只给出单一平均分；作者也明确限定了制度对比的因果解释范围。

## 8. 不足与局限

- **覆盖有限**：35 个任务、8 个领域无法穷尽真实部署中的工具生态、攻击策略和用户行为。
- **模拟用户与真实用户存在差距**：固定采用 GPT-4o-mini 有助于可比性，但未必能代表人类用户或其他攻击者的行为分布。
- **裁判偏差风险**：部分任务依赖 LLM 判断通信内容。人工抽查与裁判在 60 项中一致 56 项，其余案例提示边界措辞可能影响评分。
- **缺少细粒度归因**：尚无法区分多轮对话、用户施压、工具调用和环境状态变化各自带来的风险增量；模型间推理设置也并非完全可比。
- **外推与复现信息仍需加强**：模拟环境中的 ASR 不等同于真实部署的事故概率；算力与成本未披露，附录部分计数和汇总口径亦需进一步澄清。
