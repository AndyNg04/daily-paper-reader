## 摘要
服务于不同用户的大语言模型（LLM）智能体经常处理相关任务，但彼此独立的用户历史记录可能使其他智能体无法获取可复用的经验。汇集记忆能够扩大经验的可访问范围，却也可能迁移与接收用户需求相冲突的偏好。我们提出 ShareMem，一种在共享可复用经验的同时，以接收用户自身偏好为依据应用这些经验的记忆架构。共享经验指明如何行动以及需要查阅哪些偏好；接收用户的记忆则提供这些偏好的具体取值。两阶段整合首先在本地提炼经验，再将被接受的修改整合到共享池中。在执行过程中，范围优先检索在统一的条目数量预算下联合选择本地经验与共享经验，而与用户绑定的通道则支持初始偏好检索和由智能体主动发起的偏好检索。我们使用四种骨干模型，在网页导航（Mind2Web）、在线个性化交互（VitaBench 2.0）和多会话编程（MemoryCode）任务上评估 ShareMem。相较于匹配设置下的用户本地记忆方案，ShareMem 在全部四种模型上分别提升了上述任务的步骤成功率、平均任务成功率和对话级宏平均编程得分。消融实验表明，两阶段整合能够缩小共享池规模、减少归纳过程的词元用量，并改善下游性能，同时验证了经验指导与主动偏好检索之间的互补性。进一步分析表明，当相关本地经验稀缺时，共享带来的帮助最大，而来源质量和跨用户偏好干扰则限制了有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

## 1. 核心问题与整体含义

### 1.1 研究背景与动机
- 个性化 LLM 智能体通常为每位用户维护独立的长期记忆，其中同时包含：
  - **可复用经验**：任务流程、工具调用顺序、检查与恢复策略。
  - **用户特定偏好**：命名规则、饮品温度、出行舱位等具体要求。
- 不同用户经常执行相似任务，但独立记忆使智能体无法利用其他用户已经积累的经验。论文将其称为**经验可达性瓶颈**。
- 直接汇集历史虽然扩大信息访问范围，却可能把贡献者的偏好误用于接收用户。例如，复用编程流程是合理的，照搬另一用户的变量命名习惯则可能违背当前要求。

### 1.2 核心问题与整体意义
论文研究的是：

> **如何让智能体复用他人的任务经验，同时按照自己用户的偏好执行？**

其基本立场是区分**信息可访问性**与**信息适用性**：允许检索某条记忆，并不意味着其中的具体值适用于当前用户。因此，跨用户共享应主要传递“如何做”和“需要查询哪些约束”，而非他人的具体偏好。

## 2. 方法论：核心思想与技术流程

### 2.1 记忆分离：共享程序，保留个人取值
ShareMem 将记忆组织为三类：
- **用户偏好库**：保存当前用户的具体要求，只允许该用户的智能体访问。
- **本地经验库**：从该用户历史中提炼的可复用程序。
- **共享经验库**：整合多个用户的可迁移经验。

经验条目记录任务触发条件、输入槽位、操作步骤、需要查阅的偏好维度，以及验证和恢复策略。具体用户值应被改写为语义占位符。

例如，共享经验可以提示“订票前查询舱位偏好”，但不应保存“选择商务舱”。

### 2.2 两阶段经验整合
**第一阶段：本地整合**
1. 对符合协议的轨迹或历史会话确定适用范围。
2. 从本地经验库检索最多 **5 条邻近经验**。
3. LLM 记忆管理器结合新证据和已有经验，选择新增、替换、删除或不更新。
4. 输出被接受的本地修改集合，同时抽象掉来源用户的具体值。

**第二阶段：共享整合**
1. 将被接受的本地修改作为证据，而不是直接把所有原始会话写入共享库。
2. 为这些修改检索共享库中的邻近经验。
3. 共享管理器根据共享库现状独立决定修改操作。

需要注意：**本地删除或替换不会机械地同步为共享库中的相同操作**；没有被接受的本地修改时，共享库保持不变。

### 2.3 范围优先的联合经验检索
- 首先按环境元数据划分适用范围，并从直接匹配到宽泛回退排序。
- 在同一优先级内，本地与共享经验共同按相关性竞争，**不预留来源配额**。
- 最终采用统一的 **5 条经验预算**；低优先级范围只能填补剩余位置，不能挤掉高优先级结果。
- 每个可访问集合最多提供 **25 条候选经验**。

范围设置分别为：
- **Mind2Web**：网站 → 子域 → 域 → 其他网站。
- **VitaBench 2.0**：同任务领域 → 其他领域。
- **MemoryCode**：统一编程范围，不使用多层回退。

### 2.4 初始与主动偏好检索
- 任务开始时，依据任务描述检索最多 **10 条当前用户偏好**。
- 执行过程中，智能体可以自主发起更具体的偏好查询，每次同样最多返回 10 条。
- 共享经验只指导“哪些个性化字段需要解决”，不会自动触发查询。
- 查询是只读操作，结果加入执行上下文；当前任务、当前用户偏好和工具观察优先于经验指导。

**整体流程**可概括为：

> 历史交互 → 本地经验整合 → 共享经验整合 → 范围优先联合检索 → 查询当前用户偏好 → 执行与验证。

## 3. 实验设计：场景、Benchmark 与对比方法

### 3.1 三类评测场景

| Benchmark | 场景与规模 | 主要指标 | 主实验协议 |
|---|---|---|---|
| **Mind2Web** | 网页操作；20 个模拟用户、252 个评测任务；来源质量分析使用 1,009 个训练任务 | 元素准确率、动作 F1、步骤成功率 | 离线构建经验，评测期间冻结 |
| **VitaBench 2.0** | 配送、到店消费、旅行服务；56 个用户、771 个子任务 | Avg@3、Pass@3、Pass³ | 在线积累经验，仅全奖励子任务可贡献经验 |
| **MemoryCode** | 多会话编程；3 个固定的 20 对话子集，分别含 395、413、420 个任务 | 对话宏平均得分 D-MS | 历史经验与偏好快照冻结，可主动检索偏好 |

- **Avg@3**：三次试验的平均成功率。
- **Pass@3**：三次中至少成功一次。
- **Pass³**：三次全部成功。
- Mind2Web 主实验是在**记录的网页状态上预测动作**，并非完整实时浏览器任务执行。
- MemoryCode 使用原始 **AST/正则表达式评估器**；VitaBench 使用基于评分规则的评估器。

### 3.2 受控记忆配置
- **NONE**：不使用长期记忆。
- **PREF**：仅访问当前用户偏好。
- **LOCAL**：当前用户偏好 + 本地经验。
- **SHARE-ALL**：本地和共享经验 + 当前及其他用户偏好。
- **ShareMem**：本地和共享经验 + 仅当前用户偏好。

其中，SHARE-ALL 对其他用户偏好进行来源标注，明确其非权威地位，并在 10 个偏好位置中尽量为当前用户预留至少 7 个位置。因此，它不是简单的“无标签混合记忆”基线。

Mind2Web 不提供偏好通道，只比较 NONE、LOCAL 和 ShareMem。

### 3.3 骨干模型与额外参考系统
- 四个骨干模型：**Qwen 3.6-27B、DeepSeek v4-flash、Gemma 4-26B、Gemini 3 Flash**。
- 检索组件：**BGE-M3 嵌入模型、BGE-Reranker-v2-M3 重排序模型**。
- 额外比较：
  - Mind2Web：**AWM**。
  - VitaBench：**RAG、Rewrite、Full-CTX、Ground-truth**。
  - MemoryCode：**Full-CTX、Full-Pref**。

这些额外系统比较主要使用 Qwen，且提供的信息量不同，应视为系统级参考，而不是严格等信息量的组件对照。

## 6. 主要结论与发现

### 6.1 共享经验在主要指标上带来一致但幅度不一的收益
相较 LOCAL：

| 骨干模型 | Mind2Web 步骤成功率增益 | VitaBench Avg@3 增益 | MemoryCode D-MS 增益 |
|---|---:|---:|---:|
| Qwen | +4.10 | +2.16 | +2.91 |
| DeepSeek | +3.79 | +2.46 | +0.16 |
| Gemma | +2.46 | +1.34 | +1.39 |
| Gemini | +2.35 | +1.25 | +0.94 |

以上为百分点或 0–100 评分尺度上的分数变化。总体支持经验共享的价值，但**不意味着所有指标均提升**：例如 Gemini 在 VitaBench 的 Pass³ 略低于 LOCAL。

### 6.2 本地经验越稀缺，共享越有价值
在 Qwen Mind2Web 中：
- 同站点本地经验覆盖率 **0%**：共享增益 **+4.10**。
- 覆盖率 **49.60%**：增益 **+1.30**。
- 覆盖率 **98.81%**：增益 **−0.13**。

这说明共享主要补足本地缺失的相关经验，而非总能在完整本地记忆之上继续增益。

### 6.3 经验指导与主动偏好检索互补
Qwen MemoryCode 中：
- 仅初始偏好检索时，加入本地与共享经验带来 **+1.37**。
- 初始加主动检索时，经验带来 **+9.48**。

但这里衡量的是**本地与共享经验的合计贡献**，不能解释为跨用户共享单独贡献了 9.48 分。

### 6.4 更多记忆与更广访问不一定更好
- 两阶段可编辑整合比直接写入、仅追加产生更小经验池，并获得更好结果。
- SHARE-ALL 的平均表现通常不如 ShareMem；来源标签和禁止误用的提示仍不能完全防止采用他人偏好。
- 在暴露于他人偏好的失败样本中，审计确认的误用比例随模型和任务变化，最高为 Gemma 在 MemoryCode 的 **10.69%**。这不是全体任务的误用率。

### 6.5 收益存在上限
- 用智能体轨迹替换金标准示范，会削弱共享收益。
- 过严的经验准入阈值减少覆盖，可能抵消质量提升的好处。
- ShareMem 并非始终优于更完整的历史或偏好输入：
  - VitaBench 上低于 Rewrite 与 Full-CTX。
  - MemoryCode 上低于 Full-Pref。

## 7. 优点与亮点

- **问题定义准确**：将共享中的核心挑战从“能否访问”推进到“能否正确适用”。
- **架构清晰**：经验共享与用户偏好访问分离，比仅依靠来源标签和提示更直接地限制外来偏好暴露。
- **经验不仅描述操作，还描述约束查询**：把“需要知道什么”纳入程序记忆，与主动检索形成互补。
- **可编辑、池感知的两阶段整合**：兼顾去冗余、经验粒度和构建成本，而不是无限追加。
- **固定联合检索预算**：降低“共享只是增加上下文条目数量”的混淆。
- **边界分析较全面**：覆盖本地经验、证据质量、准入阈值和偏好干扰。
- **报告较克制**：正文明确承认可重复成功率、完整上下文和高覆盖场景下的不足。

## 8. 不足与局限

### 8.1 实验覆盖与外部有效性
- Mind2Web 的用户身份来自人工任务分配，缺乏真实用户差异；其主设置主动制造同网站本地经验缺失，较有利于展示共享收益。
- 网页主实验不是端到端实时浏览器执行，尚不能证明真实长流程任务成功率同幅度提高。
- 尚未验证大规模真实用户部署、跨组织环境和高风险任务。
- 范围依赖现成环境元数据，未知环境中的自动范围判断能力未被充分检验。

### 8.2 因果识别与统计局限
- 写入消融重新构建经验池，没有固定本地池。
- 仅追加变体同时改变维护操作和提取上下文。
- 禁用主动检索同时限制信息访问与交互机会。
- 来源质量实验同时改变归纳经验和附带示范。
- 范围优先检索并非所有模型都优于平坦检索：Gemma 的三种子平均结果中，平坦检索略高。

### 8.3 隐私与安全边界
- 偏好库访问隔离不等于完整隐私保障：共享经验的去个人化仍主要依赖 LLM 抽象与提示约束。
- 缺少形式化泄露保证、系统性的残留隐私审计，以及恶意贡献、记忆投毒和提示注入测试。
- 真实部署仍需用户授权、共享审查、来源追踪和撤回机制。

### 8.4 评估与应用成本
- 干扰审计由同一模型筛查并重复判断，可能存在系统性评判偏差；漏检未被衡量。
- AST/正则评估主要检查规则遵循，不能代表代码全部功能正确性、可维护性和安全性。
- 总推理成本、主动检索延迟及多用户并发维护开销未披露。
- 准入质量和覆盖率存在权衡；“仅成功经验”也可能遗漏具有学习价值的失败案例。

**总体评价**：ShareMem 的主要贡献是建立了“共享程序性经验、按当前用户取值执行”的清晰架构，并提供较系统的收益与边界证据。它适合本地经验不足、任务具有可迁移流程的场景，但尚不是跨用户隐私安全或真实部署有效性的完整解决方案。
