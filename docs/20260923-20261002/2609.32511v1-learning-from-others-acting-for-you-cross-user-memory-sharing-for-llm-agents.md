## 摘要
服务于不同用户的大语言模型（LLM）智能体经常需要解决相关任务，但彼此独立的用户历史可能使其他智能体无法获取可复用的经验。汇集记忆能够扩大经验的可获取范围，却也可能迁移与接收方用户需求相冲突的偏好。我们提出 ShareMem，一种在共享可复用经验的同时，以接收方用户自身偏好为依据来应用这些经验的记忆架构。共享经验指明如何行动以及需要查阅哪些偏好，而接收方用户的记忆则提供这些偏好的具体取值。两阶段整合机制先在本地提炼经验，再将通过审核的修改纳入共享池。在执行过程中，范围优先检索在统一的条目预算下联合选择本地经验与共享经验，同时通过用户绑定通道支持初始偏好检索和智能体主动发起的偏好检索。我们使用四种骨干模型，在网页导航（Mind2Web）、在线个性化交互（VitaBench 2.0）和多会话编程（MemoryCode）任务上评估 ShareMem。相较于同等配置下仅使用用户本地记忆的方案，ShareMem 在全部四种模型上均分别提升了步骤成功率、平均任务成功率和对话级宏平均编程得分。消融实验表明，两阶段整合有助于缩小共享池、降低经验归纳的词元消耗并改善下游性能，同时验证了经验指导与主动偏好检索之间的互补性。进一步分析表明，当相关本地经验匮乏时，共享带来的收益最大，而来源质量和跨用户偏好干扰则限制了有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

## 1. 核心问题与整体含义：共享经验，不共享个人偏好

### 研究动机与背景
- 多用户智能体系统中，不同用户经常处理相似任务，例如网页操作、订餐、旅行预订或编程。但各用户的历史与记忆彼此隔离，导致一个智能体无法利用其他智能体已经掌握的有效做法。
- 论文将其称为**“经验可达性瓶颈”**：有用的经验已经存在，却无法被需要它的智能体获取。
- 直接汇集所有用户的记忆又会产生另一种风险：将来源用户的偏好误当成当前用户的要求。例如，任务流程可以复用，但命名规范、饮品温度、舱位偏好通常不能直接迁移。

### 核心研究问题
> 如何让智能体复用其他用户的任务经验，同时仍按照当前用户自身的偏好行动？

论文强调两种不同的问题：
- **可获取性**：智能体是否能检索到相关经验？
- **适用性**：检索出的内容是否适合当前用户和任务？

整体意义在于：跨用户学习不能仅依赖扩大记忆访问权限，还需要把**通用程序知识**与**用户特定取值**分离。ShareMem 的基本原则是：

> 共享经验提供“怎么做、需要确认哪些偏好”，当前用户的记忆提供“这些偏好的具体值”。

## 2. 方法论：ShareMem 的核心思想与技术流程

### 2.1 记忆结构：经验与偏好分离
每个用户拥有两类本地记忆：
- **个人偏好 \(P_u\)**：保存该用户的具体要求，例如编码规则、饮食限制和出行偏好。
- **本地经验 \(E_{u,s}\)**：保存可复用的任务程序，按适用范围 \(s\) 分类。

此外，系统维护：
- **共享经验池 \(R_s\)**：跨用户共享经过抽象的任务经验。
- 默认不允许智能体访问其他用户的偏好库。

经验条目通常包含任务触发条件、输入槽位、操作步骤、偏好查询需求、验证与有限恢复策略。来源用户的姓名、地址、日期、具体偏好等应替换为语义槽位，而不是保留原值。

### 2.2 两阶段经验整合
经验写入不是直接将原始历史堆入共享池，而是经过两次整合：

1. **本地整合**
   - 对符合评估协议的轨迹或会话，确定其适用范围。
   - 检索最多 \(k_w=5\) 条相关本地经验。
   - LLM 记忆管理器结合新证据和已有经验，决定新增、替换、删除或不更新。
   - 只有实际接受的修改形成编辑集合 \(\Delta_{u,s}\)。

2. **共享整合**
   - 使用上述编辑集合，而不是所有原始会话，作为共享阶段的证据。
   - 为各项编辑检索相关共享经验，再由共享管理器独立决定如何更新共享池。
   - 本地删除或替换**不会机械地同步为同样的共享操作**；共享池根据自身内容重新判断。
   - 如果本地没有接受任何修改，共享池保持不变。

这一流程旨在减少重复、保留有用程序，并降低共享记忆的构建开销。

### 2.3 范围优先的本地—共享联合检索
执行任务时：
- 先根据网站、任务领域等元数据，将经验划分为从直接匹配到宽泛回退的范围组。
- 每个可访问经验集合最多提供 \(K_c=25\) 个候选。
- 同一优先级内，本地经验与共享经验共同排序，竞争统一的 **\(K=5\) 条预算**，没有固定的本地/共享配额。
- 只有高优先级候选不足时，才使用低优先级候选补齐；低优先级经验不能挤掉已选中的高优先级经验。

具体范围设置：
- **Mind2Web**：网站 → 子域 → 域 → 其他网站。
- **VitaBench 2.0**：同任务领域 → 其他领域。
- **MemoryCode**：单一编程范围，没有多层回退。

### 2.4 用户绑定的初始与主动偏好检索
- 初始阶段，根据任务查询最多召回 \(k_p=10\) 条当前用户偏好。
- 执行过程中，智能体可主动发起更具体的查询，补充尚未解决的个性化字段。
- 经验只指导“哪些约束需要确认”，**不会自动触发偏好查询**；是否查询及查询什么由智能体决定。
- 查询是只读操作，不修改偏好库；用户身份由环境绑定，防止跨用户访问。
- 当前任务要求、当前用户偏好和工具观察优先于经验指导。

**方法定位**：这是基于现有 LLM 的记忆管理与执行架构，而不是新的模型训练算法。

## 6. 主要结论与发现

### 6.1 共享经验带来一致但规模有限的增益
相对匹配的 LOCAL 配置：

| 核心指标 | 四模型上的增益 |
|---|---|
| Mind2Web 步骤成功率 | **+2.35～+4.10 个百分点** |
| VitaBench Avg@3 | **约 +1.25～+2.46 个百分点** |
| MemoryCode D-MS | **+0.16～+2.91 分** |

需要区分：
- 三类 benchmark 的指定核心指标在四个模型上均提升。
- **并非所有指标都提升**：例如 Gemini 的 VitaBench Pass³ 略低于 LOCAL。
- DeepSeek 的 MemoryCode 增益仅 0.16 分，实际意义与统计稳健性需进一步验证。

### 6.2 本地经验越稀缺，共享越有价值
Qwen 的 Mind2Web 分析中：
- 本地同网站覆盖率为 **0%**：共享增益 **+4.10** 个百分点。
- 覆盖率约 **49.60%**：增益 **+1.30** 个百分点。
- 覆盖率约 **98.81%**：增益 **−0.13** 个百分点。

这说明主要收益来自**补齐缺失经验**，而不是共享本身天然优于本地记忆。

### 6.3 更大的经验池不一定更好
- 两阶段可编辑整合产生更小的共享池，同时在三个 MemoryCode 子集上表现更好。
- 仅追加共享池达到 462～493 条，而两阶段方案为 1～40 条。
- 在固定五条检索预算下，重复或相似条目可能争夺候选位置，降低有效指导的密度。

### 6.4 经验指导与主动偏好检索互补
Qwen 的 MemoryCode 中：
- 仅初始召回时，加入经验指导提升 **1.37 分**。
- 允许主动检索时，加入经验指导提升 **9.48 分**。
- ShareMem 从初始召回改为初始加主动召回，提升 **13.09 分**。

这支持经验帮助智能体识别“还需要知道什么”，但该比较反映的是本地与共享经验的合并作用，不是共享经验单独的贡献。

### 6.5 来源质量与偏好干扰限制有效迁移
- 将金标准示范全部替换为智能体轨迹后，ShareMem 的步骤成功率下降 **5.90** 个百分点。
- 更严格的准入阈值能提高接纳标准，但会减少经验数量和范围覆盖。
- SHARE-ALL 的平均表现普遍不如 ShareMem；即使保留当前用户槽位、标注来源并明确禁止复制他人偏好，仍出现误用。
- 审计中，Gemma 在 MemoryCode 的**已暴露于他人偏好的失败任务**中，确认误用比例为 **10.69%**。该比例不是所有任务上的总体误用率。

### 6.6 ShareMem 并非所有参考系统中的最优方法
以 Qwen 为例：
- Mind2Web：比 AWM 高 **2.43** 个百分点。
- VitaBench：高于 RAG，但低于 Rewrite 和 Full-CTX。
- MemoryCode：显著高于原始历史 Full-CTX，但比 Full-Pref 低 **3.21 分**。

因此，选择性记忆具有紧凑性优势，但可能丢失更完整历史或偏好集合中的有用信息。

## 7. 优点

- **问题定义清晰**：将经验“能否获取”与个人偏好“是否适用”区分开，切中跨用户记忆共享的关键风险。
- **架构边界明确**：共享程序与偏好维度，具体偏好值通过用户绑定通道获得，不完全依赖执行提示词阻止误用。
- **记忆维护具有实际价值**：两阶段、可编辑整合同时改善记忆规模、构建成本和下游表现。
- **检索预算控制合理**：本地与共享经验竞争统一预算，避免仅靠额外增加上下文获得优势。
- **兼顾经验与个性化执行**：主动偏好查询让经验不仅指导操作，还能指导信息获取。
- **分析较客观**：展示了高本地覆盖时收益消失、低质量来源削弱迁移以及部分参考系统更强等边界。
- **协议描述较详细**：附录说明了用户分配、时间顺序、评分聚合、记忆更新与核心提示词，便于理解和复现。

## 8. 不足与局限

### 8.1 实验覆盖与真实性
- Mind2Web 是模拟用户分配和记录状态评估，不能证明真实浏览器长流程执行中的稳定收益，也不能验证偏好隔离效果。
- MemoryCode 的对话级样本规模有限，多子集结果仍不足以覆盖复杂真实开发场景。
- 未充分覆盖跨语言、权限差异、高风险任务和大规模多租户部署。
- 范围划分依赖网站或任务领域元数据，对标签缺失、错误以及跨领域任务的适应性尚未充分验证。

### 8.2 统计与因果归因
- 部分提升很小，主结果缺少全面的不确定性报告。
- 范围优先检索并非跨模型稳定更优：Gemma 三种子均值中，纯相似度检索反而高约 **0.20** 个百分点。
- 来源质量实验同时改变经验内容和附带示范，不能仅归因于经验抽象质量。
- 在线协议中，不同配置产生不同轨迹与后续记忆，性能差异同时包含即时作用和长期反馈效应。

### 8.3 隐私与安全保障不足
- 经验中的具体值去除主要由 LLM 提示词约束完成，**不是形式化隐私保证**。
- 即使偏好库隔离，共享经验仍可能泄漏来源信息、保留隐含偏好或受到恶意轨迹污染。
- 尚未系统评估成员推断、记忆投毒、提示注入、撤回同意和跨用户贡献删除等问题。

### 8.4 审计与应用限制
- 偏好误用审计依赖同一模型筛选和重复判断，缺少独立人工标注或异构裁判验证；漏检率未知。
- 共享收益高度依赖相关经验缺口与来源可靠性，不能默认适用于所有用户群体。
- 严格经验准入可能加剧冷启动，宽松准入又可能传播错误。
- 构建词元节省已得到报告，但实际部署延迟、运行费用、共享池并发更新与长期漂移仍缺少评估。
- 提供的版本为 **“Pre-print / Work in progress”**；当前证据更适合支持其设计原则与限定场景效果，而非全面生产可用性。

**总体评价**：ShareMem 的主要价值是提出并验证了一条清晰的跨用户学习原则——**共享可复用程序，并以接收用户的约束重新实例化**。其证据最有力地支持经验覆盖不足时的增益和紧凑记忆整合的价值；对真实规模部署、隐私保证及长期稳健性的证明仍不充分。
