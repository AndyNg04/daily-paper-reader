## 摘要
大语言模型（LLM）智能体在作为代理参与人—智能体—人通信时，面临严峻的隐私风险。为防止此类隐私泄露，智能体必须理解用户的社会关系，并遵守依赖于具体情境的社会信息披露边界。现有智能体记忆隐私研究主要关注即时交互，尚未探索长期关系中的信息披露问题。本文提出弹性隐私记忆架构 EP-Mem，将隐私重新定义为由用户掌控、跨社会角色的边界控制。EP-Mem 引入了两项设计：（1）由用户可配置的隐私策略驱动的词元级记忆，该策略对人物和事件进行分层，并将领域级默认流转规则与事实级白名单／黑名单例外相结合；（2）配备隐私引擎的可插拔边车组件，在摘要、细节和边界三种粒度上使披露控制与记忆保持一致，并在生成、存储和检索全过程中执行这些控制。我们构建了 EP-Bench，据我们所知，这是首个包含跨会话关联事件、用于评估策略条件下关系性信息披露的长期多方基准。实验表明，EP-Mem 的隐私分类准确率达到 94.0%，将披露许可判断准确率从 22% 提升至 68%，并将隐私泄露减少了 75.6%，同时保持了检索性能和跨基准泛化能力。

## Abstract
Large language model (LLM) agents face critical privacy risks when acting as delegates in human-agent-human communication. To prevent such breaches, agents must understand users' social relationships and adhere to context-dependent social information disclosure boundaries. Current studies on agent memory privacy focus on instantaneous interactions, leaving the long-term relational disclosure problem unexplored. In this paper, we propose EP-Mem, an Elastic Privacy Memory architecture that reframes privacy as user-owned boundary control across social roles. EP-Mem introduces (1) token-level memory driven by user-configurable a privacy policy that stratifies persons and events, combining domain-level default circulation rules with fact-level whitelist/blacklist exceptions; and (2) a pluggable sidecar with a privacy engine that aligns disclosure controls with memory across summary, detail, and boundary granularities, enforced throughout generation, storage, and retrieval. We construct EP-Bench, to our knowledge the first long-term multi-party benchmark with cross-session correlated events for policy-conditioned relational disclosure. Experiments show that EP-Mem achieves 94.0% privacy classification accuracy, improves disclosure-permission judgment from 22% to 68%, and reduces privacy leakage by 75.6%, while maintaining retrieval performance and cross-benchmark generalization.

  3. 验证显式授权判断和上下文脱敏，比仅依赖提示词或限制历史可见性更有效。

## 2. 方法论：用户策略、事件级授权与安全上下文生成

### 2.1 用户可配置的双侧隐私策略
策略文件同时描述**人物关系**与**信息类别**：

- **人物侧**：将接收者划分为不同信任层级。
  - L0：用户本人及其智能体。
  - L1、L2：进一步区分生活与工作领域，例如生活中的亲近关系、工作中的可信关系、同事或同学。
  - L3：外围关系。
  - L4：陌生人或公众。
- **信息侧**：将事件事实映射到用户定义的类别与隐私等级。
  - 普通类别：对应一个等级。
  - 穿透类别：可对应多个等级，默认受众取这些等级受众的并集。
  - 未授权类别：无法匹配时归入 L0，采用保守默认策略。

需要区分：**人物等级越高，信任越低；事实等级越高，通常表示其默认传播范围越广。** 生活与工作领域也不能仅按信任高低相互替代。

### 2.2 事实级白名单与黑名单
- **白名单**：对默认关系规则之外的接收者授予特定事实的访问权。
- **黑名单**：根据明确保密约束，禁止特定接收者访问某项事实。
- 判断顺序为：**先应用默认受众，再添加白名单，最后扣除黑名单；黑名单优先。**
- 系统区分“真实内容”和“掩饰性说法”：听过掩饰性说法，不意味着获得真实内容的授权。

作者允许“已知真实事实”在标注阶段支持白名单，但强调：**知情不应直接绕过最终拒绝规则。**

### 2.3 记忆粒度与边车架构
论文将记忆分为六层：

| 层级 | 内容 | EP-Mem 的作用 |
|---|---|---|
| F0 | 原子条目 | 保持原生结构；可建立与事件事实的索引 |
| F1 | 原始对话轮次 | 保留原生处理 |
| F2 | 事件级事实 | 核心隐私分类与授权控制粒度 |
| F3 | 会话摘要 | 连接原生记忆与隐私边车的共享索引 |
| F4 | 关键词 | 保留原生处理 |
| F5 | 会话元数据 | 提供关系与边界相关信息 |

- EP-Mem 不重写原生记忆系统，而是在旁侧维护隐私标注和事件事实。
- 这种 **sidecar（边车）** 设计支持增量接入、异步处理及逻辑上的存储隔离。
- 文中“词元级记忆”指显式文本记忆体系，**并不意味着逐词元执行访问控制**；主要授权粒度仍是事件级事实。

### 2.4 授权判断的三类情形
1. **单事实判断**
   - 检查黑名单、白名单、领域与默认等级，决定允许或拒绝。

2. **多事实隐私上限**
   - 对组合问题采用更严格的共同边界。
   - 不同领域的标签组合可保守地收缩至 L0。
   - 完整披露需要每个组成事实均通过授权检查，避免将多个分别可说的片段拼成不可说的整体。

3. **事件共指与跨会话片段**
   - 将问题拆分为独立信息单元，并寻找支持它们的事件事实。
   - 只将已有的、真实内容相关的白名单授权投射到对应单元；不把某个事件的授权扩散到整个类别。
   - 黑名单不在整个共指事件簇中直接合并，以保留不同片段的独立边界。
   - 每个问题单元都通过判断，才认为问题可以完整披露。

### 2.5 检索融合与上下文脱敏
- 检索阶段保留原生检索器，将原生检索分数与事件事实相关性分数加权融合；关闭事件权重时恢复原生排序。
- 生成阶段分三步：
  1. 从候选事实构建共享故事线。
  2. 按接收者授权删除、模糊或改写不可披露节点。
  3. 仅将可披露故事线和授权事实送入最终回答上下文。
- 若没有授权事实，则礼貌回避，不提供故事线。

### 2.6 策略演化
- 外部智能体根据错误反馈，更新分类、黑白名单、术语和事件共指四类补充提示。
- 更新经过批评子智能体的反泄露检查，禁止直接写入答案、题号或独特剧情补丁。
- 演化不改变固定授权规则，因此更接近**提示策略优化**，不是模型参数训练。

## 3. 实验设计：数据集、任务与对比方法

### 3.1 EP-Bench：长期多方关系披露基准
- 包含 **10 个第一人称长期脚本**，时间跨度约 **7–18 个月**，覆盖不同职业。
- 场景包括私聊、群聊、社交媒体帖子、邮件或通知等。
- 每个脚本包含至少两条因果关联故事线，以及跨会话敏感事件、状态变化和掩饰性说法。
- 主要面向中国社交语境，另提供 AI 翻译的英文版本。
- **Easy 版本**：427 个会话、752 条事件级事实。
- **Noisy 版本**：加入干扰会话后共 1,100 个会话，保留原问题与标签。
- 标签和解释由三位研究者通过共识审查。

### 3.2 三层任务
| 任务 | 规模 | 主要指标 |
|---|---:|---|
| Task 1：事件隐私分类 | 100 个问题 | 分类准确率 |
| Task 2：接收者披露许可判断 | 50 个问题；另有 50 个 T2E 泛化问题 | Exact、Partial、推理审计分数 |
| Task 3：面向不同受众回答 | 30 个问题、94 个受众实例 | 泄露、回答质量、受众差异、检索 |

关键指标包括：
- **PB**：至少泄露一项不可披露事实的回答比例。
- **PC**：发生泄露的回答中，违规事实占使用事实的比例。

- **Style、MIQ、LLM-judge**：评估关系语气、记忆整合、隐私及充分性。

## 6. 主要结论与发现

### 6.1 显式授权显著优于简单提示
- 事件隐私分类准确率达到 **94.0%**。
- Task 2 完全匹配准确率：
  - NoEngine_full：**22%**。
  - NoEngine_evid：**30%**。
  - EP-Mem：**68%**。
  - EP-Mem+Evo：**82%**。
- 移除披露判断后下降至 **28%**，说明显式判断是主要收益来源。

### 6.2 上下文脱敏是降低泄露的关键
- PB 从 NoEngine_evid 的 **0.738** 降至 EP-Mem 的 **0.180**，相对下降约 **75.6%**。
- 演化后进一步降至 **0.136**。
- 移除脱敏模块后 PB 升至 **0.493**，表明仅标注或判断权限还不够，最终生成上下文也必须受控。
- 这些是论文按脚本汇总的平均指标，**不能直接解释为所有真实部署回答的泄露概率**。

### 6.3 隐私收益仍有代价与残余风险
- EP-Mem 的回答风格、记忆整合及综合评分总体优于主要简单提示基线。
- 演化后充分性从 **4.38** 降至 **4.22**，综合分数从 **3.71** 略降至 **3.67**，说明隐私与信息充分性仍存在权衡。
- 系统并未消除泄露；部分脚本的演化甚至未改善或恶化某些指标。

### 6.4 检索总体保持，但并非全面提升
- LoCoMo 上 EP-SimpleMem 的 Recall@10 从 **0.4141** 提升至 **0.4651**。
- EP-MemGAS 的 Recall@10 略升，但 R@1、R@3、R@5 和 MRR 略降。
- 因而更准确的结论是：**边车设计通常能保持检索能力，部分配置有提升，但不保证各项指标同时改善。**

### 6.5 跨基准结果体现权衡，而非绝对优势
- CIMemories 上 EP-Mem 违规率为 **46.5%**，完整性为 **59.2%**。
- Filter-only 的违规率更低，为 **31.8%**，但完整性仅 **35.7%**。
- EP-Mem 的优势在隐私—效用平衡，而非最低违规率；迁移后的绝对违规水平仍较高。

## 7. 优点与亮点

- **问题定位贴近个人智能体应用**：将“能记住”与“能披露”明确分离。
- **用户主导且可解释**：人物、领域、类别和事实例外构成可审计策略，而非完全依赖模型自行推断社会规范。
- **事件级粒度合理**：比整段会话授权更精细，又比逐词控制更符合日常信息分享方式。
- **架构兼容性较好**：无需重写原生记忆检索器，适合对已有系统做增量增强。
- **覆盖上下文泄露通道**：不仅过滤事实，还处理摘要、故事线和回答生成中的间接暴露。
- **基准具有跨会话关联性**：真实内容、掩饰性说法、因果链和多受众问题，比孤立敏感事实测试更有挑战。
- **补充材料较透明**：提供形式化规则、提示模板、逐脚本结果和失败案例，也明确承认检索与回答不足。

## 8. 不足与局限

### 8.1 安全保证仍依赖 LLM
- 分类、事实提取、共指、脱敏和生成均可能发生模型错误。
- 虽然授权规则具有形式化描述，但大量执行过程依赖提示词，不能据此视为经过形式验证的确定性安全系统。
- 缺少针对提示注入、身份冒充、恶意社会工程和持续追问的系统性对抗评测。

### 8.2 标准证据测试弱化了真实部署难度
- 实际系统可能漏检关键保密约束、召回错误事件或使用过期关系信息。
- 标准证据实验主要证明“给定较正确输入时”的授权能力，尚未验证完整检索—授权—回答链路的可靠性。

### 8.3 基准覆盖有限
- 数据是研究者构建并审查的脚本，不等同于真实长期用户日志。
- 统一的层级与生活／工作划分可能与方法天然契合，难以覆盖复杂重叠群体、跨文化规范和多方共同拥有的信息。
- 英文版本为 AI 翻译，不能替代独立的跨语言、跨文化验证。

### 8.4 指标可能遗漏隐性泄露与事实错误
- PB 等指标虽然按规则汇总，**事实是否被回答使用仍依赖 LLM 判定**。
- 使用事实判定偏重明确谓词和对象，可能漏掉暗示、推断式暴露或多轮信息拼接。
- 将问题语义池外的事实计为违规，也可能混合隐私泄露与无依据生成。
- MIQ 在未使用事实时直接给 5 分，可能偏向无信息回答；KL 接近标准差异模式也不保证授权正确。

### 8.5 个案暴露出隐私与真实性的冲突
- 礼盒案例中，系统不泄露，但未向有权获知的客户提供足够细节。
- 咖啡案例中，演化后的回答出现“给摄影师”“是我的”等说法；从展示材料无法充分确认其证据支持，同时与标准回答有所偏离。
- 这提示：**低泄露指标不等于回答真实、充分或一致**，需要独立评估事实支持与多受众叙事一致性。

### 8.6 策略维护与系统治理尚不完整
- 用户需要维护关系、类别和例外规则；其配置成本、理解难度和误配置风险未通过用户研究验证。
- 根据“已知真实内容”生成白名单，可能固化历史误披露，且难以反映“曾经知道，但不应继续传播”的变化。
- 未充分评估授权撤销、历史记忆重新标注、共享事实权属、身份认证、存储加密及长期成本。

**总体判断：EP-Mem 是一个有价值的关系感知记忆治理框架，最有说服力的贡献是“显式授权判断 + 安全上下文投射”。目前证据支持其在受控条件下显著改善披露行为，但尚不足以将其视为真实长期代理沟通中的可靠隐私保障。**
