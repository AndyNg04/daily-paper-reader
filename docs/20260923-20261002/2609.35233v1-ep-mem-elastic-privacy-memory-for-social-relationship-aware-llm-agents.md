## 摘要
大语言模型（LLM）智能体在作为代理参与人—智能体—人通信时，面临严重的隐私风险。为防止此类隐私泄露，智能体必须理解用户的社会关系，并遵守依赖具体情境的社会信息披露边界。现有关于智能体记忆隐私的研究主要关注即时交互，尚未探索长期关系中的信息披露问题。本文提出 EP-Mem，一种弹性隐私记忆架构，将隐私重新界定为由用户掌控的跨社会角色边界控制。EP-Mem 引入了两项机制：（1）由用户可配置的隐私策略驱动的词元级记忆，该策略对人物和事件进行分层，将领域级默认流转规则与事实级白名单／黑名单例外相结合；（2）配备隐私引擎的可插拔边车组件，在摘要、细节和边界等粒度上使披露控制与记忆保持一致，并在生成、存储和检索全过程中执行这些控制。我们构建了 EP-Bench，据我们所知，这是首个包含跨会话关联事件、用于评估策略约束下关系型信息披露的长期多方基准。实验表明，EP-Mem 的隐私分类准确率达到 94.0%，将披露许可判断准确率从 22% 提升至 68%，并将隐私泄露减少了 75.6%，同时保持了检索性能和跨基准泛化能力。

## Abstract
Large language model (LLM) agents face critical privacy risks when acting as delegates in human-agent-human communication. To prevent such breaches, agents must understand users' social relationships and adhere to context-dependent social information disclosure boundaries. Current studies on agent memory privacy focus on instantaneous interactions, leaving the long-term relational disclosure problem unexplored. In this paper, we propose EP-Mem, an Elastic Privacy Memory architecture that reframes privacy as user-owned boundary control across social roles. EP-Mem introduces (1) token-level memory driven by user-configurable a privacy policy that stratifies persons and events, combining domain-level default circulation rules with fact-level whitelist/blacklist exceptions; and (2) a pluggable sidecar with a privacy engine that aligns disclosure controls with memory across summary, detail, and boundary granularities, enforced throughout generation, storage, and retrieval. We construct EP-Bench, to our knowledge the first long-term multi-party benchmark with cross-session correlated events for policy-conditioned relational disclosure. Experiments show that EP-Mem achieves 94.0% privacy classification accuracy, improves disclosure-permission judgment from 22% to 68%, and reduces privacy leakage by 75.6%, while maintaining retrieval performance and cross-benchmark generalization.

## 1. 核心问题与整体含义：长期记忆中的“知道”不等于“可以告诉”

### 研究背景与动机
- 当个人智能体从“与用户对话”转向“代表用户与第三方沟通”时，长期记忆不仅是回答问题的知识来源，也成为潜在的隐私泄露源。
- 同一事件对不同联系人可能具有不同的披露权限。例如，工作信息可以告诉同事，却未必可以告诉亲密家人；某人参与过事件，也不意味着他可以了解事件的所有细节。
- 现有长期记忆研究主要优化记忆构建、压缩和检索；隐私相关工作则多关注短期交互、孤立任务或有限关系设置，较少系统评估跨会话、多方社会关系中的选择性披露。

### 核心研究问题
> 智能体如何在保留长期记忆能力的同时，依据用户定义的社会关系、信息类别和具体上下文，决定“向谁披露什么、披露到什么程度”？

### 整体含义
- EP-Mem 将隐私从“敏感信息一律不说”转化为**用户自主控制的、依赖关系和情境的信息流转边界**。
- 理论基础是：
  - **通信隐私管理理论（CPM）**：用户拥有管理信息披露边界的权利。
  - **情境完整性理论（CI）**：隐私保护不意味着阻止一切信息流动，而是确保信息在合适的社会情境中流动。
- 文中的“弹性”主要指**面向不同受众和上下文调整披露范围**，并不是差分隐私或密码学意义上的隐私保证。

## 2. 方法论：策略分层、事实级例外与可插拔隐私引擎

### 2.1 核心思想
EP-Mem 不替换原有记忆系统，而是通过独立的 **sidecar（边车）组件**叠加隐私治理。其基本流程为：

1. 从长期对话中提取事件级事实。
2. 按用户策略标注事实的隐私类别、级别和黑白名单。
3. 检索与当前问题相关的事实。
4. 判断哪些事实可以向当前接收者披露。
5. 将允许披露的事实转换为安全上下文，再生成面向该受众的回答。

关键区分是：**相关记忆集合不等于可披露记忆集合。**

### 2.2 用户可配置的双侧隐私策略
策略文件同时描述“人物关系”和“信息类别”。

- **人物侧**：
  - 从 L0 到 L4 设置信任与披露层级：L0 为用户本人／智能体，L4 为陌生人／公开受众。
  - 中间层进一步区分生活域和工作域，例如生活亲信、工作亲信、生活同辈、工作同辈。
  - 关系由用户从自己的视角定义，不要求双方对关系的理解一致。

- **信息侧**：
  - **普通类别**：映射到一个隐私级别。
  - **穿透类别**：允许跨多个级别或领域流转，其默认受众取相关受众集合的并集。
  - **未授权类别**：无法匹配的信息暂放入 L0，采取保守默认。

- **事实级例外**：
  - 白名单允许特定接收者跨层级或跨领域访问某条事实。
  - 黑名单撤销特定事实的披露权限，且**黑名单优先于白名单**。
  - 标注时区分真实信息与掩饰性说法，避免把“听过掩饰说法”误当成“有权知道真相”。

### 2.3 记忆粒度与存储结构
论文区分六层记忆：
- F0：原子条目。
- F1：原始对话轮次。
- F2：事件级事实。
- F3：会话摘要。
- F4：关键词。
- F5：会话元数据。

隐私控制主要作用于 **F2 事件级事实**，而不是整场会话或单个词元。文中的“词元级记忆”指其依托显式文本记忆系统，不宜理解为逐 token 设置访问权限。

- 隐私侧存储与原生存储分离，通过共享 F3 索引关联。
- 若原生系统具有 F0，则额外建立 F2 到 F0 的支持关系。
- 隐私标注可以异步执行，尽量减少对原有记忆管线的改动。

### 2.4 披露判定规则
- **单事实判定**：默认受众加白名单，再移除黑名单；接收者属于最终允许集合时才能披露。
- **多事实判定**：对复合问题计算“隐私上限”，收紧默认受众；只有所有组成事实都获准，才能完整披露。
  - 同域事实取更严格层级。
  - 不同领域的组合保守收紧到 L0，再考虑白名单例外。
- **事件共指判定**：
  - 将问题拆成独立信息单元，处理同一事件在不同会话中的片段或同义描述。
  - 只有记录过真实信息披露的白名单授权才可复用。
  - 不重新改写事实级名单，也不通过共指任意扩展黑名单。

这些规则是显式、可审计的，但分类、事实对齐和共指等步骤仍依赖 LLM，因此整个系统并非形式化验证的确定性安全系统。

### 2.5 检索融合、上下文脱敏与策略演化
- **检索融合**：将原生检索分数与事件事实相关性分数加权组合；事件权重为零时恢复原生排序。MemGAS 中则以额外图检索通道实现。
- **上下文脱敏**：
  1. 将候选事实组织成共同故事线。
  2. 对当前受众保留或改写允许节点，删除或模糊禁止节点。
  3. 仅将可披露故事线和事实送入最终回答上下文。
  4. 无可披露事实时礼貌回避，不传入故事线。
- **策略演化**：
  - 外部智能体根据失败反馈改进分类、黑白名单、术语和共指四类提示原则。
  - 不修改固定披露规则和脱敏规则。
  - 审查子智能体检查是否出现题目特定补丁、答案或独有剧情线索。

## 3. 实验设计：数据集、Benchmark 与对比方法

### 3.1 EP-Bench：主要关系型披露基准
作者构建 EP-Bench，并称其为首个面向长期多方、策略条件化关系披露的基准。

- **场景**：中国社会语境中的工作、家庭、朋友和公众关系。
- **规模**：
  - 10 个第一人称长期剧本，覆盖约 7–18 个月。
  - 包含私聊、群聊、社交帖子和系统通知。
  - Easy 版本：427 个会话、752 条事件级事实。
  - Noisy 版本：扩展为 1,100 个会话，加入干扰内容。
- **设计特点**：
  - 每个剧本至少包含两条因果关联故事线。
  - 敏感事件跨会话出现，并涉及状态变化、真实情况和掩饰说法。
  - 标签和解释由三名研究者通过共识审核。
  - 提供 AI 翻译的英文版本，主要实验使用中文模板。

### 3.2 三级任务与指标
| 任务 | 规模 | 评估内容 |
|---|---:|---|
| Task 1：隐私级别分类 | 100 题 | 事件类别与级别准确率 |
| Task 2：可披露对象判断 | 50 题，另有 50 题 T2E | 完全匹配、保守部分匹配及推理审计 |
| Task 3：受众差异化回答 | 30 个问题、94 个受众实例 | 泄露、质量、受众差异和检索 |

Task 3 的主要隐私指标为：
- **PB**：出现至少一条违规事实的回答比例。
- **PC**：发生违规的回答中，违规事实占已用事实的比例。
- **PD**：发生违规的回答中，最大越界层级距离的平均值。

其他指标包括语气匹配、记忆整合质量、隐私与充分性评分、受众差异分布 KL，以及证据会话 Recall@10。

### 3.3 外部数据集
- **LoCoMo**：评估叠加隐私组件后是否影响长期记忆检索，报告 1,978 个检索实例。
- **CIMemories**：在 Douglas 与 Troy 场景进行小规模适配迁移，评估违规率和回答完整性。

### 3.4 对比方法与消融
- **NoEngine_full**：完整剧本加简单提示。
- **NoEngine_evid**：仅提供正确证据会话，加简单提示。
- **RoleHist**：仅提供涉及当前受众的历史会话。
- **EP-Mem / EP-Mem+Evo**：完整系统及策略演化版本。
- **w/o Disc**：移除显式披露判断。
- **w/o Desens.**：移除上下文脱敏。
- 原生记忆系统采用 **SimpleMem** 和 **MemGAS**。
- CIMemories 额外比较 CI-L1–L4 分级提示与 Filter-only。

## 6. 主要结论与发现

### 主实验结果
| 指标 | 对照 | EP-Mem | EP-Mem+Evo |
|---|---:|---:|---:|
| Task 1 分类准确率 | — | 94.0% | — |
| Task 2 完全匹配 | 22%（完整上下文） | 68% | 82% |
| Task 3 PB ↓ | 0.738（证据上下文） | 0.180 | 0.136 |
| Task 3 PC ↓ | 0.781 | 0.571 | 0.387 |
| Task 3 PD ↓ | 1.814 | 1.067 | 0.867 |
| Task 3 综合 LLM 评分 ↑ | 2.96 | 3.71 | 3.67 |

- 从 PB=0.738 降至 0.180，**相对降幅约 75.6%**。这里降低的是“含违规事实的回答比例”这一指标，不是所有形式隐私风险的统一降幅；主表按十个剧本等权汇总。
- 移除披露判断后，Task 2 完全匹配降至 28%；移除脱敏后，PB 升至 0.493，支持两模块的必要性。
- 演化总体改善隐私，但回答充分性从 4.38 降至 4.22，说明仍有隐私—效用权衡。

### 检索与迁移结果
- SimpleMem 在 LoCoMo 上 Recall@10 从 0.4141 升至 0.4651。
- MemGAS 的 Recall@10 略升，但早期排名指标和 MRR 略降；因此应表述为**大体保持、部分改善**，而非所有检索指标均提高。
- CIMemories 上 EP-Mem 的违规率为 46.5%、完整性为 59.2%：
  - 相比 CI 提示，违规显著减少。
  - 相比 Filter-only 的 31.8% 违规率，隐私更弱，但完整性明显更高，体现折中而非全面优胜。
- 更强模型的简单提示基线可接近 EP-Mem；某些跨模型配置中 RoleHist 的泄露指标甚至更好，说明收益依赖模型与场景。

## 7. 优点与亮点

- **问题定位准确**：将个人智能体隐私落到“代用户与第三方沟通”的实际授权问题。
- **用户控制明确**：人物关系与信息规则由用户定义，而非模型自行推测。
- **兼顾规则与例外**：领域默认流转加事实级黑白名单，比单一敏感性标签更细致。
- **控制粒度合理**：事件级事实既避免整场会话一刀切，也便于处理跨会话事件。
- **架构侵入性低**：边车存储和检索融合可适配不同记忆系统。
- **不只约束最终提示**：先构造受众安全上下文，降低生成器直接接触禁止信息的风险。
- **评估具有诊断性**：同时测量漏披露、过度披露、推理一致性和回答充分性。
- **报告较透明**：明确承认金标准证据设置，并展示不足够回答、指代错误和演化不稳定案例。

## 8. 不足与局限

### 8.1 仍缺乏强安全保证
- EP-Mem 本身仍有 PB=0.180，演化后仍为 0.136，不能视为可靠阻断所有泄露。
- 分类、名单生成、共指和脱敏依赖 LLM，任一环节误判都可能导致越界。
- 未系统测试提示注入、身份伪装、越狱或恶意群聊内容；边车隔离也不等于密码学安全或严格访问控制。

### 8.2 开放环境和动态关系覆盖不足
- 中国社会语境、十个剧本和统一关系层级限制了文化与组织场景泛化。
- 长期剧情跨度不等于充分验证真实关系变迁；分手、离职、授权撤销及历史记忆重标注仍缺少系统实验。
- 参与事件或已经知情被用于推导白名单，这一规范假设未必符合所有用户意愿。
- 社交记忆还包含第三方隐私，仅由记忆主人定义边界可能不足以处理共同所有权和冲突授权。

### 8.3 评估指标可能低估某些风险
- PB、PC、PD 虽按规则计算，但所依赖的“回答使用了哪些事实”仍由 LLM 判定，不能称为完全独立的客观测量。
- 事实使用判定侧重具体谓词和对象，可能漏掉暗示、可推断泄露或多轮拼接泄露。
- 无事实被判为使用时，MIQ 直接设为 5；空授权集下礼貌回避也可获得较高充分性分数，可能奖励过度保守回答。
- 生成与评审主要使用同一模型，存在共同偏差风险。
- 个别案例在事实捏造或表达失真时仍获得“无泄露”，说明**无泄露不等于真实、充分、可信的沟通**。

### 8.4 部署与维护成本尚不清晰
- 多阶段 LLM 调用可能增加成本、延迟与错误传播，论文未给出完整量化。
- 用户需要配置和维护类别、关系与例外规则，其可用性没有用户研究验证。
- 演化提升并非所有剧本或指标都一致，仍需更严格的独立测试和用户确认机制。

**综合评价**：EP-Mem 的主要价值是把长期记忆隐私转化为可配置、可审计、可嵌入记忆管线的关系型披露控制。它提供了有意义的架构与基准，但当前证据更适合支持受控场景下的效果改进，距离开放环境中的可靠个人代理隐私保障仍有明显差距。
